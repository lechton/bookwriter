# Derived Values, Part 02: The Wiring

A derived value is wired to its inputs. The wire is the thing that lets an input tell the derived it changed, so the derived can flip its dirty flag. Without the wire, the input would change and the derived would never find out, and the dirty flag would never flip, and the derived would hand back stale answers forever. The wire is the whole reason the laziness works.

This part is about that wire. It is about three named things and the connections between them, and the connections have to be built one at a time.

## The three named things

Three things are involved in the wiring, and each has a name and a role.

The first thing is a Signal, and we will call it price. A Signal is a closure that holds a value and a list. The value is what price stores, the number 3 to start. The list is price's own private list, sealed inside price's closure, holding something from each function that has read price. The list exists because when price changes, price needs to know which functions to re-run. Something from each of those functions is on the list because the function was caught reading price from inside an Effect, and the Effect's purpose is to let price learn the names of the functions that read it. Price's list starts empty.

The second thing is a derived value, and we will call it total. A derived is a Signal with a stored answer, a dirty flag, a rule, and its own private list. The rule is price times 100. The stored answer starts empty. The dirty flag starts true, because total has never computed and its stored answer cannot be trusted. Total's own private list starts empty. Total's list is separate from price's list. Each has its own list, sealed in its own closure, and the two lists have nothing to do with each other yet.

The third thing is markDirty. markDirty is an inner function of total, sealed inside total's closure alongside total's stored answer, total's dirty flag, and total's list. markDirty's entire job is to flip total's dirty flag to true, and then pass the news along to whatever is sitting in total's own list. markDirty does no arithmetic. markDirty never runs total's rule. markDirty is the smallest piece of total that still does something, and that something is a flag flip and a notification.

Three things. price, a Signal. total, a derived. markDirty, an inner function of total. Each named, each characterized, each given its role.

## The wire, before it is built

Before any read happens, no wire exists. price's list is empty. total's list is empty. markDirty exists, sealed inside total, but markDirty is sitting in no list anywhere. price does not know total exists. total does not know price exists. Nothing is connected to anything.

```js
const price = makeSignal(3);
const total = makeDerived(() => price.read() * 100);

// price's subscriber list size: 0
// total's own subscriber list size: 0
// is total dirty? true
```

Two empty lists. One true flag. That is the entire state before the wire is built.

## The wire is an entry in a list

The wire between price and total is not a cable and not a channel. The wire is an entry in a list. Specifically, the wire is an entry in price's private list, and that entry is markDirty.

When price's list holds markDirty, price can reach total, because markDirty is part of total. When price's list does not hold markDirty, price cannot reach total. The list is the only wire that exists. The entry is the only thing the wire is made of. markDirty is the only thing the entry points at.

State the same fact from the other side. markDirty is part of total. markDirty sits in price's list. Through markDirty sitting in price's list, price reaches total. Through markDirty sitting in price's list, total is reachable by price. One connection, stated twice, named every time.

## Why the entry is markDirty, and not something else

The entry in price's list is markDirty. It is not total's rule, and it is not total itself. The reason is the whole architecture.

Suppose the entry in price's list were total's rule, the function that does the arithmetic. Then, when price changed, price would call total's rule. That would mean total recomputes the moment price changes. That is the opposite of lazy. The entire point of a derived is to refuse that behavior. So total's rule is not the right entry for price's list.

Suppose the entry in price's list were some outer function, something that read total once and would like to be told when total changes. Then, when price changed, price would call that outer function. But that outer function knows nothing about total's internal arithmetic. It cannot flip total's flag. It is the wrong shape. So that is not the right entry either.

The right entry is a function whose entire body is: flip total's dirty flag, and then pass the news along to whatever is sitting in total's own list. That function is markDirty. When price changes and calls markDirty, two things happen, and only two things. Total's dirty flag flips to true. markDirty, having flipped the flag, looks at total's own private list, and tells anyone sitting there that total is now stale. No arithmetic. No recomputation. A flag flip and a notification. That is the smallest unit of work that still connects a change in price to a consequence in total, and that is why markDirty is the entry that sits in price's list.

## How the entry gets into price's list

The entry gets into price's list during total's first read. The first read is special because total's dirty flag starts true, so total's rule runs. Total's rule is price times 100. To compute price times 100, the rule has to read price. Reading price means calling price's read function.

Price's read function does two things, in order. It returns the value of price. And, before returning, it checks which Effect or derived is currently running, and drops that thing into price's own private list.

During total's first read, the thing currently running is total, in the form of markDirty. The reason markDirty is the thing currently running, and not total's rule, is that total's read function pushes markDirty onto the stack of running things before it calls total's rule. So when total's rule calls price's read function, price's read function sees markDirty on top of the stack, and drops markDirty into price's list.

State the sequence as a sequence. Total is read. Total's dirty flag is true, so total's rule runs. Total's rule needs price, so total's rule calls price's read function. Price's read function sees markDirty as the thing currently running. Price's read function adds markDirty to price's private list. Price's read function returns the value of price. Total's rule multiplies and finishes. Total stores the answer and clears its dirty flag. The read is over.

At the end of that sequence, price's private list contains one entry, and that entry is markDirty. The wire has been built. The wire is the entry. The entry is markDirty. markDirty is part of total. Price now reaches total through markDirty sitting in price's list.

```js
console.log("total.read() returns:", total.read()); // total.read() returns: 300

// price's subscriber list size: 1
// the entry is named: markDirty
// is it total's markDirty? true
// is total dirty now? false
```

One read. price's list went from empty to holding one entry, markDirty. Total's dirty flag went from true to false. The wire exists now.

## What the wire does, the first time price changes

Price changes. Price's write function is called with a new value. Price's write function does three things, in order. It updates the value of price. It looks at price's own private list, the list that now holds markDirty. It calls, one by one, every function sitting in that list.

The list holds exactly one entry. The entry is markDirty. Price's write function calls markDirty.

State that again, because this is the wire in action. Price's write function looks at price's private list. The list holds markDirty. Price's write function calls markDirty. The call is the signal traveling along the wire. The wire was the entry in the list. The signal traveling along the wire is the write function calling the entry. A loop, over a list, calling each entry. That is the whole physical reality of a signal traveling.

markDirty runs. markDirty does two things, in order. First, markDirty flips total's dirty flag to true. Total's stored answer is still there, still holding the old value, but it is now flagged as untrustworthy. Second, markDirty looks at total's own private list, and calls every function sitting there. Total's private list is empty, because nothing has been set up to read total yet. So the second step does nothing. The flag flip is all that happens.

```js
price.write(9);

// price's list still holds: markDirty
// is total dirty now? true
// total.read() returns: 900
```

The whole chain, from price changing to total being marked stale, took: one value update, one list lookup, one function call, one boolean flip. No arithmetic. Total did not recompute. Total's stored answer is still the old value, flagged as needing recomputation the next time somebody reads total.

Read total. The flag is up. Total's rule runs, reads the new price, multiplies, returns 900, stores it, clears the flag.

## The second wire: total's own list

The wire between price and total carries signals from price to total. price's list holds markDirty. That is the first wire.

There is a second wire, built by the same rule, and it carries signals from total to whatever reads total. The thing that reads total might be an Effect, an Effect being a wrapper that runs a function in a way that lets the Signals it reads learn the function's name. An Effect that reads total is, from total's perspective, exactly what total is from price's perspective. The Effect is downstream of total, the way total is downstream of price.

When an Effect reads total, total's read function does the same thing price's read function did. Total's read function looks at which Effect or derived is currently running. The currently running thing is the Effect, in the form of the Effect's run wrapper. Total's read function drops that wrapper, a piece of the Effect, into total's own private list.

Hold the symmetry, because the symmetry is the whole mechanism. Price's list holds whatever reads price. Total's list holds whatever reads total. The same rule, applied at two levels. When total read price, price's list gained markDirty. When an Effect reads total, total's list gains the Effect. The lists are the wires. The rule that fills them is the same rule at every level. That is why the whole thing chains.

Two wires now. Price's list holds total's markDirty, wiring price to total. Total's list holds a piece of the Effect, the Effect's run wrapper, wiring total to the Effect. price is upstream of total. total is upstream of the Effect. The Effect is the downstream end.

```js
const price2 = makeSignal(3);
const total2 = makeDerived(() => price2.read() * 100);
watchEffect(() => { console.log("  effect body ran, total2 is:", total2.read()); });
// effect body ran, total2 is: 300

// price2's list holds: markDirty
// total2's OWN list size: 1
// the entry in total2's list is named: run
```

The entry in total2's list is named run because run is the internal name every Effect's wrapper carries. The name does not matter. What matters is that total2's list now holds a piece of the Effect, the way price2's list holds total2's markDirty. Two lists, two entries, two wires, one chain.

## The whole chain, when price changes, end to end

Price2 changes. Price2's write function updates the value of price2. Price2's write function looks at price2's private list. Price2's list holds total2's markDirty. Price2's write function calls total2's markDirty.

Total2's markDirty runs. markDirty flips total2's dirty flag to true. markDirty looks at total2's own private list. Total2's list holds a piece of the Effect, the wrapper from the one that read total2 earlier. markDirty calls that wrapper.

The Effect runs. The Effect's body reads total2, because reading total2 was the Effect's whole job. Total2's read function sees that total2's dirty flag is up. Total2's read function runs total2's rule. Total2's rule reads price2, gets the new value, multiplies, returns. Total2 stores the new answer, clears the flag.

The Effect's body, having gotten the new value of total2, does its work. The work is printing.

```js
price2.write(9);
// effect body ran, total2 is: 900
```

One change at the top, price2 written. One cascade down two wires. The first wire carried the signal from price2 to total2's markDirty, and that signal flipped a flag. The second wire carried the signal from total2's markDirty to the Effect, and that signal ran the Effect, which pulled the recompute out of total2 by reading it. Every link in the chain is the same kind of link: a list, holding an entry, and a write function or a markDirty function calling that entry. The mechanism does not change between the first wire and the second. The same rule, applied twice, chained.

## The three things and the two wires

price is a Signal holding a value and a list. total is a derived holding a stored answer, a dirty flag, a rule, and a list. markDirty is an inner function of total whose job is to flip total's dirty flag and notify total's list.

The first wire is an entry in price's list. The entry is markDirty. Through that entry, price reaches total. The wire was built during total's first read, when total's rule read price and price's read function dropped markDirty into price's list.

The second wire is an entry in total's list. The entry is a wrapper from the Effect that read total. Through that entry, total reaches the Effect. The wire was built when the Effect read total, and total's read function dropped the Effect's wrapper into total's list.

The rule that built both wires is the same rule: when a thing is read, a piece of the reader goes into the thing's list. Price was read by total, so price's list holds markDirty, a piece of total. Total was read by the Effect, so total's list holds the Effect's wrapper, a piece of the Effect. One rule, two applications, two wires.

The rule that carries signals along both wires is the same rule: when a thing changes, every entry in its list is called. Price changed, so price called markDirty. markDirty, acting on total's behalf, flipped total's flag and called the entries in total's list, which was the Effect. One rule, two applications, one cascade.

Two lists, holding entries, built by reading, triggered by writing. The mechanism is small. The lists are the wires, the entries are what travels, and the same two rules govern both ends.
