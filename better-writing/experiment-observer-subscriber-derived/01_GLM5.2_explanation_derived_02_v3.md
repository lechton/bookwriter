# Derived Values, Part 02: The Wiring

A derived value skips work. When its inputs change, it does not recompute. It flips a boolean and waits. That was the claim of Part 01, and it was true. But it raises an immediate question. If the derived does not recompute when an input changes, how does the derived ever find out that the input changed? The boolean does not flip itself. Some piece of the mechanism has to catch the change and reach into the derived to flip the flag, or the derived will hand back the old answer forever, long after the input has moved on, and nobody will know the answer is wrong. That piece is the wire. The wire is the physical thing that connects an input to a derived, and the signal that travels along the wire is the physical thing that flips the flag. This part is about what the wire is made of, how it gets built, and what happens when a signal travels along it.

## Two things, not yet connected

Start with two things, and only two, because the wire connects exactly two things and naming both endpoints is the only way to name the connection.

The first thing is a Signal, and we will call it price. A Signal is a closure holding a value and a list. The value is what price stores, the number 3 to start. The list is price's own private list, sealed inside price's closure, and it holds an entry from each function that has read price. The list exists because when price changes, price needs to know which functions to re-run. An entry from each of those functions sits in the list because the function was caught reading price from inside an Effect, and the Effect's purpose is to let price learn the names of the functions that read it. Price's list starts empty. Nobody has read price yet, so price knows about nobody.

The second thing is a derived value, and we will call it total. A derived is a Signal with a stored answer, a dirty flag, a rule, and its own private list. The rule is price times 100. The stored answer starts empty. The dirty flag starts true, because total has never computed and its stored answer cannot be trusted. Total's own private list starts empty, because nothing has read total yet. Total's list is separate from price's list. Each has its own list, sealed in its own closure, and the two lists have nothing to do with each other.

Two things, named. Two empty lists, sealed in two closures. Nothing is connected to anything. Price does not know total exists. Total does not know price exists. This is the situation before any wire is built.

```js
const price = makeSignal(3);
const total = makeDerived(() => price.read() * 100);

// price's subscriber list size: 0
// total's own subscriber list size: 0
// is total dirty? true
```

Two empty lists. One true flag. That is the entire state.

## What the wire is made of

A wire between two software objects is not a cable. It is a reference. One object holds a reference to the other, or to a piece of the other, and through that reference the first object can reach the second. In this mechanism, the reference lives in a list. Specifically, the reference lives in price's private list, and the thing it points at is a piece of total.

State that precisely, because every word carries weight. The wire is an entry in price's list. The entry points at something inside total. When the entry exists, price can reach total. When the entry does not exist, price cannot reach total. There is no other channel. The list is the only wire that exists. The entry is the only thing the wire is made of.

Now the question becomes: what exactly is the entry? It cannot be total itself. Total is a bundle of a stored answer, a dirty flag, a rule, and a list. Price's list does not hold that whole bundle. Price's list holds one specific piece of total — a small function sealed inside total's closure, alongside total's stored answer and total's dirty flag, whose entire job is to flip total's dirty flag. This function needs a name, and the name is markDirty.

markDirty is an inner function of total. It is part of total. It is sealed in total's closure. It does not belong to price. It does not float free. It is total's markDirty, and its job is two things, in order: flip total's dirty flag to true, and then look at total's own private list and call every entry sitting there. markDirty does no arithmetic. markDirty never runs total's rule. markDirty is the smallest piece of total that still connects a change in an input to a consequence in total. That is the piece that will sit in price's list.

## Why the entry must be markDirty, and nothing else

The choice of what sits in price's list is not arbitrary. Consider the two alternatives.

Suppose the entry in price's list were total's rule, the function that does the arithmetic, price times 100. Then, when price changed, price would call total's rule. Total would recompute the moment price changed. That is the opposite of lazy. The entire point of a derived is to refuse that behavior. A derived that recomputes on every input change is not a derived. It is an eager computation wearing a different name. So total's rule cannot be the entry.

Suppose the entry were some outer function, code that read total once and would like to be told when total changes. Then, when price changed, price would call that outer function. But that outer function knows nothing about total's internal flag. It cannot flip it. It is the wrong shape for the job. It calls total's read function, perhaps, which would recompute total — but that is still the wrong chain of command. The purpose of the wire is to tell total it is stale. The purpose is not to tell total's readers that total is stale and then have them ask total if it is stale. The wire goes from input to derived, directly. The entry must be something inside the derived.

The right entry is a function whose body is: flip total's dirty flag, then notify total's list. That function is markDirty. When price changes and calls markDirty, two things happen and only two things. Total's dirty flag flips to true. markDirty passes the news to whatever is in total's list. No arithmetic. No recomputation. A flag flip and a notification. That is the smallest unit of work that still connects a change in price to a consequence in total, and that is why markDirty is the entry in price's list.

## How markDirty gets into price's list

The entry gets into the list during total's first read. The first read is special because total's dirty flag starts true, so total's rule must run. Total's rule is price times 100. To compute price times 100, the rule must read price. Reading price means calling price's read function. This moment, this single function call, is where the wire is built.

To understand why, one more piece of the mechanism must be named. Every derived and every Effect, when it begins running, pushes a small piece of itself onto a global stack. For a derived, the pushed piece is markDirty. For an Effect, the pushed piece is a wrapper called run. The stack is the one piece of shared state in the whole system. Every read function in every Signal checks the top of this stack to see who is currently running. The thing on top of the stack is the thing that will be dropped into the Signal's list.

Now trace total's first read, step by step. Total's read function is called. Total's dirty flag is true, so total's rule must run. Before running the rule, total's read function pushes markDirty onto the stack. Then total's rule runs. Total's rule calls price's read function. Price's read function looks at the top of the stack. The top of the stack is markDirty. Price's read function adds markDirty to price's private list. Price's read function returns the value of price, which is 3. Total's rule multiplies 3 by 100, returns 300. Total's read function stores 300, clears the dirty flag to false, and pops markDirty off the stack.

The read is over. Price's list now contains one entry, and that entry is markDirty. The wire has been built.

```js
console.log("total.read() returns:", total.read()); // total.read() returns: 300

// price's subscriber list size: 1
// the entry is named: markDirty
// is it total's markDirty? true
// is total dirty now? false
```

One read. Price's list went from empty to holding markDirty. Total's flag went from true to false. Total is now wired to price. The wire is the entry. The entry is markDirty. markDirty is part of total. Price can reach total through markDirty sitting in price's list.

State the sequence once more, as a sequence, because the order of operations is the whole mechanism and a single misordering breaks everything. Total is read. Total pushes markDirty onto the stack. Total's rule runs. Total's rule reads price. Price's read function sees markDirty on the stack. Price's read function adds markDirty to price's list. Price's read function returns the value. Total's rule multiplies. Total stores, clears the flag, pops the stack. The read is done. The wire exists.

## The signal traveling along the wire

The wire exists. Now watch a signal travel along it. Price changes. A change means price's write function is called with a new value. Price's write function does three things, in order. It updates the value of price to the new number, say 9. It looks at price's private list. It calls, one by one, every entry sitting in that list.

The list holds exactly one entry, markDirty. Price's write function calls markDirty.

The call is the signal traveling along the wire. The wire was the entry in the list. The signal is the write function calling that entry. A loop over a list, calling each entry. That is the whole physical reality of a signal traveling through this mechanism. No message passing. No event bus. No pub-sub broker. A function stored in an array, called by a loop.

markDirty runs. It does two things, in order. First, it flips total's dirty flag to true. Total's stored answer is still 300, still sitting in memory, but it is now flagged as untrustworthy. Second, markDirty looks at total's own private list and calls every entry there. Total's list is empty, because nothing has been set up to read total yet. The second step does nothing.

```js
price.write(9);

// price's list still holds: markDirty
// is total dirty now? true
// total.read() returns: 900
```

The whole chain, from price changing to total being marked stale, took four operations: one value update, one list lookup, one function call, one boolean flip. No arithmetic. Total did not recompute. Total's stored answer is still 300, flagged stale.

Now read total. Total's read function checks the flag. The flag is true. Total's rule runs. Total reads price, gets 9, multiplies by 100, returns 900, stores it, clears the flag. The recompute happened on the read, not on the write. The laziness is preserved. The wire did its single job: it caught the change and flipped the flag. It did nothing else.

## The second wire: what happens downstream of total

One wire exists now: price's list holds markDirty, connecting price to total. A signal traveling from price reaches total through that wire, and the signal flips total's flag.

A second wire can be built, and it is built by the exact same rule. The second wire connects total to whatever reads total. The thing that reads total might be an Effect — a wrapper that runs a function in a way that lets the Signals it reads learn the function's name. An Effect that reads total is, from total's perspective, exactly what total is from price's perspective. The Effect is downstream of total, the way total is downstream of price. The Effect needs to be told when total goes stale, the way total needs to be told when price changes.

When an Effect reads total, the mechanism repeats. Total's read function pushes the Effect's wrapper, called run, onto the stack. Total's read function checks the flag. If the flag is up, total's rule runs first, reading price, and price's read function adds markDirty to price's list again — harmless, since a list only holds each entry once. Then total's read function, now acting exactly like price's read function did, looks at the top of the stack. The top of the stack is run, the Effect's wrapper. Total's read function adds run to total's own private list.

The second wire exists now. Total's list holds run. Through run sitting in total's list, total can reach the Effect. The wire is the entry in total's list. The entry is run. Run is a piece of the Effect, the way markDirty is a piece of total. One rule, applied at two levels, built two wires.

```js
const price2 = makeSignal(3);
const total2 = makeDerived(() => price2.read() * 100);
watchEffect(() => { console.log("  effect body ran, total2 is:", total2.read()); });
// effect body ran, total2 is: 300

// price2's list holds: markDirty
// total2's OWN list size: 1
// the entry in total2's list is named: run
```

Price2's list holds markDirty, connecting price2 to total2. Total2's list holds run, connecting total2 to the Effect. Two lists, two entries, two wires, one chain. The chain runs from price2, through total2, to the Effect. The same rule governs every link: when a thing is read, a piece of the reader goes into the thing's list.

## One change, end to end, through two wires

Now trace a change from the very top of the chain to the very bottom. Both wires exist, and a signal will travel along both of them.

Price2 changes. Price2's write function updates the value of price2 to 9. Price2's write function looks at price2's list. The list holds markDirty. Price2's write function calls markDirty.

markDirty runs. It flips total2's dirty flag to true. Then it looks at total2's own list. Total2's list holds run, the Effect's wrapper. markDirty calls run.

Run is the wrapper around the Effect's body. When run is called, it pushes itself onto the stack and then calls the Effect's body. The Effect's body reads total2. Total2's read function checks the flag. The flag is true. Total2's rule runs, reads price2, gets 9, multiplies, returns 900, stores it, clears the flag. Total2's read function returns 900 to the Effect.

The Effect's body, now holding the value 900, does its work. The work is printing.

```js
price2.write(9);
// effect body ran, total2 is: 900
```

One change at the top. One cascade down two wires. The first wire carried the signal from price2 to markDirty, and markDirty flipped a flag. The second wire carried the signal from markDirty to run, and run triggered the Effect, which pulled the recompute out of total2 by reading it. Every link is the same kind of link: a list holding an entry, and a function calling that entry. The mechanism does not change between the first wire and the second. The same two rules — read subscribes, write notifies — apply at every level.

## The two rules that govern every wire

Two rules govern the entire mechanism, and they are the same rules at every level of the chain.

The first rule governs how a wire is built. When a Signal or a derived is read, a piece of the reader is dropped into the reader's own list. The reader might be a derived, in which case the dropped piece is markDirty. The reader might be an Effect, in which case the dropped piece is run. The identity of the piece changes, but the rule does not. Price was read by total, so price's list holds total's markDirty. Total was read by the Effect, so total's list holds the Effect's run. One rule, applied at two levels, built two wires.

The second rule governs how a signal travels along a wire. When a Signal is written, or when markDirty is called, every entry in the writer's list is called, one by one. Price was written, so price called markDirty. markDirty was called, so markDirty called run. The identity of the caller and the called changes, but the rule does not. One rule, applied at two levels, produced one cascade.

Read subscribes. Write notifies. Those are the two rules that govern every wire in the system. The rules never swap. Reading is the only moment a dependency can be discovered. Writing is the only moment a dependency is acted on. The same two rules, applied repeatedly, chain an arbitrary number of Signals, deriveds, and Effects into a single reactive graph.

## The whole mechanism, in three named things and two wires

price is a Signal holding a value and a list. total is a derived holding a stored answer, a dirty flag, a rule, and a list. markDirty is an inner function of total whose job is to flip total's flag and notify total's list. An Effect is a wrapper around a function, and when the Effect runs, a piece of it called run is pushed onto the stack and dropped into the lists of whatever Signals and deriveds the function reads.

The first wire is an entry in price's list. The entry is markDirty. Through markDirty, price reaches total. The wire was built during total's first read, when total's rule read price and price's read function found markDirty on top of the stack and dropped it into price's list.

The second wire is an entry in total's list. The entry is run. Through run, total reaches the Effect. The wire was built when the Effect read total, and total's read function found run on top of the stack and dropped it into total's list.

When price changes, price calls markDirty. markDirty flips total's flag. markDirty calls run. Run triggers the Effect. The Effect reads total. Total's flag is up, so total recomputes. The laziness is preserved at every step. No arithmetic happened on the write. The signal traveled through two wires and all it did was flip one boolean and trigger one re-read. The arithmetic waited until the read, the way a derived always does.
