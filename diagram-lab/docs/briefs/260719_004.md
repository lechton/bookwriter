# Brief 004 — The experimental workflow installed and tested on new topics

**Date:** 2026-07-19 · **Scope:** installation of the card design workflow + first controlled tests (exp-002, exp-003) · **Status:** workflow operational; adoption decision ready for review
**Builds on:** briefs 001 (quality gap), 002 (metaphor casting), 003 (pedagogy layer)

## 1. What was installed

- `docs/design-workflow.md` — the experimental workflow: the v2 design block (DIAGNOSE then CAST/RENDER), the operating procedure (experiment folder, thinking sidecar, concept line, build, shot, rubric, promote), and the judging rubric (pedagogy P1–P3, design D1–D5). Additive; the README production contract is untouched.
- `docs/metaphor-registry.md` — the Used Metaphors list (name, topic, deck, genre, origin), seeded from all existing decks, with genre observations (violation under-used in the Svelte deck; svelte-demo 01–03 genre-less).
- `src/build.mjs` — one-line change: `*.thinking.md` sidecars are excluded from the build, so reasoning artifacts can live next to their cards in `md/` without polluting decks. No existing file matches the suffix; fully reversible.
- Experiment folders `output/exp-002_key/` and `output/exp-003_new-topics/`, per the modularity convention (folder per experiment, numbered variant files, undo = delete).

## 2. Test design

- **exp-002 — bake-off on `{#key}`** (new topic, no existing card). Control arm `01_key_control.md` written in good faith under the current README contract; treatment arm `02_key_wrecking-ball.md` written under the workflow with its reasoning emitted in `02_key_wrecking-ball.thinking.md`. Same pipeline, same constraints; instructions are the only variable.
- **exp-003 — workflow-only on two more new topics**, to shake out usability: `01_flushSync_press-run.md` (violation genre) and `02_await_waiting-on-the-wire.md` (fog genre), each with a thinking sidecar. The choice genre was not exercised this round — flagged for exp-004.

## 4. Observations

1. **The control reproduced the disease on demand.** Given the current README contract, a good-faith effort produced exactly the modal local output: correct, clean, and aimed at nothing — a topic-picture with a generic question. The quality gap is instruction-driven, again.
2. **The DIAGNOSE phase upgrades the text, not just the diagram.** The treatment card's question is the learner's own words, its answer leads with the verdict ("a key change is not a refresh; it is a teardown"), and its Why-it-works explains why the wrong expectation is reasonable. None of that was asked for separately; it falls out of A1–A3.
3. **Thinking sidecars work as intended.** The reasoning is auditable without polluting the card, and the build exclusion keeps decks clean. The three-candidate CAST step produced scenes from genuinely different families each time (demolition vs hotel changeover vs repair shop; press run vs departures board vs elevator).
4. **Genre variety held.** Two violations and one fog, no contrast-monoculture drift yet; the registry's genre column makes the mix visible at a glance.
5. **Bias caveat stands.** One operator (this assistant) authored both arms, and designed the workflow. The honest next validation is a fresh model session — local Gemini — handed only `docs/design-workflow.md` plus the registry, with no other context.

## 5. Verdict

The workflow is installed, followable, and its output passes the full rubric on three new topics across two genres, while the control reproduces the old failure mode. Recommend: adopt `docs/design-workflow.md` as the default for all new card authoring, keep it experimental only for production-deck promotion until the fresh-model validation runs.
