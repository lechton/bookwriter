# Brief 001 — diagram-lab: the online vs local Gemini quality gap

**Date:** 2026-07-19 · **Scope:** diagram-lab review + first controlled experiment · **Status:** findings delivered, conventions in effect from this brief onward

## 1. Why this brief

The two demo apps in `docs/` (`flashcards_app.html`, `flashcards_app_02.html`) were produced by the online Gemini platform and are the quality reference. The card decks in `output/*/pdf/` were produced by local Gemini (3.1 Pro, high) and feel less creative. This brief records what was compared, why the gap exists, and the conventions that fix it.

## 2. Evidence on disk

All comparisons were done from rendered screenshots, not source reading alone.

- `docs/_shots/` — every slide of both online demos (21 PNGs), captured with the new `src/review-shot.mjs`.
- `output/svelte-demo/html/_shots/` — all 18 local svelte cards.
- `output/javascript-demo/html/_shots/` — all 8 local javascript cards.
- `output/javascript-demo-02/html/_shots/` — the transcription test.
- `output/exp-001_state/html/_shots/` — the controlled experiment (section 8).

| Artifact | Author | Verdict |

Key finding: local output is only "amazing" exactly where it traces the online output. Everything authored from scratch locally falls back to one skeleton.

## 4. The gap, concretely

Online Gemini invents a named visual metaphor per card: the Developer Console terminal for `$inspect`, the Blueprint Factory for `#snippet`, the Two-Way Street for `$bindable`, the Lexical Environment scene for closures. The typology is written up in `docs/Gemini_instructions.md` (The Switch, The Blueprint, The Two-Way Street, The Terminal, The Lifecycle Flow).

Local Gemini reuses one skeleton: black label chip, bordered panel, yellow/blue/green boxes, arrows ("THE LOOKUP WALKS UP", "ONE HIDDEN VARIABLE", "TWO READS, TWO OUTCOMES"). Correct and clean, but swap the labels and the figures are interchangeable. `svelte-demo` cards 01–04 are worse: literally the same `.stack` two-box diagram four times with different labels.

## 5. Diagnosis: it is the brief, not the model

1. **Different task framing.** Online got an open-ended design-studio brief ("build a beautiful flashcard app") and invented a design language. Local gets the README production contract: fixed pattern library, deterministic output, print constraints. A constrained brief yields conservative output.
2. **The pattern library anchors to the mean.** `assets/styles/diagrams.css` offers `.stack`, `.box`, `.arrow-down`, and the README says diagrams come from a "fixed pattern library". Told that, a model reuses the nearest pattern instead of inventing. "Fixed library" plus "be creative" is a contradictory prompt, resolved toward safety.
3. **Medium mismatch.** The references are screen apps (Tailwind CDN, dark terminal, Google Fonts, JS slides). The local target is print (130mm, Prince, no JS, self-hosted fonts). In translation the model keeps boxes and arrows and drops the scene-setting.
4. **The naming step is missing.** Online, every diagram got a concept name first, then markup. Local goes straight from topic to HTML and lands on box-arrow-box.
5. **No visual feedback loop.** Online iterated against a live preview. Local authors markup blind; `src/shot.mjs` existed but was not part of the authoring loop.

## 6. Side issues found

- `assets/styles/neo-brutalism.css` line 7 imports Google Fonts via `@import url(...)` — violates the self-hosted-fonts print rule and makes the PDF depend on Prince fetching network fonts.
- `src/build.mjs` line 137 hardcodes that stylesheet to `javascript-demo-02` only, a one-folder hack.
- `neo-brutalism.css` is an `!important`-heavy override sheet fighting `cards.css`, rather than a first-class theme.

## 7. Recommendations

1. **Formalize the division of labor that already emerged organically:** online Gemini = design studio (invent and name the metaphor per topic); local = production (transcribe into print-safe markup). `docs/demo_diagrams.md` and `javascript-demo-02` prove this pipeline works; make it the documented workflow.
2. **Promote `neo-brutalism.css` into a real metaphor library:** terminal window, factory stamp, two-way street, timeline, zone-compare, retained-scope dashed zones, pill arrows, label chips, each a named class set, print-safe, self-hosted fonts. Local creativity then means choosing and composing metaphors, which models do well, instead of inventing CSS from scratch, which they do conservatively. Link it for all demos and drop the folder hack.
3. **Make the diagram concept a mandatory card line**, e.g. `**Diagram concept.** The Factory Stamp` before the markup. This forces the naming step that drives downstream variety.
4. **Close the loop with screenshots:** author, `node src/shot.mjs <demo> deck`, self-critique against a reference PNG, revise.
5. **Re-author `svelte-demo` cards 01–04** regardless; they are the four weakest cards in the lab.

## 8. Experiment log

Conventions (in effect from this brief): every experiment is its own folder `output/exp-NNN_<topic>/` holding only `md/` sources; html, pdf, and `_shots` are regenerated by the build and safe to delete. Card variants are separate numbered files inside the folder (`01_state_dead-wire.md`, `02_state_live-feed.md`), so the build renders each variant as its own page and the deck stacks them for side-by-side comparison. Undo = delete the file or folder. Existing demos (`svelte-demo`, `javascript-demo`, `javascript-demo-02`) are frozen history and are never edited in place; more files beats fewer files.

### exp-001_state — same weak card, two metaphors, concept-first

- **Setup.** Took the weakest card in the lab (`svelte-demo/01_state`, a plain two-box stack) and rewrote it twice, keeping question, answer, code, and summary identical so the diagram is the only variable. Each variant opens with the mandatory `**Diagram concept.**` line before any markup.
- **Variant 1, `01_state_dead-wire.md` — "Dead Wire vs Live Wire".** Two lanes: a dashed gray dead lane (`let count = 0`, wire tagged LOST, `DOM: 0 forever`) above a solid black live lane (`let count = $state(0)`, wire tagged LIVE with arrowhead, `DOM: {count}`). One iteration was needed: the code box wrapped to two lines at 9pt, fixed with flex 1.5, 8.5pt, `white-space:nowrap`.
- **Variant 2, `02_state_live-feed.md` — "The Live Feed".** `$state` as the wire desk ("the wire · one source") with two arrows down to two subscriber boxes (`<h1>{count}</h1>`, `<button>{count}</button>`) and the caption pill "one update · every subscriber re-renders". Clean on first build.
- **Result.** Both variants build deterministically to html and pdf and are visibly stronger than the original (compare `output/svelte-demo/html/_shots/deck-01.png` against `output/exp-001_state/html/_shots/deck-01.png` and `deck-02.png`). The loop ran author → build → screenshot → fix → rebuild in minutes, which validates recommendation 4.
- **Decision:** keep both variants for now; pick a winner when `svelte-demo` 01 is formally re-authored.
