# Lecture 20: Two-Way Component Binding
> INTERVIEW QUESTION | ❱ CORE | How do you let a parent read and change a value that lives inside a child component?

Your `Input` component owns its value, but the parent needs to read and reset it. How do you set up two-way binding across the component boundary?

You already know how to pass data down to a child using normal props, and you know how to bind data to native HTML elements like `<input>` using `bind:value`. But what happens when you create your own custom components?

### The Stagnant Parent Problem

Imagine you are building a custom `<PinCode>` component for a security application. Inside the component, you have the logic to handle four separate number inputs and concatenate them into a single `pin` string. 

You import this `<PinCode>` into your `Login.svelte` parent component. The parent has a "Submit" button, but it cannot see the `pin` string because it is trapped inside the child's local state. Even worse, if the user enters the wrong PIN, the parent needs a way to wipe the child's input clean. If data strictly flows downwards, the parent is completely blind to the child's internal state and powerless to reset it.

### The `$bindable()` Rune

In Svelte 5, you can explicitly mark a child component's prop as open for two-way communication using the `$bindable` rune. 

By default, props are read-only. If the parent passes a value down, the child cannot alter it. But when the child wraps a prop in `$bindable()`, it declares: *"I am allowed to change this value, and if I do, the parent's variable will instantly update to match."*

```svelte title="PinCode.svelte"
<script>
  let { pin = $bindable() } = $props(); // 1. The child explicitly marks 'pin' as open for two-way binding
</script>

<input type="text" bind:value={pin} /> <!-- 2. The child binds its local HTML input to the bindable prop -->
```

### Binding Across the Boundary

Now that the child has given permission, the parent component can use the `bind:` directive directly on the custom component tag, exactly as it would on a native HTML `<input>`.

```svelte title="Login.svelte"
<script>
  import PinCode from './PinCode.svelte';
  
  let currentPin = $state("");

  function reset() {
    currentPin = ""; // 4. The parent changes the value, flowing back down to wipe the child's input
  }
</script>

<PinCode bind:pin={currentPin} /> <!-- 3. The parent uses 'bind:pin' to establish a two-way tunnel -->

<p>You typed: {currentPin}</p>
<button onclick={reset}>Clear Pin</button>
```

When the user types inside the child component, the native `<input>` updates the `pin` prop. Because `pin` is `$bindable()`, the change travels up the tunnel and updates the parent's `currentPin` state. When the parent clicks the reset button, `currentPin` changes to an empty string, traveling back down the tunnel to clear the child's `<input>`.

> [!KEY]
> You can provide a default fallback value to a bindable prop just like any other prop: `let { pin = $bindable("0000") } = $props();`

### Summary

To allow data to flow seamlessly in both directions across component boundaries, use the `$bindable()` rune. The child component must explicitly opt-in by wrapping its prop declaration in `$bindable()`. Once authorized, the parent component can use the `bind:propName` directive on the custom component. This creates a two-way synchronization tunnel, allowing both the parent and the child to read and modify the shared data safely.

| | **NORMAL PROPS** | **BINDABLE PROPS** |
| ---: | :--- | :--- |
| **Declaration** | `let { name } = $props();` | `let { name = $bindable() } = $props();` |
| **Data Flow** | Parent to Child (One-Way) | Two-Way Synchronization |
| **Parent Usage** | `<Child name={val} />` | `<Child bind:name={val} />` |
