## Q27 — The Assignment Operator in Svelte 3/4

@tags State (Legacy)

**Question.** What is the operational significance of the assignment operator (=) in Svelte 3/4 reactivity?

**Answer.** The assignment operator (`=`) is the fundamental trigger for reactivity. The compiler detects assignments to top-level variables and explicitly injects an internal `$$invalidate` function call to queue a DOM update. Mutating data via internal methods like `push()` without reassignment bypasses this detection.

```svelte title="App.svelte"
<script>
  let items = [1, 2, 3];

  function addItem() {
    // A method mutation alone does NOT trigger reactivity
    items.push(4); 

    // The assignment operator (=) signals the compiler to update the DOM
    items = items; 
  }
</script>

<ul>
  {#each items as item}
    <li>{item}</li>
  {/each}
</ul>
```

> **Summary.** Mutating an array or object in Svelte 3 and 4 is not enough. You must follow any mutation with an explicit assignment to trigger the compiler's reactivity tracking and update the DOM.
