Design description: A left-to-right linear pipeline of three boxes on off-white paper, teaching the one optimization that defines $derived: the body runs only when a dependency changes AND the value is read. The first box on the left is a neutral white data container labeled count = $state(...) and represents the reactive input; a small caption underneath reads "tracked as a dependency". A thick black arrow with a solid arrowhead connects it to the middle box, which is the only mustard-yellow accent in the diagram and is labeled $derived(count * 2); a small pill positioned above the arrow reads "only if read", marking the gate condition that makes recomputation lazy. The middle box connects via a second thick black arrow to the right box, a neutral white container labeled double, which is the cached value consumed downstream. Exactly four visual elements total: the input box, the derived box, the output box, and the "only if read" gate pill. No contrast row, no second input branch, no memo-cache inset, no legacy $: counter-example — the diagram argues laziness with a single arrow-gate, nothing else.
