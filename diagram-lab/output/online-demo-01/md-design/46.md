Design description: A top-to-bottom linear pipeline on off-white paper, teaching the single mechanism that protects Svelte against redundant renders: many synchronous writes collapse into one scheduled flush, which produces one DOM update. The top of the diagram is a tight vertical stack of three small neutral-white write boxes, each labeled with a reactive mutation (`count += 1`), grouped under one shared micro-label reading "synchronous writes" so the whole stack counts as a single element. A thick black arrow with a solid arrowhead connects the stack downward to the middle box, which is the only mustard-yellow accent in the diagram and is labeled "one microtask flush"; a small pill positioned beside the arrow reads "coalesced", marking that the three writes have been merged. The middle box connects via a second thick black arrow to the bottom box, a neutral white container labeled "one DOM update" with the final value shown inside. Exactly four visual elements total: the write stack, the flush box, the render box, and the "coalesced" pill. No second signal branch, no timeline, no per-write render boxes — the diagram argues batching by geometry (three into one into one), nothing else.
