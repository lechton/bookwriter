Object Property Mutations in Legacy Svelte

State (Legacy)

Question. How do you force a reactive update after modifying an object property in Svelte 3/4?

Answer. In Svelte 3 and 4, modifying a nested property on an object (e.g., user.age = 31) does not automatically trigger the reactivity system. Because the compiler tracks assignments at the top-level identifier to inject invalidation code, you must explicitly reassign the object to itself (user = user) or assign it a completely new object reference (often using the spread operator) to force the UI to render the updated state.

Summary. Mutating an object property directly avoids detection by the compiler in Svelte 3 and 4. You must always use an explicit top-level assignment to force the UI to react to the updated state.

Property Mutation (Silent)
user.age = 31
Top-Level Assignment (Reactive)
user = user
