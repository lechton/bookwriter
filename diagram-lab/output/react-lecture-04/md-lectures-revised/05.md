### The Window into JavaScript

In earlier lessons, we learned that JSX lets you write HTML-like markup inside JavaScript component functions (see Lecture 4). When you write a tag like `<h1>Breaking News</h1>`, the text inside the tag is a static string. Real web applications are dynamic. You have variables in your script, such as an article headline or a reader name. You need that markup to read those variables directly.

In plain HTML, markup is completely static. An attribute value is always a literal string, and text between tags cannot execute code. Inside JSX, the compiler encounters `{ }`. It treats content between the braces as JavaScript code rather than literal text.

You can use curly braces in two places inside JSX:
First, as text directly inside a JSX tag. The braces evaluate the variable and render its text into the heading.
Second, as attributes immediately following the `=` sign. The braces read the variable and assign its value directly to the attribute.

If you put quotes around curly braces, JSX treats the entire attribute as a literal text string. It passes the exact characters rather than evaluating the variable.

```jsx title="Data Binding Contrast"
// Legacy DOM String Concatenation:
const html = '<h1 class="title">' + headline + '</h1>';
// Declarative JSX Expression Window:
<h1 className="title">{headline}</h1>
```

In legacy JavaScript DOM scripting, developers concatenated strings with the plus operator or mutated `element.textContent` by hand. This created noisy boilerplate that invited cross-site scripting vulnerabilities. In React, curly braces let you work with JavaScript right inside your markup. React escapes string values automatically before inserting them into the document.

```html-figure src="figures/05-03-expression-evaluation.html" caption="Fig 5.1: The JSX curly brace portal evaluating dynamic JavaScript expressions versus literal string quotes."
```

> [!WILD]
> **Why do quotes disable JavaScript inside attributes?** Imagine you write `src="{avatar}"` inside your component. You refresh the page and the image breaks. Why? In JSX, quotation marks declare a literal string. The moment you type quotes, you tell the compiler that everything inside is plain text. The compiler does not look inside quotes for code. It passes the literal text string to the browser. The browser attempts to fetch an image whose file name is literally `{avatar}`. If you want the compiler to evaluate the variable `avatar`, you must replace the quotes with **curly braces**. Curly braces remove the quotes and open the window to JavaScript.

### Expressions versus Statements and Double Curlies

In JavaScript grammar, there is a fundamental distinction between an expression and a statement. An expression is code that evaluates to a single value, such as `2 + 2` or a ternary check. A statement is a command that performs an action or controls flow, like `if` or `for`.

The law of JSX curly braces is simple: you can put any valid JavaScript expression between curly braces. You can never put a JavaScript statement inside them. Under the hood, JSX compiles into JavaScript function calls. In JavaScript, you can pass an expression as a function argument. You cannot pass an `if` statement or a `for` loop as a function argument. If you need conditional logic inside JSX, you use an expression like the ternary operator or logical AND.

```jsx title="Expressions and Objects"
// Ternary Expression inside JSX:
<p>{isBreaking ? 'Urgent Alert' : 'Standard News'}</p>
// Double Curlies Object Literal for Style:
<div style={{ backgroundColor: '#0f172a', color: '#ffffff' }}>
  <span>Live Wire</span> // Inline style uses camelCase **PROPERTIES**
</div>
```

In addition to strings, numbers, and booleans, you can pass JavaScript objects inside JSX. Objects in JavaScript are also defined with curly braces. To pass an object inside a JSX attribute, you must wrap the object's curly braces inside JSX's curly braces. Beginners see double curlies and assume React invented a mysterious new syntax. In reality, it is nothing more than an ordinary JavaScript object tucked inside the JSX curly brace window.

> [!WILD]
> **What does the double curly brace syntax really mean?** Imagine you are styling a breaking news banner. You write `style={{ color: "crimson" }}`. What are those double curlies? They look like a new language feature. Look closer. The outer pair is the JSX window: it says to evaluate the JavaScript inside. The inner pair is an ordinary JavaScript **object literal**. You are passing a plain JavaScript object to the `style` prop. There is no special double curly syntax in React. It is simply an **object literal** placed inside the JSX **curly braces**.

### The JSX Evaluation Window

In plain JavaScript, generating dynamic HTML required string concatenation or manual DOM manipulation. Developers had to stitch variable values into HTML strings using templates or the plus operator. This approach was error-prone, hard to read, and vulnerable to security bugs.

React solves dynamic data binding through the **JSX evaluation window**. Instead of building HTML strings, you write JSX markup directly and embed live JavaScript values using curly braces `{ }`. Under the hood, the compiler transforms these curly braces into direct arguments inside React's element creation calls.

The non-negotiable rule of curly braces is that they accept **expressions only**. You can calculate values, format strings, and evaluate conditions on the fly. However, you cannot place JavaScript statements like `if` or `for` inside them. When passing styles or complex configuration, you tuck a standard JavaScript object literal inside the evaluation braces.

To see the JSX evaluation window in action on The National Times, we organize our banner into three files:
1. The **parent container component** `StoryBanner.jsx` coordinates dynamic story props and inline theme styles.
2. The **child component** `AuthorBadge.jsx` binds object properties to image attributes and text nodes.
3. The **child component** `PublishDate.jsx` evaluates a date formatting function expression.

All three components render live data directly from memory without manual string concatenation.

### Step 1: First, we construct the parent container StoryBanner.jsx

We start our implementation at the top: the parent container `StoryBanner.jsx`.

We begin here because the parent defines the layout and dictates the component contracts. It evaluates incoming props using curly braces and coordinates child layout without hardcoded string values:

```jsx title="StoryBanner.jsx" startLine="1" continues="bottom"
import AuthorBadge from './AuthorBadge.jsx';
import PublishDate from './PublishDate.jsx';
export default function StoryBanner({ headline, author, timestamp }) {
  return <article className="story-banner">
    <h1 className="banner-title">{headline}</h1> // Evaluates headline string in **TEXT**
    <AuthorBadge author={author} /> // Passes dynamic author **OBJECT**
    <PublishDate timestamp={timestamp} /> // Passes numeric timestamp **EXPRESSION**
  </article>;
}
```

Notice how the component `StoryBanner` uses curly braces in two distinct ways:

1. **Text interpolation:** It drops the prop `headline` directly between the `<h1>` heading tags to display the title on screen.
2. **Prop assignment:** It uses curly braces inside JSX attributes to hand live data downward. It passes the object prop `author` to the child component `<AuthorBadge />`. It passes the number prop `timestamp` to the child component `<PublishDate />`.

In traditional JavaScript, you would concatenate strings or manually set element properties. Here, the parent component does zero string surgery and never touches the DOM. It simply declares the variables it needs, and React evaluates each expression during the render pass.

### Step 2: Next, we build the author child AuthorBadge.jsx

In step 2, we fulfill the first contract established by the parent: we build `AuthorBadge.jsx`.

This child component receives an `author` object containing `name`, `role`, and `avatarUrl`:

```jsx title="AuthorBadge.jsx"
export default function AuthorBadge({ author }) {
  return (
    <div className="author-badge">
      <img src={author.avatarUrl} alt={author.name} className="author-avatar" />
      <span className="author-name">{author.name}</span> // Renders text from **OBJECT**
    </div>
  );
}
```

The child component `AuthorBadge` receives the prop `author`. It unpacks the property `author.name` inside the `<span>` element for text display. It also unpacks the property `author.avatarUrl` inside the `<img>` tag for the image source.

Why not put quotes around the property names? If you write quotes, the browser receives the literal text string rather than evaluating the object properties. By omitting quotes, the browser receives the evaluated image URL and name directly from JavaScript memory.

### Step 3: Then, we declare the date child PublishDate.jsx

In step 3, we fulfill the second contract established by the parent: we build `PublishDate.jsx`.

This child component receives a numeric `timestamp` and formats it using a JavaScript function call:

```jsx title="PublishDate.jsx"
function formatDate(epochMs) {
  return new Intl.DateTimeFormat('en-US', { dateStyle: 'full' }).format(epochMs);
}
export default function PublishDate({ timestamp }) {
  return (
    <time className="publish-date" dateTime={new Date(timestamp).toISOString()}>
      {formatDate(timestamp)} // Evaluates function call **EXPRESSION**
    </time>
  );
}
```

The child component `PublishDate` receives the numeric prop `timestamp` from its parent. It executes the helper function `formatDate` directly inside curly braces to compute dynamic markup on the fly.

Any valid JavaScript expression that produces a value can run inside curly braces. React invokes `formatDate` during render and projects the formatted string into the `<time>` element.

Similarly, the attribute `dateTime` evaluates a method chain directly inside curly braces to supply a machine-readable ISO date string.

### Step 4: Finally, we seal the banner with dynamic inline styling

In step 4, we examine how `StoryBanner.jsx` completes the component and applies dynamic theme styling:

```jsx title="StoryBanner.jsx" startLine="1" continues="top"
export default function StoryBanner({ headline, author, timestamp, isUrgent }) {
  const bannerTheme = {
    backgroundColor: isUrgent ? '#fef2f2' : '#ffffff', // Evaluates ternary in **OBJECT**
    borderColor: isUrgent ? '#ef4444' : '#e2e8f0' // camelCase CSS property **NAME**
  };
  return (
    <article className="story-banner" style={bannerTheme}>
      <h1 className="banner-title">{headline}</h1> // Dynamic text in **HEADING**
    </article>
  );
}
```

Before returning its markup, the component `StoryBanner` creates a plain JavaScript object named `bannerTheme` to calculate the card's appearance:

1. **Choosing colors with conditional logic:** It checks the prop `isUrgent` using a ternary operator. If the story is breaking news, it picks an alert red card. Otherwise, it falls back to a neutral card.
2. **Applying inline CSS styles:** It hands the object `bannerTheme` directly to the `style` prop. React takes those camelCase property names (`backgroundColor` and `borderColor`) and translates them into browser CSS rules on the `<article>` element.

In traditional JavaScript, changing an element's look required toggling classes or mutating `element.style` property by property. In React, you describe styles as an ordinary JavaScript object, and React applies them during render.

This separation gives you two clean refactoring superpowers:
1. If you change the theme styling tomorrow, you touch zero markup in the child components.
2. If you change how the story data is fetched, you touch zero CSS style code.

### Glossary

- **JSX Expression**: Any valid JavaScript code placed inside JSX curly braces that evaluates to a value.
- **Curly Braces**: The `{ }` syntax in JSX that opens an evaluation window into the JavaScript language.
- **Double Curlies**: The idiom where a JavaScript object literal `{ ... }` is passed inside JSX curly braces `{ { ... } }`.
- **Statement versus Expression**: Expressions evaluate to a value and are legal inside JSX; statements control flow and are forbidden inside JSX.
- **Evaluated Attribute**: An HTML attribute whose value is computed dynamically by a JavaScript expression rather than passed as a static string.
- **React Child Object Trap**: The runtime error triggered when a developer attempts to render a raw JavaScript object directly inside JSX text.

### Summary

**JavaScript Expressions in JSX and Curly Brace Invariants**

In daily production, curly braces are your portal between declarative markup and live JavaScript logic. Understanding what code is allowed inside curly braces prevents syntax crashes and keeps your components readable. Here is your streetwise review.

❒ The Evaluation Window and Expression Rules

1. Use curly braces to evaluate JavaScript values inside text content and attributes.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Inside tag text, `{variable}` projects strings or numbers directly into the document.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) In attributes, `prop={value}` evaluates the identifier without quotes, while `prop="{value}"` passes a literal string.

2. Restrict code inside curly braces strictly to JavaScript expressions.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Any code that evaluates to a value (variables, arithmetic, ternaries, function calls) is valid inside JSX.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Language statements like `if`, `for`, and `let` are syntax errors inside JSX and must live outside the return statement.

➔ NEVER put quotes around curly braces if you intend to evaluate a JavaScript variable.

➔ ALWAYS use expressions like ternaries (`condition ? a : b`) for conditional logic inside JSX.

➔ IF you need to pass an inline style or object prop THEN **use double curlies `style={{ property: value }}` with camelCase CSS names**.

**DO THIS:** Pass dynamic variables with unquoted curly braces and access primitive properties from objects.

```jsx right title="StoryBanner.jsx"
export default function StoryBanner({ headline, author, isLive }) {
  return (
    <article className="story-banner">
      <h2>{headline}</h2>
      <img src={author.avatarUrl} alt={author.name} />
      <span>{isLive ? 'LIVE' : 'RECORDED'}</span>
    </article>
  );
}
```

**DO NOT DO THIS:** Never quote curly braces, render raw objects, or put statements inside JSX.

```jsx wrong title="Invalid Expressions"
export default function InvalidExpressions({ headline, author, isLive }) {
  return (
    <article className="story-banner">
      <h2>"{headline}"</h2>
      <img src="{author.avatarUrl}" alt={author} />
      <span>{if (isLive) { 'LIVE' }}</span>
    </article>
  );
}
```
