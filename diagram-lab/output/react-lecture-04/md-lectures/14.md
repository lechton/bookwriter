### Passing Function References vs Calling Functions

In Lecture 12, we learned that component functions must be pure during render and that side effects must be quarantined inside event handlers. In HTML, you attach handlers using lowercase attributes containing code strings: `<button onclick="handleClick()">`. In React, how do you attach event listeners, and why does writing parentheses inside `onClick` break your app?

In JSX, event handler props use camelCase naming: `onClick`, `onChange`, `onSubmit`, `onKeyDown`. Most importantly, you must pass a **function reference**, not a function call: `<button onClick={handleClick}>`. When you omit the parentheses, you pass the function itself to React, allowing React to call it only when the user clicks. If you write `onClick={handleClick()}`, JavaScript executes the function immediately during the render pass, passing its return value (usually `undefined`) to `onClick`.

When you need to pass arguments to an event handler (such as an article ID), wrap the call inside an inline arrow function: `<button onClick={() => handleBookmark(article.id)}>`. The arrow function creates a fresh function reference that executes only when clicked, passing the exact argument required without firing during render.

```jsx title="Event Handler Reference Patterns"
// WRONG: Fires immediately during render!
<button onClick={handleClick()}>Click Me</button>
// RIGHT: Passes function reference; fires only on click:
<button onClick={handleClick}>Click Me</button>
// RIGHT: Inline arrow function passes specific arguments:
<button onClick={() => handleSelect(story.id)}>Select</button>
```

By passing function references, you ensure that event logic runs strictly in response to user actions, keeping the render phase pure and predictable.

> [!WILD]
> **What happens if an event handler calls a state setter when invoked during render?** Imagine an editor clicks a counter button. But instead of passing a function, they wrote `onClick={setCount(count + 1)}`. When React renders the component, it encounters the `setCount()` call and executes it immediately. Setting state schedules a new render. React re-renders the component, encounters the `setCount()` call again, and executes it again. Within milliseconds, React throws a fatal error: `Too many re-renders. React limits the number of renders to prevent an infinite loop`. Passing function references (`onClick={() => setCount(count + 1)}`) ensures state setters execute only in response to real user clicks.

### SyntheticEvents, Propagation, and Default Actions

In the browser DOM, events bubble upward through parent elements, and native browsers have inconsistencies in event properties across operating systems. How does React standardize event objects, and how do you stop an event from triggering handlers on parent containers?

When React invokes your event handler, it passes a single argument: a **SyntheticEvent** object. This is a cross-browser wrapper around the browser's native event. It has the exact same interface as native DOM events (`e.target`, `e.currentTarget`, `e.key`, `e.clientX`), but works identically across Chrome, Firefox, Safari, and Edge. If you ever need the underlying native browser event, it is accessible via `e.nativeEvent`.

Events in React bubble upward through the component tree just like in the DOM. If a `<button>` inside an `<article>` is clicked, the button's `onClick` fires first, followed by the article's `onClick`. To stop the event from reaching parent elements, call `e.stopPropagation()`. To prevent the browser's default behavior (such as preventing a form submit from reloading the page or preventing a link from navigating), call `e.preventDefault()`.

```jsx title="Event Propagation and Defaults"
function BookmarkButton({ onBookmark }) {
  function handleClick(e) {
    e.stopPropagation(); // Stops bubbling to parent card
    onBookmark(); // Fires parent callback
  }
  return <button onClick={handleClick}>Bookmark</button>;
}
```

Controlling event propagation and default actions gives you precise authority over how user gestures interact with nested UI components.

> [!WILD]
> **Why doesn't returning false stop event bubbling in React?** In inline HTML or legacy jQuery, writing `return false` prevented both default action and event propagation. Why doesn't that work in React? In React, returning `false` from an event handler does absolutely nothing: React completely ignores return values from event handlers. To stop an event from bubbling to parent elements, you must explicitly call `e.stopPropagation()`. To prevent default browser actions like form submissions or page reloads, you must explicitly call `e.preventDefault()`. React adheres strictly to W3C DOM standards rather than old jQuery conventions.

### Step 1: First, we construct the parent container ArticleReader.jsx

The parent container coordinates the reader view. It defines handlers for card clicks, bookmarking, and font resizing, passing callbacks downward as props.

```jsx title="ArticleReader.jsx"
import BookmarkButton from './components/BookmarkButton.jsx';
import FontControl from './components/FontControl.jsx';
export default function ArticleReader() {
  return (
    <article onClick={() => console.log('Card')}>
      <BookmarkButton onBookmark={() => console.log('Saved')} />
      <FontControl onScale={s => console.log('Scale:', s)} />
    </article>
  );
}
```

Look at line 5: `<article onClick={() => console.log('Card clicked')}>`. Look at lines 7 and 8: `<BookmarkButton onBookmark={...} />` and `<FontControl onScale={...} />`. The parent passes callbacks downward as props. If the user clicks anywhere on the article card, the card click fires. But what if the user clicks the bookmark button? We will handle that next in step 2.

### Step 2: Next, we declare the button child BookmarkButton.jsx

Step 1 passed `onBookmark` to `BookmarkButton`. When the reader clicks the bookmark button, it must trigger `onBookmark` without triggering the parent card's click handler.

```jsx title="BookmarkButton.jsx"
export default function BookmarkButton({ onBookmark }) {
  function handleClick(e) {
    e.stopPropagation(); // Stops **BUBBLING** to card
    onBookmark();
  }
  return <button onClick={handleClick}>Bookmark Story</button>;
}
```

Look at line 3: `e.stopPropagation()`. Without this line, clicking the button would trigger `onBookmark` and then bubble up to trigger the card click on the enclosing `<article>`. By calling `e.stopPropagation()`, the event stops right here at the button boundary.

What would happen if `BookmarkButton` wrote `onClick={handleClick()}` with parentheses? The function would execute immediately during render, logging the bookmark message before the page even loaded, and leaving `onClick={undefined}` on the button so future clicks do nothing. By writing `onClick={handleClick}`, we pass the function reference, allowing React to call it only when clicked.

### Step 3: Then, we declare the control child FontControl.jsx

Step 1 passed `onScale` to `FontControl`. The control has two buttons ('down' and 'up') and must pass the direction argument to `onScale`.

```jsx title="FontControl.jsx"
export default function FontControl({ onScale }) {
  return (
    <div className="font-controls">
      <button onClick={() => onScale('down')} type="button">A-</button>
      <button onClick={() => onScale('up')} type="button">A+</button>
    </div>
  );
}
```

Look at lines 4 and 5: `onClick={() => onScale('down')}` and `onClick={() => onScale('up')}`. Each button uses an inline arrow function to pass its specific argument when clicked. The arrow function executes only on click, cleanly forwarding the `'down'` or `'up'` token to the parent's `onScale` callback.

In Steps 1 through 3 we created the interactive component tree. Now we inspect `main.jsx`, which mounts `ArticleReader` to the DOM.

Look at line 6: `root.render(<ArticleReader />)`. React mounts `ArticleReader` to `<div id="root">`. When user interactions occur, React captures the browser events, packages them into SyntheticEvents, executes our handlers, and manages bubbling according to our `stopPropagation` calls.

Now let us examine an architectural detail regarding event performance in React 19.

What is event delegation in React 19? In vanilla JavaScript, adding 500 button listeners consumes memory. React optimizes this automatically using **event delegation**. In React 19, React attaches a single event listener for each event type at the root container (`<div id="root">`). When a click occurs anywhere inside the app, the event bubbles to the root, where React inspects the SyntheticEvent target and dispatches the event to the correct component handler. This makes attaching event handlers in React exceptionally lightweight and fast.

### Glossary
- **Event Handler**: A function defined to execute in response to a user interaction, such as clicking, hovering, or typing.
- **Function Reference**: Passing the name of a function (`handleClick`) rather than invoking it (`handleClick()`), allowing React to call it only when the event occurs.
- **SyntheticEvent**: React's cross-browser wrapper around native DOM event objects, ensuring consistent behavior across all browsers.
- **Event Bubbling**: The process where an event triggered on a nested element propagates upward through its ancestors in the DOM tree.
- **stopPropagation**: A method on the event object that halts further bubbling of the event up the DOM and component tree.
- **preventDefault**: A method on the event object that cancels the browser's default behavior for that event (such as navigating a link or submitting a form).

### Summary

**React 19 Event Handling and SyntheticEvent Invariants**

In daily production, responsive user interfaces depend on accurate, predictable event handling. Mastering function references, argument forwarding, and event propagation ensures clean user interactions without premature execution or infinite render loops. Here is your streetwise review.

❒ Event Handling Invariants

1. Always pass function references, never function calls, to event props.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Pass the function directly: `<button onClick={handleClick}>`.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) To pass arguments, wrap in an arrow function: `<button onClick={() => handleClick(id)}>`.

2. Manage propagation and default behavior explicitly via SyntheticEvent methods.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Call `e.stopPropagation()` to stop bubbling to parent containers.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Call `e.preventDefault()` to cancel default browser actions.

➔ NEVER call a function with parentheses inside an event prop (`onClick={fn()}`) unless that function returns another function.

➔ ALWAYS call `e.stopPropagation()` on interactive elements nested inside clickable parent containers.

➔ IF you need to pass custom arguments to a handler THEN **use an inline arrow function: `onClick={() => handler(arg)}`**.

**DO THIS:** Pass function references or arrow functions, and manage propagation explicitly.

```jsx right title="BookmarkButton.jsx"
// Passes reference and stops bubbling cleanly
export default function BookmarkButton({ onBookmark }) {
  function handleClick(e) {
    e.stopPropagation();
    onBookmark();
  }
  return <button onClick={handleClick}>Bookmark</button>;
}
```

**DO NOT DO THIS:** Never invoke functions with parentheses directly in event props.

```jsx wrong title="Premature Execution Anti-Pattern"
// FAILS: Executes immediately on render, causing infinite loops!
export default function BrokenButton({ onSave }) {
  return (
    <button onClick={onSave()}>
      Save Story
    </button>
  );
}
```

| ---: | :--- | :--- |
