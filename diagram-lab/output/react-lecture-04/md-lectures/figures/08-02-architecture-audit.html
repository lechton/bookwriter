Lessons from the Code
The Dynamic Component Props Challenge

An architectural evaluation of props passing, destructuring, default values, and prop immutability across application layers.

Component Layer Naive Expectation (Legacy Approach) What Happened (React 19 Reality)
1. The Parent Container (EditorialDesk.jsx) Static Markup Monolith Developers hardcode data inside child components or attempt to share mutable global variables, forcing code duplication for every visual variation. Single Source of Truth The parent owns story data and dictates dynamic values downward via explicit JSX attributes, establishing clear contracts for all child components.
2. The Intermediate Presenter (StoryCard.jsx) Direct Prop Mutation Beginners attempt to mutate incoming props like props.author = 'Anonymous' or clone props into mutable local mirrors that drift out of sync. Read-Only Destructuring The child unpacks incoming props cleanly via parameter destructuring and forwards dynamic attributes down to multiple distinct button instances.
3. The Terminal UI Control (ActionButton.jsx) Hardcoded Button Proliferation Creating separate PrimaryButton and SecondaryButton components with hardcoded labels, or attempting to mutate button props on click. Parameterized UI Control A single button component receives label and variant props with a fallback default (variant = 'secondary'), remaining 100% pure and reusable.
4. The Entry Point (main.jsx) Imperative DOM Rewrite Finding DOM nodes manually and rewriting element strings with string interpolation whenever data changes. Declarative Mounting createRoot mounts the top-level container, and React renders the entire component hierarchy purely from props and state without manual DOM queries.
Final Verdict Fragile Coupling Hardcoded component clones, mutable reference drift, and runtime TypeErrors from illegal prop reassignment. Bulletproof Modularity Explicit downward props contracts, frozen read-only snapshots via Object.freeze, and reusable parameterized components.
