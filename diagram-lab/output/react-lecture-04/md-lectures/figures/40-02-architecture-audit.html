Lessons from the Code
The Form State Ownership Challenge

An architectural comparison evaluating per-keystroke React reconciliation against native DOM FormData harvesting.

Component Layer Naive Expectation (Over-Controlled State) What Happened (React 19 Reality)
1. Parent Container (FeedbackPortal) Over-Centralized State Clutter Developers declare multiple useState hooks in the parent and pass values and setters down. Typing in any child input triggers re-renders across the entire portal tree. Lean State-Free Composition The parent maintains reactive state only for live search where typing drives immediate filtering. The correction form is mounted with zero props and zero state hooks.
2. Search Filter Boundary (LiveSearchInput) Uncontrolled Disconnected Input Attempting to use an uncontrolled input for live search requires an extra button or manual DOM polling. The UI cannot filter results synchronously as the user types. Synchronous Controlled State Binding value and onChange provides immediate access to every keystroke. React re-renders the input predictably to filter headlines in real time.
3. Terminal Form Boundary (ArticleCorrectionForm) Per-Keystroke Work Loop Penalty Controlling every field in a multi-line form schedules fiber work loop passes on every letter typed, causing frame drops and typing latency on mobile devices. Native Buffer & FormData Action Standard named inputs leave text in the browser's C++ buffer with zero re-renders. Clicking submit harvests all values into a native FormData object without state.
Final Verdict Fragile Coupling Redundant state hooks, verbose onChange plumbing, and sluggish mobile typing latency. Bulletproof Modularity Lag-free native typing, automatic form resetting, and zero state boilerplate for submit workflows.
