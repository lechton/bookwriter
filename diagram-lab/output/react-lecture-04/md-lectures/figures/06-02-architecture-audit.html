createRoot & Application Mounting Architecture

Evaluating modern two-step root mounting, DOM container governance, and lifecycle cleanup against legacy ReactDOM expectations.

HIERARCHY Component Layer TRADITIONAL MISTAKE Naive Expectation REACT 19 STANDARD Component Reality
main.jsx Entry Point Invokes ReactDOM.render(<App />, node) in a single blocking synchronous call, freezing the main thread and disabling concurrent rendering. Two-step createRoot(node) followed by root.render(<App />) creates an isolated root instance and initializes the concurrent scheduler with priority lanes.
<div id="root"> DOM Mount Point Assumes React appends children to existing HTML inside the container, expecting loading text or SSR markup to remain untouched. createRoot claims exclusive ownership of the container, wiping existing children on initial render to guarantee strict virtual DOM alignment.
LiveTicker.jsx Child Component Removing the container from the DOM via non-React host scripts silently abandons component state, timers, and listeners in memory. Explicit root.unmount() disposes of the component tree, runs cleanup routines, detaches listeners, and eliminates memory leaks.
