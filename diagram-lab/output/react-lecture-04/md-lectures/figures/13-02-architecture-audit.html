Layer 01
Module Tree
Build time / disk
 Import = Render

Believing that importing a file automatically instantiates components or that file layout directly dictates DOM hierarchy.

 Bundler Graph

The module tree tracks file dependencies for bundling, tree shaking, and code splitting, operating entirely before runtime.
Layer 02
Component Tree
Runtime structure
 Flat Component List

Viewing components as an unstructured collection of functions, making it impossible to predict how updates cascade.

 Parent-Child Contracts

The component tree defines clear nested boundaries: data flows downward as props, and state triggers top-down subtree renders.
Layer 03
Render Tree
Active render pass
 Direct DOM Mutation

Assuming React components directly manipulate browser DOM nodes, leading to manual DOM queries and sync bugs.

 Evaluated Elements

The render tree reflects the exact elements evaluated in a given render, which React's reconciler translates into minimal DOM updates.
Layer 04
State Anchoring
Tree position
 Function-Bound State

Assuming state lives inside the component function itself, leading to confusion when swapping components resets inputs.

 Position-Bound State

React ties state strictly to a component's position in the render tree: same position retains state; swapping types resets it.
