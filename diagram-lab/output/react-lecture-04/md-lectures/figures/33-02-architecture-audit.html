Architecture Audit
You Might Not Need an Effect: Render & Handlers vs Redundant Effects

Evaluating render-time derivations, event-handler mutations, and key-driven state resets.

Layer / Invariant
Architectural focus
Naive Conception
Common assumption
Engine Reality
React 19 implementation
Transforming Data
render derivations
 Watching props in useEffect to set state, causing double-render cascades. Compute during render. Calculate values synchronously on the fly; instant and zero extra renders.
User Interactions
event handlers
 Setting a state flag on click and firing mutations inside an Effect. Run in event handler. Event handlers know user intent directly; avoids duplicate requests on remount.
State Resets
key attribute
 Writing an effect to manually reset form fields when an active ID prop changes. Declarative keys. Pass key={id}; React automatically destroys and recreates component with initial state.
Effect Scope
external systems
 Using useEffect as an all-purpose trigger for internal component state logic. External systems only. Restrict useEffect strictly to WebSockets, browser DOM listeners, or native timers.
