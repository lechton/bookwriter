### Four Patterns for Branching JSX

In Lectures 5 and 6, we learned that JSX is syntactic sugar for JavaScript expressions and that curly braces `{}` can evaluate any valid JavaScript expression. However, curly braces cannot contain JavaScript statements like `if`, `for`, or `switch` because statements do not produce a value. Components must constantly show, hide, or swap UI elements depending on props, permissions, or loading states.

The first pattern is the **early return with an `if` statement**. Before returning the main JSX, you can evaluate an `if` condition and return completely different markup or return `null` to render nothing: `if (!isLoggedIn) return <GuestCallout />;`. Returning `null` tells React to commit zero DOM nodes for this component while keeping it mounted in the virtual tree.

The second pattern is the **ternary operator (`? :`)**. Because a ternary is an expression, it can live directly inside JSX curly braces: `{isSubscriber ? <FullStory /> : <Paywall />}`. The third pattern is the **logical AND operator (`&&`)**, used when you want to render an element if a condition is true, and nothing if false: `{unreadCount > 0 && <Badge count={unreadCount} />}`.

```jsx title="Conditional Rendering Patterns"
// Pattern 1: Early return or returning null:
if (isLoading) return <p>Loading dispatch...</p>;
// Pattern 2 & 3: Inline ternary and logical AND:
return (
  <main>
    {isSubscriber ? <FullStory /> : <Paywall />}
    {unreadCount > 0 && <Badge count={unreadCount} />}
  </main>
);
```

By choosing between early returns, inline ternaries, and logical guards, you can express any UI branching logic using standard JavaScript semantics.

> [!WILD]
> **Why does React render 0 on the screen when using &&?** Imagine an editor checking breaking news alerts. The alert count is `0`. Elena writes `{unreadAlerts && <AlertBadge />}`. She expects the badge to disappear. Instead, a bare, unstyled `0` appears in the masthead. Why? In JavaScript, the `&&` operator does not return a boolean: it returns the value of the first falsy operand, or the last operand if all are truthy. When `unreadAlerts` is `0`, JavaScript evaluates `0 && <AlertBadge />` and returns the number `0`. In React, booleans (`false`, `true`), `null`, and `undefined` are ignored during rendering, but numbers like `0` are valid renderable content. React faithfully converts the number `0` to text and renders it to the DOM.

### Suppressing Output with Null and Avoiding the Falsy Trap

In traditional DOM scripting, hiding an element means adding `display: none` or removing the node manually with `parent.removeChild(node)`. In React, you do not manipulate DOM styles or nodes directly to hide content: you control what the component returns during render.

When a component returns `null`, React unmounts its DOM nodes completely (or skips creating them if mounting). The component still exists in React's component tree and retains any internal state hooks, but leaves zero trace in the browser DOM. This makes returning `null` ideal for notification badges, banner alerts, or floating modals that should remain dormant until activated.

To avoid the falsy zero trap with `&&`, follow one iron rule: **never place a raw number on the left side of `&&`**. Instead of `{messages.length && <Badge />}`, write `{messages.length > 0 && <Badge />}` or `{Boolean(messages.length) && <Badge />}`. An explicit comparison produces a boolean `false`, which React safely ignores, preventing stray digits from contaminating your layout.

```jsx title="Falsy Zero Contrast"
// DANGEROUS: Renders literal "0" when count is 0!
<div>{count && <NotificationBadge count={count} />}</div>
// SAFE: Explicit boolean comparison renders nothing:
<div>{count > 0 && <NotificationBadge count={count} />}</div>
// SAFE: Returning null inside the child component:
function NotificationBadge({ count }) {
  if (count <= 0) return null; // Suppresses DOM cleanly
  return <span className="badge">{count}</span>;
}
```

By enforcing boolean comparisons and utilizing `null` returns, your component tree remains pristine without unexpected text leaks.

> [!WILD]
> **When should you use a ternary versus an if statement?** Imagine a component with four different rendering states: loading, error, guest, and subscriber. If you write nested ternaries: `isLoading ? <Loading /> : isError ? <Error /> : isSubscriber ? <Story /> : <Guest />`, the code becomes an unreadable pyramid of question marks and colons. Nested ternaries are notoriously error-prone and hard to debug. When you have mutually exclusive, full-component views, use `if` statements with early returns. Reserve inline ternaries strictly for simple binary choices between two compact elements or attributes (such as choosing between two class names or two button labels).

### Step 1: First, we construct the parent container EditorialGate.jsx

The parent container coordinates reader access. It evaluates `unread` to conditionally render an alert pill, and evaluates `isSubscriber` to branch between `SubscriberArticle` and `GuestCallout`.

```jsx title="EditorialGate.jsx"
import SubscriberArticle from './components/SubscriberArticle.jsx';
import GuestCallout from './components/GuestCallout.jsx';
export default function EditorialGate({ isSubscriber = true, unread = 3 }) {
  return (
    <main className="editorial-gate">
      <header>{unread > 0 && <span>{unread} Unread</span>}</header>
      {isSubscriber ? <SubscriberArticle /> : <GuestCallout />}
    </main>
  );
}
```

Look at line 6: `{unread > 0 && <span>{unread} Unread</span>}`. Notice the comparison `unread > 0`: it evaluates to a clean boolean, avoiding the falsy zero trap. Now look at line 7: `{isSubscriber ? <SubscriberArticle /> : <GuestCallout />}`. We establish the branching contracts: when `isSubscriber` is true, React renders `SubscriberArticle`. We will build `SubscriberArticle` next in step 2.

### Step 2: Next, we declare the subscriber child SubscriberArticle.jsx

Step 1 declared that `SubscriberArticle` renders when `isSubscriber` is true. The child component renders the full investigative story.

```jsx title="SubscriberArticle.jsx"
export default function SubscriberArticle() {
  return (
    <article className="subscriber-story">
      <span className="badge-exclusive">Subscriber Exclusive</span>
      <h2>Investigation: Harbor Transit Overhaul</h2>
      <p>Documents reveal unprecedented infrastructure investments.</p>
    </article>
  );
}
```

Look at lines 1 through 8: `SubscriberArticle` renders full investigative journalism. When `isSubscriber` is true, React evaluates the truthy branch of the ternary operator in `EditorialGate` and mounts this component into the DOM.

What would happen if `EditorialGate` used an `if` statement instead of a ternary for the main view? It could write `if (!isSubscriber) return <GuestCallout />; return <SubscriberArticle />;`. That early return pattern is equally valid when the entire page layout changes. However, when the surrounding page shell (such as the header and footer) must stay visible regardless of subscription status, the inline ternary inside JSX allows the header to remain mounted while swapping only the article body.

### Step 3: Then, we declare the guest fallback GuestCallout.jsx

Step 1 declared that `GuestCallout` renders when `isSubscriber` is false. The component also demonstrates an early return: if `showPrompt` is false, it returns `null` to suppress its DOM footprint completely.

```jsx title="GuestCallout.jsx"
export default function GuestCallout({ showPrompt = true }) {
  if (!showPrompt) return null; // Clean **NULL** return
  return (
    <section className="guest-callout">
      <h2>Read the Full Story</h2>
      <p>Subscribe to The National Times for access.</p>
      <button type="button">Subscribe Now</button>
    </section>
  );
}
```

Look at line 2: `if (!showPrompt) return null;`. When `showPrompt` is false, the component returns `null`, instructing React to commit zero DOM nodes. When `showPrompt` is true, lines 3 through 8 render the subscription prompt.

### Step 4: Finally, we seal the application entry point main.jsx

In Steps 1 through 3 we created the branching components. Now we inspect `main.jsx`, which mounts `EditorialGate` to the DOM.

```jsx title="main.jsx"
import { createRoot } from 'react-dom/client';
import EditorialGate from './EditorialGate.jsx';
const container = document.getElementById('root');
if (!container) throw new Error('Target container #root not found');
const root = createRoot(container); // Acquires container in **MEMORY**
root.render(<EditorialGate />); // Mounts root component into **DOM**
```

Look at line 6: `root.render(<EditorialGate />)`. React mounts `EditorialGate`, evaluates the header guard (rendering the unread pill), evaluates the ternary (mounting `SubscriberArticle`), and commits the resulting DOM into `<div id="root">`. Conditional branching executes purely through standard JavaScript semantics.

Now let us examine a common question regarding multi-case conditional rendering.

Can you use a `switch` statement for multi-case rendering? Inside JSX curly braces, no: `switch` is a statement. But you can use `switch` in two clean ways: either inside a helper function outside the JSX, or before the return statement: `let badge; switch(status) { case 'draft': badge = <DraftBadge />; break; ... } return <div>{badge}</div>;`. Alternatively, you can use a JavaScript object map: `const badges = { draft: <DraftBadge />, published: <PublishedBadge /> }; return <div>{badges[status]}</div>;`.

> [!TIP]
> **To impress the interviewer:** When asked about conditional rendering in React, immediately mention the falsy zero trap (`0 && <Component />`). Explain that JavaScript's `&&` operator short-circuits to the left operand when falsy, and since React treats `0` as a valid renderable number, it renders `0` to the DOM. Demonstrate the two senior fixes: explicit boolean comparison (`count > 0 && <Component />`) or delegating suppression to the child via `if (count <= 0) return null`.

### Glossary
- **Conditional Rendering**: The practice of rendering different JSX markup or components depending on whether certain conditions are truthy or falsy.
- **Early Return**: A pattern where a component function evaluates a condition and returns JSX or `null` immediately, skipping the rest of the function body.
- **Returning Null**: Returning `null` from a component tells React to commit zero DOM nodes for that component while keeping it in the component tree.
- **Ternary Operator**: The JavaScript expression `condition ? exprIfTrue : exprIfFalse`, used for inline binary branching within JSX curly braces.
- **Logical AND Operator**: The JavaScript operator `&&` that returns the right operand if the left operand is truthy, commonly used for inline conditional inclusion.
- **Falsy Zero Trap**: A bug where `{count && <Element />}` renders the literal number `0` when `count` is `0`, because `0` is a renderable number in React.
