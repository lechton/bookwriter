### The React 19 Form Action Revolution

In standard HTML, `<form action="/submit">` specifies a URL endpoint that triggers a browser full-page reload on submit. In previous versions of React, developers hijacked this by binding `onSubmit={e => { e.preventDefault(); ... }}`. Why does React 19 repurpose the native `action` prop to accept a JavaScript function?

In React 19, the `action` prop on `<form>` can be an asynchronous function: `<form action={handleAction}>`. When the user submits, React automatically executes the function with several built-in superpowers: (1) **Automatic preventDefault**: React prevents the browser from reloading the page automatically. (2) **Direct FormData delivery**: React constructs a `FormData` object from the form elements and passes it as the first argument: `async function handleAction(formData)`. (3) **Automatic form reset**: upon successful completion of the action, React automatically resets uncontrolled form fields.

Furthermore, React 19 runs Form Actions inside an internal **Transition**. This means the form submission does not freeze the UI, background updates stay responsive, and accompanying React 19 hooks like `useActionState` and `useFormStatus` can observe the pending state automatically.

```jsx title="Legacy onSubmit vs React 19 Action"
// LEGACY: Manual preventDefault, manual FormData, manual reset:
<form onSubmit={e => {
  e.preventDefault();
  const data = new FormData(e.currentTarget);
  sendData(data);
}}>
// REACT 19: Clean action function receiving formData directly:
<form action={async formData => await sendData(formData)}>
```

By consolidating event prevention, data collection, and form resetting into a single runtime primitive, React 19 dramatically simplifies form development.

> [!WILD]
> **What is formAction on individual buttons?** Can different buttons in the same form trigger different actions? Yes! In standard HTML, buttons support `formaction`. React 19 embraces this: you can pass different action functions to individual buttons: `<button formAction={saveDraft}>Save Draft</button>` and `<button formAction={publishStory}>Publish</button>`. When clicked, the specific button's `formAction` runs with the form's `formData`, allowing a single form to support multiple distinct workflows without complex `if/else` checks.

### Automatic Reset and Error Handling

We know React 19 Form Actions pass `formData` directly. How does React 19 handle form resets and errors when an action runs?

In legacy React, clearing an uncontrolled form after submit required imperatively calling `event.target.reset()`. In React 19, when a Form Action completes successfully, React automatically clears the form's uncontrolled inputs back to their `defaultValue` or empty state. If the action throws an error, React leaves the input values untouched in the DOM so the user does not lose their typed work.

Form Actions work identically whether the function is declared on the client or as a Server Action in frameworks like Next.js. On the client, it is a plain JavaScript function. On the server, React serializes the `formData` and sends it across the network boundary transparently.

```jsx title="Multi-Button Form Actions"
<form action={saveDraft}>
  <input name="title" />
  <button type="submit">Save Draft</button>
  <button formAction={publish}>Publish</button>
</form>
```

This universal execution model makes Form Actions the unifying standard for user submissions across both client-only and server-driven React applications.

> [!WILD]
> **Can you still use onSubmit in React 19?** Is `onSubmit` deprecated in React 19? `onSubmit` is NOT deprecated! It remains fully supported for backward compatibility and for scenarios requiring custom synthetic event manipulation or third-party validation libraries. However, for standard form submissions, `action` is the idiomatic, modern React 19 pattern because it automates `preventDefault`, `FormData` creation, and form resets.

### Step 1: First, we construct the parent container StorySubmission.jsx

The parent container manages the submitted draft title. It passes `setTitle` to `SubmissionForm` and `title` to `SubmissionNotice`.

```jsx title="StorySubmission.jsx"
import { useState } from 'react';
import SubmissionForm from './components/SubmissionForm.jsx';
import SubmissionNotice from './components/SubmissionNotice.jsx';
export default function StorySubmission() {
  const [title, setTitle] = useState(null);
  return (
    <main><SubmissionForm onSend={setTitle} /><SubmissionNotice title={title} /></main>
  );
}
```

Look at line 5: `const [title, setTitle] = useState(null);`. The parent coordinates the post-submission feedback state across the component tree. We will build `SubmissionForm` next in step 2.

### Step 2: Next, we declare the form child SubmissionForm.jsx

Step 1 passed `onSend` to `SubmissionForm`. The child component must declare a form using the React 19 `action` prop.

```jsx title="SubmissionForm.jsx"
export default function SubmissionForm({ onSend }) {
  const handleAction = async formData => {
    onSend(formData.get('title'));
  };
  return (
    <form action={handleAction}>
      <input name="title" placeholder="Story Title" /><button type="submit">Submit Draft</button>
    </form>
  );
}
```

Look at lines 2 through 4: `handleAction` receives `formData` directly as its first argument. Look at line 6: `<form action={handleAction}>`. React handles `e.preventDefault()` automatically and resets the uncontrolled input on completion.

### Step 3: Then, we declare the notice child SubmissionNotice.jsx

Step 1 passed `title` to `SubmissionNotice`. The child component must display the confirmation card once a draft is submitted.

```jsx title="SubmissionNotice.jsx"
export default function SubmissionNotice({ title }) {
  if (!title) return null;
  return (
    <div className="notice-card">
      <p>Draft received: {title}</p>
    </div>
  );
}
```

Look at lines 1 through 8: `SubmissionNotice` renders nothing until `title` is set, and displays the received draft title when the action completes.

What would happen if `SubmissionForm` used `onSubmit` instead of `action` and forgot `e.preventDefault()`? The browser would perform a native HTTP POST request, causing a full page refresh that wipes out all client-side state and resets the application. React 19's `action` prop makes this mistake impossible by preventing reload automatically.

### Step 4: Finally, we seal the application entry point main.jsx

In Steps 1 through 3 we created the action-driven component tree. Now we inspect `main.jsx`, which mounts `StorySubmission` to the DOM.

```jsx title="main.jsx"
import { createRoot } from 'react-dom/client';
import StorySubmission from './StorySubmission.jsx';
const container = document.getElementById('root');
if (!container) throw new Error('Target container #root not found');
const root = createRoot(container);
root.render(<StorySubmission />);
```

Look at line 6: `root.render(<StorySubmission />)`. React mounts the application. When the user submits, React executes `handleAction`, extracts `formData`, updates `title`, and renders the confirmation notice seamlessly.

Now let us examine an architectural consideration when passing non-input contextual data to actions.

Can you pass extra arguments to a form action? You can use JavaScript `.bind`: `<form action={updateStory.bind(null, storyId)}>`. The bound argument `storyId` becomes the first argument passed to `updateStory`, and `formData` becomes the second argument! Alternatively, include a hidden input: `<input type="hidden" name="id" value={storyId} />`. Both techniques pass extra contextual data into actions cleanly.

### Glossary
- **Form Action**: A function passed to `<form action={fn}>` in React 19 that handles submission with automatic `preventDefault` and `FormData` delivery.
- **formAction Prop**: An attribute on `<button>` or `<input type="submit">` that overrides the form's default action for that specific button.
- **Automatic Form Reset**: React 19's built-in behavior of clearing uncontrolled form fields back to defaults when an action completes successfully.
- **Action Transition**: The background execution context in React 19 where actions run, keeping the interface responsive.
- **Direct FormData**: The `FormData` instance automatically constructed and passed to the action function by React.
- **Legacy onSubmit**: The previous React pattern requiring manual `e.preventDefault()`, `new FormData()`, and `form.reset()`.

### Summary

**React 19 Form Action Invariants**

In daily production, React 19 Form Actions dramatically reduce boilerplate and streamline form handling. Allowing `<form>` to accept an asynchronous function eliminates manual event prevention and simplifies data extraction. Here is your streetwise review.

❒ Form Action Invariants

1. React 19 `<form action={fn}>` accepts an asynchronous function.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) React automatically calls `e.preventDefault()` behind the scenes.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) The action function receives `formData` directly as its first argument.

2. Uncontrolled form fields are automatically reset on success.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) If the action succeeds, React resets the form back to initial defaults.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) If the action throws an error, React preserves user input in the DOM.

3. Use `formAction` on buttons for multi-action forms.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Individual buttons can dispatch distinct action functions.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) The button's `formAction` overrides the form's default `action`.

➔ NEVER write manual `e.preventDefault()` when using React 19 Form Actions.

➔ ALWAYS ensure input fields have `name` attributes so they appear in `formData`.

➔ IF an action requires extra non-input data THEN **use `.bind(null, extraArg)` or hidden inputs**.

**DO THIS:** Use React 19 form actions to handle form submission cleanly.

```jsx right title="SubmissionForm.jsx"
// Clean React 19 form action receiving formData directly
export default function SubmissionForm({ onSend }) {
  async function handleAction(formData) {
    onSend(formData.get('title'));
  }
  return (
    <form action={handleAction}>
      <input name="title" />
      <button type="submit">Send</button>
    </form>
  );
}
```

**DO NOT DO THIS:** Never write verbose legacy onSubmit boilerplate in React 19.

```jsx wrong title="Legacy onSubmit Anti-Pattern"
// FAILS: Fragile manual boilerplate for submit, preventDefault, and reset!
export default function BrokenForm({ onSend }) {
  function handleSubmit(e) {
    e.preventDefault();
    const data = new FormData(e.currentTarget);
    onSend(data.get('title'));
    e.currentTarget.reset();
  }
  return <form onSubmit={handleSubmit}><input name="title" /></form>;
}
```
