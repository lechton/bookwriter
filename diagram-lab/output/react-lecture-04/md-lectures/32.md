### Render vs Effects: The Synchronization Contract

React component functions must remain pure: given the same props and state, they must calculate JSX without modifying the DOM, initiating network requests, or mutating external variables. When a component needs to interact with the world outside of React: like a WebSocket, browser window listener, or third-party chart: we call this an **external system**. Why does placing external system connections directly in the component function body break React applications?

The component body runs during React's **render phase**. If you initiate side effects here, they execute before the DOM even updates, and they repeat on every single re-render! React provides the **`useEffect` hook** to run side effects safely in the **commit phase**, *after* the DOM has been painted.

An Effect is not a lifecycle hook for "on mount" or "on unmount"; it is a **synchronization mechanism**. Its job is to keep your component synchronized with an external system for as long as the component remains displayed with its current props and state.

```jsx title="Side Effect in Render vs useEffect"
// BROKEN: Side effect in render leaks zombie connections!
function BrokenTicker({ room }) {
  const s = createSocket(room); s.connect(); return <div>{room}</div>;
}
// RIGHT: Synchronize with symmetrical cleanup:
function GoodTicker({ room }) {
  useEffect(() => { const s = createSocket(room); s.connect(); return () => s.disconnect(); }, [room]);
}
```

What does the dependency array actually control? An Effect's behavior depends entirely on its dependency array:
1. `[room]`: Runs on mount and re-runs whenever `room` changes (running cleanup on the old room first).
2. `[]`: Runs once on mount; cleans up only when the component unmounts.
3. No array: Runs on **every single render** (rarely desired). Key terms: **dependency array contract**, **empty dependencies**, **per-render execution**, **reactive dependency**.

### The Symmetrical Cleanup Rule and StrictMode

We know `useEffect` connects to an external system. How does React ensure external connections are closed when dependencies change or components unmount?

To disconnect an external system, an Effect must return a **cleanup function**. React invokes this cleanup function at two critical moments:
1. Before re-running the effect when a dependency value changes.
2. When the component unmounts from the screen.
Every setup action must have a **symmetrical cleanup counterpart**: `addEventListener` must pair with `removeEventListener`, `subscribe` with `unsubscribe`, `connect` with `disconnect`, and `setInterval` with `clearInterval`.

In development, React's `<StrictMode>` intentionally **mounts, unmounts, and remounts every component** (Setup -> Cleanup -> Setup). This stress-test verifies that your cleanup function properly resets all state and tears down connections. If you notice double subscriptions, audio playing twice, or memory leaks in development, your cleanup function is missing or incomplete!

```jsx title="Symmetrical Cleanup Pattern"
useEffect(() => {
  function handleResize() { setWidth(window.innerWidth); }
  window.addEventListener('resize', handleResize);
  return () => window.removeEventListener('resize', handleResize);
}, []);
```

Can you make the useEffect callback function async? An `async` function implicitly returns a `Promise`. But React requires an Effect callback to return either **nothing** or a **cleanup function**! If you return a Promise, React cannot execute it as a cleanup function. To run async logic, declare an async function inside the effect and call it: `useEffect(() => { async function load() { ... } load(); return () => cleanup(); }, [])`. Key terms: **async effect restriction**, **promise return collision**, **inner async declaration**, **cleanup return signature**.

### Step 1: First, we construct the container WireStreamer.jsx

The container manages `channel` state and synchronizes with the external feed via `useEffect`. The container must demonstrate symmetrical setup and cleanup.

```jsx title="WireStreamer.jsx"
import { useState, useEffect } from 'react';
import StreamControls from './components/StreamControls.jsx';
import FeedTicker from './components/FeedTicker.jsx';
export default function WireStreamer() {
  const [channel, setChannel] = useState('breaking');
  const [msg, setMsg] = useState('Init');
  useEffect(() => { setMsg(`Connected: ${channel}`); return () => setMsg(`Disconnected: ${channel}`); }, [channel]);
  return <div className="streamer-box"><StreamControls active={channel} onSelect={setChannel} /><FeedTicker msg={msg} /></div>;
}
```

Step 1 establishes effect synchronization: Look at line 7: `useEffect` sets up the connection when `channel` mounts or updates, and returns a cleanup function disconnecting the old channel before the next runs. We will build `StreamControls` next in step 2.

### Step 2: Next, we declare the controls child StreamControls.jsx

Step 1 passed `active` and `onSelect` to `StreamControls`. The child component must render buttons to switch channels.

```jsx title="StreamControls.jsx"
export default function StreamControls({ active, onSelect }) {
  return (
    <nav className="stream-controls">
      <button disabled={active === 'breaking'} onClick={() => onSelect('breaking')}>Breaking</button>
      <button disabled={active === 'metro'} onClick={() => onSelect('metro')}>Metro</button>
    </nav>
  );
}
```

Step 2 fulfills the channel switching role: Look at lines 4 and 5: clicking either button updates `channel` in the parent, triggering the effect's cleanup for the old channel and setup for the new one.

### Step 3: Then, we declare the display child FeedTicker.jsx

`FeedTicker` receives `msg` from `WireStreamer`. The child component must display the current connection status.

```jsx title="FeedTicker.jsx"
export default function FeedTicker({ msg }) {
  return (
    <div className="feed-ticker">
      <span className="live-dot" />
      <p>Status: <strong>{msg}</strong></p>
    </div>
  );
}
```

Step 3 completes the display component: Look at line 5: `FeedTicker` renders the active connection status verified by the Effect.

What would happen if we omitted the cleanup function from `useEffect`? If we omitted the cleanup function, every channel switch would leave the previous channel connection open in the background. The component would accumulate multiple simultaneous socket feeds, receiving duplicate updates and exhausting network sockets.

### Step 4: Finally, we seal the application entry point main.jsx

In Steps 1 through 3 we created the effect synchronization tree. Now we inspect `main.jsx`, which mounts `WireStreamer` to the DOM. The entry point must initialize the React root and render the streamer.

```jsx title="main.jsx"
import { createRoot } from 'react-dom/client';
import WireStreamer from './WireStreamer.jsx';
const container = document.getElementById('root');
if (!container) throw new Error('Target container #root not found');
const root = createRoot(container);
root.render(<WireStreamer />);
```

Step 4 seals the architecture: Look at line 6: `root.render(<WireStreamer />)`. React mounts the application. `useEffect` initiates external synchronization cleanly, managing connection lifecycles without leaking memory.

Why should you avoid using useEffect for data fetching in React 19? In older React apps developers used `useEffect` to fetch data on mount. In React 19, fetching in effects is discouraged because it creates network waterfalls, doesn't preload data on the server, and requires complex race-condition boilerplate. Modern React 19 uses Server Components, React Suspense, the `use()` hook with Promises, or libraries like TanStack Query. Key terms: **network waterfalls**, **race-condition boilerplate**, **server component prefetching**, **modern data fetching**.

### Where you will meet this

- WebSocket and SSE connections: opening real-time subscriptions and closing them on unmount.
- Window event listeners: tracking scroll position, window resize, or global keyboard shortcuts.
- Third-party imperative libraries: initializing Leaflet maps, D3 charts, or video players on a canvas.
- Timers and intervals: running periodic polls with `setInterval` and clearing them on unmount.

### Glossary

- **useEffect**: A React hook that synchronizes a component with an external system outside of React.
- **External System**: Any piece of software not controlled by React: DOM APIs, browser event listeners, WebSockets, or third-party widgets.
- **Cleanup Function**: The function returned by an Effect callback, executed before re-running the effect and on unmount.
- **Symmetrical Cleanup**: The principle that every external resource initialized in setup must be explicitly released in cleanup.
- **Dependency Array**: The array of reactive values passed as the second argument to `useEffect` that dictates when the effect re-runs.
- **StrictMode Double-Mount**: React's development mechanism that mounts, unmounts, and remounts components to verify cleanup integrity.

### Summary

**React 19 useEffect Invariants**

In daily production, `useEffect` bridges React components to external browser APIs and services, guaranteeing leak-free synchronization through symmetrical cleanups. Here is your streetwise review.

❒ useEffect Invariants

1. Effects synchronize with external systems.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Run side effects in `useEffect`, never during the pure render phase.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Effects run *after* commit and paint, keeping user interactions smooth.

2. Always provide a symmetrical cleanup function.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Return a cleanup function that tears down every resource setup created.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Cleanup runs before the next effect execution and when the component unmounts.

3. List all reactive dependencies accurately.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Include every prop, state variable, or function read inside the effect.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Passing `[]` means the effect synchronizes only once on mount.

➔ NEVER perform side effects (socket connections, DOM mutations) directly in the component body.

➔ ALWAYS return a symmetrical cleanup function from any effect that creates subscriptions or timers.

➔ IF you need async operations in an effect THEN **declare and call an async function inside**.

**DO THIS:** Synchronize with external systems and return symmetrical cleanup.

```jsx right title="WireStreamer.jsx"
useEffect(() => {
  const socket = createSocket(channel);
  socket.connect();
  return () => {
    socket.disconnect();
  };
}, [channel]);
```

**DO NOT DO THIS:** Never perform side effects in the component body or omit cleanup.

```jsx wrong title="Zombie-Socket Anti-Pattern"
export default function BrokenStreamer({ channel }) {
  const socket = createSocket(channel);
  socket.connect();
  return <div>Live: {channel}</div>;
}
```
