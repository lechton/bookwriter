### Render vs Effects: The Synchronization Contract
- [p] ◇ {preknowledge:} React component functions must remain pure: given the same props and state, they must calculate JSX without modifying the DOM, initiating network requests, or mutating external variables. When a component needs to interact with the world outside of React—like a WebSocket, browser window listener, or third-party chart—we call this an **external system**. {problem:} Why does placing external system connections directly in the component function body break React applications? ◼ Pedagogical qualification: Contrast pure rendering with side-effect execution; terms introduced: **external system**, **pure render contract**, **side effect**.
- [p] ★ {preknowledge:} The component body runs during React's **render phase**. If you initiate side effects here, they execute before the DOM even updates, and they repeat on every single re-render! React provides the **`useEffect` hook** to run side effects safely in the **commit phase**, *after* the DOM has been painted. ◼ Pedagogical qualification: Differentiate render phase from commit phase execution; terms introduced: **useEffect hook**, **commit phase**, **post-paint execution**.
- [p] ★ {preknowledge:} An Effect is not a lifecycle hook for "on mount" or "on unmount"; it is a **synchronization mechanism**. Its job is to keep your component synchronized with an external system for as long as the component remains displayed with its current props and state. ◼ Pedagogical qualification: Refocus Effect mental model on ongoing synchronization; terms introduced: **synchronization mechanism**, **external system alignment**, **state-effect parity**.
- [code] Side effect in render vs useEffect:
```jsx title="Side Effect in Render vs useEffect"
// BROKEN: Re-subscribes on every render, leaking zombie sockets!
function BrokenTicker({ room }) {
  const socket = createConnection(room); // BUG: Side effect in render!
  socket.connect();
  return <div>Connected to {room}</div>;
}
// RIGHT: Synchronize via useEffect with symmetrical cleanup:
function GoodTicker({ room }) {
  useEffect(() => {
    const socket = createConnection(room);
    socket.connect();
    return () => socket.disconnect(); // Symmetrical cleanup!
  }, [room]);
  return <div>Connected to {room}</div>;
}
```
- [grounding] Leading Question: What does the dependency array actually control?
  Confusion Point: Does omitting the dependency array make the effect run once?
  Scene & Repetition: No! An Effect's behavior depends entirely on its dependency array:
  1. `[room]`: Runs on mount and re-runs whenever `room` changes (running cleanup on the old room first).
  2. `[]`: Runs once on mount; cleans up only when the component unmounts.
  3. No array: Runs on **every single render** (rarely desired).
  Key Terms (Bold): `**dependency array contract**`, `**empty dependencies**`, `**per-render execution**`, `**reactive dependency**`.
  Resolution: The dependency array dictates when the effect re-synchronizes; include every reactive value read inside the effect.

### The Symmetrical Cleanup Rule and StrictMode
- [p] ◇ {preknowledge:} We know `useEffect` connects to an external system. {problem:} How does React ensure external connections are closed when dependencies change or components unmount? ◼ Pedagogical qualification: Teach cleanup function mechanics and symmetrical teardown; terms introduced: **cleanup function**, **symmetrical cleanup**, **unmount teardown**.
- [p] ★ {preknowledge:} To disconnect an external system, an Effect must return a **cleanup function**. React invokes this cleanup function at two critical moments:
  1. Before re-running the effect when a dependency value changes.
  2. When the component unmounts from the screen.
  Every setup action must have a **symmetrical cleanup counterpart**: `addEventListener` must pair with `removeEventListener`, `subscribe` with `unsubscribe`, `connect` with `disconnect`, and `setInterval` with `clearInterval`. ◼ Pedagogical qualification: Formulate the Symmetrical Cleanup Law; terms introduced: **symmetrical cleanup rule**, **setup-cleanup pairing**, **lifecycle symmetry**.
- [p] ★ {preknowledge:} In development, React's `<StrictMode>` intentionally **mounts, unmounts, and remounts every component** (Setup -> Cleanup -> Setup). This stress-test verifies that your cleanup function properly resets all state and tears down connections. If you notice double subscriptions, audio playing twice, or memory leaks in development, your cleanup function is missing or incomplete! ◼ Pedagogical qualification: Explain StrictMode double-invocation rationale; terms introduced: **StrictMode audit**, **double-mount stress test**, **resilience verification**.
- [code] Symmetrical cleanup patterns:
```jsx title="Symmetrical Cleanup Pattern"
useEffect(() => {
  function handleResize() { setWidth(window.innerWidth); }
  window.addEventListener('resize', handleResize);
  // Symmetrical cleanup removes the exact same listener:
  return () => window.removeEventListener('resize', handleResize);
}, []);
```
- [grounding] Leading Question: Can you make the useEffect callback function async?
  Confusion Point: Why does `useEffect(async () => { ... })` trigger a compiler error?
  Scene & Repetition: An `async` function implicitly returns a `Promise`. But React requires an Effect callback to return either **nothing** or a **cleanup function**! If you return a Promise, React cannot execute it as a cleanup function. To run async logic, declare an async function inside the effect and call it: `useEffect(() => { async function load() { ... } load(); return () => cleanup(); }, [])`.
  Key Terms (Bold): `**async effect restriction**`, `**promise return collision**`, `**inner async declaration**`, `**cleanup return signature**`.
  Resolution: Never make the effect callback itself async; declare and invoke an async function inside the effect body.

### Step 1: First, we construct the container WireStreamer.jsx
- [p] ★ {preknowledge:} The container manages `channel` state and synchronizes with the external feed via `useEffect`. {problem:} The container must demonstrate symmetrical setup and cleanup. ◼ Pedagogical qualification: Construct container demonstrating useEffect with cleanup.
- [code] Container WireStreamer.jsx:
```jsx title="WireStreamer.jsx"
import { useState, useEffect } from 'react';
import StreamControls from './components/StreamControls.jsx';
import FeedTicker from './components/FeedTicker.jsx';
export default function WireStreamer() {
  const [channel, setChannel] = useState('breaking');
  const [msg, setMsg] = useState('Init');
  useEffect(() => {
    setMsg(`Connected: ${channel}`);
    return () => setMsg(`Disconnected: ${channel}`);
  }, [channel]);
  return <div className="streamer-box"><StreamControls active={channel} onSelect={setChannel} /><FeedTicker msg={msg} /></div>;
}
```
- [p] ★ Step 1 establishes effect synchronization: Look at lines 8 through 11: `useEffect` sets up the connection when `channel` mounts or updates, and returns a cleanup function disconnecting the old channel before the next runs. We will build `StreamControls` next in step 2. ◼ Pedagogical qualification: Deconstruct useEffect setup and cleanup execution.

- [grounding] Leading Question: Why should you avoid using useEffect for data fetching in React 19?
  Confusion Point: Was `useEffect` the standard way to fetch data in earlier React versions?
  Scene & Repetition: Yes, in older React apps developers used `useEffect` to fetch data on mount. ### Where you will meet this
- WebSocket and SSE connections: opening real-time subscriptions and closing them on unmount.
- Window event listeners: tracking scroll position, window resize, or global keyboard shortcuts.

### Glossary
- **useEffect**: A React hook that synchronizes a component with an external system outside of React.
- **External System**: Any piece of software not controlled by React: DOM APIs, browser event listeners, WebSockets, or third-party widgets.
- **Cleanup Function**: The function returned by an Effect callback, executed before re-running the effect and on unmount.
- **Symmetrical Cleanup**: The principle that every external resource initialized in setup must be explicitly released in cleanup.
- **Dependency Array**: The array of reactive values passed as the second argument to `useEffect` that dictates when the effect re-runs.
- **StrictMode Double-Mount**: React's development mechanism that mounts, unmounts, and remounts components to verify cleanup integrity.

### Summary

**React 19 useEffect Invariants**

In daily production, `useEffect` bridges React components to external browser APIs and services, guaranteeing leak-free synchronization through symmetrical cleanups. Here is your streetwise review.

❒ useEffect Invariants

1. Effects synchronize with external systems.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Run side effects in `useEffect`, never during the pure render phase.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Effects run *after* commit and paint, keeping user interactions smooth.

2. Always provide a symmetrical cleanup function.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Return a cleanup function that tears down every resource setup created.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Cleanup runs before the next effect execution and when the component unmounts.

3. List all reactive dependencies accurately.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Include every prop, state variable, or function read inside the effect.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Passing `[]` means the effect synchronizes only once on mount.

➔ NEVER perform side effects (socket connections, DOM mutations) directly in the component body.

➔ ALWAYS return a symmetrical cleanup function from any effect that creates subscriptions or timers.

➔ IF you need async operations in an effect THEN **declare and call an async function inside**.

**DO THIS:** Synchronize with external systems and return symmetrical cleanup.

```jsx right title="WireStreamer.jsx"
// Clean effect synchronization with matching cleanup
useEffect(() => {
  const socket = createSocket(channel);
  socket.connect();
  return () => {
    socket.disconnect();
  };
}, [channel]);
```

**DO NOT DO THIS:** Never perform side effects in the component body or omit cleanup.

```jsx wrong title="Zombie-Socket Anti-Pattern"
// FAILS: Side effect in body creates duplicate connections on every render!
export default function BrokenStreamer({ channel }) {
  const socket = createSocket(channel);
  socket.connect(); // BUG: Leaks socket on every render!
  return <div>Live: {channel}</div>;
}
```
