### Passing Function References vs Calling Functions
- [p] ◇ {preknowledge:} In Lecture 12, we learned that component functions must be pure during render and that side effects must be quarantined inside event handlers. In HTML, you attach handlers using lowercase attributes containing code strings: `<button onclick="handleClick()">`. {problem:} In React, how do you attach event listeners, and why does writing parentheses inside `onClick` break your app? ◼ Pedagogical qualification: Contrast HTML string event handlers with React JSX function references; terms introduced: **event handler**, **function reference**, **premature execution**.
- [p] ★ {preknowledge:} In JSX, event handler props use camelCase naming: `onClick`, `onChange`, `onSubmit`, `onKeyDown`. Most importantly, you must pass a **function reference**, not a function call: `<button onClick={handleClick}>`. When you omit the parentheses, you pass the function itself to React, allowing React to call it only when the user clicks. If you write `onClick={handleClick()}`, JavaScript executes the function immediately during the render pass, passing its return value (usually `undefined`) to `onClick`. ◼ Pedagogical qualification: Deconstruct the syntax and timing difference between passing a reference and calling a function; terms introduced: **camelCase event props**, **function reference**, **callback invocation**.
- [p] ★ {preknowledge:} When you need to pass arguments to an event handler (such as an article ID), wrap the call inside an inline arrow function: `<button onClick={() => handleBookmark(article.id)}>`. The arrow function creates a fresh function reference that executes only when clicked, passing the exact argument required without firing during render. ◼ Pedagogical qualification: Explain inline arrow functions for argument passing; terms introduced: **inline arrow function**, **argument forwarding**.
- [code] Event handler reference patterns:
```jsx title="Event Handler Reference Patterns"
// WRONG: Fires immediately during render!
<button onClick={handleClick()}>Click Me</button>
// RIGHT: Passes function reference; fires only on click:
<button onClick={handleClick}>Click Me</button>
// RIGHT: Inline arrow function passes specific arguments:
<button onClick={() => handleSelect(story.id)}>Select</button>
```
- [grounding] Leading Question: What happens if an event handler calls a state setter when invoked during render?
  Confusion Point: Why does writing `onClick={setCount(count + 1)}` cause an infinite loop crash?
  Scene & Repetition: Imagine an editor clicks a counter button. But instead of passing a function, they wrote `onClick={setCount(count + 1)}`. When React renders the component, it encounters the `setCount()` call and executes it immediately. Setting state schedules a new render. React re-renders the component, encounters the `setCount()` call again, and executes it again. Within milliseconds, React throws a fatal error: `Too many re-renders. React limits the number of renders to prevent an infinite loop`. Passing function references (`onClick={() => setCount(count + 1)}`) ensures state setters execute only in response to real user clicks.
  Key Terms (Bold): `**infinite render loop**`, `**state setter**`, `**function reference**`, `**Too many re-renders**`.
  Resolution: Always pass function references or inline arrow functions to prevent immediate execution and fatal infinite render loops.

### SyntheticEvents, Propagation, and Default Actions
- [p] ◇ {preknowledge:} In the browser DOM, events bubble upward through parent elements, and native browsers have inconsistencies in event properties across operating systems. {problem:} How does React standardize event objects, and how do you stop an event from triggering handlers on parent containers? ◼ Pedagogical qualification: Introduce cross-browser event normalization and bubbling; terms introduced: **SyntheticEvent**, **event bubbling**, **event propagation**.
- [p] ★ {preknowledge:} When React invokes your event handler, it passes a single argument: a **SyntheticEvent** object. This is a cross-browser wrapper around the browser's native event. It has the exact same interface as native DOM events (`e.target`, `e.currentTarget`, `e.key`, `e.clientX`), but works identically across Chrome, Firefox, Safari, and Edge. If you ever need the underlying native browser event, it is accessible via `e.nativeEvent`. ◼ Pedagogical qualification: Explain the SyntheticEvent wrapper and cross-browser consistency; terms introduced: **SyntheticEvent**, **cross-browser wrapper**, **nativeEvent**.
- [p] ★ {preknowledge:} Events in React bubble upward through the component tree just like in the DOM. If a `<button>` inside an `<article>` is clicked, the button's `onClick` fires first, followed by the article's `onClick`. To stop the event from reaching parent elements, call `e.stopPropagation()`. To prevent the browser's default behavior (such as preventing a form submit from reloading the page or preventing a link from navigating), call `e.preventDefault()`. ◼ Pedagogical qualification: Detail `e.stopPropagation()` and `e.preventDefault()`; terms introduced: **stopPropagation**, **preventDefault**, **bubbling**.
- [code] SyntheticEvent propagation and default prevention:
```jsx title="Event Propagation and Defaults"
function BookmarkButton({ onBookmark }) {
  function handleClick(e) {
    e.stopPropagation(); // Stops bubbling to parent card
    onBookmark(); // Fires parent callback
  }
  return <button onClick={handleClick}>Bookmark</button>;
}
```
- [grounding] Leading Question: Why doesn't returning false stop event bubbling in React?
  Confusion Point: In inline HTML or legacy jQuery, writing `return false` prevented both default action and event propagation. Why doesn't that work in React?
  Scene & Repetition: In React, returning `false` from an event handler does absolutely nothing: React completely ignores return values from event handlers. To stop an event from bubbling to parent elements, you must explicitly call `e.stopPropagation()`. To prevent default browser actions like form submissions or page reloads, you must explicitly call `e.preventDefault()`. React adheres strictly to W3C DOM standards rather than old jQuery conventions.
  Key Terms (Bold): `**e.stopPropagation()**`, `**e.preventDefault()**`, `**SyntheticEvent**`, `**W3C DOM standards**`.
  Resolution: React ignores return values from event handlers; explicitly invoke `e.stopPropagation()` and `e.preventDefault()` to control event behavior.

### Step 2: Next, we declare the button child BookmarkButton.jsx
- [p] ★ {preknowledge:} Step 1 passed `onBookmark` to `BookmarkButton`. {problem:} When the reader clicks the bookmark button, it must trigger `onBookmark` without triggering the parent card's `handleCardClick`. ◼ Pedagogical qualification: Build button component stopping event bubbling with `e.stopPropagation()`.
- [code] Button child BookmarkButton.jsx:
```jsx title="BookmarkButton.jsx"
export default function BookmarkButton({ onBookmark }) {
  function handleClick(e) {
    e.stopPropagation(); // Stops **BUBBLING** to article card
    onBookmark(); // Fires parent callback
  }
  return (
    <button className="btn-bookmark" onClick={handleClick} type="button">
      Bookmark Story
    </button>
  );
}
```
- [p] ★ Step 2 fulfills the propagation contract: Look at line 3: `e.stopPropagation()`. Without this line, clicking the button would trigger `onBookmark` and then bubble up to trigger `handleCardClick` on the enclosing `<article>`. By calling `e.stopPropagation()`, the event stops right here at the button boundary. ◼ Pedagogical qualification: Deconstruct `e.stopPropagation()` and callback invocation.
- [p] What would happen if `BookmarkButton` wrote `onClick={handleClick()}` with parentheses? The function would execute immediately during render, logging the bookmark message before the page even loaded, and leaving `onClick={undefined}` on the button so future clicks do nothing. By writing `onClick={handleClick}`, we pass the function reference, allowing React to call it only when clicked. ◼ Pedagogical qualification: Apply Negative Counterfactual Law to event handler invocation.

### Glossary
- **Event Handler**: A function defined to execute in response to a user interaction, such as clicking, hovering, or typing.
- **Function Reference**: Passing the name of a function (`handleClick`) rather than invoking it (`handleClick()`), allowing React to call it only when the event occurs.
- **SyntheticEvent**: React's cross-browser wrapper around native DOM event objects, ensuring consistent behavior across all browsers.
- **Event Bubbling**: The process where an event triggered on a nested element propagates upward through its ancestors in the DOM tree.
- **stopPropagation**: A method on the event object that halts further bubbling of the event up the DOM and component tree.
- **preventDefault**: A method on the event object that cancels the browser's default behavior for that event (such as navigating a link or submitting a form).

### Summary

**React 19 Event Handling and SyntheticEvent Invariants**

In daily production, responsive user interfaces depend on accurate, predictable event handling. Mastering function references, argument forwarding, and event propagation ensures clean user interactions without premature execution or infinite render loops. Here is your streetwise review.

❒ Event Handling Invariants

1. Always pass function references, never function calls, to event props.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Pass the function directly: `<button onClick={handleClick}>`.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) To pass arguments, wrap in an arrow function: `<button onClick={() => handleClick(id)}>`.

2. Manage propagation and default behavior explicitly via SyntheticEvent methods.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Call `e.stopPropagation()` to stop bubbling to parent containers.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Call `e.preventDefault()` to cancel default browser actions.

➔ NEVER call a function with parentheses inside an event prop (`onClick={fn()}`) unless that function returns another function.

➔ ALWAYS call `e.stopPropagation()` on interactive elements nested inside clickable parent containers.

➔ IF you need to pass custom arguments to a handler THEN **use an inline arrow function: `onClick={() => handler(arg)}`**.

**DO THIS:** Pass function references or arrow functions, and manage propagation explicitly.

```jsx right title="BookmarkButton.jsx"
// Passes reference and stops bubbling cleanly
export default function BookmarkButton({ onBookmark }) {
  function handleClick(e) {
    e.stopPropagation();
    onBookmark();
  }
  return <button onClick={handleClick}>Bookmark</button>;
}
```

**DO NOT DO THIS:** Never invoke functions with parentheses directly in event props.

```jsx wrong title="Premature Execution Anti-Pattern"
// FAILS: Executes immediately on render, causing infinite loops!
export default function BrokenButton({ onSave }) {
  return (
    <button onClick={onSave()}>
      Save Story
    </button>
  );
}
```

| | **FUNCTION REFERENCE**<br>(`onClick={fn}`) | **FUNCTION CALL**<br>(`onClick={fn()}`) |
| ---: | :--- | :--- |
| **Execution timing** | Runs only when user triggers<br>the event | Runs immediately during the<br>render phase |
| **State setter safety** | Completely safe: updates state<br>after render commits | Causes fatal "Too many<br>re-renders" crash |
| **Event object access** | Automatically receives the<br>SyntheticEvent object | Receives whatever the function<br>returns (often `undefined`) |
| **Argument passing** | Wrap in arrow function:<br>`() => fn(arg)` | Passes return value of `fn(arg)`<br>to the handler prop |
| **Propagation control** | Handler can inspect and call<br>`e.stopPropagation()` | Cannot access event to call<br>propagation methods |
