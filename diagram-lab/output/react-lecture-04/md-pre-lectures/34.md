### Custom Hooks: Sharing Logic, Not State
- [p] ◇ {preknowledge:} Components frequently require identical stateful behaviors: listening to browser window events, managing input form state, or polling a server. In plain JavaScript, duplicate logic is extracted into helper functions. {problem:} Why can't we extract stateful logic into a standard JavaScript utility function? ◼ Pedagogical qualification: Explain why standard utility functions cannot call React hooks; terms introduced: **custom hook**, **stateful logic extraction**, **hook rules**.
- [p] ★ {preknowledge:} React hooks (`useState`, `useEffect`, `use`) can only be called from React component functions or from other hooks. To extract stateful logic, you write a **custom hook**: a JavaScript function whose name starts with **`use`** (e.g. `useOnlineStatus`). Because it follows the `use` prefix convention, React and ESLint enforce the Rules of Hooks within it. ◼ Pedagogical qualification: Define custom hooks and the naming convention; terms introduced: **use prefix convention**, **rules of hooks enforcement**, **custom hook signature**.
- [p] ★ {preknowledge:} The most vital mental model invariant is: **Custom hooks share stateful logic, NOT state itself!** When two components call `useOnlineStatus()`, each component gets its own completely separate, independent `isOnline` state variable. Custom hooks do not create global state; they simply reuse the blueprint of state and effects across different components. ◼ Pedagogical qualification: Emphasize state isolation vs logic reuse; terms introduced: **logic reuse**, **state isolation**, **independent hook instance**.
- [code] Duplicated logic vs custom hook:
```jsx title="Duplicated Logic vs Custom Hook"
// FRAGILE: Copy-pasted across multiple components:
function CompA() { const [on, setOn] = useState(true); useEffect(...); }
function CompB() { const [on, setOn] = useState(true); useEffect(...); }
// CLEAN: Extracted into a reusable custom hook:
export function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(true);
  useEffect(() => {
    const handle = () => setIsOnline(navigator.onLine);
    window.addEventListener('online', handle);
    window.addEventListener('offline', handle);
    return () => { window.removeEventListener('online', handle); window.removeEventListener('offline', handle); };
  }, []);
  return isOnline;
}
```
- [grounding] Leading Question: Why must custom hook names start with "use"?
  Confusion Point: Is the "use" prefix just a cosmetic naming suggestion?
  Scene & Repetition: No! The "use" prefix is a mandatory React convention. React's linter uses this prefix to identify functions that may call hooks, ensuring that early returns, conditional calls, and loop violations are caught at build time. If you name a function `getOnlineStatus` and call `useState` inside it, React linters will flag a rule violation!
  Key Terms (Bold): `**use prefix mandate**`, `**linter verification**`, `**hook rule enforcement**`, `**build-time safety**`.
  Resolution: The `use` prefix is mandatory for React linters to recognize and enforce hook constraints.

### Composing Hooks and Passing Reactive Values
- [p] ◇ {preknowledge:} We know custom hooks package state and effects. {problem:} How do custom hooks interact when one hook's output serves as another hook's input? ◼ Pedagogical qualification: Teach hook composition and reactive parameter chaining; terms introduced: **hook composition**, **reactive parameter**, **custom hook chaining**.
- [p] ★ {preknowledge:} Custom hooks can take arguments and return values just like normal functions. If you pass an argument to a custom hook, and that argument is a state variable in the calling component, the custom hook re-runs whenever the argument changes! ◼ Pedagogical qualification: Explain reactive parameter propagation into custom hooks; terms introduced: **reactive argument**, **downward dependency**, **automatic re-synchronization**.
- [p] ★ {preknowledge:} This enables powerful **hook composition**: you can build high-level domain hooks (like `useArticleSubscription(articleId)`) by composing lower-level primitives (`useOnlineStatus()`, `useEffect`, `useState`). By hiding implementation details behind declarative hook signatures, components stay concise and focused on rendering markup. ◼ Pedagogical qualification: Establish layered hook composition; terms introduced: **layered composition**, **declarative interface**, **implementation hiding**.
- [code] Composing custom hooks:
```jsx title="Composing Custom Hooks"
// Custom hook taking reactive parameter and composing primitives:
export function useWireFeed(channel) {
  const isOnline = useOnlineStatus(); // Composing custom hook!
  const [data, setData] = useState(null);
  useEffect(() => {
    if (!isOnline) return;
    const socket = connect(channel, setData);
    return () => socket.disconnect();
  }, [channel, isOnline]);
  return { data, isOnline };
}
```
- [grounding] Leading Question: When should you NOT create a custom hook?
  Confusion Point: Should every single useEffect be wrapped in a custom hook?
  Scene & Repetition: Do not create a custom hook for trivial, one-off logic that only exists in a single component and is unlikely to be reused. Wrapping everything in custom hooks adds indirection without benefit. Extract a custom hook when the logic is reused across multiple components, or when complex effect orchestration clutters a component's core rendering role.
  Key Terms (Bold): `**indirection cost**`, `**pragmatic extraction**`, `**code clutter reduction**`, `**reusability threshold**`.
  Resolution: Extract custom hooks for reused logic or to clarify complex effect orchestration; avoid unnecessary indirection for simple one-off effects.

### Step 1: First, we construct the container NetworkMonitor.jsx
- [p] ★ {preknowledge:} The container defines the `useOnlineStatus` custom hook and coordinates the children. {problem:} The container must demonstrate custom hook extraction and child composition. ◼ Pedagogical qualification: Construct container declaring reusable custom hook.
- [code] Container NetworkMonitor.jsx:
```jsx title="NetworkMonitor.jsx"
import { useState, useEffect } from 'react';
import ReporterStatusBar from './components/ReporterStatusBar.jsx';
import OfflineWarningBanner from './components/OfflineWarningBanner.jsx';
export function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(true);
  useEffect(() => {
    const set = () => setIsOnline(navigator.onLine);
    window.addEventListener('online', set); window.addEventListener('offline', set);
    return () => { window.removeEventListener('online', set); window.removeEventListener('offline', set); };
  }, []);
  return isOnline;
}
export default function NetworkMonitor() {
  return <div className="network-box"><ReporterStatusBar /><OfflineWarningBanner /></div>;
}
```

### Glossary
- **Custom Hook**: A JavaScript function whose name begins with `use` that calls other React hooks to extract and reuse stateful logic.
- **use Prefix**: The mandatory naming convention identifying custom hooks to React's compiler and ESLint plugin.
- **Stateful Logic**: The sequence of state declarations, effect synchronizations, and event callbacks that govern a dynamic behavior.
- **State Isolation**: The guarantee that each component calling a custom hook receives its own private, unshared state.
- **Hook Composition**: Calling one or more hooks inside another custom hook to build higher-level abstractions.
- **Declarative API**: Exposing clean values and actions from a hook while hiding complex browser event subscriptions.

### Summary

**React 19 Custom Hook Invariants**

In daily production, custom hooks eliminate duplicate effect boilerplate while preserving strict state isolation and declarative component design. Here is your streetwise review.

❒ Custom Hook Invariants

1. Custom hooks share stateful logic, not state.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Every component calling a custom hook gets its own independent state.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) State is tied to the caller's Fiber node, not shared globally.

2. Always prefix custom hook names with `use`.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) The `use` prefix enables ESLint to enforce the Rules of Hooks.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Functions without the prefix cannot call built-in hooks safely.

3. Encapsulate symmetrical cleanup inside the hook.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Handle all window listeners and socket teardowns internally.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Callers receive pure, clean values without worrying about resource leaks.

➔ NEVER copy-paste identical `useState` and `useEffect` blocks between components.

➔ ALWAYS prefix custom hook names with `use` to enforce hook rules.

➔ IF multiple components call the same custom hook THEN **remember each has isolated state**.

**DO THIS:** Extract stateful logic into a custom hook.

```jsx right title="useOnlineStatus.js"
// Clean custom hook sharing logic with isolated state
export function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(true);
  useEffect(() => {
    const update = () => setIsOnline(navigator.onLine);
    window.addEventListener('online', update);
    return () => window.removeEventListener('online', update);
  }, []);
  return isOnline;
}
```

**DO NOT DO THIS:** Never copy-paste hook blocks across components.

```jsx wrong title="Copy-Paste Anti-Pattern"
// FAILS: Duplicating hook logic leads to maintenance drift!
export function ComponentA() {
  const [on, setOn] = useState(true);
  useEffect(() => { /* duplicated listener */ }, []);
  return <div>{on}</div>;
}
export function ComponentB() {
  const [on, setOn] = useState(true);
  useEffect(() => { /* duplicated listener */ }, []);
  return <div>{on}</div>;
}
```
