### Four Patterns for Branching JSX
- [p] ◇ {preknowledge:} In Lectures 5 and 6, we learned that JSX is syntactic sugar for JavaScript expressions and that curly braces `{}` can evaluate any valid JavaScript expression. However, curly braces cannot contain JavaScript statements like `if`, `for`, or `switch` because statements do not produce a value. {problem:} Components must constantly show, hide, or swap UI elements depending on props, permissions, or loading states. ◼ Pedagogical qualification: Establish the boundary between statements and expressions in JSX; terms introduced: **conditional rendering**, **statements vs expressions**, **branching**.
- [p] ★ {preknowledge:} The first pattern is the **early return with an `if` statement**. Before returning the main JSX, you can evaluate an `if` condition and return completely different markup or return `null` to render nothing: `if (!isLoggedIn) return <GuestCallout />;`. Returning `null` tells React to commit zero DOM nodes for this component while keeping it mounted in the virtual tree. ◼ Pedagogical qualification: Explain early return pattern and returning `null`; terms introduced: **early return**, **returning null**, **DOM suppression**.
- [p] ★ {preknowledge:} The second pattern is the **ternary operator (`? :`)**. Because a ternary is an expression, it can live directly inside JSX curly braces: `{isSubscriber ? <FullStory /> : <Paywall />}`. The third pattern is the **logical AND operator (`&&`)**, used when you want to render an element if a condition is true, and nothing if false: `{unreadCount > 0 && <Badge count={unreadCount} />}`. ◼ Pedagogical qualification: Explain inline ternary and logical AND patterns; terms introduced: **ternary operator**, **logical AND**, **inline conditional**.
- [code] Four conditional rendering patterns:
```jsx title="Conditional Rendering Patterns"
// Pattern 1: Early return or returning null:
if (isLoading) return <p>Loading dispatch...</p>;
// Pattern 2 & 3: Inline ternary and logical AND:
return (
  <main>
    {isSubscriber ? <FullStory /> : <Paywall />}
    {unreadCount > 0 && <Badge count={unreadCount} />}
  </main>
);
```
- [grounding] Leading Question: Why does React render 0 on the screen when using &&?
  Confusion Point: Why does `{count && <Badge />}` render `0` when `count` is `0`, but `{false && <Badge />}` renders nothing?
  Scene & Repetition: Imagine an editor checking breaking news alerts. The alert count is `0`. Elena writes `{unreadAlerts && <AlertBadge />}`. She expects the badge to disappear. Instead, a bare, unstyled `0` appears in the masthead. Why? In JavaScript, the `&&` operator does not return a boolean: it returns the value of the first falsy operand, or the last operand if all are truthy. When `unreadAlerts` is `0`, JavaScript evaluates `0 && <AlertBadge />` and returns the number `0`. In React, booleans (`false`, `true`), `null`, and `undefined` are ignored during rendering, but numbers like `0` are valid renderable content. React faithfully converts the number `0` to text and renders it to the DOM.
  Key Terms (Bold): `**logical AND operator**`, `**falsy zero trap**`, `**renderable values**`, `**boolean conversion**`.
  Resolution: Always ensure the left side of `&&` is an explicit boolean using comparisons like `count > 0` or double-negation `Boolean(count)`.

### Suppressing Output with Null and Avoiding the Falsy Trap
- [p] ◇ {preknowledge:} In traditional DOM scripting, hiding an element means adding `display: none` or removing the node manually with `parent.removeChild(node)`. {problem:} In React, you do not manipulate DOM styles or nodes directly to hide content: you control what the component returns during render. ◼ Pedagogical qualification: Contrast manual DOM hiding with declarative render suppression; terms introduced: **null return**, **DOM unmounting**, **declarative visibility**.
- [p] ★ {preknowledge:} When a component returns `null`, React unmounts its DOM nodes completely (or skips creating them if mounting). The component still exists in React's component tree and retains any internal state hooks, but leaves zero trace in the browser DOM. This makes returning `null` ideal for notification badges, banner alerts, or floating modals that should remain dormant until activated. ◼ Pedagogical qualification: Explain the lifecycle and DOM impact of returning `null`; terms introduced: **unmounting**, **virtual tree retention**, **null return**.
- [p] ★ {preknowledge:} To avoid the falsy zero trap with `&&`, follow one iron rule: **never place a raw number on the left side of `&&`**. Instead of `{messages.length && <Badge />}`, write `{messages.length > 0 && <Badge />}` or `{Boolean(messages.length) && <Badge />}`. An explicit comparison produces a boolean `false`, which React safely ignores, preventing stray digits from contaminating your layout. ◼ Pedagogical qualification: Provide ironclad safeguards against the falsy zero trap.
- [code] Safe versus dangerous conditional patterns:
```jsx title="Falsy Zero Contrast"
// DANGEROUS: Renders literal "0" when count is 0!
<div>{count && <NotificationBadge count={count} />}</div>
// SAFE: Explicit boolean comparison renders nothing:
<div>{count > 0 && <NotificationBadge count={count} />}</div>
// SAFE: Returning null inside the child component:
function NotificationBadge({ count }) {
  if (count <= 0) return null; // Suppresses DOM cleanly
  return <span className="badge">{count}</span>;
}
```
- [grounding] Leading Question: When should you use a ternary versus an if statement?
  Confusion Point: If ternaries and `if` statements both branch logic, how do you decide which one to use?
  Scene & Repetition: Imagine a component with four different rendering states: loading, error, guest, and subscriber. If you write nested ternaries: `isLoading ? <Loading /> : isError ? <Error /> : isSubscriber ? <Story /> : <Guest />`, the code becomes an unreadable pyramid of question marks and colons. Nested ternaries are notoriously error-prone and hard to debug. When you have mutually exclusive, full-component views, use `if` statements with early returns. Reserve inline ternaries strictly for simple binary choices between two compact elements or attributes (such as choosing between two class names or two button labels).
  Key Terms (Bold): `**early return**`, `**nested ternaries**`, `**ternary operator**`, `**binary choice**`.
  Resolution: Use early returns with `if` statements for distinct page states; use inline ternaries only for compact binary element choices.

### Step 1: First, we construct the parent container EditorialGate.jsx
- [p] ★ {preknowledge:} The parent container coordinates reader access. It evaluates `unread` to conditionally render an alert pill, and evaluates `isSubscriber` to branch between `SubscriberArticle` and `GuestCallout`. {problem:} The parent must demonstrate inline ternary branching and safe logical AND guards. ◼ Pedagogical qualification: Construct parent container demonstrating multiple conditional rendering patterns.
- [code] Parent container EditorialGate.jsx:
```jsx title="EditorialGate.jsx"
import SubscriberArticle from './components/SubscriberArticle.jsx';
import GuestCallout from './components/GuestCallout.jsx';
export default function EditorialGate({ isSubscriber = true, unread = 3 }) {
  return (
    <main className="editorial-gate">
      <header>{unread > 0 && <span>{unread} Unread</span>}</header>
      {isSubscriber ? <SubscriberArticle /> : <GuestCallout />}
    </main>
  );
}
```
- [p] ★ Step 1 establishes the contracts: Look at line 6: `{unread > 0 && <span>{unread} Unread</span>}`. Notice the comparison `unread > 0`: it evaluates to a clean boolean, avoiding the falsy zero trap. Now look at line 7: `{isSubscriber ? <SubscriberArticle /> : <GuestCallout />}`. We establish the branching contracts: when `isSubscriber` is true, React renders `SubscriberArticle`. We will build `SubscriberArticle` next in step 2. ◼ Pedagogical qualification: Deconstruct inline ternary branching and contract declarations.

- [grounding] Leading Question: Can you use a switch statement in React?
  Confusion Point: If `if` statements and ternaries work, can you use a `switch` statement for multi-case rendering?
  Scene & Repetition: Imagine an editorial status badge with five possible states: "draft", "in-review", "approved", "published", and "archived". A chain of four ternary operators is ugly and unreadable. Can you use `switch`? Inside JSX curly braces, no: `switch` is a statement. But you can use `switch` in two clean ways: either inside a helper function outside the JSX, or before the return statement: `let badge; switch(status) { case 'draft': badge = <DraftBadge />; break; ... } return <div>{badge}</div>;`.   Resolution: Use a helper function or an object lookup table for multi-branch conditional rendering rather than deeply nested ternaries.

### Glossary
- **Conditional Rendering**: The practice of rendering different JSX markup or components depending on whether certain conditions are truthy or falsy.
- **Early Return**: A pattern where a component function evaluates a condition and returns JSX or `null` immediately, skipping the rest of the function body.
- **Returning Null**: Returning `null` from a component tells React to commit zero DOM nodes for that component while keeping it in the component tree.
- **Ternary Operator**: The JavaScript expression `condition ? exprIfTrue : exprIfFalse`, used for inline binary branching within JSX curly braces.
- **Logical AND Operator**: The JavaScript operator `&&` that returns the right operand if the left operand is truthy, commonly used for inline conditional inclusion.
- **Falsy Zero Trap**: A bug where `{count && <Element />}` renders the literal number `0` when `count` is `0`, because `0` is a renderable number in React.

Choose the right branching tool for the architectural scope.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Use early returns with `if` statements when the entire component view changes.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Use inline ternaries (`? :`) for compact binary choices inside JSX.<br>&nbsp;&nbsp;&nbsp;&nbsp;(c) Return `null` to cleanly suppress DOM rendering without leaving wrapper nodes.

2. Guard against the falsy zero trap with explicit boolean expressions.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Never place raw numbers on the left of `&&`: `{count && <Badge />}` renders `0`.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Always use comparison expressions: `{count > 0 && <Badge />}`.

➔ NEVER use raw numbers with the `&&` operator, which causes stray "0" characters to render in the DOM.

➔ ALWAYS return `null` from terminal components when they have nothing to display.

➔ IF you have more than two mutually exclusive branches THEN **use early returns or an object lookup map instead of nested ternaries**.

**DO THIS:** Use explicit comparisons with `&&` and return `null` for clean suppression.

```jsx right title="GuestCallout.jsx"
// Explicit check and clean null return
export default function GuestCallout({ showPrompt = true }) {
  if (!showPrompt) return null;
  return <section className="callout"><h2>Subscribe</h2></section>;
}
```

**DO NOT DO THIS:** Never place raw numeric counts directly on the left of the `&&` operator.

```jsx wrong title="Falsy Zero Anti-Pattern"
// FAILS: Renders literal "0" into the header when unreadCount is 0!
export default function BrokenHeader({ unreadCount }) {
  return (
    <header>
      <h1>National Times</h1>
      {unreadCount && <span className="badge">{unreadCount}</span>}
    </header>
  );
}
```
