### The Problem with In-Place Array Mutation
- [p] ◇ {preknowledge:} In Lecture 18, we learned that mutating objects in place fails because `Object.is(prev, next)` evaluates to `true`. In JavaScript, arrays are just specialized objects with numerical indices. Methods like `push()`, `pop()`, `shift()`, `unshift()`, `splice()`, `sort()`, and `reverse()` modify the array in place. {problem:} Why does `stories.push(...)` followed by `setStories(stories)` fail to update the user interface? ◼ Pedagogical qualification: Contrast mutating array methods with React reference equality; terms introduced: **in-place mutation**, **mutating methods**, **array reference equality**.
- [p] ★ {preknowledge:} When you invoke `setStories(stories)` after `stories.push(...)`, React compares the old array reference with the new array reference using `Object.is`. Because `push` modified the existing array without creating a new one, both references point to the exact same array in memory. React assumes nothing changed and bails out of re-rendering. ◼ Pedagogical qualification: Explain Object.is bailout on array references; terms introduced: **render bailout**, **heap reference**, **shallow check**.
- [p] ★ {preknowledge:} To trigger a re-render and maintain temporal consistency, you must treat state arrays as read-only. Whenever you want to add, remove, update, or reorder items, you must generate a *new array* with a new reference in memory. ◼ Pedagogical qualification: Mandate immutable array recipes; terms introduced: **read-only array**, **new array reference**, **immutable array recipes**.
- [code] In-place mutation vs immutable array creation:
```jsx title="Array Mutation vs Immutable Copy"
// FAILS: Mutates in place; Object.is returns true; skips render!
stories.push({ id: 2, title: 'City Budget' });
setStories(stories);
// WORKS: Creates a fresh array reference; triggers re-render!
setStories([...stories, { id: 2, title: 'City Budget' }]);
```
- [grounding] Leading Question: Why should you avoid copying an array with slice() just to sort it with sort()?
  Confusion Point: If you do `const copy = [...stories]; copy.sort(); setStories(copy);`, does that work?
  Scene & Repetition: Yes, making a copy first before mutating it does trigger a re-render because `copy` is a new array reference! However, modern JavaScript provides non-mutating equivalents directly: `stories.toSorted(...)` and `stories.toReversed(...)`. Using native non-mutating methods expresses your intent clearly and avoids the risk of forgetting to copy the array before calling `sort()` or `splice()`.
  Key Terms (Bold): `**modern array methods**`, `**toSorted**`, `**copy-before-mutate**`, `**declarative intent**`.
  Resolution: Modern JavaScript provides non-mutating methods like `toSorted` and `toReversed`, eliminating the risk of accidental in-place mutation.

### The Four Essential Immutable Array Recipes
- [p] ◇ {preknowledge:} We know we must produce fresh array references. {problem:} What are the exact immutable code patterns for every standard array manipulation in React? ◼ Pedagogical qualification: Structure the four canonical immutable recipes; terms introduced: **adding items**, **removing items**, **transforming items**, **reordering items**.
- [p] ★ {preknowledge:} The four standard recipes are: (1) **Adding**: use the array spread operator `[...stories, newItem]` to append, or `[newItem, ...stories]` to prepend. (2) **Removing**: use `stories.filter(item => item.id !== targetId)` to produce a new array without the matching item. (3) **Transforming / Replacing**: use `stories.map(item => item.id === targetId ? { ...item, ...updates } : item)` to produce a new array with updated elements while preserving untouched ones. (4) **Inserting**: use slice and spread `[...stories.slice(0, index), newItem, ...stories.slice(index)]`. ◼ Pedagogical qualification: Provide concrete code patterns for all four operations; terms introduced: **filter removal**, **map replacement**, **slice insertion**, **spread appending**.
- [p] ★ {preknowledge:} Every rendered list of elements requires a unique `key` prop. Stable keys allow React to track which items were added, removed, or reordered across render passes, preventing DOM recycling bugs. ◼ Pedagogical qualification: Connect array operations to list keys; terms introduced: **stable keys**, **DOM recycling**, **reconciliation identity**.
- [code] The four immutable array recipes:
```jsx title="Immutable Array Recipes"
// 1. Add: [...arr, newItem]
// 2. Remove: arr.filter(item => item.id !== id)
// 3. Update: arr.map(i => i.id === id ? { ...i, title } : i)
// 4. Insert: [...arr.slice(0, i), newItem, ...arr.slice(i)]
```
- [grounding] Leading Question: What happens if you mutate an object inside a mapped array?
  Confusion Point: Does `stories.map(s => { s.read = true; return s; })` count as immutable?
  Scene & Repetition: No! That is a mutation trap! `map` creates a new array container, but `s.read = true` mutates the *existing object* inside that container. Any past snapshots or other components referencing that same story object will have their data silently altered under their feet. Always return a new object: `stories.map(s => s.id === id ? { ...s, read: true } : s)`.
  Key Terms (Bold): `**mutation trap**`, `**shallow container copy**`, `**inner object mutation**`, `**deep immutability**`.
  Resolution: Transforming an item inside an array requires both creating a new array via `map` and creating a new object via spreading `{ ...item }`.

- [grounding] Leading Question: Why is using the array index as key dangerous when reordering?
  Confusion Point: Why can't we write `stories.map((s, index) => <li key={index}>)`?
  Scene & Repetition: When you insert, remove, or reorder items in an array, an item's index changes! If you delete item 0, the item previously at index 1 is now at index 0. ### Glossary
- **Immutable Array Recipe**: A functional programming pattern (`filter`, `map`, spread) that produces a new array instead of modifying an existing one.
- **In-Place Mutation**: Modifying an array's contents directly (`push`, `splice`, `sort`), preserving the original reference.
- **Array Spread Operator**: The `...arr` syntax that unpacks array elements into a new array literal.
- **Stable Key**: A unique, persistent identifier (such as an ID) passed to the `key` prop to identify items across renders.
- **Non-Mutating Method**: An array method (such as `filter`, `map`, `concat`, `slice`, `toSorted`) that returns a new array without altering the original.
- **Render Bailout**: React skipping component re-rendering when the new state reference equals the previous state reference via `Object.is`.

### Summary

**React 19 Array State Invariants**

In daily production, managing arrays in React state requires strictly adhering to immutable patterns. Treating state arrays as read-only and using non-mutating methods guarantees that React reliably detects changes and updates the user interface. Here is your streetwise review.

❒ Array State Invariants

1. Never use mutating array methods on React state.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Methods like `push`, `pop`, `splice`, and `sort` modify arrays in place.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) React's `Object.is` check evaluates to true and skips re-rendering.

2. Use the four immutable array recipes for all list manipulations.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Add: `[...arr, newItem]` or `[newItem, ...arr]`.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Remove: `arr.filter(item => item.id !== targetId)`.<br>&nbsp;&nbsp;&nbsp;&nbsp;(c) Update: `arr.map(item => item.id === targetId ? { ...item, ...updates } : item)`.<br>&nbsp;&nbsp;&nbsp;&nbsp;(d) Reorder: `arr.toSorted((a, b) => ...)` or `[...arr].sort(...)`.

3. Always assign stable, unique keys to rendered list elements.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Never use array indices as keys if items can be reordered or removed.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Stable keys protect DOM state and ensure accurate reconciliation.

➔ NEVER call `push()`, `splice()`, or `sort()` directly on state arrays.

➔ ALWAYS return a new array instance using `[...arr]`, `filter()`, or `map()`.

➔ IF updating an object inside an array THEN **spread both the array and the target object `{ ...item }`**.

**DO THIS:** Use non-mutating array recipes to create fresh array references.

```jsx right title="QueueControls.jsx"
// Appends immutably using array spreading
export default function QueueControls({ stories, onUpdate }) {
  function handleAdd() {
    onUpdate([...stories, { id: Date.now(), title: 'Breaking Dispatch' }]);
  }
  return <button onClick={handleAdd}>Add Dispatch</button>;
}
```

**DO NOT DO THIS:** Never mutate state arrays directly with push or splice.

```jsx wrong title="Array Mutation Anti-Pattern"
// FAILS: Mutates in place; Object.is returns true; skips render!
export default function BrokenControls({ stories, onUpdate }) {
  function handleAdd() {
    stories.push({ id: Date.now(), title: 'Breaking Dispatch' });
    onUpdate(stories);
  }
  return <button onClick={handleAdd}>Broken Add</button>;
}
```

| ---: | :--- | :--- |
| **Adding items** | Spread operator: `[...arr,`<br>`newItem]` | Mutating method: `arr.push`<br>`(newItem)` |
