### The Bridge Between HTML and React
- [p] ◇ {preknowledge:} In earlier lessons, we learned how to write React components, JSX syntax rules, and dynamic expressions (see Lectures 3, 4, and 5). You wrote an `App.jsx` component that returns markup, but that component is just a JavaScript function sitting in a file. {problem:} Web browsers do not know what `App.jsx` is: they only load `index.html`. You need an explicit bridge to connect that JavaScript function to a real DOM element on the page. ◼ Pedagogical qualification: Establish the need for a mounting API; terms introduced: **mount point**, **DOM container**, **react-dom/client**.
- [p] ★ {preknowledge:} React is a modular library rather than an all-or-nothing framework. The core `react` package only knows about components, hooks, and virtual element descriptors: it knows nothing about browser DOM nodes, phone screens, or canvas elements. To render into a web browser, React provides a separate package called `react-dom/client`. {problem:} In modern React 19, mounting is a two-step process rather than a single function call. ◼ Pedagogical qualification: Explain package separation and introduce `createRoot`; terms introduced: **createRoot**, **root.render**, **React root**.
- [p] ★ {preknowledge:} The two-step mounting sequence works in strict order. (a) First, you call `createRoot(domNode)`: this takes a physical DOM element (usually `document.getElementById('root')`) and creates a React root object in memory that takes over managing the DOM inside that container. (b) Second, you call `root.render(<App />)`: this takes your root component JSX, evaluates its component tree, and commits the resulting HTML into the DOM container. {problem:} Calling `render` directly on `react-dom` without creating a root is the obsolete React 17 pattern that disables concurrent rendering features. ◼ Pedagogical qualification: Deconstruct the two-step mounting sequence.
- [p] {old solution:} In legacy React 17 and earlier, developers called `ReactDOM.render(<App />, domNode)`. This legacy API attempted to configure the root and render the tree in a single blocking synchronous step, preventing concurrent rendering and background transitions. ◼ Educational objective: Contrast `createRoot` with legacy `ReactDOM.render`.
- [code] Legacy render versus modern createRoot:
```jsx title="Mounting Contrast"
// Legacy React 17 Synchronous Mount:
ReactDOM.render(<App />, document.getElementById('root'));
// Modern React 19 Two-Step Root Architecture:
import { createRoot } from 'react-dom/client';
const domNode = document.getElementById('root');
const root = createRoot(domNode); // 1. Acquires container in **MEMORY**
root.render(<App />); // 2. Renders component tree into **DOM**
```

- [grounding] Leading Question: Why does React need two steps to mount?
  Confusion Point: Why did React split mounting into `createRoot` and `root.render` instead of keeping a single `render` call?
  Scene & Repetition: Imagine you are setting up an electrical sub-panel in an office building. You do not plug in a high-voltage appliance and simultaneously wire the breakers to the municipal grid in one motion. First, you install the sub-panel and verify the connection to the electrical main. Once the panel is securely anchored, you switch on the circuits. `createRoot` is that sub-panel. Step 1 (`createRoot`) anchors React's memory to a specific DOM node and initializes its concurrent scheduler. Step 2 (`root.render`) switches on the circuits, evaluating your components and rendering the interface. Splitting the process lets React manage the root's lifecycle independently from individual render updates.
  Key Terms (Bold): `**createRoot**`, `**root.render**`, `**DOM container**`, `**concurrent scheduler**`.
  Resolution: Splitting mounting into two steps separates root initialization and scheduler setup from individual component rendering passes.

### Root Lifecycle, DOM Clearing, and Unmounting
- [p] ◇ {preknowledge:} Once a root is created, React takes exclusive ownership of the DOM container. When `root.render(<App />)` executes for the very first time, React clears any existing HTML markup sitting inside the container before rendering your component tree. {problem:} Developers often leave fallback text or loading spinners inside `<div id="root">Loading...</div>` in `index.html` and wonder what happens to that markup when React mounts. ◼ Pedagogical qualification: Explain the initial container wipe behavior; terms introduced: **container wipe**, **hydration caveat**.
- [p] ★ {preknowledge:} If your application uses server-side rendering (SSR) or static site generation (SSG), using `createRoot` is a serious mistake. Calling `createRoot` on server-rendered HTML wipes the existing markup and recreates every DOM node from scratch, causing an ugly screen flicker. In server-rendered applications, you must call `hydrateRoot(domNode, <App />)` instead, which reuses the existing HTML nodes and attaches event listeners. ◼ Pedagogical qualification: Distinguish client-side `createRoot` from server-side `hydrateRoot`; terms introduced: **hydrateRoot**, **hydration**.
- [p] ★ {preknowledge:} Most applications have a single `createRoot` call that runs once at startup. However, in applications where React is embedded as a widget inside a legacy non-React host page (like a WordPress blog or jQuery dashboard), the widget may need to be removed. {problem:} If non-React code removes the root DOM node without notifying React, active subscriptions, timers, and state inside the React tree will leak in memory. ◼ Pedagogical qualification: Introduce `root.unmount()` for cleanup; terms introduced: **root.unmount**, **memory leak**.
- [p] ★ Calling `root.unmount()` tells React to stop managing the root DOM node. It unmounts all components in the tree, runs their cleanup functions, detaches event listeners, and frees internal memory. Once a root is unmounted, calling `root.render` on it again will throw an error. ◼ Pedagogical qualification: Detail the exact cleanup routine of `root.unmount()`.
- [code] Root unmount cleanup sequence:
```jsx title="Root Lifecycle and Cleanup"
const root = createRoot(document.getElementById('ticker-root'));
root.render(<LiveTicker />); // Mounts live ticker widget
// When host page navigates away or removes widget:
root.unmount(); // Tears down tree and cleans up **SUBSCRIPTIONS**
```
- [grounding] Leading Question: When should you call root.unmount in production?
  Confusion Point: If an app only needs `createRoot` once, why does `root.unmount` exist?
  Scene & Repetition: Imagine The National Times has a legacy article archive built with jQuery. An editor opens a tab containing an interactive breaking news ticker built with React. When the editor clicks away to another tab, jQuery deletes the tab's DOM container. But what happened to the React component that lived inside? If you did not call **root.unmount**, React still holds the component tree, its timer intervals, and its event listeners in memory. The DOM node is gone, but the code continues running in the background, leaking memory until the tab crashes. Calling **root.unmount** before removing the DOM container ensures every component cleans up and releases its resources.
  Key Terms (Bold): `**root.unmount**`, `**memory leak**`, `**cleanup function**`, `**DOM container**`.
  Resolution: `root.unmount` is essential when React widgets live inside non-React host pages, ensuring complete cleanup of timers, listeners, and memory.

### Step 1: First, we construct the entry point main.jsx
- [p] ★ {preknowledge:} The entry point is the first JavaScript file executed by the browser after loading `index.html`. {problem:} The file must locate the target DOM container and initialize the React root. ◼ Pedagogical qualification: Construct entry point calling `createRoot`.
- [code] Entry point main.jsx:
```jsx title="main.jsx"
import { createRoot } from 'react-dom/client';
import NewsApp from './NewsApp.jsx';
const domNode = document.getElementById('root');
if (!domNode) throw new Error('Target container #root not found');
const root = createRoot(domNode); // Acquires container and sets up **SCHEDULER**
root.render(<NewsApp />); // Mounts root component into **DOM**
```
- [p] ★ Step 1 establishes the root: Look at lines 5 and 6. `createRoot(domNode)` creates the React root, and `root.render(<NewsApp />)` launches the component tree. Notice the guard clause on line 4: if `document.getElementById('root')` evaluates to null because the HTML is missing the element, the script fails fast with a clear error. ◼ Pedagogical qualification: Deconstruct root creation and guard clause.

- [callout] > [!TIP]
**To impress the interviewer:** When asked how `createRoot` differs from legacy `ReactDOM.render`, explain that `createRoot` changes the fundamental execution model of React. In React 17, `ReactDOM.render` ran synchronously from top to bottom, blocking the main thread until the entire DOM tree was committed. In React 19, `createRoot` creates an internal FiberRoot with priority lanes, enabling concurrent rendering, interruptible work, and background transitions.

### Where you will meet this
- Single-page application entry points: initializing the root application container in `main.jsx` or `index.js` across all Vite and Webpack projects.
- Micro-frontends and multi-root architectures: calling `createRoot` multiple times on a single page to mount independent React widgets into different DOM sections.
- Embedded third-party widgets: mounting a live chat widget or feedback form into a customer's existing non-React website and unmounting on close.
- Unit and integration tests: testing libraries calling `createRoot` and `root.unmount` behind the scenes to mount components into headless JSDOM nodes.

### Glossary
- **createRoot**: The React DOM client API that creates a root container for displaying content inside a browser DOM element.
- **root.render**: The method on a React root that evaluates a component tree and commits it into the DOM container.
- **root.unmount**: The method on a React root that tears down the component tree, runs cleanups, and detaches React from the DOM.
- **Root Container**: The physical DOM element (typically `<div id="root">`) managed exclusively by a React root.
- **hydrateRoot**: The server-rendering counterpart to `createRoot` that attaches event handlers to existing server-rendered HTML without wiping it.
- **Concurrent Scheduler**: The internal React engine mechanism initialized by `createRoot` that coordinates priority-based, interruptible rendering.

### Summary

**React 19 Mounting Mechanics and createRoot Invariants**

In daily production, `createRoot` is the gateway that transforms static HTML documents into dynamic React applications. Understanding root creation, container ownership, and unmounting guarantees clean architecture and prevents memory leaks. Here is your streetwise review.

❒ The Mounting Sequence and Container Governance

1. Mount applications using the two-step `createRoot` and `root.render` sequence.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Step 1 (`createRoot(domNode)`) anchors React to a physical DOM element and initializes its concurrent scheduler.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Step 2 (`root.render(<App />)`) evaluates the component hierarchy and commits the initial DOM nodes.

2. Manage container lifecycles and clean up embedded widgets.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) `root.render()` completely clears any existing HTML inside the container on its initial run.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Call `root.unmount()` whenever a React root is removed from a non-React host page to prevent memory leaks.

➔ NEVER call the legacy `ReactDOM.render` API, which disables concurrent rendering in modern React.

➔ ALWAYS verify that `document.getElementById('root')` exists before passing it to `createRoot`.

➔ IF your HTML was rendered on a server THEN **call `hydrateRoot` instead of `createRoot` to prevent screen flickering**.

**DO THIS:** Separate root initialization from rendering and provide an explicit DOM container.

```jsx right title="main.jsx"
import { createRoot } from 'react-dom/client';
import NewsApp from './NewsApp.jsx';

const container = document.getElementById('root');
if (container) {
  const root = createRoot(container);
  root.render(<NewsApp />);
}
```

**DO NOT DO THIS:** Never use legacy ReactDOM.render or call createRoot without verifying the container.

```jsx wrong title="Legacy Synchronous Mount"
import ReactDOM from 'react-dom';
import NewsApp from './NewsApp.jsx';

// Fails in React 19: disables concurrent rendering
ReactDOM.render(<NewsApp />, document.getElementById('root'));
```
