# Decision Brief: Architectural Crossroad Options Unordered Bullet Standard & Teal ➔ Marker Law (#2026_09_22_11_group_1)

**Date**: 2026-09-22
**Rule Tag**: `#2026_09_22_11_group_1`
**Components Affected**: `skills/pedagogical-crossroads/SKILL.md`, `skills/lecture-structure/SKILL.md`, `skills/verification/SKILL.md`, `src/build-lectures.mjs`, `src/lecture.css`, `skills/RULE-TAGS.md`

---

## 1. Problem Statement & Root Cause

Previously under `#2026_09_21_14_group_1`, technical crossroads were instructed to open with an "upfront visual numbered list (`1.` and `2.`)":
1. **Artificial Sequential Bias**: Numbered lists in technical prose naturally imply a chronological sequence, multi-step algorithm, or prioritized order of execution. In an architectural crossroad, however, Option 1 and Option 2 are competing design paths, trade-off alternatives, or contrasting paradigms (rigid vs composable, raw vs modern idiomatic) rather than sequential steps `1` then `2`.
2. **Visual Polish & Typographic Signature**: The user requested that option bullets be presented as unordered bullets featuring the project's signature teal `➔` bullet point marker (`var(--bullet-color, var(--accent))`), matching the project's brand design system and providing clear typographic hanging indents where wrapped lines indent cleanly past the arrow.

**Root Causes in Instructions & Build Pipeline**:
1. **Prescriptive List-Type Constraint**: In `skills/pedagogical-crossroads/SKILL.md`, `skills/lecture-structure/SKILL.md`, and `skills/verification/SKILL.md`, rules prescribed a "structured numbered list" for option declarations, unintentionally discouraging unordered bullet presentations.
2. **Compiler List Detection**: `src/build-lectures.mjs` previously rendered all unordered lists as standard `<ul>` with round bullets (`disc`), lacking automatic detection for architectural option declarations (`- **Option 1...`).

---

## 2. Changes Applied

### A. Golden Rule De-Prescription in Skills
- **`skills/pedagogical-crossroads/SKILL.md` (Section 02)**:
  - De-prescribed the rigid numbered list requirement for crossroad option declarations.
  - Mandated that crossroad options are declared using unordered bullet syntax (`- **Option 1...` and `- **Option 2...`) rendered with the project's signature teal `➔` bullet marker.
  - Replaced the abstract example with real shipped code and text from Lecture 09 (rigid individual props vs composable `{ children }` with rest forwarding).
- **`skills/lecture-structure/SKILL.md` (Section 18)**:
  - Updated crossroad declaration rule to specify unordered bullet lists (`- **Option 1...` and `- **Option 2...`) rendered with the teal `➔` marker.
- **`skills/verification/SKILL.md` (Gate 21, item 15)**:
  - Updated Gate 15 to audit for explicit unordered option lists with teal `➔` bullet markers instead of numbered lists.

### B. Build Engine Hardening (`src/build-lectures.mjs`)
- Enhanced `renderUlItems` to inspect list items for option declarations matching `/^\s*(\*\*Option\s+\d+|➔\s+)/i`.
- Automatically assigns `<ul class="options-list">` and `<li class="option-item">` when option patterns are detected.
- Automatically strips redundant leading `➔ ` characters from list item text so authors can use either `- **Option 1...` or `- ➔ **Option 1...` without duplicate arrows.

### C. Design System & CSS Styling (`src/lecture.css`)
- Added `.options-list` styling using Prince XML native list marker support:
  - `ul.options-list > li::marker, li.option-item::marker` set to `content: '➔ '; color: var(--bullet-color, var(--accent)); font-size: 1.05em; font-weight: bold;`.
  - Added clean padding and margins (`padding-left: 1.4rem; margin: 0.8rem 0 1.2rem 0;`) for consistent hanging indent.

### D. Verification on Shipped Lecture 09
- Verified in `01-02-md-LECTURES/09.md` that options compile cleanly with teal `➔` bullets.
- Built via `node src/build-lectures.mjs 09` with zero Prince warnings and visually confirmed page rendering.
