# Brief 2026-09-20-23: Explicit Entity Qualification and the "What Is What" Law

## 1. Context & Autopsy of the Defect

During review of Lecture 5 (`md-lectures-revised/05.md`), the user flagged an unqualified and fragmented explanation of child component rendering:

> *".AuthorBadge unpacks name inside*
> *span for text display, and avatar Url inside img for the*
> *image source."*

An autopsy identified the underlying cognitive defects:
1. **Bare, Unqualified Tokens**: Throwing bare words like `AuthorBadge`, `name`, `span`, and `img` forces the reader to perform mental calculations to determine what each word represents. Is `AuthorBadge` being defined or invoked? Is `name` a local variable or a prop? Is `span` an HTML element or an identifier?
2. **Missing Lineage (Disconnected Circuit)**: The sentence fails to explain where `name` or `avatarUrl` came from. It skips the fact that `AuthorBadge` receives the prop `author` from its parent, leaving the reader to mentally reconstruct the data flow.
3. **Compound Identifier Mutilation**: Splitting camelCase identifiers with spaces (*"avatar Url"*) corrupts code accuracy and breaks reader trust.
4. **Definition vs. Invocation Confusion**: Without explicit verbal markers, a reader cannot tell whether a sentence describes a component's internal declaration or its instantiation in parent JSX.

The user articulated the standard:
> *"We need to make verbally clear instead of adding overaload to the reader to make calculation. If the component is defined , we invoke it as 'the component ComponentName', if a component is invoked, the 'component <ComponentName/>'. Maximum communication clarity of what is what, attention to detail."*

## 2. Technical Decisions & Rules Added

We codified the Explicit Entity Qualification standard across `skills/` under tag `#2026_09_20_23_group_1`:

1. **`skills/lecture-revision/SKILL.md` (Principle 06B & Gate 5)**:
   - Added Principle 06B (*Explicit Entity Qualification / The "What Is What" Law*):
     - **Component Definition**: When referring to a component as a function, file, or declaration, call it **"the component `ComponentName`"** (e.g., *the component `AuthorBadge`*).
     - **Component Invocation**: When referring to a component being rendered or mounted in JSX, call it **"the component `<ComponentName />`"** (e.g., *the component `<AuthorBadge />`*).
     - **HTML Elements**: Always qualify HTML tags with their element role (e.g., *the `<span>` element*, *the `<img>` tag*, *the `<p>` paragraph*).
     - **Props and Variables**: Always state the container and property path (e.g., *the prop `author`*, *the property `author.name`*, *the variable `headline`*).
     - **Compound Identifier Integrity**: Strictly ban splitting identifiers with spaces (e.g., never `avatar Url`; always `avatarUrl` or `author.avatarUrl`).
     - Mandate lineage tracing: state where the data enters and where it lands.
     - Included COUNTER-EXAMPLE, HALF-WAY EXAMPLE, and PROPER EXAMPLE.
   - Updated Gate 5 (*The Actor Gate*) to audit for explicit entity qualification and role markers.

2. **`skills/lecture-voice/SKILL.md` (Reader 03)**:

3. **`skills/verification/SKILL.md` (Gate 08)**:
   - Updated Gate 08 (*The Developer-at-the-Keyboard Gate*) to fail any lecture that uses bare unqualified tokens or splits compound identifiers.

4. **`skills/RULE-TAGS.md`**:
