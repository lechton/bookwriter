Why JSX Is Not HTML

In earlier lessons, we learned that a React component is a JavaScript function returning markup (see Lecture 3). That markup looks nearly identical to HTML. You write angle brackets, tag names like <h1>, and attributes like src. Developers naturally assume they are writing real HTML. However, web browsers cannot understand JSX directly. Treating JSX as HTML causes sudden syntax errors.

Under the hood, a compiler like Babel or Vite's SWC transforms every JSX element into a plain JavaScript function call. Because JSX compiles into function calls, it must obey the strict grammar of JavaScript. In JavaScript, you cannot return two separate objects from a function without wrapping them. You also cannot leave syntax unclosed. Loose HTML5 parsing rules allow unclosed void tags and arbitrary attributes. The JSX compiler rejects any snippet that violates JavaScript syntactic integrity.

Because these tags become object properties and function arguments, the syntax rules of JavaScript govern every single character of JSX.

Why can't browsers read JSX directly? Imagine saving an ordinary .jsx file to your desktop and double-clicking it. The browser opens a blank white page. The developer console displays an unhandled SyntaxError: Unexpected token <. Why? Because web browsers are built to parse HTML and standard JavaScript, but JSX is neither. It is a syntax extension. You must run a compiler to transform every tag into a JavaScript function call. Without it, the browser chokes on the very first bracket. The compiler transforms your markup into plain JavaScript objects before the browser ever sees it.

The Three Strict Syntax Rules of JSX

In plain HTML5, browsers are extremely forgiving. You can omit closing tags on void elements, write lowercase attributes, and place multiple top-level elements side by side. In React, the compiler enforces three non-negotiable syntax rules.

Rule 1: Return a Single Root Element. A component function cannot return multiple adjacent elements without a single enclosing parent. Under the hood, JSX compiles into JavaScript function calls. In JavaScript, a function cannot return two values at once. Returning two adjacent elements is equivalent to returning two separate function calls, which is invalid JavaScript grammar. Every returned JSX snippet must be wrapped in a single parent tag.

Rule 2: Close All Tags Explicitly. In HTML, certain tags known as void elements (such as <img>, <input>,
, and <hr>) never require a closing slash. In JSX, every tag must be explicitly closed. You must write self-closing slashes for tags without children, such as <img />, <input />, or
. If you leave any tag unclosed, the parser cannot determine where children end. This triggers a fatal syntax error.

Rule 3: camelCase Most Attributes. In HTML, attributes use lowercase or hyphenated names like class, for, tabindex, and stroke-width. In JSX, attributes become keys inside a JavaScript object. Because words like class and for are reserved keywords in JavaScript, React uses className and htmlFor instead. All standard DOM properties use camelCase, such as tabIndex, autoFocus, and strokeWidth. As an exception, aria-* and data-* attributes remain hyphenated to match web accessibility and data specifications.

⚡ IN THE WILD

Why className instead of class in JSX? Imagine you write class="news-banner" inside your component. In JavaScript, class is not just an attribute name: it is a sacred reserved keyword used to define object-oriented classes. JSX compiles directly into a JavaScript object. Early parsers threw syntax errors when unquoted reserved words appeared as keys. Even though modern JavaScript allows unquoted reserved keys, React standardized on className to match the browser's own DOM property (element.className). This is why you must write className: it prevents collisions with JavaScript keywords and matches the native DOM property directly.

Fragments as Invisible Containers

In plain HTML, developers organize layout by grouping elements inside generic <div> containers. In complex web layouts, every extra <div> participates in layout calculations. This disrupts CSS Flexbox, CSS Grid, and HTML tables.

To solve wrapper element bloat, React provides a special invisible container called a Fragment. A Fragment allows a component to group multiple child elements without creating an extra node in the browser's DOM tree. Under the hood, the compiler transforms the Fragment shorthand <>...</> into a special React symbol. During reconciliation, React renders the child elements directly into the parent container as true siblings.

Using Fragments satisfies React's single root return rule. Every component function must return exactly one top-level value. Wrapping sibling elements inside a Fragment satisfies the compiler while keeping the rendered DOM tree completely flat. Within these grouped elements, all void tags like <img> must close explicitly with a self-closing slash. Furthermore, all standard attributes must use camelCase property names like className.

To see Fragment architecture in action on The National Times, we organize our breaking news preview into three files:

  1. The parent container component ArticlePreview.jsx groups the preview elements inside a Fragment.
  2. The child component Headline.jsx renders the article title with camelCase attributes.
  3. The child component StoryExcerpt.jsx renders the article summary paragraph.

Both child elements mount as direct siblings in the DOM without any intermediate wrapper node.

In the naive approach, developers instinctively wrap adjacent sibling elements in a generic <div> tag to satisfy the compiler. This satisfies the single root rule, but it bloats the DOM with unnecessary wrapper tags. These extra wrapper tags break CSS Flexbox and Grid layouts.

In the React 19 reality, the Fragment groups sibling elements in memory. It creates zero intermediate HTML wrapper nodes in the document. The compiler parses the single root, while the browser receives clean, semantic siblings.

⚡ IN THE WILD

Why does an extra div break flexbox and tables? Imagine you have a CSS flex container: .feed { display: flex; gap: 20px; }. Flexbox applies its spacing and alignment strictly to its immediate child elements. When your component returns a wrapper <div>, that wrapper becomes the flex child, while your headline and excerpt become grandchildren. The layout collapses. Inside an HTML <table>, placing a <div> between <tr> and <td> violates the HTML specification. Browsers eject your content into a broken position outside the table. This is why you need a Fragment. It satisfies the single root rule while rendering zero wrapper nodes in the physical DOM.

Interview Tip

To impress the interviewer: When asked why JSX requires a single root element, explain the underlying JavaScript mechanism. JSX tags compile into jsx() function calls. In JavaScript, a function cannot return multiple expressions without wrapping them in an array or parent structure. A Fragment compiles into a special React call. It tells React to render children directly into the parent container without creating a DOM wrapper.

Where you will meet this

  • News feed cards: grouping an article thumbnail and summary text inside a Fragment so they align cleanly as direct children of a CSS Grid layout.
  • Table row components: rendering multiple <td> table cells from a single child component without inserting an illegal <div> inside a <tr>.
  • Form field pairs: grouping a <label> and <input> together with a Fragment so custom form CSS can control their vertical rhythm without wrapper nodes.
  • List rendering with keys: mapping an array of stories to adjacent title and excerpt tags using <Fragment key={story.id}> to maintain list identity.

Glossary

  • JSX: A syntax extension for JavaScript that allows developers to write HTML-like markup inside JavaScript component files.
  • Single Root Rule: The syntactic requirement that every JSX expression must be enclosed in exactly one top-level element or Fragment.
  • Fragment: A React component that groups a list of children without adding an extra node or wrapper to the physical browser DOM.
  • Self-Closing Tag: A tag that closes itself with a trailing slash (<tag />), mandatory in JSX for elements without children.
  • camelCase Attributes: The naming convention used for JSX properties to prevent collisions with reserved JavaScript keywords like class and for.
  • Keyed Fragment: An explicit Fragment component imported from React that accepts a key prop during list rendering.

Summary

JSX Syntax Invariants and Fragment Mechanics

In daily production, understanding JSX syntax rules and Fragment architecture prevents build failures and keeps your DOM structure clean. While JSX resembles HTML, it is strict JavaScript that compiles into function calls. Here is your streetwise review.

❒ JSX Grammar versus HTML Tolerances
  1. Treat JSX as strict JavaScript syntax rather than permissive browser HTML.
        (a) Every tag must be explicitly closed, including void elements like img and input.
        (b) Use camelCase attribute names like className and htmlFor to avoid collisions with JavaScript reserved words.
  2. Use Fragments to satisfy the single root rule without adding wrapper nodes to the DOM.
        (a) The shorthand <>...</> groups elements without polluting the DOM or breaking CSS flexbox and grid layouts.
        (b) Use the explicit <Fragment key={id}> syntax whenever you need to pass a key during list rendering.

➔ NEVER leave void HTML tags unclosed or use the reserved word class as an attribute in JSX.

➔ ALWAYS wrap adjacent sibling elements in a Fragment <>...</> to avoid unnecessary wrapper div soup.

➔ IF you need to pass a key to a group of sibling elements in a list THEN import and use the explicit Fragment component.
