### The Imperative Toggle and the Zero Trap

- [p] ◇ In traditional DOM scripting, developers show or hide elements imperatively by querying nodes and modifying their styles: `element.classList.toggle('hidden')`. In React, the UI is a direct projection of data. Trying to imperatively toggle DOM visibility creates a split brain where the physical DOM disagrees with React's virtual tree. Instead, React handles conditional rendering declaratively: you decide which JSX to return based on props and conditions. ◼ Educational objective: establish the declarative foundation of conditional rendering versus imperative DOM manipulation.
- [p] ★ {preknowledge: JavaScript truthiness, short-circuit evaluation, JSX expressions} {bridging: developers assume logical AND short-circuits to nothing on all falsy values, but React renders numbers} When developers use the logical AND (`&&`) operator with numeric counts, a notorious bug occurs. Look at the naive attempt: ◼ Educational objective: demonstrate the common zero-rendering bug with logical AND.
- [code] Naive Conditional Rendering:
```jsx title="Naive Conditional Rendering and the Zero Trap"
export default function ArticleHeader({ commentsCount, isBreaking }) {
  return (
    <header className="article-header">
      {commentsCount && <span className="badge">{commentsCount}</span>}
      <button onClick={() => document.getElementById('pw').classList.add('show')}>
        Unlock // **WRONG:** imperative DOM mutation bypasses **REACT**
      </button>
    </header>
  );
}
```
◼ **The what-this-introduces list:** 1. `commentsCount && <span ...>`: the zero-rendering trap. 2. `document.getElementById`: imperative DOM manipulation violating declarative UI. 3. Desynchronized UI state.
- [p] ★ {preknowledge: falsy values, type coercion, JavaScript expressions} {bridging: React ignores false, null, and undefined, but numbers like 0 are valid renderable content} When `commentsCount` is `0`, JavaScript evaluates the expression `0 && <span ...>`. In JavaScript, the `&&` operator evaluates the left-hand operand; if it is falsy, it returns that operand immediately. Thus, the expression evaluates to `0`! React treats `false`, `null`, and `undefined` as empty slots, rendering nothing. But `0` is a valid number; React cannot know whether `0` is a counter or a boolean guard, so it renders a literal `0` into the DOM! To fix this, you must explicitly convert the condition to a boolean: `commentsCount > 0 && ...` or `Boolean(commentsCount) && ...`. ◼ Educational objective: deconstruct the JavaScript evaluation of 0 && JSX and how to prevent it.
- [figure] ```html-figure src="figures/10-00-conditional-rendering-branching.html" caption="Conditional rendering: early return, inline ternary, and avoiding the falsy zero trap."```
- [grounding] [!WILD] **Why does React render 0 but ignores false, null, and undefined?** Many developers wonder why React renders `0` while ignoring other falsy values. In JavaScript, `false`, `null`, and `undefined` carry no visual meaning; they represent absence. React purposely ignores them so you can write `{condition && <Element />}` without rendering unwanted strings. However, numbers like `0` are frequently legitimate content to display—such as displaying "You have 0 unread messages" or "Score: 0". If React automatically hid `0`, displaying numeric counters would be impossible. React treats numbers as text nodes. Therefore, you must ensure the left-hand side of an `&&` expression is always a genuine boolean.
- [callout] > [!TIP]
> **To impress the interviewer:** When asked how conditional rendering works in React, state that React has no special template directives like `v-if` or `*ngIf`. Instead, React relies purely on standard JavaScript control flow: `if` statements for early returns, the ternary operator `? :` for dual branches, and logical `&&` for single branches. Always mention the `0 && <Component />` trap and explain that you guard it with `count > 0` or `Boolean(count)`.

### Declarative Control Flow and the Branching Matrix

- [p] ◇ Declarative conditional rendering means your component describes what the UI should look like for every possible data state. When state changes, React recalculates the returned JSX tree and updates the DOM to match. ◼ Educational objective: define declarative conditional rendering in React.
- [p] ★ {preknowledge: if statements, ternary operator, logical AND} {bridging: developers must select the appropriate branching technique based on whether they are handling an entire component, an inline fork, or an optional element} React developers rely on three standard branching patterns: ◼ Educational objective: categorize the three primary conditional rendering patterns in React.
- [p] 1. **Early Return with null**: If essential data is missing or loading, return early before executing the main JSX: `if (!article) return null;`. ◼ Educational objective: explain early return with null.
- [p] 2. **Inline Ternary Operator (`? :`)**: For binary branching between two mutually exclusive UI elements: `{isSubscriber ? <FullArticle /> : <PaywallNotice />}`. ◼ Educational objective: explain inline ternary branching.
- [p] 3. **Logical AND Operator (`&&`)**: For conditionally rendering an element when a condition is true, and rendering nothing when false: `{isBreaking && <BreakingBadge />}`. ◼ Educational objective: explain logical AND short-circuiting.
- [p] ★ {preknowledge: component structure, clean code} {bridging: choosing the wrong branching pattern leads to nested unreadable ternaries or fragmented component bodies} When branching markup, you face an architectural crossroad between these three patterns: ◼ Educational objective: frame the crossroad between early returns, ternaries, and logical AND.
- [p] - **Option 1 (The Early Return)**: Exit the function before the main return statement when a precondition is not met. ◼ Educational objective: declare Option 1 with concrete syntax tokens.
- [p] - **Option 2 (The Inline Ternary)**: Switch between two distinct UI branches inside the JSX tree using `condition ? <A /> : <B />`. ◼ Educational objective: declare Option 2 with concrete syntax tokens.
- [p] First, examine Option 1 with an early return: ◼ Educational objective: transition to Option 1 code.
- [code] Option 1:
```jsx title="Option 1: The Early Return (Precondition Guard)"
export default function ArticleHeader({ article }) {
  if (!article) {
    return null; // Renders nothing when **DATA** is missing
  }
  return <h1>{article.title}</h1>;
}
```
◼ **The what-this-introduces list:** 1. `if (!article)`: precondition guard checking data presence. 2. `return null`: tells React to render nothing to the DOM. 3. Clean main return statement unencumbered by nested checks.
- [p] ★ In Option 1, the early return guards the rest of the component. If `article` is null or undefined, the component exits immediately. This prevents runtime errors like `Cannot read properties of null` in subsequent code. ◼ Educational objective: analyze how early returns guard components from null reference errors.
- [p] Next, examine Option 2 with inline ternary and boolean-safe logical AND: ◼ Educational objective: transition to Option 2 code.
- [code] Option 2:
```jsx title="Option 2: Inline Ternary and Boolean-Safe Logical AND"
export default function ArticleHeader({ isSubscriber, isBreaking, commentsCount }) {
  return (
    <header className="header">
      {isBreaking && <span className="badge">BREAKING</span>}
      {isSubscriber ? <p>Full Access</p> : <p>Subscribe for $1</p>}
      {commentsCount > 0 && <small>{commentsCount} comments</small>}
    </header>
  );
}
```
◼ **The what-this-introduces list:** 1. `isBreaking && ...`: logical AND for optional alert badge. 2. `isSubscriber ? ... : ...`: ternary branching between subscriber and paywall text. 3. `commentsCount > 0 && ...`: boolean comparison avoiding the zero trap.
- [p] ★ In Option 2, the ternary cleanly alternates between two mutually exclusive UI blocks, while `commentsCount > 0` ensures that zero never renders as an orphaned number. ◼ Educational objective: demonstrate clean inline branching with ternaries and boolean guards.
- [callout] > [!KEY]
> Use early returns (`return null`) for missing data guards, ternary operators (`? :`) for dual-choice branching, and logical AND (`&&`) with explicit boolean guards (`count > 0`) for optional elements.

### Glossary

- [glossary] Conditional Rendering ◼ The ability to render different JSX elements or components depending on whether a condition is true or false.
- [glossary] Early Return ◼ A programming pattern where a function exits early using `return null` when a precondition is not met, skipping subsequent code.
- [glossary] Ternary Operator ◼ The JavaScript operator (`condition ? exprIfTrue : exprIfFalse`) used for inline binary branching in JSX expressions.
- [glossary] Logical AND Operator ◼ The JavaScript operator (`&&`) that evaluates to its right-hand operand if the left-hand operand is truthy, short-circuiting otherwise.
- [glossary] Falsy Zero Trap ◼ The bug where `{count && <Element />}` evaluates to `0` instead of false, causing React to render a literal "0" text node in the DOM.

## Beyond the basics

- **Returning null to prevent rendering**: Returning `null` from a component does not affect whether lifecycle hooks or effects fire, but completely hides the component from the DOM (see [react.dev/learn/conditional-rendering#returning-null-conditionally](https://react.dev/learn/conditional-rendering#returning-null-conditionally)).
- **Avoiding the 0 && JSX trap**: The official React documentation explicitly warns against using numbers on the left side of `&&`, recommending `count > 0` or `Boolean(count)` instead (see [react.dev/learn/conditional-rendering#logical-and-operator-](https://react.dev/learn/conditional-rendering#logical-and-operator-)).
- **Assigning JSX conditionally to a variable**: You can use standard `if/else` statements outside the return statement to assign JSX to a local `let content` variable and project `{content}` in the return block (see [react.dev/learn/conditional-rendering#conditionally-assigning-jsx-to-a-variable](https://react.dev/learn/conditional-rendering#conditionally-assigning-jsx-to-a-variable)).
- **Component keys during conditional switching**: When switching between two different components at the same tree position, React unmounts the old one and mounts the new one; use the `key` prop if you need to reset state explicitly (see [react.dev/learn/preserving-and-resetting-state](https://react.dev/learn/preserving-and-resetting-state)).
- **Pure rendering and conditional branches**: Conditional branches must remain pure functions; never perform side effects or mutate variables inside conditional JSX expressions (see [react.dev/learn/keeping-components-pure](https://react.dev/learn/keeping-components-pure)).

### Summary

**Architectural Takeaways & Decision Matrix**

❒ Declarative Control Flow & Patterns

➔ ALWAYS use standard JavaScript expressions (`if`, `? :`, `&&`) to conditionally render markup declaratively.

➔ NEVER imperatively query the DOM or toggle CSS classes (`element.classList.toggle('hidden')`) to show or hide React UI.

➔ IF a component lacks essential data THEN return `null` early to prevent runtime null-reference errors.

❒ The Falsy Zero Trap & Safety

➔ ALWAYS ensure the left-hand side of a logical `&&` expression is a boolean (`count > 0` or `Boolean(count)`).

➔ NEVER write `{count && <Badge />}` when `count` can be `0`, because React will render a literal "0" string.

➔ IF choosing between two mutually exclusive UI elements THEN use an inline ternary (`condition ? <A /> : <B />`).

**DO THIS:** use explicit boolean comparison to guard optional elements

```jsx right
export default function CommentBadge({ count }) {
  return (
    <div>
      {count > 0 && <span className="badge">{count}</span>}
    </div>
  );
}
```

**DO NOT DO THIS:** use numeric values directly on the left side of logical AND

```jsx wrong
export default function CommentBadge({ count }) {
  return (
    <div>
      {count && <span className="badge">{count}</span>}
    </div>
  );
}
```
