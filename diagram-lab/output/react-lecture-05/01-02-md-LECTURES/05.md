### Literal Text and Broken Image Paths

In standard HTML, text written between opening and closing tags is always treated as a static string. If you write `<h2>authorName</h2>`, the browser displays the literal letters a-u-t-h-o-r-N-a-m-e. Similarly, if you write `<img src="avatarUrl">`, the browser attempts to fetch a file named literally `avatarUrl` from the web server. HTML has no concept of JavaScript memory or local variables.

When a developer declares variables inside a component and writes their identifiers directly into JSX, the markup remains static.

Look at the naive attempt below:

```jsx title="Naive Static JSX"
export default function JournalistProfile() {
  const authorName = 'Clara Foster';
  const avatarUrl = '/authors/clara.jpg';
  return (
    <div>
      <img src="avatarUrl" />  // **WRONG:** requests literal path, breaking **IMAGE**
      <h2>authorName</h2>      // **WRONG:** prints literal word, ignoring **VARIABLE**
    </div>
  );
}
```

When this component runs, the browser displays the literal word "authorName". The image fails to load because the browser requests a file named literally `avatarUrl`.

The JSX compiler follows a strict parsing boundary. When text is enclosed in quotes (`"avatarUrl"`) or placed between tags (`<h2>authorName</h2>`), the compiler emits literal strings: `_jsx("img", { src: "avatarUrl" })`. To tell the compiler to step out of static markup and read JavaScript memory, you must open an evaluation window using curly braces: `{}`.

```html-figure src="figures/05-00-expression-evaluation-window.html" caption="Static JSX treats text and quoted attributes as literals, while curly braces open an inline JavaScript evaluation window."
```

> [!WILD]
> **Why can you not place an if statement inside JSX?** When developers want conditional rendering, they often try writing `{if (isLead) { ... }}` inside their JSX. This triggers a fatal compiler error. Why? Because curly braces accept JavaScript **expressions**, but reject JavaScript **statements**. An expression produces a value that can be passed as an argument to `_jsx()`. A variable, a mathematical calculation, or a ternary operation (`isLead ? 'Lead' : 'Staff'`) all evaluate to a value. An `if` statement or a `for` loop produces no value. It is a control-flow statement. You cannot pass a statement as a function argument. To branch inside JSX, you must use expressions that return values.

> [!TIP]
> **To impress the interviewer:** When asked how curly braces work in JSX, explain that they create an **inline evaluation window**. This window allows you to step out of static markup into live JavaScript execution. Crucially, emphasize that curly braces accept any valid **expression** that produces a value, but reject **statements** like `if` or `for` which produce no value.

### The Curly Brace Evaluation Window and Expressions

In JSX, curly braces `{}` act as an **evaluation window**. Placing curly braces inside text content (`<h2>{authorName}</h2>`) or inside an attribute (`src={avatarUrl}`) instructs the compiler to evaluate the enclosed JavaScript code at runtime. The evaluated value is then projected directly into the rendered output.

Inside the curly brace window, you can write any valid JavaScript expression:

1. **Variables**: Evaluating local identifiers like `{authorName}`.
2. **Inline Arithmetic**: Computing live numbers like `{readMinutes * 60}`.
3. **Template Literals**: Assembling strings like `{`By ${authorName}`}`.
4. **Ternary Expressions**: Evaluating conditional values like `{isSenior ? 'Senior Editor' : 'Staff Writer'}`.

When assigning values to JSX attributes, you face an architectural crossroad between two syntax patterns:

- **Option 1 (The foundational way)**: Pass a static string literal using double quotes (`src="/authors/elena.jpg"`).
- **Option 2 (The modern idiomatic way)**: Pass a dynamic JavaScript variable using curly braces (`src={avatarUrl}`).

First, look at Option 1 using a static string literal:

```jsx title="Option 1: The Foundational Way (src='...') "
export default function JournalistProfile() {
  return (
    <img
      src="/authors/clara.jpg" // Passes static string **LITERAL**
      alt="Clara Foster"      // Static fallback **TEXT**
    />
  );
}
```

In Option 1, the quotes signal a plain string primitive. The compiler passes the string directly to the DOM attribute. This is ideal for static, hardcoded assets. However, it cannot adapt when variables change in memory.

Next, look at Option 2 using the dynamic expression window:

```jsx title="Option 2: The Modern Idiomatic Way (src={...})"
export default function JournalistProfile() {
  const avatarUrl = '/authors/clara.jpg';
  return (
    <img
      src={avatarUrl}     // Evaluates variable in **EXPRESSION**
      alt="Clara Foster" // Static fallback **TEXT**
    />
  );
}
```

In Option 2, the curly braces replace the quotes entirely. Notice that you never write `src="{avatarUrl}"`. Adding quotes around curly braces causes JSX to treat `{avatarUrl}` as a literal string of characters, breaking the link. The curly braces alone establish the evaluation window.

> [!KEY]
> Use quotes `""` for static string literals. Use curly braces `{}` for dynamic JavaScript expressions. Never wrap curly braces in quotes (`"{variable}"`).

To master JavaScript expressions in JSX, we will build a journalist profile card for The National Times. We will construct the feature across four sequential steps: constructing the container shell in `App.jsx`, declaring local variables in `JournalistProfile.jsx`, projecting text variables with curly braces, and evaluating dynamic attributes and inline math.

### Step 1: First, we construct the container shell <App.jsx>

We begin by constructing the application container in `src/App.jsx`. This component provides the outer layout for our newsroom story page. It imports `JournalistProfile` and mounts it declaratively:

```jsx title="App.jsx"
import JournalistProfile from './components/JournalistProfile.jsx';

export default function App() {
  return (
    <div className="story-container">
      <JournalistProfile /> // Mounts profile card at shell **ROOT**
    </div>
  );
}
```

Notice that `App.jsx` simply mounts `<JournalistProfile />`. It does not pass any props or configure any variables. The author data is encapsulated locally inside `JournalistProfile.jsx`.

### Step 2: Next, we declare local editorial variables <JournalistProfile.jsx>

Now we create the component file `src/components/JournalistProfile.jsx`. Inside the function body before the `return` statement, we declare four local JavaScript variables representing the author's identity and story metrics:

```jsx title="JournalistProfile.jsx" startLine="1" continues="bottom"

  const authorName = 'Clara Foster';      // Author name in **MEMORY**
  const avatarPath = '/authors/clara.jpg'; // Path to author **AVATAR**
  const readMinutes = 4;                   // Estimated read time **MINUTES**
  const isSenior = true;                   // Editorial tier **FLAG**
  return (
```

These variables live in standard JavaScript memory. They are calculated every time `JournalistProfile` executes. However, until we write our JSX return statement, these variables exist only as private data within the function scope.

### Step 3: Then, we evaluate variables in text content <JournalistProfile.jsx>

Next, we construct the JSX return statement. We project our string and boolean variables into text content using curly braces. We evaluate `authorName` inside a headline, and use a ternary expression to evaluate the author's editorial title:

```jsx title="JournalistProfile.jsx" startLine="6" continues="both"
    <div className="author-card">
      <h3 className="author-name">{authorName}</h3> // Projects author **NAME**
      <span className="author-role">
        {isSenior ? 'Senior Editor' : 'Staff Writer'} // Evaluates **TERNARY**
      </span>
```

Notice the ternary expression: `{isSenior ? 'Senior Editor' : 'Staff Writer'}`. Because `isSenior` is `true`, the expression resolves to the string 'Senior Editor'. The compiler evaluates the expression and inserts the resulting text into the `<span>`. If we attempted to write an `if` statement here, the compiler would halt with a syntax error.

### Step 4: Finally, we project dynamic attributes and math <JournalistProfile.jsx>

Finally, we complete `JournalistProfile.jsx` by binding our image asset path to the `src` attribute and computing the reading time in seconds using inline arithmetic:

```jsx title="JournalistProfile.jsx" startLine="10" continues="top"
      <img className="author-avatar" src={avatarPath} alt={authorName} />
      <p className="read-metric">{readMinutes * 60} seconds read</p>
    </div>
  );
}
```

Notice what happened on line 11: `{readMinutes * 60}` multiplied 4 by 60 to produce 240. The calculation happens directly inside the JSX evaluation window. You do not need to create an intermediate variable outside the markup. Any expression that produces a value can be evaluated right where it is needed.

### Glossary

- **JSX Evaluation Window**: The syntax construct `{}` that temporarily steps out of static JSX markup to evaluate a JavaScript expression.
- **JavaScript Expression**: Any valid unit of JavaScript code that resolves to a single value, such as a variable, calculation, or function call.
- **JavaScript Statement**: A unit of code that performs an action but produces no return value (`if`, `for`, `while`), forbidden inside JSX curlies.
- **Dynamic Attribute**: An HTML attribute whose value is computed at runtime via curly braces (`src={avatarPath}`) rather than hardcoded in quotes.
- **Ternary Expression**: An inline conditional expression (`condition ? expr1 : expr2`) that evaluates to one of two values, permitted inside JSX curlies.

## Beyond the basics

- **JSX curly braces compiler output**: The expression `{readMinutes * 60}` compiles directly to the function argument `_jsx("p", { children: [readMinutes * 60, " seconds read"] })` (see [react.dev/learn/javascript-in-jsx-with-curly-braces](https://react.dev/learn/javascript-in-jsx-with-curly-braces)).
- **Expressions vs statements in language specifications**: In the ECMAScript specification, expressions evaluate to a value, while statements control execution flow; JSX child positions only accept expressions because function calls require argument values (see [react.dev/learn/javascript-in-jsx-with-curly-braces](https://react.dev/learn/javascript-in-jsx-with-curly-braces)).
- **Objects as JSX children**: React cannot render raw JavaScript objects directly inside text curlies (`{userObject}`); attempting to do so throws a runtime error, requiring you to access primitive properties like `{userObject.name}` (see [react.dev/learn/javascript-in-jsx-with-curly-braces](https://react.dev/learn/javascript-in-jsx-with-curly-braces)).
- **Double curlies for inline style objects**: When applying inline styles in JSX, you write `style={{ color: 'red' }}`; the outer braces open the evaluation window, and the inner braces declare a JavaScript object literal (see [react.dev/learn/javascript-in-jsx-with-curly-braces](https://react.dev/learn/javascript-in-jsx-with-curly-braces)).
- **Boolean and nullish rendering**: React treats `true`, `false`, `null`, and `undefined` as empty values inside curly braces, rendering nothing to the DOM, which enables conditional rendering shortcuts like `{isPublished && <Badge />}` (see [react.dev/learn/conditional-rendering](https://react.dev/learn/conditional-rendering)).

### Summary

**Architectural Takeaways & Decision Matrix**

❒ Evaluation Windows & Text

➔ ALWAYS wrap JavaScript variables in curly braces (`{authorName}`) when rendering dynamic text inside JSX elements.

➔ NEVER write variable names as raw text (`<h2>authorName</h2>`) because JSX treats unbracketed text as literal strings.

➔ IF rendering a conditional value inside JSX THEN use a ternary expression (`{flag ? 'A' : 'B'}`) instead of an `if` statement.

❒ Dynamic Attributes

➔ ALWAYS use curly braces without quotes (`src={avatarUrl}`) when binding dynamic variables to element attributes.

➔ NEVER wrap curly braces in quotes (`src="{avatarUrl}"`) because this passes the literal string `"{avatarUrl}"` to the DOM.

**DO THIS:** evaluate variables and dynamic attributes with curly braces

```jsx right
export default function JournalistProfile() {
  const name = 'Clara';
  const avatar = '/clara.jpg';
  return <img src={avatar} alt={name} />;
}
```

**DO NOT DO THIS:** write literal names or wrap curlies inside quotes

```jsx wrong
export default function JournalistProfile() {
  const name = 'Clara';
  const avatar = '/clara.jpg';
  return <img src="avatar" alt="name" />;
}
```

| ---: | :--- | :--- |
| **Text Output** | Displays literal character strings | Projects live evaluated JavaScript values |
| **Attribute Binding** | Quoted strings: `src="path.jpg"` | Unquoted curlies: `src={avatarUrl}` |
| **Grammar Support** | Static text only | Accepts all expressions (variables, math, ternary) |
| **Statements (`if`, `for`)** | Not applicable | Forbidden: statements produce no return value |
| **Runtime Calculation** | Hardcoded at build time | Evaluated dynamically on every component render |
