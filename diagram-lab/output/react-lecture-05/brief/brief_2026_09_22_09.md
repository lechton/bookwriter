## 1. Problem Statement & Root Cause

In Lecture 13's closing comparison table, the mathematical formula for functional purity was written using LaTeX syntax: `$y = f(x)$:`.
Additionally, across Lectures 08, 12, and 13 (and their pre-lectures), directional flows were authored as `$\rightarrow$` and inequalities as `$\le$`.

Because the lecture publishing pipeline (`src/build-lectures.mjs` → PrinceXML) uses standard web markdown parsing (`marked`) without any LaTeX or MathJax engines, raw dollar signs and backslash commands were rendered verbatim in the HTML and PDF documents (e.g. `$y = f(x):`, `$\rightarrow$`). This made it look like a broken or unrendered math formula.

**Root Causes**:
1. **Instruction Self-Contamination**: Several core skills (`skills/code-blocks/SKILL.md`, `skills/figures/SKILL.md`, `skills/verification/SKILL.md`) had LaTeX math and arrow syntax embedded directly inside their own rules and checklists (e.g. `event trigger $\rightarrow$ state update`, `Title $\rightarrow$ Question...`, `$\le 10$`). This modeled LaTeX syntax to the AI agent during authoring.
2. **Missing Negative Constraint & Pipeline Clarification**: Nowhere in the skills was it stated that the publishing pipeline is a pure HTML/Markdown engine without LaTeX/MathJax support, or that all math expressions must be formatted as inline code spans and directional flows as unicode arrows.
