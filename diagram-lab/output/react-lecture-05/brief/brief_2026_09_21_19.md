# Batch Brief: 2026-09-21-19

## 1. Context & Problem
In the `### Summary` section of lectures, actionable decision rules beginning with `➔` (and category subtitles beginning with `❒`) were getting joined into a single continuous line or swallowed into a preceding subtitle's `<span class="summary-title">`, producing output such as:
`➔ ALWAYS ensure the target DOM container element exists... ➔ IF building a single-page application THEN chain...`
all merged into one line rather than rendering as distinct paragraph elements (`<p class="summary-principle">`).

## 2. Root Cause Analysis
Two interacting factors caused this defect:
1. **Markdown compiler paragraph accumulator**: In `src/build-lectures.mjs`, the helper `starters(l)` inside `parseBlocks` only checked for code fences, headings, list markers, blockquotes, and images. It did not recognize `➔` or `❒`. As a result, the paragraph accumulator `while (i < lines.length && lines[i].trim() && !starters(lines[i]))` consumed adjacent lines starting with `➔` or `❒` into a single `buf` joined by spaces.
2. **Instruction ambiguity**: `skills/lecture-structure/SKILL.md` Section 13 specified that decision rules should be structured under subtitles, but did not explicitly mandate that each `❒ {Subtitle}` heading and each `➔ {DECISION_RULE}` line must be an independent block separated by blank lines above and below.

## 3. The Golden Rule Resolution (Compiler Hardening & Instruction Clarification)
1. **`src/build-lectures.mjs` (`parseBlocks`)**:
   - Added `l.trim().startsWith('➔') || l.trim().startsWith('❒')` to `starters`.
   - Added an explicit check before code fences so any line starting with `❒` or `➔` immediately produces its own `{ t: 'p', text: line.trim() }` block.
2. **`skills/lecture-structure/SKILL.md` Section 13**:
   - Tagged `#2026_09_21_19_group_1`.
   - Mandated that every `❒ {Subtitle}` header and every `➔ {DECISION_RULE}` line must be formatted as an independent paragraph separated by blank lines above and below.
   - Added a canonical proper example showing blank-line separation.
3. **`skills/verification/SKILL.md` Section 18**:
   - Updated checklist item 3 with tag `#2026_09_21_19_group_1` and verification of blank-line block separation.
