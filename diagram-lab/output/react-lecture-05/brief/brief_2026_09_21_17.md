## 1. Context & Problem
In Lectures Q04 and Q05 of `react-lecture-05`, the Section 1 `title="Naive Pattern"` code blocks were authored with zero internal comments. This produced a barren, unbalanced macOS editor window where the entire right-hand speech bubble margin was completely blank.

## 2. Root Cause Analysis
1. **Ambiguous Anti-Pattern Scope in Section 13**:
   `skills/code-blocks/SKILL.md` Section 13 stated that right and wrong blocks must be completely free of comments, and stated that these blocks should be restricted to closing `### Summary` sections "and direct in-body anti-pattern comparisons". The authoring model interpreted any in-body flawed code snippet (like `title="Naive Pattern"`) as an anti-pattern comparison block subject to the zero-comment ban.
2. **Exclusionary Fallacy in Section 08**:
   Section 08 stated: "Banning comments in summary right/wrong blocks does NOT mean stripping comments from implementation steps." Because this exception only mentioned implementation steps (Stage C), the model deduced that Section 1's naive/historical snippets should have their comments stripped.
3. **Phase 1 Blueprint Inheritance**:
   `skills/pre-lecture/SKILL.md` Section 09 mandated pairing `{old solution:}` with a `[code]` block, but did not mandate failure-line comments. The blueprint author omitted comments, and the lecture author faithfully copied the comment-free code under Strict Blueprint Traceability.

## 3. The Golden Rule Resolution (De-Prescription & Pruning)
1. **`skills/code-blocks/SKILL.md` Section 13**:
   Pruned the phrase "and direct in-body anti-pattern comparisons". Explicitly limited the zero-comment rule to tagged `right` and `wrong` fences that sit under directive headers (`**DO THIS:**` / `**DO NOT DO THIS:**`). Clarified that all narrative macOS windows in the body are standard blocks requiring speech bubbles.
2. **`skills/code-blocks/SKILL.md` Section 08**:
   De-prescribed the narrow "implementation steps" phrasing into universal protection for all narrative macOS editor windows, explicitly citing Section 1 naive/historical snippets and Stage C assembly steps.
3. **`skills/pre-lecture/SKILL.md` Section 09**:
   Mandated that blueprint `[code]` blocks for naive/legacy patterns must include inline comments pinpointing the line of friction, syntax error, or failure.
