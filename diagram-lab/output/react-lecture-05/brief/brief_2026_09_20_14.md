The user observed: *"After so much effort and nuance in detail, it feels still hard to read. Can we make it easier to read, overall?"*

An autopsy of this passage revealed five core friction points caused by checklist overfitting:
1. **Eyeball Ping-Pong & Directive Clutter**: The prose acted like a frantic drill sergeant with a laser pointer (*"Notice the function parameters..."*, *"Look at the button click handler on line 6..."*, *"Where does onUpdateHeadline come from? Look back at Step 1..."*, *"Notice what happened..."*). The reader was constantly commanded to jump back and forth across files and fences instead of settling into a reading rhythm.
2. **Syntax Smuggling in Running Prose**: Long, multi-token JavaScript and JSX expressions (`const [headline, setHeadline] = useState(...)`, `<HeadlineViewer headline={headline} onUpdateHeadline={setHeadline} />`, `onClick={() => onUpdateHeadline('...')}`) were crammed directly into running sentences. In PDF and print rendering, this caused awkward line wrapping, hyphenation collisions, and forced the reader's human-language parser to constantly collide with code syntax.
3. **Triple Redundancy**: The reader saw the code in the window, read the right-hand comment (`// **ACTION:** Invokes parent setter...`), and then the prose re-read every line back to them line by line.
4. **Spatial Circuit in Linear Prose**: The Upward Wire / inverse data flow circuit was narrated as a dense paragraph of cross-references, overwhelming working memory.
5. **Authoring vs. Revising Conflict**: When authoring from scratch, focus is on completeness and satisfying invariants. When revising, focus must shift to human cognitive ergonomics, rhythm, and scannability.

## 2. Technical Decisions & Rules Added

To resolve this across the entire curriculum, a dedicated revision skill was created: `skills/lecture-revision/SKILL.md` (`#2026_09_20_14_group_1`).

1. **The Division of Labor (Principle 01)**:
   - Code blocks show runnable syntax.
   - Right-hand comments (`// **DATA FLOW:**`, `// **ACTION:**`, `// **CODE LOGIC:**`) handle line-level execution mechanics.
   - Prose explains the mental model, cause-and-effect relationships, and architectural stakes. Prose is forbidden from merely re-reading code lines.
2. **Zero Syntax Smuggling in Prose (Principle 02)**:
   - Inline code in prose is strictly limited to single identifiers (`headline`, `setHeadline`, `onUpdateHeadline`, `onClick`).
   - Full statements, variable declarations, arrow functions, and JSX tags are permanently banned from running sentences.
3. **Banning Eyeball Ping-Pong (Principle 03)**:
   - Eliminates repetitive imperative commands (*"Look at line X"*, *"Notice the parameter"*).
   - Replaces them with natural cause-and-effect narration (*"When the editor clicks Next Headline, HeadlineViewer doesn't change the text itself..."*).
4. **The 3-Beat Relay Pattern (Principle 04)**:
   - Whenever explaining callbacks or inverse data flow across component boundaries, dense narrative is replaced by a scannable 3-beat relay:
     1. **Beat 1: The Parent owns the truth** (names parent state and setter).
     2. **Beat 2: The Parent shares the trigger** (names prop carrying updater).
     3. **Beat 3: The Child pulls the cord** (names user click, callback invocation, and state update in parent).
   - Closes with the bold architectural term (**inverse data flow**).
5. **The Negative Counterfactual Without Platitudes (Principle 05)**:
   - Enforces concrete developer disaster without academic fluff, closing on symmetric refactoring superpowers.
6. **Figure and Pipeline Synchronization Guardrails (Principle 06)**:
   - Freezes figure tags and mandates strict prop/component name parity.
7. **The 5-Gate Readability Audit (Revision Gate 07)**:
   - Codifies the 5 verification gates (Smuggling, Ping-Pong, Relay, Redundancy, Tired-Reader).
