# Brief 2026-09-21 02: Instruction De-prescription, Curriculum Dependency Law, and Scaffolding Archetype

## Group 1: Instruction de-prescription, curriculum dependency law, and scaffolding archetype (#2026_09_21_02_group_1)

### Philosophy and Defect Origin
During the authoring of Lecture 02 (`#project_setup`: *"Explain how to set up a new React application with Vite, including the directory structure and entry points"*), an architectural defect occurred:
1. **Curriculum Inversion & Premature Syntax Smuggling**: The initial implementation constructed an artificial multi-component widget (`ProjectLauncher`, `ModeSelector`, `RuntimeSummary`) utilizing `useState` and callback props (`onSelectMode`). This violated the fundamental sequence of the React curriculum: hooks like `useState` do not debut until Q16 (`#usestate_basics`), and callback props / inverse data flow do not debut until Q15 (`#props_communication`). In Q02, the student is a newcomer learning project setup, CLI scaffolding, and runtime entry points; forcing them to parse hooks and callback circuits creates severe cognitive overload.
2. **The Rigid Single-Archetype Trap**: A root-cause investigation revealed that the instruction system and build verification script strictly mandated a single pattern for Stage C and Stage D:
   * Stage C was strictly defined as a multi-component hierarchy with Upward Wire callback circuits and negative counterfactuals.
   * Stage D rigidly enforced the exact heading `title="Summary: The Logic of Nested Components"`.
   * When an authoring model encountered Lecture 02, the instructions forced it to invent a multi-component feature tree even though the question asked for project scaffolding, directory structure, and entry points.

### De-Prescription and Remediation Under the Golden Rule
Following the **Golden Rule of De-Prescription** (de-prescribing over-specified constraints rather than piling on new bans), the instruction ecosystem and compiler were upgraded:

1. **Formalizing Two Pedagogical Archetypes**:
   * **Archetype A: Component-Driven Practical Assembly**: Used for lectures that build modular UI features from multiple components. Features top-down component nesting, Upward Wire callback circuits, Negative Counterfactual proofs, and `title="Summary: The Logic of Nested Components"`.
   * **Archetype B: Project Scaffolding & System Architecture Deconstruction**: Used for lectures covering project setup, tooling, build configuration, and framework entry points (e.g. Q02, Q06). Features deconstruction of scaffolding CLI commands (`npm create vite@latest`), configuration manifests (`package.json`, `vite.config.js`), physical entry points (`index.html`, `src/main.jsx`), starter components (`src/App.jsx`), and `title="Summary: Project Architecture & File Hierarchy"`.

2. **The Curriculum Dependency Invariant**:
   * Strictly forbids premature syntax smuggling.
   * No `useState` before Q16.
   * No callback props / inverse data flow before Q15.
   * No `useEffect` before Q35.
   * Code examples must reflect authentic project setup reality (Vite CLI flags, ESM script tags, `createRoot`, and starter counters) rather than fabricated multi-component toys.

3. **Compiler Flexibility in `src/build-lectures.mjs`**:
   * Relaxed the Stage D panel title regex from strictly requiring `Summary: The Logic of Nested Components` to also accepting `Summary: Project Architecture & File Hierarchy`, `Summary: Project Scaffolding & File Hierarchy`, and `Summary: The Scaffolded File Hierarchy`.
