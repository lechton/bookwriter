# Decision Brief: Universal Native Element Styling Law and Redundant Micro-Formatting Ban (#2026_09_22_07_group_1)

**Date**: 2026-09-22
**Rule Tag**: `#2026_09_22_07_group_1`
**Components Affected**: `skills/ui-panels/SKILL.md` (Section 02), `src/component-explorer.mjs`, `src/lecture.css`, `skills/RULE-TAGS.md`

---

## 1. Problem Statement & Root Cause

In Lecture 10, the element descriptor `[elem:a.paywall-link: Subscribe for Full Access]` rendered as plain dark body text with no hyperlink color, no underline, and no pointer cursor. In Lecture 02, the author was forced to nest `[btn: Refresh Feed]` inside `[elem:button: ...]` (`[elem:button: [btn: Refresh Feed]]`) to make the button look like a button.

**Root Causes**:
1. In `skills/ui-panels/SKILL.md`, Section 02 only defined a narrow "Semantic Typography Contract" covering `h1`, `h2`, `h3`, and `blockquote`. It lacked the overarching architectural mandate that **all** standard semantic HTML elements (`a`, `button`, `input`, `code`) must automatically inherit their authentic native visual appearance.
2. In `src/lecture.css`, typography rules existed only for `[data-elem^="[h1"]` through `[h3` and `blockquote`. There was zero styling for links (`.ui-elem.ui-tag-a`), buttons (`.ui-elem.ui-tag-button`), inputs (`.ui-elem.ui-tag-input`), or code (`.ui-elem.ui-tag-code`).
3. In `src/component-explorer.mjs`, the compiler did not extract the base HTML tag from `[elem:tag...]` to apply element-specific utility classes to the `.ui-elem` container.

---

## 2. Changes Applied

### A. Skill Invariant (`skills/ui-panels/SKILL.md`)
- Replaced the narrow *Semantic Typography Contract* with the **Universal Native Element Styling Law**:
  - If an element is declared with a semantic HTML tag in `[elem:tag...]`, it MUST automatically inherit the authentic visual appearance of that native element without requiring manual micro-formatting wrappers or redundant nested sub-tags.
  - Headings (`h1-h3`) and pull quotes (`blockquote`) automatically render in authentic editorial serif typography.
  - Links (`a`, `a.class`) render as clickable blue underlined hyperlinks (`color: #0284c7; text-decoration: underline`).
  - Buttons (`button`, `button.class`) render as interactive button pills (`background: #0891b2; color: #ffffff`).
  - Inputs (`input`, `input.class`) render with inset form field styling.
  - Code blocks (`code`, `pre`) render with mono styling.
  - Authors write clean semantic markup (e.g. `[elem:a.paywall-link: Subscribe]`, `[elem:button: Refresh Feed]`) and must never wrap redundant sub-tags inside (strictly forbidding `[elem:button: [btn: Refresh Feed]]`).

### B. Compiler Upgrades (`src/component-explorer.mjs`)
- `renderUiElem` extracts the base HTML tag (`baseTagMatch = tag.match(/^\[([a-z0-9]+)/i)`) and attaches `ui-tag-${baseTag}` to the `.ui-elem` container.
- If `baseTag === 'button'` and no button wrapper was explicitly provided, it wraps the content in `<span class="surface-ui-btn">` automatically.
- If `baseTag === 'input'` and no input wrapper was explicitly provided, it wraps the content in `<div class="surface-ui-input"><span class="surface-ui-input-placeholder">` automatically.

### C. Stylesheet Upgrades (`src/lecture.css`)
- Added `.ui-elem.ui-tag-a .ui-elem-content`, `.ui-elem[data-elem^="[a."] .ui-elem-content`, etc. with vivid link color (`#0284c7`), underline (`text-decoration: underline; text-underline-offset: 3px; font-weight: 600`), and hover state (`#0369a1`).
- Added `.ui-elem.ui-tag-code .ui-elem-content` and `.ui-elem[data-elem^="[code"] .ui-elem-content` with mono font, padding, and subtle code background.
- Cleaned up redundant `[btn: Refresh Feed]` markup in `01-02-md-LECTURES/02.md`.
