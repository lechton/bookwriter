# Brief 2026-09-21 25: Lecture Revision Comment Harmonization and Verdict Tag Protection

## Group 1: Lecture Revision Comment Harmonization and Verdict Tag Protection (#2026_09_21_25_group_1)

### Philosophy and Defect Origin
When revising production lectures into accessible explanations for junior developers, `skills/lecture-revision/SKILL.md` Section 06 previously instructed authors to:
> `write clean, lowercase, natural English speech bubbles without uppercase category tags like CODE LOGIC: or DATA FLOW:`

This phrasing created an unintentional inter-skill conflict with `skills/code-blocks/SKILL.md` Section 12 (**The Broken Code & Trap Verdict Mandate**, `#2026_09_21_18_group_1`), which strictly requires:
> `Whenever a line of code is flat-out WRONG (illegal syntax, fatal compiler crashes, reserved keyword collisions, unclosed tags, returning multiple root siblings, runtime gotchas, or anti-pattern traps), the comment MUST lead with the verdict tag // **WRONG:** [consequence with uppercase bold **KEYWORD**].`

Because of the word `"lowercase"`, revision agents fell into the Exclusionary Fallacy: they interpreted the rule as forbidding any uppercase text in comments, which stripped the `// **WRONG:**` verdict tag and lowercase-flattened load-bearing uppercase bold keywords from Section 1 naive and broken code blocks (such as in Lecture 4 and Lecture 5).

### The Golden Rule Fix
Under `#2026_09_21_25_group_1`, we prune the over-broad `"lowercase"` constraint from `skills/lecture-revision/SKILL.md` and explicitly harmonize the rule with `skills/code-blocks/SKILL.md`:
1. "Tag-free" refers strictly to bureaucratic category taxonomy labels (`CODE LOGIC:`, `DATA FLOW:`, `CLIENT API:`).
2. Broken code lines, syntax errors, and runtime gotchas in Section 1 naive blocks preserve the leading `// **WRONG:**` verdict tag and single uppercase bold keyword.
3. Standard working code in Stage C steps and pedagogical crossroads continues to use clean, natural English comments with a single load-bearing keyword in uppercase bold.
