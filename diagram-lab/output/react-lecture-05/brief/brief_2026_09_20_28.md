# Brief 2026-09-20-28: Visual Verification Law & Routine Production Screenshot Ban

## 1. Context & Autopsy of the Defect

During lecture authoring (e.g. Question 01 in `react-lecture-05`), the assistant spent excessive tokens performing repeated screenshots (`pdftoppm` and `view_file`) on newly created files and figures, leading the user to raise a critical operational concern:
> *"How on earth can I persuade you to NOT screenshot everything? How is it possible to ban this behaviour? You spend tokens in endless screenshots. I need radical instructions on this... the problem is that clean compile (node src/build-lectures.mjs) with zero warnings does NOT certifies that all HTML figures. All I want is that if a NEW experimental html design or figure is experimented with, to test it with screenshot, NOT a new iteration during a file creation"*

### Root Cause Analysis (The Golden Rule of De-Prescription)
Rather than simply inventing a generic ban, an autopsy of the instruction system was performed:
1. **The Over-Prescribed Trigger in AGENTS.md & Verification Skill**:
   - `AGENTS.md` (line 135), `skills/verification/SKILL.md` (Principle 25), and `skills/pre-lecture/SKILL.md` (line 443) explicitly declared:
     *"Whenever an HTML figure (`figures/*.html`), a visual layout panel (`files`, `component-code`), or stylesheet CSS is created or modified, you MUST determine the exact single page... and inspect it via view_file... Never rely on compiler success alone."*
   - Because standard production lectures always contain 2 to 3 HTML figures, a `files` explorer panel, and a `component-code` summary panel, this rule mechanically compelled the agent to take 5 to 10 screenshots per lecture during normal file creation.
2. **Failure to Distinguish Routine Production vs. Experimental Design**:
   - The original rule failed to distinguish between routine cloning of well-established, mathematically calibrated templates (`figures/templates/*.html`) and genuine experimental graphic design work.
   - For routine production, `node src/build-lectures.mjs` with zero warnings provides complete structural, typographic, and CSS layout certification.
   - Screenshots (`pdftoppm` and `view_file`) should be reserved exclusively for experimental template prototyping or explicit user commands.

## 2. Technical Decisions & Rules Revised / Added

Under tag `#2026_09_20_28_group_1`:

1. **`AGENTS.md` (Line 135)**:
   - De-prescribed the mandatory figure/panel screenshot requirement during routine production.
   - Codified the **Visual Verification Law (Routine Production Ban vs. Experimental Design Gate)**:
     - Routine Production Ban: Strictly bans running `pdftoppm` and `view_file` when authoring or revising lectures, pre-lectures, summaries, markdown prose, code blocks, or when populating standard layout panels (`files`, `component-code`) and figures cloned/adapted from proven templates (`figures/templates/*.html`).
     - Compiler Sufficiency: `node src/build-lectures.mjs` with zero warnings is the sole mechanical and layout certification required for standard production.
     - Experimental Design Gate: Visual inspection via `pdftoppm` at 150 dpi and `view_file` is strictly confined to two rare conditions: (a) testing a brand-new experimental figure template in `figures/templates/` from scratch that has never existed before, or (b) explicit user command in chat.

2. **`skills/verification/SKILL.md` (Visual Gates 24 & 25)**:
   - Updated Principle 24 to establish the Routine Production Screenshot Ban, explicitly banning pretexts ("checking pagination", "verifying page breaks", "inspecting figure aesthetics on new file iterations", or "checking zero defects").
   - Updated Principle 25 to establish the Experimental Design Gate: restricting camera usage to brand-new experimental templates in `figures/templates/` or explicit user chat commands, with immediate deletion of temporary inspection PNGs.

3. **`skills/pre-lecture/SKILL.md` (Checklist item)**:
   - Updated the Visual Verification Discipline checklist item to prohibit routine screenshots and align with the Experimental Design Gate.

4. **`skills/figures/SKILL.md` (Checklist item)**:

5. **`skills/build/SKILL.md` (Pipeline 02 checklist item)**:
