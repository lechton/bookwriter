# Q179: Legacy ReactDOM.hydrate and ReactDOM.render Removal
* **Topic Tag**: #legacy_hydrate | LEGACY (Server)
* **Interview Question**: *What did ReactDOM.render and ReactDOM.hydrate do, and why were they removed?*
* **Core Truth**: ReactDOM.render and ReactDOM.hydrate were synchronous root-mounting APIs tied to a legacy synchronous reconciler that could not support concurrent features, selective hydration, or streaming SSR, necessitating their complete removal in favor of createRoot and hydrateRoot.
* **The Friction**: An old legacy news widget at The National Times continues to use `ReactDOM.hydrate(element, container)` in React 18, generating console deprecation warnings; when developers attempt to add `useTransition` and Suspense streaming to the page, the widget fails to hydrate selectively, freezing the page during render spikes.
* **The Mechanism**: ReactDOM.hydrate(element, container, [callback]) (deprecated/removed): synchronously traversed the entire container DOM and attached event listeners in a single un-interruptible pass; `ReactDOMClient.hydrateRoot(container, element, [options])`: returns a modern `HydrationRoot` instance configured for concurrent rendering and selective hydration.
* **Under the Hood**: Root Fiber architecture transition: the legacy `hydrate` API created a legacy `RootTag` with synchronous priority lanes only, preventing the scheduler from yielding; `hydrateRoot` initializes a `ConcurrentRootTag` Fiber root, enabling React to split hydration into prioritized micro-tasks, hydrate clicked components out-of-order, and coordinate with streaming SSR markers.
* **The Code Experiment**:
  * *Naive*: Keeping `ReactDOM.hydrate(<App />, document.getElementById('root'))` in legacy entrypoints, disabling React 18+ concurrent hydration capabilities and triggering deprecation errors.
  * *React*: Migrating to `hydrateRoot(document.getElementById('root'), <App />)`, unlocking automatic selective hydration, concurrent transitions, and seamless integration with streaming SSR chunks.
* **Scope Boundary**: Do not cover the full migration walkthrough of a full-stack app (covered in Q180); focus strictly on the historical roles of `ReactDOM.render` and `ReactDOM.hydrate`, the legacy synchronous root architecture, the deprecation warnings, and why `createRoot`/`hydrateRoot` were architecturally necessary.
