# Q55: Labeling Custom Hooks with useDebugValue
* **Topic Tag**: `#use_debug_value` | `❱❱ MORE`
* **Interview Question**: *How do you label a custom hook's internal state in DevTools?*
* **Core Truth**: `useDebugValue` provides custom, human-readable labels for custom hooks inside React Developer Tools, with an optional formatting function to defer expensive string formatting until DevTools is actually open.
* **The Friction**: A team creates complex custom hooks like `useArticleSubscription(id)` and `useNetworkStatus()`. When inspecting components in React DevTools, the hook appears as an anonymous, unhelpful stack of raw `State` and `Effect` rows, forcing developers to waste time guessing which state belongs to which hook.
* **The Mechanism**: The `useDebugValue` hook (`useDebugValue(isOnline ? 'Online' : 'Offline')`). For expensive formatting (e.g. date formatting or serialization), pass a formatting function as the second argument: `useDebugValue(date, d => d.toDateString())`.
* **Under the Hood**: DevTools inspection protocol: `useDebugValue` has zero impact on runtime behavior or the DOM; the second argument formatter function is only invoked when React DevTools is actively inspecting the component, avoiding performance overhead in production.
* **The Code Experiment**:
  * *Naive*: Leaving complex custom hooks unlabeled, forcing developers to click through multiple anonymous state rows in DevTools.
  * *React*: Adding `useDebugValue(status, s => `Sync: ${s.state} (${s.latency}ms)`)` inside a `useLiveWire` custom hook for instant clarity in React DevTools.
* **Scope Boundary**: Focus strictly on using `useDebugValue` in custom hooks and its deferred formatting variant. Emphasize that it is for shared libraries and complex debugging, not everyday components.
