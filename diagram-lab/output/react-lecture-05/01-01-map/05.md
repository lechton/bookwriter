# Q05: JavaScript Expressions in JSX with Curly Braces
* **Topic Tag**: `#jsx_expressions` | `❱ CORE`
* **Interview Question**: *How do you use JavaScript expressions inside JSX with curly braces?*
* **Core Truth**: Curly braces `{}` establish an inline evaluation window inside JSX that steps out of static markup into live JavaScript execution, accepting any valid expression that produces a value.
* **The Friction**: A developer declares headline, author, and image URL variables in their script. They write `<h2>headline</h2>` and `<img src="avatarUrl" />`. The browser renders the literal word "headline" and breaks the image link because static JSX cannot read JavaScript variables without an explicit evaluation bridge.
* **The Mechanism**: The JSX evaluation window `{}`. Placing curly braces in text content (`<h2>{headline}</h2>`) or attributes (`src={avatarUrl}`) projects JavaScript runtime values directly into the rendered output.
* **Under the Hood**: Expressions vs Statements in compiler grammar: curly braces accept expressions that evaluate to a value (variables, ternary operations, template literals, function calls) but reject statements (`if`, `for`, `while`, `function`) which produce no value.
* **The Code Experiment**:
  * *Naive*: Writing literal variable names inside tags or attempting to embed an `if` statement directly inside JSX curlies (`{if (admin) ...}`).
  * *React*: Single component declaring local variables (`headline`, `readTime`, `avatarUrl`) and cleanly projecting them into text and dynamic attributes via `{}`.
* **Scope Boundary**: Focus on evaluating local variables, math expressions, and dynamic attributes within a single component. Do not introduce component props (passing across boundaries) or state hooks.
