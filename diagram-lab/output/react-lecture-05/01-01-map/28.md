# Q28: Thinking in React: The 5-Step Process
* **Topic Tag**: `#thinking_in_react` | `❱ CORE`
* **Interview Question**: *What is the step-by-step process for building a UI in React?*
* **Core Truth**: "Thinking in React" is a structured 5-step methodology: (1) break the UI into a component hierarchy, (2) build a static version without state, (3) identify the minimal, complete representation of UI state, (4) identify where state should live, and (5) add inverse data flow.
* **The Friction**: An engineer handed a Figma mockup immediately starts writing event handlers and `useState` calls at random. They end up with duplicated state, tangled prop passing, and a brittle codebase that requires massive rewrites before even completing the first feature.
* **The Mechanism**: The canonical 5 steps: Step 1 (Hierarchy sketch), Step 2 (Static JSX with props only), Step 3 (Minimal state audit: is it from props? does it change? is it derived?), Step 4 (State ownership: find common parent), Step 5 (Callbacks for user actions).
* **Under the Hood**: Mental discipline of declarative software engineering: separating the static structural model from dynamic runtime state eliminates premature complexity and prevents redundant state synchronization bugs.
* **The Code Experiment**:
  * *Naive*: Jumping straight into code by mixing state, network calls, and UI in a single unstructured component file.
  * *React*: Walking through the 5 steps to build a `NewsroomDashboard`: decomposing into `SearchBar`, `EditionToggle`, and `ArticleTable`, defining minimal state (`query`, `edition`), and connecting callbacks.
* **Scope Boundary**: Focus on the comprehensive architectural thought process and synthesis of Q1–Q27 concepts. Do not introduce advanced routing or global state managers.
