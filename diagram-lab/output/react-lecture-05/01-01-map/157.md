# Q157: Hybrid Architecture: Mixing Rendering Strategies in One Application
* **Topic Tag**: #rendering_models | ❱❱ MORE (Server)
* **Interview Question**: *How do you mix rendering strategies inside one app?*
* **Core Truth**: Production web applications achieve optimal performance by combining static prerendering, streaming SSR, and client-side rendering within a single routing hierarchy based on per-route freshness and personalization requirements.
* **The Friction**: The engineering team at The National Times debates whether to make the entire publication static or fully dynamic; treating the app as all-or-nothing forces them into either stale breaking news feeds or bankrupting server bills on static editorial archives.
* **The Mechanism**: Route-level rendering matrix: (1) Static Prerendering: marketing pages, terms of service, evergreen articles; (2) Streaming SSR: live election blogs, breaking news feeds, search results; (3) Pure CSR: reader account settings, internal subscriber dashboards.
* **Under the Hood**: Routing layer coordination: modern meta-framework routers configure rendering strategies per route; navigations between static, streaming, and client routes seamlessly reuse shared layouts without full document reloads.
* **The Code Experiment**:
  * *Naive*: Forcing a single global rendering mode across all 50 distinct routes of a major news publication.
  * *React*: Configuring route-level rendering strategies: exporting static prerenders for /opinion/[slug], streaming SSR for /live/[event], and client-only rendering for /account/billing.
* **Scope Boundary**: Focus on architectural route composition, mixing rendering models in a single app, and selecting strategies per route.
