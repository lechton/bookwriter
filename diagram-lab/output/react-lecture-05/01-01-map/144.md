# Q144: Metadata Precedence and Conflict Resolution: Titles, Styles, and Scripts
* **Topic Tag**: #document_metadata | ❱❱ MORE (Server)
* **Interview Question**: *How does precedence decide which title, stylesheet, or script wins?*
* **Core Truth**: React 19 resolves document metadata conflicts by DOM tree depth and explicit precedence attributes, ensuring nested page titles override parent layout titles and stylesheets load in predictable cascade order.
* **The Friction**: The root layout renders <title>The National Times</title>, while an opinion piece renders <title>The Future of AI - Opinion</title>; on navigation, the browser tab randomly flips between the two, or custom layout stylesheets are overridden by un-ordered widget styles.
* **The Mechanism**: Precedence rules: (1) <title>: the deepest rendered <title> in the component tree wins; (2) <link rel="stylesheet" precedence="default" />: the precedence string groups and orders stylesheets in <head> (e.g. precedence="high" vs precedence="low"), preventing CSS cascade bugs.
* **Under the Hood**: The Head Insertion Manager: React tracks hoisted tags in an internal registry; for stylesheets with the same precedence, React inserts them in insertion order, but guarantees higher precedence stylesheets appear later in the <head> to maintain CSS cascade priority.
* **The Code Experiment**:
  * *Naive*: Leaving <link rel="stylesheet"> tags without precedence, allowing async components to inject CSS in arbitrary order and break layout cascade rules.
  * *React*: Assigning precedence="editorial-base" to design system CSS and precedence="article-theme" to section styles, guaranteeing deterministic CSS cascading.
* **Scope Boundary**: Focus on metadata precedence rules, deep title overrides, and stylesheet precedence ordering. Do not re-explain basic metadata hoisting from Q121.
