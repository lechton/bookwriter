# Q57: Skipping Re-Renders with React.memo
* **Topic Tag**: `#memo` | `❱❱ MORE`
* **Interview Question**: *When should you wrap a component in React.memo, and when does it fail to skip re-renders?*
* **Core Truth**: `React.memo` is a higher-order component that skips re-rendering a component if its new props are shallowly equal (`Object.is`) to its previous props; it fails to skip re-renders whenever callers pass fresh object, array, or function references.
* **The Friction**: A newsroom `ComplexInteractiveChart` renders 5,000 SVG data points. Typing in an unrelated search box on the same page re-renders the parent, causing the chart to freeze for 120ms. The developer wraps the chart in `React.memo`, but it *still* re-renders on every keystroke because the parent passes `style={{ color: 'red' }}` and `onClick={() => {}}`.
* **The Mechanism**: `React.memo(Component, arePropsEqual?)`. React compares each prop using `Object.is`. To successfully bail out of rendering, all props (primitives, objects, functions) must maintain stable reference identity across parent renders.
* **Under the Hood**: Shallow prop comparison: `React.memo` loops over previous and next props objects; primitive values (`'breaking'`, `42`) compare by value, but inline objects `{}`, arrays `[]`, and functions `() => {}` create new references on every render, evaluating `Object.is(prev, next)` to `false`.
* **The Code Experiment**:
  * *Naive*: Wrapping a component in `React.memo` while passing inline functions and inline object literals, completely defeating the memoization.
  * *React*: Wrapping an expensive `StockChart` in `React.memo` and passing stable primitive props, successfully skipping chart re-renders when parent state updates.
* **Scope Boundary**: Focus on `React.memo`, its shallow comparison semantics, and identifying why unstable prop references break memoization. Do not introduce `useMemo` (Q58) or `useCallback` (Q59) implementations.
