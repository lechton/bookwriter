# Q02: Project Scaffolding: Build Tools vs Full-Stack Frameworks
* **Topic Tag**: `#project_setup` | `❱ CORE`
* **Interview Question**: *How do you create and run a new React project, and how do you choose between a framework and a build tool?*
* **Core Truth**: React requires a build tool to compile JSX into browser-compatible JavaScript; standalone client build tools (Vite) serve single-page apps via native browser ESM, while full-stack frameworks (Next.js/Remix) provide server runtimes for pre-rendered HTML and SEO.
* **The Friction**: The official documentation recommends full-stack frameworks, but your newsroom team only needs an internal article dashboard. Choosing a framework forces unnecessary server hosting costs, maintenance, and complex server configurations for a client-only widget.
* **The Mechanism**: Vite project scaffolding (`npm create vite@latest`). It transforms JSX on demand during local development and bundles static assets for production deployment on cheap static CDNs.
* **Under the Hood**: Why Create React App was slow (monolithic Webpack bundling before server boot), and how Vite leverages native browser ES Modules (`<script type="module">`) with `esbuild` pre-bundling for instant cold starts.
* **The Code Experiment**:
  * *Naive*: Legacy CRA `npm start` crawling 500 files into memory, freezing local development.
  * *React*: Vite project deconstruction (`package.json`, `vite.config.js`, `index.html` at root, `main.jsx`, `App.jsx`).
* **Scope Boundary**: Focus strictly on the toolchain decision and project file roles. Do not write complex component state, routing, or database connections.
