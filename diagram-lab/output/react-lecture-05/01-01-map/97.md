# Q97: Legacy Lifecycles: Mount, Update, Unmount, and UNSAFE Methods
* **Topic Tag**: #legacy_lifecycles | LEGACY
* **Interview Question**: *What were componentDidMount, componentDidUpdate, and componentWillUnmount, and why were some renamed UNSAFE?*
* **Core Truth**: Class lifecycle methods split synchronization by calendar phase (componentDidMount, componentDidUpdate, componentWillUnmount); pre-commit lifecycles (componentWillMount, componentWillReceiveProps, componentWillUpdate) were renamed UNSAFE_ because they break under concurrent rendering.
* **The Friction**: During a migration of a legacy news widget at The National Times, a developer encounters componentWillReceiveProps(nextProps); updating state inside this method causes race conditions and memory leaks when upgrading to React 18/19, but the developer does not know what replaced it.
* **The Mechanism**: Mapping lifecycles to useEffect: componentDidMount (effect with []), componentDidUpdate (effect with [deps]), componentWillUnmount (effect cleanup function). Understand why componentWillMount, componentWillReceiveProps, and componentWillUpdate received UNSAFE_ prefixes in React 16.3.
* **Under the Hood**: Non-idempotent pre-commit execution: in concurrent rendering, React can begin rendering, pause, abort, and restart; pre-commit lifecycles ran multiple times before commit, so if they contained side effects (like data fetches or state mutations), concurrent rendering triggered duplicated requests and corrupted state.
* **The Code Experiment**:
  * *Naive*: Using UNSAFE_componentWillReceiveProps to copy props into state, causing desynchronization and concurrent hazards.
  * *React*: Refactoring a class component's split lifecycle methods (componentDidMount, componentDidUpdate, componentWillUnmount) into a single cohesive useEffect with a cleanup function.
* **Scope Boundary**: Focus on the history, purpose, and hazards of legacy lifecycle methods, why UNSAFE_ was added, and how to map them to useEffect. Do not introduce getDerivedStateFromProps or getSnapshotBeforeUpdate beyond passing mentions.
