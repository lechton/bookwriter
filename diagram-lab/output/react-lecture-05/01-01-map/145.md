# Q145: Resource Discovery: preload vs preinit for Fonts, Styles, and Scripts
* **Topic Tag**: #preloading | ❱❱ MORE (Server)
* **Interview Question**: *preload versus preinit: warming a fetch versus loading and executing?*
* **Core Truth**: preload initiates an early background download of a resource for later use, while preinit downloads and immediately executes or applies the resource (such as evaluating a critical script or inserting a stylesheet into the cascade).
* **The Friction**: A developer at The National Times calls preload('/css/theme.css', { as: 'style' }) expecting the page styles to apply, but the page renders unstyled; another calls preinit('/fonts/headline.woff2'), which is an invalid operation; the team is confused by the distinct roles of the two APIs.
* **The Mechanism**: preload vs preinit: (1) preload(href, { as }): used for fonts (as: 'font'), images (as: 'image'), and fetch data (as: 'fetch') to warm browser cache; (2) preinit(href, { as: 'style' | 'script' }): used for critical stylesheets and scripts that must be immediately parsed and applied.
* **Under the Hood**: Emitted HTML tags: preload outputs <link rel="preload" href="..." as="..." />, which tells the browser networking layer to prioritize the download without DOM insertion; preinit outputs <link rel="stylesheet" href="..." /> or <script src="..." async />, immediately binding the resource to the page.
* **The Code Experiment**:
  * *Naive*: Using preload on a stylesheet without ever linking it as a stylesheet, leaving the page completely unstyled despite fetching the CSS.
  * *React*: Using preinit('/styles/article.css', { as: 'style', precedence: 'high' }) for critical layout CSS, and preload('/fonts/headline.woff2', { as: 'font', type: 'font/woff2' }) for web fonts.
* **Scope Boundary**: Focus on the functional differences between preload and preinit, appropriate resource types for each, and emitted HTML tags.
