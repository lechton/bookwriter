# Q69: Loading Boundaries with Suspense
* **Topic Tag**: `#suspense` | `❱❱ MORE`
* **Interview Question**: *How does Suspense display fallbacks, and where should boundaries sit?*
* **Core Truth**: `<Suspense>` coordinates asynchronous loading by catching thrown promises from its subtree and displaying a fallback UI until the promise resolves, allowing parts of the page to paint independently without freezing the whole layout.
* **The Friction**: The National Times homepage has a fast header, a fast breaking news strip, and a slow stock ticker that takes 3 seconds to fetch data. Without Suspense boundaries, either the entire page stays blank for 3 seconds or every widget must implement its own messy `if (loading) return <Spinner />` logic.
* **The Mechanism**: The `<Suspense fallback={<Skeleton />}>` component. Wrap slow or asynchronous components in Suspense boundaries. React renders the fallback UI for the suspended subtree while committing the rest of the page to the screen immediately.
* **Under the Hood**: Promise throwing and catching protocol: when a component suspends, it throws a Promise during the render phase; the nearest ancestor Suspense boundary catches the promise, attaches a `.then()` listener, renders the fallback, and resumes rendering the suspended component when the promise resolves.
* **The Code Experiment**:
  * *Naive*: A single monolithic page that either blocks the entire screen while data loads or scatters inconsistent loading spinners across every card.
  * *React*: Wrapping `<SlowStockTicker>` in its own `<Suspense fallback={<TickerSkeleton />}>`, allowing the news feed to appear instantly while the ticker loads independently.
* **Scope Boundary**: Focus on the `<Suspense>` component, fallback coordination, and boundary placement strategy. Do not delve into React Server Components (Part Two / Q101+).
