# Q17: Trigger, Render, and Commit
* **Topic Tag**: `#render_and_commit` | `❱ CORE`
* **Interview Question**: *What are the trigger, render, and commit phases of the React lifecycle, and what runs in each?*
* **Core Truth**: React updates the user interface through a rigorous three-phase cycle: Triggering a render (initial mount or state change), Rendering (calling component functions to generate virtual JSX), and Committing (surgically writing differences to the physical DOM).
* **The Friction**: Developers often believe calling `setState` immediately modifies DOM elements or that "rendering" means painting pixels on the screen. This misunderstanding leads to reading stale DOM dimensions mid-handler, writing race conditions, or fearing that frequent component renders will cause expensive browser reflows.
* **The Mechanism**: The 3-phase engine rhythm: Phase 1: Trigger (initial mount via `createRoot` or state update via setter); Phase 2: Render (React invokes the component function, obtaining a new React element tree; pure calculation, zero DOM changes); Phase 3: Commit (React applies the minimal necessary mutations to the physical DOM using `appendChild` or `node.nodeValue`, followed by browser paint).
* **Under the Hood**: The distinction between React rendering (calling JavaScript functions to compute the virtual tree) and browser painting (calculating layout and drawing pixels); why React batches and separates render from commit to keep UI responsive and prevent partial DOM tearing.
* **The Code Experiment**:
  * *Naive*: Assuming `setCount(5)` immediately changes `document.getElementById('count').textContent` on the next line of code.
  * *React*: Tracing a `LikeCounter` button through Trigger (click invokes `setLikes`), Render (`LikeCounter()` executes and returns JSX), and Commit (React updates only the specific text node in the DOM).
* **Scope Boundary**: Focus strictly on the 3 distinct phases (Trigger, Render, Commit) and their operational separation. Do not delve into concurrent priority lanes or Fiber workLoop scheduling (Q66, Q78).
