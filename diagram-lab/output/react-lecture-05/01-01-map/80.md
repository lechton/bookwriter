# Q80: Derived State Patterns vs State Mirroring Anti-Patterns
* **Topic Tag**: `#derived_state_patterns` | `❱❱❱ ADVANCED`
* **Interview Question**: *How do you derive values during render, and when is adjusting state during render legal?*
* **Core Truth**: Mirroring props in state (`useState(props.user)`) is an anti-pattern that creates stale data synchronization bugs; values should be derived directly during render, or when truly necessary, adjusted during render using specific guarded state-adjustment patterns.
* **The Friction**: A `UserProfile` component receives `props.user` and copies it into `const [name, setName] = useState(props.user.name)`. When the parent updates `props.user` to a different user, the child component does not re-run `useState` initializers, leaving the old user's name displayed on screen forever.
* **The Mechanism**: The two sanctioned patterns: Pattern 1 (Derive during render: `const fullName = `${props.user.first} ${props.user.last}``); Pattern 2 (Key reset: `<UserProfile key={props.user.id} user={props.user} />`). If state must adjust to props, do it during render with a conditional guard (`if (prevId !== props.id) { setPrevId(props.id); setSelection(null); }`).
* **Under the Hood**: Adjusting state during render: calling a state setter directly in the component body *during* render (guarded by a condition) causes React to immediately restart the render pass with the new state before committing to the DOM, avoiding an extra paint or effect waterfall.
* **The Code Experiment**:
  * *Naive*: Copying props into `useState` and writing a `useEffect` that listens to `[props.user]` to call `setName`, causing unnecessary double renders and visual flashes.
  * *React*: Deriving computed properties on the fly during render, and using the `key` prop on `<UserProfile key={user.id} />` to automatically reset local draft state when switching users.
* **Scope Boundary**: Focus on the architectural hazards of prop mirroring, the rules of in-render state adjustment, and the superiority of derived state and `key` resets.
