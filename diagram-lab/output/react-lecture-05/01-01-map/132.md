# Q132: The Dual Module Graphs: Server and Client Dependency Topologies
* **Topic Tag**: #server_graph | ❱❱ MORE (Server)
* **Interview Question**: *What are the two module graphs, and how do they reference each other?*
* **Core Truth**: Modern React applications compile into two separate module graphs—the Server Graph and the Client Graph—that execute in different environments and communicate exclusively through serialized reference IDs and network streams.
* **The Friction**: An engineer at The National Times tries to import a Server Component into a Client Component to render a live news feed inside an interactive modal; the build fails with cryptic bundler errors because circular or cross-boundary imports violate the topology of the dual module graphs.
* **The Mechanism**: Graph topology: (1) Server Graph: contains Server Components, server utilities, and database drivers; references Client Components via Client References; (2) Client Graph: contains Client Components, DOM utilities, and browser bundles; references Server Functions via Server References; (3) The bridge: Server Components can pass server-rendered elements as children across the boundary.
* **Under the Hood**: Two compilation targets and manifests: the bundler runs two passes: one targeting Node/Edge (react-server condition) producing the server runtime, and one targeting browser environments producing chunk bundles and a client manifest that maps client reference IDs to browser chunk URLs.
* **The Code Experiment**:
  * *Naive*: Attempting to import ServerFeed from './ServerFeed' inside a 'use client' component, causing a compile failure.
  * *React*: Structuring the tree so the Server Graph imports the Client Component (<ClientModal><ServerFeed /></ClientModal>) and passes server content via children props.
* **Scope Boundary**: Focus on the dual module graph architecture, compiler manifests, and reference boundaries.
