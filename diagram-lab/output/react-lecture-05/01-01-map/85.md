# Q85: Ref as a Prop in React 19
* **Topic Tag**: `#ref_as_prop` | `❱❱❱ ADVANCED`
* **Interview Question**: *How does React 19 treat ref as an ordinary prop, and how does it replace forwardRef?*
* **Core Truth**: React 19 treats `ref` as a standard prop on function components, eliminating the need for `forwardRef` and allowing components to access `props.ref` directly in their parameter list.
* **The Friction**: In React 18, passing `<CustomInput ref={myRef} />` threw a loud console error: "Function components cannot be given refs". Developers were forced to wrap components in `forwardRef((props, ref) => ...)`, cluttering component signatures and complicating TypeScript typing.
* **The Mechanism**: Ref as a standard prop (`function CustomInput({ ref, label, ...props })`). In React 19, `ref` is simply another property on the `props` object, passed down and forwarded like any other prop without higher-order wrappers.
* **Under the Hood**: Fiber element normalization: React 19 removes the special treatment of `ref` as an isolated metadata field on React element objects; during JSX creation, `ref` is stored directly on `props.ref`, deprecating `forwardRef` and streamlining fiber reconciliation.
* **The Code Experiment**:
  * *Naive*: Wrapping a component in legacy `forwardRef` with complex dual-parameter signatures `(props, ref)`.
  * *React*: A `SearchInput` component accepting `{ ref, placeholder }` directly as regular props in React 19, attaching `ref` straight to an internal `<input>`.
* **Scope Boundary**: Focus on the transition from `forwardRef` to `ref` as a prop in React 19 and prop forwarding patterns. Do not cover `useImperativeHandle` (already covered in Q51).
