# Q168: Building an RSC App from Scratch
* **Topic Tag**: #bundler_integration | ❱❱❱ ADVANCED (Server)
* **Interview Question**: *What do you implement when building an RSC app from scratch?*
* **Core Truth**: Building an RSC application without a meta-framework requires orchestrating three interconnected systems: a server bundler emitting the server runtime with custom export conditions, a client bundler generating client manifests and browser chunks, and an HTTP server that streams the Flight payload and dual-renders the HTML shell.
* **The Friction**: The platform infrastructure team at The National Times seeks to decouple their publishing CMS from Next.js by building a bespoke RSC pipeline; without meta-framework magic, their first prototype crashes because the server renderer cannot resolve `'use client'` module boundaries and client bundles attempt to evaluate Node.js database drivers in the browser.
* **The Mechanism**: Three moving parts: (1) Server bundling with condition `'react-server'` to resolve server-only code and transform `'use client'` files into client reference stubs `$$typeof: Symbol.for('react.client.reference')`; (2) Client bundling to compile actual client components into browser chunks alongside a `react-client-manifest.json` mapping module IDs to chunk URLs; (3) Runtime streaming where the server passes the manifest to `renderToPipeableStream` (from `react-server-dom-webpack/server`) and the client consumes chunks via `createFromFetch`.
* **Under the Hood**: The manifest handshake: when the server Flight serializer encounters a Client Reference stub during rendering, it consults the client manifest to locate the chunk's bundle URL and export name, emitting an `M` row (e.g. `M1:{"id":"./src/LiveTicker.js","name":"default","chunks":["chunk-ticker.js"]}`); on the client, `createFromFetch` intercepts `M1`, triggers dynamic chunk prefetching via the browser loader, and resolves the chunk before rendering the component.
* **The Code Experiment**:
  * *Naive*: Attempting to run React Server Components by simply importing standard client components into a Node.js script with `renderToString`, crashing on browser globals and missing the Flight serialization pipeline entirely.
  * *React*: Orchestrating a dual Webpack/Vite build pipeline with `react-server-dom-webpack/plugin`, running a server entry that calls `renderToPipeableStream(App, clientManifest)`, and hydrating in the browser with `createFromFetch(fetch('/rsc'))` wrapped in `use()`.
* **Scope Boundary**: Do not cover high-level meta-framework routing conventions (Next.js App Router, Remix Vite plugin) or deep Flight row serialization byte encodings (covered in Q166/Q167); focus strictly on the bare minimum architectural contracts required between bundlers, manifests, and runtimes when implementing RSC from scratch.
