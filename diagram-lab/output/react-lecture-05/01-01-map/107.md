# Q107: Crossing the Boundary: Serializable Props Between Server and Client
* **Topic Tag**: #serializable_props | ❱ CORE (Server)
* **Interview Question**: *What can you pass from a Server Component to a Client Component?*
* **Core Truth**: Props passed from Server Components to Client Components must be serializable across the network boundary, allowing primitives, plain objects, arrays, and Promises, but forbidding client callbacks, class instances, and non-serializable symbols.
* **The Friction**: A Server Component fetches article records from PostgreSQL at The National Times and attempts to pass a database row containing a custom formatAuthor() helper method and a date instance to a client ShareWidget; the build crashes with a serialization error: "Functions cannot be passed directly to Client Components".
* **The Mechanism**: Allowed serializable props: strings, numbers, booleans, null, undefined, plain objects, arrays, Maps, Sets, TypedArrays, Date, Promises, and React elements (children); Forbidden: standard functions (except Server Functions), DOM elements, class instances with methods, and symbols.
* **Under the Hood**: The RSC serialization format: the server serializes props into a streaming JSON format; functions have no meaningful serialized representation across process boundaries without code shipping, so React throws a compile-time or runtime serialization error to prevent accidental leakage.
* **The Code Experiment**:
  * *Naive*: Passing a database model instance with attached helper methods article.formatDate() as a prop to a 'use client' component.
  * *React*: Serializing the data to plain JSON primitives (id, title, publishedAt: date.toISOString()) or passing formatted strings directly from the Server Component.
* **Scope Boundary**: Focus on serializable types, forbidden types, and how to structure props crossing the server/client boundary. For Server Functions as actions, refer to Q110.
