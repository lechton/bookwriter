# Q44: Optimistic UI Updates with useOptimistic
* **Topic Tag**: `#use_optimistic` | `❱❱ MORE`
* **Interview Question**: *How do you show the value the reader expects before the server confirms?*
* **Core Truth**: `useOptimistic` allows a component to display an anticipated state immediately during an ongoing async action, automatically reverting to the actual state if the action rejects or when the server responds.
* **The Friction**: A reader clicks the "Like" heart on a breaking news report. With standard async actions, the heart stays gray for 800ms while waiting for the network round trip, making the interface feel sluggish and unresponsive. If updated with naive state, rolling back on network failure requires complex manual bookkeeping.
* **The Mechanism**: The `useOptimistic` hook (`const [optimisticState, setOptimisticState] = useOptimistic(passthroughState, updateFn)`). Inside an async transition or form action, calling `setOptimisticState(optimisticValue)` instantly switches the UI; once the action settles, React reconciles with the real state.
* **Under the Hood**: Temporary shadow state in React transitions: optimistic state is only active while an async transition is pending; React overlays the optimistic value during rendering without permanently mutating base state, discarding the optimistic overlay the moment the transition completes.
* **The Code Experiment**:
  * *Naive*: Waiting for the API promise to resolve before showing the liked heart, or manually managing rollback state in `catch` blocks.
  * *React*: An `ArticleLikeButton` using `useOptimistic` to immediately toggle the heart icon to active upon click, rolling back automatically if the background action fails.
* **Scope Boundary**: Focus on `useOptimistic` within client actions, its update function contract, and automatic rollback semantics. Do not introduce server components or database mutations.
