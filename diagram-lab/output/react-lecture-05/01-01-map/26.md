# Q26: Sharing State Between Components by Lifting It Up
* **Topic Tag**: `#lifting_state` | `❱ CORE`
* **Interview Question**: *How do two sibling components share one changing value?*
* **Core Truth**: When two sibling components need access to the same changing data, you must lift the state up to their closest common ancestor and pass it down as props and callbacks.
* **The Friction**: On The National Times article page, a `FontScaleSlider` lives in the header settings menu, while the article text lives in `ArticleBody`. Neither component can access the other's state; beginners try to query DOM elements or use window globals, breaking React's unidirectional architecture.
* **The Mechanism**: Lifting state up. Move `const [fontSize, setFontSize] = useState(16)` from the child into the common parent `ArticlePage`. Pass `fontSize` down to `ArticleBody` as a prop, and pass `setFontSize` down to `FontScaleSlider` as a callback prop.
* **Under the Hood**: Single source of truth in tree hierarchies: why locating state at the lowest common ancestor guarantees that both consumer components receive the identical value in the same render pass without sync lag.
* **The Code Experiment**:
  * *Naive*: Storing font size independently in both `FontScaleSlider` and `ArticleBody`, or attempting to pass state sideways between sibling components.
  * *React*: `ArticlePage` holding `fontSize` state, passing the value to `ArticleBody` and the change handler `onFontSizeChange` to `FontScaleSlider`.
* **Scope Boundary**: Focus strictly on lifting state to the closest common parent and passing props/callbacks down. Do not introduce React Context (reserved for Q30).
