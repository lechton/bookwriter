# Q06: Mounting the Root Component with createRoot
* **Topic Tag**: `#create_root` | `❱ CORE`
* **Interview Question**: *You wrote App.jsx. How does it actually get onto the page with createRoot?*
* **Core Truth**: `createRoot` is the official mounting bridge from `react-dom/client` that links an in-memory React element tree to a physical browser DOM container, enabling React 19 concurrent rendering.
* **The Friction**: You have authored `App.jsx`, but sitting on disk it is powerless JavaScript. Beginners often attempt legacy `ReactDOM.render()`, query DOM nodes inside components, or fail to handle a missing `<div id="root">`, resulting in silent blank screens or deprecated runtime warnings.
* **The Mechanism**: The two-step initialization API: `const root = createRoot(domNode)` establishes the concurrent root container, and `root.render(<App />)` mounts the virtual element tree into physical DOM pixels.
* **Under the Hood**: How `createRoot` initializes a Fiber root data structure attached to the container element, schedules the initial render pass, and sets up event delegation on the root container rather than individual DOM nodes.
* **The Code Experiment**:
  * *Naive*: Legacy `ReactDOM.render` causing console deprecation warnings, or calling `createRoot` on a null element when the script executes before HTML parses.
  * *React*: `src/main.jsx` safely querying `document.getElementById('root')`, initializing `createRoot`, and calling `.render(<App />)`.
* **Scope Boundary**: Focus strictly on the mounting bridge and initialization lifecycle (`index.html` <-> `main.jsx` <-> `App.jsx`). Do not introduce complex multi-component routing or internal state.
