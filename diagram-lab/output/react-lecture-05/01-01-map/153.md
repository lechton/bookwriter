# Q153: Optimistic UI with useOptimistic: Instant Updates with Server Rollbacks
* **Topic Tag**: #use_optimistic | ❱❱ MORE (Server)
* **Interview Question**: *How does optimistic UI work when the action runs on the server?*
* **Core Truth**: useOptimistic lets Client Components immediately display an anticipated optimistic state while a Server Function executes in the background, automatically reverting to the true server state if the action rejects or fails.
* **The Friction**: An editor clicks "Like" on an article comment at The National Times; on slow mobile connections, the like counter remains unchanged for 800ms while awaiting the database response; editors assume their click failed and double-click the button, or experience a frustrating lag.
* **The Mechanism**: const [optimisticState, setOptimisticState] = useOptimistic(passthroughState, updateFn): inside a transition, the component calls setOptimisticState(optimisticValue) before awaiting the Server Function; React displays the optimistic state immediately and reverts automatically when the transition finishes.
* **Under the Hood**: Transition-scoped overlay: useOptimistic maintains an optimistic overlay layer during active transitions; when the transition settles (either successfully applying the new server state or aborting due to an error), React discards the optimistic overlay and renders the canonical server-provided state.
* **The Code Experiment**:
  * *Naive*: Manually maintaining duplicate useState flags and rollback logic with ad-hoc try/catch blocks that easily go out of sync with server data.
  * *React*: Using useOptimistic inside a transition action to increment a story's upvote count instantly, cleanly reverting if the server action throws a network error.
* **Scope Boundary**: Focus on useOptimistic, how it cooperates with Server Functions in transitions, and automatic rollback semantics.
