# Q164: Action Composition: Sequencing and Orchestrating Multiple Server Actions
* **Topic Tag**: #actions | ❱❱ MORE (Server)
* **Interview Question**: *How do you compose and sequence multiple actions?*
* **Core Truth**: Complex editorial workflows require orchestrating multiple asynchronous Server Functions sequentially or in parallel within a single transition, maintaining a unified pending state without nested useEffect cascades.
* **The Friction**: Publishing an investigative article at The National Times requires three distinct steps: saving the article copy, uploading cover photography, and notifying syndication partners; an engineer links these together via three nested useEffect hooks, creating race conditions and leaving the editor with disjointed loading spinners.
* **The Mechanism**: Orchestration in transitions: startTransition(async () => { const draft = await saveDraft(data); const imgUrl = await uploadImage(file); await publishStory(draft.id, imgUrl); }): runs the entire sequence within a single transition, keeping isPending: true continuously until all steps settle.
* **Under the Hood**: Transition batching across async tasks: React's startTransition tracks the entire async execution chain until the outer promise resolves; intermediate state updates during the sequence do not trigger jarring intermediate fallback screens, ensuring atomic UI updates.
* **The Code Experiment**:
  * *Naive*: Chaining three separate useEffect hooks that watch intermediate state flags (if (step === 1) ...), creating state churn and race conditions.
  * *React*: Composing a cohesive handlePublish function that coordinates all three server operations inside a single startTransition call.
* **Scope Boundary**: Focus on orchestrating multiple Server Functions, managing combined pending state, and avoiding useEffect waterfalls for action sequencing.
