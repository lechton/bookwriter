# Q33: Storing Values with useRef
* **Topic Tag**: `#use_ref` | `❱ CORE`
* **Interview Question**: *How do you keep a value between renders without triggering a re-render?*
* **Core Truth**: `useRef` returns a mutable container object whose `.current` property persists across renders without triggering a component re-render when modified, serving as an escape hatch for values outside the visual render flow.
* **The Friction**: A live newsroom stopwatch tracks interview recording duration. Storing `const [timerId, setTimerId] = useState(null)` triggers an unwanted re-render every time the interval starts or stops, while storing `let timerId` as a local variable wipes out the ID on the next render, making it impossible to clear the interval.
* **The Mechanism**: The `useRef` hook (`const timerRef = useRef(null)`). Reading and mutating `timerRef.current` does not notify React or trigger a render, keeping values stable and mutable across the component's full lifecycle.
* **Under the Hood**: Fiber hook storage: `useRef(initialValue)` creates a plain `{ current: initialValue }` object on initial mount and attaches it to the fiber's hook linked list; on subsequent renders, React returns the exact same object reference without touching `.current`.
* **The Code Experiment**:
  * *Naive*: Using a local `let timerId` that resets to `undefined` on re-render, or using `useState` for interval IDs causing unnecessary re-renders.
  * *React*: An `InterviewRecorder` using `useRef` to store the active `intervalId`, starting and stopping the timer cleanly without re-rendering the component.
* **Scope Boundary**: Focus strictly on using `useRef` as a silent mutable value box (timers, previous values, flags). Do not cover DOM element manipulation yet (reserved for Q34).
