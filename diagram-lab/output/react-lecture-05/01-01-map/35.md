# Q35: Synchronizing with External Systems Using useEffect
* **Topic Tag**: `#use_effect` | `❱ CORE`
* **Interview Question**: *How do you connect a component to an external system, and how do you disconnect it?*
* **Core Truth**: `useEffect` synchronizes a component with external systems (browser APIs, subscriptions, network connections) outside React's control; its cleanup function runs before the effect re-executes and upon unmounting to guarantee zero resource leaks.
* **The Friction**: An article page subscribes to a WebSocket live news feed directly inside the component body: `const socket = new WebSocket(...)`. On every state update and re-render, a brand-new socket connection opens. Within two minutes, thirty orphaned sockets flood the server, crashing the reader's browser tab.
* **The Mechanism**: The `useEffect` hook (`useEffect(() => { const conn = connect(); return () => conn.disconnect(); }, [dependencies])`). React runs the setup function after the commit phase and executes the returned cleanup function before re-running setup or unmounting.
* **Under the Hood**: React's effect scheduling in the commit phase: effects run asynchronously after the browser paints so they don't block the screen; React tracks dependencies via `Object.is` and cleans up the previous effect pass before running the next.
* **The Code Experiment**:
  * *Naive*: Creating WebSocket connections or `window.addEventListener` in the component body without cleanup, spawning memory leaks on every render.
  * *React*: A `LiveTicker` subscribing to a chat/wire feed inside `useEffect` and returning a cleanup function that closes the connection when the component unmounts.
* **Scope Boundary**: Focus on the mental model of synchronization, the setup/cleanup contract, and dependency arrays. Do not delve into data fetching race conditions (Q36) or omitting unnecessary effects (Q37).
