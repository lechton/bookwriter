# Q82: The Unified Rules of React
* **Topic Tag**: `#rules_of_react` | `❱❱❱ ADVANCED`
* **Interview Question**: *What are the Rules of React, and how do the three rules interlock?*
* **Core Truth**: The Rules of React form an interlocking system: (1) Components and hooks must be pure, (2) React calls components and hooks (you never call them directly), and (3) Hooks must be called only at the top level of React functions; violating any one rule breaks the assumptions underlying reconciliation, concurrency, and compilation.
* **The Friction**: An engineer calls `Card()` as a regular function instead of `<Card />`, mutates a prop array inside render, and conditionally calls a hook. The code happens to work in a simple test, but crashes completely under React 19 Concurrent Mode and triggers compiler bailouts, corrupting application state.
* **The Mechanism**: The official Rules of React. Rule 1: Idempotent, pure calculations with zero side effects; Rule 2: Inversion of control (React controls scheduling and invocation); Rule 3: Top-level hook execution preserving stable fiber pointer indices.
* **Under the Hood**: The compiler and concurrency contract: React's Fiber reconciler and the React Compiler treat components as pure mathematical projections; breaking rule 1 breaks time-slicing and memoization, breaking rule 2 breaks Fiber lifecycle hooks, and breaking rule 3 corrupts the hook linked list.
* **The Code Experiment**:
  * *Naive*: Manually invoking component functions (`Header({ user })`), mutating external variables in render, and conditionally invoking hooks.
  * *React*: Auditing and refactoring a legacy component to strictly obey the three Rules of React, verified by `eslint-plugin-react-compiler` and StrictMode.
* **Scope Boundary**: Focus on the unified philosophy and mutual interdependence of the three Rules of React. Do not focus on isolated hook syntax (already covered in Q46).
