# Q45: Progressive Enhancement with Form Actions
* **Topic Tag**: `#progressive_enhancement` | `❱❱ MORE`
* **Interview Question**: *How do React 19 form actions support progressive enhancement when JavaScript is disabled?*
* **Core Truth**: React 19 form actions can progressively enhance native HTML `<form>` submissions by falling back to standard HTTP POST requests when JavaScript is disabled or still downloading, ensuring critical user workflows remain functional.
* **The Friction**: A reader on a flaky mobile subway connection attempts to submit an urgent news tip before the 2MB JavaScript bundle finishes downloading. In traditional Single-Page Apps, clicking submit does nothing because the event listener has not attached, leaving the reader stranded.
* **The Mechanism**: Progressive enhancement via form actions. By combining a native form endpoint (`<form action="/api/feedback" ...>`) with a client or server action, the browser executes a native browser HTTP POST if JavaScript is absent, and seamlessly upgrades to an interactive client-side transition once scripts hydrate.
* **Under the Hood**: HTML standard form semantics: browsers natively serialize inputs with `name` attributes into `application/x-www-form-urlencoded` or `multipart/form-data`; React builds on top of these native web platform primitives rather than bypassing them.
* **The Code Experiment**:
  * *Naive*: A form using `<div onClick={submit}>` or `button` without `name` attributes on inputs, which completely fails if JavaScript has not loaded.
  * *React*: An `EditorialTipForm` with semantic `<form action="/api/tip" method="POST">` and named inputs, functioning as a native HTTP form while upgrading to React action handling on hydration.
* **Scope Boundary**: Focus on the concept of progressive enhancement, native form fallback (`action` URL + `name` attributes), and resilience. Do not delve into Server Actions or server-side redirects (Q101+).
