# Q84: Asset Preloading APIs in Client Code
* **Topic Tag**: `#asset_preloading_client` | `❱❱❱ ADVANCED`
* **Interview Question**: *How do preload, preinit, preconnect, and prefetchDNS speed up asset loading?*
* **Core Truth**: React 19 provides dedicated resource loading functions (`preload`, `preinit`, `preconnect`, `prefetchDNS`) that warm up network connections, fonts, stylesheets, and scripts early during render before the browser discovers them in the DOM.
* **The Friction**: An interactive article features a heavy custom typography font and an external weather data API. The browser only discovers the font file after parsing nested CSS rules 800ms into page load, causing a jarring flash of unstyled text (FOUT) and delayed layout.
* **The Mechanism**: Resource preloading APIs from `react-dom`: `preload('font.woff2', { as: 'font' })`, `preinit('styles.css', { as: 'style' })`, `preconnect('https://api.nationaltimes.com')`, and `prefetchDNS('https://cdn.nationaltimes.com')` called during component render.
* **Under the Hood**: Early link tag hoisting: calling `preload()` emits corresponding `<link rel="preload">` tags into the document `<head>` during the earliest phase of rendering, instructing the browser's network preload scanner to initiate requests concurrently with JavaScript execution.
* **The Code Experiment**:
  * *Naive*: Letting font and script downloads wait until full DOM rendering and stylesheet evaluation complete, creating layout shifts and loading waterfalls.
  * *React*: An `EditorialFeature` component calling `preload('headline-font.woff2', { as: 'font' })` and `preconnect('https://api.nationaltimes.com')` directly in render to warm up assets before render finishes.
* **Scope Boundary**: Focus on client-side asset preloading APIs in `react-dom`. Do not confuse with server-side document streaming or HTTP/2 server push.
