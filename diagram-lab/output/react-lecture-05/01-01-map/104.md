# Q104: Hydration: Attaching Interactivity with hydrateRoot
* **Topic Tag**: #hydration | ❱ CORE (Server)
* **Interview Question**: *What is hydration, and how does hydrateRoot attach interactivity?*
* **Core Truth**: Hydration is the client-side process where React traverses existing server-rendered DOM nodes, verifies their structure matches the client component tree, and attaches event listeners without destroying or re-creating DOM nodes.
* **The Friction**: The National Times home page paints server HTML in 300ms, but readers frantically clicking the "Breaking News Alert" toggle see no response; an inexperienced developer replaces hydrateRoot with createRoot, causing the entire server DOM to flash, unmount, and blow away existing scroll positions.
* **The Mechanism**: ReactDOMClient.hydrateRoot(domNode, <App />): instructs React to adopt the server-rendered DOM tree, mount Fiber nodes corresponding to existing elements, bind SyntheticEvent handlers, and schedule initial effects.
* **Under the Hood**: Dual-tree traversal and Fiber adoption: hydrateRoot iterates over DOM child nodes while executing the component render pass; it matches DOM elements by tag name and text content to Fiber workInProgress nodes, attaching internal event listeners (__reactProps$...) to the DOM without issuing document.createElement.
* **The Code Experiment**:
  * *Naive*: Calling createRoot(container).render(<App />) on a server-rendered container, destroying the server DOM and creating visual flashes.
  * *React*: Using hydrateRoot(container, <App />) to seamlessly bind event listeners to existing server-rendered markup.
* **Scope Boundary**: Focus strictly on the hydration mechanism, how hydrateRoot works, and DOM node adoption. Do not cover hydration error debugging (that is Q105).
