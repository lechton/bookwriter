# Q03: Component Anatomy and the Capitalization Rule
* **Topic Tag**: `#component_anatomy` | `❱ CORE`
* **Interview Question**: *What is a React component, and what rules govern how you write and name one?*
* **Core Truth**: A React component is a pure JavaScript function that returns JSX markup; PascalCase capitalization is a strict compiler requirement distinguishing custom component functions from native HTML elements.
* **The Friction**: A junior developer writes `function articleCard() { ... }` and renders `<articleCard />`. The terminal shows no build error, the console shows no warning, but the browser displays an empty blank screen because it treated the tag as an unknown native HTML element.
* **The Mechanism**: PascalCase naming convention (`ArticleCard`). Capitalized tags instruct the JSX compiler to emit direct function references (`_jsx(ArticleCard)`), allowing React to execute the function and commit its elements to the DOM.
* **Under the Hood**: The JSX transpiler AST branch: lowercase identifiers compile to string literals (`_jsx("articlecard")` -> `document.createElement`), bypassing the component function entirely; uppercase identifiers compile to function identifiers (`_jsx(ArticleCard)` -> React executes `ArticleCard()`).
* **The Code Experiment**:
  * *Naive*: Lowercase `<articleCard />` creating an empty `<articlecard></articlecard>` DOM element without executing the function.
  * *React*: Capitalized `ArticleCard` returning a semantic `<article>` with headline and body, rendered declaratively as `<ArticleCard />` in `App.jsx`.
* **Scope Boundary**: Focus strictly on the single component function, its capitalization, its pure return contract, and declarative invocation (`<Card />` vs `Card()`). Do not introduce props, curly brace expressions, or multi-file trees.
