# Q146: Early Network Handshakes: preconnect and prefetchDNS
* **Topic Tag**: #preloading | ❱❱ MORE (Server)
* **Interview Question**: *What do preconnect and prefetchDNS do before any request exists?*
* **Core Truth**: prefetchDNS resolves the IP address of a third-party domain early, while preconnect goes further by performing the full TCP handshake and TLS negotiation before an actual HTTP request is initiated.
* **The Friction**: High-resolution investigative photos at The National Times are hosted on an external media CDN (cdn.nationaltimes-media.com); on mobile 4G connections, the 300ms TLS handshake and DNS lookup delay image rendering, causing readers to see blank gray boxes on initial page load.
* **The Mechanism**: Network warming APIs: prefetchDNS('https://cdn.nationaltimes-media.com') outputs <link rel="dns-prefetch" href="..." />; preconnect('https://cdn.nationaltimes-media.com') outputs <link rel="preconnect" href="..." /> (and optionally crossOrigin).
* **Under the Hood**: Connection lifecycle optimization: a cold HTTPS request requires DNS resolution (~50ms), TCP handshake (~50ms), and TLS negotiation (~100ms) before the HTTP GET request is sent; preconnect completes all three socket setup phases in the background during initial HTML streaming, eliminating 200ms of socket latency.
* **The Code Experiment**:
  * *Naive*: Allowing third-party analytics and media domains to negotiate connections only when the first image or script tag is encountered in the DOM.
  * *React*: Calling preconnect('https://images.nationaltimes.com') and prefetchDNS('https://analytics.nationaltimes.com') at the top of the root Server Component.
* **Scope Boundary**: Focus on preconnect vs prefetchDNS, socket setup mechanics, and when to use each for third-party origins.
