# Q43: Reading Form Status with useFormStatus
* **Topic Tag**: `#use_form_status` | `❱❱ MORE`
* **Interview Question**: *How does a field nested deep in a form read the form's pending state?*
* **Core Truth**: `useFormStatus` is a Context-like hook that allows any child component nested inside a `<form>` to read the parent form's submission status (`pending`, `data`, `method`, `action`) without prop drilling.
* **The Friction**: A reusable `SubmitButton` sits inside an `EditorialModal` inside a `FormContainer` inside a `<form>`. To disable the button and show a spinner during submission, the developer must drill the `isPending` boolean down through three intermediate component layers.
* **The Mechanism**: The `useFormStatus` hook (`const { pending, data, method, action } = useFormStatus()`). When placed inside a component rendered as a child of a `<form>`, it automatically reads the enclosing form's active submission status.
* **Under the Hood**: Form status context: React injects an internal form context provider into every `<form>` rendered in the tree; `useFormStatus` reads this context, meaning the hook must be called from a *child* component inside the form, not within the component that renders the `<form>` tag itself.
* **The Code Experiment**:
  * *Naive*: Calling `useFormStatus()` in the same component that renders `<form>`, which returns `pending: false` because the hook is outside its own form context.
  * *React*: Extracting a dedicated `<SubmitButton />` component that calls `useFormStatus()` to disable itself and render "Publishing..." while the parent form action executes.
* **Scope Boundary**: Focus on `useFormStatus`, its return object properties (`pending`, `data`), and the child-component placement rule. Do not cover optimistic updates (Q44).
