# Visual Aid Specification — Lecture 12: Keeping Components Pure

Where:
Place this visual aid in `md-lectures/12.md` inside the section `### The Shared Variable Trap and Render Mutations`, positioned immediately after the paragraph explaining the re-render failure ("The disaster strikes the moment anything causes the page to re-render. Suppose a journalist clicks a category filter or a new breaking alert arrives... The screen now displays Alert #4, Alert #5, and Alert #6 for the exact same three stories.").

Instruction:
Design an authoritative, two-part McGraw-Hill engineering textbook figure on a crisp white background that contrasts an isolated pure functional chamber against a contaminated pipeline linked to a persistent memory register across two successive render cycles. In the top half, labeled with an institutional blue banner "FIGURE 12-A: THE PURE EXECUTION MODEL (HERMETIC CHAMBER)", illustrate a central processing block representing the component during Render 1 and Render 2; show an incoming royal blue data bus delivering identical input tokens `props: { count: 1 }` through a clearly defined input port into the chamber, which executes internally on a clean white slate and discharges a crisp emerald green output token `JSX: <Alert #1>` down into the virtual DOM; indicate with circular numbered step badges (❶ and ❷) and a circular sync glyph labeled "User Filter Action" that when Render 2 runs, the chamber re-executes with the exact same input and yields the exact same emerald token, highlighting an engineering annotation callout: "Zero Ambient Dependencies = Deterministic Re-execution". In the bottom half, labeled with a contrasting warm slate-crimson banner "FIGURE 12-B: THE IMPURE TRAP (PERSISTENT REGISTER LEAK)", draw the exact same component chamber, but place a physicalized module memory register directly above it rendered as a compartmentalized data cell labeled `Module Scope: [ alertCount ]`; in Step ❶ (Initial Mount), illustrate an amber write-probe piercing out of the chamber into the register, advancing the cell from `[ 0 ]` to `[ 3 ]` while emitting badges `[ #1, #2, #3 ]`; then, directly adjacent in Step ❷ (Second Render), show the re-render executing with identical source stories, but depict the write-probe resuming from the un-cleared register holding `[ 3 ]`, advancing it to `[ 6 ]` and discharging corrupted red-highlighted badges `[ #4, #5, #6 ]`; connect the two cycles with a bold crimson timeline arrow beneath the register labeled "Dirty State Carried Over", using a textbook leader line pointing to the contaminated output with a concise boxed diagnostic: "Defect: Render pass mutates ambient memory that survives component teardown".

Style:
The visual style must mirror a premium McGraw-Hill / Addison-Wesley computer science college textbook: crisp, technical, structured, and visually engaging without cartoonish tropes or AI-generated abstraction. The canvas is pure white (#FFFFFF). Use distinct, purposeful textbook spot colors to guide the eye: deep authoritative cobalt blue (#1D4ED8) for the pure data bus and primary architectural framing, forest emerald (#059669) for verified pure outputs, vivid amber-gold (#D97706) for active execution probes, and crimson coral (#DC2626) strictly reserved for the state leak and corrupted values. Functional units use light engineering tint fills (soft ice-blue #F0F9FF for the pure chamber; light paper-rose #FFF1F2 for the impure chamber) bounded by precise 1.5px solid dark slate outlines (#0F172A), avoiding blurry drop shadows or heavy brutalist blocks. Typography uses a rigorous technical hierarchy: figure titles, section headers, and callouts are set in clean, highly legible geometric sans-serif (such as Frutiger, Univers, or Helvetica Neue) in dark graphite (#1E293B), while all code parameters, register values, and JSX tokens (`let alertCount`, `count: 1`, `[ 3 ]`) are set in a distinct, bold monospace (JetBrains Mono or SF Mono). Structural connections must use clean, vector-precision orthogonal paths with solid filled arrowhead terminals and classic textbook numbered callout discs (solid circles with white numbers: ❶, ❷, ❸) paired with thin, crisp 45-degree leader lines to create an authentic, polished instructional artifact.

Description:
This illustration transforms an elusive, invisible runtime flaw into an intuitive physical reality that dissolves all mental fog for the student. In software engineering education, students frequently fail to grasp why module-scoped variables are catastrophic in declarative UI frameworks because their initial local test renders output that appears 100% correct. By modeling the external variable as a physicalized hardware-style register (`[ alertCount ]`) sitting outside the component envelope, the student immediately perceives that computer memory does not reset between function invocations. When the diagram shows Render 2 beginning with `3` already sitting in the register box, the student experiences an immediate "aha moment": they visually watch the component inherit yesterday's dirt, proving instantly that rendering must never touch ambient scope and cementing the necessity of React's pure function contract.
