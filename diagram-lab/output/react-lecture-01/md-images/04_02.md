# Visual Aid Specification — Lecture 04: Mounting with createRoot

Where:
Place this visual aid in `md-lectures/04.md` inside the section `### The Missing Bridge Between Components and the Browser`, positioned immediately after the paragraph discussing why React requires a designated container rather than attaching directly to document.body ("In traditional web development, developers often wondered why React requires a designated container rather than attaching directly to document.body. If React took over document.body, it would overwrite everything on the page: third-party analytics scripts, WordPress menus, tag managers, and browser extension overlays. By requiring a root container (the designated HTML element in your page document where React takes control and renders your component tree), React establishes a clean, isolated sandbox. Inside that container element, React owns every node; outside of it, the surrounding host page remains untouched.").

Accompanying Book Paragraph:
When beginners write their first mounting script, a natural question arises: why bother querying a designated `<div id="root">` element when `document.body` is already globally available? The answer lies in the harsh reality of browser runtime environments. If you point `createRoot(document.body)` directly at the host document body, React assumes absolute ownership over every single node inside the viewport. On initial mount, it wipes out existing markup, destroying server-rendered navigation headers, analytics tracking tags, and third-party widgets. Even worse, modern browsers are full of background extensions—password managers, grammar checkers, and ad blockers—that inject their own DOM nodes directly into `<body>`. When React attempts to reconcile its virtual tree against a `document.body` that an external extension has quietly modified, React's reconciler desynchronizes completely and crashes the application with a fatal `NotFoundError: Failed to execute 'removeChild' on 'Node'`. By contrast, targeting an isolated container with `createRoot(document.getElementById('root'))` establishes a strict sandbox boundary. Inside `#root`, React owns every node; outside of it, host CMS templates, analytics tags, and browser extensions coexist without interference.
