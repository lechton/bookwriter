# Visual Aid Specification — Lecture 06: JavaScript in JSX with Curly Braces

Where:
Place this visual aid in `md-lectures/06.md` inside the section `### The Raw Object Pitfall`, positioned immediately after the paragraph explaining why React refuses to render raw objects ("React refuses to render raw objects because it cannot guess how you want multiple fields formatted on screen. Should it print JSON? Should it print commas? To display object data, you must always drill down to a specific primitive property, such as `{reporter.name}` or `{reporter.role}`.").

Accompanying Book Paragraph:
To understand why passing an object directly into JSX halts your application, visualize how React handles dynamic children. When curly braces evaluate a primitive string or number, React effortlessly creates a standard DOM text node and mounts it to the screen. But when you write `<h4>{reporter}</h4>`, curly braces evaluate to a multi-property JavaScript object. Because React cannot assume whether you want JSON, comma-separated keys, or localized labels, it halts execution immediately with its iconic fatal error: "Objects are not valid as a React child (found: object with keys {name, role})." As shown in the comparison below, curly braces grant you access to JavaScript expressions, but JSX child slots demand renderable leaf values. To display your data without crashing, always drill past the container into a specific primitive property like `{reporter.name}`.

Style:
The visual aesthetic strictly adheres to modern Swiss editorial and technical textbook design (reminiscent of Edward Tufte and Stripe Press), completely free of AI-generated abstraction or cartoonish clutter. The background is pure solid white (#FFFFFF). Structural cards and browser window wireframes feature crisp 1.5px dark slate outlines (#0F172A) with generous internal padding and zero drop shadows. The visual language relies on strict semantic color coding: deep ocean cyan (#0E7490) is used for the correct data flow, the String type badge, and the successfully rendered browser frame; warning coral red (#DC2626) is reserved strictly for the broken dashed lookup arrow, the illegal Object type badge, and the crashed error alert. Pedagogical eye-tracking is driven by a vibrant, semi-translucent study highlighter yellow (#FDE047 / #FEF08A) placed with strict restraint exclusively beneath the contrasting words in Tier 2, never on the browser UI in Tier 3 or the source data in Tier 1. Typography is strictly dual-discipline: all code tokens and file names (`ArticleHeader.jsx`, `AuthorProfile.jsx`, `{reporter}`, `{reporter.name}`) are rendered in crisp, medium-weight monospace (JetBrains Mono), while all structural tier markers, column headers, and UI text are set in clean, highly legible geometric sans-serif (Inter or Helvetica Neue) in solid dark charcoal.

Description:
This visual aid dissolves one of the most frustrating mental traps for developers learning JSX: assuming that because curly braces evaluate JavaScript, any valid JavaScript variable can be rendered as a tag's child. Developers write `<h4>{reporter}</h4>` expecting React to serialize or stringify the object, only to be stopped by React's famous "Objects are not valid as a React child" fatal error. By mapping the lifecycle across three vertical tiers—from the object definition in Tier 1, through the JSX evaluation in Tier 2, directly to the browser screen outcome in Tier 3—the diagram creates an immediate "aha moment". The student watches the red dashed arrow carry an illegal Object container directly into a crash, while the right side proves that accessing the leaf string property `{reporter.name}` allows React to construct a valid text node and render the profile. In one glance, the student internalizes the core rule: curly braces evaluate JavaScript, but JSX child nodes require primitives.
