### The Focus Hijack: Physical DOM Focus Versus Virtual Descendants

Maya navigates the municipal records archive using speech output and keyboard commands. When frontend engineers construct custom autocompleting comboboxes, a common anti-pattern is transferring physical DOM focus into the dropdown list items as the user arrows downward. Moving actual focus away from the input field destroys typing ergonomics, preventing users from editing their search query without manually tabbing backward. Managing virtual focus via `aria-activedescendant` retains keyboard focus strictly on the text input while communicating the highlighted option:

```html title="combobox-focus.html"
<li tabindex="0" onfocus="highlight(this)">Transit</li> <!-- **WRONG:** Physical focus steals cursor from input -->

<input role="combobox" aria-activedescendant="opt-1" /> <!-- **RIGHT:** Virtual focus preserves text typing cursor -->
```

```canvas title="Archive Search: Physical Focus Steal vs Virtual Descendant" width="2/3" layout="compare"
combobox | Search archives...; Transit; Housing | wrong="physical focus stole cursor" | note="✕ Cannot type or edit query"
combobox | Search archives...; Transit; Housing | right="aria-activedescendant" | note="✓ Virtual focus keeps typing active"
```

The contrast illustrates the necessity of virtual focus management in composite input controls. On the left, pressing the Down Arrow invokes `element.focus()` on the list item. While the item receives a visual focus outline, the input cursor vanishes. If Maya wants to backspace or add another character, her keystrokes fail because the active element in the DOM is no longer a text field. On the right, physical focus remains locked within the `<input>` element throughout the entire interaction. As Maya presses the Down Arrow, JavaScript updates `aria-activedescendant="opt-1"`, which instructs assistive technologies to speak the highlighted option while Maya retains continuous typing control over the text string.

### The Combobox Contract: Roles, Expansion States, and Listbox Linkage

An accessible custom combobox requires a synchronized multi-attribute contract connecting the text input to its popover listbox. Failing to declare the combobox role, expansion state, and popup linkage leaves assistive technology users unaware that typing filters dynamic results below the field. Binding the input to a semantic listbox with explicit options ensures screen readers announce result counts and selection changes:

```html title="combobox-aria.html"
<input type="text" class="search-input" /> <!-- **WRONG:** Plain input hides dynamic popup list -->

<input role="combobox" aria-expanded="true"
       aria-haspopup="listbox"
       aria-controls="res-list"
       aria-autocomplete="list" /> <!-- **RIGHT:** Full ARIA popup contract -->
```

```canvas title="Autocomplete State: Plain Input vs ARIA Combobox Contract" width="2/3" layout="compare"
combobox | Search archives... | wrong="plain text input" | sr="Search archives, edit text" | note="✕ Popup list hidden from screen reader"
combobox | Search archives...; Transit Budget ($14M) | right="combobox aria contract" | sr="Search archives, combobox, expanded, 1 of 5" | note="✓ Exposes role, state, and option index"
```

When an input declares `role="combobox"`, the screen reader announces its specialized composite identity immediately upon entry. On the right, declaring `aria-expanded="true"` informs Maya that a popup has opened, while `aria-haspopup="listbox"` and `aria-controls="res-list"` establish the programmatic bond between the search bar and the results list. When Maya arrows down, the screen reader announces: "Transit Budget ($14M), 1 of 5". Without these attributes, a screen reader announces only a generic text edit field, keeping Maya entirely oblivious to the suggested search matches.

The W3C ARIA Authoring Practices Guide establishes the definitive definition and structure of the combobox pattern:

> A combobox is an input widget that has an associated popup. The popup enables users to choose a value for the input from a collection. The popup may be a listbox, grid, tree, or dialog.

### Glossary

- **Combobox Role**: A composite input widget that pairs a single-line textbox with an associated popup listbox, grid, or tree.
- **aria-activedescendant**: A focus delegation property that identifies the currently active child element without moving physical DOM focus.
- **aria-expanded**: A boolean state indicating whether the combobox's associated popup container is currently displayed or collapsed.
- **aria-haspopup**: An attribute indicating the type of popup component triggered by the combobox widget, such as listbox or dialog.
- **Virtual Focus**: An architectural pattern where keyboard navigation updates visual styles and ARIA pointers while physical focus stays on the container.

### Summary

**Virtual Focus Architecture and Combobox Widget Engineering**

Custom form controls require an airtight contract between visual behavior and programmatic state. Stealing physical focus from an input element traps users and destroys typing flow. Retain physical focus on the text box, delegate selection states through virtual focus attributes, and expose dynamic popup relationships through standardized ARIA properties. Here is your streetwise review.

❒ The Architectural Foundation of Accessible Comboboxes

1. Virtual Focus Management
<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Physical DOM focus remains permanently on the `<input role="combobox">`.
<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Arrow keys update `aria-activedescendant` with the active option's ID.
<br>&nbsp;&nbsp;&nbsp;&nbsp;(c) Visual styling updates via CSS attribute selectors matching the active descendant.

2. Synchronized State Binding
<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Set `aria-expanded="true"` when the suggestion listbox appears.
<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Bind the input to the dropdown container using `aria-controls="listbox-id"`.
<br>&nbsp;&nbsp;&nbsp;&nbsp;(c) Declare `role="listbox"` on the popup and `role="option"` on every suggestion item.

**DO NOT DO THIS:** Move DOM focus to list elements, breaking keyboard typing and editing.
```html wrong
<input type="text" onkeydown="list[0].focus()">
<ul class="suggestions">
  <li tabindex="0">Transit</li>
</ul>
```
&nbsp;&nbsp;&nbsp;&nbsp;**DO THIS:** Retain input focus and delegate selection using aria-activedescendant.
```html right
<input role="combobox" aria-expanded="true"
       aria-controls="opt-list" aria-activedescendant="opt-1">
<ul id="opt-list" role="listbox">
  <li id="opt-1" role="option">Transit</li>
</ul>
```

➔ NEVER transfer physical DOM focus away from an active text input during autocompletion.

➔ ALWAYS update `aria-expanded` dynamically as the popup opens and closes.

➔ IF options can be filtered by typing THEN declare `aria-autocomplete="list"`.
