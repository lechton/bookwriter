# Q21: Updating Objects in State
* **Topic Tag**: `#state_objects` | `❱ CORE`
* **Interview Question**: *How do you update an object in state without mutating it?*
* **Core Truth**: React treats state objects as immutable read-only snapshots; updating an object requires creating a new object copy using the spread syntax (`...`) or non-mutating transformations so React detects reference changes via `Object.is`.
* **The Friction**: An editor edits an article author's profile on The National Times dashboard. The developer writes `profile.author.bio = newBio` and calls `setProfile(profile)`. React sees the same object reference in memory, skips re-rendering completely, and the editor's screen remains unchanged until a hard refresh.
* **The Mechanism**: Object copy with spread syntax (`setProfile({ ...profile, bio: newBio })`) and nested object copying (`setProfile({ ...profile, author: { ...profile.author, bio: newBio } })`).
* **Under the Hood**: Why reference equality matters: React's reconciler performs an `Object.is(oldState, newState)` shallow comparison. Mutating the existing object in place leaves `oldState === newState` returning `true`, causing React to bail out of scheduling a render.
* **The Code Experiment**:
  * *Naive*: Mutating properties directly on the state object (`profile.bio = 'New bio'`) and passing the mutated reference to the setter.
  * *React*: Using shallow object copying with spread syntax (`setProfile(prev => ({ ...prev, bio: 'New bio' }))`) to produce a fresh object reference.
* **Scope Boundary**: Focus strictly on immutability of JavaScript objects in state and nested spread patterns. Do not introduce Immer or external state libraries.
