# Q19: Batching and Updater Functions
* **Topic Tag**: `#state_updates` | `❱ CORE`
* **Interview Question**: *How does React queue multiple state updates, and when do you need an updater function?*
* **Core Truth**: React batches state updates across event handlers to prevent wasteful re-renders, and updater functions (`c => c + 1`) allow queuing multiple consecutive updates against the pending state rather than a stale snapshot.
* **The Friction**: In a newsletter subscription widget, a user clicks "+3 Free Passes". The handler calls `setPasses(passes + 1)` three times in a row. Instead of increasing by 3, the counter only increments by 1 because each call reads the same snapshot value (`0 + 1`).
* **The Mechanism**: State update queues and updater functions (`setState(prev => prev + 1)`). Passing a pure updater function instructs React to compute the next state based on the previous queued state rather than the snapshot value.
* **Under the Hood**: React's update queue algorithm: React processes state updates sequentially during the next render pass; direct values overwrite previous values in the queue (`[0+1, 0+1, 0+1] -> 1`), whereas updater functions pipe the accumulated result through each function (`[n=>n+1, n=>n+1, n=>n+1] -> 3`).
* **The Code Experiment**:
  * *Naive*: Calling `setPasses(passes + 1)` three times in one click handler, resulting in a single increment.
  * *React*: Calling `setPasses(prev => prev + 1)` three times, properly queueing three transformations to increment by 3.
* **Scope Boundary**: Focus on update queueing, automatic batching basics in event handlers, and the updater function syntax. Do not cover `flushSync` (Q65) or React 18 concurrent microtask batching internals (Q75).
