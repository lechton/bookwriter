# Q01: What is React and the Declarative Model
* **Topic Tag**: `#what_is_react` | `❱ CORE`
* **Interview Question**: *What is React, and how does its declarative, component-based model differ from plain JavaScript DOM scripting?*
* **Core Truth**: React replaces manual imperative DOM hunting with automatic declarative synchronization derived from data.
* **The Friction**: Elena updates her name on The National Times, but it lives in 10 places across the screen. In plain JS, manual queries inevitably miss elements, causing **state drift**.
* **The Mechanism**: Declarative UI. You write a component describing what the UI should look like for a given state; React's mounting engine calculates and applies the physical DOM updates.
* **Under the Hood**: Why manual `innerHTML` destroys input cursor focus, and how React diffs in memory to surgically patch only changed text nodes.
* **The Code Experiment**:
  * *Naive*: Plain JS `updateHeaderUser` querying DOM IDs by hand, leaving one widget stale.
  * *React*: `SiteHeader` holding `readerName` and distributing it to greeting and subscriber badge widgets from that single truth.
* **Scope Boundary**: Strictly focus on the mental shift (imperative hunting vs declarative rendering). Keep data static; do not introduce `useState`, event handlers, or lifecycle logic.
