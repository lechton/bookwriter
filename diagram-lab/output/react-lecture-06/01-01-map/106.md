# Q106: The 'use client' Directive: Establishing Client Boundaries
* **Topic Tag**: #use_client | ❱ CORE (Server)
* **Interview Question**: *What does the 'use client' directive do, and where does the client boundary sit?*
* **Core Truth**: The 'use client' directive is a bundler instruction placed at the top of a file that establishes a boundary between server and client module graphs, marking the file and all its transitive imports for inclusion in the client JavaScript bundle.
* **The Friction**: A developer wants to add an interactive bookmark button to an editorial article at The National Times; they place 'use client' at the root of ArticlePage.tsx, accidentally forcing the entire 200KB article tree, syntax highlighters, and markdown parser into the client JavaScript bundle.
* **The Mechanism**: 'use client' sits at the very top of a file (before imports); it designates an entry point into the client component module graph; all components imported by a 'use client' file automatically become client components.
* **Under the Hood**: Bundler module splitting: when the bundler encounters 'use client', it splits the dependency graph; on the server, the component is treated as a Client Reference (a stub containing file path and export name); on the client, it compiles into a bundle chunk downloaded by the browser.
* **The Code Experiment**:
  * *Naive*: Adding 'use client' to the top-level page component just to use useState in a small nested button, bloat-packing the entire page into the client bundle.
  * *React*: Keeping the page as a Server Component and extracting only the interactive BookmarkButton into a separate file marked with 'use client'.
* **Scope Boundary**: Focus on the meaning of 'use client', where to place the boundary, and module graph splitting. Do not confuse with 'use server' (Q110).
