# Q58: Caching Expensive Calculations with useMemo
* **Topic Tag**: `#use_memo` | `❱❱ MORE`
* **Interview Question**: *What does useMemo cache, and when is it wasted work?*
* **Core Truth**: `useMemo` caches the calculated result of an expensive function between renders, recomputing it only when its dependencies change; wrapping cheap computations in `useMemo` is wasted overhead that adds memory cost and code complexity.
* **The Friction**: An editor searches an archive of 50,000 news articles. On every unrelated keystroke (like toggling a theme), the component re-filters and sorts the entire 50,000-item array, locking the UI thread. Conversely, another developer wraps `const total = useMemo(() => a + b, [a, b])`, adding hook overhead for a 1-nanosecond addition.
* **The Mechanism**: The `useMemo` hook (`const cachedValue = useMemo(() => computeExpensiveValue(a, b), [a, b])`). On subsequent renders, React returns `cachedValue` directly unless `a` or `b` has changed according to `Object.is`.
* **Under the Hood**: Memory vs computation trade-off: `useMemo` stores the calculation result and dependency array in the component's fiber node; the overhead of allocating closures and comparing dependency arrays can exceed the cost of simple arithmetic or small array operations.
* **The Code Experiment**:
  * *Naive*: Wrapping basic string concatenations or small array lookups in `useMemo`, or recalculating a 50,000-item search filter on every parent render.
  * *React*: An `ArchiveSearch` component using `useMemo` to cache a heavy multi-criteria regex search across 50,000 articles, recomputing only when `query` or `rawArticles` changes.
* **Scope Boundary**: Focus on `useMemo` for expensive computations and reference stability of non-primitive props. Do not cover `useCallback` (Q59) or the React Compiler (Q63).
