# Q111: Directives: 'use client' and 'use server' as Bundler Instructions
* **Topic Tag**: #directives | ❱ CORE (Server)
* **Interview Question**: *Why are 'use client' and 'use server' called directives, and who reads them?*
* **Core Truth**: Directives are prologue string literals recognized by JavaScript compilers and bundlers to establish module boundaries, splitting code into client entrypoints ('use client') or callable RPC endpoints ('use server').
* **The Friction**: A junior developer at The National Times tries to conditionally evaluate if (isClient) { 'use client'; } or import a function called useClient() from React; the bundler ignores the string, the component executes on the server, and reader interactive widgets crash with silent failures.
* **The Mechanism**: Prologue directives: must appear before any executable code or imports (only comments allowed before); consumed by bundlers (Webpack, Turbopack, Vite) via AST plugins to partition the module graph; 'use client' marks client entrypoints, 'use server' marks server-callable endpoints.
* **Under the Hood**: AST analysis in bundler transforms: the bundler parses the AST; encountering a directive in the module prologue triggers a specialized code transform that replaces the module export with either a Client Reference (manifest pointer) or a Server Reference (action ID and RPC dispatcher).
* **The Code Experiment**:
  * *Naive*: Writing 'use client' inside a function body or after an import statement, causing the bundler to treat it as an ordinary dead string literal.
  * *React*: Placing 'use client' or 'use server' as the very first statement at file top level to correctly instruct the bundler compiler transform.
* **Scope Boundary**: Focus on the nature of directives as compiler/bundler prologue instructions and how bundlers consume them. Do not duplicate individual deep dives into 'use client' or 'use server'.
