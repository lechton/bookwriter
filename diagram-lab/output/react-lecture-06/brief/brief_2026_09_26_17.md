# Architectural Decision Brief — 2026-09-26-17: Cross-Lesson Invariant Non-Overlap, Authentic Domain Anti-Patterns, and Multi-Prop JSX Breaking Standard

## Executive Summary
This brief resolves cross-lesson curriculum encroachment, generic artificial strawmen, and multi-prop line width blowouts discovered across Lessons 02, 03, 04, 05, and 06. Under `#2026_09_26_17_group_1`, we establish the **Cross-Lesson Invariant Non-Overlap Standard**, mandating that every principle govern a distinct dimension strictly aligned with the lesson's scope boundary in `01-01-map/{nn}.md` and forbidding duplication of adjacent lesson invariants (e.g. single-root in Lesson 02 vs Lesson 03). We eliminate generic strawmen (such as indiscriminate `document.body.appendChild()` or `window.x` injection) in favor of authentic domain anti-patterns. Finally, we codify the **Multi-Prop JSX Breaking Rule**, mandating that multi-attribute JSX tags place each prop on its own indented line to maintain 100% compliance with the 80-character line width ceiling and ensure populated speech bubble margins in print.

## 1. Root Cause Analysis

### 1.1 Cross-Lesson Curriculum Encroachment
When inspecting Lesson 02 and Lesson 03, Principle 4 of Lesson 02 (*"Produce a Single Root Expression to Satisfy JavaScript Return Grammar"*) duplicated Lesson 03 Principle 1 (*"Return a Single Root Expression to Satisfy JavaScript Function Grammar"*). Single root expression grammar and Fragments belong exclusively to Question 03. This encroachment occurred because authors failed to cross-check adjacent lesson scope maps, leading to topical redundancy.

### 1.2 The Generic Strawman Factory Fallacy
Previous rules listed `document.createElement()` and `window` state as examples of anti-patterns. Authors interpreted this as permission to insert `document.body.appendChild()` or `window.currentHeadline` across Lessons 02, 05, and 06, creating absurd strawmen that no developer actually writes when learning those topics. Meanwhile, genuine platform traps—such as returning `undefined` from missing return statements or guard clauses crashing React—were omitted.

### 1.3 Horizontal Line Overflow on Multi-Prop Tags
In Lessons 04 and 06, multiple code lines exceeded 80 characters (reaching up to 114 characters in Lesson 04). Authors wrote multiple JSX attributes on a single continuous line (e.g. `<ArticleCard title="..." category="..." readTime={6} />`). In PDF print output, lines $> 80$ characters clip through the margin.

## 2. The Solution Architecture (#2026_09_26_17_group_1)

### 2.1 Cross-Lesson Invariant Non-Overlap
- Every principle must govern an independent dimension unique to the current lesson's scope boundary.
- Authors must verify that principles do not duplicate the primary invariant of adjacent lessons.
- In Lesson 02: Single Root is purged and reserved for Lesson 03. Lesson 02 focuses strictly on PascalCase Capitalization, Pure Rendering Calculations, The Return Contract & Null Suppression Whitelist, and Declarative JSX Mounting.

### 2.2 Authentic Domain Anti-Patterns
- Generic `document.body.appendChild()` and `window.x` strawmen are banned.
- Anti-patterns must represent authentic developer mistakes in the question's specific domain (e.g. returning `undefined` vs `null`, inlining function calls `{Card()}`, hardcoding duplicated card copies, mutating frozen prop objects).

### 2.3 Multi-Prop JSX Breaking Rule
- When a JSX element has more than one prop or when a single line exceeds 80 characters, each prop must sit on its own indented line with the closing `/>` or `>` on a new line.
- Guarantees 100% compliance with the 80-character ceiling and ensures speech bubble comments have space to populate margins.
