# Decision Brief 2026-09-21 30: Problematic Code Qualifier Tags and Algorithmic Comment Audit Gate

## Context & Motivation
During the authoring of Lesson 02 (Project Scaffolding: Build Tools vs Full-Stack Frameworks), two distinct code comment defects were identified:
1. **Misapplication of `WRONG` to merely slow code**: The naive monolithic bundler snippet labeled a 45-second cold-start freeze with `// **WRONG:** 45s freeze`. While synchronous whole-project bundling is slow and creates painful developer friction, it is syntactically valid and runnable JavaScript code—it is not technically wrong, illegal syntax, or a fatal runtime crash.
2. **Missing comments and barren margins**: Multiple code blocks (including `Terminal`, `package.json`, and `index.html`) were written with zero comments, and several inline comments lacked the mandatory single uppercase bold keyword (`**KEYWORD**`), leaving speech bubble margins empty.

## Strategic Decisions
1. **The Qualified Verdict Tag Extension**:
   - Reserve `// **WRONG:**` strictly for factually broken code: illegal syntax, compiler crashes, unclosed tags, runtime exceptions, and illegal mutations.
   - Introduce Problematic Code Qualifiers (`**SLOW:**`, `**FRAGILE:**`, `**LEAK:**`): When code is syntactically valid and runnable but suffers from a specific architectural flaw or performance bottleneck that the text is teaching, authors lead with an uppercase qualifier naming the flaw (e.g. `// **SLOW:** 45s cold start compiles all **FILES** into memory`).
2. **The Algorithmic Comment Audit Gate**:
   - Mandate that every narrative body code block ($\ge 3$ lines, including Shell, JSON, HTML, and JSX) must carry end-of-line comments on load-bearing lines.
   - Forbid barren zero-comment code blocks.
   - Mandate exactly one uppercase bold keyword per standard inline comment.
   - Prohibit standalone comment lines above code (which trigger compiler merging notes).
   - Enforce verification via `node src/diagnose-lecture.mjs <NN>`.
