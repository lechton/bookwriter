# Decision Brief — 2026-09-26-04: 1-to-1 UI Canvas Component Parity, Flat Element Invariant, and Empty Container Field Law

## Context & Motivation
1. **The Monolithic Collapse and Unparsed Recursive Brackets Defect**:
   During the review of Lesson 05 (UI as a Tree and Component Hierarchy), the Stage A Rendered UI Canvas (` ```components `) exhibited two critical defects:
   - *Defect 1 (The Monolithic Collapse Fallacy)*: Instead of reflecting the multi-component architecture established in the File Explorer (`App.jsx` -> `NewsHeader.jsx` + `EditorialFeed.jsx` -> `ArticleCard.jsx`), the canvas collapsed all components into a single `App.jsx` monolithic card. The child components disappeared completely from the visual tree.
   - *Defect 2 (Unparsed Recursive Nested Brackets)*: Inside that single `App.jsx` line, the author attempted to model the entire document DOM by deeply nesting element brackets: `[elem:div.national-times-layout: [elem:header.news-header: [elem:h1.title: ...]]]`. Because `component-explorer.mjs` uses single-level regex matching (`mElem = text.match(/^\[(?:elem|ui-elem):\s*(\[[^\]]+\]|[^:]+?)(?::\s*([\s\S]+))?\]$/i)`), the parser could not evaluate nested closing brackets. Raw markdown syntax (`[elem:header...`, `]]]]]`) leaked directly into the rendered HTML card.

2. **The Empty Container Tag Dilemma (`[section.editorial-grid]`)**:
   In Lesson 03, `EditorialColumn.jsx` was declared with `[elem:section.editorial-grid]` in Field 4. In `component-explorer.mjs`, Field 4 renders inside `<div class="component-explorer-surface surface-render">` (`topSurface`), which sits *above* `<div class="component-explorer-children">`. Because `<section className="editorial-grid">` has no visual text of its own, the compiler generated an empty, dashed box floating above the child story card. This confused readers because layout containers have no visual body of their own on screen. When `node.renders` is left empty, `component-explorer.mjs` automatically suppresses the top surface, allowing mounted child components to form the container's interior cleanly.

3. **Root Cause Analysis & Golden Rule of De-Prescription**:
   - In `skills/v6.2/ui-panels/SKILL.md`, Section 01 previously contained a PROPER EXAMPLE that literally taught nested bracket syntax: `FeedbackPortal.jsx | none | shell | [elem:header.portal-header: [elem:h1: Newsroom Feedback Portal]]`.
   - The skills lacked an explicit standard enforcing 1-to-1 structural parity between the ` ```files ` panel and the ` ```components ` canvas.
   - The skills did not specify what authors should put in Field 4 when a component acts solely as an architectural layout container.
   - Applying the Golden Rule of De-Prescription: we pruned the nested bracket exemplar from `ui-panels/SKILL.md`, added explicit 1-to-1 parity requirements, enforced flat element syntax (` ;; `), and established the empty Field 4 rule for pure layout containers.
