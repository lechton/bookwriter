# Architectural Decision Brief — 2026-09-27-12: Card-Free Principle Callouts and In-File Layer Symmetry Standard

## Executive Summary
This batch eliminates the "compulsory card pair" fallacy in principle callouts under tag `#2026_09_27_12_group_1`. Rule 137 in `skills/v6.3/principled-theory/SKILL.md` previously assumed that "BOTH comparative cards (*Do* and *Don't*)" must fit on a single page, which led AI authors to fabricate artificial ("fake") comparative cards for principles that describe architectural models, runtime execution timing, CLI commands, or file extensions. This resulted in grotesque comparisons—such as contrasting an HTML tag against a JavaScript function call (Principle 1), putting terminal CLI commands into code cards (Principle 5), or showing identical code differing only by an inline comment (Principle 6). The revised instructions clarify that `Model` principles and non-syntax rules omit comparative code cards entirely, and establish the **In-File Scope and Layer Symmetry Standard** for when comparative cards are used.

## 1. Root Cause Analysis
- **The compulsory card-pair assumption (Rule 137)**: Stated "so that BOTH comparative cards (*Do* and *Don't*) fit comfortably", which authors interpreted as an absolute commandment that every principle must render two cards.
- **The 100% two-card exemplar bias**: Every exemplar in the Golden Exemplar Bank showed two cards; there was not a single model of a card-free `> [!PRINCIPLE]` callout.
- **Absence of layer symmetry standard**: The instructions lacked a rule requiring that comparative cards represent peer lines of code within the exact same file, programming language, and lexical scope.
- **The resulting defects in Lesson 09**:
  - *Principle 1*: Contrasted `<div id="root">` (HTML) against `createRoot(document.body)` (JavaScript).
  - *Principle 5*: Contrasted `npm run dev` against `open file://` inside JavaScript code cards.
  - *Principle 6*: Showed 100% identical JSX code in both cards, differing only by a fake `// File: src/App.jsx` comment.
  - *Principle 8*: Forced an asynchronous timing invariant into card pairs.

## 2. Resolution (De-Prescription & Standards)
- **De-Prescription of Rule 137**: Softened Rule 137 so that the single-page budget applies "When comparative code cards are present".
- **Card-Free Standard for Model & Non-Syntax Principles (Rule 123)**: Mandated that principles categorized as `Kind: Model` (architectural mental models, execution timing) or non-syntax rules (CLI workflows, file naming) omit comparative code cards from the `> [!PRINCIPLE]` callout block entirely. The definition stands cleanly with its title and glosses, and demonstrations are placed in titled code blocks in the operational derivation below.
- **In-File Scope and Layer Symmetry Standard (Rule 124–125)**: Mandated that when comparative cards are used, both cards must demonstrate competing peer lines of code belonging to the exact same file, language, and lexical scope.
- **Section 04 Exemplars & Counter-Examples**: Added a PROPER EXAMPLE of a card-free `Model` principle callout, along with COUNTER-EXAMPLES of Layer Mismatch, Terminal Commands in Code Cards, and Identical Code with Comment Differences.
- **Audit Verification Gate 10**: Updated in `verification/SKILL.md`.
