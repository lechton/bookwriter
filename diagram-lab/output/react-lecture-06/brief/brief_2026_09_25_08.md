# Decision Brief — 2026-09-25-08: Living Production Mission Openings, Multi-Exemplar Diversity, and Anti-Template-Repetition Law

## Context & Motivation
1. **The Formulaic Repetition Defect across Sequential Lessons**:
   Across sequential lessons (Q01, Q02, Q03, Q04), AI models began opening Section 1 with the identical sentence skeleton: "Think back to how...". The user called this out as unprofessional: *"Think back to how... all lessons now open like this, it is not professional nnn iii"*, followed by the crucial clarification: *"you got it all wrong, there is no problem in starting with Think back.... the problem is writing the same thing in all lectures, get. it? nnn iii"*.
   
2. **Root Cause Analysis & Golden Rule of De-Prescription**:
   In `skills/v6.2/lecture-voice/SKILL.md` (lines 36-40), the instruction system presented only a single proper example of an opening: `"Think back to the very first script you ever wrote in vanilla JavaScript..."`.
   Because only one example existed, models treated it as a rigid boilerplate template to copy indiscriminately across every question in the bank. When previously asked to fix this, the model swung to the opposite extreme—proposing negative bans ("Zero Nostalgic Filler") and cold, sterile technical nitpicks that possessed no meaning for the reader.

3. **The Living Production Mission & Hardcore Negative Anti-Repetition Standard**:
   The user explicitly directed:
   *"In the provided examples add one hardcore negative rule: do not blindly repeat the themes here, but create novel angle and novel grounding and novel expressions how to introduce it, fitting each lecture."*
   
   To establish true pedagogical variety, openings must lead directly with the feature's **living production mission**:
   - **Production Mission**: What the live application accomplishes on *The National Times* (e.g. live newsroom dispatches, reader bookmarking, navigation indexing).
   - **Engineering Purpose**: Why the feature is essential to the system (e.g. projecting live data into markup, coordinating state across widgets).
   - **Developer at the Keyboard**: The concrete component the engineer is actively authoring.
   
   Because every question addresses a distinct production responsibility, deriving the opening from that specific purpose naturally produces organic, authentic variety across sequential lessons. We back this with a multi-exemplar spectrum (data projection, developer baseline, user action) coupled with the hardcore negative rule banning template replication.
