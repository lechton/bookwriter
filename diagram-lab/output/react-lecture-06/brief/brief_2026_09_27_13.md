# Architectural Decision Brief — 2026-09-27-13: Principle Code Comment Bottom-Attachment Standard

## Executive Summary
This batch enforces the Bottom-Attached Speech-Bubble Comment Model Standard in `skills/v6.3/principled-theory/SKILL.md` under tag `#2026_09_27_13_group_1`. The speech bubble cloud (`.cmt-bubble`) has an upward pointer (`▲`) on its top edge and is styled to sit directly beneath the code line it explains, pointing up at that code. However, previous exemplars in Section 04 wrote `// comment` on standalone lines preceding the code. This misled authors into placing comments above the code, causing bubbles to render at the top of cards with upward pointers pointing into card headers or into previous unrelated code lines. This update mandates that comments in principle comparative cards must ALWAYS be authored at the bottom/trailing end of the target code line (`code // comment`), updates all Golden Exemplars to model this standard, and adds a dedicated counter-example for the Inverted Bubble Trap.

## 1. Root Cause Analysis
- **The Exemplar Bias**: In `skills/v6.3/principled-theory/SKILL.md`, exemplars wrote `// comment` on lines above code. Authors emulated this pattern.
- **The Visual Inversion**: Because the compiler processes lines sequentially, putting `// comment` first caused the bubble to be emitted above the code. Since `.cmt-bubble::before` has an upward tail (`▲`), the bubble pointed away from the code into the header.

## 2. Resolution (De-Prescription & Exemplar Alignment)
- **Bottom-Attached Standard (Rule 129–130)**: Mandated that comments inside principle code cards must ALWAYS be placed at the bottom/trailing end of the target code line (`code // comment`), never on a line preceding the code.
- **Golden Exemplar Alignment**: Updated all Golden Exemplars in Section 04 to place comments inline at the end of the code lines.
- **Counter-Example Added**: Added `The Inverted Preceding-Comment Bubble Trap` counter-example in Section 04.
- **Gate 10 Check**: Added explicit verification check in `skills/v6.3/verification/SKILL.md`.
