# Architectural Decision Brief — 2026-09-27-10: The Autonomous Conclusion Standard, Self-Contained Card Test, and Disembodied Diagnostic Ban

## Executive Summary
This batch updates `skills/v6.3/principled-theory/SKILL.md`, `skills/v6.3/RULE-TAGS.md`, `01-01-md-PRE-lectures/v6/08.md`, and `01-02-md-LECTURES/v6/08.md` under tag `#2026_09_27_10_group_1`. It establishes **The Autonomous Conclusion Standard (Self-Contained Bubble Test)**: a reader looking *only* at a principle card's code line and its comment bubble must be able to deduce the physical syntax mistake and governing rule with 100% autonomy, without needing to reference invisible external files or decode terse compiler error codes. It permanently bans disembodied compiler diagnostic mimicry (such as `// Missing named export` or `// Missing default export`) on import statements, requiring explicit syntax token explanations (e.g. `// Wrong: default export cannot use curly braces { }` and `// Wrong: named export cannot omit curly braces { }`).

## 1. Root Cause Analysis

### 1.1 The Disembodied Diagnostic Trap
When authoring Lesson 08 Principle 2 comparative cards, the negative case was tagged with:
```javascript
import { ArticleCard } from './ArticleCard.jsx'; // Missing named export
import Badge from './ArticleCard.jsx';           // Missing default export
```
While `[MISSING_EXPORT]` is what Vite or Rollup prints in a terminal error log, writing "Missing named export" directly on an `import` line creates severe confusion for an autonomous reader:
1. **No export exists in this snippet**: The code is an `import` statement. Labeling an import line with "Missing named export" leads learners to wonder whether they forgot to write an export in the current file, or whether `{ ArticleCard }` somehow creates an export.
2. **The "Ghost File" Fallacy**: The explanation only made sense if the reader simultaneously held the hidden, invisible export declarations of `ArticleCard.jsx` in working memory. The card was not self-contained.
3. **Obscured Developer Action**: It failed to explain what the developer *physically typed wrong* on that line: placing `{}` curly braces around a default export, and omitting `{}` curly braces around a named export.

## 2. Resolution

### 2.1 The Autonomous Conclusion Standard (`skills/v6.3/principled-theory/SKILL.md`)
- Added **The Autonomous Conclusion Standard (Self-Contained Bubble Test)** to Section 04:
  - **Self-Contained Deducibility**: A reader covering the surrounding text and looking *only* at the code line and speech bubble must be able to understand the rule and mistake unambiguously.
  - **Direct Token / Syntax Binding**: Comments must explicitly name the visible syntactic tokens causing the conflict (`default export cannot use curly braces { }`, `named export cannot omit curly braces { }`).
  - **Ban on Disembodied Compiler Error Code Mimicry**: Strictly bans raw compiler error phrases (`Missing named export`, `Invalid hook call`) that refer to external invisible states.

### 2.2 Updating Lesson 08 (Option A)
- In `01-02-md-LECTURES/v6/08.md` and `01-01-md-PRE-lectures/v6/08.md`:
  - Positive Case:
    ```markdown
    > *We should do this:*
    > `import ArticleCard from './ArticleCard.jsx'; // Default import: no curly braces`
    > `import { Badge } from './ArticleCard.jsx'; // Named import: requires curly braces { }`
    ```
  - Negative Case:
    ```markdown
    > *We should not do this:*
    > `import { ArticleCard } from './ArticleCard.jsx'; // Wrong: default export cannot use curly braces { }`
    > `import Badge from './ArticleCard.jsx'; // Wrong: named export cannot omit curly braces { }`
    ```
