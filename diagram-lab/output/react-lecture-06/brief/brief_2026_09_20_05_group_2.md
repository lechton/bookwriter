# Brief 2026_09_20_05_group_2: Old Theme Code Pills

Batch #2026_09_20_05, group_2, working title: Old theme code pills.

## The trigger

The -old reader (the react-lecture-01 retro look) flattened every inline code element to a plain grey chip through one override (`body.theme-old code { ... !important }`), while the teal reader renders the same elements as the designed pill (SF Mono 600, tinted background, teal border, accent text, no mid-token breaking). Inline snippets like the lecture 40 controlled-input line and component-name pills like `ArticleCorrectionForm.jsx` therefore looked deliberately worse in old, inside prose and inside panel description columns alike.

## What changed

src/lecture.css: the theme-old variable block now carries the teal pill values (`--code-pill-color: #0e7490`, `--code-pill-bg: #eef7f9`, `--code-pill-border: rgba(14, 116, 144, 0.25)`), and the grey-chip override block is deleted so the base pill applies. After the first rebuild the user rightly reported no visible change: the snippet they pointed at (the lecture 40 controlled-input line) is a `.code-line-callout` display code line, whose old-theme grey card had been deliberately kept. That carve-out is also removed now, so display code lines get the teal accent-edged card in old as well. The remaining carve-outs stay: the review summary sheet keeps transparent code and the panel surface UI code stays plain. Everything else that makes old old (system fonts, black headings, plain bullets, left-aligned paragraphs) is untouched.

## The philosophy

The old theme is a typographic retro skin, not a downgrade of information design: its accent is already the same teal, so the code pill belongs to the shared design system rather than to one theme. A pill that never breaks mid-token is a reading aid, and reading aids are theme-independent.
