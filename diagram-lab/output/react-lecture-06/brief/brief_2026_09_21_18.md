## 1. Context & Problem
While #2026_09_21_17_group_1 restored comments to Section 1 narrative editor windows, comments in broken code snippets (like Q04 and Q05's fatal JSX errors) lacked the leading verdict tag `**WRONG:**`. This occurred because #2026_09_21_15_group_1 had restricted `**WRONG:**` exclusively to side-by-side comparative blocks contrasting right vs wrong lines directly, and mandated tag-free comments in all other contexts (including baseline snippets).

## 2. Root Cause Analysis
The authoring instructions conflated:
1. **Merely naive or historical code**: code that is syntactically valid and runnable, but un-idiomatic or legacy (e.g. imperative DOM manipulation in Q01).
2. **Flat-out WRONG code**: code that violates language grammar, crashes the compiler, uses reserved keywords, drops unclosed tags, or triggers fatal runtime errors/corruption (e.g. invalid JSX in Q04, quoting variable identifiers in Q05).

When code is broken, readers need an immediate, unmistakable verdict signal: the speech bubble must lead with `**WRONG:**`.

## 3. The Golden Rule Resolution (De-Prescription & Clarification)

   Pruned the restriction that limited `**WRONG:**` strictly to side-by-side comparisons. Codified that all broken code, compiler crashes, and anti-pattern traps MUST lead their comments with `// **WRONG:** [consequence with bold uppercase **KEYWORD**]`.
   Clarified that merely naive or historical baselines that run successfully remain tag-free.
2. **`skills/pre-lecture/SKILL.md` Section 09**:
