State Drift vs Declarative Synchronization

An architectural comparison evaluating how user identity synchronizes across declarative components versus imperative DOM queries.

Component Layer Naive Expectation (Manual DOM Lookups) What Happened (React 19 Reality)
1. The Origin (Parent: SiteHeader) Manual Node Mutation Developers query DOM nodes directly via document.getElementById, requiring manual re-queries whenever reader data changes. Single Source of Truth The parent holds reader data in a single variable and distributes it explicitly downward via props: readerName={readerName}.
2. Greeting Child (ReaderGreeting) DOM Scraping Coupling Component relies on global variables or scrapes HTML elements directly, breaking silently if IDs or classes change. Pure Presenter Boundary Unpacks ({ readerName }) via parameter destructuring and projects it into pure markup with JSX curlies {readerName}.
3. Badge Child (SubscriberBadge) State Drift Hazard Secondary widget queries a separate node; omitting manual updates leaves stale, contradictory data visible on screen. Automatic Synchronization Shares the exact same prop from the parent container. When the parent updates, both sibling components re-render in unison.
4. Root Boundary (App.jsx) Destructive Replacement Writing to container.innerHTML wipes DOM nodes, destroying active cursor focus, text selection, and CSS transitions. UI Tree Reconciliation React reconciles the UI tree in memory and surgically patches only the changed text nodes without touching active inputs.
Final Verdict Fragile State Drift Renaming an element ID or missing one imperative query causes silent state drift and desynchronized screens. Synchronized Data Truth Components stay decoupled from DOM IDs; user interface updates derive strictly and automatically from shared data.
