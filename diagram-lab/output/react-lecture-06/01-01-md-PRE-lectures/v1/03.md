### Lowercase Tags and Silent Disappearances

- [p] ◇ In standard HTML, browsers recognize dozens of built-in tags like `<article>`, `<header>`, and `<p>`. These tags are defined by web standards. When a browser sees a lowercase tag name, it creates a native DOM element in memory. If the tag name is unknown, the browser still creates an empty HTML element. It does not throw an error. It simply paints nothing on the screen. ◼ Educational objective: establish how browsers handle lowercase HTML tags and explain why unknown elements fail silently.
- [p] ★ {preknowledge: JavaScript functions, HTML elements, JSX tags} {bridging: developers assume that any function returning markup can be used as a JSX tag, but lowercase tags bypass the function completely} When Marcus writes a function named `articleCard` and places `<articleCard />` in his JSX, he expects React to run his code. Look at the naive lowercase attempt: ◼ Educational objective: demonstrate the silent failure caused by lowercase component naming.
- [code] Naive Lowercase Component:
```jsx title="Naive Lowercase Tag"
function articleCard() {
  return <article><h2>Breaking News</h2></article>;
}

export default function App() {
  return <articleCard />; // **WRONG:** compiles to native string, bypassing **FUNCTION**
}
```
◼ **The what-this-introduces list:** 1. `function articleCard`: lowercase function declaration. 2. `<articleCard />`: lowercase JSX element tag. 3. `App`: parent component mounting the tag. 4. Silent failure: no build error, but the function never runs.
- [p] ★ {preknowledge: JSX compilation, abstract syntax trees, function references} {bridging: the failure happens because the JSX compiler uses capitalization to decide between a string literal and a function identifier} The JSX compiler does not inspect your JavaScript scope to see if a function exists. Instead, it inspects the first letter of the tag name. If the tag begins with a lowercase letter, the compiler emits a string literal: `_jsx("articlecard")`. React receives this string and calls `document.createElement("articlecard")`. The browser creates an empty native DOM node. Your custom function `articleCard()` is completely ignored. ◼ Educational objective: deconstruct the AST compiler branch that routes lowercase tags to string literals.
- [figure] ```html-figure src="figures/03-00-ast-tag-routing.html" caption="The JSX compiler AST branch: lowercase tags compile to string literals, while capitalized tags compile to function references."```
- [grounding] [!WILD] **Why does a lowercase component fail silently?** The JSX compiler follows a strict syntactic rule. When the tag starts with a lowercase letter, the transpiler generates `_jsx("tagname")`. The browser treats this as an unknown custom element. It creates an empty HTML element without styling or content. The terminal reports a successful build because the syntax is valid JavaScript. The browser console stays empty because unknown HTML tags are permitted by the HTML specification. To tell the compiler that your tag represents a JavaScript function, you must capitalize the first letter: `<ArticleCard />`.
- [callout] > [!TIP]
> **To impress the interviewer:** When asked why React requires PascalCase for components, explain the compiler mechanism. JSX is transpiled into function calls like `_jsx()`. The transpiler uses the first letter to decide whether to pass a string literal (`"div"`) or a direct function identifier (`ArticleCard`). Lowercase tags always become strings, bypassing your component function entirely.

### Component Anatomy and Declarative Invocation

- [p] ◇ A React **component** is a pure JavaScript function that returns user interface markup. It is the fundamental unit of composition in React applications. Every component must satisfy two non-negotiable rules. First, its name must start with an uppercase letter using **PascalCase**. Second, it must return valid JSX markup or null. ◼ Educational objective: define the core anatomy and return contract of a React component.
- [p] ★ {preknowledge: function declarations, return statements, JSX elements} {bridging: developers often wonder whether they can invoke a component directly as a regular JavaScript function or if they must use JSX tags} When mounting a component inside another component, you face an architectural fork between two invocation patterns: ◼ Educational objective: introduce the pedagogical crossroads between imperative function calls and declarative JSX.
- [p] - **Option 1 (The foundational way)**: Call the component directly as a plain JavaScript function (`ArticleCard()`). ◼ Educational objective: declare Option 1 with concrete syntax tokens.
- [p] - **Option 2 (The modern idiomatic way)**: Declare the component as a JSX element tag (`<ArticleCard />`). ◼ Educational objective: declare Option 2 with concrete syntax tokens.
- [p] First, look at Option 1 calling the component imperatively as a function: ◼ Educational objective: transition to Option 1 code.
- [code] Option 1:
```jsx title="Option 1: The Foundational Way (ArticleCard())"
export default function App() {
  return (
    <main>
      {ArticleCard()} // Executes function directly via **PARENTHESES**
    </main>
  );
}
```
◼ **The what-this-introduces list:** 1. `ArticleCard()`: direct imperative function execution. 2. `{}`: expression evaluation window inside JSX. 3. Bypassed component boundary: React treats the returned elements as direct children of App.
- [p] ★ In Option 1, JavaScript executes `ArticleCard()` immediately during render. The function returns its JSX elements, and they appear on the screen. However, React does not see `ArticleCard` as a distinct component node. In the React DevTools tree, `ArticleCard` does not exist. React cannot manage its lifecycle independently, and future features like hooks will fail. ◼ Educational objective: explain the engine consequences and limitations of imperative component execution.
- [p] Next, look at Option 2 declaring the component as a JSX element: ◼ Educational objective: transition to Option 2 code.
- [code] Option 2:
```jsx title="Option 2: The Modern Idiomatic Way (<ArticleCard />)"
export default function App() {
  return (
    <main>
      <ArticleCard /> // Declares component boundary via **JSX TAG**
    </main>
  );
}
```
◼ **The what-this-introduces list:** 1. `<ArticleCard />`: declarative JSX element tag. 2. Self-closing syntax: clean termination for elements without children. 3. First-class component node: React registers the component in its render tree.
- [p] ★ In Option 2, the compiler transforms `<ArticleCard />` into `_jsx(ArticleCard, {})`. You do not execute the function yourself. You pass the function reference to React. React decides when to call `ArticleCard()`, mounts it as an independent node in the component tree, and displays it in React DevTools. This declarative invocation is the cornerstone of React's component model. ◼ Educational objective: analyze how declarative invocation enables React to manage component lifecycles.
- [callout] > [!KEY]
> Always name React components using PascalCase and invoke them declaratively with JSX tags (`<ArticleCard />`). Never call component functions directly with parentheses (`ArticleCard()`).

### Step 1: First, we construct the application shell <App.jsx>

- [p] We begin by constructing the parent application shell in `src/App.jsx`. This component provides the top-level container for our newsroom view. Notice that `App.jsx` imports `ArticleCard` and mounts it declaratively using an uppercase tag: `<ArticleCard />`. It does not execute the function. It hands the component reference to React: ◼ Educational objective: construct the parent shell and demonstrate declarative component mounting.
- [code] App.jsx:
```jsx title="App.jsx"
import ArticleCard from './components/ArticleCard.jsx';

export default function App() {
  return (
    <main className="newsroom-layout">
      <ArticleCard /> // Mounts custom component via **PASCALCASE**
    </main>
  );
}
```
◼ **The what-this-introduces list:** 1. `import ArticleCard`: importing the child component. 2. `export default function App`: root application component. 3. `<main>`: semantic HTML container. 4. `<ArticleCard />`: declarative JSX element tag.
- [p] Notice the syntax on `<ArticleCard />`: it uses self-closing tag syntax with a trailing slash. Because `ArticleCard` contains no inner children in this layout, the self-closing tag provides a clean, concise declaration. If you mistakenly wrote `<articleCard />` here, the compiler would emit a string literal and render a blank space. ◼ Educational objective: emphasize self-closing syntax and reinforce the capitalization rule in the parent.

### Step 3: Then, we write the pure JSX markup return <ArticleCard.jsx>

- [p] Next, we author the JSX markup returned by `ArticleCard`. A component must return markup that describes what appears on screen.       <h2>The Global Energy Shift</h2>            // Displays article **HEADLINE**

◼ **The what-this-introduces list:** 1. `<article>`: semantic HTML container tag. 2. `className`: JSX attribute for CSS classes. 3. `continues="top"`: continuation fence picking up from line 3. 4. Pure return: returns a single root element.
- [p] Notice that the return statement is wrapped in parentheses. In JavaScript, writing `return` on its own line followed by a newline causes Automatic Semicolon Insertion (ASI). The parser inserts a semicolon, returning `undefined` and leaving the screen blank. Wrapping multi-line JSX in parentheses prevents this silent failure. ◼ Educational objective: explain the mechanics of Automatic Semicolon Insertion in multi-line JSX returns.

### Step 4: Finally, we mount the application at the root <src/main.jsx>

- [p] Finally, we connect our application to the physical browser DOM in `src/main.jsx`. This file acts as the mounting bridge. It locates `<div id="root">` and calls `createRoot()`. React then renders `<App />`, executing `ArticleCard()` and committing the `<article>` tree to the document: ◼ Educational objective: complete the assembly by tracing root DOM mounting and declarative invocation.
- [code] src/main.jsx:
```jsx title="src/main.jsx"

import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = createRoot(document.getElementById('root')); // Locates host **DOM**
root.render(
  <StrictMode>
    <App /> // Mounts application tree into **ROOT**
  </StrictMode>
);
```
◼ **The what-this-introduces list:** 1. `createRoot`: React 19 client mounting entry point. 2. `StrictMode`: development runtime checks. 3. `root.render(<App />)`: mounting root component into host DOM.
- [p] Notice the purity of `ArticleCard`: given the same conditions, it always returns the exact same markup description. It does not modify external variables, query the DOM, or cause side effects. This functional purity makes React components predictable and easy to maintain. ◼ Educational objective: introduce component purity and explain why predictable returns matter.

### Glossary

- [glossary] Component ◼ A pure JavaScript function that accepts inputs and returns a tree of JSX element descriptors representing user interface markup.
- [glossary] PascalCase ◼ A naming convention where the first letter of every word is capitalized (`ArticleCard`), required by React compilers to identify custom components.
- [glossary] JSX AST Routing ◼ The compiler mechanism where lowercase tags become string literals (`"div"`) and capitalized tags become direct function identifiers (`ArticleCard`).
- [glossary] Declarative Invocation ◼ Mounting a component using JSX tag syntax (`<ArticleCard />`), allowing React to control function execution and lifecycle management.
- [glossary] Component Purity ◼ The architectural contract that a component function must calculate its output without mutating external variables or causing side effects during render.

## Beyond the basics

- **JSX compiler transform specification**: Modern React uses the `react/jsx-runtime` automatic transform, where `<ArticleCard />` compiles to `_jsx(ArticleCard, {})` and `<article />` compiles to `_jsx("article", {})` (see [react.dev/learn/your-first-component](https://react.dev/learn/your-first-component)).
- **Component purity and idempotent rendering**: React expects component functions to be pure calculations; given the same inputs, they must always return the exact same JSX without modifying preexisting variables outside their scope (see [react.dev/learn/keeping-components-pure](https://react.dev/learn/keeping-components-pure)).
- **The render tree and component instances**: When you declare `<ArticleCard />` in JSX, React creates an in-memory element descriptor; it does not instantiate a persistent object until it reconciles the render tree (see [react.dev/learn/understanding-your-ui-as-a-tree](https://react.dev/learn/understanding-your-ui-as-a-tree)).
- **Automatic Semicolon Insertion (ASI) in return statements**: JavaScript automatically inserts a semicolon after a bare `return` keyword if followed by a line break, returning `undefined` unless wrapped in parentheses (see [react.dev/learn/writing-markup-with-jsx](https://react.dev/learn/writing-markup-with-jsx)).
- **Custom HTML elements vs React components**: While HTML Web Components use hyphenated lowercase names (`<article-card>`), React components require PascalCase (`<ArticleCard>`) to compile into direct function references (see [react.dev/learn/your-first-component](https://react.dev/learn/your-first-component)).

### Summary

**Architectural Takeaways & Decision Matrix**

❒ Component Capitalization

➔ ALWAYS name component functions with PascalCase (`ArticleCard`) so the JSX compiler emits a function identifier.

➔ NEVER name component functions with lowercase letters (`articleCard`) because the compiler treats lowercase tags as native HTML strings.

➔ IF a component tag renders blank with zero console errors THEN check that the function and tag begin with a capital letter.

❒ Declarative Invocation

➔ ALWAYS mount components using JSX tag syntax (`<ArticleCard />`) to preserve component identity in React DevTools.

➔ NEVER call component functions directly with parentheses (`ArticleCard()`) because this bypasses React's component tree.

**DO THIS:** name components with PascalCase and mount with JSX tags

```jsx right
export default function ArticleCard() {
  return <article><h2>News</h2></article>;
}
```

**DO NOT DO THIS:** name components with lowercase or call as functions

```jsx wrong
function articleCard() {
  return <article><h2>News</h2></article>;
}
```
