### The Disconnected Component and the Blank Screen

- [p] ◇ In plain web development, HTML markup paints DOM nodes directly into the viewport. When you author a React component like `App.jsx`, you write a JavaScript function that returns an in-memory description of user interface elements. Sitting on disk, `App.jsx` is inert code. It has no physical connection to the browser's Document Object Model. Without an explicit bridge connecting your compiled JavaScript bundle to an existing HTML element, the browser parses `index.html`, encounters an empty `<div id="root"></div>`, and displays a completely blank page. ◼ Educational objective: establish why React components require an explicit DOM mounting bridge.
- [p] ★ {preknowledge: HTML div containers, script execution timing, DOM tree nodes} {bridging: developers assume importing a component automatically renders it, but React requires an explicit mounting target} When developers first attempt to connect their component to the DOM, they often reach for legacy APIs or invoke mounting commands before the target container exists in memory. Look at the naive attempt: ◼ Educational objective: demonstrate runtime failure and deprecation warnings caused by legacy mounting patterns.
- [code] Naive Mounting Attempt:
```js title="Naive Mounting Attempt"
import ReactDOM from 'react-dom'; // **WRONG:** legacy package import deprecated in **REACT 19**
import App from './App.jsx';

const container = document.getElementById('root'); // **FRAGILE:** null if script executes before **HTML PARSES**
ReactDOM.render(<App />, container); // **WRONG:** legacy synchronous mounting triggers **DEPRECATION WARNING**
```
◼ **The what-this-introduces list:** 1. `import ReactDOM from 'react-dom'`: legacy monolithic DOM package import. 2. `document.getElementById('root')`: DOM query that can return null. 3. `ReactDOM.render()`: deprecated synchronous mounting method.
- [p] ★ {preknowledge: synchronous DOM mutation, React 19 concurrent rendering, console deprecation warnings} {bridging: ReactDOM.render binds synchronously to the container, blocking concurrent features and producing fatal console warnings} The legacy `ReactDOM.render` API belonged to the pre-concurrent era of React. It forced synchronous rendering, meaning any slow render pass froze the browser main thread. In React 19, `ReactDOM.render` is deprecated. Calling it produces console warnings and disables concurrent features. Furthermore, if your script runs in the `<head>` before the browser parses `<div id="root">`, `document.getElementById('root')` evaluates to `null`. Passing `null` to mounting APIs crashes the application with a fatal `TypeError: Target container is not a DOM element`. ◼ Educational objective: deconstruct the deprecation of ReactDOM.render and the danger of unverified DOM queries.
- [figure] ```html-figure src="figures/09-00-createroot-mounting-bridge.html" caption="Legacy ReactDOM.render synchronously blocks DOM updates, while modern createRoot initializes an asynchronous concurrent root container."```
- [grounding] [!WILD] **Why does createRoot separate creation from rendering?** When developers first learn createRoot, they wonder why React split one ReactDOM.render() call into two separate steps: createRoot(domNode) and root.render(<App />). Why not keep a single function? Because createRoot initializes the concurrent **Fiber root** container on the physical DOM node once, while .render() can be called repeatedly to update the tree. By separating container creation from element rendering, React coordinates concurrent priority levels, preserves event listeners across updates, and allows root unmounting via root.unmount() without tearing down the physical DOM node.
- [callout] > [!TIP]
> **To impress the interviewer:** When asked how App.jsx gets onto the page, explain that createRoot is a **two-step mounting bridge** from react-dom/client. It first creates a concurrent Fiber root container attached to a physical DOM node, and then renders the virtual element tree into that container. Emphasize that legacy ReactDOM.render is deprecated in React 19 because it lacks concurrent rendering support and attaches event listeners globally to document instead of scoping them to the container.

### Principles of React: The Core Laws of Root Mounting and Build Scaffolding

- [p] ◇ To prepare for senior technical interviews, we must separate theory from application and establish the five fundamental laws governing how modern React initializes, attaches, and renders application trees into the browser DOM. In React 19, mounting is not a single opaque function call; it is an explicit bridge between living DOM nodes and concurrent fiber architectures assembled by modern build tools. We formalize these rules into five standalone principles. ◼ Educational objective: establish the necessity of principled mounting architecture for senior interviews.
- [principle] Principle 1: Always Import createRoot from the Dedicated Client Subpath
> [!PRINCIPLE]
> **Principle 1: Always Import createRoot from the Dedicated Client Subpath**
> When mounting an application in the browser, you must always import `createRoot` from the client subpath (`react-dom/client`), strictly avoiding the deprecated monolithic package (`react-dom`).
> 
> >> react-dom/client : dedicated entry point containing browser DOM client mounting APIs
> >> monolithic react-dom : legacy root package containing un-shakable legacy code and server stubs
> 
> *It is best practice to do this:*
> `import { createRoot }`
> `  from 'react-dom/client';`
> 
> *Instead of doing this:*
> `import { createRoot }`
> `  from 'react-dom';`
- [p] ★ {preknowledge: ES module subpath imports, bundler tree-shaking} {bridging: importing from the dedicated subpath isolates client runtime and trims bundle weight} Modern React applications run across diverse runtimes (browsers, Node.js servers, Cloudflare Workers, and Deno runtimes). Browsers require DOM-specific code (`createRoot`), while servers require streaming APIs (`renderToPipeableStream`). The dedicated subpath `react-dom/client` isolates browser-only DOM mounting logic into its own bundle entry point. ◼ Educational objective: deconstruct Principle 1.
- [principle] Principle 2: Create the Fiber Root First, Then Render into It
> [!PRINCIPLE]
> **Principle 2: Create the Fiber Root First, Then Render into It**
> You must mount React applications in two distinct steps: call `createRoot(container)` once to establish the **Fiber root** on your DOM node, and then call `root.render(<App />)` to project the element tree.
> 
> >> Fiber root : internal React data structure that tracks the root container, reconciliation queue, and active component tree
> >> two distinct steps : separating host container initialization from virtual DOM element projection
> 
> *It is best practice to do this:*
> `const root = createRoot(container);`
> `root.render(<App />);`
> 
> *Instead of doing this:*
> `createRoot(container, <App />);`
- [p] ★ {preknowledge: container DOM nodes, component reconciliation} {bridging: two-step lifecycle separates host container infrastructure from component reconciliation} Calling `const root = createRoot(container)` executes the setup phase. React allocates an internal `FiberRootNode` object in memory, establishes the reconciliation work queue, and attaches synthetic event listeners to the host DOM element (`<div id="root">`). This step is performed exactly once during application initialization. ◼ Educational objective: deconstruct Principle 2.
- [principle] Principle 3: Always Verify the Host Container Exists Before Initializing createRoot
> [!PRINCIPLE]
> **Principle 3: Always Verify the Host Container Exists Before Initializing createRoot**
> You must verify that the target DOM container exists before passing it to `createRoot`, throwing an immediate diagnostic error if the element is missing.
> 
> >> defensive container verification : checking whether document.getElementById returned null before mounting
> >> immediate diagnostic error : providing a clear actionable stack trace rather than crashing inside internal React code
> 
> *It is best practice to do this:*
> `const el =`
> `  document.getElementById('root');`
> `if (!el) {`
> `  throw new Error('Missing #root');`
> `}`
> `createRoot(el).render(<App />);`
> 
> *Instead of doing this:*
> `const el =`
> `  document.getElementById('root');`
> `createRoot(el).render(<App />);`
- [p] ★ {preknowledge: DOM query methods, null pointer exceptions} {bridging: unverified DOM queries throw cryptic internal errors when HTML markup fails to load} If an engineer modifies `index.html`, renames `#root`, or loads the script before the DOM tree parses, `document.getElementById('root')` evaluates to `null`. Passing `null` to `createRoot` crashes deep inside React internal code with an obscure error. A defensive check provides an immediate, descriptive error message. ◼ Educational objective: deconstruct Principle 3.
- [principle] Principle 4: Rely on Build Tools to Transpile JSX and Resolve Module Entry Points
> [!PRINCIPLE]
> **Principle 4: Rely on Build Tools to Transpile JSX and Resolve Module Entry Points**
> You must rely on modern build tools like Vite or esbuild to transpile JSX into standard JavaScript functions and serve the root HTML document with module script tags.
> 
> >> build tool transpilation : transforming JSX angle brackets into _jsx() runtime function calls
> >> module script tag : script type="module" in index.html that defers execution until DOM parsing completes
> 
> *It is best practice to do this:*
> `<!-- index.html -->`
> `<div id="root"></div>`
> `<script type="module"`
> `  src="/src/main.jsx"></script>`
> 
> *Instead of doing this:*
> `<!-- Legacy synchronous script -->`
> `<script src="/src/main.jsx"></script>`
- [p] ★ {preknowledge: browser JavaScript limitations, JSX compilation, module scripts} {bridging: browsers cannot execute JSX natively, requiring build tools to assemble the module graph} Web browsers do not understand JSX syntax natively. Build tools like Vite, esbuild, or Rollup intercept `.jsx` files, transpile JSX tags into `_jsx()` function calls, and link module imports into an optimized bundle graph. Serving `main.jsx` via `<script type="module">` guarantees deferred execution after the DOM is ready. ◼ Educational objective: deconstruct Principle 4.
- [principle] Principle 5: Scope Synthetic Event Listeners to the Root Container, Never the Document
> [!PRINCIPLE]
> **Principle 5: Scope Synthetic Event Listeners to the Root Container, Never the Document**
> You must allow React to delegate event listeners to the root DOM container (`<div id="root">`), avoiding global document listeners that pollute external host pages.
> 
> >> root event delegation : attaching event listeners directly to the container div rather than document
> >> micro-frontend isolation : preventing event interference between multiple React roots on the same page
> 
> *It is best practice to do this:*
> `// React delegates to container automatically`
> `const root = createRoot(container);`
> `root.render(<App />);`
> 
> *Instead of doing this:*
> `// Manual global event registration`
> `document.addEventListener(`
> `  'click',`
> `  handler`
> `);`
- [p] ★ {preknowledge: DOM event bubbling, synthetic event system, micro-frontends} {bridging: container-level delegation isolates events and prevents collisions with foreign frameworks} In legacy React 16, all synthetic events attached to `document`. In modern React, `createRoot` attaches all event listeners directly to the host container (`<div id="root">`). This design ensures that multiple independent React applications can coexist on the same web page without their event systems interfering with each other. ◼ Educational objective: deconstruct Principle 5.

### Let's Design a Practical Example

- [p] ◇ To master `createRoot` and understand how `App.jsx` reaches the screen, we will construct the live broadcast desk for The National Times. We will progress across four sequential steps: inspecting the host HTML document in `index.html`, constructing the root component in `src/App.jsx`, declaring the child banner component in `src/components/BreakingBanner.jsx`, and establishing the concurrent mounting bridge in `src/main.jsx`. ◼ Educational objective: outline the practical four-step implementation walkthrough.
- [code] Practical Implementation:
```components title="newsroom-live - Rendered UI Canvas"
App.jsx | none | shell
  BreakingBanner.jsx | none | header | [elem:span.live-pill: [badge: Live Broadcast]] ;; [elem:h1.news-title: Global Energy Accord Finalized]
```
```files title="newsroom-live: File Explorer"

```
- [step] Step 1: First, we inspect the host container <index.html>
- [code] Host Container:
```html title="index.html"
<!DOCTYPE html>
<html lang="en">
  <body>
    <div id="root"></div> <!-- Physical mounting **TARGET** -->
    <script type="module" src="/src/main.jsx"></script> <!-- Module entry **POINT** -->
  </body>
</html>
```
- [step] Step 2: Next, we construct the root component <src/App.jsx>
- [code] Root Component:
```jsx title="src/App.jsx"
import BreakingBanner from './components/BreakingBanner.jsx';

export default function App() {
  return (
    <main className="broadcast-shell">
      <BreakingBanner /> // Mounts broadcast alert at application **ROOT**
    </main>
  );
}
```
- [step] Step 3: Then, we declare the child banner component <src/components/BreakingBanner.jsx>
- [code] Child Component:
```jsx title="src/components/BreakingBanner.jsx"
export default function BreakingBanner() {
  return (
    <header className="banner-header">
      <span className="live-pill">Live Broadcast</span> // Status alert **BADGE**
      <h1 className="news-title">Global Energy Accord Finalized</h1> // Primary news **HEADLINE**
    </header>
  );
}
```
- [step] Step 4: Finally, we initialize createRoot and mount the tree <src/main.jsx>
- [code] Mounting Entry Point:
```jsx title="src/main.jsx"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = document.getElementById('root');
if (!container) {
  throw new Error('Target container div#root was not found'); // Diagnostic **ERROR**
}

const root = createRoot(container); // Initializes concurrent **ROOT**
root.render(<App />); // Projects element tree into **DOM**
```
