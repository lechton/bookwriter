### The Invocation Trap and Event Bubbling

- [p] ◇ In React, responding to user interaction requires understanding the difference between passing a function and calling it. When you attach an event handler to a JSX element, React expects a function reference. If you append parentheses to the function name, JavaScript executes that function immediately during the render pass, long before any user touches the keyboard or mouse. Understanding this distinction is essential for writing responsive, bug-free components. ◼ Educational objective: establish the distinction between function references and premature invocations.
- [p] ★ {preknowledge: JavaScript functions, event listeners, render lifecycle} {bridging: developers append parentheses in JSX, executing actions at render time rather than on user click} When developers write `onClick={handleClick()}`, the function runs as React evaluates the JSX. Its return value (usually `undefined`) is then assigned to the `onClick` prop, leaving the button inert when the user actually clicks it. Worse, if `handleClick()` triggers a state change or an external action, executing it during render can cause an immediate crash or an infinite re-render loop. Look at the naive implementation: ◼ Educational objective: demonstrate the immediate invocation anti-pattern in JSX.
- [code] Naive Event Handler and Unchecked Bubbling:
```jsx title="Naive Event Handler and Unchecked Bubbling"
export default function StoryCard({ story, onSelect }) {
  function handleBookmark() {
    console.log('Bookmarked:', story.id);
  }
  return (
    <article onClick={() => onSelect(story.id)}>
      <h3>{story.title}</h3>
      <button onClick={handleBookmark()}>Bookmark</button>
    </article>
  );
}
```
◼ **The what-this-introduces list:** 1. `onClick={handleBookmark()}`: premature render invocation. 2. Inert button state assigning undefined. 3. Unchecked bubbling triggering parent card clicks.
- [p] ★ {preknowledge: DOM event bubbling, synthetic events, parent-child communication} {bridging: nested clicks bubble to parent elements unless explicitly halted} Notice line 8: `onClick={handleBookmark()}`. The parentheses cause `handleBookmark` to execute immediately when `StoryCard` renders. Furthermore, even if we pass the function reference properly as `onClick={handleBookmark}`, clicking the button will bubble up through the DOM tree, firing the outer `<article>`'s `onClick` handler as well! A user attempting to save a story accidentally triggers navigation to that story. ◼ Educational objective: explain how event bubbling causes accidental parent activations.

- [grounding] [!WILD] **Why does React wrap browser events in SyntheticEvent?** In the browser DOM, event implementations historically varied across browser engines. React normalizes all native events into a unified `SyntheticEvent` wrapper that matches the W3C event specification. Under the hood in React 19, React attaches event listeners at the root DOM container rather than individual DOM nodes. This event delegation architecture provides identical cross-browser behavior, improves memory efficiency, and ensures methods like `e.stopPropagation()` and `e.preventDefault()` work consistently across every platform.
- [callout] > [!TIP]
> **To impress the interviewer:** When asked how React handles events, emphasize that React passes function references, not function invocations. Explain that React uses event delegation at the root container to manage synthetic events efficiently. Clarify that callback props enable unidirectional data flow: parents pass functions downward, and children invoke them upward with parameters. Finally, highlight that stopping propagation (`e.stopPropagation()`) is critical in nested interactive components to isolate user gestures.

### Principles of React: The Core Laws of Event Handling and Callback Communication

- [p] ◇ To prepare for senior technical interviews, we must separate naive scripting habits from React's event architecture and establish the five fundamental laws governing how components handle user gestures, prevent bubbling, and communicate across component boundaries. In React, event handling is governed by declarative function binding, propagation control, and unidirectional callback contracts. We formalize these rules into five standalone principles. ◼ Educational objective: establish the architectural necessity of principled event handling.
- [principle] Principle 1: Pass Event Handlers as Function References, Never Call Them in JSX
> [!PRINCIPLE]
> **Principle 1: Pass Event Handlers as Function References, Never Call Them in JSX**
> You must pass event handlers as **direct function references** rather than calling them with parentheses, ensuring they execute only when the user triggers the event.
> 
> >> function reference : passing an uninvoked identifier like handleClick to wait for interaction
> >> immediate invocation : appending parentheses like handleClick() executing at render time
> 
> *It is best practice to do this:*
> `<button onClick={handleClick}>`
> `  Save Article`
> `</button>`
> 
> *Instead of doing this:*
> `<button onClick={handleClick()}>`
> `  Save Article`
> `</button>`
- [p] ★ {preknowledge: function pointers, invocation operator, JSX evaluation} {bridging: calling functions during render returns undefined and triggers premature execution} In senior technical interviews, explaining why event handlers must be passed as references rather than invoked in JSX highlights render lifecycle fundamentals: ◼ Educational objective: deconstruct Principle 1.
- [principle] Principle 2: Wrap Handlers in Inline Functions When Passing Arguments
> [!PRINCIPLE]
> **Principle 2: Wrap Handlers in Inline Functions When Passing Arguments**
> You must wrap event handlers in an **inline arrow function** whenever passing custom arguments, preventing immediate execution while delivering necessary parameters.
> 
> >> inline arrow handler : an anonymous function wrapper that defers invocation until clicked
> >> parameter forwarding : delivering dynamic identifiers or record payloads to handler callbacks
> 
> *It is best practice to do this:*
> `<button`
> `  onClick={() => handleSelect(id)}>`
> `  Read`
> `</button>`
> 
> *Instead of doing this:*
> `<button`
> `  onClick={handleSelect(id)}>`
> `  Read`
> `</button>`
- [p] ★ {preknowledge: closures, arrow functions, parameter passing} {bridging: arrow function wrappers defer parameterised invocation until the click occurs} Interviewers test whether candidates understand parameter forwarding without accidentally triggering render-time execution: ◼ Educational objective: deconstruct Principle 2.
- [principle] Principle 3: Stop Event Propagation to Prevent Parent Trigger Collisions
> [!PRINCIPLE]
> **Principle 3: Stop Event Propagation to Prevent Parent Trigger Collisions**
> You must call `e.stopPropagation()` on nested interactive elements to prevent events from **bubbling up the DOM tree** and firing unwanted parent handlers.
> 
> >> event bubbling : native DOM traversal where events bubble up from child to ancestors
> >> propagation isolation : stopping event traversal at the child boundary using stopPropagation
> 
> *It is best practice to do this:*
> `function handleBookmark(e) {`
> `  e.stopPropagation();`
> `  onBookmark(storyId);`
> `}`
> 
> *Instead of doing this:*
> `function handleBookmark() {`
> `  // Bubbles to parent card!`
> `  onBookmark(storyId);`
> `}`
- [p] ★ {preknowledge: DOM event dispatch, synthetic events, nested layouts} {bridging: unstopped bubbling triggers unintended actions in parent containers} Explaining event bubbling in senior technical interviews reveals your command of both the DOM specification and React's synthetic event system: ◼ Educational objective: deconstruct Principle 3.
- [principle] Principle 4: Prevent Default Browser Actions Declaratively in Handlers
> [!PRINCIPLE]
> **Principle 4: Prevent Default Browser Actions Declaratively in Handlers**
> You must explicitly call `e.preventDefault()` inside event handlers to stop default browser behaviors like **form reloads or link navigation**.
> 
> >> default browser action : native browser reactions like page reload on form submit
> >> synthetic event interception : preventing native browser actions using preventDefault
> 
> *It is best practice to do this:*
> `function handleSubmit(e) {`
> `  e.preventDefault();`
> `  onSearch(query);`
> `}`
> 
> *Instead of doing this:*
> `function handleSubmit() {`
> `  // Page reloads and wipes state!`
> `  onSearch(query);`
> `}`
- [p] ★ {preknowledge: HTML forms, link navigation, page refreshes} {bridging: single page applications must intercept browser defaults to preserve client state} Handling native browser defaults demonstrates why Single Page Applications rely on event interception: ◼ Educational objective: deconstruct Principle 4.
- [principle] Principle 5: Use Callback Props for Inverse Data Flow from Child to Parent
> [!PRINCIPLE]
> **Principle 5: Use Callback Props for Inverse Data Flow from Child to Parent**
> You must pass **callback functions downward as props** to allow child components to notify parent containers of user interactions without mutating parent state.
> 
> >> unidirectional data flow : React law where data flows down via props and events bubble up
> >> inverse callback prop : passing a function downward so a child can emit data upward
> 
> *It is best practice to do this:*
> `// Parent passes callback down`
> `<StoryCard onSelect={handleSelect} />`
> `// Child invokes callback on click`
> `onClick={() => onSelect(story.id)}`
> 
> *Instead of doing this:*
> `// Child mutates parent data directly`
> `story.isSelected = true;`
- [p] ★ {preknowledge: unidirectional architecture, callbacks, state ownership} {bridging: callback props decouple child presentation from parent state management} Unidirectional data flow is React's cornerstone architectural pattern, and callback props are its voice: ◼ Educational objective: deconstruct Principle 5.

- [step] Step 3: Then, we declare the nested bookmark button <BookmarkButton.jsx>
- [code] Bookmark Button Propagation Stop:
```jsx title="src/components/BookmarkButton.jsx" startLine="1"
export default function BookmarkButton({ storyId, onBookmark }) {
  function handleClick(e) {
    e.stopPropagation();
    onBookmark(storyId);
  }
  return <button className="bookmark-btn" onClick={handleClick}>
    Bookmark
  </button>;
}
```
- [step] Step 4: Finally, we mount the application inside App <App.jsx>

];
export default function App() {
  function handleSelect(id) { console.log('Selected:', id); }
  function handleBookmark(id) { console.log('Bookmarked:', id); }
  return <WireFeed stories={STORIES} onSelect={handleSelect} onBookmark={handleBookmark} />;
}
