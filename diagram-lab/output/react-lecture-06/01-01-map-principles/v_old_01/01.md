## Operational Principles

### Principle 1: Describe the Target UI as a Function of Data
- **Operational Rule**: Write a render description of what the interface should look like for the current data instead of scripting every transition from the previous screen. This is the operational meaning of Declarative UI and `UI = f(data)`.
- **Review Point — Do**: Review a component by asking whether its returned markup describes the current result directly.
- **Required Lesson Proof**: Contrast a sequence of DOM query-and-mutate commands with one static React render description driven by the same value.

### Principle 2: Keep Display Data in JavaScript Memory Rather Than the DOM
- **Operational Rule**: Treat JavaScript variables and objects as the data your render reads. Treat the DOM as React's visible output, not as the storage location your application repeatedly queries to recover its own current value.
- **Review Point — Avoid**: Within a React-owned interface, avoid using text content, classes, or data attributes as the primary store for application data.
- **Required Lesson Proof**: Show one JavaScript value producing visible markup and contrast it with code that reads a DOM attribute before deciding what to display.

### Principle 3: Derive Every Repeated Display from One Source of Truth
- **Operational Rule**: When the same fact appears in several places, derive every occurrence from the same JavaScript value. Independent DOM copies drift when one update path misses a header, badge, or sidebar.
- **Review Point — Do**: Trace every repeated display back to one source value during review.
- **Required Lesson Proof**: Show a manual update leaving one widget stale, then show the same source value feeding every rendered occurrence.

### Principle 4: Give React Ownership of Managed DOM Changes
- **Operational Rule**: Update the data that a React tree reads and let reconciliation patch the managed DOM. Manual writes and destructive container replacement create a competing owner, discard useful node identity, and make the next render unpredictable.
- **Review Point — Do not**: Do not use `querySelector`, `appendChild`, or `innerHTML` to update or rebuild nodes that React owns.
- **Required Lesson Proof**: Show a manual `innerHTML` update losing input focus or conflicting with a later render, then show a data-driven React update preserving the input node while changing nearby text.
