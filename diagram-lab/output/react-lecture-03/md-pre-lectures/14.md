### Declaring and Attaching Event Handlers
- [p] Event handlers as component functions: Introduces event handlers as custom functions defined inside component bodies to respond to user interactions (clicks, keypresses, focus, input changes). Explains that event handlers are the primary, designated home for application side effects. ◼ Baptizes classic **Event Listeners**, modern **JSX Event Handlers / Callback Props**, and concrete physical reality of *functions attached to JSX event props registered with React's event delegation system*.
- [p] Standard naming conventions: Outlines the universal React naming idiom: handlers defined inside components start with `handle` followed by the event name (`handleClick`, `handleSubmit`), while callback props passed down from parents start with `on` (`onClick`, `onSelect`). ◼ Establishes clean architectural vocabulary.
- [grounding] Leading Question: What is an event handler in plain English?
  Confusion Point: Beginners often confuse event handlers with automatic render-time expressions.
  Scene & Repetition: In a car, pressing the horn button triggers a sound, and stepping on the brake slows the wheels. The horn does not blow continuously while the engine idles; it waits for your physical press. In React, components work the exact same way. An event handler is a dedicated function that waits silently until a user clicks, types, or hovers. It does not execute during render. It runs only when the user acts. It is just an action waiting for a user trigger, time and time again. Understanding **event handlers** as **user action listeners** clarifies how components execute **side effects** without breaking **component purity**.
  Key Terms (Bold): `**event handlers**`, `**user action listeners**`, `**side effects**`, `**component purity**`.
  Resolution: An event handler is a function passed to JSX that React executes exclusively in response to user interactions like clicks and keystrokes.

### Passing versus Calling Functions: The Invocation Trap
- [p] Function references versus function calls: Deconstructs the single most common mistake in React event handling: writing `onClick={handleClick()}` with trailing parentheses. - [p] Passing callbacks and inline arrows: Demonstrates the correct syntax: `onClick={handleClick}` (passing by reference). Explains how to pass parameters using inline arrow functions: `onClick={() => handleSelect(article.id)}`. ◼ Provides bulletproof syntax recipes.

export default function BookmarkButton({ id, onBookmark }) {

}

### Event Delegation: How React Dispatches Events Behind the Scenes
- [p] Root-level event delegation in React 19: Explains React's physical event engine. In modern React, React does not attach separate event listeners to every individual DOM node. Instead, it attaches a single listener per event type at the root container (`#root`). When an event occurs, React catches it at the root and maps it back down through its virtual component hierarchy, synthesizing the bubbling phase. ◼ Delivers deep under-the-hood engine insight.
- [tip] To impress the interviewer: When asked how React handles events, explain the dual mechanics of SyntheticEvents and event delegation. Point out that in React 18 and 19, event delegation attaches to the root DOM container rather than `document`, preventing collisions in micro-frontends. Explain the critical difference between `e.stopPropagation()` (which halts React's virtual bubbling) and `e.preventDefault()` (which halts browser native defaults). Conclude with the Golden Rule of event props: always pass function references (`onClick={fn}`), never function invocations (`onClick={fn()}`). ◼ Delivers authoritative interview positioning.

### Glossary
- **Event Handler**: A function defined inside or passed to a component that executes in response to a user interaction.
- **SyntheticEvent**: React's cross-browser wrapper around native DOM events providing consistent behavior across all platforms.
- **Event Bubbling**: The natural propagation mechanism where an event triggers on the target element and then bubbles up through its ancestor hierarchy.
- **stopPropagation**: A method on the event object that prevents the active event from bubbling up to parent event listeners.
- **preventDefault**: A method on the event object that stops the browser from executing its default action (such as page reloads on form submissions).

### Summary
**Responding to Events: Handlers, SyntheticEvents, and Propagation**

In daily production, mastering **React event handling** allows you to build rich, responsive user interfaces that handle user clicks, typing, and submissions reliably. By passing functions by reference, intercepting cross-browser SyntheticEvents, and controlling propagation boundaries, your interactions remain clean and predictable. Here is your streetwise review.

❒ Handlers, Function References, and Event Boundaries

1. Define event handlers inside components and pass them by **function reference**.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Always write `onClick={handleClick}`; never write `onClick={handleClick()}` which invokes on render.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) To pass arguments, wrap the call inside an inline arrow function: `onClick={() => handleClick(id)}`.

2. Leverage **SyntheticEvents** for cross-browser reliability and parameter inspection.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) React wraps native browser events in a unified SyntheticEvent matching the W3C standard.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Read user inputs and interaction details directly from properties like `e.target.value`.

3. Control event boundaries using **stopPropagation** and **preventDefault**.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Call `e.stopPropagation()` on nested interactive controls to prevent triggering parent click handlers.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Call `e.preventDefault()` on form submit events to stop the browser from reloading the page.

➔ NEVER call a function directly in an event prop (`onClick={fn()}`) unless it returns another function.

➔ ALWAYS call `e.stopPropagation()` when nesting interactive buttons inside clickable container cards.

➔ IF handling form submissions THEN **call `e.preventDefault()` before executing asynchronous network mutations**.

**DO THIS:** Pass event handlers as references and stop bubbling on nested buttons.

```jsx right title="BookmarkButton.jsx"
export default function BookmarkButton({ onBookmark }) {
  function handleClick(e) {
    e.stopPropagation();
    onBookmark();
  }
  return <button onClick={handleClick}>Save</button>;
}
```

**DO NOT DO THIS:** Never execute functions immediately during JSX render evaluation.

```jsx wrong title="BookmarkButton.jsx"
export default function BookmarkButton({ onBookmark }) {
  // Invokes immediately on render; breaks component!
  return <button onClick={onBookmark()}>Save</button>;
}
```
