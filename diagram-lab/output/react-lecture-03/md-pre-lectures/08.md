### Props: The Component Configuration Channel
- [p] Functions with arguments versus components with props: Compares passing arguments to regular JavaScript functions with passing props to React components. Explains that without props, a component is merely a static visual clone; with props, a single component acts as a reusable factory configuring different labels, prices, and variants. ◼ Baptizes classic **Component Props**, modern **Props Object / Data Contract**, and concrete physical reality of *a frozen JavaScript object passed as the first argument to a component function*.
- [p] Passing props through JSX attributes: Details how parents pass data through JSX attributes using string quotes for static text (`label="Monthly Access"`) and curly braces for dynamic expressions, numbers, and booleans (`price={5}`, `isFeatured={true}`). ◼ Reinforces JSX attribute conventions established in earlier lectures.
- [grounding] Leading Question: What are props in plain English?
  Confusion Point: Beginners often assume props are special framework directives rather than standard function arguments.
  Scene & Repetition: In standard JavaScript, when you want a function to calculate different results, you pass it arguments. You call add(2, 3) or add(10, 20). React components work the exact same way. When you want a button to display a different label or color, you pass it inputs called props. React packs every attribute you write into a single object and hands it to your component function. It is just function arguments wrapped in an object, time and time again.
  Key Terms (Bold): `**props**`, `**function arguments**`, `**component**`, `**data contract**`.
  Resolution: Props are simply plain JavaScript function arguments passed through JSX attributes to configure a component's output.

- [code] SubscribeButton.jsx snippet:
```jsx title="SubscribeButton.jsx"
export default function SubscribeButton({ label, price, isFeatured = false }) {
  return (
    <button className={`sub-btn ${isFeatured ? 'featured' : ''}`}>
      <span className="btn-label">{label}</span> // Projects dynamic label prop into **SPAN**
      <span className="btn-price">${price}</span> // Projects dynamic price prop into **SPAN**
      {isFeatured && <span className="featured-tag">Best Value</span>} // Conditionally renders featured **TAG**
    </button>
  );
}
```
◼ **Code Self-Audit (What this snippet introduces):**
1. `({ label, price, isFeatured = false })`: Object destructuring with default fallback parameter.
2. `className={...}`: Template literal dynamically injecting CSS class based on boolean prop.
3. `{label}` & `{price}`: Interpolated prop values projected into text nodes.
4. `{isFeatured && ...}`: Short-circuit conditional rendering driven by prop flag.
- [p] Destructuring and default values: Unpacks the parameter list. Explains how `{ label, price, isFeatured = false }` extracts the three attributes directly into scope. Explains that if the parent omits `isFeatured`, the variable safely defaults to `false`. ◼ Removes confusion about nested parameter braces.
- [p] Prop interpolation and conditional rendering: Explains how `{label}` and `{price}` are rendered into spans, and how logical AND conditionally renders the "Best Value" tag only when `isFeatured` is `true`. ◼ Shows how multiple props combine into rich UI output.

### The Immutability Law: Why Props Are Strictly Read-Only
- [p] Pure functions and the immutability constraint: Explains why a component can never modify its own props. Details that React components are designed to act as pure functions: given the same inputs, they must return the same user interface description without causing external side effects. ◼ Baptizes **immutability law**, **read-only snapshots**, and **pure function**.
- [p] The danger of prop mutation: Analyzes what happens if a child component attempts to mutate `props.price = 0`. Explains that because the parent component owns the original data, mutating props from a child would secretly alter shared data from behind, corrupting parent state and causing silent state drift across sibling components. ◼ Unpacks the runtime rationale for `Object.freeze()`.
- [p] Unidirectional data flow in React: Details the principle of **unidirectional data flow** (one-way data flow). Explains that data flows strictly downward from parent to child. If a value needs to change over time, the parent component must hold that value in state and pass a new snapshot downward during a re-render. ◼ Baptizes **unidirectional data flow**.
- [grounding] Leading Question: Why can a component never mutate props?
  Confusion Point: Developers attempt to reformat or normalize data by reassigning props directly inside child components.
  Scene & Repetition: Imagine you hire a courier to deliver an official contract. The courier opens the envelope, crosses out the price with a pen, and writes a new number. The recipient and the sender are now completely out of sync. Chaos ensues. This is why React freezes props. Props are an official delivery from the parent component. If a child component could alter its own props, data would change secretly from behind, causing subtle bugs across your app. This is the **immutability law**: props are strictly **read-only snapshots**, preserving **unidirectional data flow**.
  Key Terms (Bold): `**immutability law**`, `**read-only snapshots**`, `**props**`, `**unidirectional data flow**`.
  Resolution: Props are strictly read-only so data flows in a single predictable direction from parent to child without unexpected side effects.
- [callout] Senior interview strategy: Explaining props immutability and pure components during senior technical interviews. ◼ Focus on pure functions, predictable time-travel debugging, preventing state drift, and preserving unidirectional data flow.

### Glossary
- [glossary] Props ◼ The inputs passed to a React component via JSX attributes, assembled by React into a single read-only JavaScript object.
- [glossary] Object Destructuring ◼ The JavaScript syntax ({ label, price }) used in component parameters to extract properties from the props object directly into local variables.
- [glossary] Unidirectional Data Flow ◼ The architectural principle in React where data always flows in one single direction, downward from parent components to child components.
- [glossary] Immutability ◼ The rule stating that props cannot be modified, reassigned, or mutated by the receiving child component.
- [glossary] Default Prop Value ◼ A fallback value assigned during destructuring (such as isFeatured = false) used when the parent omits that prop.

- [code] DO THIS: Extract props using object destructuring and treat them as immutable inputs.
```jsx right title="SubscribeButton.jsx"
export default function SubscribeButton({ label, price }) {
  return (
    <button className="sub-btn">
      <span>{label}</span>
      <span>${price}</span>
    </button>
  );
}
```
◼ **Code Self-Audit (What makes the right code resilient):**
1. `({ label, price })`: Uses object destructuring in the parameter signature for clean, readable variable access.
2. Treats `label` and `price` as read-only inputs, projecting them directly into JSX text nodes without mutation.
- [code] DO NOT DO THIS: Never attempt to mutate or reassign incoming props inside a child component.
```jsx wrong title="SubscribeButton.jsx"
export default function SubscribeButton(props) {
  props.price = props.price * 0.9; // **WRONG:** mutating props crashes or corrupts parent **STATE**
  return <button>{props.label} - ${props.price}</button>;
}
```
◼ **Code Self-Audit (The runtime failure and state corruption triggered by the wrong code):**
1. `props.price = props.price * 0.9`: Directly mutates the incoming props object, violating React's immutability law.
2. In strict mode, React freezes the props object, throwing a `TypeError: Cannot assign to read only property` crash.
