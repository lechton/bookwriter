# Pre-Lecture Blueprint: Q07 — Container Composition with Children and Prop Spreading

- [ladder-1] You built a component that shows a news story with its title and author. ◼ Educational objective: name what the reader is building.
- [ladder-2] One story has no author, but the page still shows the word "By" with nothing after it. ◼ Educational objective: show the failure the reader can see.
- [ladder-3] How can one component keep the same design for every story and let each story choose its content? ◼ Educational objective: ask the lesson's question plainly.

### One design, different content for every story

- [p] ◇ {theme} On a news site, every story appears in the same card: the same border, the same spacing, the same layout. Only the content changes. One story has a title and an author, another a title and a photo, another only a title. Every React developer meets this question: how does one card component show different content for each story? ◼ Educational objective: bird's-eye view; open with the theme from the map's Theme and Options, from a page the reader knows.

- [p] ◇ {categories: the count} There are two ways to give a card its content. ◼ Educational objective: categorical clarity; the count comes first.

- [p] ◇ {way 1: props, Lecture 6} The first way is props, which the reader met in Lecture 6. The caller passes values as attributes. ◼ Educational objective: the earlier way, named with its lecture.

- [code] Props: the caller passes values:

```jsx title="Props: the caller passes values"
<NewsCard title="New Park Opens Today" author="Anna Lyon" /> {/* values */}
```

- [code] Props: inside NewsCard:

```jsx title="Props: inside NewsCard"
<h2>{title}</h2>
<p>By {author}</p> {/* drawn for every story */}
```

◼ **The what-this-introduces list:** 1. `NewsCard`: one prop for each piece of text. 2. `author`: a value the card places in a line it always draws.

- [p] ◇ {way 1: who decides, when it fits} The card decides what the content looks like: always a title, then a line that starts with "By"; the caller only fills in the values. It fits well when every card shows the same pieces in the same order (a product card with a name and a price). It fits badly when stories differ: "By" with nothing after it, and no place for a photo. ◼ Educational objective: a fair account of the first way, with where it fits and where it fails.

- [p] ◇ {way 2: children, this chapter} The second way is children, which this chapter teaches. The caller does not pass values in attributes; it writes the content itself in a place the reader knows from HTML, between the card's opening and closing tags. ◼ Educational objective: the chapter's way, named, and the place pointed at.

- [code] Children: the place for the content:

```jsx title="Children: the place for the content"
<CardContainer>
  The content goes here {/* this becomes children */}
</CardContainer>
```

- [p] ◇ {way 2: what fills the place} Whatever we write between `<CardContainer>` and `</CardContainer>`, React collects automatically and hands to the card inside a prop named `children`. We never write the word `children` in the call and do not choose the name. ◼ Educational objective: point into the code: the place, what fills it, who moves it, what it is called.

- [p] ◇ {way 2: the contrast with props} With props, the information sits inside the opening tag, in an attribute whose name we choose, such as `title`. With `children`, it sits between the tags, and its name is fixed. ◼ Educational objective: set the new idea against the one the reader knows (owner's direction, `intro-examples.md` Example 2).

- [p] ◇ {way 2: the real example} So a story with a photo and no author writes exactly that between the tags, a heading and an image. ◼ Educational objective: say what the next code is for.

- [code] Children: the caller writes the content:

```jsx title="Children: the caller writes the content"
<CardContainer>
  <h2>New Park Opens Today</h2>
  <img src="/park.jpg" alt="The new park" /> {/* a photo, no author */}
</CardContainer>
```

- [code] Children: inside CardContainer:

```jsx title="Children: inside CardContainer"
<div className="card">{children}</div> {/* all of it lands here */}
```

◼ **The what-this-introduces list:** 1. `CardContainer`: a card that draws only the design. 2. `{children}`: the place where the caller's content appears.

- [p] ◇ {way 2: who decides} Both lines, the `<h2>` and the `<img>`, arrive in the card as `children`, and one line inside the card decides where they appear. The card writes `{children}` where the content should appear and does not need to know what it is. The caller decides the content, and the card gives only the design around it: a photo story writes an `<img>`, a story without an author writes no author line. ◼ Educational objective: who decides what in the second way; the runway teaches it in full.

- [ways] Two ways to give a card its content ◼ (1) Give the card its content with **props** (Lecture 6): the card decides the layout, and the caller passes the values. (2) Give the card its content with **children** (this chapter): the caller writes the content, and the card gives the design around it. ◼ Educational objective: the `> [!WAYS]` reminder after the explanation, repeating the frame "Give the card its content with", one way per line.

- [p] ◇ {later way} Some components need content in more than one place, such as a header and a footer; for those, developers pass JSX in named props or use patterns such as render props, which Lecture 89 covers. ◼ Educational objective: the advanced way a senior would mention, in one sentence with its lecture, not taught.

- [p] ◇ {this chapter's way} Owner's sentence, kept as written: "In this chapter, we write one React component that keeps the design the same and lets each story decide its own content. In React, this approach is enabled by a prop named `children`." Then the path: a card that forgets to place it, why one prop for every piece breaks when stories differ, how the card passes on attributes and its class, and the two ways compared again at the end. ◼ Educational objective: say where the chapter goes.

- [p] ◇ {question} This lesson answers three questions, in bold, one per line: How does content written between a component's tags reach the component? How do we pass attributes like `id` and `aria-label` through a component without listing each one? How do we keep the container's class and add the caller's class, even when the caller passes none? ◼ Educational objective: the three parts of the interview question, in the reader's words.

- [recall] Lecture 3 (JSX) ◼ JSX compiles every tag into a `_jsx` call that returns an object describing the element. Attributes such as `aria-label` and `data-story-id` keep their dashes, and `class` is written `className`.
- [recall] Lecture 4 (Values in JSX) ◼ Curly braces put a JavaScript value into the markup. `null`, `undefined`, and `false` show nothing on the screen, and `+` joins two strings into one.
- [recall] Lecture 5 (The component tree) ◼ Writing one tag inside another builds the tree of components and elements on the page.
- [recall] Lecture 6 (Props) ◼ The attributes on a component's tag arrive as one props object, and braces in the parameter list unpack its keys. A default such as `author = 'Staff'` fills a prop the caller left out.

### Content between a component's tags arrives as the children prop

- [runway] The `children` prop, used by Questions 1, 2, 3, and 4.

- [p] ◇ {runway: purpose, then name it and show it} A close look at the second way: `CardContainer` has one job, to draw the shared design. The story's content goes between its opening and closing tags, the same way the reader nests an `<h2>` inside an `<article>`. ◼ Educational objective: say what the new component is for before showing it.

- [code] Content between the tags:

```jsx title="Content between the tags"
<CardContainer>
  <h2>New Park Opens Today</h2> {/* this whole line goes to CardContainer */}
</CardContainer>
```

- [p] ◇ {runway: who does what, spelled out} Look at what sits between `<CardContainer>` and `</CardContainer>`: the whole line `<h2>New Park Opens Today</h2>`. React takes everything written between the opening and the closing tag and hands it to `CardContainer` as a prop. That prop is always called `children`; the reader does not choose the name. Picture: `<CardContainer>` the children are here `</CardContainer>`. Inside `CardContainer`, `children` holds the `<h2>` the caller wrote; with three elements, it holds all three. The `_jsx` call from Lecture 3 shows the same thing. ◼ Educational objective: spell out what moves where, instead of "React puts that `<h2>` into the props object under the key `children`".

- [code] Compiled call:

```js title="Compiled call"
_jsx(CardContainer, {
  children: _jsx("h2", { children: "New Park Opens Today" }), // the nested h2
});
```

- [p] ◇ {runway: the receiving side} To show that content, `CardContainer` unpacks `children` from its props, as Lecture 6 taught for any prop, and writes `{children}` where the content should appear. ◼ Educational objective: show the receiving side in its own fence.

- [code] Where the container places children:

```jsx title="Where the container places children"
function CardContainer({ children }) {
  return <div className="card">{children}</div>; // the h2 lands in the div
}
```

- [p] ◇ {runway: second tiny example} Because the content comes from the caller, the same `CardContainer` works for a different story: the caller writes a photo and a headline. `children` holds both, and they appear inside the shared design in the order the caller wrote them. Closing rule: whatever you write between a component's tags reaches that component as its `children` prop. ◼ Educational objective: confirm the idea with different content.

- [code] A photo and a headline as children:

```jsx title="A photo and a headline as children"
<CardContainer>
  <img src="/school.jpg" alt="Children walking to school" /> {/* first child */}
  <h2>School Starts on Monday</h2> {/* second child */}
</CardContainer>
```

- [p] ◇ {runway: container component} A component like `CardContainer`, which draws a shared design and shows whatever it receives as `children`, is called a **container component**. The caller decides the content, and the container decides the design around it. Preview, one sentence: Lecture 10 shows how a container can show nothing at all when it receives no content. ◼ Educational objective: name the term from the map's Terms table; the map's Preview row.

### Rest syntax collects the props you did not name

- [runway] Rest syntax in destructuring, used by Questions 3 and 4.

- [p] ◇ {runway: purpose, then plain JavaScript first} A container often receives more props than it uses itself, such as an `id` or an `aria-label` for its outer element. To collect them, we use rest syntax, a plain JavaScript feature. In destructuring, the reader names the keys they want, and three dots before a last name collect every other key into a new object. ◼ Educational objective: the purpose, then the refresher the Terms table asks for.

- [code] Rest syntax on a plain object:

```js title="Rest syntax on a plain object"
const story = { title: 'New Park', id: 'top', date: 'May 3' };
const { title, ...rest } = story; // title is 'New Park'
console.log(rest); // { id: 'top', date: 'May 3' }
```

- [p] ◇ {runway: on props} `title` leaves the object by name, and `rest` holds the keys that are left; `story` does not change. The props object is an ordinary object, so the same syntax works in a parameter list. The caller writes `<CardContainer id="top" aria-label="Main story">`. ◼ Educational objective: carry the same syntax onto props.

- [code] Rest syntax on props:

```jsx title="Rest syntax on props"
function CardContainer({ children, ...rest }) {
  console.log(rest); // { id: 'top', 'aria-label': 'Main story' }
  return <div className="card">{children}</div>;
}
```

- [p] ◇ {runway: closing rule} `children` takes the nested content by name, and `rest` collects `id` and `aria-label`. Rest syntax takes out the keys you name and gathers all the others into one object. ◼ Educational objective: close with the rule.

### Spread writes every key of an object as an attribute

- [runway] JSX spread attributes, used by Questions 3 and 4.

- [p] ◇ {runway: purpose, then name it and show it} Once the remaining props sit together in one object, we need a way to write them onto an element. In JSX, `{...object}` inside a tag writes each key of the object as an attribute. Two links, one spread and one written by hand, are the same. ◼ Educational objective: the purpose, then the form next to its code.

- [code] Spread attributes:

```jsx title="Spread attributes"
const link = { href: '/sport', title: 'Sport news' };
const first = <a {...link}>Sport</a>; // link gives href and title
const second = <a href="/sport" title="Sport news">Sport</a>; // written by hand
```

- [p] ◇ {runway: who does what} React reads the object and writes `href` and `title` on the `<a>`, so the browser gets `<a href="/sport" title="Sport news">Sport</a>`. This is called **JSX spread attributes**. ◼ Educational objective: say who acts and what the browser gets.

- [code] Spread attributes with dashes:

```jsx title="Spread attributes with dashes"
const ids = { id: 'top', 'data-story-id': '42' };
const section = <section {...ids}>Top story</section>; // id and data-story-id
```

- [p] ◇ {runway: closing rule} The browser gets `<section id="top" data-story-id="42">`. Rest syntax gathers keys into an object, and spread writes an object's keys back out as attributes. ◼ Educational objective: confirm with a second example and close. The order of attributes around a spread and spreading the whole props object stay with Questions 3 and 4.

### Principles of React: Container Composition and Prop Spreading

[question-cycle]
- Question: Why does content written between a component's tags disappear from the screen?
- Code and result: Caller writes `<CardContainer><h2>New Park Opens Today</h2></CardContainer>`, but `CardContainer` returns `<div className="card" />`. DevTools shows an empty `<div class="card"></div>`, the headline is missing, and the console shows no error.
- Verdict: does not work
- Answer: React did hand the headline to `CardContainer` as `children`, as the first section showed. Receiving the prop is only half of the work: the component decides where the content appears by writing `{children}`. This one never mentions `children`, so React draws the empty `<div>`. No warning, because a component may ignore any prop. Do not re-teach the first section; point back to it.
- Fix: Unpack `{ children }` and write `{children}` inside the `<div>`.
- Rule with boundary: Content between the tags appears only where the component writes `{children}`; if it never does, the content is missing with no warning.
- Needs: `children` prop
- Example: Caller writes a headline between the tags, and `CardContainer` writes `{children}` inside its `<div>`.
- Diagram: ASCII diagram from the caller's tags, through the container's return, to the browser DOM.

> [!PRINCIPLE]
> **Principle 1: Content between the tags arrives as the children prop**
>
> Everything written between a component's opening and closing tags reaches it as a prop named `children`. The content appears only where the component writes `{children}`. If it never does, the content is missing, with no warning.
>
> *We should do this:*
> ```jsx
> function CardContainer({ children }) {
>   return <div className="card">{children}</div>; // shows the content
> }
> ```
> *Instead of doing this:*
> ```jsx
> function CardContainer({ children }) {
>   return <div className="card" />; // content never appears
> }
> ```
> >> `children` prop : The prop that holds everything written between a component's opening and closing tags.

[question-cycle]
- Question: Do we add a new prop to `NewsCard` for every piece a story might have?
- Code and result: A page renders `<NewsCard title="New Park Opens Today" author="Anna Lyon" />` and `<NewsCard title="Rain Expected This Weekend" />`. The second story shows "By" with nothing after it, because `NewsCard` draws `<p>By {author}</p>` for every story. A third story with a photo has no place in `NewsCard`.
- Verdict: does not work
- Answer: Every optional piece becomes one more prop, and `NewsCard` draws each piece for every story, even when the story has none. Each change edits the same shared file, and the order of the pieces stays fixed. `CardContainer` draws only the shared design and writes `{children}`; each caller writes the elements its story has. A named prop stays only for something every story must show in the same place, such as `title`.
- Fix: Write the content between `<CardContainer>` tags instead of adding props to `NewsCard`.
- Rule with boundary: Use `children` for content that differs between stories; keep a named prop only for something every story shows in the same place.
- Needs: container component, `children` prop
- Example: Three stories through `CardContainer`: title and author, title only, photo and title.
- Diagram: ASCII diagram contrasting `NewsCard` with an empty "By" line and `CardContainer` with `{children}`.

> [!PRINCIPLE]
> **Principle 2: Let the caller fill the container instead of adding a prop for every piece**
>
> When stories need different content inside the same design, let each caller write its content between the container's tags. This is called composition. A prop for each optional piece makes the component draw that piece for every story, and every new kind of story changes the shared file.
>
> *We should do this:*
> ```jsx
> <CardContainer>
>   <h2>Rain Expected This Weekend</h2> {/* no author, no empty line */}
> </CardContainer>
> ```
> *Instead of doing this:*
> ```jsx
> <NewsCard title="Rain Expected This Weekend" /> // shows "By" with no author
> ```
> >> composition : Building a component's content from elements the caller writes between its tags.

[question-cycle]
- Question: Can we pass the whole props object onto the container element with spread?
- Code and result: `CardContainer(props)` writes `<div className="card" {...props}>`. Caller passes `isFeatured={true}` and `date="May 3"`. The console warns "React does not recognize the `isFeatured` prop on a DOM element", and DevTools shows `<div class="card" date="May 3">`.
- Verdict: does not work
- Answer: `props` holds everything the caller passed, including props only the component should read. React warns about camelCase names such as `isFeatured` and writes lowercase ones such as `date` into the page; a `title` read for the heading would become a hover tooltip. Rest syntax takes out the props the component reads and leaves the others in `rest`.
- Fix: Unpack `{ children, isFeatured, ...rest }` and spread only `{...rest}` on the `<div>`.
- Rule with boundary: Spread only `{...rest}` on a browser element; never the whole `props` object.
- Needs: rest syntax, JSX spread attributes
- Example: `CardContainer` unpacks `{ children, isFeatured, ...rest }` and writes `<div className="card" {...rest}>{children}</div>`.
- Diagram: ASCII diagram showing `props` splitting into the props the component reads and `rest`, and only `rest` reaching the `<div>`.

> [!PRINCIPLE]
> **Principle 3: Spread only the props the container does not use**
>
> Spreading the whole props object onto a browser element also writes the component's own props there: React warns about camelCase names and writes lowercase ones into the page. Unpack the props the container reads and spread only the rest.
>
> *We should do this:*
> ```jsx
> function CardContainer({ children, isFeatured, ...rest }) {
>   return (
>     <div className="card" {...rest}> {/* only the other props */}
>       {children}
>     </div>
>   );
> }
> ```
> *Instead of doing this:*
> ```jsx
> function CardContainer(props) {
>   return (
>     <div className="card" {...props}> {/* every prop lands on the div */}
>       {props.children}
>     </div>
>   );
> }
> ```
> >> Rest syntax : The `...rest` form in destructuring that collects the keys you did not name into a new object.
> >> JSX spread attributes : The `{...rest}` form in a JSX tag that writes each key of an object as an attribute.

[question-cycle]
- Question: How do we keep the container's class and add the caller's class?
- Code and result: Container renders `<div className="card" {...rest}>{children}</div>`. Caller passes `className="featured"`. DevTools shows `<div class="featured">`; the story loses the border and padding of `.card`.
- Verdict: does not work
- Answer: JSX applies attributes left to right, so `className` in `rest` replaces the one written before the spread; after the spread, the container's class would replace the caller's. JSX never joins classes by itself.
- Fix, in steps (`lecture-structure` Section 12C): the junior fix takes `className` out and joins `'card ' + className`, giving `class="card featured"`; its catch: a story with no class gets `class="card undefined"`, because `+` turns `undefined` into text; the senior fix adds the Lecture 6 default `className = ''`, giving `class="card "`. A caller passing `null` still gets `class="card null"`.
- Rule with boundary: a value before `{...rest}` can be replaced, a value after it always wins; when both sides add a class, take `className` out with `= ''` and join the strings.
- Needs: JSX spread attributes (runway), string `+` (Lecture 4), default parameter value (Lecture 6)
- Example: `CardContainer({ className = '', children, ...rest })` with `className={'card ' + className}`.
- Diagram: one table from the lost class to the finished container: code on the div, what the caller passes, the DOM class.

> [!PRINCIPLE]
> **Principle 4: Around a spread, the last attribute wins; join classes with a default**
>
> JSX applies attributes from left to right: when the same attribute appears twice, the last one wins. When both the container and the caller add a class, take `className` out with a default, `className = ''`, and join the strings yourself, so a missing class does not print `undefined`.
>
> *We should do this:*
> ```jsx
> function CardContainer({ className = '', children, ...rest }) {
>   const fullClass = 'card ' + className; // keeps both classes
>   return <div className={fullClass} {...rest}>{children}</div>;
> }
> ```
> *Instead of doing this:*
> ```jsx
> function CardContainer({ children, ...rest }) {
>   return <div className="card" {...rest}>{children}</div>; // card is lost
> }
> ```
> >> Attribute precedence : The left-to-right order in which a later JSX attribute replaces an earlier one.
> >> Default parameter value : A value in the parameter list that fills a prop when it is missing or `undefined`.

### For the interview

> **The Interview Question:** How do the children prop, spread attributes, and default values work?

- [interview] The Hidden Signal ◼ Whether the candidate knows where these values come from: content between the tags compiles into the `children` prop, a component that passes attributes on unpacks what it reads and spreads only `...rest`, JSX applies attributes left to right, and a default fills a prop the caller left out.
- [interview] The Classic Trap ◼ Assuming `children` is always an array: with one element it is a single object, and `children.map()` throws `TypeError: children.map is not a function`. Writing `<div {...props} />`, which puts the component's own props on the browser element.
- [interview] What is Actually Going On ◼ Nested JSX becomes the `children` key of the props object. The container receives element objects, not finished HTML. Spread copies keys left to right, and the last value wins. Defaults apply only to `undefined` or missing props, never to `null` or `false`.
- [interview] Where It Gets Tricky ◼ `<Card children="attr">nested</Card>`: the content between the tags wins, because the compiler adds it after the attributes. If a container never writes `{children}`, the components between its tags never run.

### Glossary

- [glossary] children prop ◼ The prop that holds everything written between a component's opening and closing tags.
- [glossary] container component ◼ A component that draws a shared design and shows whatever it receives as `children`.
- [glossary] composition ◼ Building a component's content from elements the caller writes between its tags, instead of adding a prop for every piece.
- [glossary] rest syntax ◼ The JavaScript `...rest` form in destructuring that collects the keys you did not name into a new object.
- [glossary] JSX spread attributes ◼ The `{...rest}` form in a JSX tag that writes each key of an object as an attribute.
- [glossary] default parameter value ◼ A value written in the parameter list, such as `className = ''`, that fills a prop when it is `undefined` or left out.
