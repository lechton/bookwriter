LESSONS FROM THE CODE
Container Composition and Passing Attributes On

One prop for every piece of a story, compared with content written as children and props spread with care.

Component Layer Naive Pattern One Prop per Piece NewsCard React Contract Content as Children CardContainer
<StoryList /> Caller Component ✕ Passes one prop for every piece (title, author, imageUrl); a story without an author still shows "By" with nothing after it. ✓ Writes each story's content between <CardContainer> tags: a headline, an author, a date, or a photo, only where the story has one.
<CardContainer /> Container Component ✕ Never writes {children}, so the content is missing with no warning, or calls children.map, which crashes when there is only one child. ✓ Writes {children} where the content belongs and never looks inside it.
{ ...rest } Attribute Forwarding ✕ Spreads full props onto <div {...props}>, so React warns about isFeatured and writes date="May 3" into the page. ✓ Unpacks the props it reads (color, children) and spreads only ...rest, so id and aria-label reach the <div>.
className = '' Order and Defaults ✕ Places static className="card" before spread, so the caller's class replaces it, or joins a missing class into "card undefined". ✓ Gives className the default '' and joins the classes itself (`card card-${color} ${className}`.trim()).
Result
Every new kind of story means another prop and another edit to the shared file; spreading all props puts the component's own props on the page.
The design stays in one place and each caller writes its own content; only the remaining props reach the <div>, and both classes are kept.
