Architectural Contrast Matrix
State Arrays: In-Place Mutation vs Immutable Transitions

Comparing memory references, setter reconciliation, and nested object safety across array operations.

Architectural Layer Array Operation Anti-Pattern In-Place Mutation Same Array Reference React Paradigm Immutable Transition Brand-New Array Container
Removing Items Deleting elements by id or index Broken
items.splice(index, 1)

Mutates array in place. Setter receives the same reference and React skips the render.

 Correct
items.filter(item => item.id !== id)

Produces a fresh array excluding the target id. React detects reference change and re-renders.
Adding & Inserting Appending or placing items at index Crashes
setItems(items.push(newItem))

push() returns length number (4). Next render throws items.map is not a function.

 Correct
[...items, newItem]

Spreads into a new array. To insert at index i, slice before and after the new item.
Reordering & Sorting Changing element order Silent Failure
setItems(items.sort(compare))

sort() returns the same mutated array. Screen stays in old order until unrelated update.

 Correct
items.toSorted(compare)

Returns a new sorted array (or [...items].sort()). Triggers immediate visual re-render.
Updating Item Object Modifying one item's properties Corrupts Snapshots
next[0].title = 'Updated'

Shallow copy shares item objects. Mutating item damages previous renders and breaks Reset.

 Correct
items.map(s => s.id === id ? {...s, title} : s)

Returns a new array with a brand-new object for the edited item. Preserves other item references.
