LESSONS FROM THE CODE
Lifecycle Stages, Subtree Scope & Commit Boundaries

Contrasting imperative DOM timing assumptions with the declarative trigger, render, and commit lifecycle

Component Layer File & Scope Naive Antipattern Imperative Timing Errors Premature Reads & Full Rebuilds Idiomatic Architecture Three-Step Lifecycle Targeted Render & Commit
App.jsx Application Shell ×Global re-render fear: Assumes a click in a child component forces the entire application root to re-render, creating unnecessary performance anxiety. ✓Isolated parent tree: Mounts on initial root trigger; stays completely uncalled during child state updates because it owns no changing state.
StoryTitle.jsx Static Sibling ×Sibling cascade assumption: Expects state updates in adjacent branches to re-render sibling components across the layout. ✓Bypassed sibling subtree: Remains completely idle during like updates because state re-renders cascade strictly downward into the owner's children.
LikeCounter.jsx State Boundary ×Synchronous DOM reads: Mutates textContent directly or queries the DOM immediately after calling setLikes, reading stale uncommitted text. ✓Computed variable flow: Computes the next state value once in a local variable, triggers a re-render with the setter, and passes the computed value to telemetry.
LikeLabel.jsx Child Leaf Display ×Input destruction fear: Fears that re-rendering will rebuild the DOM tree, wiping active user comments and resetting keyboard focus. ✓Targeted node commit: React diffs the returned JSX and updates only the specific text node containing the count, preserving surrounding inputs untouched.
Verdict Stale & Misaligned: Querying the DOM right after a setter reads stale data because the commit runs after the handler, while manual DOM mutations bypass React state. Predictable & Preserved: Triggering via setters, rendering pure component functions, and committing minimal DOM diffs preserves inputs and keeps state synchronized.
