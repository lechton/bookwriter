What props are and how React passes them as a single object

In standard JavaScript, functions accept arguments so that a single calculation can run on different inputs. For example, a function double(x) returns x * 2 for any number you provide. React components are JavaScript functions that return user interface markup. If a component could only return hardcoded text, you would need a new component function for every distinct item in your application. React solves this through props, which is short for properties. Props allow a parent component to pass custom data down to child components, letting one single component layout render hundreds of different stories or products.

When you render a custom component tag in JSX, any attributes you write become properties on a single JavaScript object. For instance, writing <ArticleCard title="Rail Strike Ends" readTime={3} /> tells React to create an object: { title: "Rail Strike Ends", readTime: 3 } React passes this object as the first and only argument to your ArticleCard component function. In React terminology, the location where you render the tag is called the call site, the attributes are called props, and the component receiving the data is the child component. The attributes on the tag do not reach the browser DOM directly; React hands them exclusively to the component function.

When working with props, modern JavaScript provides a concise syntax called object destructuring. Instead of writing function ArticleCard(props) and repeating props.title and props.readTime throughout your markup, you can write function ArticleCard({ title, readTime }) In JavaScript, placing curly braces { } inside the parameter list tells the runtime to automatically unpack specific keys from the incoming object into local variables. This syntax is standard ECMAScript, but it is the universal convention in React because it makes a component's required inputs immediately visible at the top of the function. If a destructured parameter name does not match any attribute on the tag (such as writing { headline } when the tag passed title=), the local variable receives undefined.

Under the hood, the JSX compiler converts every component tag into a function call. As we learned in Lecture 4, writing <ArticleCard title="Rail Strike Ends" readTime={3} /> transforms into _jsx(ArticleCard, { title: "Rail Strike Ends", readTime: 3 }) Notice that the second argument to _jsx is a standard JavaScript object literal. React instantiates this object, freezes it shallowly in development mode using Object.freeze(), and provides it to your component when invoking the function. This mechanical reality proves why components receive exactly one object argument rather than a list of separate parameters.

How JavaScript handles prop types, string concatenation, and default values

In JSX, how you wrap an attribute value determines its JavaScript data type. As established in Lecture 4, quotes pass a static string literal (readTime="5"), while curly braces evaluate a live JavaScript expression (readTime={5}). When a child component receives a prop, the runtime respects that exact type. If a component receives "5" as a string and performs addition ({readTime + 1}), JavaScript performs string concatenation via type coercion, converting 1 to "1" and producing "51". By contrast, multiplication ({readTime * 60}) coerces the string to a number and yields 300. This discrepancy can hide bugs during initial testing until an addition operation reveals the error.

When designing components, some props are optional. If a parent component omits an attribute or passes readTime={undefined}, the incoming property is undefined. To prevent blank slots on screen, JavaScript allows you to specify a default parameter value directly inside the destructuring braces: function ArticleCard({ title, readTime = 5 }) If the parent does not provide readTime, the local variable automatically takes the fallback value 5. However, default parameter values only trigger when a value is strictly undefined or missing; they do not trigger when a parent passes null or 0.

When working with external API data, database records often contain null for unmeasured fields. If a parent passes readTime={null}, the default parameter readTime = 5 does not engage because null is a defined value. In JSX, {null} renders as an empty string, producing min read. In older JavaScript codebases, developers wrote readTime || 5 using the logical OR operator. However, || treats any falsy value as missing, which replaces a valid 0 (such as a 0-minute quick read) with 5. Modern codebases use the nullish coalescing operator (??): const time = readTime ?? 5; Nullish coalescing checks strictly for null and undefined, preserving valid 0 values while providing a resilient fallback.

The read-only contract, frozen objects, and why mutating inputs corrupts the tree

In React, components must be pure functions with respect to their inputs. A pure function is one that does not alter any objects or variables that existed before it was called, and returns the exact same JSX description given the same inputs. Props represent data owned by the parent component. If a child component were allowed to perform a mutation by directly reassigning props.title = 'Breaking News' it would modify memory owned by the parent. React enforces an immutability contract: props are strictly read-only.

To protect developers from accidental mutations, React shallowly freezes the props object in development mode using Object.freeze(). When code runs inside an ES module, JavaScript automatically executes in strict mode. In strict mode, attempting to assign a property on a frozen object immediately throws a fatal exception: TypeError: Cannot assign to read only property 'title' of object '#<Object>' In older non-strict scripts, the assignment is silently ignored without updating the object.

It is critical to understand that React's development freeze is a diagnostic alarm, not a runtime security sandbox. In production builds, React skips Object.freeze() to maximize rendering performance. Furthermore, Object.freeze() is shallow: if a parent passes an object prop like article={{ title: 'Rail Strike', readTime: 3 }} React freezes only the outer container, leaving nested properties mutable. If a child executes article.title = article.title.toUpperCase() the assignment succeeds in both development and production. This mutation silently corrupts data in the parent and across sibling components showing the same article (such as a sidebar), causing state drift.

Instead of mutating incoming props, a component that needs an altered display format calculates a new local variable during render: const headline = title.toUpperCase(); The component renders {headline} in its JSX while leaving the incoming prop completely untouched. If data must change dynamically over time in response to user events, the component does not modify props; instead, the owner component manages that value using React state (introduced in Lecture 14).

For the interview

The Interview Question: How do you pass data into a component, and why can a component never change its own props?

1. The Hidden Signal

The interviewer is testing your grasp of React's component execution model, unidirectional data flow, functional purity, and JavaScript runtime mechanics. A junior candidate says props are "passed like HTML attributes." A senior engineer explains that JSX attributes bundle into a single frozen object passed as the sole argument to the component function, and that props must remain immutable because components must be pure functions with respect to their inputs. Mutating props destroys pure render guarantees, breaks memoization, and causes parent-child state drift across sibling elements.

2. The Classic Trap

The classic trap is assuming that props behave like regular mutable JavaScript function arguments, or attempting to write props.title = props.title.toUpperCase() to clean up display text. Candidates often fail to realize that React freezes props in development, causing fatal TypeError crashes in strict mode. Another frequent trap is forgetting destructuring braces (function Card(title) instead of function Card({ title })), which binds the entire props object to the first parameter and crashes with Objects are not valid as a React child when rendered.

3. What is Actually Going On

Under the hood, the JSX compiler translates component tags into _jsx(Component, propsObject). React instantiates the props object, calls Object.freeze() on it in development, and passes it to the component. Because ES modules execute in JavaScript strict mode, any attempt to assign a property on a frozen object throws a runtime TypeError. In production builds, React skips Object.freeze() to optimize performance, meaning mutations succeed silently in production while failing in development. Furthermore, Object.freeze() is shallow: mutating nested object properties succeeds in all environments, corrupting shared memory in the parent and across sibling components.

4. Where It Gets Tricky

Where this gets tricky in production is handling optional props and fallback values. While default parameter syntax ({ readTime = 5 }) cleanly fills in for missing or undefined props, it does not trigger for null or 0. If an API returns null for an uncalculated field, default parameters leave the value as null, rendering an empty slot. Using logical OR (readTime || 5) replaces valid 0 values because 0 is falsy. Senior engineers use nullish coalescing (readTime ?? 5) during render to preserve valid zeros while providing resilient fallbacks. When data must change over time, state management (Lecture 14) is used instead of prop mutation.

Glossary

  • Props: The single read-only JavaScript object containing all attributes passed from a parent component to a child component.
  • Object Destructuring: The JavaScript syntax using curly braces to unpack specific properties from an object into local variables within a parameter list.
  • Type Coercion: The automatic conversion of values from one data type to another by JavaScript, such as concatenating numbers as strings during addition.
  • Default Parameter: A fallback value specified in a function parameter list that assigns automatically when an incoming argument is missing or undefined.
  • Mutation: The direct modification of an existing object's properties in memory, strictly forbidden on props in React.

Architectural Takeaways & Decision Matrix

❒ Prop Passing and Parameter Destructuring

➔ IF passing data to a child component, THEN write attributes on the custom component tag at the JSX call site.

➔ IF unpacking incoming props, THEN wrap parameter names in curly braces matching attribute names to avoid raw object binding crashes.

❒ Prop Types and Fallback Defaults

➔ IF passing numbers, booleans, or JavaScript expressions, THEN wrap values in curly braces to prevent string type coercion bugs.

➔ IF specifying fallback values for optional props, THEN assign default parameters after = in destructuring, using ?? during render if data can contain null.

❒ Immutability Contract and Component Purity

➔ IF formatting or altering incoming prop values for display, THEN calculate a new local variable during render rather than mutating props.

➔ IF data must change dynamically over time in response to user input, THEN manage that data in state rather than modifying props.
