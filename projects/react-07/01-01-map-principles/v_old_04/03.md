## Authorized Scope
Q03 teaches the syntax rules of JSX and the mechanics of React Fragments: JSX is a syntax extension that compiles into nested `_jsx` calls; every component must return a single root element because JavaScript functions cannot return multiple values without an enclosing container; React Fragments (`<>...</>`) group sibling elements without injecting wrapper DOM nodes, preserving clean DOM trees and CSS flexbox/grid layouts; all tags must be explicitly closed; and standard HTML/SVG attributes use camelCase while `aria-*` and `data-*` attributes preserve their hyphens. It builds on Q01's declarative model and Q02's component anatomy and PascalCase naming, and leaves dynamic curly-brace expressions to Q04, component tree hierarchy to Q05, props to Q06, keyed fragment lists to Q11, ref attachments on fragments to Q34, raw element object inspection and `$$typeof` to Q76, and inline style objects to Q83.

## Principles

### Principle 1: Enclose multiple adjacent elements in a single parent container
- **Kind**: Decision
- **Rule**: Wrap multiple adjacent JSX sibling tags in a single parent container (such as a semantic HTML element or a Fragment), because JSX compiles into a JavaScript expression that evaluates to a single return value, and returning adjacent expressions without an enclosing tag throws a fatal compiler syntax error.
- **Importance**: Fundamental JSX grammar rule; unclosed adjacent returns fail compilation in Vite (`Adjacent JSX elements must be wrapped in an enclosing tag`); essential interview expectation.
- **Review Point — Do**: Wrap all returned sibling elements in a single parent container; never leave adjacent JSX elements unwrapped at the top level of a return statement.
- **Required Lesson Proof**: In `ArticleCard.jsx`, return adjacent `<h1>Headline</h1>` and `<p>Summary</p>` without an enclosing tag; show the Vite compiler build error: `Adjacent JSX elements must be wrapped in an enclosing tag. Did you want a JSX fragment <>...</>?`; then wrap them in a container and show clean compilation.
- **Sources**: card Core Truth, Under the Hood; `writing-markup-with-jsx.md` Rule 1 and DeepDive; merged JavaScript comma operator and single-value return candidate.

### Principle 2: Prefer React Fragments over dummy wrappers when grouping siblings
- **Kind**: Decision
- **Rule**: Use React Fragments (`<>...</>`) to group sibling elements whenever they do not require a shared semantic HTML parent, avoiding redundant wrapper `<div>` nodes that pollute the DOM tree, add unnecessary nesting depth, and break CSS flexbox or grid layout calculations.
- **Importance**: Direct interview question topic ("how do Fragments group elements without wrapper nodes?"); prevents "div soup" and CSS layout breakage that senior reviewers reject in PRs.
- **Review Point — Prefer**: Prefer `<>...</>` Fragments when grouping sibling elements; avoid adding meaningless `<div>` wrapper tags solely to satisfy the single-root rule.
- **Required Lesson Proof**: In `App.jsx`, place three `ArticleCard` instances inside a CSS Grid container (`display: grid; grid-template-columns: repeat(3, 1fr)`); show that wrapping them in a dummy `<div>` causes CSS Grid to treat the wrapper as a single cell, collapsing the 3-column layout into 1 column; replace the wrapper with `<>...</>`, show the DOM tree free of wrapper nodes, and verify all three cards align properly in their 3 grid columns.
- **Sources**: card Mechanism, Code Experiment; `Fragment.md` Intro and Usage; `writing-markup-with-jsx.md` Rule 1; merged CSS layout failure and virtual container candidates.

### Principle 3: Explicitly close every JSX tag, including self-closing elements
- **Kind**: Decision
- **Rule**: Close every JSX tag explicitly, adding a trailing slash to self-closing void elements (`<img />`, `<br />`, `<input />`, `<hr />`) and pairing container tags (`<li>...</li>`), because JSX follows strict XML parsing rules where unclosed tags trigger fatal compile-time syntax errors.
- **Importance**: Distinguishes JSX from loose HTML5; pasting raw HTML with void tags (`<img src="...">`, `<br>`) breaks the build immediately with syntax errors that juniors often struggle to decipher.
- **Review Point — Do not**: Do not omit the closing slash on void elements or leave open container tags; write every tag as `<tag />` or `<tag>...</tag>`.
- **Required Lesson Proof**: Paste a raw HTML snippet containing `<img src="lead.jpg">` and `<br>` into `ArticleCard.jsx`; show the Vite compile error: `Expected corresponding JSX closing tag for <img>` or `Unterminated JSX contents`; fix both tags to `<img src="lead.jpg" />` and `<br />`, and show the build succeeds.
- **Sources**: card Friction, Mechanism; `writing-markup-with-jsx.md` Rule 2 and Challenges 1 & 2.

### Principle 4: Write standard HTML attributes in camelCase while keeping hyphens on aria and data attributes
- **Kind**: Decision
- **Rule**: Name standard HTML and SVG attributes using camelCase (such as `className` for `class` and `htmlFor` for `for`), because JSX attributes compile into JavaScript object keys where reserved words and hyphenated identifiers are invalid, but preserve hyphens on `aria-*` and `data-*` attributes to match web accessibility and dataset standards.
- **Importance**: Senior reviewers flag `class` and `for` in JSX; browsers log console warnings (`Invalid DOM property 'class'. Did you mean 'className'?`); prevents subtle attribute binding bugs.
- **Review Point — Condition**: Use camelCase for standard HTML/SVG attributes (write `className` and `htmlFor`); use hyphens only for `aria-*` and `data-*` attributes.
- **Required Lesson Proof**: Write `<article class="story" for="summary">` in `ArticleCard.jsx`; run the application and show the browser console warnings: `Warning: Invalid DOM property 'class'. Did you mean 'className'?` and `Warning: Invalid DOM property 'for'. Did you mean 'htmlFor'?`; update to `className="story"` and `htmlFor="summary"`, add `aria-label="Story card"` and `data-testid="article-card"`, and verify that the console is clean with zero warnings.
- **Sources**: card Mechanism; `writing-markup-with-jsx.md` Rule 3 and Pitfall; merged JavaScript object key constraint and aria/data caveat candidates.

## Senior Answer
JSX is a syntax extension for JavaScript that lets you write HTML-like markup inside JavaScript files. Under the hood, JSX compiles into nested `_jsx()` function calls that evaluate to JavaScript element descriptor objects, not HTML strings. Because of this compilation step, every component must return a single root element: a JavaScript function cannot return multiple expressions without an enclosing container, so returning adjacent tags throws a compiler syntax error. When sibling elements do not share a semantic parent, you group them with React Fragments (`<>...</>`), which act as virtual containers that React unpacks directly into the parent DOM without injecting wrapper nodes, keeping the DOM tree clean and preserving direct parent-child CSS Flexbox and Grid layouts. Every JSX tag must be closed explicitly, including self-closing void elements like `<img />` and `<br />`. Finally, because JSX attributes compile into keys of JavaScript objects, standard HTML and SVG attributes use camelCase (`className` instead of the reserved word `class`, and `htmlFor` instead of `for`), while `aria-*` and `data-*` attributes preserve their hyphens for accessibility and dataset compatibility. Dynamic values inside curly braces are introduced in Q04, and keyed fragment loops belong to Q11.
