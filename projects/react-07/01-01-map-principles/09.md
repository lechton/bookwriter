## Authorized Scope
Lesson 09 follows the newsroom app from the browser's first request to the first card on screen. The browser loads `index.html`, which holds an empty `<div id="root">`. A `<script type="module">` tag loads `src/main.jsx`. That file imports `createRoot` from `react-dom/client` and `App` from `App.jsx`. `createRoot` hands the `<div>` to React. `root.render(<App />)` calls `App` and puts its output inside the `<div>`. The browser cannot read JSX or package names such as `react-dom/client`. Vite, the build tool, turns each file into plain JavaScript the browser can run. Its dev server does this on every request, and its build writes the finished files for a server. An app has one root, and every other component nests inside `App`. The lesson builds on Q08, where files import each other, and on Q03, where JSX compiles to `_jsx` calls. It also builds on Q01, where plain JavaScript found an element with `document.getElementById`.

## Principles

### Principle 1: `index.html` loads `main.jsx`, and `main.jsx` hands the root element to React
- **Handle**: `page-to-root-chain`
- **Kind**: Model
- **Reader Question**: "My `index.html` has only an empty `<div>`. How does `App` get there?"
- **Reader Expects**: the HTML links `App.jsx`, or React finds the components by itself
- **React Does**: the browser reads `index.html`; `<script type="module" src="/src/main.jsx">` loads `main.jsx`; it imports `createRoot` and `App`; `document.getElementById('root')` finds the `<div>`; `createRoot` makes it the React root; `root.render(<App />)` asks React to call `App` and to replace whatever the `<div>` held with its output; `root.render` returns before that render runs
- **Placement**: `index.html` holds `<div id="root"></div>` and the module script; `main.jsx` holds `createRoot(document.getElementById('root')).render(<App />)`; the id in `getElementById` matches the id in `index.html`
- **Real Mistake**: `createRoot(document.getElementById('app'))` against `<div id="root">`; `getElementById` returns `null`, the console shows "Target container is not a DOM element.", and the page stays blank; verified in React 19.3.0 with Vite 8.3.4
- **Fix In**: this principle
- **Importance**: the first part of the interview question; interviewers ask what `createRoot` does and where `App` starts
- **Prediction**: with `<div id="root">Loading...</div>`, a `console.log(rootEl.textContent)` on the line after `root.render(<App />)` prints "Loading..."; a moment later the page shows the cards, and "Loading..." is gone.
- **Required Lesson Proof**: the three files side by side; the id typo: the error and the blank page; the right id: the cards; the log after `root.render` that still prints "Loading...".

### Principle 2: Serve the app through Vite, never as raw files
- **Handle**: `serve-through-vite`
- **Kind**: Decision
- **Reader Question**: "Can I just open `index.html`, or link `App.jsx` in a script tag?"
- **Reader Expects**: the browser runs any JavaScript file, as it runs any HTML file
- **React Does**: the browser does not read JSX, and it cannot find a package by a name such as `react-dom/client`; the Vite dev server turns each file into plain JavaScript as the browser asks for it, with JSX as `_jsxDEV` calls and package names as file paths; `vite build` writes the finished files into `dist`, with `dist/index.html` pointing to one hashed script
- **Placement**: `npm run dev` while working, and the page opened at the address it prints; `npm run build` before deploying, and only `dist` sent to the server; `index.html` keeps `<script type="module" src="/src/main.jsx">`
- **Real Mistake**: `index.html` opened by double-click, as a `file://` page; Chrome blocks the module script by CORS, and the page shows only its loading text; a plain static server fails too, with "Expected a JavaScript-or-Wasm module script but the server responded with a MIME type of "application/octet-stream""; verified in Chrome 154
- **Importance**: the second part of the interview question; the card's Friction and Naive code
- **Review Point**: Do not
- **Required Lesson Proof**: the same project three ways: `file://`, a plain static server, and `npm run dev`, with the console of each; the Network tab showing `main.jsx` as Vite sends it; `npm run build` and the `dist` folder.

### Principle 3: Pass `root.render` an element, `<App />`
- **Handle**: `render-an-element`
- **Kind**: Decision
- **Reader Question**: "Do I pass `App` or `<App />` to `root.render`?"
- **Reader Expects**: `App` is the component, so pass it, as a function is passed to a handler
- **React Does**: `root.render` takes one React node: JSX such as `<App />`, a string, a number, `null`, or `undefined`; `<App />` is an element that tells React to call `App`; `App` alone is a function, which React cannot draw
- **Placement**: `root.render(<App />)`; a function that returns JSX is called first, `root.render(createApp())`
- **Real Mistake**: `root.render(App)`; the console shows "Functions are not valid as a React child", and the page stays empty; verified in React 19.3.0 with Vite 8.3.4
- **Importance**: a react.dev Troubleshooting entry; the first edit a reader makes to `main.jsx`
- **Review Point**: Do
- **Required Lesson Proof**: `root.render(App)`: the error and the empty page; `root.render(<App />)`: the cards.

### Principle 4: Start the app with `createRoot`, not with `ReactDOM.render`
- **Handle**: `no-legacy-render`
- **Kind**: Decision
- **Reader Question**: "A tutorial writes `ReactDOM.render(<App />, root)`. Why does it fail?"
- **Reader Expects**: tutorials show working code, and React keeps old functions
- **React Does**: React 19 removed `ReactDOM.render`; the entry imports `createRoot` from `react-dom/client`, makes the root once, and calls `render` on it with one argument; root options go to `createRoot`
- **Placement**: `import { createRoot } from 'react-dom/client'`, then `createRoot(rootEl).render(<App />)`; options as `createRoot(rootEl, { onUncaughtError })`
- **Real Mistake**: `import ReactDOM from 'react-dom'` and `ReactDOM.render(<App />, rootEl)`; the console shows "ReactDOM.render is not a function", and the page stays blank; the same habit on the new API, `root.render(<App />, rootEl)`, prints "You passed a second argument to root.render(...) but it only accepts one argument."; verified in React 19.3.0 with Vite 8.3.4
- **Importance**: the card's Naive code; interviewers ask why `createRoot` replaced it; old tutorials and answers still show it
- **Review Point**: Do not
- **Required Lesson Proof**: the legacy call: the error; `root.render` with two arguments: the warning; the `createRoot` entry: the cards.

### Principle 5: Create one root, and nest everything else inside `App`
- **Handle**: `one-root-per-app`
- **Kind**: Decision
- **Reader Question**: "The header and the cards both need to update. Do I call `createRoot` for each?"
- **Reader Expects**: each part of the page that changes needs its own root
- **React Does**: one root owns the `<div>` and everything React draws inside it; new parts of the page are components nested inside `App`; a second `createRoot` on the same `<div>` is an error; in an app built fully with React, components change the page with state, not with new roots or new `root.render` calls
- **Placement**: one `createRoot` call in `main.jsx`; a page built only partly with React, such as an old site with one React widget, creates one root per React part, each on its own element
- **Real Mistake**: a second `createRoot(document.getElementById('root'))` to show a new edition; the console shows "You are calling ReactDOMClient.createRoot() on a container that has already been passed to createRoot() before..."; verified in React 19.3.0 with Vite 8.3.4
- **Importance**: reviewers flag a second root inside a React page; Q14 and Q15 build on the single root
- **Review Point**: Condition
- **Required Lesson Proof**: `createRoot` called twice on `#root`: the console error; the header moved into `App` as a component: one root draws both; `root.render` called twice on one root: the same `<h1>` changes from "Monday" to "Tuesday".

## Senior Answer
The browser loads `index.html`, which holds an empty `<div id="root">` and a module script for `main.jsx`. In `main.jsx`, I find the `<div>` and pass it to `createRoot` from `react-dom/client`. Then I call `root.render(<App />)`. React calls `App` and replaces what the `<div>` held with its output. If the id is wrong, `createRoot` gets `null` and throws. I pass an element, `<App />`, not the function `App`. React 19 removed `ReactDOM.render`, so old tutorials fail. The browser cannot run JSX or find a package by name. So Vite turns each file into plain JavaScript as the browser asks for it. For production, `vite build` writes finished files into `dist`. Opening `index.html` from disk does not work. An app has one root. Everything else nests inside `App` and updates with state.
