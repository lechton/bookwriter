## Authorized Scope
Lesson 02 teaches what a component is and how to write one. It works on `ArticleCard`, which returns an `<article>` with a headline and a short text. `App` uses it. A component is a plain JavaScript function that returns JSX. Our code never calls it. We write `<ArticleCard />` in another component's markup, and React calls the function while it renders. Its name must start with a capital letter. A lowercase tag is read as an HTML tag, so the function never runs. Long markup after `return` goes inside parentheses that open on the same line. Each component is defined at the top level of the file, never inside another component. The lesson builds on Q01: a component describes the page, and React builds the DOM from it.

## Principles

### Principle 1: React calls the component when another component's markup names it
- **Handle**: `react-calls-it`
- **Kind**: Model
- **Reader Question**: "I wrote `function ArticleCard()`. Who calls it, and when?"
- **Reader Expects**: we call it ourselves, as with any JavaScript function, `ArticleCard()`; a habit from plain JavaScript
- **React Does**: `App` returns markup that contains `<ArticleCard />`; the tag hands React the function itself, not its result; while React renders `App`'s output, it calls `ArticleCard`; the `<article>` it returns goes into the DOM; the DOM shows `<article>`, never `<ArticleCard>`
- **Placement**: the function defined once; `<ArticleCard />` written in another component's markup wherever a card should appear
- **Real Mistake**: none; a reader who calls `ArticleCard()` by hand gets the same markup in this lesson, and the cost comes with Hooks in Q37
- **Importance**: interviewers ask who calls a component; Q14 and Q15 explain state and rendering on top of it
- **Prediction**: with `console.log('ArticleCard runs')` in its body, `ArticleCard` logs nothing while no markup uses it, and logs twice when `App` writes `<ArticleCard />` twice; the DOM then holds two `<article>` elements and no `<ArticleCard>` tag.
- **Required Lesson Proof**: `ArticleCard` with a body log; `App` without the tag: the console is silent; `App` with `<ArticleCard />` twice: two logs, two articles, and DevTools shows only `<main>` and `<article>` tags.

### Principle 2: Start a component's name with a capital letter
- **Handle**: `capital-name`
- **Kind**: Decision
- **Reader Question**: "Does it matter whether I call it `articleCard` or `ArticleCard`?"
- **Reader Expects**: no; JavaScript accepts any function name, and plain JavaScript names functions in camelCase, `articleCard`
- **React Does**: a tag that starts with a lowercase letter is read as an HTML tag; React passes the text `'articleCard'` to the browser, which makes an empty `<articlecard>` element; the function never runs; React prints two errors in the development console and nothing on the page
- **Placement**: `function ArticleCard()` and `<ArticleCard />`, both with a capital first letter; lowercase only for HTML tags such as `<article>`
- **Real Mistake**: `function articleCard()` used as `<articleCard />`; the build passes, the DOM holds `<articlecard></articlecard>`, the headline never appears, and the console shows "<articleCard /> is using incorrect casing. Use PascalCase for React components, or lowercase for HTML elements." and "The tag <articleCard> is unrecognized in this browser. If you meant to render a React component, start its name with an uppercase letter."; verified in React 19.3.0
- **Importance**: the card's Friction; reviewers flag it on sight; interviewers ask why the capital letter matters
- **Review Point**: Do not
- **Required Lesson Proof**: `App` renders `<articleCard />`: DevTools shows the empty `<articlecard>`, the console shows both errors, and the body log of `articleCard` never prints; renamed `ArticleCard` in both places, the article appears.

### Principle 3: Open the parentheses on the same line as `return`
- **Handle**: `return-parentheses`
- **Kind**: Decision
- **Reader Question**: "My markup is long. Can I start it on the line after `return`?"
- **Reader Expects**: yes; line breaks do not matter in HTML, and JavaScript usually ignores them
- **React Does**: JavaScript ends a `return` that stands alone on its line, as if a semicolon followed it; the function returns `undefined`; React shows nothing for `ArticleCard` and reports no error on the page; esbuild prints a warning in the build output
- **Placement**: `return (` on one line, the markup inside, `);` after it; or the whole markup on the `return` line
- **Real Mistake**: `return` alone on a line with `<article>` on the next; the card is blank, the page and the console show no error, and esbuild warns "The following expression is not returned because of an automatically-inserted semicolon"; verified in React 19.3.0 and esbuild 0.28.2
- **Importance**: an official Pitfall and Challenge; a blank card with no error is hard to trace
- **Review Point**: Do
- **Required Lesson Proof**: `ArticleCard` with `return` alone on its line: `App` shows an empty `<main>`; with `return (` on the same line: the article appears.

### Principle 4: Define every component at the top level of the file
- **Handle**: `top-level-components`
- **Kind**: Decision
- **Reader Question**: "`ArticleCard` is only used inside `App`. Can I define it inside `App`?"
- **Reader Expects**: yes; plain JavaScript often keeps a helper function inside the only function that uses it
- **React Does**: each time `App` runs, it makes a new `ArticleCard` function; React sees a different component in the same place, throws away the old DOM, and builds new elements; on the first render the page looks the same; on the next render of `App`, anything typed inside the card is gone
- **Placement**: `function ArticleCard()` beside `function App()`, at the top level of the file; never inside another component's body
- **Real Mistake**: `function ArticleCard()` written inside `App`; the first render looks right; after `App` renders again, an `<input>` inside the card is a new element and its typed text is empty; verified in React 19.3.0 with a second `root.render`
- **Importance**: an official Pitfall ("very slow and causes bugs"); reviewers flag it in every code review
- **Review Point**: Do
- **Required Lesson Proof**: `App` and `ArticleCard` side by side at the top level of `App.jsx`. The failure needs a second render, which needs state (Q14), so the lesson shows the right placement, states the recorded result, and Q24 shows it.

## Senior Answer
A React component is a JavaScript function that returns JSX. It describes one piece of the page, such as an article card. I never call it myself. I write it as a tag, like `<ArticleCard />`, in another component's markup. React then calls the function while it renders, and puts what it returns on the page. A few rules follow. The name must start with a capital letter. A lowercase tag is read as an HTML tag, so the function never runs. If the markup starts on the line after `return`, JavaScript returns nothing. So I open the parentheses on the `return` line. And I define every component at the top level of the file, never inside another component. A nested one is a new component on every render, so React rebuilds its DOM each time.
