## Authorized Scope
Lesson 10 works on `ArticleHeader`, the top of a news story. It shows a "BREAKING" badge only for urgent stories and a "LIVE" badge or a date. It shows a comment count only when there are comments. React has no special syntax for this. The component is a function, so it branches with plain JavaScript. An `if` can return different JSX, or `null` for nothing. Inside JSX, a ternary, `cond ? <A /> : <B />`, picks one of two. The `&&` operator, `cond && <A />`, shows something or nothing. `false`, `null`, and `undefined` print nothing. But a number on the left of `&&` prints itself, so `0` lands on the page. React leaves out what the JSX leaves out; nothing is hidden with the DOM. The lesson builds on Q04, where braces held expressions and `null` printed nothing. It also builds on Q06, where props reached the component.

## Principles

### Principle 1: Return the JSX for the case, and let React add or remove the DOM
- **Handle**: `branch-in-jsx`
- **Kind**: Model
- **Reader Question**: "How do I hide the comments when they are turned off? Do I find the element and hide it?"
- **Reader Expects**: find the element with `document.getElementById` and add a `hidden` class or `display: none`, as in a plain JavaScript page
- **React Does**: the component is a function of its props; for each render it returns the JSX for this case, built with plain JavaScript; React makes the DOM match: a part the JSX leaves out has no DOM node at all; while the component runs, its own elements are not in the page yet, so a DOM lookup finds nothing
- **Placement**: the condition goes in the component, as JavaScript around the JSX: `{commentsEnabled && <CommentList />}`, or an `if` that returns other JSX; no `document` calls in the component
- **Real Mistake**: `document.getElementById('comments').classList.add('hidden')` inside `ArticleHeader`; the render throws "Cannot read properties of null (reading 'classList')", and the page goes blank; verified in React 19.3.0
- **Fix In**: this principle
- **Importance**: the card's Core Truth and Naive code; interviewers ask how React shows and hides markup
- **Prediction**: with `style={{ display: 'none' }}`, the "BREAKING" `<span>` is still in the Elements panel, hidden; with `{isBreaking && <span />}` and `isBreaking={false}`, there is no `<span>` at all.
- **Required Lesson Proof**: the `classList` line: the `TypeError` and the blank page; the `&&` version: the comments present for one story and absent for another; the two hidden badges side by side in the Elements panel.

### Principle 2: Guard missing data with an early return
- **Handle**: `return-early`
- **Kind**: Decision
- **Reader Question**: "The article has not arrived yet. Why is the whole page blank?"
- **Reader Expects**: a missing value prints nothing, as `{undefined}` printed nothing in Q04
- **React Does**: `{undefined}` prints nothing, but `article.title` with no `article` reads a property of `undefined` and throws; the throw stops the render, and React removes the whole app from the page; `if (!article) return null;` returns before any read, and that card renders nothing
- **Placement**: the guard is the first statement of the component, before the first read of the data: `if (!article) return null;`, or a placeholder such as `return <p>Loading story</p>;`; when the parent knows the data is missing, it can leave the component out instead
- **Real Mistake**: `ArticleHeader({ article })` reading `article.title` for a story whose data is missing; the console shows "Cannot read properties of undefined (reading 'title')", and every story on the page disappears; verified in React 19.3.0
- **Importance**: the card's first Mechanism; a blank page in production from one missing record
- **Review Point**: Do
- **Required Lesson Proof**: a list of three headers, one without data: the blank page and the error; with the guard: two headers and nothing for the third; with the placeholder: "Loading story" in its place.

### Principle 3: A ternary picks one of two, and `&&` shows one or nothing
- **Handle**: `ternary-or-and`
- **Kind**: Decision
- **Reader Question**: "Do I use a ternary or `&&`?"
- **Reader Expects**: they are the same, or only `if` works
- **React Does**: `cond ? <A /> : <B />` evaluates to one of the two elements, so exactly one shows; `cond && <A />` evaluates to `<A />` when `cond` is true, and to `false` otherwise, which prints nothing
- **Placement**: two outcomes, `{isLive ? <LiveBadge /> : <StaticDate />}`; one outcome or nothing, `{isBreaking && <span className="alert">BREAKING</span>}`; when both branches share most of the markup, branch only the part that differs, as in `className={'card ' + (isBreaking ? 'breaking' : '')}`
- **Real Mistake**: none
- **Importance**: the card's Mechanism; interviewers ask for both forms and when each fits
- **Review Point**: Condition
- **Required Lesson Proof**: two headers, live and not live: `LIVE` in one, the date in the other; two stories, breaking and not: the badge in one, nothing in the other; the class built with a ternary: `class="card breaking"` and `class="card "`.

### Principle 4: Put a boolean on the left of `&&`, never a number
- **Handle**: `boolean-left-of-and`
- **Kind**: Decision
- **Reader Question**: "Why is there a `0` on the card?"
- **Reader Expects**: `0` counts as false, so `&&` shows nothing, as in an `if`
- **React Does**: `&&` returns its left side when that side is falsy; `0` is falsy, so `commentCount && <CommentBadge />` is `0`, and React prints numbers; `NaN` prints too, with a warning; a non-empty string such as `"false"` and an empty array are truthy, so the right side shows
- **Placement**: compare first, `{commentCount > 0 && <CommentBadge />}`; pass booleans in braces, `isBreaking={false}`; test an array by its length, `tags.length > 0`
- **Real Mistake**: `{commentCount && <CommentBadge count={commentCount} />}` in `ArticleHeader`; a story with no comments shows a bare `0` under its title; verified in React 19.3.0
- **Importance**: react.dev's `<Pitfall>` and the card's Under the Hood; interviewers ask for this trap by name
- **Review Point**: Do not
- **Required Lesson Proof**: two stories with `0` and `12` comments: the stray `0`, then nothing after `> 0`; `isBreaking="false"`: the badge shows; `isBreaking={false}`: it does not.

### Principle 5: Move complex branching above the `return`
- **Handle**: `branch-before-return`
- **Kind**: Decision
- **Reader Question**: "The header has five cases. Do I nest ternaries?"
- **Reader Expects**: everything belongs inside the JSX, so nest a ternary in each branch
- **React Does**: braces in JSX hold one expression, so several cases become nested ternaries; above the `return`, the component can use `if` statements and a variable that holds JSX, and the JSX places that variable once
- **Placement**: `let badge = null;`, then `if (isBreaking) badge = <span className="alert">BREAKING</span>; else if (isLive) badge = <LiveBadge />;`, then `<header>{badge}<h2>{title}</h2></header>`; a short ternary or `&&` stays inline
- **Real Mistake**: none
- **Importance**: react.dev's Recap bullets 3 and 6 and Challenge 3; reviewers flag nested ternaries in JSX
- **Review Point**: Prefer
- **Required Lesson Proof**: the header with a breaking, a live, and a plain story, written first with nested ternaries and then with `let badge` and `if`: the same three outputs in the DOM.

## Senior Answer
A component is a function, so I branch with plain JavaScript and return the JSX for each case. React adds or removes the DOM nodes to match. I never hide parts with DOM calls in the component. When data may be missing, I return early, with `null` or a placeholder, before I read any field. Otherwise one missing record throws and blanks the page. Inside JSX, a ternary picks one of two outputs. The `&&` operator shows something or nothing, because `false`, `null`, and `undefined` print nothing. But `&&` returns its left side, and React prints numbers. So `count && <Badge />` shows `0`. I always put a boolean on the left, such as `count > 0`. When there are many cases, I move the branching above the `return` into `if` statements and a variable.
