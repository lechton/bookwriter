## Authorized Scope
Lesson 06 teaches props. It works on `ArticleCard`, rendered three times by `EditorialFeed`. Each card needs its own `title` and `readTime`. The parent writes them as attributes on the tag. React collects the attributes of one tag into one object, the props. It calls `ArticleCard` with that object as its only argument. The component unpacks it in its parameter list, `function ArticleCard({ title, readTime })`. A number goes in curly braces, or it arrives as a string. A default after `=` fills a prop that is missing. A component never changes its props. The values belong to the parent. When the card needs another form of a value, it makes a new variable during render. The lesson builds on Q05, where `App` wrote `readerName` on a child's tag and the child read `props.readerName`. It also builds on Q04, where quotes pass a string and braces pass a value.

## Principles

### Principle 1: The attributes on a tag become the component's one argument, the props
- **Handle**: `props-are-arguments`
- **Kind**: Model
- **Reader Question**: "I render three `ArticleCard`s and they all show the same headline. How does each get its own?"
- **Reader Expects**: write `title="Rail Strike Ends"` on each tag, as with an HTML attribute, and the card shows it; or copy the component three times
- **React Does**: the build collects the attributes of one tag into one object, `{ title: "Rail Strike Ends", readTime: 3 }`; React calls `ArticleCard` with that object as its only argument; each tag gets its own object; nothing appears until the component reads a value from it; the attribute never reaches the DOM by itself
- **Placement**: the values on the parent's tags, `<ArticleCard title="Rail Strike Ends" readTime={3} />`; the headline in the card read from the props, as Q05 read `props.readerName`
- **Real Mistake**: `title` added on three tags while `ArticleCard` still returns `<h2>Night Trains Return to Europe</h2>`; every card shows the same headline, and the console stays silent; verified in React 19.3.0
- **Fix In**: `destructure-in-parameters`
- **Importance**: the card's Friction and the first half of the interview question; every later lesson that passes data builds on it
- **Prediction**: `console.log(props)` in `ArticleCard` prints one object per tag, `{"title":"Night Trains Return to Europe","readTime":5}` and `{"title":"Rail Strike Ends","readTime":3}`, in the order of the tags.
- **Required Lesson Proof**: `EditorialFeed` renders three `ArticleCard` tags with different `title` and `readTime`; with the fixed `<h2>`, three equal headlines; the logged props show three different objects; then the card reads its props and the three headlines differ.

### Principle 2: Unpack the props in the parameter list, inside braces
- **Handle**: `destructure-in-parameters`
- **Kind**: Decision
- **Reader Question**: "How do I get `title` and `readTime` out of the props?"
- **Reader Expects**: list them as parameters, `function ArticleCard(title, readTime)`, as with any JavaScript function
- **React Does**: React passes one argument, the props object; a plain parameter receives the whole object; braces in the parameter list, `({ title, readTime })`, unpack the keys into variables of the same names; `function ArticleCard(props)` with `props.title` reads the same values
- **Placement**: `function ArticleCard({ title, readTime })`; the names in the braces equal the attribute names on the tag
- **Real Mistake**: `function ArticleCard(title, readTime)`; `title` holds the whole object, `readTime` is `undefined`, and `{title}` stops the render with "Objects are not valid as a React child (found: object with keys {title, readTime})"; a name that differs from the attribute, `{ headline }` for `title=`, leaves an empty heading with no error; verified in React 19.3.0
- **Importance**: an official react.dev Pitfall; the missing braces take down the render
- **Review Point**: Do
- **Required Lesson Proof**: `ArticleCard(title, readTime)`: the error in the console and a blank page; `ArticleCard({ title, readTime })`: three cards with their own headline and read time; `{ headline }`: an empty `<h2>` and a silent console.

### Principle 3: Pass numbers in curly braces, or they arrive as strings
- **Handle**: `number-props-in-braces`
- **Kind**: Decision
- **Reader Question**: "I wrote `readTime="5"`. Why does the card say `51 min`?"
- **Reader Expects**: `5` is `5`, quoted or not, as in an HTML attribute
- **React Does**: a quoted attribute is always a string, so the prop is `"5"`; `"5" + 1` joins two strings into `"51"`; `"5" * 60` turns the string into a number and gives `300`, so some lines look right; `readTime={5}` passes the number
- **Placement**: `readTime={5}`; quotes only for text, `title="Rail Strike Ends"`
- **Real Mistake**: `<ArticleCard readTime="5" />` and `{readTime + 1} min with the summary`; the card shows `51 min with the summary`, while `{readTime * 60} seconds` shows `300 seconds`; verified in React 19.3.0
- **Importance**: a shipped bug that one test can miss; reviewers flag a quoted number on sight
- **Review Point**: Do
- **Required Lesson Proof**: two cards, `readTime="5"` and `readTime={5}`, each with `{readTime + 1} min with the summary` and `{readTime * 60} seconds`: `51` against `6`, and `300` on both.

### Principle 4: A default fills a missing prop, and only a missing one
- **Handle**: `default-for-missing`
- **Kind**: Decision
- **Reader Question**: "What if a parent leaves out `readTime`?"
- **Reader Expects**: the card breaks, or React fills in something; or `readTime || 5`, the older JavaScript habit
- **React Does**: a missing prop is `undefined`, and `{readTime} min read` shows ` min read`; `readTime = 5` in the braces fills it when the prop is missing or `undefined`; `null` and `0` pass through unchanged; `readTime || 5` also replaces a real `0`; React 19 checks no `propTypes` on function components, so a missing required prop gives no warning
- **Placement**: `function ArticleCard({ title, readTime = 5 })` for an optional prop; no default for a required prop such as `title`; `readTime ?? 5` when the data can hold `null`
- **Real Mistake**: article data with `readTime: null` reaches a card with `readTime = 5`; the card shows ` min read`; verified in React 19.3.0
- **Importance**: the card's Code Experiment; reviewers flag `||` used for defaults; a default that looks right and misses `null` ships an empty line
- **Review Point**: Condition
- **Required Lesson Proof**: four cards against `readTime = 5`: no `readTime`, `readTime={undefined}`, `readTime={null}`, and `readTime={0}`, showing `5`, `5`, nothing, and `0`; then `readTime ?? 5` with `null` shows `5`, and `readTime || 5` with `0` shows `5`.

### Principle 5: Props are read-only, so make a new variable instead
- **Handle**: `props-read-only`
- **Kind**: Decision
- **Reader Question**: "The headline should be in capitals. Can I just write `props.title = props.title.toUpperCase()`?"
- **Reader Expects**: yes; props is an object, and JavaScript lets you change a property of any object
- **React Does**: the props belong to the parent, which built the object; in development React freezes it; a Vite file is an ES module, which runs in strict mode, so the assignment throws and the page goes blank; the production build does not freeze it, so the same line works there and ships; the freeze covers only the top level, so changing `article.title` inside an object prop works in every build and changes the object the parent and its siblings show
- **Placement**: a new variable during render, `const headline = title.toUpperCase()`, and `{headline}` in the JSX; the parent's values stay as they came
- **Real Mistake**: `props.title = props.title.toUpperCase()` in `ArticleCard`; the console shows "Cannot assign to read only property 'title' of object '#<Object>'" in development, while the production build shows the capitals with no error; with an `article` object prop, `article.title = article.title.toUpperCase()` also turns the sidebar's "Most read" line into capitals; verified in React 19.3.0, development and production
- **Importance**: the second half of the interview question; reviewers reject it on sight; the nested version corrupts data no error reports
- **Review Point**: Do not
- **Required Lesson Proof**: `ArticleCard` with `props.title = ...`: the error and a blank page; the same card with `article` as an object prop, also shown by a `MostRead` sidebar: both turn to capitals; then `const headline = title.toUpperCase()`: the card in capitals, the sidebar unchanged.

## Senior Answer
I pass data to a component by writing attributes on its tag, as in `<ArticleCard title="Rail Strike Ends" readTime={3} />`. React collects them into one object, the props, and calls the component with it. The component unpacks what it needs in its parameter list, with braces: `function ArticleCard({ title, readTime })`. Without the braces, the first parameter gets the whole object. Numbers go in curly braces, because a quoted value is always a string. A default after `=`, such as `readTime = 5`, covers a prop that is missing or `undefined`. It does not cover `null` or `0`. A component never changes its own props, because they belong to the parent. In development React freezes the object, so an assignment throws. In production it does not, and the freeze never covered nested objects. So changing a prop corrupts the parent's data, and every component that shows it. Instead I make a new variable during render, like `const headline = title.toUpperCase()`. And when a value must change over time, it becomes state.
