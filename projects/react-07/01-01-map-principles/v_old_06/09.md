# Q09: Mounting the Root Component with createRoot and Vite Tooling — Operational Principle Map
- **Source Map**: `01-01-map/09.md`
- **Topic Tag**: `#create_root` | `❱ CORE`
- **Interview Question**: *How does your root component attach to the browser DOM with createRoot, and how do build tools assemble it?*

## Authorized Scope
Q09 teaches the client-side mounting bridge in a Vite project: `index.html` holds an empty (or placeholder) `<div id="root">` and loads `/src/main.jsx` as a module, `main.jsx` imports `createRoot` from `react-dom/client`, creates one root for that container, and calls `root.render(<App />)`, React then owns only that container's contents, and Vite's development server transforms `.jsx` files on request while `vite build` bundles them into `dist/` for an HTTP server; it builds on Q01 (roots adopted one at a time, React's DOM left to React), Q02 declarative invocation, Q03 the JSX compiler transform, and Q08 ES modules, and it excludes state updates (Q14), the render and commit phases (Q15), StrictMode (Q46), error boundaries and root error options (Q72), portals (Q51), server rendering and hydration (Q102, Q104), code splitting (Q70), and routing.

## Principles

### Principle 1: Hand React one container and expect it to replace that container's contents
- **Kind**: Model
- **Rule**: `createRoot(container)` gives React ownership of the DOM inside that one element, so the first `root.render` replaces whatever HTML the container held, while every node outside it, such as a static masthead in `index.html`, stays exactly as the browser parsed it.
- **Importance**: A developer without this model is surprised that server-side or hand-written content inside `#root` vanishes, and misses the easy win of a loading placeholder that React removes on the first render.
- **Prediction**: With `<p id="static">Static masthead</p>` before `<div id="root"><p>Loading the National Times…</p></div>`, the placeholder is visible while JavaScript loads and is replaced by the rendered `App`, while the masthead survives unchanged in the Elements panel.
- **Required Lesson Proof**: Add the masthead and the placeholder to `index.html`, throttle the network in DevTools to see the placeholder, then show the Elements panel after the first render.
- **Sources**: Mechanism of `01-01-map/09.md`; createRoot Intro and `root.render` clearing Caveat; the merged masthead and placeholder candidates, verified in React 19.3.

### Principle 2: Give `createRoot` an element that exists
- **Kind**: Decision
- **Rule**: Pass `createRoot` the DOM node returned by `document.getElementById('root')`, with an `id` that matches `index.html` exactly, and never a JSX element, because `createRoot` needs a real container before anything can render.
- **Importance**: A mistyped `id` or `createRoot(<App />)` throws "Target container is not a DOM element." and leaves a blank page; in a Vite project the module script is deferred, so script position is not the cause and the `id` is the first thing to check.
- **Review Point — Do**: Check that the `id` in `getElementById` matches the container in `index.html` and that the argument is that DOM node.
- **Required Lesson Proof**: Change the `id` to `'app'` and show the error, log the `null` returned by `getElementById`, show the same error for `createRoot(<App />)`, then move the module script into `<head>` and show that the app still mounts.
- **Sources**: createRoot Troubleshooting "Target container is not a DOM element"; the merged `null`-container, JSX-argument, and deferred-module candidates, verified in React 19.3 and Chrome.

### Principle 3: Render an element with a single argument
- **Kind**: Decision
- **Rule**: After creating the root, call `root.render(<App />)` with one React element, not the function `App`, and put root options in `createRoot(container, options)`, because a root that is created but never rendered, or rendered with a function, shows nothing.
- **Importance**: `root.render(App)` logs "Functions are not valid as a React child" and `root.render(<App />, options)` logs "You passed a second argument to root.render(...) but it only accepts one argument.", and a forgotten `root.render` shows a blank page with no message at all.
- **Review Point — Do not**: Do not pass a component function or a second argument to `root.render`; pass `<App />` and move options to `createRoot`.
- **Required Lesson Proof**: Remove the `root.render` call and show the silent blank page, then show both console errors for `root.render(App)` and for a second argument, and fix each.
- **Sources**: createRoot Troubleshooting entries "nothing is displayed", "Functions are not valid as a React child", and "You passed a second argument to root.render", merged and verified in React 19.3; the Prerequisite row for declarative invocation (Q02).

### Principle 4: Create the root once and grow the app inside `App`
- **Kind**: Decision
- **Rule**: Call `createRoot` once at startup in `main.jsx` for the app's single container and add every new screen or widget as a component nested inside `App`, because one root means one owner for that part of the DOM.
- **Importance**: A second `createRoot` on the same container logs "You are calling ReactDOMClient.createRoot() on a container that has already been passed to createRoot() before. Instead, call root.render() on the existing root instead if you want to update it.", and apps that create roots for new widgets lose shared tree structure.
- **Review Point — Do**: Check that `main.jsx` creates one root and that new UI is added inside `App`, keeping extra roots for pages only partly built with React (Q01) and repeated `root.render` calls for rare cases, since components update through state (Q14).
- **Required Lesson Proof**: Call `createRoot` twice on `#root` and show the warning, then remove the second call and render the new widget inside `App`.
- **Sources**: createRoot Caveats and Usage "Rendering an app fully built with React" and "Updating a root component", merged; the second-root warning, verified in React 19.3; the Prerequisite row for multiple roots (Q01).

### Principle 5: Serve the app over HTTP through Vite
- **Kind**: Decision
- **Rule**: Run the Vite development server (`npm run dev`) while developing and serve the built `dist/` folder from an HTTP server (`vite preview` locally), because browsers run neither JSX nor module scripts loaded from `file://`, and the built page requests `/assets/index-[hash].js` from the server root.
- **Importance**: Double-clicking `index.html` blocks the module with "Access to script at 'file:///…/src/main.jsx' from origin 'null' has been blocked by CORS policy", a classic `<script src="App.jsx">` fails with "Uncaught SyntaxError: Unexpected token 'export'", and `dist/index.html` from disk fails the same way, so the page stays blank each time.
- **Review Point — Do not**: Do not open `index.html` or `dist/index.html` from disk or link `.jsx` files with classic script tags; start `npm run dev`, or build and serve `dist/` over HTTP.
- **Required Lesson Proof**: Open `index.html` via `file://` and show the CORS error, show the classic-script `SyntaxError`, then run `npm run dev` and show the page, and finally run `vite build`, show the hashed file in `dist/assets/`, and serve it with `vite preview`.
- **Sources**: Friction and Code Experiment of `01-01-map/09.md`; build-a-react-app-from-scratch Step 1; add-react-to-an-existing-project Step 1; the merged `file://`, classic-script, `dist/`, and transform-versus-bundle candidates, verified with Vite 8.3.1 in Chrome.

### Principle 6: Keep JSX in `.jsx` files
- **Kind**: Decision
- **Rule**: Name every file that contains JSX with the `.jsx` extension (`App.jsx`, `main.jsx`), because Vite's React setup transforms JSX only in `.jsx` and `.tsx` files and parses `.js` files as plain JavaScript.
- **Importance**: A component left in `App.js`, a habit from Create React App, fails the build with `[builtin:vite-transform] Unexpected JSX expression`, which does not mention the file extension as the cause.
- **Review Point — Do**: Check that every file containing JSX ends in `.jsx` and that imports use the new extension.
- **Required Lesson Proof**: Rename `App.jsx` to `App.js`, run `vite build` and show the error, then rename it back and show a clean build.
- **Sources**: general engineering knowledge; verified with Vite 8.3.1; the Supporting row on Create React App's deprecation.

### Principle 7: Mount with `createRoot` from `react-dom/client`
- **Kind**: Decision
- **Rule**: Import `createRoot` from `react-dom/client`, because React splits the component model (`react`) from the browser renderer (`react-dom/client`), and React 19 removed the legacy `ReactDOM.render`, `ReactDOM.hydrate`, and `unmountComponentAtNode`.
- **Importance**: A developer who learned React years ago writes `import { render } from 'react-dom'`, gets `undefined`, and the page fails with "render is not a function".
- **Review Point — Do not**: Do not import `render` from `react-dom`; import `createRoot` from `react-dom/client` in `main.jsx`, and keep component files free of renderer imports.
- **Required Lesson Proof**: Show the legacy call failing with "render is not a function" in the console, then show the `createRoot` version mounting, and point out that only `main.jsx` imports from `react-dom/client`.
- **Sources**: Under the Hood and Code Experiment Naive of `01-01-map/09.md`; React 19 upgrade guide removals, merged; the failure verified in React 19.3 with Vite 8.3.1.

### Principle 8: Expect `root.render` to update the DOM after your code continues
- **Kind**: Model
- **Rule**: `root.render` schedules the render instead of finishing it inside the call, so the lines after it still run against the container's old contents and the DOM appears only after the current code yields.
- **Importance**: The imperative habit of querying the page right after rendering (`document.querySelector('h1')` straight after `root.render`) returns stale content or `null`, a confusing bug for developers coming from DOM scripting.
- **Prediction**: Logging `document.getElementById('root').innerHTML` on the line after `root.render(<h1>The National Times</h1>)` prints the old placeholder, while the Elements panel shows the heading once the page has loaded.
- **Required Lesson Proof**: Add the log after `root.render`, show the placeholder in the console, and show the rendered heading in the Elements panel.
- **Sources**: createRoot `root.render` Caveat and its `🚩` example; the merged `innerHTML` candidate, verified in React 19.3; the Preview row for the render pipeline (Q15).

## Senior Answer
The page's `index.html` contains a container, usually `<div id="root">`, and loads `/src/main.jsx` as a module; `main.jsx` imports `createRoot` from `react-dom/client`, the browser renderer that React keeps separate from the component model in `react`, creates one root for that container with `createRoot(document.getElementById('root'))`, and calls `root.render(<App />)` with a single element. From then on React owns only that container: the first render replaces anything inside it, which makes a loading placeholder useful, and everything outside stays untouched; the render is scheduled, so code on the next line still sees the old contents. I create the root once and grow the app inside `App`, and I use `createRoot` because React 19 removed `ReactDOM.render`. Vite assembles it: its development server transforms `.jsx` files on request and serves native ES modules over HTTP, so opening `index.html` from disk fails, JSX must live in `.jsx` files, and `vite build` bundles everything into hashed files in `dist/` that I serve from an HTTP server.
