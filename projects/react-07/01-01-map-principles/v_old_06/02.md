## Authorized Scope
Q02 teaches the anatomy, naming, definition, and invocation of a single React component function: a component is a regular JavaScript function that returns JSX markup; PascalCase capitalization distinguishes custom component functions from native HTML tags in the JSX compiler; components must be declared at the module's top level and never nested inside another component function; and components must be invoked declaratively in JSX (`<Card />`) rather than called directly as functions (`Card()`). It builds on Q01's declarative projection model, and leaves JSX grammar and single-root rules to Q03, curly-brace expressions to Q04, component tree hierarchy to Q05, props to Q06, multi-file ES module imports/exports to Q08, root mounting to Q09, pure rendering guarantees and side-effect avoidance to Q12, and state preservation mechanics to Q24.

## Principles

### Principle 1: Capitalize custom component names with PascalCase
- **Kind**: Decision
- **Rule**: Name custom component functions with PascalCase (`ArticleCard`), ensuring the JSX transpiler treats the tag as a variable identifier and emits a direct function reference (`_jsx(ArticleCard)`), whereas lowercase names compile to string literals (`_jsx("articleCard")`) that the browser treats as unknown native HTML elements.
- **Importance**: Senior reviewers flag lowercase component names immediately; interviewers probe why capitalization is mandatory in JSX; prevents the bug where a component builds without errors but produces an empty unknown DOM element on screen, reported only by an incorrect-casing error in the development console.
- **Review Point — Do**: Capitalize all custom component names with PascalCase; never use camelCase or lowercase for component definitions or JSX tags.
- **Required Lesson Proof**: In `App.jsx`, render `<articleCard />` (lowercase) and show in DevTools that the DOM contains an empty `<articlecard></articlecard>` node with no rendered article markup while the development console shows React's incorrect-casing error for `<articleCard />`; inspect the compiled output showing `_jsx("articleCard")`; then rename the function and tag to `ArticleCard`, inspect the compiled output showing `_jsx(ArticleCard)`, and show the rendered article heading and body in the DOM.
- **Sources**: card Core Truth, Mechanism, Under the Hood, Code Experiment; `your-first-component.md` Pitfall, Recap bullet 1; `createElement.md` Caveat; merged AST compiler branch candidate.

### Principle 2: Declare components at the top level of the module and never nest their definitions
- **Kind**: Decision
- **Rule**: Define every component function at the top level of its module file; never declare a component function inside the body of another component, because a nested declaration creates a new function reference on every parent render, forcing React to treat it as a brand-new component type, destroy its subtree DOM, and reset all child state.
- **Importance**: Primary official Pitfall in `your-first-component.md`; senior reviewers flag nested component definitions in pull requests as severe performance and state-loss bugs; interviewers probe component scoping.
- **Review Point — Do not**: Do not define a component function inside another component; declare each component at the top level of the module and pass needed data through props.
- **Required Lesson Proof**: Declare `function EditorialByline() { ... }` inside `ArticleCard`, render `<ArticleCard />`, and show that each call to `ArticleCard` re-evaluates a distinct `EditorialByline` function reference; move `EditorialByline` outside to module scope, showing stable function identity across invocations; preview Q24 in one sentence for the state-reset proof.
- **Sources**: `your-first-component.md` Nesting Pitfall; card Scope Boundary; merged function recreation candidate; Q24 preview.

### Principle 3: Render components declaratively in JSX rather than calling them as functions
- **Kind**: Decision
- **Rule**: Invoke components declaratively using JSX tags (`<ArticleCard />`) and never call component functions directly (`ArticleCard()`), because JSX allows React to orchestrate rendering, associate the component with its position in the fiber tree, enable reconciliation, and manage hook lifecycles.
- **Importance**: Direct rule from `reference/rules/react-calls-components-and-hooks.md`; core interview distinction between React and template functions; calling component functions directly breaks hook call order and strips the component of its tree identity.
- **Review Point — Do not**: Do not call component functions directly like `{ArticleCard()}`; invoke them declaratively as JSX elements `<ArticleCard />`.
- **Required Lesson Proof**: Render `{ArticleCard()}` inside `App.jsx` and inspect React DevTools to show that `ArticleCard` is completely missing from the React component tree (inlined as raw elements under `App`); then switch to `<ArticleCard />` and show `ArticleCard` appear as an explicit component node in the React DevTools tree.
- **Sources**: card Scope Boundary; `reference/rules/react-calls-components-and-hooks.md` ("Never call component functions directly"); merged helper stack execution candidate.

## Senior Answer
A React component is a regular JavaScript function that returns JSX markup describing a piece of the user interface. Two core authoring rules govern how you write and name one. First, its name must always begin with a capital letter using PascalCase, like `ArticleCard`. This is a compiler requirement: lowercase tags compile to string literals like `_jsx('articleCard')`, which the browser treats as unknown HTML tags and renders as empty DOM elements, while capitalized tags compile to function identifiers like `_jsx(ArticleCard)` that React can invoke. Second, every component must be declared at the top level of the module. You must never nest a component definition inside another component function, because each parent render would create a brand-new function reference, causing React to treat it as a different component type, unmount the subtree, and reset its DOM and state. Finally, you use components declaratively in JSX as `<ArticleCard />` and never call them directly as `ArticleCard()`, which allows React to manage tree position, reconciliation, and component lifecycles. If a multi-line JSX expression follows the return keyword, wrap it in parentheses to prevent JavaScript's Automatic Semicolon Insertion from truncating the output, and keep the component pure, leaving multi-file imports to Q08 and pure rendering guarantees to Q12.
