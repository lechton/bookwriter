## Authorized Scope
Lesson 01 teaches the change of habit that React asks for. In plain JavaScript we find each element on the page and change it by hand. In React we write a component, `SiteHeader`, that describes what the header shows for the data it has. React reads that description and builds the page from it. The reader's name lives in one variable, `readerName`, and every place that shows the name reads it. So the places cannot disagree. When the data changes, React compares the new description with the last one. It changes only the text that differs, so a search box keeps what the reader typed. The data stays fixed in this lesson. The lesson builds on nothing earlier; the reader knows HTML, plain JavaScript, and the DOM.

## Principles

### Principle 1: Describe what the page shows for the data, and React builds it
- **Handle**: `describe-from-data`
- **Kind**: Model
- **Reader Question**: "In plain JavaScript I find each element by its id and change its text. What do I write instead in React?"
- **Reader Expects**: some React way to find elements and change them, like `document.getElementById('greeting').textContent = ...`; a habit from plain JavaScript and jQuery
- **React Does**: we write `SiteHeader`, a function that returns the header's markup with `readerName` in it; React calls it and builds the DOM from what it returns; the page shows "Welcome back, Elena" and "Subscriber: Elena"; no line of our code finds or changes an element
- **Placement**: what each element shows goes in the markup `SiteHeader` returns; no `getElementById` and no `textContent` in our code
- **Real Mistake**: the plain JavaScript `updateHeaderUser('Elena Ruiz')` sets the greeting by id and forgets the badge; the page shows "Welcome back, Elena Ruiz" beside "Subscriber: Elena"; verified in jsdom 30.1.2
- **Fix In**: `one-value-every-place`
- **Importance**: it is the interview question; every later lesson assumes the reader describes instead of commands
- **Prediction**: `SiteHeader` with `readerName = 'Elena'` shows the name in the greeting and in the badge, and a search of our code finds no DOM call.
- **Required Lesson Proof**: the card's plain JavaScript page with a greeting and a badge; `updateHeaderUser('Elena Ruiz')` leaves the badge on "Elena"; then `SiteHeader` returns the same header from `readerName`, and the DOM shows the name in both places.

### Principle 2: Keep each value in one variable, and let every place read it
- **Handle**: `one-value-every-place`
- **Kind**: Decision
- **Reader Question**: "The reader's name shows in the greeting and in the badge. Do I write it in both places?"
- **Reader Expects**: yes, copy "Elena" into each spot, as in a static HTML page
- **React Does**: `const readerName = 'Elena'` holds the name once; the greeting and the badge both read `readerName`; change the variable to `'Elena Ruiz'` and both places show the new name, because both are built from it
- **Placement**: one `readerName` variable; every place that shows the name reads it with `{readerName}`; no copy of the name typed into the markup
- **Real Mistake**: markup pasted from the old HTML keeps `Subscriber: Elena` as fixed text in the badge; after `readerName` becomes `'Elena Ruiz'`, the greeting shows "Elena Ruiz" and the badge still "Elena"; verified in React 19.3.0
- **Importance**: state drift is the card's Friction; "single source of truth" is the phrase interviewers wait for; reviewers flag a value typed twice
- **Review Point**: Do
- **Required Lesson Proof**: `SiteHeader` first with the badge text typed in by hand: change `readerName` and the badge keeps "Elena"; then with `{readerName}` in both places: both show "Elena Ruiz".

### Principle 3: When the data changes, React changes only the text that differs
- **Handle**: `smallest-change`
- **Kind**: Model
- **Reader Question**: "If React builds the header from my description, does it rebuild the whole header when the name changes, and wipe what the reader typed in the search box?"
- **Reader Expects**: yes, the whole header is thrown away and made again, as with `header.innerHTML = ...`; a habit from template strings and server pages that reload
- **React Does**: React calls `SiteHeader` again and gets a new description; it compares it with the last one; it changes the two text pieces that hold the name; the `<input>` stays the same element, so the typed text and the focus stay
- **Placement**: describe the whole header from the data and let React change the page; never rebuild part of the page with `innerHTML`
- **Real Mistake**: the plain JavaScript habit of rebuilding the header with a template string, `header.innerHTML = '<p>Welcome back, ' + name + '</p><input>...'`; the new `<input>` is empty, "elections" typed into the old one is gone, and focus falls back to the page body; verified in jsdom 30.1.2
- **Fix In**: this principle
- **Importance**: interviewers ask how React updates the page and what the virtual DOM is; the card's Under the Hood
- **Prediction**: with "elections" typed in the search box, a change of name to "Elena Ruiz" changes two text pieces on the page; the search box keeps "elections" and the focus.
- **Required Lesson Proof**: the plain JavaScript header with "elections" typed in the search box; `innerHTML` with the new name empties the box and moves focus to the body. The React half needs a second render, which needs `root.render` (Q09) or state (Q14), so the lesson states it with the recorded result and Q15 `commit-only-differences` shows it.

## Senior Answer
React is a JavaScript library for building user interfaces out of components. In plain JavaScript, I find each element and change it by hand. That is imperative code: I give every step. If I miss one element, the page shows old data. In React, I write declarative code instead. A component describes what the page should show for the current data. React builds the DOM from that description. I keep each value in one place, and every part of the page reads it. So the parts cannot disagree. When the data changes, React compares the new description with the old one. It changes only what differs. So an input keeps its text and its focus. People call this the virtual DOM. React's own docs just say it applies the minimal changes needed.
