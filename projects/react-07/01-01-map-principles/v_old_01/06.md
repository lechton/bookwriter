## Operational Principles

### Principle 1: Parameterize Instances Along the Parent-to-Child Path
- **Operational Rule**: Keep reusable markup in one child component and let the parent provide each varying value at that child's JSX call site. The resulting props object makes the owner-to-consumer path visible while preventing hardcoded duplicates and hidden DOM or global lookups.
- **Review Point — Do**: Identify values that vary per instance and pass each one from the owning parent instead of copying markup or bypassing the component path.
- **Required Lesson Proof**: Render several instances from one component, trace one value from parent memory through the child element's props object, and contrast the result with hardcoded duplicate cards.

### Principle 2: Destructure the Inputs the Component Consumes
- **Operational Rule**: Name the props a component reads at its function boundary so the input contract is immediately visible and later code can use focused local bindings. Destructuring is an access decision, not permission to modify the received values.
- **Review Point — Prefer**: Prefer parameter destructuring when it makes the component's consumed inputs clearer; retain a named props object when the whole object has a deliberate use.
- **Required Lesson Proof**: Compare `props.title` access with `function ArticleCard({ title, readTime })` and identify exactly which inputs each form exposes to review.

### Principle 3: Apply Defaults Only to Genuinely Optional Props
- **Operational Rule**: Assign a destructuring default when missing or `undefined` input has a legitimate fallback. The default does not replace an explicit `null`, so the fallback policy must match the component's data contract.
- **Review Point — Condition**: Use a parameter default for a genuinely optional prop; require the prop when absence would make the component invalid or misleading.
- **Required Lesson Proof**: Compare a supplied value, an omitted value using the default, an explicit `undefined`, and an explicit `null` that does not trigger the default.

### Principle 4: Keep Props Read-Only and Derive New Values Locally
- **Operational Rule**: Never assign back to received props when display output needs formatting or transformation. Calculate a fresh local value instead, preserving the parent-owned input and the pure relationship between input and rendered output.
- **Review Point — Do not**: Do not reassign `props.title` or mutate a prop object in place; derive uppercase, formatted, or computed output in a local constant.
- **Required Lesson Proof**: Compare a prop mutation against a frozen development object with a local derived constant, then inspect the unchanged input before and after render.
