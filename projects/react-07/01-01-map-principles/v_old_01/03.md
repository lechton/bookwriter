## Operational Principles

### Principle 1: Return One JSX Root Expression
- **Operational Rule**: Make a component's return provide one enclosing JSX expression. Adjacent top-level JSX elements are separate expressions, so the JavaScript parser cannot treat them as one return value.
- **Review Point — Do not**: Do not place adjacent root-level JSX elements in one return without an enclosing element or Fragment.
- **Required Lesson Proof**: Show the parser failure for adjacent roots and the compiled shape of the same siblings under one enclosing expression.

### Principle 2: Use a Fragment When Grouping Should Add No DOM Node
- **Operational Rule**: Use `<>...</>` or an explicit Fragment to group siblings when a real wrapper would change semantics or layout. The Fragment satisfies the one-root expression rule but does not create an extra host element.
- **Review Point — Condition**: Use a semantic DOM wrapper when the page needs that element; use a Fragment when the wrapper would exist only to satisfy JSX grouping.
- **Required Lesson Proof**: Compare the browser DOM for a wrapper `<div>` and a Fragment, including one flex, grid, list, or table relationship affected by the extra node.

### Principle 3: Close Every JSX Tag Explicitly
- **Operational Rule**: Give paired elements a closing tag and self-close elements with no children. JSX uses a stricter tag grammar than the browser's forgiving HTML parser, so omitted closures fail before rendering.
- **Review Point — Do not**: Do not leave a JSX tag such as `<img>` or `<input>` unclosed.
- **Required Lesson Proof**: Show the compiler error for an unclosed tag and the valid self-closing form that compiles.

### Principle 4: Use React's DOM Property Names for JSX Attributes
- **Operational Rule**: Write JSX attributes using the names React maps to DOM properties, including `className`, `htmlFor`, and other camelCase property names. Preserve the standard hyphenated forms for `aria-*` and `data-*` attributes.
- **Review Point — Do**: Check attribute names against the React DOM API rather than mechanically pasting HTML spellings or camel-casing accessibility attributes.
- **Required Lesson Proof**: Map HTML `class` and `for` to DOM `className` and `htmlFor`, then show that `aria-label` and `data-*` remain hyphenated.
