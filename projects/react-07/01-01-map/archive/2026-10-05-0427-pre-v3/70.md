# Q70: Code-Splitting on Demand with React.lazy
* **Topic Tag**: `#lazy` | `❱❱ MORE`
* **Interview Question**: *How do you code-split a component and load it on demand with lazy?*
* **Core Truth**: `React.lazy` enables dynamic code-splitting by deferring component bundle downloads until the component is first rendered, pairing with `<Suspense>` to show a fallback while the JavaScript chunk downloads over the network.
* **The Friction**: An editorial news site includes an admin analytics dashboard and a heavy PDF viewer in `App.jsx`. Every normal reader downloads the 3MB bundle containing the admin code, even though 99.9% of readers never open the admin panel, destroying mobile page-load speed.
* **The Mechanism**: `React.lazy(() => import('./AdminPanel.jsx'))` paired with `<Suspense fallback={<Spinner />}>`. The bundler (Vite/Webpack) splits the imported file into a separate `.js` chunk that is fetched only when the `<AdminPanel />` tag renders.
* **Under the Hood**: Dynamic ES Modules and Suspense integration: `import()` returns a promise that resolves to the module namespace; `React.lazy` wraps this promise in a special lazy element type that throws the promise during render, activating the surrounding Suspense boundary until the network chunk downloads.
* **The Code Experiment**:
  * *Naive*: Statically importing heavy modals (`import HeavyChart from './HeavyChart'`) at the top of `App.jsx`, forcing all users to download the code on initial page load.
  * *React*: Dynamically importing via `const HeavyChart = React.lazy(() => import('./HeavyChart'))`, wrapping in `<Suspense fallback={<ChartSkeleton />}>` so the chunk downloads only when opened.
* **Scope Boundary**: Focus on `React.lazy`, dynamic `import()`, and bundling chunk separation with Suspense fallbacks. Do not introduce route-level frameworks (Next.js/Remix) or server components.
