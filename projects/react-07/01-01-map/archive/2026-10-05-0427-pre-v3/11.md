# Q11: Rendering Lists and Keys
* **Topic Tag**: `#rendering_lists` | `❱ CORE`
* **Interview Question**: *How do you render a list from an array, and why does React demand a key on every item?*
* **Core Truth**: React transforms arrays of data into arrays of JSX elements using `.map()`; every item in a dynamically rendered list requires a unique, stable `key` prop so React's reconciler can match items across renders during insertions, deletions, and reordering.
* **The Friction**: The National Times homepage renders a live feed of thirty breaking headlines. When an editor publishes an urgent top story at index 0, React without keys (or using array indices) reuses existing DOM nodes inappropriately, scrambling correction inputs, audio playback bars, and article checkboxes across unrelated stories.
* **The Mechanism**: Array `.map()` rendering with stable entity IDs (`key={story.id}`). Transforming arrays of objects into JSX elements within curly braces `{stories.map(story => <StoryRow key={story.id} story={story} />)}`.
* **Under the Hood**: How React's reconciler diffs lists: without stable keys, React defaults to index-based positional diffing (mutating existing DOM nodes in-place rather than moving or preserving their internal state); stable keys give elements persistent identity across renders regardless of array order.
* **The Code Experiment**:
  * *Naive*: Using `stories.map((story, index) => <StoryRow key={index} ... />)` or omitting `key`, causing inputs and state inside list items to glitch when a new item is prepended.
  * *React*: Using `stories.map(story => <StoryRow key={story.id} ... />)` with permanent database IDs, preserving component state and DOM integrity across reordering.
* **Scope Boundary**: Focus strictly on mapping arrays to JSX and the reconciliation role of stable keys. Do not introduce stateful list mutations like `useState` or dynamic filtering (reserved for Q22 and Q25).
