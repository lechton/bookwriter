# Q71: Reading Promises and Context with use()
* **Topic Tag**: `#use_promise` | `❱❱ MORE`
* **Interview Question**: *What is the use() API, and how does it read promises and context conditionally?*
* **Core Truth**: The `use()` API unwraps the value of a Promise or Context directly during render; unlike standard hooks, `use()` can be called conditionally inside `if` statements and loops, integrating natively with `<Suspense>` and Error Boundaries.
* **The Friction**: An article reader component wants to fetch editorial comments only if `showComments` is true. Traditionally, hooks cannot be called inside `if (showComments)`, forcing developers into awkward wrapper components or eager fetching that wastes network bandwidth.
* **The Mechanism**: The `use()` API (`const comments = use(commentsPromise)`). When passed a pending promise, `use()` suspends the component; when resolved, it returns the value; if rejected, it throws to the nearest Error Boundary.
* **Under the Hood**: Why `use()` can be conditional: unlike hooks which rely on a fixed fiber linked-list index, `use()` tracks resources dynamically; when a promise suspends, React pauses rendering and resumes the component execution from the top once the promise settles.
* **The Code Experiment**:
  * *Naive*: Calling a hook conditionally (`if (show) useEffect(...)`) crashing React, or eagerly fetching data when comments are collapsed.
  * *React*: An `ArticleComments` component conditionally calling `const data = use(commentsPromise)` only when `isOpen` is true, wrapped in `<Suspense>` for automatic loading states.
* **Scope Boundary**: Focus on `use(promise)` and conditional `use(Context)` in client components. Do not confuse with React Server Component async/await (reserved for Part Two / Q101+).
