# Q180: Migrating Legacy SSR to Streaming with hydrateRoot
* **Topic Tag**: #legacy_hydrate | LEGACY (Server)
* **Interview Question**: *How do you migrate a renderToString plus ReactDOM.hydrate app to streaming with hydrateRoot?*
* **Core Truth**: Migrating from a legacy renderToString and ReactDOM.hydrate pipeline to streaming with hydrateRoot requires replacing synchronous string generation with renderToPipeableStream on the server, wrapping client mounting in hydrateRoot, and moving inline manual script injections into React's bootstrapScriptContent options.
* **The Friction**: The core engineering team at The National Times inherits a monolithic React 17 server codebase with 500,000 daily readers that crashes on traffic surges; they must modernize to streaming SSR and selective hydration without rewriting their application components or disrupting existing editorial layouts.
* **The Mechanism**: Step-by-step migration: (1) Replace server `renderToString` with `renderToPipeableStream(App, { bootstrapScripts: ['/client.js'], onShellReady() { res.statusCode = 200; pipe(res); } })`; (2) Replace client `ReactDOM.hydrate(<App />, container)` with `hydrateRoot(container, <App />)`; (3) Wrap slow data-fetching components in `<Suspense>` boundaries to enable out-of-order streaming.
* **Under the Hood**: Reconciler pipeline modernization: the legacy pipeline required the server to build the full HTML string in memory and manually inject bundle `<script>` tags, while the client blocked until the entire DOM hydrated; the modern pipeline streams HTML chunks incrementally, allowing the browser to parse DOM early and `hydrateRoot` to attach listeners selectively as user interactions occur.
* **The Code Experiment**:
  * *Naive*: Attempting to modernize by simply swapping `ReactDOM.hydrate` for `hydrateRoot` in the browser while leaving the server on synchronous `renderToString`, missing out on streaming TTFB gains and concurrent out-of-order flushes.
  * *React*: Upgrading both ends of the wire simultaneously: converting the Express route to `renderToPipeableStream` with `onShellReady` and updating the browser entrypoint to `hydrateRoot`, transitioning the entire app to streaming SSR and selective hydration with zero component rewrites.
* **Scope Boundary**: Do not cover React Server Components or `'use client'` migrations (covered in Q101–Q168); focus strictly on the concrete, step-by-step operational migration of a traditional SSR React 17/18 app (renderToString + ReactDOM.hydrate) to modern streaming SSR (renderToPipeableStream + hydrateRoot).
