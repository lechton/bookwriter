### Pasted HTML and Compiler Crashes

- [p] ◇ In plain HTML, web browsers are remarkably forgiving. Browsers allow unclosed void tags like `<img>` or `<input>`. Browsers also permit multiple adjacent elements at the top level of a file. If you paste raw HTML markup into a standard `.html` file, the browser engine parses the text and paints the page. ◼ Educational objective: establish the forgiving baseline of plain HTML before introducing the strict grammar of JSX.
- [p] ★ {preknowledge: HTML elements, JavaScript functions, return statements} {bridging: developers assume they can paste HTML directly into React components, but JSX is strict JavaScript syntax that enforces rigorous compiler rules} When a developer pastes raw HTML into a React component function, the build tool halts immediately. Look at the naive HTML paste attempt: ◼ Educational objective: demonstrate the syntax crashes caused by pasting raw HTML into a component.
- [code] Naive HTML Paste:
```jsx title="Naive HTML Paste"
export default function NewsWire() {
  return (
    <img src="/wire.jpg"> // **WRONG:** unclosed void tag halts **COMPILER**
    <h2>Wire Update</h2>  // **WRONG:** adjacent sibling violates single **ROOT**
    <p class="wire-copy">Live wire feed.</p>
  );
}
```
◼ **The what-this-introduces list:** 1. Unclosed `<img>`: missing self-closing slash. 2. Adjacent siblings: multiple top-level elements inside a single return. 3. `class` attribute: JavaScript reserved word collision. 4. Compiler crash: syntax errors preventing bundle generation.
- [p] ★ {preknowledge: JavaScript return syntax, function arguments, compiler transforms} {bridging: the failure occurs because JSX is not HTML; it is a syntax extension for JavaScript that compiles to function calls} The compiler crashes because a JavaScript function cannot return multiple values. Writing `return a, b` evaluates both but returns only the second value. Furthermore, JSX compiles into `_jsx()` function calls. Every `_jsx()` call represents a single element descriptor. You cannot pass two separate expressions to a single `return` statement without a wrapping structure. ◼ Educational objective: deconstruct why JavaScript functions cannot return adjacent sibling expressions.
- [figure] ```html-figure src="figures/04-00-jsx-root-and-fragments.html" caption="DOM wrapper divs pollute the DOM and break layouts, while React Fragments group siblings with zero DOM overhead."```
- [grounding] [!WILD] **Why does a wrapper div break your CSS Flexbox layout?** When developers hit the single-root error, their instinctive reflex is wrapping everything in a `<div>`. While this satisfies the compiler, it often destroys layout styling. In CSS Flexbox and Grid, layout properties apply exclusively to direct child elements. If a parent container declares `display: flex; gap: 16px;`, its direct children become flex items. Placing an extra `<div>` wrapper around your siblings turns those elements into grandchildren. The flex container now sees only one child: the wrapper div. Your flex row layout collapses into a single vertical block, and gap spacing between items vanishes. React Fragments solve this by satisfying the compiler without creating a physical DOM wrapper.
- [callout] > [!TIP]
> **To impress the interviewer:** When asked to explain JSX, do not call it "HTML inside JavaScript." State that JSX is a strict syntax extension that compiles into regular JavaScript function calls (`_jsx()`). Because functions can only return a single value, every JSX snippet requires a single root element.

### The Invariants of JSX and React Fragments

- [p] ◇ **JSX** stands for JavaScript XML. It is a syntax extension that lets you write HTML-like markup inside JavaScript files. Because JSX compiles directly into JavaScript, it enforces three strict syntactic invariants: ◼ Educational objective: introduce the three fundamental syntactic invariants of JSX.
- [p] 1. **Single Root Invariant**: Every component return must have exactly one root element. ◼ Educational objective: declare the single root requirement.
- [p] 2. **Explicit Closing Invariant**: Every tag must be closed explicitly, including void elements (`<img />`, `<input />`). ◼ Educational objective: declare the explicit closing requirement.
- [p] 3. **CamelCase Property Invariant**: Attribute names use camelCase (`className`, `htmlFor`) to prevent collisions with JavaScript reserved keywords. ◼ Educational objective: declare the camelCase attribute requirement.
- [p] ★ {preknowledge: wrapper elements, DOM trees, CSS layout constraints} {bridging: to satisfy the single root invariant without polluting the DOM, developers face a pedagogical crossroads between an extra DOM container and a React Fragment} When grouping adjacent sibling elements, you face a choice between two architectural approaches: ◼ Educational objective: frame the pedagogical crossroads between DOM wrapper elements and React Fragments.
- [p] - **Option 1 (The foundational way)**: Wrap adjacent siblings in an explicit DOM container element (`<div className="wire-group">`). ◼ Educational objective: declare Option 1 with concrete syntax tokens.
- [p] - **Option 2 (The modern idiomatic way)**: Wrap adjacent siblings in a lightweight React Fragment (`<>...</>`). ◼ Educational objective: declare Option 2 with concrete syntax tokens.
- [p] First, look at Option 1 using an explicit wrapper element: ◼ Educational objective: transition to Option 1 code.
- [code] Option 1:
```jsx title="Option 1: The Foundational Way (<div className>)"
export default function NewsWire() {
  return (
    <div className="wire-group"> // Inserts physical wrapper **NODE**
      <h2>Wire Update</h2>       // Child element inside **DIV**
      <p>Live wire feed.</p>     // Sibling element inside **DIV**
    </div>
  );
}
```
◼ **The what-this-introduces list:** 1. `<div className="wire-group">`: physical HTML wrapper container. 2. `className`: JSX replacement for the reserved word `class`. 3. Extra DOM node: an additional element inserted into the browser's DOM tree.
- [p] ★ In Option 1, the code compiles successfully because the `<div>` serves as a single root. However, the browser creates a physical `<div>` element in the DOM. In complex layouts, nesting dozens of unnecessary wrapper divs bloats DOM memory and breaks CSS Flexbox and Grid alignments. ◼ Educational objective: deconstruct the architectural cost of unnecessary wrapper elements.
- [p] Next, look at Option 2 using a React Fragment: ◼ Educational objective: transition to Option 2 code.
- [code] Option 2:
```jsx title="Option 2: The Modern Idiomatic Way (<>...</>)"
export default function NewsWire() {
  return (
    <>                     // Groups siblings with **ZERO DOM**
      <h2>Wire Update</h2> // Direct child of **PARENT**
      <p>Live wire feed.</p>
    </>
  );
}
```
◼ **The what-this-introduces list:** 1. `<>`: opening empty Fragment syntax. 2. `</>`: closing Fragment syntax. 3. Zero DOM footprint: children mount directly into the parent container.
- [p] ★ In Option 2, the empty tags `<>...</>` represent a **React Fragment**. The compiler transforms this into `_jsx(Fragment, { children: [...] })`. React evaluates the children but inserts zero wrapper nodes into the browser DOM. The `<h2>` and `<p>` elements mount as direct children of the parent container, preserving CSS layouts perfectly. ◼ Educational objective: explain how the Fragment compiler symbol eliminates DOM wrapper overhead.
- [callout] > [!KEY]
> Always use React Fragments (`<>...</>`) to group adjacent sibling elements when you do not need an extra physical DOM wrapper for styling or semantics.

### Step 1: First, we construct the parent flex container <App.jsx>

- [p] We begin by constructing the parent layout container in `src/App.jsx`. This component uses CSS Flexbox to position items side by side in a row with a defined gap. Notice that `App.jsx` mounts `<NewsWire />` as an immediate child of the flex container: ◼ Educational objective: construct the parent flexbox container and mount the child component.

```jsx title="App.jsx"

  return (
```

◼ **The what-this-introduces list:** 1. `import NewsWire`: importing child component. 2. `wire-feed-flex`: CSS class declaring `display: flex; gap: 16px;`. 3. `<NewsWire />`: mounting child component inside flex container.
- [p] Notice what is critical here: `wire-feed-flex` expects its immediate children to participate in the flex row layout. If `NewsWire` renders an extra wrapper `<div>`, the flex items become trapped inside that wrapper, destroying the horizontal row layout. ◼ Educational objective: explain the layout dependency between parent flex containers and child components.

### Step 2: Next, we declare the Fragment root and void tag <NewsWire.jsx>

- [p] Now we create the component file `src/components/NewsWire.jsx`. We begin by declaring the function and opening a React Fragment `<>`. Inside the Fragment, we place our first element: a self-closing `<img />` tag with explicit `className`: ◼ Educational objective: declare the Fragment root and enforce self-closing void tag syntax.
- [code] NewsWire.jsx:
```jsx title="NewsWire.jsx" startLine="1" continues="bottom"
export default function NewsWire() {
  return (
    <>                                                         // Opens lightweight **FRAGMENT**
      <img className="wire-icon" src="/wire.png" alt="Wire" /> // Self-closing void **TAG**
```
◼ **The what-this-introduces list:** 1. `export default function NewsWire`: component function declaration. 2. `<>`: opening Fragment tag. 3. `<img ... />`: self-closing void element with trailing slash. 4. `className="wire-icon"`: camelCase attribute mapping to DOM property.
- [p] Notice the trailing slash on `<img ... />`. In HTML, void elements like `<img>` or `<input>` can omit closing tags. In JSX, all tags must be explicitly closed. Omitting the slash causes an immediate syntax error. ◼ Educational objective: explain the strict XML requirement for self-closing void tags.

### Step 3: Then, we complete the sibling elements <NewsWire.jsx>

- [p] Next, we add the remaining sibling elements: a headline and a timestamp paragraph. We then close the Fragment with `</>` and close the return statement: ◼ Educational objective: complete the sibling elements and close the Fragment.
- [code] NewsWire.jsx:
```jsx title="NewsWire.jsx" startLine="5" continues="top"

      <p className="wire-time">Updated 1 minute ago.</p>        // Sibling timestamp **COPY**
    </>                                                        // Closes React **FRAGMENT**
  );

```
◼ **The what-this-introduces list:** 1. `<h2 className="wire-headline">`: sibling headline element. 2. `<p className="wire-time">`: sibling timestamp element. 3. `</>`: closing Fragment syntax. 4. Zero DOM footprint: children mount directly into parent flex container.
- [p] Notice that `<h2>` and `<p>` are direct siblings of `<img>`. Because they are enclosed in `<>...</>`, React bundles them into a single return value without adding a `<div>`. All three elements mount as direct children of `wire-feed-flex`. ◼ Educational objective: verify that Fragment children preserve parent flex layout.

### Step 4: Finally, we mount the application at the root <src/main.jsx>

- [p] Finally, we connect our application to the physical browser DOM in `src/main.jsx`. This file acts as the mounting bridge. It locates `<div id="root">` and calls `createRoot()`. React then renders `<App />`, executing `NewsWire()` and committing the elements directly into the flex container: ◼ Educational objective: connect the application tree to the physical browser DOM.
- [code] src/main.jsx:
```jsx title="src/main.jsx"
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = createRoot(document.getElementById('root')); // Locates host **DOM**
root.render(
  <StrictMode>
    <App /> // Mounts application tree into **ROOT**
  </StrictMode>
);
```
◼ **The what-this-introduces list:** 1. `createRoot`: React 19 client mounting API. 2. `document.getElementById('root')`: locating the host DOM container. 3. `<StrictMode>`: React development verification wrapper. 4. `<App />`: mounting the root application component.
- [p] When React renders this tree, it evaluates `<App />`, encounters `<NewsWire />`, and unpacks its Fragment. The image, headline, and paragraph render directly inside the parent `<div>`. No wrapper node is created. ◼ Educational objective: trace end-to-end mounting and Fragment unwrapping in the DOM.

### Glossary

- [glossary] JSX ◼ A syntax extension for JavaScript that allows developers to write XML-like markup that compiles into standard `_jsx()` function calls.
- [glossary] React Fragment ◼ A built-in React component (`<>...</>`) that groups a list of children without adding extra nodes to the physical browser DOM.
- [glossary] Single Root Invariant ◼ The compiler requirement that every component return statement must resolve to a single JavaScript expression.
- [glossary] Self-Closing Tag ◼ A tag that closes itself with a trailing slash (`<img />`), mandatory in JSX for void HTML elements that have no children.
- [glossary] className Property ◼ The JSX attribute used to assign CSS classes, replacing the reserved JavaScript keyword `class`.

## Beyond the basics

- **JSX compilation under the hood**: The JSX transform turns `<><h1>Hello</h1></>` into `_jsx(Fragment, { children: _jsx("h1", { children: "Hello" }) })` using the React Fragment symbol (see [react.dev/learn/writing-markup-with-jsx](https://react.dev/learn/writing-markup-with-jsx)).
- **Fragments with keys in mapped collections**: While the shorthand `<>...</>` syntax does not accept attributes, the explicit `<React.Fragment key={id}>` syntax allows passing keys when rendering lists of fragments (see [react.dev/learn/rendering-lists](https://react.dev/learn/rendering-lists)).
- **DOM property mapping**: JSX attributes closely match browser DOM properties rather than HTML attribute strings; for example, `class` becomes `className` and `for` becomes `htmlFor` (see [react.dev/learn/writing-markup-with-jsx](https://react.dev/learn/writing-markup-with-jsx)).
- **Single-expression returns in JavaScript**: A JavaScript `return` statement can only evaluate and return one value; wrapping multiple expressions in parentheses and a Fragment creates a single compound expression (see [react.dev/learn/writing-markup-with-jsx](https://react.dev/learn/writing-markup-with-jsx)).
- **Void elements and strict XML rules**: In HTML5, void elements like `<input>`, `<img>`, and `<br>` can omit closing slashes, but JSX strictly follows XML rules where all tags must be explicitly closed (see [react.dev/learn/writing-markup-with-jsx](https://react.dev/learn/writing-markup-with-jsx)).

### Summary

**Architectural Takeaways & Decision Matrix**

❒ Single Root & Fragments

➔ ALWAYS wrap adjacent sibling elements in a React Fragment (`<>...</>`) to satisfy the single-return rule without adding DOM nodes.

➔ NEVER wrap sibling elements in an unnecessary `<div>` when they reside inside CSS Flexbox or Grid containers.

➔ IF returning multiple siblings without a wrapper THEN use `<>...</>` to prevent compiler syntax errors.

❒ Tag Closing & Attributes

➔ ALWAYS close all JSX tags explicitly, including void elements like `<img />`, `<input />`, and `<br />`.

➔ ALWAYS use `className` instead of `class` when assigning CSS styling to avoid collisions with JavaScript reserved words.

**DO THIS:** wrap sibling elements in a Fragment with self-closing tags

```jsx right
export default function NewsWire() {
  return (
    <>
      <img className="icon" src="/wire.png" alt="Wire" />
      <h2>Live Update</h2>
    </>
  );
}
```

**DO NOT DO THIS:** return adjacent elements or use unclosed tags and class

```jsx wrong
export default function NewsWire() {
  return (
    <img class="icon" src="/wire.png">
    <h2>Live Update</h2>
  );
}
```
