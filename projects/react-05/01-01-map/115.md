# Q115: Server/Client Composition: Passing Server Components as Children
* **Topic Tag**: #composition | ❱ CORE (Server)
* **Interview Question**: *How do you pass server-rendered children into a Client Component?*
* **Core Truth**: Client Components can accept server-rendered elements as children or props, allowing developers to nest zero-bundle-size Server Components inside interactive client wrappers without pulling server code into the client bundle.
* **The Friction**: A photo gallery carousel at The National Times requires client interactivity (swipe gestures, active slide index), but each slide displays a 50KB high-resolution editorial article fetched from the database; importing the slides directly inside the 'use client' carousel bloats the client bundle with database queries and markdown formatters.
* **The Mechanism**: Composition pattern: <ClientCarousel><ServerArticleSlide id="1" /><ServerArticleSlide id="2" /></ClientCarousel>: the parent Server Component renders the slides on the server and passes the resulting React elements as children to the Client Component.
* **Under the Hood**: Serialization of JSX elements: the Server Component evaluates <ServerArticleSlide /> into an RSC element payload on the server; the Client Component receives this already-resolved element object as a prop, never needing the source code of ServerArticleSlide.
* **The Code Experiment**:
  * *Naive*: Importing and rendering Server Components directly inside a file marked with 'use client', causing a build error or forcing the imported code to run as client components.
  * *React*: Passing server-rendered components as children into an interactive 'use client' wrapper, preserving zero-bundle-size server rendering for the nested content.
* **Scope Boundary**: Focus on component composition across the server/client boundary (slots, children pattern). Do not confuse with client-side render props or context.
