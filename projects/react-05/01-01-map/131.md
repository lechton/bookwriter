# Q131: The 'use client' Boundary: Module Edges, Imports, and Exports
* **Topic Tag**: #use_client | ❱❱ MORE (Server)
* **Interview Question**: *What does a 'use client' file mean for its imports and exports?*
* **Core Truth**: The 'use client' directive defines a module boundary where the marked file and its entire downstream import subgraph are bundled for the browser, while its exports act as entrypoints that Server Components can import as Client References.
* **The Friction**: A developer at The National Times adds 'use client' to a comment widget that imports a shared formatting.ts utility; formatting.ts happens to import a 150KB markdown parser and internal config, accidentally dragging the entire dependency tree into the reader's client bundle.
* **The Mechanism**: Module boundary mechanics: (1) All transitive imports of a 'use client' module become part of the client bundle; (2) Exports of a 'use client' module must be valid React components or serializable values; (3) Server Components can import and render Client Components, but Client Components cannot import Server Components directly.
* **Under the Hood**: Bundler module graph slicing: bundlers like Webpack and Turbopack treat 'use client' as a boundary cut; every node reachable via import from this root is placed in the client chunk manifest, while the server build generates a client reference proxy { $$typeof: Symbol.for('react.client.reference'), id, name }.
* **The Code Experiment**:
  * *Naive*: Importing a heavy server utility or giant helper library into a 'use client' component, unwittingly bloating the client bundle.
  * *React*: Isolating client-specific interactive UI into leaf components with minimal imports, importing shared presentational utilities that have zero server-only dependencies.
* **Scope Boundary**: Focus on the module graph rules, transitive imports, and exported boundary contracts of 'use client'. Do not re-explain basic client component usage from Q106.
