# Q15: Inverse Data Flow with Callback Props
* **Topic Tag**: `#callback_props` | `❱ CORE`
* **Interview Question**: *How does a child component notify its parent or trigger actions using callback props?*
* **Core Truth**: React enforces unidirectional data flow (props flow down), so child components communicate upward by invoking callback functions passed down from parents as props.
* **The Friction**: A `FilterBar` component contains buttons for "Politics", "Business", and "Tech", but the active filter and headline query belong to the top-level `NewsroomPage`. Beginners try to reach into parent state, mutate parent variables directly, or use global events, breaking React's predictable component boundaries.
* **The Mechanism**: Inverse data flow via callback props. The parent defines a handler function and passes it down (`<FilterBar onSelectCategory={handleCategoryChange} />`); the child invokes `props.onSelectCategory('Business')` upon user interaction.
* **Under the Hood**: How JavaScript closures allow child components to execute functions that close over parent scope, enabling child-triggered notifications while keeping state ownership and update authority strictly inside the parent.
* **The Code Experiment**:
  * *Naive*: Attempting to mutate parent variables from inside a child, or hardcoding child components so they cannot notify containing screens.
  * *React*: `NewsroomPage` passing an `onSelectCategory` callback prop to a reusable `FilterBar`, which triggers the callback on button click with the selected category slug.
* **Scope Boundary**: Focus on passing and invoking function props (callback props) and the mental model of inverse data flow. Keep state static or simulated via console/arguments; do not fully implement `useState` management yet (reserved for Q16).
