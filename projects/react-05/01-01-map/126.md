# Q126: Server Preloading: Warming Resources Early with react-dom APIs
* **Topic Tag**: #preloading | ❱ CORE (Server)
* **Interview Question**: *How do preload, preinit, preconnect, and prefetchDNS speed up loading?*
* **Core Truth**: React 19's server preloading APIs emit early resource hints into the initial HTML stream, instructing the browser to warm connections and fetch critical fonts, scripts, and stylesheets before the parser discovers them in the DOM.
* **The Friction**: The custom editorial serif font Times Romanesque and headline hero images at The National Times are only discovered by the browser after deep HTML parsing, causing noticeable layout shifts (CLS) and flashing text; manual <link rel="preload"> tags in templates frequently fall out of sync with component requirements.
* **The Mechanism**: Resource preloading APIs from react-dom: preload(href, { as }), preinit(href, { as }), preconnect(origin), prefetchDNS(origin); can be called inside Server Components during render to inject <link> hints into the HTML <head>.
* **Under the Hood**: Early hint emission in the stream: when preload or preinit is invoked during server rendering, React hoists the corresponding <link rel="preload"> or <script> tags into the earliest flushed chunk of the HTML stream, enabling parallel resource download while the rest of the page renders.
* **The Code Experiment**:
  * *Naive*: Allowing hero article images and web fonts to be discovered lazily when their <img> and @font-face rules appear deep in the document body.
  * *React*: Calling preload('/fonts/editorial.woff2', { as: 'font' }) and preload(heroImageUrl, { as: 'image' }) inside the ArticleHero component to trigger immediate browser fetching.
* **Scope Boundary**: Focus on server resource preloading (preload, preinit, preconnect, prefetchDNS) and head emission. For client-side dynamic preloading, refer back to Q84.
