# Q08: Passing Data into Components with Props
* **Topic Tag**: `#props` | `❱ CORE`
* **Interview Question**: *How do you pass data into a component, and why can a component never change its own props?*
* **Core Truth**: Props are read-only input snapshots passed downward from parent to child; components must treat props as immutable values to preserve unidirectional data flow and deterministic rendering.
* **The Friction**: A developer creates an `ArticleCard` component, but every copy on the homepage displays the exact same static headline. When the developer attempts to mutate `props.title = 'Updated'` inside the child, React fails or creates subtle rendering bugs where sibling cards lose synchronization.
* **The Mechanism**: Component props. A parent passes custom attributes in JSX (`<ArticleCard title="..." />`), the child receives them as an immutable object (unpacked via destructuring `{ title }`), and props remain strictly read-only.
* **Under the Hood**: Why React freezes the `props` object in development (`Object.freeze`), how mutating props breaks memoization and reconciliation assumptions, and how unidirectional data flow guarantees that only the data owner can trigger an update.
* **The Code Experiment**:
  * *Naive*: Mutating `props.title` directly inside a child component, or duplicating static markup instead of passing props.
  * *React*: Parent `NewsFeed` passing distinct `title` and `author` props to multiple reusable `ArticleCard` instances, with child components unpacking props via parameter destructuring.
* **Scope Boundary**: Focus on basic downward data flow, prop passing, parameter destructuring, and the immutability contract. Do not introduce the `children` prop (Q9) or callback functions passed to props (Q15).
