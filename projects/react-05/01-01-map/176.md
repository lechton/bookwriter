# Q176: Legacy renderToString: Status and Legitimate Uses
* **Topic Tag**: #legacy_render_to_string | LEGACY (Server)
* **Interview Question**: *What is renderToString's status today, and what is it still legitimately used for?*
* **Core Truth**: renderToString is a legacy, synchronous server API that cannot support streaming, out-of-order Suspense, or React Server Components, but remains legitimately useful for generating static HTML strings in non-streaming contexts like transactional email generation and static 404/500 fallback pages.
* **The Friction**: The legacy email newsletter service at The National Times was migrated by an overzealous engineer to `renderToPipeableStream`, introducing complex Node stream piping and async buffering for a simple batch email worker that just needs a flat HTML string to pass to SendGrid.
* **The Mechanism**: ReactDOMServer.renderToString(element): synchronously evaluates a React element tree and returns an HTML string; it blocks the execution thread until the entire tree finishes rendering, throws an error if any component suspends on a promise, and omits modern streaming markers.
* **Under the Hood**: Synchronous call stack recursion: `renderToString` walks the element tree via synchronous recursive function calls, pushing each child onto the JavaScript call stack; because it cannot yield to the event loop, it cannot await promises, support Suspense fallbacks, or emit incremental chunks, making it obsolete for modern interactive web applications.
* **The Code Experiment**:
  * *Naive*: Using `renderToString` to render a modern news portal homepage with async data requirements, which crashes on `<Suspense>` boundaries and blocks the Node.js event loop during high traffic.
  * *React*: Reserving `renderToString` exclusively for generating offline transactional email templates and static error pages, while using `renderToPipeableStream` for all interactive, streaming web page responses.
* **Scope Boundary**: Do not cover `renderToStaticMarkup` (covered in Q177) or streaming APIs (covered in Q110/Q160); focus strictly on the modern status of `renderToString`, its architectural limitations (no Suspense, no streaming, event loop blocking), and its remaining valid use cases (emails, error templates).
