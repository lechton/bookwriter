# Q30: Passing Data Deeply with Context and the use() API
* **Topic Tag**: `#context` | `❱ CORE`
* **Interview Question**: *How do you pass data many levels deep without prop drilling, and how does the use() API read it?*
* **Core Truth**: Context teleports data down the component tree without manual prop drilling through intermediate components; React 19 allows reading context anywhere using the flexible `use(ThemeContext)` API alongside `<ThemeContext.Provider>`.
* **The Friction**: The National Times app theme (`'dark' | 'light'`) is selected at the root `App` component, but a deeply nested `ShareButton` four levels down inside an article card needs the theme. Every intermediate component (`Page`, `Column`, `ArticleCard`, `ActionBar`) must accept and forward a `theme` prop it never uses.
* **The Mechanism**: React Context: `createContext()`, `<ThemeContext value={currentTheme}>` (React 19 syntax) / `<ThemeContext.Provider value={...}>`, and reading it in child components using `use(ThemeContext)` or `useContext(ThemeContext)`.
* **Under the Hood**: How context establishes an ambient value in the Fiber tree; when a provider's value changes, React scans downward and schedules re-renders for all consumer components reading that context, bypassing intermediate component props.
* **The Code Experiment**:
  * *Naive*: Manually passing `theme` through five layers of intermediate components that have no interest in theme styling (prop drilling).
  * *React*: An `App` providing `ThemeContext`, and a deeply nested `EditorialBadge` reading the theme directly with `use(ThemeContext)` without touching any intermediate props.
* **Scope Boundary**: Focus on basic context creation, provider wrapping, and reading with `use()` / `useContext()`. Do not cover context optimization or split providers (reserved for Q32) or combining with reducers (Q31).
