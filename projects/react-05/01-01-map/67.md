# Q67: Prioritizing UI Updates with useTransition
* **Topic Tag**: `#use_transition` | `❱❱ MORE`
* **Interview Question**: *How do you keep typing responsive while a big re-render runs with useTransition?*
* **Core Truth**: `useTransition` marks specific state updates as non-blocking transitions, allowing urgent updates like typing to interrupt heavy background rendering while providing an `isPending` indicator.
* **The Friction**: An editor types into a fast search input that filters 5,000 articles. Updating the search query and the filtered list in the same state setter freezes the text cursor with every keystroke because the browser must render 5,000 items before drawing the typed letter.
* **The Mechanism**: The `useTransition` hook (`const [isPending, startTransition] = useTransition()`). Keep the input state update urgent (`setQuery(text)`), and wrap the heavy list update in `startTransition(() => { setFilteredQuery(text); })`.
* **Under the Hood**: Priority lane scheduling: urgent updates run in synchronous/input priority lanes, while `startTransition` schedules updates in transition lanes; if a new urgent update arrives while a transition is rendering, React interrupts and discards the in-progress transition render.
* **The Code Experiment**:
  * *Naive*: Updating input text and filtering 5,000 rows in a single synchronous state setter, causing stuttering keystrokes.
  * *React*: An `ArticleSearch` component splitting the update: `setQuery` updates the input immediately, while `startTransition` renders the search results in the background, displaying an `isPending` spinner without typing lag.
* **Scope Boundary**: Focus on `useTransition`, `startTransition`, `isPending`, and separating urgent from non-urgent updates. Do not confuse with `useDeferredValue` (Q68).
