# Q09: Component Composition with the Children Prop
* **Topic Tag**: `#children` | `❱ CORE`
* **Interview Question**: *How do the children prop, spread attributes, and default values work?*
* **Core Truth**: The `children` prop enables component composition by projecting nested JSX content between opening and closing tags, while prop spreading forwards attributes and default parameters provide reliable fallbacks.
* **The Friction**: A team builds a `Modal` or `Card` component. They attempt to pass raw HTML strings or create ten separate props (`bodyText`, `footerButton`, `imageTag`) just to customize the card's inner layout. The component becomes an unmaintainable prop-drilling monster.
* **The Mechanism**: The `children` slot prop (`{ children }`), attribute spreading (`{...rest}`), and default prop values (`{ theme = 'light' }`). Enclosing JSX between `<Card><h2>Headline</h2></Card>` passes the inner tree directly into `props.children`.
* **Under the Hood**: How JSX translates nested tags into the `children` property of the props object in `_jsx()`, and how component composition prevents prop drilling by allowing parents to assemble UI directly.
* **The Code Experiment**:
  * *Naive*: A rigid `Card` component with ten separate text and styling props trying to anticipate every possible layout permutation.
  * *React*: A composable `ArticleBox` component accepting `{ children, tier = 'standard', ...rest }` that wraps arbitrary editorial content with consistent layout and styling.
* **Scope Boundary**: Focus on composition via `children`, default prop fallbacks, and spreading. Do not introduce context providers or render props.
