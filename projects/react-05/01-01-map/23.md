# Q23: Controlled Inputs
* **Topic Tag**: `#controlled_inputs` | `❱ CORE`
* **Interview Question**: *How do you make an input, textarea, or select fully controlled by React state?*
* **Core Truth**: A controlled input binds its `value` prop directly to React state and updates that state via an `onChange` handler, establishing React as the single source of truth for the form element's DOM value.
* **The Friction**: A reader types into an article feedback textarea. If the input is uncontrolled or half-controlled, React cannot sanitize text on the fly, validate character limits before display, or reset the field after submission without reaching into the DOM with imperative element selectors.
* **The Mechanism**: The controlled input pattern: pairing `value={text}` with `onChange={e => setText(e.target.value)}`. React pushes state into the input's DOM property on every render and intercepts keystrokes to update state.
* **Under the Hood**: How React synchronizes the physical DOM `input.value` property with the virtual element `value` prop on every commit; how the transition between `undefined` and defined values triggers the classic "uncontrolled to controlled" console warning.
* **The Code Experiment**:
  * *Naive*: Setting `value={text}` without an `onChange` handler (freezing the input so the user cannot type), or allowing `value` to start as `undefined` before becoming a string.
  * *React*: An `ArticleCorrectionForm` with controlled `<input>` and `<textarea>` components enforcing a live character count and resetting fields declaratively upon submission.
* **Scope Boundary**: Focus on single-input and multi-input controlled form synchronization (`value` + `onChange`). Do not introduce React 19 form actions or `useActionState` (reserved for Q40–Q45).
