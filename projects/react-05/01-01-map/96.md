# Q96: Legacy Class Components: Reading and Understanding 2019 Code
* **Topic Tag**: #legacy_class | LEGACY
* **Interview Question**: *How do class components work, and how do you read one today?*
* **Core Truth**: Class components extend React.Component and manage state via this.state and this.setState, requiring explicit method binding and lifecycle methods that modern function components replace with hooks and closures.
* **The Friction**: An engineer at The National Times inherits an enterprise newsroom codebase authored in 2019 where every article widget is written as an ES6 class with constructor(props), this.state, this.handleClick = this.handleClick.bind(this), and a render() method; unable to read class patterns, the engineer cannot maintain or refactor legacy features.
* **The Mechanism**: Class component anatomy: class ArticleCard extends React.Component { constructor(props) { super(props); this.state = { count: 0 }; } render() { return <div>{this.state.count}</div>; } }. Contrast each piece directly with modern equivalents (useState, closures, arrow functions).
* **Under the Hood**: this context binding in JavaScript classes: class methods in JavaScript are not bound by default; invoking this.setState from an unbound event callback throws TypeError: Cannot read property 'setState' of undefined, which necessitated manual .bind(this) in constructors.
* **The Code Experiment**:
  * *Naive*: Forgetting to bind event handler methods in the constructor of a class component, causing runtime crashes on button clicks.
  * *React*: Side-by-side comparison of a legacy class ArticleSubscriber with its modern function component equivalent, mapping this.state to useState and class methods to local functions.
* **Scope Boundary**: Focus strictly on reading, understanding, and translating class components to modern function components. Do not write new class components for modern features.
