# Q101: React Server Components: Overview and Purpose
* **Topic Tag**: #rsc_overview | ❱ CORE (Server)
* **Interview Question**: *What are React Server Components, and why do they exist?*
* **Core Truth**: React Server Components execute exclusively on the server at build or request time, outputting a serialized description of UI (the RSC payload) rather than executable JavaScript, eliminating heavy dependencies from the client bundle.
* **The Friction**: An article page at The National Times ships 450KB of client JavaScript just to parse markdown, format timestamps, and highlight code blocks—even though the article text and author byline never change after publication; mobile readers on slow connections face a 4-second delay before the article becomes readable.
* **The Mechanism**: Server Components run only on the server, have direct access to server data sources, and emit no JavaScript into the client bundle; Client Components ('use client') are hydrated in the browser for interactivity.
* **Under the Hood**: The RSC payload: Server components are rendered into a streaming JSON-like tree format (UI description, server data, and client component module references); the browser React runtime consumes this stream to construct the DOM without downloading the server component source code.
* **The Code Experiment**:
  * *Naive*: Importing a heavy markdown parser (marked or unified, 120KB) in a client component to render an article body on every reader device.
  * *React*: Authoring ArticleContent as a Server Component that awaits database content, runs marked on the server, and sends zero markdown-parser bytes to the browser.
* **Scope Boundary**: Focus on the architectural motivation, zero-bundle-size benefit, and what RSCs are. Do not delve into deep streaming mechanics or Server Functions.
