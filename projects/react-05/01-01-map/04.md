# Q04: JSX Syntax Rules and Fragments
* **Topic Tag**: `#jsx` | `❱ CORE`
* **Interview Question**: *What is JSX, what syntax rules must every snippet follow, and how do Fragments group elements without wrapper nodes?*
* **Core Truth**: JSX is strict JavaScript syntax that compiles to function calls, requiring a single root element, explicit tag closing, and camelCase attributes; Fragments (`<>...</>`) group sibling elements without polluting the physical DOM.
* **The Friction**: A developer pastes clean HTML into a component. The build crashes immediately: an unclosed `<img>` tag halts the compiler, adjacent `<h2>` and `<p>` tags violate the single-return rule, and wrapping them in a `<div>` breaks the parent CSS Grid / Flexbox layout.
* **The Mechanism**: JSX syntax invariants and React Fragments (`<>...</>`). Fragments satisfy the compiler's single-expression requirement while rendering zero wrapper nodes in the physical DOM.
* **Under the Hood**: Why functions cannot return multiple expressions in JavaScript (`return a, b` returns only b), how `jsx()` requires a single parent node, and how the Fragment compiler symbol unwraps children directly into the parent container.
* **The Code Experiment**:
  * *Naive*: Returning adjacent sibling elements without a root, or wrapping in an unnecessary `<div>` that breaks flex gap alignment.
  * *React*: Wrapping sibling headline, summary, and self-closing `<img />` tags inside a lightweight Fragment `<>...</>`.
* **Scope Boundary**: Focus strictly on JSX syntax grammar (self-closing tags, `className`, single root, and Fragments). Do not introduce dynamic curly brace variables or component props.
