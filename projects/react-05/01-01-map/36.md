# Q36: Client-Side Data Fetching with useEffect
* **Topic Tag**: `#data_fetching_client` | `❱ CORE`
* **Interview Question**: *How do you fetch data from an API in a client component, and how do you handle loading, error, and race conditions?*
* **Core Truth**: Client-side data fetching with `useEffect` requires managing explicit loading, error, and data states, while utilizing an `AbortController` or boolean flag in the cleanup function to prevent race conditions and unmounted state updates.
* **The Friction**: A reader rapidly clicks between "Politics" and "Sports" news tabs. The "Politics" fetch is slow and returns *after* the fast "Sports" fetch finishes, overwriting the screen with the wrong category's articles (a race condition). Meanwhile, navigating away triggers "Can't perform a React state update on an unmounted component" errors.
* **The Mechanism**: Fetching with cleanup and status states (`data`, `isLoading`, `error`). Using `AbortController` inside `useEffect`: pass `controller.signal` to `fetch()`, and call `controller.abort()` in the cleanup function so outdated or cancelled requests are safely discarded.
* **Under the Hood**: Network latency vs render cycles: asynchronous promise resolution occurs outside React's render pipeline; without abort cleanup, stale responses resolve in arbitrary order and write to component state out of sequence.
* **The Code Experiment**:
  * *Naive*: Plain `fetch().then(res => setData(res))` inside `useEffect` without error handling, loading states, or cancellation, causing race conditions when props change quickly.
  * *React*: An `ArticleReader` component fetching article content by `articleId`, tracking `isLoading` and `error`, and aborting the fetch via `AbortController` in the effect cleanup.
* **Scope Boundary**: Focus on client-side `fetch` with `useEffect`, loading/error states, and `AbortController`. Do not cover React 19 `use(promise)` (Q71), React Server Components (Q101+), or TanStack Query.
