# Q120: Resuming: Shipping Server UI State Without Shipping Component Code
* **Topic Tag**: #resume | ❱ CORE (Server)
* **Interview Question**: *What does resuming mean: shipping server state without shipping component code?*
* **Core Truth**: Resuming is an emerging rendering architecture that captures the exact execution state of components on the server and pauses them, allowing the client to resume execution and attach interactivity without re-rendering components from scratch or downloading unused component code.
* **The Friction**: A complex investigative piece at The National Times contains dozens of interactive data charts; under standard hydration, the client must download the entire component code and re-execute all chart rendering logic just to attach click handlers; on low-powered mobile devices, this causes severe main-thread freezing.
* **The Mechanism**: Resuming vs Hydration: Hydration requires the browser to download component code, execute the render function, diff the virtual DOM against the server HTML, and attach handlers; Resuming serializes event handlers and component state directly into the HTML, allowing the browser to execute handlers on demand without re-running component functions.
* **Under the Hood**: Serialized execution closures: the server emits HTML annotated with serialized state and event listener markers; when an event occurs, the runtime lazily loads only the specific handler code and resumes execution from the serialized closure state, bypassing the initial render pass entirely.
* **The Code Experiment**:
  * *Naive*: Forcing mobile devices to re-execute complex editorial rendering algorithms during hydration just to make an accordion toggle clickable.
  * *React*: Understanding the architectural shift from full hydration (re-rendering to attach listeners) to resumption (resuming execution from serialized state without full component re-execution).
* **Scope Boundary**: Focus on the theoretical and architectural distinction between hydration and resumption, what is resumed, and why it differs from traditional re-render hydration.
