# Q62: Windowing Large Lists with Virtualization
* **Topic Tag**: `#virtualization` | `❱❱ MORE`
* **Interview Question**: *How do you render a list of ten thousand items without rendering ten thousand rows?*
* **Core Truth**: Virtualization (windowing) renders only the small subset of list items currently visible within the browser's viewport, calculating dynamic offsets so thousands of items can be browsed with minimal DOM nodes and zero memory bloat.
* **The Friction**: The National Times historical archive contains 25,000 published articles. Rendering all 25,000 rows as physical DOM nodes freezes the browser for 4 seconds during mounting, consumes 400MB of RAM, and drops scrolling to 5 frames per second.
* **The Mechanism**: Virtualization windowing technique (via libraries like `tanstack-virtual` or `react-window`). Calculate the total scrollable height, render an outer container with a spacer, and mount only the ~20 visible DOM rows based on current `scrollTop`.
* **Under the Hood**: DOM node overhead vs JavaScript memory: modern browsers handle millions of JS objects easily, but creating 25,000 complex DOM nodes overwhelms the layout, paint, and accessibility tree calculation engines; virtualization caps the DOM node count to a constant number regardless of data size.
* **The Code Experiment**:
  * *Naive*: Rendering `articles.map(a => <ArticleRow key={a.id} />)` directly for 25,000 items, causing browser freezes and memory warnings.
  * *React*: A `VirtualArchiveList` rendering a 600px viewport that tracks scroll offset and renders only the 15 visible rows plus an overscan buffer.
* **Scope Boundary**: Focus on the concept and architecture of virtualization (windowing), viewport clipping, and DOM overhead trade-offs. Do not introduce full third-party library API specifics.
