# Q39: Reusing Logic with Custom Hooks
* **Topic Tag**: `#custom_hooks` | `❱ CORE`
* **Interview Question**: *How do you extract and reuse stateful logic between components?*
* **Core Truth**: Custom hooks are JavaScript functions whose names start with `use` that can call other React hooks, allowing developers to extract and share stateful logic across multiple components without sharing the underlying state itself.
* **The Friction**: Both an `ArticleHeader` and a `LiveComments` widget need to know if the user is online. Both components copy-paste twelve lines of `useState` (`isOnline`) and `useEffect` with `window.addEventListener('online')` and `('offline')`. When a bug fix is needed, one copy is updated while the other is forgotten.
* **The Mechanism**: Custom hooks. Extract the shared logic into `function useOnlineStatus() { const [isOnline, setIsOnline] = useState(navigator.onLine); useEffect(...); return isOnline; }`. Components simply call `const isOnline = useOnlineStatus()`.
* **Under the Hood**: Independent state instances: custom hooks share *stateful logic*, not *state*; each component calling `useOnlineStatus()` receives its own completely isolated `useState` and `useEffect` fiber nodes in the tree.
* **The Code Experiment**:
  * *Naive*: Duplicating window event listeners and state across multiple component files, or attempting to share state by passing hook references as props.
  * *React*: Extracting a `useOnlineStatus` hook and consuming it across both `StatusBar` and `SaveDraftButton`, verifying that each component has its own isolated status.
* **Scope Boundary**: Focus on creating custom hooks to share logic, naming conventions (`use...`), and understanding isolated state. Do not cover advanced hook patterns like `useSyncExternalStore` (Q54) or custom hook DevTools labeling (Q55).
