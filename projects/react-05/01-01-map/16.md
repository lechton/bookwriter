# Q16: Component Memory with useState
* **Topic Tag**: `#use_state` | `❱ CORE`
* **Interview Question**: *Why do ordinary variables forget their values between renders, and how does useState remember?*
* **Core Truth**: Ordinary local variables disappear when a function finishes executing, but `useState` provides persistent component memory that survives across renders and triggers React to re-render the component with updated values.
* **The Friction**: A developer implements an article bookmark toggle using `let isBookmarked = false` inside `ArticleCard`. On click, `isBookmarked = !isBookmarked` changes the variable, but the bookmark icon remains gray. Even if the component re-executes, local variables reset to their initial values on every call, and React has no way of knowing it needs to update the screen.
* **The Mechanism**: The `useState` hook (`const [state, setState] = useState(initialValue)`). Calling the setter updates React's internal state record for that component instance and schedules a re-render.
* **Under the Hood**: How React stores state outside the component function in an internal Fiber cell (linked list of hook nodes associated with the component's tree position), preserving the value between function executions and providing the current value on the next render pass.
* **The Code Experiment**:
  * *Naive*: Incrementing a local `let likes = 0` variable on button click; the UI never re-renders, and any future render resets `likes` back to `0`.
  * *React*: A `StoryCard` with `const [likes, setLikes] = useState(0)` where clicking the button calls `setLikes(likes + 1)`, causing React to re-render the card with the updated count.
* **Scope Boundary**: Focus strictly on the core purpose of `useState` (persistent memory + triggering re-render), array destructuring `[value, setValue]`, and contrasting with local variables. Do not cover updater functions (Q19) or asynchronous snapshot closures (Q18).
