Lecture 5: JavaScript Expressions in JSX with Curly Braces

Literal Text and Broken Image Paths

In standard HTML, text written between opening and closing tags is always treated as a static string. If you write <h2>authorName</h2> the browser displays the literal letters a-u-t-h-o-r-N-a-m-e. Similarly, if you write <img src="avatarUrl">, the browser attempts to fetch a file named literally avatarUrl from the web server. HTML has no concept of JavaScript memory or local variables.

When a developer declares variables inside a component and writes their identifiers directly into JSX, the markup remains static.

The JSX compiler follows a strict parsing boundary. When text is enclosed in quotes ("avatarUrl") or placed between tags (<h2>authorName</h2>), the compiler emits literal strings: _jsx("img", { src: "avatarUrl" }) To tell the compiler to step out of static markup and read JavaScript memory, you must open an evaluation window using curly braces: {}.

⚡ IN THE WILD

Why can you not place an if statement inside JSX? When developers want conditional rendering, they often try writing {if (isLead) { ... }} inside their JSX. This triggers a fatal compiler error. Why? Because curly braces accept JavaScript expressions, but reject JavaScript statements. An expression produces a value that can be passed as an argument to _jsx(). A variable, a mathematical calculation, or a ternary operation (isLead ? 'Lead' : 'Staff') all evaluate to a value. An if statement or a for loop produces no value. It is a control-flow statement. You cannot pass a statement as a function argument. To branch inside JSX, you must use expressions that return values.

Interview Tip

To impress the interviewer: When asked how curly braces work in JSX, explain that they create an inline evaluation window. This window allows you to step out of static markup into live JavaScript execution. Crucially, emphasize that curly braces accept any valid expression that produces a value, but reject statements like if or for which produce no value.

The Curly Brace Evaluation Window and Expressions

In JSX, curly braces {} act as an evaluation window. Placing curly braces inside text content (<h2>{authorName}</h2>) or inside an attribute (src={avatarUrl}) instructs the compiler to evaluate the enclosed JavaScript code at runtime. The evaluated value is then projected directly into the rendered output.

Inside the curly brace window, you can write any valid JavaScript expression:

  1. Variables: Evaluating local identifiers like {authorName}.
  2. Inline Arithmetic: Computing live numbers like {readMinutes * 60}.
  3. Template Literals: Assembling strings like {By ${authorName}}.
  4. Ternary Expressions: Evaluating conditional values like {isSenior ? 'Senior Editor' : 'Staff Writer'}

When assigning values to JSX attributes, you face an architectural crossroad between two syntax patterns:

  • Option 1 (The foundational way): Pass a static string literal using double quotes (src="/authors/elena.jpg").
  • Option 2 (The modern idiomatic way): Pass a dynamic JavaScript variable using curly braces (src={avatarUrl}).

First, look at Option 1 using a static string literal:

Next, look at Option 2 using the dynamic expression window:

Option 2: The Modern Idiomatic Way (src={...})
1export default function JournalistProfile() {
2 const avatarUrl = '/authors/clara.jpg';
3 return (
4 <img

7 />

9}

In Option 2, the curly braces replace the quotes entirely. Notice that you never write src="{avatarUrl}". Adding quotes around curly braces causes JSX to treat {avatarUrl} as a literal string of characters, breaking the link. The curly braces alone establish the evaluation window.

Key Takeaway

Use quotes "" for static string literals. Use curly braces {} for dynamic JavaScript expressions. Never wrap curly braces in quotes ("{variable}").

Curly braces bridge the gap between static markup and dynamic JavaScript execution.

Glossary

  • JSX Evaluation Window: The syntax construct {} that temporarily steps out of static JSX markup to evaluate a JavaScript expression.
  • JavaScript Expression: Any valid unit of JavaScript code that resolves to a single value, such as a variable, calculation, or function call.
  • JavaScript Statement: A unit of code that performs an action but produces no return value (if, for, while), forbidden inside JSX curlies.
  • Dynamic Attribute: An HTML attribute whose value is computed at runtime via curly braces (src={avatarPath}) rather than hardcoded in quotes.
  • Ternary Expression: An inline conditional expression (condition ? expr1 : expr2) that evaluates to one of two values, permitted inside JSX curlies.

Beyond the basics

  • JSX curly braces compiler output: The expression {readMinutes * 60} compiles directly to the function argument _jsx("p", { children: [readMinutes * 60, " seconds read"] }) (see react.dev/learn/javascript-in-jsx-with-curly-braces).
  • Expressions vs statements in language specifications: In the ECMAScript specification, expressions evaluate to a value, while statements control execution flow; JSX child positions only accept expressions because function calls require argument values (see react.dev/learn/javascript-in-jsx-with-curly-braces).
  • Objects as JSX children: React cannot render raw JavaScript objects directly inside text curlies ({userObject}); attempting to do so throws a runtime error, requiring you to access primitive properties like {userObject.name} (see react.dev/learn/javascript-in-jsx-with-curly-braces).
  • Double curlies for inline style objects: When applying inline styles in JSX, you write style={{ color: 'red' }}; the outer braces open the evaluation window, and the inner braces declare a JavaScript object literal (see react.dev/learn/javascript-in-jsx-with-curly-braces).
  • Boolean and nullish rendering: React treats true, false, null, and undefined as empty values inside curly braces, rendering nothing to the DOM, which enables conditional rendering shortcuts like {isPublished && <Badge />} (see react.dev/learn/conditional-rendering).

Summary

Architectural Takeaways & Decision Matrix

❒ Evaluation Windows & Text

➔ ALWAYS wrap JavaScript variables in curly braces ({authorName}) when rendering dynamic text inside JSX elements.

➔ NEVER write variable names as raw text (<h2>authorName</h2>) because JSX treats unbracketed text as literal strings.

➔ IF rendering a conditional value inside JSX THEN use a ternary expression ({flag ? 'A' : 'B'}) instead of an if statement.

❒ Dynamic Attributes

➔ ALWAYS use curly braces without quotes (src={avatarUrl}) when binding dynamic variables to element attributes.

➔ NEVER wrap curly braces in quotes (src="{avatarUrl}") because this passes the literal string "{avatarUrl}" to the DOM.
