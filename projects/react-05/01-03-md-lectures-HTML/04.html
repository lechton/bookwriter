Lecture 4: JSX Syntax Rules and Fragments

Interview Question

CORE

What is JSX, what syntax rules must every snippet follow, and how do Fragments group elements without wrapper nodes?

Imagine this scenario:

  1. An editor on The National Times copies formatted news alert text into a new story component.
  2. The news alert text contains an unclosed image tag, an adjacent headline, and summary text.
  3. The developer pastes the markup directly into the component return statement.
  4. Why does the local build crash instantly with fatal syntax errors across multiple lines?
  5. The development server halts, blocking the newsroom team from previewing breaking news alerts.
  6. The compiler treated the pasted HTML as strict JavaScript rather than permissive markup.
  7. Today, you will master JSX syntax rules and use Fragments to group elements with zero DOM overhead.

Pasted HTML and Compiler Crashes

In plain HTML, web browsers are remarkably forgiving. Browsers allow unclosed void tags like <img> or <input>. Browsers also permit multiple adjacent elements at the top level of a document. If you paste raw HTML markup into a standard .html file, the browser parses the text and paints the page.

When a developer pastes raw HTML into a React component function, the build tool halts immediately.

Look at the naive HTML paste attempt below:

Naive HTML Paste
1export default function NewsAlert() {
2 return (
3 <img src="/breaking.jpg">

4 <h2>Alert Update</h2>

5 <p class="alert-text">Live news feed.</p>
6 );
7}

When this snippet runs through the compiler, the build tool crashes immediately. Notice the syntax errors: an unclosed <img> tag and adjacent sibling elements without an enclosing parent.

The compiler crashes because a JavaScript function cannot return multiple values. Writing return a, b evaluates both expressions but returns only the second value. Furthermore, JSX compiles into _jsx() function calls. Every _jsx() call represents a single element descriptor. You cannot pass two separate expressions to a single return statement without a wrapping structure.

⚡ IN THE WILD

Why does a wrapper div break your CSS Flexbox layout? When developers hit the single-root error, their instinctive reflex is wrapping everything in a <div>. While this satisfies the compiler, it often destroys layout styling. In CSS Flexbox and Grid, layout properties apply exclusively to direct child elements. If a parent container declares display: flex; gap: 16px;, its direct children become flex items. Placing an extra <div> wrapper around your siblings turns those elements into grandchildren. The flex container now sees only one child: the wrapper div. Your flex row layout collapses into a single vertical block, and gap spacing between items vanishes. React Fragments solve this by satisfying the compiler without creating a physical DOM wrapper.

Interview Tip

To impress the interviewer: When asked to explain JSX, do not call it "HTML inside JavaScript." State that JSX is a strict syntax extension that compiles into regular JavaScript function calls (_jsx()). Because functions can only return a single value, every JSX snippet requires a single root element.

The Invariants of JSX and React Fragments

JSX stands for JavaScript XML. It is a syntax extension that lets you write HTML-like markup inside JavaScript files. Because JSX compiles directly into JavaScript, it enforces three strict syntactic invariants:

  1. Single Root Invariant: Every component return must have exactly one root element.
  2. Explicit Closing Invariant: Every tag must be closed explicitly, including void elements (<img />, <input />).
  3. CamelCase Property Invariant: Attribute names use camelCase (className, htmlFor) to prevent collisions with JavaScript reserved keywords.

To satisfy the single root invariant without polluting the DOM, you face an architectural crossroad between two approaches:

  • Option 1 (The foundational way): Wrap adjacent siblings in an explicit DOM container element (<div className="alert-group">).
  • Option 2 (The modern idiomatic way): Wrap adjacent siblings in a lightweight React Fragment (<>...</>).

First, look at Option 1 using an explicit wrapper element:

Option 1: The Foundational Way (<div className>)
1export default function NewsAlert() {
2 return (
3 <div className="alert-group">

In Option 1, the code compiles successfully because the <div> serves as a single root. However, the browser creates a physical <div> element in the DOM. In complex layouts, nesting dozens of unnecessary wrapper divs bloats DOM memory and breaks CSS Flexbox and Grid alignments.

Next, look at Option 2 using a React Fragment:

Option 2: The Modern Idiomatic Way (<>...</>)

In Option 2, the empty tags <>...</> represent a React Fragment. The compiler transforms this into _jsx(Fragment, { children: [...] }) React evaluates the children but inserts zero wrapper nodes into the browser DOM. The <h2> and <p> elements mount as direct children of the parent container, preserving CSS layouts perfectly.

Key Takeaway

Always use React Fragments (<>...</>) to group adjacent sibling elements when you do not need an extra physical DOM wrapper for styling or semantics.

Component Summary

App

The parent component manages the top-level news alert flexbox layout. It mounts <NewsAlert /> as an immediate child of the flex container. Notice it expects its children to align in a direct horizontal row. Why? To maintain strict flex gap and item alignment across the newsroom header.

NewsAlert

The child component groups multiple sibling elements using a React Fragment. It provides the thumbnail image, headline, and timestamp. Notice it renders zero wrapper <div> nodes into the physical DOM. When does it mount? React unwraps the Fragment in memory, committing all three siblings directly into the parent flex container.

In our experiment, we saw how pasting raw HTML halted the compiler. JSX is strict JavaScript syntax that requires a single root element, explicit tag closing, and camelCase attributes. By wrapping siblings in a Fragment <>...</>, we satisfied the compiler's single-expression invariant while preserving our CSS Flexbox layout with zero DOM overhead.

Where you will meet this

  1. CSS Grid & Flexbox Layouts: Returning multiple grid or flex items from a child component without breaking layout alignment with extra wrapper divs.
  2. HTML Table Rows & Cells: Returning multiple <td> table data cells from a component without inserting invalid <div> tags inside a <tr>.
  3. Semantic Definition Lists: Grouping adjacent <dt> and <dd> elements in a dictionary component while maintaining valid HTML markup.
  4. SEO & Accessibility Trees: Keeping the browser DOM tree shallow and semantic, eliminating unnecessary <div> clutter for screen readers.

Glossary

  • JSX: A syntax extension for JavaScript that allows developers to write XML-like markup that compiles into standard _jsx() function calls.
  • React Fragment: A built-in React component (<>...</>) that groups a list of children without adding extra nodes to the physical browser DOM.
  • Single Root Invariant: The compiler requirement that every component return statement must resolve to a single JavaScript expression.
  • Self-Closing Tag: A tag that closes itself with a trailing slash (<img />), mandatory in JSX for void HTML elements that have no children.
  • className Property: The JSX attribute used to assign CSS classes, replacing the reserved JavaScript keyword class.

Beyond the basics

  • JSX compilation under the hood: The JSX transform turns <><h1>Hello</h1></> into _jsx(Fragment, { children: _jsx("h1", { children: "Hello" }) }) using the React Fragment symbol (see react.dev/learn/writing-markup-with-jsx).
  • Fragments with keys in mapped collections: While the shorthand <>...</> syntax does not accept attributes, the explicit <React.Fragment key={id}> syntax allows passing keys when rendering lists of fragments (see react.dev/learn/rendering-lists).
  • DOM property mapping: JSX attributes closely match browser DOM properties rather than HTML attribute strings; for example, class becomes className and for becomes htmlFor (see react.dev/learn/writing-markup-with-jsx).
  • Single-expression returns in JavaScript: A JavaScript return statement can only evaluate and return one value; wrapping multiple expressions in parentheses and a Fragment creates a single compound expression (see react.dev/learn/writing-markup-with-jsx).
  • Void elements and strict XML rules: In HTML5, void elements like <input>, <img>, and
    can omit closing slashes, but JSX strictly follows XML rules where all tags must be explicitly closed (see react.dev/learn/writing-markup-with-jsx).
