## Context & Defect Analysis
In Lecture 03, Step 2 (`ArticleHeader.jsx`), the lead-in sentence stated:
> "In modern React, we choose the unpacked pattern using JavaScript parameter destructuring:"

However, the code block immediately following had zero comment on line 1 (`export default function ArticleHeader({ headline })`), placing comment bubbles only on child JSX elements (`<span>` and `<h2>`).

This revealed a critical breakdown in reader alignment:
1. **The Saliency Gap**: The prose explicitly primed the reader to inspect parameter destructuring, but when the reader's eye looked at the right-hand margin of the code window, the speech bubbles pointed elsewhere. The line containing the discussed mechanism was left completely bare.
2. **Missing Universal Law**: While density rules checked for percentages of comments, no rule mandated that code comments must follow the content of the text and track the reader's attention.

## The Solution: Universal Comment-Prose Synchronization
1. **Comments Follow the Text & Reader Mind**: Code comments must track the mind of the reader. What the surrounding prose underlines, discusses, or explains, the code comments must also underline on that exact line of code, using the same vocabulary.
2. **Symmetric Highlighting in Comparative Snippets**: When comparing two code snippets (such as Option A vs Option B), the comments in both snippets must explicitly highlight the diverging parts where the two options differ, using symmetric vocabulary so the reader instantly sees the contrast.
3. **De-Prescription Note**: This rule sets a universal standard of reader-mind alignment rather than an authoritarian micro-prescription on specific syntactic constructs.
