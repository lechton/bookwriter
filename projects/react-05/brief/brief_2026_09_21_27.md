# Brief 2026-09-21 27: The Two-Tier Convention Protocol (Prune First, Decode Second)

## Group 1: Two-Tier Convention Protocol and Convention Callout Standard (#2026_09_21_27_group_1)

### Philosophy and Defect Origin
During the authoring of Lesson 01, the author routinely utilized specialized domain metaphors, editorial vocabulary, and UI visual nicknames (such as "masthead", "byline", "ticker", and "slug") across both the lecture markdown and the embedded HTML figures (e.g. *Top-Down Masthead Assembly*, *Declares masthead container*).

This revealed a critical instructional blind spot:
1. **Focus on React APIs Only**: `skills/lecture-voice/SKILL.md` and `skills/lecture-revision/SKILL.md` carefully audit React framework terminology (`props`, `state`, `reconciliation`), but lack an audit checkpoint for everyday industry UI naming conventions.
2. **The Senior Assumption**: Senior engineers assume terms like "masthead" are self-evident everyday words. But to a junior developer, encountering "masthead" triggers confusion: is it an HTML tag, a React API, or arbitrary jargon?
3. **The Anti-De-Prescription Trap**: Attempting to solve every jargon instance by adding an explanatory callout box creates unnecessary reading tax when the word can simply be replaced with plain English (e.g. "site header").
4. **The Code-Figure Desynchronization Risk**: If an author replaces "masthead" in prose with "site header" but fails to update the embedded HTML figures, the student experiences immediate confusion when the diagram labels contradict the text.

### The Standardized Fix
Under `#2026_09_21_27_group_1`, we establish the **Two-Tier Convention Protocol** in `skills/lecture-voice/SKILL.md` (Section 25) and `skills/lecture-revision/SKILL.md` (Section 10), and teach `src/build-lectures.mjs` to render the `> [!CONVENTION]` callout:

1. **Tier 1 (First Priority: Prune & Replace Everywhere)**:
   - Audit all domain slang, newsroom metaphors, and visual nicknames across prose, code, and figure cards.
   - If a self-evident everyday English term exists (e.g. replacing "masthead" with "site header", "ticker" with "live news bar", "lede" with "article summary"), replace it across both the lecture text AND inside the embedded HTML figure containers.
   - Do not force the junior reader to decode unnecessary print-media metaphors when simple English does the job.

2. **Tier 2 (Fallback: Inescapable Industry Standards via `> [!CONVENTION]`)**:
   - When a convention represents an inescapable, universal frontend standard that developers must recognize in technical interviews, job requirements, and UI component libraries (such as "slug", "accordion", "toast", "drawer", "breadcrumbs", or "hero section"), retain the term.
   - Decode the term immediately using an explicit `> [!CONVENTION]` callout structured across three concrete facts:
     (a) **Physical Origin**: Where the metaphor comes from in the physical world.
     (b) **Web Engineering Reality**: What physical UI widget, component, or data format it represents on screen.
     (c) **Operational Justification**: Why production teams standardize on this term instead of generic labels.

3. **Compiler Integration**:
   - `src/build-lectures.mjs` natively recognizes `> [!CONVENTION]` and renders it with the authoritative eyebrow `UI & Domain Convention` and distinctive chrome.
