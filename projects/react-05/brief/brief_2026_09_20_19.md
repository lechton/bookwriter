# Brief 2026-09-20-19: The Holistic Editorial Standard on Idiosyncratic Explanations

## 1. Context & Autopsy of the Defect

During review of Lecture 4 (`02-01-md-revised/04.md`), a specific illustrative failure scenario (*"Imagine if the parent page used CSS Grid or Flexbox: an extra `<div>` would break your layout..."*) was repeated almost verbatim across Step 1, Step 4, and the surrounding callouts.

The user flagged this repetition: *"now you repeat this in 4 again and again, the same thing?"*

An autopsy identified the underlying defect:
1. **Confusing Core Concepts with Idiosyncratic Explanations**: The writer confused the pedagogical necessity of reinforcing a foundational concept (e.g. Fragments producing zero DOM nodes) with repeating the *exact same illustrative vehicle* (the CSS Grid / Flexbox failure scenario).
2. **Step 1 vs. Step 4 Echo**: Because `ArticlePreview.jsx` appeared in both Step 1 and Step 4, the writer applied the Socratic failure arc twice to the same file, treating the reader as if they had forgotten what was explained two pages earlier.
3. **Cognitive Fatigue**: Repeating a specific illustrative vignette across multiple steps in the same lecture flattens the prose and creates an echo chamber.

The user articulated the overarching editorial principle:
> *"Imagine you are a professional editor editing the book in a holistic way. Do not repeat idiosyncratic explanation across steps. Although it can be useful (in fact necessary) to repeat some key ideas in more than one place in more than one texts, this is to be done when it is pedagogically necessary, it is not useful to repeat the same idiosyncratic explanation that you have already made somewhere in the text. Make sure each part of the text offers a unique angle and does not appear repetitive."*
