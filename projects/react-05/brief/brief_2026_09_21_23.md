## 1. Context & Motivation
In revised Lecture 02 of React 05, terminal commands authored in ` ```bash ` blocks used standard shell comment syntax (`# comment`). In the resulting PDF, the comments failed to extract into the right-hand `.cmt-bubble` panel and instead wrapped awkwardly as literal monospace code text.

Investigating the compiler revealed that `highlightLine(raw)` in `src/build-lectures.mjs` was hardcoded exclusively for C-style (`//`) and HTML (`<!--`) comments, completely ignoring `#` comments. Meanwhile, `skills/code-blocks/SKILL.md` artificially mandated "standard `//` comments only", forcing authors to write un-idiomatic `//` comments inside bash blocks.

Per the Golden Rule of De-Prescription, rather than teaching birds how to fly by enforcing unnatural `//` comments in bash, the solution is to de-prescribe the artificial rule and harden the build compiler to natively support standard comment delimiters across languages.

## 2. Changes Applied
1. **Build Compiler Hardening (`src/build-lectures.mjs`)**:
   - Updated `highlightLine(raw)` full-line regex to `mFull = raw.match(/^(?:\/\/|<!--|#)(\s|$)/)`.
   - Updated inline comment search to `idx = raw.search(/(?:\/\/|<!--|#)(\s|$)/)`.
   - Updated `matchToken` extraction to dynamically handle `#`, `//`, and `<!--`.
   - Now natively parses `#` comments (followed by space or EOL) in shell/terminal blocks into right-hand `.cmt-bubble` speech bubbles.
2. **Skill De-Prescription (`skills/code-blocks/SKILL.md`)**:
   - Section 04: Pruned the artificial "standard `//` comments only" prescription, permitting natural comments (`//` for JS/JSX, `#` for Bash/Shell, `<!--` for HTML).
   - Section 08: Documented that the build compiler automatically extracts inline comments across `//`, `#`, and `<!--` delimiters into floating speech bubbles.
3. **Revision Skill Alignment (`skills/lecture-revision/SKILL.md`)**:
   - Section 06: Noted that tag-free comments use natural `//` in JavaScript and `#` in Bash.
