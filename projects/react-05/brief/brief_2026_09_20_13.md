# Brief 2026-09-20-13: Explicit Architectural Relations

## 1. Context & Autopsy of the Defect

During review of Lecture 07 (`01-02-md-LECTURES/07.md`), the user flagged a critical pedagogical disconnect in Step 1 (`NewsPortal.jsx`):
```jsx
import SiteHeader from './SiteHeader.jsx';
import { ArticleList } from './ArticleComponents.jsx';
```
The step prose explained this import with cryptic shorthand:
> *Notice line 2: `import { ArticleList } from './ArticleComponents.jsx'`. Here we use curly braces because `ArticleList` is a named export from a shared module.*

The user noted:
* The code invokes `<ArticleList />`, but the UI Canvas panel displays `ArticleComponents`.
* The prose completely misses that `ArticleComponents.jsx` encodes **two** components, not one (`ArticleList` and `ArticleCard`).
* The shorthand merely names a grammatical category ("named export from a shared module") while leaving the living architectural relations cryptic.

The root problem is general: whenever code establishes a relation between two entities (file to component, parent to child, prop to state, or UI canvas node to JSX element), that relation becomes confusing the moment the author treats the connection as self-evident or uses shorthand that names a technical category without unpacking the physical connections.

## 2. Technical Decisions & Rules Added

1. **The Law of Explicit Architectural Relations (skills/lecture-voice/SKILL.md, Principle 31)**:
   - Added Principle 31: "Make relations between entities explicit rather than cryptic whenever code connects two files, components, or props: state the exact count and names of all components involved, explain why the syntax differs (such as named exports requiring curly braces), and clarify why one part is imported while another remains internal, avoiding shorthand that merely names a technical category."
   - Accompanied by a COUNTER-EXAMPLE showing the cryptic shorthand from Lecture 7 and a PROPER EXAMPLE showing the explicit disambiguation.
2. **Lecture Structure Integration (skills/lecture-structure/SKILL.md, Section 19)**:
   - Added explicit relation requirement to Stage C sequential steps, ensuring that whenever a step imports or mounts a component with an asymmetry, the author unpacks the count, names, syntax rationale, and role division.
3. **Pre-Lecture Blueprinting (skills/pre-lecture/SKILL.md, Stage C)**:
   - Required pre-lecture step `[p]` bullets to plan explicit architectural relations (module inventory, syntax rationale, and role division) whenever a step imports or mounts a component with an asymmetry.
4. **Verification Gate (skills/verification/SKILL.md, Gate 17)**:
   - Added Gate 17 verifying that any code step connecting files, components, or props makes the relationship explicit and inventories all components in asymmetrical modules.

## 3. Lecture 07 Alignment

The trigger passage in `01-02-md-LECTURES/07.md` and its blueprint in `01-01-md-PRE-lectures/07.md` are updated to follow the new standard:
