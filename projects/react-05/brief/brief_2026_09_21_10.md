# Brief 2026_09_21_10: Component File Names in Step Headings and Ban on "Presenter" Jargon

- **Date**: 2026-09-21
- **Tag**: `#2026_09_21_10_group_1`
- **Affected Skills**: `skills/lecture-structure/SKILL.md`, `skills/pre-lecture/SKILL.md`, `skills/lecture-voice/SKILL.md`, `skills/verification/SKILL.md`, `skills/RULE-TAGS.md`

## Context & Defect Analysis
In Lecture 03, the author authored step headings such as `### Step 2: Next, we build the article header presenter` and `### Step 3: Then, we declare the author byline presenter`.

This introduced two major defects:
1. **Omission of Target File Names**: The step headings omitted the exact component file name (`ArticleHeader.jsx`, `ArticleAuthor.jsx`), breaking the navigational standard established across earlier lectures where every step heading explicitly identifies the file being constructed.
2. **Invention of Fake Jargon ("Presenter")**: The author used obsolete and non-standard "presenter" jargon ("article header presenter", "author byline presenter", "pure presenter"). In standard React, components that render UI are simply **components** (parent component, child component, header component, author component).

## The Solution: Explicit Step Titles and Jargon Ban
1. **Explicit Step Title Pattern**: Every Stage C step heading must end with the exact file name being built or inspected:
   - `### Step 1: First, we construct the parent container <ParentComponent.jsx>`
   - `### Step 2: Next, we build the child component <ChildComponent.jsx>`
   - `### Step 3: Then, we declare the child component <ChildComponent.jsx>`
   - `### Step 4: Finally, we mount the feature inside <App.jsx>`
2. **Strict Ban on "Presenter" Jargon**: In React, UI building blocks are components. Never refer to components as "presenters", "header presenters", or "pure presenters".
