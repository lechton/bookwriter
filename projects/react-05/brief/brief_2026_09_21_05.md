# Brief 2026-09-21 05: Instruction Root-Cause Diff Presentation Standard (The "iii" Protocol)

## Group 1: Instruction Root-Cause Diff Presentation Standard (#2026_09_21_05_group_1)

### Philosophy and Defect Origin
When the user issues the `"iii"` directive (Instruction Root-Cause & Pruning Trigger), they require granular visibility and immediate reviewability of every proposed change to the instructions and skills before any files are touched.

In the past, an agent responding to `"iii"` might offer high-level narrative summaries of what it intended to change, or discuss philosophical concepts without displaying the exact line-level text modifications. This forced the user to guess what text would be pruned or added, or to repeatedly ask for clarification.

### The Standardized "iii" Response Format
Under `#2026_09_21_05_group_1`, the `"iii"` control directive is codified to require:
1. **Root-Cause Analysis**: Explicitly identify which existing rule, constraint, or phrasing enabled, encouraged, or created the observed defect or excessive pressure.
2. **Section-by-Section Breakdown**: Group proposed changes clearly by file, section, and principle number.
3. **Line-Level Diffs**: For each affected file and section, display the exact text being pruned/removed (Target Content) and the exact text being added or substituted (Replacement Content).
4. **Registry Entry**: Provide the full row to be added to `skills/RULE-TAGS.md`.

This ensures that the user can inspect the exact pruning, additions, and removals directly and make an informed decision before granting execution approval via `"ppp"` or `"ppi"`.
