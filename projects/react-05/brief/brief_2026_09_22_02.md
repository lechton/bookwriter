# Decision Brief: Web-Inspector UI Element Standard and Semantic Typography in Rendered UI Canvas (#2026_09_22_02_group_1)

**Date**: 2026-09-22
**Rule Tag**: `#2026_09_22_02_group_1`
**Components Affected**: `skills/ui-panels/SKILL.md` (Sections 01 & 02), `skills/RULE-TAGS.md`

---

## 1. Problem Statement & Root Cause

Previously, Field 4 in `skills/ui-panels/SKILL.md` (Section 02) was narrowly defined as:
```markdown
[ ] Field 4 (Rendered Controls): Render native UI controls using [button: ...], [input: ...], or [badge: ...]. Separate multiple controls on the same component using ;;.
```
This minimal instruction, paired with a generic flat example in Section 01, resulted in authors dumping flat badge pills (e.g. `[badge: Morning Edition Live]`) and unadorned controls with no structural distinction between DOM nodes, no semantic tag descriptors, and no authentic typography.

---

## 2. Changes Applied

### A. `skills/ui-panels/SKILL.md`
- **Section 01**: Updated the canonical `PROPER EXAMPLE` to demonstrate the Web-Inspector Element Standard using `[elem:tag:content]` wrappers, nested controls, and semantic tag descriptors.
- **Section 02**:
  - Replaced the primitive control instruction with the **Web-Inspector Standard** (`[elem:tag:content]` or `[elem:tag]`).
  - Added the **Semantic Typography Contract**: Headings (`h1`, `h2`, `h3`) and pull quotes (`blockquote`) automatically render with authentic editorial serif typography (`Times New Roman` / Georgia) to reflect real browser rendering, while body elements render in sans-serif.
  - Added the **Inspector Badge Clearance** rule: Built-in top clearance (`margin-top: 1.15rem`) separating the mono tag badge from component titles above.

### B. `skills/RULE-TAGS.md`
- Registered `#2026_09_22_02_group_1` with full metadata and intent.
