### Pasted HTML and Compiler Crashes

In plain HTML, web browsers are remarkably forgiving. Browsers allow unclosed void tags like `<img>` or `<input>`. Browsers also permit multiple adjacent elements at the top level of a document. If you paste raw HTML markup into a standard `.html` file, the browser parses the text and paints the page.

When a developer pastes raw HTML into a React component function, the build tool halts immediately.

Look at the naive HTML paste attempt below:

```jsx title="Naive HTML Paste"
export default function NewsAlert() {
  return (
    <img src="/breaking.jpg"> // **WRONG:** unclosed void tag halts **COMPILER**
    <h2>Alert Update</h2>     // **WRONG:** adjacent sibling violates single **ROOT**
    <p class="alert-text">Live news feed.</p>
  );
}
```

When this snippet runs through the compiler, the build tool crashes immediately. Notice the syntax errors: an unclosed `<img>` tag and adjacent sibling elements without an enclosing parent.

The compiler crashes because a JavaScript function cannot return multiple values. Writing `return a, b` evaluates both expressions but returns only the second value. Furthermore, JSX compiles into `_jsx()` function calls. Every `_jsx()` call represents a single element descriptor. You cannot pass two separate expressions to a single `return` statement without a wrapping structure.


> [!WILD]
> **Why does a wrapper div break your CSS Flexbox layout?** When developers hit the single-root error, their instinctive reflex is wrapping everything in a `<div>`. While this satisfies the compiler, it often destroys layout styling. In CSS Flexbox and Grid, layout properties apply exclusively to direct child elements. If a parent container declares `display: flex; gap: 16px;`, its direct children become flex items. Placing an extra `<div>` wrapper around your siblings turns those elements into grandchildren. The flex container now sees only one child: the wrapper div. Your flex row layout collapses into a single vertical block, and gap spacing between items vanishes. React Fragments solve this by satisfying the compiler without creating a physical DOM wrapper.

> [!TIP]
> **To impress the interviewer:** When asked to explain JSX, do not call it "HTML inside JavaScript." State that JSX is a strict syntax extension that compiles into regular JavaScript function calls (`_jsx()`). Because functions can only return a single value, every JSX snippet requires a single root element.

### The Invariants of JSX and React Fragments

**JSX** stands for JavaScript XML. It is a syntax extension that lets you write HTML-like markup inside JavaScript files. Because JSX compiles directly into JavaScript, it enforces three strict syntactic invariants:

1. **Single Root Invariant**: Every component return must have exactly one root element.
2. **Explicit Closing Invariant**: Every tag must be closed explicitly, including void elements (`<img />`, `<input />`).
3. **CamelCase Property Invariant**: Attribute names use camelCase (`className`, `htmlFor`) to prevent collisions with JavaScript reserved keywords.

To satisfy the single root invariant without polluting the DOM, you face an architectural crossroad between two approaches:

- **Option 1 (The foundational way)**: Wrap adjacent siblings in an explicit DOM container element (`<div className="alert-group">`).
- **Option 2 (The modern idiomatic way)**: Wrap adjacent siblings in a lightweight React Fragment (`<>...</>`).

First, look at Option 1 using an explicit wrapper element:

```jsx title="Option 1: The Foundational Way (<div className>)"
export default function NewsAlert() {
  return (
    <div className="alert-group"> // Inserts physical wrapper **NODE**
      <h2>Alert Update</h2>       // Child element inside **DIV**
      <p>Live news feed.</p>      // Sibling element inside **DIV**
    </div>
  );
}
```

In Option 1, the code compiles successfully because the `<div>` serves as a single root. However, the browser creates a physical `<div>` element in the DOM. In complex layouts, nesting dozens of unnecessary wrapper divs bloats DOM memory and breaks CSS Flexbox and Grid alignments.

Next, look at Option 2 using a React Fragment:

```jsx title="Option 2: The Modern Idiomatic Way (<>...</>)"
export default function NewsAlert() {
  return (
    <>                      // Groups siblings with **ZERO DOM**
      <h2>Alert Update</h2> // Direct child of **PARENT**
      <p>Live news feed.</p>
    </>
  );
}
```

In Option 2, the empty tags `<>...</>` represent a **React Fragment**. The compiler transforms this into `_jsx(Fragment, { children: [...] })`. React evaluates the children but inserts zero wrapper nodes into the browser DOM. The `<h2>` and `<p>` elements mount as direct children of the parent container, preserving CSS layouts perfectly.

> [!KEY]
> Always use React Fragments (`<>...</>`) to group adjacent sibling elements when you do not need an extra physical DOM wrapper for styling or semantics.

To master JSX syntax and Fragments, we will build a breaking news alert for The National Times. We will construct the feature across four sequential steps: building the parent flex container in `App.jsx`, opening the Fragment and self-closing image in `NewsAlert.jsx`, completing the sibling elements and Fragment closing, and mounting the root in `src/main.jsx`.

### Step 1: First, we construct the parent flex container <App.jsx>

We begin by constructing the parent layout container in `src/App.jsx`. This component uses CSS Flexbox to position items side by side in a row with a defined gap. Notice that `App.jsx` mounts `<NewsAlert />` as an immediate child of the flex container:

```jsx title="App.jsx"
import NewsAlert from './components/NewsAlert.jsx';

export default function App() {
  return (
    <div className="alert-feed-flex">
      <NewsAlert /> // Mounts alert items directly in **FLEX ROW**
    </div>
  );
}
```

Notice what is critical here: `alert-feed-flex` expects its immediate children to participate in the flex row layout. If `NewsAlert` renders an extra wrapper `<div>`, the flex items become trapped inside that wrapper, destroying the horizontal row layout.

### Step 2: Next, we declare the Fragment root and void tag <NewsAlert.jsx>

Now we create the component file `src/components/NewsAlert.jsx`. We begin by declaring the function and opening a React Fragment `<>`. Inside the Fragment, we place our first element: a self-closing `<img />` tag with explicit `className`:

```jsx title="NewsAlert.jsx" startLine="1" continues="bottom"
export default function NewsAlert() {
  return (
    <>                                                                     // Opens lightweight **FRAGMENT**
      <img className="story-photo" src="/breaking.jpg" alt="Story photo" /> // Self-closing void **TAG**
```

Notice the trailing slash on `<img ... />`. In HTML, void elements like `<img>` or `<input>` can omit closing tags. In JSX, all tags must be explicitly closed. Omitting the slash causes an immediate syntax error.

### Step 3: Then, we complete the sibling elements <NewsAlert.jsx>

Next, we add the remaining sibling elements: a headline and a timestamp paragraph. We then close the Fragment with `</>` and close the return statement:

```jsx title="NewsAlert.jsx" startLine="5" continues="top"
      <h2 className="alert-headline">Breaking Alert</h2>         // Sibling headline **ELEMENT**
      <p className="alert-time">Updated 1 minute ago.</p>        // Sibling timestamp **TEXT**
    </>                                                        // Closes React **FRAGMENT**
  );
}
```

Notice that `<h2>` and `<p>` are direct siblings of `<img>`. Because they are enclosed in `<>...</>`, React bundles them into a single return value without adding a `<div>`. All three elements mount as direct children of `alert-feed-flex`.

### Step 4: Finally, we mount the application at the root <src/main.jsx>

Finally, we connect our application to the physical browser DOM in `src/main.jsx`. This file acts as the mounting bridge. It locates `<div id="root">` and calls `createRoot()`. React then renders `<App />`, executing `NewsAlert()` and committing the elements directly into the flex container:

```jsx title="src/main.jsx"
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = createRoot(document.getElementById('root')); // Locates host **DOM**
root.render(
  <StrictMode>
    <App /> // Mounts application tree into **ROOT**
  </StrictMode>
);
```

When React renders this tree, it evaluates `<App />`, encounters `<NewsAlert />`, and unpacks its Fragment. The image, headline, and paragraph render directly inside the parent `<div>`. No wrapper node is created.

In our experiment, we saw how pasting raw HTML halted the compiler. JSX is strict JavaScript syntax that requires a single root element, explicit tag closing, and camelCase attributes. By wrapping siblings in a Fragment `<>...</>`, we satisfied the compiler's single-expression invariant while preserving our CSS Flexbox layout with zero DOM overhead.

### Where you will meet this

1. **CSS Grid & Flexbox Layouts**: Returning multiple grid or flex items from a child component without breaking layout alignment with extra wrapper divs.
2. **HTML Table Rows & Cells**: Returning multiple `<td>` table data cells from a component without inserting invalid `<div>` tags inside a `<tr>`.
3. **Semantic Definition Lists**: Grouping adjacent `<dt>` and `<dd>` elements in a dictionary component while maintaining valid HTML markup.
4. **SEO & Accessibility Trees**: Keeping the browser DOM tree shallow and semantic, eliminating unnecessary `<div>` clutter for screen readers.

### Glossary

- **JSX**: A syntax extension for JavaScript that allows developers to write XML-like markup that compiles into standard `_jsx()` function calls.
- **React Fragment**: A built-in React component (`<>...</>`) that groups a list of children without adding extra nodes to the physical browser DOM.
- **Single Root Invariant**: The compiler requirement that every component return statement must resolve to a single JavaScript expression.
- **Self-Closing Tag**: A tag that closes itself with a trailing slash (`<img />`), mandatory in JSX for void HTML elements that have no children.
- **className Property**: The JSX attribute used to assign CSS classes, replacing the reserved JavaScript keyword `class`.

## Beyond the basics

- **JSX compilation under the hood**: The JSX transform turns `<><h1>Hello</h1></>` into `_jsx(Fragment, { children: _jsx("h1", { children: "Hello" }) })` using the React Fragment symbol (see [react.dev/learn/writing-markup-with-jsx](https://react.dev/learn/writing-markup-with-jsx)).
- **Fragments with keys in mapped collections**: While the shorthand `<>...</>` syntax does not accept attributes, the explicit `<React.Fragment key={id}>` syntax allows passing keys when rendering lists of fragments (see [react.dev/learn/rendering-lists](https://react.dev/learn/rendering-lists)).
- **DOM property mapping**: JSX attributes closely match browser DOM properties rather than HTML attribute strings; for example, `class` becomes `className` and `for` becomes `htmlFor` (see [react.dev/learn/writing-markup-with-jsx](https://react.dev/learn/writing-markup-with-jsx)).
- **Single-expression returns in JavaScript**: A JavaScript `return` statement can only evaluate and return one value; wrapping multiple expressions in parentheses and a Fragment creates a single compound expression (see [react.dev/learn/writing-markup-with-jsx](https://react.dev/learn/writing-markup-with-jsx)).
- **Void elements and strict XML rules**: In HTML5, void elements like `<input>`, `<img>`, and `<br>` can omit closing slashes, but JSX strictly follows XML rules where all tags must be explicitly closed (see [react.dev/learn/writing-markup-with-jsx](https://react.dev/learn/writing-markup-with-jsx)).

### Summary

**Architectural Takeaways & Decision Matrix**

❒ Single Root & Fragments

➔ ALWAYS wrap adjacent sibling elements in a React Fragment (`<>...</>`) to satisfy the single-return rule without adding DOM nodes.

➔ NEVER wrap sibling elements in an unnecessary `<div>` when they reside inside CSS Flexbox or Grid containers.

➔ IF returning multiple siblings without a wrapper THEN use `<>...</>` to prevent compiler syntax errors.

❒ Tag Closing & Attributes

➔ ALWAYS close all JSX tags explicitly, including void elements like `<img />`, `<input />`, and `<br />`.

➔ ALWAYS use `className` instead of `class` when assigning CSS styling to avoid collisions with JavaScript reserved words.

**DO THIS:** wrap sibling elements in a Fragment with self-closing tags

```jsx right
export default function NewsAlert() {
  return (
    <>
      <img className="story-photo" src="/breaking.jpg" alt="Story photo" />
      <h2>Live Update</h2>
    </>
  );
}
```

**DO NOT DO THIS:** return adjacent elements or use unclosed tags and class

```jsx wrong
export default function NewsAlert() {
  return (
    <img class="story-photo" src="/breaking.jpg">
    <h2>Live Update</h2>
  );
}
```
