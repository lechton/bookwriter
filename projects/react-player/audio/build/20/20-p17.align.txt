Now, the interview prep. For the interview.
The question itself goes like this. How do you make an input, a text area, or a select fully controlled by React state?
How would you answer that clearly, in thirty seconds?
A controlled field takes what it shows from state, and reports every change back to state. I give it two props: value from state, and on change, which saves e dot target dot value with the setter. React's on change fires on every key, like the browser's input event, not like the change event. After every render, React writes the state into the field, so state is the single source of truth. To empty the box after Send, I only set the state to an empty string. Four rules keep this working.
First, value always comes with on change. Without it, React puts the old text back after every key, and logs a read only field error. The handler saves exactly e dot target dot value, right away. Second, default value is not controlled. It only sets the starting text, and the box keeps its own text after that. Third, menus and tick boxes use the same pair. A select takes value on the select itself, never selected on an option. A checkbox takes checked, and reads e dot target dot checked. And fourth, start with an empty string. A controlled field must get a string from the first render. If it starts as undefined, React warns that an uncontrolled input is changing to controlled.
