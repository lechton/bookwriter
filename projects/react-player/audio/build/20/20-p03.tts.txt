Here they are, gathered in one place. <short pause> One. On change sends every key into state. React calls it on every key, so the count can follow each letter. <breath> Two. Value sends state back into the box. Then setting state is enough to empty the box after Send. A prop that only sets the starting text cannot do this. <short pause> Three. Value without on change freezes the box. React puts the old text back after every key... and the Console shows an error. <breath> Four. A menu and a tick box use the same pair. The menu takes its choice from state. The tick box takes its tick from state, and its handler reads the tick, not the text. <short pause> And five. A controlled box starts with an empty string. If it starts with nothing at all, React warns as soon as the user types.

Before we walk through each one, there's a map of all five.

The table gives each principle three things: its name, why it matters in debugging and interviews, and the React rule. <short pause> Principle one, on change sends every key into state. A count or a greeting that never moves means the typed text never reached state, and interviewers also ask why React's on change fires on every key. The rule: give the box on change, and save the new text with the setter on every key. <breath> Principle two, value sends state back into the box. A form that keeps its old text after Send, while the count says zero, is the most common form bug. So give the box value from state, and the box always shows what state holds. <short pause> Principle three, value without on change freezes the box. A box that refuses every letter looks broken, and the Console error explains why. Every box with value also needs an on change that saves the new text right away. <breath> Principle four, the same pair on a menu and a tick box. A tick box that will not untick, or a menu that ignores its starting choice, comes from the habits of plain HTML. Put the chosen value on the menu itself, give the tick box its tick from state, and read the tick back from the browser. <short pause> And principle five, a controlled box starts with an empty string. A warning about a box changing from uncontrolled to controlled shows up on the first key... and it confuses many developers. <exhales> The fix is simple: start the state behind every box with an empty string, never with nothing.
