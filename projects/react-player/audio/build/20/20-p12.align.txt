So, what does value mean on a menu?
On a select tag, value says which option is chosen. It must match the value of one of the options inside. And each option tag has two texts. The text between its tags, such as Banana, is what the user reads. Its value, such as banana with a small b, is the string the menu reports to our code.
So the user reads Banana, with a capital B... but our code receives banana with a small b. Where did that string come from? The browser supplies it.
It goes like this. The user picks Banana. The menu's value becomes the value of that option, which is banana. React calls on change, and e dot target dot value is banana. Set fruit saves banana, and React writes it back into the menu... so Banana stays chosen.
Next, a rule worth remembering. Never mark an option as selected.
In plain HTML, you choose the starting option by writing selected on that option. A developer who knows HTML might write something like this. A select tag, with two option tags inside. The first is Delivery. The second is Payment... and that one carries the word selected. That's the plain HTML habit, and it's marked wrong, because React does not support it.
React does not support selected on an option. The menu still opens on Payment, but React prints a red error in the Console. The error tells you to use value, or default value, on the select instead.
The React way puts the choice on the select itself. So the select tag gets value equals payment, in quotes, and an on change that calls set topic with e dot target dot value. The two option tags, Delivery and Payment, stay plain, with no selected anywhere. React chooses the option whose value matches.
React reads value on the select, and chooses the option whose value matches. When the menu only needs a starting choice and no state, use default value on the select instead. It works the same way as default value on a text box.
And what does checked mean, on a tick box?
A tick box has no text to show. It is either ticked, or not. So it does not use value. It uses checked, a React prop that holds true or false. After every render, React makes the box ticked or unticked to match.
In Lesson eighteen, a tick box without checked kept its own tick inside the browser. That box was uncontrolled. With checked from state, React decides the tick... and the box becomes controlled.
The handler reads e dot target dot checked, which the browser supplies. It is the tick right after the click. True if the box is now ticked, and false if not.
For a tick box that only needs a starting tick, React has default checked, which works like default value. And a tick box with checked but no on change freezes too, just like the frozen text box of Principle three. React prints the same read-only error, but this time it names checked and default checked.
