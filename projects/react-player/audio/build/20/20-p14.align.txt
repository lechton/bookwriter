So... where did undefined come from?
Our code never writes undefined. JavaScript supplies it. Here, use state receives no starting value, and in JavaScript, a missing argument is undefined. So React saves undefined as the first state of city.
Next, why React warns when the box works.
The box works, right? So what is React complaining about? Here is what happens, in order.
The page opens. City is undefined, so the box gets no real value at all. React treats the box as uncontrolled, the same as a box with no value prop. Then the user types a. On change runs, and set city saves the string a. React renders again. And now the box has a real value, the string a. So the same box has switched, from uncontrolled to controlled. React cannot tell which one we meant... so it warns.
React's documentation explains it the same way. You cannot give a box an undefined value first, and a string later. In its words, "React won't know whether you want the component to be uncontrolled or controlled." A box must stay one kind for its whole life.
Think of a notebook that is suddenly declared a whiteboard, in the middle of the lesson. The student was writing freely, and now the teacher wants to write on the same page. Nobody knows who owns the page any more.
Now, one thing to keep straight. Starting with nothing, and starting with an empty string... are not the same.
Both versions draw the same empty box when the page opens. But they split at step one. When the state starts as an empty string, value is a real string from the very first render. So the box is controlled from the start... and it never switches.
The opposite pair really is the same. An undefined value, and no value prop at all, are the exact same thing for React. Both give an uncontrolled box.
