The tick box has a value too. So why is reading it wrong? Here is what happens.
The user ticks the box, and React calls on change. On a tick box, e dot target dot value is a fixed string that never changes with the tick. When the tick box has no value of its own, the browser makes this string on. So set wants reply saves the string on. React treats any text that is not empty as ticked, so the box is ticked. So far, so good. Then the user clicks again to untick. The browser removes the tick for a moment, and React calls on change again. But e dot target dot value is still on... so state is still on. State did not change, so React puts the tick back, and the box stays ticked.
The fix is to read the tick itself. Same input, same checked equals wants reply. Only the on change is different. It now calls set wants reply with e dot target dot checked. That's true or false, right after the click.
After a reload, the box ticks and unticks with each click.

Let's pull Principle four together. Menus and tick boxes, the same pair, with their own props. Control a menu with value on the select itself, never selected on an option. Control a tick box with checked, and read e dot target dot checked in its handler. A menu reports the value of the picked option, so value on the select must match one option. Writing selected on an option is the plain HTML habit, and React does not support it. A tick box holds true or false, so it takes checked from state. Its e dot target dot value is a fixed string such as on, which never changes with the tick. So, do this. Put value equals topic, in curly braces, on the select tag, with set topic reading e dot target dot value. The choice lives on the select. And give the tick box checked equals wants reply, with set wants reply reading e dot target dot checked. Don't do this. Don't write selected on the Payment option, because React does not support it. And don't let the tick box handler read e dot target dot value. It's always on... so the box never unticks.
