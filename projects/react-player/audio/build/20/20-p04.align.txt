Here's something that trips people up. React's on change, and the browser's change event, are not the same.
If you have written plain JavaScript, this may surprise you. The browser has its own event called change... and it does not fire on every key. In plain JavaScript, there are two different events you can listen to on a text box.
You can see both of them in page dot js, one per line. Line one tells message box to listen for change, in quotes, and logs e dot target dot value. That one runs only when the user leaves the box. Line two is almost the same, but it listens for input, in quotes. And that one runs on every key.
The browser's change event waits until the user is done with the box, and clicks somewhere else. The browser's input event fires on every change.
React's on change behaves like the second line, the input event. So the two share a name, but they are not the same. The browser's change event waits for the user to leave the box. React's on change... fires on every key.
React also accepts on input, which does the same job. React code uses on change by long habit, so this book uses it too.
