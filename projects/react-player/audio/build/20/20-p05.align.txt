So, principle one. On change... React calls it on every key. When the page must react to what the user types, give the box on change, and save e dot target dot value with the setter. The count must move while the user types, so the text must reach state on every key. React's on change is not the browser's change event, which waits for the user to leave the box. It fires on every key, like the browser's input event. By the time it runs, the browser has already put the new letter into the box, so e dot target dot value holds the whole new text.
