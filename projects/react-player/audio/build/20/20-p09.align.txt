Now we come to Section three, and with it, Principle three. Value without on change... freezes the box.
Once again, we start with the smallest case. A box that's stuck on John.
What if a box has value, but no on change? When the page opens, the box shows John... and the Console already shows a red error.
In figure fifteen, the browser is at localhost five one seven three. There's one box labeled Name, and it holds John. Below it, the Console has a red line. Put simply, React is complaining that we gave a form field a value without an on change handler. In its own words: you provided a value prop to a form field without an on change handler. This will render a read-only field. If the field should be mutable, use default value. Otherwise, set either on change or read only.
And the box itself? It has value, and nothing else.
The file is App dot jsx, and it's tiny. Line one imports use state from React. Line three starts the App component. On line four, we make a piece of state called name, with its setter, set name, and it starts as John. Then the return wraps a label, with the word Name in it, and inside the label sits the input, on line nine. Its only prop is value equals name, in curly braces. The note next to it says it plainly: wrong, value without on change.
Now the user clicks at the end of the box, and types two letters, n and y, to make Johnny. But the box still shows John.
Figure sixteen is the same page, after those two letters were typed. And honestly... it looks exactly like figure fifteen. The Name box still says John, and the same red read-only error sits in the Console.
No line of our code removes the letters. So who removes them? React does. Here is what happens on every key, in order.
First, the user presses n. Second, the browser puts n into the box. Third, the box has no on change, so no code of ours runs, and name stays John. Fourth, React writes the value it was given, John, back into the box. And fifth... the box shows John again.
Remember the whiteboard. A student calls out a letter, but the teacher is not listening. So the board never changes.
So, what the red error is telling you.
React prints this error while you develop, whenever a box has value and no on change. And it even offers three ways out.
If the box should be editable, add on change. If you only wanted a starting text, use default value instead. And if the box should really be frozen, say so with the read only prop. Then React knows you meant it... and the error goes away.
