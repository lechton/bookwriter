Principle four, then, in one card. One status. A single string cannot be in two looks at once. Keep the current look in one status string, and compute everything else from it, or from other state... instead of keeping several true or false values. Every true or false value doubles the number of combinations, and most of them are looks nobody designed. With two switches for checking and error, forget to set is checking back to false... and the error shows while the box stays off. The user cannot even fix the typo. One status holds exactly one string, so setting the next look turns the old one off, by itself. And if you want a true or false name, compute it: status, triple equals, the string checking. So, what to do. Make status with use state, starting at typing, and later call set status with error. That replaces checking, so the box works again. And what not to do. Two switches, is checking and is error, both starting false... then set is error to true. That's the wrong one. Is checking is still true, so the error shows on a box that is still off.
