Two names, then. Imperative code gives a command for every step... turn this off, show that. Declarative code describes the result. When done is true, the button is off, and the thank-you line is there.
Think of a car ride across a city. In the imperative style, you sit next to the driver and call out every turn. Left here... right at the bakery... straight on to the bridge. In the declarative style, you get into a taxi and say only the address. The taxi driver knows the streets, and finds the way. In React, the handler says the address... and React is the driver.
Now, a promo code box... that has five looks.
The Subscribe button has only two looks. Before the click, and after it. Real forms have more. Look at the checkout page of any online shop. Under the cart, there is often a small box called Promo code. You type a code and click Apply. Then the shop's server checks the code.
While the server checks, the page says Checking... and you cannot click Apply again. If the code is wrong, a red line says the code is not valid. If the code is right, the box goes away, and a line says the discount was applied. So this small box has five looks over time. Empty, typed, checking, refused... and accepted.
In plain JavaScript, every change from one look to another needs its own commands. Show this line, hide that one, turn the button off, turn it back on. With five looks, there are many changes to cover. And if you forget one command... the page ends up in a look that nobody designed.
In this lesson, we build that promo code box twice. First, we build it in plain JavaScript, and we watch one forgotten command break the page. Then we build it in React. There, we describe each look once... and let state decide which look is on the screen.
