All five words come from JavaScript.
Let's go through them one by one. Async, in front of a function, means the function is allowed to wait. Only an async function may use await. Await pauses the function at that line, until the promise has its answer. Here it waits for the promise that check code returns. While the function waits, the browser keeps the page alive... so the shopper can still scroll. When the answer is yes, the function goes on with the next line. Then try and catch, which work as a pair. JavaScript runs the code inside try. If something there fails, JavaScript stops at that point, and jumps into catch. A promise that says no counts as a failure at its await. We write catch with no name after it, because this handler doesn't need the error object. And last, finally. It runs at the end in both cases... after try finished, or after catch ran.
On the last line, add event listener hands handle submit to the browser. The word submit names the event. The browser fires it when the form is sent, which happens when the shopper clicks Apply. Just like React in Lesson eleven, the plain browser passes the handler an event object, e. And here too, calling its prevent default method stops the page from reloading.
