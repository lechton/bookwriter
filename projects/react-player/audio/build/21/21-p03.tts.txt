<short pause> The five principles of reacting to input with state.

So let's gather it all up. <short pause> A page that changes in several ways over time is hard to keep right, when our code changes each element by hand. React lets us describe every look once... and pick the look with state. <breath> Five practical rules follow from that. <short pause> Principle one. One forgotten command breaks the page. Plain page code needs a command for every change from one look to another. And one forgotten command leaves the page in a look nobody designed. <short pause> Principle two. List every look first. Before writing any logic, list every look the user can see. Then draw each look from one value. <breath> Principle three. Find every trigger. Some changes come from the user. Others come from the computer, such as a server's answer. Both kinds must set state. <short pause> Principle four. One status, instead of many switches. One value that names the current look cannot be in two looks at once. Several true or false values... can. <breath> And principle five. Handlers only set the next state. The handler says which look comes next. The JSX already says what each look shows... and React changes the page to match.
