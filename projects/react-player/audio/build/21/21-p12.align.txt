Section five. Principle five. Handlers only set the next state.
Computing a class... instead of adding one.
In plain JavaScript, we changed the look of an element by adding or removing a CSS class. Here is a small example. A picture should get a blue frame when the user clicks it. Our stylesheet has a class for that... picture, dash dash, active.
The plain way finds the picture element by its id, and keeps it in a variable called image. Then it adds the class on the click.
Three short lines of plain JavaScript, in picture dot js. Line one tells image to listen for a click, with add event listener. Line two is the whole point. On the click, image dot class list dot add puts in the class picture, dash dash, active. And the note on that line says it plainly... a command. Put the blue frame on this element. Line three just closes it up.
React does not ask us to command the element. Instead, we compute the class name from state... on every render.
And the React version? This is Picture dot jsx. Line one imports use state from react. Line four gives us a piece of state, is active, with its setter, set is active, and it starts as false. Then line six makes a variable, class name, holding the string picture. Lines seven and eight say... if is active is true, add a space and picture dash dash active to the end of it. The note there says exactly that: add the second class to the text when is active is true. And line eleven returns an image. Its class name is the one we just worked out, the class text computed above, as the note puts it. On click, it calls set is active with true. The source is park dot jpg, and the alt text is The new park.
The sign plus equals comes from JavaScript. Used on a string, it adds text to the end of it. So when is active is true, the text grows to picture, space, picture dash dash active. And the space at the start of that second part... keeps the two class names apart.
The user clicks the picture once. The Elements panel then shows both classes on the image.
Look at figure twenty-four. It's the Elements panel, after that one click. There's the image tag, and its class attribute holds both names, picture, and picture dash dash active. Its alt is The new park, and its source is park dot jpg. The note beside it says both classes were computed from is active. React wrote them both into the class attribute.
Here is what happened, in order.
One click, and the handler set is active to true. Then React drew Picture again. This time is active was true... so the class name became picture, space, picture dash dash active. And last, React compared the new class name with the old one, which was just picture. They differ, so React wrote the new class name into the image's class attribute.
The handler never talks about classes. It only says that the picture is now active. The React docs describe the rule like this: "in React you need to describe what you want to see rather than manipulate the UI elements". This is the taxi again. The handler names the address... and React drives.
