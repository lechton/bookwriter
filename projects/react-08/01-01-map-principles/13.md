## Authorized Scope
Lesson 13 teaches how a component responds to a click or a keystroke. We write a function, the event handler, and pass it to an element through a prop such as `onClick`. React calls the function when the user clicks, never before. React hands the function an event object. With it, the handler can cancel the browser's own action, such as a form reloading the page. A click starts on the element the user clicked and then runs the handlers of every parent above it. `e.stopPropagation()` keeps an inner button's click to itself. A child tells its parent about a click by calling a function the parent passed down as a prop. The lesson builds on Q02, where a function reference differs from a call. It also builds on Q11, where the arrow function first appeared. It also builds on Q12, where side effects were kept out of rendering. Without state, a handler shows its result with `alert` or `console.log`. The example is the article card. It has a Like button, a comment form, and a Read button that tells the list which article to open.

## Theme and Options
- **Theme**: A page must answer the user: a click on Like, text typed into a comment box. How does a component run our code when the user acts?
- **Options**: none (starting point: `onclick="..."` attributes and `addEventListener` on plain HTML pages, which nobody who knows event props would choose for an element React builds)
- **This lesson teaches**: event handler props

## Principle Thread
- **Anchor**: Event handling: one click travels from the element to the functions we hand React
- **Axis**: the path of one click: the function we hand over, the event the click brings, the parents it climbs through, and the parent component it reaches
- **Why This Axis**: Each step needs the one before it. A handler must be handed over before anything can run, so passing comes first. The event object is what the handler receives when the click arrives, and it is the tool for both later steps. The climb through the parents happens next, as the browser moves the click up the page, and stopping it uses the event object. A parent component hears about the click last, through a callback prop, which the reader can only follow once they know how a handler runs and where a click goes. Two axes were rejected. "One kind of event per principle: click, typing, submit" repeats the same rules three times. "Browser, then React, then our code" splits passing and calling across two places.
- **Spoken Preview**: Everything in this lesson comes down to one idea: event handling, which means that one click travels from the element to the functions we hand React. First, event handlers, which means the click runs a function we pass, never one we call: we write the function's name, or an arrow around the call, so nothing runs before the user clicks. Second, the event object, which means the click brings the browser's own action, which we can cancel: a form's submit reloads the page unless the handler prevents it. Third, event propagation, which means the click travels up through every parent that listens: when an inner button must act alone, its handler stops the climb. Fourth, callback props, which means the click reaches the parent through a function it passed down: the child calls that function, and the parent decides what the click means.
- **Closing Line**: Pass the function, cancel the default, stop the climb, and call the parent.

## Principles

### Principle 1: Event handlers: the click runs a function we pass, never one we call
- **Handle**: `pass-not-call`
- **Thread Step**: the function we hand over
- **Rule**: We pass a function to an event prop such as `onClick`: its name, `onClick={handleLike}`, or an arrow around a call that needs an argument, `onClick={() => handleShare(article.title)}`, never a call such as `onClick={handleLike()}`.
- **Kind**: Model
- **Reader Question**: "I wrote `onClick={handleLike()}`. Why do the alerts pop up when the page loads, and never when I click?"
- **Reader Expects**: `onClick` works like the HTML attribute `onclick="handleLike()"`, where the parentheses are part of the code the browser runs on a click
- **React Does**: the braces run their code while React calls the component (Q04), so `handleLike()` runs at once and passes its result, `undefined`, to `onClick`; with Strict Mode each card is called twice, so the page load shows six alerts for three cards, and a click shows nothing, because `onClick` holds no function; `onClick={handleLike}` passes the function itself, and React calls it when the user clicks; the handler sits inside the component, so it reads `article` from the props and needs no argument; a handler that needs one, such as `handleShare(article.title)`, invites the same call, which runs on load for every card; an arrow around the call, `() => handleShare(article.title)`, is a new function that React calls on the click, and only then does `handleShare` run; the HTML habits fail too: a string throws on the click, and the lowercase `onclick` prints a warning and does nothing
- **Placement**: `function handleLike() { ... }` inside `ArticleCard`, above the `return`; `<button onClick={handleLike}>Like</button>`; `<button onClick={() => handleShare(article.title)}>Share</button>`
- **Real Mistake**: `<button onClick={handleLike()}>Like</button>` in `ArticleCard`, with `handleLike` showing `alert('You liked "' + article.title + '"')`; the page shows six alerts while it loads and none on a click; `onClick={handleLike}` shows one alert, on the click; verified in React 19.3.1, Vite 8.3.4, and Chrome
- **Fix In**: this principle
- **Importance**: react.dev's first `<Pitfall>` on events; the card's Friction; reviewers and interviewers expect "passed, not called"
- **Prediction**: with `onClick={handleLike}`, loading the page shows no alert, and a click on the first card's Like shows "You liked "New Park Opens Today""
- **Required Lesson Proof**: the called handler: six alerts on load, none on a click; the passed handler: one alert on a click; the called `handleShare(article.title)` and its arrow form; the string and the lowercase forms.

### Principle 2: The event object: the click brings the browser's own action, which we can cancel
- **Handle**: `event-object`
- **Thread Step**: the event the click brings
- **Rule**: Every handler receives the event object as its first argument; when the browser's own action, such as reloading the page on a form's submit, is not wanted, the handler calls `e.preventDefault()` before anything else.
- **Kind**: Decision
- **Reader Question**: "Post reloads the page and my comment disappears. Why?"
- **Reader Expects**: the handler replaces what the browser does, so a form whose `onSubmit` shows an alert does only that; `return false` stops the rest, as in HTML
- **React Does**: React calls the handler with one argument, the event object, named `e` by convention; the handler runs, the alert shows, and then the browser does what a form submit always does: it sends the form by reloading the page, here to `/?comment=Great+news%21`, so the comment box comes back empty; `return false` changes nothing in React; `e.preventDefault()` tells the browser to skip its own action, so the page stays and the comment stays in the box; the same object carries what the user did: in an `onChange` handler, `e.target.value` holds the text typed so far, one call per keystroke
- **Placement**: `function handleSubmit(e) { e.preventDefault(); ... }` inside `ArticleCard`; `<form onSubmit={handleSubmit}>` around the comment box and the Post button
- **Real Mistake**: `<form onSubmit={handleSubmit}>` with `function handleSubmit() { alert('Thanks for your comment!'); }`; after "Great news!" is typed and Post is pressed, the alert shows, the page reloads to `/?comment=Great+news%21`, and the comment box is empty; `e.preventDefault()` as the first line keeps the page and the comment; verified in React 19.3.1 and Chrome
- **Importance**: react.dev's "Preventing default behavior"; every form before Q40 needs it; reviewers flag a form that reloads
- **Review Point**: Do
- **Required Lesson Proof**: the form without `preventDefault`: the alert, the new address, the empty box; with `return false`: the same; with `e.preventDefault()`: the alert and the comment kept; the `onChange` log for "Hi".

### Principle 3: Event propagation: the click travels up through every parent that listens
- **Handle**: `event-propagation`
- **Thread Step**: the parents it climbs through
- **Rule**: A click runs the handler of the element it started on and then the handlers of every parent above it; when an inner button must act alone, its handler calls `e.stopPropagation()`, and a clickable parent always keeps a real button inside it for the keyboard.
- **Kind**: Decision
- **Reader Question**: "Clicking Like also opened the article. Why?"
- **Reader Expects**: a click belongs to the element under the mouse, so the Like button's handler runs and nothing else
- **React Does**: a click starts on the element the user clicked and then climbs to its parent, and to that parent's parent, running every `onClick` it meets on the way; this is called propagation, or bubbling; the Like button's handler runs first and shows "You liked ...", then the `<article>`'s `handleOpen` runs and opens the article; `e.stopPropagation()` in the Like handler ends the climb there, so one alert shows, while a click on the title still reaches the `<article>`; `e.target` is the element the click started on, and `e.currentTarget` the element whose handler runs; an `onClickCapture` handler on a parent runs before all of them, even when a button stops the climb; `stopPropagation` and `preventDefault` are unrelated: one stops the parents, the other stops the browser; a clickable `<article>` is a mouse shortcut: Tab skips it and lands on the buttons inside, so keyboard users need a real button that opens the article
- **Placement**: `e.stopPropagation()` as the first line of `handleLike(e)`; `<article onClick={handleOpen}>` for the mouse; a real `<button>` inside for the keyboard, such as the Read button of `callback-props`
- **Real Mistake**: `ArticleCard` with `<article className="card" onClick={handleOpen}>`, where `handleOpen` shows `alert('Opening "' + article.title + '"')`, and, inside it, `<button onClick={handleLike}>Like</button>`; a click on Like shows "You liked "New Park Opens Today"" and then "Opening "New Park Opens Today""; `e.stopPropagation()` in `handleLike` leaves only the first alert; verified in React 19.3.1 and Chrome
- **Importance**: react.dev's "Event propagation"; the card's Code Experiment React; interviewers ask `stopPropagation` against `preventDefault`
- **Review Point**: Condition
- **Required Lesson Proof**: Like inside the clickable card: two alerts; with `stopPropagation`: one, and the title still opens the article; the capture log on the list; `e.target` and `e.currentTarget` on a title click; Tab from the top of the page.

### Principle 4: Callback props: the click reaches the parent through a function it passed down
- **Handle**: `callback-props`
- **Thread Step**: the parent component it reaches
- **Rule**: A child reports a user's action to its parent by calling a function prop the parent passed down, named for the event, such as `onSelect`; an event prop on our own component does nothing until the component passes it to a browser element.
- **Kind**: Decision
- **Reader Question**: "The Read button is in `ArticleCard`, but `ArticleList` decides what opening means. How does the card tell it?"
- **Reader Expects**: `onClick` works on any tag, so `<ArticleCard onClick={...} />` makes the whole card clickable
- **React Does**: `onClick` on a browser element such as `<button>` is an event React listens for; on our own component it is only a prop, and `ArticleCard` never reads it, so a click does nothing; data flows down through props (Q06), and a child cannot reach the parent's variables, so `selectedId = article.id` in the card throws "selectedId is not defined"; the parent passes down a function instead, `onSelect={handleSelect}`, and the card calls it from a real element's handler, `onClick={() => onSelect(article.id)}`; the parent's `handleSelect` then runs with the id and decides what opening means, here an alert, and in Q14 a change on the screen; our own event props start with `on` and are named for the app's action
- **Placement**: `function handleSelect(id) { ... }` in `ArticleList`, passed as `<ArticleCard ... onSelect={handleSelect} />`; `ArticleCard({ article, onSelect })` with `<button onClick={() => onSelect(article.id)}>Read</button>`
- **Real Mistake**: `ArticleList` writes `<ArticleCard key={article.id} article={article} onClick={() => handleSelect(article.id)} />`, and `ArticleCard` has a plain `<button>Read</button>`; a click shows nothing, and the console is empty; `onSelect` read by the card and called from the button's `onClick` shows "Opening article 1"; verified in React 19.3.1 and Chrome
- **Importance**: the bank question's second half; the card's Core Truth; interviewers ask how a child talks to its parent
- **Review Point**: Do
- **Required Lesson Proof**: `onClick` on `<ArticleCard>`: no alert; the child assigning to `selectedId`: the error; `onSelect` called from the Read button: "Opening article 1".

## Senior Answer
In React, I pass a function to an event prop such as `onClick`. React calls it when the user acts. Code in the braces runs while the component renders, so `onClick={handleClick()}` runs at once and passes `undefined`. I pass the name, or an arrow around a call that needs an argument. React calls the handler with an event object. `e.preventDefault()` cancels the browser's own action, such as a form reloading the page. A click starts on the element it hit and climbs through every parent's handler. `e.stopPropagation()` stops that climb, which is a different job from `preventDefault`. For a child to talk to its parent, the parent passes down a function, by convention named `onSomething`. The child calls it with the data, and the parent decides what the click means. So data still flows down, and only calls flow up. An `onClick` on my own component does nothing until the component hands it to a real element. That element is ideally a `<button>`, which the keyboard can reach.
