## Authorized Scope
Lesson 10 teaches how a component shows a part of the page only in some cases. React has no special syntax for it. The component uses plain JavaScript to choose which JSX to return. An `if` above the `return` can return `null`, and then the component shows nothing. Inside the JSX, `condition && <Piece />` shows one piece or nothing. `condition ? <A /> : <B />` shows one of two pieces. When there are more than two cases, an `if` above the `return` stores the chosen JSX in a variable. JSX that is left out makes no element in the DOM. Every choice depends on props, because the values do not change yet. The lesson builds on Q04. There the ternary chose between two texts, and `false`, `null`, and `undefined` showed nothing while numbers showed. The example is the article card of the article site. It has a "New" label, a comment count, and a sign-in prompt, and its featured slot is sometimes empty.

## Theme and Options
- **Theme**: Some parts of a page appear only in some cases: a "New" label on new articles, a sign-in prompt for visitors. How does a component show, hide, or switch a part of the page?
- **Option**: Hiding with CSS: `<span className="new-label" hidden={!isNew}>New</span>` | Q04 `#jsx_expressions` | the element stays in the DOM and the browser does not draw it; fits a part that must keep its place in the page while it is hidden
- **Option**: Conditional rendering: `{isNew && <span className="new-label">New</span>}` | this lesson | the element exists only when the condition holds; fits a part that depends on data, and every part whose data may be missing
- **This lesson teaches**: conditional rendering

## Principle Thread
- **Anchor**: Conditional rendering: each time it runs, a component chooses which JSX to return
- **Axis**: how many pieces the choice has: none, one or nothing, one of two, one of many
- **Why This Axis**: Each step needs the one before it. Showing nothing comes first, because it teaches the model every later step uses: JSX that is not returned makes no element, and the component still runs. One piece or nothing builds on that model and on Q04's fact that `false` shows nothing while a number shows. One of two adds the second piece and the ternary from Q04, now with JSX. One of many builds on all three and moves the choice above the `return`. Two axes were rejected. "One syntax per principle: `if`, `&&`, ternary, variable" puts `if` in two places and gives the listener no order to predict. "Where the choice sits: above the `return`, inside the JSX, in the parent" puts `&&` and the ternary in one group and leaves the zero trap with no place of its own.
- **Spoken Preview**: Everything in this lesson comes down to one idea: conditional rendering, which means that each time it runs, a component chooses which JSX to return. First, returning null, which means choosing to show nothing: when there is nothing to show, the component returns null at its very top, before any line reads the missing data. Second, logical AND, which means choosing one piece or nothing: we put a true or false value on its left side, never a bare number, because a zero shows up on the page. Third, the ternary operator, which means choosing between two pieces: we write the choice inside the JSX, so the parts both cases share are written only once. Fourth, an if statement and a variable, which means choosing among many pieces: we make the choice above the return and place the result in the JSX, instead of putting one ternary inside another.
- **Closing Line**: Nothing, one or nothing, one of two, and one of many.

## Principles

### Principle 1: Returning null: choosing to show nothing
- **Handle**: `return-null`
- **Thread Step**: none: the component shows nothing
- **Rule**: When a component has nothing to show for its props, it returns `null` from an `if` at its very top, before any line reads the missing data; when the parent decides whether the component appears at all, the parent leaves out its tag instead.
- **Kind**: Model
- **Reader Question**: "Some days there is no featured article. How does the featured card show nothing instead of breaking the page?"
- **Reader Expects**: the card can stay and look empty, or be hidden with CSS, as on a plain HTML page where a missing value leaves an empty box
- **React Does**: React runs the component, and every line of its JSX runs, so `{article.title}` reads a property of `null` and throws "Cannot read properties of null (reading 'title')"; React removes the whole page and warns "An error occurred in the <ArticleCard> component"; a class that hides the card does not help, because the JSX still runs; `article?.title` stops the crash but leaves an empty card; an `if` at the top that returns `null` ends the function before any line reads `article`, and React shows nothing for the card while the rest of the page stays; the component still ran, so a log at its top prints; JSX that is not returned makes no element in the DOM
- **Placement**: `if (!article) { return null; }` as the first line of `ArticleCard`, above every line that reads `article`; or `{featured && <ArticleCard article={featured} />}` in the parent when the parent owns the decision
- **Real Mistake**: `ArticleCard({ article })` returns `<article>` with `{article.title}` and `{article.author}`, and `App` writes `<ArticleCard article={featured} />` with `featured` set to `null` on a day with no featured article; the page goes blank, the other articles too, and the console shows "Cannot read properties of null (reading 'title')"; `if (!article) { return null; }` at the top shows the other articles; verified in React 19.3.1, Vite 8.3.4, and Chrome
- **Fix In**: this principle
- **Importance**: the card's Mechanism; one missing value blanks the whole page; Q72 builds on the crash; interviewers ask what a component that renders nothing returns
- **Prediction**: with `article={null}`, the Elements panel shows no `<article>` for the featured slot, while a `console.log` at the top of `ArticleCard` still prints for it: six lines for three tags with Strict Mode; with `{featured && <ArticleCard ... />}` in the parent, four lines, because the featured card never runs
- **Required Lesson Proof**: the featured card with `null`: the blank page and the error; `article?.title`: the empty card; the early return: no card, the other articles shown, and the log still printed.

### Principle 2: Logical AND: choosing one piece or nothing
- **Handle**: `and-not-number`
- **Thread Step**: one or nothing: the component shows a piece or leaves it out
- **Rule**: To show a piece or nothing, we write `condition && <Piece />` with a true or false value on the left, such as `commentCount > 0`, never a bare number.
- **Kind**: Decision
- **Reader Question**: "The 'New' label should show only on new articles, and the comment count only when there are comments. Do I need an `if` for that?"
- **Reader Expects**: `&&` works like `if`: when the left side is "nothing", nothing shows, whether it is `false` or `0`
- **React Does**: `a && b` gives back `a` when `a` is falsy, and `b` otherwise; with `isNew` true it gives the `<span>`, with `false` it gives `false`, which shows nothing (Q04); with `commentCount` at 0 it gives `0`, a number, and React shows numbers, so a bare `0` appears in the card; `commentCount > 0` turns the number into `true` or `false`; a quoted `isNew="false"` is a text, which is truthy, so the label shows; an empty array is truthy too
- **Placement**: `{isNew && <span className="new-label">New</span>}` and `{commentCount > 0 && <p>{commentCount} comments</p>}` inside the card's JSX
- **Real Mistake**: `{commentCount && <p>{commentCount} comments</p>}` in `ArticleCard`; the article with 3 comments shows "3 comments", and the article with none shows a bare `0` under its title; `commentCount > 0 &&` shows nothing for it; verified in React 19.3.1 and Chrome
- **Importance**: react.dev's `<Pitfall>`; the card's Under the Hood; the bank row's hook (a badge only when the count is not zero); interviewers ask why the `0` shows
- **Review Point**: Do not
- **Required Lesson Proof**: two cards, 3 and 0 comments, with the bare number on the left: "3 comments" and `0`; with `> 0`: "3 comments" and nothing; the "New" label on one card of two; `isNew="false"`: the label shows.

### Principle 3: The ternary operator: choosing between two pieces
- **Handle**: `ternary-two-pieces`
- **Thread Step**: one of two: the component shows exactly one of two pieces
- **Rule**: To show one of two pieces in the same place, we write `condition ? <A /> : <B />` inside the JSX and keep the markup both cases share written once; two whole returns fit only when the two cases share nothing.
- **Kind**: Decision
- **Reader Question**: "Signed-in readers see the summary, visitors see a sign-in prompt. Do I write two returns?"
- **Reader Expects**: an `if` with two `return` statements, each with the whole card, as Q04 placed statements above the `return`
- **React Does**: both forms show the same page; the two returns copy the title and the author into both branches, so a change made in one branch only, such as the author's name, reaches only one kind of reader; a ternary inside the JSX chooses only the part that differs, and the title and author are written once; it always has two answers, and one without the `:` part stops the build with "[PARSE_ERROR] Expected `:` but found `}`"; `condition ? <A /> : null` does what `&&` does
- **Placement**: `{isSignedIn ? <p>{summary}</p> : <p>Sign in to read this article.</p>}` in place of the text, inside the one `<article>`
- **Real Mistake**: `ArticleCard` with `if (isSignedIn) { return <article>...</article>; }` and a second `return <article>...</article>;` for visitors, each with the title; the author's name, added later only to the first return, shows for signed-in readers and is missing for visitors; the ternary with the shared markup written once shows the author for both; verified in React 19.3.1 and Chrome
- **Importance**: the interview question's "switch"; react.dev's ternary section; reviewers flag duplicated branches
- **Review Point**: Condition
- **Required Lesson Proof**: the two-return version with the author added to one branch: visitors see no author, signed-in readers do; the ternary: the author on every card, with the summary or the prompt; the ternary without `:`: the overlay.

### Principle 4: An if statement and a variable: choosing among many pieces
- **Handle**: `if-and-variable`
- **Thread Step**: one of many: the component picks one of several pieces
- **Rule**: When a choice has more than two cases, we pick the piece with `if`, `else if`, and `else` above the `return`, store it in a variable, and place the variable in the JSX, instead of nesting one ternary inside another.
- **Kind**: Decision
- **Reader Question**: "The comment line needs three wordings: no comments, one comment, many comments. Can I put one ternary inside another?"
- **Reader Expects**: a ternary inside a ternary, because a ternary already chose between two texts
- **React Does**: the nested ternary works and shows "No comments yet", "1 comment", and "5 comments"; but the reader must match each `:` to its `?` to see which text belongs to which case, and a fourth case makes it worse; an `if`, `else if`, and `else` above the `return` set one variable, `let commentText`, and the JSX shows `{commentText}`; each case reads as one line; the variable can hold text or JSX; when the cases grow further, a child component or an object of values can replace the conditions
- **Placement**: `let commentText;` and the `if` chain above the `return` of `ArticleCard`; `<p>{commentText}</p>` in the JSX
- **Real Mistake**: `<p>{commentCount === 0 ? 'No comments yet' : commentCount === 1 ? '1 comment' : commentCount + ' comments'}</p>` in `ArticleCard`; it shows the right three texts, and a reviewer must untangle three `?` and `:` to check them; the `if` chain shows the same texts; verified in React 19.3.1 and Chrome
- **Importance**: react.dev's Challenge 3 refactor; reviewers flag nested ternaries; interviewers ask how to handle more than two cases
- **Review Point**: Prefer

## Senior Answer
React has no special syntax for conditions. A component uses plain JavaScript to choose which JSX to return. When it has nothing to show, it returns `null` from an `if` at its top. That `if` comes before any line reads missing data. For one piece or nothing, I write `condition && <Piece />`. The left side must be true or false, because a `0` there shows up on the page. For one of two pieces, I write a ternary inside the JSX, so the shared markup is written once. For more cases, I choose above the `return` with `if` and `else if`. I store the result in a variable and place it in the JSX. JSX that is not returned makes no element in the DOM. That differs from hiding with CSS, which keeps the element and still runs every line of its JSX. When the parent decides whether a component appears, it simply leaves out the tag.
