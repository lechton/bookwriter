## Authorized Scope
Lesson 03 teaches the rules of JSX. It works on `ArticleCard`, the card from Q02, and on `TopStories`, a small component that returns list items. JSX looks like HTML, but it is JavaScript. The build turns each tag into a `_jsx` call. The call returns a plain object that describes the element. React reads these objects and builds the DOM. Three rules follow from this. A component returns one root, because a function returns one value. Every tag is closed, including `<img />` and `<br />`. Attributes are written as JavaScript names, so `class` becomes `className` and `for` becomes `htmlFor`. A Fragment, written `<>...</>`, groups elements for the return and adds nothing to the DOM. The lesson builds on Q01, where a component describes the page. It also builds on Q02, where a component is a capitalized function that returns JSX. Values from variables stay out of this lesson.

## Principles

### Principle 1: JSX is JavaScript that describes elements
- **Handle**: `jsx-is-javascript`
- **Kind**: Model
- **Reader Question**: "My component returns something that looks like HTML. Is it HTML?"
- **Reader Expects**: yes, a kind of HTML string that the browser reads, like a template in PHP or Handlebars
- **React Does**: the build turns each tag into a `_jsx` call; `<h2 className="headline">Night Trains Return to Europe</h2>` becomes `_jsx("h2", { className: "headline", children: "Night Trains Return to Europe" })`; the call returns a plain object, a React element; React reads these objects when it renders and builds the DOM; the browser never sees JSX
- **Placement**: JSX wherever a JavaScript value can go: after `return`, or in a variable
- **Real Mistake**: none; the HTML picture breaks no code by itself, and the three rules below show where it misleads
- **Importance**: interviewers open with "what is JSX"; every rule of this lesson follows from it
- **Prediction**: `const headline = <h2 className="headline">Night Trains Return to Europe</h2>;` followed by `console.log(headline)` prints an object with `type: 'h2'` and `props: { className: 'headline', children: 'Night Trains Return to Europe' }`, not a string of HTML.
- **Required Lesson Proof**: the compiled code of `ArticleCard`'s headline, shown beside the JSX; then the logged object in the console.

### Principle 2: A component returns one root, because a function returns one value
- **Handle**: `one-root`
- **Kind**: Decision
- **Reader Question**: "I pasted a heading and a paragraph after `return`. Why does the build fail?"
- **Reader Expects**: HTML allows any number of tags side by side, so JSX should too
- **React Does**: each tag is one `_jsx` call, so one value; `return` gives back one value; two calls side by side are not one expression, so the parser stops before anything runs
- **Placement**: one parent around everything the component returns: an element the page needs, such as `<article>`, or a Fragment
- **Real Mistake**: `ArticleCard` returns `<h2>Night Trains Return to Europe</h2>` and `<p>Sleeper routes reopen.</p>` side by side; the build fails; Babel says "Adjacent JSX elements must be wrapped in an enclosing tag. Did you want a JSX fragment <>...</>?"; esbuild gives a parse error that does not name the cause; verified with @babel/parser 8.0.7 and esbuild 0.28.2
- **Importance**: the card's Friction; the first build error every newcomer meets; interviewers ask why the rule exists
- **Review Point**: Do not
- **Required Lesson Proof**: `ArticleCard` with the two tags side by side: the build error; the same tags inside `<article>`: the card appears.

### Principle 3: Group with a Fragment when the page needs no extra element
- **Handle**: `fragment-or-element`
- **Kind**: Decision
- **Reader Question**: "So I wrap everything in a `<div>`?"
- **Reader Expects**: yes; a `<div>` is the usual way to group tags in HTML
- **React Does**: a `<div>` becomes a real element in the DOM, between the parent and the children; `<>...</>` is a Fragment; it groups the elements for the `return` and adds no element, so the children land straight inside the parent
- **Placement**: a Fragment when the group exists only to satisfy `one-root`; an element when the page needs the box, for meaning (`<article>`, `<header>`) or for a style
- **Real Mistake**: `TopStories` returns two `<li>` wrapped in a `<div>`, and `App` places it in `<ul className="stories">`; the DOM is `<ul><div><li>`, and `.stories > li` matches no item, so the list styles stop applying; with `<>...</>` the DOM is `<ul><li><li>` and both match; verified in React 19.3.0
- **Importance**: the last part of the interview question; wrapper divs break list, flex, and grid layouts, and reviewers remove them
- **Review Point**: Condition
- **Required Lesson Proof**: `TopStories` with the `<div>`: DevTools shows the `<div>` inside the `<ul>`, and `document.querySelectorAll('.stories > li').length` is `0`; with the Fragment: no `<div>`, and the count is `2`.

### Principle 4: Close every tag, including `<img />` and `<br />`
- **Handle**: `close-every-tag`
- **Kind**: Decision
- **Reader Question**: "HTML lets me write `<img>` and `<br>` without closing them. Why does JSX refuse?"
- **Reader Expects**: these tags never have content, so they need no closing tag, as in HTML
- **React Does**: the JSX parser needs every tag closed, either with a closing tag or with `/>`; an open `<img>` makes it read the rest of the markup as the image's content; the parser then meets `</article>` and stops
- **Placement**: `<img src="/img/night-train.jpg" alt="A night train" />`, `<br />`, `<li>Rail strike ends</li>`; any tag may close itself
- **Real Mistake**: HTML pasted into `ArticleCard` with `<img src="/img/night-train.jpg" alt="A night train">`; the build fails with esbuild's "Unexpected closing "article" tag does not match opening "img" tag"; Babel reports an unexpected token at the end of the file; verified with esbuild 0.28.2 and @babel/parser 8.0.7
- **Importance**: the card's Friction; pasted HTML fails at once, and the message points at the wrong line
- **Review Point**: Do not
- **Required Lesson Proof**: `ArticleCard` with the open `<img>`: the build error; with `<img ... />`: the image and the headline appear.

### Principle 5: Write attributes as JavaScript names
- **Handle**: `camelcase-attributes`
- **Kind**: Decision
- **Reader Question**: "Can I keep `class` and `for` from my HTML?"
- **Reader Expects**: yes; attributes are copied to the page as written, as in HTML
- **React Does**: JSX attributes become keys of a JavaScript object; `class` and `for` are JavaScript keywords, so React uses `className` and `htmlFor`, the names of the DOM properties; other attributes of several words use camelCase (`tabIndex`, `strokeWidth`); `aria-*` and `data-*` keep their dashes; React 19 still sets `class` on the element, and prints an error for each wrong name
- **Placement**: `className="headline"`, `htmlFor="email"`, `tabIndex="0"`; `aria-label` and `data-story-id` as in HTML
- **Real Mistake**: HTML pasted with `<label class="label" for="email">`; the page looks right, and the console shows "Invalid DOM property `class`. Did you mean `className`?" and the same for `for`; verified in React 19.3.0
- **Importance**: reviewers flag `class` on sight; a console full of these errors hides the ones that matter
- **Review Point**: Do
- **Required Lesson Proof**: `ArticleCard` with a sign-up line `<label class="label" for="email">` and an `<input id="email">`: the two console errors; with `className` and `htmlFor`: a clean console; `data-story-id="7"` on the `<article>` prints no error.

## Senior Answer
JSX is a syntax extension for JavaScript. It looks like HTML, but the build turns each tag into a function call. The call returns a plain object that describes the element. React reads those objects and builds the DOM. Because it is JavaScript, JSX is stricter than HTML. A component returns one value, so it needs one root. Two tags side by side fail the build. Every tag must be closed, so I write `<img />` and `<br />`. Attributes become object keys, so I write `className` instead of `class`, and `htmlFor` instead of `for`. `aria-` and `data-` attributes keep their dashes. When I need a root but not an extra element, I use a Fragment, written `<>` and `</>`. It groups the elements and leaves nothing in the DOM, so lists and grid layouts keep working.
