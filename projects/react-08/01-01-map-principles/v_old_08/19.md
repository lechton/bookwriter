## Authorized Scope
Lesson 19 teaches how to change an array that lives in state. It works on one component, `NewsTicker`, which shows tonight's stories from a `stories` array. An array is an object, so the rule of Q18 holds. The setter compares arrays with `Object.is`, and only a new array leads to a render. Some array methods change the array in place: `push`, `splice`, `sort`, and `reverse`. After them, the setter gets the same array and React skips the render. So every change builds a new array. We remove with `filter`, add and insert with spread, and sort a copy or call `toSorted`. A copied array still holds the same story objects. So to correct one story, we use `map` and return a new object for that story. The lesson builds on Q11, which taught `map` and `filter`, and on Q12, which named the methods that change an array. It also builds on Q14, `useState`, and Q18, `Object.is` and object spread.

## Principles

### Principle 1: The setter skips the render when it gets the same array
- **Handle**: `same-array-no-render`
- **Kind**: Model
- **Reader Question**: "I call `stories.splice(1, 1)` and then `setStories(stories)`. Why does the typo story stay on screen?"
- **Reader Expects**: the story disappears; the array really lost an item, and the setter was called; a habit from plain JavaScript, where `splice` is the usual way to delete from a list
- **React Does**: `splice` removes the item from the array React already holds; `setStories(stories)` hands back that same array; `Object.is` finds the same array; React skips the render; no body log; the screen keeps "Typo storey"; a click on the unrelated Views button renders and shows two stories; `initialStories` is that same array, so Reset shows two stories too; `push`, `sort`, and `reverse` behave the same way
- **Placement**: the setter looks only at which array it receives, not at what is inside it; an array changed in place is still the current array
- **Real Mistake**: `stories.splice(1, 1); setStories(stories)`, the card's Friction: no body log, the screen keeps "Typo storey", and the story disappears only after a click on Views (React 19.3.0)
- **Fix In**: `filter-to-remove`
- **Importance**: the bank row's scenario; interviewers ask which array methods are safe on state; Q18's model now hides behind methods that do not look like assignments
- **Prediction**: `push`, `splice`, `sort`, or `reverse` on `stories` followed by `setStories(stories)` produces no body log; the next render caused by any other state shows the change.
- **Required Lesson Proof**: `NewsTicker` with `useState(initialStories)`, a body log, a Views counter, and a "Delete typo" button whose handler calls `stories.splice(1, 1)` and `setStories(stories)`; the click logs nothing and the screen keeps three stories; a click on Views logs a render and shows two.

### Principle 2: Remove with `filter`, which returns a new array
- **Handle**: `filter-to-remove`
- **Kind**: Decision
- **Reader Question**: "How do I delete the typo story without changing the array?"
- **Reader Expects**: some copying version of `splice`; the name `slice` looks like it, and both take an index; a habit from reading `slice` and `splice` as one method
- **React Does**: `stories.filter(s => s.id !== 2)` builds a new array with every story whose id is not 2; the old array is untouched; the setter gets a new array; React renders; the screen shows two stories; Reset shows three, because `initialStories` kept the typo story; `slice(1, 1)` copies the part from index 1 up to index 1, which is nothing; the setter gets an empty array and the ticker shows no stories
- **Placement**: `setStories(stories.filter(s => s.id !== id))`, filtering on the story's id, not its position; a fresh copy changed with `splice` before the setter also works; not `splice` on `stories`, and not `slice` in place of `splice`
- **Real Mistake**: `setStories(stories.slice(1, 1))`, written for `splice(1, 1)`: a render runs and the ticker empties (React 19.3.0)
- **Importance**: the "remove" of the interview question; the react.dev Pitfall on `slice` and `splice`
- **Review Point**: Do
- **Required Lesson Proof**: the "Delete typo" button of `NewsTicker` with `filter` on the id: the screen shows two stories, and Reset shows three; the same button with `slice(1, 1)`: the ticker empties.

### Principle 3: Add and insert with spread
- **Handle**: `spread-to-add`
- **Kind**: Decision
- **Reader Question**: "A late story comes in. How do I add it to the end, or between two stories?"
- **Reader Expects**: `push` and `splice`, but on the value the setter gets: `setStories(stories.push(lateStory))`; a habit from chaining array calls, as with `map` and `filter`
- **React Does**: `push` changes the array and returns its new length, 4; the setter stores the number 4; the next render calls `stories.map`, and a number has no `map`; the render throws "stories.map is not a function"; React removes the ticker from the page; `[...stories, lateStory]` copies every story into a new array and adds the late one at the end; React renders four stories; `[...stories.slice(0, 1), lateStory, ...stories.slice(1)]` puts it in second place; Reset shows the original three
- **Placement**: `setStories([...stories, lateStory])` at the end, `[lateStory, ...stories]` at the start, and two `slice` calls around it to insert; the late story gets its id in the handler, with the story
- **Real Mistake**: `setStories(stories.push(lateStory))`: the render throws "stories.map is not a function" and the ticker disappears (React 19.3.0)
- **Importance**: the "add" and "insert" of the interview question; `push` is the first method a JavaScript developer reaches for
- **Review Point**: Do
- **Required Lesson Proof**: an "Add late story" button on `NewsTicker` with `setStories(stories.push(lateStory))`: the ticker disappears with the error above; with spread: four stories, the late one last; an "Insert" button with two slices: the late story second; Reset: the original three.

### Principle 4: Sort a copy, never the array in state
- **Handle**: `sort-a-copy`
- **Kind**: Decision
- **Reader Question**: "I want the ticker sorted by time. Can I write `setStories(stories.sort(byTime))`?"
- **Reader Expects**: yes; `sort` returns the sorted array, and it goes straight to the setter, so this looks like a new value; a habit from chaining array methods that return new arrays
- **React Does**: `sort` reorders the array in place and returns that same array; the setter gets the current array; React skips the render; the screen keeps the old order; a click on Views shows the sorted order; Reset keeps it sorted, because `initialStories` was sorted too; `[...stories].sort(byTime)` sorts a fresh copy, and `stories.toSorted(byTime)` returns a sorted copy; React renders the new order, and Reset shows the original order
- **Placement**: `setStories(stories.toSorted(byTime))`, or `setStories([...stories].sort(byTime))`; the same for reversing, with `toReversed()` or a copy; not `sort` or `reverse` on `stories`
- **Real Mistake**: `setStories(stories.sort(byTime))`: no body log, the order stays, and Reset later shows the sorted order (React 19.3.0)
- **Importance**: the "reorder" of the interview question and the card's Friction; reviewers flag `sort` on state because it returns a value and looks safe
- **Review Point**: Do
- **Required Lesson Proof**: a "Sort by time" button on `NewsTicker` with `stories.sort(byTime)` passed to the setter: no body log; a click on Views shows the order 19, 20, 21, and Reset keeps it; with `toSorted`: the order changes at once, and Reset brings back 21, 19, 20.

### Principle 5: To change one item, copy that item too
- **Handle**: `copy-changed-item`
- **Kind**: Decision
- **Reader Question**: "I copied the array first, `const next = [...stories]`, then wrote `next[1].title = 'Corrected'`. The title changes. Is that fine?"
- **Reader Expects**: yes; spread made a new array, so changing it is safe; the same habit as Q18's shallow copy, now hidden by the array
- **React Does**: spread copies the array, not the story objects inside it; `next[1]` is the same object as `stories[1]` and `initialStories[1]`; the assignment changes that shared object; `next` is a new array, so React renders and the screen shows "Corrected"; Reset passes `initialStories`, whose second story now says "Corrected"; `stories.map(s => s.id === 2 ? { ...s, title: 'Corrected' } : s)` returns a new array with a new object for the changed story and the same objects for the rest; the screen shows "Corrected", and Reset shows "Typo storey"
- **Placement**: `setStories(stories.map(s => s.id === id ? { ...s, title } : s))`; not an assignment to an item of a copied array, and not an assignment inside `map`
- **Real Mistake**: `const next = [...stories]; next[1].title = 'Corrected'; setStories(next)`, the card's Friction: the screen shows "Corrected", and Reset also shows "Corrected" instead of "Typo storey" (React 19.3.0)
- **Importance**: the card's Core Truth; the copy passes a quick review and still changes old state; interviewers ask what a copied array shares
- **Review Point**: Do
- **Required Lesson Proof**: a "Correct typo" button on `NewsTicker` with the copied array and the assignment, then Reset: "Corrected" stays; with `map` and an object copy, then Reset: "Typo storey" comes back.

## Senior Answer
I treat an array in state as read-only, just like an object. The setter compares arrays by reference. If I call `push`, `splice`, or `sort` on the array, it is still the same array. So React skips the render, and the screen shows the old list. Instead, every change builds a new array. To remove, I use `filter` on the item's id. To add, I spread the old array and put the new item at the end or the start. To insert, I spread two slices around the new item. To reorder, I sort a copy, or call `toSorted`. Copying the array does not copy the items inside it. So to change one item, I use `map` and return a new object for that item, with object spread. The other items stay as they are. When the copies get deep, Immer can write them for me.
