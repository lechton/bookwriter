## Authorized Scope
Lesson 08 teaches how to split components into files. Each file is a module: its names stay inside it until it exports them, and another file uses them only by importing them. A default export is imported without braces and under any name. A named export is imported inside braces, with its exact name. The import must match the export, or the page stops before anything runs. A file has one default export at most, for its main component, and named exports for the rest. An import path starts from the file that imports, so a file in `components` reaches its neighbor with `./`. The lesson moves Town News's card, badges, and feed out of `App.jsx` into a `components` folder. It builds on Q05, where a name outside a component's scope throws, and ends the single file kept since Q02.

## Theme and Options
- **Theme**: A project grows past one file. How does a component written in one file get used in another?
- **Options**: none (starting point: every component lives in `App.jsx`, Lectures 2 to 7)

## Principle Thread
- **Anchor**: Each file is a module: its names stay inside until it exports them, and another file uses them only by importing them
- **Axis**: the move of one component to its own file: the file it lands in, the import that must match its export, the kind of export it gets, and the path that finds it
- **Why This Axis**: The reader first meets the wall around a file: the moved component is gone from `App.jsx` until something crosses the wall. The crossing comes next, export and import, and its first failure is a mismatch of the two forms. Choosing between the forms needs both in hand, so it comes third. Paths come last, because they only become a problem once a second file moves into the folder and imports its neighbor. One axis was rejected. "Exporting side, importing side" splits each form into two halves and leaves the path with no place.
- **Spoken Preview**: Everything in this lesson comes down to one idea: each file is a module, and its names cross to another file only by export and import. First, modules, which means each file keeps its names to itself until it exports them: a moved component is gone from the old file until the new file exports it and the old one imports it. Second, imports match exports, which means braces for a named export, none for the default: the wrong form stops the page before anything runs. Third, default and named exports, which means one default for the file's main component, named exports for the rest: a file has one default at most. Fourth, import paths, which means a path starts from the file that imports: a file in the components folder reaches its neighbor with a dot and a slash.
- **Closing Line**: One wall per file, an import that matches, one default, and a path from here.

## Principles

### Principle 1: Modules: each file keeps its names to itself until it exports them
- **Handle**: `file-is-module`
- **Thread Step**: the file it lands in
- **Rule**: We treat each file as a module: a component moved to its own file is exported there with `export`, and imported with `import` by every file that uses it; a function only its file uses stays unexported.
- **Kind**: Model
- **Reader Question**: "I moved `ArticleCard` into its own file. Why does `App` say it is not defined?"
- **Reader Expects**: every file of the project sees every other file's functions, as scripts loaded on one HTML page do
- **React Does**: each file is a module with its own scope, like a function's in Lecture 5; the moved `ArticleCard` exists only inside `ArticleCard.jsx`, so `App`'s `<ArticleCard />` meets a name that does not exist there and throws "ArticleCard is not defined"; `export` opens one name to other files, and `import` brings it in; an import of a name the file never exported stops the page before anything runs; a module's top level runs once, however many files import it; a file with JSX needs the `.jsx` name
- **Placement**: `export default function ArticleCard(...)` in `src/components/ArticleCard.jsx`; `import ArticleCard from './components/ArticleCard.jsx'` at the top of `App.jsx`
- **Real Mistake**: `ArticleCard` cut from `App.jsx` and pasted into `components/ArticleCard.jsx` with no `export`, and no `import` in `App.jsx`; the page goes empty, and the console shows "ArticleCard is not defined"; with the `export` and the `import`, the card shows; verified in React 19.3.1, Vite 8.3.4, and Chrome
- **Fix In**: this principle
- **Importance**: the card's Friction (the 1,200-line `App.jsx`); every project from here on has many files; the first error every split meets
- **Prediction**: a `console.log` at the top of `Badge.jsx` prints once though two files import it, while a log inside `Badge` prints on every render; `formatTitle`, left unexported in `ArticleCard.jsx`, is "not defined" in `App.jsx`
- **Required Lesson Proof**: `ArticleCard` moved with no export and no import: the error; with both: the card; the unexported helper: the error in `App.jsx`; the run-once log.

### Principle 2: Imports match exports: braces for a named export, none for the default
- **Handle**: `import-matches-export`
- **Thread Step**: the import that must match its export
- **Rule**: We write each import in the form of its export: no braces for a default export, under any name we choose, and braces with the exact name for a named export.
- **Kind**: Decision
- **Reader Question**: "Do I write braces around the name or not?"
- **Reader Expects**: the braces are optional, or the name alone finds the function, because both lines name the same component
- **React Does**: the browser links the modules before any code runs; `import ArticleCard from` asks the file for its default export, and `import { ArticleCard } from` asks for an export named `ArticleCard`; when the file has no such export, the browser stops loading the page with "The requested module ... does not provide an export named 'default'", and `vite build` stops with `[MISSING_EXPORT]`; a default import can take any name, while a named import must spell the name exactly; `import * as` turns a mismatch into `undefined`, which reaches React as "Element type is invalid ... got: undefined"
- **Placement**: `import ArticleCard from './components/ArticleCard.jsx'` for `export default`; `import { Badge } from './components/Badge.jsx'` for `export function Badge`
- **Real Mistake**: `components/ArticleCard.jsx` with `export function ArticleCard`, and `import ArticleCard from './components/ArticleCard.jsx'` in `App.jsx`; the page stays empty, and the console shows "The requested module '/src/components/ArticleCard.jsx' does not provide an export named 'default'"; `vite build` fails with `[MISSING_EXPORT] "default" is not exported by "src/components/ArticleCard.jsx"`; `import { ArticleCard }` fixes it; verified in Vite 8.3.4 and Chrome
- **Importance**: the bank question's second part; the card's Friction; reviewers and interviewers expect the rule
- **Review Point**: Do not
- **Required Lesson Proof**: the four pairings of export and import: two load, two stop with the message; the default imported as `StoryBox`: the card shows.

### Principle 3: Default and named exports: one default for the file's main component, named exports for the rest
- **Handle**: `default-or-named`
- **Thread Step**: the kind of export it gets
- **Rule**: We give a file at most one default export, for its main component, and we export its other components with names; a file of several small components uses named exports only, and every exported function keeps a name.
- **Kind**: Decision
- **Reader Question**: "Should the badges be default or named exports?"
- **Reader Expects**: `export default` on everything, as `App` has had since Lecture 1
- **React Does**: a module has one default slot, so a second `export default` stops the build with "A module cannot have multiple default exports."; named exports have no limit; a file with one main component often exports it as the default, and a file of several equal components exports each by name; teams often keep one style to avoid mixing; an exported function needs a name of its own: `export default () => ...` gets the name "default"
- **Placement**: `export default function CardContainer` in `CardContainer.jsx`; `export function LiveBadge` and `export function NewBadge` in `Badges.jsx`
- **Real Mistake**: `export default function Badge` added under `export default function ArticleCard` in the same file; the page stays empty, and the overlay shows "[PARSE_ERROR] A module cannot have multiple default exports."; `export function Badge` with `import ArticleCard, { Badge }` shows both; verified in Vite 8.3.4 and Chrome
- **Importance**: the bank question's distinction; react.dev's convention; reviewers flag nameless default exports
- **Review Point**: Prefer
- **Required Lesson Proof**: two default exports in one file: the overlay; one default and one named: both components; the nameless default: its name "default".

### Principle 4: Import paths: a path starts from the file that imports
- **Handle**: `import-paths`
- **Thread Step**: the path that finds it
- **Rule**: We write each import path from the folder of the file that imports: `./` for a file beside it, `../` for the folder above, and no dot at all for a package such as `'react'`.
- **Kind**: Decision
- **Reader Question**: "I moved the feed into `components`. Why can't it find the card?"
- **Reader Expects**: paths start from the project, or from `App.jsx`, so the import lines can be copied from file to file
- **React Does**: the build reads each path from the folder of the file that holds the import; `./components/CardContainer.jsx` from `App.jsx` means `src/components/CardContainer.jsx`, but the same line inside `components/EditorialFeed.jsx` means `src/components/components/CardContainer.jsx`, which does not exist; Vite stops with "Failed to resolve import ... Does the file exist?"; `./CardContainer.jsx` finds the neighbor; a package name such as `'react'` has no dot, because it points into the installed packages; the `.jsx` at the end may be left out
- **Placement**: `'./components/EditorialFeed.jsx'` in `App.jsx`; `'./CardContainer.jsx'` and `'./Badges.jsx'` in `components/EditorialFeed.jsx`
- **Real Mistake**: `components/EditorialFeed.jsx` with `import CardContainer from './components/CardContainer.jsx'`, copied from `App.jsx`; the page stays empty, and the overlay shows "Failed to resolve import "./components/CardContainer.jsx" from "src/components/EditorialFeed.jsx". Does the file exist?"; `'./CardContainer.jsx'` loads it; verified in Vite 8.3.4 and Chrome
- **Importance**: the first file moved into a folder that imports a neighbor meets it; copying import lines between files is the habit that causes it
- **Review Point**: Do
- **Required Lesson Proof**: the copied path inside `components`: the overlay; the path from the file's own folder: the feed.

## Senior Answer
Each file is an ES module with its own scope. A component in one file is invisible to the others until its file exports it and the other file imports it. A file can have one default export, usually its main component, and any number of named exports. A default export is imported without braces, under any name I choose. A named export is imported with braces and its exact name. If the forms do not match, the browser stops before anything runs. It reports that the module "does not provide an export named default", and the production build reports a missing export. I keep one main component per file as the default. Small related components get named exports, and every exported function keeps a name. Import paths start from the importing file. A file in `components` imports its neighbor with `./`, and a package such as `react` has no dot.
