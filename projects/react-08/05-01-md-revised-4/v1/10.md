# Lecture 10: Conditional Rendering in React
> INTERVIEW QUESTION | ❱ CORE | How do you show, hide, or switch JSX based on a condition?

::: pagebreak

## Example: article cards on a news site

The example for this whole lecture is a small news site. Its home page lists the latest articles, and each article appears as a card with a title, the author's name, and a short summary. The page runs on Vite, the development server that serves it at `localhost:5173` and shows the changes as we save. Here is the page as a signed-in reader sees it:

```page caption="The home page of the news site. Outlined in green: the two parts that only the park card shows."
heading: Latest Articles
card: title=New Park Opens Today | author=Mary Jones | text=The park on Main Street opens at noon. | label=New | foot=3 comments | good=label,foot
card: title=Rain Expected This Weekend | author=Oliver Brooks | text=Heavy rain is expected on Saturday and Sunday.
```

Look closely: the two cards do not show the same parts. The park card has a red "New" label above its title; the rain card has none. The park card ends with "3 comments"; the rain card has no comment line at all. Yet one component drew both cards, so something inside that component decided, card by card, what to show. Each thing you see follows a rule of the form IF something is true, THEN show this part:

| on the page | the rule behind it |
| --- | --- |
| a red New label on the park card only | IF the article is new, THEN show the New label |
| "3 comments" on the park card only | IF the article has comments, THEN show the comment count |
| a summary on both cards, for this signed-in reader | IF the reader is signed in, THEN show the summary, ELSE a sign-in prompt |

The park article is new and has 3 comments, so both of the first two rules show their part. The rain article is not new and has no comments, so neither part appears. A visitor who is not signed in would see a sign-in prompt in place of each summary.

Showing a part of the page only when a condition holds is called **conditional rendering**, and it is the topic of this lecture: how does one React component show a part in one case and leave it out in another?

## The components behind the page

Three components draw this page. Each one either holds data or receives it from its parent as props, and the data flows down, from parent to child:

```hierarchy layout=stack caption="The components of the news site, and what each one holds or receives."
App | holds: `featured` (`null` today) and `isSignedIn`
  ArticleCard | gets: `article` (the featured one), `isSignedIn`
  ArticleList | gets: `isSignedIn` | holds: two articles
    ArticleCard | gets: `article`, `isSignedIn`
    ArticleCard | gets: `article`, `isSignedIn`
notes:
`App` is the whole page. It knows whether the reader is signed in, and it has a slot for a featured article at the top; today there is no featured article, so `featured` is `null`.
`App` passes its featured article, and `isSignedIn`, to an `ArticleCard`.
`ArticleList` holds the two articles, park and rain, and passes each one, with `isSignedIn`, to a card of its own.
Every card is the same component, `ArticleCard`; only the props it receives differ. So the rules above are written inside `ArticleCard`, reading its props; section 2 shows the one case where `App` decides instead.
```

Each article is one object. `ArticleList` keeps the two objects at the top of its file and passes each one to a card as its `article` prop:

```jsx title="ArticleList.jsx" good="14-15"
const park = {
  title: 'New Park Opens Today', author: 'Mary Jones',
  summary: 'The park on Main Street opens at noon.',
  ~isNew: true, commentCount: 3~, // New, with 3 comments: the label and the count show
};
const rain = {
  title: 'Rain Expected This Weekend', author: 'Oliver Brooks',
  summary: 'Heavy rain is expected on Saturday and Sunday.',
  ~isNew: false, commentCount: 0~, // Not new, no comments: neither part shows
};
export default function ArticleList({ isSignedIn }) {
  return (
    <section>
      <ArticleCard ~article={park}~ isSignedIn={isSignedIn} /> {/* Each card receives one article object */}
      <ArticleCard article={rain} isSignedIn={isSignedIn} />
    </section>
  );
}
```

So inside `ArticleCard`, each rule reads a field of the article it received: "the article is new" is `article.isNew`, "the article has comments" depends on `article.commentCount`, and "the reader is signed in" is the prop `isSignedIn`. React calls `ArticleCard` again whenever its parent renders it again, for example with new props, and each call returns the JSX for the card.

## Two ways to show a part only in some cases

React builds elements in the DOM; the browser then draws them on the screen. So a part that appears only in some cases can be stopped at either step:

```tree caption="Two ways to keep a part off the page: stop the browser drawing it, or stop React building it."
Show a part only in some cases
- Hide it | the element is built, but the browser does not draw it
- Leave it out | the component does not return it, so React builds nothing
```

> [!FACT] `!` turns `true` into `false` and `false` into `true`, so in the left panel below, `hidden={!article.isNew}` hides the label exactly when the article is not new. `!` works on any value: in a condition, `null`, `undefined`, `0`, and `''` count as false, so `!article` is `true` when `article` is `null`.

::: row caption="The rain article is not new, so isNew is false. In both versions the rain card shows no label; only the DOM differs."
::: col title="Hide it" tag="the browser" tone=plain
```jsx
<span className="new-label" hidden={!article.isNew}>New</span>
```
```dom title="Elements panel: the rain card"
<article class="card">
*  <span class="new-label" hidden="">New</span>
  <h2>Rain Expected This Weekend</h2>
```
For the rain card, `!article.isNew` is `true`, so the span is still there with `hidden` on it, and the browser applies `display: none`.
:::
::: col title="Leave it out" tag="React" tone=good
```jsx
{article.isNew && <span className="new-label">New</span>}
```
```dom title="Elements panel: the rain card"
<article class="card">
  <h2>Rain Expected This Weekend</h2>
```
For the rain card, `article.isNew` is `false`, so there is no span at all. With a true or false value such as `article.isNew`, this line gives the span when the value is true and nothing when it is false; section 2 shows how `&&` works, and the one value where it surprises.
:::
:::

Why does the difference matter? In two cases. When the data is missing, hidden JSX still runs: `<h2 hidden={!article}>{article.title}</h2>` still reads `article.title`, and throws when `article` is `null`, as section 1 shows. JSX that is left out never runs. And when the part holds something the user typed into it, and the typed text lives inside that part, hiding keeps the text, while leaving the part out throws it away. So the test is one question: must the part keep what is inside it while it is gone? If yes, hide it. If no, leave it out; that is the right choice for every part that only depends on data, such as the New label, which depends only on `article.isNew`. That is conditional rendering: each time React calls a component, the component chooses which JSX to return, using plain JavaScript.

## Conditional rendering: what the choice covers, then how many outcomes

Call each part of the card's JSX that may or may not appear a **piece** (the rest of this lecture uses the two words alike): the New label, the comment count, the summary. A choice can cover the whole component, or a piece inside its JSX; for a piece, the tool depends on how many outcomes the choice has:

```tree caption="The four kinds of choice: first what the choice covers, then how many outcomes it has."
Leave it out: conditional rendering
- The whole card, or nothing | decided at the top of the function
  - No card at all | `return null` in the card, or the parent leaves the card's tag out
- A piece inside the card | decided in the JSX, or above the `return`
  - One piece, or nothing | `&&`
  - One of two pieces | the ternary, `? :`
  - One of three or more | `if` and a variable
```

In short: when the whole component has nothing to show, `return null`; when one piece shows or not, `&&`; when one of two pieces always shows, the ternary; when there are three or more outcomes, `if` and a variable. We take the four in this order, because each builds on the one before.

## 1. No card at all: return null at the top

```tree size=mini here="No card at all"
Leave it out: conditional rendering
- The whole card, or nothing
  - No card at all
- A piece inside the card
  - One piece, or nothing
  - One of two pieces
  - One of three or more
```

> [!PRINCIPLE]
> **Principle 1: No card at all: return null at the top**
>
> When a component has nothing to show for its props, it returns `null`.
>
> The `if` goes at the very top, before any line reads the missing data. When the parent decides whether the component appears at all, the parent leaves out its tag instead; section 2 shows how.
>
> *We should do this:*
>
> ```jsx
> function Profile({ user }) {
>   if (!user) {
>     return ~null~; // No user: this card shows nothing, the rest of the page stays
>   }
>   return <h2>{user.name}</h2>;
> }
> ```
>
> *We should not do this:*
>
> ```jsx
> function Profile({ user }) {
>   return <h2>{~user.name~}</h2>; // **WRONG:** user is null, so reading its name throws
> }
> ```

The first choice decides whether the component shows at all: the whole card when its data is there, nothing when it is missing.

```hierarchy
App | holds: `featured = null`
  ArticleCard | gets: `article`, which is `null` | here: returns the card, or null
notes:
`App` has no featured article today, so `featured` is `null`.
`App` still renders `<ArticleCard article={featured} isSignedIn={isSignedIn} />`, so the card receives `null` as its `article`.
The card's JSX reads `article.title` right away.
We want: no featured card, and the rest of the page still there.
```

The card, as written so far, reads the title straight away, even when `article` is `null`:

```jsx title="ArticleCard.jsx" bad="4"
export default function ArticleCard({ article, isSignedIn }) {
  return (
    <article className="card">
      <h2>{~article.title~}</h2> {/* **WRONG:** article is null, so reading its title throws */}
```

> [!FACT] Reading a property of `null` throws a `TypeError`. Optional chaining, `?.`, reads it safely instead: `null?.title` gives `undefined`.

When `article` is `null`, the three versions below give three different pages. They differ in how the card reads `article`: plainly, as in `article.title`; with `?.` on every read, as in `article?.title`, `article?.author`, and `article?.summary`; or after an `if` placed at the top of the card. The cards are cropped to their title and author:

::: row caption="Three versions of ArticleCard, with article set to null. The featured card would sit right under the site heading."
::: col title="`article.title`" tone=bad
```page size=mini
blank
console: TypeError: Cannot read properties of null (reading 'title')
```

:::

```page size=mini

card: ghost | bad=card
card: title=New Park Opens Today | author=Mary Jones
card: title=Rain Expected This Weekend | author=Oliver Brooks
```
With `article` set to `null`, every read with `?.` gives `undefined`: no crash, but an empty card box stays where the featured card would be.

```page size=mini

```
With `article` set to `null`, the `if` returns `null` before any line reads `article`: no featured card, and the page stays.

```chain caption="Why each version gives its page, when article is null."
!`article.title` -> throws a `TypeError` -> nothing catches the error, so React blanks the whole page
!`article?.title` -> gives `undefined`, no crash -> React still builds the empty `<article>` box
+`if (!article) return null` -> no line reads `article` -> `null` builds nothing, the page stays
```

The fix goes at the very top of `ArticleCard`, before the `return` that builds the card, so that when `article` is `null` the function stops before any line reads it:

```jsx title="ArticleCard.jsx" good="2-4"
export default function ArticleCard({ article, isSignedIn }) {
  if (!article) {
    return ~null~; // Article is null: the card stops here and builds nothing
  }
  return (
    <article className="card">
      <h2>{article.title}</h2>
```

A `return` inside an `if` ends the function early, so when the condition holds, no later line runs: an **early return**. When `article` is an object, the `if` is skipped and the card is built as before.

The card still runs when it returns `null`; it only builds nothing. With the early return in place and `featured` set to `null`, a `console.log('card runs')` on the first line of `ArticleCard` prints for all three cards, the featured one included:

```console title="Console, with featured set to null and the early return in place"
log: card runs
log: card runs
log: card runs
log: card runs
log: card runs
log: card runs
```

Six lines for three cards, because the app is wrapped in `<StrictMode>`, as Vite's starter project does, and in development Strict Mode runs each component twice to help catch mistakes. The featured card ran, and returned nothing. Who decides that nothing shows can be the card itself, as here, or its parent:

```tree dir=right
Nothing to show: who decides?
- The card itself | when `article` is `null` and nothing outside the card has to go with it: `if (!article) return null`, at its very top
- The parent | when the parent has no article to show and owns markup around the card, such as a heading: it leaves the card's tag out (section 2)
```


## 2. One piece, or nothing: a true or false value left of &&

```tree size=mini here="One piece, or nothing"
Leave it out: conditional rendering
- The whole card, or nothing
  - No card at all
- A piece inside the card
  - One piece, or nothing
  - One of two pieces
  - One of three or more
```

> [!FACT] The common **falsy** values, the ones that count as false in a condition, are `false`, `0`, `''`, `null`, `undefined`, and `NaN`. `&&` gives back its left side when that side is falsy, and its right side otherwise. In JSX, React shows nothing for `false`, `null`, and `undefined`, but it shows a number as text.

> [!PRINCIPLE]
> **Principle 2: One piece, or nothing: `&&` with a true or false value on the left**
>
> To show a piece or nothing, we write `condition && <Piece />`.
>
> The left side must be a true or false value, such as `count > 0`. Notice: a bare number on the left shows on the page when it is 0.
>
> *We should do this:*
>
> ```jsx
> function Inbox({ count }) {
>   return (
>     <div>
>       {~count > 0~ && <p>{count} messages</p>} {/* Count is 0: false, so nothing shows */}
>     </div>
>   );
> }
> ```
>
> *We should not do this:*
>
> ```jsx
> function Inbox({ count }) {
>   return (
>     <div>
>       {~count~ && <p>{count} messages</p>} {/* **PROBLEMATIC:** count is 0, so the page shows 0 */}
>     </div>
>   );
> }
> ```

Section 1 removed the whole card when its data was missing. Now the card is there, and one piece inside it appears on some cards and not on others.

```hierarchy
ArticleList | holds: park (new, 3 comments) and rain (not new, 0 comments)
  ArticleCard | gets: the park `article` | here: shows each piece, or not
  ArticleCard | gets: the rain `article` | here: shows each piece, or not
notes:
`ArticleList` renders one `ArticleCard` for each article.
Each card receives one article object, with `isNew` and `commentCount`.
The New label belongs only to new articles; the comment line only to articles with comments.
We want: the park card (new, 3 comments) shows both pieces; the rain card (not new, 0 comments) shows neither.
```

Inside the card's `return`, a first version uses `&&` for both pieces: the label above the title, meant to show when `article.isNew` is true, and the comment line below the summary, meant to show when `article.commentCount` is not zero:

```jsx title="ArticleCard.jsx" bad="7" startLine="5"
  return (
    <article className="card">
      {~article.isNew~ && <span className="new-label">New</span>} {/* True or false: New, or nothing */}
      <h2>{article.title}</h2>
      <p className="author">{article.author}</p>
      <p>{article.summary}</p>
      {~article.commentCount~ && <p>{article.commentCount} comments</p>} {/* **PROBLEMATIC:** 0 comments, so the page shows 0 */}
    </article>
  );
```

Rendered for both cards, this first version gives:

```page caption="Look at the rain card, which is not new and has 0 comments: no label, as wanted, but a bare 0 under its summary, where the comment line would be. The park card is right."
heading: Latest Articles
card: title=New Park Opens Today | author=Mary Jones | text=The park on Main Street opens at noon. | label=New | foot=3 comments
card: title=Rain Expected This Weekend | author=Oliver Brooks | text=Heavy rain is expected on Saturday and Sunday. | raw=0 | bad=raw
```

So, as the falsy fact above the box said, `&&` is not an inline `if`: it gives back one of its two sides, and the page shows whatever it gave back. For each card, the table follows the left side to the page:

| card | left side | && gives back | the page shows |
| --- | --- | --- | --- |
| park | `isNew: true` | `<span>New</span>` | New |
| rain | `isNew: false` | `false` | nothing |
| park | `commentCount: 3` | `<p>3 comments</p>` | 3 comments |
| !rain | `commentCount: 0` | `0` | 0 |

> [!FACT] A **comparison** gives `true` or `false`: `count > 0` asks whether `count` is greater than 0, `count === 1` whether it is exactly 1, and `featured !== null` whether `featured` is anything other than `null`.

A comparison always gives a real `true` or `false`, so it is a safe left side. For the rain card, `0 > 0` gives `false`, and the page shows nothing; for the park card, `3 > 0` gives `true`, and the page shows "3 comments":

```jsx title="ArticleCard.jsx" good="1" startLine="11"
      {~article.commentCount > 0~ && <p>{article.commentCount} comments</p>} {/* A comparison: true or false, never a bare 0 */}
```

```tree dir=right
What stands left of &&?
- +a true or false value on the left | the piece when true, nothing when false: `article.isNew`, `article.commentCount > 0`
- !a number on the left, such as `article.commentCount` | when it is `0`, as on the rain card, `0` itself appears on the page
```

Seen from a parent, a child component is just one piece of the parent's JSX, so a parent uses the same `&&` to leave a whole child out: the other way to show no card at all, which section 1 named. Suppose `App` puts a "Featured today" heading above the featured card. Only `App` can remove that heading: it belongs to `App`, so the card's `return null` would leave the heading above an empty space. `App` leaves both out together, with a comparison on the left, inside its own `return`, where the featured slot goes:

```jsx title="App.jsx" good="3,8"
return (
  <main>
    {~featured !== null~ && ( /* No featured article: no heading and no card */
      <section className="featured">
        <h2>Featured today</h2>
        <ArticleCard article={featured} isSignedIn={isSignedIn} />
      </section>
    )}
    <ArticleList isSignedIn={isSignedIn} />
  </main>
);
```

When `featured` is `null`, the comparison gives `false`, so neither the heading nor the card appears, and the card never runs: the `console.log` from section 1 now prints four lines, for the two list cards only. When `featured` is an article, the comparison gives `true`, and both appear. The card still keeps its own `if (!article) return null`, for any other parent that passes `null`.


## 3. One of two pieces: a ternary around the piece that differs

```tree size=mini here="One of two pieces"
Leave it out: conditional rendering
- The whole card, or nothing
  - No card at all
- A piece inside the card
  - One piece, or nothing
  - One of two pieces
  - One of three or more
```

> [!FACT] The ternary `condition ? a : b` gives `a` when the condition is true and `b` otherwise. Each box shows a whole small component. In the box below, `name` stands for the title, `<Summary />` and `<SignInPrompt />` for the two paragraphs.

> [!PRINCIPLE]
> **Principle 3: One of two pieces: a ternary around the piece that differs**
>
> To show one of two pieces in the same place, we write `condition ? <A /> : <B />` inside the JSX.
>
> The markup both cases share is written once, outside the ternary. Two whole returns fit only when the two cases share nothing.
>
> *We should do this:*
>
> ```jsx
> function Card({ name, isSignedIn }) {
>   return (
>     <article>
>       ~<h2>{name}</h2>~ {/* Shared by both readers, so written once */}
>       {~isSignedIn ? <Summary /> : <SignInPrompt />~} {/* The only part that differs between readers */}
>     </article>
>   );
> }
> ```
>
> *We should not do this:*
>
> ```jsx
> function Card({ name, isSignedIn }) {
>   if (isSignedIn) {
>     return <article><h2>{name}</h2><Summary /></article>;
>   }
>   return <article>~<h2>{name}</h2>~<SignInPrompt /></article>; // **PROBLEMATIC:** the same h2 again
> }
> ```

With `&&`, the piece shows or nothing does. Now one of two pieces must always show in the same place, depending on the reader: the summary when the reader is signed in, the sign-in prompt when not.

```hierarchy
ArticleList | gets: `isSignedIn`
  ArticleCard | gets: `article`, `isSignedIn` | here: summary, or sign-in prompt
notes:
`ArticleList` passes `isSignedIn` on to every card.
Signed-in readers see the summary; visitors see a sign-in prompt in its place.
Everything else on the card is the same for both readers: the New label, the title, the author, the comment line.
We want: the shared parts written once, so a later change reaches both readers.
```

Suppose the card had been split into two whole returns, one for each kind of reader: when `isSignedIn` is true, the `if` returns the first; otherwise the second return runs:

```jsx title="ArticleCard.jsx" startLine="1"
export default function ArticleCard({ article, isSignedIn }) {
  if (!article) {
    return null;
  }
  if (~isSignedIn~) { // Signed in: this return runs, and the function ends here
    return <article className="card">...the card for signed-in readers...</article>;
  }
  return <article className="card">...the card for visitors...</article>;
}
```

Both returns carry the New label and the comment line. When section 2's `> 0` fix arrived, it went into the signed-in return only. Here is the rain card, with 0 comments, for each kind of reader:

::: row caption="The rain card, with 0 comments, seen by a signed-in reader and by a visitor: only the visitor's card shows the bare 0 again."
::: col title="The signed-in return, when `isSignedIn` is true" tone=plain
```jsx good="8-10"
<article className="card">
  {article.isNew && (
    <span className="new-label">New</span>
  )}
  <h2>{article.title}</h2>
  <p className="author">{article.author}</p>
  <p>{article.summary}</p>
  {~article.commentCount > 0~ && ( /* The fix reached this copy */
    <p>{article.commentCount} comments</p>
  )}
</article>
```
```page size=mini
card: title=Rain Expected This Weekend | author=Oliver Brooks | text=Heavy rain is expected on Saturday and Sunday.
```
:::
::: col title="The visitor return, when `isSignedIn` is false" tone=bad
```jsx bad="8-10"
<article className="card">
  {article.isNew && (
    <span className="new-label">New</span>
  )}
  <h2>{article.title}</h2>
```

Two returns copy the same markup, so every later change must be made twice; miss one copy, and the two cards drift apart. Between the two readers, only one paragraph really differs, the summary or the sign-in prompt, so only that paragraph should sit inside the choice.

> [!FACT] Inside JSX braces only an **expression** can go: code that gives a value. An `if` is a statement, so it cannot; the ternary, as the box at the top of this section showed, is an expression.

One `return`, with the ternary right where the paragraph goes: when `isSignedIn` is true it gives the summary, otherwise the prompt. Every shared part is written once, so the `> 0` fix now reaches both readers:

```jsx title="ArticleCard.jsx" good="10-14" startLine="1"
export default function ArticleCard({ article, isSignedIn }) {
  if (!article) {
    return null;
  }
  return (
    <article className="card">
      {article.isNew && <span className="new-label">New</span>}
      <h2>{article.title}</h2>
      <p className="author">{article.author}</p>
      {~isSignedIn~ ? ( /* Signed in: the summary; otherwise the prompt */
        <p>{article.summary}</p>
      ) : (
        <p>Sign in to read this article.</p>
      )}
      {~article.commentCount > 0~ && <p>{article.commentCount} comments</p>} {/* Written once: the fix reaches both readers */}
    </article>
  );
}
```

```tree dir=right
Do the two cases share markup?
- +Yes | one `return`, with a ternary around the part that differs
- No | separate returns are fine: in section 1, one case returns `null` and shares nothing with the card
```

A ternary always needs both sides. With only the first side written, `{isSignedIn ? <p>{article.summary}</p>}`, the build cannot read the file, and Vite covers the page with its dark error box, the **error overlay**:

```overlay size=mini
message: [PARSE_ERROR] Expected ':' but found '}'
file: src/components/ArticleCard.jsx
```

When one side is "nothing", the tool is section 2's `&&`.


## 4. One of three or more: if and a variable above the return

```tree size=mini here="One of three or more"
Leave it out: conditional rendering
- The whole card, or nothing
  - No card at all
- A piece inside the card
  - One piece, or nothing
  - One of two pieces
  - One of three or more
```

> [!PRINCIPLE]
> **Principle 4: One of three or more: `if` and a variable above the return**
>
> When a choice has more than two cases, we pick the piece with `if`, `else if`, and `else` above the `return`.
>
> We store it in a variable and place the variable in the JSX. A ternary inside another ternary works, but it is hard to read.
>
> *We should do this:*
>
> ```jsx
> function CountLabel({ count }) {
>   let label;
>   if (~count === 0~) { // One case per branch, read from top to bottom
>     label = 'None';
>   } else if (count === 1) {
>     label = 'One';
>   } else {
>     label = 'Many';
>   }
>   return <p>{~label~}</p>; // Holds the one word the if chain picked
> }
> ```
>
> *We should not do this:*
>
> ```jsx
> function CountLabel({ count }) {
>   return (
>     <p>{count === 0 ? 'None' : ~count === 1 ?~ 'One' : 'Many'}</p> {/* **PROBLEMATIC:** a ternary inside a ternary */}
>   );
> }
> ```

A ternary chooses between two outcomes. Now the design changes, and the choice gets three: instead of hiding the comment line when there are no comments, every card shows a comment line, worded for none (0), one (1), or many (2 or more).

```hierarchy
ArticleList | holds: the articles
  ArticleCard | gets: `article`, with its `commentCount` | here: picks the comment wording
notes:
The card already has the number it needs: `article.commentCount`.
The comment line must now read differently for none, one, and many comments.
We want: each case readable on a line of its own.
```

```chain caption="One wording for each count; 5 stands for any count of 2 or more."
`commentCount: 0` -> No comments yet
`commentCount: 1` -> 1 comment
`commentCount: 5` -> 5 comments
```

Both versions below start from `const count = article.commentCount;`, written right after the `if (!article) return null` check:

::: row caption="The same three wordings, for a count of 0, 1, or more, chosen two ways."
::: col title="A ternary inside a ternary, in the JSX" tone=bad
```jsx
<p className="comments">
  {count === 0
    ? 'No comments yet'
    : ~count === 1~ // **PROBLEMATIC:** a second ternary inside the first
      ? '1 comment'
      : count + ' comments'}
</p>
```
It gives the right wording for 0, 1, and 5, but to read it you pair each `:` with its `?`. Each new case adds another level.
:::
::: col title="`if`, `else if`, `else`, above the `return`" tone=good
```jsx
let commentText;
if (~count === 0~) { // One case per branch, top to bottom
  commentText = 'No comments yet';
} else if (count === 1) {
  commentText = '1 comment';
} else {
  commentText = count + ' comments';
}
```
```jsx
<p className="comments">{commentText}</p>
```
For a count of 0, the first branch runs; for 1, the second; for any other count, the `else`. One case per line, above the `return`; the JSX only places the result.
:::
:::

Both versions give the same comment lines:

```page caption="Both versions, for the park card with 3 comments and the rain card with 0. A card with 1 comment would read 1 comment."
heading: Latest Articles
card: title=New Park Opens Today | author=Mary Jones | text=The park on Main Street opens at noon. | label=New | foot=3 comments
card: title=Rain Expected This Weekend | author=Oliver Brooks | text=Heavy rain is expected on Saturday and Sunday. | foot=No comments yet | good=foot
```

The variable can hold JSX as well as text: `commentText = <em>No comments yet</em>;` works the same way. This settles where each tool goes, depending on whether it is an expression or a statement:

```tree dir=right
Where does the choice go?
- Inside the JSX braces | expressions only: `&&` and `? :`
- Above the `return` | statements: `if (!article) return null`, and `if` with a variable
```


## Putting the four together

The four tools in one card, as the four sections built it: `return null` when there is no article; `&&` for the New label, shown when the article is new; the ternary for the summary when `isSignedIn` is true and the sign-in prompt when it is false; and `if` with a variable for the comment wording: "No comments yet" for 0, "1 comment" for 1, and the count plus "comments" otherwise:

**DO THIS:**

```jsx right
export default function ArticleCard({ article, isSignedIn }) {
  if (!article) {
    return null;
  }
  const count = article.commentCount;
  let commentText;
  if (count === 0) {
    commentText = 'No comments yet';
  } else if (count === 1) {
    commentText = '1 comment';
  } else {
    commentText = count + ' comments';
  }
  return (
    <article className="card">
      {article.isNew && <span className="new-label">New</span>}
      <h2>{article.title}</h2>
      <p className="author">{article.author}</p>
      {isSignedIn ? <p>{article.summary}</p> : <p>Sign in to read this article.</p>}
      <p className="comments">{commentText}</p>
    </article>
  );
}
```

The same card with the four mistakes, marked in red: it reads `article` without checking it first, so the card throws a `TypeError` when `article` is `null` (line 2); it nests one ternary inside another (line 10); it copies the markup into two returns that have already drifted apart, so visitors lose the New label even on the new park card (lines 14 to 21); and it puts a bare number left of `&&`, so a visitor sees a bare 0 on the rain card, which has 0 comments (line 19):

**DO NOT DO THIS:**

```jsx wrong bad="2,10,14-21"
export default function ArticleCard({ article, isSignedIn }) {
  const count = article.commentCount;
  if (isSignedIn) {
    return (
      <article className="card">
        {article.isNew && <span className="new-label">New</span>}
        <h2>{article.title}</h2>
        <p className="author">{article.author}</p>
        <p>{article.summary}</p>
        <p>{count === 0 ? 'No comments yet' : count === 1 ? '1 comment' : count + ' comments'}</p>
      </article>
    );
  }
  return (
    <article className="card">
      <h2>{article.title}</h2>
      <p className="author">{article.author}</p>
      <p>Sign in to read this article.</p>
      {count && <p>{count} comments</p>}
    </article>
  );
}
```

## For the interview

- **Is `&&` an inline `if`?** No. It gives back one of its two sides, so `0 && <Badge />` gives back `0`, and React shows it. Put a true or false value on the left: `count > 0 && <Badge />`.
- **Is returning `null` the same as leaving the tag out in the parent?** The page looks the same when the parent puts nothing around the tag; when the parent has its own markup there, such as a heading, only leaving the tag out removes that too. With `null`, the component still runs every time its parent renders, and a `console.log` inside it still prints. When the parent leaves the tag out, the component never runs.
- **Why not just `display: none`?** Two reasons. Hidden JSX still runs, so `<h2 hidden={!article}>{article.title}</h2>` still throws when `article` is `null`. And a hidden element stays in the DOM with what is inside it, such as typed text, while a part that is left out is removed and, when it comes back, built again, empty. So hide only a part that must keep what is inside it while it is gone.
- **`return null` or `return;` with no value?** `return;` gives `undefined`. Before React 18, returning `undefined` threw an error; now both show nothing. `null` says that the choice is on purpose.
- **Why would `<ArticleCard article={park} isSignedIn="false" />` show the summary to a visitor?** A prop written in quotes is text, and any non-empty text is **truthy**, the opposite of falsy, so the ternary takes its first side. `isSignedIn={false}`, in braces, passes a real `false`.

## Where you will meet this

- An unread badge, shown only when there are unread messages: `unread > 0 && <Badge />`, never `unread && <Badge />`, which shows a 0 when there are none.
- A header that shows "Sign in" when the reader is a visitor and an avatar when the reader is signed in: a ternary.
- An order status with one wording for each of four stages (placed, packed, shipped, delivered): an `if` chain into a variable.

## Summary

```tree caption="The whole lecture as one tree."
Show a part only in some cases
- Hide it | when the part must keep what is inside it while it is gone
- Leave it out | when the part only depends on data: conditional rendering
  - The whole card, or nothing | decided at the top of the function
    - No card at all | when there is nothing to show: `return null` at the top, or the parent leaves the tag out
  - A piece inside the card | decided in the JSX, or above the `return`
    - One piece, or nothing | `&&`, with true or false on the left
    - One of two pieces | the ternary, around the part that differs
    - One of three or more | `if` and a variable, above the `return`
```

**No card at all, one piece or nothing, one of two pieces, or one of three or more.**
