# Brief 2026-10-15-04: One File, Real Line Numbers

## Why

The owner looked at the case studies of Lectures 1 to 3 and saw code windows that made little sense on the page. The skills already had the rules: a file shown in parts is a continuation chain (`startLine`, `continues`), and the build colors each row by its line number, so a chain keeps one run of stripes. The lectures did not follow them. Every window started at line 1, wherever its lines sat in the file. One file was cut into several windows, each numbered from 1. Lines from two components shared one window, as "App.jsx (the two lines that change)". The labels in brackets on the tabs also hid the windows from the build's chain check, which grouped windows by an exact file name, so the build never warned.

One part was a real gap. The rules were written for React 07's case study, where each step adds the next lines of a file. The react-08 case study changes a file the reader has already seen (Lecture 3 pastes the old page and repairs it), and no rule said how a window shows a change. React 07 Lecture 16 had done it once, with the changed lines at their real `startLine`.

## Group 1: One File, Real Line Numbers (#2026_10_15_04_group_1)

- `code-blocks` Section 02: the tab of a window that shows part of a project file holds the file's name alone; the line numbers and the sentence before the window say which part it shows.
- `code-blocks` Section 06: an opening paragraph states the standard (a window is a view of a real file, numbered as the editor numbers it, stripes by line number); a chain may sit in one step or run across the steps that build a file; a proper example (Lecture 3, Step 1) and two counter-examples (the first Lecture 3 Step 1, and React 07 Lecture 8's chain that repeats line 10).
- `code-blocks` Section 06B (new): a window that shows a change carries the file's name, the real `startLine` counted after the change, no `continues`, one window per place, the file's indentation, and the changed part only when the component is longer than the ceiling; a proper example (Lecture 3, Steps 2 to 4) and a counter-example (the first Lecture 3, Step 2).
- `lecture-structure` Section 16, `pre-lecture` Section 13, `verification` Section 16 and its gate 4, `lecture-revision`, the skills README, and `produce_prompt.md` point to Sections 06 and 06B. The pre-lecture now plans the numbers, so the lecture author copies them.
- `src/build-lectures.mjs`: the chain check is rewritten. It warns about a tab with words after the file name, about a chain whose next window does not start right after the last row of the window above it (blank rows count; comment-only lines merge into the next row and take no number), about a chain that never closes, and about a window that shows the middle of a file (an indented first line, or one that starts with `return` or a tag) numbered from line 1. Chains are tracked per file across the lecture, so React 07's chains across steps still pass. The pipeline-figure check is kept.

The rule is a positive standard with paired examples. No ban was added: the bracketed labels go because the standard says what the tab holds.
