# Brief 2026-10-17-02: Charts, Principle Boxes, and Examples the Eye Can Read

## Why

After the summary skills were written (batch 01), the owner read Lecture 11 and named four defects. Charts used the map's spoken thread labels ("One name each", "The name's place") that read as riddles on a page: "We need an oracle to decode this one." The principle box came last, as one long sentence, with flags that named only the effect: "it makes little sense the principle to be in the end", "It's a huge sentence". The opening listed rules about topic sections and new articles that the picture never showed: "the eyes see these two, they do not visually correlate." And comparisons hid their code behind ellipses over examples too long to read: "it has to be simple and elegant." The owner also praised two charts, the "what each version gives back" chain and the "What gives back one element per item?" tree, as the model. The owner decided: the box goes at the start of each section, and the edition rewrites each rule in short sentences while the maps stay as they are.

## Group 1: The chart test (#2026_10_17_02_group_1)

`summary-figures` Section 02B: a chart passes when it is understood with the text covered. Boxes are built from what the reader sees, the root says what the chart is about, each connection has one meaning, every word points at something visible, keywords stand out. `summary-edition` no longer copies the map's thread labels into headings, charts, or the closing line when they read as riddles. Casebook Case 14.

## Group 2: The principle box first, in short sentences (#2026_10_17_02_group_2)

`summary-edition` Sections 07 and 12: the box opens each section after the "you are here" map; its rule is rewritten in short sentences keeping every condition of the map's Rule; cards are the shortest code that shows the rule; a flag names the cause on its line, then the effect. The build keeps a section's heading, map, facts, and box together, and the hierarchy panel names the choice (`here: chooses which cards to draw`). Casebook Case 15.

## Group 3: The opening points at the picture; claims checked by running them (#2026_10_17_02_group_3)

`summary-edition` Section 04: each rule of the opening stands beside the part of the page it explains, in a table "on the page / the rule behind it", and a rule about a part the reader cannot see waits, or the picture is drawn to show it. `summary-audit` Section 06: a reader's claim about runtime behaviour is checked by running React; two readers claimed a `<div>` inside a `<ul>` logs an error, and React 19.3.1 showed it does not.

## Group 4: Minimal examples (#2026_10_17_02_group_4)

`summary-edition` Section 11B: each side of a comparison shows the whole line that differs, with no ellipsis, and the example is designed so that line is short. The build drops line numbers on one-line snippets and keeps short inline code on one line. Casebook Case 16.
