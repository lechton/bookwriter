Lecture 11

Rendering Lists and Keys

Interview question❱ CORE
How do you render a list from an array, and why does React demand a key on every item?

A site shows the same kind of item many times: articles, comments, products. Only the data differs. Until now, ArticleList wrote one <ArticleCard /> tag per article, so thirty articles would need thirty tags. How does one array of articles become one card per article, and why does React ask for a key?

From one tag per article to one array

The articles move out of the JSX into one array in src/articles.js. Each article has an id, a number that belongs to that article and to no other.

articles.js
1export const articles = [
2 { id: 1, title: 'New Park Opens Today', author: 'Mary Jones', topic: 'City' },
3 { id: 2, title: 'Rain Expected This Weekend', author: 'Oliver Brooks', topic: 'Weather' },
4 { id: 3, title: 'Five Soups for Cold Days', author: 'Samantha Robinson', topic: 'Food' },
5];

That is rendering a list: an array of data becomes an array of elements, each with its own key.

Every item, only some items, one name each

1Every item: map() and an arrow that gives back

To stop writing tags by hand, we call articles.map(). We add a curly brace after the arrow, to leave room for a second line later:

ArticleList.jsx
1<main>
2 {articles.map(article => {
3 <ArticleCard article={article} />;
4 })}
5</main>

An arrow function gives back the expression right after =>. After => {, the body is a block, and it gives back only what return names; without return, it gives back undefined.

articles.map(article => { <Card />; })[undefined, undefined, undefined]no cards
articles.map(article => ( <Card /> ))[<Card>, <Card>, <Card>]three cards

map() calls the function once per item and collects what it gives back into a new array, and React shows an array of elements in order. A for loop cannot go inside the braces, because it is a statement, and forEach() gives back undefined, so neither shows anything.

ArticleList.jsx
1<main>
2 {articles.map(article => (
3 <ArticleCard article={article} />
4 ))}
5</main>
Principle 1
Mapping: turning every item into an element

To show one element per item, we call map() on the array inside the JSX, and its arrow function gives back the element: right after =>, or with return when the body starts with a curly brace.

We should do this
1{items.map(item => (
2 <Item item={item} /> {/* one element per item */}
3))}
We should not do this
1{items.map(item => {
2 <Item item={item} />; // PROBLEMATIC missing return renders nothing
3})}

2Only some items: filter() first, and a message for none

Each topic gets its own section. ArticleList receives a topic, keeps only that topic's articles with filter(), and maps what is left. App renders <ArticleList topic="City" /> and <ArticleList topic="Sport" />, and there is no Sport article yet.

ArticleList.jsx
1export default function ArticleList({ topic }) {
2 const shown = articles.filter(article => article.topic === topic);
3 return (
4 <section>
5 <h2>{topic}</h2>
6 {shown.length && (
7 shown.map(article => <ArticleCard article={article} />)
8 )}
9 </section>

filter() gives back a new array with only the items that pass the test. For Sport, that array is empty, its length is 0, and this is Lecture 10's trap again: 0 && ... gives back 0, and React draws numbers. A real comparison and a ternary give the reader a message:

ArticleList.jsx
1{shown.length > 0 ? (
2 shown.map(article => <ArticleCard article={article} />)
3) : (
4 <p>No {topic} articles yet.</p>
5)}
Principle 2
Filtering: turning only some items into elements

To show only some items, we call filter() before map(); when the filtered array can be empty, we test its length with > 0 and show a message instead.

We should do this
1const shown = items.filter(item => item.isOpen);
2{shown.length > 0 ? (
3 shown.map(item => <Item item={item} />) {/* cards */}
4) : (
5 <p>Nothing here yet.</p> {/* shown when array is empty */}
6)}
We should not do this
1const shown = items.filter(item => item.isOpen);
2{shown.length && shown.map(item => <Item item={item} />)} // PROBLEMATIC renders 0 on page

3One name each: a key from the item's id

The cards show fine, but the console warns:

ElementsConsole
!Each child in a list should have a unique "key" prop.

To see what the key does, we type "Great news!" into the comment box of the rain card. Then we add a new article, "Library Opens on Sundays", at the top of articles.js, and save.

When a list is shown again, React matches each new element with one it already built and keeps it. Without a key, it matches by position: the first with the first, the second with the second. The new article pushed every article down one place, so the second card on the page now receives the park article's data, while the text typed into its box stays where it was.

A key names each element. With key={article.id}, React matches by name: every article keeps its own element, and only the new article gets a new one. The four possible keys give four results after the same typing and the same save:

ArticleList.jsx
1{articles.map(article => (
2 <ArticleCard key={article.id} article={article} />
3))}

The index is a safe key only for a list that never inserts, deletes, or reorders, such as the links in a footer.

Principle 3
Keys: naming each element so React can tell the items apart

We give each element a key from the item's own id, so React matches every item with the same element the next time the list is shown; the array index fits only a list that never changes order, and a key made while rendering fits nothing.

We should do this
1{items.map(item => (
2 <Item key={item.id} item={item} /> {/* follows the item */}
3))}
We should not do this
1{items.map((item, index) => (
2 <Item key={index} item={item} /> {/* PROBLEMATIC index tracks position */}
3))}

4The name's place: on the tag inside map()

The Elements panel shows <article class="card"> many times, so the key seems to belong on the <article> inside ArticleCard. The warning stays.

map() gives back an array of <ArticleCard> elements, and those are the items React matches. The <article> inside the card is one element of the card's own markup, not an item of any array. The warning even names ArticleList, the component with the map().

React keeps the key for itself: the card never receives a key prop, and reading it gives undefined. A card that needs the id gets it again under another name, such as articleId={article.id}. An item made of several tags uses <Fragment key={article.id}>, because <> takes no key.

Principle 4
The key's place: naming the element the map gives back

We write the key directly on the tag the map() call gives back, never inside the child component and never inside a spread object, and when the child needs the id, we pass it again as a prop of its own.

We should do this
1{items.map(item => (
2 <Item key={item.id} item={item} /> {/* on the array item */}
3))}
We should not do this
1function Item({ item }) {
2 return <li key={item.id}>{item.name}</li>; // PROBLEMATIC warning stays
3}

For the interview

  • Why does React need a key? To match each item with the element it built last time. Without one, React matches by position, so an item added at the top moves typed text and focus to the wrong item.
  • Is key={index} fine? Only for a list that never inserts, deletes, or reorders. The index is the position, so it hides the warning and keeps the bug. Many tutorials use it on fixed lists with no inputs, where the bug never shows.
  • Why not key={Math.random()}? It changes on every render, so nothing matches, every element is built again, and typed text and focus are lost.
  • Must keys be unique on the whole page? No, only among the items of one array.
  • Can the child read its key? No. props.key is undefined; pass the id under another name.
  • Why does an empty list with length && show a 0? 0 && ... gives back 0, and React draws numbers. Write length > 0.

Where you will meet this

  • Every list from data: comments, search results, cart items, messages. Each comes from an array, goes through map(), and takes its key from the item's id.
  • Data from a server: each record already has an id that can be its key.
  • Rows with inputs, such as quantities in a cart or checkboxes in a to-do list: index keys move the entries to other rows when the list is sorted or an item is deleted.
