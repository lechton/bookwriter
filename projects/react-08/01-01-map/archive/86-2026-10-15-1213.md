# Q86: Ref Cleanup Functions in React 19
* **Topic Tag**: `#ref_cleanups` | `❱❱❱ ADVANCED`
* **Interview Question**: *How do React 19 ref cleanup functions work, and how do they eliminate memory leaks?*
* **Core Truth**: React 19 allows ref callbacks to return a cleanup function that executes when the DOM node unmounts or changes, mirroring `useEffect` cleanup and eliminating memory leaks from manual event listeners and third-party DOM widgets.
* **The Friction**: A developer binds a third-party charting library or canvas animator using a callback ref: `ref={node => { if (node) chart = new Chart(node); }}`. When the component unmounts, React traditionally called the callback with `null`, forcing awkward `if (node) ... else chart.destroy()` branching that developers frequently forgot, leaking memory.
* **The Mechanism**: Ref cleanup callbacks (`ref={node => { const chart = new Chart(node); return () => chart.destroy(); }}`). The cleanup function returned from the ref callback is called automatically by React when the DOM element is removed.
* **Under the Hood**: Commit phase cleanup lifecycle: when a ref callback returns a function, React stores the cleanup reference on the host fiber; upon unmounting or when the ref callback identity changes, React executes the cleanup function synchronously during DOM detachment.
* **The Code Experiment**:
  * *Naive*: Attaching an imperative library or resize observer in a callback ref without handling the `null` unmount phase, causing memory leaks.
  * *React*: A `NewsMapCanvas` component attaching a Leaflet map via `ref={el => { const map = init(el); return () => map.destroy(); }}`, guaranteeing clean teardown.
* **Scope Boundary**: Focus on React 19 ref callback cleanup functions, comparing with `useEffect` cleanup semantics. Do not cover standard object refs (`useRef`).
