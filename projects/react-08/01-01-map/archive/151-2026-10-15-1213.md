# Q151: Selective and Progressive Hydration: Prioritizing User Interaction
* **Topic Tag**: #hydration | ❱❱ MORE (Server)
* **Interview Question**: *What are selective hydration and progressive hydration?*
* **Core Truth**: Selective hydration allows React to hydrate individual <Suspense> boundaries independently and out-of-order, automatically prioritizing whichever boundary the user interacts with over quiescent background content.
* **The Friction**: A reader scrolls down an investigative article at The National Times and clicks "Reply to Comment" at the bottom of the page; under monolithic hydration, the click is ignored while React spends 400ms hydrating 20 unviewed infographics and sidebars higher up on the page.
* **The Mechanism**: Selective hydration in <Suspense>: boundaries hydrate independently as their code splits load; if a user clicks or focuses an unhydrated boundary, React pauses current hydration work, immediately hydrates the clicked boundary synchronously, and replays the user's click event.
* **Under the Hood**: Event replay and priority promotion: React captures early user events on unhydrated DOM nodes; when a click occurs, React upgrades the priority of the containing Suspense boundary's Fiber hydration task in the scheduler, hydrates it immediately, and re-dispatches the captured native event to the newly bound SyntheticEvent handler.
* **The Code Experiment**:
  * *Naive*: Blocking interactivity across the entire page with a single root hydration pass that forces users to wait for all components to hydrate.
  * *React*: Wrapping discrete interactive widgets (<Comments />, <NewsletterModal />) in separate <Suspense> boundaries, enabling selective hydration and instant event replay.
* **Scope Boundary**: Focus on selective and progressive hydration mechanics, event capture, and prioritization. Do not confuse with basic hydrateRoot (Q104).
