# Q10: Conditional Rendering in React
* **Topic Tag**: `#conditional_rendering` | `❱ CORE`
* **Interview Question**: *How do you show, hide, or switch JSX based on a condition?*
* **Core Truth**: React branches markup using standard JavaScript control flow: `if/else` statements for early returns, the ternary operator `? :` for inline branching, logical `&&` for short-circuiting, and returning `null` to render nothing.
* **The Friction**: An article card must display a "New" label only when an article is new, show members-only text when the user is signed in, and hide comments completely when disabled. Writing messy imperative `display: none` DOM queries causes flickering and layout bugs.
* **The Mechanism**: Declarative conditional rendering. Using early returns (`if (!article) return null`), inline ternary expressions (`{isSignedIn ? <FullText /> : <SignInPrompt />}`), and inline logical AND (`{isNew && <span className="new-label">New</span>}`).
* **Under the Hood**: How React treats falsy values: `false`, `null`, and `undefined` render nothing in the DOM. The classic `0 && <Component />` trap: why evaluating the number `0` prints a literal "0" onto the physical screen instead of rendering nothing.
* **The Code Experiment**:
  * *Naive*: Imperative DOM manipulation toggling CSS classes (`el.classList.add('hidden')`), or falling into the `{count && <Badge />}` zero-rendering trap.
  * *React*: An `ArticleHeader` component cleanly branching the "New" label and members-only text using early returns, ternaries, and boolean-coerced `&&` expressions.
* **Scope Boundary**: Focus on branching markup based on props. Do not introduce dynamic interactive toggles via `useState` (reserved for Q14).
