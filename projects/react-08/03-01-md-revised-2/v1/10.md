# Lecture 10: Conditional Rendering in React
> INTERVIEW QUESTION | ❱ CORE | How do you show, hide, or switch JSX based on a condition?

```page caption="One component, ArticleCard, draws both cards. The New label and the comment count appear only on the park card."
heading: Latest Articles
card: title=New Park Opens Today | author=Mary Jones | text=The park on Main Street opens at noon. | label=New | foot=3 comments | good=label,foot
card: title=Rain Expected This Weekend | author=Oliver Brooks | text=Heavy rain is expected on Saturday and Sunday.
```

Some parts of a card belong only to some articles: the "New" label to new articles, the comment count to articles with comments, a sign-in prompt to visitors. How does one component show a part in one case and leave it out in another?

## Two ways to leave a part off the page

::: row caption="The rain article is not new. Same page, two different DOMs."
::: col title="Hiding with CSS" tag="HTML and CSS" tone=plain
```jsx
<span className="new-label" hidden={!isNew}>New</span>
```
```dom title="Elements panel: the rain card"
<article class="card">
*  <span class="new-label" hidden="">New</span>
  <h2>Rain Expected This Weekend</h2>
```
The span stays in the DOM. The browser does not draw it.
:::
::: col title="Conditional rendering" tag="this lecture" tone=good
```jsx
{isNew && <span className="new-label">New</span>}
```
```dom title="Elements panel: the rain card"
<article class="card">
  <h2>Rain Expected This Weekend</h2>
```
There is no span at all. React built nothing.
:::
:::

**Hiding with CSS** fits a part that must keep its place and what is inside it while hidden (Lecture 73). **Conditional rendering** fits every part that depends on data, and every part whose data may be missing. It means one thing: each time it runs, a component chooses which JSX to return. React adds no special syntax for it; the choice is plain JavaScript.

## Count the pieces, then pick the tool

```ladder anchor="Each time it runs, a component chooses which JSX to return."
Nothing | return null | No featured article today | _
One or nothing | && | The New label, the comment count | # or _
One of two | ? : | The summary or the sign-in prompt | A or B
One of many | if + variable | No comments, 1 comment, 5 comments | A B C
```

## 1. Nothing: return null at the top

Some days there is no featured article. `App` sets `featured` to `null` and still renders `<ArticleCard article={featured} />`. The card runs, reaches `article.title`, and reading a property of `null` throws a **`TypeError`**. An error while React renders removes the whole page, not just the card.

::: row caption="Three versions of ArticleCard, with article set to null."
::: col title="`article.title`" tone=bad
```page size=mini
blank
console: TypeError: Cannot read properties of null (reading 'title')
```
The whole page is blank.
:::
::: col title="`article?.title`" tone=bad
```page size=mini
heading: Latest Articles
card: ghost | bad=card
card: title=New Park Opens Today | author=Mary Jones
card: title=Rain Expected This Weekend | author=Oliver Brooks
```
No crash, but an empty card box stays.
:::
::: col title="`if (!article) return null`" tone=good
```page size=mini
heading: Latest Articles
card: title=New Park Opens Today | author=Mary Jones
card: title=Rain Expected This Weekend | author=Oliver Brooks
```
The slot shows nothing. The page stays.
:::
:::

```jsx title="ArticleCard.jsx" good="2-4"
export default function ArticleCard({ article }) {
  if (!article) {
    return null; // nothing to show: no card at all
  }
  return (
    <article className="card">
      <h2>{article.title}</h2>
```

The `if` runs before any line reads `article`, and `null` makes no element. An `if` with a `return` that ends a function early is an **early return**. If the parent owns markup around the card, such as a "Featured today" heading, the parent leaves the whole tag out with `{featured && ...}`, and the card never runs.

> [!PRINCIPLE]
> **Principle 1: Returning null: choosing to show nothing**
>
> When a component has nothing to show for its props, it returns `null` from an `if` at its very top, before any line reads the missing data; when the parent decides whether the component appears at all, the parent leaves out its tag instead.
>
> *We should do this:*
>
> ```jsx
> function Profile({ user }) {
>   if (!user) {
>     return null; // nothing shows, the page stays
>   }
>   return <h2>{user.name}</h2>;
> }
> ```
>
> *We should not do this:*
>
> ```jsx
> function Profile({ user }) {
>   return <h2>{user.name}</h2>; // **WRONG:** null user crashes render
> }
> ```

## 2. One or nothing: a true or false value left of &&

```jsx title="ArticleCard.jsx" bad="2"
{article.isNew && <span className="new-label">New</span>}
{article.commentCount && <p>{article.commentCount} comments</p>}
```

```page caption="The rain article has no comments, and its card shows a bare 0."
heading: Latest Articles
card: title=New Park Opens Today | author=Mary Jones | text=The park on Main Street opens at noon. | label=New | foot=3 comments
card: title=Rain Expected This Weekend | author=Oliver Brooks | text=Heavy rain is expected on Saturday and Sunday. | raw=0 | bad=raw
```

**Logical AND** (`&&`) is not an inline `if`. It gives back one of its two sides: the left side when that side is **falsy**, the right side otherwise. The falsy values are `false`, `0`, `''`, `null`, `undefined`, and `NaN`.

| card | left side | && gives back | the page shows |
| --- | --- | --- | --- |
| park | `isNew: true` | `<span>New</span>` | New |
| rain | `isNew: false` | `false` | nothing |
| park | `commentCount: 3` | `<p>3 comments</p>` | 3 comments |
| !rain | `commentCount: 0` | `0` | 0 |

React draws nothing for `false`, `null`, and `undefined`, but it draws numbers. A comparison always gives a real `true` or `false`:

```jsx title="ArticleCard.jsx" good="1"
{article.commentCount > 0 && <p>{article.commentCount} comments</p>}
```

The same trap hides in quotes: `isNew="false"` passes the text "false", and any non-empty text is truthy, so the label shows. Braces pass a real boolean: `isNew={false}`.

> [!PRINCIPLE]
> **Principle 2: Logical AND: choosing one piece or nothing**
>
> To show a piece or nothing, we write `condition && <Piece />` with a true or false value on the left, such as `commentCount > 0`, never a bare number.
>
> *We should do this:*
>
> ```jsx
> const count = 0;
> {count > 0 && <p>{count} messages</p>} // shows nothing
> ```
>
> *We should not do this:*
>
> ```jsx
> const count = 0;
> {count && <p>{count} messages</p>} // **PROBLEMATIC:** renders a bare 0
> ```

## 3. One of two: a ternary around the part that differs

Signed-in readers see the summary; visitors see a sign-in prompt. A first version writes two whole returns. Later, the author's name is added to the first one only.

::: row caption="Two returns copy the same markup. A change made in one never reaches the other."
::: col title="Signed-in return" tone=plain
```jsx good="3"
<article className="card">
  <h2>{article.title}</h2>
  <p className="author">{article.author}</p>
  <p>{article.summary}</p>
</article>
```
```page size=mini
card: title=New Park Opens Today | author=Mary Jones | text=The park on Main Street opens at noon.
```
:::
::: col title="Visitor return" tone=bad
```jsx bad="3"
<article className="card">
  <h2>{article.title}</h2>
  {/* the author was never added here */}
  <p>Sign in to read this article.</p>
</article>
```
```page size=mini
card: title=New Park Opens Today | missing=author | text=[Sign in] to read this article. | bad=missing
```
:::
:::

Only one paragraph differs, so only that paragraph goes inside the choice. An `if` cannot sit inside JSX braces, but the **ternary** (`? :`) can, because it is an expression:

```jsx title="ArticleCard.jsx" good="4-8"
<article className="card">
  <h2>{article.title}</h2>
  <p className="author">{article.author}</p>
  {isSignedIn ? (
    <p>{article.summary}</p>
  ) : (
    <p>Sign in to read this article.</p>
  )}
</article>
```

The card, the title, and the author are written once. A ternary always needs both sides; for one side, use `&&`.

> [!PRINCIPLE]
> **Principle 3: The ternary operator: choosing between two pieces**
>
> To show one of two pieces in the same place, we write `condition ? <A /> : <B />` inside the JSX and keep the markup both cases share written once; two whole returns fit only when the two cases share nothing.
>
> *We should do this:*
>
> ```jsx
> <h2>{name}</h2>
> {isSignedIn ? <Summary /> : <SignInPrompt />} // only this differs
> ```
>
> *We should not do this:*
>
> ```jsx
> if (isSignedIn) {
>   return <><h2>{name}</h2><Summary /></>;
> }
> return <><h2>{name}</h2><SignInPrompt /></>; // **PROBLEMATIC:** duplicate markup
> ```

## 4. One of many: if and a variable above the return

```chain caption="The comment line now needs three wordings."
`count: 0` -> No comments yet
`count: 1` -> 1 comment
`count: 5` -> 5 comments
```

::: row
::: col title="A ternary inside a ternary" tone=bad
```jsx
<p className="comments">
  {count === 0
    ? 'No comments yet'
    : count === 1
      ? '1 comment'
      : count + ' comments'}
</p>
```
It works, but to read it you pair each `:` with its `?`. A fourth case adds a fourth level.
:::
::: col title="`if`, `else if`, `else` into a variable" tone=good
```jsx
let commentText;
if (count === 0) {
  commentText = 'No comments yet';
} else if (count === 1) {
  commentText = '1 comment';
} else {
  commentText = count + ' comments';
}
```
```jsx
<p className="comments">{commentText}</p>
```
One case per line, above the `return`. The JSX only places the result.
:::
:::

A variable can hold text, a number, or JSX. When the cases keep growing, an object of texts or a child component takes over.

> [!PRINCIPLE]
> **Principle 4: An if statement and a variable: choosing among many pieces**
>
> When a choice has more than two cases, we pick the piece with `if`, `else if`, and `else` above the `return`, store it in a variable, and place the variable in the JSX, instead of nesting one ternary inside another.
>
> *We should do this:*
>
> ```jsx
> let label;
> if (count === 0) {
>   label = 'None';
> } else if (count === 1) {
>   label = 'One';
> } else {
>   label = 'Many';
> }
> return <p>{label}</p>; // one case per line above
> ```
>
> *We should not do this:*
>
> ```jsx
> return (
>   <p>{count === 0 ? 'None' : count === 1 ? 'One' : 'Many'}</p>
> ); // **PROBLEMATIC:** nested ternaries obscure logic
> ```

## For the interview

- **Is `&&` an inline `if`?** No. It gives back one of its two sides, so `0 && <Badge />` gives back `0`, and React draws it. Put a true or false value on the left: `count > 0 && <Badge />`.
- **Is returning `null` the same as leaving the tag out in the parent?** The page looks the same. With `null`, the component still runs, and a `console.log` inside it still prints. When the parent leaves the tag out, the component never runs.
- **Why not just `display: none`?** A hidden element stays in the DOM with what is inside it, such as typed text. A part that is left out is removed; when it comes back, React builds it again, empty. Hide only a part that must keep what is inside it (Lecture 73).
- **`return null` or a bare `return;`?** In React 19 both show nothing. `null` says that the choice is on purpose.
- **Why does `isNew="false"` show the label?** Quotes pass text, and non-empty text is truthy. Write `isNew={false}`.

## Where you will meet this

- An unread badge: `unread > 0 && <Badge />`, never `unread && <Badge />`.
- A header that shows "Sign in" to visitors and an avatar to members: a ternary.
- An order status with four wordings (placed, packed, shipped, delivered): an `if` chain into a variable, or an object of texts.

## Summary

| pieces | write | instead of |
| --- | --- | --- |
| +Nothing | `if (!article) return null;` at the very top | reading the data first, or hiding missing data with CSS |
| +One or nothing | `count > 0 && <Piece />` | a bare number left of `&&` |
| +One of two | `cond ? <A /> : <B />` around the part that differs | two whole returns that copy the shared markup |
| +One of many | `if`, `else if`, `else` above the `return`, into a variable | a ternary inside a ternary |

**Nothing, one or nothing, one of two, and one of many.**

**DO THIS:**

```jsx right
function ArticleCard({ article, isSignedIn }) {
  if (!article) {
    return null;
  }
  return (
    <article className="card">
      <h2>{article.title}</h2>
      {isSignedIn ? <p>{article.summary}</p> : <p>Sign in to read.</p>}
      {article.commentCount > 0 && <p>{article.commentCount} comments</p>}
    </article>
  );
}
```

**DO NOT DO THIS:**

```jsx wrong
function ArticleCard({ article }) {
  return (
    <article className="card">
      <h2>{article.title}</h2>
      {article.commentCount && <p>{article.commentCount} comments</p>}
    </article>
  );
}
```
