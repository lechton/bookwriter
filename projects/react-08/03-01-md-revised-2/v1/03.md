Most React work starts from HTML that already exists: an old site, a designer's mockup, an example from the web. Our site is moving to React. What changes when HTML moves into a component?

The browser never reads `App.jsx` as we wrote it. The dev server rewrites it into plain JavaScript first; this is the **build**. When the build cannot read a file, nothing in that file runs, and Vite covers the page with an **error overlay** that names the message, the file, and the line.

## One idea, five rules on the way to the page

```ladder anchor="JSX looks like HTML, but it is JavaScript: each tag becomes a call that builds an object."
The tag | _jsxDEV() | Each tag becomes a call
Its end | <img /> | Every tag closed
The return | one root | One value per function
The group | <> </> | One value, no extra box
Its attributes | className | JavaScript names
```

## 1. The tag: each tag becomes a call that returns an object

A card stored in a variable and logged with `console.log(card)` appears on the page as usual, but the Console panel shows an object, not markup. The Sources panel, which shows each file as the browser received it, has no tags at all:

```stages caption="One tag on its way to the page."
We write | App.jsx | <h2 className="title">City Library Extends Its Hours</h2>
The build writes a call | Sources panel | _jsxDEV("h2", { className: "title", children: "City Library..." })
The call returns an object | Console panel | { type: 'h2', props: { className: 'title', children: 'City Library...' } }
React builds the DOM | Elements panel | <h2 class="title">City Library Extends Its Hours</h2>
```

This rewrite is the **JSX transform**. The tag's name becomes the first argument; its attributes and content become an object, the second. The call returns a plain object, a **React element**, and React builds the DOM from those objects, so the browser never receives a tag. An `<article>` holding an `<h2>` and a `<p>` gives one object whose `children` holds two more.

The transform also explains Lecture 2's capital letter:

```chain
+`<ArticleCard />` -> `_jsxDEV(ArticleCard, {})` -> our function: React calls it
!`<articleCard />` -> `_jsxDEV("articleCard", {})` -> only a text: an unknown HTML tag
```

Every rule below follows from this one fact.

> [!PRINCIPLE]
> **Principle 1: The JSX transform: each tag becomes a JavaScript call that returns an object**
>
> We read JSX as JavaScript: the build turns each tag into a call, the call returns an object that describes the element, and React builds the DOM from those objects.
>
> *We should do this:*
>
> ```jsx
> function Greeting() {
>   const note = <p className="note">Hello, John Hall</p>; // an object
>   return note;
> }
> ```

## 2. Its end: every tag closed

HTML lets a **void element** such as `<img>`, `<br>`, or `<input>` stay open, because it can never hold anything. The card above was pasted that way:

```jsx title="App.jsx" bad="4"
function ArticleCard() {
  return (
    <article>
      <img src="/library.jpg" alt="The city library">
      <h2>City Library Extends Its Hours</h2>
    </article>
  );
}
```

::: row caption="The same card with the image open, and with the image closed."
::: col title="`<img ...>`" tone=bad
```overlay size=mini
message: [PARSE_ERROR] Expected corresponding JSX closing tag for 'img'.
 4 │ <img src="/library.jpg" alt="The city library">
   │  ─┬─
   │   ╰─── Opened here
 6 │ </article>
   │   ───┬───
   │      ╰───── Expected `</img>`
```
The build stops at line 6. A second message, at the function's last brace, goes away with the first.
:::
::: col title="`<img ... />`" tone=good
```page size=mini
card: img=The city library | title=City Library Extends Its Hours
```
The photo and the title appear.
:::
:::

A call must know where its content ends. After an open tag, the build reads everything as that tag's content until the closing tag, and JSX makes no exception for void elements:

```chain
!`<img ...>` opens -> the `<h2>` becomes its content -> at `</article>`, still waiting for `</img>`
+`<img ... />` closes at once -> the `<h2>` sits next to it -> `</article>` closes the card
```

`<br>`, `<input>`, and an `<li>` or `<p>` left open, as HTML allows, fail the same way. Any tag may close itself, such as `<div className="spacer" />`.

> [!PRINCIPLE]
> **Principle 2: Closed tags: JavaScript must know where each tag ends**
>
> We close every tag, with a closing tag or with a slash, `<img />` and `<br />` too, because JavaScript must know where each tag ends.
>
> *We should do this:*
>
> ```jsx
> <section>
>   <img src="/john.jpg" alt="John Hall" /> {/* closed with a slash */}
>   <p>John Hall<br />Boston</p>
> </section>
> ```
>
> *We should not do this:*
>
> ```jsx
> <section>
>   <img src="/john.jpg" alt="John Hall"> {/* waits for </img> */}
>   <p>John Hall<br>Boston</p>
> </section>
> ```

## 3. The return: one root

Another old card has no `<article>` around it, only a heading and a paragraph:

```jsx title="App.jsx" bad="3-4"
function ArticleCard() {
  return (
    <h2>City Library Extends Its Hours</h2>
    <p>The library now stays open until nine.</p>
  );
}
```

::: row caption="Two tags side by side, and the same tags inside one article."
::: col title="Two tags after `return`" tone=bad
```overlay size=mini
message: Adjacent JSX elements must be wrapped in an enclosing tag.
help: Did you want a JSX fragment <>...</>?
```
The build stops, and nothing in the file runs.
:::
::: col title="One `<article>` around both" tone=good
```page size=mini
card: title=City Library Extends Its Hours | text=The library now stays open until nine.
```
The card appears.
:::
:::

Each tag is one call, and each call gives one value. A function gives back one value with `return`, so two calls side by side have nowhere to go. One element around both is one call, and the two inner calls become its `children`:

```jsx title="App.jsx" good="3,6"
function ArticleCard() {
  return (
    <article>
      <h2>City Library Extends Its Hours</h2>
      <p>The library now stays open until nine.</p>
    </article>
  );
}
```

> [!PRINCIPLE]
> **Principle 3: Single root: a JavaScript function returns one value**
>
> We return one root from every component, one element that holds the rest, because a JavaScript function returns one value.
>
> *We should do this:*
>
> ```jsx
> return (
>   <section> {/* one root */}
>     <h2>John Hall</h2>
>     <p>Author of 12 articles</p>
>   </section>
> );
> ```
>
> *We should not do this:*
>
> ```jsx
> return (
>   <h2>John Hall</h2>
>   <p>Author of 12 articles</p> {/* a second value */}
> );
> ```

## 4. The group: a Fragment adds no box

The home page shows the featured articles in a row. `index.css` makes the list a **flex layout**, whose children sit side by side, and gives a border to each `.articles > li`, a **child selector** that matches only the list's direct children. A new component, `FeaturedArticles`, returns the two items, and `App` places it inside `<ul className="articles">`. Two `<li>` side by side would stop the build, so they get a `<div>` around them:

```jsx title="App.jsx" bad="3,6"
function FeaturedArticles() {
  return (
    <div>
      <li>Ten easy summer recipes</li>
      <li>New park opens today</li>
    </div>
  );
}
```

::: row caption="The build passes both times. The DOM, and so the layout, differs."
::: col title="Wrapped in a `<div>`" tone=bad
```dom title="Elements panel"
<ul class="articles">
!  <div>
    <li>Ten easy summer recipes</li>
    <li>New park opens today</li>
!  </div>
</ul>
```
```page size=mini
stack: Ten easy summer recipes ; New park opens today
```
The list's only child is the `<div>`: the items stack, with no border.
:::
::: col title="Wrapped in a Fragment, `<>`" tone=good
```dom title="Elements panel"
<ul class="articles">
+  <li>Ten easy summer recipes</li>
+  <li>New park opens today</li>
</ul>
```
```page size=mini
row: Ten easy summer recipes ; New park opens today
```
The items are the list's own children: a row, each with its border.
:::
:::

A `<div>` is a real element, so React builds it, between the list and its items. A **Fragment**, written `<>` and `</>`, is one call too, so it gives one root, but React builds no element for it and puts its children straight into the parent:

```jsx title="App.jsx" good="3,6"
function FeaturedArticles() {
  return (
    <>
      <li>Ten easy summer recipes</li>
      <li>New park opens today</li>
    </>
  );
}
```

An element is still the right root when the page needs the box, for its meaning or a style, as the `<article>` in rule 3.

> [!PRINCIPLE]
> **Principle 4: Fragments: one JavaScript value that adds no element to the page**
>
> When the elements need one root but the page needs no extra box, we group them with a Fragment, `<>` and `</>`, and we keep an element only when the page needs the box.
>
> *We should do this:*
>
> ```jsx
> function NameCells() {
>   return (
>     <> {/* no element in the DOM */}
>       <td>John</td>
>       <td>Hall</td>
>     </>
>   );
> }
> ```
>
> *We should not do this:*
>
> ```jsx
> function NameCells() {
>   return (
>     <div> {/* a div inside the table row */}
>       <td>John</td>
>       <td>Hall</td>
>     </div>
>   );
> }
> ```

## 5. Its attributes: JavaScript names

The old newsletter form is pasted with its HTML attributes:

```jsx title="App.jsx" bad="4-5"
function SignUp() {
  return (
    <form>
      <label class="label" for="email">Your email</label>
      <input id="email" type="email" tabindex="0" />
    </form>
  );
}
```

::: row caption="The page looks the same both times. Only the console tells them apart."
::: col title="`class`, `for`, `tabindex`" tone=bad
```page size=mini
form: Your email
error: Invalid DOM property `class`. Did you mean `className`?
error: Invalid DOM property `for`. Did you mean `htmlFor`?
error: Invalid DOM property `tabindex`. Did you mean `tabIndex`?
```
The label still works, and three errors fill the console.
:::
::: col title="`className`, `htmlFor`, `tabIndex`" tone=good
```page size=mini
form: Your email
quiet: Console: no messages
```
The same page, and a clean console.
:::
:::

The attributes become the properties of the object the call receives, so they take JavaScript names. `class` and `for` are **reserved words** in JavaScript, so React uses the names the DOM gives these properties:

| HTML | JSX | why |
| --- | --- | --- |
| `class` | `className` | `class` is a reserved word |
| `for` | `htmlFor` | `for` is a reserved word |
| `tabindex` | `tabIndex` | names of several words use camelCase |
| `aria-label`, `data-form-id` | unchanged | `aria-*` and `data-*` keep their dashes |

React 19 still writes `class="label"` into the page, which is why the page looks right. A console full of these errors hides the one error that matters.

> [!PRINCIPLE]
> **Principle 5: camelCase attributes: each attribute becomes a JavaScript property name**
>
> We write each attribute as a JavaScript property name: `className` for `class`, `htmlFor` for `for`, camelCase for names of several words, and dashes only in `aria-*` and `data-*`.
>
> *We should do this:*
>
> ```jsx
> <form className="contact"> {/* className, not class */}
>   <label htmlFor="name">Name</label>
>   <input id="name" placeholder="John Hall" data-user-id="7" />
> </form>
> ```
>
> *We should not do this:*
>
> ```jsx
> <form class="contact"> {/* an error in the console */}
>   <label for="name">Name</label>
>   <input id="name" placeholder="John Hall" data-user-id="7" />
> </form>
> ```

## For the interview

- **What is JSX?** Not HTML. The build turns each tag into a function call, the call returns a plain object, and React builds the DOM from those objects. The browser never sees JSX, and every rule follows from that.
- **Is JSX just HTML with a few differences?** That is the classic trap. An open `<img>` stops the build, two tags side by side stop it again, and `class` fills the console with errors. HTML accepts all three; JavaScript does not.
- **Does a Fragment appear in the Elements panel?** No. Its children sit directly inside the parent.
- **Can a Fragment take a key?** The empty tag cannot. The long form, `<Fragment key={...}>`, can (Lecture 11).
- **Can I keep the HTML comments of my old page?** No. They stop the build with "HTML comments are not allowed in modules". A JSX comment needs curly braces (Lecture 4).
- **Old tutorials start with `import React from 'react'`. Do I need it?** Not for JSX. The old transform called `React.createElement`; React 19 requires the new transform, which adds its own import, as the Sources panel shows.

## Where you will meet this

- A designer's HTML mockup or a snippet from a CSS library: every `class`, open `<input>`, and group of tags side by side needs the same five checks.
- A table row component that returns several `<td>` cells: a Fragment, because a `<div>` inside a `<tr>` breaks the table.
- An SVG icon pasted from a design tool: `stroke-width` becomes `strokeWidth`.

## Summary

| step | the HTML habit | the JSX rule |
| --- | --- | --- |
| +The tag | markup the browser reads as it is | a call that returns an object; React builds the DOM from it |
| +Its end | `<img>`, `<br>`, `<input>` left open | every tag closed: `<img />`, `<br />`, `<input />` |
| +The return | any number of tags side by side | one root that holds the rest |
| +The group | a `<div>` around the group | a Fragment, `<>` and `</>`: no element on the page |
| +Its attributes | `class`, `for`, `tabindex` | `className`, `htmlFor`, `tabIndex`; `aria-*` and `data-*` unchanged |

**One call per tag, every tag closed, one root, no extra box, and JavaScript names.**

**DO THIS:**

```jsx right
function SearchBox() {
  return (
    <section>
      <label htmlFor="query">Words to find</label>
      <input id="query" type="search" />
    </section>
  );
}
```

**DO NOT DO THIS:**

```jsx wrong
function SearchBox() {
  return (
    <label for="query">Words to find</label>
    <input id="query" type="search">
  );
}
```
