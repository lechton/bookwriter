Who changes the page when the data changes

The full header, built with commands and built from one description, after Mary becomes Mary Brooks and the count goes from 3 to 4.

Component Layer Naive Expectation (the plain JavaScript habit) What Happened (React 19)
The whole header Step 1, the core mechanism An update function sets each element It finds each place with getElementById and writes the new value into textContent. React builds it from the data The JSX reads userName and unreadCount, and React fills the empty root. Our code has no DOM call.
Five places, two values Step 2, many places from one value One command per place Five commands on every change, and the notice is easy to type as fixed text. A forgotten place keeps "Mary" or "3". Every place reads its variable Three places read {userName} and two read {unreadCount}, so each shows the current value.
The search box Step 3, describing the page again The header is rebuilt innerHTML makes a new, empty box, and the focus falls back to the page. The same node stays React changes five texts and leaves the <input> in place, so it keeps "elections" and the cursor.
Verdict Commands Every place needs its own update, and one forgotten update leaves old data on the page. One description The page is described from its data, and React makes the smallest change that keeps it true.
