LESSONS FROM THE CODE
Branching Mechanics, Operator Choice & DOM Visibility

Contrasting imperative DOM manipulation and falsy evaluation traps with declarative React conditional rendering

Component Layer Architecture Naive Expectation Imperative Pattern Fragile / Bug-Prone What Happened Declarative React Predictable & Safe
DOM Nodes Element Presence ✕ Manual DOM mutation: querying the DOM during render and calling classList.add('hidden') throws a TypeError because elements do not exist yet. ✓ Declarative omission: JSX branches return elements only when needed; React creates or removes real DOM nodes cleanly.
Data Guard Missing Input ✕ Unchecked read: reading article.title when the prop is undefined throws a runtime error that crashes the entire component tree. ✓ Early return guard: checking if (!article) return null; exits before property access, rendering an empty slot safely.
Binary Choice Operator Shape ✕ Inverted AND pairs: writing {isLive && <A />} and {!isLive && <B />} duplicates conditions and invites state drift. ✓ Unified ternary: writing {isLive ? <A /> : <B />} cleanly selects exactly one of two alternative branches.
Number Guard Short-Circuit Trap ✕ Raw numeric check: 0 && <Badge /> evaluates to 0, which React treats as visible text and paints as an unwanted 0 on screen. ✓ Explicit boolean: count > 0 && <Badge /> evaluates to false, which React suppresses completely from the DOM.
Complex Logic Code Structure ✕ Nested inline ternaries: chaining multiple ? : operators inside JSX creates unreadable code that confuses reviewers. ✓ Extracted variable: assigning JSX to a let variable using if/else above the return keeps markup clean and flat.
Verdict Fragile & Error-Prone: Imperative DOM lookups and uncoerced numeric checks cause blank screens, crashes, and visual bugs. Resilient & Idiomatic: Declarative JavaScript control flow keeps markup synchronized, safe against missing data, and readable.
