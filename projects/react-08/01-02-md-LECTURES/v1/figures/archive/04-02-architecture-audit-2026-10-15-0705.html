Lessons from the Code
The JSX Expressions & Dynamic Evaluation Challenge

An architectural comparison evaluating text interpolation, dynamic attribute binding, and expression grammar.

Component Layer Naive Expectation (Static Strings & Statements) What Happened (Curly Braces & Expression Window)
1. Text Nodes (Variable Projection) Literal Variable Name Writing <h2>headline</h2> causes the compiler to treat the word as static text, printing the literal string "headline" to the screen. Evaluation Window `{}` Writing <h2>{headline}</h2> opens an inline JavaScript window, passing the live memory value into the rendered element tree.
2. Element Attributes (Resource URL Resolution) Quoted Attribute String Writing src="avatarUrl" emits a static string literal. The browser network stack requests /avatarUrl, producing a 404 broken image. Unquoted Braces `{avatarUrl}` Omitting quotes and writing src={avatarUrl} evaluates the variable in memory, binding the resolved image path directly to the DOM property.
3. Language Grammar (Expressions vs Statements) Control-Flow Statement Writing {if (readTime > 10) ...} halts the compiler. Statements produce zero values and cannot be passed into JavaScript function arguments. Value-Producing Expression Writing {readTime > 10 ? "Long" : "Quick"} resolves to a single value in memory, perfectly satisfying ECMAScript argument grammar.
Architectural Verdict Broken Placeholders & Syntax Crashes Treating JSX like auto-evaluating HTML templates triggers literal placeholder text, broken image URLs, and fatal compiler crashes. Predictable Runtime Evaluation Using curly braces as an evaluation window establishes a clean bridge between declarative markup and live JavaScript calculation.
