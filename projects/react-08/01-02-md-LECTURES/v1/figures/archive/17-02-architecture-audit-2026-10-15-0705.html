Batching and Updater Functions in Practice

How React queues state updates and resolves them during render

Component Layer Architecture Naive Expectation Immediate Mutation Assumes each call repaints instantly What Happened Queued Resolution React batches updates per handler
App.jsx Root Shell ✕ Global re-render churn
Parent component coordinates updates, forcing the whole tree to re-render on every ticket click. 		✓ Isolated boundary state
TicketOrder encapsulates ticket state; parent App renders once and never re-renders on clicks.
TicketOrder.jsx Batching ✕ One render per setter call
Calling three setters in one click handler triggers three consecutive re-renders. 		✓ One render per event handler
React waits until the handler finishes, batching all updates into a single coordinated render.
TicketOrder.jsx Value Queue ✕ Consecutive values accumulate
Three calls to setTickets(tickets + 1) add three because each call adds one. 		✓ Repeated snapshot replacement
Each call reads snapshot 0, queueing "replace with 1" three times; screen updates to 1.
TicketOrder.jsx Updater Queue ✕ Updaters run inside the handler
Passing t => t + 1 runs the calculation immediately when the setter is called. 		✓ Updaters run during render
React queues the function and invokes it during the next render, passing the running total.
OrderControls.jsx Async Boundary ✕ Code after await reads newest state
Calling setPending(pending - 1) after await reads the incremented value. 		✓ Await preserves render snapshot
The resumed handler sees snapshot 0, ending at -1; updaters receive the live total, ending at 0.
Verdict Immediate mutation mental model
Treating setters as instant variable reassignments creates race conditions and lost increments. 		Batched update queue mental model
React walks queued instructions in order during render, ensuring predictable transitions and fast UI.
