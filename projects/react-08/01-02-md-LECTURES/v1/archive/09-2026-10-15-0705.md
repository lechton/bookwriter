### The browser starts at index.html and needs an explicit mounting bridge

Every web application begins with an HTML document. When you build a traditional website, you write native HTML tags directly inside HTML files. The browser parses those tags and paints them immediately. In a React application, however, your components return descriptions of markup written in JSX. The browser cannot run JSX syntax on its own. It cannot guess which HTML element your components belong to. To display components on screen, React requires an explicit mounting bridge. This bridge connects your virtual component tree to a real, living HTML element on the page.

When you inspect a new React project, the root `index.html` file contains almost nothing. You find an HTML shell with an empty `<div id="root"></div>` tag and a module script. Looking at this empty container, a newcomer wonders how component code ever reaches the screen. A developer might attempt to link `App.jsx` directly inside `index.html` using a traditional `<script>` tag. Or they might double-click `index.html` to open it as a local file (`file://`) in Chrome. When they do, the browser fails immediately. The browser encounters raw JSX tags and halts with a fatal syntax error: `Uncaught SyntaxError: Unexpected token '<'`.

The mounting pipeline connects three files. First, `index.html` provides the host HTML container and loads the entry script. Second, `src/main.jsx` finds that container and initializes React. Third, `src/App.jsx` provides the root component that renders the application interface.

```files title="Project folders: File Explorer"
index.html | boundary | Host HTML document containing the physical container div#root
src/
  main.jsx | boundary | Application entry point bridging DOM container to React via createRoot
  App.jsx | parent | Root application shell composing the interface layout
  components/
    StatusCard.jsx | child | Modular child component displaying pending item count
```

In `index.html`, the document provides a physical HTML container and loads the entry script:

```html title="index.html"
<!DOCTYPE html>
<html lang="en">
  <head>
    <title>Item Tracker</title>
  </head>
  <body>
    <div id="root">Loading...</div> <!-- Physical DOM container -->
    <script type="module" src="/src/main.jsx"></script> <!-- Module entry -->
  </body>
</html>
```

In `src/main.jsx`, the entry script imports `createRoot` and mounts the root component:

```jsx title="Application Entry Point"
import { createRoot } from 'react-dom/client'; // Browser mounting renderer
import App from './App.jsx'; // Root component import

const container = document.getElementById('root'); // Finds container node
const root = createRoot(container); // Creates React root

root.render(<App />); // Mounts component tree into container
```

In `src/App.jsx`, the top-level component defines the user interface layout:

```jsx title="Root Component Layout"
export default function App() { // Root application component
  return (
    <main className="tracker-layout"> {/* Application shell */}
      <h1>Item Tracker</h1>
    </main>
  );
}
```

- **Lecture 1 (What React is and the DOM)**: Plain JavaScript finds an HTML element using `document.getElementById('root')`, which returns the living DOM node or `null` if no element with that identifier exists on the page.
- **Lecture 2 (Component anatomy)**: A React component is a JavaScript function that starts with a capital letter. Writing `<App />` creates a React element that tells React to execute `App()`, whereas writing `App` refers to the bare function itself.

### How index.html loads main.jsx through a module script

We know that HTML documents load external scripts using `<script>` tags. Traditionally, a classic script ran synchronously and treated all code as a single global scope. In modern web development, adding `type="module"` to a `<script>` tag tells the browser that the file is an **ES module** that uses `import` and `export` statements.

Modern browser engines automatically **defer** module scripts. While the browser downloads `main.jsx` across the network, it continues parsing the rest of the HTML document without pausing. The module script executes only after the entire HTML document has been parsed into memory. Because of this deferred timing, a `<script type="module">` tag placed in the `<head>` of your document can safely find `<div id="root">` even though the `<div>` tag appears further down in the `<body>`.

```html title="index.html"
<head>
  <title>Item Tracker</title>
  <!-- Module scripts are deferred until HTML parsing completes -->
  <script type="module" src="/src/main.jsx"></script> <!-- Safe in head -->
</head>
<body>
  <div id="root">Loading...</div> <!-- Found safely by getElementById -->
</body>
```

If you omit `type="module"`, the browser treats the file as a classic script. The browser cannot run `import` statements outside a module and stops with `Uncaught SyntaxError: Cannot use import statement outside a module`.

### How createRoot and root.render attach components to the page

React separates its core component architecture from browser rendering. The core package, `react`, manages element descriptions, component logic, and component trees. The browser renderer, `react-dom/client`, provides the bridge that turns those element descriptions into physical browser DOM nodes. Only the application entry file (`main.jsx`) imports from `react-dom/client`; all your component files import purely from `react`.

Calling `createRoot(domNode)` creates a React root object for that specific DOM element and gives React exclusive ownership of the HTML inside it. When `root.render(<App />)` runs for the first time, React wipes whatever placeholder HTML originally lived inside that element (such as `"Loading..."`) and replaces it with the rendered output of `<App />`. Any HTML written outside that container, such as a static navigation bar or footer in `index.html`, remains completely untouched.

Calling `root.render` does not block the browser thread to update the DOM synchronously on the spot. Instead, `root.render` schedules a render task in React's queue and returns immediately. If you read `container.textContent` on the line directly following `root.render(<App />)`, the console still prints `"Loading..."` because React has not painted the DOM yet. The browser paints the updated DOM tree only after the current JavaScript execution frame finishes and yields control back to the browser event loop.

```jsx title="Asynchronous Render Execution"
const container = document.getElementById('root');
const root = createRoot(container); // Creates concurrent root

root.render(<App />); // Schedules render task asynchronously

// The next line executes before React paints the DOM:
console.log(container.textContent); // Still prints: "Loading..."
```

When you need to tear down a React tree (for example, when a tab panel built in another library removes the container from the page), you can call `root.unmount()`. Calling `root.unmount()` empties the container and detaches React. Once unmounted, calling `root.render` again on that same root throws `Cannot update an unmounted root`. In standard single-page React applications, you rarely need to call `root.unmount`.

### Why Vite transforms JSX and serves modules over HTTP

Web browsers understand ECMAScript, but they do not understand JSX syntax like `<App />`. If a browser encounters a raw `<` token inside a JavaScript file, it halts with a syntax error. Furthermore, browsers cannot resolve bare package specifiers like `import { createRoot } from 'react-dom/client'` because browsers only know how to load files from explicit paths starting with `/`, `./`, or `../`.

To solve these limitations, modern projects use **Vite**. During development, running `npm run dev` starts a local HTTP **dev server** at `http://localhost:5173`. When the browser requests `/src/main.jsx`, Vite intercepts the request, transforms the JSX into standard function calls (`_jsxDEV`), rewrites package imports into browser-accessible URLs, and serves the files over HTTP. When you are ready to deploy, running `npm run build` compiles your application into static HTML, JavaScript, and CSS bundles inside a `dist/` directory.

```bash title="Terminal"
$ npm run dev # Starts local development server

  VITE v6.0.0  ready in 180 ms

  ➜  Local:   http://localhost:5173/ # Serves modules over HTTP
  ➜  Network: use --host to expose
```

If you double-click `index.html` from your desktop folder, the browser opens it using the `file://` protocol. For security reasons, modern browsers treat the local disk origin as `null` and block all `<script type="module">` tags under cross-origin security rules. To run a modern React application, you must always serve your files over HTTP using the Vite development server.

> [!WILD]
> **Why does double-clicking index.html fail to load React?**
>
> When you double-click an HTML file on your desktop, the browser loads it over the local `file://` protocol. Modern browsers treat the local filesystem origin as `null` and block all module scripts (`<script type="module">`) under strict security policies. The browser console logs: `Access to script from origin 'null' has been blocked by CORS policy`. To run a modern React application, you must always serve your files over an HTTP server. During development, Vite provides an instant HTTP dev server (`npm run dev`), and for production builds, `vite preview` serves your compiled `dist/` directory locally over HTTP.

### Principles of React: Mounting the Root with createRoot

### Question 1: An empty div in HTML receives the component tree

The browser loads `index.html`, which defines `<div id="root">Loading...</div>` and links the entry script with `<script type="module" src="/src/main.jsx"></script>`. In `src/main.jsx`, a developer attempts to connect the application by searching for an element with the identifier `'app'`:

```jsx title="Target ID Mismatch"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = document.getElementById('app'); // Returns null on mismatch
const root = createRoot(container); // Throws runtime exception

root.render(<App />);
```

When the browser loads the page, the screen stays completely blank, and the browser console throws: `Uncaught Error: Target container is not a DOM element.`

**Why does the screen stay blank with "Target container is not a DOM element"?**

---

**ANSWER**

**The code does not do what we wanted.** `document.getElementById('app')` returns `null` because no element with that identifier exists in `index.html`.

The browser executes `document.getElementById('app')` and scans the loaded HTML document. Because the container in `index.html` is written as `<div id="root">`, the lookup finds nothing and returns `null`. The function `createRoot` requires a living browser DOM element to manage. Receiving `null`, `createRoot` throws an immediate runtime error and halts execution before any component can mount.

The fix is matching the identifier string character for character with the `id` attribute defined in `index.html`. When `document.getElementById('root')` finds the valid `<div>` element, `createRoot` takes ownership of that container. Calling `root.render(<App />)` then replaces the placeholder text `"Loading..."` with the rendered component output of `App`.

```ascii title="The mounting bridge from HTML container to component tree"
index.html:      <div id="root">Loading...</div>
                       |
                       v
main.jsx:        const container = document.getElementById('root');
                 const root = createRoot(container);
                       |
                       v
DOM tree:        root.render(<App />);  -->  [clears "Loading..."]
                                        -->  <div><App output /></div>
```

> [!PRINCIPLE]
> **Principle 1: index.html loads main.jsx, and main.jsx hands the root element to React**
> When the browser loads index.html, the module script requests main.jsx. In that file, document.getElementById finds the physical container element, and createRoot hands that container to React. Calling root.render replaces any initial content inside the container with your component tree. If the identifier in getElementById does not match the id attribute in index.html, the method returns null, causing createRoot to throw a fatal error that leaves the page blank.
>
> >> root container : the physical HTML element that React takes over to display and manage components
>
> *We should do this:*
> `const element = document.getElementById('root');`
> `const root = createRoot(element);`
> `root.render(<App />); // replaces placeholder content`
>
> *We should not do this:*
> `const element = document.getElementById('app'); // returns null`
> `const root = createRoot(element); // throws on null container`

### Question 2: Double-clicking index.html blocks the module script

A developer wants to test their project without opening the terminal. They locate `index.html` in their local desktop folder and double-click the file to open it directly in Chrome:

```text title="Browser Address Bar"
file:///Users/developer/project/index.html
```

The browser displays the initial placeholder text `"Loading..."`, but the React components never paint to the screen. In the developer console, Chrome logs: `Access to script at 'file:///Users/developer/project/src/main.jsx' from origin 'null' has been blocked by CORS policy: Cross origin requests are only supported for protocol schemes: http, data, chrome, https.`

**Why does opening index.html directly from disk fail to load the application?**

---

**ANSWER**

**The code does not do what we wanted.** Modern browsers block ES module scripts loaded over the local `file://` protocol.

Modern browsers enforce strict security rules around ES modules (`<script type="module">`). When an HTML file is loaded from your local filesystem using `file://`, the browser assigns the document an origin of `null`. The browser blocks any script tag that tries to import external module files from origin `null` to prevent malicious local script execution. Furthermore, browser engines cannot compile JSX syntax or locate bare package imports like `react-dom/client` without a development server.

The fix is running the project through Vite by executing `npm run dev` in your terminal. Vite boots a local HTTP server at `http://localhost:5173`. When the browser visits this HTTP address, module scripts load under a valid origin without security blocks. Vite compiles JSX on the fly and rewrites package imports so the browser runs them smoothly. For production, `npm run build` compiles your files into static assets in `dist/`.

```ascii title="Protocol comparison: file:// vs Vite HTTP server"
file:// protocol:
  file:///project/index.html  -->  origin: null  -->  CORS error on module
  browser fails to resolve 'react-dom/client' and cannot parse JSX tags

http:// protocol (Vite dev server):
  http://localhost:5173/      -->  HTTP 200 OK  -->  ES modules load cleanly
  Vite transforms JSX on the fly and maps package names to local file paths
```

> [!PRINCIPLE]
> **Principle 2: Serve the app through Vite, never as raw files**
> Web browsers do not understand JSX syntax and cannot resolve package imports like react-dom/client directly from disk. Furthermore, modern browsers treat local disk files loaded over file:// as having a null origin, blocking all module scripts with security errors. Running the Vite development server transforms JSX into standard JavaScript on the fly and serves your application over HTTP. For deployment, Vite bundles your project into static files inside dist.
>
> >> dev server : a local HTTP server that transforms JSX and serves modules on demand during development
>
> *It is best practice to do this:*
> `// Run Vite dev server: npm run dev`
> `// Local server URL: http://localhost:5173/`
> `<script type="module" src="/src/main.jsx"></script> {/* HTTP */}`
>
> *Instead of doing this:*
> `// Double-clicking file:///project/index.html`
> `<script type="module" src="/src/main.jsx"></script> {/* CORS */}`

### Question 3: Passing the bare function App leaves the page empty

In `src/main.jsx`, a developer imports `App` and passes the bare component name directly into `root.render`:

```jsx title="Bare Function Argument"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = document.getElementById('root');
const root = createRoot(container);

// Passing bare function identifier without JSX tags:
root.render(App); // Does not mount component
```

The browser screen remains blank. In the console, React logs: `Warning: Functions are not valid as a React child. This may happen if you return a Component instead of <Component /> from render. Or maybe you meant to call this function rather than return it.`

**Why does root.render require angle brackets around App?**

---

**ANSWER**

**The code does not do what we wanted.** `App` is a bare JavaScript function, but `root.render` expects a React element.

In React, a component is a JavaScript function that returns markup descriptions. When you pass `App` without angle brackets, you pass the raw function object itself. React cannot display a function object on the screen. Writing `<App />` creates a **React element**: an object descriptor that tells React to execute the `App` component function and render the resulting JSX tree.

The fix is wrapping `App` in JSX angle brackets: `root.render(<App />)`. The method `root.render` accepts React elements, strings, numbers, `null`, or `undefined`. If a factory helper function returns a JSX element, call the function so `root.render` receives the returned element: `root.render(createApp())`.

```ascii title="Bare function reference vs React element descriptor"
root.render(App):
  Value passed: [Function: App]  (raw JavaScript function reference)
  React runtime: Cannot mount bare function -> Error: Functions not valid

root.render(<App />):
  Value passed: { type: App, props: {} }  (React element descriptor)
  React runtime: Calls App(), receives JSX, mounts resulting DOM nodes
```

> [!PRINCIPLE]
> **Principle 3: Pass root.render an element, <App />**
> A React component is a JavaScript function, but root.render requires a **React element** to mount. Writing the bare name App passes a function reference, which React cannot display on the page. Writing <App /> creates an element descriptor that instructs React to call the component function and render its returned markup. When rendering a helper function that returns JSX, call the function first so root.render receives the resulting element.
>
> >> React element : an object descriptor created with JSX that instructs React what markup to mount
>
> *We should do this:*
> `const root = createRoot(document.getElementById('root'));`
> `root.render(<App />); // passes a React element descriptor`
>
> *We should not do this:*
> `const root = createRoot(document.getElementById('root'));`
> `root.render(App); // error: Functions are not valid child`

### Question 4: Older tutorials that call `ReactDOM.render` fail in React 19

A developer consults an older tutorial and attempts to mount the application using the classic `ReactDOM.render` syntax:

```jsx title="Legacy Mounting Pattern"
import ReactDOM from 'react-dom'; // Legacy package import
import App from './App.jsx';

const container = document.getElementById('root');

// Legacy mounting method removed in React 19:
ReactDOM.render(<App />, container); // Throws runtime TypeError
```

When the script runs in the browser, JavaScript halts with an uncaught error: `TypeError: ReactDOM.render is not a function`. The screen stays blank.

**Why does ReactDOM.render fail in modern React projects?**

---

**ANSWER**

**The code does not do what we wanted.** React 19 completely removed the legacy `ReactDOM.render` method.

In React 19, legacy mounting functions, including `ReactDOM.render`, `ReactDOM.hydrate`, and `unmountComponentAtNode`, were permanently removed. Applications must import `createRoot` from the client renderer subpath, `'react-dom/client'`. You create the root once with `createRoot(container)`, and call `root.render` with a single argument: the React element.

If a developer carries over the old two-argument habit and writes `root.render(<App />, container)`, React logs a console warning: `Warning: You passed a second argument to root.render(...) but it only accepts one argument.` Any root configuration options, such as `onUncaughtError`, must be passed as the second argument to `createRoot(container, options)`, not to `root.render`.

```ascii title="Legacy ReactDOM.render vs modern createRoot API"
Legacy React (Removed in React 19):
  ReactDOM.render(<App />, container);  -->  TypeError: render is not a function

Modern React 19:
  const root = createRoot(container);   -->  prepares concurrent root container
  root.render(<App />);   -->  schedules mounting with single argument
```

> [!PRINCIPLE]
> **Principle 4: Start the app with createRoot, not with ReactDOM.render**
> React 19 completely removed the legacy ReactDOM.render function. Applications must import createRoot from react-dom/client, initialize the root container once, and call root.render with a single React element argument. The render method accepts only one parameter; passing the DOM container or configuration options as a second argument to root.render triggers a console warning. Pass root options directly to createRoot as its second argument.
>
> >> client subpath : the react-dom/client import path providing browser-specific root creation functions
>
> *We should do this:*
> `import { createRoot } from 'react-dom/client';`
> `const root = createRoot(document.getElementById('root'));`
> `root.render(<App />); // modern client root mounting`
>
> *We should not do this:*
> `import ReactDOM from 'react-dom'; // removed in React 19`
> `ReactDOM.render(<App />, document.getElementById('root'));`

### Question 5: Calling createRoot twice on the same container triggers a warning

A developer wants to display an application layout and a status card. In `src/main.jsx`, they find `<div id="root">` and call `createRoot` twice to mount each section:

```jsx title="Duplicate Root Containers"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';
import StatusCard from './components/StatusCard.jsx';

const container = document.getElementById('root');

createRoot(container).render(<App />); // First root created
createRoot(container).render(<StatusCard />); // Duplicate root
```

The browser renders the list, but the console logs: `Warning: You are calling ReactDOMClient.createRoot() on a container that has already been passed to createRoot() before. Instead, call root.render() on the existing root to update it.`

**Why does calling createRoot multiple times on the same container cause issues?**

---

**ANSWER**

**The code does not do what we wanted.** Initializing multiple roots on the same DOM element creates conflicting root containers.

When you pass a DOM node to `createRoot(container)`, React creates an internal root record and assumes exclusive ownership of the DOM inside that container. Calling `createRoot` again on that same element creates a second, competing root that attempts to control the same physical DOM nodes. This creates memory leaks, overrides event listeners, and breaks React's update guarantees.

In an application built fully with React, you call `createRoot` exactly once at startup in `main.jsx`. All user interface sections should be composed as child components nested inside `App`. Components update the page using state, not by creating additional roots. If you are embedding React into an existing multi-page website that is only partially built with React, you create one root for each separate physical HTML container on the page.

```ascii title="Single root architecture vs duplicate root warning"
Single Root (Correct):
  createRoot(#root)  -->  Root  -->  <App />  -->  <StatusCard />

Duplicate Roots (Broken):
  createRoot(#root)  -->  Root 1  -->  <App />        (competing control)
  createRoot(#root)  -->  Root 2  -->  <StatusCard /> (warning: already passed)
```

> [!PRINCIPLE]
> **Principle 5: Create one root, and nest everything else inside App**
> In an application built fully with React, create a single root container at startup in main.jsx. That root manages the entire DOM tree inside its container. Calling createRoot multiple times on the same DOM element causes conflicting update cycles and logs a warning. Add new interface sections by nesting child components inside App rather than creating additional roots. When embedding React into an existing multi-page website, create one root for each separate physical container element.
>
> >> single root : an application architecture where one root container manages the complete component hierarchy
>
> *It is best practice to do this:*
> `const root = createRoot(document.getElementById('root'));`
> `root.render(<App />); // one root: all components nest inside App`
>
> *Instead of doing this:*
> `const container = document.getElementById('root');`
> `createRoot(container).render(<App />);`
> `createRoot(container).render(<StatusCard />); // duplicate root`

### Step 1: First, we inspect the host HTML document <index.html>

We begin at the root of the project by inspecting `index.html`. Unlike traditional web pages containing hundreds of lines of static layout markup, our React host document contains a minimal shell. Inside `<body>`, we define `<div id="root">` with a loading placeholder that appears while JavaScript downloads. We link our application entry point using `<script type="module" src="/src/main.jsx"></script>`. Because the script tag uses `type="module"`, the browser defers execution until the HTML document is fully parsed, ensuring `document.getElementById('root')` can always find the container.

```html title="index.html"
<!DOCTYPE html>
<html lang="en">
  <head>
    <title>Task Tracker</title>
  </head>
  <body>
    <div id="root"><p>Loading...</p></div> <!-- Host container -->
    <script type="module" src="/src/main.jsx"></script> <!-- Module entry -->
  </body>
</html>
```

The `<div id="root">` element acts as the single boundary that React will control. The `<script type="module">` tag tells the browser to treat `main.jsx` as an ES module and execute it after the document has been parsed.

### Step 2: Next, we construct the root application component <src/App.jsx>

With our host HTML document established, we create `src/App.jsx`. This component acts as the root of our React component tree. Notice that `App.jsx` imports purely from `'react'` and child component modules; it contains zero imports from `'react-dom'` or `'react-dom/client'`. By keeping `App` isolated from the DOM mounting bridge, our component remains pure, testable, and independent of browser-specific mounting code. In this step, `App` renders the application heading and prepares a container for our child status card.

```jsx title="App.jsx"
import StatusCard from './components/StatusCard.jsx'; // Child module

export default function App() {
  return (
    <main className="tracker-layout"> {/* Root layout container */}
      <h1>Task Tracker</h1>
      <StatusCard label="PENDING" count={3} /> {/* Composes child */}
    </main>
  );
}
```

Notice how `App` acts as the orchestrator. It imports `StatusCard` as a child component and passes it dynamic props. It never interacts with `document.getElementById` or touches browser DOM nodes directly.

### Step 3: Then, we declare the child item card component <src/components/StatusCard.jsx>

Following our single root architecture, we grow our application by adding components inside `App`, rather than creating additional roots. We create `src/components/StatusCard.jsx` to display active task counts. It receives `label` and `count` props, wraps them in a styled container, and renders declarative JSX. Because this component lives in its own module, other views can reuse it without touching `App.jsx` or the mounting entry file.

```jsx title="StatusCard.jsx"
export default function StatusCard({ label, count }) { // Leaf props
  return (
    <aside className="status-card"> {/* Styled container */}
      <span className="label">{label}</span>
      <p className="count-text">{count} Items Active</p>
    </aside>
  );
}
```

Notice that `StatusCard` is a self-contained leaf component. It has a single responsibility: rendering an item count and label. It receives data through props and returns declarative JSX without managing external state.

### Step 4: Finally, we initialize createRoot and mount the tree <src/main.jsx>

Finally, we connect our React application to the browser page in `src/main.jsx`. We import `createRoot` from `'react-dom/client'` and import our top-level `App` component. We find the container element using `document.getElementById('root')`. We verify that the element exists with `if (container)` before passing it to `createRoot`, and call `root.render(<App />)` with our root JSX tag. When Vite serves this project, React mounts `App`, clears the loading placeholder, and renders the complete user interface into the browser window.

```jsx title="main.jsx"
import { createRoot } from 'react-dom/client'; // React 19 client
import App from './App.jsx'; // Root component

const container = document.getElementById('root'); // Finds container

if (container) {
  const root = createRoot(container); // Connects to DOM
  root.render(<App />); // Mounts tree into container
}
```

Notice the clean sequence in `main.jsx`. We first find the container node. We verify it exists before passing it to `createRoot`. Once the root is initialized, `root.render(<App />)` mounts the virtual tree into the physical container.

### For the interview

> **The Interview Question:** How does your root component attach to the browser DOM with createRoot, and how do build tools assemble it?

**1. The Hidden Signal**

The interviewer is not asking whether you can memorize three lines of boilerplate. They are probing whether you understand the fundamental boundary between the declarative React component model (`react`) and the imperative browser DOM mounting renderer (`react-dom/client`). A junior developer treats `main.jsx` as magic syntax; a senior engineer explains that React needs an explicit mounting bridge to bind virtual element descriptor trees to physical HTML containers, and that build tools transform JSX into browser-compatible modules because native browser engines cannot parse JSX or resolve bare package specifiers.

**2. The Classic Trap**

The classic trap is assuming that `root.render` updates the browser DOM synchronously on the spot, or reciting legacy methods from older tutorials. Candidates often claim that `ReactDOM.render` is still supported, unaware that React 19 completely removed legacy mounting functions. Another fatal trap is writing `root.render(App)` without JSX angle brackets, passing a raw function reference that causes React to crash with `Functions are not valid as a React child`.

**3. What is Actually Going On**

The mounting pipeline follows four distinct steps. First, `index.html` loads `main.jsx` using a deferred `<script type="module">` tag. Second, `document.getElementById('root')` finds the physical container element in memory. Third, `createRoot(container)` creates a React root object that takes exclusive ownership of that container. Fourth, `root.render(<App />)` schedules the mounting of the `<App />` element tree into the container. React clears any placeholder content inside the container and paints the component output. In development, Vite intercepts requests, transforms JSX into `_jsxDEV` calls, and serves native modules over HTTP. For production, `vite build` bundles everything into static files inside `dist/`.

**4. Where It Gets Tricky**

What happens if you inspect `container.textContent` immediately after calling `root.render(<App />)`? It still contains the old placeholder text because `root.render` schedules updates asynchronously rather than blocking the JavaScript thread synchronously. What happens if you call `createRoot` twice on the same container? React logs a warning because duplicate roots create competing ownership of the same DOM tree; you should always create one root per application and nest all UI inside `App`. What happens if you double-click `index.html` from your desktop? Modern browsers block module scripts over the `file://` protocol with CORS errors, requiring files to be served over HTTP via Vite.

### Glossary

- **createRoot**: The modern React DOM client method that creates a root container for a physical browser element.
- **root.render**: The root method that schedules the rendering of a React element tree into the designated DOM container.
- **root container**: The physical HTML element, typically `<div id="root">`, that React takes over to manage its user interface.
- **module script**: An HTML `<script type="module">` tag that loads ES modules and automatically defers execution until HTML parsing completes.
- **dev server**: A local development HTTP server that compiles JSX on demand and serves native ES modules with instant updates.
- **single root**: An application architecture where one root container manages the complete component hierarchy from a single top-level component.

### Summary

**Architectural Takeaways & Decision Matrix**

❒ Root Initialization & Container Ownership

➔ ALWAYS pass an existing DOM element to `createRoot` and let React take exclusive ownership of that container.

➔ NEVER call `createRoot` multiple times on the same container; nest all interface sections as child components inside `App`.

➔ IF you are embedding React into an existing multi-page website with separate widgets, THEN create one root for each separate physical DOM container.

❒ Tooling & Mounting APIs

➔ ALWAYS import `createRoot` from `react-dom/client` in your entry file, and pass `root.render` a React element like `<App />`.

➔ NEVER open React projects over the `file://` protocol; always serve them over HTTP using the Vite development server.

➔ NEVER call the removed `ReactDOM.render` method or pass a second argument to `root.render`.

**DO THIS:** import createRoot from react-dom/client and render a React element

```jsx right
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = document.getElementById('root');
const root = createRoot(container);
root.render(<App />);
```

**DO NOT DO THIS:** import removed legacy render or pass raw functions without JSX tags

```jsx wrong
import { render } from 'react-dom';

render(App, document.getElementById('root'));
```
