Lecture 4: JavaScript Expressions in JSX with Curly Braces

Interview Question

CORE

How do you use JavaScript expressions inside JSX with curly braces?

Imagine this scenario:

  1. You move an article into a component, and its title, its author, and the address of its photo now sit in variables at the top of the function.
  2. You write the title into the markup, save, and the page shows the word title; the photo is a broken image.
  3. How does markup that looks like HTML read the values that live in JavaScript?

A page shows values that live in JavaScript

Almost nothing on a real page is typed once and left alone. An article card shows a title, the author's name, the date, and a photo, and each of them comes from somewhere: a database, a form, a calculation. In JavaScript, a value like that lives in a variable. In Lecture 3, every tag we pasted from the old site held fixed text, and every attribute held a fixed value in quotes. Every value in this lesson is fixed in local variables. A value that changes over time while the user interacts with the page requires state, which Lecture 14 introduces. So every React developer meets the same question: how does markup that looks like HTML read the values that live in JavaScript?

The answer is one idea, and this chapter follows it from the first question to the last: curly braces open a window to JavaScript: the code inside runs when React calls the component, and its value takes the place of the braces. Each rule of the chapter follows one value through that window: where it opens, in the text or in an attribute; what it holds, an expression or a comment; and what comes out, a value the page shows or an object it does not.

This lesson answers six questions:

  • Lecture 1 wrote {userName}. What do the braces actually do, and what stays text?
  • My image address is in a variable. How do I put it into src?
  • The label should say Live now only when the article is live. Can I write an if inside the braces?
  • The HTML I pasted in Lecture 3 has comments. How do I keep a note in my markup?
  • My label says Live: {isLive}. Why does the page show only Live:?
  • Why does my date crash the page, and why do some attributes have two pairs of braces?

The questions stand on what Lectures 1, 2, and 3 established:

  • Lecture 1 (What is React): A component describes what the page shows, and React builds the DOM from that description. A local variable made with const holds a value inside the component, and {userName} showed that value in the greeting and in the corner. This chapter explains what those curly braces do.
  • Lecture 2 (Component anatomy): React calls our component wherever a tag names it; that call is rendering. console.log prints in the Console panel, once per call in this course's projects. A function returns undefined when it gives back nothing.
  • Lecture 3 (JSX syntax): The build turns each tag into a call that returns an object, a React element, and the Sources panel shows those calls. An object keeps values under names, its properties. When the build cannot read a file, Vite's error overlay covers the page. Attributes are JavaScript names, such as className.

Some code gives back a value, and some code only does a job

JavaScript code comes in two kinds. An expression is code that gives back a value: 540, wordCount, wordCount / 200, and Math.ceil(wordCount / 200) are all expressions. A statement is code that does a job and gives back nothing we can keep: const makes a variable, if decides whether to run some lines, and for repeats them. A simple test tells them apart: an expression can stand on the right of =, and a statement cannot.

Plain JavaScript: expressions and a statement
1const wordCount = 540;
2const readTime = Math.ceil(wordCount / 200);
Evaluates expression to 3
3if (readTime > 2) {
Statement checks condition without yielding value
4 console.log('A long read');
5}

wordCount / 200 gives back 2.7, and Math.ceil rounds it up, so readTime holds 3. The if checks whether readTime is more than 2 and runs the line inside, so the Console panel shows "A long read". We could write const result = Math.ceil(wordCount / 200) but never const result = if (readTime > 2) ...

The ternary operator chooses one of two values

Sometimes the value depends on a yes-or-no question. The ternary operator asks it in one expression: a condition, a question mark, the value for yes, a colon, and the value for no. Because it gives back a value, it can stand on the right of =, where an if cannot:

Plain JavaScript: a ternary chooses a value
1const isLive = false;
2const label = isLive ? 'Live now' : 'Recorded';
Evaluates to 'Recorded'

The condition isLive is tested. Because it is false, the expression chooses 'Recorded' and stores it in label.

Two ways to build a text from pieces

An address such as /images/library-hours.jpg is often built from a fixed start, a value, and a fixed end. String concatenation joins texts with +. A template literal does the same in one text: it is written between backticks, and ${...} inside it puts in the value of an expression:

Plain JavaScript: concatenation and a template literal
1const imageId = 'library-hours';
2const first = '/images/' + imageId + '.jpg';
3const second = `/images/${imageId}.jpg`;
Evaluates to the same path

Both approaches produce the identical string /images/library-hours.jpg.

JavaScript has values for yes, no, and nothing

A yes-or-no value is a boolean: true or false. A variable such as isLive holds one. JavaScript also has two values that mean "nothing here": undefined, which Lecture 2 met as the result of a function that gives back nothing, and null, which we write on purpose when a value is missing.

A date is an object

JavaScript keeps a date in a Date object. new Date(2026, 9, 15) makes October 15, 2026; the months count from 0, so 9 is October. A date is an object, not a text, so to show it we ask it for a text: toLocaleDateString('en-US') gives back '10/15/2026'.

Some HTML attributes take a yes or a no, and one takes CSS

Some HTML attributes are on or off. A boolean attribute such as disabled works by being there: <button disabled> is disabled, and so is <button disabled="false">, because the browser looks only at whether the attribute exists, not at its text.

The style attribute sets CSS on one element: in HTML it holds CSS text, such as style="color: gray". A class in a stylesheet is the usual way to style; style is for a value that only this element has.

Principles of React: Curly Braces Open a Window to JavaScript

Everything in this lesson comes down to one idea: curly braces open a window to JavaScript, and the value of the code inside takes their place.

The first two principles say where the window opens. First, embedding expressions, which means curly braces put a JavaScript value where the text goes: the name of a variable in braces shows its value, and everything outside the braces stays text. Second, dynamic attributes, which means curly braces put a JavaScript value where the attribute value goes: the whole value goes in one pair of braces, with no quotes, and quotes stay for fixed text.

The next two say what the window holds. Third, expressions, not statements, which means curly braces hold code that produces a value: a variable, a sum, a call, or a choice with a question mark, but never a statement such as if. Fourth, JSX comments, which means curly braces hold a comment the page never shows: a note in the markup goes inside braces, between a slash and a star.

The last two say what comes out. Fifth, rendered values, which means curly braces show strings and numbers, and nothing for true, false, null, and undefined: a value the reader must see becomes text first. Sixth, double curlies, which means curly braces pass an object only to an attribute that expects one: an object is never shown as text, and the style attribute takes one inside a second pair of braces.

PRINCIPLE 1

Embedding expressions: curly braces put a JavaScript value where the text goes

We put a value from JavaScript into the text by writing it in curly braces; everything outside the braces stays text, and the code inside runs each time React calls the component.

Curly braces between JSX tags create an evaluation window. The JavaScript expression inside the braces is evaluated on every render cycle, and its result takes the place of the braces in the DOM. Any text outside the braces remains literal text. When an expression and text are separated by a line break, JSX strips the intervening whitespace, so spaces between values and words must be kept explicitly on the same line or with a spaced string expression.

We should do this:
const minutes = 4;
<p>{minutes} min read</p>
Displays number with space before word
We should not do this:
const minutes = 4;
<p>
{minutes}
min read
PROBLEMATIC: dropped break touches number
</p>

My image address is in a variable. How do I put it into src?

ANSWER

The code does not do what we wanted. Both image elements fail to load their source files.

Inspect the Elements panel. The markup reveals that the browser received the literal text inside quotes:

Elements panel: literal strings in attributes
1<img src="{avatarUrl}" alt="Author">
Requests literal brace path
2<img src="/images/{imageId}.jpg" alt="Library">

Quotes always pass fixed text in JSX, whether or not curly braces are written inside them. When the browser attempts to fetch src="{avatarUrl}", it requests /%7BavatarUrl%7D from the dev server, which does not exist. Similarly, src="/images/{imageId}.jpg" asks for the literal filename {imageId}.jpg.

Curly braces only open a JavaScript window in attributes when placed directly after the equals sign without quotes. To pass a single variable, write src={avatarUrl}. To build an attribute from multiple pieces, write one complete JavaScript expression inside the braces using concatenation or a template literal:

App.jsx
1function ArticleCard() {
2 const avatarUrl = '/samantha-robinson.jpg';
3 const imageId = 'library-hours';
4 return (
5 <article>
6 <img src={avatarUrl} alt="Author" />
Evaluates variable path
7 <img src={`/images/${imageId}.jpg`} alt="Library" />
Valid path
8 </article>
9 );
10}

The same rule applies to boolean attributes. In HTML, writing disabled="false" still disables a button because the browser checks whether the attribute is present, not what text it holds. React warns in the console: "Received the string false for the boolean attribute disabled. Did you mean disabled={false}?". Writing disabled={false} tells React to omit the attribute from the DOM completely.

PRINCIPLE 2

Dynamic attributes: curly braces put a JavaScript value where the attribute value goes

We give an attribute a value from JavaScript by writing the whole value in one pair of curly braces, right after the equals sign and with no quotes, and we keep quotes for fixed text.

Attributes in JSX accept either quotes for literal string values or curly braces for dynamic JavaScript values. Putting quotes around curly braces treats the braces as literal characters. To evaluate an expression for an attribute, place the curly braces directly against the equals sign with no quotes. When combining fixed paths with variables, construct the entire string inside the single pair of braces using template literals or string concatenation.

We should do this:
const photoUrl = '/john-hall.jpg';
<img src={photoUrl} alt={name} />
Evaluates variable as image path
We should not do this:
const photoUrl = '/john-hall.jpg';
<img src="{photoUrl}" alt="{name}" />
PROBLEMATIC: quotes request literal path

The label should say Live now only when the article is live. Can I write an if inside the braces?

ANSWER

The code does not do what we wanted. The build fails immediately with a parse error:

Vite error overlay: unexpected token
[PARSE_ERROR] Unexpected token
 5 │       <p>{if (isLive) { 'Live now' }}</p>
   │           ─┬─

Recall from Lecture 3 that JSX tags become function calls. The content between tags becomes the children argument of that call. In JavaScript, arguments to a function can only be expressions, code that computes and produces a value.

An if statement is a control flow statement. It executes actions, but it produces no value that can be assigned or passed. JavaScript does not allow a statement to stand where an expression is expected, so the compiler halts before generating any runnable code. for loops and variable declarations with const fail for the same reason.

To choose between values inside JSX braces, use the ternary operator because it is an expression that yields a value:

App.jsx
1function ArticleCard() {
2 const isLive = false;
3 return (
4 <article>
5 <h2>City Library Extends Its Hours</h2>
6 <p>{isLive ? 'Live now' : 'Recorded'}</p>
Ternary yields value
7 </article>
8 );
9}

Save, and the page renders "Recorded". If the logic requires multiple statements or complex branches, execute the if statement above the return in standard JavaScript, assign the result to a local variable, and reference that variable inside the braces:

App.jsx
1function ArticleCard() {
2 const isLive = false;
3 let status = 'Recorded';
Initializes fallback status string
4 if (isLive) {
5 status = 'Live now';
6 }
7 return (
8 <p>{status}</p>
Reads result computed before return
9 );
10}

Curly braces can contain any JavaScript expression: mathematical calculations like {Math.ceil(wordCount / 200)}, method calls like {title.toUpperCase()}, or function invocations. However, curly braces cannot replace tag names: writing <{tag}> is illegal syntax and stops the build.

PRINCIPLE 3

Expressions, not statements: curly braces hold code that produces a value

We put only an expression, code that produces a value, inside curly braces: a variable, a sum, a call, or a ternary; a statement such as if goes above the return, and its result goes into the braces through a variable.

Curly braces in JSX compile to object property assignments or function call arguments, which only accept expressions. Statements like if, for, let, or const do not evaluate to values and trigger parse errors at build time. When conditional logic must reside directly inside JSX markup, use ternary expressions. When logic spans multiple statements, compute the result into a local variable before the return statement and pass that variable into the JSX braces.

We should do this:
const isOnline = true;
<p>{isOnline ? 'Online' : 'Away'}</p>
Ternary evaluates to string
We should not do this:
const isOnline = true;
<p>{if (isOnline) { 'Online' }}</p>
WRONG: statement halts compiler

QUESTION 5

A boolean in the braces shows nothing

The developer adds a status indicator to show whether the library is open for live consultations:

App.jsx
1function ArticleCard() {
2 const isLive = false;
3 return (
4 <article>
5 <h2>City Library Extends Its Hours</h2>
6 <p>Live: {isLive}</p>

7 </article>
8 );
9}

The developer saves. The card appears, but the paragraph reads only "Live: " with a blank space where the boolean should be. The Console panel shows zero warnings or errors.

My label says Live: {isLive}. Why does the page show only Live:?

ANSWER

The code does not do what we wanted. The boolean value is completely invisible on the page.

In JavaScript, console.log(false) prints the word "false" to the console. React behaves differently. React renders strings and numbers as visible text nodes, but it intentionally ignores true, false, null, and undefined:

What JSX renders for each JavaScript value
Value        Inside braces         What appears on screen
'text'       {'text'}              text
42           {42}                  42
0            {0}                   0
true         {true}                (nothing)
false        {false}               (nothing)
null         {null}                (nothing)
undefined    {undefined}           (nothing)

React skips booleans, null, and undefined so that conditional rendering expressions can output nothing when a condition is not met. If false rendered as the word "false", writing {isLoggedIn && <UserMenu />} would print "false" on screen for logged-out visitors. An array of strings in braces shows its items joined, while turning an array of data into a list of elements with keys is the subject of Lecture 11.

Notice that the number 0 is not ignored. 0 is a number, and numbers always render on screen. Lecture 10 explores how this distinction impacts conditional rendering bugs.

This silent omission also hides typos. If you reference {author.nmae} instead of {author.name}, the expression evaluates to undefined, and React renders an empty string without warning.

When you want a boolean value to be visible to the user, convert it to a string explicitly using a ternary operator:

App.jsx
1function ArticleCard() {
2 const isLive = false;
3 return (
4 <article>
5 <h2>City Library Extends Its Hours</h2>
6 <p>Live: {isLive ? 'Yes' : 'No'}</p>
Converts boolean to text
7 </article>
8 );
9}

Save, and the paragraph reads "Live: No". If a function identifier is placed inside braces without parentheses, such as {formatDate}, React renders nothing and logs an explicit warning: "Functions are not valid as a React child. ... Or maybe you meant to call this function rather than return it.". Always invoke functions with parentheses: {formatDate()}.

PRINCIPLE 5

Rendered values: curly braces show strings and numbers, and nothing for true, false, null, and undefined

We expect strings and numbers to show as text, and true, false, null, and undefined to show nothing, so a value the reader must see, such as yes or no, becomes text before it reaches the braces.

React transforms strings and numbers into text nodes in the DOM, including zero and NaN. To make conditional rendering seamless, React intentionally suppresses booleans, null, and undefined, rendering no DOM nodes for them without error. When boolean states or missing values must be visible to the end user, convert them into string literals before rendering by using ternary operators or explicit formatting functions.

We should do this:
const isVerified = false;
<p>
Verified: {isVerified ? 'Yes' : 'No'}
Evaluates to 'No' string
</p>
We should not do this:
const isVerified = false;
<p>Verified: {isVerified}</p>
PROBLEMATIC: boolean renders no DOM text

PRINCIPLE 6

Double curlies: curly braces pass an object only to an attribute that expects one

We show a field of an object or a formatted string, never the object itself, and we pass an object only to an attribute that expects one, such as style, where the outer braces open the window and the inner braces write the object.

Plain JavaScript objects and Date instances have no default text representation and cannot be rendered directly as JSX children. Placing an object between tags throws a runtime error that unmounts the component tree. Always extract primitive values or call formatting methods before rendering. Double curly braces are not special syntax; they represent an object literal passed inside a single JSX attribute evaluation window.

We should do this:
const joinedAt = new Date(2024, 2, 5);
<p style={{ color: 'gray' }}>
Passes inline style object
Member since {joinedAt.toLocaleDateString('en-US')}
</p>
We should not do this:
const joinedAt = new Date(2024, 2, 5);
<p>Member since {joinedAt}</p>
WRONG: object child crashes render

⚡ IN THE WILD

Does a string that holds HTML tags show as HTML? A reader's comment might arrive from an API containing HTML markup, such as '<b>Updated</b>'. A developer might expect the browser to render bold text. However, React writes every string into the page as literal text, creating a text node rather than parsing HTML elements. The browser displays the literal angle brackets and letters <b>Updated</b> and the Elements panel shows &lt;b&gt;Updated&lt;/b&gt;. This automatic escaping is a built-in security feature that protects users from Cross-Site Scripting (XSS) attacks. Lecture 48 covers dangerouslySetInnerHTML, the explicit property used when raw HTML must be injected intentionally.

A developer coming from HTML or templating libraries brings three ingrained habits: expect quotes to read variables, put statements such as if inside braces, and expect objects like dates to print automatically. Each habit meets JavaScript in its own way. Quotes always pass fixed text, statements produce no value and halt the build, and objects cannot be converted to text and crash the render. In React 19, the three steps followed the thread: opening the braces in text and attributes, computing expressions and notes inside them, and ensuring that every value that reaches the page is a string or a number.

For the interview

The Interview Question: How do you use JavaScript expressions inside JSX with curly braces?

1. The Hidden Signal

The interviewer wants to hear that curly braces are not template markers: they are an evaluation window into JavaScript that becomes an argument in a function call. A strong candidate explains that braces accept only expressions that produce values, and that the resulting value takes the place of the braces when React renders the component.

2. The Classic Trap

The classic trap is saying "You can write any JavaScript inside JSX braces." You cannot write statements such as if, for, or const inside braces because statements produce no value; they cause build errors. A second trap is believing that {{ }} is a special syntax, rather than an object literal passed to an attribute window.

3. What is Actually Going On

Braces open a JavaScript window in two places: between tags as children, and after an attribute equals sign as a prop. Between tags, React converts strings and numbers into text, while silently skipping true, false, null, and undefined. Objects, including Date instances, cannot be converted to text and crash the render with an error. In attributes, braces pass raw JavaScript values directly, without quotes.

4. Where It Gets Tricky

Why does {false} render nothing while {0} renders 0?

React treats boolean values, null, and undefined as invisible values so conditional expressions can render nothing cleanly. Numbers are treated as visible content, so 0 is converted to the character "0".

Why does rendering a Date object crash the whole component?

React does not guess how an object should look as text. It throws "Objects are not valid as a React child", which removes the entire component tree unless caught by an error boundary.

What does src="{avatarUrl}" actually pass to the browser?

It passes the literal string "{avatarUrl}". The browser encodes the braces and requests /%7BavatarUrl%7D, resulting in a broken image. Dynamic attributes must omit quotes: src={avatarUrl}.

How do you write a comment inside JSX markup?

Between tags, you open curly braces and write a multi-line JavaScript comment: {/* comment */}. Plain <!-- --> comments cause a syntax error, and // comments render as visible text on the page.

Glossary

  • Expression: JavaScript code that produces a value, such as wordCount / 200, Math.ceil(x), or a ternary.
  • Statement: JavaScript code that performs an action without producing a value, such as if, for, or const.
  • Ternary operator: An expression that tests a condition and produces one of two values, written as condition ? yes : no.
  • Template literal: A string written between backticks that evaluates expressions inside ${...}.
  • Boolean: A JavaScript value representing true or false.
  • null: A JavaScript primitive representing the intentional absence of any object value.
  • JSX comment: A comment inside JSX markup written as {/* ... */} within curly braces.
  • Double curlies: The appearance of an object literal passed directly into a JSX attribute window, as in style={{ color: 'gray' }}.
  • Date: A JavaScript built-in object that represents a single moment in time.

Curly braces open a window to JavaScript

❒ Embedding expressions: curly braces put a JavaScript value where the text goes

➔ ALWAYS write dynamic text inside curly braces between tags.

➔ NEVER put a line break between a value and text if you want a space; use {' '} if formatters break the line.

❒ Dynamic attributes: curly braces put a JavaScript value where the attribute value goes

➔ ALWAYS pass JavaScript values to attributes using curly braces right after = with no quotes.

➔ NEVER put quotes around curly braces or variable names in attributes; quotes always pass fixed text.

➔ ALWAYS place expressions such as variables, calculations, calls, and ternaries inside curly braces.

➔ NEVER put statements such as if, for, or const inside braces; put them above the return.
