### What is an Effect: Synchronizing with External Systems

Component logic in React falls into two distinct categories:

- **Rendering code**: The calculation phase located in the top-level body of your component. It takes props and state, calculates JSX, and must remain completely pure. It must never reach outside the component or trigger side effects.
- **Event handlers**: Nested functions triggered by specific user interactions like clicks, submits, or keyboard input. These handle side effects like saving an article or submitting a form.

However, many applications require code to execute not because of a specific button click, but because the component appeared on the screen or because its reactive properties changed. Examples include:

- Subscribing to an external WebSocket, Server-Sent Events feed, or real-time message queue.
- Registering global browser event listeners on the `window` or `document` (such as resize or keydown handlers).
- Initializing a third-party, non-React plugin like a Leaflet map or a charting canvas.
- Starting a persistent interval timer to ping an external server.

In React, an **Effect** is an intentional escape hatch designed to synchronize your component with an **external system** outside React's control.

> [!WILD]
> **What is the purpose of an Effect?** Imagine a submarine diving deep beneath the ocean waves. Inside the submarine, the navigation computers calculate depth and speed purely from internal equations. The crew does not open the submarine's outer hatch just to check their math! But if the submarine needs to receive a sonar broadcast from a surface ship, it extends an external antenna through the hull into the open water. When the mission ends or the submarine changes course, it retracts the antenna safely back into the hull. That is useEffect. Your component is the submarine. Rendering is pure internal navigation math. The external ocean is the outside world: WebSockets, browser event listeners, or third-party APIs. The Effect extends the antenna, and the cleanup function retracts it. If you forget to retract the antenna, it snaps off and floods the vessel with water! Understanding **rendering** as **internal navigation** and **useEffect** as an **extendable antenna** clarifies why **Effects exist to synchronize with external systems**.

### The Setup and Cleanup Symmetry and Strict Mode

The fundamental contract of `useEffect` is **symmetry**. Whatever side effect your setup function creates, your cleanup function must dismantle:

```js title="Setup and Cleanup Symmetry"
useEffect(() => {
  const sub = externalSystem.subscribe(); // Setup opens connection, starts timer, or adds listener

  return () => {
    sub.unsubscribe(); // Cleanup closes connection, cancels timer, or removes listener
  };
}, [dependency]);
```

React manages this symmetry across the component lifecycle:

1. **Mounting**: React runs the setup code after committing the component to the DOM.
2. **Re-rendering with changed dependencies**: React runs the cleanup code from the *previous* render using the old dependency values, and then immediately runs the setup code with the new dependency values.
3. **Unmounting**: React runs the cleanup code one final time to detach from the external system permanently.

In development mode, React wraps your components in `<StrictMode>`. Under Strict Mode, React intentionally mounts your component, runs the cleanup, and immediately re-mounts it: `Setup -> Cleanup -> Setup`.

This double-execution is not a bug; it is an intentional audit designed to expose missing cleanup functions. If your setup code opens a connection but your cleanup does not close it, you will immediately see two open connections in your network console.

> [!WILD]
> **Why does React run Effects twice in development?** Imagine a parachute manufacturer testing emergency parachutes before soldiers board an airplane. The inspector does not just pack the chute once and say "looks good." The inspector pulls the rip cord to deploy the canopy, checks that it opens fully, folds it back up neatly into the pack, and then deploys it a second time to prove that it can be reset and deployed flawlessly! That is React Strict Mode. React mounts your component (deploys the parachute), immediately runs your cleanup (packs it back up), and then mounts it again. If your setup opens a WebSocket but your cleanup does not close it, you are left with two open sockets, instantly exposing the defect in development. Understanding **Strict Mode** as a **parachute deployment test** clarifies why **running effects twice proves setup and cleanup symmetry**.

### The National Times Live Feed Subscription Architecture

To observe `useEffect` synchronization in production, inspect the live news feed subscriber for The National Times. The component subscribes to real-time bulletin updates from an external mock feed client:

```components title="national-times — Component Explorer"
LiveFeedApp.jsx | | generic
  FeedSubscriber.jsx | topic="..." | card | Active Feed Topic: breaking ;; [BREAKING] Bulletin at 10:45:00 AM
    feedClient.js | | api
```

The component explorer panel above shows the hierarchy. On the left, `LiveFeedApp.jsx` controls the selected topic and toggles the subscription. On the right, `FeedSubscriber.jsx` receives `topic` as a prop and synchronizes with `feedClient.js`.

First, examine the external system API `feedClient.js`:

```js title="feedClient.js"
export function createFeedConnection(topic) {
  let activeInterval = null;

  return {
    connect(onMessage) {
      activeInterval = setInterval(() => {
        onMessage(`[${topic.toUpperCase()}] Bulletin at ${new Date().toLocaleTimeString()}`);
      }, 3000);
    },
    disconnect() {
      if (activeInterval) {
        clearInterval(activeInterval);
        activeInterval = null;
      }
    },
  }; // External system provides explicit connect and disconnect **SYMMETRY**
}
```

The external client constructor provides symmetrical `connect` and `disconnect` methods. If `disconnect` is never called, the interval continues running forever in the browser background.

Next, examine the subscriber component `FeedSubscriber.jsx`:

```jsx title="FeedSubscriber.jsx"
import { useEffect, useState } from 'react';
import { createFeedConnection } from './feedClient.js';

export default function FeedSubscriber({ topic }) {
  const [bulletin, setBulletin] = useState('Connecting to live feed...');

  useEffect(() => {
    const connection = createFeedConnection(topic); // Setup establishes connection to external **SYSTEM**
    connection.connect(message => {
      setBulletin(message);
    });

    return () => {
      connection.disconnect(); // Cleanup disconnects on unmount or topic **CHANGE**
    };
  }, [topic]); // Re-synchronizes only when reactive dependency changes

  return (
    <div className="feed-subscriber-card">
      <h4>Active Feed Topic: {topic}</h4>
      <p className="feed-bulletin">{bulletin}</p>
    </div>
  );
}
```

Notice the implementation in `FeedSubscriber.jsx`:

1. `topic` is passed into the dependency array `[topic]`. When the parent switches the topic from `'breaking'` to `'markets'`, React first executes the cleanup function for `'breaking'` (calling `connection.disconnect()`), and then executes the setup function for `'markets'` (calling `createFeedConnection('markets').connect(...)`).
2. If the user unmounts `FeedSubscriber`, the cleanup function executes immediately, terminating the interval and freeing system resources.
3. If Clara had placed `createFeedConnection` in the component body outside `useEffect`, every re-render caused by `setBulletin` would create a new connection, multiplying intervals exponentially!

Finally, examine the parent component `LiveFeedApp.jsx`:

```jsx title="LiveFeedApp.jsx"
import { useState } from 'react';
import FeedSubscriber from './FeedSubscriber.jsx';

export default function LiveFeedApp() {
  const [topic, setTopic] = useState('breaking'); // Selected news feed topic **STATE**
  const [isSubscribed, setIsSubscribed] = useState(true); // Active feed subscription toggle **FLAG**

  return (
    <main className="feed-app-container">
      <select value={topic} onChange={e => setTopic(e.target.value)}>
        <option value="breaking">Breaking News</option>
        <option value="markets">Global Markets</option>
      </select>
      <button onClick={() => setIsSubscribed(s => !s)}>
        {isSubscribed ? 'Disconnect Feed' : 'Connect Feed'}
      </button>
      {isSubscribed && <FeedSubscriber topic={topic} />}
    </main>
  ); // Mounts subscriber or unmounts it to trigger effect **CLEANUP**
}
```

`LiveFeedApp` provides interactive controls to switch topics and toggle subscription state. When the editor clicks "Disconnect Feed", `FeedSubscriber` unmounts, proving that cleanup shuts down all active background feeds.

### The Dependency Array Rules

The dependency array tells React when to re-synchronize the effect. There are three dependency patterns:

1. **`useEffect(fn, [a, b])` (with dependencies)**: Runs setup on initial mount, and runs cleanup followed by setup whenever `a` or `b` changes by `Object.is` comparison.
2. **`useEffect(fn, [])` (empty array)**: Runs setup exactly once on mount, and runs cleanup exactly once on unmount. Used for subscriptions that do not depend on any changing props or state.
3. **`useEffect(fn)` (omitted dependency array)**: Runs on every single render. This is almost always an architectural defect because it re-synchronizes after every prop or state change.

The golden rule of dependencies is: **Every reactive value (props, state, and variables derived from them) read inside the Effect must be declared in the dependency array.** React's linter enforces this rule to prevent stale closure bugs.

### Where you will meet this

- Real-time WebSockets and SSE: Connecting to chat rooms, collaboration boards, and live financial feeds.
- Global window event listeners: Listening to `keydown` for global hotkeys, `resize` for responsive canvases, or `online`/`offline` connectivity events.
- Third-party imperative library initialization: Setting up Mapbox or Leaflet map instances, Chart.js canvases, or video.js media players.
- Document title and head synchronization: Updating `document.title` to reflect active page titles in client-rendered apps.
- Animation loops and canvas rendering: Starting requestAnimationFrame loops and canceling them on unmount.

### Glossary

- **Synchronization Effect**: A React mechanism designed to keep a component in sync with an external system outside React.
- **External System**: Any system not managed by React's declarative state, including browser APIs, WebSockets, network timers, and third-party DOM libraries.
- **Setup Function**: The primary function passed to useEffect that executes after the DOM has been committed.
- **Cleanup Function**: The function optionally returned by the setup function that executes before the next effect run and on unmount.
- **Symmetrical Lifecycle**: The design pattern where every resource acquired in setup is cleanly released in cleanup.
- **Strict Mode Verification**: React's development-mode practice of running effects twice to verify setup and teardown integrity.

### Summary

**The useEffect Hook: Setup, Cleanup, and Synchronization**

The `useEffect` hook connects components to external systems outside React. Adhering to setup and cleanup symmetry guarantees that resources acquired during setup are released before re-synchronization and on unmount, preventing ghost listeners and connection leaks.

❒ Core Takeaways of useEffect Architecture
1. Distinguish pure calculations from synchronization.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Keep pure render math in the component body.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Reserve `useEffect` strictly for synchronizing with external systems.
2. Implement setup and cleanup symmetry.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Always return a cleanup function when opening connections, adding listeners, or starting timers.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) React executes cleanup before re-running the effect and upon component unmount.
3. Obey the reactive dependency invariant.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Include every prop and state variable read inside the effect in the dependency array.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Understand that Strict Mode mounts twice in development to verify cleanup symmetry.
➔ ALWAYS return a cleanup function when subscribing to external sockets, timers, or window events.<br>
➔ NEVER place external side effects directly inside the component render body.

**DO NOT DO THIS:** Create external connections inside the render body without cleanup.
```jsx wrong title="BadSubscriber"
export function BadSubscriber({ topic }) {
  const connection = createFeedConnection(topic);
  connection.connect(msg => console.log(msg));
  return <div>Connecting...</div>;
}
```

**DO THIS:** Synchronize inside useEffect with symmetrical setup and cleanup functions.
```jsx right title="GoodSubscriber"
export function GoodSubscriber({ topic }) {
  const [bulletin, setBulletin] = useState('');

  useEffect(() => {
    const connection = createFeedConnection(topic);
    connection.connect(msg => setBulletin(msg));

    return () => {
      connection.disconnect();
    };
  }, [topic]);

  return <div>{bulletin}</div>;
}
```
