### Opening the JavaScript Portal: The Power of Curly Braces
- [p] Literal markup text versus dynamic values: Explains that in standard JSX, any characters written between tags or inside quotes are interpreted as static string literals. Introduces curly braces `{ }` as the syntactic window that steps out of markup and into live JavaScript execution. ◼ Baptizes classic **JSX Interpolation / Embedded Expressions**, modern **JSX Curly Brace Expressions**, and concrete physical reality of *JavaScript variables evaluated and passed as arguments to element descriptor functions*.
- [p] The portal mechanism in the compiler: Details how the JSX transform processes curly braces. Explains that when the compiler encounters `{headline}`, it does not emit a string literal; instead, it outputs the variable identifier directly into the arguments of `_jsx()`. ◼ Solidifies how JSX bridges markup structure and JavaScript memory.
- [grounding] Leading Question: What does a curly brace really do?
  Confusion Point: Beginners often think curly braces are template string placeholders like Mustache or string concatenation syntax.
  Scene & Repetition: When you write plain text inside JSX tags, the browser treats it as literal text. If you write the word headline, the screen displays the word headline. How do you tell the computer to stop reading text and start running code? You wrap the word in curly braces: `{headline}`. The curly brace acts as a portal. Inside the braces, you are back in regular JavaScript. You can read variables, add numbers, or run calculations. It is a live portal into JavaScript, time and time again.
  Key Terms (Bold): `**curly braces**`, `**evaluation portal**`, `**literal text**`, `**JavaScript expression**`.
  Resolution: Curly braces instruct the compiler to evaluate the enclosed token as live JavaScript rather than literal markup text.

### Expressions versus Statements: The Value Requirement
- [p] Defining JavaScript expressions: Formulates the fundamental requirement that only **JavaScript expressions** are permitted inside JSX curly braces. Explains that an expression is any piece of JavaScript code that resolves to a single value, including variables, property lookups, arithmetic operations, template literals, function invocations, and ternary conditionals. ◼ Baptizes **JavaScript expression** and **value requirement**.
- [p] The statement prohibition: Deconstructs why **JavaScript statements** (such as `if`, `for`, `while`, or variable declarations like `let x = 1`) are strictly forbidden inside curly braces. Explains that statements execute an action or declaration but do not resolve to a value, making them invalid as function arguments in compiled JSX. ◼ Clarifies why branching in JSX uses ternary operators and logical operators rather than `if` statements.
- [callout] One-line insider takeaway: Highlighting the definitive distinction between expressions and statements in JSX. ◼ Reinforces that expressions evaluate to a value, statements do not, and only expressions belong in curly braces.

### Expressions in Attributes: Dynamic Props and the Quote Trap
- [p] Passing dynamic values to element attributes: Explains that curly braces can be placed immediately after the `=` attribute operator to pass dynamic JavaScript values to element attributes, such as `src={imageUrl}` or `alt={imageAlt}`. ◼ Baptizes **dynamic attributes**.
- [p] The Quote Trap: Details the common beginner mistake of wrapping curly braces inside quotation marks: `src="{imageUrl}"`. Explains that quotation marks instruct the compiler to treat the entire string as a literal value, causing the browser to request an image named literally `"{imageUrl}"`, which results in a 404 network error and a broken image icon. ◼ Baptizes **quote trap** and explains its network consequence.
- [grounding] Leading Question: Why do quotes break dynamic attributes?
  Confusion Point: Beginners wonder why writing src="{imageUrl}" fails to load the image.
  Scene & Repetition: Imagine you create an image tag and type `src="{imageUrl}"`. You reload the page, and the user's avatar is completely broken. Why? Because you put quotation marks around the curly braces. In JSX, quotation marks mean literal text. The browser does not read your variable; it literally asks the server for an image named `"{imageUrl}"`. The server cannot find it, and the image crashes. This is the **quote trap**: quotation marks turn your dynamic variables into broken literal text strings.
  Key Terms (Bold): `**quote trap**`, `**dynamic attribute**`, `**literal string**`, `**curly braces**`.
  Resolution: Never wrap curly braces in quotation marks; use curly braces alone to pass dynamic values to JSX attributes.

### The "Double Curlies" Pattern: Objects and Inline Styles
- [p] Deconstructing the double curlies syntax: Explains that writing `style={{ color: 'crimson', fontSize: '1.2rem' }}` is not a special React directive or custom operator. Explains that the outer pair of curly braces opens the JSX expression window, while the inner pair defines a standard JavaScript object literal. ◼ Baptizes **double curlies** and **inline style objects**.
- [p] CSS property naming in JavaScript style objects: Details why inline styles in React require camelCased property names (`backgroundColor` instead of `background-color`, `fontSize` instead of `font-size`) and why unitless numbers default to pixel dimensions. ◼ Unpacks the technical rules governing React style objects.
- [grounding] Leading Question: Are double curlies special React syntax?
  Confusion Point: Developers assume double curlies are a built-in React template operator.
  Scene & Repetition: When developers first see `style={{ color: 'red' }}`, they think React invented a special double-bracket syntax. But double curlies are not a special feature. Look closely: the outer pair of curly braces opens the JavaScript portal. The inner pair of curly braces is just an ordinary JavaScript object. You are simply passing a JavaScript object into a JavaScript portal. That is all it is. Two separate curly brace pairs sitting next to each other.
  Key Terms (Bold): `**double curlies**`, `**JavaScript object literal**`, `**inline style**`, `**evaluation portal**`.
  Resolution: Double curlies are simply a plain JavaScript object literal wrapped inside standard JSX expression braces.

### Glossary
- [glossary] Curly Braces ({ }) ◼ The JSX syntax mechanism that opens an evaluation portal to execute JavaScript expressions inside markup.
- [glossary] JavaScript Expression ◼ Any valid unit of JavaScript code that resolves to a single value, such as a variable, calculation, or function call.
- [glossary] JavaScript Statement ◼ A syntactic unit of code that performs an action (such as `if`, `for`, or `let`) but does not evaluate to a value and cannot be placed inside JSX curly braces.
- [glossary] Double Curlies ◼ The pattern of placing a JavaScript object literal `{ key: value }` directly inside JSX expression braces `{ ... }`, commonly used for inline styles.
- [glossary] Quote Trap ◼ The beginner mistake of wrapping JSX curly braces in quotation marks (`"{value}"`), causing React to treat the expression as a literal string.

```jsx right title="StoryDetails.jsx"
      <img src={imageUrl} alt={headline} />

```
◼ **Code Self-Audit (What makes the right code resilient):**
1. `src={imageUrl}`: Passes the dynamic variable directly to the attribute without quotes, allowing the browser to fetch the correct URL.
2. `<h2>{headline}</h2>`: Projects the dynamic string variable into the heading text node cleanly.
- [code] DO NOT DO THIS: Never wrap curly braces in quotation marks or place JavaScript statements inside JSX.
```jsx wrong title="StoryDetails.jsx"
export default function StoryDetails({ headline, imageUrl }) {
  return (
    <div className="story-card">
      <img src="{imageUrl}" alt="headline" /> // **WRONG:** quotes treat variable as literal **STRING**
      <h2>{if (headline) headline}</h2> // **WRONG:** statement crashes **COMPILER**
    </div>
  );
}
```
◼ **Code Self-Audit (The runtime failure and compiler crash triggered by the wrong code):**
1. `src="{imageUrl}"`: Passes literal string `"{imageUrl}"`, triggering a 404 image load failure in the browser.
2. `{if (headline) headline}`: Placing an `if` statement inside curly braces causes an immediate compile-time syntax crash.
