### What is a React Component?

Introduces React's core innovation of bundling markup structure and dynamic rendering logic into self-contained units called **components**. ◼ Baptizes classic **React Component**, modern **Function Component**, and concrete physical reality of *a regular JavaScript function returning an object descriptor*.
- [p] Sprinkling JavaScript functions with markup: Details the physical structure of a component as a standard JavaScript function that returns a user interface description written in JSX. - [grounding] Leading Question: What is a React component under the hood?

  Key Terms (Bold): `**component**`, `**plain JavaScript function**`, `**UI descriptor**`, `**virtual DOM**`.
  Resolution: React runs your plain function to receive an object describing the screen, then surgically turns that object into real browser elements.

### The Capitalization Law: Why Case Dictates DOM Identity
- [p] The JSX compilation fork: Deconstructs how the JSX compiler transforms tags into JavaScript function calls. Explains that tags beginning with a lowercase letter compile into string literals representing native browser elements, whereas tags beginning with an uppercase letter compile into direct function identifier references. ◼ Baptizes **PascalCase**, **capitalization**, **native DOM tag**, and **component function**.
- [p] Lowercase tag failure mode: Traces what happened to Leo's `<authorProfile />`. Explains that the compiler output `_jsx('authorProfile', {})` instructed the browser to locate an HTML element named `<authorprofile>`. Because no such native element exists, the browser rendered an empty, inert custom element, completely bypassing Leo's JavaScript function. ◼ Explains the exact browser failure mechanism when capitalization is violated.
- [callout] One-line insider takeaway: Highlighting the definitive distinction between lowercase and uppercase in JSX. ◼ Reinforces that in JSX, lowercase means a real browser tag, while uppercase means a React component function.

- [grounding] Leading Question: Why does capitalization change how code runs?
  Confusion Point: In regular JavaScript, capitalization is merely a naming style, so developers assume JSX capitalization is optional.
  Scene & Repetition: In standard JavaScript, writing a lowercase function name works identically to an uppercase name. But in JSX, capitalization is an ironclad compiler law. If you type `<authorProfile />`, the compiler treats it as a built-in browser element. If you type `<AuthorProfile />`, the compiler treats it as your custom component function. This single capital letter decides whether React invokes your function or sends an unknown string to the browser.

  Resolution: Capitalization tells the JSX compiler whether to emit a string for a native browser tag or execute a JavaScript function reference.

### Return Rules: Parentheses and Automatic Semicolon Insertion
- [p] The single-line versus multi-line return boundary: Explains that while a single JSX element can sit on the same line as the `return` keyword, multi-line JSX markup must be wrapped in parentheses. ◼ Baptizes **Automatic Semicolon Insertion** (**ASI**).
- [p] The silent semicolon trap: Details how the JavaScript engine automatically inserts an invisible semicolon immediately after a standalone `return` keyword on its own line. Demonstrates that writing `return` followed by a newline causes the function to return `undefined`, triggering React's runtime error warning that nothing was returned from render. ◼ Unpacks the exact runtime crash triggered by omitted return parentheses.
- [grounding] Leading Question: Why does returning on a newline fail?
  Confusion Point: Code looks visually connected on adjacent lines, but the runtime returns undefined.
  Scene & Repetition: You hit Enter after typing `return` to keep your code tidy and readable. On the next line, you start your JSX markup. You save the file, and your browser screen crashes with a blank error. Why? Because the JavaScript language inserts a hidden semicolon right after the word `return`. Your function ends immediately. It returns `undefined`, and your entire component is completely ignored. This is the silent trap of **Automatic Semicolon Insertion**: hitting Enter cuts off your return statement before it ever reaches your markup.
  Key Terms (Bold): `**Automatic Semicolon Insertion**`, `**ASI**`, `**return statement**`, `**parentheses**`.
  Resolution: Wrapping multi-line JSX in parentheses tells JavaScript that the return statement continues onto subsequent lines.

### The Anti-Nesting Law: Never Define Components Inside Components
- [p] Component composition versus nested definition: Formulates the critical distinction between rendering a child component inside a parent (composition) and defining a component function body inside another component function (nested definition). ◼ Baptizes **component composition**, **nested component definitions**, and **component identity**.
- [p] The performance and state destruction penalty: Explains that nesting function declarations forces JavaScript to re-allocate a brand new function reference in computer memory on every single render cycle. Details how React treats this new function reference as a completely different component type, unmounting the previous DOM node, discarding user input and focus state, and remounting the entire subtree from scratch. ◼ Explains why component definitions must live at the top level of the file.
- [grounding] Leading Question: When does nested code destroy your state?
  Confusion Point: Nesting helper functions feels like clean encapsulation, but it destroys state and performance in React.
  Scene & Repetition: You might think declaring a helper component inside your main component keeps your file organized. It looks harmless. But every time the parent component re-renders, the computer creates a brand new function in memory. React looks at that new function, assumes it is a completely new component type, and tears down the entire DOM tree. Any input you typed vanishes instantly. This is the danger of **nested component definitions**: you recreate the component blueprint on every render, resetting state over and over again.
  Key Terms (Bold): `**nested component definitions**`, `**component identity**`, `**re-render**`, `**top-level declaration**`.
  Resolution: Declare every component at the top level of your file so React preserves stable component identity across every render cycle.

### Glossary
- [glossary] Component ◼ A self-contained, reusable JavaScript function that begins with a capital letter and returns a user interface description in JSX.
- [glossary] PascalCase ◼ The naming convention where the first letter of every word is capitalized, required for all React component function names.
- [glossary] Automatic Semicolon Insertion (ASI) ◼ The JavaScript parser mechanism that automatically inserts semicolons at line breaks, requiring parentheses around multi-line return statements.
- [glossary] Component Identity ◼ The persistent reference React uses to track a component across renders, preserved only when the component is declared at the top level.
- [glossary] UI Descriptor Tree ◼ An in-memory hierarchy of lightweight JavaScript objects generated by JSX that describes the intended DOM structure to React.

```jsx wrong title="ArticleHeader.jsx"
}
```
◼ **Code Self-Audit (The runtime failure and state destruction triggered by the wrong code):**
1. `function AuthorProfile()` inside `ArticleHeader`: Allocates a new function reference on every render, forcing React to destroy and recreate the DOM subtree.
