Lecture 3: The Invisible Footer Links

Interview Question

CORE

What is the difference between inherit, initial, unset, and revert when resetting properties?

Imagine this scenario:

  1. Zoe applies a modern dark theme to the website footer at The National Times.
  2. She sets the footer card background to dark slate (#0f172a) and declares text color as white (#ffffff).
  3. On the staging page, the body text turns white, but every legal disclaimer link in the footer vanishes.
  4. DevTools reveals that an unstyled default rule turned the link text pitch black against the dark slate card.
  5. Why did setting the container text to white cause nested links to render in pitch black?
  6. Guessing random reset keywords breaks typography, form controls, and theme switches across the site.
  7. Today you master the four universal reset keywords to navigate the cascade and restore values safely.

The Reset Quartet: How Properties Find Their Roots

In CSS, resetting a property is not a single generic command. The language provides four universal reset keywords: inherit, initial, unset, and revert. Each keyword instructs the browser layout engine to fetch values from a completely different authority tier: the parent element, the static W3C specification table, the property's natural inheritance behavior, or the browser's built-in stylesheet.

Reaching for the wrong reset keyword without understanding these distinct origins causes immediate visual catastrophes, such as turning critical links completely invisible against dark surfaces.

Consider the newsroom footer on The National Times website. Zoe wants all text and legal disclaimer links to render in crisp white against a dark slate card:

Pearls of Wisdom

Industry Naming Conventions: Container Themes Versus Hyperlink Overrides: In web design systems, containers establish baseline typographical surfaces (background-color and color). However, HTML <a> elements do not naturally adopt their parent's text color. Every web browser ships with a built-in stylesheet that targets hyperlinks with an explicit rule: color: -webkit-link (standard link blue). Because this browser rule directly targets the anchor tag, it defeats normal typography inheritance. To force a link to blend into its parent card, developers must explicitly override that property using a reset keyword.

index.html
1<footer class="footer-dark">
2 <h4 class="footer-title">The National Times</h4>
3 <p class="footer-copy">Investigative reporting and daily news analysis.</p>
4 <a href="/privacy" class="footer-link">Privacy Policy</a>
5</footer>

In index.html, the Privacy Policy link sits directly inside the <footer class="footer-dark"> container alongside the publication title and copyright notice.

Now review what happens when Zoe writes color: initial versus color: inherit:

footer-links.css
1.footer-dark {
2 background-color: #0f172a;
3 color: #ffffff;
4 padding: 18px;
5}
6
7.footer-dark a {
8 color: initial;
WRONG: Resets to W3C specification black (#000000)
9}
10
11.footer-dark a {
12 color: inherit;
RIGHT: Copies white (#ffffff) from parent container
13}

In footer-links.css, .footer-dark sets its background to dark slate (#0f172a) and its text to white (#ffffff). The competing link rules declare two different reset keywords.

Figure 3.1 demonstrates the visual consequence on screen. In the left panel, Zoe wrote color: initial, hoping it would make the link look normal. But initial does not mean "match the surrounding page." It tells the browser to consult the static W3C specification dictionary, which defines the initial constant for color as pure black (#000000). Because pitch-black text sits on a dark slate background, the link vanishes into the surface.

In the right panel, Zoe fixes the problem by declaring color: inherit. The inherit keyword commands the browser to climb up the DOM tree and copy the computed color of the parent <footer class="footer-dark">. The link turns crisp white (#ffffff), producing readable text that adapts dynamically whenever the footer theme changes.

The official W3C specification defines the foundational behavior of these CSS-wide keywords:

"The unset CSS-wide keyword acts as either inherit or initial, depending on whether the property is inherited or not. If the cascaded value of a property is the unset keyword, then if it is an inherited property, this is treated as inherit, and if it is not, this is treated as initial."

The Five Universal Reset Keywords Deconstructed

To choose the correct keyword during a production incident, examine how each keyword resolves its value inside the browser engine:

keywords-overview.css
1.badge-label {
2 color: inherit;
1. inherit: copies computed value from direct DOM parent
3 color: initial;
2. initial: resets to static W3C specification default (black)
4 color: unset;
3. unset: behaves as inherit for typography, initial for boxes
5 color: revert;
4. revert: rolls back to browser user-agent stylesheet defaults
6 color: revert-layer;
5. revert-layer: rolls back to the preceding cascade layer
7}

In keywords-overview.css, each universal keyword selects a distinct resolution station in the cascade.

1. inherit: Copying the Parent Value

The keyword inherit commands the browser engine to look upward in the DOM tree. Instead of using a default browser constant or an initial specification value, the element copies the exact computed value of the property from its direct parent container.

In your HTML, you have an anchor link nested inside a container: <footer class="footer-dark"><a href="/privacy">Privacy Policy</a></footer>. When you declare color: inherit on the link, you tell the browser: "Do not use your own default link blue. Look at the parent footer, copy its computed white color (#ffffff), and paint this link with that exact same white." When you inspect the link in DevTools under the Computed tab, color displays rgb(255, 255, 255).

Using inherit frees you from hardcoding color overrides across dozens of components. The link automatically synchronizes with whatever background surface surrounds it.

2. initial: Resetting to the Static Specification Constant

The keyword initial references the static W3C specification table. It resets a property to the foundational default defined in the official specification dictionary, completely ignoring parent containers, page themes, and even the browser's own built-in stylesheet.

Junior developers often write initial assuming it means "make this look normal." That is a dangerous mistake. The W3C specification table defines the initial constant for color as pure black (#000000). If your link sits on a dark container, writing color: initial turns the text pitch black, causing it to disappear.

Furthermore, applying initial to layout properties causes immediate structural collapse. For example, the W3C specification table defines the initial value of display as inline. If you write li { display: initial; }, the browser strips away the bullet point, removes vertical margins, and crushes your list into a broken horizontal text string!

3. unset: The Conditional Inheritance Switch

The keyword unset acts as a smart chameleon. Instead of forcing you to remember whether every single property should be reset with inherit or initial, typing unset lets the browser decide based on inheritance rules:

  • For naturally inherited properties (such as color, font-family, line-height): unset behaves like inherit. It pulls the value from the parent container.
  • For non-inherited box properties (such as margin, padding, border, background): unset behaves like initial. It wipes out box dimensions back to zero or transparent.

When you inspect an element with all: unset in DevTools, its text properties continue to match the surrounding container typography, while all margins, borders, and paddings drop to zero.

4. revert: Rolling Back to Browser Defaults

The keyword revert commands the CSS engine to step backward across origin boundaries. It discards all rules declared in author stylesheets for that property and restores the styles defined by the user's custom preferences or the browser's built-in user-agent stylesheet.

When you build a website, your author styles sit on top of the browser's built-in stylesheet foundation. Typing revert tells the browser: "Ignore whatever rules I wrote in my stylesheets for this element, and restore the exact styles you natively provide."

When you write button.unstyled { all: revert; }, the browser restores its native button appearance: system font, clickable grey bevel, and accessible focus outlines. In Chrome DevTools, your custom styles are struck through, and the Styles panel reveals the underlying user-agent stylesheet taking back control.

5. revert-layer: Rolling Back to the Previous Cascade Layer

Introduced in CSS Cascading and Inheritance Level 5 alongside @layer, revert-layer rolls back a property to the value declared in the previous cascade layer:

In layer-rollback.css, revert-layer yields control to the preceding layer rather than falling back to browser defaults.

Figure 3.3 illustrates the power of revert-layer. When a utility class uses revert, it bypasses all author layers and falls all the way back to the browser's raw unstyled grey bevel. When it uses revert-layer, it steps backward exactly one layer, yielding cleanly to the components layer while preserving application branding.

The Semantic Trap: How initial Destroys HTML Structure

To understand why senior engineers avoid initial on layout properties, examine how it breaks semantic HTML elements:

navigation.html
1<nav class="site-navigation">
2 <ul>
3 <li><a href="/news">News</a></li>
4 <li><a href="/opinion">Opinion</a></li>
5 <li><a href="/business">Business</a></li>
6 </ul>
7</nav>
semantic-breakdown.css
1nav.site-navigation ul li {
2 display: initial;
WRONG: Resets display to inline, collapsing list into text stream
3 margin: initial;
4}
5
6nav.site-navigation ul li {
7 display: revert;
RIGHT: Restores user-agent stylesheet's list-item behavior
8 margin: 0;
9}

In semantic-breakdown.css, setting display: initial destroys list item rendering.

Figure 3.2 contrasts initial against revert. Every HTML element depends on the browser's built-in stylesheet for its visual behavior:

  • <div>, <section>, <article>, and <p> receive display: block.
  • <ul> and <ol> receive display: block and list-style-type: disc.
  • <li> receives display: list-item.
  • <h1> through <h6> receive bold font weight and calibrated block margins.
  • <button> receives appearance: auto, internal padding, and system font rendering.

None of these defaults exist in the W3C specification table for initial! If you write li { display: initial; }, the browser sets display: inline. The bullet point vanishes, vertical margins stop functioning, and the navigation items collapse horizontally.

Remember: initial knows only the abstract W3C specification table; revert respects the living browser stylesheet that gives HTML tags their semantic shapes.

The Power Tool: all: revert vs all: unset

The all shorthand property allows you to reset every CSS property on an element (except direction and unicode-bidi) in a single declaration:

button-controls.html
1<div class="control-panel">
2 <button class="btn-submit">Submit Story</button>
3</div>
button-reset.css
1.control-panel .btn-submit {
2 all: unset;
WRONG: Strips button bevel, padding, and focus ring
3}
4
5.control-panel .btn-submit {
6 all: revert;
RIGHT: Restores native browser button styling and focus
7}

In button-reset.css, all: unset strips interactive button styling, while all: revert restores native browser controls.

Figure 3.4 demonstrates the difference between these two universal resets:

  • When to Use all: unset: Use all: unset when creating custom icon buttons or turning a <fieldset> into a plain transparent container. Because unset converts to inherit for typography, your text continues to match the surrounding website while all borders and paddings drop to zero.
  • When to Use all: revert: Use all: revert when rendering user-generated Markdown or articles from a CMS. If your global stylesheet has aggressive resets that flatten headings and lists, writing .article-body * { all: revert; } instantly restores beautiful, accessible native browser typography.

Summary

The Universal Reset Quartet

CSS provides four universal reset keywords to navigate the cascade with precision. Understanding where each keyword routes property values prevents broken layouts and invisible typography.

  1. The inherit keyword copies the computed property value from the direct DOM parent.
  2. The initial keyword resets a property to the static constant in the W3C specification table.
  3. The unset keyword acts as inherit for inherited properties and initial for non-inherited properties.
  4. The revert keyword rolls back author styles to the browser's built-in user-agent stylesheet.
  5. The revert-layer keyword steps backward exactly one layer within Cascade Layers.
  6. Writing color: initial turns text pitch black (#000000), vanishing against dark containers.
  7. Writing display: initial collapses blocks and list items into unstyled inline text streams.
  8. Use all: unset for transparent icon buttons, and all: revert for native article typography.

DO NOT DO THIS: Use color: initial to reset links inside dark containers, turning text pitch black.

styles.css
1.footer-dark a {
2 color: initial;
3}

DO THIS: Use color: inherit so that hyperlinks automatically copy the container's surface text color.

styles.css
1.footer-dark a {
2 color: inherit;
3}

➔ NEVER use initial on layout properties like display, which turns blocks and list items into inline text.

➔ ALWAYS use inherit on hyperlinks, SVG icons, and helper labels inside themed cards.

➔ IF you need to restore native browser typography for user articles THEN apply all: revert.
