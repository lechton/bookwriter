4. Subscribers confuse the stretched article card with an urgent alert, distorting the front page hierarchy.
5. Slapping manual percentage widths prevents stretching but shatters whenever screen dimensions change.
6. The editor needs columns that remain rigidly locked across rows without hardcoded widths.

### The One-Dimensional Boundary: Why Flex Lines Cannot Talk

In modern CSS layout architecture, the boundary between Flexbox and CSS Grid is defined by dimensionality. A **one-dimensional layout** system calculates space along only a single axis at a time. When a flex container enables wrapping, each wrapped line is generated as an isolated layout boundary that distributes space without any coordination or reference to the rows above or below it. In contrast, a **two-dimensional layout** system coordinates both horizontal column tracks and vertical row tracks simultaneously from the parent container. Failing to recognize this mechanical boundary causes the notorious **orphan card** trap: a lone trailing card that wraps onto a new line and expands to the full width of the viewport like an accidental billboard.

When developers build multi-card grids with Flexbox, they frequently combine `display: flex` and `flex-wrap: wrap` with `flex: 1`. On the first row, three cards fit comfortably side by side. However, when the fourth story card arrives, it has no room on row one and wraps onto row two. At this exact moment, the one-dimensional limitation of Flexbox manifests. Row two is an isolated formatting line with zero memory of row one. The browser layout engine queries row two, observes that the single orphan card is the sole occupant of the line, and hands one hundred percent of the line's positive free space to that single card. The card stretches across the entire screen, shattering the three-column layout established directly above it.

CSS Grid eliminates this defect at the architectural root. Instead of allowing child elements to size themselves and push lines open, Grid establishes a rigid, container-level coordinate blueprint. By declaring `grid-template-columns: repeat(3, 1fr)`, the parent container constructs three immutable vertical column tracks before any content is placed. When the fourth card wraps onto row two, it does not invent its own width. It drops strictly into column track one, leaving tracks two and three gracefully empty and preserving the newspaper's three-column visual rhythm.

> [!WISDOM]
> **Industry Naming Conventions: Card Decks, Feature Matrices, and Component Grids:** In professional publishing systems, multi-article presentations are routinely authored using semantic containers like `<div class="card-deck">` wrapping multiple `<article class="story-card">` components. Junior developers frequently assume that wrapping cards with `display: flex; flex-wrap: wrap;` represents modern best practice because Flexbox was taught as the universal replacement for legacy floats. However, design systems at premier news organizations treat Flexbox and Grid as complementary layers: CSS Grid is deployed on the outer parent container to establish the rigid two-dimensional track matrix, while Flexbox is deployed inside each individual card to vertically align headlines, excerpts, and action buttons. Using Grid for the container and Flexbox for component internals prevents orphan card stretching while guaranteeing perfect baseline alignment across asymmetric content.

To observe how linear line isolation causes orphan card stretching while CSS Grid maintains structural column tracks, examine the document structure of this editorial card deck:

```html title="card-deck.html"
<div class="card-deck">
  <article class="story-card"><h3 class="card-title">Story #1</h3></article>
  <article class="story-card"><h3 class="card-title">Story #2</h3></article>
  <article class="story-card"><h3 class="card-title">Story #3</h3></article>
  <article class="story-card"><h3 class="card-title">Story #4</h3></article>
</div>
```

In `card-deck.html`, four article cards sit inside a shared parent container.

Now examine the flawed wrapping flexbox layout:

```css title="deck-flex.css"
.card-deck.flex {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
}

.card-deck.flex .story-card {
  flex: 1 1 70px; /* Line 2 isolates space, stretching orphan card 4 across the screen */
}
```

In `deck-flex.css`, line two acts as an isolated universe, handing all free space to the fourth card.

To enforce rigid multi-row columns, declare a two-dimensional grid:

```css title="deck-grid.css"
.card-deck.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr); /* Locks parent into three immutable column tracks */
  gap: 8px;
}
```

In `deck-grid.css`, the parent defines three permanent column tracks that govern all rows.

Figure 17.1 contrasts both layout algorithms. In the left panel, the container `.card-deck.flex` uses wrapping flexbox. The first three story cards completely fill the width of row one. Because there is no room left on that line, card four wraps onto row two alone. Because Flexbox treats every wrapped line as an independent layout universe, line two has zero knowledge of the three columns established directly above it. The browser queries line two and asks how much positive free space is available. Because card four is the only element on that line, and because `flex: 1` commands it to absorb all available space, the browser hands one hundred percent of line two's width to card four. The orphan card stretches across the entire screen like an accidental banner ad, completely distorting editorial priority.

In the right panel of Figure 17.1, the container `.card-deck.grid` declares `display: grid; grid-template-columns: repeat(3, 1fr);`. The entire layout transforms into an immutable two-dimensional matrix. The parent container defines three vertical column tracks before any child card is placed. Cards one, two, and three take their positions in tracks one, two, and three on row one. When card four wraps to row two, it drops strictly into column track one. Column tracks two and three remain gracefully empty. The fourth card retains the exact same column width as the cards above it, preserving clean newspaper column alignment.

The official W3C Flexible Box Layout Level 1 specification explicitly documents this linear line isolation:

> "In the flex layout model, the children of a flex container can be laid out in any direction, and can 'flex' their sizes, either growing to fill unused space or shrinking to avoid overflowing the parent. Both horizontal and vertical alignment of the children can be easily manipulated. Nesting of these boxes (horizontal inside vertical, or vertical inside horizontal) can be used to build layouts in two dimensions."<br><br>*CSS Flexible Box Layout Module Level 1, `resources/spec/csswg-drafts/css-flexbox-1/Overview.bs`*

By contrast, the W3C CSS Grid Layout Module Level 2 specification formalizes the native two-dimensional coordinate model:

> "This CSS module defines a two-dimensional grid-based layout system, optimized for user interface design. In the grid layout model, the children of a grid container can be positioned into arbitrary slots in a predefined flexible or fixed-size layout grid."<br><br>*CSS Grid Layout Module Level 2, `resources/spec/csswg-drafts/css-grid-2/Overview.bs`*

### The Fragile Workarounds That Break in Production

When junior developers encounter the stretching orphan card in a flexbox layout, their first instinct is rarely to switch layout models. Instead, they attempt to patch the symptom with fragile CSS workarounds:

1. **Name and Origins:** The **percentage basis hack** (`flex: 0 0 31%`) and **invisible spacer tags** (`<div class="spacer"></div>`) were born during the transition era between floats and CSS Grid, when developers tried to force one-dimensional tools into two-dimensional grids.

2. **The Everyday Physical Analogy:** Think of wrapping flexbox like **passengers boarding a bus with movable bench rows**. In flexbox, row two does not know how row one arranged its seats; if only one passenger sits on row two, they stretch their legs across the entire aisle. Trying to fix this with hardcoded percentages is like **cutting passenger luggage with a saw to make it fit an exact percentage of the floor**. At fractional screen widths, rounding errors cause bags to bump each other, triggering unexpected passenger spillover. In contrast, CSS Grid is like **pre-installed stadium seating bolted into concrete**: seats 1, 2, and 3 exist permanently. If only one person sits in row two, they sit in seat 1, and seats 2 and 3 remain empty.

3. **Historical Context (The Problem It Solved):** Before CSS Grid gained universal browser support in 2017, developers spent thousands of hours writing media query breakpoints to adjust flex percentage bases from 31% to 48% to 100%. CSS Grid solved this permanently by allowing the parent container to define tracks that naturally accommodate dynamic item counts without manual arithmetic.

4. **Browser Calculation Sequence:** In CSS Grid:
- The parent container establishes grid lines and gutters along both inline and block axes.
- The auto-placement algorithm traverses child elements in DOM order.
- It places children into available track cells sequentially.
- When an item wraps to a new row, it is constrained to the column lines defined by the parent, never inventing arbitrary widths.

Examine the fragile percentage workaround that developers often deploy:

```css title="fragile-percent.css"
.fragile-deck .deck-card {
  flex: 0 0 31%; /* Subpixel rounding causes premature wrap; leaves 63% trailing void */
  margin: 1%;
}
```

In `fragile-percent.css`, hardcoded percentages suffer from subpixel rounding errors on high-DPI screens, causing the third card on row one to wrap prematurely while leaving an ugly trailing void on row two.

```html-figure src="md-lectures/figures/17-02-fragile-workarounds.html" caption="The percentage basis hack introduces subpixel rounding errors and leaves an awkward 63% trailing void on row two. CSS Grid handles column math natively, ensuring flush borders and zero rounding defects."
```

Figure 17.2 exposes the defects of the percentage workaround. In the left panel, using `flex: 0 0 31%` prevents the fourth card from expanding to 100%, but creates a glaring 63% empty void on the second row that looks like a missing data error. Furthermore, on fractional viewports (like 998px), subpixel rounding causes cards to exceed 100% total width, triggering premature wraps. In the right panel, native CSS Grid manages columns effortlessly with zero subpixel rounding defects.

### Container-In Versus Content-Out: The Smart Baker Algorithm

To make confident architectural decisions, you must understand the distinction between **content-out** sizing (Flexbox) and **container-in** sizing (CSS Grid).

In a **content-out** model, child elements inspect their internal text, images, and padding, calculate their natural size, and demand space along the parent axis. The parent merely arranges space around them. This makes Flexbox ideal for toolbars, search groups, and keyword chips where items should vary in width based on their label.

In a **container-in** model, the parent container establishes an immutable spatial blueprint: column tracks and row tracks separated by explicit gutters. Child elements have no authority over track dimensions; they are simply slotted into the blueprint. This makes CSS Grid mandatory whenever visual harmony requires rigid alignment across both dimensions.

The defining mechanical breakthrough of CSS Grid is the fractional unit (`fr`). To understand how the browser computes `fr` track dimensions, visualize **shares of a pie calculated by a smart baker**:

```html title="baker-layout.html"
<div class="baker-grid">
  <aside class="ad-slot">Ad Slot (120px)</aside>
  <article class="story-summary">Story Summary (1fr)</article>
  <article class="lead-feature">Lead Feature (2fr)</article>
</div>
```

```css title="baker-grid.css"
.baker-grid {
  display: grid;
  width: 600px;
  grid-template-columns: 120px 1fr 2fr; /* Fixed ad slot followed by fractional tracks */
  gap: 12px;
}
```

In `baker-grid.css`, fixed columns and gutters are resolved first, and remaining space is divided among `fr` shares.

```html-figure src="md-lectures/figures/17-03-fractional-unit-baker.html" caption="The Smart Baker Algorithm: fixed columns (120px) and gutters (24px) are subtracted first. The remaining 456px of free space is divided proportionally among 1fr (152px) and 2fr (304px) tracks."
```

Figure 17.3 illustrates the Smart Baker Algorithm step by step:
1. **Subtract All Fixed Costs First:** Before looking at any `fr` values, the browser measures the fixed 120px ad slot plus two 12px gaps ($2 \times 12\text{px} = 24\text{px}$). Total non-negotiable overhead is $120\text{px} + 24\text{px} = 144\text{px}$.
2. **Measure the Leftover Pie (Positive Free Space):** The browser subtracts fixed costs from total container width: $600\text{px} - 144\text{px} = 456\text{px}$. This remaining 456px is the positive free space pool.
3. **Count Total Fractional Shares:** The browser sums declared fractional units: $1\text{fr} + 2\text{fr} = 3\text{ shares}$.
4. **Compute the Value of One Share:** The browser divides remaining space by total shares: $456\text{px} \div 3 = 152\text{px per share}$.
5. **Distribute Proportional Slices:** Track two receives one share ($1 \times 152\text{px} = 152\text{px}$). Track three receives two shares ($2 \times 152\text{px} = 304\text{px}$).

Because the layout engine subtracts fixed tracks and gutters **before** distributing `fr` shares, fractional tracks can never overflow the container and never require manual percentage guesswork.

### Glossary

- **One-Dimensional Layout**: A layout system (like Flexbox) that computes positioning and space distribution along a single axis at a time.
- **Two-Dimensional Layout**: A layout system (like CSS Grid) that coordinates rows and columns simultaneously from a parent container.
- **Orphan Card**: A trailing item in a wrapped layout that sits alone on the final line and stretches awkwardly across the container.
- **Fractional Unit (fr)**: A CSS Grid length unit representing a fraction of the remaining positive free space in the grid container.
- **Container-In Sizing**: A layout paradigm where the parent container dictates spatial tracks before child content is placed.

### Summary

**Streetwise Review: Defeating the Orphan Card Trap with CSS Grid**

Flexbox calculates space along one dimension at a time. When flex items wrap, each line behaves as an isolated universe with zero memory of sibling lines, causing orphan cards to stretch across the full viewport. CSS Grid establishes a two-dimensional container-in coordinate blueprint that locks columns across rows regardless of item count.

❒ Architectural Rules for 1D vs 2D Layouts

1. **Deploy Grid for Multi-Row Card Matrices:** Never rely on wrapping flexbox for two-dimensional grids.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Declare `grid-template-columns: repeat(N, 1fr)` to lock columns into immutable vertical tracks.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Orphan cards drop into column one, preserving grid symmetry without stretching.
2. **Reserve Flexbox for Content-Out Components:** Use flexbox inside components.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Use Flexbox for navigation bars, search groups, and toolbars where item widths depend on text length.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Combine Grid on the outer card deck with Flexbox inside individual cards for ideal alignment.
3. **Master the Smart Baker Algorithm:** Use `fr` units instead of fragile percentage hacks.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Fixed widths and gutters are subtracted first, eliminating subpixel overflow.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Remaining free space is divided proportionally among declared fractional shares.

➔ NEVER use `flex-wrap: wrap` with `flex: 1` when you need cards to maintain consistent column widths across rows.<br>
➔ ALWAYS use CSS Grid on parent containers when building multi-column, multi-row card decks.<br>
➔ IF an element sits alone on the final row of a grid, THEN let it occupy column one while trailing tracks remain empty.

**DO NOT DO THIS:**
```css wrong
.card-deck {
  display: flex;
  flex-wrap: wrap;
}
.card-deck .card {
  flex: 1;
}
```

**DO THIS:**
```css right
.card-deck {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 12px;
}
```
