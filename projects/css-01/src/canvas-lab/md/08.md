# Lecture 8: The Box That Forgot Its Children
> INTERVIEW QUESTION | ❱ CORE | How does the browser size a box, why do two margins that touch become one, and why does a parent full of floats end up with zero height?

1. Mira, the front-page editor of The National Times, drops three photo thumbnails into the Sunday teaser box.
2. She floats them left so the headline text can sit beside them, exactly as the old print layout did.
3. The lavender background of the teaser box vanishes; the thumbnails hang in white space as if the box had never existed.
4. Where did the box go, and why does the browser insist it is still there?
5. Five minutes before the front page goes live, the two story columns beneath the teaser also overflow their row by 64 pixels.
6. Every fix she tries moves the problem somewhere else: a wider box, a shorter margin, a lost gap between headline and standfirst.
7. Today you learn the three rules that explain all of it: how a box is measured, how touching margins merge, and how a parent decides which children count.

### The Box Model: One Declaration, Two Widths

Every element on the front page is a rectangle made of four nested bands: content, padding, border, and margin. The question the browser must answer is which of those bands the `width` property refers to, and the default answer, `content-box`, is the one that surprises everyone. The same five-line rule produces two different rendered widths depending on a single `box-sizing` value:

```css title="story-column.css"
.story-column { width: 120px; height: 56px; } /* The number Mira typed */
.story-column { padding: 16px; border: 2px solid #cbd5e1; margin: 20px; } /* Each band adds to the outside under content-box */
.story-column { box-sizing: border-box; } /* **RIGHT:** width now means the border edge, padding grows inward */
```

```figure mode="box" layout="compare" caption="One declaration, two widths. Under content-box the padding and border are added outside the 120px; under border-box they are carved out of it."
verdict=wrong | tag=content-box | label=.story-column
width=120 | height=56 | padding=16 | border=2 | margin=20
---
verdict=right | tag=border-box | label=.story-column
sizing=border-box | width=120 | height=56 | padding=16 | border=2 | margin=20
```

Read the two measurement lines under the figures. On the left the browser reports 156 pixels for a box declared at 120, because it added 32 pixels of padding and 4 pixels of border outside the content. On the right the border edge is exactly 120 and the content shrank to 84 to make room. Two 50 percent columns with 16 pixels of padding overflow their row under `content-box` for precisely this reason: each column is 50 percent plus 36 pixels, and the second one falls onto the next line. The margin band sits outside both models and is never part of the width; that is why it is drawn with a dashed edge, the browser paints nothing there.

### Margins That Touch: Collapse in Normal Flow

Mira sets 24 pixels below the headline and 16 pixels above the standfirst and expects a 40 pixel gap. She gets 24. In normal block flow, two vertical margins that meet do not add; the larger one wins and the smaller one disappears inside it:

```css title="headline-gap.css"
h2.headline { margin-bottom: 24px; } /* The larger of the two */
p.dek { margin-top: 16px; } /* Swallowed inside the 24 in normal flow */
.story { display: flex; flex-direction: column; } /* Inside a flex container the margins no longer collapse */
```

```figure mode="margin" layout="compare" caption="The same two margins in normal flow and inside a flex column. In flow the smaller margin is drawn inside the larger one and the gap is 24; in the flex column both survive and the gap is 40."
tag=block flow | a=24 | b=16 | label-a=h2.headline | label-b=p.dek
---
tag=flex column | context=flex | a=24 | b=16 | label-a=h2.headline | label-b=p.dek
```

The left figure draws the 16 pixel band inside the 24 pixel band, because that is where the browser puts it: the two margins occupy the same space and the gap measures 24. The right figure is the same markup inside a flex column, and now the bands stack and the gap measures 40. MDN states the rule in one sentence:

> The top and bottom margins of blocks are sometimes combined (collapsed) into a single margin whose size is the largest of the individual margins (or just one of them, if they are equal), a behavior known as margin collapsing. Note that the margins of floating and absolutely positioned elements never collapse.
*MDN Web Docs, Mastering margin collapsing, resources/web-performance/mdn/files/en-us/web/css/guides/box_model/margin_collapsing/index.md*

Collapse happens only in the vertical direction, only in normal flow, and never inside a flex or grid container. When the gap you measure is smaller than the sum you wrote, collapse is the first suspect.

### Floating Boxes: The Parent That Forgot Its Children

A floated element is pulled to one side of its container and taken out of the normal flow. Its parent stops counting it when computing height. Float every child of the teaser box and the box has nothing left to measure, so its height falls to the padding alone and the lavender background shrinks to a stripe:

```css title="teaser.css"
.teaser img { float: left; margin-right: 8px; } /* **WRONG:** every child leaves the flow, the parent measures nothing */
.teaser { display: flow-root; } /* **RIGHT:** a new block formatting context contains the floats again */
```

```figure mode="float" layout="compare" caption="Three floated thumbnails inside the teaser. Without a formatting context the parent's height is only its padding; with flow-root the parent contains its floats and measures the full 64 pixels."
verdict=wrong | tag=collapsed parent | parent=.teaser | items=3 | float=left
---
verdict=right | tag=flow-root | parent=.teaser | items=3 | float=left | contain=flow-root
```

Look at the height measurement on the right side of each figure. The collapsed parent measures 24 pixels, which is its top and bottom padding and border with nothing between them; the thumbnails hang below its bottom edge. With `display: flow-root` the parent establishes a block formatting context, floats are included in its height again, and the box measures 64. MDN describes the mechanism that causes the escape:

> When an element is floated, it is taken out of the normal flow of the document (though still remaining part of it). It is shifted to the left, or right, until it touches the edge of its containing box, or another floated element.
*MDN Web Docs, float, resources/web-performance/mdn/files/en-us/web/css/reference/properties/float/index.md*

The older fixes, `overflow: hidden` on the parent or a clearfix pseudo-element, work by the same principle: each one creates a block formatting context. `flow-root` is the modern spelling of that intent with no side effects.

### Float in Running Text: The Margin Is the Gutter

Floats were invented for exactly one thing that still matters: wrapping text around an image. The words wrap around the float's margin edge, not its border, so the margin is the gutter between picture and prose. The byline, however, must never sit beside the picture, and that is what `clear` is for:

```css title="lede-image.css"
img.lede { float: left; margin: 0 16px 8px 0; } /* The margin is the gutter the words respect */
.byline { clear: left; } /* **RIGHT:** the byline drops below the bottom of every left float */
```

```figure mode="float-text" layout="compare" caption="Text wraps around the float's margin edge. Without clear the short byline is wedged beside the image; with clear left it moves below the float's bottom margin edge."
verdict=wrong | tag=no clear | float=left | margin=0 16 8 0
---
verdict=right | tag=clear left | float=left | margin=0 16 8 0 | clear=left
```

The peach band around the image is the margin; the first line of text starts at its right edge, never at the image's border. In the left figure the paragraph is too short to pass the float, so the byline is laid beside the image like any other line. In the right figure `clear: left` gives the byline clearance: the browser pushes it down until its top edge is below the bottom margin edge of every left float, drawn here as the dashed line above the byline.

### Centering a Box: Auto Margins Split the Free Space

The interview classic has a trap in it. `text-align: center` centers inline content inside a box; it never moves the box itself. A block with a fixed width is centered by giving both horizontal margins the value `auto`, which tells the browser to split the remaining free space equally:

```css title="cta.css"
.cta { width: 120px; text-align: center; } /* **WRONG:** the words move, the box stays at the left edge */
.cta { width: 120px; margin: 0 auto; } /* **RIGHT:** two auto margins share the free space equally */
```

```figure mode="center" layout="compare" caption="A 120px box inside a parent whose content box is 260px wide. text-align leaves 140px of free space on one side; margin auto splits it into two equal 70px margins."
verdict=wrong | tag=text-align: center | parent=260 | width=120 | method=text-align | label=div.cta
---
verdict=right | tag=margin: 0 auto | parent=260 | width=120 | method=auto | label=div.cta
```

The dashed purple lines are free space, the invisible quantity the browser distributes; the dot marks each segment's midpoint. On the left all 140 pixels of free space pile up on the right of the box because a left-aligned block keeps its left margin at zero. On the right the two `auto` margins resolve to 70 pixels each. The same rule explains why `margin: auto` does nothing on a block without a width: with no fixed width there is no free space to divide.

> [!TIP]
> **To impress the interviewer:** name the three mechanisms as one family. Sizing decides how wide a box is (`box-sizing`), collapsing decides how far apart two blocks are (largest vertical margin wins in normal flow), and the block formatting context decides which children a parent measures (`display: flow-root` brings floats back in). Then add the modern verdict: floats are for wrapping text around images and nothing else; every column layout that once used floats is flexbox or grid today, where margins do not collapse and children are never lost.

### Where you will meet this

- Story grids: two 50 percent columns with padding overflow their row until `box-sizing: border-box` is set globally.
- Article headers: a headline and standfirst whose gap is smaller than the two margins you wrote, because they collapsed.
- Teaser and card components: a container with a background that disappears the moment its children float.
- Long-form articles: a lede image floated left with a margin that acts as the gutter, and a byline that needs `clear`.
- Call-to-action blocks: a fixed-width subscribe box that stays glued to the left until both margins are `auto`.

### Glossary

- **Box model**: The four nested rectangles of every element: content, padding, border, and margin.
- **box-sizing**: The property that decides whether `width` measures the content edge (`content-box`, the default) or the border edge (`border-box`).
- **Margin collapsing**: The merging of two touching vertical margins in normal flow into a single margin equal to the larger one.
- **Float**: A box shifted to the left or right of its container, removed from normal flow, around which inline content wraps.
- **Block formatting context**: A layout region whose parent contains its floats and whose margins do not collapse with the outside; created by `display: flow-root`, among others.
- **Clearance**: The extra space `clear` adds above an element so that its top edge sits below the floats on the named side.
- **Auto margin**: A margin the browser resolves by taking a share of the free space in the containing block.

### Summary

**Three Rules of the Box**

Every layout defect in the front-page incident traces back to one of three rules: how the browser measures a box, how touching margins merge, and which children a parent counts. Learn the three as one family and the floats, the gaps, and the overflow stop being mysteries. Here is your streetwise review.

❒ Sizing and Spacing

1. Set `box-sizing: border-box` once, globally, and width means the border edge everywhere.
2. In normal flow, two touching vertical margins collapse to the larger one; in flex and grid they do not.

❒ Floats and Containment

1. A parent does not count floated children in its height.

**DO NOT DO THIS:** Float every child and leave the parent in normal flow.
```css wrong
.teaser img { float: left; }
```
&nbsp;&nbsp;&nbsp;&nbsp;**DO THIS:** Give the parent a block formatting context so it contains the floats again.
```css right
.teaser { display: flow-root; }
```
2. Center a fixed-width block with auto margins, not with text alignment.

**DO NOT DO THIS:** Expect text-align to move the box.
```css wrong
.cta { width: 120px; text-align: center; }
```
&nbsp;&nbsp;&nbsp;&nbsp;**DO THIS:** Let two auto margins split the free space.
```css right
.cta { width: 120px; margin: 0 auto; }
```

➔ NEVER build a column layout with floats in 2026; use flexbox or grid, where children are never lost.

➔ ALWAYS suspect margin collapse when a vertical gap measures less than the sum you wrote.

➔ IF a container's background vanishes THEN check whether every child is floated or absolutely positioned.
