Accompanying Book Paragraph:
React is deliberately architected as an isolated client library rather than an all-controlling page framework. A component file sitting on disk is an inert JavaScript function; it never executes itself, never queries the document tree, and never attaches to the browser window without explicit instructions. To mount your application, your code builds an entry bridge targeting a single designated container element—traditionally `<div id="root"></div>`—using `createRoot`. Why does React insist on this strict isolation instead of mounting directly to `document.body`? If React assumed ownership of `document.body`, its reconciliation engine would treat every node on the page as its own, wiping out third-party analytics scripts, host CMS navigation menus, and browser extension overlays. By establishing an isolated sandbox island inside `<div id="root">`, React guarantees that it strictly controls the DOM nodes within that container while leaving the surrounding host page completely untouched. Furthermore, modern React splits root initialization into a two-step concurrent API: `createRoot(domNode)` constructs an in-memory concurrent Fiber root container with its own event and scheduling boundaries, while `root.render(<App />)` initiates tree evaluation and minimal DOM mutation. When embedding interactive widgets into legacy multi-page architectures, calling `root.unmount()` cleanly destroys the component tree, detaches all event listeners, and empties the container without leaking memory.
