# Visual Aid Specification — Lecture 12: Keeping Components Pure

Where:
Place this visual aid in `md-lectures/12.md` inside the section `### The Shared Variable Trap and Render Mutations`, positioned immediately after the paragraph describing the re-render failure ("The disaster strikes the moment anything causes the page to re-render. Suppose a journalist clicks a category filter or a new breaking alert arrives... The screen now displays Alert #4, Alert #5, and Alert #6 for the exact same three stories.").

Instruction:
Create a clean, two-column horizontal comparison graphic on a pure white background that visually demonstrates why mutating an external variable during render works on initial mount but corrupts data upon re-render, creating an instant "aha moment" regarding render purity. On the left side, labeled "PURE (DERIVED FROM PROPS)", depict two stacked sequential render passes of a single component box with an input port on top receiving `count: 1` and an output port on the bottom emitting the UI badge `Alert #1`: show that in Render 1 the output is `Alert #1` and in Render 2 (triggered by a subtle refresh icon labeled "Re-render / Filter") the exact same input `count: 1` enters the box and produces the identical `Alert #1` badge, accompanied by a clean green check badge reading "Idempotent: Identical Output". On the right side, labeled "IMPURE (MUTATING OUTSIDE VARIABLE)", depict the exact same two sequential render passes, but place a shared persistent memory pill above them in module scope labeled `let alertCount = 0`: in Render 1, draw a thin directional arrow descending into the component showing `alertCount++`, leaving the memory pill updated to `3` while the screen displays `Alert #1, #2, #3`; then, in Render 2 directly below it, show the re-render running the same stories, but the arrow now reads from the dirty memory pill holding `3`, incrementing it to `6` and outputting corrupted badges `Alert #4, #5, #6`, accompanied by an amber alert pill reading "State Drift: Memory Leaked Across Renders". Connect the two impure passes with a prominent vertical dashed connector to make it unmistakably obvious that the external variable acted as a dirty bridge carrying old state into what should have been a fresh, isolated calculation.

Style:
The aesthetic must strictly adhere to the Swiss editorial and technical publishing character of this course rather than retro Neo-Brutalism or generic AI illustration. The background is pure white (#FFFFFF) with zero texture, grain, or gradient. Containers and cards use clean, crisp rectangular geometry with subtle 1px structural borders in light slate gray (#D0D0D0 / #E2E8F0) and soft neutral surface fills (#F6F6F4 / #F8FAFC), completely avoiding heavy black offset drop-shadows, sticker borders, or playful doodles. The primary accent is the course's signature deep cyan/ocean slate (#0E7490), used selectively for headers, flow arrows, and active component frames. Typography is strictly dual-discipline: all explanatory labels and step markers use clean, neutral geometric sans-serif (Inter or Helvetica Neue) in solid dark charcoal (#0F172A), while all variables, expressions, and component names (`let alertCount`, `count: 1`, `Alert #1`) are rendered in crisp, medium-weight monospace (JetBrains Mono). Visual indicators are restrained: use a quiet desaturated slate-teal pill for stable status and a subdued terracotta-ember pill (#C2410C) for the impure leak, avoiding harsh neon greens or oversaturated reds. Maintain generous whitespace around every node, perfectly orthogonal connecting paths with clean terminal arrowheads, and absolute typographic minimalism with zero decorative clutter.

Description:
This graphic attacks the central counter-intuitive puzzle of React purity: why code that looks completely functional on first load suddenly breaks when the user interacts with the page. Developers often struggle to understand why an external counter is considered "dangerous" when their initial local tests produce the correct numbers (1, 2, 3). By visually aligning Render 1 directly above Render 2, the graphic forces the reader's eye to track the lifecycle of the outside variable across time. In the pure column, the reader sees an airtight container where inputs flow in and predictable output flows out, leaving zero residue in memory. In the impure column, the reader immediately spots the illegal wire reaching outside the component into module memory, leaving a persistent residue of `3` that contaminates the subsequent render pass. This side-by-side contrast dissolves the abstraction of "idempotence" and "side effects" into a visible mechanical truth: an impure component cannot be safely re-rendered because it is tethered to outside history.
