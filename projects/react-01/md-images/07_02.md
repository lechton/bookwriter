# Visual Aid Specification — Lecture 07: Splitting Components with Imports and Exports

Where:
Place this visual aid in `md-lectures/07.md` inside the section `### Four Common Import Traps and How to Avoid Them`, positioned immediately after the first trap description ("1. **Adding curly braces to a default import**: Writing `import { SiteHeader } from './SiteHeader.jsx'` when `SiteHeader.jsx` used `export default`. JavaScript looks for a named export called `SiteHeader`, finds nothing, and assigns `undefined`. When React tries to render `<SiteHeader />`, it throws: `Element type is invalid: expected a string or a class/function but got: undefined`.").

Accompanying Book Paragraph:
When developers first split components across files, the most frequent point of failure is adding curly braces to a default import: writing `import { SiteHeader } from './SiteHeader.jsx'`. Because `SiteHeader.jsx` exports its component via `export default`, JavaScript registers it as the default export of the module, not a named property called `SiteHeader`. When you write `import { SiteHeader }`, JavaScript searches the module's named exports dictionary, finds no entry with that name, and silently assigns `undefined` to your variable. The moment React attempts to mount `<SiteHeader />` into the page tree, the entire application terminates with a blank screen and throws: `Element type is invalid: expected a string or a class/function but got: undefined`. As shown in the comparison below, curly braces are not decorative syntax; omitting curly braces links directly to the default export function, whereas wrapping the identifier in curly braces queries a non-existent named export, crashing the browser.
