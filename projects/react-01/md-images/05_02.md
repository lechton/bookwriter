# Visual Aid Specification — Lecture 05: The Rules of JSX

Where:
Place this visual aid in `md-lectures/05.md` inside the section `### Rule 1: Return a Single Root Element`, positioned immediately after the paragraph explaining why adjacent elements fail in compiled JavaScript ("Why does this fail? Look at the compiled JavaScript. Returning two adjacent tags is equivalent to writing return _jsx('h3', ...) _jsx('p', ...);. In JavaScript, a function cannot return two independent expressions or objects from a single return statement.").

Accompanying Book Paragraph:
JSX is not HTML; it is a compile-time syntactic illusion designed to be converted into pure JavaScript. When an engineer pastes HTML into a component file and hits a syntax crash, it is because they are evaluating markup through the lens of a browser DOM parser rather than a JavaScript compiler. Under the hood, build tools like Babel or SWC transform every JSX tag into a call to `_jsx()`, which returns a plain JavaScript element descriptor object. This compilation pipeline is the root cause of every JSX grammar rule. If you attempt to return two adjacent tags without a wrapper, the compiler emits two independent `_jsx()` expressions side by side—an impossible syntax violation in ECMAScript, where a function return statement can only accept a single expression value. Wrapping adjacent elements in a React Fragment (`<>...</>`) resolves the error because it compiles into a single `_jsx(Fragment, { children: [...] })` call that packages both elements into a single descriptor object. At runtime, React unrolls this Fragment directly into the parent DOM without injecting redundant `<div>` wrapper nodes, preserving clean document semantics and preventing CSS Grid or Flexbox layout breakage. Similarly, attributes must follow JavaScript identifier rules: `class` becomes `className` to prevent collisions with the reserved JavaScript class keyword, and hyphenated attributes become camelCase properties because hyphens are parsed as mathematical subtraction operators in JavaScript object literals.

Description:
This visual aid dissolves the mystery of why JSX enforces strict syntax rules that differ from standard HTML.
