Accompanying Book Paragraph:
When developers transition from raw HTML to React, the single most jarring compile-time barrier is the single root element rule. In standard HTML, placing sibling tags like `<h3>` and `<p>` next to each other is completely valid document structure. But in JSX, returning adjacent tags fails at build time because JSX compiles into JavaScript function calls: `return _jsx('h3', ...) _jsx('p', ...);`. A JavaScript function cannot return two independent values or objects side by side without a syntax error. Beginners often react by wrapping everything in redundant `<div>` containers—bloating the DOM tree with "div soup" and breaking parent-child layouts in CSS Flexbox and Grid. React solves this cleanly with the Fragment (`<>...</>`), which groups sibling elements into a single element descriptor object at compile time, then vanishes completely when rendered into the browser DOM. As contrasted in the comparison below, omitting the wrapper halts the compiler with an immediate syntax error, whereas wrapping the adjacent tags in `<>...</>` produces a valid single return and renders direct sibling DOM nodes without intermediate wrapper pollution.

By organizing the component lifecycle into a compact, space-efficient vertical layout with large characters and surgical marker highlights, the student's eye instantly connects the JavaScript compilation reality (a function cannot return two objects side-by-side) with the concrete solution (wrapping siblings in empty angle brackets `<>` and `</>`).
