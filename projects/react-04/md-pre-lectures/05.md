### The Window into JavaScript
- [p] ◇ {preknowledge:} In earlier lessons, we learned that JSX lets you write HTML-like markup inside JavaScript component functions (see Lecture 4). When you write a tag like `<h1>Breaking News</h1>`, the text inside the tag is a static string. {problem:} Real web applications are dynamic: you have variables in your script, such as an article headline or a reader name, and you need that markup to read those variables directly. ◼ Pedagogical qualification: Introduce the need for dynamic data binding in markup; terms introduced: **curly braces**, **JavaScript expression**, **data binding**.
- [p] ★ {preknowledge:} In plain HTML, markup is completely static: an attribute value is always a literal string, and text between tags cannot execute code. In JSX, curly braces `{ }` open a direct window into the JavaScript world. When the compiler encounters `{ }` inside JSX, it treats the content between the braces as real JavaScript code rather than literal text. {problem:} Developers often wonder where curly braces are allowed and how the compiler interprets them. ◼ Pedagogical qualification: Establish the two valid locations for curly braces; terms introduced: **text interpolation**, **dynamic attribute**.
- [p] ★ {preknowledge:} You can use curly braces in exactly two places inside JSX. (a) As text directly inside a JSX tag: `<h1>{headline}</h1>` evaluates the variable `headline` and renders its text into the heading. (b) As attributes immediately following the `=` sign: `src={photoUrl}` reads the variable `photoUrl` and assigns its value directly to the attribute. {problem:} If you put quotes around curly braces, like `src="{photoUrl}"`, JSX treats the entire attribute as a literal text string, passing the exact characters `"{photoUrl}"` rather than evaluating the variable. ◼ Pedagogical qualification: Contrast quoted string literals with unquoted curly brace expressions.
- [p] {old solution:} In legacy JavaScript DOM scripting, developers concatenated strings with the plus operator (`'<h1>' + headline + '</h1>'`) or mutated `element.textContent` by hand, creating noisy boilerplate that invited cross-site scripting vulnerabilities. ◼ Educational objective: Contrast curly brace expressions with manual string concatenation.
- [code] String concatenation versus JSX expression:
```jsx title="Data Binding Contrast"
// Legacy DOM String Concatenation:
const html = '<h1 class="title">' + headline + '</h1>';
// Declarative JSX Expression Window:
<h1 className="title">{headline}</h1>
```

- [grounding] Leading Question: Why do quotes disable JavaScript inside attributes?
  Confusion Point: Why does `src="{photoUrl}"` pass a literal string instead of evaluating the variable?
  Scene & Repetition: Imagine you write `src="{avatar}"` inside your component. You refresh the page and the image breaks. Why? In JSX, quotation marks `"` and `"` declare a literal string. The moment you type quotes, you tell the compiler: "Everything between these quotes is plain text." The compiler obeys. It does not look inside the quotes for code. It passes the literal text string `"{avatar}"` to the browser, and the browser attempts to fetch an image whose file name is literally `{avatar}`. If you want the compiler to evaluate the variable `avatar`, you must replace the quotes with **curly braces**: `src={avatar}`. Curly braces remove the quotes and open the window to JavaScript.
  Key Terms (Bold): `**curly braces**`, `**literal string**`, `**evaluated attribute**`.
  Resolution: Quotes tell the compiler to treat attribute values as literal text; removing quotes and using curly braces tells the compiler to evaluate the JavaScript identifier.

### Expressions versus Statements and Double Curlies
- [p] ◇ {preknowledge:} In JavaScript grammar, there is a fundamental distinction between an expression and a statement. An expression is any piece of code that evaluates to a single value, like `2 + 2`, `formatDate(today)`, or `user.isSubscribed ? "Premium" : "Standard"`. A statement is a command that performs an action or controls flow, like `if (condition) { }`, `for (...)`, or `let x = 1`. {problem:} Developers frequently try to place `if` statements or loops directly inside JSX curly braces and trigger immediate compiler syntax errors. ◼ Pedagogical qualification: Define the expression invariant of JSX curly braces; terms introduced: **expression**, **statement**, **ternary operator**.
- [p] ★ {preknowledge:} The law of JSX curly braces is simple: you can put any valid JavaScript expression between curly braces, and you can never put a JavaScript statement inside them. Why? Because JSX compiles into function calls: `jsx('h1', { children: expression })`. In JavaScript, you can pass an expression as a function argument, but you cannot pass an `if` statement or a `for` loop as a function argument. If you need conditional logic inside JSX, you use an expression like the ternary operator (`condition ? a : b`) or logical AND (`condition && a`). ◼ Pedagogical qualification: Ground the expression rule in function call argument semantics.
- [p] ★ {preknowledge:} In addition to strings, numbers, and booleans, you can pass JavaScript objects inside JSX. Objects in JavaScript are also defined with curly braces: `{ color: 'red', margin: 10 }`. To pass an object inside a JSX attribute, you must wrap the object's curly braces inside JSX's curly braces: `style={{ color: 'red', margin: 10 }}`. {problem:} Beginners see `{{` and `}}` and assume React invented a mysterious "double curlies" syntax. In reality, it is nothing more than an ordinary JavaScript object tucked inside the JSX curly brace window. ◼ Pedagogical qualification: Demystify the double curlies syntax for inline styles and object props; terms introduced: **double curlies**, **inline styles**, **object literal**.
- [code] Expressions and double curlies syntax:
```jsx title="Expressions and Objects"
// Ternary Expression inside JSX:
<p>{isBreaking ? 'Urgent Alert' : 'Standard News'}</p>
// Double Curlies Object Literal for Style:
<div style={{ backgroundColor: '#0f172a', color: '#ffffff' }}>
  <span>Live Wire</span> // Inline style uses camelCase **PROPERTIES**
</div>
```
- [grounding] Leading Question: What does the double curly brace syntax really mean?
  Confusion Point: Is `{{` a special React syntax for styling and complex props?
  Scene & Repetition: Imagine you are styling a breaking news banner. You write `style={{ color: "crimson" }}`. What are those double curlies? They look like a new language feature. But look closer. The outer pair `{ }` is the JSX window: it says "evaluate the JavaScript inside." The inner pair `{ }` is an ordinary JavaScript **object literal**: `{ color: "crimson" }`. You are passing a plain JavaScript object to the `style` prop. There is no special double curly syntax in React. It is simply an **object literal** placed inside the JSX **curly braces**.
  Key Terms (Bold): `**curly braces**`, `**object literal**`, `**inline styles**`, `**double curlies**`.
  Resolution: Double curlies are not a distinct React feature: the outer braces open the JavaScript window, and the inner braces declare a standard JavaScript object.

### Step 1: First, we construct the parent container StoryBanner.jsx
- [p] ★ {preknowledge:} In React, the parent container defines the dynamic data and dictates how child components receive it. {problem:} The parent must pass dynamic values (a headline string, an author object, and a numeric timestamp) downward without hardcoding static text. ◼ Pedagogical qualification: Construct parent container passing dynamic expressions through props.
- [code] Parent container StoryBanner:
```jsx title="StoryBanner.jsx" startLine="1" continues="bottom"
import AuthorBadge from './AuthorBadge.jsx';
import PublishDate from './PublishDate.jsx';
export default function StoryBanner({ headline, author, timestamp }) {
  return <article className="story-banner">
    <h1 className="banner-title">{headline}</h1> // Evaluates headline string in **TEXT**
    <AuthorBadge author={author} /> // Passes dynamic author **OBJECT**
    <PublishDate timestamp={timestamp} /> // Passes numeric timestamp **EXPRESSION**
  </article>;
}
```
- [p] ★ Step 1 establishes the contract: Notice lines 6, 7, and 8: `{headline}`, `author={author}`, and `timestamp={timestamp}`. The curly braces evaluate variables in scope and pass them as props to the children. We will build those children next. ◼ Pedagogical qualification: Deconstruct parent props contract.

### Step 2: Next, we build the author child AuthorBadge.jsx
- [p] ★ {preknowledge:} Step 1 established the contract: `AuthorBadge` receives an `author` object containing `name`, `role`, and `avatarUrl`. {problem:} The child component must evaluate object properties both as text content and as dynamic HTML attributes. ◼ Pedagogical qualification: Fulfill child contract; demonstrate attribute and text expression evaluation.

- [p] ★ Step 2 fulfills the contract: Look at lines 5 and 6: `src={author.avatarUrl}` and `alt={author.name}`. There are zero quotes around the curly braces. The browser receives the evaluated image URL and alt text directly from JavaScript memory. ◼ Pedagogical qualification: Underline absence of quotes on evaluated attributes.

### Step 3: Then, we declare the date child PublishDate.jsx
- [p] ★ {preknowledge:} Step 1 also established the contract for `PublishDate`, which receives a raw numeric `timestamp`. {problem:} The child must transform that numeric timestamp into a human-readable string using a JavaScript function call expression directly inside markup. ◼ Pedagogical qualification: Demonstrate function call expressions inside JSX curly braces.
- [code] Date child component:
```jsx title="PublishDate.jsx"
function formatDate(epochMs) {
  return new Intl.DateTimeFormat('en-US', { dateStyle: 'full' }).format(epochMs);
}
export default function PublishDate({ timestamp }) {
  return (
    <time className="publish-date" dateTime={new Date(timestamp).toISOString()}>
      {formatDate(timestamp)} // Evaluates function call **EXPRESSION**
    </time>
  );
}
```
- [p] ★ Step 3 demonstrates function evaluation: Look at line 7: `{formatDate(timestamp)}`. Any valid JavaScript function call that returns a string or number can be embedded directly between curly braces. React invokes `formatDate` during render and projects the returned string into the `<time>` node. ◼ Pedagogical qualification: Explain function execution during render pass.

### Step 4: Finally, we seal the banner with dynamic inline styling
- [p] ★ {preknowledge:} Now that all components evaluate their dynamic data, we add an urgent edition theme using inline styles. {problem:} The component must apply dynamic style rules using camelCase properties without writing invalid CSS string syntax. ◼ Pedagogical qualification: Apply double curlies inline style object to seal component.

Passing an object variable `bannerTheme` or writing inline `style={{ ... }}` produces the exact same result: a JavaScript object describing CSS properties. ◼ Pedagogical qualification: Prove equivalence of object variable and inline double curlies.

### Glossary
- **JSX Expression**: Any valid JavaScript code placed inside JSX curly braces that evaluates to a value.
- **Curly Braces**: The `{ }` syntax in JSX that opens an evaluation window into the JavaScript language.
- **Double Curlies**: The idiom where a JavaScript object literal `{ ... }` is passed inside JSX curly braces `{ { ... } }`.
- **Statement versus Expression**: Expressions evaluate to a value and are legal inside JSX; statements control flow and are forbidden inside JSX.
- **Evaluated Attribute**: An HTML attribute whose value is computed dynamically by a JavaScript expression rather than passed as a static string.
- **React Child Object Trap**: The runtime error triggered when a developer attempts to render a raw JavaScript object directly inside JSX text.

### Summary

**JavaScript Expressions in JSX and Curly Brace Invariants**

In daily production, curly braces are your portal between declarative markup and live JavaScript logic. Understanding what code is allowed inside curly braces prevents syntax crashes and keeps your components readable. Here is your streetwise review.

❒ The Evaluation Window and Expression Rules

1. Use curly braces to evaluate JavaScript values inside text content and attributes.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Inside tag text, `{variable}` projects strings or numbers directly into the document.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) In attributes, `prop={value}` evaluates the identifier without quotes, while `prop="{value}"` passes a literal string.

2. Restrict code inside curly braces strictly to JavaScript expressions.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Any code that evaluates to a value (variables, arithmetic, ternaries, function calls) is valid inside JSX.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Language statements like `if`, `for`, and `let` are syntax errors inside JSX and must live outside the return statement.

➔ NEVER put quotes around curly braces if you intend to evaluate a JavaScript variable.

➔ ALWAYS use expressions like ternaries (`condition ? a : b`) for conditional logic inside JSX.

➔ IF you need to pass an inline style or object prop THEN **use double curlies `style={{ property: value }}` with camelCase CSS names**.

**DO THIS:** Pass dynamic variables with unquoted curly braces and access primitive properties from objects.

```jsx right title="StoryBanner.jsx"
export default function StoryBanner({ headline, author, isLive }) {
  return (
    <article className="story-banner">
      <h2>{headline}</h2>
      <img src={author.avatarUrl} alt={author.name} />
      <span>{isLive ? 'LIVE' : 'RECORDED'}</span>
    </article>
  );
}
```

**DO NOT DO THIS:** Never quote curly braces, render raw objects, or put statements inside JSX.

```jsx wrong title="Invalid Expressions"
export default function InvalidExpressions({ headline, author, isLive }) {
  return (
    <article className="story-banner">
      <h2>"{headline}"</h2>
      <img src="{author.avatarUrl}" alt={author} />
      <span>{if (isLive) { 'LIVE' }}</span>
    </article>
  );
}
```
