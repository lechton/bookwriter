The Anatomy of a React Component

In earlier lessons, we learned that React replaces manual DOM mutations with declarative UI descriptions (see Lecture 1). In the project setup, we configured Vite to compile and serve our source files (see Lecture 2). Now you open your project editor to write your first visual building block. You create a JavaScript function that returns markup resembling HTML, and the browser displays it on screen.

What exactly is this function? In React, this foundational unit is called a component (a self-contained, reusable JavaScript function that accepts data inputs called props and returns markup describing a section of the user interface).

In traditional web development, a webpage was divided across three distinct files: an HTML file for document structure, a CSS file for presentation, and a JavaScript file for behavior. If an engineer renamed an element class or moved a badge inside the HTML file, the JavaScript file broke silently because its document.querySelector call returned null. React solves this fragmentation by grouping code by feature rather than by technology. A React component unites markup, styling, and behavior into a single, cohesive unit. Instead of writing separate templates and mutation scripts, you define the visual structure of a component once, and you can reuse that component across dozens of pages.

To understand how components collaborate in a real application, consider an article page on The National Times. A complete news article does not live as a single monolithic block of markup inside one file. Instead, we assemble the view from focused, modular components. The top-level layout ArticlePage.jsx provides the structural container for the page. Inside that layout, ArticleHeadline.jsx displays the category eyebrow and headline title, while AuthorProfile.jsx renders the author credit card directly below the headline.

Examining these files reveals the five universal traits that define the anatomy of every React component: (a) The function declaration (function Name()) defines a standard JavaScript function that encapsulates the component's visual blueprint. (b) The props parameter (({ propName })) accepts an incoming configuration object, allowing parent components to pass data downward. (c) The returned JSX markup (return <tag>...</tag>) describes what the user interface should look like for the given data. (d) The wrapping parentheses (return ( ... );) protect multi-line return statements from JavaScript parser quirks. (e) The capitalized name (ArticleHeadline) signals to the JSX compiler that the element is a custom component rather than a native HTML tag.

⚡ IN THE WILD

Why does React combine markup and logic? In traditional websites, you wrote HTML in one file, CSS in a second file, and JavaScript in a third file. When an engineer renamed a button ID in the HTML file, the JavaScript file broke silently because its query selector failed. You had to search across three files, time and time again. React eliminates this fragmentation. Instead of separating technologies across different files, React groups them by feature into a self-contained unit called a component. Each component owns its own markup and logic. When you update a component, its structure and behavior stay perfectly aligned.

The Capitalization Rule: PascalCase versus Native HTML

When you write HTML tags in an ordinary webpage, tag names are case-insensitive: writing <DIV>, <div>, or <Div> all produce a standard division element in the browser DOM. In React JSX, however, writing <AuthorProfile /> executes your custom function, whereas writing <authorProfile /> renders an empty, invisible tag without running your code.

Why does React insist that component names start with a capital letter? The reason stems directly from how JSX compiles into JavaScript. Browsers cannot execute JSX syntax natively. A build tool like Vite transforms every JSX tag into a JavaScript function call: jsx() (or classically React.createElement()).

During compilation, the JSX compiler inspects the very first letter of the tag name to determine what code to emit:

  • If the tag name begins with a lowercase letter (such as <article>, <header>, or <div>), the compiler treats it as a native HTML element. It emits the tag name as a string literal: jsx('header', ...). At runtime, React passes that string directly to the browser DOM engine to create a native document element.
  • If the tag name begins with an uppercase letter (such as <ArticleHeadline> or <AuthorProfile>), the compiler treats it as a custom component. It emits the name as a direct variable identifier: jsx(AuthorProfile, ...). At runtime, React executes that function to obtain its returned elements.
JSX Tag Comparison
1<article className="card" />

2<AuthorProfile author="Elena" />

3<authorProfile author="Elena" />

If you name your component with a lowercase letter and render <authorProfile />, the compiler outputs jsx('authorProfile', ...). React assumes you are attempting to render a custom HTML tag called <authorProfile>. Because HTML allows unknown custom element names, the browser creates a generic HTML element in the DOM, leaves it completely unstyled, and never executes your JavaScript function.

⚡ IN THE WILD

Why must component names start with capitals? Imagine you write a function named authorProfile and render <authorProfile /> in your page. The screen displays an empty space. The browser console shows zero errors. Why? Because the compiler saw the lowercase letter "a" and assumed you were asking for a native HTML element named <authorProfile>. The browser creates an unknown HTML tag in the DOM, leaves it unstyled, and never executes your function. This is why capitalization is mandatory: lowercase names create native DOM elements, while capitalized PascalCase names instruct React to execute your custom component function.

Parentheses and Automatic Semicolon Insertion

In JavaScript, functions can return values across multiple lines when expressions are structured properly. When writing a React component, developers frequently place the opening JSX tag on the line immediately below the return keyword. However, placing a line break immediately after return causes the function to return undefined, resulting in a blank screen or a runtime crash.

The JavaScript grammar specification includes a feature called Automatic Semicolon Insertion (ASI). When the JavaScript parser encounters a line break immediately following a return keyword, it assumes the return statement is complete and automatically inserts an invisible semicolon: return;. All subsequent lines of code are ignored, and the component function returns undefined instead of your intended JSX elements.

⚡ IN THE WILD

Why does a line break break return? You write a component and press Enter right after the return keyword to start your markup on a clean new line. When you refresh the page, the screen is completely blank. Why? Because JavaScript has a built-in parser rule called Automatic Semicolon Insertion. When the computer sees a line break after return, it assumes you finished your thought and secretly inserts a semicolon. Your markup is ignored, and your function returns nothing. Wrapping your markup in parentheses keeps the expression alive across multiple lines, ensuring your component returns its intended JSX markup.

The Single-Root Rule and Fragment Syntax

In JavaScript, a function can return only a single value at a time: a number, a string, an object, or an array. In React, JSX tags compile into JavaScript function calls, which evaluate to individual JavaScript objects in memory. If you write two adjacent JSX tags side by side without a shared parent container, the compiler fails with a syntax error because a function cannot return two independent values.

When developers encounter this single-root rule, their immediate instinct is to wrap adjacent sibling elements inside an extra <div>. While this satisfies the compiler, it pollutes the HTML document tree with dozens of unnecessary wrapper nodes, which breaks CSS flexbox and grid layouts that rely on direct parent-child relationships.

React solves this with a built-in primitive called a Fragment, written with the empty tag syntax <>...</>. A Fragment groups multiple sibling elements together so they satisfy the single-root requirement without creating an actual node in the browser DOM. When React renders a Fragment, it injects the child elements directly into the parent container without any surrounding wrapper.

⚡ IN THE WILD

Why can components return only one tag? Imagine you write a component that returns a headline and a paragraph side by side. The compiler stops with an error. Why? Because under the hood, JSX tags are real JavaScript function calls. A JavaScript function can return only one value at a time. It cannot return two separate objects sitting side by side. If you need to return two elements, you group them. But wrapping them in an extra <div> clutters your HTML and breaks CSS grid layouts. React solves this with a Fragment. Written as <>...</>, a Fragment satisfies the single-root rule while leaving your real DOM elements clean and unpolluted.

Interview Tip

To impress the interviewer: When asked why React requires PascalCase and Fragments, do not say "it is just React syntax." Explain the JavaScript compiler mechanics: JSX tag names compile to string arguments for native DOM elements when lowercase, but to variable references when capitalized. Similarly, JSX elements are plain JavaScript objects in memory, and functions cannot return multiple values without a wrapper, which is why Fragments group siblings without polluting the DOM.

Glossary

  • Component: A self-contained, reusable JavaScript function that accepts data inputs called props and returns markup describing a section of the user interface.
  • PascalCase: The naming convention where every word in an identifier begins with a capital letter, required for custom React component names to distinguish them from native HTML tags.
  • JSX Compiler: The build-time tool that inspects JSX tag names and transforms them into JavaScript function calls, emitting string literals for lowercase tags and variable identifiers for capitalized tags.
  • Automatic Semicolon Insertion: The JavaScript parser rule where a semicolon is inserted automatically after a return keyword followed by a line break, causing functions to return undefined unless wrapped in parentheses.
  • Fragment: A built-in React wrapper written as <>...</> that groups multiple sibling elements to satisfy the single-root rule without adding an extra node to the browser DOM.
  • Props: The single configuration object passed into a React component function by its parent, containing all attributes and child elements.

Summary

Component Anatomy, PascalCase Casing, and Syntax Rules

In daily production, authoring React components requires following strict syntactical rules governing naming, return formatting, and structural grouping. Here is your streetwise review.

❒ Core Rules of Component Architecture
  1. Always name custom components using PascalCase capitalization.
        (a) Lowercase tag names instruct the JSX compiler to emit string literals that create native browser DOM elements.
        (b) Capitalized tag names instruct the compiler to emit variable identifiers that execute your custom component functions.
  2. Always wrap multi-line JSX returns in parentheses.
        (a) Placing a line break immediately after the return keyword triggers Automatic Semicolon Insertion, returning undefined.
        (b) Parentheses signal to the parser that the return expression continues onto subsequent lines.
  3. Always satisfy the single-root rule using Fragments instead of wrapper divs.
        (a) Functions cannot return multiple values side by side; wrapping in extra divs pollutes the DOM and breaks CSS layouts.
        (b) Use empty Fragment tags <>...</> to group siblings in memory without adding physical DOM nodes.

➔ NEVER name a custom component with a lowercase initial letter.

➔ ALWAYS wrap multi-line JSX return statements in parentheses.

➔ IF returning adjacent sibling elements THEN group them inside an empty Fragment <>...</>.

DO THIS: Name custom components with PascalCase, wrap multi-line returns in parentheses, and group siblings using Fragments.
