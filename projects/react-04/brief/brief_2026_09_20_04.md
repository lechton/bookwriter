# Brief 2026_09_20_04: The Lecture 40 Standard

Batch #2026_09_20_04, groups 1 through 8. The lecture 40 remake (two new panels, top-down steps, the calm professor narration, the scene-engine-punchline cadence, structured code annotations) shipped as a working exemplar whose innovations existed in no instruction; its blueprint improvised them all: thin step bullets with no narration, 13 undocumented pre-element tags, and one stale figure pointer. This batch codifies the exemplar so the next pre-lectures inherit it as law instead of luck.

## group_1: Rule tags, registry, briefs

The debugging system itself: every new rule carries #YYYY_MM_DD_NN_group_M at its end; every group gets a registry row in skills/RULE-TAGS.md; every batch ships a brief in this folder explaining the rules, the philosophy, and the tags; and every new rule ships with a PROPER example drawn verbatim from shipped lecture text wherever it exists, because the example carries the doctrine and the checkbox carries the index.

## group_2: The calm professor narration

The assembly steps speak as direct instruction on how to write the code: notice-moves anchored to concrete lines, per-step recaps, inline alternatives (Mind you, the easiest way...), warning charges (Never forget the name attribute), and rhetorical questions only where the reader genuinely has one. The mechanical template question (Are you curious how we build this?) is the named counter-example.

## group_3: Scene, engine, punchline

Two-system comparisons decompose into the physical scene, what the engine does or does not do, and a single-condition punchline. The compressed subordinate clause (While the search bar had to react to every keypress, this correction form collects...) is the named counter-example; the numbered opening beats model the same cadence.

## group_4: The top-down assembly law

Step 1 constructs the parent and establishes every child's contract up front; later steps fulfill those contracts; the final step seals the deepest boundary instead of mounting the parent. Forward references (props we will provide later in step 4) are banned. Stage A opens with the Rendered UI Canvas before the files scaffold, Stage D carries the Component Role panel before the audit table, and the body order swaps to the shipped 40 order (the practical example precedes the phased flow that explains it).

## group_5: The two panel modes

The components panel has two faces: explorer mode (connecting code, before the first mechanism code) and canvas mode (Rendered UI Canvas, snippet-free, before Step 1). The component-code panel has code-fidelity mode and role mode ([role:] entries, zero code, serif prose in the four-beat rhythm: what it is, what it owns or receives, the relational contrast, and Why? answered directly).

## group_6: Code Logic and Data Flow annotations

The assembly fences annotate load-bearing lines with // **CODE LOGIC:**<br> (what the line does mechanically) and // **DATA FLOW:**<br> (which direction data moves and where it lands), riding the existing speech-bubble renderer; they are the sanctioned exception to the short-label comment rule inside the practical example fences.

## group_7: Pre-lecture structure security

The core worry this batch answers: securing the structure for the next blueprints. Staging 34's example now mirrors the 40 standard; a new law requires each step's [p] bullet to carry the narration itself (the notice-move, the recap, the alternative, the warning) instead of a summary; the 13 summary-family tags are codified into the pre-element taxonomy; the parent-naming law relaxes App.jsx to a default (a short everyday domain name is allowed when the parent owns real architecture); and a new gate requires every [figure] src to exist on disk and match its bullet, the exact check that would have caught the stale 40-02-01 pointer, which this batch also fixes in md-pre-lectures/40.md.

## group_8: Verification gates follow the standard

Structure Gates 15 and 17 now test the panel pair (canvas before Step 1, role panel before the audit table), the top-down steps, and the narration (a notice-move and a recap per step).
