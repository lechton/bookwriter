# Brief 2026-09-20-24: The Pre-Example Mechanism Bridge

## 1. Context & Autopsy of the Defect

In `react 04`, intense focus on perfecting the 5-stage practical example (Stages A through E) created a structural blind spot: lectures often jumped directly from high-level problem motivation (e.g., "The Fragility of Manual DOM Scripting" and "The Declarative Shift") straight into multi-file code assembly (`### Let's Design a Practical Example...`), omitting the theoretical introduction of the core React primitive itself.

In Lecture 1, for example, the student was asked to build and assemble `SiteHeader.jsx`, `ReaderGreeting.jsx`, and `SubscriberInfo.jsx` without the lecture text ever explaining:
- What a **component** actually is (a self-contained, reusable JavaScript function returning markup).
- Why component names **must be capitalized** (`<SiteHeader />` vs `<header>`).
- What **props** are and how data passes downward.
- How components **nest** to form an interface tree.

In `react 03`, this transition was handled seamlessly by a dedicated conceptual section (`### Components as Reusable Blueprints`) that grounded the React mechanism in the plain web platform baseline before any code files were opened.

## 2. Technical Decisions & Rules Added

We codified the Pre-Example Mechanism Bridge across `skills/` under tag `#2026_09_20_24_group_1`:

1. **Rejection of Rigid "4-Beat" Formulas**:
   - Rather than enforcing an authoritarian, formulaic "4-Beat Arc" that generates stiff, robotic compliance, the rule requires natural pedagogical content and teaches by example using the gold-standard passage from Lecture 1.

2. **Dedicated to This Particular Lecture**:
   - Explicitly mandated that the pre-example section must be **dedicated to this particular lecture's unique topic** rather than generic framework filler:
     - **Lecture 1**: `### Components as Reusable Blueprints` (components, capitalization `<SiteHeader />` vs `<header>`, props, nesting).
     - **Lecture 2**: `### The Component Tree as a Living Hierarchy` (parent-child trees, top-down data flow, root vs. leaf components).
     - **Lecture 3**: `### Functions as Markup Engines` (functions returning JSX, return statement grammar, UI descriptors).
     - **Lecture 4**: `### Fragments as Invisible Containers` (single root rule, self-closing void elements, zero-wrapper DOM unwrapping).
     - **Lecture 5**: `### The JSX Evaluation Window` (single curlies for expressions, statements banned, double curlies for object literals).

3. **`skills/lecture-structure/SKILL.md` (Skeleton 15B)**:
   - Mandated the dedicated pre-example mechanism section in the lecture skeleton immediately before Stage A.

4. **`skills/lecture-revision/SKILL.md` (Principle 04B)**:
   - Mandated that during a revision pass, if a lecture jumps directly from problem motivation into the practical example, the revision must author and insert the missing conceptual section.

5. **`skills/verification/SKILL.md` (Gate 09B)**:
   - Added Gate 09B (*The Pre-Example Mechanism Bridge Gate*) to fail any lecture that jumps directly from problem philosophy into code without this dedicated section.

6. **`skills/RULE-TAGS.md`**:
   - Registered `#2026_09_20_24_group_1` in the rule tags registry.
