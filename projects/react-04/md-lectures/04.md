### Why JSX Is Not HTML

In earlier lessons, we learned that a React component is a JavaScript function returning markup (see Lecture 3). When you write that markup, it looks nearly identical to HTML: you write angle brackets, tag names like `<h1>`, and attributes like `src`. Developers naturally assume they are writing real HTML, but web browsers cannot understand JSX directly, and treating JSX as HTML causes sudden syntax errors.

Under the hood, a compiler like Babel or Vite's SWC transforms every JSX element into a plain JavaScript function call: `jsx('h1', { children: 'Breaking' })`. Because JSX compiles into function calls, it must obey the strict grammar of JavaScript. In JavaScript, you cannot return two separate objects from a function without wrapping them, and you cannot leave syntax unclosed. Loose HTML5 parsing rules allow unclosed void tags and arbitrary attributes, but the JSX compiler rejects any snippet that violates JavaScript syntactic integrity.

```jsx title="Compilation Model"
// JSX Source:
<h1 className="headline">Breaking News</h1>
// Compiled JavaScript Output:
jsx('h1', { className: 'headline', children: 'Breaking News' });
```

This compilation step transforms declarative markup into in-memory JavaScript objects called UI descriptors. When the compiler evaluates `<h1 className="headline">Breaking News</h1>`, it passes the tag name `'h1'` as a string to denote a native DOM element, followed by an object containing its properties and child nodes. Because these tags become object properties and function arguments, the syntax rules of JavaScript govern every single character of JSX.

> [!WILD]
> **Why can't browsers read JSX directly?** Imagine saving an ordinary `.jsx` file to your desktop and double-clicking it. The browser opens a blank white page. The developer console displays an unhandled SyntaxError: Unexpected token `<`. Why? Because web browsers are built to parse HTML and standard JavaScript, but JSX is neither. It is a syntax extension. If you do not run a **compiler** to transform every tag into a JavaScript function call, the browser chokes on the very first bracket. The compiler transforms your markup into plain JavaScript objects before the browser ever sees it.

### The Three Strict Syntax Rules of JSX

In plain HTML5, browsers are extremely forgiving: you can omit closing tags on `<img>` or `<input>`, you can write `class="card"`, and you can place multiple top-level elements side by side. In React, the compiler enforces three non-negotiable syntax rules.

Rule 1: Return a Single Root Element. A component function cannot return multiple adjacent elements without a single enclosing parent. Under the hood, JSX compiles into JavaScript function calls. In JavaScript, a function cannot return two values at once: writing `return a, b;` returns only `b`. Returning `<header /><p />` is equivalent to returning `jsx('header'), jsx('p')`, which is invalid JavaScript grammar. Every returned JSX snippet must be wrapped in a single parent tag.

Rule 2: Close All Tags Explicitly. In HTML, certain tags known as void elements (such as `<img>`, `<input>`, `<br>`, and `<hr>`) never require a closing slash. In JSX, every tag must be explicitly closed. You must write `<img src="..." />`, `<input type="text" />`, or `<br />`. If you leave any tag unclosed, the compiler parser cannot determine where the element's children end, triggering a fatal syntax error.

Rule 3: camelCase Most Attributes. In HTML, attributes use lowercase or hyphenated names like `class`, `for`, `tabindex`, and `stroke-width`. In JSX, attributes become keys inside a JavaScript object: `jsx('div', { className: 'card' })`. Because words like `class` and `for` are reserved keywords in JavaScript (`class Component` and `for (;;)`), React uses `className` and `htmlFor` instead. All standard DOM properties use camelCase: `tabIndex`, `autoFocus`, `strokeWidth`. As an exception, `aria-*` and `data-*` attributes remain hyphenated to match web accessibility and data specifications.

```jsx title="JSX Rules Comparison"
<div className="card">
  <img src="news.jpg" alt="Harbor" /> // Self-closing tag satisfies **PARSER**
  <h2 className="title">Strike Enters Day 2</h2> // camelCase attribute avoids reserved **KEYWORD**
</div>
```


> [!WILD]
> **Why className instead of class in JSX?** Imagine you write `class="news-banner"` inside your component. In JavaScript, `class` is not just an attribute name: it is a sacred reserved keyword used to define object-oriented classes. Because JSX compiles directly into a JavaScript object (`{ class: "news-banner" }`), early JavaScript parsers threw fatal syntax errors when unquoted reserved words appeared as property keys. Even though modern JavaScript allows unquoted reserved keys, React standardized on **className** to match the browser's own DOM property (`element.className`). This is why you must write **className**: it prevents collisions with JavaScript keywords and matches the native DOM property directly.

### Step 1: First, we construct the parent container ArticlePreview.jsx

We start our implementation at the top: the parent container `ArticlePreview.jsx`.

We begin here because the parent defines the layout and dictates the component hierarchy. It groups both children inside a Fragment `<>...</>` to satisfy the single root rule without adding a wrapper `<div>` to the real DOM:

```jsx title="ArticlePreview.jsx"
import Headline from './Headline.jsx';
import StoryExcerpt from './StoryExcerpt.jsx';
export default function ArticlePreview({ title, text }) {
  return (
    <>
      <Headline title={title} /> // Mounts headline without extra wrapper **DIV**
      <StoryExcerpt text={text} /> // Mounts excerpt as direct sibling in **DOM**
    </>
  );
}
```

Look at lines 5 and 8: `<>` and `</>`. These opening and closing Fragment tags satisfy the compiler's single root rule. However, when React mounts this component into the browser DOM, it creates zero physical wrapper elements.

Now look at lines 6 and 7: `<Headline title={title} />` and `<StoryExcerpt text={text} />`. The parent dictates the contract, passing `title` and `text` props downward to both children.

To recap this first step: the parent uses a Fragment to group its children cleanly without polluting the physical DOM tree.

### Step 2: Next, we build the heading child Headline.jsx

In step 2, we fulfill the first contract established by the parent: we build `Headline.jsx`.

This child component renders the semantic heading:

```jsx title="Headline.jsx"
export default function Headline({ title }) {
  return <h2 className="headline-text">{title}</h2>; // Renders heading with camelCase **CLASSNAME**
}
```

Notice the attribute on line 2: `className="headline-text"`. Rather than using the reserved JavaScript keyword `class`, it uses `className`, adhering strictly to JSX naming conventions.

To recap this step: child components render semantic HTML elements using camelCase attributes to avoid keyword collisions.

### Step 3: Then, we declare the excerpt child StoryExcerpt.jsx

In step 3, we fulfill the second contract established by the parent: we build `StoryExcerpt.jsx`.

This child component renders the summary text:

```jsx title="StoryExcerpt.jsx"
export default function StoryExcerpt({ text }) {
  return <p className="story-excerpt">{text}</p>; // Projects excerpt into paragraph **NODE**
}
```

Notice that `StoryExcerpt` receives its `text` prop and renders a simple paragraph. Because `ArticlePreview` used a Fragment, this `<p>` element sits as an immediate sibling to `<h2>` in the browser's physical DOM.

To recap this step: both child components render clean semantic markup that integrates seamlessly into the parent's container.

### Step 4: Finally, we seal the preview with Fragment grouping

In step 4, we examine how `ArticlePreview.jsx` completes the component and exports the Fragment-wrapped structure:

```jsx title="ArticlePreview.jsx"
import Headline from './Headline.jsx';
import StoryExcerpt from './StoryExcerpt.jsx';
export default function ArticlePreview({ title, text }) {
  return (
    <>
      <Headline title={title} /> // Mounts headline without extra wrapper **DIV**
      <StoryExcerpt text={text} /> // Mounts excerpt as direct sibling in **DOM**
    </>
  );
}
```

Look at lines 5 and 8: `<>` and `</>`. Because `ArticlePreview` returns a Fragment, the `<h2>` and `<p>` elements become direct siblings in the DOM. When mounted inside an outer CSS Grid or Flexbox container, these child elements participate directly in layout calculations without an intermediate `<div>` intercepting column or row rules.

To recap this final step: Fragments allow components to return multiple sibling nodes that participate directly in outer CSS flex and grid structures.

### Lessons from the Experiment: Naive Expectation vs Reality

To review the architectural lessons from this implementation, examine the component hierarchy:

```component-code title="Summary: The Logic of Nested Components"
ArticlePreview.jsx | none | parent | [role: The **parent container** groups editorial elements in memory using a React Fragment. Notice it returns multiple sibling elements with **zero wrapper div nodes**. Why? To allow the child elements to participate directly in the outer page grid without breaking flexbox or table layouts.]
  Headline.jsx | none | header | [role: This is the **headline child component**. Notice it renders a semantic `<h2>` element using camelCase `className` instead of plain HTML `class`. Why? Because JSX compiles to JavaScript objects where `class` is a reserved language keyword.]
  StoryExcerpt.jsx | none | card | [role: This is the **excerpt child component**. Notice it renders a summary paragraph and a self-closing `<img />` tag. Why? Because the JSX compiler enforces strict XML-style self-closing tags on all void HTML elements.]
```

In the naive approach, developers instinctively wrap adjacent sibling elements in a generic `<div>` tag to satisfy the compiler. While this satisfies the single root rule, it introduces wrapper div soup, bloating the DOM and breaking CSS flexbox and grid layouts.

In the React 19 reality, the `<>...</>` Fragment groups sibling elements in memory without creating an intermediate HTML wrapper node in the document. The compiler parses the single root, while the browser receives clean, semantic siblings.


> [!WILD]
> **Why does an extra div break flexbox and tables?** Imagine you have a CSS flex container: `.feed { display: flex; gap: 20px; }`. Flexbox applies its spacing and alignment strictly to its immediate child elements. When your component returns a wrapper `<div>`, that wrapper becomes the flex child, while your headline and excerpt become grandchildren. The layout collapses. Worse, inside an HTML `<table>`, placing a `<div>` between `<tr>` and `<td>` violates the HTML specification, causing browsers to eject your content into a broken position outside the table. This is why you need a **Fragment**: it satisfies the single root rule while rendering zero wrapper nodes in the physical DOM.

> [!TIP]
> **To impress the interviewer:** When asked why JSX requires a single root element, explain the underlying JavaScript mechanism: JSX tags compile into `jsx()` function calls. In JavaScript, a function cannot return multiple expressions without wrapping them in an array or parent structure. A Fragment compiles into a call that tells React to render a list of children directly into the parent container without creating an unnecessary DOM wrapper.

### Where you will meet this

- News feed cards: grouping an article thumbnail and summary text inside a Fragment so they align cleanly as direct children of a CSS Grid layout.
- Table row components: rendering multiple `<td>` table cells from a single child component without inserting an illegal `<div>` inside a `<tr>`.
- Form field pairs: grouping a `<label>` and `<input>` together with a Fragment so custom form CSS can control their vertical rhythm without wrapper nodes.
- List rendering with keys: mapping an array of stories to adjacent title and excerpt tags using `<Fragment key={story.id}>` to maintain list identity.

### Glossary

- **JSX**: A syntax extension for JavaScript that allows developers to write HTML-like markup inside JavaScript component files.
- **Single Root Rule**: The syntactic requirement that every JSX expression must be enclosed in exactly one top-level element or Fragment.
- **Fragment**: A React component that groups a list of children without adding an extra node or wrapper to the physical browser DOM.
- **Self-Closing Tag**: A tag that closes itself with a trailing slash (`<tag />`), mandatory in JSX for elements without children.
- **camelCase Attributes**: The naming convention used for JSX properties to prevent collisions with reserved JavaScript keywords like class and for.
- **Keyed Fragment**: An explicit Fragment component imported from React that accepts a key prop during list rendering.

1. Treat JSX as strict JavaScript syntax rather than permissive browser HTML.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Every tag must be explicitly closed, including void elements like img and input.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Use camelCase attribute names like className and htmlFor to avoid collisions with JavaScript reserved words.

2. Use Fragments to satisfy the single root rule without adding wrapper nodes to the DOM.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) The shorthand `<>...</>` groups elements without polluting the DOM or breaking CSS flexbox and grid layouts.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Use the explicit `<Fragment key={id}>` syntax whenever you need to pass a key during list rendering.

➔ NEVER leave void HTML tags unclosed or use the reserved word `class` as an attribute in JSX.

➔ ALWAYS wrap adjacent sibling elements in a Fragment `<>...</>` to avoid unnecessary wrapper div soup.

➔ IF you need to pass a key to a group of sibling elements in a list THEN **import and use the explicit Fragment component**.

**DO THIS:** Wrap adjacent elements in a Fragment and use camelCase attributes with self-closing tags.

```jsx right title="ArticlePreview.jsx"
export default function ArticlePreview({ title, summary }) {
  return (
    <>
      <img src="news.jpg" alt="News" />
      <h2 className="headline">{title}</h2>
      <p className="summary">{summary}</p>
    </>
  );
}
```

**DO NOT DO THIS:** Never return multiple adjacent elements without a parent, leave tags unclosed, or use class.

```jsx wrong title="Invalid Markup"
export default function InvalidMarkup({ title, summary }) {
  return (
    <img src="news.jpg">
    <h2 class="headline">{title}</h2>

  );
}
```
