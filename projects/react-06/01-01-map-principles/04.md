- **Interview Question**: *How do you use JavaScript expressions inside JSX with curly braces?*

## Authorized Scope
Q04 teaches the JSX curly braces inside one component with local variables and no props or state: curly braces open a window to JavaScript in exactly two places, the content between tags and an attribute value right after `=`, and everywhere else JSX text and quoted values are literal characters; the expression inside runs while React renders the component and its result takes the place of the braces; quotes pass a fixed string while braces pass a JavaScript value, so a value built from several parts is one expression inside one pair of braces; braces accept expressions that produce a value (variables, arithmetic, template literals, ternaries, function calls) and reject statements such as `if` and `for`, whose logic moves above the `return`; in content, strings and numbers print as text while `true`, `false`, `null`, and `undefined` print nothing, and a plain object or a `Date` cannot be printed at all; and `{{ }}` is an ordinary object literal inside the attribute window, as in `style={{ color: 'pink' }}`. It builds on Q03 (JSX grammar, closed tags, `className`) and Q02 (one component function), and it leaves conditional output to Q10, arrays and `.map()` to Q11, passing values to custom components to Q06 and Q07, render purity to Q12, event props to Q13, changing values over time to Q14, string escaping to Q48, and the rules of the `style` object to Q83.

## Principles

### Principle 1: Read curly braces as a window to JavaScript that opens in two places
- **Kind**: Model
- **Roles**: `{headline}` between tags: content window, the value prints as text; `src={avatarUrl}`: attribute window, the value becomes the attribute; text outside braces and quoted values: literal characters copied as written.
- **Placement**: braces between an opening and a closing tag, or right after the `=` of an attribute; not around a tag name (`<{tag}>` fails to compile).
- **Mechanism**: the JSX compiler copies outside text as string literals and puts the code inside braces into the compiled call unchanged; React runs that code each time it renders the component, and the result takes the place of the braces.
- **Defect**: `<h2>headline</h2>` shows the word "headline"; `// note` in content shows on screen as `// note`; no error is reported for either (verified in React 19.3).
- **Importance**: The card's Friction and the first bug of a newcomer to JSX; Q10, Q11, and Q13 rest on render-time evaluation, and Q13 uses it to explain why `onClick={handleClick()}` runs at render.
- **Prediction**: `<h2>{headline}</h2>` shows the variable's value, and editing the string changes the heading after reload; `<h1>To Do List for {formatDate(today)}</h1>` shows the weekday, and a `console.log` inside `formatDate` prints when the component renders; `{/* note */}` shows nothing.
- **Required Lesson Proof**: In one `ArticleCard`, render `<h2>headline</h2>` beside `<h2>{headline}</h2>` and show both on screen; add a log inside `formatDate` and show it in the console when the card renders; add `// note` as content, show the text on screen, then wrap it as `{/* note */}` and show it gone.
- **Sources**: Core Truth, Mechanism, and Friction of `01-01-map/04.md`; Recap bullets 2 and 3; "Using curly braces" and "Where to use curly braces"; learn/index.md "Displaying data"; the merged `<{tag}>`, render-time call, and comment candidates, verified in React 19.3.

### Principle 2: Quote a fixed string, and brace a value that comes from JavaScript
- **Kind**: Decision
- **Roles**: `className="avatar"`: quoted value, a fixed string; `src={avatarUrl}`: braced value, read from the variable when the component renders; `src={baseUrl + imageId + '.jpg'}`: one expression that builds the string.
- **Placement**: braces directly after `=` with no quotes around them, and the whole value inside one pair; not braces inside quotes (`src="{avatarUrl}"`, `src="{baseUrl}{imageId}.jpg"`).
- **Mechanism**: a quoted value is a string literal, so braces written inside it are ordinary characters; a braced value passes whatever JavaScript value the expression produces, including numbers, booleans, and `undefined`, which leaves the attribute out.
- **Defect**: `src="{avatarUrl}"` puts the characters `{avatarUrl}` into the DOM and the image request fails with no React error; `disabled="false"` keeps the button disabled, because the browser sees the attribute present, and React logs a development warning; `disabled={false}` removes the attribute (verified in React 19.3).
- **Importance**: The card's Friction; reviewers flag braces inside quotes, and the failures ship silently as a broken image or a dead button; Q06 recalls the rule for props.
- **Review Point — Condition**: When the value is fixed text, write it in quotes; when it comes from a variable, a calculation, or several parts, remove the quotes and write one expression in one pair of braces.
- **Required Lesson Proof**: Render `<img src="{avatarUrl}" />` and show the broken image and the literal `src` in the Elements panel, change it to `src={avatarUrl}` and show the photo; build `src="{baseUrl}{imageId}.jpg"` and then `src={baseUrl + imageId + '.jpg'}` and show both values in the Elements panel; render a button with `disabled="false"` and show that it cannot be clicked, then `disabled={false}`.
- **Sources**: Mechanism and Friction of `01-01-map/04.md`; Recap bullet 1; "Passing strings with quotes" and "Where to use curly braces"; Challenge "Write an expression inside JSX curly braces" with its Solution; the merged `src="{avatarUrl}"`, multi-part URL, and `disabled="false"` candidates, verified in React 19.3.

### Principle 3: Put expressions in braces, and move statements above the return
- **Kind**: Decision
- **Roles**: expression: code that produces a value (`headline`, `readTime * 2`, `` `${readTime} min` ``, `isAdmin ? 'Editor' : 'Reader'`, `formatDate(today)`); statement: code that performs control flow and produces no value (`if`, `for`, `while`).
- **Placement**: expressions inside the braces; an `if` or a loop in the component body above the `return`, storing its result in a variable that the braces read; not `{if (isAdmin) { ... }}` inside JSX.
- **Mechanism**: the braces compile into an argument of a function call, and JavaScript accepts only an expression in that position; a statement there is a syntax error.
- **Defect**: `<p>{if (isAdmin) { 'Editor' }}</p>` stops the build at the `if` with an unexpected token error; `{for (...) {}}` and `{while (...) {}}` fail the same way (verified with esbuild and `@babel/parser`).
- **Importance**: The card's Code Experiment Naive and a standard interview probe ("what can go inside the braces?"); without it a newcomer has no path from `if` thinking to JSX, and Q10 recalls it.
- **Review Point — Do not**: Do not write `if`, `for`, or `while` inside JSX braces; compute the value above the `return` and read the variable, or use an expression form such as a ternary or a function call.
- **Required Lesson Proof**: Write `<p>{if (isAdmin) { 'Editor' }}</p>`, show the build error, then fix it twice: `const role = ...` computed with `if` above the `return` and read as `{role}`, and `{isAdmin ? 'Editor' : 'Reader'}`, naming Q10 as the owner of branching; also show `{3 * 4}` and `{today.getFullYear()}` printing `12` and the year.
- **Sources**: Under the Hood and Code Experiment Naive of `01-01-map/04.md`; "Using curly braces" (any JavaScript expression, including function calls); the merged valid-expression and loop-statement candidates, verified with esbuild and `@babel/parser`; the Supporting row correcting the card's `function` claim; the Preview rows for the ternary and JSX in a variable (Q10).

### Principle 4: Predict what content braces print from the value's type
- **Kind**: Model
- **Roles**: string: printed as text; number: printed as text, `0` and `NaN` included; `true` and `false`: print nothing; `null` and `undefined`: print nothing; array: prints its items in order (lists are Q11's).
- **Placement**: content between tags, as in `<p>{readTime}</p>`; attributes follow Principle 2.
- **Mechanism**: React accepts strings, numbers, booleans, `null`, `undefined`, elements, and arrays of these as content (React nodes); it writes strings and numbers into text nodes and leaves booleans, `null`, and `undefined` as empty places.
- **Defect**: `{article.titel}`, a misspelled property, is `undefined`, so the heading renders empty with no error; `{isPublished}` shows nothing where the reader expected "true"; `{readTime}` with `0` prints `0` (verified in React 19.3).
- **Importance**: The card's Under the Hood names the render matrix; a developer without it cannot explain an empty heading or a stray `0`, and Q07 and Q10 recall the model from Q04.
- **Prediction**: `<p>[{'s'}][{0}][{NaN}][{true}][{false}][{null}][{undefined}]</p>` renders `[s][0][NaN][][][][]`; `{String(isPublished)}` prints `true`.
- **Required Lesson Proof**: Render the bracketed line and show the screen text matching the prediction; render `{article.titel}` and show the empty heading and an empty console; then name Q10 as the lesson where `0` on the left of `&&` prints by mistake.
- **Sources**: Under the Hood of `01-01-map/04.md`; common.md `children` definition; isValidElement "React elements vs React nodes"; the merged `0` and `NaN`, boolean, and misspelled-property candidates, verified in React 19.3; the Preview rows for `&&` (Q10) and arrays (Q11).

### Principle 5: Turn objects, dates, and functions into text before they reach content
- **Kind**: Decision
- **Roles**: `person`: plain object, cannot be printed; `person.name`: string field, prints; `today`: `Date` object, cannot be printed; `formatDate(today)`: call that returns a string; `formatDate`: the function itself, prints nothing.
- **Placement**: a field or a formatter call inside content braces (`{person.name}`, `{formatDate(today)}`); not the object, the `Date`, or the uncalled function (`{person}`, `{today}`, `{formatDate}`).
- **Mechanism**: a plain object or a `Date` is not a React node, so React does not know how to display it and stops the render with an error; a function is not a React node either, so React prints nothing in its place and reports a development console error.
- **Defect**: `<h1>{person}'s Todos</h1>` throws "Objects are not valid as a React child" and nothing renders; `{today}` throws the same error; `{formatDate}` leaves the heading without its date and logs a console error (verified in React 19.3).
- **Importance**: The react.dev Challenge "Fix the mistake" is built on this crash, and printing a whole API object or a `Date` is a common junior bug; Q07 and Q11 recall it from Q04.
- **Review Point — Do not**: Do not place a plain object, a `Date`, or a function reference in content; read the field or call the formatter that returns a string or number.
- **Required Lesson Proof**: Render `<h1>{person}'s Todos</h1>`, show the error and the blank screen, change it to `{person.name}`; render `{today}`, show the same error, change it to `{formatDate(today)}`; remove the parentheses, show the missing date and the console error, and restore the call.
- **Sources**: react.dev Challenge "Fix the mistake" and its Solution; the merged `Date` and uncalled-function candidates, verified in React 19.3.

### Principle 6: Read double curlies as an object inside the attribute braces
- **Kind**: Model
- **Roles**: outer braces: the attribute window from Principle 1; inner braces: an ordinary JavaScript object literal; `style`: an attribute that expects an object.
- **Placement**: `style={{ backgroundColor: 'black', color: 'pink' }}` or an object held in a variable, `style={theme}`; the object's property rules are previewed for Q83.
- **Mechanism**: JSX has no double-brace syntax; the outer pair opens the window and the expression inside happens to be an object literal, so a variable holding the same object produces the same result.
- **Defect**: A reader who takes `{{` for special template syntax cannot read `style={theme}`, `person={{ name: 'Hedy' }}` (Q06), or `dangerouslySetInnerHTML={{ __html }}` (Q48), and tries `style="color: pink"`, which throws (verified in React 19.3).
- **Importance**: A react.dev Recap bullet and part of a complete answer; Q06 and Q07 recall the model from Q04.
- **Prediction**: `<ul style={{ backgroundColor: 'black', color: 'pink' }}>` and `<ul style={theme}>` with `const theme = { backgroundColor: 'black', color: 'pink' }` produce the same `style="background-color: black; color: pink;"` in the DOM.
- **Required Lesson Proof**: Render both lists and show the identical `style` attribute in the Elements panel; then name Q83 as the owner of camelCase style keys and of the error for a string `style`, and note that fixed styling belongs in a class.
- **Sources**: Recap bullet 4; "Using double curlies" and "More fun with JavaScript objects"; common.md "Applying CSS styles"; the merged `style={theme}` candidate, verified in React 19.3; the Preview rows for the `style` object rules (Q83).

## Senior Answer
Curly braces are a window from JSX back into JavaScript, and they open in exactly two places: between tags, where the value prints as content, and right after an attribute's `=`, where the value becomes the attribute. Everything outside them is literal, so `<h2>headline</h2>` prints the word and `<h2>{headline}</h2>` prints the variable. The code inside runs each time React renders the component, and its result takes the place of the braces, so `{formatDate(today)}` calls the function during render. For attributes I use quotes for fixed text and braces for a JavaScript value, never braces inside quotes: `src="{avatarUrl}"` sends the literal characters and the image breaks, and `disabled="false"` still disables the button. When a value has several parts, I build it as one expression in one pair of braces. Braces take expressions, such as variables, arithmetic, template literals, ternaries, and function calls, but not statements; an `if` inside JSX does not compile, so I compute the value above the `return` and read the variable. In content, strings and numbers print, `0` included, while `true`, `false`, `null`, and `undefined` print nothing, which is why a misspelled property leaves an empty heading without an error. A plain object or a `Date` cannot be printed and throws "Objects are not valid as a React child", so I read a field or call a formatter, and I make sure a function is called rather than placed. Finally, `{{ }}` is not special syntax: it is an object literal inside the attribute braces, which is how `style={{ color: 'pink' }}` works.
