# Q06: Passing Data with Props and the Read-Only Contract — Operational Principle Map
- **Source Map**: `01-01-map/06.md`
- **Topic Tag**: `#props` | `❱ CORE`
- **Interview Question**: *How do you pass data into a component, and why can a component never change its own props?*

## Authorized Scope
Q06 teaches passing static data downward: attributes at a JSX call site (`<ArticleCard title="..." readTime={5} />`) become one props object that the child receives as its only argument, the child destructures the props it uses in its parameter list, optional props get parameter defaults that apply only when a value is missing or `undefined`, and the child treats the whole object, including nested objects, as read-only and derives new values during render; it builds on Q02 component definition, Q04 quoted versus braced attribute values, and Q05 the parent-child edges of the tree, and it excludes children composition and spread (Q07), event handlers and callback props (Q13, Q47), state (Q14), render-order purity (Q12), StrictMode (Q46), memoization (Q55), the React Compiler (Q63), TypeScript prop types (Q90), and legacy `defaultProps` (Q100).

## Principles

### Principle 1: Read props as one object the parent builds at the call site
- **Kind**: Model
- **Rule**: Every attribute written on `<ArticleCard title="Budget passes" readTime={5} />` becomes a key of a single props object that the parent creates and React passes to `ArticleCard` as its only argument, so the parent decides the values and the child only reads them.
- **Importance**: An interviewer expects "props are the arguments of a component function" as the opening of the answer, and every later lesson on callbacks, children, and lifting state builds on the parent owning the values.
- **Prediction**: A `console.log(props)` inside `ArticleCard` rendered from three call sites prints three objects whose keys match the attributes and whose values differ per call site.
- **Required Lesson Proof**: Render three `ArticleCard` call sites with different `title` and `readTime` values and show the three logged objects in the console next to the three different cards on screen.
- **Sources**: Mechanism of `01-01-map/06.md`; passing-props Step 1, Step 2, and Recap bullet 1 (merged).

### Principle 2: Turn what differs between instances into props
- **Kind**: Decision
- **Rule**: When copies of a component differ only in some values, keep one component and make exactly those values props, and do not add a prop that can be derived from another one, such as a tag count next to a `tags` array.
- **Importance**: A reviewer flags three copy-pasted cards with hardcoded headlines because every fix must be made three times, and flags redundant props because the count and the array can disagree.
- **Review Point — Do**: Check that each prop carries a value that varies between call sites and that no prop can be computed from another prop.
- **Required Lesson Proof**: Replace three hardcoded identical cards with one `ArticleCard` receiving `title` and `readTime`, then show a `tagCount` prop disagreeing with `tags` and fix it with `tags.length` computed in the child.
- **Sources**: Friction and Code Experiment Naive of `01-01-map/06.md`; passing-props Challenge 1 Hint and Solution note (`awardCount`), merged.

### Principle 3: Destructure props inside braces in the parameter list
- **Kind**: Decision
- **Rule**: Write `function ArticleCard({ title, readTime })` so the parameter unpacks the props object into named variables, because a bare `function ArticleCard(title)` binds the whole props object to `title`.
- **Importance**: react.dev marks it as a Pitfall, and the missing braces crash the render with "Objects are not valid as a React child (found: object with keys {title})".
- **Review Point — Do not**: Do not name a single prop as the bare parameter; destructure it inside `({ ... })` or read it from `props`.
- **Required Lesson Proof**: Remove the braces, show the error in the console and the blank card, restore the braces, and show the equivalent `props.title` form rendering the same headline.
- **Sources**: passing-props Pitfall and its `props.person` equivalence (merged); Mechanism of `01-01-map/06.md`; the error text verified in React 19.3 with Vite 8.3.1.

### Principle 4: Decide which props are required and give the optional ones defaults
- **Kind**: Decision
- **Rule**: Classify every prop as required or optional, give each optional prop a default in the destructuring (`readTime = 3`), and leave required props without a default, knowing that React 19 checks neither: `propTypes` and `defaultProps` on function components are silently ignored.
- **Importance**: A missing optional prop leaves a hole on screen (JSX renders nothing for `undefined`, so the card reads " min read"), and a returning developer who writes `propTypes` with `isRequired` gets no warning at all, so a missing headline ships unnoticed.
- **Review Point — Do**: Check that every optional prop has a parameter default and that required props are documented or typed rather than guarded by `propTypes`.
- **Required Lesson Proof**: Omit `readTime` and show " min read" with the number missing, add `readTime = 3` and show "3 min read", then add `ArticleCard.propTypes` with `title: PropTypes.string.isRequired`, omit `title`, and show an empty headline with a silent console.
- **Sources**: passing-props "Specifying a default value" and Recap bullet 3; Code Experiment React; React 19 upgrade guide, merged; the Preview rows for `defaultProps` (Q100) and TypeScript (Q90).

### Principle 5: Expect `null` and `0` to bypass a default
- **Kind**: Decision
- **Rule**: A parameter default fires only when the prop is missing or `undefined`, so a parent that sends `null` gets `null` and a parent that sends `0` gets `0`.
- **Importance**: Articles loaded from an API often carry `byline: null` for "no byline", and a card with `byline = 'Staff Reporter'` then shows an empty byline, a bug that survives because the default looks correct.
- **Review Point — Condition**: If a parent may send `null` for "no value", normalize it where the data enters or use `byline ?? 'Staff Reporter'` in the child; if `0` is a valid value, rely on the default leaving it alone.
- **Required Lesson Proof**: Render `<Card />`, `<Card size={undefined} />`, `<Card size={null} />`, and `<Card size={0} />` against `size = 100` and show `100`, `100`, `null`, and `0`, then show the empty byline with `byline={null}` and its `??` correction.
- **Sources**: passing-props "Specifying a default value" ("if you pass `size={null}` or `size={0}`, the default value will **not** be used") and Recap bullet 3; outputs verified in React 19.3 with Vite 8.3.1.

### Principle 6: Treat props as read-only and derive new values
- **Kind**: Decision
- **Rule**: Never assign to props or to objects inside them; compute display values as new constants during render (`const headline = title.toUpperCase()`), because the values belong to the parent, which creates a new props object whenever it wants the child to show something different.
- **Importance**: In development, `props.title = ...` throws "Cannot assign to read only property 'title' of object '#<Object>'", but the freeze is shallow and absent in production, so mutating a nested `story` object passes silently and changes what a sibling card that shares the object displays.
- **Review Point — Do not**: Do not assign to a prop or to a property of an object received as a prop; derive a new value, and when the screen must change over time, use state (Preview of Q14).
- **Required Lesson Proof**: Show the development TypeError for `props.title = props.title.toUpperCase()`, then pass one shared `story` object to two cards, mutate it in the first, and show both cards displaying `BUDGET PASSES`, then derive `headline` without mutation and show each card correct.
- **Sources**: Core Truth, Under the Hood, and Code Experiment of `01-01-map/06.md`; passing-props "How props change over time"; Rules of React "Don't mutate Props"; createElement freezing Caveat; the merged freeze, shallow-freeze, production, reassignment, and copy candidates, verified in React 19.3.

## Senior Answer
I pass data by writing attributes at the call site, `<ArticleCard title="Budget passes" readTime={5} />`, which React collects into one props object and hands to the component as its only argument; the child destructures what it uses in its parameter list, `function ArticleCard({ title, readTime })`, since forgetting the braces binds the whole object and crashes the render. I make exactly the values that differ between instances into props and derive anything computable, such as a count from an array. I decide which props are required and give the optional ones parameter defaults, remembering that a default applies only for a missing or `undefined` prop, not for `null` or `0`, and that React 19 no longer checks `propTypes` or applies `defaultProps` on function components. A component can never change its own props because they belong to the parent that created them: React freezes the object in development so an assignment throws, but the freeze is shallow and absent in production, so a nested mutation silently corrupts the parent's data and every sibling that shares it; the child derives new values during render instead, and anything that must change over time becomes state.
