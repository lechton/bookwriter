# Q07: Container Composition with Children and Prop Spreading — Operational Principle Map

## Authorized Scope
Teach open container composition through the `children` prop and deliberate JSX prop forwarding through rest-and-spread syntax. Show how a wrapper owns its shell while callers own nested content, how React passes that content as an opaque renderable value, and how forwarding can preserve supported host attributes without creating a rigid prop matrix.

- **Core Truth**: Choosing caller-owned nested structure becomes Principle 1 and honoring the slot becomes Principle 2.

- **Mechanism**: Nested JSX and `children` access become Principle 2; intentional rest-and-spread forwarding becomes Principle 4; filtering the forwarded object becomes Principle 5; resolving overwrite order becomes Principle 6.

## Operational Principles

### Principle 1: Use `children` When the Caller Should Own the Inner Structure
- **Operational Rule**: Accept nested JSX through `children` when a container should provide a stable shell around content chosen by its caller. This slot-composition contract avoids a growing matrix of props for every possible headline, badge, image, or action arrangement.
- **Review Point — Condition**: Use `children` for open-ended nested structure; use named props when the component itself owns the meaning and placement of a specific value.
- **Required Lesson Proof**: Replace a rigid card API with many layout props by one `CardContainer` that wraps two visibly different caller-supplied JSX structures.

### Principle 2: Place the `children` Slot Where Nested Content Belongs
- **Operational Rule**: Render `children` at the precise location where caller-owned content should enter the container's shell. Omitting the slot silently discards the nested JSX, while placing it in the wrong region breaks the container's layout and semantic contract.
- **Review Point — Do**: Verify that every component advertised as a wrapper renders its `children` exactly once at the intended content boundary unless duplication is an explicit API feature.
- **Required Lesson Proof**: Compile `<Card><EditorialContent /></Card>` into a props object, then compare a wrapper that omits `children` with one that renders it in the intended body region.

### Principle 3: Treat `children` as an Opaque React Node
- **Operational Rule**: Pass or render `children` without assuming that it is always one element, an array, or a particular internal object shape. React may supply text, one element, several elements, an empty value, or another renderable tree through the same prop.
- **Review Point — Do not**: Do not mutate `children` or inspect undocumented element internals to decide how the container should render.
- **Required Lesson Proof**: Feed the same container text, one component, and several sibling elements, then show that the slot renders each form without array-specific code.

### Principle 4: Spread Props Only for a Genuine Pass-Through Boundary
- **Operational Rule**: Use `{...restProps}` when a thin wrapper intentionally forwards a family of supported attributes to one underlying element or component. Explicit props remain clearer when the forwarding surface is small or when the wrapper transforms the values.
- **Review Point — Prefer**: Prefer explicit prop names by default and use spread syntax when forwarding is the wrapper's stated responsibility rather than a shortcut for avoiding API design.
- **Required Lesson Proof**: Compare repetitive forwarding of several ordinary host attributes with a concise rest-prop handoff, while keeping the forwarding destination visible.

### Principle 5: Remove Component-Only Props Before Forwarding
- **Operational Rule**: Destructure props consumed by the wrapper before spreading the safe remainder onto a host element or child component. Filtering prevents internal configuration names from leaking to the DOM or crossing a boundary that does not support them.
- **Review Point — Do**: Inspect the contents of the rest object and forward only attributes that the destination is designed to receive.
- **Required Lesson Proof**: Show one component-only prop leaking through a blind spread, then remove it through destructuring and inspect the clean destination props.

### Principle 6: Order Spreads and Explicit Props by Override Policy
- **Operational Rule**: Place a spread before or after explicit props intentionally because later JSX props override earlier ones. The order decides whether caller input may replace a default or whether the wrapper must enforce a value.
- **Review Point — Condition**: Put caller props after defaults when callers may override them; put an enforced prop after the spread when the wrapper must retain control.
- **Required Lesson Proof**: Render the same competing value with two attribute orders and inspect which value reaches the destination in each case.
