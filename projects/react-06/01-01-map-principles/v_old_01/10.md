# Q10: Conditional Rendering in React — Operational Principle Map
- **Source Map**: `01-01-map/10.md`

- **Interview Question**: *How do you show, hide, or switch JSX based on a condition?*

## Authorized Scope
Teach how to select standard JavaScript branching forms for JSX driven by static props: early returns for whole-component outcomes, ternaries for two alternatives, logical AND for one-sided inclusion, and the distinction between removing markup and merely hiding an existing DOM node.

## Deferred Scope
- Array mapping and keys belong to Q11.
- Event-driven changes and callback props belong to Q13–Q15, while interactive condition changes with `useState` belong to Q16.
- Suspense fallbacks, routing branches, transitions, and server/client rendering conditions remain outside this lesson.

- Q01 owns declarative output instead of manual DOM mutation.
- Q02 owns intentional `null` returns.
- Q04 owns expression grammar, primitive render suppression, and the numeric `0 && <Component />` guard.
- Q06 owns reading the props that supply this lesson's conditions.

## Coverage and Disposition Ledger
- **Core Truth**: Whole-component `if` branches become Principle 1, two-sided inline alternatives become Principle 2, and one-sided inclusion becomes Principle 3; returning `null` remains a Q02 prerequisite.
- **Friction**: Imperative DOM toggling reuses Q01's declarative ownership rule, while the new choice between removing a node and retaining a visually hidden node becomes Principle 4.
- **Mechanism**: Early returns, ternaries, and logical AND each become a principle because code can choose the wrong branch shape independently and each correction differs.
- **Under the Hood**: Suppression of `false`, `null`, and `undefined` plus the numeric-zero trap remain Q04 prerequisites that support Principle 3 rather than becoming Q10 principles again.
- **Code Experiment**: Article guards, either-or labels, and optional badges prove Principles 1 through 3; DOM and accessibility inspection prove Principle 4; extracting a long condition is supporting readability advice within those choices, not another source obligation.
- **Scope Boundary**: Conditions may come from static props; list mapping, event-driven changes, state, Suspense, routing, transitions, and server/client branches remain deferred.

## Operational Principles

### Principle 1: Use an Early Return for a Whole-Component Outcome
- **Operational Rule**: Put an `if` statement before the main JSX return when a condition replaces the component's complete output or intentionally suppresses it. This keeps guard states and alternate full views separate from the normal render path.
- **Review Point — Condition**: Use an early return when the branch controls the whole component; keep a local branch inline when the surrounding layout remains shared.
- **Required Lesson Proof**: Compare an unavailable-article guard returning `null` or alternate JSX with an equivalent deeply wrapped main return, then trace which structure is easier to review.

### Principle 2: Use a Ternary for Exactly Two Inline Alternatives
- **Operational Rule**: Use `condition ? firstJSX : secondJSX` when one location must render one of two meaningful alternatives. Both branches remain explicit, making a live badge versus a publication date or subscriber message versus public summary visible in one decision.
- **Review Point — Condition**: Choose a ternary for a local either-or branch; extract the decision when nested ternaries or large branch bodies obscure the two outcomes.
- **Required Lesson Proof**: Render both outcomes from the same prop and compare the readable two-branch form with a nested conditional that hides which alternative belongs to which condition.

### Principle 3: Use Logical AND for One-Sided Inclusion
- **Operational Rule**: Use `condition && jsx` when the true branch adds one piece of markup and the false branch should add nothing. The left operand should already express a boolean decision; Q04's numeric guard still applies when the source value is a count.
- **Review Point — Condition**: Choose `&&` for an optional addition with no alternate UI; choose a ternary when the false case has its own visible output.
- **Required Lesson Proof**: Compare an optional breaking-news badge with a two-way status label, then reuse the Q04 boolean comparison to prevent a numeric zero from appearing.

### Principle 4: Choose Between Removing Markup and Visually Hiding It
- **Operational Rule**: Conditional rendering omits a React node and therefore removes its host output from the DOM, while CSS visibility techniques leave the element present. Choose based on whether the element should exist for layout, accessibility, measurement, or later interaction, not merely on which syntax is shorter.
- **Review Point — Condition**: Render nothing when the node should be absent; use an appropriate visual-hiding technique when the node must remain in the document for a deliberate reason.
- **Required Lesson Proof**: Compare the Elements tree and accessibility consequence of a conditionally absent notice with a notice retained in the DOM and hidden by styling.
