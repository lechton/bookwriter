## Operational Principles

### Principle 1: Decompose the Interface into Root, Branch, and Leaf Responsibilities
- **Operational Rule**: Give the application one root composition point, use branch components to group coherent interface regions, and use leaf components for focused terminal output. Boundaries should follow stable responsibilities rather than arbitrary line counts or a one-component-per-tag habit.
- **Review Point — Prefer**: Prefer a component boundary when a region has a clear domain role, can change independently, or is reused; keep tightly coupled markup together when splitting adds no ownership value.
- **Required Lesson Proof**: Refactor one monolithic page into a root, two branch regions, and a leaf while naming the responsibility protected by each boundary.

### Principle 2: Read the Rendered JSX Nesting as the Component Tree
- **Operational Rule**: Determine parent-child relationships from which component elements a parent returns. File location, import direction, and alphabetical order do not create a tree edge; rendered JSX nesting does.
- **Review Point — Do**: Trace a component's direct children from its returned JSX before reasoning about ownership or data flow.
- **Required Lesson Proof**: Show identical imports used in two different JSX nestings and compare the different element graphs React receives.

### Principle 3: Trace Rendering from Parent to Direct Children
- **Operational Rule**: Start runtime reasoning at the root, inspect the elements its component returns, and continue down each branch. A parent is evaluated before React can discover and evaluate the child elements described in that return value.
- **Review Point — Do**: When debugging which component rendered, follow the active branch from owner to direct child instead of treating the page as a flat list of functions.
- **Required Lesson Proof**: Instrument a small root, branch, and leaf tree and show the top-down discovery and evaluation sequence.

### Principle 4: Use Ancestry to Locate Structural Ownership
- **Operational Rule**: When related regions need a shared coordination point, locate their nearest common ancestor and make the relationship visible through that branch instead of letting siblings reach sideways into one another. Q05 establishes the structural route; later lessons supply the prop, callback, or state mechanics.
- **Review Point — Do**: Trace both consumers upward to their nearest shared ancestor before choosing where a cross-region relationship belongs.
- **Required Lesson Proof**: Contrast a lateral sibling dependency with the same relationship drawn through a common ancestor, without introducing later data APIs.
