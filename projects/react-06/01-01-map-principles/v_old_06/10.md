# Q10: Conditional Rendering in React — Operational Principle Map
- **Source Map**: `01-01-map/10.md`
- **Topic Tag**: `#conditional_rendering` | `❱ CORE`
- **Interview Question**: *How do you show, hide, or switch JSX based on a condition?*

## Authorized Scope
Q10 teaches branching markup on props with plain JavaScript: early returns (`if (!article) return null`), inline ternaries (`{isLive ? <LiveBadge /> : <StaticDate />}`), logical AND (`{isBreaking && <span className="alert">BREAKING</span>}`), boolean-coerced guards (`commentCount > 0 && ...`), JSX assigned to variables, and the difference between omitting an element and hiding it, all inside an `ArticleHeader` whose branches are shown by rendering it with different props; it builds on Q04 (curly braces accept expressions, and `false`, `null`, and `undefined` render no node), Q05 (the render tree), Q06 props, and Q09 `root.render`, and it excludes state-driven toggles (Q14), state loss when a branch unmounts (Q24), hooks after early returns (Q37), `<Activity>` (Q73), and lists (Q11).

## Principles

### Principle 1: Return early when the component cannot produce its output
- **Kind**: Decision
- **Rule**: When the whole output depends on a condition, such as `article` being present, check it at the top of the component and return `null` or a fallback before any line reads from the data, and when the question is only whether the parent shows the component at all, keep the condition in the parent's JSX.
- **Importance**: A card that reads `article.title` while the data is missing crashes the render with "Cannot read properties of undefined (reading 'title')", and a component that silently returns `null` for a parent's layout decision surprises whoever renders it.
- **Review Point — Condition**: If the component cannot render without the data, guard it with an early return before reading from it; if the decision is whether the parent includes it, write the condition in the parent's JSX.
- **Required Lesson Proof**: Render `<ArticleHeader article={undefined} />` and show the error in the console, add `if (!article) return null` and show the empty slot, then move the condition to the parent as `{article && <ArticleHeader article={article} />}`.
- **Sources**: Mechanism of `01-01-map/10.md`; conditional-rendering "Conditionally returning JSX", "Conditionally returning nothing with `null`", and its Note, merged; the error verified in React 19.3 with Vite 8.3.1.

### Principle 2: Use `&&` for show-or-nothing and the ternary for one of two
- **Kind**: Decision
- **Rule**: Write `{isBreaking && <span className="alert">BREAKING</span>}` when the alternative is nothing, because a false condition leaves a hole that renders no node, and write `{isLive ? <LiveBadge /> : <StaticDate />}` when each case shows something, so both outcomes sit side by side in one expression.
- **Importance**: An interviewer expects the operator choice explained by branch shape, and a developer without it writes `&&` pairs that emulate an `else` (`{isLive && <LiveBadge />}{!isLive && <StaticDate />}`), duplicating the condition in two places that can drift apart.
- **Review Point — Condition**: If one branch renders nothing, use `&&` with a boolean left side; if both branches render something, use the ternary; both are valid React, and the branch shape decides.
- **Required Lesson Proof**: Render `ArticleHeader` twice, with `isBreaking` and `isLive` set to `true` and to `false`, and show on screen and in the Elements panel which badge each form produces.
- **Sources**: Mechanism of `01-01-map/10.md`; Recap bullets 4 and 5; conditional-rendering "Conditionally including JSX" and the logical AND section, merged.

### Principle 3: Make the left side of `&&` an explicit boolean
- **Kind**: Decision
- **Rule**: `&&` returns its left operand when that operand is falsy, and React prints numbers, so write a comparison such as `commentCount > 0 && ...` or `tags.length > 0 && ...` instead of relying on the truthiness of a number, `NaN`, or an array.
- **Importance**: `{commentCount && <span>comments</span>}` prints a stray `0` on every article without comments, `NaN` prints `NaN` and logs "Received NaN for the `children` attribute. If this is expected, cast the value to a string.", and an empty `tags` array is truthy, so an empty list renders.
- **Review Point — Do not**: Do not put a number, a value that can be `NaN`, or an array on the left of `&&`; compare it to produce `true` or `false`.
- **Required Lesson Proof**: Render `commentCount={0}`, `rating={NaN}`, and `tags={[]}` with bare `&&` guards and show `0`, `NaN`, and an empty `<ul>` in the Elements panel with the `NaN` warning in the console, then apply the comparisons and show all three render nothing.
- **Sources**: Under the Hood and Code Experiment of `01-01-map/10.md`; conditional-rendering Pitfall and Challenge 2 Solution; the merged `NaN`, empty-array, and empty-string candidates, verified in React 19.3.

### Principle 4: Move branching out of JSX when it outgrows one expression
- **Kind**: Decision
- **Rule**: When conditions nest or one case's information is spread across several ternaries, compute the result before the `return` with `if` statements and a variable, a lookup object keyed by the case, or a child component per case, and embed only the result in the JSX.
- **Importance**: A reviewer cannot match outputs to conditions in a chain like `a ? b ? <X /> : <Y /> : <Z />`, and adding a new case to scattered ternaries means editing several places at once.
- **Review Point — Prefer**: Prefer one level of inline condition per expression; beyond that, prefer `let content` assigned in `if` statements, a lookup object, or extracted components.
- **Required Lesson Proof**: Refactor an `ArticleHeader` whose badge area uses a nested ternary for breaking, live, and archived stories into `let badge` assigned in `if` statements, then into a lookup object, and show the same three rendered outputs.
- **Sources**: conditional-rendering ternary section ("use it in moderation ... consider extracting child components"), "Conditionally assigning JSX to a variable", Recap bullet 3, and Challenge 3 with its Solutions, merged.

### Principle 5: Omit elements through JSX instead of hiding them with DOM commands
- **Kind**: Decision
- **Rule**: Decide visibility in the JSX, so a hidden badge or comment section is simply not part of the output and does not exist in the DOM, and keep CSS hiding (a class or the `hidden` attribute set through JSX props) for the cases where the node must remain, never adding classes through `classList` on nodes React manages.
- **Importance**: The card's Friction is `display: none` toggled by DOM queries that flicker and drift from React's output; an omitted element also disappears from `document.querySelector`, while a CSS-hidden one stays in the DOM where queries still find it (`display: none` does remove it from the accessibility tree, so the difference is the DOM, not what a screen reader announces).
- **Review Point — Condition**: If the element should not exist, omit it with a condition; if its DOM node must survive while invisible, hide it with a class or `hidden` passed as a prop; in neither case edit React's nodes with `classList`.
- **Required Lesson Proof**: Render the comment section once omitted and once with `hidden`, show in the Elements panel that only the second exists, and run `document.querySelector('.comments')` in the console to show `null` versus a node.
- **Sources**: Friction and Code Experiment Naive of `01-01-map/10.md`; the merged `querySelector` candidate; the Prerequisite row for React's DOM (Q01); the Deferred row for `<Activity>` (Q73).

## Senior Answer
In React, conditions are plain JavaScript inside the component that describes the UI for its current props. When the whole output depends on something, like the article existing, I return early with `null` or a fallback before reading from it, and when the decision is whether the parent shows a component, I put the condition in the parent's JSX. Inline, I use `&&` when the alternative is nothing, because `false`, `null`, and `undefined` render no node, and a ternary when each branch shows something; the left side of `&&` must be a real boolean, since `0 && <Badge />` prints `0`, `NaN` prints `NaN`, and an empty array is truthy, so I write `count > 0 &&`. When branches nest or scatter, I move the logic before the `return` into `if` statements with a variable, a lookup object, or separate components. To hide something I leave it out of the JSX, so it is absent from the DOM, and I use a CSS class or `hidden` prop only when the node must stay, never toggling classes on React's nodes by hand.
