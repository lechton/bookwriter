What is a React component, and what rules govern how you write and name one?

The Silent Blank Screen of Lowercase Tags

In standard JavaScript development, developers follow camelCase naming conventions for almost every identifier. You write helper functions named calculateReadingTime(), declare variables named activeArticle, and attach event handlers named handleSubscribe(). When starting out with React, developers naturally carry this established muscle memory forward. You write articleCard(), assemble headline and summary markup inside its body, and mount it as <articleCard />. The syntax looks clean, the code editor shows no red squiggles, and the terminal build finishes with zero errors.

When you refresh the browser page, the article card is completely missing. The terminal reports no errors, and the browser developer console reports zero warnings. When you inspect the living page in the Elements panel, you find a bizarre custom tag: <articlecard></articlecard>. The browser treated your component tag as a native HTML element instead of executing your JavaScript function. The browser ignores the unknown tag, skips your function, and leaves an empty white screen.

To see this failure in concrete code, examine how a junior developer attempts to declare and mount a news card:

Notice what happened under the hood. When the JSX transpiler parsed <articleCard />, it looked at the very first letter of the tag. Because the letter a is lowercase, the compiler assumed <articleCard /> was a native HTML tag like <div> or <article>. It compiled the tag into _jsx("articlecard", {}). At runtime, React passed this string literal directly to document.createElement("articlecard") The browser instantiated a generic, unstyled HTMLUnknownElement and appended it to the DOM. Your component function articleCard() sat completely forgotten in JavaScript memory.

When the browser encounters an unknown tag in markup, it does not throw an exception. The HTML specification dictates that unrecognized tag names instantiate a generic HTMLUnknownElement DOM node. The JSX compiler converted <articleCard /> into a string literal request for "articlecard". React instructed the browser to create that unknown element directly. Your function articleCard() remained idle in JavaScript memory, completely untouched by React's rendering pipeline.

⚡ IN THE WILD

Why do lowercase custom tags fail silently in the browser?

When the browser parser encounters an unrecognized HTML tag name, it never throws a syntax error. Under the W3C HTML living standard, browsers instantiate an HTMLUnknownElement DOM node with default inline layout styles. The JSX compiler branches on tag identifier casing. Lowercase identifiers compile into string literals for document.createElement(). Uppercase identifiers compile into direct function references. The browser allows unknown HTML tags for backwards compatibility, rendering the element completely invisible with zero console warnings.

What is a React Component and How Does JSX Compile Markup?

A React component is the foundational building block of modern web applications. At its core, a component is a standard JavaScript function that returns a description of a user interface written in JSX. Unlike monolithic HTML files where markup, style, and scripts live in separate silos, a React component unifies structure and presentation into an isolated, reusable unit. When you declare ArticleCard(), you are defining a reusable blueprint for a slice of the page. Every time React evaluates this component, it executes the function to calculate what elements should appear on the screen.

In standard JavaScript runtimes, JSX markup is not valid language grammar. Browsers cannot parse tags like <ArticleCard /> natively. Before your code reaches the browser, a compiler like Babel or SWC parses your source code into an Abstract Syntax Tree (AST). When the parser encounters an opening angle bracket, it inspects the very first character of the tag name. If the character is lowercase, the compiler treats the tag as a built-in DOM element, emitting _jsx("article"). If the character begins with an uppercase letter, the compiler emits an unquoted function identifier: _jsx(ArticleCard).

React models every component as a pure mathematical projection: UI = f(data). A component function must behave as a pure calculation that returns UI descriptors without modifying outside state. When React calls your component, it expects the function to evaluate its inputs and return JSX markup or null. If a component tries to manipulate the DOM imperatively inside its body, it breaks React's ability to coordinate screen updates across renders.

To coordinate updates safely, React splits execution into two distinct stages: the Render Phase and the Commit Phase. In the render phase, React executes your component function in memory to produce a lightweight JavaScript object called a UI descriptor. React attaches this descriptor to an internal Fiber node. This Fiber node tracks component position, lifecycle, and scheduled updates. Only during the subsequent commit phase does React touch the real browser DOM, inserting or updating living HTML elements. Calling a component function directly as {ArticleCard()} bypasses fiber creation, breaking React's ability to manage the component in memory.

Principles of React: Component Anatomy and Invocation

When preparing for senior engineering interviews, candidates must explain why React enforces strict capitalization, purity, and return contracts for components. To master this architecture, we formalize the four governing principles of component anatomy and invocation:

Treat component functions as pure calculations that produce identical UI descriptors for identical inputs. Rendering code must never mutate external variables, alter outside objects, or perform imperative DOM updates. PRINCIPLE 3

Fulfill the Pure Return Contract and Use Null to Explicitly Suppress Output

return contract the requirement that a component return a valid element descriptor or null

Every component function must return a valid React element, Fragment, or null. Forgetting a return statement causes the function to evaluate to undefined, triggering a fatal development crash. To intentionally render nothing on screen, explicitly return null so React paints an empty slot cleanly.

The component retains its registered position in the hierarchy without emitting unnecessary elements. When props update later—such as changing isPublished to true—React re-evaluates the component and mounts the article card seamlessly, without ever throwing undefined runtime errors.

Glossary

  • Component: A self-contained, reusable JavaScript function whose name starts with an uppercase letter and returns a tree of UI descriptors written in JSX.
  • PascalCase: A naming convention where the first letter of each compound word is capitalized, used by the JSX compiler to distinguish custom component functions from native HTML elements.
  • UI Descriptor: A lightweight JavaScript object produced by the JSX transpiler that describes what elements, attributes, and children should appear on the screen.
  • Fiber Node: An internal React data structure that represents a component instance in memory, tracking its lifecycle, hooks, and position in the virtual DOM tree.
  • Render Phase: The initial computational phase of React's execution where component functions are evaluated in memory to produce UI descriptor trees without modifying the living browser DOM.
