Lecture 3: Component Anatomy and the Capitalization Rule

Interview Question

CORE

What is a React component, and what rules govern how you write and name one?

Imagine this scenario:

  1. Leo writes a new editorial card for the morning edition of The National Times.
  2. He builds a JavaScript function to display the article headline, summary, and journalist profile.
  3. Leo names the function articleCard and mounts it in the layout as an articleCard tag.
  4. Why does the browser screen remain completely blank with zero errors in the console?
  5. Editors see no published story, while the terminal reports a successful build.
  6. The compiler treated the lowercase tag as an unknown native HTML element.
  7. Today, you will master component anatomy and the strict capitalization rule that powers React.

Lowercase Tags and Silent Disappearances

In standard HTML, web browsers recognize dozens of built-in tags like <article>, <header>, and <p>. These tags are defined by web standards. When a browser parses a lowercase tag name, it creates a native DOM element in memory. If the tag name is unknown, the browser still creates an empty HTML element. It does not throw an error. It simply paints nothing on the screen.

When Leo writes a function named articleCard and places <articleCard /> in his JSX, he expects React to run his code.

Look at the naive lowercase attempt below:

Naive Lowercase Tag

2 return (<article><h2>Breaking News</h2></article>);
3}
4
5export default function App() {
6 return (<articleCard />);
WRONG: compiles to native string, bypassing FUNCTION
7}

When App runs, the browser displays a blank space. Notice the problem: the function articleCard is never executed. The terminal reports a successful build, and the browser console stays clean.

The JSX compiler does not inspect your JavaScript scope to see if a function exists. Instead, it inspects the first letter of the tag name. If the tag begins with a lowercase letter, the compiler emits a string literal: _jsx("articlecard"). React receives this string and calls document.createElement("articlecard"). The browser creates an empty native DOM node. Your custom function articleCard() is completely ignored.

⚡ IN THE WILD

Why does a lowercase component fail silently? The JSX compiler follows a strict syntactic rule. When the tag starts with a lowercase letter, the transpiler generates _jsx("tagname"). The browser treats this as an unknown custom element. It creates an empty HTML element without styling or content. The terminal reports a successful build because the syntax is valid JavaScript. The browser console stays empty because unknown HTML tags are permitted by the HTML specification. To tell the compiler that your tag represents a JavaScript function, you must capitalize the first letter: <ArticleCard />.

Interview Tip

To impress the interviewer: When asked why React requires PascalCase for components, explain the compiler mechanism. JSX is transpiled into function calls like _jsx(). The transpiler uses the first letter to decide whether to pass a string literal ("div") or a direct function identifier (ArticleCard). Lowercase tags always become strings, bypassing your component function entirely.

Principles of React: The Core Laws of Component Anatomy and Invocation

To prepare for any technical interview, we must separate theory from application and establish the five fundamental laws governing how React identifies, instantiates, and executes component functions. In React, a component is not an HTML tag—it is a pure JavaScript function that returns user interface descriptors. We formalize these rules into five standalone principles.

PRINCIPLE 1

Always Capitalize Component Names Using PascalCase

You must name every React component using PascalCase (starting with an uppercase letter), so the compiler routes the tag to your custom JavaScript function rather than a native HTML element string.

We should do this:
<ArticleCard />
Transpiles to _jsx(ArticleCard, {})
We should not do this:
<articleCard />
Transpiles to _jsx('articlecard', {})

In senior technical interviews, explaining why React requires PascalCase requires dissecting the compiler's Abstract Syntax Tree (AST) tag name evaluation:

  1. The Lowercase Tag Pathway (Native HTML String Literal): If the tag begins with a lowercase character (/^[a-z]/), the JSX compiler assumes it represents a built-in browser host element. It emits a string literal: _jsx("articlecard", {}). At runtime, React passes this raw string to document.createElement("articlecard"). Because "articlecard" is not a standard HTML element, the browser instantiates an empty HTMLUnknownElement, ignoring your JavaScript function completely and painting a blank node.
  2. The Uppercase Tag Pathway (Component Function Identifier): If the tag begins with an uppercase character (/^[A-Z]/) or contains a dot (Article.Card), the JSX compiler treats it as an in-scope JavaScript variable. It emits the variable identifier directly: _jsx(ArticleCard, {}). At runtime, React receives a direct function reference, invokes ArticleCard(props) in memory, and mounts its rendered tree.

PRINCIPLE 2

Invoke Components Declaratively with JSX Tags Rather Than Function Parentheses

You must invoke components declaratively using JSX tags (<ArticleCard />), never calling the component function directly with parentheses (ArticleCard()).

It is best practice to do this:
<ArticleCard headline="News" />
Preserves component boundary and hooks
Instead of doing this:
{ArticleCard({ headline: 'News' })}
Bypasses React lifecycle and DevTools tree

To understand why calling a component with parentheses breaks your architecture in production, senior engineers analyze three runtime consequences:

  1. Fiber Node Boundary and Lifecycle: Writing <ArticleCard /> instructs React to create a dedicated Fiber node in the virtual DOM tree. React controls when to mount, reconcile, re-render, or unmount this instance independently. Calling ArticleCard() directly bypasses Fiber creation: it immediately executes the function during the parent's render phase and splices the returned JSX into the parent's children.
  2. React Hooks State Allocation: React tracks hooks (such as useState and useEffect) by associating an internal linked list of hook records with the currently rendering Fiber node. Calling ArticleCard() directly inside a parent component binds ArticleCard's internal hooks to the parent's Fiber. If conditional branches alter when ArticleCard() is called, the parent's hook order is corrupted, throwing the notorious Rendered fewer hooks than expected runtime error.
  3. DevTools Hierarchy and Profiling: React DevTools inspects the Fiber tree. A declarative tag <ArticleCard /> appears as an inspectable component node displaying its own props, state, and render timings. Calling {ArticleCard()} erases the component from DevTools entirely, flattening its elements into the parent and making debugging and performance profiling impossible.
Principle 2: Declarative JSX Tag vs Direct Function Call
1export default function App() {
WRONG: Direct function call flattens elements and breaks component hooks
2 return (<main>{ArticleCard({ headline: 'News' })}</main>);
3}

RIGHT: Declarative JSX tag creates independent component boundary

7}
PRINCIPLE 3

Always Return Valid JSX Markup or Null from Component Functions

You must ensure every component return statement evaluates to valid JSX markup or null, never returning undefined (which halts React rendering).

We should do this:
return (<div>Story</div>);
Valid JSX node rendered to UI
We should not do this:
return;
Implicit undefined return throws runtime error

In technical interviews, this return contract is evaluated across three distinct evaluation results:

  1. Valid React Nodes (Elements, Primitives, and Portals): A component may return a JSX element (<article />), a React Fragment (<>...</>), a string ("Breaking News"), a number (42), or an array of elements. React reconciles each of these types into corresponding DOM nodes or text nodes.
  2. The Intentional Zero-Node Render (null): Returning null is the official, intentional mechanism for conditional rendering when a component should display nothing. React keeps the component cleanly mounted in the Fiber tree, retains its hook state, and renders zero DOM nodes.
  3. The Unintentional Crash (undefined): In JavaScript, a function without an explicit return statement or with a bare return; automatically evaluates to undefined. In React, returning undefined is treated as a developer bug (such as forgetting a return statement inside a conditional guard). React throws an immediate fatal error: Nothing was returned from render. An unhandled error occurred inside your component.

PRINCIPLE 4

Keep Component Rendering Pure with Zero Side Effects

pure calculations code that produces the same output for identical inputs without mutating outside state

You must author component functions as pure calculations of incoming props, never modifying external variables or querying DOM nodes during render.

We should do this:
return (<h2>{headline}</h2>);
Pure calculation from incoming prop
We should not do this:
window.articleCount++; return (<h2>{headline}</h2>);
Side effect in render causes rendering bugs

Senior React interviews evaluate purity through three mathematical and architectural guarantees:

  1. Mathematical Projection (UI = f(props)): A pure component function is an idempotent calculation. Given identical props, it must return the exact same JSX tree every single time it executes, without depending on external mutable state or time-sensitive calculations (such as Date.now() or Math.random()).
  2. Zero Side Effects in the Render Phase: A side effect is any operation that modifies state outside the current function execution: mutating a global variable, modifying an incoming prop, updating the DOM manually, writing to localStorage, or firing network requests. Executing side effects during render violates React's concurrency model, where renders can be aborted, restarted, or paused by the scheduler. Side effects belong exclusively inside event handlers or lifecycle hooks like useEffect.
  3. The StrictMode Double-Render Verification: In development mode under React.StrictMode, React intentionally executes component functions twice for every state or prop change. If a component mutates an external counter (globalCount++) during render, the counter increments by two instead of one. This deliberate double-render acts as an automated audit that immediately exposes impure functions.

4 return (<span>Rendered {globalRenderCount} times</span>);

7function ArticleCount({ count }) {

PRINCIPLE 5

Parameterize Component Content Through Props to Guarantee Reusability

You should pass all variable data into components through props, rather than hardcoding values or reading global variables inside the function body.

It is best practice to do this:
function Card({ title }) { return (<h3>{title}</h3>); }
Reusable component renders any story
Instead of doing this:
function Card() { return (<h3>Breaking News</h3>); }
Hardcoded text destroys component reuse

In enterprise software architecture, parameterizing components via props establishes two fundamental boundaries:

  1. The Component as a Reusable UI Blueprint: A component function should define structural layout, styling rules, and semantic markup, while remaining completely agnostic of specific content. Hardcoding values like "Breaking News" couples the function to a single instance. Passing title as a prop turns the component into an adaptable template that can render thousands of unique news items across the application.
  2. Isolation from Global State Drift: When a component reads global variables or window properties directly inside its body, it introduces hidden dependencies that make the component impossible to test in isolation, unpredictable in concurrent rendering, and brittle to refactor. Explicit props make all incoming data dependencies visible at the call site, guaranteeing predictable, testable, and reusable interface components.

Component Summary

App

The parent component serves as the top-level application shell. It imports ArticleCard and mounts it declaratively using an uppercase JSX tag. Notice it never calls ArticleCard() imperatively with parentheses. Why? To allow React to register the component in its render tree and manage its lifecycle.

ArticleCard

The child component encapsulates the editorial card markup. It is declared as a pure function using PascalCase capitalization. Notice it returns semantic HTML tags without mutating outside variables. When does it run? React executes the function during render, committing its <article> tree to the browser DOM.

In our experiment, we saw how a lowercase tag caused a silent blank screen. The JSX transpiler uses the first letter of every tag to choose between a string literal and a function identifier. By adopting PascalCase and declarative JSX tags, we allow React to construct a managed component tree.

  2. News Publication Feeds: Building modular article widgets like ArticleTeaser, JournalistProfile, and NewsAlert that compose into clean editorial layouts.

Glossary

  • Component: A pure JavaScript function that accepts inputs and returns a tree of JSX element descriptors representing user interface markup.
  • PascalCase: A naming convention where the first letter of every word is capitalized (ArticleCard), required by React compilers to identify custom components.
  • JSX AST Routing: The compiler mechanism where lowercase tags become string literals ("div") and capitalized tags become direct function identifiers (ArticleCard).
  • Declarative Invocation: Mounting a component using JSX tag syntax (<ArticleCard />), allowing React to control function execution and lifecycle management.
  • Component Purity: The architectural contract that a component function must calculate its output without mutating external variables or causing side effects during render.

Beyond the basics

  • JSX compiler transform specification: Modern React uses the react/jsx-runtime automatic transform, where <ArticleCard /> compiles to _jsx(ArticleCard, {}) and <article /> compiles to _jsx("article", {}) (see react.dev/learn/your-first-component).
  • Component purity and idempotent rendering: React expects component functions to be pure calculations; given the same inputs, they must always return the exact same JSX without modifying preexisting variables outside their scope (see react.dev/learn/keeping-components-pure).
  • The render tree and component instances: When you declare <ArticleCard /> in JSX, React creates an in-memory element descriptor; it does not instantiate a persistent object until it reconciles the render tree (see react.dev/learn/understanding-your-ui-as-a-tree).
  • Automatic Semicolon Insertion (ASI) in return statements: JavaScript automatically inserts a semicolon after a bare return keyword if followed by a line break, returning undefined unless wrapped in parentheses (see react.dev/learn/writing-markup-with-jsx).
  • Custom HTML elements vs React components: While HTML Web Components use hyphenated lowercase names (<article-card>), React components require PascalCase (<ArticleCard>) to compile into direct function references (see react.dev/learn/your-first-component).
