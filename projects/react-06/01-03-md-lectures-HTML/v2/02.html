Lecture 2: Component Anatomy and the Capitalization Rule

Interview Question

CORE

What is a React component, and what rules govern how you write and name one?

Imagine this scenario:

  1. Marcus writes a new editorial card for the morning edition of The National Times.
  2. He builds a JavaScript function to display the article headline, summary, and author byline.
  3. Marcus names the function articleCard and mounts it in the layout as an articleCard tag.
  4. Why does the browser screen remain completely blank with zero errors in the console?
  5. Editors see no published story, while the terminal reports a successful build.
  6. The compiler treated the lowercase tag as an unknown native HTML element.
  7. Today, you will master component anatomy and the strict capitalization rule that powers React.

Lowercase Tags and Silent Disappearances

In standard HTML, web browsers recognize dozens of built-in tags like <article>, <header>, and <p>. These tags are defined by web standards. When a browser parses a lowercase tag name, it creates a native DOM element in memory. If the tag name is unknown, the browser still creates an empty HTML element. It does not throw an error. It simply paints nothing on the screen.

When Marcus writes a function named articleCard and places <articleCard /> in his JSX, he expects React to run his code.

Look at the naive lowercase attempt below:

Naive Lowercase Tag
1function articleCard() {
2 return (<article><h2>Breaking News</h2></article>);
3}
4
5export default function App() {
6 return (<articleCard />);
WRONG: compiles to native string, bypassing FUNCTION
7}

When App runs, the browser displays a blank space. Notice the problem: the function articleCard is never executed. The terminal reports a successful build, and the browser console stays clean.

The JSX compiler does not inspect your JavaScript scope to see if a function exists. Instead, it inspects the first letter of the tag name. If the tag begins with a lowercase letter, the compiler emits a string literal: _jsx("articlecard"). React receives this string and calls document.createElement("articlecard"). The browser creates an empty native DOM node. Your custom function articleCard() is completely ignored.

⚡ IN THE WILD

Why does a lowercase component fail silently? The JSX compiler follows a strict syntactic rule. When the tag starts with a lowercase letter, the transpiler generates _jsx("tagname"). The browser treats this as an unknown custom element. It creates an empty HTML element without styling or content. The terminal reports a successful build because the syntax is valid JavaScript. The browser console stays empty because unknown HTML tags are permitted by the HTML specification. To tell the compiler that your tag represents a JavaScript function, you must capitalize the first letter: <ArticleCard />.

Interview Tip

To impress the interviewer: When asked why React requires PascalCase for components, explain the compiler mechanism. JSX is transpiled into function calls like _jsx(). The transpiler uses the first letter to decide whether to pass a string literal ("div") or a direct function identifier (ArticleCard). Lowercase tags always become strings, bypassing your component function entirely.

Principles of React: The Core Laws of Component Anatomy and Invocation

To prepare for any technical interview, we must separate theory from application and establish the five fundamental laws governing how React identifies, instantiates, and executes component functions. In React, a component is not an HTML tag; it is a pure JavaScript function that returns user interface descriptors. We formalize these rules into five standalone principles.

PRINCIPLE 1

Always Capitalize Component Names Using PascalCase

You must name every React component using PascalCase (starting with an uppercase letter), so the compiler routes the tag to your custom JavaScript function rather than a native HTML element string.

We should do this:
<ArticleCard />
Transpiles to _jsx(ArticleCard, {})
We should not do this:
<articleCard />
Transpiles to _jsx('articlecard', {})

In senior technical interviews, explaining why React requires PascalCase requires dissecting the compiler's Abstract Syntax Tree (AST) tag name evaluation:

  1. The Lowercase Tag Pathway (Native HTML String Literal): If the tag begins with a lowercase character (/^[a-z]/), the JSX compiler assumes it represents a built-in browser host element. It emits a string literal: _jsx("articlecard", {}). At runtime, React passes this raw string to document.createElement("articlecard"). Because "articlecard" is not a standard HTML element, the browser instantiates an empty HTMLUnknownElement, ignoring your JavaScript function completely and painting a blank node.
  2. The Uppercase Tag Pathway (Component Function Identifier): If the tag begins with an uppercase character (/^[A-Z]/) or contains a dot (Article.Card), the JSX compiler treats it as an in-scope JavaScript variable. It emits the variable identifier directly: _jsx(ArticleCard, {}). At runtime, React receives a direct function reference, invokes ArticleCard(props) in memory, and mounts its rendered tree.

PRINCIPLE 2

Invoke Components Declaratively with JSX Tags Rather Than Function Parentheses

You must invoke components declaratively using JSX tags (<ArticleCard />), never calling the component function directly with parentheses (ArticleCard()).

It is best practice to do this:
<ArticleCard />
Preserves component boundary and hooks
Instead of doing this:
{ArticleCard()}
Bypasses React lifecycle and DevTools tree

To understand why calling a component with parentheses breaks your architecture in production, senior engineers analyze three runtime consequences:

  1. Fiber Node Boundary and Lifecycle: Writing <ArticleCard /> instructs React to create a dedicated Fiber node in the virtual DOM tree. React controls when to mount, reconcile, re-render, or unmount this instance independently. Calling ArticleCard() directly bypasses Fiber creation: it immediately executes the function during the parent's render phase and splices the returned JSX into the parent's children.
  2. React Hooks State Allocation: React tracks hooks by associating an internal linked list of hook records with the currently rendering Fiber node. Calling ArticleCard() directly inside a parent component binds ArticleCard's internal hooks to the parent's Fiber, risking hook order corruption and runtime crashes.
  3. DevTools Hierarchy and Profiling: React DevTools inspects the Fiber tree. A declarative tag <ArticleCard /> appears as an inspectable component node displaying its own props, state, and render timings. Calling {ArticleCard()} erases the component from DevTools entirely, flattening its elements into the parent.
Principle 2: Declarative Tag vs Function Call

WRONG: Direct function call flattens tree and breaks hooks
2 return (<main>{ArticleCard()}</main>);
3}
4
5export default function App() {
RIGHT: Declarative JSX tag creates independent boundary
6 return (<main><ArticleCard /></main>);
7}
PRINCIPLE 3

Always Return Valid JSX Markup or Null from Component Functions

You must ensure every component return statement evaluates to valid JSX markup or null, never returning undefined (which halts React rendering).

We should do this:
return (<div>Story</div>);
Valid JSX node rendered to UI
We should not do this:
return;
Implicit undefined return throws runtime error

In technical interviews, this return contract is evaluated across three distinct evaluation results:

  1. Valid React Nodes (Elements, Primitives, and Portals): A component may return a JSX element (<article />), a React Fragment (<>...</>), a string ("Breaking News"), a number (42), or an array of elements. React reconciles each of these types into corresponding DOM nodes or text nodes.
  2. The Intentional Zero-Node Render (null): Returning null is the official, intentional mechanism for conditional rendering when a component should display nothing. React keeps the component cleanly mounted in the Fiber tree, retains its hook state, and renders zero DOM nodes.
  3. The Unintentional Crash (undefined): In JavaScript, a function without an explicit return statement or with a bare return; automatically evaluates to undefined. In React, returning undefined is treated as a developer bug (such as forgetting a return statement inside a conditional guard). React throws an immediate fatal error.

PRINCIPLE 4

Keep Component Rendering Pure with Zero Side Effects

pure calculations code that produces the same output for identical inputs without mutating outside state

You must author component functions as pure calculations, never modifying external variables or querying DOM nodes during render.

We should do this:
return (<h2>Headline</h2>);
Pure calculation produces deterministic UI
We should not do this:
window.articleCount++; return (<h2>Headline</h2>);
Side effect in render causes rendering bugs

Senior React interviews evaluate purity through three mathematical and architectural guarantees:

  1. Mathematical Projection (UI = f(data)): A pure component function is an idempotent calculation. Given identical data, it must return the exact same JSX tree every single time it executes, without depending on external mutable state or time-sensitive calculations (such as Date.now() or Math.random()).
  2. Zero Side Effects in the Render Phase: A side effect is any operation that modifies state outside the current function execution: mutating a global variable, updating the DOM manually, writing to localStorage, or firing network requests. Executing side effects during render violates React's concurrency model, where renders can be aborted, restarted, or paused by the scheduler.
  3. The StrictMode Double-Render Verification: In development mode under React.StrictMode, React intentionally executes component functions twice for every render. If a component mutates an external counter (globalCount++) during render, the counter increments by two instead of one. This deliberate double-render acts as an automated audit that immediately exposes impure functions.

PRINCIPLE 5

Declare Component Functions at Top-Level Module Scope, Never Nested Inside Other Components

You must always define component functions at the top-level scope of a module, strictly avoiding nesting component declarations inside the body of another component.

We should do this:
function Byline() { return (<span>Byline</span>); } function Card() { return (<Byline />); }
Top-level definition preserves identity across renders
We should not do this:
function Card() { function Byline() { return (<span>Byline</span>); } return (<Byline />); }
Nested declaration recreates component type on every render

In software architecture, understanding why nesting component definitions is catastrophic requires analyzing how React tracks component identity:

  1. Function Reference Identity and Remounting: When a component is declared inside another component's body, JavaScript creates a brand-new function object on every render pass of the parent. Because React compares component types by function reference (prevType === nextType), React sees a completely different component type. It destroys the previous DOM subtree, runs unmount cleanup, and remounts from scratch.
  2. State and Focus Destruction: Remounting on every render wipes all local state held by the child, causes active input focus to vanish, cancels CSS transitions, and severely degrades rendering performance. Defining components at top-level module scope guarantees a stable function reference across all renders.

Component Summary

App

The application shell mounts the editorial card inside the top-level layout. Notice it invokes the child using declarative JSX syntax <ArticleCard /> rather than a function call ArticleCard(). Why? To ensure React registers a dedicated Fiber node boundary in the virtual DOM tree.

ArticleCard

The editorial card component wraps newsroom copy in semantic markup. Notice its name starts with a capital letter ArticleCard. Why? To instruct the JSX compiler to treat the tag as a custom function reference rather than an unknown HTML tag string.

EditorialByline

The byline metadata component is declared at the top-level module scope. Notice it is never nested inside ArticleCard. Why? To maintain a stable function identity across renders, preventing costly remounting and lost state.

In standard JavaScript, functions are invoked imperatively with parentheses. React transforms this model: you write functions whose names start with a capital letter, and you invoke them declaratively as JSX elements. React manages the underlying execution, registers boundaries in memory, and keeps your interface pure and predictable.

Where you will meet this

  1. Design System Component Libraries: Writing foundational UI primitives like Button, Modal, and TextInput with strict PascalCase names and top-level module exports.
  2. Multi-Column Editorial Dashboards: Composing complex newspaper layouts by assembling independent, self-contained card and header components.

Glossary

  • Component: A pure JavaScript function that accepts inputs and returns a description of user interface markup as React elements.
  • PascalCase: A naming convention where the first letter of each compound word is capitalized (for example, ArticleCard), required by React to differentiate custom components from native HTML elements.
  • Fiber Node: An internal data structure created by React representing a unit of work and a component instance in the virtual DOM tree.
  • Declarative Invocation: Rendering a component by writing its tag name in JSX (<ArticleCard />), leaving React to manage instantiation and lifecycle.
  • Component Identity: The mechanism by which React determines whether two rendered elements represent the same component instance, based on function reference equality and tree position.

Beyond the basics

  • AST tag name transpilation: Modern JSX transforms compile uppercase tags into jsx(Component, props) while lowercase tags compile to jsx("tag", props). This decision is made purely at parse time by inspecting character casing (see react.dev/learn/your-first-component).
  • Why calling components as functions breaks hooks: Hooks rely on React's internal current Fiber dispatcher. Calling a component imperatively (MyComponent()) executes it within the caller's Fiber context, causing hook order mismatches when conditional branches change (see react.dev/reference/rules/rules-of-hooks).
  • Top-level declaration and remount prevention: Declaring a component inside another component re-creates the function on every render pass. Because prevType !== nextType, React completely destroys and remounts the child subtree (see react.dev/learn/preserving-and-resetting-state).
