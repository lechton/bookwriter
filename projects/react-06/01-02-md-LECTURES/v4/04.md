### The Literal Text Trap and Broken Image Paths

Think back to how you render data in traditional browser scripts. In plain JavaScript, you declare a variable holding an article headline: `const headline = "Transit Accord Reached"`. In classic templating languages, you might expect the template engine to look up that variable automatically. When developers transition to React, they often assume JSX reads variables the same way. You sit at your keyboard, type the variable name between HTML tags, and expect React to find it.

On The National Times, Clara Foster sits down to format a breaking transit dispatch card. Clara opens `DispatchCard.jsx` and declares local variables: the story headline and the author's avatar URL. Then, Clara writes the component markup:

`return (
  <article className="dispatch-card">
    <h2>headline</h2>
    <img src="avatarUrl" alt="Author photo" />
  </article>
);`

Clara saves the file and switches to the browser.

Instead of displaying the transit headline, the screen prints the literal word "headline". Beneath it, the author photo shows an empty broken-image icon. The browser network console reports an immediate failure:

`GET http://localhost:5173/avatarUrl 404 (Not Found)`

The browser treated `"avatarUrl"` as a literal URL string path rather than reading Clara's JavaScript variable from memory.

```jsx title="Naive Literal JSX"
function DispatchCard() {
  const headline = "Transit Union Approves Contract";
  const avatarUrl = "/photos/reporters/clara.jpg"; // Holds image file **PATH**
  return (
    <article className="dispatch-card">
      <h2>headline</h2> // **WRONG:** prints text instead of **VARIABLE**
      <img src="avatarUrl" /> // **WRONG:** requests path **AVATARURL**
    </article>
  );
}
```

Why did this happen? In JSX, text written between tags is treated as static character content. The JSX compiler does not scan text nodes for matching JavaScript identifiers. It simply passes the characters straight through to the browser DOM.

To fix an urgent news alert on the same card, Clara tries another common developer impulse. Clara writes a standard JavaScript `if` statement directly inside the markup:

```jsx title="Naive Statement in JSX"
function DispatchCard() {
  const isUrgent = true; // Tracks urgent story **STATUS**
  return (
    <span className="badge">
      {if (isUrgent) { "URGENT" }} // **WRONG:** statement crashes **PARSER**
    </span>
  );
}
```

The moment Clara saves the file, the local dev server halts compilation. The browser displays a red error overlay:

`SyntaxError: Unexpected token 'if'`

The compiler rejected the code instantly. Why does JSX permit variables inside curly braces but crash on an `if` statement?

> [!WILD]
> **Why does an attribute quote break variable lookup?**
>
> In HTML, quotes around attributes are standard syntax for strings. In JSX, however, double quotes strictly instruct the compiler to create a static string literal. When you write `src="avatarUrl"`, React tells the browser to fetch the relative path `/avatarUrl` from your web server. The server cannot find a file named `avatarUrl`, returning a 404 error. To read a variable from memory, you must remove the quotes and enclose the variable in curly braces: `src={avatarUrl}`.

### The Evaluation Window: Bridging Markup and JavaScript Execution

To understand dynamic data, we must recognize two alternating modes. JSX switches between markup mode and JavaScript mode. When the compiler parses a JSX element, it begins in markup mode. In markup mode, every character between tags is treated as literal text.

To step out of static markup and run live JavaScript, React provides an **evaluation window** marked by curly braces (`{}`). When the compiler encounters an opening curly brace `{`, it temporarily exits markup mode. It evaluates the JavaScript code sitting inside before returning to markup mode at the closing brace `}`.

The most critical rule of the JSX evaluation window is the divide between **expressions** and **statements**. In ECMAScript grammar, an **expression** is any unit of code that resolves to a single discrete value in memory. Numbers (`4 + 2`), variables (`headline`), template literals (`` `${readTime} min` ``), ternary conditions (`isUrgent ? "URGENT" : "STANDARD"`), and function calls (`formatDate()`) are all expressions.

A **statement**, by contrast, controls execution flow without producing a value. Statements like `if`, `for`, `while`, and `switch` perform actions, but they evaluate to nothing. JSX compiles directly into JavaScript function calls (`_jsx()`). Every item inside curly braces must produce a passing value. Placing an `if` statement inside curly braces fails. JavaScript function arguments cannot accept control-flow statements.

Once an expression evaluates, React consults its **primitive render matrix** to determine what appears on screen:

1. **Strings and Numbers**: Strings (`"Transit"`) and numbers (`42`) render directly into visible browser DOM text nodes.
2. **Booleans**: The values `true` and `false` are treated as invisible values and emit zero DOM nodes.
3. **Null and Undefined**: The primitives `null` and `undefined` are also treated as invisible and render nothing to the screen.

This behavior allows developers to write conditional expressions without printing unwanted words like "false" or "null" onto the screen.

### Principles of React: JavaScript Expressions and JSX Evaluation

In technical interviews, senior candidates must articulate the compiler grammar that separates JSX evaluation windows from plain template strings. To master this architecture, we formalize the five governing principles of JavaScript expressions in JSX:

> [!PRINCIPLE]
> **Principle 1: Step Out of Static Markup Using Curly Braces as an Evaluation Window**
> We put curly braces `{}` around variables when we want to step out of plain HTML text (**static markup**). The **curly braces** open a window where React can read live values from JavaScript memory.
> 
> >> curly braces : punctuation markers ({}) that open an inline JavaScript evaluation window inside JSX
> >> static markup : raw HTML text nodes that display character strings literally on screen
> 
> *We should do this:*
> `// Evaluating variable in curly braces`
> `<h2>{headline}</h2>`
> 
> *We should not do this:*
> `// Rendering variable as static text`
> `<h2>headline</h2>`

A React component executes as standard JavaScript. When the compiler encounters an HTML tag, it treats all enclosed content as raw text. Writing `<h2>headline</h2>` instructs the compiler to emit `_jsx("h2", { children: "headline" })`. The browser paints the literal characters. Placing curly braces around the variable switches the parser to expression evaluation. The compiler emits `_jsx("h2", { children: headline })`. This passes the unquoted variable to runtime memory. The browser paints the actual article title.

> [!PRINCIPLE]
> **Principle 2: Pass Only Value-Producing Expressions Inside Curly Braces**
> We only put code that calculates a direct value inside curly braces (**JavaScript expressions that resolve to a value**). We cannot put blocks like `if` or `for` inside curly braces (**control-flow statements**) because they do not produce a value.
> 
> >> JavaScript expressions that resolve to a value : units of code that calculate a result you can pass as an argument
> >> control-flow statements : imperative blocks like if, for, or while that execute actions without evaluating to a value
> 
> *We should do this:*
> `// Passing value-producing expression`
> `<span className="badge">`
> `  {isUrgent ? 'URGENT' : 'STANDARD'}`
> `</span>`
> 
> *We should not do this:*
> `// Passing control-flow statement`
> `<span className="badge">`
> `  {if (isUrgent) { 'URGENT' }}`
> `</span>`

In JavaScript, every function call requires arguments that evaluate to values. Under the hood, JSX compiles tags into `_jsx(type, props)` function calls. Child content compiles into the `children` property: `_jsx("span", { children: [expression] })`. Placing an `if` statement causes the compiler to emit `_jsx("span", { children: if (...) })`. In ECMAScript grammar, placing a statement inside an argument list is illegal. Ternary expressions (`condition ? a : b`) resolve to single values. This makes them valid everywhere expressions are accepted.

> [!PRINCIPLE]
> **Principle 3: Drop String Quotes to Bind Dynamic Attributes**
> We connect dynamic data to attributes using curly braces without any quotation marks (**naked curly braces**). If we add quotes around the braces, React will treat our variable as plain text instead of reading the live data (**dynamic attribute values**).
> 
> >> naked curly braces : curly braces placed directly after the equals sign without enclosing quotation marks
> >> dynamic attribute values : element properties that read variable values from JavaScript memory at runtime
> 
> *We should do this:*
> `// Binding variable in naked curlies`
> `<img src={avatarUrl} alt="Reporter" />`
> 
> *We should not do this:*
> `// Quoting variable as string literal`
> `<img src="avatarUrl" alt="Reporter" />`

In JSX attributes, quotes and curly braces are mutually exclusive. Double quotes (`src="..."`) signal a static string literal. Writing `src="avatarUrl"` assigns the literal string `"avatarUrl"` to the DOM element. Writing `src="{avatarUrl}"` assigns the literal nine-character string `"{avatarUrl}"`. To pass a live variable, omit the quotes entirely and write `src={avatarUrl}`. The compiler transforms this into `_jsx("img", { src: avatarUrl, alt: "Reporter" })`. React reads the string stored in memory. The browser image loader receives the valid file path.

> [!PRINCIPLE]
> **Principle 4: Respect React's Primitive Render Matrix for Booleans, Null, and Undefined**
> We rely on React's built-in rules for primitive types (**primitive render matrix**). React displays text and numbers on the screen, but it leaves booleans, `null`, and `undefined` completely hidden (**invisible**).
> 
> >> primitive render matrix : the engine lookup table governing how raw JavaScript data types paint to the DOM
> >> invisible : evaluating cleanly in code while emitting zero characters or nodes to the browser document
> 
> *It is best practice to do this:*
> `// Rendering primitive number directly`
> `<p>Read time: {readTime} min</p>`
> 
> *Instead of doing this:*
> `// Wrapping primitive in String() call`
> `<p>Read time: {String(readTime)} min</p>`

In JavaScript, primitives behave differently when cast to strings. When React resolves child expressions, it checks runtime types. Numbers (`42`) and strings (`"Transit"`) compile into visible DOM text nodes. However, booleans (`true`, `false`), `null`, and `undefined` are empty render slots. React renders nothing for these primitives. This behavior is essential for conditional rendering. Writing `{isUrgent && <span className="alert">LIVE</span>}` evaluates to `false` when not urgent. Because `false` renders nothing, the badge disappears cleanly. The page avoids extra DOM nodes and raw text.

> [!PRINCIPLE]
> **Principle 5: Double Curlicues Represent Object Literals Inside the Evaluation Window**
> We write style objects using two sets of curly braces like `style={{ color: 'red' }}` (**double curly braces**). The outer braces open the JavaScript window in JSX, while the inner braces create a normal JavaScript object (**object literal**).
> 
> >> double curly braces : an outer evaluation brace enclosing an inner JavaScript object literal ({ { ... } })
> >> object literal : a comma-separated list of key-value pairs wrapped in curly braces in JavaScript memory
> 
> *We should do this:*
> `// Passing object literal in curlies`
> `<div style={{`
> `  padding: 16,`
> `  backgroundColor: '#f1f5f9'`
> `}} />`
> 
> *We should not do this:*
> `// Omitting inner object curlies`
> `<div style={`
> `  padding: 16,`
> `  backgroundColor: '#f1f5f9'`
> `} />`

Junior developers often find double curly braces confusing in inline styles: `style={{ width: 100 }}`. React does not have a special double-brace operator. The outer curly brace `{` opens the JSX evaluation window. The inner curly brace `{ width: 100 }` is a standard JavaScript object literal. If you omit the inner braces, the parser evaluates `padding: 16` as a labeled statement. That triggers a fatal syntax crash. Recognizing that `{{}}` is an object literal inside an evaluation window demystifies the syntax.

| **SYNTAX CONSTRUCT**<br>(JavaScript code unit) | **GRAMMAR TYPE**<br>(ECMAScript classification) | **VALID IN JSX CURLIES?**<br>(compiler acceptance) | **RUNTIME CONSEQUENCE**<br>(compiler & DOM behavior) |
| :--- | :--- | :--- | :--- |
| `headline`<br>`readTime` | Variable identifier<br>(Expression) | Valid<br>`<h2>{headline}</h2>` | Evaluates variable value in memory; paints string or number to DOM |
| `readTime * 2`<br>`count + 1` | Mathematical operation<br>(Expression) | Valid<br>`<span>{readTime * 2}</span>` | Calculates arithmetic result; emits single numeric value to text node |
| `` `${readTime} min` `` | Template literal<br>(Expression) | Valid<br>`<p>{`${readTime} min`}</p>` | Evaluates string interpolation; emits unified string to text node |
| `isUrgent ? 'A' : 'B'` | Ternary conditional<br>(Expression) | Valid<br>`<span>{isUrgent ? 'A' : 'B'}</span>` | Resolves condition; returns single branch value to component props |
| `if (isUrgent) { ... }` | Control-flow block<br>(Statement) | Invalid<br>(Compiler Crash) | Produces no value; triggers `SyntaxError: Unexpected token 'if'` |
| `for (let i = 0...)` | Iteration block<br>(Statement) | Invalid<br>(Compiler Crash) | Executes side effects without value; rejected by compiler argument parser |

To see how these principles operate under the hood, examine the transpiled JavaScript output emitted by the compiler. When build tools transform JSX, every expression inside curly braces becomes an argument in a standard `_jsx()` call:

```js title="Transpiled Expression Output"
import { jsx as _jsx, jsxs as _jsxs } from 'react/jsx-runtime'; // Imports runtime **FUNCTIONS**
const output = _jsxs("article", { // Evaluates root article **CONTAINER**
  className: "dispatch-card",
  children: [
    _jsx("h2", { children: headline }), // Passes variable as child **VALUE**
    _jsx("img", { src: avatarUrl }), // Assigns variable to src **PROPERTY**
    _jsxs("p", { children: [readTime, " min"] }) // Evaluates static and dynamic **CHILDREN**
  ]
});
```

> [!TIP]
> **To impress the interviewer:** Avoid saying "React doesn't support if statements." The authoritative answer is rooted in **ECMAScript argument grammar**. JSX compiles into JavaScript function calls (`_jsx()`). In JavaScript, function arguments must be expressions evaluating to a value. An `if` block is a control-flow statement producing no value. This makes it illegal as a function argument. Use value-producing expressions like ternary operators (`condition ? a : b`) instead.

### Step 1: First, we construct the news dispatch card with inline expressions <DispatchCard.jsx>

In Step 1, we build the presentation card component `DispatchCard.jsx`. On The National Times, breaking dispatches require live data. They display a headline, reporter photo, and reading time. In traditional templates, developers had to concatenate strings or perform manual DOM selections. In React, we declare local variables in the component body. We cleanly project them into markup using curly braces. Here we reach a foundational architectural crossroad when binding attributes:

When passing values to JSX attributes, developers choose between two syntax approaches:
- **Option 1 (The Foundational Way: Static String Attribute)**: Wrap the attribute value in double quotes (`src="avatarUrl"`), treating the value as a literal string.
- **Option 2 (The Modern Idiomatic Way: Dynamic Expression Window)**: Supply the attribute value in naked curly braces (`src={avatarUrl}`), evaluating the variable reference in memory.

First, examine Option 1 with a static string attribute:

```jsx title="Option 1: The Foundational Way (src='avatarUrl')"
export default function DispatchCard() {
  const avatarUrl = "/photos/clara.jpg"; // Local avatar **PATH**
  return (
    <article className="dispatch-card">
      <img src="avatarUrl" /> // **WRONG:** requests path **AVATARURL**
    </article>
  );
}
```

In Option 1, wrapping `"avatarUrl"` in double quotes tells the JSX compiler to emit a static string primitive. When the browser renders the `<img>` tag, its network engine requests the literal endpoint `http://localhost:5173/avatarUrl`. The file does not exist on disk, resulting in a 404 network failure and a broken image icon on the front page.

Next, examine Option 2 using the modern idiomatic dynamic expression window:

```jsx title="Option 2: The Modern Idiomatic Way (src={avatarUrl})"
export default function DispatchCard() {
  const avatarUrl = "/photos/clara.jpg"; // Local reporter photo **PATH**
  return (
    <article className="dispatch-card">
      <img src={avatarUrl} /> // Binds dynamic image source from **MEMORY**
    </article>
  );
}
```

In Option 2, writing `src={avatarUrl}` omits the quotation marks and opens an evaluation window. The compiler reads the identifier `avatarUrl` from local scope and assigns the string `"/photos/clara.jpg"` directly to the DOM node's `src` property. The browser fetches the reporter's photograph seamlessly.

Now, examine the first half of `DispatchCard.jsx`, establishing local variables and evaluating the headline and urgency badge:

```jsx title="DispatchCard.jsx" startLine="1" continues="bottom"
export default function DispatchCard() {
  const headline = "Transit Union Approves Contract"; // Story headline **STRING**
  const reporter = "Clara Foster"; // Reporter byline **NAME**
  const avatarUrl = "/photos/clara.jpg"; // Reporter photo endpoint **URL**
  const isUrgent = true; // Breaking dispatch urgency **FLAG**
  return (
    <article className="dispatch-card">
      <span className="badge">{isUrgent ? "URGENT" : "STANDARD"}</span> // Evaluates conditional ternary **BADGE**
      <h2 className="headline">{headline}</h2> // Projects headline variable into **HEADING**
```

Notice how `{isUrgent ? "URGENT" : "STANDARD"}` evaluates a ternary expression directly inside the badge. When `isUrgent` is `true`, it resolves to the string `"URGENT"`. Directly beneath, `{headline}` reads the article title from memory.

Next, examine the conclusion of `DispatchCard.jsx`, binding the dynamic image attribute and calculating reading duration:

```jsx title="DispatchCard.jsx" startLine="10" continues="top"
      <div className="meta">
        <img src={avatarUrl} alt={reporter} /> // Binds dynamic image and alt **PROPERTIES**
        <span>{reporter} • 4 min</span> // Interpolates reporter name and duration **TEXT**
      </div>
    </article>
  );
}
```

The component concludes by passing `avatarUrl` into `src` using naked curly braces. React passes the image URL directly into the DOM element property, rendering the portrait without network errors.

### Step 2: Finally, we mount the dispatch card into the page container <App.jsx>

In Step 2, we complete the practical example by mounting `DispatchCard` inside the top-level application container `App.jsx`. The root component establishes the newsroom page shell using `<main className="page-shell">` and an application masthead header `<h1>`. By mounting `<DispatchCard />` declaratively inside `App`, we keep the page container lean and focused on layout, while `DispatchCard` cleanly encapsulates its local variables and dynamic evaluation logic.

```jsx title="App.jsx"
import DispatchCard from './components/DispatchCard.jsx'; // Imports dispatch card **COMPONENT**
export default function App() {
  return (
    <main className="page-shell">
      <h1>The National Times</h1> // Renders newsroom layout **MASTHEAD**
      <DispatchCard /> // Mounts evaluated dispatch presentation **CARD**
    </main>
  );
}
```

By separating `DispatchCard` from `App`, we maintain a clean architectural boundary. `App` manages the top-level semantic structure of the document, while `DispatchCard` manages its internal dynamic expressions.

### Where you will meet this

1. **Dynamic Content Cards and Editorial Feeds**: Online news portals like The National Times project headlines, reporter names, publication dates, and category tags directly into article cards using curly braces, eliminating manual string assembly.
2. **Media Players and Image Galleries**: Binding dynamic media URLs to `src`, `poster`, and `href` attributes requires naked curly braces (`src={videoUrl}`) to prevent the browser from requesting literal placeholder strings.
3. **Calculated Metrics and Live Analytics**: Dashboards evaluate mathematical expressions directly inside JSX (such as `{activeReaders * 100 / totalSubscribers}%`) to compute and display formatted metrics in real time without intermediate state variables.

### Glossary

- **Evaluation Window**: An inline JavaScript portal established by curly braces (`{}`) inside JSX that steps out of static markup to evaluate live expressions.
- **JavaScript Expression**: Any unit of code that evaluates to a single discrete value in memory (such as variables, math, ternary operations, and function calls).
- **Control-Flow Statement**: Imperative JavaScript language constructs (like `if`, `for`, or `while`) that execute actions without returning a value, strictly forbidden inside JSX curly braces.
- **Dynamic JSX Attribute**: An HTML-like element property bound to a live JavaScript expression using naked curly braces without quotes (`src={avatarUrl}`).
- **Primitive Render Matrix**: React's internal type-resolution rules that paint numbers and strings to the DOM while rendering booleans, `null`, and `undefined` as invisible empty output.
- **Double Curlicues**: The syntax pattern `{{ ... }}` used in JSX where an outer evaluation window encloses an inner JavaScript object literal.

### Summary

**JavaScript Expressions in JSX Decision Matrix**

❒ Text and Variable Interpolation

➔ ALWAYS enclose JavaScript variables in curly braces (`<h2>{headline}</h2>`) to project evaluated runtime values into the rendered DOM.

➔ NEVER write bare variable names inside tag children (`<h2>headline</h2>`), which causes the browser to display literal placeholder text.

❒ Dynamic Attribute Binding

➔ ALWAYS use naked curly braces without quotes (`src={avatarUrl}`) when binding dynamic variables to HTML attributes.

➔ NEVER enclose curly braces in quotation marks (`src="{avatarUrl}"`), which instructs the compiler to treat the expression as a literal string.

❒ Expressions vs Statements

➔ ALWAYS use value-producing expressions (such as ternary operators `{isUrgent ? 'A' : 'B'}`) inside curly braces.

➔ NEVER place control-flow statements (`if`, `for`, `while`) inside JSX curly braces, which triggers fatal compiler syntax crashes.

**DO THIS:** Evaluate expressions with curly braces and bind naked attributes

```jsx right

    <article className="dispatch-card">
      <h2>{headline}</h2>

}
```

**DO NOT DO THIS:** Write literal variable names or quote dynamic attribute curlicues
