Lessons from the Code
The Component Anatomy & Capitalization Challenge

An architectural comparison evaluating component naming, compiler AST emission, and declarative invocation.

Component Layer Naive Expectation (Lowercase Tag / Function Call) What Happened (PascalCase Declarative Tag)
1. The Declaration (Naming Convention) Lowercase Function Name Declaring function articleCard() causes the JSX parser to treat <articleCard /> as an unknown native HTML element, leaving the function unexecuted. PascalCase Capitalization Declaring function ArticleCard() explicitly signals a custom React component, allowing JSX to recognize it as a callable JavaScript function in memory.
2. The Compiler AST (Parser Transformation) Quoted String Literal Lowercase tags compile to string literals: _jsx("articlecard", {}). The browser passes the string to document.createElement, producing an empty tag. Function Identifier Reference Uppercase tags compile to identifiers: _jsx(ArticleCard, {}). React receives the unquoted function reference and executes it to evaluate the UI.
3. The Invocation (Mounting Strategy) Direct Function Execution Calling {ArticleCard()} executes immediately during parent render, stripping component boundaries and flattening markup into the parent layout. Declarative JSX Element Writing <ArticleCard /> creates an independent React descriptor node, preserving component tree identity and allowing React to govern reconciliation.
Final Verdict Silent Blank Failure The browser generates an empty DOM element with zero error messages, leaving editorial content completely invisible. Predictable Component Tree The component renders semantic article markup reliably, preserving independent component boundaries and clean layout composition.
