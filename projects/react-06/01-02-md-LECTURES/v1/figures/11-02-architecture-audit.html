Lessons from the Code
The Breaking News Feed Challenge

An architectural comparison evaluating how React reconciles dynamically rendered lists during insertions, prepends, and reordering.

Component Layer Naive Expectation (Positional Index Keys) What Happened (Stable Entity Keys)
1. The Container (Parent Feed) Positional Slot Matching Developers map arrays using key={index}. When an item is prepended at index 0, every index shifts by one, forcing React to mutate every downstream DOM node in the list. Entity Identity Mapping React binds each item to a permanent database ID via key={story.id}. Prepending an item at index 0 inserts one new DOM node at the top while leaving all existing nodes completely untouched.
2. The List Entry (Story Item) In-Place Node Recycling React mutates existing DOM attributes in place. Child state and uncontrolled text inputs do not move, remaining attached to the old physical slot. Structural Node Repositioning React physically moves the DOM node in the tree without remounting or mutating its internal contents, preserving focus and node integrity.
3. The Terminal UI Control (Story Note) Desynchronized Input State User notes and checkboxes desynchronize from their headlines because the native <input> element was reused for a completely different article. Permanent State Affinity The native <input> element retains its typed text and focus because its host component maintained continuous identity via story.id.
Final Verdict Corrupted DOM State Prepending items scrambles inputs, checkboxes, and media players across unrelated records. Preserved Node Identity List items retain their local DOM state, focus, and component identity across all reorders.
