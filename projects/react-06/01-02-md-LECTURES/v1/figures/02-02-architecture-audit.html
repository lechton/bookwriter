Lessons from the Code
Build Tools vs Full-Stack Frameworks

An architectural comparison evaluating project scaffolding, execution runtimes, and deployment models across modern React applications.

Architecture Layer Naive Expectation (CRA / Monolithic Bundle) What Happened (Vite Native ESM & Static SPA)
1. Scaffolding CLI (npm create vite) Opaque Monolith Setup Install react-scripts with hidden Webpack configs, locking dependencies behind rigid unconfigurable abstractions. Lean Starter Generator Scaffolds minimal project files directly onto disk with clean scripts and transparent dependencies under developer control.
2. Build Config (vite.config.js) Complex Ejection Barrier Modifying build rules requires permanent, irreversible npm run eject, exposing 1,000 lines of fragile Webpack boilerplate. Declarative Plugin Pipeline A 5-line configuration file supplying @vitejs/plugin-react to handle fast JSX compilation via esbuild and Rolldown.
3. Entry Bridge (index.html & main.jsx) Hidden Script Injection HTML sits in /public as a background template; bundler magically injects generated bundle scripts at runtime. Native ESM Root Entry index.html sits at root declaring <script type="module" src="/src/main.jsx">, letting the browser drive module requests.
4. Root Component (src/App.jsx) Server Runtime Mandate Assume all modern React requires Node.js servers, hydration overhead, and edge runtimes even for private internal dashboards. Pure Client-Side Mounting React renders purely in the browser DOM via createRoot; static production bundles deploy to low-cost CDN storage.
Final Verdict Heavy Server Overhead Forcing full-stack frameworks on internal SPAs introduces unnecessary server maintenance, cold starts, and hosting bills. Lean Static Distribution Standalone build tools serve lightning-fast local development and deliver resilient static assets anywhere on the globe.
