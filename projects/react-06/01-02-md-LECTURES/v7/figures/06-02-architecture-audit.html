Architecture Audit: Hardcoded Duplication vs Pure Read-Only Props

Deconstructing parameter passing, fallback defaults, and the immutability guarantee across component layers

TIER & SCOPE Component Layer NAIVE APPROACH Duplication & Mutation Hardcoded cards & direct assignment REACT 19 ARCHITECTURE Read-Only Prop Flow Destructuring, defaults & derivations
Feed Container <ArticleFeed.jsx> Copies and pastes three identical cards with hardcoded text, or passes redundant props like count alongside an array that easily drift out of sync. Reuses a single component by passing differing values as attributes; React bundles them into one props object at each call site.
Card Presentation <ArticleCard.jsx> Omits destructuring braces so the whole object binds to one name, crashing when rendered; mutates props directly with uppercase assignments. Unpacks properties using parameter destructuring, provides fallback defaults for optional values, and calculates uppercase text pure in render.
Root Coordinator <App.jsx> Passes shared objects across siblings and relies on legacy propTypes or defaultProps that React 19 silently ignores on function components. Acts as the single source of truth; distributes data top-down and ensures child components never corrupt shared objects.
Runtime Engine Immutability Contract Assumes props can be modified in place or relies on shallow development freezing to prevent silent data corruption in production. Props are strictly read-only; React freezes props shallowly in development to enforce pure function contracts, while the child derives new values.
Verdict Contract Integrity Fragile Mutation & Drift Hardcoded card clones, fatal object-as-child crashes, silent nested object corruption, and desynchronized state drift. Pure Read-Only Flow Clean component reuse, predictable unidirectional data flow, resilient fallback defaults, and protected pure rendering.
