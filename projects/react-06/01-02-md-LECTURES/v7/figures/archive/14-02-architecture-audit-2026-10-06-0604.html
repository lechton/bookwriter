COMPONENT MEMORY & INSTANCE ISOLATION WITH USESTATE
Contrasting ephemeral function variables against persistent React state memory across component instances.
Component Layer Architecture Naive Expectation Ephemeral Variable Disappears on Render React Reality useState Memory Retained Across Renders
Reading Desk Root
src/App.jsx
Container 		Assumes multiple cards share a global variable or require parent synchronization to maintain counts. Renders independent <StoryCard /> instances. Each card manages its own state without leaking data to siblings or parent.
Interactive Card
StoryCard.jsx
Memory Boundary 		Assumes reassigning a local variable (likes = likes + 1) directly updates the button on screen. Local variables discard changes and reset on render. Calling the setter function stores the next value in React and triggers a re-render.
Instance Isolation
StoryCard.jsx
Call Order 		Assumes calling useState(0) resets the counter back to zero every time the component function executes. React reads the argument once on initial render. On subsequent renders, React returns the stored value by matching the Hook's call order.
Architectural Verdict Fragile
Local assignments fail to trigger renders, and function scope resets variables back to zero on every execution. 		Resilient
useState provides private, isolated component memory that persists across renders and drives declarative screen updates.
