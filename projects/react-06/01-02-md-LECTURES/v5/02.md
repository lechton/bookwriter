### The Silent Blank Screen of Lowercase Tags

Think back to how you write functions in standard JavaScript. You write `function calculateTotal()` or `function formatDate()`. You instinctively use camelCase, starting the function name with a lowercase letter. When junior developers build their first React component, they naturally follow that familiar muscle memory.

On The National Times, Julian sits down to build an article presentation card for Leo Smith's morning column. The card needs to display a headline and a short editorial summary. Julian opens a new file, declares `function articleCard()`, and writes semantic HTML markup inside. Then, Julian mounts `<articleCard />` inside the application layout and refreshes the browser.

When Julian opens the browser, the screen is completely blank. The Vite terminal shows no build error, and the browser DevTools console prints zero warnings. Julian opens the Elements panel in DevTools to inspect the DOM tree. The browser created a literal `<articlecard></articlecard>` node with zero contents inside. The JavaScript function was never executed, its return statement was never reached, and the editorial markup never made it to the screen.

```jsx title="Naive Lowercase Component"
function articleCard() {
  return (
    <article className="news-card">
      <h2>Preserving the Historic District</h2> // Renders story **HEADLINE**
      <p>City council approves zoning.</p> // Renders summary **COPY**
    </article>
  ); // **WRONG:** lowercase name causes compiler to treat tag as native **STRING**
}
```

Why did the browser create an empty tag instead of calling the function? The answer lies in how the JSX compiler parses markup. The compiler inspects the first character of every tag name to determine its compilation pathway. If the first character is lowercase, the parser classifies the tag as a built-in browser DOM element. It emits a quoted string literal: `_jsx("articlecard", {})`.

When React runs in the browser, it takes that string literal and calls the native browser method `document.createElement("articlecard")`. The HTML specification permits arbitrary custom tag names without throwing errors. The browser creates an unknown HTML element in the DOM tree. Because no HTML tag named `articlecard` exists in the living web standard, the element has no default styling and zero contents. The JavaScript function `articleCard` sits in memory untouched.

> [!WILD]
> **Why do lowercase custom tags fail silently in browsers?** In the early web, browser makers agreed that HTML must never crash when encountering unknown tags. If an author wrote `<custom-box>`, the browser created a generic `HTMLUnknownElement` and continued parsing. The JSX compiler relies on this exact platform rule. When JSX sees `<articleCard />`, it treats it as an unknown native HTML element and emits a string literal. React creates the empty DOM node and continues without warning. To signal that a tag represents a JavaScript function in memory, you must capitalize the first letter.

### What is a React Component?

In plain JavaScript, functions process data, perform calculations, or run procedural commands. In React, a **component** is a pure JavaScript function with a single dedicated purpose: it accepts inputs and returns a description of what should appear on the screen.

You do not write imperative commands telling the browser how to construct DOM nodes. You do not call `document.createElement()` or attach children with `appendChild()`. Instead, you write a component function that returns JSX markup describing the desired visual structure. React executes your function, inspects the returned markup tree, and handles the low-level browser operations required to paint those pixels.

Every React component must fulfill a strict **return contract**: it must return a valid React element, a Fragment, or `null`. If a component returns `undefined` or omits its return statement, React halts execution and throws an error in development: "Nothing was returned from render." A component operates as a pure projection of its inputs: given the same data, it returns the exact same user interface descriptor.

When you mount a component in JSX using `<ArticleCard />`, you are not calling `ArticleCard()` directly. You are creating a lightweight **UI descriptor** in memory. You are declaring to React: "This section of the page belongs to the `ArticleCard` component." React registers the component in its internal tree, schedules its evaluation, and invokes the function when appropriate.

### Principles of React: Component Anatomy and Execution

In senior engineering interviews, candidates are routinely asked to explain the rules governing React components and how the JSX compiler distinguishes custom functions from native browser tags. To master this architecture, we formalize the three governing principles of component anatomy:

> [!PRINCIPLE]
> **Principle 1: Capitalize Component Names to Trigger Function Invocation**
> React component names must start with a capital letter in PascalCase. The JSX compiler uses capitalization as a zero-cost discriminator: lowercase tags compile into string literals for native HTML elements, while capitalized tags compile into unquoted function identifiers in memory.
> 
> >> function identifier : an unquoted reference to a JavaScript function in memory
> 
> *We should do this:*
> `// PascalCase emits function reference`
> `function ArticleCard() {`
> `  return (`
> `    <article className="card">`
> `      <h2>Morning Dispatch</h2>`
> `    </article>`
> `  );`
> `}`
> 
> *We should not do this:*
> `// lowercase emits string literal`
> `function articleCard() {`
> `  return (`
> `    <article className="card">`
> `      <h2>Morning Dispatch</h2>`
> `    </article>`
> `  );`
> `}`
When you name a component, the JSX compiler inspects the very first letter of the tag to decide how to generate its Abstract Syntax Tree (AST). If the tag begins with a lowercase letter (`<articleCard />`), the compiler assumes it is a built-in browser element. It emits a string literal: `_jsx("articlecard", {})`. At runtime, React passes this string directly to `document.createElement("articlecard")`.

Because `"articlecard"` is not a standard HTML element, the browser instantiates an empty `HTMLUnknownElement`. Under the HTML specification, unknown tags are completely legal, so the browser logs zero console warnings and the compiler reports a successful build. The screen simply renders a blank node, and your custom JavaScript function is completely ignored.

Capitalizing the first letter (`<ArticleCard />`) changes the compiler's entire pathway. The uppercase letter instructs the compiler to emit an unquoted variable identifier: `_jsx(ArticleCard, {})`. React receives a live pointer to your function in memory, executes `ArticleCard()`, and commits your returned markup to the browser DOM.

> [!TIP]
> **To impress the interviewer:** When asked why React requires PascalCase, explain that JSX is not HTML; it is a syntactic transformation into standard JavaScript. In JavaScript, there is no way for a compiler to know at parse time whether `articleCard` refers to a function in your file or a future HTML standard element. Rather than requiring developers to register components through a runtime API, React uses capitalization as a zero-cost compiler convention. Uppercase emits variable identifiers; lowercase emits string literals.

> [!PRINCIPLE]
> **Principle 2: Return Declarative UI Descriptors Rather Than Mutating the DOM**
> React component functions must return a valid UI descriptor (JSX elements, fragments, or null) describing the intended markup. Components never manipulate the DOM directly during render, ensuring execution remains pure, predictable, and testable.
> 
> >> UI descriptor : a lightweight JavaScript object tree describing the desired DOM structure
> 
> *It is best practice to do this:*
> `// Returning a declarative UI descriptor`
> `function NewsSnippet({ text }) {`
> `  return (`
> `    <p className="summary">{text}</p>`
> `  );`
> `}`
> 
> *Instead of doing this:*
> `// Mutating DOM nodes inside component`
> `function NewsSnippet({ text }) {`
> `  document.body.append(text);`
> `  return null;`
> `}`
In plain JavaScript, functions frequently achieve their purpose through side effects—appending nodes to `document.body`, setting cookies, or modifying outside variables. It can be tempting to reach for `document.body.append()` inside a component when you want to inject content quickly.

In React, a component function must behave as a pure mathematical calculation: given the same inputs, it must return the exact same UI descriptor every single time. React splits its work into two distinct phases: the **render phase**, where component functions execute to produce lightweight descriptor objects in memory, and the **commit phase**, where React applies DOM changes to the screen.

React's rendering engine reserves the right to pause, abort, or restart a component's render phase to keep the browser responsive. If your component mutates the real DOM or modifies outside variables while rendering, those side effects execute behind React's back. To help developers detect these bugs early, development mode runs under `React.StrictMode`, which intentionally invokes every component function twice. If a component performs side effects during render, those mutations trigger twice, immediately exposing the bug before it reaches production.

> [!PRINCIPLE]
> **Principle 3: Invoke Components Declaratively via JSX Tags Rather Than Direct Calls**
> Components must be mounted using declarative JSX tags like `<ArticleCard />` rather than called directly as JavaScript functions. Mounting via JSX preserves the component's unique identity in React's element tree, enabling independent lifecycle management, memoization, and hook state.
> 
> >> element tree identity : React registering a component as a distinct node in memory with its own lifecycle
> 
> *It is best practice to do this:*
> `// Mounting declarative JSX element`
> `function App() {`
> `  return (`
> `    <main>`
> `      <ArticleCard />`
> `    </main>`
> `  );`
> `}`
> 
> *Instead of doing this:*
> `// Calling component function directly`
> `function App() {`
> `  return (`
> `    <main>`
> `      {ArticleCard()}`
> `    </main>`
> `  );`
> `}`
At first glance, calling `{ArticleCard()}` seems completely harmless. A React component is just a standard JavaScript function, and executing it directly returns markup that paints onto the screen. In a simple static card with no state, you will not see any visual difference between `<ArticleCard />` and `{ArticleCard()}`.

The danger is invisible because JSX tags are not immediate function calls. When you write `<ArticleCard />`, you are handing React a description of what should appear on the screen. Behind the scenes, React creates an internal **Fiber node** for each component. This Fiber node serves as the component's personal record in memory. It tracks where the component lives in the tree, when it needs to re-render, and what data belongs to it.

This personal record is how React manages state. React keeps track of hooks by linking them together in a chain. It then attaches this chain directly to the component's internal Fiber node. Every time the component re-renders, React walks down this chain link by link, retrieving each state variable in the exact same order.

When you call `{ArticleCard()}` directly with parentheses, you bypass this entire system. JavaScript executes the function immediately, dumping its raw HTML tags straight into the parent component. React never creates a Fiber node for `ArticleCard`.

Because `ArticleCard` has no personal record in memory, its hooks have nowhere to go. React ends up attaching them to the parent's hook chain instead. The moment someone adds conditional rendering or changes the order of calls, the parent's chain gets scrambled. State values swap into the wrong variables, or the entire application crashes with a fatal error.

Skipping the Fiber node also breaks your developer tools. React DevTools inspects the tree of Fiber nodes, not your raw JavaScript code. Because `{ArticleCard()}` never registered a Fiber node, `ArticleCard` vanishes from the DevTools tree entirely. You cannot inspect its props, check its state, or profile its rendering speed.

To consolidate these platform mechanics, examine the three approaches side by side:

| **TAG SYNTAX**<br>(developer input) | **COMPILER OUTPUT**<br>(transpiled AST) | **RUNTIME EXECUTION**<br>(React engine) | **BROWSER DOM RESULT**<br>(rendered pixels) |
| :--- | :--- | :--- | :--- |
| `<articleCard />`<br>(lowercase) | `_jsx("articleCard", {})`<br>(string literal) | Bypasses component function;<br>calls `document.createElement` | Empty `<articlecard>` element;<br>blank screen |
| `<ArticleCard />`<br>(PascalCase) | `_jsx(ArticleCard, {})`<br>(function identifier) | React invokes `ArticleCard()`;<br>evaluates returned JSX tree | Semantic `<article>` tree;<br>headline and paragraph rendered |
| `{ArticleCard()}`<br>(direct call) | Plain JS call expression;<br>inlines returned JSX | Bypasses React element tree;<br>strips component node identity | Output inlined into parent;<br>loses independent component boundary |

To see how the JSX compiler transforms these tags into JavaScript, compare the source code against the compiled output:

```js title="Transpiler Output Comparison"
<articleCard />; // (1) Lowercase tag written in source **JSX**
<ArticleCard />; // (2) Capitalized tag written in source **JSX**
_jsx("articleCard", {}); // (3) String literal emitted for browser **DOM**
_jsx(ArticleCard, {}); // (4) Function identifier emitted for React **ENGINE**
```

### Step 1: First, we construct the article card component <ArticleCard.jsx>

We begin by constructing our independent presentation component `ArticleCard.jsx`. Notice the function name: it uses **PascalCase** capitalization (`ArticleCard`). The capitalized first letter instructs the JSX compiler to treat every `<ArticleCard />` tag as a reference to this function.

Inside the function body, we fulfill the pure return contract by returning semantic article markup. The markup contains a self-contained `<article>` container holding an `<h2>` headline and a `<p>` summary. The copy is static text, keeping this component completely focused on its primary responsibility: defining the structural template for an editorial card.

```jsx title="ArticleCard.jsx"
export default function ArticleCard() {
  return (
    <article className="news-card">
      <h2 className="headline">Green Transit Corridor</h2> // Renders article **HEADLINE**
      <p className="summary">Light rail expansion planned.</p> // Renders summary **COPY**
    </article>
  ); // Fulfills pure return **CONTRACT**
}
```

Notice what is absent from this function: zero DOM queries, zero imperative modifications, and zero external side effects. The function is completely pure. Whenever React invokes `ArticleCard`, it evaluates the return expression and produces an immutable UI descriptor representing this card structure.

### Step 2: Finally, we mount the component into the application tree <App.jsx>

Now that `ArticleCard.jsx` is defined, we import it into the root application container `App.jsx` and mount it into the visual layout. When integrating a component function into JSX, you arrive at a foundational architectural crossroad:

- **Option 1 (The Foundational / Imperative Way)**: Call the component directly as a standard JavaScript function: `{ArticleCard()}`.
- **Option 2 (The Modern Idiomatic / Declarative Way)**: Mount the component declaratively using a JSX element tag: `<ArticleCard />`.

First, examine Option 1 with direct function execution:

```jsx title="Option 1: The Foundational Way ({ArticleCard()})"
export default function App() {
  return (
    <main className="page-layout">
      <h1>Morning Edition</h1>
      {ArticleCard()} // **WRONG:** executes immediately, stripping component **IDENTITY**
    </main>
  );
}
```

In Option 1, `{ArticleCard()}` executes immediately as an ordinary JavaScript function during the execution of `App`. React never creates a separate component node for `ArticleCard` in its internal descriptor tree. Its returned markup is inlined directly into `App` as raw child elements. React cannot attach independent lifecycle behavior, cannot optimize re-renders for `ArticleCard`, and will fail if hooks are added later.

Next, examine Option 2 with declarative JSX element mounting:

```jsx title="Option 2: The Modern Idiomatic Way (<ArticleCard />)"
import ArticleCard from './components/ArticleCard.jsx'; // Imports card **COMPONENT**
export default function App() {
  return (
    <main className="page-layout">
      <h1>Morning Edition</h1> // Renders publication **MASTHEAD**
      <ArticleCard /> // Mounts card as declarative **DESCRIPTOR**
    </main>
  );
}
```

In Option 2, writing `<ArticleCard />` does not invoke the function immediately. Instead, it creates a React element descriptor `{ type: ArticleCard, props: {} }`. React registers `ArticleCard` as a distinct child node in the component hierarchy. React decides when to invoke the function, encapsulates its rendering, and preserves its independent identity across updates.

In plain HTML templates, adding an article card required copying markup across files or concatenating HTML strings in JavaScript. In React, `ArticleCard` encapsulates its structure in a single reusable function. Because it follows PascalCase naming and declarative invocation, `App` can render one, two, or ten article cards without duplicating markup, and React manages every instance as an independent node in the visual tree.

### Where you will meet this

1. **Design System Component Libraries**: Every modern design system relies on strict PascalCase naming. Capitalized tags ensure that custom components like `<Button />`, `<Card />`, and `<Dialog />` never collide with native HTML controls like `<button>`, `<dialog>`, or `<div>`.
2. **Editorial Content Layouts**: Digital newsrooms like The National Times organize articles into modular presentation cards, bylines, and media blocks. Writing each section as an independent capitalized component allows editorial desks to compose diverse page layouts effortlessly.
3. **Micro-Frontend Application Portals**: Large web platforms assemble multiple independent features into unified dashboards. Structuring each widget as an encapsulated component guarantees that individual teams can build, test, and maintain their UI blocks without interfering with sibling components.

### Glossary

- **Component**: A pure JavaScript function that accepts inputs and returns a JSX descriptor representing a slice of the user interface.
- **PascalCase Capitalization**: The naming convention where every word in an identifier begins with an uppercase letter (`ArticleCard`), strictly required by the JSX compiler to distinguish custom components from native HTML tags.
- **JSX Transpiler**: The build-time compiler tool (such as Babel, SWC, or esbuild) that transforms JSX tags into standard JavaScript `_jsx()` function calls.
- **Declarative Invocation**: Mounting a component via a JSX element tag (`<ArticleCard />`), instructing React to manage the function's execution and tree identity rather than calling it imperatively.
- **UI Descriptor**: A lightweight JavaScript object returned by a component that describes the desired DOM nodes, attributes, and children for React to construct.

### Summary

**Component Anatomy & Capitalization Decision Matrix**

❒ Component Declaration & Capitalization

➔ ALWAYS name custom component functions using PascalCase capitalization (`ArticleCard`) so the JSX compiler emits function identifiers instead of native HTML string literals.

➔ NEVER name custom component functions with a lowercase first letter (`articleCard`), which causes the browser to render an empty unknown HTML element and fail silently.

❒ Invocation & Tree Identity

➔ ALWAYS invoke components declaratively using JSX tags (`<ArticleCard />`) to preserve independent component identity and allow React to manage the render lifecycle.

➔ NEVER invoke component functions directly as plain JavaScript calls (`{ArticleCard()}`), which strips component boundaries and inlines output into the parent.

**DO THIS:** Name components with PascalCase and mount them declaratively

```jsx right
export default function ArticleCard() {
  return (
    <article className="card">
      <h2>Preserving History</h2>
    </article>
  );
}

function App() {
  return <ArticleCard />;
}
```
