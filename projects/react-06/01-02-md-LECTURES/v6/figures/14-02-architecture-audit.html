Component Memory & State Architecture
The Architecture of Component Memory

Contrasting ephemeral local variables and render-time mutations with persistent React state cells and scheduled re-renders

Dimension Memory Mechanism Anti-Pattern Fragile Local Variables Ephemeral Data & Frozen Screens React Reality useState Memory Persistent Cells & Scheduled Renders
Variable Lifetime Call Stack Memory ✕ Ephemeral Function Scope
Local variables (let likes = 0) are allocated on the JavaScript call stack and discarded the moment the function returns, losing all memory. 		✓ External Fiber State Slot
React maintains state outside the component function in an internal memory record keyed to the component's position in the UI tree.
Visual Updates Engine Notification ✕ Silent In-Memory Mutation
Reassigning likes = likes + 1 modifies local memory without notifying React, leaving the browser screen frozen at its starting text. 		✓ Scheduled Re-Render Queue
Invoking the setter function (setLikes) updates the internal cell and schedules a fresh render pass to update the DOM.
Render Stability Initial Value Handling ✕ Repeated Variable Reset
Every render pass re-executes the function from the top, resetting ordinary local variables back to their initial values. 		✓ One-Time Initial Seeding
The argument in useState(0) seeds the cell once during initial mount; on all future renders, React returns the current stored value.
Instance Scope Component Identity ✕ Module Scope Leakage
Storing counts in module-level variables shares mutable state across all cards, leaking side effects between unrelated stories. 		✓ Isolated Instance Memory
Each rendered <StoryCard /> receives its own distinct state slot, ensuring updates affect only that specific instance.
Execution Timing Update Lifecycle ✕ Unconditional Render Invocation
Calling a setter during render (onClick={setLikes(1)}) triggers an immediate re-render, creating a fatal infinite loop. 		✓ Deferred Event Execution
Wrapping setter calls in event handlers (onClick={() => setLikes(1)}) defers updates until the user interacts.
Verdict Frozen Screens & Infinite Crashes
Relying on local variables leaves interfaces unresponsive, while calling setters during render crashes the application with runaway loops. 		Deterministic State & Pure Renders
Encapsulating state in useState and triggering updates from event handlers guarantees stable, persistent, and isolated component memory.
