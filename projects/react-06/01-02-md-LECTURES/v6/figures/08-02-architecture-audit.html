LESSONS FROM THE CODE
Module Architecture & Component Splitting Audit

Deconstructing the structural trade-offs between monolithic files and modular ES module contracts.

LAYER File / Scope NAIVE APPROACH Monolithic File High Friction REACT 19 STANDARD Dedicated ES Modules Clean Boundaries
<App.jsx> Application Shell ✕ Keep all card components, badges, and formatting helpers inside App.jsx to avoid creating extra files or import statements. ✓ App.jsx imports ArticleCard and Badge from dedicated modules, remaining a lean orchestrator with zero internal card clutter.
<ArticleCard.jsx> Primary Component ✕ Export an anonymous arrow function as default and assume importing files will always use the intended component name. ✓ Exports a named function declaration so React error stacks show <ArticleCard>, while private helpers remain unexported and safe.
<Badge> Named Export Utility ✕ Attempt to import Badge without curly braces or import ArticleCard with braces, assuming bundlers sort it out. ✓ Imports { Badge } with curly braces matching its named export; bundlers verify the contract at build time and reject mismatches.
VERDICT System Impact Fragile Coupling: Monolithic bloat, git merge conflicts, anonymous <default> error stacks, and Linux CI path crashes. Modular Resilience: Clean ES module contracts, build-time export verification, explicit component names, and effortless reuse across pages.
