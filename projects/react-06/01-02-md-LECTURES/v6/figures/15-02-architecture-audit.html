LESSONS FROM THE CODE
How One Like Reaches the Screen

What each part of the story page expected, and what React did in the trigger, the render, and the commit

Component Layer File and Role Naive Expectation The Page by Hand Changed and read on the same line What Happened Trigger, Render, Commit React changes the page after the handler
App.jsx Parent ✕ A click runs the whole app
Every like should run App and StoryTitle again. 		✓ Only the state owner and its children run
A like logs only LikeCounter and LikeLabel.
LikeCounter.jsx By hand ✕ Write the number into the page
textContent = likes + 1 should count up. 		✓ The setter starts the three steps
By hand it shows 1 on every click; setLikes shows 1, 2, 3.
LikeCounter.jsx Handler ✕ Read the new number back
The line after the setter should find 1. 		✓ The page changes after the handler
It sent 0; sending next gives the server 1, then 2.
LikeCounter.jsx Comment box ✕ A new run wipes the comment
Each like should rebuild the <input> and lose the text. 		✓ The commit changes only what differs
The <input> stays the same node, with its text.
LikeLabel.jsx Display ✕ Same output, no run
A label whose output looks the same should not run again. 		✓ It runs, and the commit decides
It runs on every like; the commit changes only its text.
Verdict A page managed by hand
The count sticks at 1, and the server hears every like one click late. 		A page React updates
The setter triggers, React renders the owner and its children, and the commit changes only the count.
