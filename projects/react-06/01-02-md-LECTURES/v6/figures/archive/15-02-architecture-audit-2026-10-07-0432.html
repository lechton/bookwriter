LESSONS FROM THE CODE
One Click, Three Steps

What each part of the story page expected after a click, and what React did in the trigger, the render, and the commit

Component Layer File and Role Naive Expectation Like Plain DOM Code The page changes on the line that asks for it What Happened Trigger, Render, Commit The page changes after the handler, and only where it differs
App.jsx Parent ✕ A like runs the whole page again
A change anywhere should run App and every component in it, as a page reload would. 		✓ Only the counter and its child run
App runs prints once, on the first render; a click prints only the counter's line and LikeLabel runs.
LikeCounter.jsx Click handler ✕ The setter changes the page at once
Reading .like-count after setLikes(likes + 1) sent 0 while the page went on to show 1. 		✓ Compute the number once
const next = likes + 1 goes to the setter and to the report, which sends 1.
LikeCounter.jsx Comment field ✕ A render rebuilds the input
Running the counter again should replace the field and wipe great post. 		✓ The same DOM node stays
The <input> sits in the same place in the JSX, so the commit leaves it and its text alone.
LikeLabel.jsx Child ✕ The text changes by itself
The number should change without the label's code running. 		✓ The child renders, the commit changes one text node
LikeLabel runs on every like, and only the number inside Likes: 1 changes on the page.
Verdict Reports one behind and fear of renders
Reading the page after a setter gets the old value, and avoiding renders protects nothing. 		Three steps the reader can predict
The setter triggers, React renders the counter and its child, and the commit changes only the number.
