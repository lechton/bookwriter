Component Purity & Rendering Laws
The Architecture of Pure Rendering

Contrasting mutable outside state, render-phase side effects, and non-idempotent calls with pure mathematical functions

Dimension Purity Mechanism Anti-Pattern Fragile / Naive Practice Corrupted State & DOM Crashes React Reality Pure Component Architecture Deterministic Formulas
Execution Model Render Contract ✕ Single Execution Assumption
Assuming components execute exactly once; treating double console logs in development as bugs and removing StrictMode. 		✓ On-Demand Pure Calculation
React calls components as needed; StrictMode double-rendering stress-tests purity so calling twice returns identical JSX.
Data Mutation External Variables ✕ Outside Variable Mutation
Incrementing module variables (count++) or pushing into props arrays causes doubled numbers (#2, #4) and duplicate items. 		✓ Unidirectional Downward Props
Pass values as props; compute new arrays using spread syntax ([...items, newItem]) without altering preexisting memory.
DOM Interaction Side Effects in Render ✕ Imperative Document Writes
Querying document.getElementById() to set classes in the body crashes on initial load because DOM nodes do not exist yet. 		✓ Declarative JSX Expressions
Calculate classes and markup directly in JSX with ternary operators; move external side effects into event handlers.
Determinism Idempotent Output ✕ Non-Idempotent Render Calls
Invoking Math.random() or new Date() in the body causes disagreeing values between render passes and freezes clocks. 		✓ Injected Props and State
Generate random values or capture timestamps outside of render and pass them downward as props to guarantee reproducible output.
Local Mutation Fresh Scope ✕ Mutating After Passing to JSX
Modifying a style object after writing <Header styles={styles} /> leaks the modified values into earlier elements. 		✓ Safe Local Array / Object Build
Creating fresh arrays inside render and populating them locally is 100% pure as long as mutation finishes before passing to JSX.
Verdict State Drift & Fragile Lifecycle Crashes
Mutating outside variables or the DOM during render produces desynchronized UI, broken caches, and silent runtime failures. 		Deterministic UI & Safe Concurrency
Treating components as pure mathematical formulas (UI = f(props)) guarantees predictable rendering across development checks and production builds.
