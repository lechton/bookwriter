# Architectural Decision Brief: 2026-10-04-01: Radical Decoupling Standard, Secondary Token Detection Protocol & Anti-Map-Regurgitation

## Executive Summary
This batch eliminates the cognitive exhaustion and narrative quality degradation caused by bundling mechanical code comment audit requirements directly into initial lecture authoring. It establishes the **Radical Decoupling Standard**, dividing production into two clean, independent phases: Phase 1 (Authoring) drafts prose and code with simple, natural trailing comments (`code // comment`) and ZERO tildes, directing 100% of cognitive energy toward pedagogy, narrative flow, and easy-to-read B2 English; Phase 2 (Secondary Post-Edit Audit) loads `code-comment-audit` to execute the 5-step Secondary Token Detection Protocol, locating focal tokens, wrapping them in `~token~`, calibrating line widths, and verifying the 9 algorithmic invariants via `diagnose-lecture.mjs`. In addition, this batch introduces the **Anti-Map-Regurgitation Standard** and provides a dedicated Golden Exemplar for card-free `Kind: Model` principles in `principled-theory`.

## 1. Root Cause Analysis

### 1.1 Cognitive Overload from In-Flight Comment Auditing
In batch `#2026_10_03_04_group_1`, `code-comment-audit` was mistakenly bundled directly into `writing a lecture` and `pre-lecture`. Forcing the language model to simultaneously compute token column offsets, count characters under 80/68 ceilings, avoid 3-consecutive-line stacking, and maintain density invariants drained more than 70% of the model's active context and reasoning capacity during lecture generation.

### 1.2 Regurgitation of Raw Map Drafting Notes
Under heavy cognitive strain, the authoring process defaulted to path-of-least-resistance generation: copying and lightly paraphrasing the raw technical drafting notes from `01-01-map-principles/18.md` directly into the principle definition. This bypassed the Two-Step Translation Protocol, producing stiff, bureaucratic sentences ("inside running code", "calling a setter records the next value and queues the next render", "fixed snapshot provided by React for one render pass") that sounded like internal AI specification notes rather than clear, mentor-led explanations for students.

### 1.3 Missing Golden Exemplar for Kind: Model Principles
While Rule 123 of `principled-theory` explicitly required `Kind: Model` principles to omit comparative breakout cards, all seven existing Golden Exemplars featured breakout cards (`*It is best practice to do this:*` / `*Instead of doing this:*`). Lacking an explicit card-free model exemplar, the generator attempted awkward compromises, including emitting unquoted cards as prose outside the callout container.

## 2. Architectural Decisions & Resolutions

### 2.1 The Radical Decoupling Standard
- **Phase 1: Initial Authoring**: Authors follow `lecture-voice`, `lecture-structure`, and `principled-theory`. Code blocks are written with clean, natural trailing comments (`code // comment`) with ZERO `~token~` tildes. Blueprints and drafting focus 100% on pedagogy, organic vocabulary introductions, tactile physical machine traces, and the 3-Beat Operational Rhythm.
- **Phase 2: Secondary Post-Edit Audit**: Authors invoke `code-comment-audit` as a dedicated secondary pass. The model scans existing comments, identifies the focal token on each line, wraps it in `~token~`, checks line budgets (80 characters in editor fences, 68 in principle cards), and runs `node src/diagnose-lecture.mjs {NN}`.

### 2.2 The 5-Step Secondary Token Detection Protocol
Codified in `code-comment-audit/SKILL.md` Section 01:
1. **Comment Scan & Density Verification**: Scan all titled code fences and principle cards. Check block density (Invariants 4 & 5). Ensure summary blocks are 100% comment-free (Invariant 6). Check spacing for at least 1 line of breathing room (Invariant 7).
2. **Focal Token Identification**: For each line with a trailing comment, locate the specific semantic target being explained (prop, state setter, hook call, callback, parameter, dynamic value, or event handler). Distinguish structural/shell lines from targeted value/action lines.
3. **Token Wrapping & Tilde Parity**: Wrap ONLY the focal token in tildes (`~token~`). For multiline data records, wrap the complete final item (`~{ id: '...', ... }~`). Enforce even tilde count (Invariant 3). Enforce comment on every token line (Invariant 2) and token on every non-shell comment line (Invariant 1).
4. **Line Width & Clearance Calibration**: Check that lines with target tokens and comments do not exceed 80 characters (68 in principle callouts; Invariant 8).
5. **Automated Algorithmic Verification**: Execute `node src/diagnose-lecture.mjs {NN}` to mechanically verify all 9 deterministic invariants.

### 2.3 Anti-Map-Regurgitation Standard
Added to `principled-theory/SKILL.md` Section 04: Explicitly forbids copying, regurgitating, or lightly paraphrasing the raw technical drafting notes from `01-01-map-principles/{nn}.md`. Principles must be freshly reconstructed into natural, conversational B2 English using the 3-Beat Operational Rhythm and canonical nouns with everyday human verbs.

### 2.4 Kind: Model Golden Exemplar
Added to `principled-theory/SKILL.md` Golden Exemplars: A card-free `> [!PRINCIPLE]` callout exemplifying State as a Snapshot, demonstrating how to decompress lifecycle invariants across 3 calm, active sentences without syntax breakout cards.
