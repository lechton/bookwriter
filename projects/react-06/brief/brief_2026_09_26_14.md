# Architectural Decision Brief — 2026-09-26-14: Principle Code Case Indentation Protection and Backticked Line Standard

## Executive Summary
This brief resolves the code formatting and indentation collapse defect in principle comparative cards (`media_1790396265390.png`). Under `#2026_09_26_14_group_1`, we identify the dual root cause—a compiler whitespace stripping bug in `processCaseSnippet` combined with an Exclusionary Fallacy misinterpretation of multiline backtick rules—and implement a robust two-layer fix: (1) fixing the compiler in `src/build-lectures.mjs` to preserve leading indentation unconditionally, and (2) establishing the explicit line-by-line backtick standard with rigid 2-space indentation for all principle comparative cards across `skills/v6.3/code-blocks/SKILL.md`, `skills/v6.3/principled-theory/SKILL.md`, and lecture markdown sources.

## 1. Root Cause Analysis

### 1.1 The Compiler Whitespace Stripping Bug
In `src/build-lectures.mjs`, the principle case parser `processCaseSnippet(lines, label)` processed code lines using:
```javascript
const trimmed = line.trim();
...
codeLines.push(trimmed);
```
When code lines did not contain enclosing backticks (e.g. `>   return (`), `line.trim()` immediately stripped off the two leading spaces of indentation, collapsing `return (`, `<h1>`, and `);` flush left. Even if the markdown author carefully typed 2-space or 4-space nesting, the compiler aggressively destroyed it before emitting `<pre><code>`.

### 1.2 The AI Exclusionary Fallacy (Rule Misapplication)
In `skills/v6.3/code-blocks/SKILL.md`, rule `#2026_09_25_09_group_1` was originally introduced to eliminate shredded inline backticks in prose callout boxes (mandating that multiline snippets in prose use a single opening and closing pair of backticks). However, AI models committed the classic Exclusionary Fallacy: interpreting the prohibition against line-by-line backticks in narrative prose as a blanket ban across ALL markdown surfaces, including principle comparative cards (`> *It is best practice to do this:*`). Stripping the backticks from principle lines then exposed those lines directly to the compiler's `line.trim()` bug, wiping out indentation.

### 1.3 The Two Distinct Markdown Code Card Contexts
To permanently prevent this confusion, we formalize the boundary between the two code snippet contexts:
1. **Narrative Prose & Callout Boxes**: Multiline snippets embedded in narrative prose or callout boxes (`[!NOTE]`, `[!TIP]`) use a single pair of opening and closing backticks around the entire block.
2. **Principle Comparative Cards (`> *It is best practice to do this:*` / `> *Instead of doing this:*`)**: Each code line is individually wrapped in backticks (e.g. ``> `  return (` ``) with rigid 2-space JSX nesting, ensuring crisp syntax highlighting and indentation preservation across every markdown processor, static generator, and Prince PDF layout engine.

## 2. The Solution Architecture (#2026_09_26_14_group_1)

### 2.1 Compiler Indentation Preservation (`src/build-lectures.mjs`)
`processCaseSnippet` was updated so that leading spaces are preserved regardless of whether lines have backticks or are raw indented text:
```javascript
const rawContent = line.replace(/^>\s?/, '');
const match = rawContent.match(/^`([\s\S]*)`$/);
if (match) {
  codeLines.push(match[1]);
} else {
  codeLines.push(rawContent);
}
```
This guarantees that even if a future editor omits backticks, the compiler will never strip leading indentation spaces.

### 2.2 Skill Rules and Exemplar Standardization
1. **`skills/v6.3/code-blocks/SKILL.md` (Section 14B)**: Clarified the exact distinction between narrative prose code blocks (single-pair) and principle comparative cards (line-by-line backticks).
2. **`skills/v6.3/principled-theory/SKILL.md` (Section 04 & Golden Exemplar Bank)**: Added a mandatory checklist item requiring individual line backticks with 2-space indentation, and converted all 5 canonical exemplars (plus Lesson 2 Principle 3 and Lesson 4 Principles 4 and 5) to use line-by-line backticks with explicit 2-space indentation.
