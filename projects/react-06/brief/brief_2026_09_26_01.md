# Decision Brief — 2026-09-26-01: Visceral Action-Paired Principle Code Comments, Symmetrical Comparative Cards, and Anti-Jargon Standard

## Context & Motivation
1. **The Abstract Jargon and Asymmetry Anti-Patterns in Principle Cards**:
   During the authoring and review of Lesson 05 (UI as a Tree and Component Hierarchy), the principle comparative cards exhibited several recurrent failure modes:
   - *Trap 1 (Abstract Academic Jargon and Buzzword Soup)*: Models generated disembodied, noun-heavy comments and subtitles in principle cards, such as `// Horizontal cross-component coupling`, `// Conflating components with DOM nodes`, `// Monolithic entanglement`, and `// Rigid coupling`. These phrases failed to explain which component talks to what or what code mistake is actually being made.
   - *Trap 2 (Asymmetrical and Empty Anti-Pattern Cards)*: Models generated comparative cards where the "best practice" card contained full code, but the "instead of doing this" card contained only an isolated comment (e.g. `// Never mounted in a JSX return!`) with zero illustrative or executable code.
   - *Trap 3 (Card Width Budget Overflow and Formatting Collapse)*: Code lines inside principle cards exceeded the 40-character line width budget (such as `import ArticleCard from './ArticleCard.jsx';` at 44 characters), forcing mid-line wrapping in print or triggering compiler validator warnings.

2. **Root Cause Analysis & Golden Rule of De-Prescription**:
   - In `skills/v6.2/principled-theory/SKILL.md`, the existing reference exemplar in Section 04 literally modeled the bad behavior by using the abstract comment `// Monolithic entanglement` and `// Ticker and Video tangled in one node`.
   - The skill lacked explicit question-based standards defining how comments inside `> [!PRINCIPLE]` callouts should be structured. Models treated the subtitle area as a place to regurgitate textbook theory rather than describing physical developer code actions.
   - Applying the Golden Rule of De-Prescription: rather than adding restrictive prohibitions, we pruned the flawed exemplar and replaced it with clean, verified models drawn directly from shipped Lesson 05 code, establishing the Visceral Action-Pair Standard.

3. **The Proper Solution: Visceral Action Pairs and Symmetrical Code Cards**:
   - **Action-Paired Principle Comments (Active Verb Phrases)**: Comments and subtitles in principle cards must describe the exact physical action the developer is taking with code, paired symmetrically between the idiomatic pattern and the anti-pattern (e.g. `// Composing custom React components` vs `// Dumping raw HTML tags`; `// Passing data downward through props` vs `// Storing data on window to bypass props`; `// Isolating features in branch subtrees` vs `// Blending multiple sections in one node`).
   - **Anti-Jargon Standard**: Strictly ban abstract academic buzzwords (`conflating`, `coupling`, `entanglement`) in code comments that fail to name the physical elements involved.
   - **Symmetrical Code Cards & 40-Character Line Budget**: Both cards must contain real, balanced, indented code snippets illustrating the exact same scenario. Snippets must preserve 2-space JSX nesting, proper newlines, and stay strictly within $\le 40$ characters per line (breaking imports or JSX tags across indented lines if needed).
