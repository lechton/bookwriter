# Architectural Decision Brief: 2026-10-03-03: Comment Pointer Targeting, Data Collection Placement, and Action Line Execution Law

## Executive Summary
This batch updates `skills/v6.4/code-comment-audit/SKILL.md`, `skills/v6.4/code-blocks/SKILL.md`, and `skills/v6.4/RULE-TAGS.md` under tag `#2026_10_03_03_group_1`. It establishes three foundational conventions: (1) concise scannable comments ("Imports child card", "Static article collection", "Logs selected article identifier") serve as vital browsing guides that let readers quickly view what is happening; (2) comment pointer tails must ALWAYS point directly to the newsworthy token wrapped in tildes (`~target~`); (3) comments on multiline data structures belong at the end of the last value to summarize the collection as a whole; and (4) comments on runtime actions (logging, mutations) belong on the actual execution line (`console.log(...)`) rather than outer function signatures.

## 1. Root Cause Analysis

### 1.1 Mispositioned Pointers on Boilerplate Margins
In Lecture 13, comments on `import ArticleCard`, `const articles = [`, and `function handleSelect(id)` lacked target token markers (`~target~`). The compiler fell back to the line indentation offset, causing pointer tails to point directly at language keywords (`import`, `const`, `function`) rather than the subject of the annotation.

### 1.2 Interrupted Data Declarations
Attaching a comment to the opening line of an array or object literal (`const articles = [ // Static article collection`) interrupted the declaration before the student even saw the data values, placing the speech bubble awkwardly above the collection instead of beneath it.

### 1.3 Action Annotations on Wrapper Signatures
Attaching an action comment ("Logs selected article identifier") to a function header (`function handleSelect(id) { // ...`) misattributed the action to the declaration rather than the actual line where execution occurs (`console.log(...)`).

## 2. Resolution

### 2.1 The Newsworthy Target Rule
Every code line carrying a comment must wrap its newsworthy token or phrase in tildes (`~target~`), enabling the compiler to render a dashed underline and compute pixel-accurate `--token-offset` centering the speech bubble pointer tail directly under that subject.

### 2.2 The Data Placement Rule
When annotating a multiline collection (such as mock datasets or configuration objects), the comment is placed on the line of the last value (e.g. `~{ id: 'art-2', title: 'Clean Energy Accord' }~ // Static article collection`), allowing the speech bubble to summarize the complete set of values.

### 2.3 The Action/Execution Placement Rule
When a comment describes a runtime action (such as logging or state updates), the comment attaches to the actual line of execution (`~console.log('Selected article:', id)~; // Logs selected article identifier`), ensuring the pointer tail points directly at the action itself.
