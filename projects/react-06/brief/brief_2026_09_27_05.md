# Architectural Decision Brief — 2026-09-27-05: Probabilistic Pitfall Framing and Empathetic Scenario Standard

## Executive Summary
This batch updates `skills/v6.3/lecture-voice/SKILL.md`, `skills/v6.3/principled-theory/SKILL.md`, `skills/v6.3/pre-lecture/SKILL.md`, and `skills/v6.3/RULE-TAGS.md`, and refactors Lesson 05 (`01-01-md-PRE-lectures/v6/05.md` and `01-02-md-LECTURES/v6/05.md`). It resolves the defect of dogmatically projecting misconceptions and bugs onto students as absolute universal truths (e.g., claiming "a beginner will always do this", "when developers first build layouts, they do X"). It introduces the Probabilistic Pitfall Framing & Empathetic Scenario Standard, mandating probabilistic phrasing ("a junior developer may fall into this trap...", "it is possible that a student of React may assume X because of Y...", "we sometimes see developers encounter this confusion..."), requiring that the intuitive reasoning behind naive impulses be validated before revealing runtime engine reality, and pruning absolute assertions from skill exemplars.

## 1. Root Cause Analysis

### 1.1 The Absolute Error Projection Defect
When explaining why certain programming patterns are flawed or why specific framework rules exist, AI authors frequently slipped into dogmatic, absolute assertions about the reader's cognitive state (e.g., *"When developers first start building multi-section layouts, they view an application as a flat collection of HTML tags"*, *"When beginners look at a JavaScript file with several functions, they assume that declaring variables at the top of the file lets all functions access them"*). This creates an authoritarian, patronizing tone that alienates readers who never made that mistake, while sounding unrealistic and dogmatic.

### 1.2 Exemplar Mimicry in Skill Files
In `skills/v6.3/principled-theory/SKILL.md`, canonical exemplars themselves contained absolute assertions (e.g., line 425 and line 622: *"Developers often assume that React hides all falsy values..."*). In accordance with the Golden Rule of De-Prescription and root-cause pruning, these benchmark exemplars had to be softened so that models reading the skill files would naturally emulate empathetic, probabilistic framing.

## 2. Resolution

### 2.1 Lecture Voice Skill (`skills/v6.3/lecture-voice/SKILL.md`)
Added Section 02's `The Probabilistic Pitfall Framing Standard (Anti-Absolute-Error Projection)` with PROPER and COUNTER examples tagged `#2026_09_27_05_group_1`:
- Prohibits asserting absolute claims about what beginners or developers always do.
- Mandates probabilistic, empathetic scenario phrasing:
  - *"a junior developer may fall into this trap..."*
  - *"it is possible that a student of React may assume X, thinking this because of Y..."*
  - *"we sometimes see developers make this mistake..."*
- Requires validating the intuitive logic behind the naive impulse before demonstrating how the runtime engine behaves.
