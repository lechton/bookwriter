## 1. Motivation and Rationale

### 1.1 The Post-Edit Refactoring Cascade
When code blocks are created without planning comments upfront, authors naturally write dense single-line expressions (such as multi-attribute JSX tags or single-line objects). Adding speech bubble comments during a subsequent post-edit audit frequently pushes lines past the 80-character ceiling. Slicing these lines across multiple rows then risks pushing the block beyond the strict 10-line budget, creating secondary refactoring cascades that destabilize previously written code.

### 1.2 Upfront Invariant Embedding
By embedding the code comment invariants directly into Phase 1 blueprinting (`pre-lecture` Section 13) and Phase 2 lecture authoring (`lecture-structure` Sections 16 & 25):
1. **Load Order Alignment**: When drafting pre-lectures, `code-blocks` is now loaded so that line ceilings, continuation fences, and comment planning govern blueprint snippets from the start. When writing lectures, `code-comment-audit` is loaded so comment placement is validated during initial drafting.
2. **Data Placement Upfront**: Authors format multiline data collections so the final object properties accommodate the comment within the 80-character limit from the beginning.
3. **Target Token Discipline**: Every commented line is authored with `~target~` tokens from inception.
4. **Summary Block Cleanness**: Summary decision blocks (`right`/`wrong`) are kept strictly comment-free from day one.

### 1.3 Algorithmic Diagnostic Verification Gate
To eliminate human/model guesswork and provide instantaneous feedback, `src/diagnose-lecture.mjs` has been enhanced with Section 4:
- Mechanically checks every line with an inline comment (`//`, `<!--`, `#`) in editor code blocks to ensure it contains a target token (`~target~` or `**target**`).
- Mechanically checks every line in principle comparison cards to ensure it stays within the 68-character ceiling and carries target tokens.
- Mechanically verifies that summary comparative blocks (`right`/`wrong`) contain zero comments.
