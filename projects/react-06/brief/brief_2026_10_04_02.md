# Architectural Decision Brief: 2026-10-04-02: Principles of Principles: Teach by Living Example, Paired Role Anchors & Tactile Clarity

## Executive Summary
This batch addresses a fundamental pedagogical flaw in instruction design: the tendency of AI systems to react to prose defects by inventing new negative bans and micro-regulations ("The Reflexive Ban Fallacy"), while treating "Teach by Living Example" as a decorative ritual. It de-prescribes the rigid single-paragraph constraint in `principled-theory/SKILL.md`, authorizes structured, labeled decomposition for paired platform concepts, and establishes intuitive cognitive role anchors (*The Listener* vs *The Trigger*) and tactile markup (`<button>`, `<span>`, `<svg>`). It permanently anchors the doctrine into the Golden Exemplars Bank with the user's gold standard PROPER EXAMPLE and the unedited Lesson 14 COUNTER-EXAMPLE, and records `#2026_10_04_02_group_1` in `skills/v6.4/RULE-TAGS.md`.

## 1. Root Cause Analysis

### 1.1 The Decorative Example Syndrome and Legislative Over-Regulation
When an authoring agent produced a cramped, ungrammatical principle definition in Lesson 14 (*"The event object provides currentTarget for the element owning the handler and target for the innermost node..."*), previous AI proposals attempted to create new micro-laws: an "Anti-Beat-Inversion Law", an "Anti-Echo Law", and a "Balanced Two-Actor Syntax Law". This stacked regulatory red tape without curing the underlying cause. While the meta-checklist praised "Teach by Living Example", the actual skills files contained zero counter-examples of bad principle definitions, leaving the model with no living contrast of its own prose mistakes.

### 1.2 The Single-Paragraph Constraint as a Defect Generator
Rule 104 previously commanded: "Does the principle definition decompress the concept across 2 to 3 calm, active sentences?" By dogmatically enforcing a continuous prose paragraph, the instruction literally forbade visual chunking. When explaining paired platform mechanisms that operate in tandem (such as `currentTarget` vs `target`, `props` vs `state`, or `render` vs `commit`), forcing both concepts into a single running paragraph caused syntactic congestion, detached mental mappings, and hand-waving filler slang (*"preventing broken lookups"*).

## 2. The Solution: Structured Decomposition & Role Anchors

### 2.1 Structured Breathing Room for Paired Concepts
When a principle contrasts two interrelated platform entities, the definition is authorized to decompress using clean, scannable bullet items:
- A brief 1-sentence framing lead-in.
- Item 1 with an intuitive role anchor in parentheses (e.g. `e.currentTarget (The Listener)`).
- Item 2 with an intuitive role anchor in parentheses (e.g. `e.target (The Trigger)`).
- A 2-sentence closing operational scene and developer decision naming the exact runtime failure prevented (e.g. *"so nested clicks never return undefined"*).

### 2.2 Concrete Markup Grounding
Definitions must replace abstract phrases like "innermost node" or "container element" with tactile, living HTML elements that developers touch daily: `<button>`, card container, `<span>`, `<svg>` icon.

### 2.3 Naming the Concrete Runtime Failure
Hand-waving filler slang like "preventing broken lookups" is pruned. Principles must state the exact physical failure prevented (e.g. evaluating `undefined` when reading attributes from nested tags).
