# Architectural Decision Brief — 2026-09-26-20: Count-Last Principle Discovery and Q01-Q10 Blind Rescan

## Executive Summary
This batch removes principle-count anchoring from the discovery workflow. The previous skill correctly said that the count should emerge, but it did not control the order of work: an author could still inspect a numbered map, estimate a tidy total, and then split or merge candidates around that estimate. The revised workflow starts with an unnumbered source-obligation register, creates an unnumbered candidate inventory, assigns every candidate a disposition, applies semantic ownership and atomicity tests, and numbers only the surviving principles. The final total is a checksum of the completed audit, not an objective, estimate, range, quota, or quality signal.

## 1. Root Cause Analysis

### 1.1 “Let the Count Emerge” Was an Outcome Without a Procedure
The original `map-principles` skill stated that the number should emerge from independent decisions, yet it did not require a count-blind sequence. Because the current map and all previous numbered maps were visible at the start, existing list lengths remained strong anchors even when no explicit quota existed.

### 1.2 Source Sections Were Not Persistently Accounted For
The old output format had Authorized Scope and principles but no durable record showing what happened to each source obligation. A reviewer could not tell whether an omitted mechanism was deliberately supporting explanation, prior knowledge, deferred scope, or an accidental gap.

### 1.3 Splitting and Merging Lacked Independent Tests
The old skill mentioned differing review actions and failures, but it did not require concrete pass/fail, correction, and omission tests. This allowed one wrong-and-remedy pair to become two principles, while two independently failing concerns could be compressed into one tidy heading.

### 1.4 Generic Exemplars Carried Fixed Lesson Numbers
The downstream `principled-theory` exemplar bank labeled reusable writing patterns as fixed positions such as “Lesson 1 Principle 5.” Those labels could silently override the approved map or make an old list length appear canonical. Generic exemplars now use `Principle N`; only the real Lesson 04 benchmark keeps approved lesson positions.

### 1.5 A Historical Registry Description Still Advertised a Range
The active skill no longer required a numeric range, but the registry description for `#2026_09_26_16_group_1` still said foundational topics naturally contain four to six invariants. That characterization is now explicitly superseded. The useful multi-code-block explanation standard from that batch remains active.

## 2. Resolution (#2026_09_26_20_group_1)

### 2.1 Count-Last Discovery Order
The author first records every operational obligation in Core Truth, Friction, Mechanism, Under the Hood, Code Experiment, and Scope Boundary. Each obligation may yield zero, one, or several candidates. Candidates remain unnumbered until the audit is complete.

### 2.2 Complete Candidate Records and Dispositions
Each candidate records the developer action, triggering condition, mechanism, prevented failure, and required lesson proof. It then receives exactly one disposition: `New principle`, `Prior prerequisite`, `Supporting explanation`, or `Deferred`.

### 2.3 Semantic Ownership and Atomicity
Earlier maps are normalized into an unnumbered ownership index so their content can prevent overlap without making their totals targets. Candidates remain separate only when code can pass one and fail another, their fixes require different changes, or omission would leave an authorized operational obligation uncovered. Candidates merge when they express the same decision, condition, mechanism, failure, and correction.

### 2.4 Coverage and Disposition Ledger
Every principle map now contains a ledger covering all six source dimensions. The ledger makes omissions and non-principle dispositions visible without forcing one principle per source section.

### 2.5 Count as Checksum
The final total is calculated only after all obligations and candidates have dispositions. Repeated totals trigger a count-blind semantic rerun, not an automatic increase or decrease. Aesthetic pressure for a smaller, larger, uniform, or deliberately varied list is explicitly excluded from the decision.
