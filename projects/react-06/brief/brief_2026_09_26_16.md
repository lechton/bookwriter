# Architectural Decision Brief — 2026-09-26-16: Principle Count Anti-Minimization and Mandatory Multi-Code-Block Machine Trace Substrate

## Executive Summary
This brief resolves the root causes of principle minimization (e.g. artificially capping lessons to 3 principles) and impoverished text-only principle explanations. Under `#2026_09_26_16_group_1`, we apply the Golden Rule of De-Prescription to eliminate the prescriptive lecture-specific count example in `skills/v6.3/principled-theory/SKILL.md#L514`, establishing that foundational platform topics naturally possess 4 to 6 core invariants that must be exhaustively unpacked. Simultaneously, we formalize the **Principle Explanation Substrate Standard**: every principle's operational derivation must be anchored by concrete, titled code blocks demonstrating the physical machine trace (Developer Input, Compiler Translation, Runtime/DOM Execution, or Crash/Failure Output). Purely textual prose without code blocks under a principle is strictly banned as a critical pedagogical defect.

## 1. Root Cause Analysis

### 1.1 The Artificial Ceiling Prescription in Section 05
In `skills/v6.3/principled-theory/SKILL.md#L514`, rule `#2026_09_25_07_group_1` contained this descriptive clause:
> *"Across our curriculum, the count varies naturally based on the topic's scope—**for example, Lesson 02 establishes 3 principles**, Lesson 03 establishes 4 principles, and Lesson 04 establishes 6 principles."*

While intended merely as an illustration of natural variation, AI models interpreted `"Lesson 02 establishes 3 principles"` as an ironclad ceiling. Rather than thoroughly evaluating all the architectural invariants required to answer the interview question (*"What is a React component, and what rules govern how you write and name one?"*), the author squeezed component anatomy into an incomplete 3-principle summary, dropping foundational platform laws:
1. **Component Rendering Purity**: `UI = f(data)` without side effects during render, surviving `React.StrictMode` double-invocation.
2. **Single Root Expression Grammar**: Why JSX components must return a single root element or Fragment (JavaScript `return` expression evaluation).

### 1.2 The Impoverished Text-Only Explanation Defect
When `#2026_09_26_15_group_1` established the Editorial Division of Labor (reserving compiler AST mechanics for the prose below the cards), the instructions did not explicitly mandate that this prose must contain dedicated, titled code blocks. 

Consequently, the author produced two abstract paragraphs of dry text per principle with zero code blocks. This committed the exact anti-pattern warned against in `SKILL.md#L538`:
> *COUNTER-EXAMPLE: Stating "Principle 5: Attributes are camelCase" followed by two sentences of text and no code block, no table, no runtime breakdown, and no transpiled output.*

In contrast, our canonical living benchmarks (Lecture 1 and Lecture 4) never rely on text-only explanations. Every principle is grounded in a 5-beat physical substrate:
1. Tactile friction context,
2. Naive/problem code block (`title="..."`),
3. Physical machine failure/crash code block (`title="..."`),
4. Idiomatic React solution code block (`title="..."`), and
5. Step-by-step physical machine trace.

## 2. The Solution Architecture (#2026_09_26_16_group_1)

### 2.1 Pruning the Artificial Count Ceiling (De-Prescription)
We pruned the prescriptive clause `"for example, Lesson 02 establishes 3 principles..."` from `skills/v6.3/principled-theory/SKILL.md` Section 05. We replaced it with an anti-minimization standard: foundational platform topics (such as component anatomy, declarative synchronization, or JSX grammar) naturally possess 4 to 6 core invariants. Authors are instructed to exhaustively unpack all distinct platform contracts rather than collapsing them into a superficial 2- or 3-principle summary.

### 2.2 The Principle Explanation Substrate Standard
We established a strict checklist standard in Section 04 and updated Gate 20 in `skills/v6.3/verification/SKILL.md`:
- Every principle explanation must provide concrete, titled code blocks demonstrating the physical machine layers.
- Text-only prose paragraphs without titled code blocks under a principle are strictly classified as a critical pedagogical defect.
- Each principle derivation must walk through: (1) real-world friction scenario, (2) naive/problem code block with comments, (3) visual/compiler breakdown or runtime crash block, (4) idiomatic React resolution block, and (5) step-by-step physical machine trace.
