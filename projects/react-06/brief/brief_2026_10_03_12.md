# Architectural Decision Brief: 2026-10-03-12: Total Ban on Multi-Line Code in Content & Invariant 9 Algorithmic Audit Gate

## Executive Summary
This batch eliminates a critical rendering and layout defect where multi-line code was authored as simple narrative content in Markdown prose instead of within proper fenced code blocks or callout containers. It updates `skills/v6.4/code-blocks/SKILL.md` to establish an absolute ban on multi-line code in narrative content, calibrates `skills/v6.4/code-comment-audit/SKILL.md` and `skills/v6.4/principled-theory/SKILL.md` to protect card-free `Kind: Model` principles, implements **Invariant 9: MULTILINE_CODE_AS_CONTENT** in `src/diagnose-lecture.mjs` and `src/build-lectures.mjs`, and records `#2026_10_03_12_group_1` in `skills/v6.4/RULE-TAGS.md`.

## 1. Root Cause Analysis

### 1.1 Multi-Line Code Passed as Simple Text
In several lectures (`16.md`, `17.md`, and `18.md`), comparative breakout cards (`*It is best practice to do this:*` / `*Instead of doing this:*`) were emitted as raw paragraph text without blockquote (`>`) prefixes or fenced code block markers (```` ``` ````). 
Because markdown block parsers treat lines without block prefixes as plain paragraphs (`{ t: 'p', text: ... }`), the inline code processor evaluated each backticked line with `isDisplayCode()`. Any line beginning with a JavaScript keyword (`function`, `const`, `return`) was converted into `<span class="code-line-callout"><code>...</code></span>`. This fragmented cohesive multi-line components into a staircase of disconnected, bordered boxes with margins.

### 1.2 Tooling Blind Spot in Diagnostic Invariants
Previously, `src/diagnose-lecture.mjs` inspected only fenced code blocks (`blocks.filter(b => b.t === 'code')`) and blockquoted lines (`line.startsWith('>')`). It had zero inspection of raw prose paragraphs (`t: 'p'`). Consequently, files containing severe multi-line code fragmentation passed the 8-invariant diagnostic gate with a false-positive `[PASS]`, allowing corrupted layouts to be compiled into published PDFs.

### 1.3 Conflicting Instructions Between Model Principles and Universal Code Comment Audits
`principled-theory` Rule 123 explicitly exempts `Kind: Model` principles from comparative breakout cards. However, early drafts of `code-comment-audit` (Rules 12 and 13) asserted universal coverage over "principle breakout cards" without qualification. Confronted with contradictory prompts, authoring agents attempted pathological compliance by omitting cards from the `> [!PRINCIPLE]` callout while dumping unquoted cards as simple text into narrative prose.

## 2. Resolution

### 2.1 Tooling: Invariant 9 in `diagnose-lecture.mjs` & `build-lectures.mjs`
Added **Invariant 9: MULTILINE_CODE_AS_CONTENT** to the deterministic verification suite:
- Scans all lines outside of fenced code blocks and outside of blockquotes.
- Flags unquoted card headers (`^\s*\*(?:It is best practice to do this|Instead of doing this|We should do this|We should not do this):\*`).
- Flags consecutive lines wrapped in backticks (multi-line code passed as prose).
- In `diagnose-lecture.mjs`, failures increment `gateFailures++` and exit with code 1.
- In `build-lectures.mjs`, `checkLecture()` outputs descriptive warnings to prevent regressions.

### 2.2 Skill Rules Update
- **`code-blocks/SKILL.md` (Section 14B)**: Replaced the legacy single-block multiline backtick exception with an absolute standard: multi-line code belongs strictly inside titled fenced code blocks (` ```jsx `) or inside `> [!PRINCIPLE]` callouts with `>` prefixes on every line. Backticks in prose are reserved exclusively for single inline identifiers.
- **`code-comment-audit/SKILL.md` (Rules 12, 13 & Section 08)**: Calibrated audit scope to recognize card-free `Kind: Model` principles and added Invariant 9 to the 9-invariant deterministic gate.
- **`principled-theory/SKILL.md` (Rules 129 & 142)**: Mandated that comparative breakout cards exist strictly inside `> [!PRINCIPLE]` callouts with `>` prefixes, and reaffirmed that `Kind: Model` principles remain card-free.
