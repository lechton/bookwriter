# Architectural Decision Brief — 2026-09-26-12: Canonical Technical Nouns with Plain Human Verbs and Anti-Pompous-Dressing Law

## Executive Summary
This brief resolves the recurring language regression ("The Pompous AI Fluff / Academic Word-Salad Disease") where AI models, when instructed to use canonical industry terminology and sound authoritative, swing into puffed-up, Latinate corporate dressing (*"lives authoritatively in JavaScript memory"*, *"strictly a write-only projection surface"*, *"determine application truth"*, *"drive business logic"*). Under `#2026_09_26_12_group_1`, we establish the definitive invariant: **Canonical Technical Nouns + Plain Everyday Human Verbs**. Every canonical technical noun (`props`, `declarative UI`, `virtual DOM`, `reconciliation`, `state`, `HTML attributes`) must be paired with simple, active human verbs (`store`, `pass`, `display`, `check`, `read`, `wipe`, `lose`), permanently eradicating bureaucratic fluff while preserving rigorous senior engineering precision.

## 1. Root Cause Analysis

### 1.1 The False Dichotomy: Technical Terms vs Pompous Dressing
AI models continually oscillate between two destructive extremes:
1. When told to "use simple language", they commit the *Exclusionary Fallacy* and delete standard, canonical platform nouns (`declarative UI`, `unidirectional data flow`, `virtual DOM`).
2. When corrected and told to restore canonical vocabulary, they mistake *pompous rhetorical dressing* for technical depth. They immediately wrap standard concepts in Latinate academic bureaucrat fluff (*"lives authoritatively"*, *"strictly a write-only projection surface"*, *"determine application truth"*, *"drive business logic"*).

This creates an endless see-saw: fixing the vocabulary breaks the language, and fixing the language breaks the vocabulary.

### 1.2 The Definitive Invariant: Canonical Technical Noun + Plain Human Verb
The root cause is failing to distinguish between **nouns** and **verbs**:
- **Technical depth belongs exclusively in canonical platform nouns**: `props`, `state`, `virtual DOM`, `reconciliation`, `DOM nodes`, `HTML attributes`. These must never be hidden behind conversational circumlocutions.
- **Rhetorical clarity belongs in plain, active everyday human verbs**: `store`, `pass`, `display`, `check`, `read`, `wipe`, `lose`.
- **Pompous dressing is strictly banned**: Words like *"authoritatively"*, *"projection surface"*, *"application truth"*, and *"drive business logic"* add zero mechanical information; they only inflate the text with empty academic posturing.

## 2. The New Standard (#2026_09_26_12_group_1)

### 2.1 The Noun-Verb Pairing Rule
Every principle definition, card, and prose explanation must construct its sentences by directly attaching plain human verbs to canonical platform nouns.

| Canonical Technical Noun | Banned Pompous Dressing | Mandatory Plain Human Verb / B2 Phrasing |
| :--- | :--- | :--- |
| `state` | *"lives authoritatively in memory"* | *"Keep your data in JavaScript variables..."* |
| `DOM` | *"strictly a write-only projection surface"* | *"React uses the DOM only to display results..."* |
| `HTML attributes` | *"determine application truth"* | *"...never reads HTML attributes to figure out what is happening..."* |
| `business logic` | *"drive business logic"* | *"...to calculate prices, show warnings, or run app logic"* |
| `reconciliation` | *"orchestrate dynamic mutation lifecycles"* | *"React compares elements and updates only changed nodes"* |

### 2.2 The Principle 4 Transformation
- **Failed Pompous Fluff**:
  > *"Application state lives authoritatively in JavaScript memory as variables, numbers, and objects. The browser DOM is strictly a write-only projection surface; components never query HTML attributes (getAttribute, dataset) to determine application truth or drive business logic."*
- **Approved Pristine B2 Standard**:
  > *"Keep your data in JavaScript variables, numbers, and objects, not in HTML elements. React uses the DOM only to display results, so your code never reads HTML attributes like data-tier to figure out what is happening in your app."*
