# Decision Brief — 2026-09-25-01: Compound Default Versioning Convention & Single-Lecture Deck Prohibition

## Context & Motivation
1. **Dynamic Compound Versioning Convention**:
   Previously, the build compiler (`src/build-lectures.mjs`) labeled deck outputs either with a hardcoded version string (`React v6.0`) or purely by skills version without incorporating the lesson markdown directory version, causing a mismatch across artifacts and logs.
   Under the new convention, the default version is determined dynamically by compounding:
   - The highest edition found in `skills/` (currently `v6.2`), AND
   - The highest version folder found in lesson markdown files (`01-02-md-LECTURES/`, currently `v2`).
   The resulting compound version is `${skillsVersion}-${lessonVersionNum}` (e.g. `v6.1` + `v5` ➔ `v6.1-5`; currently `v6.2` + `v2` ➔ `v6.2-2`).
   This compound version is reflected consistently across all multi-theme deck artifacts (`React v6.2-2 Q01-Q13-black.pdf`, `-teal.pdf`, `-old.pdf`, `-enhanced.pdf`, `-teal-pro.pdf`, and the default alias `React v6.2-2 Q01-Q13.pdf`).

2. **Removal and Absolute Prohibition of Individual File Decks**:
   A prior instruction defect caused single-question deck artifacts (such as `React v6.0 Q13-Q13-old.pdf`, `React v6.0 Q10-Q10*.pdf`, etc.) to be generated whenever individual lectures were compiled or when `--range {n}-{n}` was executed.
   These files make no sense: each individual lecture already produces its own canonical output (`13.html` and `13.pdf`). A "deck" is strictly a multi-lecture reader spanning at least two distinct questions (`first !== last` and `allNumFiles > 1`).
   The compiler now enforces this invariant, skips deck generation for single files, and automatically purges any legacy single-file decks matching `Q(\d+)-Q\1`.
