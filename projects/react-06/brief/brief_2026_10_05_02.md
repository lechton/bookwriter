## The Changes and Their Reasons

1. **Effects in the react.dev order (CORE).** `#effect_events` (old 48) becomes Q35 and `#effect_dependencies` (old 47) becomes Q36, right after the effect lifecycle (Q34) and before custom hooks. A newcomer meets the dependency lint warning at the first effect; react.dev teaches separating events from effects and removing dependencies before custom hooks. Both move from MORE to CORE.
2. **Rules of hooks into CORE.** `#rules_of_hooks` (old 46) becomes Q37, before custom hooks (Q38). By then the reader has used useState, useReducer, context, useRef, and useEffect, so the call-order rule explains errors already seen and governs the hooks about to be written. Interviewers treat it as basic knowledge. The useState lesson (Q14) still previews "call hooks at the top level", as react.dev does.
3. **Context performance after memoization.** `#context_optimization` (old 29, CORE) becomes Q59 in MORE, after re-render mechanics, `memo`, `useMemo`, `useCallback`, and composition (Q54 to Q58). Its fixes (a memoized provider value, split contexts, children composition) depend on those lessons. CORE keeps context itself (Q27) and reducer with context (Q28).
4. **Client security (new, MORE).** Q48 `#xss_safety`: how React escapes text, and when `dangerouslySetInnerHTML` removes that protection. A classic interview question with no client-side home before; the server security questions (Q130, Q149, Q162) cover trust boundaries and taint, not rendering untrusted HTML.
5. **State libraries (new, MORE).** Q60 `#state_libraries`: when an app outgrows useState and context, and what external stores (Redux, Zustand) and server-cache libraries (TanStack Query) add. Placed after `useSyncExternalStore` (Q53) and context performance (Q59), which it builds on.
6. **Component testing (new, ADVANCED).** Q87 `#testing_components`: testing components the way a reader uses them. Placed just before `act()` (now Q88), which assumes it. Only `act()` existed before.
7. **DevTools duplicate merged.** Old Q64 (`#profiler_component`) and old Q95 (`#dev_tools_mastery`) asked nearly the same question. They become one Q64 tagged `#dev_tools_mastery`, which also absorbs old Q55 `#use_debug_value` (labeling a custom hook's state in the inspector is a DevTools concern).
8. **Insertion effect merged.** Old Q50 `#use_insertion_effect` (an API for CSS-in-JS library authors) joins Q49 `#use_layout_effect`, whose question and hook now name it as the even earlier effect reserved for style libraries.

Net count: CORE gains three and loses one (41); MORE gains three, loses three to CORE, and merges two away (34); ADVANCED gains one and merges one away (20).
