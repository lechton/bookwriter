# Brief 2026-09-21 08: Universal Grounding Card Downstream Placement and Concept Baptism Law

## Batch Tag
`#2026_09_21_08_group_1`

## Motivation & Context
In Lecture 03 (`#component_anatomy`), a critical structural defect recurred: the `[!WILD]` friction card was inserted immediately below the very first introductory paragraph of Section 1, asking:
> `**Why does writing a lowercase tag render an empty node?**`

At this point in the lecture, the student had only read that HTML has native tags and React has custom functions called components. Capitalization, casing conventions, lowercase vs. uppercase tags, and PascalCase had **never been introduced, explained, or demonstrated in code**. The card interrogated a mystery the student did not even know existed, and attempted to resolve it using unbaptized terms (`PascalCase`, `compiler transform`).

The previous rule `#2026_09_21_03_group_1` had an accidental limiting clause:
> *"whenever a section explores distinctions between key ideas, categories, paradigms, or tools (such as a client build tool versus a full-stack framework)..."*

Because this was framed around macro tool/paradigm choices, authoring models treated it as an exception rather than a universal invariant, continuing to place friction cards at the top of sections during syntax or naming lessons.

## Architectural Changes & Universal Standard
1. **Downstream Resolution Instrument**: The `[!WILD]` / `[grounding]` friction card is strictly a downstream resolution instrument, never a section opener. It must be placed strictly AFTER:
   (a) The baseline concept and its rules have been formally introduced in prose.
   (b) The naive attempt, common friction point, or trap has been demonstrated in a literal code snippet.
   (c) The physical failure symptom in the browser or runtime has been explained.
2. **Ban on Interrogating Unintroduced Topics**: The 6–9 word opening question must ONLY interrogate an observable consequence, syntax behavior, or failure the student has already seen in the preceding text and code.
3. **Dedicated Verification Gate**: Added Gate 14 in `skills/verification/SKILL.md` auditing downstream card placement and zero unbaptized concepts inside alert cards.
