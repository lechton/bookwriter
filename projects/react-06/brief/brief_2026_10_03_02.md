# Architectural Decision Brief: 2026-10-03-02: Code Comment Audit Skill & Targeted Balloon Pointer Pipeline

## 1. Root Cause Analysis

### 1.1 Decoupling Code Comment Standards from Generation Prompts
During lecture authoring, agents and authors manage high-level pedagogical pacing, concept coverage, file architecture, and narrative flow. Loading granular rules about speech bubble character offsets, tab indentations, and dashed underlines into the primary authoring prompt overloads context and distracts from core pedagogical goals. A dedicated, post-edit audit skill allows authors to scan existing Markdown files and calibrate code annotations systematically without polluting early drafting stages.

### 1.2 Uncalibrated Balloon Pointer Alignment
Previously, code comment bubbles (`.cmt-bubble`) in editor blocks and principle cards floated with a static left margin, pointing vaguely to the left edge of the code window or element tag rather than the specific keyword, prop, or function call being taught. Furthermore, the targeted word or phrase lacked visual highlighting, leaving readers to guess which part of a multi-token line the comment referenced.

## 2. Resolution

### 2.1 Compiler and CSS Infrastructure (`src/build-lectures.mjs` & `src/lecture.css`)
- **Token Target Recognition**: In `src/build-lectures.mjs`, `tokenizeCodeWithTarget` extracts targets delimited by tildes (`~target~`) or double asterisks (`**target**`). It wraps the target in `<span class="target-token">...</span>` with full syntax highlighting.
- **Center-Point Arithmetic**: The compiler calculates the exact horizontal character column of the token center relative to line indentation: `centerChar = codeBeforeTarget.length + (target.length / 2)`. It converts this into pixel units (`tipOffset = Math.round(centerChar * charWidth)`) and passes `--token-offset` to the bubble element.
- **Indentation Offsets**: The speech bubble container receives `--indent-offset`, ensuring the comment box is indented with the line of code above it.
- **Pointer Alignment**: In `src/lecture.css`, the upward pointer tail (`.cmt-bubble::before`) sets `left: var(--token-offset, 16px)`, positioning its top tip directly beneath the center of the annotated token.
- **Dashed Underline & Vertical Clearance**: Set `.target-token` to `border-bottom: 2.5px dashed #a8a8a8; padding-bottom: 2px;`, providing a soft medium-light neutral shade with calibrated 2.5px weight. Increased bubble `margin-top` to `11px` in editor blocks (`13px` in principle cards) to guarantee a clean minimal distance between the dashed underline and the pointer tip so they never touch. Contextual overrides provide softened shades for comparative blocks (`#2ca662` for recommended patterns, `#de5252` for anti-patterns and cautions).

### 2.2 Creation of the Code Comment Audit Skill (`skills/v6.4/code-comment-audit/SKILL.md`)
Created `code-comment-audit/SKILL.md` following prompt-writing standards:
- **Audit Scope**: All code blocks (theory snippets, principle cards, Stage C steps) require comments, EXCEPT comparative summary blocks at the end of lessons (`right`/`wrong`), which remain strictly comment-free per workspace law.
- **Comment Density**: 2 to 4 annotations on substantial blocks targeting load-bearing mechanics (event handlers, state setters, callback props, semantic attributes).
- **Voice and Phrasing**: Clear, direct, upper-intermediate (B2) conversational English without robotic tags.
- **Vertical Alignment**: Bubbles placed immediately under the targeted line with matching tab indentation (`--indent-offset`).
- **Pointer Targeting**: Precise pointer tails calculated via `~target~` syntax and `--token-offset`.
- **Semantic Underlining**: Proper dashed underline color mapping.
- **Line Budget**: Preservation of the 10-line code ceiling and 80/68-character line limits.

### 2.4 Page Column Benchmark Architecture (Left vs Right Starting Points)
- Established a universal benchmark in `src/build-lectures.mjs` based on the horizontal character column of the targeted token (`colIndex = indentLen + codeBeforeTarget.length + (target.length / 2)`).
- **Page Column Benchmark**: Column 36 divides the left side from the right side of the page (column 30 in principle cards).
- **Left Starting Point (`colIndex <= 36`)**: The bubble anchors on the left at line indentation (`--indent-offset`) and extends to the right; its pointer tail is positioned from the left (`left: var(--token-offset)`).
- **Right Starting Point (`colIndex > 36`)**: The bubble anchors on the right at token center + shoulder (`--right-edge`) via `.cmt-bubble-right` and extends to the left (`transform: translateX(-100%); white-space: nowrap;`); its pointer tail is positioned from the right (`right: var(--tail-shoulder, 24px); left: auto;`).
- This eliminates all ad-hoc offsets: every comment on the right half of the page automatically starts from the right, extending left with a clean 24px shoulder, pointing dead-center at the token without stabbing the dashed underline.
