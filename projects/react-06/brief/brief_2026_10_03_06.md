## 1. Motivation and Rationale

### 1.1 The Clinical Labeling Trap
When writing code comments, models and authors often default to clinical classification labels. Describing an array declaration as `// Static collection outside render` is technically true, but pedagogically sterile:
- "Collection" is textbook CS taxonomy for an array or list.
- "Static" merely classifies the data without explaining why it is fixed.
- "Outside render" fails to explain *why* the placement matters or what runtime failure it prevents.

### 1.2 Concrete Mechanical Explanation
In contrast, `// Declared outside App to avoid recreating array on each render` provides immediate, tangible understanding:
1. **Physical Actor & Location**: Declared outside `App`.
2. **Prevented Runtime Penalty**: Avoids recreating the array in memory on each render pass.
