## Why

The skill named the syllabus card as the authority for a lesson's topic and question and never mentioned the question bank. When bank Version 2 moved useState to Q14, map 14 was still the events map. The production agent noticed, opened map 16 because it was about useState, and wrote Lecture 14 from it without a report. Nothing in the skill told it to compare the files or to stop. The cards now match bank Version 3 (briefs 2026-10-05-05 and -06), but maps 14 to 22 still follow Version 1, and the next bank version can move topics again.

## What Changed

Following "prune before banning", the existing authority rules were revised and one check was added. No prohibition was added.

- **Section 01, first rule (revised)**: bank row {nn} of the live `questions/questions.md` is the authority for the lesson's number, topic tag, tier, and interview question. The card stays the authority for the code experiment and scope boundary.
- **Section 01, new rule**: before Discovery, the bank row and the card must carry the same number, topic tag, and question text. When they differ, the work stops with a report of both values instead of continuing with whichever card looks closest. The rule also restates that `questions/archive/` and `questions/drafts/` are history and proposals, never the current bank.
- **Section 01, approved-map rule (revised)**: an approved map is the authority for its principles only while its header still carries the tag and question of its bank row. A map whose header differs was written for another bank version and is rebuilt before a pre-lecture or lecture relies on it.
- **Section 01, examples (new)**: a PROPER EXAMPLE (row 15 and card 15 agree, so Discovery starts; an older map 15 says `#callback_props`, so the author stops and reports) and a COUNTER-EXAMPLE drawn from the real Lecture 14 run, plus a note on why tag and question text are compared rather than the file number alone.
- **Output Contract (revised)**: the map header gains a `Bank Row` line naming the row and the bank version; the header rule and the Completion Gate now require the tag, tier, and question to equal the bank row; the Notes say how to treat maps written before this batch (no `Bank Row` line, so compare tag and question with the live row).
- **Description, opening paragraph, agent default prompt, and README routing line**: now say the map is built from a bank row and its card, and that the two are confirmed to agree first.
