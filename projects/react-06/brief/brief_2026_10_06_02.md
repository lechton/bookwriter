## The Problem

- **Terms drift by name.** Map 04 lists "local variable (`const`, `let`)" and map 14 listed "local variable (`let`, `const`)". With 22 maps and more to come, a search for one name misses the other, and two maps can claim two different first appearances without anyone noticing.
- **Card search was described, not given.** Section 03 asked the author to read four key lines of every card but gave no command, so each author built a different search, or read only the neighbours.
- **Nothing checked one map against another.** `diagnose-map.mjs` checked a map alone. A Recall term pointing at a map that does not list it, or a citation like `Q04 braces-window` to a handle that does not exist, passed.
- **Messages between lessons had no home.** A promise ("see Lecture 17") or a reusable example lived only in one lecture's prose. Lecture 05 still points render and commit at Lecture 17, while bank Version 3 moved that topic to Q15. No file told the Lecture 15 author.

## The Changes

1. **Term names reused** (`group_1`): `map-principles` Section 07 asks a term an earlier map lists to keep that map's name, character for character, with map 14's first draft as the counter-example. Map 14 is renamed to match map 04.
2. **Card search command** (`group_2`): Section 03 gives `rg -N --sort path '^\* \*\*(Topic Tag|Core Truth|The Mechanism|Scope Boundary)\*\*' 01-01-map/[0-9]*.md`, which prints 720 lines, four per card, in bank order.
3. **Cross-map and handout checks** (`group_3`): `diagnose-map.mjs` check 7 fails when two maps date a term to different first lessons, when a Recall term is absent under the same name from the map it names, or when a cited `Q{NN} handle` does not exist. A check that needs a map not yet written is a NOTE. Check 8 validates `handouts/{NN}.json` and fails while a `map`-stage message to the lesson is open. The map now requires a `Handout:` line in Sources Read. Section 13 describes both checks.
4. **Handouts** (`group_4`): one JSON inbox per receiving lesson in `handouts/`. Each message has `id`, `from`, `to` (number and tag, checked against the live bank), `kind` (`promise`, `reuse`, `caution`, `correction`, `move`), `stage` (`map` or `lecture`), `source`, `msg`, `affects`, `status`, and `resolution`. Files are written only through `node src/handout.mjs add` and `close`, which validate and roll back a broken save. `node src/handout.mjs {NN}` also shows other maps' ledger rows that name the lesson as owner and the later maps that recall it. A message to an earlier lesson is a request applied through that lesson's normal revision; a `move` is always stage `map` and changes the cards first. New `map-principles` Section 11B holds the rules, with `14-37-01` as the PROPER EXAMPLE and the Lecture 05 pointer as the COUNTER-EXAMPLE. The Output Contract gains the `Handout:` line and a Completion Gate box.
5. **Handouts in later stages** (`group_5`): `pre-lecture` 01B reads the inbox, plans and closes `lecture` messages, and sends a message for each forward promise or found error. `lecture-structure` 06 asks that every `lecture` message is delivered and every forward promise has a message. `verification` item 23 checks the inbox is empty. The README load order names the inbox command for maps and pre-lectures.
