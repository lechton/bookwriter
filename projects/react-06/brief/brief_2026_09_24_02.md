# Brief 2026_09_24_02: Principled Theory Standard and Universal Variant F Default

## Origin & Context
Following the successful creation and visual audit of Lecture 4 (JSX Grammar and Fragments), the user established a universal standard for principle-based lessons. A formal skill was requested under `principled-theory` to define how theory sections must be authored autonomously and completely, how practical case studies and terminal digests must introduce strictly zero new concepts, how principles must be structured with canonical callout formatting and dual comparison pairs (`We should do this:` / `We should not do this:` and `It is best practice to do this:` / `Instead of doing this:`), and how Variant F should serve as the default appearance for all project PDFs.

## Rules & Standards Introduced

### 1. Skill: `principled-theory` (`skills/v6.0/principled-theory/SKILL.md`)
- **Autonomous and Complete Theory Law**: Theory must be completely self-contained, independent, and exhaustive before the practical example begins. A candidate must be able to master 100% of the topic's compiler mechanics, language grammar invariants, and mental models from the theory alone.
- **Zero-New-Concept Case Study Law**: The practical case study (`### Let's Design a Practical Example`, Stages A through E) introduces strictly zero new concepts, properties, or syntax. It strictly synthesizes the principles taught in theory.
- **Zero-New-Concept Terminal Sections Law**: `### Where you will meet this`, `### Glossary`, `## Beyond the basics`, and `### Summary` introduce no new terms, reinforcing and referencing only what was baptized in the theory.
- **Canonical Principle Anatomy**:
  - `> [!PRINCIPLE]`
  - `> **Principle N: Catchy Title**`
  - Bold authoritative definition.
  - Comparative code cases: Pair 1 (`We should do this:` / `We should not do this:`) for syntax validity and compiler errors; Pair 2 (`It is best practice to do this:` / `Instead of doing this:`) for idiomatic architecture and best practices.
- **Mandatory Tangible Accompaniments**: Bullet breakdowns, full-width comparative tables, line-numbered code blocks with comment bubbles, and standalone HTML figures.
- **Senior Candidate Interview Framing Standard**: Ground explanations in platform reality (W3C DOM specifications, ECMAScript parser boundaries, AST tokens, function return mechanics), contrasting naive candidate answers with deep runtime rationale.

### 2. Universal Variant F Project Default (`src/lecture.css`)
- Deep Teal (`#0e7490`) as the universal accent for headings, marginalia, bullets, and links.
- Pure black (`#000000`) for narrative bold text (`p strong`, `p b`).
- System UI typography (`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`) with weight 700 for headings and body prose.
- Full-bleed architectural cobalt ribbon (`#0284c7`) with pure black principle titles.
- Clean code callout containers without inner nested borders.
- Monospace font standardized to JetBrains Mono.
- All variants A through F preserved in `src/build-variants.mjs` for future reference.
