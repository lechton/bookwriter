## The Problem

The rebuild of map 14 (brief 2026-10-05-08) found that no card owned the `useState` initializer function: `useState(createInitialTodos)` instead of `useState(createInitialTodos())`. react.dev teaches it under useState Usage ("Avoiding recreating the initial state"), reviewers flag the second form, and card 46 already assumes it when it says StrictMode calls initializer functions twice.

## The Change

- **Card 14, The Mechanism**: one added sentence: React uses the argument only on the first render, but the expression in it still runs on every render, so an expensive start value is passed as an initializer function, which React calls only once.
- **Card 14, Scope Boundary**: "the initial value and the initializer function" added to the focus list. The bank row is unchanged.
- **Map 14**: the ledger row moves from "Deferred, unassigned" to Principle, with a merged row for the runtime proof; new Principle 4, "Pass an expensive start value as an initializer function" (Decision, Review Point Condition: pass the function when the start value costs real work, a plain value when it is cheap); the Authorized Scope and the Senior Answer gain one clause each; the Completion Gate drops the unassigned-owner exception and records the gap as closed.
- **Why a separate principle**: Principle 2 is the model (the argument matters only on the first render). The initializer is a decision with its own failure (work repeated on every render and thrown away) and its own correction (pass the function), so the atomicity test splits them.
- **Why it is Principle 4 and not 3**: appending keeps the existing numbers stable, and Principle 4 needs only Principle 2 before it.

## Proof

Reproduced with React 19.3.0 and React DOM 19.3.0 in jsdom under Node: with `useState(createInitialTodos())`, a mount and three keystrokes in a text field called `createInitialTodos` four times; with `useState(createInitialTodos)` it was called once; both showed 50 todos.
