# Decision Brief: Universal Dashed Border Default for Inspected DOM Elements and Anti-Input-Box Law (#2026_09_22_08_group_1)

**Date**: 2026-09-22
**Rule Tag**: `#2026_09_22_08_group_1`
**Components Affected**: `skills/ui-panels/SKILL.md` (Section 02), `src/lecture.css`, `skills/RULE-TAGS.md`

---

## 1. Problem Statement & Root Cause

In Lecture 11, the Rendered UI Canvas displayed `[elem:h3.story-headline: Summit Concludes in Geneva]` and `[elem:span.category-tag: World]` inside `.ui-elem` containers styled with `background: #ffffff; border: 1.5px solid #cbd5e1; box-shadow: 0 1px 3px rgba(15, 23, 42, 0.04);`.

Because interactive form controls (`<input>`, e.g. `[input.note-input]`) also render as white fields with solid borders, rendering headings, spans, and divs with a solid border caused typographic content and status badges to look identically to text input fields.

**Root Causes**:
1. In `src/lecture.css`, `.ui-elem` defaulted to a solid border (`border: 1.5px solid #cbd5e1`) and elevation box-shadow (`box-shadow: 0 1px 3px rgba(15, 23, 42, 0.04)`), creating a visual form-input affordance for all inspected elements.
2. In `skills/ui-panels/SKILL.md`, there was no invariant defining the boundary perimeter styling of `.ui-elem` overlays to demarcate structural DOM element boundaries from interactive form inputs.

---

## 2. Changes Applied

### A. Universal Default in Stylesheet (`src/lecture.css`)
- Updated the base `.ui-elem` definition in `src/lecture.css` so that all inspected DOM elements uniformly render with a dashed perimeter:
  ```css
  /* Web-Inspector Element Overlays for Internal Content */
  .ui-elem {
  	position: relative;
  	margin: 1.25rem 0 0.35rem;
  	padding: 0.75rem 0.85rem;
  	background: #ffffff;
  	border: 1.5px dashed #cbd5e1;
  	border-radius: 7px;
  	box-shadow: none;
  	box-sizing: border-box;
  	width: 100%;
  }
  ```
- Solid borders are strictly reserved for actual interactive form controls (`.surface-ui-input`), creating an unmistakable visual distinction between typographic DOM elements and form input fields.

### B. Skill Invariant (`skills/ui-panels/SKILL.md`)
- Added the **Inspector Overlay Perimeter and Anti-Input-Box Law** to Section 02:
  - Every inspected DOM element overlay (`.ui-elem`) renders as a white container bounded by a subtle dashed perimeter (`border: 1.5px dashed #cbd5e1; box-shadow: none`).
  - Solid borders are strictly reserved for actual interactive form controls (such as `.surface-ui-input`) to prevent typographic content (headings, paragraphs, tags, divs) from being visually mistaken for text inputs.
