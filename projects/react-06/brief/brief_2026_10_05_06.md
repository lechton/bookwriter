### Card 15 (`#render_and_commit`)

- **Core Truth**: "rigorous", "virtual JSX", and "surgically writing differences to the physical DOM" replaced with the react.dev definitions: rendering is React calling our components, and the commit changes only the DOM nodes that differ; the browser paints afterward.
- **The Friction**: "writing race conditions" removed, because nothing in this topic causes one. - **The Mechanism**: adds which components React calls (the root on the first render; the component whose state changed and everything it returns, recursively, afterward), and states the commit exactly as react.dev does (`appendChild()` on the first render, only the calculated changes afterward).
- **Under the Hood**: "partial DOM tearing" removed (tearing is a concurrent-rendering term, Q66) and batching removed (Q17); it now explains React rendering versus browser painting, why purity lets React render without touching the screen (StrictMode, Q46), and why an unchanged result causes no DOM change.

### Card 16 (`#state_snapshots`)
