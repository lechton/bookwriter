Lectures 04, 12 and 13 were once rewritten without being asked and had to be restored from a backup in `/tmp`, older archives carry hand-made names (`14.md`, `14b.md`), and `produce_lectures.py --force` had its own separate archive step (added by `#2026_10_04_09_group_1`). A draft could be lost, and no log file recorded what moved where.

## Root Cause

There was no single, safe way to retire a lecture. Each agent improvised: copying, renaming, or overwriting, one folder at a time. A lecture leaves files in up to eight places (pre-lecture, lecture, figures, HTML, PDF, and the three revised folders), so a hand move easily missed some of them, and a forced rewrite left the old draft in place for the new session to inherit.

## Changes

1. **`archive_lecture.py`**: `python3 archive_lecture.py NN` moves every file of lecture NN (for example `14.md`, `14.html`, `14-01-code-assembly-pipeline.html`, but never `140.md`) from the eight locations of the latest version folder into the `archive/` subfolder next to each file, under a timestamped name such as `14-2026-10-04-0913.md`.
   - Files are only moved, never deleted or overwritten.
   - The whole plan is checked before the first move. If any target name is taken, nothing moves.
   - If a move fails midway, every file moved so far is put back.
   - Every move is appended to `ARCHIVE-LOG.md` with the time, the action, and a reason (`--reason`).
   - `--dry-run` shows the plan, `--list` shows the archived stamps of a lecture, `--restore STAMP` moves a version back (it refuses if a working file is in the way), and `--version` picks a version folder.
2. **`produce_lectures.py --force`**: before a forced rewrite, `archive_for_rewrite(n)` no longer moves files itself; it now calls `archive_lecture.archive` with the reason `produce_lectures --force`, so the old draft is archived and logged and the new session authors from scratch. The help text says so.
3. **AGENTS.md**: the control directive `aaa NN` runs the dry run, shows the plan, runs the archive, reports the moves, and does nothing else. The "Retiring Lecture Files" section says never to delete, overwrite, or hand-move a lecture file and points to the script.

## Validation

- The script was tested in a sandbox copy of the project before its first real run.
- First real run, on `aaa 14`: six Lecture 14 files moved with stamp `2026-10-04-0913` (pre-lecture, lecture, two figures, HTML, PDF), all logged in `ARCHIVE-LOG.md`. The older hand-made archives `14.md` and `14b.md` were left untouched.

## How to Trace or Revert

- See every move: `ARCHIVE-LOG.md`.
- Bring a version back: `python3 archive_lecture.py 14 --list`, then `python3 archive_lecture.py 14 --restore 2026-10-04-0913` (archive the current working files first).
- Undo the protocol itself: remove the `aaa NN` line and the "Retiring Lecture Files" section from AGENTS.md, and restore the previous `--force` path in `produce_lectures.py`. `archive_lecture.py` is a standalone file.

Not touched: any lecture content, pre-lecture content, principle map, syllabus card, or skill rule.
