# Brief 2026-10-07 02: Four sequential principle passes

## Problem
A principle box in Lecture 16 was drafted as:
"When React calls a component, useState gives it a fixed state value for that run, called a snapshot. We might expect calling a setter like setCount(count + 1) to change the variable in our code right away. It does not. The setter stores the next value in React and asks for a new render. In the running function, the variable remains the constant it was when the run started. So every line in that run, and every setter call inside it, reads the same value."

The text was completely incomprehensible, abstract, and repetitive. It repeated the exact failure mode rejected in October (Case 1 and Case 3 of examples.md): leading with abstract labels ("called a snapshot"), turning the principle into a glossary side-note, personifying React ("stores in React and asks for a render"), and failing to ground the behavior in plain JavaScript. Because diagnose-lecture only verified structural and syntactic invariants, the model received a clean green pass and assumed the prose was ready.
