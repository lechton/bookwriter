# Architectural Decision Brief — 2026-09-27-06: Default Code-Plus Principle Cards, Targeted Speech-Bubble Comment Models, and Single-Page Callout Budget

## Executive Summary
This batch updates `skills/v6.3/principled-theory/SKILL.md`, `skills/v6.3/build/SKILL.md`, `skills/v6.3/RULE-TAGS.md`, `src/build-lectures.mjs`, and `src/lecture.css`. It establishes the full-width breakout principle card layout (`code-plus`) with top-right watermark background badges and line-targeted speech-bubble cloud comments (`.cmt-bubble`) as the default compilation pipeline output across all lectures, while keeping the alternative legacy compact format available via the `--compact-principles` CLI flag. It standardizes the Line-Targeted Speech-Bubble Comment Model Standard with four canonical exemplars drawn from Lesson 05 (JSX nesting, layout decomposition, top-down render walk, and closest common ancestor data routing), and enforces the Single-Page Callout Budget to eliminate broken, multi-page principle spreads.

## 1. Root Cause Analysis

### 1.1 The Compact Box vs. Full-Width Readability Conflict
Previously, principle code cards were rendered inside the standard content column width (~450px) using dense `<pre><code>` blocks and trailing comments that frequently bumped into horizontal width limits or caused ugly line wrapping. Users requested a dedicated full-length format (`code-plus`) that breaks out to the full editor width (~710px), applies generous monospace typography, and includes top-right watermark badges.

### 1.2 Disconnected Comments and Vague Slogans
Inline comments inside principle cards were often vague ("here we add elements", "branch container", "counter-example") or laden with corporate buzzwords ("owning masthead branding", "application truth"). Furthermore, when rendered inside `<pre><code>` blocks, comments did not visually align with the specific elements they described. By extracting inline comments into upward-pointing speech bubble clouds (`.cmt-bubble`) placed directly beneath target code lines, comments now visually and physically point to the exact JSX tag or statement being taught.

### 1.3 Principle Break Across Page Boundaries
When comments were expanded into speech bubbles, the vertical height of `.callout-principle` grew. Because the definition card, case headers, and padding had loose margins, total callout height exceeded the ~970px printable height of an A4 page, forcing Prince to break the callout mid-block (pushing the counter-example onto the next page and creating the false impression that the counter-example was missing). Tightening the vertical rhythm and enforcing compact 4-to-8 line snippets guarantees that both cards fit together on a single page.

## 2. Resolution

### 2.1 Default Code-Plus Pipeline (`src/build-lectures.mjs` & `src/lecture.css`)
- Integrated `code-plus` transformations directly into `processCaseSnippet` in `src/build-lectures.mjs`:
  - Tokenizes code lines into `.case-code-line` flex items (`white-space: pre; line-height: 1.40;`).
  - Extracts inline comments `// ...` into `.cmt-bubble` speech clouds with upward pointer tails (`▲`) aligned with indentation (`--indent-offset`).
  - Injects top-right watermark background badges (`.case-watermark-bg`, 44px, opacity 0.18) matching card icons.
- Baked responsive, tight vertical rhythm styles into `src/lecture.css` so both cases fit on one page.
- Retained the alternative legacy format via `node src/build-lectures.mjs --compact-principles` (or `--legacy-principles`), which applies the `.compact` modifier class.

### 2.2 Principled Theory Skill (`skills/v6.3/principled-theory/SKILL.md`)
- Added **The Line-Targeted Speech-Bubble Comment Model Standard** under Section 01:
  - Line-targeted precision: every comment attaches directly to the code line it explains.
  - Plain, conversational human English: strictly bans corporate slogans ("masthead", "brand ownership", "application truth").
  - Concrete explanatory role: states plainly *what this specific element does* or *why this exact line fails*.
  - Single-Page Callout Budget: mandates 4–8 lines per card and max 2–3 comment bubbles so both cards fit on a single page.
- Added **The Targeted Speech-Bubble Comment Canon (The 4 Core Architectural Models)** with PROPER examples drawn verbatim from Lesson 05:
  1. *Model 1: Component Hierarchy & JSX Nesting* (`EditorialByline` nested inside `ArticleCard` vs function declaration order).
  2. *Model 2: Layout Decomposition* (`NewsHeader` and `EditorialFeed` branch containers vs monolithic inlined markup).
  3. *Model 3: Top-Down Render Walk* (`EditorialFeed` evaluating before child `ArticleCard` vs omitted child never running).
  4. *Model 4: Unidirectional Data Flow* (passing `edition` through common ancestor `App` vs horizontal sibling scope crash).

### 2.3 Build Skill (`skills/v6.3/build/SKILL.md`)
- Updated Section 01 and core command examples to document `node src/build-lectures.mjs` as compiling full-width `code-plus` principles by default, and `node src/build-lectures.mjs --compact-principles` as the alternative format.
