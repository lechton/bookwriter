# Brief 2026-09-20-22: The One-by-One Revision & Build Pipeline and Control Directives

## 1. Context & Autopsy of the Defect

During lecture revision workflows, there was a tendency to batch-author multiple revised Markdown files (e.g. `01.md` through `05.md`) in one continuous pass, waiting until all Markdown files were written before compiling any PDFs.

An autopsy identified why this delayed-batch workflow is defective:
1. **Compounding Pattern Defects**: When an agent or author makes an uninspected stylistic choice (such as a 23-word clause-chained sentence or an idiosyncratic failure scenario), that choice is replicated across all subsequent Markdown files in the batch before any visual layout is seen.
2. **Concealed Visual & Print Breaks**: The Markdown source cannot show Prince XML typesetting results, mid-word hyphenations ("el-ement", "con-ventions"), card border collisions, or page fit overflows. Waiting until the end to build all PDFs conceals these defects until cleanup is 5x more expensive.
3. **Broken Feedback Loop**: A revision workflow must provide tight, immediate feedback. Compiling and inspecting the PDF for Lecture N immediately guarantees that Lecture N is 100% solid before touching Lecture N+1.

## 2. Technical Decisions & Rules Added

We codified the One-by-One Revision & Build Pipeline across `skills/` under tag `#2026_09_20_22_group_1`:

1. **`skills/lecture-revision/SKILL.md` (Revision Workflow 00)**:
   - Added Revision Workflow 00 (*The One-by-One Revision & Build Pipeline: MD ➔ PDF ➔ Verify ➔ Next*):
     1. Revise Markdown for Lecture N (`02-01-md-revised/{N}.md`).
     2. Immediately compile the PDF for Lecture N (`node src/build-lectures.mjs`).
     3. Verify Gate & Layout (zero Prince warnings, no mid-word hyphenations, no code overflow, 8-gate compliance).
     4. Advance to Lecture N+1 only after Lecture N is fully verified and clean.
   - Strictly banned batch-authoring all Markdown files before building PDFs.
   - Provided explicit COUNTER-EXAMPLE (delayed-batch pass) and PROPER EXAMPLE (single-lecture cycle).

2. **`skills/verification/SKILL.md` (Audit Protocol 05)**:

## 3. Clarification on Control Directives

- **`ppp`**: Means ONLY "proceed" — execute the approved plan or action immediately without asking further confirmation. It does NOT mean "execute both instruction updates and lecture revisions."
- **`ppi`**: Means proceed to edit instructions and skills ONLY, stopping the moment instructions and skills are finished, and never editing lectures or other files.
- **`nnn`**: Means chat-only discussion; never edit files or run modifying commands.
