# Q114: Reading Form Pending State: The useFormStatus Hook
* **Topic Tag**: #use_form_status | ❱ CORE (Server)
* **Interview Question**: *How does a nested field read the form's pending state during a server action?*
* **Core Truth**: useFormStatus is a specialized hook that reads the status of the parent <form> from React's internal context, giving deeply nested submit buttons and inputs access to pending, data, method, and action without prop drilling.
* **The Friction**: A shared design-system SubmitButton at The National Times sits inside a modal, wrapped in four layers of editorial layout components; to show a "Publishing..." spinner and disable double-clicks during an action, developers drill isPending through every intermediate component.
* **The Mechanism**: const { pending, data, method, action } = useFormStatus(): must be called from a component rendered inside a <form>; returns whether the enclosing form is currently submitting, the FormData being submitted, and the form method.
* **Under the Hood**: Implicit Form Context: React's <form> component internally provides a context holding the current action execution status; useFormStatus subscribes to this context, which is why it must be in a child component of the form, not in the component rendering the <form> itself.
* **The Code Experiment**:
  * *Naive*: Calling useFormStatus in the same component that renders <form>, which returns pending: false because the hook cannot read its own form's context.
  * *React*: Extracting <SubmitButton /> into a separate child component that calls useFormStatus to display "Saving..." and disable itself while pending.
* **Scope Boundary**: Focus on useFormStatus, the requirement that it be called from a child component of the form, and what properties it exposes.
