# Q05: UI as a Tree and Component Hierarchy
* **Topic Tag**: `#ui_tree` | `❱ CORE`
* **Interview Question**: *How does React organize nested components into a tree, and why does hierarchy dictate data flow?*
* **Core Truth**: React models interfaces as a hierarchical tree of nested component elements; understanding this structural tree is the prerequisite for data flow, subtree rendering, and architectural composition.
* **The Friction**: Marcus views an application as a flat collection of files and pasted HTML snippets. When one component needs to communicate with another, he tries to reach across horizontally or embed heavy dependencies everywhere, unaware of parent-child hierarchy.
* **The Mechanism**: Component Tree hierarchy. Top-level root (`App`), intermediate branch containers (`Header`, `Main`), and terminal leaf components (`ArticleCard`, `EditorialByline`).
* **Under the Hood**: How JSX nesting (`<App><Header /><Main><ArticleCard /></Main></App>`) forms a tree of React element objects with parent-child-ancestor relationships, governing how React visits nodes during rendering.
* **The Code Experiment**:
  * *Naive*: A monolithic single-function layout dumping all header, feed, and footer elements in one 500-line block.
  * *React*: Decomposed tree with `App` nesting `NewsHeader` and `EditorialFeed`, forming a clean structural hierarchy.
* **Scope Boundary**: Focus strictly on the structural component tree and nesting relationships. Do not introduce dynamic props destructuring, state, or effects.
