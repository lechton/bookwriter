# Q105: Hydration Mismatches: Causes, Warnings, and Remediation
* **Topic Tag**: #hydration_errors | ❱ CORE (Server)
* **Interview Question**: *What causes hydration mismatches, and how do you fix them?*
* **Core Truth**: Hydration mismatches occur when the client render produces a different virtual DOM tree than the server-generated HTML, forcing React to discard server markup, log loud console warnings, and incur performance penalties.
* **The Friction**: A weather widget in the header displays "Published: 2:00 AM UTC" from the server, but on the client it renders "Published: 9:00 PM EST" using new Date().toLocaleTimeString(); React throws an ugly hydration mismatch error in DevTools, and text flickers violently on page load.
* **The Mechanism**: Root causes and fixes: (1) Non-deterministic values (Date.now(), Math.random()); (2) Browser-only globals (window.innerWidth, localStorage); (3) Invalid HTML nesting (e.g. <p> inside <p>, or <div> inside <p>); Remediation: two-pass rendering with useEffect or suppressHydrationWarning.
* **Under the Hood**: Tree reconciliation during hydration: when React's reconciler encounters a mismatch between a Fiber node and the current DOM node during hydration, in development it logs a detailed diff (Server vs Client) and marks the fiber with a hydration error flag, falling back to client rendering for that subtree.
* **The Code Experiment**:
  * *Naive*: Rendering <span>{typeof window !== 'undefined' ? window.innerWidth : 1200}</span> directly in render, triggering an inevitable hydration mismatch.
  * *React*: Using a two-pass render with useEffect or useSyncExternalStore so the server and client initial render match, updating the client-only value after mount.
* **Scope Boundary**: Focus on diagnosing, preventing, and fixing hydration errors. Do not cover general error boundaries or server crash errors.
