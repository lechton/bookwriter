# Q91: Typing Hooks with Strict TypeScript Generics
* **Topic Tag**: `#typescript_hooks` | `❱❱❱ ADVANCED`
* **Interview Question**: *How do you type useState, useReducer, and useRef with strict TypeScript generics?*
* **Core Truth**: Explicit TypeScript generics on hooks ensure type safety for union states (`useState<User | null>`), enforce exhaustive action branching via discriminated unions in `useReducer`, and distinguish read-only DOM refs from mutable containers in `useRef`.
* **The Friction**: An article editor starts with `const [user, setUser] = useState(null)`. TypeScript infers the type as `null`, causing `setUser({ id: '1', name: 'Alice' })` to fail type checking; meanwhile, `useRef<HTMLInputElement>(null)` is accidentally mutated as a number, triggering runtime crashes.
* **The Mechanism**: Hook generics: `useState<Article | null>(null)`, discriminated action unions in `useReducer<React.Reducer<State, Action>>(reducer, initial)` (`type Action = { type: 'edit'; text: string } | { type: 'reset' }`), and distinguishing `useRef<HTMLDivElement>(null)` (read-only DOM node) from `useRef<number | null>(null)` (mutable value box).
* **Under the Hood**: TypeScript overload resolution for hooks: `useRef` has two distinct overloads—passing an initial value matching the generic type yields a mutable `RefObject<T>`, while passing `null` with a non-null generic yields a `RefObject<T>` with read-only `.current` tailored for DOM elements.
* **The Code Experiment**:
  * *Naive*: Relying on default inference for nullable state or typing reducer actions as `{ type: string; payload?: any }`, losing autocomplete and exhaustiveness checks.
  * *React*: A `NewsroomWorkspace` typing nullable article state with union generics, discriminated actions in a reducer, and strictly typing DOM vs timer refs.
* **Scope Boundary**: Focus on typing `useState`, `useReducer`, and `useRef`. Do not introduce generic component definitions (Q92) or polymorphic typing (Q93).
