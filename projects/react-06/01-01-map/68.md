# Q68: Deferring Values with useDeferredValue
* **Topic Tag**: `#use_deferred_value` | `❱❱ MORE`
* **Interview Question**: *What does useDeferredValue defer, and how is it different from a transition?*
* **Core Truth**: `useDeferredValue` accepts a value and returns a deferred version of it that lags behind during urgent updates, allowing child components to render with the old value while a new concurrent render computes in the background.
* **The Friction**: A parent component receives `query` as a prop from an external input outside its control. Because the child component does not own the state setter, it cannot wrap the update in `startTransition`, leaving the child unable to prevent input freezing during heavy re-renders.
* **The Mechanism**: The `useDeferredValue` hook (`const deferredQuery = useDeferredValue(query)`). React renders immediately with the old `deferredQuery`, and concurrently prepares a second render in the background with the new value.
* **Under the Hood**: Dual-render scheduling: when `query` changes, React first performs an urgent render using the new `query` but keeping `deferredQuery` at its old value; once the urgent render paints, React launches a background transition render with the updated `deferredQuery`.
* **The Code Experiment**:
  * *Naive*: A child `SearchResults` component re-rendering immediately on every prop change, lagging the parent input.
  * *React*: `SearchResults` using `const deferredQuery = useDeferredValue(query)`, styling the list with reduced opacity (`deferredQuery !== query ? 0.6 : 1`) while the new list calculates.
* **Scope Boundary**: Focus on `useDeferredValue`, comparing it with `useTransition` (wrapping state setters vs deferring received values), and stale value indicators. Do not cover Suspense integration yet (Q69).
