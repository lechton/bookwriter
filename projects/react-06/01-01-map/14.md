# Q14: Component Memory with useState
* **Topic Tag**: `#use_state` | `❱ CORE`
* **Interview Question**: *Why do ordinary variables forget their values between renders, and how does useState remember?*
* **Core Truth**: A local variable is created fresh each time React calls the component function, and changing it tells React nothing; `useState`, a Hook React provides, keeps a value for this component between renders and returns a setter function that stores the next value and asks React to render the component again.
* **The Friction**: A developer implements an article bookmark toggle with `let isBookmarked = false` inside `ArticleCard`. On click, `isBookmarked = !isBookmarked` changes the variable, but the bookmark icon stays gray: assigning a local variable does not trigger a render, and whenever something else re-renders the card, the function runs again from the top and `isBookmarked` starts over at `false`.
* **The Mechanism**: The `useState` Hook (`const [isBookmarked, setIsBookmarked] = useState(false)`), called at the top level of the component. It returns a pair: the value for this render and a setter. Calling `setIsBookmarked(true)` stores the new value inside React and queues a render, and on that render `useState` returns `true`. A component can call `useState` several times to keep several independent values.
* **Under the Hood**: React keeps state outside the component function, attached to the component's position in the tree, and tells the `useState` calls apart by the order in which the component makes them (why that order must never change belongs to Q37). State belongs to one rendered instance: two `<StoryCard />` elements on the same page each keep their own count, and their parent can neither read nor change it.
* **The Code Experiment**:
  * *Naive*: Incrementing a local `let likes = 0` variable on button click; the UI never re-renders, and any future render resets `likes` back to `0`.
  * *React*: A `StoryCard` with `const [likes, setLikes] = useState(0)` where clicking the button calls `setLikes(likes + 1)`, so React renders the card again with the new count, while a second `StoryCard` beside it keeps its own count.
* **Scope Boundary**: Focus strictly on why local variables fail, the `useState` pair and its array destructuring `[value, setValue]`, multiple state variables, and state being private to each instance. Do not cover what happens between the setter call and the screen update (Q15), state as a snapshot (Q16), or updater functions (Q17).
