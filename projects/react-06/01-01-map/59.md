# Q59: Caching Function References with useCallback
* **Topic Tag**: `#use_callback` | `❱❱ MORE`
* **Interview Question**: *What does useCallback do, and when do you actually need it?*
* **Core Truth**: `useCallback` caches a function definition between renders so its reference identity remains stable, which is necessary only when passing callbacks to memoized child components or as effect dependencies.
* **The Friction**: An `ArticleCard` wrapped in `React.memo` receives an `onBookmark` handler: `const handleBookmark = () => bookmark(id)`. Because a new function reference is created every render, `React.memo` detects a prop change and re-renders the card anyway, rendering the memoization completely useless.
* **The Mechanism**: The `useCallback` hook (`const cachedFn = useCallback(() => { doSomething(a, b); }, [a, b])`). React holds onto the same function instance across renders until dependencies change.
* **Under the Hood**: `useCallback(fn, deps)` is syntactic sugar for `useMemo(() => fn, deps)`; it preserves the function reference in the fiber's hook record, allowing child `React.memo` shallow prop checks (`prev.onClick === next.onClick`) to evaluate to `true`.
* **The Code Experiment**:
  * *Naive*: Wrapping every function in `useCallback` even when passed to unmemoized native HTML tags (`<button onClick={...}>`), wasting memory and lines of code.
  * *React*: Passing a `useCallback`-stabilized `handleShare` callback to a memoized `SocialShareToolbar`, successfully preventing the toolbar from re-rendering when the article body updates.
* **Scope Boundary**: Focus on `useCallback` for reference stability with `React.memo` and effect dependencies. Contrast with `useMemo`. Do not cover architectural composition alternatives (Q60).
