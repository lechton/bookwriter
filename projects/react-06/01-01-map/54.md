# Q54: Subscribing to External Stores with useSyncExternalStore
* **Topic Tag**: `#use_sync_external_store` | `❱❱ MORE`
* **Interview Question**: *How do you subscribe to a store that lives outside React?*
* **Core Truth**: `useSyncExternalStore` provides a concurrency-safe bridge to subscribe to non-React mutable stores (browser APIs, global state libraries) guaranteeing synchronous reads and preventing visual tearing during concurrent rendering.
* **The Friction**: A newsroom app listens to browser network connectivity (`navigator.onLine`) or a third-party analytics store using `useEffect` and `useState`. During concurrent rendering, React pauses and resumes rendering across multiple frames; an external mutation mid-render causes different components to read conflicting values, resulting in "tearing".
* **The Mechanism**: The `useSyncExternalStore` hook (`useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)`). React registers the subscription and calls `getSnapshot()` synchronously to ensure all components read a consistent state slice during every render.
* **Under the Hood**: Concurrency and tearing prevention: mutable external stores don't participate in React's immutable snapshot system. `useSyncExternalStore` forces React to detect if the store changed during an ongoing render pass, restarting the render synchronously if a tear occurs.
* **The Code Experiment**:
  * *Naive*: Subscribing to `window.addEventListener('resize')` inside `useEffect` and setting state, risking inconsistent window dimension reads during heavy concurrent renders.
  * *React*: Creating a `useWindowWidth` hook using `useSyncExternalStore` to cleanly subscribe to window resize events with deterministic snapshots.
* **Scope Boundary**: Focus on the purpose of `useSyncExternalStore`, tearing prevention, and subscribing to native browser APIs. Do not build full custom state management libraries.
