# Q135: Advanced Boundary Serialization: Dates, Maps, Sets, and Promises
* **Topic Tag**: #serializable_props | ❱❱ MORE (Server)
* **Interview Question**: *Which special values cross the boundary: dates, maps, sets, promises, and typed arrays?*
* **Core Truth**: React's Flight protocol goes beyond standard JSON by natively serializing Date, Map, Set, BigInt, ArrayBuffer, typed arrays, and unresolved Promise objects across the server/client boundary, but silently rejects class instances and standard functions.
* **The Friction**: A developer at The National Times passes an editorial publication timestamp article.publishedAt (a JavaScript Date instance) and a Set of topic tags to a client component, expecting them to turn into plain strings or arrays; another passes a class instance new ArticleModel(), which crashes the build with a serialization violation.
* **The Mechanism**: Extended serialization types: Date (reconstructed as real Date on client), Map and Set (reconstructed with full methods), BigInt, Uint8Array, and Promise (unresolved promises can be streamed and read with use()); plain objects and arrays are preserved; class instances lose prototype chains or fail build.
* **Under the Hood**: Flight encoding tags: React Flight serializes values with type prefixes (e.g. "$D" for Date ISO strings, "$Q" for Maps, "$W" for Sets, "$n" for BigInt); the client Flight parser decodes these type tags and reconstructs authentic JavaScript objects rather than raw JSON primitives.
* **The Code Experiment**:
  * *Naive*: Passing a custom class instance with methods new UserSession() across the server/client boundary, stripping all prototype methods.
  * *React*: Passing native Date, Set, and Promise objects directly across the boundary, consuming them natively in the Client Component.
* **Scope Boundary**: Focus on the extended serialization capabilities of Flight beyond JSON (Dates, Sets, Maps, Promises, TypedArrays) and the fate of class prototypes.
