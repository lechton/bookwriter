# Q143: Hydration Bootstrapping: The Role of bootstrapScripts and bootstrapModules
* **Topic Tag**: #bootstrap_scripts | ❱❱ MORE (Server)
* **Interview Question**: *What are bootstrapScripts and when does the page hydrate?*
* **Core Truth**: bootstrapScripts and bootstrapModules options in server render streams inject the initial client entrypoint <script> tags into the HTML stream, orchestrating when the browser downloads the bundle and invokes hydrateRoot.
* **The Friction**: A newly deployed article page at The National Times streams beautiful HTML instantly, but the interactive "Font Size Adjuster" and audio player remain dead forever; the infrastructure team forgot to pass bootstrapModules to renderToPipeableStream, so the browser never downloads the client JavaScript bundle.
* **The Mechanism**: Stream options: renderToPipeableStream(jsx, { bootstrapModules: ['/main.js'], bootstrapScriptContent: 'window.ENV = "prod";' }): React injects <script type="module" src="/main.js" async></script> into the HTML stream; the browser downloads the module in parallel with HTML streaming and executes hydrateRoot.
* **Under the Hood**: Script injection timing: React injects the bootstrap script tags immediately after the initial shell chunk; because they are marked async or type="module", the browser begins fetching the client JavaScript concurrently while the server streams deferred Suspense chunks.
* **The Code Experiment**:
  * *Naive*: Manually hardcoding <script src="/bundle.js"> at the bottom of a root layout component, which interferes with React's stream chunk ordering.
  * *React*: Passing bootstrapModules: ['/client/entry.js'] directly to renderToPipeableStream so React coordinates script placement and hydration lifecycle.
* **Scope Boundary**: Focus on bootstrapScripts, bootstrapModules, bootstrapScriptContent, and how they initiate client hydration.
