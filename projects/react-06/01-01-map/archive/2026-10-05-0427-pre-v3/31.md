# Q31: Combining Reducer with Context for App-Wide State
* **Topic Tag**: `#reducer_context` | `❱ CORE`
* **Interview Question**: *How do you combine a reducer with context for app-wide state?*
* **Core Truth**: Combining `useReducer` with Context allows providing state and dispatch through separate contexts to the entire component tree, enabling any descendant to read state or dispatch actions without prop drilling.
* **The Friction**: An editorial workspace manages a live article queue. The queue state and its ten transition functions (`addStory`, `removeStory`, `reorderQueue`, `archive`) must be drilled through five layout layers (`Workspace` -> `SplitPane` -> `Sidebar` -> `QueueList` -> `QueueItem`), polluting intermediate components with props they never touch.
* **The Mechanism**: The Reducer + Split Context pattern: create `QueueContext` (for state) and `QueueDispatchContext` (for dispatch). The provider calls `const [queue, dispatch] = useReducer(queueReducer, initialQueue)` and wraps children in both context providers.
* **Under the Hood**: Why split contexts: separating the state context from the dispatch context ensures that components that only dispatch actions (like an "Add Story" button) do not re-render when the queue state changes, optimizing the render tree.
* **The Code Experiment**:
  * *Naive*: Drilling `queue` and ten distinct event handler functions down through five intermediate component layers.
  * *React*: An `ArticleQueueProvider` exposing `useQueue()` and `useQueueDispatch()` custom hooks, allowing deep buttons to dispatch actions directly without touching intermediate props.
* **Scope Boundary**: Focus on combining `useReducer` and Context with split state/dispatch providers. Do not introduce Redux, Zustand, or external state managers.
