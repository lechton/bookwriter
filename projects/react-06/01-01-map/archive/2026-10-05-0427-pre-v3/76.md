# Q76: JSX Transpilation and React Element Objects
* **Topic Tag**: `#create_element_deep` | `❱❱❱ ADVANCED`
* **Interview Question**: *What does JSX compile into, and what is an element object?*
* **Core Truth**: JSX compiles into `jsx()` or `createElement()` function calls that return plain, immutable JavaScript element objects containing `type`, `props`, `key`, and a security-protecting `$$typeof: Symbol.for('react.transitional.element')`.
* **The Friction**: Developers often believe JSX creates real DOM elements or that React elements are heavy class instances. This misunderstanding leads to fear of creating JSX elements in helpers, or worse, vulnerabilities where user-supplied JSON from an API could spoof a React element and inject arbitrary HTML (XSS).
* **The Mechanism**: The React Element Object. JSX `<h1 className="title">Hello</h1>` compiles to `_jsx('h1', { className: 'title', children: 'Hello' })`, producing a lightweight frozen object `{ $$typeof, type, key, props }`.
* **Under the Hood**: XSS defense via `$$typeof`: JSON cannot store JavaScript `Symbol` primitives (`JSON.stringify` drops symbols or cannot serialize `Symbol.for`); if an attacker tries to inject `{ type: 'div', props: { dangerouslySetInnerHTML: ... } }` via a JSON API, React detects the missing or invalid `$$typeof` symbol and refuses to render it.
* **The Code Experiment**:
  * *Naive*: Assuming `<Card />` is an active DOM node or instance, attempting to call DOM methods like `.focus()` directly on the JSX expression.
  * *React*: Logging a JSX element `console.log(<ArticleCard title="News" />)` to inspect its raw `{ $$typeof, type, props, key }` structure, demonstrating that it is an inert data description.
* **Scope Boundary**: Focus strictly on JSX compilation output (`_jsx`/`createElement`), the structure of React elements, and the security role of `$$typeof`. Do not cover Fiber node data structures yet (reserved for Q78).
