# Q113: Managing Action Results: Errors and State with useActionState
* **Topic Tag**: #action_results | ❱ CORE (Server)
* **Interview Question**: *How do a Server Function's return values and errors reach the UI?*
* **Core Truth**: useActionState manages the lifecycle of a form action, capturing returned values, validation errors, and pending state across transitions, allowing Server Function results to seamlessly update the UI.
* **The Friction**: An editor at The National Times submits an article publish form with a missing headline; the server action returns { error: 'Headline is required' }, but because the form used a raw server action without state tracking, the error disappears into the void and the editor is left staring at an unresponsive screen.
* **The Mechanism**: const [state, formAction, isPending] = useActionState(actionFn, initialState, permalink?): binds a form action, tracks pending execution, and stores the latest result in state to render inline errors and feedback.
* **Under the Hood**: Transition coordination in useActionState: useActionState wraps the action invocation in an internal transition; when the action promise resolves or rejects, React updates the hook's internal Fiber state and re-renders the component with the new result without manual useState wiring.
* **The Code Experiment**:
  * *Naive*: Manually maintaining const [error, setError] = useState(null) and wrapping server calls in ad-hoc try/catch blocks that lose pending transition state.
  * *React*: Using const [state, formAction, isPending] = useActionState(updateStory, null) to display inline server validation errors and disable submit while pending.
* **Scope Boundary**: Focus on useActionState API, managing return values and errors from Server Functions. For nested pending state without prop drilling, see useFormStatus (Q114).
