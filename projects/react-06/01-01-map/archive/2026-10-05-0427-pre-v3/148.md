# Q148: Cache Completion Coordination: The cacheSignal API
* **Topic Tag**: #cache_signal | ❱❱ MORE (Server)
* **Interview Question**: *What is cacheSignal and when is caching 'done'?*
* **Core Truth**: cacheSignal() returns an AbortSignal tied to the lifecycle of the current request cache, signaling when all pending cached asynchronous operations have completed or when the request context has been aborted.
* **The Friction**: A custom background telemetry logger at The National Times tries to read cached editorial metrics after a server render finishes; because the request ended, the cache was already invalidated, causing unhandled promise rejections and leaked background fetch operations.
* **The Mechanism**: const signal = cacheSignal(): provides an AbortSignal that aborts when the request ends or the render pass aborts; can be passed to fetch(url, { signal }) to automatically cancel in-flight fetches when the render pass is abandoned.
* **Under the Hood**: Lifecycle binding: cacheSignal ties downstream asynchronous fetch calls directly to the life of the server render; if the client disconnects or a prerender times out, cacheSignal fires an abort event, preventing orphaned backend queries from running to completion.
* **The Code Experiment**:
  * *Naive*: Initiating long-running database or API calls inside cached functions without an abort signal, leaving zombie connections open after the client disconnects.
  * *React*: Passing cacheSignal() to outgoing fetch calls (fetch('/api/feed', { signal: cacheSignal() })), ensuring automatic cancellation when the render pass finishes or aborts.
* **Scope Boundary**: Focus on cacheSignal(), its relation to AbortSignal, and managing asynchronous cancellation in server render lifecycles.
