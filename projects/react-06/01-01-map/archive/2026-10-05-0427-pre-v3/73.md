# Q73: Preserving Subtree State with `<Activity>`
* **Topic Tag**: `#activity_component` | `❱❱ MORE`
* **Interview Question**: *How do you hide a subtree without losing its state with <Activity>?*
* **Core Truth**: The `<Activity>` component (formerly Offscreen) allows hiding a component subtree visually and deprioritizing its background effects while preserving its full DOM and state memory across tab or view switches.
* **The Friction**: An investigative reporter types complex search filters and scrolled down 400 items in the "Archive Search" tab, then clicks "Live Feed" to check breaking news. When they click back, the archive component has unmounted, completely wiping out their search query, scroll position, and active filters.
* **The Mechanism**: The `<Activity mode={isActive ? 'visible' : 'hidden'}>` component. When set to `'hidden'`, React hides the DOM (via `display: none` / content-visibility), pauses effects and timers, but keeps the fiber tree and internal state alive in memory.
* **Under the Hood**: Offscreen fiber management: React retains the component's fiber nodes and DOM elements in memory, deprioritizing any scheduled updates to the lowest background lane; when switched back to `'visible'`, the component instantly reappears without the latency of remounting or re-fetching.
* **The Code Experiment**:
  * *Naive*: Conditionally unmounting tabs (`{tab === 'archive' && <Archive />}`), destroying user draft state and scroll position on every tab switch.
  * *React*: Wrapping tab panels in `<Activity mode={currentTab === tab.id ? 'visible' : 'hidden'}>`, maintaining instant switching and pristine preserved state.
* **Scope Boundary**: Focus on the `<Activity>` component, `mode="visible" | "hidden"`, and the mental model of pre-rendering and background suspension. Do not confuse with CSS `display: none` alone.
