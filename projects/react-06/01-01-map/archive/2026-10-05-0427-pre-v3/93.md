# Q93: Polymorphic Components with the "as" Prop
* **Topic Tag**: `#typescript_polymorphism` | `❱❱❱ ADVANCED`
* **Interview Question**: *How do you build polymorphic components with the as prop in TypeScript?*
* **Core Truth**: Polymorphic components dynamically switch their underlying HTML element or component using an `as` prop while preserving strict TypeScript type safety for element-specific HTML attributes.
* **The Friction**: A design system `Button` must render as an `<button>` by default, but as an `<a>` link when given `href="/breaking-news"`. If implemented naively with loose types, TypeScript either rejects `href` on buttons or allows invalid combinations like passing `href` to `<button>` or `disabled` to `<a>`.
* **The Mechanism**: Polymorphic typing with TypeScript generics: `type PolymorphicProps<E extends React.ElementType, P> = P & { as?: E } & Omit<React.ComponentPropsWithoutRef<E>, keyof P | 'as'>`. The component computes valid HTML attributes based on the resolved `as` element.
* **Under the Hood**: Type-level subtraction and intersection: `React.ComponentPropsWithoutRef<E>` extracts the exact HTML attributes for tag `E`; using `Omit` avoids prop collisions, ensuring that when `as="a"`, TypeScript enforces `href` and forbids invalid button attributes.
* **The Code Experiment**:
  * *Naive*: Typing a button with an optional `href` prop and using conditional ternaries inside JSX, failing to type-check valid HTML attributes for anchors vs buttons.
  * *React*: A polymorphic `ActionControl` component accepting `as="a" | "button"` that provides full autocomplete for `href` and `target` when rendered as an anchor.
* **Scope Boundary**: Focus on the architecture and type-level implementation of the polymorphic `as` prop. Do not introduce third-party component libraries.
