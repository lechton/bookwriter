# Q171: Cache Identity and Cache Key Semantics
* **Topic Tag**: #cache | ❱❱❱ ADVANCED (Server)
* **Interview Question**: *What defines cache identity: which calls share results and which never will?*
* **Core Truth**: React's cache() derives cache identity exclusively from function instance identity and shallow argument equality via Object.is, meaning inline function definitions, new object literals, or differing server request lifecycles will never share cached values.
* **The Friction**: During live election night coverage at The National Times, server database queries for election results spike tenfold despite developers wrapping the query in cache(); the team discovers that an inline helper function redefined inside a component and passing new query filter objects destroyed cache hit rates completely.
* **The Mechanism**: cache(fn): wraps a data-fetching function at module scope; arguments are compared using Object.is across the current server request context; identical primitive arguments or referentially identical objects share the cached promise or result, while distinct function instances or new object references create separate cache entries.
* **Under the Hood**: Internal WeakMap and Map graph: React stores cached results in an AsyncLocalStorage-backed request store using a multi-level tree of Map (for primitives) and WeakMap (for objects) keyed first by function identity, then sequentially by each argument via Object.is; when the server request terminates, the entire cache store is dereferenced and garbage-collected.
* **The Code Experiment**:
  * *Naive*: Wrapping a database query with `cache()` defined inside a component body and calling it with inline object literals `fetchStory({ id: 42 })`, generating a fresh function instance and object reference on every render that completely misses the cache.
  * *React*: Defining `const getStory = cache((id) => db.story.find(id))` once at top-level module scope and calling it with stable primitive identifiers (`getStory(42)`), guaranteeing identical cache lookups across all server components in that request.
* **Scope Boundary**: Do not re-explain basic deduplication concepts (covered in Q116) or Next.js fetch cache/unstable_cache extensions; focus strictly on React's native cache() identity rules, argument equality semantics (Object.is), and AsyncLocalStorage-backed multi-level Map/WeakMap internals.
