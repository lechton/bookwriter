# Q22: Updating Arrays in State
* **Topic Tag**: `#state_arrays` | `❱ CORE`
* **Interview Question**: *How do you add, remove, insert, and reorder items in a state array?*
* **Core Truth**: State arrays must be treated as read-only; every list modification (adding, removing, inserting, sorting) must produce a new array using non-mutating array methods like `.concat()`, `.filter()`, `.map()`, and `[...slice, newItem, ...slice]`.
* **The Friction**: An editor reorders the breaking news ticker or deletes a published typo from the lineup. The developer uses `stories.push(newStory)`, `stories.splice(index, 1)`, or `stories.sort()`. Because mutating methods alter the array in place without changing its array reference, React bails out of re-rendering, leaving stale and ghost stories visible on screen.
* **The Mechanism**: Immutable array operations: adding with spread (`[...stories, newStory]`), removing with `.filter()` (`stories.filter(s => s.id !== id)`), transforming with `.map()`, and inserting/reordering via `.slice()` and spread.
* **Under the Hood**: Mutating vs non-mutating array prototype methods in JavaScript; how in-place mutations poison React's internal fiber memoizedState reference, breaking time-travel debugging, concurrency, and shallow reconciliation bailing.
* **The Code Experiment**:
  * *Naive*: Calling `.push()` or `.splice()` directly on state arrays inside event handlers and calling `setStories(stories)`.
  * *React*: A `NewsTicker` manager implementing clean immutable operations for adding, removing, and updating stories using `.filter()`, `.map()`, and spread syntax.
* **Scope Boundary**: Focus on immutable recipes for array operations in state. Do not introduce drag-and-drop libraries or virtualization (Q62).
