# Q100: Abandoned Patterns: cloneElement, Children Utilities, and defaultProps
* **Topic Tag**: #legacy_patterns | LEGACY
* **Interview Question**: *What were cloneElement, the Children utilities, and defaultProps for, and why were they abandoned?*
* **Core Truth**: cloneElement, React.Children utilities, and defaultProps were legacy patterns for injecting props and manipulating child trees that modern React abandoned in favor of JavaScript default parameters, Context, and explicit composition.
* **The Friction**: An old layout component at The National Times uses React.Children.map(props.children, child => React.cloneElement(child, { activeTheme })); when an engineer passes a Fragment or a nested component as a child, cloneElement silently fails or injects props into the wrong element, creating brittle, unpredictable layouts.
* **The Mechanism**: Deprecated patterns and modern replacements: (1) defaultProps on function components (abandoned in favor of ES6 default parameters { theme = 'light' }); (2) cloneElement (replaced by Context or render props); (3) React.Children utilities (map, count, only, replaced by passing arrays or slots).
* **Under the Hood**: Fragility of runtime element inspection: cloneElement and React.Children inspect and clone opaque React element objects at runtime, breaking encapsulation, breaking TypeScript type safety, and making it impossible for the React Compiler to optimize the component tree.
* **The Code Experiment**:
  * *Naive*: Using React.cloneElement to secretly inject theme and onClick into children, breaking when children are wrapped in a div or Fragment.
  * *React*: Refactoring a legacy ButtonGroup from React.Children.map and cloneElement to a modern Context-based compound component (ButtonContext).
* **Scope Boundary**: Focus on why cloneElement, React.Children, and defaultProps were phased out, and how to refactor them to Context, default parameters, and slots. Concludes Part One of the curriculum.
