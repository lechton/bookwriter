# Q161: Bundler and Router Integration: Fulfilling the RSC Contract
* **Topic Tag**: #bundler_integration | ❱❱ MORE (Server)
* **Interview Question**: *What must a bundler and router provide for RSC to work?*
* **Core Truth**: React Server Components require a bundler to split the module graph into server/client manifests and an RSC-aware router to request and reconcile Flight streams on client navigation.
* **The Friction**: An architect at The National Times tries to use RSC with a vanilla Webpack setup without an RSC plugin or specialized router; client navigation attempts to fetch HTML documents rather than RSC payloads, breaking client component state and triggering full page refreshes.
* **The Mechanism**: The RSC contract: (1) React provides runtime APIs (react-server-dom-*); (2) Bundler provides module splitting, client reference manifests, and server action transforms; (3) Router intercepts navigations, requests ?_rsc=... Flight payloads, and passes them to use() or React root.
* **Under the Hood**: Separation of responsibilities: React itself provides no file-system routing or bundling; it defines the serialization format and reconciler; the bundler maps module IDs to URLs, and the router coordinates URL changes with RSC payload stream fetches.
* **The Code Experiment**:
  * *Naive*: Expecting npm install react alone to enable Server Components without an integrated build toolchain or RSC router.
  * *React*: Understanding the three moving parts (React Flight runtime, bundler manifest transform, and client-side navigation router) and how they coordinate page transitions.
* **Scope Boundary**: Focus on the responsibilities of React vs bundler vs router in an RSC system. For building a custom RSC bundler setup from scratch, see Q168.
