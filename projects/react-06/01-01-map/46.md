# Q46: StrictMode and Development Double-Invocation
* **Topic Tag**: `#strict_mode` | `❱❱ MORE`
* **Interview Question**: *Why does React render your components twice in development, and how does StrictMode audit your code?*
* **Core Truth**: `<StrictMode>` runs extra checks in development only: it renders each component one extra time to expose impure rendering, runs each Effect's setup and cleanup one extra time to expose missing cleanup, runs ref callbacks one extra time to expose missing ref cleanup, and warns about deprecated APIs. In production builds it does nothing.
* **The Friction**: A developer sees `console.log('Rendering ArticleList')` print twice and a live-score Effect open two WebSocket connections on page load. Believing React is broken, they remove `<StrictMode>` from `main.jsx`. The logs go quiet, but the missing `socket.close()` cleanup ships to production, where every visit to the scores page and back leaves one more socket open.
* **The Mechanism**: Wrapping the root in `<StrictMode>` (`createRoot(el).render(<StrictMode><App /></StrictMode>)`) or wrapping any subtree. In development, React calls component bodies, state initializer functions, updater functions, and reducers twice and keeps one result; on mount it runs setup, then cleanup, then setup again for every Effect and every ref callback.
* **Under the Hood**: The audit relies on idempotence: a pure component called twice with the same props returns the same JSX, so the second call is invisible, while an impure one (pushing into a module-level array, mutating a prop) shows doubled output. The extra setup, cleanup, setup cycle simulates the component unmounting and mounting again, the same sequence a reader triggers by navigating away and back, so an Effect whose cleanup does not undo its setup leaks visibly in development instead of silently in production.
* **The Code Experiment**:
  * *Naive*: A `LiveScores` component whose Effect opens a socket without returning a cleanup, and whose render pushes each headline into a module-level array; StrictMode shows two open connections and doubled headlines.
  * *React*: The same component with a pure render and an Effect that returns `() => socket.close()`; under StrictMode the console shows connect, disconnect, connect, and exactly one live connection remains.
* **Scope Boundary**: Focus on what StrictMode re-runs, which bug each re-run exposes, and that it is inactive in production. Build on purity (Q12) and the Effect lifecycle (Q34) without re-teaching them; do not teach React 19 ref cleanup functions in depth (Q86) or legacy class lifecycle warnings.
