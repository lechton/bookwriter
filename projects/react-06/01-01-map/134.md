# Q134: Passing Server Functions to Client Components as Props
* **Topic Tag**: #use_server | ❱❱ MORE (Server)
* **Interview Question**: *How do you pass Server Functions down as props into Client Components?*
* **Core Truth**: Server Functions can be passed directly as props from Server Components into Client Components, where they behave like asynchronous callback functions that automatically invoke remote server execution when called.
* **The Friction**: An interactive headline tag picker at The National Times needs to save tag changes to PostgreSQL on every click; the client developer attempts to write custom fetch API endpoints, not realizing the parent Server Component can pass a 'use server' save function directly as an onSave prop.
* **The Mechanism**: Passing actions: <TagPicker onSave={saveTagAction} />: where saveTagAction is an async Server Function; inside TagPicker (a 'use client' component), calling await onSave(newTag) transparently executes the server action over an encrypted RPC fetch call.
* **Under the Hood**: Server Reference serialization: when a Server Function is passed across the boundary as a prop, React serializes it as a Server Reference tuple containing the action ID and bound arguments; the client runtime receives a callable proxy function that dispatches the HTTP POST request.
* **The Code Experiment**:
  * *Naive*: Building custom REST API controllers and writing client fetch('/api/tags', { method: 'POST', body: JSON.stringify(tag) }) with manual error handling.
  * *React*: Passing an async Server Function saveTag from ArticlePage directly to <TagPicker onSave={saveTag} />, calling it seamlessly inside an event handler.
* **Scope Boundary**: Focus on passing Server Functions as props to Client Components, calling them from client callbacks, and how they serialize. Progressive enhancement with <form action> was covered in Q112.
