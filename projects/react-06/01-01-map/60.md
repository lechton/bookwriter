# Q60: Architectural Composition over Memoization
* **Topic Tag**: `#composition_over_memo` | `❱❱ MORE`
* **Interview Question**: *How does component composition replace memoization without useCallback or useMemo?*
* **Core Truth**: Passing slow or expensive components as `children` or JSX props (slots) to stateful containers prevents them from re-rendering when container state changes, eliminating the need for `React.memo`, `useMemo`, and `useCallback`.
* **The Friction**: A developer builds an article page with a heavy `InteractiveTimeline` inside an `ArticleContainer` that manages local scroll and zoom state. To keep the timeline from re-rendering on zoom, the developer wraps everything in `React.memo`, `useMemo`, and `useCallback`, creating a brittle web of dependencies.
* **The Mechanism**: Component composition and slot architecture. Lift state down into a stateful wrapper, or pass the expensive component as `children`: `<ZoomContainer><InteractiveTimeline /></ZoomContainer>`. When `ZoomContainer` re-renders, `children` was created in the parent and retains its element reference.
* **Under the Hood**: Element reference identity during render: JSX produces React element objects (`_jsx`); when `ZoomContainer` re-renders due to its own state, its `props.children` object is the exact same reference from the parent pass, allowing React to skip re-rendering the `children` subtree entirely.
* **The Code Experiment**:
  * *Naive*: Nesting an expensive `Timeline` directly inside an interactive `ZoomController` component, requiring complex `memo` and `useCallback` plumbing to stop re-renders.
  * *React*: Refactoring `ZoomController` to accept `{ children }`, passing `<Timeline />` as a child from the root; `ZoomController` updates its zoom state without re-rendering `Timeline`.
* **Scope Boundary**: Focus on architectural slot composition (`children`, component-as-prop) as a cleaner, superior alternative to manual memoization hooks. Do not introduce virtualization (Q62) or the compiler (Q63).
