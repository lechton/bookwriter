# Q06: Passing Data with Props and the Read-Only Contract
* **Topic Tag**: `#props` | `❱ CORE`
* **Interview Question**: *How do you pass data into a component, and why can a component never change its own props?*
* **Core Truth**: Props are read-only input objects passed down from parents to children; components must never mutate their own props to preserve pure function contracts and predictable unidirectional data flow.
* **The Friction**: An editor renders three `ArticleCard` components, but every card displays the exact same hardcoded headline. When trying to differentiate them, a developer attempts to reassign `props.title = 'Breaking News'`, triggering silent mutation bugs or strict mode errors.
* **The Mechanism**: Declaring props on JSX call sites (`<ArticleCard title="..." readTime={5} />`) and destructuring them in the component parameter list (`function ArticleCard({ title, readTime })`).
* **Under the Hood**: Why props are frozen / read-only: React freezes the props object in development; mutating props destroys pure render guarantees, breaks memoization, and causes parent-child state drift.
* **The Code Experiment**:
  * *Naive*: Hardcoded repeated cards, followed by direct parameter mutation (`props.title = props.title.toUpperCase()`).
  * *React*: Pure component destructuring props with fallback defaults, deriving uppercase values during render without mutating the input object.
* **Scope Boundary**: Focus on passing data downward, destructuring syntax, default values, and the immutability contract. Do not introduce children composition, event callbacks, or state.
