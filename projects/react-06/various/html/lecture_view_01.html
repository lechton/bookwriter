Lecture 10: Conditional Rendering in React

Interview Question › CORE

How do you show, hide, or switch JSX based on a condition?

Imagine this scenario:
  1. Julian builds the live article header for The National Times.
  2. The header must show a red "Breaking News" badge for urgent stories, a paywall notice for non-subscribers, and comment counts.
  3. Julian uses imperative DOM queries to toggle CSS classes, causing layout flickering and desynchronized state.
  4. When Julian switches to an inline logical AND expression, evaluating zero prints a literal "0" onto the physical screen!
  5. Why does React render the number zero, and how do declarative control flow patterns keep the UI in sync?
  6. React branches markup using standard JavaScript control flow: early returns with null, inline ternaries, and boolean-safe logical AND.
  7. Today, you will master declarative conditional rendering, avoid the falsy zero trap, and write bulletproof UI branching.

The Power of Declarative Branching

In standard HTML, the structure of the document is static. If you want to change what is visible on the screen, you must write JavaScript to physically interact with the DOM, manually adding or removing nodes. This imperative approach becomes brittle as applications grow.

React introduces a paradigm shift: Declarative Conditional Rendering. Because React components are simply JavaScript functions returning JSX, you can use standard JavaScript control flow to determine what markup gets rendered. You don't hide elements with CSS; you simply tell React not to render them in the first place.

ArticleHeader.jsx 
export default function ArticleHeader({ isUrgent, commentCount }) {
  return (
    <header>
      <h1>The National Times</h1>
      
      {/* Using a Ternary Operator for A/B switching */}
      {isUrgent ? (
        <Badge variant="danger">Breaking News</Badge>
      ) : null}

      {/* Boolean-safe Logical AND for conditional insertion */}
      {commentCount > 0 && (
        <span className="meta">{commentCount} Comments</span>
      )}
    </header>
  );
}

Notice how the logic lives directly inside the markup structure. When the state changes, React automatically re-evaluates the function and seamlessly reconciles the differences, ensuring your user interface is always a perfectly synchronized reflection of your application state.
