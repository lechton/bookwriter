4.3 Unidirectional Data Flow & Callback Inheritance

In React's architectural paradigm, data strictly adheres to a unidirectional, top-down flow. State is initialized at the highest logical point in the component tree and is subsequently passed down to child components via props. However, modern interactive applications require deep child components to trigger state mutations at higher levels.

To achieve this "bottom-up" transmission without violating React's unidirectional rule, developers utilize callback function inheritance. The parent component defines a state-mutating method and passes it downward as a prop. When a user interacts with a child node, that node executes the inherited callback, effectively transmitting the new data payload back up the component hierarchy.

Figure 4.3.1: Component Hierarchy & Prop Inheritance (Top-Down)
>> The Setup Phase: The parent defines the logic and passes it down the tree
   as functional props before any user interaction occurs.

    ┌────────────────────────────────────────┐
    │ App                                    │
(1) │ State: user = { name: 'E.', role: 1 }  │
    │ Method: handleUpdate(newUserData)      │
    └───────────────────┬────────────────────┘
                        │
                        │  prop: onUserUpdate={handleUpdate}
                        ▼
    ┌────────────────────────────────────────┐
    │ UserProfile                            │
(2) │ Props: { onUserUpdate: [Function] }    │
    │                                        │
    └───────────────────┬────────────────────┘
                        │
                        │                                  ┌────────────────┐
                        ├─ (3) prop: onNameSubmit={...} ─► │ NameEditor     │
                        │                                  └────────────────┘
                        │
                        │                                  ┌────────────────┐
                        └─ (4) prop: onRoleSelect={...} ─► │ RoleSelector   │
                                                           └────────────────┘

As illustrated in Figure 4.3.1, the infrastructure for communication is laid out during the initial render phase. The App component acts as the source of truth, while NameEditor and RoleSelector remain ignorant of the overarching state, simply accepting functions that dictate how they should report changes.

Once an interaction occurs, the execution phase begins, mapping a sequential path from the user's action directly to the root state mutation.

    │                                        │
