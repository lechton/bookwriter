### Literal Text and Broken Image Paths

- [p] ◇ In standard HTML, text written between opening and closing tags is always treated as a static string. If you write `<h2>authorName</h2>`, the browser displays the literal letters a-u-t-h-o-r-N-a-m-e. Similarly, if you write `<img src="avatarUrl">`, the browser attempts to fetch a file named literally `avatarUrl` from the web server. HTML has no concept of JavaScript memory or local variables. ◼ Educational objective: establish how plain HTML treats text and attributes as static strings.
- [p] ★ {preknowledge: JavaScript variables, HTML attributes, JSX markup} {bridging: developers assume JSX automatically connects markup to local variables, but JSX is static markup by default} When a developer declares variables inside a component and writes their identifiers directly into JSX, the markup remains static. Look at the naive attempt: ◼ Educational objective: demonstrate the failure caused by omitting the JSX evaluation window.
- [code] Naive Static JSX:
```jsx title="Naive Static JSX"
export default function AuthorByline() {
  const authorName = 'Elena Rostova';
  const avatarUrl = '/authors/elena.jpg';
  return (
    <div>
      <img src="avatarUrl" />  // **WRONG:** requests literal path, breaking **IMAGE**
      <h2>authorName</h2>      // **WRONG:** prints literal word, ignoring **VARIABLE**
    </div>
  );
}
```
◼ **The what-this-introduces list:** 1. `const authorName`: local string variable in component memory. 2. `const avatarUrl`: local path variable. 3. `src="avatarUrl"`: literal string attribute causing 404 image failure. 4. `<h2>authorName</h2>`: literal text node ignoring variable scope.
- [p] ★ {preknowledge: JSX compiler transforms, string literals, JavaScript identifiers} {bridging: the failure happens because the compiler treats quoted attributes and tag text as literal strings unless told to evaluate them} The JSX compiler follows a strict parsing boundary. When text is enclosed in quotes (`"avatarUrl"`) or placed between tags (`<h2>authorName</h2>`), the compiler emits literal strings: `_jsx("img", { src: "avatarUrl" })`. To tell the compiler to step out of static markup and read JavaScript memory, you must open an evaluation window using curly braces: `{}`. ◼ Educational objective: deconstruct the parsing boundary separating static markup strings from dynamic evaluation windows.
- [figure] ```html-figure src="figures/05-00-expression-evaluation-window.html" caption="Static JSX treats text and quoted attributes as literals, while curly braces open an inline JavaScript evaluation window."```
- [grounding] [!WILD] **Why can you not place an if statement inside JSX?** When developers want conditional rendering, they often try writing `{if (isLead) { ... }}` inside their JSX. This triggers a fatal compiler error. Why? Because curly braces accept JavaScript **expressions**, but reject JavaScript **statements**. An expression produces a value that can be passed as an argument to `_jsx()`. A variable, a mathematical calculation, or a ternary operation (`isLead ? 'Lead' : 'Staff'`) all evaluate to a value. An `if` statement or a `for` loop produces no value. It is a control-flow statement. You cannot pass a statement as a function argument. To branch inside JSX, you must use expressions that return values.
- [callout] > [!TIP]
> **To impress the interviewer:** When asked how curly braces work in JSX, explain that they create an **inline evaluation window**. This window allows you to step out of static markup into live JavaScript execution. Crucially, emphasize that curly braces accept any valid **expression** that produces a value, but reject **statements** like `if` or `for` which produce no value.

### The Curly Brace Evaluation Window and Expressions

- [p] ◇ In JSX, curly braces `{}` act as an **evaluation window**. Placing curly braces inside text content (`<h2>{authorName}</h2>`) or inside an attribute (`src={avatarUrl}`) instructs the compiler to evaluate the enclosed JavaScript code at runtime. The evaluated value is then projected directly into the rendered output. ◼ Educational objective: define the curly brace evaluation window in text and attributes.
- [p] ★ {preknowledge: expressions, statements, primitive values} {bridging: developers must distinguish between expressions that evaluate to a value and statements that do not} Inside the curly brace window, you can write any valid JavaScript expression: ◼ Educational objective: categorize the types of expressions supported inside JSX curlies.
- [p] 1. **Variables**: Evaluating local identifiers like `{authorName}`. ◼ Educational objective: explain variable evaluation.
- [p] 2. **Inline Arithmetic**: Computing live numbers like `{readMinutes * 60}`. ◼ Educational objective: explain inline arithmetic.
- [p] 3. **Template Literals**: Assembling strings like `{`By ${authorName}`}`. ◼ Educational objective: explain template literal evaluation.
- [p] 4. **Ternary Expressions**: Evaluating conditional values like `{isLead ? 'Senior Editor' : 'Staff Writer'}`. ◼ Educational objective: explain ternary expressions.
- [p] ★ {preknowledge: HTML attributes, string quotes, JavaScript variables} {bridging: when passing attribute values, developers encounter a pedagogical crossroads between static string literals and dynamic expression windows} When assigning values to JSX attributes, you face an architectural fork between two syntax patterns: ◼ Educational objective: frame the pedagogical crossroads between static attributes and expression windows.
- [p] - **Option 1 (The foundational way)**: Pass a static string literal using double quotes (`src="/authors/elena.jpg"`). ◼ Educational objective: declare Option 1 with concrete syntax tokens.
- [p] - **Option 2 (The modern idiomatic way)**: Pass a dynamic JavaScript variable using curly braces (`src={avatarUrl}`). ◼ Educational objective: declare Option 2 with concrete syntax tokens.
- [p] First, look at Option 1 using a static string literal: ◼ Educational objective: transition to Option 1 code.
- [code] Option 1:
```jsx title="Option 1: The Foundational Way (src='...') "
export default function AuthorByline() {
  return (
    <img
      src="/authors/elena.jpg" // Passes static string **LITERAL**
      alt="Elena Rostova"      // Static fallback **TEXT**
    />
  );
}
```
◼ **The what-this-introduces list:** 1. `src="..."`: static string attribute. 2. Quotes: indicates an immutable string literal. 3. Zero JavaScript evaluation: value cannot change based on local variables.
- [p] ★ In Option 1, the quotes signal a plain string primitive. The compiler passes the string directly to the DOM attribute. This is ideal for static, hardcoded assets. However, it cannot adapt when variables change in memory. ◼ Educational objective: deconstruct the static nature of quoted JSX attributes.
- [p] Next, look at Option 2 using the dynamic expression window: ◼ Educational objective: transition to Option 2 code.
- [code] Option 2:
```jsx title="Option 2: The Modern Idiomatic Way (src={...})"
export default function AuthorByline() {
  const avatarUrl = '/authors/elena.jpg';
  return (
    <img
      src={avatarUrl}     // Evaluates variable in **EXPRESSION**
      alt="Elena Rostova" // Static fallback **TEXT**
    />
  );
}
```
◼ **The what-this-introduces list:** 1. `src={avatarUrl}`: curly brace attribute binding. 2. Omission of quotes: quotes around curlies like `"{avatarUrl}"` treat the braces as literal characters. 3. Dynamic evaluation: reads variable from component memory.
- [p] ★ In Option 2, the curly braces replace the quotes entirely. Notice that you never write `src="{avatarUrl}"`. Adding quotes around curly braces causes JSX to treat `{avatarUrl}` as a literal string of characters, breaking the link. The curly braces alone establish the evaluation window. ◼ Educational objective: warn against the common trap of wrapping curly braces inside quotes.
- [callout] > [!KEY]
> Use quotes `""` for static string literals. Use curly braces `{}` for dynamic JavaScript expressions. Never wrap curly braces in quotes (`"{variable}"`).

### Glossary

- [glossary] JSX Evaluation Window ◼ The syntax construct `{}` that temporarily steps out of static JSX markup to evaluate a JavaScript expression.
- [glossary] JavaScript Expression ◼ Any valid unit of JavaScript code that resolves to a single value, such as a variable, calculation, or function call.
- [glossary] JavaScript Statement ◼ A unit of code that performs an action but produces no return value (`if`, `for`, `while`), forbidden inside JSX curlies.
- [glossary] Dynamic Attribute ◼ An HTML attribute whose value is computed at runtime via curly braces (`src={avatarPath}`) rather than hardcoded in quotes.
- [glossary] Ternary Expression ◼ An inline conditional expression (`condition ? expr1 : expr2`) that evaluates to one of two values, permitted inside JSX curlies.

## Beyond the basics

- **JSX curly braces compiler output**: The expression `{readMinutes * 60}` compiles directly to the function argument `_jsx("p", { children: [readMinutes * 60, " seconds read"] })` (see [react.dev/learn/javascript-in-jsx-with-curly-braces](https://react.dev/learn/javascript-in-jsx-with-curly-braces)).
- **Expressions vs statements in language specifications**: In the ECMAScript specification, expressions evaluate to a value, while statements control execution flow; JSX child positions only accept expressions because function calls require argument values (see [react.dev/learn/javascript-in-jsx-with-curly-braces](https://react.dev/learn/javascript-in-jsx-with-curly-braces)).
- **Objects as JSX children**: React cannot render raw JavaScript objects directly inside text curlies (`{userObject}`); attempting to do so throws a runtime error, requiring you to access primitive properties like `{userObject.name}` (see [react.dev/learn/javascript-in-jsx-with-curly-braces](https://react.dev/learn/javascript-in-jsx-with-curly-braces)).
- **Double curlies for inline style objects**: When applying inline styles in JSX, you write `style={{ color: 'red' }}`; the outer braces open the evaluation window, and the inner braces declare a JavaScript object literal (see [react.dev/learn/javascript-in-jsx-with-curly-braces](https://react.dev/learn/javascript-in-jsx-with-curly-braces)).
- **Boolean and nullish rendering**: React treats `true`, `false`, `null`, and `undefined` as empty values inside curly braces, rendering nothing to the DOM, which enables conditional rendering shortcuts like `{isPublished && <Badge />}` (see [react.dev/learn/conditional-rendering](https://react.dev/learn/conditional-rendering)).

### Summary

**Architectural Takeaways & Decision Matrix**

❒ Evaluation Windows & Text

➔ ALWAYS wrap JavaScript variables in curly braces (`{authorName}`) when rendering dynamic text inside JSX elements.

➔ NEVER write variable names as raw text (`<h2>authorName</h2>`) because JSX treats unbracketed text as literal strings.

➔ IF rendering a conditional value inside JSX THEN use a ternary expression (`{flag ? 'A' : 'B'}`) instead of an `if` statement.

❒ Dynamic Attributes

➔ ALWAYS use curly braces without quotes (`src={avatarUrl}`) when binding dynamic variables to element attributes.

➔ NEVER wrap curly braces in quotes (`src="{avatarUrl}"`) because this passes the literal string `"{avatarUrl}"` to the DOM.

**DO THIS:** evaluate variables and dynamic attributes with curly braces

```jsx right
export default function AuthorByline() {
  const name = 'Elena';
  const avatar = '/elena.jpg';
  return <img src={avatar} alt={name} />;
}
```

**DO NOT DO THIS:** write literal names or wrap curlies inside quotes

```jsx wrong
export default function AuthorByline() {
  const name = 'Elena';
  const avatar = '/elena.jpg';
  return <img src="avatar" alt="name" />;
}
```

| | **STATIC MARKUP**<br>(literal strings) | **CURLY BRACES { }**<br>(expression window) |
| ---: | :--- | :--- |
| **Text Output** | Displays literal character strings | Projects live evaluated JavaScript values |
| **Attribute Binding** | Quoted strings: `src="path.jpg"` | Unquoted curlies: `src={avatarUrl}` |
| **Grammar Support** | Static text only | Accepts all expressions (variables, math, ternary) |
| **Statements (`if`, `for`)** | Not applicable | Forbidden: statements produce no return value |
| **Runtime Calculation** | Hardcoded at build time | Evaluated dynamically on every component render |
