### The Silent Blank Screen of Lowercase Tags

- [p] ★ {preknowledge: writing standard JavaScript functions, declaring HTML tags in templates, opening browser developer tools} When building user interfaces with React, every piece of the page begins as a JavaScript function. You sit at your keyboard, write a function that returns HTML-like markup, and place that tag into your layout. In standard JavaScript, functions conventionally use camelCase naming, like `calculateTotal()` or `formatDate()`. Following that habit, a developer writes `function articleCard()` and mounts `<articleCard />`. ◼ Educational objective: anchor in standard JavaScript naming habits and set up the innocent junior developer impulse.
- [p] ★ {problem: lowercase custom tags compile to unknown native DOM strings and fail silently} When Julian opens the browser, the screen is completely blank. The Vite terminal shows no syntax errors, and the browser console prints zero warnings. When you inspect the DOM in developer tools, the browser created a literal `<articlecard></articlecard>` node with zero contents. The JavaScript function was never executed, its return statement was never reached, and the article markup never rendered. ◼ Educational objective: deconstruct the silent failure mode of lowercase custom tags.
- [p] ★ {old solution: writing custom component functions with lowercase camelCase names} To see this failure in real code, examine the broken lowercase component declaration:

- [code] Naive Lowercase Component:

```jsx title="Naive Lowercase Component"
function articleCard() {
  return (
    <article className="news-card">
      <h2>Preserving the Historic District</h2>
      <p>City council approves preservation zoning.</p>
    </article>
  ); // **WRONG:** lowercase name causes compiler to treat tag as native **STRING**
}
```

◼ **The what-this-introduces list:** 1. `articleCard`: naive lowercase function declaration. 2. Return statement: valid semantic markup trapped inside an uninvoked function. 3. Silent bypass: compiler treats the identifier as an unknown HTML element.

- [p] ★ {mechanism: JSX AST compiler branch treats lowercase as string literals} The JSX compiler evaluates the first letter of every tag to choose its compilation pathway. If the first character is lowercase, the parser classifies the tag as a built-in browser DOM element. It emits a string literal: `_jsx("articlecard", {})`. When React runs in the browser, it asks `document.createElement("articlecard")`. The browser creates an unknown HTML element. If the tag begins with a capital letter, the compiler emits a direct function identifier: `_jsx(ArticleCard, {})`. React receives the function reference and calls it to evaluate the UI. ◼ Educational objective: explain the AST compiler branching mechanism that splits string literals from function identifiers.
- [grounding] [!] Grounding card: Why do lowercase custom tags fail silently? ◼ Opening question: Why do lowercase custom tags fail silently in browsers? ◼ Friction target: Developers writing camelCase component names wonder why their functions never run. ◼ Tactile scene: A developer mounts `<articleCard />`, sees a blank rectangle, inspects the DOM, and finds an empty `<articlecard>` element. ◼ Bold key terms: **JSX compiler**, **string literal**, **identifier**, **custom tag**, **silent failure**. ◼ Operational resolution: The HTML parser permits arbitrary custom element names without throwing errors; capitalized names are mandatory to signal a JavaScript function reference to the JSX compiler.

### What is a React Component?

- [p] ◇ {conceptual grounding: functions that return descriptions of visual interface} In plain JavaScript, functions process data, calculate numbers, or trigger side effects. In React, a **component** is a pure JavaScript function with a single dedicated purpose: it accepts inputs and returns a description of what should appear on screen. You do not manually create DOM nodes or attach elements with `appendChild`. Instead, you write a function that returns JSX markup describing the structure. ◼ Educational objective: define the core nature of a React component as a UI-describing function.
- [p] ◇ {the pure return contract: components must return valid UI descriptors} A React component must fulfill a strict **return contract**: it must return a valid React element, a Fragment, or `null`. If a component returns `undefined` or forgets its return statement, React halts execution or renders nothing. Every component function is an engine that translates state and inputs into visual structure, operating as a pure calculation: given the same conditions, it returns the same UI descriptor. ◼ Educational objective: establish the return contract and predictable execution model of components.
- [p] ◇ {declarative invocation: tags represent descriptors rather than immediate function calls} When you write `<ArticleCard />` in JSX, you are not immediately calling `ArticleCard()`. You are creating a lightweight **UI descriptor** that tells React: "When you are ready to paint this section of the tree, invoke `ArticleCard`." This declarative separation gives React full control over when to call your component, how to manage its memory, and how to optimize DOM updates. ◼ Educational objective: distinguish declarative tag instantiation from direct imperative function calls.

### Principles of React: Component Anatomy and Execution

- [p] ◇ In technical interviews, engineering candidates are routinely asked to explain the rules governing React components and how JSX differentiates custom functions from native browser tags. To master this architecture, we formalize the three governing principles of component anatomy: ◼ Educational objective: frame the upcoming principles around senior technical evaluation.

> [!PRINCIPLE]
> **Principle 1: Enforce PascalCase Capitalization to Emit Function Identifiers**
> Every custom component name begins with an **uppercase letter** (`ArticleCard`), instructing the compiler to emit a direct function identifier rather than an HTML string literal.
> 
> >> uppercase letter : starting character formatted in PascalCase (such as ArticleCard)
> >> function identifier : an unquoted reference to a JavaScript function in memory
> 
> *We should do this:*
> `function ArticleCard() {`
> `  return (`
> `    <article className="card">`
> `      <h2>Morning Dispatch</h2>`
> `    </article>`
> `  );`
> `}`
> 
> *We should not do this:*
> `function articleCard() {`
> `  return (`
> `    <article className="card">`
> `      <h2>Morning Dispatch</h2>`
> `    </article>`
> `  );`
> `}`

- [p] ★ Principle 1 operational derivation: The JSX specification uses the Unicode category of the tag's opening character to branch AST generation. When the compiler parses `<articleCard />`, it emits `_jsx("articleCard", {})` as a string. The JavaScript runtime passes this string to `document.createElement("articleCard")`. The browser creates an unknown HTML element and paints nothing because it contains no child nodes. When the compiler parses `<ArticleCard />`, it recognizes the uppercase letter and emits `_jsx(ArticleCard, {})` without quotes. React holds the actual function in memory and invokes it, obtaining the `<article>` tree and committing it to the DOM. ◼ Educational objective: prove the compiler AST branch and document.createElement consequences.

> [!PRINCIPLE]
> **Principle 2: Fulfill the Pure Return Contract by Always Returning a Single UI Descriptor**
> A component function always **returns a valid JSX descriptor** or `null`, ensuring React receives a renderable specification for the DOM.
> 
> >> valid JSX descriptor : an element or fragment representing markup structure
> >> renderable specification : an object describing what nodes the browser should create
> 
> *We should do this:*
> `function NewsSnippet() {`
> `  return (`
> `    <p className="summary">`
> `      Breaking news updates.`
> `    </p>`
> `  );`
> `}`
> 
> *We should not do this:*
> `function NewsSnippet() {`
> `  // Forgot return statement`
> `  <p className="summary">`
> `    Breaking news updates.`
> `  </p>;`
> `}`

- [p] ★ Principle 2 operational derivation: In JavaScript, a function without an explicit `return` statement resolves to `undefined`. If your component calculates markup but forgets to return it, the function returns `undefined`. React treats `undefined` as a developer error and throws a runtime exception in development: "Nothing was returned from render." Component functions do not mutate external variables; they must return their UI descriptor cleanly to the caller. ◼ Educational objective: unpack the return contract and the runtime exception caused by missing returns.

> [!PRINCIPLE]
> **Principle 3: Invoke Components Declaratively via JSX Tags Rather Than Direct Calls**
> Mount components using **declarative JSX tags** (`<ArticleCard />`), preserving component identity and tree ownership inside React.
> 
> >> declarative JSX tags : syntax like `<ArticleCard />` that compiles into element descriptors
> >> tree ownership : React managing component lifecycle, re-renders, and DOM reconciliation
> 
> *It is best practice to do this:*
> `function App() {`
> `  return (`
> `    <main>`
> `      <ArticleCard />`
> `    </main>`
> `  );`
> `}`
> 
> *Instead of doing this:*
> `function App() {`
> `  return (`
> `    <main>`
> `      {ArticleCard()}`
> `    </main>`
> `  );`
> `}`

- [p] ★ Principle 3 operational derivation: When you call `{ArticleCard()}` directly, it executes immediately as a plain JavaScript helper function during the parent's render. React never sees `ArticleCard` as a distinct node in its element tree. Its output is flattened directly into the parent. If you later add hooks or state, calling the function directly violates the Rules of Hooks and breaks reconciliation. Using `<ArticleCard />` creates a descriptor node with its own identity, allowing React to optimize renders and manage component boundaries independently. ◼ Educational objective: deconstruct why declarative JSX mounting is required over direct function execution.

- [comparison] Consolidated Reference Table:
| **TAG SYNTAX**<br>(developer input) | **COMPILER OUTPUT**<br>(transpiled AST) | **RUNTIME EXECUTION**<br>(React engine) | **BROWSER DOM RESULT**<br>(rendered pixels) |
| :--- | :--- | :--- | :--- |
| `<articleCard />`<br>(lowercase) | `_jsx("articleCard", {})`<br>(string literal) | Bypasses component function;<br>calls `document.createElement` | Empty `<articlecard>` element;<br>blank screen |
| `<ArticleCard />`<br>(PascalCase) | `_jsx(ArticleCard, {})`<br>(function identifier) | React invokes `ArticleCard()`;<br>evaluates returned JSX tree | Semantic `<article>` tree;<br>headline and paragraph rendered |
| `{ArticleCard()}`<br>(direct call) | Plain JS call expression;<br>inlines returned JSX | Bypasses React element tree;<br>strips component node identity | Output inlined into parent;<br>loses independent component boundary |

- [p] ★ To verify this compiler behavior, examine the transpiled JavaScript output generated from both tag formats:

- [code] Transpiler Output Comparison:

```js title="Transpiler Output Comparison"
<articleCard />; // (1) Lowercase tag written in source JSX
<ArticleCard />; // (2) Capitalized component tag written in source JSX
_jsx("articleCard", {}); // (3) String literal emitted for browser DOM
_jsx(ArticleCard, {}); // (4) Function identifier emitted for React engine
```

◼ **The what-this-introduces list:** 1. String literal emission: quotes surrounding lowercase tag names. 2. Function identifier emission: unquoted function reference passed directly to `_jsx()`. 3. Engine dispatch: how React routes string tags to DOM elements and function tags to component evaluators.

### Step 1: First, we construct the article card component <ArticleCard.jsx>

- [p] ★ We begin by constructing our independent presentation component `ArticleCard.jsx`. Notice the function name: it uses **PascalCase** capitalization (`ArticleCard`). Inside the function body, we fulfill the pure return contract by returning semantic article markup. The markup contains a self-contained `<article>` container holding an `<h2>` headline and a `<p>` summary. The copy is static text, keeping this initial component completely isolated and self-contained without requiring props or external variables. ◼ Meaningful pedagogical commentary: component anatomy, PascalCase naming, semantic HTML return, pure calculation without external dependencies.

- [code] ArticleCard.jsx:

```jsx title="ArticleCard.jsx"
export default function ArticleCard() {
  return (
    <article className="news-card">
      <h2 className="headline">Green Transit Corridor</h2> // Renders article **HEADLINE**
      <p className="summary">Light rail expansion planned.</p> // Renders summary **COPY**
    </article>
  ); // Fulfills pure return **CONTRACT**
}
```

◼ **The what-this-introduces list:** 1. `ArticleCard`: PascalCase component function declaration. 2. `return (...)`: parenthesized return contract wrapping the JSX tree. 3. Semantic markup: `<article>`, `<h2>`, and `<p>` elements forming a cohesive presentation unit.

### Step 2: Finally, we mount the component into the application tree <App.jsx>

- [p] ★ Now that `ArticleCard.jsx` is defined, we import it into the root container `App.jsx` and mount it into the visual layout. Here we reach a foundational architectural crossroad that every junior developer encounters: ◼ Meaningful pedagogical commentary: component mounting, parent-child integration, introducing the crossroad between declarative tags and direct function calls.

- [p] ◇ When mounting a component function into JSX, you face a choice:
- **Option 1 (The Foundational / Imperative Way)**: Call the component directly as a standard JavaScript function inside curly braces: `{ArticleCard()}`.
- **Option 2 (The Modern Idiomatic / Declarative Way)**: Mount the component declaratively using a JSX element tag: `<ArticleCard />`.

- [p] ★ First, examine Option 1 with direct function execution:

- [code] Option 1: The Foundational Way (Direct Function Call):

```jsx title="Option 1: The Foundational Way ({ArticleCard()})"
export default function App() {
  return (
    <main className="page-layout">
      <h1>Morning Edition</h1>
      {ArticleCard()} // **WRONG:** executes immediately, stripping component **IDENTITY**
    </main>
  );
}
```

- [p] ★ In Option 1, `{ArticleCard()}` executes immediately as an ordinary JavaScript function during the execution of `App`. React never creates a separate component node for `ArticleCard` in its internal descriptor tree. Its returned markup is inlined directly into `App` as raw child elements. React cannot attach independent lifecycle behavior, cannot optimize re-renders for `ArticleCard`, and will fail if hooks are added later. ◼ Educational objective: prove why calling components as functions breaks tree ownership and component boundaries.

- [p] ★ Next, examine Option 2 with declarative JSX element mounting:

- [code] Option 2: The Modern Idiomatic Way (Declarative Tag):

```jsx title="Option 2: The Modern Idiomatic Way (<ArticleCard />)"
import ArticleCard from './components/ArticleCard.jsx';
export default function App() {
  return (
    <main className="page-layout">
      <h1>Morning Edition</h1> // Declares layout **HEADER**
      <ArticleCard /> // Declares component **DESCRIPTOR**
    </main>
  );
}
```

- [p] ★ In Option 2, writing `<ArticleCard />` does not invoke the function immediately. Instead, it creates a React element descriptor `{ type: ArticleCard, props: {} }`. React registers `ArticleCard` as a distinct child node in the component hierarchy. React decides when to invoke the function, encapsulates its rendering, and preserves its independent identity across updates. ◼ Meaningful pedagogical commentary: declarative element creation, component tree identity, React reconciler ownership.

◼ **The what-this-introduces list:** 1. `import ArticleCard`: importing a default component export. 2. `<ArticleCard />`: declarative JSX element instantiation. 3. Component hierarchy: `App` acting as the parent layout container for the child `ArticleCard`.

### Where you will meet this

- [p] 1. **Design System Component Libraries**: Every design system (such as buttons, cards, dialogs, and typography primitives) relies on strict PascalCase naming. Capitalized tags ensure that custom styled components (`<Button />`) never collide with native HTML controls (`<button>`).
- [p] 2. **Editorial Content Layouts**: Online publications like The National Times organize articles into modular presentation cards, bylines, and photo galleries. Writing each section as an independent capitalized component allows editorial desks to compose diverse page layouts effortlessly.
- [p] 3. **Micro-Frontend Application Portals**: Large web platforms assemble multiple independent features into unified dashboards. Structuring each widget as an encapsulated component guarantees that individual teams can build, test, and maintain their UI blocks without interfering with sibling components.

### Glossary

- [glossary] Component ◼ A pure JavaScript function that accepts inputs and returns a JSX descriptor representing a slice of the user interface.
- [glossary] PascalCase Capitalization ◼ The naming convention where every word in an identifier begins with an uppercase letter (`ArticleCard`), strictly required by the JSX compiler to distinguish custom components from native HTML tags.
- [glossary] JSX Transpiler ◼ The build-time compiler tool (such as Babel, SWC, or esbuild) that transforms JSX tags into standard JavaScript `_jsx()` function calls.
- [glossary] Declarative Invocation ◼ Mounting a component via a JSX element tag (`<ArticleCard />`), instructing React to manage the function's execution and tree identity rather than calling it imperatively.
- [glossary] UI Descriptor ◼ A lightweight JavaScript object returned by a component that describes the desired DOM nodes, attributes, and children for React to construct.

### Summary

**Component Anatomy & Capitalization Decision Matrix**

❒ Component Declaration & Capitalization

➔ ALWAYS name custom component functions using PascalCase capitalization (`ArticleCard`) so the JSX compiler emits function identifiers instead of native HTML string literals.

➔ NEVER name custom component functions with a lowercase first letter (`articleCard`), which causes the browser to render an empty unknown HTML element and fail silently.

❒ Invocation & Tree Identity

➔ ALWAYS invoke components declaratively using JSX tags (`<ArticleCard />`) to preserve independent component identity and allow React to manage the render lifecycle.

➔ NEVER invoke component functions directly as plain JavaScript calls (`{ArticleCard()}`), which strips component boundaries and inlines output into the parent.

**DO THIS:** Name components with PascalCase and mount them declaratively

```jsx right
export default function ArticleCard() {
  return (
    <article className="card">
      <h2>Preserving History</h2>
    </article>
  );
}

function App() {
  return <ArticleCard />;
}
```

**DO NOT DO THIS:** Use lowercase names or call the component function directly

```jsx wrong
function articleCard() {
  return (
    <article className="card">
      <h2>Preserving History</h2>
    </article>
  );
}

function App() {
  return <articleCard />;
}
```
