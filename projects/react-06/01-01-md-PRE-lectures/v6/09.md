### The Mystery of the Empty Root Container

- [p] ★ {preknowledge: component declarations, JSX markup, HTML document structure} In previous lessons, you learned how to write React components: you declared JavaScript functions that return JSX describing user interface elements. You organized those components into separate files and shared them using ES module imports and exports. But components alone do not automatically appear in the browser window. A web browser only understands native HTML, CSS, and plain JavaScript. When you open a modern React project, you find an `index.html` file that contains almost no markup: just a plain `<body>` with an empty `<div id="root"></div>` and a single `<script>` tag. ◼ Educational objective: recall component functions and confront the physical reality of an empty host HTML document.
- [p] ★ {problem: naive attempts to link JSX components directly fail in the browser} A developer who is new to React might look at `App.jsx` and attempt to link it directly inside `index.html` using a traditional `<script src="src/App.jsx"></script>` tag, or double-click `index.html` to open it as a local file (`file://`). When they do, the browser fails immediately. The browser JavaScript engine encounters JSX tags like `<App />` and throws a fatal syntax error: `Uncaught SyntaxError: Unexpected token '<'`. Browsers do not understand JSX syntax natively. Furthermore, opening the file directly from disk triggers security errors that block modern JavaScript modules from loading. ◼ Educational objective: expose the failure of opening raw JSX or local file paths directly in the browser.
- [p] ★ {old solution: legacy ReactDOM.render and monolithic script tags} Years ago, older tutorials told developers to load full React bundles through classic script tags and call `ReactDOM.render(<App />, document.getElementById('root'))`. In React 19, that old method has been completely removed. If you try to call `ReactDOM.render`, JavaScript throws an error because the function no longer exists. ◼ Educational objective: identify the legacy ReactDOM.render method and explain why it fails in modern React 19.

- [code] Naive Direct Script Loading Attempt:

```html title="Naive index.html Attempt"
<!DOCTYPE html>
<html>
  <head>
    <title>The National Times</title>
    <!-- Classic script cannot parse JSX tags -->
    <script src=~"/src/App.jsx"~></script> // SyntaxError on JSX tags
  </head>
  <body><div id=~"root"~></div></body>
</html>
```

◼ **The what-this-introduces list:** 1. `<script src="/src/App.jsx">`: naive classic script tag attempting to load raw JSX directly. 2. `<div id="root">`: empty HTML container waiting for a mounting bridge. 3. `SyntaxError`: the browser error caused by uncompiled JSX syntax.

- [p] ★ {mechanism: the mounting pipeline with createRoot and Vite} To display React components in the browser, modern applications use a clear mounting pipeline. First, `index.html` loads a JavaScript entry file, `src/main.jsx`, using a modern module script: `<script type="module" src="/src/main.jsx"></script>`. Second, `main.jsx` imports `createRoot` from the browser renderer package, `react-dom/client`. Third, `createRoot` finds the physical HTML container on the page using `document.getElementById('root')`. Finally, `root.render(<App />)` takes the virtual React element tree and mounts it directly into the real browser DOM. Meanwhile, a build tool like Vite transforms JSX on the fly and serves files over a local HTTP server so the browser can execute them safely. ◼ Educational objective: outline the modern client-side mounting pipeline from HTML to createRoot to screen.

### How React Connects to the Browser and Why Tools Transform Markup

- [p] ◇ {conceptual grounding: the separation of React and ReactDOM} To understand how React mounts to the screen, we must first recognize an important design decision: React separates the core component model from the browser renderer. The core package, named `react`, is responsible for creating elements, managing component logic, and calculating UI descriptions. It knows nothing about HTML tags or web browsers; in fact, the same core React library powers mobile applications in React Native. The browser renderer, named `react-dom/client`, is the bridge that turns those React element descriptions into real browser DOM elements like `<div>`, `<article>`, and `<p>`. In an application, only your entry file (`main.jsx`) imports from `react-dom/client`; all your component files import purely from `react`. ◼ Educational objective: establish the clear boundary between the core React library and the ReactDOM client renderer.
- [p] ◇ {syntactic grounding: the DOM container query} In standard JavaScript, `document.getElementById('root')` is a built-in browser method. It searches the active HTML page for an element whose `id` attribute equals `'root'`. If it finds the element, it returns a reference to that living DOM node in memory. If no element with that ID exists on the page, the method returns `null`. This DOM node is the physical home where React will place its elements. ◼ Educational objective: remind the reader what document.getElementById does and what it returns when an element is found or missing.
- [p] ◇ {syntactic grounding: module scripts in HTML} In modern HTML, adding `type="module"` to a `<script>` tag tells the browser that the file uses modern JavaScript `import` and `export` statements. Unlike classic scripts, module scripts are automatically **deferred** by the browser. This means the browser downloads the script in the background while continuing to parse the HTML document. The script only executes after the entire HTML document has been parsed into memory. Because of this, a module script placed in the `<head>` of your page can safely find `<div id="root">` even though the `<div>` is written further down in the `<body>`. ◼ Educational objective: explain how type="module" enables ES modules and automatically defers execution until HTML parsing completes.
- [p] ★ {compiler transformation: why Vite is required during development} Browsers understand standard JavaScript, but they do not understand JSX tags like `<h1>` inside `.jsx` files. In addition, when you write `import React from 'react'`, the browser does not know where to find node modules on your computer. This is why we use a build tool like Vite. During development, Vite runs a local HTTP server on `http://localhost:5173`. When the browser requests `/src/main.jsx`, Vite intercepts the request, transforms the JSX into standard JavaScript function calls in memory, and serves the result as native ES modules over HTTP. In production, `vite build` bundles all your code and styles into static files inside a `dist/` directory that can be deployed to any web server. ◼ Educational objective: explain the role of Vite's development server in transforming JSX and serving native ES modules over HTTP.

### Principles of React: Mounting the Root with createRoot

- [p] ◇ When preparing for technical interviews, candidates must clearly explain how React connects to the real browser DOM, why React 19 removed legacy mounting methods, how `createRoot` manages container contents and update timing, and how modern tooling like Vite powers development and production builds. To master these concepts, we formalize the eight governing principles of root mounting and tooling: ◼ Educational objective: frame the eight principles from the perspective of an engineering candidate preparing for technical interviews.

> [!PRINCIPLE]
> **Principle 1: Hand React One Container and Expect It to Replace That Container's Contents**
> Give React ownership of one physical DOM element by passing it to `createRoot`. The first time you call `root.render`, React replaces all existing HTML inside that container with your component tree. Any HTML outside that container, such as a static header or footer in `index.html`, remains untouched in the browser.
> 
> >> container element : a physical HTML tag on the page that React takes over to display its component tree
> >> placeholder content : temporary HTML placed inside the container that displays while JavaScript downloads
> 
> *It is best practice to do this:*
> `<div id=~"root"~>`
> `  <p>Loading...</p> // React replaces container contents on mount`
> `</div>`
> 
> *Instead of doing this:*
> `<div id="root" />`
> `<div id=~"extra-root"~ /> // Avoid multiple mounting targets`

- [p] ★ Principle 1 operational derivation: When you call `createRoot(container)`, you give React exclusive ownership of the DOM inside that specific element. When `root.render(<App />)` runs for the first time, React wipes whatever HTML was inside that container and replaces it with the rendered output of `App`. This clearing behavior has a helpful practical benefit: you can place friendly placeholder HTML inside `<div id="root">`, such as `<p>Loading The National Times...</p>`. While the user's browser downloads and parses the JavaScript bundles, this placeholder is visible on screen. As soon as React mounts, it replaces the placeholder with your actual newsroom application. Furthermore, any markup written outside the container, like a static navigation bar or copyright notice in `index.html`, stays completely intact. ◼ Educational objective: demonstrate that React owns only the DOM inside its container and explain how to use loading placeholders.

> [!PRINCIPLE]
> **Principle 2: Give createRoot an Element That Exists**
> Always pass `createRoot` a real, existing DOM node returned by `document.getElementById`. Make sure the identifier string matches the `id` in `index.html` character for character. Never pass `createRoot` a JSX element or a missing selector.
> 
> >> null container error : a fatal runtime crash thrown when createRoot receives null instead of a valid DOM element
> 
> *We should do this:*
> `const element = document.getElementById(~'root'~); // Finds real DOM node`
> `const root = createRoot(element); // Passes verified element`
> 
> *We should not do this:*
> `const root = createRoot(document.getElementById(~'app'~)); // Typo is null`
> `const root = createRoot(~<App />~); // Wrong: JSX is not a DOM node`

- [p] ★ Principle 2 operational derivation: `createRoot` expects exactly one parameter: a valid browser DOM element. If you make a typo in the identifier, such as typing `document.getElementById('app')` when `index.html` defines `<div id="root">`, the browser method finds nothing and returns `null`. Passing `null` to `createRoot` causes React to throw a fatal error: `"Target container is not a DOM element."`. The same error occurs if you pass a JSX component directly into `createRoot(<App />)`. In a modern Vite project, because the script uses `type="module"`, the script is automatically deferred, so script position in HTML is not the cause. When you encounter this error, always verify that the container ID in `index.html` matches `getElementById` exactly. ◼ Educational objective: explain the cause of the target container error and prove how to diagnose ID mismatches.

> [!PRINCIPLE]
> **Principle 3: Render an Element with a Single Argument**
> Call `root.render` with exactly one React element, such as `<App />`. Never pass the raw component function `App` without JSX tags, and never pass configuration options to `render`. Put root options directly inside `createRoot(container, options)`.
> 
> >> React element : a descriptor object created with JSX tags like <App /> that tells React what to mount
> 
> *We should do this:*
> `const root = createRoot(container, options); // Root options go here`
> `root.render(~<App />~); // Renders single React element with tags`
> 
> *We should not do this:*
> `root.render(~App~); // Missing tags: passes function instead of element`
> `root.render(<App />, ~options~); // Invalid: render accepts 1 argument`

- [p] ★ Principle 3 operational derivation: Creating a root and rendering it are two distinct operations. Calling `createRoot(container)` prepares the container in memory, but nothing displays on screen until you call `root.render()`. When calling `render`, you must pass a React element (`<App />`), not a bare function (`App`). If you pass `root.render(App)`, React logs a console error: `"Functions are not valid as a React child. This may happen if you return a Component instead of <Component /> from render."` and leaves the page blank. In addition, `root.render` accepts only one argument. If you pass a second argument, React logs: `"You passed a second argument to root.render(...) but it only accepts one argument."`. If you need to configure root options, such as error logging handlers, pass them as the second argument to `createRoot`, not to `render`. ◼ Educational objective: contrast passing React elements versus raw component functions and place root options correctly.

> [!PRINCIPLE]
> **Principle 4: Create the Root Once and Grow the App Inside App**
> Call `createRoot` exactly once at startup in `main.jsx` for your single page application. Add all new sections, feeds, and banners as components nested inside `App`, rather than creating multiple roots on the same container.
> 
> >> single root architecture : an application pattern where one root manages the entire component tree
> 
> *It is best practice to do this:*
> `const root = ~createRoot(container)~; // One root at startup in main.jsx`
> `root.render(<App />);`
> 
> *Instead of doing this:*
> `~createRoot(container)~.render(<NewsBanner />); // Duplicate root warns`

- [p] ★ Principle 4 operational derivation: In a project fully built with React, you should only call `createRoot` once in your entry file. If code in your application calls `createRoot` a second time on the same container, React detects the duplicate root and logs a clear warning: `"You are calling ReactDOMClient.createRoot() on a container that has already been passed to createRoot() before. Instead, call root.render() on the existing root instead if you want to update it."`. Creating multiple roots on the same DOM element splits ownership, creates memory leaks, and breaks communication between components. If you want to add new user interface elements, like a breaking news banner or a sidebar, add them as child components inside `App.jsx`. In standard React development, components update by changing their state, not by calling `root.render` again. ◼ Educational objective: prove why full React applications use a single root and demonstrate the duplicate root warning.

> [!PRINCIPLE]
> **Principle 5: Serve the App Over HTTP Through Vite**
> Run the Vite development server using `npm run dev` during development, and serve the built `dist/` directory from a web server using `vite preview`. Never double-click `index.html` from your desktop or load files over the `file://` protocol.
> 
> >> HTTP protocol : the web communication protocol that allows browsers to load modules and fetch assets safely
> >> file protocol : the local disk protocol that browsers restrict from executing modern module scripts
> 
> *It is best practice to do this:*
> `$ npm run ~dev~ // Serves native ES modules over HTTP`
> 
> *Instead of doing this:*
> `$ open ~file://index.html~ // Local file protocol blocks ES modules`

- [p] ★ Principle 5 operational derivation: Modern web browsers enforce strict security rules around ES modules. When you open an HTML file from your hard drive using the `file://` protocol, the browser treats the origin as `null`. When `index.html` tries to load `<script type="module" src="/src/main.jsx">`, Chrome blocks the script with a security error: `"Access to script at 'file:///.../src/main.jsx' from origin 'null' has been blocked by CORS policy"`. The same failure happens if you double-click `dist/index.html` after running `vite build`, because the production HTML requests `/assets/index-[hash].js` from the server root. To run a modern React application, you must serve it over HTTP. Vite provides `npm run dev` for instant development with hot module replacement, and `vite preview` to test your production build on a local HTTP server. ◼ Educational objective: explain browser CORS restrictions on the file protocol and demonstrate how Vite serves code over HTTP.

> [!PRINCIPLE]
> **Principle 6: Keep JSX in .jsx Files**
> Name every file that contains JSX syntax with the `.jsx` extension, such as `App.jsx` or `main.jsx`. Vite transforms JSX only in `.jsx` and `.tsx` files, and treats standard `.js` files as plain JavaScript.
> 
> >> JSX file extension : the explicit file suffix that tells build tools to compile JSX markup into function calls
> 
> *It is best practice to do this:*
> `// File: ~App.jsx~`
> `export default function App() { return <h1>News</h1>; } // Compiles JSX`
> 
> *Instead of doing this:*
> `// File: ~App.js~`
> `export default function App() { return <h1>News</h1>; } // Fails in Vite`

- [p] ★ Principle 6 operational derivation: In older build setups like Create React App, developers often placed JSX markup inside files ending in `.js`. Vite adopts a faster, stricter architecture: it parses files ending in `.js` as standard ECMAScript. If you leave JSX tags inside a file named `App.js`, Vite's transformer stops with a build error: `"[builtin:vite-transform] Unexpected JSX expression"`. The error message does not explicitly mention the file extension, which can confuse developers who are used to older tools. By naming every file containing JSX with `.jsx`, you ensure Vite applies its fast React compiler plugin and converts your tags into valid JavaScript. ◼ Educational objective: demonstrate why Vite requires the .jsx extension and show the unexpected JSX build error.

> [!PRINCIPLE]
> **Principle 7: Mount with createRoot from react-dom/client**
> Import `createRoot` directly from `react-dom/client` in your entry file. Never import `render` from `react-dom`, because React 19 completely removed the legacy `ReactDOM.render` and `ReactDOM.hydrate` methods.
> 
> >> client entry point : the react-dom/client subpath providing root creation methods for web browsers
> 
> *We should do this:*
> `import { ~createRoot~ } from 'react-dom/client'; // Modern mounting API`
> `const root = createRoot(document.getElementById('root'));`
> 
> *We should not do this:*
> `import { ~render~ } from 'react-dom'; // Removed in React 19: undefined`
> `render(<App />, document.getElementById('root')); // Crashes runtime`

- [p] ★ Principle 7 operational derivation: Developers returning to React after several years often reach for `import { render } from 'react-dom'`. In React 19, the legacy `render`, `hydrate`, and `unmountComponentAtNode` functions were removed entirely. If you attempt to import `render` from `'react-dom'`, the imported value is `undefined`. Calling `render(...)` immediately crashes in the browser with `TypeError: render is not a function`. The modern mounting API lives exclusively in `'react-dom/client'`. Furthermore, keeping `createRoot` isolated in `main.jsx` ensures that your component files (`App.jsx`, `NewsBanner.jsx`) remain pure: they import only from `'react'`, keeping them independent of browser-specific mounting code. ◼ Educational objective: highlight the complete removal of legacy ReactDOM APIs in React 19 and isolate client mounting code to main.jsx.

> [!PRINCIPLE]
> **Principle 8: Expect root.render to Update the DOM After Your Code Continues**
> Understand that `root.render` schedules the rendering work asynchronously rather than updating the browser DOM immediately on the same line. Code written immediately after `root.render` still sees the container's old HTML content.
> 
> >> scheduled rendering : the asynchronous process where React queues updates and paints the DOM after current code finishes
> 
> *It is best practice to do this:*
> `root.render(~<App />~); // Schedules async render queue`
> 
> *Instead of doing this:*
> `root.render(<App />);`
> `console.log(container.~innerHTML~); // Stale: DOM has not updated yet`

- [p] ★ Principle 8 operational derivation: When developers come to React from imperative JavaScript, they often expect functions to complete all their work immediately. If you write `root.render(<h1>The National Times</h1>)` and on the very next line write `console.log(document.getElementById('root').innerHTML)`, the console does not log your new heading! Instead, it logs the old placeholder text that was originally inside `<div id="root">`. This happens because `root.render` does not block the main browser thread to mutate the DOM synchronously. It schedules a render task in React's internal queue. React evaluates your components, calculates the differences, and paints the real browser DOM only after your current JavaScript execution frame finishes and yields back to the browser. ◼ Educational objective: prove that root.render executes asynchronously and break the habit of querying the DOM immediately after rendering.

### Step 1: First, we inspect the host HTML document <index.html>

- [p] ★ {step motivation: inspecting the container element and deferred module script tag} We start at the root of the project by inspecting `index.html`. Unlike traditional web pages that contain hundreds of lines of static content, our React host document contains a clean, minimal shell. Inside the `<body>`, we define `<div id="root">` with a loading placeholder that appears while JavaScript loads. Crucially, we link our entry point using `<script type="module" src="/src/main.jsx"></script>`. Because this script tag has `type="module"`, the browser defers execution until the HTML document is fully parsed, ensuring `document.getElementById('root')` can always find the container. ◼ Meaningful pedagogical commentary: container element isolation, placeholder HTML, and deferred module script loading.

- [code] index.html:

```html title="index.html"
<!DOCTYPE html>
<html lang="en">
  <head>
    <title>The National Times</title>
  </head>
  <body>
    <div id=~"root"~><p>Loading...</p></div> // Mount target container
    <script type=~"module"~ src="/src/main.jsx"></script> // Entry script
  </body>
</html>
```

◼ **The what-this-introduces list:** 1. `<div id="root">`: the designated physical host container for React. 2. `<p>`: loading placeholder replaced on first render. 3. `<script type="module">`: deferred ES module script loading `src/main.jsx`.

### Step 2: Next, we construct the root component <src/App.jsx>

- [p] ★ {step motivation: creating the top-level parent component that will mount into the root} With our host HTML defined, we create `src/App.jsx`. This component acts as the root of our React component tree. Notice that `App.jsx` imports purely from `'react'` and child component files; it contains zero imports from `'react-dom'` or `'react-dom/client'`. By keeping `App` isolated from the DOM mounting bridge, our component remains pure, testable, and reusable. In this step, `App` renders the newsroom header and prepares a container for our child news banner. ◼ Meaningful pedagogical commentary: separating component logic from mounting code, pure component declarations.

- [code] App.jsx:

```jsx title="App.jsx"
import NewsBanner from './components/NewsBanner.jsx'; // Child module

export default function App() {
  return (
    <main className=~"newsroom-layout"~> // Root layout shell
      <h1>The National Times</h1>
      <NewsBanner message=~"Accord Finalized"~ /> // Composes banner
    </main>
  );
}
```

◼ **The what-this-introduces list:** 1. `import NewsBanner`: importing the modular child banner component. 2. `export default function App`: top-level root component function. 3. `<NewsBanner message="...">`: declarative child mounting with a message prop.

### Step 3: Then, we declare the child banner component <src/components/NewsBanner.jsx>

- [p] ★ {step motivation: declaring a modular child component that grows inside the App tree} Following our single-root rule, we grow our application by adding components inside `App`, rather than creating new roots. We create `src/components/NewsBanner.jsx` to display editorial announcements. It receives a `message` prop, displays a `"LATEST NEWS"` badge, and wraps the text in a clean container. Because this component lives in its own module, the editorial desk can update its layout without touching either `App.jsx` or the mounting entry file. ◼ Meaningful pedagogical commentary: modular leaf component structure, growing UI within the tree.

- [code] NewsBanner.jsx:

```jsx title="NewsBanner.jsx"
export default function NewsBanner({ ~message~ }) { // Leaf prop
  return (
    <aside className=~"news-banner"~> // Styled banner aside
      <span className="badge">LATEST NEWS</span>
      <p className="banner-text">{~message~}</p>
    </aside>
  );
}
```

◼ **The what-this-introduces list:** 1. `export default function NewsBanner`: named default export for the child component. 2. `{ message }`: prop destructuring receiving announcement text. 3. `<aside className="news-banner">`: semantic markup displaying the banner.

### Step 4: Finally, we initialize createRoot and mount the tree <src/main.jsx>

- [p] ★ {step motivation: bridging the virtual component tree to the physical browser DOM} Finally, we connect our React application to the browser page in `src/main.jsx`. We import `createRoot` from `'react-dom/client'`, and import our top-level `App` component. We find the container element using `document.getElementById('root')`. We check that the element exists, pass it to `createRoot`, and call `root.render(<App />)` with our root JSX tag. When Vite serves this project, React mounts `App`, clears the loading placeholder, and renders our complete newsroom interface into the browser window. ◼ Meaningful pedagogical commentary: connecting the mounting bridge, verifying container existence, executing root.render.

- [code] main.jsx:

```jsx title="main.jsx"
import { ~createRoot~ } from 'react-dom/client'; // React 19 client
import App from './App.jsx';

const container = document.getElementById(~'root'~); // Finds DOM node

if (container) {
  const root = ~createRoot(container)~; // Connects to DOM
  root.render(<App />); // Mounts tree into container
}
```

◼ **The what-this-introduces list:** 1. `import { createRoot } from 'react-dom/client'`: importing the modern browser mounting API. 2. `document.getElementById('root')`: finding the host DOM container. 3. `if (container)`: defensive guard preventing null pointer crashes. 4. `root.render(<App />)`: mounting the virtual component tree into the physical DOM.

### Where you will meet this

- [p] 1. **Project Scaffolding and Setup**: When you create a new application using Vite (`npm create vite@latest`), the generator creates `index.html`, `src/main.jsx`, and `src/App.jsx` using this exact `createRoot` mounting architecture.
- [p] 2. **Embedding React in Existing Web Pages**: When adding React to an existing server-rendered website (such as WordPress, Django, or Rails), you identify a single `<div>` on the page and mount a standalone React widget into it with `createRoot`.
- [p] 3. **Application Diagnostic Audits**: During production debugging, senior engineers inspect `main.jsx` to verify that root configuration options, error logging handlers, and StrictMode boundaries are correctly configured.

### Glossary

- [glossary] createRoot ◼ The modern React DOM client method that creates a concurrent root container for a physical browser element.
- [glossary] root.render ◼ The root method that schedules the rendering of a React element tree into the designated DOM container.
- [glossary] DOM Container ◼ The physical HTML element, typically `<div id="root">`, that React takes over to manage its user interface.
- [glossary] Module Script ◼ An HTML `<script type="module">` tag that loads ES modules and automatically defers execution until HTML parsing completes.
- [glossary] Vite Dev Server ◼ A local development server that compiles JSX on demand and serves native ES modules over HTTP with instant updates.
- [glossary] Single Root Architecture ◼ An application design pattern where one root manages the entire user interface tree from a single top-level component.

### Summary

**Architectural Takeaways & Decision Matrix**

❒ Root Initialization & Container Ownership

➔ ALWAYS pass an existing DOM element to `createRoot` and let React own that container's inner content.

➔ NEVER call `createRoot` twice on the same container; grow your application by adding child components inside `App`.

❒ Tooling & Mounting APIs

➔ ALWAYS import `createRoot` from `react-dom/client` in your entry file, and name JSX files with `.jsx`.

➔ NEVER open React projects over the `file://` protocol; always serve them over HTTP using Vite.

**DO THIS:** import createRoot from react-dom/client and render a React element

```jsx right
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = document.getElementById('root');
const root = createRoot(container);
root.render(<App />);
```

**DO NOT DO THIS:** import removed legacy render or pass raw functions without JSX tags

```jsx wrong
import { render } from 'react-dom';

render(App, document.getElementById('root'));
```

| | **MODERN REACT 19 & VITE**<br>(createRoot Pipeline) | **LEGACY / NAIVE PRACTICE**<br>(ReactDOM.render & file://) |
| ---: | :--- | :--- |
| **Mounting Function** | `createRoot`<br>`(container)`<br>`from`<br>`'react-dom/client'` | `ReactDOM.render()`<br>*(Removed in React 19)* |
| **Container Ownership** | Owns `<div id="root">`;<br>first render clears content | Uncontrolled replacement or<br>mounting to `document.body` |
| **Server Protocol** | Local HTTP server<br>(`http://`<br>`localhost:5173`) | Opening local disk files<br>via `file://` (blocks CORS) |
| **File Extension** | `.jsx` or `.tsx` required<br>for JSX compilation | `.js` files containing JSX<br>(fails with syntax error) |
| **Render Execution** | Scheduled asynchronously;<br>browser paints smoothly | Synchronous expectation;<br>queries return stale DOM |
| **Component Growth** | Single root;<br>all new UI nests in `<App />` | Multiple roots on same node<br>(triggers warning) |
