### The Evaluation Window: Bridging Markup and JavaScript Execution

- [p] ◇ {conceptual grounding: curly braces act as an inline escape hatch into JavaScript} To understand how React resolves variables, we must recognize that JSX operates in two alternating modes: markup mode and JavaScript mode. When the compiler parses tags, it begins in markup mode. In markup mode, any characters you type between tags are treated as literal text. To step out of static markup and execute live JavaScript, React provides an **evaluation window** marked by curly braces (`{}`). When the compiler encounters an opening curly brace `{`, it switches out of markup mode and evaluates whatever valid JavaScript expression sits inside before returning to markup mode at the closing brace `}`. ◼ Educational objective: establish curly braces as an inline mode-switching evaluation portal.
- [p] ◇ {the grammar divide: expressions produce values while statements execute actions} The most critical rule of the JSX evaluation window is the distinction between **expressions** and **statements**. In ECMAScript grammar, an **expression** is any unit of code that evaluates to a single discrete value in memory. Numbers (`4 + 2`), variables (`headline`), template literals (`` `${readTime} min` ``), ternary conditions (`isUrgent ? "URGENT" : "STANDARD"`), and function calls (`formatDate()`) are all expressions. A **statement**, by contrast, is a command that controls execution flow without returning a value. Statements like `if`, `for`, `while`, `switch`, and `function` declarations perform actions but produce zero values in memory. Because JSX tags compile directly into JavaScript function arguments, every item inside curly braces must produce a value that can be passed into `_jsx()`. ◼ Educational objective: derive the expression-versus-statement invariant from ECMAScript grammar and function argument requirements.
- [p] ◇ {the primitive render matrix: visual painting versus silent values} Once an expression evaluates, React consults its **primitive render matrix** to determine what appears on screen. Strings and numbers evaluate directly into visible DOM text nodes (`4` renders as the text "4"). However, booleans (`true`, `false`), `null`, and `undefined` are treated as **invisible visual values**. React renders nothing to the DOM for these types. This intentional design allows developers to use logical expressions like `{isUrgent && <span className="alert">LIVE</span>}` to show or hide elements conditionally without printing ugly strings like "false" or "null" onto the user's screen. ◼ Educational objective: explain how React's primitive render matrix enables conditional rendering while keeping falsy tokens invisible.

### Principles of React: JavaScript Expressions and JSX Evaluation

- [p] ◇ In technical interviews, engineering candidates are routinely evaluated on their understanding of compiler boundaries, language grammar, and how JSX transforms dynamic data into DOM output. To master this architecture, we formalize the five governing principles of JavaScript expressions in JSX: ◼ Educational objective: frame the upcoming principles around senior technical evaluation and compiler mechanics.

> [!PRINCIPLE]
> **Principle 1: Step Out of Static Markup Using Curly Braces as an Evaluation Window**
> We put curly braces `{}` around variables when we want to step out of plain HTML text (**static markup**). The **curly braces** open a window where React can read live values from JavaScript memory.
> 
> >> curly braces : punctuation markers ({}) that open an inline JavaScript evaluation window inside JSX
> >> static markup : raw HTML text nodes that display character strings literally on screen
> 
> *We should do this:*
> `<h2>{headline}</h2>`
> 
> *We should not do this:*
> `<h2>headline</h2>`

- [p] ★ A React component executes as standard JavaScript. When the compiler encounters an HTML tag in JSX, it treats all enclosed content as a raw string literal. Writing `<h2>headline</h2>` instructs the compiler to emit `_jsx("h2", { children: "headline" })`. The browser paints the literal characters "headline". Placing curly braces around the variable tells the parser to switch from markup tokenization to JavaScript expression evaluation. The compiler emits `_jsx("h2", { children: headline })`, passing the unquoted variable reference directly to the runtime so the browser paints the actual article title. ◼ Educational objective: unpack the compilation difference between string literal children and identifier references.

> [!PRINCIPLE]
> **Principle 2: Pass Only Value-Producing Expressions Inside Curly Braces**
> We only put code that calculates a direct value inside curly braces (**JavaScript expressions that resolve to a value**). We cannot put blocks like `if` or `for` inside curly braces (**control-flow statements**) because they do not produce a value.
> 
> >> JavaScript expressions that resolve to a value : units of code that calculate a result you can pass as an argument
> >> control-flow statements : imperative blocks like if, for, or while that execute actions without evaluating to a value
> 
> *We should do this:*
> `<span className="badge">{isUrgent ? 'URGENT' : 'STANDARD'}</span>`
> 
> *We should not do this:*
> `<span className="badge">{if (isUrgent) { 'URGENT' }}</span>`

- [p] ★ In JavaScript, every function call requires arguments that evaluate to discrete values: `doSomething(argument)`. Under the hood, JSX compiles tags into `_jsx(type, props)` function calls. Child content inside tags compiles into the `children` property of the `props` argument object: `_jsx("span", { children: [expression] })`. If you place an `if` statement inside curly braces, the compiler attempts to emit `_jsx("span", { children: if (isUrgent) { "URGENT" } })`. In ECMAScript grammar, placing a statement inside an object literal or function argument list is a fatal syntax violation. Ternary expressions (`condition ? a : b`) and logical operators (`a && b`) resolve to single values, making them syntactically valid everywhere expressions are accepted. ◼ Educational objective: deconstruct the ECMAScript argument invariant that permits expressions and rejects statements.

> [!PRINCIPLE]
> **Principle 3: Drop String Quotes to Bind Dynamic Attributes**
> We connect dynamic data to attributes using curly braces without any quotation marks (**naked curly braces**). If we add quotes around the braces, React will treat our variable as plain text instead of reading the live data (**dynamic attribute values**).
> 
> >> naked curly braces : curly braces placed directly after the equals sign without enclosing quotation marks
> >> dynamic attribute values : element properties that read variable values from JavaScript memory at runtime
> 
> *We should do this:*
> `<img src={avatarUrl} alt="Reporter" />`
> 
> *We should not do this:*
> `<img src="avatarUrl" alt="Reporter" />`

- [p] ★ When assigning attributes in JSX, quotation marks and curly braces are mutually exclusive. Double quotes (`src="..."`) signal a static string literal. If you write `src="avatarUrl"`, the compiler assigns the literal seven-character string `"avatarUrl"` to the DOM element's `src` property. If you write `src="{avatarUrl}"`, the compiler assigns the literal nine-character string `"{avatarUrl}"`. To pass a live JavaScript variable or calculated value, you must omit the quotes entirely and write `src={avatarUrl}`. The compiler transforms this into `_jsx("img", { src: avatarUrl, alt: "Reporter" })`, reading the living string stored in memory and passing the correct file path to the browser image loader. ◼ Educational objective: explain why quotes and curlicues cannot be combined and show the resulting transpiled object.

> [!PRINCIPLE]
> **Principle 4: Respect React's Primitive Render Matrix for Booleans, Null, and Undefined**
> We rely on React's built-in rules for primitive types (**primitive render matrix**). React displays text and numbers on the screen, but it leaves booleans, `null`, and `undefined` completely hidden (**invisible**).
> 
> >> primitive render matrix : the engine lookup table governing how raw JavaScript data types paint to the DOM
> >> invisible : evaluating cleanly in code while emitting zero characters or nodes to the browser document
> 
> *It is best practice to do this:*
> `<p>Read time: {readTime} min</p>`
> 
> *Instead of doing this:*
> `<p>Read time: {String(readTime)} min</p>`

- [p] ★ In JavaScript, data primitives behave differently when cast to strings. When React resolves child expressions, it checks the runtime type of each value. Numbers (`42`) and strings (`"Transit"`) compile directly into DOM text nodes. However, boolean values (`true`, `false`), `null`, and `undefined` are classified as empty render slots. React deliberately renders nothing for these primitives. This behavior is essential for conditional rendering: writing `{isUrgent && <span className="alert">LIVE</span>}` evaluates to `false` when the story is not urgent. Because `false` renders nothing, the badge disappears cleanly from the layout with zero extra DOM nodes and zero literal "false" text printed to the page. ◼ Educational objective: deconstruct the primitive render matrix and explain why boolean values render silently.

> [!PRINCIPLE]
> **Principle 5: Double Curlicues Represent Object Literals Inside the Evaluation Window**
> We write style objects using two sets of curly braces like `style={{ color: 'red' }}` (**double curly braces**). The outer braces open the JavaScript window in JSX, while the inner braces create a normal JavaScript object (**object literal**).
> 
> >> double curly braces : an outer evaluation brace enclosing an inner JavaScript object literal ({ { ... } })
> >> object literal : a comma-separated list of key-value pairs wrapped in curly braces in JavaScript memory
> 
> *We should do this:*
> `<div style={{ padding: 16, backgroundColor: '#f1f5f9' }} />`
> 
> *We should not do this:*
> `<div style={ padding: 16, backgroundColor: '#f1f5f9' } />`

- [p] ★ A common source of confusion for junior developers is the double curly brace syntax seen in inline styles: `style={{ width: 100 }}`. React does not have a special double-brace operator. The first, outer curly brace `{` opens the JSX evaluation window. The second, inner curly brace `{ width: 100 }` is an ordinary JavaScript object literal. If you omit the inner braces, the parser attempts to evaluate `padding: 16` as a labeled statement, triggering a fatal syntax crash. Recognizing that `{{}}` is simply an object literal sitting inside an evaluation window demystifies the syntax and reinforces the rule that curly braces accept any valid JavaScript expression. ◼ Educational objective: demystify double curly braces by dissecting them into an evaluation window plus an object literal.

- [comparison] Expressions vs Statements in JSX Evaluation Windows:
| **SYNTAX CONSTRUCT**<br>(JavaScript code unit) | **GRAMMAR TYPE**<br>(ECMAScript classification) | **VALID IN JSX CURLIES?**<br>(compiler acceptance) | **RUNTIME CONSEQUENCE**<br>(compiler & DOM behavior) |
| :--- | :--- | :--- | :--- |
| `headline`<br>`readTime` | Variable identifier<br>(Expression) | Valid<br>`<h2>{headline}</h2>` | Evaluates variable value in memory; paints string or number to DOM |
| `readTime * 2`<br>`count + 1` | Mathematical operation<br>(Expression) | Valid<br>`<span>{readTime * 2}</span>` | Calculates arithmetic result; emits single numeric value to text node |
| `` `${readTime} min` `` | Template literal<br>(Expression) | Valid<br>`<p>{`${readTime} min`}</p>` | Evaluates string interpolation; emits unified string to text node |
| `isUrgent ? 'A' : 'B'` | Ternary conditional<br>(Expression) | Valid<br>`<span>{isUrgent ? 'A' : 'B'}</span>` | Resolves condition; returns single branch value to component props |
| `if (isUrgent) { ... }` | Control-flow block<br>(Statement) | Invalid<br>(Compiler Crash) | Produces no value; triggers `SyntaxError: Unexpected token 'if'` |
| `for (let i = 0...)` | Iteration block<br>(Statement) | Invalid<br>(Compiler Crash) | Executes side effects without value; rejected by compiler argument parser |

- [p] ★ To see how these principles operate under the hood, examine the transpiled JavaScript output emitted by the compiler. When build tools transform JSX, every expression inside curly braces becomes an argument in a standard `_jsx()` call:

- [code] JSX Transpilation of Expressions:

```js title="Transpiled Expression Output"
import { jsx as _jsx, jsxs as _jsxs } from 'react/jsx-runtime';
const output = _jsxs("article", {
  className: "dispatch-card",
  children: [
    _jsx("h2", { children: headline }), // Passes identifier as children **VALUE**
    _jsx("img", { src: avatarUrl, alt: "Reporter" }), // Passes variable to src **PROPERTY**
    _jsxs("p", { children: [readTime, " min read"] }) // Passes number and string in **ARRAY**
  ]
});
```

◼ **The what-this-introduces list:** 1. `children: headline`: variable identifier passed directly without string quotation marks. 2. `src: avatarUrl`: dynamic attribute mapped straight to the element property object. 3. Array of children: how React receives mixed expressions and static strings in a single parent container.

- [callout] > [!TIP] **To impress the interviewer:** When asked why you cannot write an `if` statement inside JSX curly braces, avoid saying "because React doesn't support if statements." The authoritative, senior answer is rooted in **ECMAScript argument grammar**: JSX tags compile directly into JavaScript function calls (`_jsx()`). In JavaScript, the arguments passed to a function call must be expressions that evaluate to a value. An `if` block is a control-flow statement that returns no value, making it syntactically illegal as a function argument. To conditionally render content inside JSX, you use value-producing expressions such as ternary operators (`condition ? a : b`) or logical AND operators (`condition && a`).

### Step 1: First, we construct the news dispatch card with inline expressions <DispatchCard.jsx>

- [p] ★ In Step 1, we build the presentation card component `DispatchCard.jsx`. On The National Times, breaking news dispatches require live data: a story headline, an author byline, an avatar image, an urgency flag, and an estimated reading time. In traditional templates, developers had to concatenate strings or perform manual DOM selections. - [p] ◇ When passing values to JSX attributes, developers choose between two syntax approaches:
- [p] ◇ - **Option 1 (The Foundational Way: Static String Attribute)**: Wrap the attribute value in double quotes (`src="avatarUrl"`), treating the value as a literal string.
- [p] ◇ - **Option 2 (The Modern Idiomatic Way: Dynamic Expression Window)**: Supply the attribute value in naked curly braces (`src={avatarUrl}`), evaluating the variable reference in memory.

- [p] ★ First, examine Option 1 with a static string attribute:

- [code] Option 1: The Foundational Way (Static String Attribute):

```jsx title="DispatchCard.jsx"
  const headline = "Metropolitan Transit Union Approves Contract";
  const reporter = "Clara Foster";
  const avatarUrl = "/photos/clara.jpg";
  const readTime = 4;
  const isUrgent = true;
  return (

  );
}
```

### Glossary

- [glossary] Evaluation Window ◼ An inline JavaScript portal established by curly braces (`{}`) inside JSX that steps out of static markup to evaluate live expressions.
- [glossary] JavaScript Expression ◼ Any unit of code that evaluates to a single discrete value in memory (such as variables, math, ternary operations, and function calls).
- [glossary] Control-Flow Statement ◼ Imperative JavaScript language constructs (like `if`, `for`, or `while`) that execute actions without returning a value, strictly forbidden inside JSX curly braces.
- [glossary] Dynamic JSX Attribute ◼ An HTML-like element property bound to a live JavaScript expression using naked curly braces without quotes (`src={avatarUrl}`).
- [glossary] Primitive Render Matrix ◼ React's internal type-resolution rules that paint numbers and strings to the DOM while rendering booleans, `null`, and `undefined` as invisible empty output.
- [glossary] Double Curlicues ◼ The syntax pattern `{{ ... }}` used in JSX where an outer evaluation window encloses an inner JavaScript object literal.

### Summary

**JavaScript Expressions in JSX Decision Matrix**

❒ Text and Variable Interpolation

➔ ALWAYS enclose JavaScript variables in curly braces (`<h2>{headline}</h2>`) to project evaluated runtime values into the rendered DOM.

➔ NEVER write bare variable names inside tag children (`<h2>headline</h2>`), which causes the browser to display literal placeholder text.

❒ Dynamic Attribute Binding

➔ ALWAYS use naked curly braces without quotes (`src={avatarUrl}`) when binding dynamic variables to HTML attributes.

➔ NEVER enclose curly braces in quotation marks (`src="{avatarUrl}"`), which instructs the compiler to treat the expression as a literal string.

❒ Expressions vs Statements

➔ ALWAYS use value-producing expressions (such as ternary operators `{isUrgent ? 'A' : 'B'}`) inside curly braces.

➔ NEVER place control-flow statements (`if`, `for`, `while`) inside JSX curly braces, which triggers fatal compiler syntax crashes.

**DO THIS:** Evaluate expressions with curly braces and bind naked attributes

```jsx right
export default function DispatchCard() {
  const headline = "Transit Union Approves Contract";
  const avatarUrl = "/photos/clara.jpg";
  return (
    <article className="dispatch-card">
      <h2>{headline}</h2>
      <img src={avatarUrl} alt="Reporter" />
    </article>
  );
}
```

**DO NOT DO THIS:** Write literal variable names or quote dynamic attribute curlicues

```jsx wrong
export default function DispatchCard() {
  const headline = "Transit Union Approves Contract";
  const avatarUrl = "/photos/clara.jpg";
  return (
    <article className="dispatch-card">
      <h2>headline</h2>
      <img src="avatarUrl" alt="Reporter" />
    </article>
  );
}
```

| | **STATIC JSX MARKUP**<br>(Raw String Mode) | **DYNAMIC JSX EXPRESSIONS**<br>(Evaluation Window `{}`) |
| ---: | :--- | :--- |
| **Text Interpolation** | Writes literal characters:<br>`<h2>headline</h2>` | Evaluates identifier in memory:<br>`<h2>{headline}</h2>` |
| **Attribute Binding** | Raw string literal:<br>`src="avatarUrl"` | Living variable reference:<br>`src={avatarUrl}` |
| **Accepted Grammar** | Raw text tokens and XML tags | Any value-producing expression:<br>ternary, math, template literal |
| **Forbidden Grammar** | Unclosed XML tags | Control-flow statements:<br>`if`, `for`, `while`, `switch` |
| **Boolean Output** | Prints literal string:<br>`"true"` or `"false"` | Invisible visual value:<br>emits zero nodes to the DOM |
| **Under the Hood** | Emits static string argument:<br>`_jsx("h2", { children: "headline" })` | Emits runtime variable argument:<br>`_jsx("h2", { children: headline })` |
