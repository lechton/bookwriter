## 1. Why This Batch Exists

In Principle 2 of Lecture 20 (`defaultValue` vs. `value`), the text opened with a five-paragraph buildup before stating what either prop meant:

> We have two versions of the same page. They differ in one word on the box. The first version uses `defaultValue`. The second version uses `value`. In both versions, the user types John. Both boxes show John. So far, there is no difference. Then the user clicks Clear... That is strange. `name` is empty, and the greeting shows it. So why does the box still show John?

For a fast thinker and impatient reader, this suspense is frustrating. They cannot hold multiple unresolved pieces (`A`, `B`, typing outcomes, button clicks, and a riddle) in working memory while waiting for a resolution several paragraphs later. Worse, if the resolution after the definition merely recites the code trace mechanically (`setName('') empties name, React re-renders and writes that empty string`), it bores the reader instead of giving them the logical picture.

Two places in `writing/SKILL.md` had encouraged that suspense:
1. Section 3 (`Show what happens, step by step, when the result surprises`) used the five-paragraph `defaultValue` vs. `value` riddle as its `PROPER` example.
2. Section 4 (`Say "the same" or "not the same" only after the steps`) told the writer to hold back the verdict until the end of the explanation.
