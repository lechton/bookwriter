# Brief 2026-11-09 03: Browser preview before the opening code when the example has enough to show

## Why

In the Lecture 22 opening, the example shows a list of three players (`John`, `Mia`, `Sara`) and a `3 players` count line above them. Placed directly before the code, a `page` browser preview lets the reader see both parts on the screen at once before comparing the two ways of writing the count in code. In other openings, such as a single `<p>{text}</p>` line that prints `John` or an attribute on `<MyComponent />`, a browser preview has too little information to add anything beyond the one line of code.

Earlier, `skills/v10.6/moves/smallest-code-first.md` said "When the idea shows on a page, show the browser first, then the code, then the browser after each thing the user does", which was too broad, while `skills/v10.6/opening-essence/SKILL.md` did not say when to place a browser preview before the opening code.

## What changed

Group 1:
1. `skills/v10.6/opening-essence/SKILL.md`, Move 1, first form: when the opening example has enough on-screen parts to make a browser preview meaningful, such as a list of players and a count line above it, show that browser preview directly before the code; skip the preview when the code only passes props or renders a single word such as `John`.
2. `skills/v10.6/moves/smallest-code-first.md`, How to do it, item 2: show the browser directly before the code when the example has enough information on the screen for a browser preview to help, and skip it when the example has too little to show on a screen.

Group 2: this brief, its row in `01_TOC.md`, and two rows in `skills/v10.6/RULE-TAGS.md`.

## How far it reaches

Applies to the Opening Essence of a lecture and the start of a principle whenever the opening uses the smallest code first.
