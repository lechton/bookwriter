# Brief 2026-11-13 01: how react-10 lectures are written with bookflow, Opus 5.5 high in every step

Tag: #2026_11_13_01_group_1

## Why

The owner asked to record how the remaining react-10 lectures are written, so the same operation can be repeated later in the same way: the command, the models, the skills, the steps, and what to do when a run stops. React 11 now exists as the default React project, but react-10 keeps being finished with bookflow exactly as lectures 21 to 40 were written.

## What was done

- Lectures 34 and 35 were written on 2026-11-09, and lectures 36 to 38 in the run that started on 2026-11-10.
- On 2026-11-13 a test run wrote lectures 39 and 40. Lecture 39 already had its map from the 2026-11-10 run, so the run kept it and started at the draft. Both lectures finished with lecture, lab report, HTML, and PDF.
- Right after, a run for lectures 41 to 60 started at 03:09.

## The settings

- **Project:** `projects/react-10`. Bookflow writes only in the folder it runs in, so react-11 is never touched.
- **Questions:** `questions/questions.md`, 180 questions. Each lecture number is a question number.
- **Skills:** `skills/v10.6`, the folder every lecture so far used. Bookflow picks the newest skills folder by default, which is now `v10.7`, so the command names `skills=v10.6`. For the writing agents `v10.7` is the same: it differs only in `README.md`, `RULE-TAGS.md`, and the version names inside `editing-skills/SKILL.md`.
- **Models:** Opus 5.5 with high thinking (`droid/claude-opus-5-5:high`) for all four agents: the mapper, the writer (drafter), the lecturer, and the checker. The command names each one, so a change of the defaults in the factory repo cannot change them.
- **Lecture:** `lecture=whole`, one chat writes the whole lecture.
- **Tries:** 3 for each step, then the lecture is skipped and the run goes to the next one.

## The steps of one lecture

Bookflow looks at which files of the lecture already exist and starts at the first missing step. A file that exists is kept.

1. **Look.** No agent. Picks the next step from the files on disk.
2. **Map.** Opus 5.5 high writes the principle map in `01-01-map-principles/v1/NN.md`. It reads the skills `README.md`, `lecture`, `map`, and `opening-essence`.
3. **Draft.** Opus 5.5 high writes the first draft from the map in `01-01-md-DRAFT-lectures/v1/NN.md`. It reads `README.md`, `lecture`, and `check`.
4. **Lecture.** Opus 5.5 high writes the final lecture in `01-02-md-LECTURES/v1/NN.md`. It reads `README.md`, `lecture`, and `check`.
5. **Save copy.** No agent. The lecture is copied into the archive before the check may change it.
6. **Check.** Opus 5.5 high runs the lecture's code in `lab/`, fixes the lecture where the code does not behave as written, and writes the report `lab/reports/NN.md`. It reads `README.md`, `check`, `figures`, and `lecture`.
7. **Build.** No agent. Builds `01-03-md-lectures-HTML/v1/NN.html` and `01-04-md-lectures-PDF/v1/NN.pdf`.

The skills point the agents on to the others they need, such as `moves`, `examples`, and `clarity`. One lecture takes about 30 minutes: lecture 40 took 31 minutes.

## The command

Run it from the project folder, inside a `screen` session, so the run keeps going when the chat or the terminal window closes. Change `from` and `to` to the lectures wanted.

```
cd projects/react-10
M=droid/claude-opus-5-5:high
screen -dmS bookflow-41-60 sh -c "factory workflow bookflow from=41 to=60 skills=v10.6 lecture=whole model=$M mapper_model=$M writer_model=$M lecturer_model=$M checker_model=$M > ~/.factory/bookflow/screen-41-60.log 2>&1"
```

- Watch it: `tail -f ~/.factory/bookflow/screen-41-60.log`, and `Ctrl+C` to stop watching. The run goes on.
- Open the run screen: `screen -r bookflow-41-60`, and `Ctrl+A` then `D` to leave it running.
- The run log of each run and of each lecture is in `~/.factory/bookflow/react-10/`.
- Only one run at a time on the same project.

## When a run stops

- **Stopped from outside.** Two runs started directly from an agent chat on 2026-11-09 and 2026-11-13 were stopped after 10 to 15 minutes. The screen said "stopped by you" and the run log "host-failure". A run inside `screen` was not stopped. Nothing was lost: the agent of the step kept working and saved its file.
- **Continue.** In the project folder, `factory workflow bookflow continue=true` continues the stopped run from its next step. A finished step is never done again. Inside `screen`: `screen -dmS bookflow-continue sh -c "factory workflow bookflow continue=true > ~/.factory/bookflow/screen-continue.log 2>&1"`.
- **The 2-hour limit.** The factory engine gives each agent step at most 2 hours (`thinkTimeoutMs` in the factory repo, `libs/workflows/engine/walk/settings.ts`). On 2026-11-10 the draft of lecture 39 hit it: the agent started at 02:53, the engine gave up at 04:53, and the run stopped with "child-failed". A draft normally takes 5 to 10 minutes, so that agent was stuck, not slow. A new run starts that lecture again at its first missing file.
- **Lost internet.** On 2026-11-13 the lecture agent of lecture 40 lost its connection after it had saved the lecture. The run does not stop: the screen shows "factory: waiting" with the agent's thread, and the run sends "continue" to that thread by itself. Sending "continue" to the thread in Synara by hand also works. The run then goes on by itself.
