What Conditional Rendering Is and Why We Need It

React does not invent special HTML attributes for conditions! You use plain JavaScript right inside your component function. An if check at the top hides the whole component, the ternary operator switches between two elements, and && includes one element when a condition is true.

Look at the three words that unlock every rule in this lesson:

  • What does "conditional rendering" mean? It simply means returning different markup depending on a condition, instead of creating every DOM node ahead of time and hiding elements with CSS.
  • What does "ternary" mean? Just like primary means one and secondary means two, ternary means three parts: the condition before ?, the true branch, and the false branch after :.
  • What does "short-circuit" with && mean? It works like an electrical switch that stops the current early. When the left side of && is falsy, JavaScript stops right there and hands that left-hand value back without running the right side!

What conditional rendering means in React

Look at any real city news page. Every story card shares the same outer box, yet different stories show different pieces inside. An unfinished draft story should not appear on the public feed at all. A subscriber-only story hides its summary and shows a sign-in notice instead. A breaking news story wears a Live badge at the top, while a regular story leaves that badge off. And a story with four reader comments shows a comment count at the bottom, while a story with zero comments hides that line.

In plain JavaScript without React, you would put every possible badge, notice, and counter into the HTML ahead of time. Then you would hunt through the page and toggle CSS classes to hide the pieces you do not want.

In React, you never hide and show DOM nodes by hand. Instead, your component checks its props and returns only the markup that belongs on the screen. Returning different markup depending on a condition is called conditional rendering.

Three ways to write conditions in React: if, ? :, and &&

React does not invent special HTML attributes for conditions. Because a React component is a JavaScript function, you choose what markup to return with three standard tools from plain JavaScript:

  • An if statement before return decides whether the whole component returns its markup or stops early and returns null so nothing appears on the page.
  • The ternary operator sits inside JSX curly braces and switches between two pieces of markup in one spot, using ? for the first branch and : for the second.
  • The logical AND operator && sits inside JSX curly braces and includes one piece of markup only when a boolean condition is true.

Why if stays outside curly braces while ? : and && go inside

Recall from earlier lessons that curly braces { } inside JSX open a window for JavaScript. However, you cannot put every kind of JavaScript inside { }. JavaScript divides its code into two groups:

  • A statement performs an action, such as an if block or a let variable declaration. A statement does not produce a value, so it can only live outside JSX, above return.
  • An expression produces a single value, such as a ternary switch or an && check. Because JSX curly braces { } must hand a value to React, only expressions can sit inside { }.

When an expression inside { } finishes running, it hands its resulting value to React. React divides those values into two groups when building the browser DOM:

  • Values that render visible text: React turns strings and numbers, including the number 0, into visible text nodes on the page.
  • Values that render nothing at all: React treats null, undefined, booleans, and an empty string as empty holes in the markup. It creates zero DOM nodes for them.

Four Principles of Conditional Rendering

PRINCIPLES

Every conditional rendering bug comes from mixing up where statements and expressions belong, or forgetting what value JavaScript actually hands to React. Walking from the top of our card component down into its markup gives us four rules:

  1. Principle 1: Returning Early with if and return null: An if statement at the top of a component can stop the function early when nothing should appear on screen. Returning null tells React to create zero DOM nodes, while forgetting that check lets an unpublished draft card leak onto the public page.
  2. Principle 2: Switching Between Two Branches with the Ternary Operator: JSX curly braces only accept expressions that produce a value. Writing an if statement inside { } stops the build with a syntax error. Instead, use the ternary operator inside curly braces, or set a let variable above return when the branches grow long.
  3. Principle 3: Showing One Element with && and a Real Boolean: Inside curly braces, the && operator shows a badge when its condition is true and returns false when the condition is false. React renders nothing for the boolean false. However, passing "false" in quotation marks sends a non-empty text string that is truthy in JavaScript, so the badge appears anyway!
  4. Principle 4: Avoiding the Zero Trap on the Left Side of &&: Never put a raw number directly on the left side of &&. When a comment count is zero, the && operator returns the number 0 itself, and React prints a stray zero on the page! Always compare the number with > 0 so the left side evaluates to a real boolean.

Section 2 · Principle 2Use the Ternary Operator ? : to Switch Between Two Elements

Why you cannot put an if statement inside JSX curly braces

In Principle 1, we hid the entire card by putting an if statement above return. Now what if we want to keep the card's outer box, heading, and reading-time line, and swap only the middle paragraph?

Beginners know that curly braces { } run JavaScript inside JSX, so they often try to write an if block right inside the braces. However, JSX curly braces sit inside a JavaScript function call where a value expression is required, and an if block is a statement rather than a value. To switch between two pieces of markup inside curly braces, use the ternary operator. When the branches get long, assign the markup to a let variable before return.

How the ternary operator ? : works in plain JavaScript

In plain JavaScript, an if statement controls which block of lines runs. The ternary operator is a compact expression that evaluates directly to a single value. It has three parts:

  1. Before the question mark ?: the condition to test.
  2. Between ? and the colon :: the value returned when the condition is true.
  3. After the colon :: the value returned when the condition is false.

Look at how the ternary operator produces a value directly inside a variable assignment, where an if statement cannot sit:

Plain JavaScript
1const isSubscriberOnly = true;
2
3const message = isSubscriberOnly ? 'Subscribers only' : 'Open story';
Expression: evaluates to 'Subscribers only'
4console.log(message);

Section 3 · Principle 3Use Logical AND && with a Boolean to Show or Hide One Element

Why isBreaking ? <LiveBadge /> : null and isBreaking && <LiveBadge /> do the exact same thing

In Principle 2, we had two branches: a subscriber notice or a story summary. Now what if there is only one branch? When a story is breaking news, we want to show a Live badge at the top of the card. When it is not breaking news, we want to show nothing at all in that spot.

Look at two ways to write that one-branch check inside JSX curly braces side by side:

A ternary with : null vs. the && shortcut
1{isBreaking ? <LiveBadge /> : null}
1. Ternary with : null when false
2{isBreaking && <LiveBadge />}
2. Logical && shortcut: returns false when isBreaking is false

Yes, when isBreaking is a real boolean, both lines do the exact same thing! You do not need to write : null at the end when there is no second branch.

However, look at what happens if the parent passes "false" in quotation marks instead of {false} in curly braces:

  • Boolean in curly braces: Passes the real boolean false. The && operator stops at the left side and returns false, which React renders as zero DOM nodes.
  • String in quotation marks: It may look like false, but it is NOT the same thing! Quotation marks pass the five-letter text string 'false'. Because every non-empty string is truthy in JavaScript, && keeps going and renders the Live badge anyway!

How the && operator works in plain JavaScript

In plain JavaScript, the logical AND operator && reads from left to right. This behavior is called short-circuit evaluation:

  • If the left side is falsy, && stops right there and returns that exact left-hand value without looking at the right side.
  • If the left side is truthy, && keeps going and returns the right-hand value.

For the Interview

The Interview Question: How do you show, hide, or switch JSX based on a condition?

How to Answer Clearly in 30 Seconds

"React handles conditional rendering with standard JavaScript rather than special template attributes:

  1. Early return with if and return null outside JSX: Before the component's return statement, an if statement can return a different JSX tree early, or return null when the component should render nothing at all. When a component returns null, React creates zero DOM nodes for it.
  2. The ternary operator condition ? <A /> : <B /> inside { }: JSX curly braces only accept JavaScript expressions that evaluate to a value, so writing {if ...} inside { } fails at build time with a syntax error. To switch between two pieces of JSX inline, we use ? :. When the branches get long, we assign JSX to a let variable inside an if block before return.
  3. The logical AND operator condition && <Element /> inside { }: To show one piece of JSX when a boolean condition is true and nothing when it is false, we use &&. When the left side is false, && short-circuits to false, and React treats false, null, and undefined as empty holes that produce zero DOM nodes.
  4. Never put a raw number on the left side of &&: If we write {commentCount && <p>{commentCount} comments</p>} and commentCount is 0, 0 && <p>...</p> evaluates to the number 0 rather than false. Because React renders numbers as visible text nodes, a literal 0 appears on the screen! Always write {commentCount > 0 && <p>{commentCount} comments</p>} so the left side evaluates to a boolean."

Three Classic Follow-Up Questions Interviewers Ask

  1. "Why does {commentCount && <p>{commentCount} comments</p>} print 0 on the screen when commentCount is 0, and what does React render for all six falsy values in JavaScript?"
    JavaScript's && operator does not convert its left side into a boolean; when the left side is falsy, && returns that exact left-hand value. So 0 && <p>...</p> returns the number 0. React ignores false, null, undefined, and the empty string "", creating zero DOM nodes for those four falsy values. However, 0 is a valid number to display in UIs such as prices and scores, so React renders 0 as a text node "0" in the DOM. And if a broken calculation produces NaN, NaN && <p>...</p> returns NaN, which React renders as "NaN" while logging a Console error. Comparing commentCount > 0 && ... converts the left side into the boolean false so nothing renders.
  1. "Why can't you write an if statement directly inside JSX curly braces { }, and when should you use let with if instead of ? :?"
    During the build, JSX tags compile into _jsxDEV function calls whose children sit inside an object property or array. A JavaScript function argument or array slot can only hold an expression that evaluates to a value, such as a ? b : c or a && b. Because if / else is a statement rather than a value expression, {if ...} stops the parser at build time with Unexpected token. When a condition switches between two compact pieces of markup, inline ? : is clean. When a branch spans many lines or needs else if, we declare a let variable before return and reassign it in an if block. That keeps the shared wrapper in one place without nesting ternaries.
  1. "What happens if a parent component passes isBreaking=\"false\" in quotation marks to a child that renders {isBreaking && <LiveBadge />}?"
    The LiveBadge still renders on the screen with zero Console errors! Quotation marks on a JSX attribute always create a JavaScript string literal. Inside the child component, isBreaking is the five-character string 'false', not the boolean false. In JavaScript, every non-empty string is truthy, so 'false' && <LiveBadge /> evaluates and returns the right-hand side, <LiveBadge />. Boolean props must be passed inside curly braces, such as isBreaking={false}.
