The children Prop, Spread Attributes, and Default Values

Interview Question · ❱ CORE

How do the children prop, spread attributes, and default values work?

OverviewWhat children, Spread Attributes, and Default Values Do

Two ways to pass information into a component: on the tag vs. between the tags

When you place a component tag on the page, there are two ways to pass information into it. You can write a named attribute on the opening tag, or you can place content directly between the opening and closing tags:

Two ways to pass information into MyComponent
1<MyComponent name="John" />
1. Passed as a named attribute on the opening tag
2<MyComponent>My name is John</MyComponent>
2. Placed between the opening and closing tags

Look at where each piece of information lands inside the component's props object:

  • In the first tag, you gave the value the attribute name name. React puts "John" inside props.name.
  • In the second tag, you wrote no attribute name at all. Instead, you placed the greeting text directly between the opening and closing tags. Whenever you place anything between a component's opening and closing tags, React automatically puts all of it inside props under one reserved name: children. Here, props.children holds that greeting text.

Why your component must write {children} to show wrapped elements

Look closely at the two kinds of wrapper tags in our code: a built-in HTML <article> tag and our own <ArticleCard> component tag. Both can wrap elements between an opening tag and a closing tag.

Yet the browser and React handle those wrapped elements in two very different ways:

  • On a built-in HTML tag, such as <article> or <section>, the tag itself is a single box in the DOM. Any elements you place between <article> and </article> go straight inside that box automatically.
  • On your own React component tag, such as <ArticleCard>, the component returns an entire tree of elements, with a heading and two paragraphs. React cannot guess where your nested badges belong inside that card. Do they go above the heading, or at the bottom of the card? So React hands those nested tags to your function inside the children prop. Nothing appears on the page until your code writes {children} in the exact spot where they belong:

Three Principles of children, Spread Attributes, and Default Values

PRINCIPLES

Once a component accepts props, three tools let you compose it cleanly:

  1. Principle 1: The children Prop: Whenever you place content between a component's opening and closing tags, React puts that content inside props.children, and it appears on the page wherever your component writes {children}.
  2. Principle 2: JSX Spread Attributes: When an object already holds the properties a component needs, writing {...object} on the tag opens that object. It spreads every item onto props automatically, just as if you had written each attribute by hand.
  3. Principle 3: Default Prop Values: Writing = with a fallback value in the component's parameter list gives a missing prop a default value whenever a tag leaves that attribute out.

Here is the overview of all three principles before we walk through each one step by step:

#PrincipleWhat Question It AnswersThe React Rule
Principle 1The children Prop: Nest JSX and Render {children}Where do elements placed between <MyComponent> and </MyComponent> go, and how do you display them on the page?Place nested elements between the opening and closing tags in the parent, unpack children in the child, and write {children} where that content belongs.
Principle 2Spread Attributes: Forward Object Keys with {...object}How do you pass every property of an object onto a component tag without typing each attribute by hand, and how do you override one property?Write {...object} on the tag to spread its properties onto props, and write any attribute you want to override after the spread.
Principle 3Default Values: Set Fallbacks with = in ParametersHow do you give a prop a fallback value when a parent tag leaves that attribute out, and which empty values trigger that fallback?Set fallback values with = in the parameter list, which run whenever the prop is left out or undefined.

Section 1 · Principle 1Use the children Prop to Render Wrapped Elements

Why wrapped elements only appear where your component writes {children}

Wrapping badge tags inside our card tag looks just like wrapping tags inside an HTML <article>. However, while the browser automatically displays anything inside <article>...</article>, a React component returns several elements of its own. React cannot guess whether your wrapped badges belong at the top of the card or at the bottom. So React puts everything between the opening and closing tags inside props.children and waits for your component to write {children} in the exact spot where those elements belong.

Principle 1

The children Prop: Nest JSX Between Component Tags and Render {children}

When you place JSX between a component's opening and closing tags, unpack the reserved children prop in the child component and render {children} where it belongs.

Wrapping tags inside your own component looks just like wrapping tags inside an HTML <article>, and that is the trap. An HTML tag shows its wrapped elements automatically, but your React component does not. Whenever you place tags between a component's opening and closing tags, React packs them into props under the exact name children. If you forget to render {children}, those wrapped elements vanish from the screen with zero Console errors. The same thing happens if you invent a custom prop name like badges!

Now imagine the object had ten items instead of three. Typing every single item by hand takes time and clutters the tag. Instead of writing each item out one by one, you can write {...article}:

The shortcut: writing {...article}

Writing {...article} on the tag is the exact same thing as writing all three attributes out by hand! You do not need to write each and every single item yourself. Inside the component, you still get props.title and the other two properties on props, just as if you had defined every single one on the tag by hand.

Why is {...article} called "spreading"?

Think of the article object as a closed box holding the title, the subtitle, and the content packed together. Normally, you would have to reach into the box and lay out each item on the tag one by one. With the three dots ..., JavaScript opens the box and spreads all of its items out across the tag for you automatically:

  • In the second tag, there are no three dots to open the box. React puts the entire closed object inside props.article. The title is now tucked one level deeper inside props.article.title. There is no props.title at all! So if the component asks for { title }, that property is undefined.

Combining {...article} with another attribute on the same tag: before vs. after

In the examples above, {...article} was the only thing written on <MyComponent {...article} />. Can you also write {...article} together with other attributes on the exact same tag?

Yes! Suppose our article object holds an old title, and we want to pass every field from it into <MyComponent>, except we want to give it a new title. We can write both {...article} and title="New Title" on the same tag.

When you put both on the same tag, there are two ways to order them:

  • Order 1: {...article} comes before title="New Title". That means {...article} is first on the left, and title="New Title" is second on the right.
  • Order 2: title="New Title" comes before {...article}. That means title="New Title" is first on the left, and {...article} is second on the right.

Look at both orders side by side:

The two ways to order {...article} and title='New Title' on the same tag
1const article = { title: 'Old Title', subtitle: 'Main Street' };
2
3<MyComponent {...article} title="New Title" />
Order 1: {...article} is first, title="New Title" is last -> "New Title" wins!
4<MyComponent title="New Title" {...article} />
Order 2: title="New Title" is first, {...article} is last -> "Old Title" overwrites it!

Why do those two orders produce different titles? Because JavaScript reads attributes on a tag from left to right, and whichever one comes last overwrites the earlier one:

  1. In Order 1, {...article} runs first and copies the old title. Then title="New Title" runs second and replaces it with 'New Title'.
  2. In Order 2, title="New Title" runs first and sets the new title. Then {...article} runs second and overwrites the title back to 'Old Title'!

How object spread ... works in plain JavaScript

That left-to-right rule comes straight from plain JavaScript objects. When you write ...parkStory inside a new object literal, JavaScript copies every property from parkStory into the new object from left to right. Interview PrepFor the Interview

The Interview Question: How do the children prop, spread attributes, and default values work?

How to Answer Clearly in 30 Seconds

"These three mechanisms control how a parent composes a child component's props:

  1. The children prop: Any JSX placed between a component's opening and closing tags, like <ArticleCard><NewBadge /></ArticleCard>, is packed by the JSX compiler into props.children. Unlike built-in HTML tags, a React component only displays that nested content where it explicitly evaluates {children} in its returned JSX. This enables slot composition, where a wrapper component provides the layout box without knowing its inner content ahead of time.
  2. JSX spread attributes with {...object}: Writing {...parkStory} on a JSX tag copies every own enumerable property from parkStory into the component's props object. Attributes are evaluated from left to right, so whichever key comes last wins. Place {...parkStory} before an explicit attribute when you want that explicit attribute to override the object.
  3. Default prop values with prop = defaultValue: In React 19, we define default prop values with = in the destructured parameter list, such as { title, readTime = 3, children }. React 19 removed defaultProps on function components. Because parameter defaults use standard JavaScript rules, the fallback runs only when the prop is omitted or undefined, never when it is null or 0."

Three Classic Follow-Up Questions Interviewers Ask

  1. "When a component sets { readTime = 3 }, what happens if the parent passes undefined, null, or 0? And does ArticleCard.defaultProps still work in React 19?"
    JavaScript default parameters check strictly for === undefined. If the parent omits readTime or passes readTime={undefined}, readTime falls back to 3. If the parent passes readTime={0}, 0 is kept. If the parent passes readTime={null}, null is not undefined, so readTime stays null. In that case, null + 2 evaluates to 2, and {null} renders nothing in JSX. As for ArticleCard.defaultProps, React 19 removed support for defaultProps on function components, so it is silently ignored at runtime.
  1. "What is the difference between <ArticleCard {...parkStory} readTime={5}> and <ArticleCard readTime={5} {...parkStory}> when parkStory.readTime is 3?"
    JSX attributes are merged from left to right into the props object. In <ArticleCard {...parkStory} readTime={5}>, parkStory copies readTime: 3 first, and then readTime={5} overwrites it to 5. In <ArticleCard readTime={5} {...parkStory}>, readTime: 5 is set first, and then {...parkStory} copies readTime: 3 over it, silently overwriting 5 back to 3.
  1. "What happens if a component forwards {...props} directly onto a built-in DOM element like <article {...props}>, and how do you prevent it?"
    If props contains custom component props such as readTime or isBreaking, spreading {...props} onto <article> passes those custom names to a real HTML element. React then logs a red Console error saying it does not recognize the readTime prop on a DOM element. To prevent that error, strip your component's own props first with rest destructuring in the parameter list. Once you unpack { title, summary, readTime, children, ...domProps }, spread only {...domProps} onto <article>.
