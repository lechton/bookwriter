A component does NOT become a parent because of which folder its file sits in on disk. In React, the component that places <Child /> inside its returned markup is the parent, and <Child /> is its child!

Look at the four everyday words programmers borrow from a family tree and a real tree:

  • Root: Just like the root of a tree holds the whole tree, the root component, App, sits at the very top and holds the entire page.
  • Parent and child: Whenever an outer component returns <Child /> inside its JSX, that outer component is the parent and Child is its child.
  • Siblings: Two components placed side by side inside the same parent are siblings, just like brothers or sisters who share the same parent.
  • Leaf: At the tip of a real tree branch sits a leaf, which has no smaller branches growing out of it. In React, a leaf component returns only built-in HTML tags and zero other React components.

Four Principles of Component Hierarchy and Render Trees

PRINCIPLES

Designing a clean React page means giving every component a clear place in the tree so layout containers, cards, and small badges never get mixed up. Walking through our news page from top to bottom gives us four practical rules:

  1. Principle 1: Root, Parent, Child, and Leaf Roles: A component's place in the tree is decided by which component renders its JSX tag. Placing a page-wide header inside a card traps the main site header inside the card box instead of at the top of the page.
  2. Principle 2: Module Dependency Graph vs. Component Render Tree: A single file on disk is not the same as a single component node in memory. One badge file can export two leaf components, and importing a card file once on disk lets you render multiple card subtrees in memory.
  3. Principle 3: Sibling Components Cannot Read Each Other's Variables: Two sibling components sitting side by side have separate function scopes. Trying to read a sibling's variable crashes the page, and copying the variable into both files lets the two siblings drift out of sync.
  4. Principle 4: A Child Must Never Render Its Own Parent: Component imports and JSX tags must flow strictly downward from root to leaves. If a child imports and renders its own parent, React enters an endless render loop and crashes the browser tab.

Section 1 · Principle 1Tree Roles: Root, Parent, Child, and Leaf

How parent, child, and leaf roles work

Every component on a page has a specific size and job. The site header belongs at the top of the page. The article list belongs below the header. The article card belongs inside the list, and the small status badges belong inside the card.

Those four positions give us the four roles in any React component tree:

  1. Root Component: The top-level component mounted into the page root that wraps the entire application.
  2. Parent Component: Any component that renders another React component tag inside its JSX.
  3. Child Component: Any component whose JSX tag is rendered inside a parent component.
  4. Leaf Component: A component at the bottom tip of a branch that returns only built-in HTML tags and zero other React components.

Section 2 · Principle 2Two Maps: The Module Graph on Disk vs. The Render Tree in Memory

Why importing a component file once and rendering <ArticleCard /> twice are NOT the same thing

Compare the import line at the top of a file with the two <ArticleCard /> tags inside the returned markup:

1 file import on disk vs. 2 rendered cards in memory
1import ArticleCard from './ArticleCard.jsx';
1. On disk: you import the file ONLY ONCE!
2
3export default function ArticleList() {
4 return (
5 <section>
6 <ArticleCard />
2. In memory: 1st live ArticleCard on screen
7 <ArticleCard />
3. In memory: 2nd live ArticleCard on screen
8 </section>
9 );
10}

One file on disk and one component on screen are NOT the same thing! You import a component file once at the top of the file, and then you can render as many <ArticleCard /> tags as you want inside return.

That is why a React project actually has two different maps:

  1. The Module Dependency Graph on Disk: Shows which .jsx file imports which other .jsx file. Every file appears once in this graph no matter how many components it exports or how many times its tag is rendered.
  2. The Component Render Tree in Memory: Shows every live component instance that React renders onto the screen. Every JSX tag creates its own node and child subtree in memory.

Section 4 · Principle 4Tree Direction: Why a Child Component Must Never Render Its Own Parent

Why component tags must flow from top to bottom

In a healthy component tree, every branch points strictly downward from larger containers to smaller pieces:

  • The root component renders the list.
  • The list renders the card.
  • The card renders the badges.

What happens if a branch points upward instead, so a child component imports its own parent and renders that parent's tag inside its JSX? The two components call each other back and forth forever until the browser tab crashes. In computer science terms, a React component tree must be a directed acyclic graph, meaning branches flow in one direction from top to bottom with zero circular loops:

How must component tags flow through the Render Tree?
Circular loop
ArticleList renders <ArticleCard /> and ArticleCard renders <ArticleList />
Parent and child call each other back and forth forever
Crashes with RangeError: Maximum call stack size exceeded
Strict top-down flow
App -> ArticleList -> ArticleCard -> Badges
DO point every import and JSX tag strictly downward
Rendering stops cleanly at the HTML leaf components
Figure 13 — One-way top-down component hierarchy vs. a circular parent-in-child loop.

Principle 4

Interview PrepFor the Interview

The Interview Question: How do you model a React UI as a component tree, and how do you decide which components are parents, children, siblings, or leaves?

How to Answer Clearly in 30 Seconds

"We model a React UI by breaking the visual page into nested boxes from the largest layout shell down to the smallest UI atoms. At the very top sits the root component, App, which we pass to root.render. Whenever one component renders another component's tag in its JSX, the outer component is the parent and the inner component is its child. Two components rendered side by side inside the same parent, such as <SiteHeader /> and <ArticleList />, are siblings. At the bottom tips of the tree sit leaf components, such as <LiveBadge />, which return only built-in HTML tags and zero other React components. As we build this tree, we follow three architectural rules. First, the Module Dependency Graph on disk is different from the Component Render Tree in memory, because one imported file can be rendered multiple times. Second, siblings cannot read each other's local variables, so shared data must live above both siblings in a single source of truth. Third, the tree must flow strictly top-down, because a child rendering its own parent triggers an infinite loop and a RangeError crash."

Three Classic Follow-Up Questions Interviewers Ask

  1. "What is the difference between the Module Dependency Graph and the Component Render Tree?"
    - The Module Dependency Graph maps static .jsx files and their import statements on disk, where ArticleList.jsx imports ArticleCard.jsx only once. The Component Render Tree maps the live component instances rendered in memory at runtime, where rendering <ArticleCard /> twice creates two card nodes and four badge leaf nodes.
  1. "Can two sibling components read variables directly from each other?"
    - No. Each component is a JavaScript function with its own private local scope, so reading a sibling's local variable throws an Uncaught ReferenceError. Duplicating the variable in both siblings causes the UI to drift out of sync. Shared data must live in a single source of truth above both siblings. Static constants can be imported from a shared module, while dynamic data is lifted into their common parent component.
  1. "What happens if a child component imports and renders its own parent component?"
    - React enters an infinite render cycle where the parent renders the child and the child renders a new instance of the parent. Within a fraction of a second, the JavaScript engine exhausts the call stack and crashes with Uncaught RangeError: Maximum call stack size exceeded.
