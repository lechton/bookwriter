## Scope

Covered here:
- What a custom Hook is: a JavaScript function our code writes, whose name starts with `use` followed by a capital letter, and which calls other Hooks. The docs: "You might not find these Hooks in React, but you can create your own Hooks for your application's needs."
- Extracting a custom Hook from two components that copy the same `useState` and `useEffect`: the docs' `StatusBar` and `SaveButton`, and the docs' `useOnlineStatus`.
- What a custom Hook returns: the docs: "At the end of the function, return `isOnline`. This lets your components read that value." and "Hooks may return arbitrary values."
- The behavior before and after extracting is the same. The docs: "The behavior before and after extracting a custom Hook is identical."
- Custom Hooks share stateful logic, not state itself. The docs: "Each call to a Hook is completely independent from every other call to the same Hook."
- When the state itself must be shared, lift it up and pass it down. The docs: "When you need to share the state itself between multiple components, lift it up and pass it down instead."
- When a custom Hook is worth writing, and when it is not, from the docs' section "When to use custom Hooks": for an Effect, yes; for a single `useState`, "probably unnecessary"; never a "lifecycle" Hook such as `useMount`.

## Start of the Lecture

**Opening Essence of the chapter**:
- The idea is the shape of a way of working, moving shared logic out of two components, so it opens in plain words on a real screen, as Examples 8 and 9 of opening-essence open. The short code comes in Principle 1.
- The real screen: a notes app, or any app that saves the user's work to a server. The docs' case: "You want to warn the user if their network connection has accidentally gone off while they were using your app."
- Parts of the screen: a heading at the top that reads `Online`, and a `Save progress` button below it.
- What the user does, and what the user sees change:
  1. The Wi-Fi drops, or the user turns it off.
  2. The heading changes to `Disconnected`.
  3. At the same moment, the button turns grey, cannot be clicked, and reads `Reconnecting...`.
  4. The Wi-Fi comes back: the heading reads `Online` again, and the button reads `Save progress` and can be clicked.
- The question that screen raises for the developer: two different components need the same knowledge, whether the network is on, and the same code to keep it, one state variable and one Effect that listens to the browser. Where does that code live?
- The answer, the docs: "Declare a function called `useOnlineStatus` and move all the duplicated code into it from the components you wrote earlier". Each component then calls `useOnlineStatus()` and reads `isOnline`.
- Key idea the reader must remember: a custom Hook shares the code, not the value. The docs: "Custom Hooks let you share *stateful logic* but not *state itself.*" Every component that calls `useOnlineStatus()` gets its own `isOnline` and its own Effect.
- Confusion to say out loud: *"It may look the same, or work the same at first, but it is NOT the same thing!"*
  1. Both components call `useOnlineStatus()`, and both change at the same moment.
  2. It looks as if they read one shared `isOnline`.
  3. They do not. The docs: "These are two completely independent state variables and Effects! They happened to have the same value at the same time because you synchronized them with the same external value (whether the network is on)."
- What is at stake for the user, on the example page, when the code is copied instead of shared:
  1. The two components each hold a copy of the same `useState` and `useEffect`.
  2. The docs name a flaw of the copied code: it "assumes that when the component mounts, `isOnline` is already `true`, but this may be wrong if the network already went offline."
  3. A developer fixes that flaw in `StatusBar` only, with `useState(navigator.onLine)`.
  4. A user opens the app while offline.
  5. The heading reads `Disconnected`, and the button next to it still reads `Save progress` and can be clicked. The page gives two answers to one question.
  6. The page result in step 5 is `unconfirmed`, a lab check.
- Where readers usually go wrong:
  1. They copy the `useState` and the `useEffect` into the second component, and later fix only one copy.
  2. They think two calls of one custom Hook share one value, and put state in a custom Hook to share it between components.
  3. They wrap every small piece of code in a custom Hook, including a single `useState`, or write Hooks named after timing, such as `useMount`.

**Theme**: two components on one screen, a status heading and a Save button, need the same network state, and copying its code into both lets the two copies drift apart.

**Ways** (to reuse logic between components, from the docs):
1. Copy the state and the Effect into each component: it works, the docs: "These two components work fine, but the duplication in logic between them is unfortunate." Fits only while the code is tiny. The docs: "Some duplication is fine." Opening and Principle 1.
2. Extract a custom Hook: when two or more components need the same stateful logic, most of all an Effect that talks to an external system. The docs: "whenever you write an Effect, consider whether it would be clearer to also wrap it in a custom Hook." This lesson, Principles 1 and 2.
3. Lift the state up and pass it down: when two components need the same value, one state for both. Lesson 24; context for far components, Lesson 28. Principle 3.
4. A regular function without the `use` prefix: when the shared code calls no Hooks, such as the docs' `getSorted`. Lesson 38. Named in Interview depth.

**Example page chosen for this lesson**: the docs' own case from "Custom Hooks: Sharing logic between components", a status heading and a Save button that follow the network.
- Parts of the page:
  1. `StatusBar`: a heading `<h1>` that reads `Online` or `Disconnected`.
  2. `SaveButton`: a button that reads `Save progress` and can be clicked while online, and reads `Reconnecting...` and is disabled while offline.
  3. In Principle 3 only: under the heading, a line `All changes saved` after the user clicks Save.
- What the user does, and what each action changes:
  1. The page opens online: `Online`, and `Save progress`.
  2. The network goes off: `Disconnected`, and a grey `Reconnecting...`.
  3. The network comes back: `Online`, and `Save progress`.
  4. The user clicks `Save progress`: the Console shows `Progress saved`. In Principle 3, the line `All changes saved` should appear under the heading.
- Files:
  1. `src/useOnlineStatus.js`: `import { useState, useEffect } from 'react';`, `export function useOnlineStatus()`, `const [isOnline, setIsOnline] = useState(navigator.onLine);`, the Effect with `handleOnline`, `handleOffline`, `window.addEventListener('online', handleOnline)`, `window.addEventListener('offline', handleOffline)`, the cleanup with both `window.removeEventListener` calls, `[]`, and `return isOnline;`. A `.js` file, as in the docs, because it returns no JSX.
  2. `src/StatusBar.jsx`: `export default function StatusBar()`, `const isOnline = useOnlineStatus();`, `return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;`.
  3. `src/SaveButton.jsx`: `export default function SaveButton()`, `const isOnline = useOnlineStatus();`, `function handleSaveClick() { console.log('Progress saved'); }`, `<button disabled={!isOnline} onClick={handleSaveClick}>{isOnline ? 'Save progress' : 'Reconnecting...'}</button>`.
  4. `src/App.jsx`: `<StatusBar />` then `<SaveButton />` inside a Fragment.
  5. `index.html` and `src/main.jsx` with `<StrictMode>`, Lesson 07.
  6. The docs write the strings with emoji: `'✅ Online'`, `'❌ Disconnected'`, `console.log('✅ Progress saved')`. Dropped here, because a voice cannot read them. See Open Issues.
  7. The docs' App renders `<SaveButton />` above `<StatusBar />`. Here the heading comes first, as a status line sits at the top of an app.
- How the page grows:
  1. Opening and Principle 1: `StatusBar.jsx` and `SaveButton.jsx` each hold their own copy of `useState` and `useEffect`. Then the copies move into `src/useOnlineStatus.js`, and both components call `useOnlineStatus()`.
  2. Principle 2: one line `console.log('Listening to the network')` is added at the start of the Effect's setup in `useOnlineStatus.js`, to count the Effects. It is removed at the end of the principle.
  3. Principle 3: a short wrong try with a custom Hook `useSaveStatus` that holds `isSaved`, called in both components. Then the fix: `isSaved` lives in `App.jsx`, `StatusBar` receives `isSaved` as a prop, and `SaveButton` receives `onSave`. This is the final page.

4. The user's action needs no explanation: the Wi-Fi drops and comes back. The Save click is the only click.
5. Every word of the code but `online`, `offline`, and `navigator.onLine` was taught in Lessons 04 to 38.
6. The broken case in Principle 3 is big: the user clicks Save, and the `All changes saved` line never appears.

## Principles

### Principle 1: useOnlineStatus Takes the Copied Effect Out of Both Components

- **Rule**: When two components copy the same state and Effect, move that code into one function named `use` followed by a capital letter, return the value the components need, and let each component call it; the page works exactly as before.
- **Move**: Smallest code first, because a custom Hook is a new idea and the reader must see the whole function before the files; then Side by side, for the copied version and the extracted version, which are the exact same thing on the page.
- **Opening Essence**:
  - Smallest code, the docs' first step: the two components as if React had a built-in `useOnlineStatus`: `function StatusBar() { const isOnline = useOnlineStatus(); ... }` and `function SaveButton() { const isOnline = useOnlineStatus(); ... }`. The docs: "Imagine for a moment that, similar to `useState` and `useEffect`, there was a built-in `useOnlineStatus` Hook."
  - Then the docs' answer: "Although there is no such built-in Hook, you can write it yourself."
  - Confusion to say out loud: *"Yes, it is the exact same thing!"* The component that calls `useOnlineStatus()` does exactly what the component did with the `useState` and `useEffect` written inside it. The docs: "The behavior before and after extracting a custom Hook is identical."
  - Key idea: a custom Hook is a plain JavaScript function. The only things that make it a Hook are its name, `use` and a capital letter, and the Hooks it calls inside.
  - What is at stake: with two copies, every fix must be made twice; the opening's story of the `navigator.onLine` fix in one copy.
- **Root Distinction**:
  - Junior: "A Hook is something React gives me, like `useState`; I cannot make one."
  - Senior: a custom Hook is our own function that calls React's Hooks; React gives the built-in Hooks, and our code builds new ones from them.
- **Simplest version**: `function useOnlineStatus() { const [isOnline, setIsOnline] = useState(true); useEffect(() => { ... }, []); return isOnline; }` and, in a component, `const isOnline = useOnlineStatus();`.
- **Words to teach**:
  - *custom Hook*: a function our code writes, whose name starts with `use` followed by a capital letter, and which calls other Hooks. Provided by our code; its inner Hooks are provided by React. Needed when the copied lines move into `useOnlineStatus.js`.
  - *extract*: the docs' word for moving duplicated code out of components into one function. Needed at the move.

### Principle 2: Each Call to useOnlineStatus Gets Its Own isOnline

- **Rule**: Every call to a custom Hook runs its own copy of the Hooks inside it, so two components that call `useOnlineStatus()` hold two separate `isOnline` states and two separate Effects, which only look shared because both follow the same browser value.
- **Move**: Steps for a surprise, because the two components change at the same moment, which looks like one shared value, and only the count of Effects shows that there are two.
- **Opening Essence**:
  - The real screen and action: the Wi-Fi drops, and the heading and the button change together.
  - Smallest code, the docs' pair: `function StatusBar() { const isOnline = useOnlineStatus(); }` and `function SaveButton() { const isOnline = useOnlineStatus(); }`, next to what they really run: `const [isOnline, setIsOnline] = useState(true); useEffect(() => { ... }, []);` written in each.
  - Confusion to say out loud: *"It may look the same, or work the same at first, but it is NOT the same thing!"* One `isOnline` shared by both, and two `isOnline` states that hold the same value, look the same on the page. The docs: "it's wrong to think that a single `isOnline` state variable is shared between them."
  - Key idea, the docs: "**Custom Hooks let you share *stateful logic* but not *state itself.* Each call to a Hook is completely independent from every other call to the same Hook.**"
- **Root Distinction**:
  - Junior: "`StatusBar` and `SaveButton` read the same `isOnline`, because they call the same Hook."
  - Senior: they call the same function; each call creates its own state and its own Effect inside the component that called it.
- **Simplest version**: `const isOnline = useOnlineStatus();` in `StatusBar`, and the same line in `SaveButton`. Two calls, two `useState` calls, two Effects, two pairs of listeners on `window`.
- **Words to teach**:
  - *stateful logic*: the code that creates and updates state, here the `useState` and the Effect inside `useOnlineStatus`. The docs' words. Needed when the reader asks what a custom Hook shares.

### Principle 3: A Shared isSaved Lives in App, Not in a Custom Hook

- **Rule**: When two components must show one value that changes, such as whether the work was saved, lift that state into their closest common parent and pass it down; a custom Hook would give each component its own copy, and the copies never agree.
- **Move**: Side by side, because the two versions of `isSaved` look alike in code, a call to the same Hook or a prop from `App`, and only one of them gives both components one value.
- **Opening Essence**:
  - The real screen and action: the user clicks `Save progress`, and expects a line under the heading that says `All changes saved`.
  - Smallest code: `function useSaveStatus() { const [isSaved, setIsSaved] = useState(false); return [isSaved, setIsSaved]; }`, called as `const [isSaved] = useSaveStatus();` in `StatusBar` and `const [isSaved, setIsSaved] = useSaveStatus();` in `SaveButton`.
  - Confusion to say out loud: *"It may look the same, or work the same at first, but it is NOT the same thing!"* `useOnlineStatus` in two components looked shared because the browser keeps both in step. `useSaveStatus` in two components has nothing outside to keep them in step.
  - What is at stake: the user clicks Save, the work is saved, and the screen never says so.
- **Root Distinction**:
  - Junior: "`useOnlineStatus` let both components see the network, so `useSaveStatus` will let both components see `isSaved`."
  - Senior: a custom Hook shares the code that makes state; to share the state itself, one component owns it and passes it down.
- **Simplest version**: in `App`, `const [isSaved, setIsSaved] = useState(false);`, then `<StatusBar isSaved={isSaved} />` and `<SaveButton onSave={() => setIsSaved(true)} />`.
- **Words to teach**:
  - *share the state itself*: the docs' words for one value read by several components. Provided by the docs. Needed at the click on Save. The docs: "When you need to share the state itself between multiple components, lift it up and pass it down instead."

  - Helper: none.
- **Side by side**:

- **Real beginner mistake** (the docs' warning "it's wrong to think that a single `isOnline` state variable is shared between them", and the syllabus card's naive experiment "attempting to share state"):

## Interview Points

- A custom Hook is a JavaScript function whose name starts with `use` followed by a capital letter and which calls other Hooks.
- Extract one when two or more components repeat the same stateful logic, most of all an Effect that talks to an external system or a browser API.
- The component then says what it wants, such as the online status, and the Hook holds how, such as the browser's `online` and `offline` events.
- A custom Hook returns whatever the components need; `useOnlineStatus` returns `isOnline`.
- The behavior before and after extracting is identical; the Hook's code runs as part of the component's render.
- Custom Hooks share stateful logic, not state itself: each call gets its own state and its own Effects.
- To share one value between components, lift the state up and pass it down, or use context when the components are far apart.
- A custom Hook's code re-runs on every render, so it must be pure, and it always receives the latest props and state.
- Wrap an event handler that a custom Hook receives in an Effect Event, so the Effect does not re-synchronize on every render.
- Do not extract for every bit of duplication, do not wrap a single `useState`, and do not write lifecycle Hooks such as `useMount`; name each Hook after its purpose.
- Wrapping Effects in custom Hooks lets the app move to a better API, such as `useSyncExternalStore`, without changing the components.
