## 4. Principle 4: A serverUrl in State Joins the Array

### `serverUrl` above the component vs. `serverUrl` in state

In Principle 1, `serverUrl` sat above the component as a fixed constant, and the dependency array was `[roomId]`. Now suppose we let the user edit the server address in a text box by moving `serverUrl` into state inside `ChatRoom`. Both versions below pass the server URL and room ID to `createConnection`, and they differ only in where `serverUrl` is declared and whether it joins the dependency array:

```jsx title="serverUrl declared above the component: not reactive"
const ~serverUrl~ = 'https://localhost:1234'; // Outside the component: never changes on a re-render

function ChatRoom({ roomId }) {
  useEffect(() => {
    const connection = createConnection(serverUrl, roomId);
    connection.connect();
    return () => connection.disconnect();
  }, ~[roomId]~); // Only roomId is reactive here
}
```

```jsx title="serverUrl declared in state inside the component: reactive"
function ChatRoom({ roomId }) {
  const [~serverUrl~, setServerUrl] = useState('https://localhost:1234'); // Inside the component: can change on a re-render

  useEffect(() => {
    const connection = createConnection(serverUrl, roomId);
    connection.connect();
    return () => connection.disconnect();
  }, ~[roomId, serverUrl]~); // Both roomId and serverUrl are reactive and belong in the array
}
```

**It may look the same, or work the same at first, but it is NOT the same thing!** Inside the Effect, the call to `createConnection` is character-for-character identical in both versions, and both start with `'https://localhost:1234'`. With `serverUrl` declared above the component, the URL "never changes due to a re-render", so the array lists only `[roomId]`. With `serverUrl` declared in state inside the component, the URL "may change over time", so it must join the array as `[roomId, serverUrl]`. As the docs explain, "dependencies only do something when they change over time!"

React's docs use four terms to define which values belong in the dependency array:
1. **Reactive values**: React's docs state in bold that "**Props, state, and other values declared inside the component are _reactive_**". They can change on a re-render because they are calculated during rendering and participate in the React data flow.
2. **The rendering data flow**: During rendering, React passes props and context into your component, reads your state snapshots, and calculates the variables in your component body from top to bottom. That calculation during rendering is the React **rendering data flow**, and every value calculated in it is reactive.
3. **Stable values**: Some values returned by React are guaranteed "to not change on a re-render". Two examples are the state setter from `useState` and the ref object from `useRef` (as seen in Lesson 30). As the docs' Note explains: "Stable values aren't reactive, so you may omit them from the list. Including them is allowed." That is why the linter never asks you to put `setServerUrl` or `setRoomId` in the dependency array.
4. **Mutable values and global variables**: A value such as `location.pathname` or `ref.current` that "can change at any time completely outside of the React rendering data flow" is a **mutable value**. Because changing it does not trigger a re-render, it cannot be a dependency.

A regular variable calculated in the component body is also reactive and must go in the dependency array. Why? Well, as the docs explain, "It's a regular variable that you calculate during rendering," so it can change on a re-render just like props and state. All values inside the component, including props, state, and variables in your component's body, are reactive. Here is the docs' example where `serverUrl` is calculated during rendering from a prop and a context value from `useContext` (as seen in Lesson 28). The nullish coalescing operator `??` falls back to the default URL when the prop is null or undefined:

```jsx title="A regular variable calculated in the component body is also reactive"
function ChatRoom({ roomId, selectedServerUrl }) {
  const settings = useContext(SettingsContext);
  const ~serverUrl~ = selectedServerUrl ?? settings.defaultServerUrl; // Calculated during rendering -> reactive!

  useEffect(() => {
    const connection = createConnection(serverUrl, roomId);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId, ~serverUrl~]); // Must list serverUrl because it can change on a re-render
}
```

When neither `serverUrl` nor `roomId` depends on props or state, you can declare both fixed constants either above the component or inside the Effect:

```jsx title="Declaring fixed constants above the component"
const ~serverUrl~ = 'https://localhost:1234'; // Declared outside the component: not calculated during rendering
const roomId = 'general';

function ChatRoomOutside() {
  useEffect(() => {
    const connection = createConnection(serverUrl, roomId);
    connection.connect();
    return () => connection.disconnect();
  }, ~[]~); // Empty array: uses zero reactive values
}
```

```jsx title="Declaring fixed constants inside the Effect"
function ChatRoomInside() {
  useEffect(() => {
    const ~serverUrl~ = 'https://localhost:1234'; // Declared inside the Effect: not calculated during rendering
    const roomId = 'general';
    const connection = createConnection(serverUrl, roomId);
    connection.connect();
    return () => connection.disconnect();
  }, ~[]~); // Exact same empty array: uses zero reactive values!
}
```

**Yes, it is the exact same thing** for the dependency array! Whether you declare fixed constants above the component or inside the Effect, "They aren't calculated during rendering, so they're not reactive." To remove a dependency honestly, you move it outside the component or inside the Effect. As the `useEffect` reference puts it, "you need to "prove" to the linter that it *doesn't need* to be a dependency." That also shows what `[]` truly means from the Effect's perspective: not "run only on mount", but "your Effect's code does not use *any* reactive values." If `roomId` or `serverUrl` later moves into state, "your Effect's code won't change. You will only need to add them to the dependencies."

```tree caption="Which values read by an Effect are reactive and belong in the dependency array, and which do not."
Four kinds of values an Effect can read, and which ones belong in the dependency array
- +Props, state, and variables in the component body [`roomId` `serverUrl`] | Calculated **during rendering** in the React data flow | **Reactive**: must be listed in `[roomId, serverUrl]`
- +Constants outside the component or inside the Effect [`const serverUrl` at top of file] | Never change due to a **re-render** | **Not reactive**: can be omitted, leaving `[]` when none remain
- +Stable values from React [`setServerUrl` `ref` object] | Guaranteed **not to change** on a re-render | **Stable**: omitting or including them is allowed
- !Mutable values outside rendering [`location.pathname` `ref.current`] | ~Change **outside React's rendering data flow** | **Cannot be dependencies** because changing them never triggers a re-render
```

### Adding the `Server URL:` input box to `ChatRoom.jsx`

Now we update `ChatRoom.jsx` so the server URL lives in state with a controlled input box (as seen in Lesson 20). We also add `serverUrl` to the dependency array:

```jsx title="src/components/ChatRoom.jsx"
import { useState, useEffect } from 'react';
import { createConnection } from '../chat.js';

export default function ChatRoom({ roomId }) {
  const [~serverUrl~, setServerUrl] = useState('https://localhost:1234'); // Reactive state variable

  useEffect(() => {
    const connection = createConnection(serverUrl, roomId);
    connection.connect();
    return () => {
      connection.disconnect();
    };
  }, ~[roomId, serverUrl]~); // Re-synchronizes whenever either roomId or serverUrl changes

  return (
    <section>
      <label>
        Server URL:{' '}
        <input
          ~value={serverUrl}~ // Shows the current serverUrl in the input box
          ~onChange={e => setServerUrl(e.target.value)}~ // Updates serverUrl on every keystroke by the user
        />
      </label>
      <h1>Welcome to the {roomId} room!</h1>
    </section>
  );
}
```

**Beware! Because `serverUrl` is now a reactive dependency in `[roomId, serverUrl]`, every single keystroke by the user in the URL box disconnects from the old URL and connects to the new URL.** Here is what happens when the user types `5` at the end of `https://localhost:1234`:
1. The user types `5` at the end of the `Server URL:` box.
2. `setServerUrl` updates state with the new URL and asks React to re-render `ChatRoom`. The page now shows `https://localhost:12345` in the input box.
3. React compares the new dependency array with the previous render's array using `Object.is`.
4. Because `serverUrl` changed, React calls the previous render's cleanup function, which prints the disconnect line for `https://localhost:1234`.
5. React runs the new render's setup function, which prints the connect line for `https://localhost:12345`.

```page width=text caption="After the user types 5 at the end of the Server URL box: the Effect disconnects from the old URL and connects to the new URL."
form:
  select: Choose the chat room: | general
  button: Close chat
  field: Server URL: | https://localhost:12345 | good
heading: Welcome to the general room!
log: ✅ Connecting to "general" room at https://localhost:1234... | chat.js:5
log: ❌ Disconnected from "general" room at https://localhost:1234 | chat.js:8

log: ❌ Disconnected from "general" room at https://localhost:1234 | chat.js:8
log: ✅ Connecting to "general" room at https://localhost:12345... | chat.js:5
```

As the docs summarize: "Whenever you change a reactive value like `roomId` or `serverUrl`, the Effect re-connects to the chat server."

### Why mutable values like `location.pathname` and `ref.current` cannot be dependencies

**Beware! Putting a mutable value such as `location.pathname` or `ref.current` in the dependency array will not make your Effect re-run when that value mutates.** Walk through the four steps from the docs' Deep Dive "Can global or mutable values be dependencies?":
1. A developer wants an Effect to re-synchronize when `location.pathname` or `ref.current` changes (as seen in Lesson 30). So the developer puts that value in the dependency array.
2. Later, some code outside React mutates `location.pathname` or assigns a new value to `ref.current`.
3. Because mutating an external object or `ref.current` happens completely outside of the React rendering data flow, it does not trigger a re-render of the component.
4. Because the component never re-renders, React never checks the dependency array. The Effect stays on the old value. As the docs explain: "even if you specified it in the dependencies, React *wouldn't know* to re-synchronize the Effect when it changes."

To subscribe to an external mutable value such as `location.pathname`, the docs recommend `useSyncExternalStore` (covered in Lesson 53). By contrast, an object or function created inside the component body during rendering has the opposite problem. It is brand-new on every render, so listing it in the dependency array re-synchronizes the Effect on every render. The docs' Challenge on fixing a connection switch shows this when a component creates a new `createConnection` function during rendering. Passing a simple boolean prop such as `isEncrypted` instead keeps the dependency equal across renders (covered in Lesson 37).

> [!PRINCIPLE]
> **Principle 4: Reactive Values: Everything Calculated in the Component Body Belongs in the Array**
>
> *Props, state, and variables in the component body are reactive and belong in the dependency array; constants outside rendering are not reactive, and mutable values cannot be dependencies.*
>
> A value is reactive when it is calculated during rendering as part of the React data flow. Moving `serverUrl` from a top-level file constant into state or calculating it inside the component means it can change on a re-render, so it must join `[roomId, serverUrl]`. Conversely, mutating `ref.current` or `location.pathname` never triggers a re-render, so listing them in the array will never re-synchronize the Effect.
>
> **DO THIS:**
> ```jsx
> function ChatRoom({ roomId }) {
>   const [~serverUrl~, setServerUrl] = useState('https://localhost:1234'); // Reactive state inside the component
>   useEffect(() => {
>     const connection = createConnection(serverUrl, roomId);
>     connection.connect();
>     return () => connection.disconnect();
>   }, ~[roomId, serverUrl]~); // Lists both reactive values read by the Effect
> }
> ```
>
> **DO NOT DO THIS:**
> ```jsx
> function ChatRoom({ roomId }) {
>   useEffect(() => {
>     const connection = createConnection(serverUrl, roomId);
>     connection.connect();
>     return () => connection.disconnect();
>   }, [roomId, ~ref.current~]); // **WRONG:** mutating ref.current never triggers a re-render, so it cannot be a dependency!
> }
> ```
