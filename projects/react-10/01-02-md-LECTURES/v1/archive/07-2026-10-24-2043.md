## Why We Need an HTML Page and Vite to Mount React

### A browser loads an HTML file first, never a React component file

In Lectures 4, 5, and 6, we built our news page out of components and connected them inside `App.jsx`. The page header, the section banner, and the article card all sit ready inside that root component.

Yet if you open a browser and visit a web address, nothing from `App.jsx` can appear on its own. A browser never starts by loading a `.jsx` component file. Every website visit begins with an HTML file, `index.html`. That HTML file does two jobs: it places one empty box on the page and invites our startup JavaScript file in.

```tree caption="What a browser loads first when visiting a website vs. how React reaches the screen."
How a React component reaches the browser screen
- !Load `src/App.jsx` directly in the browser | Browsers do not start from a `.jsx` component file | Raw JSX tags and package imports **cannot run directly** in the browser
- +Start from `index.html` and mount through `src/main.jsx` | `index.html` places one empty **`<div id="root">`** on the page | `src/main.jsx` grabs that box with `createRoot` and renders **`<App />`** inside it
```

### Three startup files that put our page on the screen

Every React project built with Vite uses three startup files to bridge that gap between the browser and your component tree:

```files title="city-news: Startup Files" caption="The three files that work together to mount a React application in the browser."
index.html | entry | The HTML document loaded by the browser with an empty #root div and a module script tag
src/
  main.jsx | boundary | Looks up #root in the DOM, creates the React root, and renders <App />
  App.jsx | root | Top-level component that returns the <main> newsroom page layout
```

Let us walk through how those three files hand work to one another from top to bottom.

First, the browser loads `index.html`, which puts one empty box with `id="root"` on the page and loads our startup script:

```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <~div id="root"~></div> <!-- 1. Empty HTML box waiting for React -->
    <script ~type="module"~ src="/src/main.jsx"></script> <!-- 2. Loads main.jsx as an ES module -->
  </body>
</html>
```

Second, our startup file `main.jsx` asks the browser for that host box, creates a React root on it, and renders `<App />`:

```jsx title="src/main.jsx" startLine="1"
import { ~createRoot~ } from 'react-dom/client'; // 1. Import React's browser DOM root creator
import App from './App.jsx';

const container = ~document.getElementById('root')~; // 2. Grab the <div id="root"> from index.html
const root = ~createRoot(container)~; // 3. Create the React root on that DOM box
~root.render(<App />)~; // 4. Paint the <App /> component tree inside #root
```

Third, React calls our `App` component in `App.jsx` and receives the markup for the newsroom page:

```jsx title="src/App.jsx" startLine="1"
export default function ~App~() { // Root component imported and rendered by main.jsx
  return (
    <main>
      <header>
        <h1>Latest Articles</h1>
        <p>City News</p>
      </header>
      <section>
        <h2>Section: City News</h2>
        <article className="card">
          <span className="badge">Live</span>
          <span className="badge">New</span>
          <h3>New Park Opens Today</h3>
          <p>The park on Main Street opens at noon.</p>
        </article>
      </section>
    </main>
  );
}
```

When all three files connect, React places the `<main>` layout from our root component directly inside `<div id="root">`:

### A Quick Map of the Lesson

Here are the four things we are going to look at in this lesson:

1. **The single ID that holds the whole app:** We are going to see how the main HTML page of a React project, `index.html`, sits almost completely empty. It holds just one blank `<div>` with `id="root"`, and the entire React application will hang from that single ID.
2. **The `type="module"` switch and Vite:** Right below that empty box, we will see why we have to place `type="module"` on our `<script>` tag so the browser allows module imports. Then we will see how Vite steps in behind the scenes to translate JSX tags and package names before the browser ever sees the file.
3. **Why `createRoot` alone leaves a blank screen:** Next, we will step into `main.jsx` and see why mounting takes two separate calls. First we hand our HTML box to `createRoot`, and then we call `root.render` on the result. Forget that second line, and the page stays completely blank without a single error in the Console.
4. **The angle-bracket trap in `root.render`:** Finally, we will look at the last line of the startup file and see why we have to pass `<App />` instead of the raw `App` function. Those two angle brackets are the clue that tells Vite and React to build the page instead of rejecting the function.

| # | Principle | Why It Matters in Debugging and Interviews | The React 19 Rule |
| :--- | :--- | :--- | :--- |
| **Principle 1** | **The HTML Host Container** | Mismatched IDs between `index.html` and `main.jsx` make `document.getElementById` return `null` and crash `createRoot`. | Put `<div id="root"></div>` in `index.html` and pass that exact DOM element to `createRoot`. |
| **Principle 2** | **The Module Entry and Build Tool** | Missing `type="module"` blocks `import`, while serving raw `.jsx` without Vite fails on bare package names and `<App />`. | Load `main.jsx` with `<script type="module">` and let Vite rewrite bare imports and JSX tags. |
| **Principle 3** | **Two-Step Mounting** | Calling `createRoot` without `root.render` leaves the screen blank with zero Console errors. | Import `createRoot` from `react-dom/client`, create the root on the DOM node, and call `root.render`. |
| **Principle 4** | **JSX Element vs. Function** | Passing the raw function `App` to `root.render` leaves the page blank and logs a React child warning. | Pass the JSX element `<App />` to `root.render` so React receives an element object and calls `App`. |

## 1. Principle 1: The HTML Host Container: Match the ID in index.html and main.jsx

### React does not build the whole HTML document, it moves into one empty box on the page

When you inspect a finished React website, every heading, button, and card on screen comes from React. That makes it easy to assume React creates the entire document starting from `<html>` and `<body>`. In reality, the browser builds the outer HTML page from `index.html` first, and React only takes over **one chosen DOM element** inside `<body>`.

- **In daily coding**: The HTML page and `main.jsx` meet on a single string ID, usually `'root'`. If someone changes the ID in one file **but forgets to update the other**, the DOM lookup returns `null` and `createRoot` crashes immediately.
- **In an interview**: Be clear about what `createRoot` takes as its input. It never takes a React component; it takes a **real browser DOM node** found in `index.html`.

```tree caption="How index.html and src/main.jsx must agree on the exact same ID string."
Connecting index.html to src/main.jsx
- !Mismatched IDs [`id="app"` vs. `'root'`] | `document.getElementById` cannot find `#root` and returns **`null`** | `createRoot` crashes with **`Target container is not a DOM element`**
- +Matching IDs [`id="root"` and `'root'`] | +**DO** keep the exact same ID in both files | `document.getElementById` returns the live **`<div>`** for `createRoot`
```

### What happens when the IDs in index.html and main.jsx do not match

Suppose a developer edits `index.html` and renames the host box ID to `app`:

```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <div ~id="app"~></div> <!-- Changed to "app" in index.html -->
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
```

Meanwhile, `main.jsx` still asks the browser to find `'root'`:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = ~document.getElementById('root')~; // **WRONG:** returns null because #root no longer exists
const root = ~createRoot(container)~; // **WRONG:** passes null into createRoot and crashes!
root.render(<App />);
```

When you open the browser, the screen stays blank and the Console prints an error:

```devconsole caption="Console error when document.getElementById returns null and main.jsx passes null to createRoot."
x Uncaught Error: Target container is not a DOM element.
```

Look at what happened in order:
1. The browser parsed `index.html` and created `<div id="app"></div>`, with no root box anywhere on the page.
2. In the startup file, `document.getElementById` searched the page for `'root'`. Finding nothing, it returned `null`.
3. Passing `null` into `createRoot` crashed the startup script before React could ever reach the render step.

You get the exact same error if you skip the DOM lookup and pass `<App />` directly into `createRoot`:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = ~createRoot(<App />)~; // **WRONG:** <App /> is a React element, not a browser DOM node!
```

`createRoot` only accepts a real browser DOM container from the HTML page.

### What if index.html already has HTML inside #root?

Interviewers and code reviewers sometimes ask what happens if `index.html` places a temporary message inside the host box, such as a `<p>Loading...</p>` line.

While the JavaScript bundle is still downloading over the network, the browser shows `<p>Loading...</p>` inside `<div id="root">`. The moment `root.render` runs for the first time, React wipes out every existing child node inside `<div id="root">` and replaces it with your rendered component tree. Anything outside `<div id="root">` stays untouched.

```tree dir=right caption="The three-part handshake that connects the HTML host box to React."
The Two-File Host Handshake
- +1. HTML host element [`index.html`] | Places `<div id="root"></div>` inside `<body>`
- +2. Browser DOM lookup [`src/main.jsx`] | Calls `document.getElementById` with `'root'` to grab the live `<div>`
- +3. React root creation [`createRoot`] | Attaches React's root manager to that real DOM element
```

> [!PRINCIPLE]
> **Principle 1: The HTML Host Container: Match the ID in index.html and main.jsx**
>
> *Pass a real browser DOM element to createRoot by matching the container ID in index.html with the ID in document.getElementById.*
>
> `createRoot` takes a real browser DOM element, not a React component. The HTML file provides an empty `<div id="root"></div>`, and the startup file looks it up with `document.getElementById`. If the two IDs do not match, the lookup returns `null` and `createRoot` throws a target container error.
>
> **DO THIS:**
> ```jsx title="src/main.jsx"
> const container = ~document.getElementById('root')~; // Matches <div id="root"> in index.html
> const root = ~createRoot(container)~; // Passes the real browser DOM element
> root.render(<App />);
> ```
>
> **DO NOT DO THIS:**
> ```jsx title="src/main.jsx"
> const container = ~document.getElementById('app')~; // **WRONG:** returns null when index.html uses id="root"
> const root = ~createRoot(container)~; // **WRONG:** crashes because container is null
> root.render(<App />);
> ```

## 2. Principle 2: The Module Entry and Build Tool: Use type="module" and Vite

### A browser needs type="module" for imports and Vite to translate JSX and package names

When you run `npm run dev`, Vite starts a local server and opens your page so smoothly that it feels as if the browser is running `main.jsx` directly. In reality, two strict browser rules stand between your source file and the screen:

- **In daily coding**: If you write a `<script>` tag in the HTML file **without `type="module"`**, the browser runs the script in classic mode and stops on the first import line.
- **In an interview**: When an interviewer asks why we use a build tool like Vite instead of opening `.jsx` files directly in the browser, name the **two things Vite translates**:
  1. Vite rewrites **bare package names** from `node_modules` into real URL paths the browser can fetch.
  2. Vite compiles **JSX angle-bracket tags** like `<App />` into standard JavaScript `jsx` function calls.

```tree caption="What breaks when loading main.jsx as a classic script without Vite vs. using type='module' with Vite."
How the browser loads and understands `src/main.jsx`
- !Classic `<script>` without Vite | Rejects `import` lines, bare package names, and `<App />` JSX tags | Stops with **`SyntaxError`** or **`TypeError`** before React runs
- +`<script type="module">` with Vite | +**DO** add `type="module"` in `index.html` and run Vite | Browser enables `import`, and Vite translates package names and JSX into plain JS
```

### What happens when you leave type="module" off the script tag

Look at what happens in the HTML file when a developer writes a normal `<script>` tag and forgets `type="module"`:

```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <div id="root"></div>
    <~script src="/src/main.jsx"~></script> <!-- **WRONG:** classic script mode forbids import statements! -->
  </body>
</html>
```

The moment the browser reads line 1 of `main.jsx` and sees the word `import`, it stops with a syntax error:

```devconsole caption="Browser Console error when index.html loads main.jsx without type='module'."
x Uncaught SyntaxError: Cannot use import statement outside a module
```

Adding `type="module"` to the `<script>` tag switches the browser into ES module mode so imports work across files:

In classic script mode, the browser rejects `import` on line 1 of `main.jsx`.

### Two things inside main.jsx that the browser cannot run without Vite

Even after you add `type="module"`, the browser still cannot run a raw `main.jsx` file on its own. Look at lines 1 and 5 of our startup file:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from ~'react-dom/client'~; // 1. Bare package name: browser does not know where node_modules lives
import App from './App.jsx';

const root = createRoot(document.getElementById('root'));
root.render(~<App />~); // 2. JSX tag: browser JavaScript engine rejects the < character
```

If you serve that file through a plain static server without Vite, the browser hits two roadblocks:
1. **Line 1 uses a bare package name**: Relative imports start with a dot, so the browser knows what URL to fetch. By contrast, the `react-dom` client import on line 1 has no dot prefix, so a raw browser refuses to search `node_modules` and throws a type error.
2. **Line 5 uses JSX angle brackets**: As we saw in Lecture 2, `<App />` is JSX, not standard JavaScript. Without Vite compiling that tag first, the browser stops on the `<` character with a `SyntaxError`.

Vite solves both problems in two modes:
- **During development**, running `vite` starts a local server that transforms each file on the fly. It rewrites bare package imports to pre-bundled URLs and compiles `<App />` into a plain `jsx` call.
- **For production**, running `vite build` bundles and minifies your entire module tree ahead of time into plain `.js` files that any static web server can deliver.

```tree dir=right caption="How index.html and Vite work together to deliver valid JavaScript to the browser."
How index.html and Vite Deliver main.jsx
- +1. Module script tag [`index.html`] | `<script type="module">` unlocks ES module `import` syntax in the browser
- +2. Package resolution [`Vite`] | Rewrites bare package names like `'react-dom/client'` into valid browser URLs
- +3. JSX compilation [`Vite`] | Compiles `<App />` into a standard JavaScript `jsx` call before execution
```

> [!PRINCIPLE]
> **Principle 2: The Module Entry and Build Tool: Use type="module" and Vite**
>
> *Load the entry file with type="module" in index.html, and use a build tool like Vite to resolve bare package imports and compile JSX into standard JavaScript.*
>
> In the HTML file, `<script type="module">` tells the browser to load the startup file with ES module `import` support. Before that file reaches the browser, Vite resolves bare package imports from `node_modules` and compiles JSX tags like `<App />` into standard JavaScript calls.
>
> **DO THIS:**
> ```html title="index.html"
> <body>
>   <div id="root"></div>
>   <script ~type="module"~ src="/src/main.jsx"></script> <!-- Enables ES module imports -->
> </body>
> ```
>
> **DO NOT DO THIS:**
> ```html title="index.html"
> <body>
>   <div id="root"></div>
>   <~script src="/src/main.jsx"~></script> <!-- **WRONG:** classic script mode rejects import statements -->
> </body>
> ```

## 3. Principle 3: Two-Step Mounting: Call createRoot First, Then Call root.render

### Creating the React root and painting the screen are two separate steps

At first glance, the name `createRoot` sounds as if it mounts your application all by itself. In React 19, however, connecting React to the HTML box and painting your components inside it are **two separate steps**:

- **In daily coding**: If you call `createRoot` on the host element **but forget to call `root.render` on the next line**, the screen stays completely blank and the Console prints **zero errors**!
- **In an interview**: State the package and both steps in order. First, import `createRoot` from the `react-dom` client package and call it on the DOM node. Second, call `root.render` with `<App />` to paint the UI.

### What happens when you call createRoot and forget root.render

Look at what happens when a developer writes the `createRoot` line in `main.jsx` and stops there:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = document.getElementById('root');
const root = ~createRoot(container)~; // **WRONG:** creates the root in memory, but never calls root.render!
```

Because that code is valid JavaScript and valid React, nothing crashes. Instead, the browser shows a blank white page, `<div id="root"></div>` stays completely empty in the Elements panel, and the Console is silent:

### Completing the mount with root.render or chaining both calls

To put the component tree on screen, add the second step and call `root.render` on the `root` object:

```jsx title="src/main.jsx" startLine="1"
import { ~createRoot~ } from 'react-dom/client'; // Import from react-dom/client, never from 'react'
import App from './App.jsx';

const container = document.getElementById('root');
const root = ~createRoot(container)~; // Step 1: Claim the #root DOM container
~root.render(<App />)~; // Step 2: Paint the <App /> tree inside #root
```

When you do not need to keep the `root` variable around, you can chain both calls in one line:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

~createRoot(document.getElementById('root')).render(<App />)~; // Step 1 and Step 2 chained together
```

Both forms execute the exact same two steps: `createRoot` runs first and returns the root object, and `.render` runs immediately on that returned root.

### Why createRoot lives in react-dom/client and replaces ReactDOM.render

Two quick package questions often come up alongside `createRoot` in interviews:
1. **Why the `react-dom` client package instead of `'react'`?** As we saw in Lecture 1, `'react'` holds platform-independent component logic that works on the web, on mobile, and on servers. Browser DOM mounting lives in the `react-dom` client package, so importing `createRoot` from the core package fails immediately.
2. **What happened to `ReactDOM.render` from older tutorials?** React 17 used a single call, `ReactDOM.render`, that took both `<App />` and the DOM node at once. React 19 removed `ReactDOM.render` completely. Because `createRoot` already remembers your DOM node, `root.render` takes **only one argument**: the root element.

```tree dir=right caption="The two distinct steps that mount a React 19 application."
The Two-Step Mount in React 19
- +1. Create the root [`createRoot`] | Connects React to the `#root` DOM element and returns the `root` object
- +2. Render the tree [`root.render`] | Evaluates `<App />` and mounts the resulting DOM nodes inside `#root`
```

> [!PRINCIPLE]
> **Principle 3: Two-Step Mounting: Call createRoot First, Then Call root.render**
>
> *Import createRoot from the react-dom client package, call createRoot on the DOM container to create a React root, and then call root.render to mount your component tree.*
>
> Mounting in React 19 takes two steps using `createRoot` from the `react-dom` client package. First, `createRoot` attaches a React root manager to the browser DOM element. Second, `root.render` renders your component tree inside that root. Calling `createRoot` without `root.render` leaves the page blank with zero Console errors.
>
> **DO THIS:**
> ```jsx title="src/main.jsx"
> import { ~createRoot~ } from 'react-dom/client'; // Browser DOM root API lives in react-dom/client
> import App from './App.jsx';
>
> const root = ~createRoot(document.getElementById('root'))~; // Step 1: Create root
> ~root.render(<App />)~; // Step 2: Paint the component tree
> ```
>
> **DO NOT DO THIS:**
> ```jsx title="src/main.jsx"
> import { createRoot } from 'react-dom/client';
> import App from './App.jsx';
>
> const root = ~createRoot(document.getElementById('root'))~; // **WRONG:** stops after step 1; screen stays blank!
> ```

## 4. Principle 4: Pass a JSX Element to root.render, Not the Component Function

### Passing a function to an event listener is not the same as passing a JSX element to root.render

In plain JavaScript, you often pass a raw function name like `handleClick` into `addEventListener` so the browser can call it later. Because our root component is also an imported JavaScript function, it is tempting to pass `App` straight into `root.render` without angle brackets.

- **In daily coding**: Writing `App` without angle brackets inside `root.render` leaves the screen blank and prints a React warning in the Console saying functions are not valid as a React child.
- **In an interview**: Explain what the angle brackets do. Writing `<App />` tells Vite to create a **React element object** whose `type` points to our component. `root.render` expects that element object, never the raw uncalled function.

```tree caption="Passing the raw App function reference vs. passing the <App /> JSX element to root.render."
What should you pass to root.render?
- !Raw function reference [`App`] | Passes the uncalled JavaScript function `App` | Leaves `#root` empty and logs **`Functions are not valid as a React child`**
- +JSX element tag [`<App />`] | +**DO** wrap `App` in angle brackets as `<App />` | Vite creates `{ type: App, props: {} }`, and React calls `App` to build the page
```

### What happens when you pass the raw App function to root.render

Look at what happens when we pass the function name `App` without angle brackets to `root.render`:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = createRoot(document.getElementById('root'));
root.render(~App~); // **WRONG:** passes the raw function App instead of the JSX element <App />!
```

When you open the browser, `<div id="root"></div>` stays empty and React prints a helpful error in the Console that even names the exact mistake:

```devconsole caption="React Console error when main.jsx passes the raw function App to root.render instead of <App />."
x Functions are not valid as a React child. This may happen if you return App instead of <App /> from render. Or maybe you meant to call this function rather than return it.
```

### Wrapping App in angle brackets as <App /> fixes the mount

Now wrap `App` in angle brackets as a JSX tag:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = createRoot(document.getElementById('root'));
root.render(~<App />~); // Passes a React element object whose type is App
```

Look at why those two angle brackets make all the difference:
1. As we learned in Lecture 2, Vite compiles `<App />` into a `jsx` function call that returns a plain React element object in memory.
2. As we learned in Lectures 4 and 5, starting `App` with a capital letter tells JSX to put our imported component function into that element object's `type` field.
3. When `root.render` receives that element object, React calls `App` during rendering and mounts the returned page layout inside the host container.

> [!PRINCIPLE]
> **Principle 4: Pass a JSX Element to root.render, Not the Function**
>
> *Always pass a JSX element like <App /> to root.render rather than passing the raw component function App.*
>
> `root.render` expects a React element such as `<App />`, not the raw component function. Vite compiles `<App />` into a plain element object whose type points to `App`. Passing the raw `App` function to `root.render` leaves the container empty and logs a React child warning.
>
> **DO THIS:**
> ```jsx title="src/main.jsx"
> const root = createRoot(document.getElementById('root'));
> root.render(~<App />~); // Passes a React element object { type: App, props: {} }
> ```
>
> **DO NOT DO THIS:**
> ```jsx title="src/main.jsx"
> const root = createRoot(document.getElementById('root'));
> root.render(~App~); // **WRONG:** passes a raw function; logs Functions are not valid as a React child
> ```

## Putting All Four Principles Together

Here is how `index.html` and `main.jsx` bring all four principles together on a single screen:

```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <~div id="root"~></div> <!-- Principle 1: Host container with id="root" -->
    <script ~type="module"~ src="/src/main.jsx"></script> <!-- Principle 2: ES module entry point -->
  </body>
</html>
```

In `main.jsx`, Vite resolves the package import and compiles `<App />` so the browser can create the root and render the tree:

```jsx title="src/main.jsx" startLine="1"
import { ~createRoot~ } from 'react-dom/client'; // Principle 2 & 3: Bare import resolved by Vite
import App from './App.jsx';

const container = ~document.getElementById('root')~; // Principle 1: Matches id="root" in index.html
const root = ~createRoot(container)~; // Principle 3: Creates the React root manager
~root.render(<App />)~; // Principle 3 & 4: Renders the <App /> JSX element into #root
```

```tree dir=right caption="The complete startup chain from index.html through Vite and createRoot to the rendered DOM."
How a React 19 App Mounts from Start to Finish
- +1. `index.html` [`<div id="root">` + `type="module"`] | Provides the empty DOM container and loads `src/main.jsx` as an ES module
- +2. `Vite` [dev server or build] | Rewrites `'react-dom/client'` into a browser URL and compiles `<App />` into a `jsx` call
- +3. `createRoot` [`src/main.jsx`] | Attaches React's root manager to the live `<div id="root">` node
- +4. `root.render` [`<App />`] | Calls `App` and inserts its returned `<main>` tree inside `<div id="root">`
```

## For the Interview

When an interviewer asks how you mount a root component with `createRoot` and why we use Vite, walk through the startup chain from `index.html` to `main.jsx`. Then name the two translations Vite performs:

| Principle | What Breaks Without It | Browser or React Symptom | Fix |
| :--- | :--- | :--- | :--- |
| **1. HTML Host Container** | `document.getElementById` looks up an ID that does not match `index.html`, or `createRoot` is given `<App />` | `Uncaught Error: Target container is not a DOM element.` | Put `<div id="root"></div>` in `index.html` and pass that DOM node to `createRoot` |
| **2. Module Entry and Vite** | Omitting `type="module"` or serving `.jsx` without a build tool | `Cannot use import statement outside a module`, `Failed to resolve module specifier`, or `Unexpected token '<'` | Load `main.jsx` with `<script type="module">` and let Vite transform JSX and bare imports |
| **3. Two-Step Mount** | Calling `createRoot` without `root.render`, or importing `createRoot` from `'react'` | Blank screen with 0 errors, or `TypeError: createRoot is not a function` | Import `createRoot` from `'react-dom/client'`, create `root`, and call `root.render` |
| **4. JSX Element in render** | Passing the raw function `App` to `root.render` instead of `<App />` | Blank screen and Console error `Functions are not valid as a React child.` | Pass `<App />` so Vite creates a React element `{ type: App, props: {} }` |

### Traps Look-Alike Comparisons

Interviewers love testing small mistakes in the three-line startup file because each mistake produces a completely different failure mode:

| What You Wrote | What It Actually Passes or Does | Runtime Result | What to Write Instead |
| :--- | :--- | :--- | :--- |
| `'app'` in `getElementById` when HTML has `id="root"` | Passes `null` to `createRoot` | Throws `Uncaught Error: Target container is not a DOM element.` | Match the exact ID string `'root'` in both `index.html` and `main.jsx` |
| Passing `<App />` to `createRoot` | Passes a React element object instead of a browser DOM node | Throws `Uncaught Error: Target container is not a DOM element.` | Pass the `#root` DOM element to `createRoot`, then pass `<App />` to `root.render` |
| `<script src="/src/main.jsx">` without `type="module"` | Loads `main.jsx` in classic non-module script mode | Throws `Uncaught SyntaxError: Cannot use import statement outside a module` | Add `type="module"` to the `<script>` tag in `index.html` |
| Calling `createRoot` without `root.render` | Creates the React root object in memory but renders nothing | Blank page and empty `<div id="root"></div>` with zero Console errors | Call `root.render` with `<App />` on the returned root object |
| Passing raw `App` to `root.render` | Passes the uncalled function reference `App` as a child | Blank page and Console error `Functions are not valid as a React child.` | Pass the JSX element `<App />` to `root.render` |

### Battle-Tested Code

Here is the wrong startup setup alongside the clean React 19 startup setup.

**DO NOT DO THIS:**

```wrong
import { createRoot } from 'react';
import App from './App.jsx';

const root = createRoot(document.getElementById('app'));
root.render(App);
```

**DO THIS:**

```right
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = document.getElementById('root');
const root = createRoot(container);
root.render(<App />);
```

### Follow-Up Questions

1. **What happens if `index.html` already has HTML inside `<div id="root"><p>Loading...</p></div>` when `root.render` runs?**
   While the JavaScript bundle is downloading, the browser displays `<p>Loading...</p>` inside `#root`. The moment `root.render` runs for the first time, React clears all existing child nodes inside `#root` and replaces them with your rendered React component tree.

2. **Why is `createRoot` imported from `'react-dom/client'` instead of `'react'`?**
   The `'react'` package contains only platform-independent concepts like components, elements, and hooks that work everywhere, including mobile apps and servers. The `'react-dom/client'` package contains the browser-specific renderer that knows how to talk to real browser DOM nodes.

3. **Can a single HTML page call `createRoot` more than once?**
   Yes. A full-page React application normally uses a single `#root` container. However, a mostly static HTML page can place several container elements on the page and call `createRoot` once for each widget.
