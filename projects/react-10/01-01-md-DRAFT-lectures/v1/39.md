# Lecture 39: Reusing Logic Between Components with Custom Hooks
> INTERVIEW QUESTION | ❱ CORE | How do you extract and reuse stateful logic between components?

---

## How Two Components Use the Same Logic

### A status heading and a Save button that both follow the network

Picture a notes app that saves your work to a server. At the top of the screen, a heading reads `Online`. Below it sits a `Save progress` button.

```page caption="The notes app while the network is on: the heading reads Online, and the button takes clicks."
heading: Online
form:
  button: Save progress
```

Now the Wi-Fi drops, or the user turns it off. Two things change at the same moment:
1. The heading changes to `Disconnected`.
2. The button turns grey, reads `Reconnecting...`, and stops taking clicks.

```page caption="The same notes app right after the Wi-Fi drops: the heading reads Disconnected, and the button is grey and takes no clicks."
heading: Disconnected
form:
  button: Reconnecting... | | disabled
```

When the Wi-Fi comes back, the heading reads `Online` again, and the button reads `Save progress` and takes clicks again.

Here is the question this screen raises for the developer. The heading and the button are two different components, and they look nothing alike. Yet both need the same knowledge: is the network on right now? Both also need the same code to keep that knowledge up to date: one state variable, and one Effect that listens to the browser (as seen in Lesson 32). Where does that code live?

It lives in one function of our own, named `useOnlineStatus`. We move the state variable and the Effect into it, and each component calls it to read `isOnline`. React does not provide this function. Our code writes it, and inside it our code calls React's own Hooks, `useState` and `useEffect`. A function like this is called a **custom Hook**.

There are two ways to give both components the same code:
- **Copy it into each component:** the heading and the button each hold their own state variable and their own Effect, line for line the same. It works, but every later fix must be made twice.
- **Extract a custom Hook:** the state variable and the Effect move into `useOnlineStatus`, written once. Each component calls `useOnlineStatus()` and reads the value it returns.

```tree caption="Two ways to give the heading and the button the same network code: copy it into both, or write it once in a custom Hook."
Two ways to give both components the same network code
- !Copy the state and the Effect into each component | The same lines live in **two files** | Every later fix must be made **twice**, and one copy is easy to forget
- +Extract a custom Hook [`useOnlineStatus`] | The state and the Effect live in **one function** | Each component **calls it** and reads `isOnline`
```

### What is at stake

Copied code drifts apart. Here is how it happens on our screen:
1. The heading and the button each hold a copy of the same state variable and the same Effect.
2. Both copies start by assuming that the network is on. That is wrong for a user who opens the app while already offline.
3. A developer notices the problem and fixes the starting value in the heading's copy only, so the heading now asks the browser whether the network is on.
4. Later, a user opens the app while offline.

The page now gives two answers to one question. The heading reads `Disconnected`. Right below it, the button still reads `Save progress` and takes clicks.

```page caption="A user opens the app while offline, after the fix went into the heading's copy only: the heading says Disconnected, and the button still offers to save."
heading: Disconnected
form:
  button: Save progress
```

With a custom Hook, there is only one copy, so there is nothing to forget. The fix goes into `useOnlineStatus` once, and both components get it.

### A custom Hook shares the code, not the value

This is the idea to remember from this lesson: **a custom Hook shares the code that makes state, not the state itself.** Every component that calls `useOnlineStatus()` gets its own `isOnline` and its own Effect.

That sounds wrong at first, because the heading and the button change at the same moment. It looks as if both read one shared `isOnline`. **It may look the same, but it is NOT the same thing!** There are two `isOnline` values, one in each component. They agree only because both listen to the same browser events, and the browser tells both at once when the network goes off.

So a custom Hook cannot give two components one value. When two components must show one value that changes, such as whether the work was saved, the state moves up into their parent instead (as seen in Lesson 24).

Developers usually go wrong here in three ways:
1. They copy the state variable and the Effect into a second component, and later fix only one copy.
2. They think two calls of one custom Hook share one value, and they put state in a custom Hook to share it between components.
3. They wrap every small piece of code in a custom Hook, even a single `useState`, or they name Hooks after timing, such as `useMount`.

### Our project files

Our notes app uses five files. In the entry file, React mounts `App` inside `<StrictMode>` (as seen in Lesson 07). `App` renders the heading component and the button component, and both import the custom Hook from its own file:

```files title="notes-app: File Explorer" caption="How the files of our notes app sit inside src/: two components, the App that renders them, and the custom Hook they both call."
index.html | entry | The HTML page with the empty root div where React mounts
src/
  main.jsx | boundary | Imports `App` from `./App.jsx` and mounts it inside `<StrictMode>`
  App.jsx | parent | Exports `App` as default and renders `<StatusBar />` and `<SaveButton />`
  StatusBar.jsx | component | Exports `StatusBar` as default and renders the `Online` or `Disconnected` heading
  SaveButton.jsx | component | Exports `SaveButton` as default and renders the `Save progress` button

```

The custom Hook lives in a `.js` file, not a `.jsx` file, because it returns a value and no JSX.

### Three Principles of Custom Hooks

**PRINCIPLES:** A custom Hook is our own function that calls React's Hooks. It moves repeated stateful code out of components, but each call still runs that code separately. Three practical rules follow:
1. **Principle 1: Extract the Copied State and Effect into a Custom Hook**: When two components copy the same state variable and Effect, move that code into one function whose name starts with `use` and a capital letter, return the value the components need, and let each component call it. The page works exactly as before, and every later fix happens in one place.
2. **Principle 2: Each Call Gets Its Own State and Its Own Effect**: Two components that call `useOnlineStatus()` hold two separate `isOnline` values and run two separate Effects. They show the same value only because both listen to the same browser events.
3. **Principle 3: Share One Changing Value Through the Parent, Not Through a Custom Hook**: When two components must show one value that changes, such as whether the work was saved, the state lives in their parent and goes down as props. A custom Hook would give each component its own copy, and the copies never agree.

Here is the complete map of those three principles before we walk through each one:

| # | Principle | Why It Matters in Debugging and Interviews | The React Rule |
| :--- | :--- | :--- | :--- |
| **Principle 1** | **Extracting a Custom Hook** | Copied state and Effects drift apart: a fix in one copy leaves the other component showing an old answer, such as a Save button that still takes clicks while the heading says `Disconnected`. | Move the shared `useState` and `useEffect` into one function named `use` plus a capital letter, end it with `return`, and call it from each component. |
| **Principle 2** | **Independent Calls** | Interviewers ask whether two components that call the same custom Hook share its state; they do not, and the Console shows one Effect setup for each component. | Each call to a custom Hook runs its own `useState` and its own `useEffect` inside the component that called it. |
| **Principle 3** | **Sharing the Value Itself** | A state variable inside a custom Hook gives each component its own copy, so a click in one component never reaches the other, with no error and no warning. | To share one changing value, lift the state into the closest common parent and pass it down as props. |

## 1. Principle 1: useOnlineStatus Takes the Copied Effect Out of Both Components

### Imagine React had a useOnlineStatus Hook

React gives us built-in Hooks such as `useState` and `useEffect`. Imagine for a moment that React also had a built-in `useOnlineStatus` Hook. Each of our two components would need only one line to know whether the network is on:

```jsx title="StatusBar and SaveButton, if React had a useOnlineStatus Hook"
function StatusBar() {
  const isOnline = ~useOnlineStatus()~; // true while the network is on, false while it is off
  return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
}

function SaveButton() {
  const isOnline = ~useOnlineStatus()~; // The same question, asked by a second component
  return <button disabled={!isOnline}>{isOnline ? 'Save progress' : 'Reconnecting...'}</button>;
}
```

React has no such Hook. But we can write it ourselves.

A **custom Hook** is a plain JavaScript function with two marks. Its name starts with `use` followed by a capital letter (as seen in Lesson 38), and it calls other Hooks inside. Nothing else makes it a Hook. Many developers think a Hook is something only React can provide. It is not: React provides the built-in Hooks, and our code builds new Hooks out of them.

### The two copies we start with

Before the Hook exists, each component holds its own copy of the network code. Here is the heading:

```jsx title="src/StatusBar.jsx"
import { useState, useEffect } from 'react';

export default function StatusBar() {
  const [isOnline, setIsOnline] = ~useState(true)~; // Assumes the network is on when the page opens
  useEffect(() => {
    function handleOnline() {
      setIsOnline(true);
    }
    function handleOffline() {
      setIsOnline(false);
    }
    window.addEventListener(~'online'~, handleOnline); // The browser calls handleOnline when the network comes back
    window.addEventListener(~'offline'~, handleOffline); // The browser calls handleOffline when the network goes off
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);

  return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
}
```

`online` and `offline` are two events that the browser fires on `window`. The Effect listens to both, and its cleanup removes both listeners when the component unmounts (as seen in Lesson 32).

The button needs the same knowledge, so a developer copies the same state variable and the same Effect into it:

```jsx title="src/SaveButton.jsx"
import { useState, useEffect } from 'react';

export default function SaveButton() {
  const [isOnline, setIsOnline] = ~useState(true)~; // The same line, copied from StatusBar
  useEffect(() => {
    function handleOnline() {
      setIsOnline(true);
    }
    function handleOffline() {
      setIsOnline(false);
    }
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);

  function handleSaveClick() {
    console.log('Progress saved');
  }

  return (
    <button disabled={!isOnline} onClick={handleSaveClick}>
      {isOnline ? 'Save progress' : 'Reconnecting...'}
    </button>
  );
}
```

These two components work fine. But every line from `useState` to the end of the Effect now appears twice, in two files.

### A fix in one copy splits the page

Both copies start with `useState(true)`, so both assume the network is on when the page opens. That is wrong for a user who opens the app while already offline.

The browser can tell us the truth. `navigator.onLine` is a value the browser provides: `true` when the browser is online right now, and `false` when it is offline. A developer notices the problem in the heading and changes the starting value there. The button's copy is forgotten:

```jsx title="The starting value in each copy after the fix went into StatusBar only"
const [isOnline, setIsOnline] = useState(~navigator.onLine~); // StatusBar.jsx: asks the browser, so false for an offline user
const [isOnline, setIsOnline] = useState(~true~); // SaveButton.jsx: still assumes the network is on
```

This is the page from the start of the lesson. For a user who opens the app offline, the heading reads `Disconnected`, and the button below it still reads `Save progress` and takes clicks.

### Moving the copies into useOnlineStatus

The cure is to **extract** a custom Hook. To extract means to move the duplicated code out of the components and into one function that both components call. It takes three steps:
1. Create the file `src/useOnlineStatus.js`, and declare `export function useOnlineStatus()` in it.
2. Move the state variable and the Effect into that function, with the fixed starting value `navigator.onLine`.
3. End the function with `return isOnline;`, so each component can read the value.

```js title="src/useOnlineStatus.js"
import { useState, useEffect } from 'react';

export function ~useOnlineStatus~() { // Our own function: use plus a capital letter, and it calls Hooks
  const [isOnline, setIsOnline] = useState(~navigator.onLine~); // The fix, written once for both components
  useEffect(() => {
    function handleOnline() {
      setIsOnline(true);
    }
    function handleOffline() {
      setIsOnline(false);
    }
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);
  ~return isOnline;~ // Hands the value back to whichever component called the Hook
}
```

The last line decides what the components receive. A custom Hook may return any value: a boolean, a pair such as the one `useState` returns, or an object. `useOnlineStatus` returns the one thing our components need, `isOnline`.

Now each component shrinks to the part that is really its own:

```jsx title="src/StatusBar.jsx"
import { ~useOnlineStatus~ } from './useOnlineStatus.js'; // A named export, so the name goes inside curly braces

export default function StatusBar() {
  const isOnline = ~useOnlineStatus()~; // Holds whatever useOnlineStatus returned: true or false
  return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
}
```

```jsx title="src/SaveButton.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';

export default function SaveButton() {
  const isOnline = ~useOnlineStatus()~; // The same call, in a second component
  function handleSaveClick() {
    console.log('Progress saved');
  }

  return (
    <button disabled={!isOnline} onClick={handleSaveClick}>
      {isOnline ? 'Save progress' : 'Reconnecting...'}
    </button>
  );
}
```

Two names in these files need a word.
- **`isOnline` in each component** is a new constant of that component. Its name matches the state variable inside the Hook only because we chose it. We could call it `online` in one component and `isOnline` in the other.
- **`useState` and `useEffect` are gone from the imports** of both component files. Only `useOnlineStatus.js` imports them now, because only the Hook calls them.

Compare `StatusBar` with the network lines written inside it, and `StatusBar` with `useOnlineStatus()` inside it. **Yes, it is the exact same thing!** When React renders `StatusBar`, `StatusBar` calls `useOnlineStatus()`, and `useOnlineStatus` calls `useState` and `useEffect`. Those are the same calls, in the same order, during the same render of `StatusBar`, as when the lines were written inside `StatusBar` itself. The code of a custom Hook simply runs as part of the component that calls it. The heading still reads `Online` or `Disconnected`, and the button still turns into a grey `Reconnecting...` when the Wi-Fi drops.

The difference is in how the components read. `StatusBar` now says *what* it wants, the online status. The Hook holds *how* to get it: the browser's `online` and `offline` events, and the listeners that follow them. React's docs put it this way: the code of your components expresses your intent, not the implementation.

```tree dir=right caption="The same page before and after extracting useOnlineStatus: the lines move into one function, and every component calls it."
Moving the network code out of both components
- !Before: copied into each component [`useState` `useEffect` in StatusBar.jsx and SaveButton.jsx] | The same lines live in **two files** | A fix in one file **splits the page in two**
- +After: extracted into one custom Hook [`useOnlineStatus`] | The lines live **once**, in `useOnlineStatus.js` | Each component **calls the Hook** and reads `isOnline`; the page works **exactly as before**
```

### Forgetting return isOnline

The last line of the Hook is easy to forget, because nothing else in the Hook needs it. Compare the two endings of `useOnlineStatus.js`:

```js title="src/useOnlineStatus.js, ending with return isOnline" startLine="18"
  }, []);
  ~return isOnline;~ // StatusBar receives true while the network is on
}
```

```js title="src/useOnlineStatus.js, ending without return" startLine="18"
  ~}, []);~ // **WRONG:** the Effect is the last line, so the function ends and StatusBar receives undefined
}
```

Without the last line, the Hook gives nothing back. A JavaScript function that reaches its end without `return` gives back `undefined`. So `const isOnline = useOnlineStatus();` holds `undefined` in both components, even while the network is on:
- The heading's condition treats `undefined` as false, so the heading reads `Disconnected`.
- The button's `disabled={!isOnline}` turns `undefined` into `true`, so the button stays grey and reads `Reconnecting...`.

```page caption="The notes app while the network is on, when useOnlineStatus has no return line: both components behave as if the network were off."
heading: Disconnected
form:
  button: Reconnecting... | | disabled
console: quiet
```

The Hook still listens to the network, and its state still changes. No component ever sees that state, because the Hook never hands it back.

> [!PRINCIPLE]
> **Principle 1: Extracting a Custom Hook: Move the Copied State and Effect into One use Function**
>
> *When two components copy the same state variable and Effect, move that code into one function named `use` followed by a capital letter, return the value the components need, and call that function from each component.*
>
> Copied stateful code drifts apart: a fix goes into one copy, and the other component keeps showing an old answer. A custom Hook holds that code once. Its code runs as part of each component that calls it, so the page works exactly as before, and the next fix happens in one place. The last line of the Hook hands the value back; without it, every component receives `undefined`.
>
> **DO THIS:**
> ```jsx
> function StatusBar() {
>   const isOnline = ~useOnlineStatus()~; // The network code lives once, in useOnlineStatus.js
>   return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
> }
> function SaveButton() {
>   const isOnline = ~useOnlineStatus()~; // The same Hook, so a fix inside it reaches both components
>   return <button disabled={!isOnline}>Save progress</button>;
> }
> ```
>
> **DO NOT DO THIS:**
> ```jsx
> function StatusBar() {
>   const [isOnline, setIsOnline] = ~useState(navigator.onLine)~; // **WRONG:** a copy of the network state, fixed in this copy only
>   return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
> }
> function SaveButton() {
>   const [isOnline, setIsOnline] = ~useState(true)~; // **WRONG:** the second copy still assumes the network is on

## 2. Principle 2: Each Call to useOnlineStatus Gets Its Own isOnline

### Two components that change at the same moment

When the Wi-Fi drops, the heading and the button change together, in the same instant. Both call `useOnlineStatus()`. So it is natural to think that both read one shared `isOnline`.

They do not. Each call to `useOnlineStatus()` creates its own state variable and its own Effect, inside the component that made the call:

```jsx title="What the two calls to useOnlineStatus really run"
function StatusBar() {
  const isOnline = ~useOnlineStatus()~; // Runs useState and useEffect for StatusBar
}

function SaveButton() {
  const isOnline = ~useOnlineStatus()~; // Runs useState and useEffect again, this time for SaveButton
}
```

Is this the same as the two copies we started with in Principle 1? **Yes, it is the exact same thing!** Two components that each call `useOnlineStatus()` run exactly what two components with the copied `useState` and `useEffect` ran. The Hook removed the copied text from our files. It did not remove the second state variable or the second Effect.

So is one shared `isOnline` the same as two `isOnline` values that hold the same value? **It may look the same on the page, but it is NOT the same thing!** The heading and the button agree because both listen to the same browser events. Nothing in React links the two values.

React's docs name the two halves of this idea:
- **Stateful logic** is the code that creates and updates state. Here it is the `useState` call and the Effect inside `useOnlineStatus`. A custom Hook shares this code.
- **State itself** is the stored value. Here it is each component's `isOnline`. A custom Hook does not share it.

In the docs' words: custom Hooks let you share stateful logic but not state itself. Each call to a Hook is completely independent from every other call to the same Hook.

1. React renders `StatusBar`. `StatusBar` calls `useOnlineStatus()`, which creates one state variable and declares one Effect, both belonging to `StatusBar`.
2. React renders `SaveButton`. `SaveButton` calls `useOnlineStatus()`, which creates a second state variable and declares a second Effect, both belonging to `SaveButton`.
3. After React puts the page on the screen, it runs the setup of both Effects. That gives two lines, one for each component. In production, the Console stops here, at two lines.
4. In development, Strict Mode runs one extra setup and cleanup for every Effect (as seen in Lesson 32). Each of the two Effects runs its setup twice, so the line appears four times.

If both components shared one Effect, the Console would show one line in production and two in development.

### When the network goes off

The same two Effects explain why the heading and the button change together. Here is what happens when the Wi-Fi drops:
1. The browser fires one `offline` event on `window`.
2. Two listeners are attached to that event, one from each Effect. So the browser calls two `handleOffline` functions.
3. The `handleOffline` of `StatusBar` calls the `setIsOnline` of `StatusBar`. The `handleOffline` of `SaveButton` calls the `setIsOnline` of `SaveButton`.
4. React re-renders both components. The heading reads `Disconnected`, and the button reads `Reconnecting...`.

No line of `SaveButton.jsx` writes `setIsOnline`. The second `setIsOnline` is created by the `useState` call inside `useOnlineStatus`, while React renders `SaveButton`. The second pair of listeners comes from the same place: the Effect that `useOnlineStatus` declares during the render of `SaveButton`.

```tree caption="One browser event, two calls to useOnlineStatus: each component holds its own isOnline and its own Effect, and both follow the same browser."
- +SaveButton calls `useOnlineStatus` | Its **own** `isOnline` and its **own** Effect | Its `handleOffline` sets **its own** state, and the button reads **Reconnecting...**
```

Now we remove the `console.log` line from the Hook. It was there only to count the Effects.

> [!PRINCIPLE]
> **Principle 2: Independent Calls: Each Call to a Custom Hook Gets Its Own State and Its Own Effect**
>
> *Every call to a custom Hook runs its own copy of the Hooks inside it, so two components that call `useOnlineStatus()` hold two separate `isOnline` values and two separate Effects.*
>
> A custom Hook shares stateful logic, the code that makes state, and not the state itself. When two components call the same Hook, each one gets its own state variable, its own setter, and its own Effect. The heading and the button change at the same moment only because both listen to the same browser events. The Console shows the Effect's setup once for each component.
>
> **DO THIS:**
> ```jsx
> function StatusBar() {
>   const isOnline = ~useOnlineStatus()~; // StatusBar's own isOnline, which follows the browser
>   return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
> }
> ```
>
> **DO NOT DO THIS:**
> ```jsx
> function SaveButton() {
>   const isOnline = ~useOnlineStatus()~; // **WRONG:** read as the isOnline of StatusBar; it is a second state, with its own Effect and its own listeners
>   return <button disabled={!isOnline}>Save progress</button>;
> }
> ```

## 3. Principle 3: A Shared isSaved Lives in App, Not in a Custom Hook

### The user clicks Save and expects a confirmation

Now the user clicks `Save progress`. The user expects a line under the heading that says `All changes saved`.

The line belongs to the heading component, and the click belongs to the button component. So both components need one value: whether the work was saved. A developer who just saw `useOnlineStatus` keep both components in step writes a second custom Hook for this value:

```js title="src/useSaveStatus.js"
import { useState } from 'react';

export function ~useSaveStatus~() { // A custom Hook that holds one state variable
  const [isSaved, setIsSaved] = useState(false);
  return [isSaved, setIsSaved];
}
```

The heading reads `isSaved` from it and shows the line:

```jsx title="src/StatusBar.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';
import { useSaveStatus } from './useSaveStatus.js';

export default function StatusBar() {
  const isOnline = useOnlineStatus();
  const [isSaved] = ~useSaveStatus()~; // StatusBar reads isSaved from its own call
  return (
    <>
      <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>
      {isSaved && <p>All changes saved</p>}
    </>
  );
}
```

The button calls the setter when the user clicks:

```jsx title="src/SaveButton.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';
import { useSaveStatus } from './useSaveStatus.js';

export default function SaveButton() {
  const isOnline = useOnlineStatus();
  const [isSaved, setIsSaved] = ~useSaveStatus()~; // SaveButton gets the setter from its own call
  function handleSaveClick() {
    console.log('Progress saved');
    setIsSaved(true);
  }

  return (
    <button disabled={!isOnline} onClick={handleSaveClick}>
      {isOnline ? 'Save progress' : 'Reconnecting...'}
    </button>
  );
}
```

The code has the same shape as `useOnlineStatus`: one Hook, called in both components. **It may look the same, but it is NOT the same thing!** The two `isOnline` values agreed because the browser told both of them about the network. The two `isSaved` values have nothing outside React to keep them in step.

### Why All changes saved never appears

**Beware! The click saves the work, and the screen never says so.** The button changes its own `isSaved`, and the heading keeps reading a different one.

Here is what happens, in order:
1. The page opens. `StatusBar` calls `useSaveStatus()` and gets its own `isSaved`, which is `false`. `SaveButton` calls `useSaveStatus()` and gets a second `isSaved`, also `false`.
2. `StatusBar` checks its own `isSaved`. It is `false`, so the heading shows no line under it.
3. The user clicks `Save progress`. `handleSaveClick` prints `Progress saved` and calls the `setIsSaved` that `SaveButton` received from its own call.
4. React re-renders `SaveButton`. The `isSaved` of `SaveButton` is now `true`.
5. Nothing ever called the setter of `StatusBar`. Its `isSaved` is still `false`, and the click does not ask React to render `StatusBar` again.
6. The line `All changes saved` never appears.

```page caption="The notes app after the user clicks Save progress, when each component calls useSaveStatus: the Console says the progress was saved, and the page shows no confirmation."
heading: Online
form:
  button: Save progress
console:
  log: Progress saved | SaveButton.jsx:8
```

The Console shows no error and no warning, so nothing points the developer to the bug.

### Moving isSaved into App

When two components must show one value that changes, the value cannot live in a custom Hook. It lives in their closest common parent, which passes it down (as seen in Lesson 24). React's docs say it plainly: when you need to share the state itself between multiple components, lift it up and pass it down instead.

So we delete `useSaveStatus.js`, and `App` holds `isSaved`:

```jsx title="src/App.jsx"
import { useState } from 'react';
import StatusBar from './StatusBar.jsx';
import SaveButton from './SaveButton.jsx';

export default function App() {
  const [isSaved, setIsSaved] = ~useState(false)~; // One isSaved, owned by the parent of both components
  return (
    <>
      <StatusBar ~isSaved={isSaved}~ /> {/* The heading reads the value as a prop */}
      <SaveButton ~onSave={() => setIsSaved(true)}~ /> {/* The button gets a function that changes the value in App */}
    </>
  );
}
```

The heading takes `isSaved` as a prop, and the button takes `onSave`, a function that `App` created (as seen in Lesson 23). Both components still call `useOnlineStatus()`, because each still needs its own view of the network:

```jsx title="src/StatusBar.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';

export default function StatusBar(~{ isSaved }~) { // The one isSaved of App, passed down as a prop
  const isOnline = useOnlineStatus();
  return (
    <>
      <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>
      {isSaved && <p>All changes saved</p>}
    </>
  );
}
```

```jsx title="src/SaveButton.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';

export default function SaveButton(~{ onSave }~) { // A function from App that sets the isSaved of App
  const isOnline = useOnlineStatus();
  return (
    <button disabled={!isOnline} onClick={onSave}>
      {isOnline ? 'Save progress' : 'Reconnecting...'}
    </button>
  );
}
```

Now one click changes the one `isSaved` that both components read. Look at the page after the click, in both versions:

When the two components sit far apart in the tree, passing the value through every level gets long. Context carries it down instead (as seen in Lesson 28). The rule stays the same: one component owns the value, and the others receive it.

```tree caption="What a custom Hook shares and what a parent shares: the code that makes state, or one value for several components."
Two ways to reuse something between components
- +A custom Hook [`useOnlineStatus`] | Shares the **code** that makes state | Each component gets **its own value**; fits `isOnline`, which the browser keeps in step
- !A custom Hook for a shared value [`useSaveStatus`] | Gives each component **its own `isSaved`** | A click in the button **never reaches** the heading
- +State in the parent, passed down [`isSaved` in `App`] | Shares **one value** | Both components read the **same `isSaved`**, so the heading confirms the save
```

> [!PRINCIPLE]
> **Principle 3: Sharing the Value Itself: Lift the State into the Parent, Not into a Custom Hook**
>
> *When two components must show one value that changes, such as whether the work was saved, put that state in their closest common parent and pass it down as props.*
>
> A custom Hook gives every component that calls it a separate copy of its state. That is right for `isOnline`, because the browser keeps every copy in step. It is wrong for `isSaved`: the button changes its own copy, and the heading keeps reading the other one, with no error and no warning. The parent owns one value, passes it down, and hands the button a function that changes it.
>
> **DO THIS:**
> ```jsx
> export default function App() {
>   const [isSaved, setIsSaved] = useState(false);
>   return (
>     <>
>       <StatusBar ~isSaved={isSaved}~ /> {/* Both components read the one isSaved of App */}
>       <SaveButton onSave={() => setIsSaved(true)} />
>     </>
>   );
> }
> ```
>
> **DO NOT DO THIS:**
> ```jsx
> export default function StatusBar() {
>   const [isSaved] = ~useSaveStatus()~; // **WRONG:** a separate isSaved that the click in SaveButton never changes
>   return isSaved && <p>All changes saved</p>;
> }
> ```

```jsx title="src/StatusBar.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';
```

```jsx title="src/SaveButton.jsx"
  const isOnline = ~useOnlineStatus()~; // Principle 2: a second, separate isOnline
  return (
    <button disabled={!isOnline} onClick={onSave}>
      {isOnline ? 'Save progress' : 'Reconnecting...'}
    </button>
  );

```

```js title="src/useOnlineStatus.js"
import { useState, useEffect } from 'react';

export function ~useOnlineStatus~() { // Principle 1: the copied state and Effect, written once
  const [isOnline, setIsOnline] = useState(navigator.onLine);
  useEffect(() => {
    function handleOnline() {
      setIsOnline(true);
    }
    function handleOffline() {
      setIsOnline(false);
    }
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);
  ~return isOnline;~ // Principle 1: the value each component reads
}
```

When the page opens, React calls `App` first. `App` creates `isSaved`. Then React calls `StatusBar`, whose call to `useOnlineStatus` creates the first `isOnline` and the first Effect. Then React calls `SaveButton`, whose call creates the second `isOnline` and the second Effect:

```tree caption="The order in which React calls the components of the notes app, and the state each call creates."

- +`StatusBar` [2. Called second] | Receives `isSaved` as a **prop** | Calls `useOnlineStatus` and gets the **first** `isOnline` and the **first** Effect
- +`SaveButton` [3. Called third] | Receives `onSave` as a **prop** | Calls `useOnlineStatus` and gets the **second** `isOnline` and the **second** Effect
```

| Aspect | The Habit to Avoid | The React Rule |
| :--- | :--- | :--- |
| **Reusing stateful code** | Copy the same `useState` and `useEffect` into a second component, then fix only one copy | Extract one custom Hook, such as `useOnlineStatus`, and call it from each component |
| **The value a Hook gives** | Forget `return isOnline;`, so every component receives `undefined` | End the Hook with `return` and the value the components need |
| **Two calls of one Hook** | Believe both components read one shared `isOnline` | Each call creates its own state and its own Effect; the browser keeps them in step |
| **One value for two components** | Put `isSaved` in a custom Hook and call it in both components | Lift `isSaved` into `App` and pass it down as props |

## For the Interview

> **The Interview Question:** How do you extract and reuse stateful logic between components?

### How to Answer Clearly in 30 Seconds

"When two components repeat the same stateful logic, such as a state variable and an Effect that listens to the browser's `online` and `offline` events, I extract it into a custom Hook. A custom Hook is my own JavaScript function whose name starts with `use` and a capital letter, and which calls other Hooks. It returns what the components need, so each component calls `useOnlineStatus()` and reads `isOnline`. The page behaves exactly as before, and every fix happens in one place. Two things to keep in mind:
1. **A custom Hook shares logic, not state**: every call runs its own `useState` and its own `useEffect`, so two components get two independent values.
2. **To share the value itself**, I lift the state into the closest common parent and pass it down as props, or I use context when the components are far apart."

### Three Classic Follow-Up Questions Interviewers Ask

1. **"If two components call the same custom Hook, do they share its state?"**
   **No.** Each call to a Hook is completely independent from every other call to the same Hook. When `StatusBar` and `SaveButton` both call `useOnlineStatus()`, each one gets its own `isOnline`, its own setter, and its own Effect with its own listeners. They show the same value only because both listen to the same browser events. A state variable inside a custom Hook such as `useSaveStatus` therefore cannot carry a click from one component to the other. For that, the state goes up into the parent.
2. **"Should every piece of repeated code become a custom Hook?"**
   **No.** React's docs say that some duplication is fine. A Hook that wraps a single `useState` adds a name and saves nothing. The strongest case for a custom Hook is an Effect that talks to something outside React, such as the network, a socket, or a media query. Name the Hook after its purpose, such as `useOnlineStatus` or `useChatRoom`, and never after timing, such as `useMount`: a Hook like `useMount` hides the Effect's dependencies, and the linter checks only direct `useEffect` calls, so it cannot warn about them. A function that calls no Hooks at all stays a regular function without the `use` prefix, such as `getSorted` (as seen in Lesson 38).
3. **"Why wrap an Effect in a custom Hook even when it already works inside the component?"**
   Because the component then says what it wants, and the Hook hides how it is done. `StatusBar` asks for the online status, and only `useOnlineStatus` knows about `navigator.onLine` and the browser's events. That pays off when a better way arrives. React's docs later rewrite `useOnlineStatus` with `useSyncExternalStore`, a Hook that Lesson 53 covers, and no component has to change. One more detail follows from where the code runs: the code of a custom Hook runs again on every render of its component, so it must stay pure, and it always receives the latest props and state (as seen in Lesson 14).

```tree dir=right caption="Interview summary: what a custom Hook shares between components, and what it does not."
What a custom Hook shares between components
- +The code that makes state [`useState` `useEffect` inside `useOnlineStatus`] | Written **once**, called from **every component** | Each fix happens **in one place**
- !Not the state itself [`isOnline` in StatusBar and SaveButton] | Every call creates its **own value** and its **own Effect** | To share **one value**, lift it into the **parent** and pass it down
```
