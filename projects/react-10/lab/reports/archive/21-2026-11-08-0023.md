## Fixes

1. Principle 2, *The box turns itself back on*, step 4. React also swaps the two message lines in that commit, so "only the `disabled` attribute" was false.
   - Old: "4. React compares the new JSX with the last one, and in the DOM it changes only the `disabled` attribute of the email box and of the button, as Lesson 13 showed."
   - New: "4. React compares the new JSX with the last one and changes only what differs, as Lesson 13 showed. It takes the `disabled` attribute off the email box and the button, and it swaps the Subscribing... line for the error line."
2. The build listed four parenthesis violations, all calls written in prose. Each was rewritten without the call:
   - Old: "1. The timer calls `setStatus('error')`." New: "1. The timer calls `setStatus` with `'error'`."
   - Old: "3. The second click calls `setIsSending(true)`, so `isSending` and `isError` are both true." New: "3. The second click sets `isSending` to true, while `isError` is still true."
   - Old: "1. The user's keystroke calls `setStatus('typing')`, and React calls `SubscribeBox` again." New: "1. The user's keystroke sets `status` to `'typing'`, and React calls `SubscribeBox` again."
   - Old: "The developer could add `classList.remove('invalid')` inside `handleEmailChange`." New: "The developer could also call `classList.remove` inside `handleEmailChange`."

After the fixes, p2-state was run again and matches the new step 4.
