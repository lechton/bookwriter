## Fixes

- Principle 1, good column preview. Old: `console: Warning: Each child in a list should have a unique "key" prop.` New: `console: Each child in a list should have a unique "key" prop.`
- Principle 2, Mistake 1 walk. Old: "When you save both files and reload the browser, the entire page crashes with a red error overlay! The error reports a `ReferenceError` saying `email` is not defined inside the row file." New: "When you save both files and reload the browser, the entire page goes blank! The Console reports an uncaught reference error saying that `email` is not defined, and React adds that the error happened inside the row component. Above that error, the Console also shows the missing-key message, because the row tags inside the map call still have no key."
- Principle 2, bad column tag. Old: `tag="ReferenceError or missing-key warning"`. New: `tag="blank page + ReferenceError"`.
- Principle 2, bad column preview. Old: a `page size=mini` block with `overlay: ReferenceError: email is not defined` and `in EmailRow at src/components/EmailRow.jsx:3:14`. New: a `page size=mini` block with `blank`, followed by a `devconsole` block with `x Each child in a list should have a unique "key" prop.` and `x Uncaught ReferenceError: email is not defined`.
- Principle 2, spread paragraph. Old: "React treats `key` specially and does not create a list key from spread props accurately across modern React builds." New: "The email object has an `id` field but no `key` field, so the spread passes no key, and the missing-key message stays in the Console. And when a spread object does hold a `key` field, React prints a separate error asking you to write the key directly on the tag."

New: `<input id="mail-undefined" type="checkbox">`, `<input id="mail-101" type="checkbox">`, `<input id="mail-102" type="checkbox">`, the order the Elements panel shows.
