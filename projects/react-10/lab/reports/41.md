## Claims checked against react.dev

- The `<form>` reference: `action` takes "A string containing a URL, or a function"; React runs a function in a Transition, it "may be async", and React calls it "with a single argument containing the form data"; React propagates errors to the nearest Error Boundary; the pending state; `useActionState` and `useOptimistic`; Server Functions; "By default, the browser sends the form data to the current URL and refreshes the page"; and the note that `onSubmit` "works in every version of React and gives you direct access to the submit event". All matched the lecture and Follow-up 1.
- The sentence the lecture quoted, "After the action function succeeds, all uncontrolled field elements in the form are reset.", is not on the `<form>` reference page. The page says React "Resets the form's uncontrolled fields when the function succeeds." The quote was replaced, see Fixes.
- The `<form>` reference also says that `onSubmit` skips the reset and that the form's `reset()` method resets uncontrolled fields. Matched Principle 2.

## Fixes

1. Principle 2, *Who empties the box?*
   - Old: React's docs promise it in one sentence: "After the action function succeeds, all uncontrolled field elements in the form are reset."
   - New: React's docs name it among the things React does when `action` holds a function: it "resets the form's uncontrolled fields when the function succeeds."
