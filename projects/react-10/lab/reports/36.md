# Lab report: Lecture 36, Separating Events from Effects with useEffectEvent

Checked on 2026-11-10 against the lab: React 19.3.1, React DOM 19.3.1, Vite 8.3.6, `@vitejs/plugin-react` 6.2.1, all in a hidden Chrome, on the dev server with Strict Mode on, the way the lecture's `main.jsx` mounts `App`. Every case uses the lecture's own `chat.js`, `notifications.js`, and `App.jsx`, and the lecture's `ChatRoom.jsx` for that principle. `lab/cases/36/helper.mjs` holds the user actions, ticking the Mute notifications box and picking a room in the menu, and a Console watcher that stamps each line with the seconds since the page opened, so the three-second messages can be placed against the user's actions. The chat helper picks `hey` or `lol` at random, so the message texts differ from run to run; the lecture's previews show one possible run, and the cases check the count and order of the lines. Run every command from `projects/react-10`.

## Cases

- Case: lab/cases/36/p0-open, run with `node lab/check.mjs lab/cases/36/p0-open`.
- Claims: the opening preview. The page shows the menu on general, the unticked box, and "Welcome to the general room!". In development, the Console shows connect, disconnect, connect for general from Strict Mode, and about three seconds later one line `🔔 New message: hey`.
- Matched: the screen, the three Strict Mode lines with the exact texts `✅ Connecting to "general" room at https://localhost:1234...` and `❌ Disconnected from "general" room at https://localhost:1234`, and one notification line three seconds after the connect.
- Fixed: nothing.

- Case: lab/cases/36/p1-muted-in-effect, run with `node lab/check.mjs lab/cases/36/p1-muted-in-effect`.
- Claims: with `[roomId, muted]`, ticking the box prints a disconnect from general and a new connect to general, and the heading stays on general. Every untick does the same. A user who ticks and unticks the box faster than every three seconds gets no messages at all, because each reconnect clears the timer before it fires.
- Matched: each tick and each untick printed one disconnect and one connect for general, with the heading unchanged. While the box was toggled every two seconds for twelve seconds, six reconnects printed and no message arrived.
- Fixed: nothing.

- Case: lab/cases/36/p2-on-message, run with `node lab/check.mjs lab/cases/36/p2-on-message`.
- Claims: with `onMessage` and `[roomId]`, ticking the box prints no disconnect and no connect, and no notification line appears for the next messages. Unticking the box brings the notification lines back on the same connection.
- Matched: after the tick, 6.8 seconds passed with no Console line. After the untick, three notification lines arrived three seconds apart, with no disconnect or connect line in between.
- Fixed: nothing.

- Case: lab/cases/36/p2-on-message-in-deps, run with `node lab/check.mjs lab/cases/36/p2-on-message-in-deps`.
- Claims: with `[roomId, onMessage]`, the chat disconnects and connects again on every render of `ChatRoom`, including every tick of the box.
- Matched: the tick and the untick each printed a disconnect and a connect for general, and picking travel printed a disconnect from general and a connect to travel. With no render for 3.5 seconds, nothing reconnected.
- Fixed: nothing.

- Case: lab/cases/36/p3-suppressed, run with `node lab/check.mjs lab/cases/36/p3-suppressed`.
- Claims: with `[roomId]` and the linter suppressed, ticking the box prints no disconnect, and notification lines keep coming. Picking travel while the box is ticked reconnects, and then no notification lines appear. Unticking the box then brings no notification lines back until the room changes again.
- Matched: two notification lines arrived after the tick. Picking travel printed one disconnect and one connect, then nothing for 6.8 seconds. After the untick, nothing for 6.9 seconds. Picking music reconnected, and its first message printed a notification line.
- Fixed: nothing.

- Case: lab/cases/36/p4-on-mount, run with `node lab/check.mjs lab/cases/36/p4-on-mount`.
- Claims: with the whole connection inside `onMount` and `[]`, picking travel changes the heading to travel, the Console shows no disconnect and no new connect, and the messages still come from the general connection.
- Matched: the heading read "Welcome to the travel room!", the Console kept only the three general lines, and a notification line still arrived after the pick. Calling `onMessage` from inside `onMount` threw no error.

- Case: lab/cases/36/p5-render, run with `node lab/check.mjs lab/cases/36/p5-render` and with `node lab/check.mjs lab/cases/36/p5-render --prod`.
- Claims: calling `onMessage` in the body of `ChatRoom` throws an error, the page goes blank, and the Console shows `Uncaught Error: A function wrapped in useEffectEvent can't be called during rendering.` and then "An error occurred in the <ChatRoom> component. Consider adding an error boundary to your tree to customize error handling behavior."
- Matched: the blank page and the error line, word for word.
- Differed: the second message is a warning, not an error, and React adds a third sentence to it: "Visit https://react.dev/link/error-boundaries to learn more about error boundaries." The lecture drew the message as an error and cut that sentence. See fix 1. In the production build, the error is the minified React error #440, and the warning is not printed; the lecture's Console is a development Console, so nothing changed for that.

- Case: lab/cases/36/p5-click, run with `node lab/check.mjs lab/cases/36/p5-click`.

- Case: lab/cases/36/p5-child, run with `node lab/check.mjs lab/cases/36/p5-child`. This is a probe: `MessageList` receives `onMessage` as a prop, logs whether it is the same function as on the last render, and lists it in the array of its own Effect.

- Matched: every committed render handed `MessageList` a new function, and its Effect ran again after the tick and after the untick. Calling `onMessage` from the child's Effect threw no error.

- Case: lab/cases/36/final, run with `node lab/check.mjs lab/cases/36/final`.
