## Fixes

1. Principle 3, before the final `SignupForm`.
   - Old: At submit, our code reads each box from the place that keeps its text. React's docs say it directly: "If you instead control an input with state, read from that state on submit rather than from `FormData`."
   - New: At submit, our code reads each box from the place that keeps its text: the email from `FormData`, and the password from state.
2. Principle 3, the paragraph on the starting value.
   - Old: With `useState()` and no starting value, the box starts uncontrolled. When the user types the first letter, the Console shows the warning that begins "A component is changing an uncontrolled input to be controlled".
   - New: With `useState()` and no starting value, the box starts uncontrolled. When the user types the first letter, the Console shows the red error that begins "A component is changing an uncontrolled input to be controlled". In our form, the page breaks even before that. `password.length` asks for the length of `undefined`, so the page stays blank when it loads. The Console shows the red error "Cannot read properties of undefined".
3. Follow-up 3.
   - Old: the first keystroke by the user makes React warn that "A component is changing an uncontrolled input to be controlled".
   - New: the first keystroke by the user makes React print the error "A component is changing an uncontrolled input to be controlled".
