## Fixes

1. Principle 4, *Reading data before the first submit*, the page preview of the crash. React prints the warning with a third sentence.
   - Old: `  warn: An error occurred in the <CommentFooter> component. Consider adding an error boundary to your tree to customize error handling behavior.`
   - New: `  warn: An error occurred in the <CommentFooter> component. Consider adding an error boundary to your tree to customize error handling behavior. Visit https://react.dev/link/error-boundaries to learn more about error boundaries.`
2. For the Interview, follow-up 1. With no form above, `method` is `null` too.
   - Old: "With no form above, the Hook returns `pending` as `false`, and `data` and `action` as `null`."
   - New: "With no form above, the Hook returns `pending` as `false`, and `data`, `method`, and `action` as `null`."
3. For the Interview, follow-up 3. The old text led the reader to expect `'post'` for a form with a function in `action`; React DOM reports `'get'` for our form, and a `method` prop on such a form triggers a Console error.
   - Old: "`method` is the string `'get'` or `'post'`. React's docs add that when a function is passed to the `action` prop of a form, the HTTP method is POST, whatever the `method` prop says."
   - New: "During a submission, `method` is the string `'get'` or `'post'`, taken from the `method` prop of the form, and `'get'` when the form has no `method` prop. Our comment form has a function in its `action` prop and no `method` prop, so `method` reads `'get'` during the wait. React does not want a `method` prop on such a form. When the form has `method="post"` next to a function, the Console shows this error: "Cannot specify a encType or method for a form that specifies a function as the action. React provides those automatically. They will get overridden.""
