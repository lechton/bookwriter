# 07. Mounting the Root Component with createRoot and Vite Tooling

> INTERVIEW QUESTION | ❱ CORE | How do you mount the root component to the DOM using `createRoot`, and why do we use tooling like Vite?

## Why We Need an HTML Page and Vite to Mount React

### A browser loads an HTML file first, never a React component file

Beat: In Lectures 4, 5, and 6, we built our news page out of components and connected them inside `App.jsx`. The page header, the section banner, and the article card all sit ready inside that root component.
Shows: Prose only.

Beat: Yet if you open a browser and visit a web address, nothing from `App.jsx` can appear on its own. A browser never starts by loading a `.jsx` component file. Every website visit begins with an HTML file, `index.html`. That HTML file does two jobs: it places one empty box on the page and invites our startup JavaScript file in.
Shows: `tree` comparing loading `src/App.jsx` directly in the browser vs. starting from `index.html` and mounting through `src/main.jsx`.

### Three startup files that put our page on the screen

Beat: Every React project built with Vite uses three startup files to bridge that gap between the browser and your component tree:
Shows: `files` explorer with `index.html`, `src/main.jsx`, and `src/App.jsx`.

Beat: Let us walk through how those three files hand work to one another from top to bottom. First, the browser loads `index.html`, which puts one empty box with `id="root"` on the page and loads our startup script:
```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <~div id="root"~></div> <!-- 1. Empty HTML box waiting for React -->
    <script ~type="module"~ src="/src/main.jsx"></script> <!-- 2. Loads main.jsx as an ES module -->
  </body>
</html>
```
Shows: Code block `index.html` highlighting `<div id="root">` and `type="module"`.

Beat: Second, our startup file `main.jsx` asks the browser for that host box, creates a React root on it, and renders `<App />`:
```jsx title="src/main.jsx" startLine="1"
import { ~createRoot~ } from 'react-dom/client'; // 1. Import React's browser DOM root creator
import App from './App.jsx';

const container = ~document.getElementById('root')~; // 2. Grab the <div id="root"> from index.html
const root = ~createRoot(container)~; // 3. Create the React root on that DOM box
~root.render(<App />)~; // 4. Paint the <App /> component tree inside #root
```
Shows: Code block `src/main.jsx`.

Beat: Third, React calls our `App` component in `App.jsx` and receives the markup for the newsroom page:
```jsx title="src/App.jsx" startLine="1"
export default function ~App~() { // Root component imported and rendered by main.jsx
  return (
    <main>
      <header>
        <h1>Latest Articles</h1>
        <p>City News</p>
      </header>
      <section>
        <h2>Section: City News</h2>
        <article className="card">
          <span className="badge">Live</span>
          <span className="badge">New</span>
          <h3>New Park Opens Today</h3>
          <p>The park on Main Street opens at noon.</p>
        </article>
      </section>
    </main>
  );
}
```
Shows: Code block `src/App.jsx`.

## 1. Principle 1: The HTML Host Container: Match the ID in index.html and main.jsx

### React does not build the whole HTML document, it moves into one empty box on the page

Beat: When you inspect a finished React website, every heading, button, and card on screen comes from React. That makes it easy to assume React creates the entire document starting from `<html>` and `<body>`. In reality, the browser builds the outer HTML page from `index.html` first, and React only takes over **one chosen DOM element** inside `<body>`.
Shows: Prose only.

Beat: - **In daily coding**: The HTML page and `main.jsx` meet on a single string ID, usually `'root'`. If someone changes the ID in one file **but forgets to update the other**, the DOM lookup returns `null` and `createRoot` crashes immediately.
- **In an interview**: Be clear about what `createRoot` takes as its input. It never takes a React component; it takes a **real browser DOM node** found in `index.html`.
Shows: `tree` comparing mismatched IDs (`id="app"` vs. `'root'`) with matching IDs (`id="root"` and `'root'`).

### What happens when the IDs in index.html and main.jsx do not match

Beat: Suppose a developer edits `index.html` and renames the host box ID to `app`:
```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <div ~id="app"~></div> <!-- Changed to "app" in index.html -->
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
```
Shows: Code block `index.html` with `id="app"`.

Beat: Meanwhile, `main.jsx` still asks the browser to find `'root'`:
```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = ~document.getElementById('root')~; // **WRONG:** returns null because #root no longer exists
const root = ~createRoot(container)~; // **WRONG:** passes null into createRoot and crashes!
root.render(<App />);
```
Shows: Code block `src/main.jsx` looking up `'root'`.

Beat: When you open the browser, the screen stays blank and the Console prints an error:
Shows: `devconsole` showing `Uncaught Error: Target container is not a DOM element.`

Beat: Look at what happened in order:
1. The browser parsed `index.html` and created `<div id="app"></div>`, with no root box anywhere on the page.
2. In the startup file, `document.getElementById` searched the page for `'root'`. Finding nothing, it returned `null`.
3. Passing `null` into `createRoot` crashed the startup script before React could ever reach the render step.
Shows: Numbered walkthrough.

Beat: You get the exact same error if you skip the DOM lookup and pass `<App />` directly into `createRoot`:
```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = ~createRoot(<App />)~; // **WRONG:** <App /> is a React element, not a browser DOM node!
```
Shows: Code block `src/main.jsx` passing `<App />` to `createRoot`.

### What if index.html already has HTML inside #root?

Beat: Interviewers and code reviewers sometimes ask what happens if `index.html` places a temporary message inside the host box, such as a `<p>Loading...</p>` line. While the JavaScript bundle is still downloading over the network, the browser shows `<p>Loading...</p>` inside `<div id="root">`. The moment `root.render` runs for the first time, React wipes out every existing child node inside `<div id="root">` and replaces it with your rendered component tree. Anything outside `<div id="root">` stays untouched.
Shows: `tree dir=right` (`The Two-File Host Handshake`) and `[!PRINCIPLE]` card for Principle 1.

## 2. Principle 2: The Module Entry and Build Tool: Use type="module" and Vite

### A browser needs type="module" for imports and Vite to translate JSX and package names

Beat: When you run `npm run dev`, Vite starts a local server and opens your page so smoothly that it feels as if the browser is running `main.jsx` directly. In reality, two strict browser rules stand between your source file and the screen:
Shows: Prose only.

Beat: - **In daily coding**: If you write a `<script>` tag in the HTML file **without `type="module"`**, the browser runs the script in classic mode and stops on the first import line.
- **In an interview**: When an interviewer asks why we use a build tool like Vite instead of opening `.jsx` files directly in the browser, name the **two things Vite translates**:
  1. Vite rewrites **bare package names** from `node_modules` into real URL paths the browser can fetch.
  2. Vite compiles **JSX angle-bracket tags** like `<App />` into standard JavaScript `jsx` function calls.
Shows: `tree` comparing classic `<script>` without Vite vs. `<script type="module">` with Vite.

### What happens when you leave type="module" off the script tag

Beat: Look at what happens in the HTML file when a developer writes a normal `<script>` tag and forgets `type="module"`:
```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <div id="root"></div>
    <~script src="/src/main.jsx"~></script> <!-- **WRONG:** classic script mode forbids import statements! -->
  </body>
</html>
```
Shows: Code block `index.html` without `type="module"`.

Beat: The moment the browser reads line 1 of `main.jsx` and sees the word `import`, it stops with a syntax error:
Shows: `devconsole` (`Uncaught SyntaxError: Cannot use import statement outside a module`) and `::: row` comparing without `type="module"` vs. with `type="module"`.

### Two things inside main.jsx that the browser cannot run without Vite

Beat: Even after you add `type="module"`, the browser still cannot run a raw `main.jsx` file on its own. Look at lines 1 and 5 of our startup file:
```jsx title="src/main.jsx" startLine="1"
import { createRoot } from ~'react-dom/client'~; // 1. Bare package name: browser does not know where node_modules lives
import App from './App.jsx';

const root = createRoot(document.getElementById('root'));
root.render(~<App />~); // 2. JSX tag: browser JavaScript engine rejects the < character
```
Shows: Code block `src/main.jsx` highlighting `'react-dom/client'` and `<App />`.

Beat: If you serve that file through a plain static server without Vite, the browser hits two roadblocks:
1. **Line 1 uses a bare package name**: Relative imports start with a dot, so the browser knows what URL to fetch. By contrast, the `react-dom` client import on line 1 has no dot prefix, so a raw browser refuses to search `node_modules` and throws a type error.
2. **Line 5 uses JSX angle brackets**: As we saw in Lecture 2, `<App />` is JSX, not standard JavaScript. Without Vite compiling that tag first, the browser stops on the `<` character with a `SyntaxError`.
Shows: Numbered walkthrough + development (`vite`) vs. production (`vite build`) bullets + `tree dir=right` (`How index.html and Vite Deliver main.jsx`) + `[!PRINCIPLE]` card for Principle 2.

## 3. Principle 3: Two-Step Mounting: Call createRoot First, Then Call root.render

### Creating the React root and painting the screen are two separate steps

Beat: At first glance, the name `createRoot` sounds as if it mounts your application all by itself. In React 19, however, connecting React to the HTML box and painting your components inside it are **two separate steps**:
- **In daily coding**: If you call `createRoot` on the host element **but forget to call `root.render` on the next line**, the screen stays completely blank and the Console prints **zero errors**!
- **In an interview**: State the package and both steps in order. First, import `createRoot` from the `react-dom` client package and call it on the DOM node. Second, call `root.render` with `<App />` to paint the UI.
Shows: Prose and daily coding / interview bullets.

### What happens when you call createRoot and forget root.render

Beat: Look at what happens when a developer writes the `createRoot` line in `main.jsx` and stops there:
```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = document.getElementById('root');
const root = ~createRoot(container)~; // **WRONG:** creates the root in memory, but never calls root.render!
```
Shows: Code block `src/main.jsx` without `root.render` + `::: row` comparing `createRoot Only` vs. `createRoot + root.render`.

### Completing the mount with root.render or chaining both calls

Beat: To put the component tree on screen, add the second step and call `root.render` on the `root` object:
```jsx title="src/main.jsx" startLine="1"
import { ~createRoot~ } from 'react-dom/client'; // Import from react-dom/client, never from 'react'
import App from './App.jsx';

const container = document.getElementById('root');
const root = ~createRoot(container)~; // Step 1: Claim the #root DOM container
~root.render(<App />)~; // Step 2: Paint the <App /> tree inside #root
```
Shows: Code block `src/main.jsx` with two-step mount.

Beat: When you do not need to keep the `root` variable around, you can chain both calls in one line:
```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

~createRoot(document.getElementById('root')).render(<App />)~; // Step 1 and Step 2 chained together
```
Shows: Code block `src/main.jsx` chained form + subsection `### Why createRoot lives in react-dom/client and replaces ReactDOM.render` + `tree dir=right` (`The Two-Step Mount in React 19`) + `[!PRINCIPLE]` card for Principle 3.

## 4. Principle 4: Pass a JSX Element to root.render, Not the Component Function

### Passing a function to an event listener is not the same as passing a JSX element to root.render

Beat: In plain JavaScript, you often pass a raw function name like `handleClick` into `addEventListener` so the browser can call it later. Because our root component is also an imported JavaScript function, it is tempting to pass `App` straight into `root.render` without angle brackets.
- **In daily coding**: Writing `App` without angle brackets inside `root.render` leaves the screen blank and prints a React warning in the Console saying functions are not valid as a React child.
- **In an interview**: Explain what the angle brackets do. Writing `<App />` tells Vite to create a **React element object** whose `type` points to our component. `root.render` expects that element object, never the raw uncalled function.
Shows: `tree` comparing raw function reference `App` vs. JSX element tag `<App />`.

### What happens when you pass the raw App function to root.render

Beat: Look at what happens when we pass the function name `App` without angle brackets to `root.render`:
```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = createRoot(document.getElementById('root'));
root.render(~App~); // **WRONG:** passes the raw function App instead of the JSX element <App />!
```
Shows: Code block `src/main.jsx` passing `App` + `devconsole` (`Functions are not valid as a React child...`).

### Wrapping App in angle brackets as <App /> fixes the mount

Beat: Now wrap `App` in angle brackets as a JSX tag:
```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = createRoot(document.getElementById('root'));
root.render(~<App />~); // Passes a React element object whose type is App
```
Shows: Code block `src/main.jsx` passing `<App />` + 3-item numbered walkthrough + `::: row` comparing `root.render` with `App` vs. `root.render` with `<App />` + `[!PRINCIPLE]` card for Principle 4.

## Putting All Four Principles Together

```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <~div id="root"~></div> <!-- Principle 1: Host container with id="root" -->

  </body>

```

Beat: In `main.jsx`, Vite resolves the package import and compiles `<App />` so the browser can create the root and render the tree:
```jsx title="src/main.jsx" startLine="1"
import { ~createRoot~ } from 'react-dom/client'; // Principle 2 & 3: Bare import resolved by Vite
import App from './App.jsx';

const container = ~document.getElementById('root')~; // Principle 1: Matches id="root" in index.html
const root = ~createRoot(container)~; // Principle 3: Creates the React root manager
~root.render(<App />)~; // Principle 3 & 4: Renders the <App /> JSX element into #root
```
