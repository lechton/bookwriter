# Q19: Updating Arrays in State
* **Topic Tag**: `#state_arrays` | `❱ CORE`
* **Interview Question**: *How do you add, remove, insert, and reorder items in a state array?*
* **Core Truth**: We treat an array in state as read-only, like an object: every change (adding, removing, inserting, replacing, reordering) builds a new array with JavaScript's non-mutating methods and passes it to the setter. Copying the array does not copy the items inside it, so changing one item means replacing that item with a new object too.
* **The Friction**: An author deletes a story with a typo from the list of articles and re-sorts the list by time. The developer calls `stories.splice(index, 1)` and `stories.sort(byTime)`, then `setStories(stories)`. Both methods change the array in place and the setter receives the same array, so React skips the re-render and the deleted story stays on screen. A later fix copies the array but writes `copy[0].title = 'Corrected'`, which also changes the story object that the previous render's array still holds.
* **The Mechanism**: Adding with spread (`[...stories, newStory]`), removing with `filter` (`stories.filter(s => s.id !== id)`), inserting with `slice` and spread (`[...stories.slice(0, i), newStory, ...stories.slice(i)]`), replacing with `map`, reordering a copy (`[...stories].sort(byTime)` or `stories.toSorted(byTime)`), and changing one item with `map` plus an object copy (`stories.map(s => s.id === id ? { ...s, title } : s)`).
* **Under the Hood**: JavaScript's array methods split into two groups: `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, and assignment by index change the array they are called on, while spread, `concat`, `filter`, `slice`, `map`, `toSorted`, `toReversed`, and `toSpliced` return a new array. The setter compares arrays with `Object.is`, so only a new array triggers a re-render, and since a copied array points to the same item objects, an item must be copied before it is changed.
* **The Code Experiment**:
  * *Naive*: Calling `.push()` or `.splice()` directly on the state array inside an event handler and calling `setStories(stories)`, then "fixing" an item by mutating it inside a copied array.
  * *React*: An `ArticleList` manager that adds, removes, inserts, reorders, and corrects stories with spread, `filter`, `slice`, `toSorted`, and `map` with an object copy, each producing a new array.
* **Scope Boundary**: Focus on the non-mutating recipe for each array operation and on copying the changed item. Do not re-teach object spread (Q18), list keys (Q11, Q61), or state structure (Q22), and do not introduce drag-and-drop libraries or virtualization (Q62); Immer may be named as an optional helper without teaching its API.
