# Q123: Request Memoization: Deduplicating Work with cache()
* **Topic Tag**: #cache | ❱ CORE (Server)
* **Interview Question**: *What is cache(), and how does it deduplicate work within a request?*
* **Core Truth**: React's cache() function memoizes the result of data fetches or computations for the duration of a single server render pass, preventing duplicate database queries and prop drilling across independent components.
* **The Friction**: An article page renders a Header, ArticleContent, and SidebarWidget; all three independently fetch the current user's subscription status from the database; without request caching, the server executes three identical SQL queries per page view, overloading the database during peak traffic.
* **The Mechanism**: const getSubscription = cache(async (userId) => { return await db.subscriptions.findUnique({ where: { userId } }); }): memoizes function output based on shallow argument equality for the lifecycle of a single incoming server request.
* **Under the Hood**: Per-request cache storage: React attaches a cache map to the current server request context (Fiber root / async storage); cache hits return the existing promise or value without re-executing the wrapped function; the cache is completely discarded when the request completes, preventing cross-request memory leaks.
* **The Code Experiment**:
  * *Naive*: Prop-drilling fetched user subscription data through five layout levels or querying the database three times in separate child components.
  * *React*: Wrapping the database query in cache(), allowing Header, ArticleContent, and SidebarWidget to call getSubscription(userId) independently with zero duplicate queries.
* **Scope Boundary**: Focus on React's cache() API for per-request function memoization in Server Components. Do not confuse with framework-specific persistent fetch caches.
