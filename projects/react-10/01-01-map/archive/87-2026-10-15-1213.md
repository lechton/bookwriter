# Q87: Testing Components the Way a Reader Uses Them
* **Topic Tag**: `#testing_components` | `❱❱❱ ADVANCED`
* **Interview Question**: *How do you test React components the way a reader uses them?*
* **Core Truth**: A component test should render the component, act on it the way a reader does (click, type, tab), and assert on what the reader sees; tests written this way survive refactors, because they depend on visible output and accessible roles rather than on state variable names or internal functions.
* **The Friction**: The team's tests assert that a `SubscribeCard` holds `subscribed: true` in state and that a mocked child received certain props. Converting the card from `useState` to `useReducer` breaks thirty tests while the screen behaves exactly as before, yet a real bug, the Subscribe button wired to the wrong handler, passes every test and ships.
* **The Mechanism**: React Testing Library with a test runner (Vitest or Jest) and a DOM environment (jsdom): `render(<SubscribeCard />)`, then `await user.click(screen.getByRole('button', { name: /subscribe/i }))` with `@testing-library/user-event`, then `expect(await screen.findByText(/subscribed/i)).toBeInTheDocument()`. Query priority: `getByRole`, `getByLabelText`, `getByText`, and `getByTestId` only as a last resort; `findBy` queries for UI that appears asynchronously; network calls mocked at the network boundary (for example with MSW) instead of mocking our own components.
* **Under the Hood**: Role queries read the accessibility tree the way assistive technology does, so a button without an accessible name fails the test and the accessibility check at the same time. Testing Library wraps `render` and user-event interactions in `act()`, so React finishes pending updates and effects before the assertion runs (the mechanics belong to Q88).
* **The Code Experiment**:
  * *Naive*: A test that reads internal state or a mocked child's props, or finds the button with `container.querySelector('.btn-primary')`, passing even when the click does nothing.
  * *React*: A test that renders `SubscribeCard`, clicks the button found by its role and name, and asserts that the confirmation text appears, failing the moment the handler is miswired.
* **Scope Boundary**: Focus on user-centric component testing with React Testing Library, query priority, user-event, and asynchronous assertions. Do not cover `act()` internals (Q88), end-to-end browser tools like Playwright or Cypress, or snapshot testing in depth.
