# Q79: SyntheticEvent Delegation at the Root Container
* **Topic Tag**: `#synthetic_events` | `❱❱❱ ADVANCED`
* **Interview Question**: *How does React's SyntheticEvent delegator work at the root DOM container?*
* **Core Truth**: React does not attach event listeners to individual DOM nodes; it attaches a single centralized listener per event type to the root DOM container (`#root`), intercepting native browser events and re-dispatching cross-browser `SyntheticEvent` instances up the fiber tree.
* **The Friction**: A developer renders a table of 10,000 newsroom rows, each with an `onClick` handler. In vanilla JS, attaching 10,000 listeners consumes massive memory. In React, beginners fear performance drops from thousands of `onClick` props, or get confused when `e.stopPropagation()` in React fails to stop a native listener attached to `document.body`.
* **The Mechanism**: Root event delegation and SyntheticEvent. React attaches listeners to `document.getElementById('root')` during `createRoot`. When a native event bubbles to the root, React creates a `SyntheticEvent` wrapper and traverses the Fiber `return` pointers to simulate capturing and bubbling.
* **Under the Hood**: React 16 vs 17+ delegation boundary: React 16 attached listeners to `document`, which caused bugs when embedding multiple React roots or micro-frontends; React 17+ delegates strictly at the root DOM container (`#root`), keeping event propagation properly scoped to the app container.
* **The Code Experiment**:
  * *Naive*: Attaching manual DOM listeners with `addEventListener` to thousands of individual buttons, wasting memory.
  * *React*: Declaring standard `onClick` props across thousands of rows, verifying via browser DevTools Event Listeners tab that only a single listener exists at the `#root` container.
* **Scope Boundary**: Focus on root delegation mechanics, the `SyntheticEvent` cross-browser wrapper, and event propagation differences between React synthetic events and native DOM events.
