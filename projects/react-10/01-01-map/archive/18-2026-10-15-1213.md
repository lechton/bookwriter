# Q18: Updating Objects in State
* **Topic Tag**: `#state_objects` | `❱ CORE`
* **Interview Question**: *How do you update an object in state without mutating it?*
* **Core Truth**: We treat every object we put in state as read-only: to change it, we create a new object with the change, using spread syntax (`...`), and pass that new object to the setter. React does not stop us from mutating, but the setter compares the new value with the current one using `Object.is`, and when it receives the same object, it skips the re-render.
* **The Friction**: An editor changes an author's bio on The National Times dashboard. The developer writes `profile.author.bio = newBio` and calls `setProfile(profile)`. The setter receives the same object it already holds, so React skips the re-render and the screen keeps the old bio; minutes later, when an unrelated state change re-renders the page, the new bio suddenly appears, because the object was changed all along.
* **The Mechanism**: Copying with spread syntax (`setProfile({ ...profile, title: newTitle })`), copying every level along the path to a nested change (`setProfile({ ...profile, author: { ...profile.author, bio: newBio } })`), and one change handler for many fields with a computed property name (`setProfile({ ...profile, [e.target.name]: e.target.value })`).
* **Under the Hood**: `Object.is` checks identity, not contents: a mutated object is still the same object, so it compares equal to itself. Spread copies only one level, and a nested object is a separate object that the parent only points to, so a nested change needs a fresh copy of each object between the root and the changed property. Leaving old objects untouched also keeps every earlier render's snapshot correct.
* **The Code Experiment**:
  * *Naive*: Mutating a nested property directly on the state object (`profile.author.bio = 'New bio'`) and passing the same object to the setter.
  * *React*: Copying both levels with spread syntax (`setProfile(p => ({ ...p, author: { ...p.author, bio: 'New bio' } }))`) so the setter receives a new object and React re-renders.
* **Scope Boundary**: Focus strictly on treating state objects as read-only, single-level and nested spread copies, and the computed-property handler. Do not cover arrays (Q19) or restructuring state to avoid deep nesting (Q22); Immer may be named as an optional helper for deep nesting without teaching its API, and external state libraries belong to Q60.
