## 1. Verdict

**Verdict:** `change`

The opening starts on an 18-line toy code component (`src/App.jsx` with `name`, `setName`, `value`, `onChange`, and a `Clear` button) whose question the reader does not know yet and whose result shows no surprise, instead of opening in plain words on a real screen the reader has used.

## 2. Form of Move 1 Used

The current opening uses the **smallest-code** form of Move 1 (`### The smallest controlled box: a name, a greeting, and a Clear button`), followed by six paragraphs that re-explain `useState` from Lesson 12 and trace the code before finally mentioning a contact form at the end of the opening.

Under Step 5, a smallest-code opening is valid only when the lesson teaches a piece of syntax or when a few lines of code produce a result the reader does not expect. Controlled inputs are a way of working (two-way data flow where `onChange` sends every user edit into React state and `value` forces the form field to show what state holds on every render), and the opening code shows no surprise at all: typing `John` into the Name box shows `John` and `Hello, John`, and clicking `Clear` clears both. Because the short code shows no surprise, this lesson must open with the **plain-words** form of Move 1 on a real screen the reader has used.

## 4. Plan for the New Opening

- **Real screen and user action (Points 1 and 2):** Open in plain words on a customer-support **Contact Us** screen on an online store such as Amazon, with a **Message** box, a character counter under it reading `0 / 200`, and a **Send** button. Walk through two actions the user performs on that screen with real numbers:
  1. The user types the 19-character question `Where is my parcel?` into the Message box. As each letter is typed, the text appears in the box and the counter below ticks up letter by letter from `0 / 200` to `1 / 200`, `2 / 200`, all the way to `19 / 200`.
  2. The user clicks **Send**. At once, the Message box becomes blank and the counter drops from `19 / 200` back to `0 / 200`, ready for the next message.
- **The question and immediate answer (Point 3):** Ask how the counter outside the box knows every letter while the user is still typing, and how clicking Send clears the text inside the box without our code ever reaching into the DOM element to erase it. Answer at once: the box does not keep its own private text; instead, React state holds the message in one place, and the box and state stay linked in a two-way loop.
- **The React pieces on that screen and the `tree` figure (Point 4):** Name the React pieces right on that screen and follow them with a `tree` Box-to-Boxes figure comparing the two directions of a controlled box (`onChange` sending every keystroke from the box into state, and `value` sending state back into the box on every render, vs. an uncontrolled box that keeps its own text inside the browser):
  1. A state variable `message` and its setter `setMessage` hold the current text in one place.
  2. The `onChange` prop on the Message box runs on every keystroke and passes the typed text (`e.target.value`) into `setMessage`, so state hears every letter right away and the `{message.length} / 200` counter updates live.
  3. The `value` prop on the Message box (`value={message}`) forces the box to display whatever `message` holds on every render, so when the Send button calls `setMessage('')`, both the Message box and the counter read from the same empty string and clear together.
- **Everyday image to unlock one word (Point 5):** Use the **classroom whiteboard** image in two sentences right after the React pieces on the screen to unlock the single word **controlled**: students call out letters (`onChange`), only the teacher writes on the board (state via the setter), and the board shows only what the teacher wrote (`value`). Keeping the classroom whiteboard image unlocks **controlled** here and keeps the later references in Principles 2, 3, and 5 intact.
- **The broken case on that screen / What is at stake (Point 6):** Show what goes wrong for the user on that exact screen when either half of the two-way loop is missing:
  1. If the box sends keystrokes to state with `onChange` but does not read `value` back from state, clicking **Send** resets `message` to an empty string so the counter drops to `0 / 200`, while `Where is my parcel?` stays visible inside the Message box. The screen gives two different answers at once, and clicking Send again submits an empty message while the old text still sits in the box.
  2. If the box reads `value` from state without `onChange`, typing a letter never updates `message`, so React overwrites the box with the old empty string after every keystroke, leaving the box frozen and the counter stuck at `0 / 200`.
- **Bridge sentence to the example page (Point 7):** End the opening with one sentence that steps into `### Our example page: the Contact Us form`: `"In this lesson, we will build that exact Contact Us form step by step across every kind of form control: a Message text area with its 0 / 200 counter, a Name input, a Topic drop-down menu, an Email me a reply tick box, and a conditional Email input that all reset together on Send."`
