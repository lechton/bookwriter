## 4. Plan for the New Opening

- **Real screen and user action (Points 1 and 2):** Open on the **Members** screen of a Slack channel (or WhatsApp group chat) with 10 members, a **Search members** box at the top, a counter line reading `Showing 10 of 10 members`, a list of member rows each with **Make admin** and **Remove** buttons, and a footer line reading `Admin: Mia`. Walk through what the user does and sees change with real numbers:
  1. The user types `a` into the search box. The list narrows to the 3 matching members, and the counter line updates from `Showing 10 of 10 members` to `Showing 3 of 10 members`.
  2. The user clicks **Remove** on Mia's row. Three things change on the screen at once: Mia's row disappears so 2 rows remain, the counter updates from `Showing 3 of 10 members` to `Showing 2 of 9 members`, and the footer changes from `Admin: Mia` to `No admin yet`.
- **The question and immediate answer (Point 3):** Ask the one question that screen raises: when one click on Remove changes the visible rows, both numbers in the counter, and the admin line at the bottom, does the component keep separate state variables for the filtered list, the counts, and the admin's object and update all of them in every click handler? Answer at once: no, it does not. The component keeps in state only the raw facts that change over time and cannot be calculated from anything else, and it calculates every other value fresh during rendering.
- **The React pieces on that screen and the `tree` figure (Point 4):** Name the two ways a React component gives the screen a value, tied directly to that Members screen, and keep the `tree` Box-to-Boxes figure (`Two ways to give the page a value`: a state value with `useState` vs. a calculated value with `const`):
  1. **A state value (`useState`):** React remembers it between renders, and it changes only when our code calls its setter. On the Members screen, only the full member list, the search text in the box, and the chosen admin's ID live in state.
  2. **A calculated value (`const`):** A `const` in the component body. React keeps nothing of it between renders. Every time React calls the component, the line runs again and computes the matching rows, the two counts (`2 of 9`), and the admin from the current state. State holds only what changes over time and cannot be calculated from anything else; React's docs state the goal as making state easy to update without introducing mistakes and, paraphrasing Albert Einstein, making state as simple as it can be, but no simpler.
- **Everyday image to unlock one word (Point 5):** After the screen and the React pieces, use a one- or two-sentence everyday image to unlock the interview question's word **derived** (one thing derives from another when it comes out of it, the way a river comes out of its spring, so a derived value comes out of state or props during rendering) or use the **paper shopping list** image in two sentences to unlock **redundant state** vs. **calculated value** (`writing the number 3 at the bottom of a paper shopping list and having to fix it by hand whenever a line is crossed out, versus counting the lines when needed`).
- **The broken case on that screen / What is at stake (Point 6):** On that same Slack or WhatsApp Members screen, show what the user sees when a developer gives every value on the screen its own `useState`: after the user clicks **Remove** on Mia, if the click handler updates only the main member list and forgets the extra setters, the screen shows two answers that disagree. The counter at the top still says `Showing 3 of 10 members` above 2 rows, or Mia's row stays on screen, and the bottom line still says `Admin: Mia` after Mia has left the group, with zero errors in the Console.
- **Bridge sentence to the example page (Point 7):** End `### What is at stake` (or the start of `### A team page where every value comes from one list`) with one sentence that moves from the channel Members screen to the lesson's smaller example page: `"In this lesson, we will build this exact screen on a smaller scale for a five-player sports team, with a Search players box, a 'Showing 5 of 5 players' counter, Make captain and Remove buttons on each row, and a captain line at the bottom."`
