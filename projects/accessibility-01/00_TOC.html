Part One: Web Accessibility (Q01–Q34)

Standards, Semantic Trees, Assistive Technologies & Patterns
CORE — Foundations and Content (Q01–Q17)
# Lecture & Interview Question Topic & Tier Core Architectural Takeaway
01
The Field With No Name
What is web accessibility, and who actually benefits when a site is accessible?
Scenario: A subscriber who is blind phones the newsroom because the checkout rejects her: her screen reader never hears the card field, and the sale is lost.
 CORE #what_is_accessibility If a control has no programmatic name, it does not exist for a screen reader, no matter how visually immaculate it appears on screen.
02
The Four Pillars of POUR
What are the four principles of WCAG (POUR), and how do they organize every success criterion?
Scenario: A developer fixes the contrast but the keyboard still cannot reach the button; fixing one kind of barrier leaves three more standing.
 CORE #pour Accessibility is not a single visual checklist; an interface is accessible only when all four pillars of POUR stand simultaneously.
03
The Three Levels of Conformance
What do WCAG conformance levels A, AA, and AAA mean, and which level should a product target?
Scenario: The team ships A only, calls the audit green, and a year later fails the procurement check that demanded AA.
 CORE #wcag_levels Level A is the floor, Level AA is the legal and commercial contract, and Level AAA is the aspirational ceiling for specialized contexts.
04
What Native Elements Give You for Free
Why is semantic HTML the foundation of accessibility, and what does a native element give you for free?
Scenario: A div styled as a button looks perfect and works for mice only: no keyboard, no name, no role, no announcement.
 CORE #semantics Semantic HTML is the browser's native accessibility layer; using a native element guarantees keyboard focus, keyboard event dispatch, and screen reader roles with zero custom code.
05
The First Rule of ARIA and When to Use It
What does the first rule of ARIA actually say, and when is ARIA the right tool?
Scenario: A developer sprinkles ARIA roles over broken markup and the screen reader experience gets worse, not better.
 CORE #native_vs_aria ARIA adjusts the accessibility tree for assistive software, but it never modifies DOM behavior, styling, or keyboard operation; a role is a promise that your JavaScript must manually fulfill.
06
The Structural Soundness of a Page
What defines the structural soundness of a page for assistive technologies?
Scenario: The article text is in English, but the screen reader attempts to pronounce it with a French accent because the `lang` attribute is missing.
 CORE #page_structure Structural soundness means declaring what a document is, what language it speaks, and how its regions relate before rendering visual content; assistive tech relies on structure, not pixels.
07
The Document Outline and Heading Hierarchy
How do headings structure a page for screen reader users, and what makes a heading hierarchy correct?
Scenario: A screen reader user jumps by headings to find the sports section and lands nowhere, because the page has no h2s, only styled divs.
 CORE #headings Headings are not decorative typography; they form the interactive, single-key navigational outline that non-visual readers depend on to skim the web.
08
Landmark Regions and Structural Page Navigation
What are landmark regions, and how do they let screen reader users skip across a page?
Scenario: On a 40-section front page, a keyboard user tabs through 60 links before reaching the first story.
 CORE #landmarks Landmark regions transform a flat DOM into an auditory topological map, enabling screen reader users to jump past repetitive menus directly to primary content in a single keystroke.
09
Skip Links and Bypass Blocks
How do skip links work and when are they necessary?
Scenario: A keyboard-only user has to tab through a 40-item mega menu on every single page refresh just to read the news.
 CORE #skip_links A skip link must be the first focusable control in the DOM, must become visually prominent on focus, and must target a container possessing tabindex="-1" so programmatic focus transfers reliably.
10
The Count You Cannot Hear
Why should you use native list semantics for grouped content?
Scenario: The sidebar shows five related stories, but the screen reader just reads them as a continuous block of text, making it impossible to know how many there are.
 CORE #lists Native list semantics convert an unmeasurable block of text into a bounded container with announced item counts, positional awareness, and keyboard exit shortcuts.
11
The Photo Without Words
What makes image alt text good or bad, and when is alt left empty?
Scenario: The lead story is a photo of the flooded bridge; a screen reader user hears only the file name.
 CORE #alt_text Always supply `alt=""` on decorative images to remove them cleanly from the accessibility tree.
12
The Chart Behind the Glass
How do you make complex images and SVG icons accessible?
Scenario: The new interactive data visualization goes live, but screen reader users just hear "graphic" with no explanation of the data.
 CORE #images Always apply aria-hidden="true" on decorative icons adjacent to visible text.
13
The Chorus of Click Heres
What distinguishes a good link from a bad one, and when should you use a button instead?
Scenario: A screen reader user pulls up a list of links on the page and hears "Click here", "Click here", "Read more", completely devoid of context.
 CORE #links Always append file type and size indicators when linking directly to non-HTML payloads like PDFs.
14
The Whispering Palette
What contrast ratios does WCAG require, and how would you test and fix a failing palette?
Scenario: A gray-on-gray redesign looks premium, but the refund link becomes invisible to a third of readers over 50.
 CORE #color_contrast Always test non-text UI borders and focus outlines against the 3 to 1 contrast threshold.
15
The Lawnmower Scroll
What is the difference between zooming text to 200% and reflowing at 320 CSS pixels?
Scenario: The user zooms the page to read the article, and the text disappears off the side of the screen requiring horizontal scrolling for every line.
 CORE #zoom_reflow 200% text zoom evaluates legacy character resizing under WCAG 1.4.4; 320px reflow evaluates modern responsive single-column layout under WCAG 1.4.10.
16
Vestibular Triggers and Motion
How do you handle vestibular triggers and respect user preferences for reduced motion?
Scenario: The new parallax scrolling animation goes live, and users report feeling physically dizzy when browsing the front page.
 CORE #motion Respecting `prefers-reduced-motion` protects readers from vestibular illness under WCAG 2.3.3, while providing an in-page pause button ensures baseline Level A compliance under WCAG 2.2.2.
17
Touch Targets and Spacing
What are the WCAG 2.2 requirements for touch target sizes and spacing?
Scenario: A user with a slight tremor repeatedly clicks the "Cancel" link instead of the "Save" button on their phone.
 CORE #touch_targets WCAG 2.2 Criterion 2.5.8 mandates a 24x24px minimum target or non-overlapping spacing circle at Level AA, while Criterion 2.5.5 recommends 44x44px at Level AAA.
MORE — Forms, Focus, and Basic ARIA (Q18–Q26)
# Lecture & Interview Question Topic & Tier Core Architectural Takeaway
18
Form Grouping and Error Association
How do you group related form controls and associate validation errors?
Scenario: The checkout form highlights three fields in red, but the screen reader just says "edit text" without explaining the error.
 MORE #forms Visual error outlines convey nothing to screen readers. Expose error state through `aria-invalid="true"` and connect error text through `aria-describedby`.
19
Labels Versus Placeholders
Why is a placeholder never a label, and how do you properly associate labels with inputs?
Scenario: A subscriber with memory loss clicks into the card field, the placeholder vanishes, and she no longer knows what to type.
 MORE #labels Placeholders represent transient format examples, never element identities. A form control without an associated label lacks a permanent accessible name.
20
Full Keyboard Operability
What does full keyboard operability require?
Scenario: A developer builds a custom slider that works perfectly with a mouse drag, but completely ignores the arrow keys.
 MORE #keyboard If a widget can be operated with a mouse, it must be operable with a keyboard. Arrow keys, Home, End, and Enter/Space form the core of custom widget navigation.
21
Tab Order and Focus Sequence
What determines the tab order of a page, and how do you keep it sane?
Scenario: The tab key jumps from the masthead to the footer and back into an ad, and the subscriber gives up before the email field.
 MORE #focus_order Sequential focus order must mirror visual reading flow. Ban positive `tabindex` completely and align DOM source order with CSS layout.
22
Visible Focus Indicators and Outline
Why is the visible focus indicator critical, and why should you never use `outline: none`?
Scenario: The keyboard focus lands on the submit button, but there is no visual change, leaving the user guessing where their keystrokes will go.
 MORE #focus_visible Removing focus indicators with `outline: none` blinds keyboard operators. Use `:focus-visible` to style high-contrast focus rings for keyboards while keeping mouse clicks clean.
23
Single-Page Focus Management
How and when do you programmatically move focus in a single-page application?
Scenario: A user deletes a row in their inbox, the DOM node vanishes, and the browser resets their focus to the very top of the page.
 MORE #focus_management Never allow the browser to reset focus to the document root when deleting elements. Compute the adjacent target and transfer focus programmatically before or upon removal.
24
ARIA Roles, States, and Properties
What are ARIA roles, states, and properties, and what do they actually do?
Scenario: A developer adds `aria-checked="true"` to a div and expects it to magically become toggleable with the spacebar.
 MORE #aria_basics ARIA defines how an element sounds to assistive technology, not how it works. Always pair ARIA roles and states with native keyboard listeners and focus semantics.
25
Accessible Name Computation
What is an accessible name, and what is the computation order?
Scenario: A button has text, an aria-label, and a title attribute. Which one does the screen reader actually announce?
 MORE #accessible_name ARIA labels override visible inner text in the accessible name calculation. Always ensure your accessible name matches or includes the visible text on screen.
26
Live Regions and Dynamic Announcements
How do you announce dynamic content changes to screen readers without stealing focus?
Scenario: The user clicks 'Add to cart', the cart icon updates visually, but the screen reader remains completely silent.
 MORE #live_regions Live regions must exist in the initial DOM before dynamic text is inserted. Use polite for routine status updates and reserve assertive strictly for emergencies.
ADVANCED — Patterns and Testing (Q27–Q34)
# Lecture & Interview Question Topic & Tier Core Architectural Takeaway
27
Modal Dialog Pattern and Focus Trapping
What are the required keyboard behaviors and ARIA roles for an accessible modal dialog?
Scenario: The newsletter modal pops up, but the screen reader user is still tabbing through the obscured page behind it.
 ADVANCED #dialog_pattern An accessible modal dialog must trap keyboard focus within its bounds, dismiss on the Escape key, and restore focus to the originating trigger upon closing.
28
The Accessible Tab Interface
How do you implement an accessible tab interface with correct focus management?
Scenario: A user tabs into the tablist and has to press tab 15 times to reach the panel content.
 ADVANCED #tabs_pattern The entire tablist must occupy exactly one tab stop in the sequential navigation order, delegating lateral movement between tabs to the Arrow keys.
29
Menu Pattern Versus Navigation Links
When should you use a menu pattern instead of simple navigation links?
Scenario: The developer implements a custom dropdown as a `menu`, but screen reader users get stuck because the arrows keys do nothing.
 ADVANCED #menu_pattern Never use role="menu" for website navigation links; reserve it exclusively for application command menus that trigger immediate in-page actions.
30
Custom Controls and the Combobox Pattern
How do you build a custom control when native HTML doesn't suffice?
Scenario: The design calls for a complex combobox, but the naive implementation leaves screen reader users trapped.
 ADVANCED #custom_controls Never move physical DOM focus away from the combobox text input; manage the active dropdown item virtually using aria-activedescendant.
31
How Screen Readers Parse the DOM
How do screen readers parse the DOM and build the accessibility tree?
Scenario: The developer hides an element with `opacity: 0`, but the screen reader still reads it out loud.
 ADVANCED #screen_readers Screen readers never interact with raw HTML; they query the operating system's accessibility API populated by the browser's accessibility tree.
32
The Boundaries of Automated Testing
What can automated accessibility tools catch, and why does a passing audit never prove a site is accessible?
Scenario: The dashboard shows a 100 accessibility score the same week a blind reader cancels because she cannot check out.
 ADVANCED #automated_testing Automated tools catch syntax and missing attributes, covering roughly 30% to 40% of WCAG criteria; true accessibility requires manual keyboard and screen reader verification.
33
Manual Accessibility Testing
How do you manually test a page for accessibility using only a keyboard and a screen reader?
Scenario: The automated scan is clean, but you need to prove the checkout flow is actually usable by a blind customer.
 ADVANCED #manual_testing Manual testing begins by unplugging the mouse; if a workflow cannot be completed using Tab, Arrows, and Enter, the feature is broken.
34
The Holistic Testing Strategy
How do you combine automated, manual, and user testing in a development lifecycle?
Scenario: The team performs a massive accessibility audit right before launch and discovers architectural flaws that require a full rewrite.
 ADVANCED #testing_strategy Accessibility is a continuous engineering discipline; shift it left into design systems and pull requests rather than auditing it at launch.

Part Two: Web Performance & Runtime Internals (Q35–Q54)

Critical Path, Core Web Vitals, JIT Optimization & Memory
CORE — Loading and the Network (Q35–Q43)
# Lecture & Interview Question Topic & Tier Core Architectural Takeaway
35
The Cost Model of the Web
What is web performance, and what is the cost model of the web?
Scenario: The new marketing page takes 8 seconds to load on a 3G connection, and 40% of visitors bounce before seeing the hero image.
 CORE #perf_basics Performance is user retention; round-trip latency and main thread CPU execution cost far more than raw network bandwidth.
36
The Critical Rendering Path
What is the critical rendering path from HTML to paint, and what blocks it?
Scenario: The browser receives the HTML immediately, but the screen stays white for three seconds while a massive stylesheet downloads.
 CORE #critical_rendering_path CSS is render-blocking and JavaScript is parser-blocking; optimize First Contentful Paint by inlining critical styles and deferring scripts.
37
Script Loading: Async Versus Defer
What is the difference between `async` and `defer`, and where should scripts go?
Scenario: A third-party analytics script is added to the ``, and suddenly the entire page stops rendering until it finishes loading.
 CORE #script_loading Use defer for application scripts that depend on the DOM or each other; use async only for independent third-party utilities that do not care about execution order.
38
Optimizing Images and Cumulative Layout Shift
How do you optimize images and prevent them from causing layout shifts?
Scenario: The article text jumps down exactly when the hero image finally loads, causing the user to click the wrong link.
 CORE #images_perf Always set explicit width and height attributes on images so browsers calculate aspect-ratio and reserve layout space before downloading.
39
Web Font Loading: Eliminating Invisible Text
How do you load web fonts without causing a Flash of Invisible Text (FOIT)?
Scenario: The custom brand font takes two seconds to load, leaving the headlines completely blank in the meantime.
 CORE #fonts_perf Content visibility always trumps brand typography; render text immediately using local fallbacks and preload critical fonts to minimize swap shift.
40
HTTP Caching: Headers, Revalidation, and Cache Busting
How do HTTP caching headers work, and what is cache busting?
Scenario: You deploy a critical bug fix, but users complain the site is still broken because their browsers are clinging to yesterday's JavaScript.
 CORE #caching Pair immutable one-year cache headers on content-hashed static assets with `no-cache` conditional revalidation on root HTML documents.
41
Payload Compression: Gzip Versus Brotli
What is the difference between gzip and Brotli, and what should you compress?
Scenario: The server is sending a 2MB uncompressed JSON payload on every request, choking the mobile connection.
 CORE #compression Always enable Brotli for text-based assets, keep Gzip as an HTTP fallback, and never compress pre-compressed binary media.
42
Content Delivery Networks: Latency and Edge Routing
Why do CDNs matter, and how does distance affect latency?
Scenario: Users in Australia wait four seconds for the initial HTML response because the origin server is in Virginia.
 CORE #cdn You cannot accelerate the speed of light; move computing resources and cache layers physically closer to users via edge points of presence.
43
Bundle Size: Code Splitting and Tree Shaking
How do you manage bundle size with code splitting and tree shaking?
Scenario: A user on a slow phone downloads the entire charting library just to read a text article that has no charts.
 CORE #bundles Ship only the JavaScript required for the initial route; load heavy interactive modules on demand and prune dead exports with static ESM imports.
MORE — Measurement and Optimization (Q44–Q49)
# Lecture & Interview Question Topic & Tier Core Architectural Takeaway
44
Core Web Vitals: Thresholds and the 75th Percentile
What are the Core Web Vitals, their thresholds, and why are they measured at the 75th percentile?
Scenario: The product manager asks why the dashboard shows an LCP of 4 seconds when it loads instantly on her MacBook.
 MORE #core_web_vitals Core Web Vitals assess real human perception at the 75th percentile: LCP under 2.5s, INP under 200ms, and CLS under 0.10.
45
Lab Versus Field Data: Why Scores Diverge
Why can your Lighthouse score be 100 while real users experience a failing INP?
Scenario: The build pipeline enforces a perfect Lighthouse score, but the real-user monitoring data shows massive latency in the field.
 MORE #lab_vs_field Lab data is for debugging and catching regressions before release; field data is the ultimate truth of real human user experience.
46
Lighthouse Performance Scoring: Mechanics and Weights
What exactly does a Lighthouse performance audit measure, and how is the score weighted?
Scenario: The team spends a week optimizing JavaScript execution, but the Lighthouse score barely moves because LCP dominates the weighting.
 MORE #lighthouse Three metrics govern eighty percent of your Lighthouse score: Total Blocking Time (30%), Largest Contentful Paint (25%), and Cumulative Layout Shift (25%).
47
DevTools Performance Panel: Diagnosing Slow Interactions
How do you use the Chrome DevTools Performance panel to diagnose a slow interaction?
Scenario: A button click takes 800ms to respond, and you need to prove exactly which JavaScript function is blocking the main thread.
 MORE #devtools_perf Use DevTools CPU throttling to capture real mobile interactions, follow the red warning triangles in the Main track, and rank bottlenecks using the Bottom-Up tab.
48
Resource Hints: Preload, Preconnect, and Prefetch
How do resource hints like `preload` and `preconnect` optimize the critical path?
Scenario: The browser discovers the hero image only after parsing the CSS, delaying the LCP by a full second.
 MORE #resource_hints Use `preload` for critical current-page assets hidden from the HTML scanner; use `preconnect` for important third-party origins; use `prefetch` for the next page.
49
Native Image Lazy Loading: Viewport Versus Offscreen
How does the `loading="lazy"` attribute work, and when is it a mistake to use it?
Scenario: A developer adds `loading="lazy"` to every image on the page, and the hero image suddenly loads much slower than before.
 MORE #lazy_loading Never lazy-load the above-the-fold hero image; load the LCP element eagerly with `fetchpriority="high"`, and lazy-load everything below the fold.
ADVANCED — Runtime and Engine Internals (Q50–Q54)
# Lecture & Interview Question Topic & Tier Core Architectural Takeaway
50
The Main Thread: Long Tasks and Yielding Strategies
What is the single-threaded model, what is a long task, and how do you yield?
Scenario: The main thread is blocked by a massive data parsing loop, and the entire UI freezes so the user can't even scroll.
 ADVANCED #main_thread Any main thread task taking longer than 50ms is a Long Task; break heavy loops into smaller sub-tasks and yield using `scheduler.yield()`.
51
The Browser Event Loop: Tasks, Microtasks, and Starvation
How does the browser event loop prioritize microtasks over macrotasks?
Scenario: A developer queues a thousand promises, starving the event loop and preventing the browser from rendering the next frame.
 ADVANCED #event_loop Microtasks always drain to total exhaustion before the browser can render or process user input; recursive promises create a synchronous freeze disguised as asynchronous code.
52
Rendering Performance: Layout Thrashing and Composite Layers
What causes layout thrashing, and how does it differ from a repaint or a composite?
Scenario: An animation runs at 15 frames per second because every frame triggers a full document layout recalculation.
 ADVANCED #rendering_perf Querying geometry properties like `offsetWidth` or `getBoundingClientRect()` after modifying the DOM forces an immediate synchronous reflow; always batch all reads before any writes.
53
V8 Engine Internals: Hidden Classes and Inline Caches
How does V8 execute JavaScript, and what makes code optimized or deoptimized?
Scenario: Two implementations of the same sorting algorithm have a 10x performance difference purely because of how the objects are shaped.
 ADVANCED #js_engine V8 relies on consistent object shapes to optimize property lookups; always initialize all object properties in the exact same order inside constructor functions.
54
JavaScript Memory Management: Garbage Collection and Leaks
What causes memory leaks in JavaScript, and how does garbage collection pressure affect performance?
Scenario: The single-page application gets progressively slower over an hour until the browser tab crashes with an out-of-memory error.
 ADVANCED #memory Memory leaks occur when unreachable DOM or data objects remain anchored to GC roots via closures, timers, or global listeners; always tear down event bindings and clear references.
