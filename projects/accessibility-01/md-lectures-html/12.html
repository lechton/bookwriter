Lecture 12: The Chart Behind the Glass

Interview Question

CORE

How do you make complex images and SVG icons accessible?

Imagine this scenario:

  1. David opens the National Times investigative special on the city's four-billion-dollar annual municipal budget.
  2. Sighted subscribers instantly examine a colorful interactive vector chart comparing housing, transit, and emergency allocations.
  3. David's screen reader moves to the visualization container and announces a single word: "Graphic".
  4. Which city agency gained funding and which community program was cut?
  5. David cannot inspect a single dollar figure, percentage shift, or historical trend.
  6. The graphics desk spent three weeks designing the chart, yet it locks non-visual readers behind opaque digital glass.
  7. Today you learn to wire vector diagrams and SVG icons with explicit roles, internal titles, and companion data tables.

Vector Visualizations: Unlabelled Path Cluster Versus Accessible Graphic

David inspects the National Times municipal budget report using speech software. When developers output raw vector paths without semantic roles or programmatic names, browsers fail to expose them as coherent graphic objects. Adding an image role and programmatic label gives assistive tools an immediate accessible name:

The contrast reveals why inline vector elements require deliberate semantic scaffolding. Unlike raster images like PNG or JPEG where the browser automatically instantiates an image element, inline SVG creates a tree of XML geometry nodes inside the Document Object Model. Without an explicit image role, user agents struggle to map the shape cluster to an accessible object. Assigning role="img" unifies the internal vector nodes into a single atomic graphic, while aria-labelledby binds the container directly to internal title and description metadata.

Vector Icons: Auditory Clutter Versus Hidden Presentation

Modern editorial interfaces embed dozens of inline vector icons beside article utilities, social sharing tools, and bookmark triggers. When engineers include raw SVG tags alongside visible text, screen readers announce each vector shape as an isolated graphic, producing repetitive auditory noise. Adding aria-hidden="true" and focusable="false" suppresses presentational shapes so assistive listeners hear only the clean button text:

When an icon button carries no visible text, such as a standalone search glass or close cross, the engineering pattern flips. The parent interactive button must receive an explicit programmatic label via aria-label, while the internal vector icon remains hidden with aria-hidden="true". This ensures the operating system accessibility API exposes an actionable name ("Search archive articles, button") without stuttering over the child SVG.

The Two-Part Alternative Architecture for Complex Visualizations

A multi-dimensional graphic like our four-billion-dollar municipal budget chart cannot be reduced to a single short sentence. Sighted analysts do not simply observe the visual geometry; they compare agency funding levels, verify percentages, and inspect spending deltas. The official W3C Web Accessibility Initiative Complex Images Tutorial defines the required architecture:

Complex images contain substantial information – more than can be conveyed in a short phrase or sentence. These are typically graphs and charts, diagrams and illustrations where the page text relies on the user being able to understand the image, and maps showing locations or weather systems. In these cases, a two-part text alternative is required. The first part is the short description to identify the image and indicate the location of the long description. The second part is the long description – a textual representation of the essential information conveyed by the image.

W3C, Complex Images Tutorial, resources/accessibility/wai/pages/design-develop/tutorials/images/complex.md

Interview Tip

To impress the interviewer: never claim that an aria-label on an SVG chart solves accessibility. Articulate the W3C Two-Part Text Alternative framework: Part 1 provides a high-level summary of the visual trend using role="img", internal title and desc tags, and aria-labelledby; Part 2 provides the underlying raw data in a semantic companion HTML table. For icons, explain the strict boundary: decorative icons use aria-hidden="true" focusable="false", while standalone icon buttons place aria-label on the parent button.

Where you will meet this

  • Municipal election maps: summarizing district victor margins in SVG descriptions while offering searchable voting tally tables below.
  • Financial portfolio analytics: rendering asset allocation donut charts alongside tables listing exact equity values and yields.
  • Meteorological radar charts: announcing regional precipitation bands in an SVG title while providing hourly temperature and wind speed tables.
  • Design system icon components: enforcing aria-hidden across all decorative glyphs while pairing standalone buttons with explicit accessible names.
  • Public health dashboards: presenting vaccination trendline SVGs alongside historical epidemiological data grids.

Glossary

  • Scalable Vector Graphics (SVG): An XML-based markup format for rendering two-dimensional vector illustrations, charts, and interface icons directly in the DOM.
  • Two-Part Text Alternative: The accessibility architecture for complex graphics requiring a concise high-level summary paired with structured tabular data.
  • role="img" on SVG: An explicit ARIA role that unifies an SVG container into a single accessible image node, preventing screen readers from traversing internal paths.
  • SVG Title and Desc: Native XML child elements inside an SVG providing accessible names and longform descriptive text to assistive software.
  • aria-labelledby on SVG: An attribute linking the outer SVG element to its internal title and desc IDs to guarantee reliable speech announcement across browsers.
  • Data Table Fallback: A semantic HTML table paired with a complex graphic, providing a structured, queryable equivalent of the visualized metrics.

Summary

Accessible Vectors and Complex Visualizations

In modern frontend architecture, vector graphics and data visualizations are first-class editorial assets that require deliberate non-visual scaffolding. Treating an inline SVG as an unlabelled blob of shapes creates an impassable barrier for assistive technologies. Simple icons must be cleanly separated into decorative and functional patterns, while data-heavy charts demand a dual-layer strategy combining high-level narrative summaries with granular tabular fallbacks. Here is your streetwise review.

❒ The Two Vector Strategies

  1. Icons require binary accessibility classification.
        (a) If an icon is accompanied by visible text, hide it completely with aria-hidden="true" and focusable="false".
        (b) If an icon acts alone as a button, place the accessible label on the parent <button> element.
  2. Complex charts demand the two-part alternative framework.
        (a) Set role="img" on the outer <svg> and bind internal <title> and <desc> elements via aria-labelledby.
        (b) Provide a companion HTML table so non-visual readers can query granular numbers and calculations.

❒ The Developer's Levers

  1. Never leave an inline SVG chart without an explicit image role and title binding.

DO NOT DO THIS: Output bare vector paths that screen readers announce as silent or disconnected shapes.

index.html
1<svg viewBox="0 0 500 300">
2 <path d="M10 80 Q 95 10 180 80" stroke="black" />
3</svg>

    DO THIS: Declare role="img" and link accessible title and desc child elements.

index.html
1<svg role="img" aria-labelledby="t d" viewBox="0 0 500 300">
2 <title id="t">Revenue Growth</title>
3 <desc id="d">Quarterly revenue increased 14 percent.</desc>
4 <path d="M10 80 Q 95 10 180 80" stroke="black" />
5</svg>
  1. Never substitute a brief sentence for an entire data visualization.

DO NOT DO THIS: Force non-visual users to rely on a single sentence for a sixty-point data chart.

index.html
1<p>Here is our complete multi-year budget breakdown across all agencies.</p>

    DO THIS: Pair the graphic with an accessible companion data table.

index.html
1<details>
2 <summary>View Budget Table</summary>
3 <table><caption>Annual Allocations</caption></table>
4</details>

➔ NEVER rely on aria-label alone as the sole accessibility solution for a complex multi-metric chart.

➔ ALWAYS apply aria-hidden="true" on decorative icons adjacent to visible text.

➔ IF an image conveys tabular data THEN provide a real semantic HTML table alongside the visual representation.
