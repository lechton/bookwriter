### Image Alternatives: Raw File Path Versus Factual Alt Text

Marcus opens the National Times flood dispatch using speech software. When an engineer leaves the alt attribute off an image, assistive software falls back to reading the raw file path, speaking cryptic numbers that leave Marcus unaware whether the highway is submerged. Supplying an explicit alt attribute provides a factual alternative that communicates the scene directly to assistive listeners:

```html title="image-alt-comparison.html"
<img src="/img/flood.jpg" /> <!-- **WRONG:** missing alt forces raw filename **FALLBACK** -->

<img src="/img/flood.jpg" alt="Floodwaters submerge bridge" /> <!-- **RIGHT:** descriptive alt conveys factual **MESSAGE** -->
```

```canvas title="Flood Photo: Missing Alt vs Descriptive Text Alternative" width="2/3" layout="compare"
image | /img/flood.jpg | wrong="missing alt" | alt=missing | sr="flood dot jpg, graphic" | note="✕ Raw filename spoken · No accessible name"
image | /img/flood.jpg | right="descriptive alt" | alt="Floodwaters submerge bridge" | sr="Floodwaters submerge bridge, graphic" | note="✓ Factual description spoken to reader"
```

The contrast illustrates the stark divide between an unlabelled image node and a descriptive accessible name. When the alt attribute is missing entirely, user agents inspect the accessibility tree, locate an image without a programmatic label, and fall back to synthesizing the raw image URL. Marcus hears an exhausting stream of slashes and file extensions that conveys zero editorial context. With descriptive alternative text in place, the browser exposes the text directly to assistive technology, announcing the exact conditions of the submerged bridge in under three seconds.

### The Three Personalities of Alt Text

Authoring high-quality text alternatives requires identifying the functional purpose of the graphic in the editorial narrative. The official W3C Web Accessibility Initiative Images Tutorial establishes three functional categories:

> Images must have text alternatives that describe the information or function represented by them. This ensures that images can be used by people with various disabilities. This tutorial demonstrates how to provide appropriate text alternatives based on the purpose of the image:
> - Informative images: Images that graphically represent concepts and information, typically pictures, photos, and illustrations. The text alternative should be at least a short description conveying the essential information presented by the image.
> - Decorative images: Provide a null text alternative (alt="") when the only purpose of an image is to add visual decoration to the page, rather than to convey information that is important to understanding the page.
> - Functional images: The text alternative of an image used as a link or as a button should describe the functionality of the link or button rather than the visual image.
*W3C, Images Tutorial, resources/accessibility/wai/pages/design-develop/tutorials/images/index.md*

Each category demands a distinct engineering mindset:

```html title="image-categories.html"
<img src="/photos/flooded-bridge.jpg"
     alt="Muddy floodwaters reaching the steel trusses of Route 9 bridge, completely submerging the roadway" /> <!-- **RIGHT:** informative alt describes factual **MESSAGE** -->

<img src="/icons/flourish-divider.svg"
     alt="" /> <!-- **RIGHT:** empty alt hides decorative flourish from **SCREEN READERS** -->

<a href="/alerts/rss">
  <img src="/icons/rss-feed.svg"
       alt="Subscribe to breaking emergency RSS feed" /> <!-- **RIGHT:** functional alt communicates destination of **LINK** -->
</a>
```

If an image is informative, describe the scene's key facts rather than its artistic composition. Marcus does not need to know that the photograph was shot on a 35mm lens with shallow depth of field; he needs to know that floodwaters have submerged the roadway. If an image is functional, describe what activating the control accomplishes. An envelope icon acting as a contact link requires `alt="Email the Newsroom"`, never `alt="White envelope with red wax seal"`.

### Decorative Flourishes: Auditory Noise Versus Null Alt Silence

Frontend developers often assume every image element in the DOM must contain spoken descriptions. When designers include decorative section dividers, background geometric shapes, or visual ornaments, adding descriptive alt text causes speech synthesizers to broadcast continuous auditory clutter. Assigning a null alt attribute instructs the browser engine to remove the decorative graphic from the accessibility tree entirely:

```html title="decorative-flourish.html"
<img src="/icons/divider-leaf.svg" alt="Small decorative leaf flourish" /> <!-- **WRONG:** announces decorative ornament as auditory **NOISE** -->

<img src="/icons/divider-leaf.svg" alt="" /> <!-- **RIGHT:** null alt removes graphic from **ACCESSIBILITY TREE** -->
```

```canvas title="Editorial Divider: Spoken Flourish vs Null Alt Silence" width="2/3" layout="compare"
image | /icons/divider-leaf.svg | wrong="decorative noise" | sr="Small decorative leaf flourish, graphic" | note="✕ Auditory spam · Distracts from editorial text"
image | /icons/divider-leaf.svg | right="null alt" | alt="" | note="✓ Stripped from accessibility tree · Completely silent"
```

The difference between missing alt and null alt represents one of the most critical concepts in web accessibility. W3C Technique H67 codifies this exact behavioral distinction:

> If no title attribute is used, and the alt text is set to null (i.e., alt="") it indicates to assistive technology that the image can be safely ignored. Having a "null" alt attribute is not the same as having no alt attribute.
*W3C, Techniques for WCAG 2.2: H67 Using null alt text and no title attribute on img elements for images that assistive technology should ignore*

An empty string `alt=""` actively declares to the browser that the element serves a purely presentational role. The accessibility tree prunes the node, allowing screen reader focus to glide smoothly from one paragraph to the next without verbal interruption. Conversely, omitting the attribute leaves the accessibility tree in an unlabelled state, triggering the noisy filename fallback.

### Three Antipatterns That Corrupt Image Descriptions

Even when teams enforce alt attributes across all templates, three subtle antipatterns degrade non-visual usability:

1. The Redundant Role Antipattern. Authors frequently write `alt="Photo of flooded bridge"` or `alt="Graphic showing stock chart"`. Because screen readers automatically announce the native role ("graphic" or "image") before reading the accessible name, writing "Photo of" forces synthesizers to stutter: "Graphic, Photo of flooded bridge". Always begin the description directly with the subject: `alt="Flooded bridge over cresting river"`.

2. The Redundant Caption Antipattern. When an editorial image includes a visible `<figcaption>` beneath it reading "Route 9 bridge closed at dawn due to high water," copying that identical phrase into the alt attribute causes screen readers to speak the exact same sentence twice in succession. Either describe complementary visual details in the alt attribute or set `alt=""` if the visible caption conveys the complete equivalent.

3. The Keyword Stuffing Antipattern. Packing marketing terms into the alt attribute (`alt="breaking news valley flood disaster local weather update live"`) destroys readability for assistive technology users. Modern search engines penalize keyword stuffing, while accessibility linters flag repetitive attribute stuffing as low-quality markup.

> [!TIP]
> **To impress the interviewer:** define image accessibility using the three functional categories in the W3C Images Tutorial: informative (explain factual context), functional (state control action or destination), and decorative (supply empty alt="" to hide presentational fluff). Quote Technique H67: having a null alt attribute is not the same as having no alt attribute. Emphasize that omitting alt triggers raw filename speech fallbacks like "DSC_9042.jpg", while prefixing descriptions with "Image of" introduces redundant role announcements.

### Where you will meet this

- Breaking news dispatches: writing concise damage summaries for storm and flood photography rather than exposing camera upload filenames.
- Social media publishing tools: enforcing mandatory alt text input prompts before reporters can post embedded field photography.
- Editorial data graphics: supplying executive summaries for charts while providing structured tables for detailed inspection.
- Navigation icon buttons: declaring action-oriented alt text like "Search archives" on magnifying glass icons rather than describing the glass lens.
- Author bylines: assigning `alt=""` to circular avatar images when the journalist's name is already rendered in adjacent text.

### Glossary

- **Alternative Text (alt)**: An HTML attribute on image elements providing a text equivalent of non-text content for assistive software and search engines.
- **Null Alt (alt="")**: An empty alt attribute indicating to browsers that an image is decorative and should be pruned from the accessibility tree.
- **Informative Image**: An image that communicates factual concepts or narrative context, requiring a concise descriptive alternative.
- **Functional Image**: An image acting as an interactive control, such as an icon button, where alt text must state the action rather than visual styling.
- **File Name Fallback**: The screen reader fallback mechanism where missing alt attributes trigger speech synthesis of raw image file paths.
- **Redundant Role Prefix**: The authoring mistake of including phrases like "image of" or "picture of" in alt text, causing speech synthesizers to duplicate role announcements.

### Summary

**Alternative Text as Contextual Communication**

In modern frontend architecture, alternative text is the foundational bridge between graphic media and non-visual comprehension. Sighted users digest photography, charts, and icons instantaneously, but assistive software requires explicit programmatic names to give visual media an audible voice. Omitting attributes introduces noisy file paths, while describing presentational dividers creates verbal fatigue. Here is your streetwise review.

❒ The Three Image Archetypes

1. Informative images require essential factual context.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Describe the editorial message conveyed by the image rather than trivial artistic composition.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Complement the surrounding text and caption rather than duplicating identical sentences.
2. Functional images require action descriptions.<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) When an image sits inside a link or button, describe what activating the control does.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Write `alt="Print article"` on a printer icon, not `alt="Gray desktop printer"`.
3. Decorative images demand null alt attributes (`alt=""`).<br>&nbsp;&nbsp;&nbsp;&nbsp;(a) Set `alt=""` on background flourishes, spacer rules, and icons duplicated by adjacent text.<br>&nbsp;&nbsp;&nbsp;&nbsp;(b) Never omit the alt attribute entirely; missing alt forces user agents to speak raw filenames.

❒ The Developer's Levers

1. Never ship an image without an explicit `alt` attribute.

**DO NOT DO THIS:** Omit the alt attribute and force screen readers to speak raw file paths.
```html wrong
<img src="/photos/flood-bridge.jpg">
```
&nbsp;&nbsp;&nbsp;&nbsp;**DO THIS:** Provide concise descriptive alt text that explains the scene.
```html right
<img src="/photos/flood-bridge.jpg" alt="Floodwaters submerging the Route 9 highway bridge">
```
2. Never announce decorative elements to assistive technology.

**DO NOT DO THIS:** Describe presentational divider icons that carry no informational value.
```html wrong
<img src="/icons/divider-leaf.svg" alt="Small decorative leaf divider">
```
&nbsp;&nbsp;&nbsp;&nbsp;**DO THIS:** Hide purely decorative elements using null alt.
```html right
<img src="/icons/divider-leaf.svg" alt="">
```

➔ NEVER include the phrases "image of" or "photo of" in your alt text.

➔ ALWAYS supply `alt=""` on decorative images to remove them cleanly from the accessibility tree.

➔ IF an image is an interactive control THEN write the action it performs rather than what it looks like.
