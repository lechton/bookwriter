# Lecture 39: Reusing Logic Between Components with Custom Hooks

*(How can two components use the same state and Effect without copying the code?)*

> INTERVIEW QUESTION | ❱ CORE | How do you extract and reuse stateful logic between components?

---

## VS | Copied Code vs. a Custom Hook `useOnlineStatus`: the Hook keeps one copy of the code, and each component still gets its own value

**A custom Hook lets two components reuse the same stateful logic without copying code, while giving each component its own independent state.**

Say your page has a top bar that shows a green dot when the internet works, and a Save button that disables itself when the internet drops. Both parts of the page need to watch the internet connection in the exact same way.

**Why:** Copying the `useState` and `useEffect` lines into both components duplicates your logic in two places. Moving those lines into a custom Hook like `useOnlineStatus` keeps the logic in one function, while each component still gets its own independent state.

Let's start from plain JavaScript. Two places in your code need the same lines. What do you do? You move the lines into a function, and you call that function from both places.

```js title="The same lines, moved into one function, in plain JavaScript"
function formatPrice(amount) {
  return '$' + amount.toFixed(2);
}

~formatPrice(9)~; // '$9.00', from the one copy of the code
~formatPrice(25)~; // '$25.00', from the same copy
```

A custom Hook is exactly that: a function. There is only one difference. Inside it, you call React's Hooks, such as `useState` and `useEffect`. That is why its name starts with `use`.

> [!DEFINITION]
> **What is a custom Hook?** [REVIEW] A custom Hook is a plain JavaScript function that our code writes, not React. React gives us the built-in Hooks, such as `useState` and `useEffect`, and we build new Hooks out of them.
> Two things make a function a Hook: its name starts with `use` and a capital letter, such as `useOnlineStatus`, and it calls other Hooks inside.
> A function that calls no Hooks at all stays a regular function, without the `use` at the start, such as `getSorted` (Lesson 38).

Now the part that surprises everyone. In plain JavaScript, every call of a function gets its own local variables. You already know this:

```js title="Two calls of one function, two separate arrays, in plain JavaScript"
function createCart() {
  const items = [];
  return items;
}

const cartA = ~createCart()~; // A new array
const cartB = ~createCart()~; // Another new array
cartA.push('Socks');
console.log(cartB); // [], because cartB is a different array
```

One function, two calls, two arrays. Nobody expects `cartB` to contain socks.

Hooks work the same way. Say two components both call one custom Hook. Each call runs `useState` and `useEffect` again, for that component. So each component gets its own value. That is what the sentence means: **a custom Hook shares the code, not the value.**

And when two components need one value, the same for both? Then a custom Hook is the wrong tool. The value goes up into their parent, which passes it down as props (Lesson 24).

### The Rule of Thumb: the same code, or the same value?

**Ask one question: do the two components need the same code, or the same value? The same code goes in a custom Hook. The same value goes in their parent.**

A senior developer also knows the three classic mistakes:
1. **Copying the code into a second component.** Later, a fix goes into one copy only, and the two components disagree on the same screen.
2. **Believing that two calls of one Hook share one value.** A click in one component then never reaches the other component.
3. **Wrapping every small piece of code in a Hook.** A Hook around a single `useState` saves nothing. A Hook named after timing, such as `useMount`, hides what it does.

The rest of the lesson shows each mistake on a small notes app.

## SECTION | A Notes App That Follows the Network

Our page is a notes app that saves your work to a server. It has a heading and one button.

```page width=text caption="The notes app while the network is on: the heading says Online, and the button takes clicks."
heading: Online
form:
  button: Save progress
```

Now the Wi-Fi drops. Two things change at the same moment:
1. The heading says `Disconnected`.
2. The button turns grey, says `Reconnecting...`, and ignores clicks.

```page width=text caption="The same notes app right after the Wi-Fi drops: the heading says Disconnected, and the grey button takes no clicks."
heading: Disconnected
form:
  button: Reconnecting... | | disabled
```

When the Wi-Fi comes back, the heading says `Online` again, and the button says `Save progress` again.

How does the page know about the network? The browser tells it. In plain JavaScript, you would write this:

```js title="What the browser tells us about the network, in plain JavaScript"
window.addEventListener(~'offline'~, () => console.log('Network off')); // The browser calls this when the network goes off
window.addEventListener(~'online'~, () => console.log('Network on')); // The browser calls this when the network comes back
console.log(~navigator.onLine~); // true or false, right now
```

So the browser gives us two events on the window: `offline` and `online`. It also gives us `navigator.onLine`, which is true or false at this very moment.

In React, listening to the browser is the job of an Effect.

> [!DEFINITION]
> **What is an Effect?** [REVIEW] An Effect is code that React runs after it puts the component on the screen. You write it with `useEffect`.
> It is the place to connect to something outside React. Here, the Effect calls `addEventListener` to listen to the browser's `online` and `offline` events.
> The function the Effect returns is the cleanup. React calls it when the component leaves the screen, and it calls `removeEventListener`, so no listener is left behind.
> In development, Strict Mode runs one extra setup and cleanup for every Effect, to show you a missing cleanup (Lesson 32).

The heading and the button are two different components, and they look nothing alike. But both need the same knowledge: is the network on right now? And both need the same code to keep it up to date: one state variable and one Effect.

Here are the files of the finished app:

```files title="notes-app: File Explorer" caption="The files of the finished notes app inside src/: two components, the App that renders them, and the custom Hook they both call."
index.html | entry | The HTML page with the empty root div where React mounts
src/
  main.jsx | boundary | Imports `App` from `./App.jsx` and mounts it inside `<StrictMode>`
  App.jsx | parent | Exports `App` as default and renders `<StatusBar />` and `<SaveButton />`
  StatusBar.jsx | component | Exports `StatusBar` as default and renders the `Online` or `Disconnected` heading
  SaveButton.jsx | component | Exports `SaveButton` as default and renders the `Save progress` button
  useOnlineStatus.js | custom Hook | Exports `useOnlineStatus` by name and returns `isOnline`
```

The Hook's file ends in `.js`, not `.jsx`. It returns a value, not JSX.

**PRINCIPLES:** A custom Hook shares the code, not the value. Three principles follow:
1. **Principle 1: Extract the Copied State and Effect into a Custom Hook.** The network code lives once, in `useOnlineStatus`, so one fix reaches both components.
2. **Principle 2: Each Call Gets Its Own State and Its Own Effect.** The heading and the button hold two separate `isOnline` values. The browser keeps them in step.
3. **Principle 3: Share One Changing Value Through the Parent.** The saved status lives in `App`, because a custom Hook would give each component its own copy.

## PRINCIPLE | `useOnlineStatus`: the network code lives once, so one fix reaches both components

> [!PRINCIPLE]
> **Principle 1: Extracting a Custom Hook: Move the Copied State and Effect into One use Function**
>
> *When two components copy the same state variable and Effect, move that code into one function named use plus a capital letter, return the value the components need, and call that function from each component.*
>
> Copied code drifts apart: a fix goes into one copy, and the other component keeps showing an old answer. A custom Hook holds the code once. Its code runs as part of each component that calls it, so the page works exactly as before. The last line of the Hook hands the value back. Without it, every component receives undefined.
>
> **DO THIS:**
> ```jsx
> function StatusBar() {
>   const isOnline = ~useOnlineStatus()~; // The network code lives once, in useOnlineStatus.js
>   return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
> }
> function SaveButton() {
>   const isOnline = ~useOnlineStatus()~; // The same Hook, so a fix inside it reaches both components
>   return <button disabled={!isOnline}>Save progress</button>;
> }
> ```
>
> **DO NOT DO THIS:**
> ```jsx
> function StatusBar() {
>   const [isOnline, setIsOnline] = ~useState(navigator.onLine)~; // **WRONG:** a copy of the network state, fixed in this copy only
>   return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
> }
> function SaveButton() {
>   const [isOnline, setIsOnline] = ~useState(true)~; // **WRONG:** the second copy still assumes the network is on
>   return <button disabled={!isOnline}>Save progress</button>;
> }
> ```

Imagine for a moment that React had a built-in `useOnlineStatus` Hook. Then each component would need one line:

```jsx title="StatusBar and SaveButton, if React had a useOnlineStatus Hook"
function StatusBar() {
  const isOnline = ~useOnlineStatus()~; // true while the network is on, false while it is off
  return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
}

function SaveButton() {
  const isOnline = ~useOnlineStatus()~; // The same question, asked by a second component
  return <button disabled={!isOnline}>{isOnline ? 'Save progress' : 'Reconnecting...'}</button>;
}
```

React has no such Hook. But a Hook is just a function, so we can write it ourselves. First, let's look at what we have before it exists.

### The two copies we start with

Here is the heading, with its own state variable and its own Effect:

```jsx title="src/StatusBar.jsx"
import { useState, useEffect } from 'react';

export default function StatusBar() {
  const [isOnline, setIsOnline] = ~useState(true)~; // Assumes the network is on when the page opens
  useEffect(() => {
    function handleOnline() {
      setIsOnline(true);
    }
    function handleOffline() {
      setIsOnline(false);
    }
    window.addEventListener(~'online'~, handleOnline); // The browser calls handleOnline when the network comes back
    window.addEventListener(~'offline'~, handleOffline); // The browser calls handleOffline when the network goes off
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);

  return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
}
```

The button needs the same knowledge. So a developer copies the same lines into it:

```jsx title="src/SaveButton.jsx"
import { useState, useEffect } from 'react';

export default function SaveButton() {
  const [isOnline, setIsOnline] = ~useState(true)~; // The same line, copied from StatusBar
  useEffect(() => {
    function handleOnline() {
      setIsOnline(true);
    }
    function handleOffline() {
      setIsOnline(false);
    }
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);

  function handleSaveClick() {
    console.log('Progress saved');
  }

    <button disabled={!isOnline} onClick={handleSaveClick}>
      {isOnline ? 'Save progress' : 'Reconnecting...'}
    </button>
```

Both components work. But every line from `useState` to the end of the Effect now lives twice, in two files.

### A fix in one copy splits the page

Both copies start with `useState(true)`. So both assume the network is on when the page opens. That is wrong for a user who opens the app while already offline.

The fix is easy: ask the browser. `navigator.onLine` is `false` for an offline user. A developer makes the fix in the heading's file and forgets the button's file:

```jsx title="The starting value in each copy, after the fix went into StatusBar only"
const [isOnline, setIsOnline] = useState(~navigator.onLine~); // StatusBar.jsx: asks the browser, so false for an offline user
const [isOnline, setIsOnline] = useState(~true~); // SaveButton.jsx: still assumes the network is on
```

A user opens the app while offline:

```page width=text caption="A user opens the app while offline, after the fix went into the heading only: the heading says Disconnected, and the button still offers to save."
heading: Disconnected
form:
  button: Save progress | | bad
console: quiet
```

**The page gives two answers to one question, and the Console shows no error.** The heading says `Disconnected`. Right below it, the button still says `Save progress` and takes clicks.

This is the real cost of copied code. It works today. It breaks on the first fix that reaches only one copy.

### Moving the copies into useOnlineStatus

The fix is to extract a custom Hook. To extract means to move the repeated code out of the components and into one function. It takes three steps:
1. Create the file `useOnlineStatus.js`, and declare a function named `useOnlineStatus` in it.
2. Move the state variable and the Effect into that function, with the fixed starting value, `navigator.onLine`.
3. End the function with `return isOnline;`, so each component can read the value.

```js title="src/useOnlineStatus.js"
import { useState, useEffect } from 'react';

export function ~useOnlineStatus~() { // Our own function: use plus a capital letter, and it calls Hooks
  const [isOnline, setIsOnline] = useState(~navigator.onLine~); // The fix, written once for both components
  useEffect(() => {
    function handleOnline() {
      setIsOnline(true);
    }
    function handleOffline() {
      setIsOnline(false);
    }
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);
  ~return isOnline;~ // Hands the value back to whichever component called the Hook
}
```

The last line decides what the components receive. A custom Hook can return any value: a boolean, a pair like the one `useState` returns, or an object. Our components need one thing, so the Hook returns `isOnline`.

Now each component shrinks to the part that is really its own:

```jsx title="src/StatusBar.jsx"
import { ~useOnlineStatus~ } from './useOnlineStatus.js'; // A named export, so the name goes inside curly braces

export default function StatusBar() {
  const isOnline = ~useOnlineStatus()~; // Holds whatever useOnlineStatus returned: true or false
  return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
}
```

```jsx title="src/SaveButton.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';

export default function SaveButton() {
  const isOnline = ~useOnlineStatus()~; // The same call, in a second component
  function handleSaveClick() {
    console.log('Progress saved');
  }

  return (
    <button disabled={!isOnline} onClick={handleSaveClick}>
      {isOnline ? 'Save progress' : 'Reconnecting...'}
    </button>
  );
}
```

Two small details:
- **The name `isOnline` in each component** is just a new constant of that component. It matches the name inside the Hook only because we chose it. One component could call it `online`.
- **`useState` and `useEffect` left the imports** of both component files. Only the Hook's file imports them now, because only the Hook calls them.

### The page works exactly as before

The heading with the network lines written inside it, and the heading with one call to `useOnlineStatus`: **yes, it is the exact same thing!**

Why? Because a custom Hook is a function, and a function runs where you call it. Here is what happens when React renders the heading:
1. React calls `StatusBar`.
2. `StatusBar` calls `useOnlineStatus`.
3. The Hook calls `useState` and `useEffect`.

Those are the same calls, in the same order, during the same render of `StatusBar`. For React, nothing changed. The user sees no change either.

What changes is how the components read. `StatusBar` now says *what* it wants: the online status. The Hook holds *how* to get it: the browser's events and the listeners. React's docs put it this way: the code of your components expresses your intent, not the implementation.

```tree dir=right caption="The same page before and after extracting useOnlineStatus: the lines move into one function, and every component calls it."
Moving the network code out of both components
- !Before: copied into each component [`useState` `useEffect` in StatusBar.jsx and SaveButton.jsx] | The same lines live in **two files** | A fix in one file **splits the page in two**
- +After: extracted into one custom Hook [`useOnlineStatus`] | The lines live **once**, in `useOnlineStatus.js` | Each component **calls the Hook** and reads `isOnline`; the page works **exactly as before**
```

### Forgetting return isOnline

The last line of the Hook is easy to forget, because nothing inside the Hook needs it. Compare the two endings:

```js title="src/useOnlineStatus.js, ending with return isOnline" startLine="18"
  }, []);
  ~return isOnline;~ // StatusBar receives true while the network is on
}
```

```js title="src/useOnlineStatus.js, ending without return" startLine="18"

}
```

Remember plain JavaScript: a function without `return` gives back `undefined`. So both components receive `undefined`, and both act as if the network were off, even while it is on:
- The heading treats `undefined` as false, so it says `Disconnected`.
- The button's `disabled` gets the opposite of `undefined`, which is true. So the button stays grey and says `Reconnecting...`.

```page width=text caption="The notes app while the network is on, when useOnlineStatus has no return line: both components behave as if the network were off."

form:
  button: Reconnecting... | | disabled
console: quiet
```

The Hook still listens to the network, and its state still changes. But no component ever sees that state, because the Hook never hands it back. The Console stays quiet.

Remember: one copy of the code, in one function, and that function ends with `return`.

## PRINCIPLE | `useOnlineStatus` in two components: each one gets its own `isOnline` and its own Effect

> [!PRINCIPLE]
> **Principle 2: Independent Calls: Each Call to a Custom Hook Gets Its Own State and Its Own Effect**
>
> *Every call to a custom Hook runs the Hooks inside it again, so two components that call useOnlineStatus hold two separate isOnline values and run two separate Effects.*
>
> A custom Hook shares the code that makes state, not the state itself. When two components call the same Hook, each one gets its own state variable, its own setter, and its own Effect. The heading and the button change at the same moment only because both listen to the same browser events. The Console shows the Effect's setup once for each component.
>
> **DO THIS:**
> ```jsx
> function StatusBar() {
>   const isOnline = ~useOnlineStatus()~; // StatusBar's own isOnline, kept up to date by the browser's events
>   return <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>;
> }
> ```
>
> **DO NOT DO THIS:**
> ```jsx
> function SaveButton() {
>   const isOnline = ~useOnlineStatus()~; // **WRONG:** read as the isOnline of StatusBar; it is a second state, with its own Effect
>   return <button disabled={!isOnline}>Save progress</button>;
> }
> ```

When the Wi-Fi drops, the heading and the button change in the same instant. So it looks as if both read one shared `isOnline`. **It may look the same, but it is NOT the same thing!**

Remember `createCart` from the start of the lesson. Two calls, two arrays. Here it is two calls, two states:

```jsx title="What the two calls to useOnlineStatus really run"
function StatusBar() {
  const isOnline = ~useOnlineStatus()~; // Runs useState and useEffect for StatusBar
}

function SaveButton() {
  const isOnline = ~useOnlineStatus()~; // Runs useState and useEffect again, this time for SaveButton
}
```

Compare the two components that call the Hook with the two components that hold the copied lines from Principle 1. **Yes, it is the exact same thing!** Both versions run two state variables and two Effects. The Hook removed the copied text from our files. It did not remove the second state variable or the second Effect.

> [!DEFINITION]
> **What is stateful logic?** [NEW] Stateful logic is the code that creates and updates state. In our app, it is the `useState` call and the Effect inside `useOnlineStatus`.
> The state itself is something else: the stored value. In our app, it is the `isOnline` of each component.
> A custom Hook shares the stateful logic. It does not share the state itself.
> React's docs say it in one line: custom Hooks let you share stateful logic but not state itself. Each call to a Hook is completely independent from every other call to the same Hook (Lesson 39).

### When the network goes off

**One browser event reaches two separate Effects, so both components update at once.** Here is what happens when the Wi-Fi drops:
1. The browser fires one `offline` event on `window`.
2. Two listeners wait for that event, one from each Effect. So the browser calls two `handleOffline` functions.
3. The heading's `handleOffline` calls the heading's setter. The button's `handleOffline` calls the button's setter.
4. React renders both components again. The heading says `Disconnected`, and the button says `Reconnecting...`.

No line of the button's file mentions `setIsOnline`. The button's setter comes from the `useState` call inside the Hook, which runs while React renders `SaveButton`. The button's listeners come from the same place.

## PRINCIPLE | `isSaved` in `App`: two components read one value, passed down as props

> [!PRINCIPLE]
> **Principle 3: Sharing the Value Itself: Lift the State into the Parent, Not into a Custom Hook**
>
> *When two components must show one value that changes, such as whether the work was saved, put that state in their closest common parent and pass it down as props.*
>
> A custom Hook gives every component that calls it a separate copy of its state. That is right for isOnline, because the browser keeps every copy in step. It is wrong for isSaved: the button changes its own copy, and the heading keeps reading the other one, with no error and no warning. The parent owns one value, passes it down, and hands the button a function that changes it.
>
> **DO THIS:**
> ```jsx
> export default function App() {
>   const [isSaved, setIsSaved] = useState(false);
>   return (
>     <>
>       <StatusBar ~isSaved={isSaved}~ /> {/* Both components read the one isSaved of App */}
>       <SaveButton onSave={() => setIsSaved(true)} />
>     </>
>   );
> }
> ```
>
> **DO NOT DO THIS:**
> ```jsx
> export default function StatusBar() {
>   const [isSaved] = ~useSaveStatus()~; // **WRONG:** a separate isSaved that the click in SaveButton never changes
>   return isSaved && <p>All changes saved</p>;
> }
> ```

Now the user clicks `Save progress`. Under the heading, the user expects a line: `All changes saved`.

The line belongs to the heading. The click belongs to the button. So both components need one value: was the work saved?

A developer who just saw `useOnlineStatus` keep both components in step writes a second Hook for this value:

```js title="src/useSaveStatus.js"
import { useState } from 'react';

export function ~useSaveStatus~() { // A custom Hook that holds one state variable
  const [isSaved, setIsSaved] = useState(false);
  return [isSaved, setIsSaved];
}
```

The heading reads `isSaved` from it:

```jsx title="src/StatusBar.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';
import { useSaveStatus } from './useSaveStatus.js';

export default function StatusBar() {
  const isOnline = useOnlineStatus();
  const [isSaved] = ~useSaveStatus()~; // StatusBar reads isSaved from its own call
  return (
    <>
      <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>
      {isSaved && <p>All changes saved</p>}
    </>
  );
}
```

The button calls the setter on click:

```jsx title="src/SaveButton.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';
import { useSaveStatus } from './useSaveStatus.js';

export default function SaveButton() {
  const isOnline = useOnlineStatus();
  const [isSaved, setIsSaved] = ~useSaveStatus()~; // SaveButton gets the setter from its own call
  function handleSaveClick() {
    console.log('Progress saved');
    setIsSaved(true);
  }

  return (
    <button disabled={!isOnline} onClick={handleSaveClick}>
      {isOnline ? 'Save progress' : 'Reconnecting...'}
    </button>
  );
}
```

Same shape as `useOnlineStatus`: one Hook, called in both components. **It may look the same, but it is NOT the same thing!** The two `isOnline` values agreed because the browser told both of them about the network. The two `isSaved` values have nothing outside React to keep them in step.

### Why All changes saved never appears

**Beware! The click saves the work, and the screen never says so.** Here is what happens, in order:
1. The page opens. Each component calls `useSaveStatus` and gets its own `isSaved`, set to false.
2. The heading checks its own `isSaved`. It is `false`, so no line appears under the heading.
3. The user clicks `Save progress`. The handler prints `Progress saved` and calls the button's own setter.
4. React renders `SaveButton` again. The button's `isSaved` is now `true`.
5. Nobody called the heading's setter. The heading's `isSaved` is still `false`, and React has no reason to render the heading again.
6. The line `All changes saved` never appears.

```page width=text caption="The notes app after the user clicks Save progress, when each component calls useSaveStatus: the Console says the progress was saved, and the page shows no confirmation."

form:
  button: Save progress
console:
  log: Progress saved | SaveButton.jsx:8
```

Remember `createCart`: putting socks into one cart never puts them into the other cart. Here, true in the button's `isSaved` never reaches the heading's `isSaved`. The Console shows no error and no warning.

### Moving isSaved into App

When two components must show one value that changes, the value cannot live in a custom Hook. It lives in their closest common parent.

> [!DEFINITION]
> **What is lifting state up?** [REVIEW] Two components need the same value. You remove the state from both, and you put it once in their closest common parent.
> The parent passes the value down as a prop. To let a child change it, the parent also passes down a function that calls the setter.
> Now there is one value, and every child reads that same value (Lesson 24).

React's docs say it plainly: when you need to share the state itself between multiple components, lift it up and pass it down instead.

So we delete the file of `useSaveStatus`. Now the parent, `App`, holds the one `isSaved`:

```jsx title="src/App.jsx"
import { useState } from 'react';
import StatusBar from './StatusBar.jsx';
import SaveButton from './SaveButton.jsx';

export default function App() {
  const [isSaved, setIsSaved] = ~useState(false)~; // One isSaved, owned by the parent of both components
  return (
    <>
      <StatusBar ~isSaved={isSaved}~ /> {/* The heading reads the value as a prop */}
      <SaveButton ~onSave={() => setIsSaved(true)}~ /> {/* The button gets a function that changes the value in App */}
    </>
  );
}
```

The heading takes `isSaved` as a prop. The button takes `onSave`, a function that `App` created (Lesson 23). Both components still call `useOnlineStatus`, because each still needs its own view of the network:

```jsx title="src/StatusBar.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';

export default function StatusBar(~{ isSaved }~) { // The one isSaved of App, passed down as a prop
  const isOnline = useOnlineStatus();
  return (
    <>
      <h1>{isOnline ? 'Online' : 'Disconnected'}</h1>
      {isSaved && <p>All changes saved</p>}
    </>
  );
}
```

```jsx title="src/SaveButton.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';

export default function SaveButton(~{ onSave }~) { // A function from App that sets the isSaved of App
  const isOnline = useOnlineStatus();
  return (
    <button disabled={!isOnline} onClick={onSave}>
      {isOnline ? 'Save progress' : 'Reconnecting...'}
    </button>
  );
}
```

The button no longer needs `handleSaveClick`. It hands `onSave` straight to `onClick`, so the click calls the function from the parent. The `Progress saved` log is gone with it.

When the two components sit far apart in the tree, passing the value through every level gets long. Context carries it down instead (Lesson 28). The rule stays the same: one component owns the value, and the others receive it.

```tree caption="What a custom Hook shares and what a parent shares: the code that makes state, or one value for several components."
Two ways to reuse something between components
- +A custom Hook [`useOnlineStatus`] | Shares the **code** that makes state | Each component gets **its own value**; fits `isOnline`, which the browser keeps in step
- !A custom Hook for a shared value [`useSaveStatus`] | Gives each component **its own `isSaved`** | A click in the button **never reaches** the heading
- +State in the parent, passed down [`isSaved` in `App`] | Shares **one value** | Both components read the **same `isSaved`**, so the heading confirms the save
```

Remember the Rule of Thumb: the same code goes in a custom Hook, the same value goes in the parent.

```jsx title="src/StatusBar.jsx"
  const isOnline = ~useOnlineStatus()~; // Principle 2: StatusBar's own isOnline and its own Effect
```

```jsx title="src/SaveButton.jsx"
import { useOnlineStatus } from './useOnlineStatus.js';

export default function SaveButton({ onSave }) {
  const isOnline = ~useOnlineStatus()~; // Principle 2: a second, separate isOnline
  return (
    <button disabled={!isOnline} onClick={onSave}>
      {isOnline ? 'Save progress' : 'Reconnecting...'}
    </button>
  );
}
```

```js title="src/useOnlineStatus.js"
import { useState, useEffect } from 'react';

export function ~useOnlineStatus~() { // Principle 1: the copied state and Effect, written once
  const [isOnline, setIsOnline] = useState(navigator.onLine);
  useEffect(() => {
    function handleOnline() {
      setIsOnline(true);
    }
    function handleOffline() {
      setIsOnline(false);
    }
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);
  ~return isOnline;~ // Principle 1: the value each component reads
}
```

| What you want | The habit to avoid | The React rule |
| :--- | :--- | :--- |
| **Reuse stateful code** | Copy the same `useState` and `useEffect` into a second component, then fix only one copy | Extract one custom Hook, such as `useOnlineStatus`, and call it from each component |
| **Get a value out of the Hook** | Forget `return isOnline;`, so every component receives `undefined` | End the Hook with `return` and the value the components need |
| **Understand two calls of one Hook** | Believe both components read one shared `isOnline` | Each call creates its own state and its own Effect; the browser keeps them in step |
| **Show one value in two components** | Put `isSaved` in a custom Hook and call it in both components | Lift `isSaved` into `App` and pass it down as props |

One last time, the sentence of this lesson: **a custom Hook shares the code, not the value.**

## For the Interview

> **The Interview Question:** How do you extract and reuse stateful logic between components?

### How to Answer Clearly in 30 Seconds

"Sometimes two components repeat the same stateful logic, such as a state variable and an Effect that listens to the network. Then I extract that logic into a custom Hook. A custom Hook is my own JavaScript function. Its name starts with `use` and a capital letter, and it calls other Hooks. It returns what the components need, so each component calls `useOnlineStatus` and reads `isOnline`. The page behaves exactly as before, and every fix happens in one place. Two things to keep in mind:
1. **A custom Hook shares logic, not state**: every call runs its own `useState` and its own `useEffect`, so two components get two independent values.
2. **To share the value itself**, I lift the state into the closest common parent and pass it down as props. When the components are far apart, I use context."

### Three Classic Follow-Up Questions Interviewers Ask

1. **"If two components call the same custom Hook, do they share its state?"**
   **No.** Each call to a Hook is completely independent from every other call to the same Hook. When `StatusBar` and `SaveButton` both call `useOnlineStatus`, each one gets its own `isOnline`, its own setter, and its own Effect with its own listeners. They show the same value only because both listen to the same browser events. So a state variable inside a Hook such as `useSaveStatus` cannot carry a click from one component to the other. For that, the state goes up into the parent.
2. **"Should every piece of repeated code become a custom Hook?"**
   **No.** React's docs say that some duplication is fine. A Hook that wraps a single `useState` adds a name and saves nothing. The strongest case for a custom Hook is an Effect that talks to something outside React, such as the network, a socket, or a media query. Name the Hook after its purpose, such as `useOnlineStatus` or `useChatRoom`, never after timing, such as `useMount`. A Hook like `useMount` hides the Effect's dependencies, and the linter checks only direct `useEffect` calls, so it cannot warn about them. A function that calls no Hooks stays a regular function without the `use` prefix, such as `getSorted` (Lesson 38).
3. **"Why wrap an Effect in a custom Hook even when it already works inside the component?"**
   Because the component then says what it wants, and the Hook hides how it is done. `StatusBar` asks for the online status, and only `useOnlineStatus` knows about `navigator.onLine` and the browser's events. That pays off when a better way arrives. React's docs later rewrite `useOnlineStatus` with `useSyncExternalStore` (Lesson 53), and no component has to change. One more detail follows from where the code runs: the code of a custom Hook runs again on every render of its component. So it must stay pure, and it always receives the latest props and state (Lesson 14).

```tree dir=right caption="Interview summary: what a custom Hook shares between components, and what it does not."
What a custom Hook shares between components
- +The code that makes state [`useState` `useEffect` inside `useOnlineStatus`] | Written **once**, called from **every component** | Each fix happens **in one place**
- !Not the state itself [`isOnline` in StatusBar and SaveButton] | Every call creates its **own value** and its **own Effect** | To share **one value**, lift it into the **parent** and pass it down
```
