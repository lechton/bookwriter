# Lecture 7: Mounting the Root Component with createRoot and Vite Tooling
> INTERVIEW QUESTION | ❱ CORE | How do you mount the root component to the DOM using `createRoot`, and why do we use tooling like Vite?

## What We Are Building Today

Picture a newspaper team that has finished writing every component for its front page. The header, the section banner, and the story card all work and connect inside `App.jsx`.

Yet when we open the browser, nothing from `App.jsx` can appear on its own. A browser does not load a React component file when it visits a web address. The browser loads an HTML file first, and that HTML file has to invite JavaScript in.

Today we connect our finished `App` component to a real browser page across three startup files:

```files title="city-news: Startup Files" caption="The three files that work together to mount a React application in the browser."
index.html | entry | The HTML document loaded by the browser with an empty #root div and a module script tag
src/
  main.jsx | boundary | Looks up #root in the DOM, creates the React root, and renders <App />
  App.jsx | root | Top-level component that returns the <main> newsroom page layout
```

When those three files connect properly, the browser displays our City News page inside the empty host box:

```page caption="The City News page after main.jsx mounts <App /> into the #root element in index.html."
heading: Latest Articles
line: City News
line: Section: City News | good
card: badge=Live | badge=New | title=New Park Opens Today | text=The park on Main Street opens at noon. | good
```

### A Quick Map of the Lesson

Here are the four things we are going to look at in this lesson:

1. **The single ID that holds the whole app:** We are going to see how the main HTML page of a React project, `index.html`, sits almost completely empty. It holds just one blank `<div>` with `id="root"`, and the entire React application will hang from that single ID.
2. **The `type="module"` switch and Vite:** Right below that empty box, we will see why we have to place `type="module"` on our `<script>` tag so the browser allows module imports. Then we will see how Vite steps in behind the scenes to translate JSX tags and package names before the browser ever sees the file.
3. **Why `createRoot` alone leaves a blank screen:** Next, we will step into `main.jsx` and see why mounting takes two separate calls. First we hand our HTML box to `createRoot`, and then we call `root.render` on the result. Forget that second line, and the page stays completely blank without a single error in the Console.
4. **The angle-bracket trap in `root.render`:** Finally, we will look at the last line of the startup file and see why we have to pass `<App />` instead of the raw `App` function. Those two angle brackets are the clue that tells Vite and React to build the page instead of rejecting the function.

| # | Principle | What Breaks Without It | The React 19 Rule |
| :--- | :--- | :--- | :--- |
| **Principle 1** | **The HTML Host Container** | Mismatched IDs between `index.html` and `main.jsx` make `document.getElementById` return `null` and crash `createRoot`. | Put `<div id="root"></div>` in `index.html` and pass that exact DOM element to `createRoot`. |
| **Principle 2** | **The Module Entry and Build Tool** | Missing `type="module"` blocks `import`, while serving raw `.jsx` without Vite fails on bare package names and `<App />`. | Load `main.jsx` with `<script type="module">` and let Vite rewrite bare imports and JSX tags. |
| **Principle 3** | **Two-Step Mounting** | Calling `createRoot` without `root.render` leaves the screen blank with zero Console errors. | Import `createRoot` from `react-dom/client`, create the root on the DOM node, and call `root.render`. |
| **Principle 4** | **JSX Element vs Function** | Passing the raw function `App` to `root.render` leaves the page blank and logs a React child warning. | Pass the JSX element `<App />` to `root.render` so React receives an element object and calls `App`. |

## 1. Principle 1: The HTML Host Container

### Why React Needs One Real HTML Box on the Page

A junior developer often thinks React builds the whole web page from scratch, starting with `<html>` and `<body>`. A senior engineer keeps two layers separate: the browser loads a regular HTML document first, and React moves into one chosen element inside that document.

Think of a framed chalkboard bolted to a classroom wall. The wall and the wooden frame belong to the building, while the teacher only writes and erases inside the board. In a React app, `index.html` is that wall, and one empty `<div>` on the page is the frame reserved for React.

Here is the HTML file the browser loads first when you open the site:

```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <~div id="root"~></div> <!-- Empty host box waiting for React -->
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
```

Line 4 creates an empty `<div>` with `id="root"`, and line 5 loads our startup JavaScript file.

Now the startup file asks the browser for that exact `<div>` by its ID and mounts the page inside it:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = ~document.getElementById('root')~; // Finds the <div id="root"> in index.html
const root = createRoot(container);
root.render(<App />);
```

Notice how the two files meet on the exact string `'root'`. In the HTML file, `id="root"` labels the empty box on the page. In the startup file, `document.getElementById` looks up `'root'` and asks the browser to hand back that live DOM element.

For completeness, here is the `App` component that the startup file imports and renders:

```jsx title="src/App.jsx" startLine="1"
export default function App() {
  return (
    <main>
      <header>
        <h1>Latest Articles</h1>
        <p>City News</p>
      </header>
      <section>
        <h2>Section: City News</h2>
        <article className="card">
          <span className="badge">Live</span>
          <span className="badge">New</span>
          <h3>New Park Opens Today</h3>
          <p>The park on Main Street opens at noon.</p>
        </article>
      </section>
    </main>
  );
}
```

Once `root.render` runs, React builds the page markup from our root component and places it inside `<div id="root">`:

### What Breaks When the Two IDs Do Not Match

This string match between the HTML file and the startup file is fragile. If the ID in one file changes by even one letter, `document.getElementById` cannot find the element and returns `null`.

Suppose someone edits the HTML file and renames the box ID to `app`:

```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <div ~id="app"~></div> <!-- ID is now "app", not "root" -->
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
```

Meanwhile, the startup file still asks the browser for `'root'`:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = ~document.getElementById('root')~; // Returns null because #root does not exist
const root = ~createRoot(container)~; // Crashes: null is not a DOM element
root.render(<App />);
```

Because no element in the HTML file has `id="root"`, the container variable becomes `null`. Passing `null` into `createRoot` crashes the app before anything can render:

```devconsole caption="Console error when document.getElementById returns null and main.jsx passes null to createRoot."
x Uncaught Error: Target container is not a DOM element.
```

You get the exact same crash if you skip the DOM lookup and pass `<App />` directly into `createRoot`:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = ~createRoot(<App />)~; // Wrong: <App /> is a React element, not a DOM node
```

`createRoot` always needs a real browser DOM element first, such as the box returned by `document.getElementById`.

One small detail often comes up in code reviews: what if `index.html` puts a temporary loading message inside `<div id="root">`? While the JavaScript bundle downloads, the browser shows that placeholder HTML inside the box. The moment `root.render` runs for the first time, React clears every existing child inside `<div id="root">` and replaces it with your component tree.

Keep the ID string identical in both files so the browser hands `createRoot` a real DOM container:

```tree dir=right caption="How index.html and src/main.jsx connect through the shared root ID string."
The Two-File Host Handshake
- +1. HTML host element [`index.html`] | Places `<div id="root"></div>` inside `<body>`
- +2. Browser DOM lookup [`src/main.jsx`] | Calls `document.getElementById` with `'root'` to get the live `<div>`
- +3. React root creation [`createRoot`] | Attaches the React root manager to that real DOM element
```

> [!PRINCIPLE]
> **Principle 1: The HTML Host Container: Match the ID in index.html and main.jsx**
>
> *Pass a real browser DOM element to createRoot by matching the container ID in index.html with the ID in document.getElementById.*
>
> `createRoot` takes a real browser DOM element, not a React component. The HTML file provides an empty `<div id="root"></div>`, and the startup file looks it up with `document.getElementById`. If the two IDs do not match, the lookup returns `null` and `createRoot` throws a target container error.
>
> **DO THIS:**
> ```jsx title="src/main.jsx"
> const container = ~document.getElementById('root')~; // Matches <div id="root"> in index.html
> const root = ~createRoot(container)~; // Passes the real browser DOM element
> root.render(<App />);
> ```
>
> **DO NOT DO THIS:**
> ```jsx title="src/main.jsx"
> const container = ~document.getElementById('app')~; // **WRONG:** returns null when index.html uses id="root"
> const root = ~createRoot(container)~; // **WRONG:** crashes because container is null
> root.render(<App />);
> ```

## 2. Principle 2: The Module Entry and Build Tool

### Why the Browser Needs type="module" and Vite

A junior developer often treats Vite as a black box that just starts a local web server. A senior engineer knows the two exact browser rules that make both `<script type="module">` and Vite necessary.

Think of an international delegation arriving at a conference hall. First, the front door must be unlocked for visiting delegates; second, an interpreter inside the hall must translate their speeches into the local language. In our project, `<script type="module">` unlocks module imports at the browser door, and Vite is the interpreter that translates JSX and package names.

Look at line 5 of `index.html`, where the HTML page invites our startup file in:

```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <div id="root"></div>
    <script ~type="module"~ ~src="/src/main.jsx"~></script> <!-- Loads main.jsx as an ES module -->
  </body>
</html>
```

The attribute `type="module"` tells the browser that this script uses ES module `import` statements.

If a developer forgets `type="module"` and writes a plain `<script>` tag, the browser treats the file as an old classic script:

```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <div id="root"></div>
    <~script src="/src/main.jsx"~></script> <!-- Classic script mode: import is forbidden -->
  </body>
</html>
```

As soon as the browser hits the first `import` line in the startup file, it stops with a syntax error:

```devconsole caption="Browser Console error when index.html loads main.jsx without type='module'."
x Uncaught SyntaxError: Cannot use import statement outside a module
```

### What Vite Translates Before the Browser Runs the File

Adding `type="module"` lets the browser read `import` lines, but a raw React file still contains two things a browser cannot run on its own.

Look closely at lines 1 and 5 of our startup file:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from ~'react-dom/client'~; // 1. Bare package name, not a URL path
import App from './App.jsx';

const root = createRoot(document.getElementById('root'));
root.render(~<App />~); // 2. JSX tag syntax, not standard JavaScript
```

First, the `react-dom` client import on line 1 uses a bare package name sitting inside `node_modules`, not a relative URL path. Without a build tool, a browser refuses to guess where bare package names live and throws a `TypeError` for the unresolved module specifier.

Second, `<App />` on line 5 is JSX syntax, not valid JavaScript. As we saw in Lecture 02, a browser engine that meets a raw `<` character inside JavaScript stops with a `SyntaxError`.

When you run `vite` during development, Vite steps between your source files and the browser. It rewrites bare package imports into pre-bundled browser URLs, and it compiles `<App />` into a standard `jsx` function call. When you run `vite build` for production, Vite bundles and minifies the entire module graph into plain `.js` files that any static web server can deliver.

Here is how `index.html`, Vite, and the browser divide the startup work:

```tree dir=right caption="How the module script tag and Vite prepare src/main.jsx for the browser."
How index.html and Vite Deliver main.jsx
- +1. Module script tag [`index.html`] | `<script type="module">` enables ES module `import` syntax in the browser
- +2. Package resolution [`Vite`] | Rewrites bare package names from `node_modules` into valid browser URLs
- +3. JSX compilation [`Vite`] | Compiles `<App />` into a standard JavaScript `jsx` call before execution
```

> [!PRINCIPLE]
> **Principle 2: The Module Entry and Build Tool: Use type="module" and Vite**
>
> *Load the entry file with type="module" in index.html, and use a build tool like Vite to resolve bare package imports and compile JSX into standard JavaScript.*
>
> In the HTML file, `<script type="module">` tells the browser to load the startup file with ES module `import` support. Before that file reaches the browser, Vite resolves bare package imports from `node_modules` and compiles JSX tags like `<App />` into standard JavaScript calls.
>
> **DO THIS:**
> ```html title="index.html"
> <body>
>   <div id="root"></div>
>   <script ~type="module"~ src="/src/main.jsx"></script> <!-- Enables ES module imports -->
> </body>
> ```
>
> **DO NOT DO THIS:**
> ```html title="index.html"
> <body>
>   <div id="root"></div>
>   <~script src="/src/main.jsx"~></script> <!-- **WRONG:** classic script mode rejects import statements -->
> </body>
> ```

## 3. Principle 3: Two-Step Mounting with createRoot and root.render

### Why Creating a Root Does Not Paint the Screen Yet

A junior developer often assumes calling `createRoot` puts the application on the screen. A senior engineer separates the two steps in React 19. First, `createRoot` claims the DOM container, and second, `root.render` paints the component tree inside it.

Think of unlocking a theater stage versus raising the curtain on a play. Unlocking the stage prepares the lights and soundboard. Yet the audience still sees an empty stage until the crew raises the curtain.

In React 19, `createRoot` comes from the client DOM package, not from `'react'`. As we saw in Lecture 01, `'react'` holds platform-independent component logic, while the `react-dom` client package knows how to talk to browser DOM nodes.

Watch what happens when a developer calls `createRoot` on the `#root` element and stops there:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = document.getElementById('root');
const root = ~createRoot(container)~; // Creates the React root, but never calls root.render
```

This code is valid JavaScript, so the browser Console shows zero errors. Yet the page stays completely blank because nothing told `root` what component tree to render:

### Calling root.render to Paint the Component Tree

To paint the screen, we take the root object returned by `createRoot` and call `root.render` with our top-level element:

```jsx title="src/main.jsx" startLine="1"
import { ~createRoot~ } from 'react-dom/client'; // Step 0: Import from react-dom/client
import App from './App.jsx';

const container = document.getElementById('root');
const root = ~createRoot(container)~; // Step 1: Create the React root for #root
~root.render(<App />)~; // Step 2: Render the <App /> tree into that root
```

Many developers chain both calls into one expression when they do not need to store the `root` variable:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

~createRoot(document.getElementById('root')).render(<App />)~; // Creates the root and renders <App /> right away
```

Both styles run the exact same two operations in the exact same order.

Notice also how React 19 differs from older React 17 tutorials you may see online. Old React 17 code called a single `ReactDOM.render` function that took both the element and the container at once. React 19 removed `ReactDOM.render`, so calling it today throws a `TypeError` saying it is not a function.

And because `createRoot` already remembers the DOM container, `root.render` takes only one argument. If you pass the container a second time to `root.render`, React logs a Console error telling you not to pass the container again.

Each of the two calls in React 19 has one clear job:

```tree dir=right caption="The two distinct steps that mount a React 19 application."
The Two-Step Mount in React 19
- +1. Create the root [`createRoot`] | Connects React to the `#root` DOM element and returns the `root` object
- +2. Render the tree [`root.render`] | Evaluates `<App />` and mounts the resulting DOM nodes inside `#root`
```

> [!PRINCIPLE]
> **Principle 3: Two-Step Mounting: Call createRoot First, Then Call root.render**
>
> *Import createRoot from the react-dom client package, call createRoot on the DOM container to create a React root, and then call root.render to mount your component tree.*
>
> Mounting in React 19 takes two steps using `createRoot` from the `react-dom` client package. First, `createRoot` attaches a React root manager to the browser DOM element. Second, `root.render` renders your component tree inside that root. Calling `createRoot` without `root.render` leaves the page blank with zero Console errors.
>
> **DO THIS:**
> ```jsx title="src/main.jsx"
> import { ~createRoot~ } from 'react-dom/client'; // Browser DOM root API lives in react-dom/client
> import App from './App.jsx';
>
> const root = ~createRoot(document.getElementById('root'))~; // Step 1: Create root
> ~root.render(<App />)~; // Step 2: Paint the component tree
> ```
>
> **DO NOT DO THIS:**
> ```jsx title="src/main.jsx"
> import { createRoot } from 'react-dom/client';
> import App from './App.jsx';
>
> const root = ~createRoot(document.getElementById('root'))~; // **WRONG:** stops after step 1; screen stays blank!
> ```

## 4. Principle 4: Passing a JSX Element Instead of the Component Function to root.render

### Why root.render with <App /> Works and Passing App Fails

A junior developer sees the imported component and passes `App` straight into `root.render` like an event callback. A senior engineer distinguishes the raw function `App` from the JSX element `<App />` that rendering requires.

Think of a theater director handing the stage crew an unprinted script binder instead of a cast list on a cue sheet. The stage crew only knows how to place actors from a cue sheet onto the stage, not what to do with a raw binder.

Look at what happens when we pass the function name `App` without angle brackets to `root.render`:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = createRoot(document.getElementById('root'));
root.render(~App~); // Wrong: passes the raw function instead of <App />
```

In JavaScript, `App` is a function object, and a raw function is not a valid React child. React refuses to mount it, leaves `<div id="root">` empty, and logs a clear warning in the Console:

```devconsole caption="React Console error when main.jsx passes the raw function App to root.render instead of <App />."
x Functions are not valid as a React child. This may happen if you return App instead of <App /> from render. Or maybe you meant to call this function rather than return it.
```

### How <App /> Creates the Element Object React Needs

Now replace `App` with the JSX tag `<App />`:

```jsx title="src/main.jsx" startLine="1"
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const root = createRoot(document.getElementById('root'));
root.render(~<App />~); // Right: passes a React element whose type is App
```

Why does wrapping `App` in angle brackets as `<App />` make all the difference?

As we learned in Lecture 02, Vite compiles `<App />` into a `jsx` call that returns a plain React element object. When `root.render` receives that element object, React calls `App` during rendering and builds the real DOM nodes inside the host container.

As we saw in Lecture 04 and Lecture 05, `App` must start with a capital letter. That capital letter tells JSX to treat `<App />` as your imported component rather than a lowercase HTML tag.

Here is the difference between handing `root.render` a raw function versus a JSX element:

```tree caption="Passing the raw App function reference vs. passing the <App /> JSX element to root.render."
What should you pass to root.render?
- !Raw function reference [`App`] | Passes the uncalled JavaScript function `App` | Leaves `#root` empty and logs **`Functions are not valid as a React child`**
- +JSX element tag [`<App />`] | +**DO** pass `<App />` so Vite creates `{ type: App, props: {} }` | React calls `App` and mounts the `<main>` tree inside `#root`
```

> [!PRINCIPLE]
> **Principle 4: Pass a JSX Element to root.render, Not the Function**
>
> *Always pass a JSX element like <App /> to root.render rather than passing the raw component function App.*
>
> `root.render` expects a React element such as `<App />`, not the raw component function. Vite compiles `<App />` into a plain element object whose type points to `App`. Passing the raw `App` function to `root.render` leaves the container empty and logs a React child warning.
>
> **DO THIS:**
> ```jsx title="src/main.jsx"
> const root = createRoot(document.getElementById('root'));
> root.render(~<App />~); // Passes a React element object { type: App, props: {} }
> ```
>
> **DO NOT DO THIS:**
> ```jsx title="src/main.jsx"
> const root = createRoot(document.getElementById('root'));
> root.render(~App~); // **WRONG:** passes a raw function; logs Functions are not valid as a React child
> ```

## Putting All Four Principles Together

Let us put all three startup files side by side and trace the full journey from the browser loading `index.html` to the rendered newsroom page.

First, the HTML file places the `<div id="root"></div>` host container on the page and loads the startup file with `type="module"`:

```html title="index.html" startLine="1"
<!DOCTYPE html>
<html lang="en">
  <body>
    <~div id="root"~></div> <!-- Principle 1: Host container with id="root" -->
    <script ~type="module"~ src="/src/main.jsx"></script> <!-- Principle 2: ES module entry point -->
  </body>
</html>
```

Next, Vite transforms the startup file so the browser can import `createRoot`, create the React root, and render `<App />`:

```jsx title="src/main.jsx" startLine="1"
import { ~createRoot~ } from 'react-dom/client'; // Principle 2 & 3: Bare import resolved by Vite
import App from './App.jsx';

const container = ~document.getElementById('root')~; // Principle 1: Matches id="root" in index.html
const root = ~createRoot(container)~; // Principle 3: Creates the React root manager
~root.render(<App />)~; // Principle 3 & 4: Renders the <App /> JSX element into #root
```

Finally, React calls `App` and builds the `<main>` article layout inside the host container:

```jsx title="src/App.jsx" startLine="1"
export default function ~App~() { // Exported root component rendered by main.jsx
  return (
    <main>
      <header>
        <h1>Latest Articles</h1>
        <p>City News</p>
      </header>
      <section>
        <h2>Section: City News</h2>
        <article className="card">
          <span className="badge">Live</span>
          <span className="badge">New</span>
          <h3>New Park Opens Today</h3>
          <p>The park on Main Street opens at noon.</p>
        </article>
      </section>
    </main>
  );
}
```

## For the Interview

When an interviewer asks how you mount a root component with `createRoot` and why we use Vite, lead with the two-step mount from `index.html` to `main.jsx`. Then state the two jobs Vite performs before the browser runs the code:

| Principle | What Breaks Without It | Browser or React Symptom | Fix |
| :--- | :--- | :--- | :--- |
| **1. HTML Host Container** | `document.getElementById` looks up an ID that does not match `index.html`, or `createRoot` is given `<App />` | `Uncaught Error: Target container is not a DOM element.` | Put `<div id="root"></div>` in `index.html` and pass that DOM node to `createRoot` |
| **2. Module Entry and Vite** | Omitting `type="module"` or serving `.jsx` without a build tool | `Cannot use import statement outside a module`, `Failed to resolve module specifier`, or `Unexpected token '<'` | Load `main.jsx` with `<script type="module">` and let Vite transform JSX and bare imports |
| **3. Two-Step Mount** | Calling `createRoot` without `root.render`, or importing `createRoot` from `'react'` | Blank screen with 0 errors, or `TypeError: createRoot is not a function` | Import `createRoot` from `'react-dom/client'`, create `root`, and call `root.render` |
| **4. JSX Element in render** | Passing the raw function `App` to `root.render` instead of `<App />` | Blank screen and Console error `Functions are not valid as a React child.` | Pass `<App />` so Vite creates a React element `{ type: App, props: {} }` |

### Traps Look-Alike Comparisons

Interviewers love testing subtle mistakes in the three-line startup file because each mistake produces a completely different failure mode:

| What You Wrote | What It Actually Passes or Does | Runtime Result | What to Write Instead |
| :--- | :--- | :--- | :--- |
| `'app'` in `getElementById` when HTML has `id="root"` | Passes `null` to `createRoot` | Throws `Uncaught Error: Target container is not a DOM element.` | Match the exact ID string `'root'` in both `index.html` and `main.jsx` |
| Passing `<App />` to `createRoot` | Passes a React element object instead of a browser DOM node | Throws `Uncaught Error: Target container is not a DOM element.` | Pass the `#root` DOM element to `createRoot`, then pass `<App />` to `root.render` |
| `<script src="/src/main.jsx">` without `type="module"` | Loads `main.jsx` in classic non-module script mode | Throws `Uncaught SyntaxError: Cannot use import statement outside a module` | Add `type="module"` to the `<script>` tag in `index.html` |
| Calling `createRoot` without `root.render` | Creates the React root object in memory but renders nothing | Blank page and empty `<div id="root"></div>` with zero Console errors | Call `root.render` with `<App />` on the returned root object |
| Passing raw `App` to `root.render` | Passes the uncalled function reference `App` as a child | Blank page and Console error `Functions are not valid as a React child.` | Pass the JSX element `<App />` to `root.render` |

### Battle-Tested Code

Here is the wrong startup setup alongside the clean React 19 startup setup.

**DO NOT DO THIS:**

```wrong
import { createRoot } from 'react';
import App from './App.jsx';

const root = createRoot(document.getElementById('app'));
root.render(App);
```

**DO THIS:**

```right
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

const container = document.getElementById('root');
const root = createRoot(container);
root.render(<App />);
```

### Follow-Up Questions

1. **What happens if `index.html` already has HTML inside `<div id="root"><p>Loading...</p></div>` when `root.render` runs?**
   While the JavaScript bundle is downloading, the browser displays `<p>Loading...</p>` inside `#root`. The moment `root.render` runs for the first time, React clears all existing child nodes inside `#root` and replaces them with your rendered React component tree.

2. **Why is `createRoot` imported from `'react-dom/client'` instead of `'react'`?**
   The `'react'` package contains only platform-independent concepts like components, elements, and hooks that work everywhere, including mobile apps and servers. The `'react-dom/client'` package contains the browser-specific renderer that knows how to talk to real browser DOM nodes.

3. **Can a single HTML page call `createRoot` more than once?**
   Yes. A full-page React application normally uses a single `#root` container. However, a mostly static HTML page can place several container elements on the page and call `createRoot` once for each widget.
