## 2. Principle 2: Picking travel Runs the Cleanup for general First

### Both functions read `roomId`, but not from the same render

Look again at the setup function and the cleanup function inside `ChatRoom`:

```jsx title="The setup and cleanup inside ChatRoom.jsx"
useEffect(() => {
  const connection = createConnection(serverUrl, ~roomId~); // Reads roomId from the render that starts this Effect
  connection.connect();
  return () => {
    ~connection.disconnect()~; // Disconnects the connection created with that same render's roomId
  };
}, [roomId]);
```

The `useEffect` reference states the exact three-step timing for when React calls your setup and cleanup functions:
1. **When the component mounts**: "Your setup code runs when your component is added to the page."
2. **After every commit with changed dependencies**: "First, your cleanup code runs with the old props and state. Then, your setup code runs with the new props and state."
3. **When the component unmounts**: "Your cleanup code runs one final time after your component is removed from the page."

**It may look the same, or work the same at first, but it is NOT the same thing!** The cleanup function and the setup function sit inside the same `useEffect` call and work with `connection` built from `roomId`. When the user switches the menu from `general` to `travel`, the prop `roomId` is now `'travel'`, so it is easy to assume both functions see `'travel'`. They do not. First, the cleanup disconnects from `"general"` using the previous render's value. Only then does the new setup connect to `"travel"` using the new render's value. As React's docs state in bold: "**React always cleans up the previous render's Effect before the next render's Effect.**" In the docs' words, "React needs to re-synchronize your Effect to re-connect you to a different room."

```tree dir=right caption="What React runs after a commit where roomId changed from general to travel."
How React re-synchronizes when `roomId` changes from `'general'` to `'travel'`
- +1. Commit the new UI [`Welcome to the travel room!`] | React updates the heading text in the DOM first
- +2. Run the OLD render's cleanup [`roomId` is `'general'`] | Calls `disconnect` from the **`'general'` render**
- +3. Run the NEW render's setup [`roomId` is `'travel'`] | Calls `connect` from the **`'travel'` render**
```

### Why the cleanup still holds `'general'` after the heading says `travel`

**Beware! When the user picks `travel`, the Console prints a disconnect line for `general` after the heading on the page already welcomes the user to the travel room.** Here is what happens in order when the user picks `travel`:
1. The user picks `travel` in the room menu, and `setRoomId` asks React for a re-render.
2. `App` renders and passes the new `roomId` down to `ChatRoom`, and React commits the travel room heading to the DOM.
3. React compares the new dependency array `['travel']` with the previous array using `Object.is` (as seen in Lesson 32). Because `'travel'` and `'general'` are not equal, the docs explain: "The Effect can't be skipped."
4. React calls the cleanup function that the `general` render's setup returned. That cleanup disconnects the connection created for the general room, printing the disconnect line for `general`.
5. React calls the `travel` render's setup function, which creates a new connection and prints the connect line for `travel`.

That cleanup still holds `"general"` because every render of a component keeps its own snapshot of props and state (as seen in Lesson 15). Why? Well, as the docs explain in their Deep Dive, "Each Effect "captures" the `text` value from its corresponding render." During the first render, `roomId` was `'general'`, so the first render's Effect and its cleanup function captured `'general'`:

```jsx title="The first render's Effect with 'general' captured in its snapshot"
() => {
  const connection = createConnection(serverUrl, ~'general'~); // Captured 'general' during the 1st render
  connection.connect();
  return () => ~connection.disconnect()~; // Always disconnects the 1st render's 'general' connection
}
```

Later, when the user clicks the Close chat button while in the `music` room, `ChatRoom` unmounts from the page. React calls the active render's cleanup one final time, printing the disconnect line for `music`.

### Why clicking Open chat in development prints three lines

**Beware! In development with Strict Mode, clicking the Open chat button prints three lines in the Console for a single mount: connect, disconnect, and connect again.** Here is what React runs when the user clicks the Open chat button in development:
1. React runs the first render's setup for `general`, which prints the first connect line for `general`.
2. React immediately calls that setup's cleanup function, which prints the disconnect line for `general`.
3. React runs the setup for `general` once more, which prints the second connect line for `general`.

```page width=text caption="After the user clicks Open chat in development: Strict Mode runs setup, cleanup, and setup to verify that the Effect can re-synchronize."
form:
  select: Choose the chat room: | general
  button: Close chat
heading: Welcome to the general room!
log: ✅ Connecting to "general" room at https://localhost:1234... | chat.js:5
log: ❌ Disconnected from "general" room at https://localhost:1234 | chat.js:8
log: ✅ Connecting to "general" room at https://localhost:1234... | chat.js:5
```

As the docs explain: "In development, React always remounts each component once." They compare this check to "opening a door and closing it an extra time to check if the door lock works" (as seen in Lesson 32). Lesson 47 covers this development check in full, along with how saving a file in development also re-synchronizes your Effect.

When `ChatRoom` re-renders while `roomId` is still `'general'`, nothing reconnects. React compares the second render's `['general']` array with the first render's array using `Object.is`. As the docs state: "**Because all dependencies are the same, React *ignores* the Effect from the second render.** It never gets called." When a third render later changes `roomId` to `'travel'`, the docs' Deep Dive notes that before applying the third render's Effect, React "needs to clean up the last Effect that _did_ run." Because the second render's Effect was skipped, React cleans up the first render's Effect before running the third render's Effect.

### What happens when you forget the cleanup function

**Beware! Without a cleanup function, switching from `general` to `travel` never closes the connection to `general`, so the user ends up connected to both rooms at the same time.** Look at what happens when a developer leaves the `return` out of `ChatRoom.jsx`:
1. The setup function opens a connection to `roomId` and returns no cleanup function.
2. The user switches the menu from `general` to `travel`. The page now displays the travel room heading, while React has no cleanup function to call for the previous room.
3. React immediately runs the new setup for `travel` and prints the connect line for `travel`, with no disconnect line for `general` before it.
4. Nothing closed the connection to `general`, so it stays open in the background while the new connection to `travel` is also open. Each new room the user picks adds one more open connection.

As the docs' Troubleshooting entry reminds us: "The cleanup function runs not only during unmount, but before every re-render with changed dependencies." And that cleanup must always mirror the setup that created it: "Avoid: Cleanup logic without corresponding setup logic."

> [!PRINCIPLE]
> **Principle 2: Re-Synchronization Order: Old Cleanup Runs with Old Values Before New Setup Runs with New Values**
>
> *After a commit with changed dependencies, React runs the previous render's cleanup with the old values before running the new setup with the new values.*
>
> Each render captures its own snapshot of props and state. When the user switches the room to `'travel'`, the cleanup function that React calls was created during the first render, so it disconnects from `'general'`. Only then does the new setup connect to `'travel'`. Omitting that cleanup leaves `'general'` connected in the background every time the user switches rooms.
>
> **DO THIS:**
> ```jsx
> useEffect(() => {
>   const connection = createConnection(serverUrl, roomId);
>   connection.connect();
>   ~return () => connection.disconnect();~ // Closes the old roomId connection before the new setup runs
> }, [roomId]);
> ```
>
> **DO NOT DO THIS:**
> ```jsx
> useEffect(() => {
>   const connection = createConnection(serverUrl, roomId);
>   ~connection.connect();~ // **WRONG:** no cleanup returned, so every room change leaves the old connection open!
> }, [roomId]);
> ```
