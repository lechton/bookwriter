Principle 1

Always Replace the Object, Never Edit It in Place

Treat state objects as read-only
1
The Goal

Click +1, see Quantity: 2

The card holds an item object in state: { quantity: 1, giftWrap: false }. When we click +1, we expect the count to increase by one immediately.

On the screenitem in state
Coffee mugQuantity: 1Gift wrap: No+1Add gift wrap
 { quantity: 1, giftWrap: false }
Coffee mugQuantity: 2Gift wrap: No+1Add gift wrap
 { quantity: 2, giftWrap: false }
2
The Problem

We edit the field in place, and nothing happens on screen

We change the field inside the object, then pass the same item back into setItem:

item.quantity = item.quantity + 1;
setItem(item);

setItem compares the object we pass in with the object it already holds. It uses Object.is and asks one question:

Is this the SAME object, or a NEW object?

Object.is never looks inside an object to check its fields. Our item is the same object, so React skips the render and the card still shows Quantity: 1.

3
The Solution

Build a new object with { } and pass it to setItem

Instead of changing item, we write a new object with curly braces { } and copy each field into it:

item.quantity = item.quantity + 1;
setItem(item);
↓
setItem({ quantity: item.quantity + 1, giftWrap: item.giftWrap });

Follow the values. Each field of the new object is filled from the old item:

quantity: item.quantity + 1→quantity: 2
giftWrap: item.giftWrap→giftWrap: false

So setItem receives { quantity: 2, giftWrap: false }, an object that did not exist a moment ago.

setItem asks its question again:

Is this the SAME object, or a NEW object?
setItem(item)SAME→Quantity: 1 setItem({ quantity: 2, giftWrap: false })NEW→Quantity: 2
4
In Code

A new object, not an edited one

✓ DO THISPass a brand-new object
function handleAddOne() {
  setItem({ quantity: item.quantity + 1, giftWrap: item.giftWrap });
}
✗ DO NOT DO THISEdit item and pass it back
function handleAddOne() {
  item.quantity = item.quantity + 1;
  setItem(item);
}
Principle 4

Write One Handler for Multiple <input> Boxes [e.target.name]

1
The Goal

Updating two properties of the same object

Suppose we have a person object in state and two <input> boxes on the screen. We type "John" in the first box, then "Robinson" in the second.

On the screenperson in state
NameSurname
 { name: "", surname: "" }
NameJohnSurname
 { name: "John", surname: "" }
NameJohnSurnameRobinson
 { name: "John", surname: "Robinson" }
2
The Problem

Look at the two setPerson lines we end up writing

If we write a separate function for each <input> box, we write:

setPerson({ ...person, name: e.target.value })
setPerson({ ...person, surname: e.target.value })

Everything in those two lines is identical except for one word: name versus surname.

3
The Solution

Replace both lines with [e.target.name]

Instead of writing name: in one function and surname: in another, we write one single function:

setPerson({ ...person, name: e.target.value })
setPerson({ ...person, surname: e.target.value })
↓
setPerson({ ...person, [e.target.name]: e.target.value })

Then we label the first <input> box with name="name" and the second with name="surname", so [e.target.name] knows which property to change:

The <input> boxWe typeBecomes
<input name="name" />Johnname: "John"
<input name="surname" />Robinsonsurname: "Robinson"

One single function gives us { name: "John", surname: "Robinson" }

4
In Code

One function for both boxes

✓ DO THISOne function for both <input> boxes
function handleChange(e) {
  setPerson({ ...person, [e.target.name]: e.target.value });
}

<label>Name <input name="name" onChange={handleChange} /></label>
<label>Surname <input name="surname" onChange={handleChange} /></label>
✗ DO NOT DO THISA separate function for each <input> box
function handleNameChange(e) {
  setPerson({ ...person, name: e.target.value });
}

function handleSurnameChange(e) {
  setPerson({ ...person, surname: e.target.value });
}

<label>Name <input onChange={handleNameChange} /></label>
<label>Surname <input onChange={handleSurnameChange} /></label>
