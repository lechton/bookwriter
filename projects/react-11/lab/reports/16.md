## Fixes

All fixes come from p5-timing. The code, previews, and Console blocks were already right.

- PRINCIPLES list, item 5. Old: "React calls updater functions during the next render, and calls each one twice in Strict Mode during development." New: "React decides when to call updater functions, mostly during the next render, and calls each one twice in Strict Mode during development."
- Overview table, Principle 5 rule. Old: "Keep updaters pure because they run during render; use an updater". New: "Keep updaters pure because React decides when they run, mostly during render; use an updater".
- Principle 5, `handleImpure` comment. Old: "**WRONG:** inside the updater -> runs during the next RENDER, twice in StrictMode!" New: "**WRONG:** inside the updater -> React decides when it runs, and runs it twice in StrictMode!"
- Principle 5, first confusion bullet. Old: "Your click handler only puts the updater function into React's queue. React calls that updater function later, **during the next render**, under the exact same purity rules as your component body! Think of an updater function as a **recipe card** handed to the kitchen. In `<StrictMode>` development, the cook reads that recipe card **twice** to check the calculation and throws the second dish away." New: "Your click handler only hands the updater function to React, and React decides when to call it. React calls most updaters **during the next render**, under the exact same purity rules as your component body! When nothing else waits in the queue yet, React may even call the first updater once right inside the setter call. That early call checks whether the state will change at all. Think of an updater function as a **recipe card** handed to the kitchen. The cook decides when to cook it. In `<StrictMode>` development, the cook cooks every recipe card **twice** to check the calculation and throws one of the two dishes away."
- Principle 5 tree, updater box. Old: "Runs **during the next render**, NOT on the click | Must be **100% pure**: `<StrictMode>` calls it **twice** in development and discards the 2nd result". New: "**React decides** when it runs, mostly **during the next render** | Must be **100% pure**: `<StrictMode>` calls it **twice** in development and keeps **one** result".
