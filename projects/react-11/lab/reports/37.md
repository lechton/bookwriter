## Fixes in the lecture

1. Principle 1, after "Object and function dependencies can make your Effect re-synchronize more often than you need." New paragraph: "The linter sees this too. With `[options]`, it no longer reports a missing dependency. Instead, it warns that this object changes the dependencies of the Effect on every render, and it tells you to move the object inside the Effect. Principle 2 does exactly that."
2. For the Interview, follow-up question 2. Old text: "If that Effect also set state, each run would cause a render, a new `options`, and another run, with no end." New text: "If that Effect also set state to a new value on every run, such as a new object, the runs would never end. Each run would cause a render, a new `options`, and another run, and the Console would fill with React's error `Maximum update depth exceeded`. Setting state to a value it already holds, such as `true` again, causes no new render, so the runs stop."
3. The build listed nine parentheses, all inside code in prose. Each sentence was changed:
   - Old: "2. `setMessage('h')` asks React to render `ChatRoom` again." New: "2. `setMessage` stores `h` and asks React to render `ChatRoom` again."
   - Old: "as `Object.is(roomId1, roomId2)` showed." New: "as the two `'music'` strings showed."
   - Old: "Call it outside the Effect, as in `const { roomId, serverUrl } = getOptions();`, and list the two strings." New: "Call it outside the Effect, read `roomId` and `serverUrl` from the object it returns, and list the two strings."
   - Old: "The Effect hands the connection a function with `connection.on('message', ...)`, and the connection calls" New: "The Effect hands the connection a function through its `on` method, and the connection calls"
   - Old: "React's docs show the same bug with a timer that adds one every second: the Effect "always calls `setCount(0 + 1)` every second, and you always see `1`."" New: "React's docs show the same bug with a counter that should go up by one every second. The Effect keeps adding one to the first value, zero, "and you always see `1`.""
   - Summary table, two rows. Old cells: "`setMessages([...messages, msg])`, with `[roomId, messages]`", "`setMessages(msgs => [...msgs, msg])`, with `[roomId]`", "`setMessages([...messages, msg])`, with `[roomId]` and the comment", "`setMessages(msgs => [...msgs, msg])`, with no comment". New cells: "The Effect reads `messages`, with `[roomId, messages]`", "An updater function, with `[roomId]`", "The Effect reads `messages`, with `[roomId]` and the comment", "An updater function, with no comment".
   - Old: "such as `setMessages(msgs => [...msgs, msg])`, it no longer reads that state." New: "such as adding a message with `msgs => [...msgs, msg]`, it no longer reads that state."
   - Old: "even with the same contents: React's docs show `Object.is(options1, options2)` returning `false`." New: "even with the same contents. React's docs show two objects with the same server and the same room, and `Object.is` returns `false` for them."
