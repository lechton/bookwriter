# Q48: What React Escapes and Where Its Protection Ends
* **Topic Tag**: `#xss_safety` | `❱❱ MORE`
* **Interview Question**: *How does React protect you from cross-site scripting, and when does dangerouslySetInnerHTML remove that protection?*
* **Core Truth**: React DOM escapes every string we place in JSX text or attributes, so a reader's `<script>` arrives on screen as harmless characters; `dangerouslySetInnerHTML` hands a raw string to the browser's HTML parser and switches that protection off, so the string must come from a trusted source or be sanitized first.
* **The Friction**: Reader comments render as `{comment.body}`, and a posted `<img src=x onerror=alert(1)>` appears on screen as plain text. Then the team renders article bodies written on the admin page with `dangerouslySetInnerHTML`. A compromised admin account inserts the same payload into one article, and its `onerror` script runs in every visitor's browser with full access to the page and the reader's logged-in session.
* **The Mechanism**: Default escaping for `{value}` in children and attributes; `dangerouslySetInnerHTML={{ __html: html }}` only for HTML from a trusted source or after sanitizing it with a library such as DOMPurify (`DOMPurify.sanitize(article.html)`); checking user-supplied URLs before placing them in `href` or `src`, because React 19 blocks `javascript:` URLs but still renders a link to any other address it is given.
* **Under the Hood**: On the client, React DOM writes our strings into text nodes and attribute values, which the browser never parses as markup; on the server, React escapes `<`, `>`, `&`, and quotes in the HTML it sends. The object form `{ __html }` exists so raw HTML can never reach the parser by accident from a plain string, and anything inside that raw HTML, including `onerror` attributes, is parsed and run by the browser exactly as written.
* **The Code Experiment**:
  * *Naive*: An `ArticleBody` that passes HTML from the admin page straight into `dangerouslySetInnerHTML`, where an injected `<img onerror>` runs script as soon as the article loads.
  * *React*: The same component sanitizing with `DOMPurify.sanitize` before rendering, contrasted with comments rendered as plain `{comment.body}` text, which needs no sanitizing at all.
* **Scope Boundary**: Focus on React's default escaping, the opt-out through `dangerouslySetInnerHTML`, sanitizing untrusted HTML, and the `javascript:` URL guard. Do not cover server-side security, Taint APIs, or Server Function authorization (Q130, Q149, Q162), or Content Security Policy configuration in depth.
