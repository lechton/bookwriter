# Q83: React HTML Components vs Raw HTML
* **Topic Tag**: `#html_components` | `❱❱❱ ADVANCED`
* **Interview Question**: *How do React's built-in HTML components differ from raw HTML?*
* **Core Truth**: Built-in JSX elements are JavaScript object descriptions that map to browser DOM nodes with property renames (`className`, `htmlFor`), synthetic event wiring, and enhanced React 19 capabilities for `<form>`, `<input>`, `<link>`, and `<meta>`.
* **The Friction**: A developer pastes raw HTML with `class="news-card"` and `<label for="input">` into JSX, triggering compiler warnings, while writing `style="color: red"` crashes the app with a type error because React expects a JavaScript style object.
* **The Mechanism**: JSX HTML mapping invariants: attribute renames (`class` -> `className`, `for` -> `htmlFor`), camelCase properties (`tabIndex`, `aria-*` and `data-*` retaining hyphens), object-based `style={{ color: 'red' }}`, and React 19 hoisted tags (`<title>`, `<meta>`, `<link>`) automatically managed in the document head.
* **Under the Hood**: Property vs Attribute mapping: JSX attributes map to DOM object properties (IDL attributes) rather than HTML string attributes; React 19 document metadata hoisting discovers `<meta>` or `<link>` anywhere in the component tree and moves them to `<head>` during commit.
* **The Code Experiment**:
  * *Naive*: Writing string-based inline styles (`style="margin-top: 10px"`) and using `class` and `for`, causing runtime errors and broken accessibility associations.
  * *React*: An `ArticleHeadMeta` component using `className`, `htmlFor`, object styles, and rendering `<title>` and `<link rel="canonical">` directly inside the component body, hoisted automatically by React 19.
* **Scope Boundary**: Focus on JSX attribute differences from HTML and React 19 built-in component enhancements. Do not cover SSR streaming serialization of HTML (Q101+).
