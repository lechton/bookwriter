# Q137: Progressive Enhancement: Submitting Forms Before Client Hydration
* **Topic Tag**: #progressive_enhancement | ❱❱ MORE (Server)
* **Interview Question**: *How do forms submit before hydration has even finished?*
* **Core Truth**: When a form with a Server Function action renders on the server, React generates a standard HTML <form action="..." method="POST"> with hidden fields, allowing the browser to submit native HTTP POST requests even if client JavaScript has not loaded or failed entirely.
* **The Friction**: During a live breaking news event in a low-bandwidth region, mobile readers attempt to submit an eyewitness tip through a newsroom form at The National Times while the client bundle is stuck downloading; if the form requires hydration, clicks do nothing; under progressive enhancement, the browser posts the form immediately.
* **The Mechanism**: Progressive form anatomy: <form action={submitTip}> renders as <form action="/?_rsc_action=..." method="POST"><input type="hidden" name="$$ACTION_ID" value="..." />...: native browser submits multipart form data; the server router intercepts the POST, executes submitTip(formData), and re-renders the page.
* **Under the Hood**: The duality of action dispatch: before hydration, native browser POST submits the form, and the server returns a new HTML document with updated state; after hydration, React intercepts the submit event, prevents full reload, and calls the action via fetch() while retaining client state.
* **The Code Experiment**:
  * *Naive*: Relying on onClick handlers or unenhanced onSubmit hooks that leave form inputs dead until large JavaScript bundles parse.
  * *React*: Using <form action={serverAction}> with standard named inputs (<input name="email" />), ensuring 100% reliable submission before hydration.
* **Scope Boundary**: Focus on progressive enhancement mechanics, what HTML React renders for actions, and how forms function in no-JS environments.
