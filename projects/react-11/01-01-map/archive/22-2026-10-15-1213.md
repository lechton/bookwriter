# Q22: Structuring State and Avoiding Redundancy
* **Topic Tag**: `#state_structure` | `❱ CORE`
* **Interview Question**: *How do you decide which values belong in state and which are derived?*
* **Core Truth**: State should hold the smallest set of values that change over time and cannot be computed from anything else; any value that can be calculated from props or other state during render is computed there instead of stored, so there is no second copy to fall out of sync.
* **The Friction**: A newsroom developer stores `articles`, `filterText`, `filteredArticles`, and `articleCount` as four separate `useState` variables. When an article is added, the developer forgets to update `articleCount` and `filteredArticles`, and the counter says "0 results" while five articles are displayed.
* **The Mechanism**: react.dev's structuring rules: group values that always change together (`position: { x, y }`); avoid contradictions (one `status` instead of `isSending` and `isSent`); avoid redundant state (compute `filteredArticles = articles.filter(...)` and `articleCount = filteredArticles.length` in the component body); avoid duplication (store `selectedId`, not a copy of the selected article object); and avoid deep nesting (store items flat, keyed by id, with child ids in arrays). A prop is copied into state only when we deliberately want its first value, and then it is named for that (`initialColor`).
* **Under the Hood**: Two copies of one fact need code that updates both on every change, and any missed path leaves them disagreeing on screen; a computed value cannot disagree, because it is recalculated on every render from the one stored source. A copied prop is worse: `useState(color)` reads `color` only on the first render, so later changes from the parent never reach the copy. Computing during render is usually cheap; when a measured calculation is slow, `useMemo` (Q56) caches it.
* **The Code Experiment**:
  * *Naive*: Keeping `filteredList` and `totalCount` in their own state and updating them with extra setter calls whenever `search` changes, plus a `selectedStory` object that keeps the old title after the story is edited.
  * *React*: A `StorySearch` component storing only `stories`, `query`, and `selectedId` in state, and calculating the filtered stories, the match count, and the selected story during render.
* **Scope Boundary**: Focus on the structuring rules: grouping, contradictions, redundant and derived values, duplication, flattening nested state, and mirrored props. Do not cover replacing Effects that synchronize derived state (Q33), `useMemo` (Q56), or resetting state with a `key` (Q24).
