# Q49: Layout Effects and Insertion Effects
* **Topic Tag**: `#use_layout_effect` | `❱❱ MORE`
* **Interview Question**: *When must code run after DOM updates but before the browser paints, and why is useInsertionEffect reserved for style libraries?*
* **Core Truth**: `useLayoutEffect` runs after React updates the DOM but before the browser paints, so code that measures layout and sets state again finishes before the reader sees the first frame; `useInsertionEffect` runs earlier still, before any layout effect, so a CSS-in-JS library can insert its `<style>` rules before any component measures. Application code uses `useEffect` by default, `useLayoutEffect` only to prevent a visible flicker, and `useInsertionEffect` practically never.
* **The Friction**: An editorial tooltip calculates its position relative to an article button. Placed in `useEffect`, the tooltip first paints at `top: 0, left: 0`, then measures the button and jumps to `top: 140px, left: 200px` one frame later, and the reader sees it flicker on every hover. Separately, a CSS-in-JS library that injects its rules inside `useLayoutEffect` races with that tooltip's measurement, so the tooltip measures before the styles exist and the browser recalculates layout again.
* **The Mechanism**: The `useLayoutEffect` hook (`useLayoutEffect(() => { const rect = buttonRef.current.getBoundingClientRect(); setCoords(rect); }, [])`), which React runs synchronously during the commit, re-rendering before the paint when it sets state. The `useInsertionEffect` hook (`useInsertionEffect(() => { insertStyleRule(rule); }, [rule])`), which can neither update state nor read refs, because refs are not attached yet when it runs.
* **Under the Hood**: Commit order: React updates the DOM and runs insertion effects, then layout effects run, then the browser lays out and paints, then `useEffect` runs. A state update inside a layout effect forces a synchronous re-render before the paint, which hides the intermediate position but also blocks the paint, so slow work in a layout effect makes every interaction feel slower.
* **The Code Experiment**:
  * *Naive*: Positioning a floating tooltip inside `useEffect`, causing a visible jump on every first render.
  * *React*: A `Tooltip` component using `useLayoutEffect` to measure the button and apply its offset before the first paint, next to a minimal style injector written with `useInsertionEffect` and labeled as library code.
* **Scope Boundary**: Focus on choosing among the three effect timings, measuring layout before paint, and why insertion effects belong to style libraries. Build on `useRef` (Q29), DOM refs (Q30), and `useEffect` (Q31) without re-teaching them; do not use layout effects for data fetching, and do not build a full CSS-in-JS library.
