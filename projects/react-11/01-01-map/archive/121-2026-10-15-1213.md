# Q121: Document Metadata: Hoisting Titles, Meta Tags, and Links
* **Topic Tag**: #document_metadata | ❱ CORE (Server)
* **Interview Question**: *How do you set titles, meta tags, and links with React components?*
* **Core Truth**: React 19 natively hoists <title>, <meta>, and <link> components rendered anywhere in the component tree into the document <head>, eliminating external head management libraries.
* **The Friction**: Editors at The National Times complain that social media preview cards on Twitter/X show generic homepage titles instead of article headlines; developers attempt to string-concatenate <head> tags in an Express template or use legacy external libraries that cause hydration mismatches and race conditions.
* **The Mechanism**: Native document metadata components: <title>{article.title}</title>, <meta name="description" content={article.summary} />, <link rel="canonical" href={url} /> rendered inside any deep component; React hoists them to <head> and deduplicates tags with matching rel or property.
* **Under the Hood**: React's <head> hoisting reconciler: when React encounters <title>, <meta>, or <link> during server rendering or client hydration, it intercepts these elements and places them directly into the document's <head>, managing precedence and automatically updating or cleaning them up when components unmount.
* **The Code Experiment**:
  * *Naive*: Using third-party head manager wrappers or document.title = ... in useEffect, which fails to render social meta tags into the initial server HTML.
  * *React*: Rendering <title> and <meta property="og:title" ... /> directly inside the ArticlePage component body, allowing React to hoist them into <head> automatically on both server and client.
* **Scope Boundary**: Focus on React 19's native metadata hoisting and deduplication. Do not confuse with client asset preloading APIs (preload, preinit, covered in Q126).
