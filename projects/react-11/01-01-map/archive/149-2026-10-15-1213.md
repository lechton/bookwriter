# Q149: The Taint APIs: Preventing Secret Leakage to Client Bundles
* **Topic Tag**: #security | ❱❱ MORE (Server)
* **Interview Question**: *How do the taint APIs mark values that must never reach the client?*
* **Core Truth**: React's Taint APIs (taintObjectReference and taintUniqueValue) explicitly mark sensitive objects and secret strings so that React throws a fatal error if they are ever passed as props to a Client Component or emitted into the RSC payload.
* **The Friction**: An editorial user profile object fetched from the database at The National Times includes hashedPassword and sessionToken; a developer passes the whole user object to an interactive <UserAvatar user={user} /> client component; the user's private session token is serialized into the public RSC payload and exposed in DevTools.
* **The Mechanism**: Taint APIs: (1) experimental_taintObjectReference(message, object): prevents passing the specified object reference to client components; (2) experimental_taintUniqueValue(message, lifetime, value): prevents passing a specific secret string (e.g. an API key or password) anywhere across the boundary.
* **Under the Hood**: Flight serialization blocker: during RSC payload generation, React's Flight serializer inspects each value against an internal set of tainted references and values; if a tainted object or value is encountered, the serializer immediately throws the registered error message and aborts serialization.
* **The Code Experiment**:
  * *Naive*: Relying on developers to remember to delete user.secretToken before passing objects to client components.
  * *React*: Tainting the user record (experimental_taintObjectReference('Do not pass user record to client', user)) immediately after database fetch, guaranteeing an immediate build/runtime error if passed to a Client Component.
* **Scope Boundary**: Focus on experimental_taintObjectReference and experimental_taintUniqueValue, what they protect, and how the Flight serializer enforces taint checks.
