# Q167: Flight Serialization Protocol: Encoding Types and Cyclic Structures
* **Topic Tag**: #serialization_protocol | ❱❱❱ ADVANCED (Server)
* **Interview Question**: *How does serialization encode client references, promises, and typed values across the wire?*
* **Core Truth**: React's Flight serialization protocol encodes rich JavaScript types using escape-prefixed strings ($D for Date, $Q for Map, $W for Set, $@ for Promise, $K for React Element) while detecting and rejecting cyclical object graphs and non-serializable prototypes.
* **The Friction**: A developer at The National Times creates an article data structure where article.author.articles references the original article; passing this cyclic data structure to a Client Component causes the server process to hang or crash with TypeError: Converting circular structure to JSON.
* **The Mechanism**: Flight type prefixes: $D (Date ISO string), $Q (Map entries), $W (Set entries), $n (BigInt), $@ (streaming Promise ID), $$ (escaped literal dollar sign); functions and cyclic references are explicitly detected and throw serialization errors.
* **Under the Hood**: Streaming serialization pipeline: unlike JSON.stringify which requires the entire tree in memory, Flight serializes object trees recursively while writing directly to the stream; when it encounters an unresolved promise, it emits a promise token and schedules a streaming task to emit the resolved value in a later row.
* **The Code Experiment**:
  * *Naive*: Attempting to serialize circular object graphs or complex class instances across the boundary, causing serialization halts.
  * *React*: Normalizing server data into acyclic structures and leveraging Flight's native $D (Date) and $Q (Map) encoding for rich type fidelity.
* **Scope Boundary**: Focus on the deep mechanics of the Flight serialization protocol, prefix markers, cycle detection, and streaming promise serialization.
