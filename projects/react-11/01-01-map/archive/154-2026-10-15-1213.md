# Q154: Handling FormData and File Uploads in Server Functions
* **Topic Tag**: #form_actions | ❱❱ MORE (Server)
* **Interview Question**: *How does a Server Function read submitted fields and files from FormData?*
* **Core Truth**: Server Functions invoked via <form action={fn}> receive a standard FormData instance containing all named form fields, including text entries, checkboxes, and File objects for file uploads, without requiring manual JSON parsing or multipart decoding libraries.
* **The Friction**: A citizen journalism submission portal at The National Times allows readers to upload an eyewitness photo along with a caption and location; developers attempt to write custom multer middleware and base64-encode files in client state, crashing when JavaScript fails to load on spotty mobile networks.
* **The Mechanism**: async function submitReport(formData: FormData): reads fields via formData.get('title'), formData.getAll('tags'), and extracts binary attachments via const file = formData.get('photo') as File; const bytes = await file.arrayBuffer();.
* **Under the Hood**: Multipart/form-data streaming: whether submitted natively via browser HTTP POST or intercepted by React's client fetch RPC, the request is transmitted as multipart/form-data; the server runtime parses the stream into a native FormData object with standard Web API File and Blob instances.
* **The Code Experiment**:
  * *Naive*: Encoding file uploads as base64 strings in JSON payloads over custom API endpoints, causing 33% payload bloat and high memory overhead.
  * *React*: Using native <form action={uploadAsset}> with <input type="file" name="attachment" />, accessing formData.get('attachment') directly as a File in the Server Function.
* **Scope Boundary**: Focus on consuming FormData (text, checkboxes, files) inside Server Functions and native multipart handling. Progressive enhancement was covered in Q112/Q137.
