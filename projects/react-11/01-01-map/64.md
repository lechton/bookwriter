# Q64: React Developer Tools: Components, Profiler, and useDebugValue
* **Topic Tag**: `#dev_tools_mastery` | `❱❱ MORE`
* **Interview Question**: *How do you inspect component trees, label and audit hook state, and profile renders with React Developer Tools?*
* **Core Truth**: React Developer Tools reads React's own component tree, not the DOM: the Components tab shows each component's props, state, hooks, and the owner that rendered it; the Profiler tab records commits and shows which components rendered, how long each took, and why; and `useDebugValue` gives a custom hook a readable label in the Components tab.
* **The Friction**: The site's search box lags while the reader types. The developer floods the console with `console.log` calls, then wraps random components in `memo` without knowing which one is slow. Opening the Components tab does not help either: the team's `useArticleSubscription` hook appears as an anonymous stack of `State` and `Effect` rows, so nobody can tell which value belongs to it.
* **The Mechanism**: The Components tab (inspecting and editing props and state, the "rendered by" owner chain, and the "Highlight updates when components render" setting); the Profiler tab (recording an interaction, the flamegraph for each commit, the ranked chart, and the "Record why each component rendered while profiling" setting); the `<Profiler id="SearchResults" onRender={onRender}>` component for timing in code; and `useDebugValue(isOnline ? 'Online' : 'Offline')`, with a formatter for expensive labels: `useDebugValue(date, (d) => d.toDateString())`.
* **Under the Hood**: The extension installs a global hook, `__REACT_DEVTOOLS_GLOBAL_HOOK__`, before the page's scripts run, and React reports every commit to it, so inspection needs no changes to application code. In the Profiler, `actualDuration` is the time spent rendering the committed subtree and `baseDuration` estimates re-rendering the whole subtree with no memoization, so comparing them shows what memoization saves; profiling a production build requires React's profiling build. The `useDebugValue` formatter runs only while DevTools inspects the component.
* **The Code Experiment**:
  * *Naive*: Guessing the bottleneck by sprinkling `console.time()` calls and wrapping innocent components in `memo`, with no measurement before or after.
  * *React*: Recording a typing session in the Profiler, finding `MarkdownPreview` at the top of the ranked chart with "props changed: options" as the reason, and adding `useDebugValue` inside a `useOnlineStatus` hook so its value reads "Online" in the Components tab.
* **Scope Boundary**: Focus on the DevTools workflow (Components and Profiler tabs), the `<Profiler>` component, and `useDebugValue`. Do not re-teach the memoization fixes (Q55 to Q57) or the React Compiler (Q63), and do not cover the browser's Performance panel CPU profiling in depth.
