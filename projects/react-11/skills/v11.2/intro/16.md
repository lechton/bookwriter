# Lecture 16: Batching and Updater Functions

*(When you call `setScore(score + 1)` three times in one click, why does the score go up by `1` instead of `3`?)*

> INTERVIEW QUESTION | ❱ CORE | How does React queue multiple state updates, and when do you need an updater function?

---

## Next State Value `score + 1` vs. Updater Function `s => s + 1`: passing `score + 1` replaces the state, while an updater function `s => s + 1` builds on the previous update in the queue

First, let's set the four building blocks this lesson stands on:

1. **State and its setter** come from `useState`: state is the value React keeps for a component between renders, and the setter, such as `setScore`, asks React to update that value (Lesson 12).
2. **A render** is React calling your component function to ask what JSX should appear on the screen (Lesson 13).
3. **A snapshot** is the fixed copy of state that one render hands to your code. Calling `setScore` never changes the `score` variable inside the handler that is already running (Lesson 15).
4. **A pure function** is a function that only calculates its result from its inputs and changes nothing outside (Lesson 14).

In plain JavaScript, if you add `1` to a variable three times in a row, the variable goes up by `3`.

React state setters break this rule.

When you call `setScore` inside an event handler, React does not stop your handler to re-render the screen right away. Instead, React places each update into a waiting line called a **queue**. React waits until every line of your event handler has finished, then runs all the queued updates together in one single render. React's docs call this **batching**, because it prevents your component from rendering a "half-finished" screen after each setter call.

What happens when React walks that queue depends on what you pass to `setScore`:

- When you pass a plain value like `setScore(score + 1)`, you are telling React: *"Replace the score with `1`."*
- When you pass a function like `setScore(s => s + 1)`, you are telling React: *"Take whatever the score is at this point in the queue, and add `1` to it."*

React's docs call a function passed to a setter an **updater function**, and they give the update queue two rules:

1. **React waits until the whole event handler finishes before processing the state updates.** In the docs' words, "React waits until all code in the event handlers has run before processing your state updates." React batches all setter calls from one click into a single render, and it never batches across two separate clicks.
2. **An updater function receives the pending state from the update queued before it.** In the docs' words, "React queues this function to be processed after all the other code in the event handler has run." During the next render, React calls each queued updater function in order. It takes the return value of the first updater (the **pending state**) and passes it as the input `s` to the next updater in line.

**Beware! Calling `setScore(score + 1)` three times in one click does not add `3`. It tells React to replace the score with the exact same number three times.**

### What happens when you give the setter three updates in one click?

Think of a waiter at a restaurant. You do not see the waiter run to the kitchen after the first word you say. The waiter stands at your table, writes every line of your order on a notepad, and walks to the kitchen once at the end.

In a component, "the notepad" is the update queue that React reads from top to bottom during the next render:

1. **Passing the next value `setScore(score + 1)` three times.** It is like telling the waiter: *"Make my order 1 coffee. Make my order 1 coffee. Make my order 1 coffee."* Each line overwrites the line before it, so the kitchen makes `1` coffee. In React, every line in your handler reads the same snapshot (`0`), so all three calls put *"replace with `1`"* into the queue.
2. **Passing an updater function `setScore(s => s + 1)` three times.** It is like telling the waiter: *"Add 1 coffee to my order. Add 1 more. Add 1 more."* Each instruction builds on the one before it, so the kitchen makes `3` coffees. In React, the first updater turns `0` into `1`, the second receives `1` and returns `2`, and the third receives `2` and returns `3`.

Passing a plain value like `setScore(score + 1)` is completely fine when your click handler updates `score` only once per click, because there are no earlier updates in the queue for it to overwrite.

### Calling `setScore(score + 1)` Three Times in One Click: all three calls read `score` at `0`, so the `+3` button adds `1` instead of `3`

**Beware! If a helper function calls `setScore(score + 1)` and you call that helper three times in one click, the second and third calls overwrite the first one instead of adding to it.**

Developers write small helper functions all the time so they do not repeat the same code in multiple buttons. A shopping cart has an `addOneItem` helper that a "Buy 3-pack" button calls three times. A game scoreboard has an `addPoint` helper that the `+1`, `+2`, and `+3` buttons share. If that helper passes `score + 1` instead of an updater function, calling it three times in one click changes the screen by only `1`.

Let's see what calling `setScore(score + 1)` three times does to a real page. On a basketball scoreboard, the screen shows the home team's `score` (starting at `0`) and a `lastPlay` line underneath (starting at `'Game start'`). The developer writes a helper named `addPoint` that calls `setScore(score + 1)`. When the scorekeeper clicks the `+3` button, the click handler `handleThree` does two things:

1. It calls `addPoint()` three times in a row to add three points.
2. On the last line, it calls `setLastPlay('Three-pointer')` to update the play line.

At the start of the game, the board shows `Home: 0`. Then a player hits a three-point shot, and the scorekeeper clicks `+3`:

```page width=text caption="After one click on +3: the play line says Three-pointer, but the score only went up by 1."
heading: Scoreboard
line: Home: 1 | bad
line: Last play: Three-pointer | good
line: [+1] [+2] [+3]
```

**The page now displays the wrong score.** The play line says `Last play: Three-pointer`, yet the score moved from `0` to `1` instead of `3`.

Here is what went wrong, step by step:

1. **React renders the scoreboard with `score` at `0`:** The snapshot for this render locks `score` at `0`.
2. **The scorekeeper clicks `+3` and `addPoint()` runs three times:** The first call reads `score` (`0`), calculates `0 + 1`, and puts *"replace with `1`"* in the queue. Because `score` never changes inside a running handler, the second and third calls also read `0` and put *"replace with `1`"* in the queue two more times.
3. **The handler updates the play line and finishes:** The last line puts *"replace with `'Three-pointer'`"* into the `lastPlay` queue.
4. **React batches the queues and renders once:** React walks the `score` queue from top to bottom. All three slips say *"replace with `1`"*, so the screen updates to `Home: 1` and `Last play: Three-pointer`.

**This bug hides in two ways.** First, the `+1` button works fine because it calls `addPoint()` only once per click, and the Console shows zero errors or warnings. Second, if a developer tries to debug the updater by putting `console.log` inside `setScore(s => { console.log(s); return s + 1; })`, `<StrictMode>` calls every updater function twice in development to check that it is pure. The Console prints six logs for one click while the board shows `Home: 3`, tricking the developer into thinking the updater ran six times for real.

### The Rule of Thumb: `setScore(score + 1)` overwrites earlier updates in the same click, so pass `s => s + 1` whenever updates stack up

**When a click updates the same state variable more than once before the next render, pass an updater function `s => s + 1` so each update builds on the pending state before it.** React's docs state how React walks the queue: if a queued item is a function, React calls it with the pending state; if it is a plain value, React replaces the pending state with that value.

At the end of the day, a senior developer follows three rules:

1. **Updating the same state multiple times in one click? Pass an updater function `s => s + 1`.** In a developer's mind, calling `setScore(score + 1)` three times and calling `setScore(s => s + 1)` three times look like they do the same job: both say "add one". They are NOT the same! `setScore(score + 1)` calculates `0 + 1` right now from the frozen snapshot and queues *"replace with `1`"* three times. `setScore(s => s + 1)` hands the function to React so each step adds `1` to the pending state `s` (`0 -> 1 -> 2 -> 3`).
2. **Never mix a plain value update after an updater function for the same state.** If a handler calls `setScore(s => s + 1)` first and `setScore(score + 2)` second on the next line, the plain value `score + 2` runs second in the queue. It ignores the `1` from the updater and overwrites the score with `0 + 2` (`2` instead of `3`). When helpers for the same state can run in the same click, write all of them with updater functions.
3. **Keep updater functions pure, and put `console.log` outside the setter.** Because an updater function is written inside your click handler, it looks like click-handler code. It is NOT! React runs updater functions during rendering, and `<StrictMode>` calls each updater twice in development (keeping one result) to catch side effects. Never put `console.log`, network calls, or other setters inside `s => { ... }`. Put them in the event handler above `setScore`.
