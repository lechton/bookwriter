# Brief 2026-11-05 02: the runtime check moves from the map to the lecture

Tag: #2026_11_05_02_group_1

## Why

The Lesson 15 bookflow run showed the map writer building its own React and Vite project in headless Chrome to test the map's facts. It built two of them in `/tmp`, about 74 MB each, with several driver scripts and dev server logs. Two problems follow. The tokens go into setting up a project again for every lesson. And the test protects the wrong text: the first draft and the simplified lecture are written after the map, and either can change a code block, a preview, or an error string. Stage B only asked the simplifier to reread its own work. The owner decided to test the final lecture instead, in one test project that stays installed inside react-10.

## What changed

- `lab/` is new: one React 19.3.1, React DOM 19.3.1, Vite 8.3.6, and `@vitejs/plugin-react` 6.2.1 project, installed once with `npm install`, with Puppeteer bringing its own Chrome. `node lab/check.mjs <case>` runs one case and prints the screen, the Console, the Vite overlay, and Vite messages, with options for clicks, StrictMode off, a production build, JavaScript in the page, the `#root` HTML, and a screenshot. Cases live in `lab/cases/{NN}/`, reports in `lab/reports/{NN}.md`. `lab/README.md` explains it.
- `v1/map-principles/SKILL.md`: the map takes runtime facts and exact strings from the corpus, quoted with their page. A string the corpus does not give is marked `unconfirmed`, so the check of the lecture finds the real one. The pipeline table gains step 4, and the Completion Gate item changes to match.
- `v1/verification/SKILL.md`: Stage B keeps B1 and B2, the reading gates. The new Stage C runs every runtime claim of the lecture in `lab/`, fixes the lecture where it differs, and then runs the build, links, and files gates, which move unchanged from B3, B4, and B5 to C3, C4, and C5 and keep their original tag. C6 writes the report last. A format sample and the Lesson 15 run as counter-example come with it.
- `README.md`: the pipeline table gains step 4, the gates line names Stage C, and the source rule covers the runtime check.
- `notes/prompt_v10.1.md`: Step 1 no longer uses headless Chrome, Step 3 no longer builds, and a new Step 4 runs the check in a fresh Opus thread and builds.
- In the factory repo, the `bookflow` workflow gains the `lesson.check` step with its own `checker.md` prompt and an Opus default model (`checker_model=` changes it). The mapper prompt drops its headless Chrome step, and the simplifier prompt no longer builds. A lesson whose lecture exists and has no `lab/reports/{NN}.md` goes to the check; a lesson with a report and no HTML goes to the build.

## Lessons already written

Lessons with HTML and PDF are complete as before, and `next=` still picks only lessons without HTML, so lectures 01 to 14 are not checked by this change. The Lesson 15 map, written on 2026-11-05 with the old rule, is kept as it is.

## How to trace or revert

Grep `#2026_11_05_02_group_1` for every rule of this batch. Reverting means restoring Section 3 item 1 and the React Does field of `map-principles`, folding Stage C back into Stage B as B3 to B5, removing step 4 from the two tables and the prompt, and deleting `lab/`.
