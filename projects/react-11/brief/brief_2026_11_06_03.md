# Brief 2026-11-06 03: Skills `v10.4`, explain what the lesson is about and stop touring the code

## Why this batch exists

The owner found that Lecture 21, the first lecture written from scratch under `v10.3`, read like a line by line tour of its code. Lecture 20, rewritten under `v10.3` the same evening, showed the same problem in a milder form.

In Lecture 20, the opening defined one code word after another, in four paragraphs, before the reader had seen any box do anything. One paragraph held `value`, `name`, `onChange`, `e`, `e.target`, and `e.target.value`. Two of those, `e.target` and the setter, were taught in Lessons 11 and 12.

In Lecture 21, a lesson about state, Principle 1 explained `classList`, `disabled`, `Promise`, `resolve`, `reject`, `===`, `length`, `async`, `await`, `try`, `catch`, and `finally`, because the plain JavaScript example brought them in. The phrase "in order" or "step by step" appears 19 times, against 4 to 8 in Lectures 17 to 19. Most step lists follow a code block with no question before them, and some read a single line aloud.

A comparison of Lectures 17 to 21 and the archived `v10.2` copy of Lecture 20 showed that the problem starts with `v10.3`. Before it, a new code word came in through a confusion, a contrast, or an everyday picture, and step lists answered a question the reader was already asking.

The cause was in the skills, not in the writer:
- `writing` Section 2 asked for a sentence for every new code word, with no limit. It did not tell the lesson's own words from words already taught or helper words.
- `writing` Section 3 asked for steps before every result, not only before a surprising one.
- The `map` fields New code words and What happens, in order handed the writer a word list and a step list for every principle. Map 21 listed eight helper words for Principle 1.
- The `v10.2` rule against reciting the code block survived only as "Do not repeat the names of a code block in the sentence above it, unless a name is new". Section 2 made almost every name new, so the rule did nothing.
- `check` Step B and `writing` Section 11 asked only what was missing, never what was too much.
- Every counter-example pointed in one direction, too little explanation.

So `v10.4` narrows the two rules, brings back the reciting rule, and makes the reads look both ways. Following Prune Before Banning, no rule was added where an existing rule could be narrowed.

## Groups

### #2026_11_06_03_group_1: Explain the lesson's words when the reader needs them

### #2026_11_06_03_group_2: Steps answer a surprise
- `writing` Section 3: steps come after the reader's question and show what the code does not show. A line the reader can read needs no steps. Counter-example: the Lecture 21 walk through one line.

- `map` Section 4: What happens, in order becomes Surprises and their steps.

### #2026_11_06_03_group_3: The code block carries the names

### #2026_11_06_03_group_4: The reads look for too much as well as too little
