# Brief 2026-11-15 001: keep a copy before every skill edit, and number briefs with three digits

## Why
The owner wants safety in tracing earlier versions of every skill edit. Git keeps only what is committed, and skill edits often stay uncommitted for a while, so the old text could be lost. The owner also wants three digits in the names of briefs and copies, for days with many edits.

## Group 1, #2026_11_15_001_group_1, skills/v11.3/editing-skills/SKILL.md
New section "Keep a copy before every edit", with the owner's words. Before any change to a file in skills/v11.3/, the file is copied unchanged into skills/archive/v11.3/, in the same folder path, named with the file name, the date, and a three-digit number from 001. The brief of the edit names each copy. Files in archive/ are old versions, never current rules.

## Group 2, #2026_11_15_001_group_2, skills/v11.3/editing-skills/SKILL.md
Item 6 of "How to edit a skill": tags become #YYYY_MM_DD_NNN_group_M and briefs brief_YYYY_MM_DD_NNN.md, three digits from 001. Older briefs and tags keep their two-digit names.

## Group 3, #2026_11_15_001_group_3, AGENTS.md (workspace)
"Writing a Brief" now names briefs with three digits from 001. "Rule Authoring" gets one reminder line that points to the new section and says the archive/ files are never current rules.

## Group 4, #2026_11_15_001_group_4
This brief, its row in brief/01_TOC.md, and four rows in skills/v11.3/RULE-TAGS.md.

## How to trace or revert
Search for 2026_11_15_001 in skills/v11.3/ and AGENTS.md. The copies made before this edit are skills/archive/v11.3/editing-skills/SKILL_2026_11_15_001.md and skills/archive/v11.3/RULE-TAGS_2026_11_15_001.md. To revert, restore those two copies, remove the two lines in AGENTS.md, and remove this brief and its table row.
