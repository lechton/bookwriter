### 2. The changes made to the owner's text, and why

1. **Every em dash became a colon or a pair of commas**, by the workspace law: for example "`item.quantity = 2`: this doesn't work", "guess what: `setItem` does not care", "your old state, and even `initialItem`, still shares".
2. **Brackets became commas**, because the build counts brackets in the text as violations: "all the old fields, `quantity: 1` and `giftWrap: false`"; "a `To` box, which updates `item.recipient`, and a `Message` box, which updates `item.message`"; "`name="recipient"` and `name="message"`".
3. **Italics and bold inside the Summary became capitals**, because the build reads the Summary as one italic line: "AFTER it", "EVERY object", "ONE shared `handleChange` function".
4. **The two numbered steps of the Principle 4 Description became "First, ..." and "Second, ..."**, because the build joins the text of a card into one paragraph, so a numbered list would run together.
5. **Each comment moved from its own line to the end of the code line it explains**, because the build draws a comment as a bubble under its line and flags a highlight without one. The words of the comments are the owner's.
6. **In the Principle 4 DO THIS block, only the first `name=` is highlighted**, so every highlight has its comment bubble.
