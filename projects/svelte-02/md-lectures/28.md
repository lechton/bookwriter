# Lecture 28: Await Blocks
> INTERVIEW QUESTION | ❱ CORE | How do you handle loading, success, and error states when fetching data?

1. You are fetching a list of users from a remote database for an admin dashboard.
2. You write a function that calls an API and assigns the result to a variable.
3. How do we wait?
4. A blank screen confuses users who assume the app has frozen completely.
5. It is exhausting to manually juggle separate state variables for loading, success, and error.
6. We will learn how to let the template handle the sequence natively.

### The Boolean Juggling Trap
When fetching data from an external server, the network request takes time to complete. During this wait, the interface needs to reflect what is happening. Your first instinct might be to create three separate state variables to track the progress of the request, manually toggling them as the promise resolves or rejects.

```components title="Fetching Data — Component Explorer"
App.svelte | | shell
  ManualFetch.svelte | | generic | **Loading...**
  NativeFetch.svelte | | generic | **Loading users from database...**
```

Both boxes paint a waiting screen first, each with the exact words its template prints. The difference between the two versions lives in the script, never on the screen.

When you manage the loading lifecycle manually, you clutter your component's script block with boilerplate. You have to remember to set the loading state to true, catch any errors, and finally flip the loading state back to false regardless of the outcome. 

```svelte title="ManualFetch.svelte"
<script>
  let data = $state(null);
  let loading = $state(true);
  let error = $state(null);

  async function loadUsers() {
    try {
      const res = await fetch('/api/users');
      data = await res.json();
    } catch (err) {
      error = err.message; // ✖️ managing three states **manually** is prone to bugs
    } finally {
      loading = false;
    }
  }

  loadUsers();
</script>

{#if loading}
  <p>Loading...</p>
{:else if error}
  <p>Error: {error}</p>
{:else}
  <ul>
    {#each data as user}
      <li>{user.name}</li>
    {/each}
  </ul>
{/if}
```

This approach works, but it requires maintaining three synchronized variables. If you ever need to refetch the data, you must manually reset the error and loading states back to their initial values. Furthermore, if you trigger multiple fetches in rapid succession, you risk race conditions where an older request overwrites the data of a newer one.

### The Native Await Block
Svelte provides a dedicated block syntax specifically designed to consume promises directly in your markup. Instead of resolving the promise in your script and updating separate variables, you assign the raw promise to a single variable and hand it off to the template.

```svelte title="NativeFetch.svelte"
<script>
  let usersPromise = fetch('/api/users').then(res => res.json()); // ✔️ store the **promise** directly instead of resolving it manually
</script>

{#await usersPromise}
  <p>Loading users from database...</p>
{:then users}
  <ul>
    {#each users as user}
      <li>{user.name}</li>
    {/each}
  </ul>
{:catch error}
  <p>Error fetching users: {error.message}</p>
{/await}
```

The `{#await}` block dramatically simplifies your code by combining the loading, success, and error branches into a single, cohesive structure. It automatically extracts the resolved value into the `users` variable within the `{:then}` block, and passes any thrown exception to the `error` variable in the `{:catch}` block. 

> [!TIP]
> **To impress the interviewer:** Mention that the `{#await}` block automatically ignores out-of-order responses if the promise variable is reassigned before the first request finishes, eliminating race conditions entirely.

### Summary
Handling asynchronous data fetching requires coordinating multiple states, but you do not have to write that coordination yourself. Svelte's native template blocks are built to consume promises directly and securely.
- Never manually track loading and error states with separate variables if you can avoid it.
- Store the raw promise in your script and let the template resolve it.
- Use the `{#await}` block to define the pending state UI.
- Use the `{:then}` block to define the success state UI.
- Use the `{:catch}` block to safely render any errors.
