# Lecture 29: Lifecycle Hooks
> INTERVIEW QUESTION | ❱ CORE | How do you run code once when the component first appears, and once when it's removed?

1. You are building a live chat widget for a customer support dashboard.
2. The widget opens a persistent connection to receive new messages in real time.
3. When does it connect?
4. A connection opened too early fails because the chat window does not exist yet.
5. A connection left open after the window closes leaks memory and drains server resources.
6. We will learn how to trigger setup and teardown at the exact right moments.

### Component Lifespans
Every component has a distinct lifecycle. It is created, it enters the document, it updates as data changes, and eventually it is destroyed and removed from the screen. When integrating with external systems like third-party libraries, network requests, or timers, you need precise control over the moment a component enters and leaves the page.

Svelte provides a dedicated hook to execute logic exactly once when the component first renders into the DOM. This ensures that any elements you need to target actually exist, and prevents redundant network requests if the component updates later.

```svelte title="ChatWidget.svelte"
<script>
  import { onMount } from 'svelte';
  let messages = $state([]);
  let status = $state('connecting');
  
  onMount(() => {
    const socket = new WebSocket('wss://api.example.com/chat'); // ✔️ initialize the **connection** only when the component enters the DOM
    socket.addEventListener('open', () => status = 'connected');
    socket.addEventListener('message', (e) => messages.push(e.data));
    
    return () => {
      socket.close(); // ✔️ return a **cleanup** function to run when the component leaves the DOM
    };
  });
</script>

<p>Status: {status}</p>
<ul>
  {#each messages as msg}
    <li>{msg}</li>
  {/each}
</ul>
```

The `onMount` function accepts a callback that runs immediately after the component is added to the DOM. If you return a function from this callback, Svelte will automatically execute it the moment the component is destroyed. This pattern pairs the setup and teardown logic perfectly together in a single visual block, making it impossible to forget the cleanup step.

### Destructor Independence
While returning a cleanup function from the mount hook is the cleanest pattern, sometimes you have destruction logic that is completely independent of the initial setup. Svelte also provides a standalone hook for these scenarios.

```svelte title="ChatWidget.svelte"
<script>
  import { onDestroy } from 'svelte';
  
  onDestroy(() => {
    console.log('Chat widget was removed from the DOM'); // ✔️ use the standalone hook for independent **teardown** logging
  });
</script>
```

You can call these lifecycle functions from anywhere in your script, or even extract them into shared helper modules, as long as they are executed synchronously during the component's initialization phase. 

> [!TIP]
> **To impress the interviewer:** Mention that while `$effect` can also run code on mount and return a cleanup function, `onMount` is explicitly designed for initialization logic that should never re-run. Unlike an effect, `onMount` intentionally does not track reactive dependencies, guaranteeing it fires exactly once.

### Summary
Connecting and disconnecting from external resources must be tightly bound to the visual presence of a component. Svelte's lifecycle hooks guarantee that your setup logic only runs when the component is ready, and your teardown logic always fires when the component leaves.
- Import `onMount` from the `svelte` package to run code after the first render.
- Return a function from `onMount` to handle teardown operations like clearing intervals or closing sockets.
- Grouping setup and cleanup together prevents memory leaks and missing reference bugs.
- Use the standalone `onDestroy` hook for teardown logic that does not belong to a specific setup sequence.

| | **SETUP**<br>(mount) | **TEARDOWN**<br>(unmount) |
| ---: | :--- | :--- |
| **Hook** | `onMount` | Cleanup function |
| **Timing** | After first render | Before component removal |
| **Use case** | Fetching data, connecting | Clearing timers, disconnecting |
