Lecture 32: Complex Derivations with $derived.by

Interview Question

CORE

How do you write a derived value that needs multiple statements, loops, or try/catch?

Imagine this scenario:

  1. A journalist files one more story at the end of the night at the National Times. The paper pays by the word.
  2. The page shows one payout total under the story list. That total counts the words of every story, because the paper pays by the word.
  3. The new story lands on the list.
  4. But the payout total still shows the old number. Why does it not move?
  5. The correct total is a derived value, a number computed from other data. This one needs steps: visit every story, add its words, skip any story with no word count.
  6. One line cannot hold those steps.
  7. Svelte has a second form of the same tool, one that takes a whole function. Inside it, loops and safety checks are just normal JavaScript.

The Payment That Does Not Fit on One Line

The National Times pays its freelance writers per story: the number of words in the piece times a rate per word. One story is a one line calculation, and the tool you already know handles it. The $derived rune, a Svelte function whose name starts with a dollar sign, wraps an expression and recalculates the value automatically whenever the inputs inside that expression change.

PayoutBoard.svelte
1<script>
2 let words = $state(800);
3 let rate = $state(0.5);
4 let payout = $derived(words * rate);
RIGHT: one multiplication, one line, stays IN sync.
5</script>
6<p>Payout for this story: {payout}</p>

Now the night ends. Forty stories were filed, the payout board must show one total for all of them, and the one line form hits a wall. The total needs a loop that walks the list of stories, a running sum held in a temporary variable, and a guard so that one broken record, a story filed without a word count, cannot turn the whole board into garbage. You could force it all into one crowded chain of array methods, but the moment a guard becomes necessary that chain breaks. An expression is exactly one computation; it has no room for steps.

Look at the board that owns this problem. One component, PayoutBoard.svelte, holds the stories array in its script, and the rendered surface on the right shows the story list with the payout total underneath.

The annotation names the value that must change when the list changes: totalPayout, one number derived from many records. The board needs a calculation with steps, and the $derived rune has a second form built for exactly that.

A Second Form That Takes a Whole Function

The second form is written $derived.by, and instead of an expression it accepts a function. Between the braces you write a normal JavaScript function body: statements, loops, and temporary variables, in any order, as many as you need. The function must end by returning the value, and that returned value is what the board displays.

PayoutBoard.svelte
1<script>
2 let stories = $state([
3 { title: 'Harbor strike', words: 800, rate: 0.5 },
4 { title: 'Election night', words: 1200, rate: 0.5 },
5 { title: 'City budget', words: 950, rate: 0.5 }
6 ]);
7 let totalPayout = $derived.by(() => {
8 let subtotal = 0;
RIGHT: a TEMP variable that lives only inside this function.
9 for (const story of stories) {
RIGHT: a FULL loop, impossible in a one line expression.
10 subtotal += story.words * story.rate;
11 }
12 return subtotal;
The RETURN value is what the board shows.
13 });
14</script>
15<p>Total payout tonight: {totalPayout}</p>

The dependency rule from the one line form carries over unchanged. Anything the function reads synchronously, meaning any value read while the function is actually running, counts as a dependency of the derived value. Here the body reads the stories array, so stories is the dependency. When a writer files a new story and the array changes, Svelte marks totalPayout as dirty, a stale value that needs a fresh run, and re-executes the function the next time the board reads the total. This is push-pull reactivity: the change is pushed as a notification to everything that depends on the array, and the actual calculation is pulled only when the value is read. Nothing runs for values nobody looks at.

A Safety Net for Broken Records

Every newsroom has a damaged record: a story filed in a rush without a word count. Multiplying a missing count by a rate produces NaN, the JavaScript value for "not a number", and that NaN then poisons the whole sum. The board shows a payout of NaN and the accounting desk panics. In the one line form you have no room for a guard. Inside a function body you have the full JavaScript toolkit for errors: throw to flag a bad record and try/catch to catch the problem and substitute a safe value.

PayoutBoard.svelte
1<script>
2 let stories = $state([
3 { title: 'Harbor strike', words: 800, rate: 0.5 },
4 { title: 'Election night', rate: 0.5 }
5 ]);
6 let totalPayout = $derived.by(() => {
7 try {
8 let subtotal = 0;
9 for (const story of stories) {
10 if (!story.words || !story.rate) {
11 throw new Error('Damaged story record');
RIGHT: FLAG the bad record instead of computing garbage.
12 }
13 subtotal += story.words * story.rate;
14 }
15 return subtotal;
16 } catch {
17 return 0;
RIGHT: the GUARD keeps one broken record from breaking the whole board.
18 }
19 });
20</script>
21<p>Total payout tonight: {totalPayout}</p>

The damaged record throws, the catch block catches it, and the board shows zero instead of NaN. The editors fix the record in the morning; tonight the page stays alive. Note that this is still a pure calculation: the function reads the list and returns a number, and it never writes to any state.

Two Forms, One Machine

The two forms are not two different tools. $derived(expression) is shorthand for $derived.by(() => expression): the one line form wraps your expression in a function under the hood. Both share one dependency tracker, one dirtiness system, and one rule set. Pick the expression form for a single computation, and reach for the function form the moment the calculation needs more than one step.

That shared rule set includes one hard limit. Svelte disallows state changes inside a derived value, in both forms. A derived function must be a pure calculation: read inputs, return a value, touch nothing else. If you find yourself wanting to update state from inside the function, that work belongs in an event handler or an effect, not in the derived value, because a calculation that secretly writes state can loop forever and the board would never settle on a number.

Interview Tip

To impress the interviewer: Say that $derived(expression) is sugar for $derived.by(() => expression), so the two forms share one dependency tracker. Anything read synchronously inside the function body becomes a dependency, the body re-runs only when a dependency changes and the value is next read, and Svelte forbids state writes inside a derived, which is what keeps it a pure calculation. Then note that try/catch, loops, and temporary variables are only reachable through the function form.

Key Takeaway

When the calculation needs more than one expression, swap $derived(expr) for $derived.by(() => { ... }). Everything between the braces is a plain JavaScript function, loops and safety nets included.

Summary

The $derived rune computes a value from one expression and keeps it in sync with its inputs. When the calculation needs multiple statements, a loop, a temporary variable, or error handling, use the $derived.by form, which accepts a whole function. The function body is ordinary JavaScript: anything it reads synchronously becomes a dependency, and Svelte re-runs it when a dependency changes and the value is next read. The two forms are one machine, so the expression form is simply shorthand for the function form, and both must stay free of side effects.

  • $derived(expr) handles one expression; $derived.by(() => { ... }) handles a whole function body.
  • Inside the body you can declare temporary variables, run loops, and use try/catch.
  • Anything read synchronously in the body becomes a dependency; the body re-runs only when a dependency changes and the value is read.
  • Svelte disallows state changes inside a derived, in both forms, so the function stays a pure calculation.
  • $derived(expression) is shorthand for $derived.by(() => expression).
