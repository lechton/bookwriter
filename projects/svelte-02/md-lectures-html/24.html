Lecture 24: Objects and Arrays in $state

Interview Question

CORE

How do you store and update objects and arrays in $state?

You declared a user variable holding a state object with a name property and tried to update the name directly. Does it actually work? What happens when you try pushing a new item to a state array? Imagine you are building the breaking news dashboard for the National Times. A massive election story drops, field reporters are filing raw updates by the second, and your component needs to render a rapid fire list of incoming dispatch objects. You declare your state array and try to push a new dispatch object into it, or you try to update the timestamp property of an existing dispatch deep inside that list. If you expect the framework to ignore these deep mutations because they do not replace the entire top level variable, you will be surprised when the dashboard lights up with the fresh data perfectly synchronized. The mechanism that makes this work is deep proxying, and understanding how it treats objects and arrays is the difference between a real time dashboard and a stale, broken screen.

Before the code, fix the ownership map in your head: one component, NewsDashboard.svelte, owns both reactive values. The breakingStory object and the dispatches array are declared in its script, and everything the reader will see on the right side of the panel below, the headline, the logging button, and the growing dispatch list, is the rendered surface that reads those two values.

State: Deep Proxying

When you pass an object or an array into the state rune, Svelte does not just monitor the top level variable for complete replacements. Instead, it recursively wraps the data in a Proxy, which is a native JavaScript feature that intercepts reads and writes to the underlying data structure. This means Svelte is actively listening whenever you mutate a property deep inside the object or modify an array using its standard built in methods. You do not need to clone the array, spread the old values into a new object, or manually reassign the top level variable just to trigger an update. The framework tracks the exact property you touched and updates only the parts of the user interface that depend on that specific piece of data.

NewsDashboard.svelte
1<script>
2 let breakingStory = $state({ headline: 'Election Called', updates: 0 });
3 let dispatches = $state([]);
4 function logUpdate(text) {
5 breakingStory.updates += 1;
Deep property mutation triggers an update automatically
6 dispatches.push({ id: Date.now(), text });
Array push is intercepted and triggers an update
7 }
8</script>
9
10<h2>{breakingStory.headline} ({breakingStory.updates} updates)</h2>
11<button onclick={() => logUpdate('Polls open')}>Log Dispatch</button>
12<ul>
13 {#each dispatches as dispatch (dispatch.id)}
14 <li>{dispatch.text}</li>
15 {/each}
16</ul>

The code you write reads exactly like plain, vanilla JavaScript. Because the array itself is a reactive proxy, calling the push method directly notifies the framework that the list has changed, and the user interface updates instantly. The exact same rule applies to the updates counter nested inside the breaking story object. The proxy intercepts the increment operation and surgically updates the heading element in the DOM without requiring any extra ceremony or special framework methods.

State: Destructuring Disconnect

The deep proxy magic is powerful, but it only works as long as you perform your mutations on the proxied object itself. If you destructure a primitive property out of a state object, you physically sever the reactive connection. The destructured variable becomes a plain, isolated value that is completely unaware of the proxy it originally came from, and changing this disconnected copy will never update the screen.

NewsDashboard.svelte
1<script>
2 let breakingStory = $state({ headline: 'Election Called', updates: 0 });
3 function renameStory(newHeadline) {
4 let { headline } = breakingStory;
5 headline = newHeadline;
Mutates a disconnected string, the user interface remains stale
6 breakingStory.headline = newHeadline;
Mutates the property on the proxy, triggering an update
7 }
8</script>

When you destructure a primitive value like a string, a number, or a boolean, you are making a standalone copy in memory. Svelte cannot track what you do with that local copy because the proxy only protects the original object properties. You must always write directly to the properties of the state object, or bind directly to them in your markup, to ensure the proxy can intercept the change and trigger the necessary updates.

State: Replacing the Container

While deep mutation works perfectly for incremental changes, there are times when an external API gives you a completely fresh array or a brand new object. In these cases, you do not need to painstakingly iterate through the old array and update it piece by piece to maintain reactivity. You can simply reassign the top level variable to the new data payload. Svelte tracks the top level binding just as closely as the deep properties, making bulk replacements entirely safe.

NewsDashboard.svelte
1<script>
2 let dispatches = $state([]);
3 async function refreshAll() {
4 const freshData = await fetch('/api/dispatches').then(res => res.json());
5 dispatches = freshData;
Reassigning the top level variable works and proxifies the new data
6 }
7</script>

When you overwrite the array with fresh data, Svelte instantly discards the old proxy, wraps the newly provided array in a fresh proxy, and updates the view to reflect the new state. You always have two valid ways to work with complex state in Svelte 5: you can either mutate the existing proxy deeply using standard JavaScript methods, or you can replace the entire container with a new one. Both approaches are completely safe, highly performant, and guaranteed to keep the screen perfectly synchronized with your data.

Key Takeaway

Passing an object or array to state creates a deep proxy that silently intercepts mutations on every nested property and array index.

Interview Tip

To impress the interviewer: Explain that Svelte 5 completely removes the need for the Svelte 4 assignment trick where developers had to awkwardly write array = array after a push just to trigger an update. Clarify that the new deep proxy architecture intercepts standard array methods like push, pop, shift, and splice natively, allowing you to write standard mutable JavaScript while keeping the user interface entirely reactive and free of boilerplate.

Summary

Storing objects and arrays in state wraps them in a deep proxy that automatically intercepts reads and writes. This architecture allows you to mutate nested properties directly or use standard array methods like push without any extra framework specific syntax, and Svelte will automatically update the corresponding parts of the user interface. You must remember to perform your mutations on the proxy object itself, because destructuring primitive values creates disconnected copies that abandon the reactive tracking. When receiving fresh data from a server or external source, you can freely replace the entire object or array by reassigning the top level variable, which Svelte will immediately wrap in a new proxy and track seamlessly.

State wraps objects and arrays in a recursive deep proxy that actively listens for mutations. Modifying a nested property directly updates the view without ever requiring a top level reassignment. Standard array methods like push and splice are intercepted by the proxy and work reactively out of the box. Destructuring primitive properties from a state object breaks the reactive connection and creates a dead copy. * Reassigning the top level variable with entirely new data is safe and correctly applies a new proxy to the fresh payload.
