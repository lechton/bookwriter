What is $state.raw, and when should you choose it over $state?

Imagine this scenario:

  1. A journalist opens the search archive on the National Times website to browse 10,000 published articles.
  2. The code stores the articles in $state(articles), but the display only updates when the journalist searches.
  3. The journalist types a single letter into the search box to find a story.
  4. Why does typing in the search box freeze the screen, even though no article ever changes?
  5. Letters appear seconds late on screen, locking up the interface while the journalist types.
  6. Svelte creates ten thousand deep reactive proxies to track properties that are never edited.
  7. Today you learn how shallow state ignores nested properties to keep large datasets fast.

The Hidden Tax of Deep Reactive Proxies

In Lecture 36, we discovered how Svelte 5 achieves deep reactivity by wrapping plain objects and arrays in recursive JavaScript Proxies (see Lecture 36). Whenever code accesses or mutates a property, Svelte's proxy traps intercept the operation to track dependencies and trigger surgical DOM updates. In interactive forms and dynamic profiles, this fine-grained reactivity makes application state feel effortless and responsive.

However, deep reactivity is not a zero-cost abstraction. To provide property-level tracking, Svelte must wrap the top-level container and recursively traverse every nested object and array, wrapping each child in its own proxy instance. When an application manages a handful of items, this proxying overhead is imperceptible. But frontend applications frequently ingest large reference datasets: catalog indexes, geographical coordinates, historical archives, or large article databases.

On the National Times website, journalists rely on a central search archive containing ten thousand published articles. Each article record contains an identifier, headline, category, publication date, and word count. This archive is entirely read-only; journalists filter articles by category or keyword to research past reporting, but they never edit an individual article record on this page.

When a developer stores this ten-thousand-record dataset using standard $state (see Lecture 4), Svelte obediently constructs ten thousand nested proxy wrappers across computer memory. This creates two severe performance bottlenecks:

  • Memory footprint expansion: Every proxy instance and its associated signal metadata consume browser heap memory. Storing thousands of proxies multiplies garbage collection overhead and balloons application memory usage.
  • Initialization and traversal latency: Constructing thousands of proxies during component initialization consumes valuable CPU cycles. Whenever the journalist types into the search box, reading properties across thousands of proxied records forces the JavaScript engine to execute proxy get traps repeatedly, producing dropped frames and stuttering input lag.

Before inspecting how to eliminate this overhead, examine the component hierarchy that renders the archive. ArticleSearch.svelte serves as the container shell managing search input and article state, while ArticleTable.svelte renders the matching article rows on screen.

Opting Out of Deep Proxies with $state.raw

To eliminate the proxy overhead of large datasets, Svelte 5 introduces $state.raw.

The $state.raw rune creates a shallow reactive signal. Unlike standard $state, $state.raw does not wrap objects or arrays in JavaScript Proxies. The underlying data structure remains completely untouched as plain, inert JavaScript data in computer memory. Svelte sets up a single reactive signal pointing directly to the variable reference itself, without inspecting, traversing, or instrumenting any nested properties.

Consider the architectural contrast in memory:

  • With let articles = $state(articleData): Svelte creates one parent proxy, ten thousand child proxies, and thousands of internal signal bindings.
  • With let articles = $state.raw(articleData): Svelte creates exactly one root signal holding a reference to the plain array. Zero proxy wrappers are allocated.

Because no proxies exist, accessing properties on raw data incurs zero trap overhead. Your code reads directly from native JavaScript objects at full hardware speed. Keystrokes in the search input remain instant, and memory consumption drops to the baseline cost of the raw JSON payload.

The Reassignment Contract: Mutation Versus Replacement

While $state.raw eliminates proxy overhead, it fundamentally changes how you update data on screen.

Because Svelte does not place proxy traps on raw objects, Svelte has no way of knowing when an internal property changes. If a developer attempts to mutate an item inside a raw state variable, the operation succeeds in computer memory, but Svelte receives zero notification:

App.js
1articles[0].title = 'Breaking News Update';
Mutates memory, but DOM never updates.

This brings us to the foundational contract of raw state: raw state cannot be mutated; it can only be reassigned.

To update a $state.raw value on screen, you must replace the entire reference by assigning a new value to the variable. When you reassign the variable, Svelte's root signal catches the assignment and notifies all dependent templates, derived calculations, and effects to update:

App.js
1articles = [...articles, newArticle];
Reassignment fires the root signal.

When to Choose $state.raw Over $state

The choice between $state and $state.raw comes down to the frequency of property-level mutations versus the cost of proxy allocation. Choose $state.raw in three primary scenarios:

  • Large read-only or reference datasets: When storing static lookup tables, historical archives, geographical coordinates, or large API responses, you rarely mutate individual fields. Deep proxying wastes CPU and memory tracking changes that will never occur. Storing reference data in $state.raw gives you maximum performance.
  • Complex third-party library instances: Modern web applications integrate specialized client-side libraries: Chart.js visualization instances, Leaflet map objects, Three.js 3D scenes, WebGL renderers, or Monaco code editors. These external objects manage their own internal state, contain cyclic references, and rely on private class fields. Wrapping external instances in Svelte's $state proxies frequently triggers runtime errors or degrades performance. Wrapping them in $state.raw preserves the exact original instance while still letting your component react when the instance is swapped or reset.
  • High-frequency immutable streaming feeds: In financial dashboards, telemetry viewers, or multiplayer canvases, state updates frequently arrive as complete immutable snapshots over a WebSocket. Because each update replaces the entire payload, deep proxy tracking on every incoming message is discarded seconds later. Reassigning raw immutable snapshots avoids continuous proxy creation and keeps the garbage collector idle.

What about primitive values like numbers, strings, or booleans? For primitive values, let count = $state(0) and let count = $state.raw(0) behave identically. In JavaScript, primitive types are immutable and passed by value; Svelte never proxies primitives under any circumstances. $state.raw is specifically designed for reference types: objects, arrays, and class instances.

Key Takeaway

$state.raw creates a shallow reactive signal that leaves objects and arrays unproxied, skipping deep tracking overhead and requiring whole-value reassignment to update the screen.

Interview Tip

To impress the interviewer: Explain that $state.raw creates a shallow signal without wrapping objects or arrays in recursive JavaScript Proxies. Highlight the trade-off: you gain dramatic memory and CPU savings for large datasets by eliminating proxy allocation, but you forfeit fine-grained property mutation. Emphasize that mutating a property on a raw object or calling array methods like push fails silently because no proxy traps exist to notify Svelte; updates require variable reassignment like data = [...data, item]. Outline the three canonical use cases: first, large read-only datasets where individual properties never mutate; second, complex third-party class instances like Chart.js or Three.js objects whose internal prototypes and private fields would break under proxy wrapping; and third, high-frequency immutable streams where replacing entire snapshots is faster than deep traversal.

Summary

Svelte 5 offers $state.raw as an intentional opt-out from recursive deep reactivity. While standard $state proxies nested objects to enable granular property mutations, $state.raw treats objects and arrays as plain, inert JavaScript structures. This eliminates proxy allocation, dramatically reducing memory usage and CPU latency for large datasets. In exchange, raw state enforces an immutable reassignment contract: internal property mutations never trigger updates, requiring developers to replace the entire object or array reference to update the screen.

  • $state.raw creates a shallow reactive signal without wrapping objects or arrays in JavaScript Proxies.
  • Deep proxying in $state introduces memory and initialization overhead on massive datasets.
  • Mutating properties inside raw state fails to trigger DOM updates because no proxy traps exist.
  • Updating raw state requires reassigning the variable reference using immutable replacement patterns.
  • $state.raw is ideal for large read-only datasets, external library instances, and immutable streaming feeds.
  • For primitive values like numbers and strings, $state and $state.raw behave identically.
