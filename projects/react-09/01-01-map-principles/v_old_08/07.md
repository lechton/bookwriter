## Authorized Scope
Lesson 07 teaches the three tools of a container component. It works on `CardContainer`, the shared design around every story. It sets it against `NewsCard`, a rigid card that takes a prop for every piece. JSX nested between a component's tags becomes one more prop, `children`. The container decides where it goes by writing `{children}` in its JSX. The caller decides what it is. So a new layout needs no new prop. The rest syntax, `{ children, ...rest }`, gathers the props the container does not use. The spread syntax, `{...rest}`, writes them all on the container's `<div>`. Attributes apply from left to right, so the order around the spread decides which value wins. When the container joins its class with the caller's by hand, a default in the destructuring, `className = ''`, keeps a missing class from printing `undefined`. The lesson builds on Q06, where attributes become the props object and braces unpack it. There a default already filled a missing prop. It also builds on Q03, where JSX compiles to `_jsx` calls, and on Q05, where nesting builds the tree.

## Theme and Options
- **Theme**: How does one card component show different content for each story?
- **Option**: props: `<NewsCard title="New Park Opens Today" author="Anna Lyon" />`, and the card places each value in its own markup | Q06 `#props` | every card shows the same pieces in the same order, such as a product card with a name and a price
- **Option**: children: `<CardContainer><h2>New Park Opens Today</h2></CardContainer>`, and the card writes `{children}` where the content goes | this lesson | each story has different pieces, such as an author on one and a photo on another
- **Option**: both together: a named prop for what every story shows in the same place, such as a `title`, and `children` for the rest | this lesson | the cards share one piece and differ in the rest
- **This lesson teaches**: children

## Principles

### Principle 1: Nested JSX arrives as the `children` prop
- **Handle**: `children-is-a-prop`
- **Kind**: Model
- **Reader Question**: "I put a headline between `<CardContainer>` and `</CardContainer>`. Where does it go?"
- **Reader Expects**: inside the card, on its own, as content inside a `<div>` in HTML
- **React Does**: the build puts the nested JSX in the props object under the key `children`, `_jsx(CardContainer, { children: [...] })`; React calls `CardContainer` with it; the content shows only where the container writes `{children}` in its JSX; React never adds it by itself
- **Placement**: `function CardContainer({ children })` returning `<div className="card">{children}</div>`; `{children}` placed whole, wherever the content belongs
- **Real Mistake**: `CardContainer` returns `<div className="card" />` and ignores `children`; the page shows an empty card, the headline and author line are gone, and the console stays silent; verified in React 19.3.0
- **Fix In**: this principle
- **Importance**: the card's Core Truth and the first part of the interview question; interviewers ask what `children` is
- **Prediction**: in `CardContainer`, `Array.isArray(children)` is `true` with a length of `2` for a headline and an author line, `false` for the headline alone, where `children.type` is `'h2'`, and `children` is a string for plain text; so `children.map` throws "children.map is not a function" with one child.
- **Required Lesson Proof**: `CardContainer` without `{children}`: the empty `<div class="card">` in DevTools; with `{children}`: the headline and author line inside it; the logged shape of `children` for two children, one, and plain text.

### Principle 2: Let the caller fill the card instead of adding a prop for every piece
- **Handle**: `slot-over-flags`
- **Kind**: Decision
- **Reader Question**: "One story has an author, another a photo, a third only a title. Do I add a prop for each?"
- **Reader Expects**: yes; a prop per option, like the settings of a function
- **React Does**: each new piece adds a prop to `NewsCard`, and its JSX draws that piece for every story, even those that pass nothing; `CardContainer` draws only the shared design, and each caller writes the pieces it needs, in the order it wants
- **Placement**: content that differs between callers goes in `children`; a value every card must show in a fixed place and format, such as the title of `ArticleCard`, stays a named prop
- **Real Mistake**: `NewsCard({ title, author })` with `<p>By {author}</p>`; a story without an author still shows the word "By" with nothing after it; verified in React 19.3.0
- **Importance**: the card's Friction; reviewers stop a component whose props grow with every design request
- **Review Point**: Condition
- **Required Lesson Proof**: two stories through `NewsCard`, one with `author="Anna Lyon"`, one without: "By" with nothing after it on the second; the same stories through `CardContainer`: the author line only where the caller wrote it, and a photo in a third story with no change to `CardContainer`.

### Principle 3: Spread only the props the container does not use
- **Handle**: `spread-only-the-rest`
- **Kind**: Decision
- **Reader Question**: "Callers want to add `id`, `aria-label`, and `data-story-id` to the card. Do I list each one?"
- **Reader Expects**: list them all, or pass the whole props object to the `<div>` with `{...props}` and be done
- **React Does**: `{ children, isFeatured, ...rest }` takes out the named props and gathers the others into `rest`; `{...rest}` writes each one on the `<div>` as an attribute; `{...props}` writes every prop, including those meant for the component; React warns about some and writes others into the DOM without a word
- **Placement**: `function CardContainer({ children, isFeatured, ...rest })` and `<div className="card" {...rest}>{children}</div>`; spread only in a wrapper that passes attributes through; a component that reads its data lists its props by name
- **Real Mistake**: `<div className="card" {...props} />` in `CardContainer`, with `isFeatured={true}` and `date="May 3"` from the caller; the console shows "React does not recognize the `isFeatured` prop on a DOM element", and the DOM gets `date="May 3"`; verified in React 19.3.0
- **Importance**: the second part of the interview question; react.dev warns to use spread with restraint; reviewers flag `{...props}` on a DOM element
- **Review Point**: Do not
- **Required Lesson Proof**: `CardContainer` with `{...props}`: the console warning and `date` in DevTools; with `{ children, isFeatured, ...rest }` and `{...rest}`: a clean console, and `id`, `aria-label`, and `data-story-id` still on the `<div>`.

### Principle 4: Around a spread, the last attribute wins; join classes with a default
- **Handle**: `spread-order-wins`
- **Kind**: Decision
- **Reader Question**: "The caller passed `className="featured"`. Why did my card lose its border and padding?"
- **Reader Expects**: the two classes add up, as in HTML, where an element can have several classes
- **React Does**: JSX applies attributes from left to right; a `className` in `rest` replaces the one written before the spread; a `className` written after the spread replaces the caller's; nothing merges by itself; joining by hand with `'card ' + className` turns a missing class into the text `undefined`; the default from Q06, `className = ''`, fills it with an empty string
- **Placement**: a value the caller may change goes before `{...rest}`; a value the container must keep goes after it; when both sides add a class, take `className` out with a default and join them, `{ className = '', ...rest }` and `className={'card ' + className}`
- **Real Mistake**: `<div className="card" {...rest}>` with `className="featured"` from the caller; the DOM shows `class="featured"`, and the card loses the border and padding of `.card`; verified in React 19.3.0
- **Importance**: reviewers flag a base class callers can erase, or a default callers cannot change
- **Review Point**: Condition
- **Required Lesson Proof**: `CardContainer` with `className="card"` before the spread: `class="featured"`; after it: `class="card"`; joined: `class="card featured"`; joined with no `className` passed: `class="card undefined"`; with `className = ''`: `class="card "`, which matches `.card`.

## Senior Answer
Anything I nest between a component's tags reaches it as a prop called `children`. The container decides where it goes by writing `{children}` in its JSX. If it never writes it, the content disappears without an error. `children` has no fixed shape: one child is an element, two are an array. So I place it whole. This lets a container keep the design while each caller writes the content. I keep a named prop only for something every card must show. Spread attributes forward props I do not use. I take out the props the component needs, gather the rest with `...rest`, and write `{...rest}` on the element. Spreading everything leaks component props into the DOM, and React warns about them. Attributes apply left to right, so the last one wins. I put overridable defaults before the spread, and values I must keep after it. Default values go in the destructuring, as in `className = ''`. They fill a prop that is missing or `undefined`, but not `null` or `false`.
