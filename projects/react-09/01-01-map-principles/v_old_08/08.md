## Authorized Scope
Lesson 08 moves `ArticleCard` out of a long `App.jsx` into its own file, `src/components/ArticleCard.jsx`. Each file is a module with its own names. A name crosses into another file only when one file exports it and the other imports it. A move takes three steps: make the file, export the component, import it where it is used. A default export is imported without braces, under any name. A named export is imported with braces, under its exact name. A file has at most one default export and any number of named ones. The card file exports `ArticleCard` as its default and `BreakingBadge` as a named helper. The lesson builds on Q02, where `export default` marked the main component of `App.jsx`. It also builds on Q05, where one file held the whole tree.

## Theme and Options

- **This lesson teaches**: ES modules, each component in its own file, exported from it and imported where it is used

## Principles

### Principle 1: Each file is a module, and names cross files only by export and import
- **Handle**: `file-is-module`
- **Kind**: Model
- **Reader Question**: "I moved `ArticleCard` into its own file. Why does `App` say it is not defined?"
- **Reader Expects**: files in the same project see each other, like scripts on one HTML page
- **React Does**: the build treats each file as a module with its own names; `App.jsx` sees `ArticleCard` only if `ArticleCard.jsx` exports it and `App.jsx` imports it; without the import, the render of `App` throws, and the page goes blank
- **Placement**: in `src/components/ArticleCard.jsx`, `export default function ArticleCard`; at the top of `App.jsx`, `import ArticleCard from './components/ArticleCard.jsx'`; a helper used only inside the card file stays unexported
- **Real Mistake**: `ArticleCard` moved to its own file and exported, with no import in `App.jsx`; the console shows "ArticleCard is not defined", and the page is blank; verified in React 19.3.0 with Vite 8.3.4
- **Fix In**: this principle
- **Importance**: the first part of the interview question; the card's Friction, a thousand-line file nobody can merge
- **Prediction**: a `console.log` at the top of `ArticleCard.jsx` prints once, even when `App.jsx` and `Sidebar.jsx` both import it; a `console.log` inside `ArticleCard` prints for every card on every render.
- **Required Lesson Proof**: `ArticleCard` moved with no import: the blank page and "ArticleCard is not defined"; with the import: the cards back; the two logs, one at the top of the file and one in the component, with their counts.

### Principle 2: Import with the same form the file used to export
- **Handle**: `import-matches-export`
- **Kind**: Decision
- **Reader Question**: "Do I write braces around the name or not?"
- **Reader Expects**: either works, or the braces are JSX braces that read a value
- **React Does**: `export default function ArticleCard` is imported as `import ArticleCard from`, without braces and under any name; `export function BreakingBadge` is imported as `import { BreakingBadge } from`, with braces and the exact name; a mismatch stops the module before any component runs
- **Placement**: read the export line first, then write the import to match: `import ArticleCard, { BreakingBadge } from './components/ArticleCard.jsx'`
- **Real Mistake**: `import ArticleCard from './components/ArticleCard.jsx'` when the file has only `export function ArticleCard`; the console shows "The requested module '/src/components/ArticleCard.jsx' does not provide an export named 'default'", the page keeps its loading text, and `vite build` stops with `[MISSING_EXPORT] "default" is not exported by "src/components/ArticleCard.jsx"`; verified in React 19.3.0 with Vite 8.3.4
- **Importance**: the second part of the interview question; the card's Naive code; the commonest error after a file move
- **Review Point**: Do
- **Required Lesson Proof**: the card file with only named exports, imported without braces: the console error and the build error; with `{ ArticleCard }`: the cards back; `import { ArticleCard }` against a default export: the mirror message.

### Principle 3: One default export for the main component, named exports for the rest
- **Handle**: `default-or-named`
- **Kind**: Decision
- **Reader Question**: "Should `BreakingBadge` be a default or a named export?"
- **Reader Expects**: it does not matter, or every component in the file can be a default
- **React Does**: a file has at most one default export and any number of named exports; a second `export default` stops the build; a default without a name, `export default () => {}`, shows as `<default>` in error messages
- **Placement**: the component the file is named after is the default, `export default function ArticleCard`; helpers other files also use are named, `export function BreakingBadge`; when a team keeps one style, follow it
- **Real Mistake**: `export default function BreakingBadge` added to `ArticleCard.jsx`, which already has a default; the build stops with "A module cannot have multiple default exports."; verified with Vite 8.3.4
- **Importance**: interviewers ask when to use each; reviewers flag mixed styles and anonymous defaults
- **Review Point**: Condition
- **Required Lesson Proof**: a second `export default` in the card file: the build error; `BreakingBadge` as a named export: both imports in `App.jsx` work; an anonymous default that throws: "An error occurred in the <default> component", against the named version, which shows `ArticleCard`.

## Senior Answer
Every file is a module with its own names. To split a component out, I make a file, export the component, and import it where it is used. Without the import, the render throws that the name is not defined. A default export is imported without braces, and I can give it any name. A named export is imported with braces, under its exact name. If the two forms do not match, the module fails to load and the build stops. A file can have one default export and many named ones. I make the main component of a file its default, and helpers named exports, unless the team keeps one style. I always name the functions, because an anonymous default shows up as `<default>` in error messages.
