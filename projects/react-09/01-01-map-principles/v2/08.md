# Q08 Principle Map (River Version v2): Passing Data with Props and the Read-Only Contract
- **Version**: River Version (`v2`)
- **Bank Row**: `questions/questions.md` row 08, Version 4
- **Topic Tag**: `#props` | `❱ CORE`
- **Interview Question**: *How do you pass data into a component, and why can a component never change its own props?*

## Authorized Scope
- How a parent component passes data into a child component by writing JSX attributes on the child tag (`<ArticleCard title="New Park Opens Today" summary="The park on Main Street opens at noon." />`), and how React collects every attribute on that tag into a single `props` object passed as the first argument to the child component function.
- How a child component reads its props either through the whole `props` object (`function ArticleCard(props)` -> `props.title`) or through JavaScript object destructuring inside its parameter list (`function ArticleCard({ title, summary })`), and what breaks when a developer omits the parameter, misspells a prop key, or forgets the curly braces around destructured parameter names (`function ArticleCard(title, summary)`).
- How JSX attribute syntax determines the JavaScript type of each prop value: string literals in quotes (`title="New Park Opens Today"`) versus JavaScript expressions in curly braces for numbers, booleans, arrays, and objects (`readTime={3}`, `author={{ name: 'Maya Lin', role: 'Editor' }}`), and how a common parent component (`App`) passes shared data down to sibling child components (`SiteHeader` and `ArticleList`).
- Why props are a read-only snapshot for the current render: why assigning to the `props` object inside a child (`props.title = ...` or `props.readTime = ...`) throws a runtime `TypeError` because React freezes the `props` object in development, why mutating an object passed as a prop (`author.name = ...` or `article.title = ...`) corrupts the parent's and sibling components' data across renders, and how a child computes derived display values safely with local `const` variables inside the component body.
- Out of scope: the `children` slot prop, JSX spread attributes (`<ArticleCard {...props} />`), and default parameter values (`readTime = 3`) (`Q09 #children`), conditional rendering (`Q10 #conditional_rendering`), event handlers (`Q11 #event_handling`), `useState` interactive state (`Q12 #use_state`), rendering lists with `.map()` and the `key` prop (`Q18 #rendering_lists`, with `key` and `ref` mentioned only as an interview boundary note on reserved React names), and callback props for child-to-parent communication (`Q23 #callback_props`).

## General Concepts Introduction (Runway Plan)
- **Theme**: In Lectures 06 and 07 our mounted news application rendered `ArticleCard` inside `ArticleList`, but because the title (`New Park Opens Today`) and summary were hardcoded inside `ArticleCard.jsx`, placing two `<ArticleCard />` tags on the page stamped out two identical cards with the exact same text.
- **Ways**:
  - Reading the whole `props` parameter object (`function ArticleCard(props)` and reading `props.title`, `props.summary`).
  - Destructuring the `props` object directly in the function parameter list (`function ArticleCard({ title, summary })`), which is the standard everyday pattern in React components.
- **Recall**:
  - Curly braces `{}` inside JSX evaluate a JavaScript expression between tags (`<h3>{title}</h3>`) or right after `=` on an attribute (`readTime={3}`), while double curly braces `{{ ... }}` pass a JavaScript object literal inside JSX curly braces (Lecture 03, `Q03 #jsx_expressions`).
  - Our code never calls a component function directly; we write `<ArticleCard />` and React calls `ArticleCard(...)` during rendering (Lecture 04, `Q04 #component_anatomy`).
  - Sibling components (`SiteHeader` and `ArticleList`) sit on separate branches under their common parent `App` and cannot read local variables from each other sideways (Lecture 06, `Q06 #ui_tree`).
  - `src/main.jsx` mounts `<App />` into `<div id="root"></div>` in `index.html` through `createRoot` and `root.render` (Lecture 07, `Q07 #create_root`).
- **Runway topics**:
  - How passing arguments to a plain JavaScript function compares to writing attributes on a JSX component tag.
  - How JavaScript object destructuring in function parameters (`function showCard({ title, readTime })`) unpacks properties from the first argument object into local variables.
  - How Vite compiles JSX attributes on `<ArticleCard title="New Park Opens Today" readTime={3} />` into a single plain JavaScript object `{ title: 'New Park Opens Today', readTime: 3 }` passed to `jsxDEV(ArticleCard, { ... })`.
  - How the project files (`src/App.jsx`, `src/components/SiteHeader.jsx`, `src/components/ArticleList.jsx`, `src/components/ArticleCard.jsx`, and `src/components/Badges.jsx`) pass data down the Component Render Tree from `App` to `SiteHeader` and `ArticleList`, and from `ArticleList` to multiple `ArticleCard` instances.
- **Example**: The city news page from Lectures 06 and 07 (`App` rendering `SiteHeader` and `ArticleList`, and `ArticleList` rendering two `ArticleCard` cards: `'New Park Opens Today'` with a `3` minute read time and `'Library Extends Hours'` with a `5` minute read time, each with `Live` and `New` badges).

## Principle Thread
- **Anchor**: How parent components pass data down the Component Render Tree through JSX attributes that React packages into a single read-only `props` object for each child component instance.
- **Axis**: Cause-to-effect flow from passing props on the parent tag to receiving, typing, and protecting them inside the child component:
  1. Passing attributes on a parent's JSX tag and receiving them as the child component's single `props` object argument (Principle 1).
  2. Unpacking properties from that single first argument object with curly braces (`function ArticleCard({ title, summary })`) instead of treating props as separate positional parameters (Principle 2).
  3. Passing strings with quotes versus numbers, booleans, and objects with curly braces `{}` down the tree from a common parent to siblings and children (Principle 3).
  4. Respecting the read-only contract by never mutating `props` or prop objects during render, and deriving local `const` values instead (Principle 4).
- **Why This Axis**: Each step builds directly on the one before it: a child component cannot destructure props until the parent passes attributes on the JSX tag and React bundles them into the first parameter object (Principle 1); once the reader sees that React always passes a single object as the first argument, the rule requiring curly braces `{ title, summary }` in the parameter list instead of positional parameters `(title, summary)` has an immediate physical explanation (Principle 2); once string props flow into `ArticleCard`, passing numbers (`readTime={3}`), objects (`author={{ name: 'Maya Lin' }}`), and shared parent values (`category="City News"`) across the tree follows naturally (Principle 3); and once multiple components receive data from above, it becomes clear why a child must treat its props as a read-only snapshot and compute derived local variables instead of mutating `props` (Principle 4).

## Principles

### Principle 1: Passing Attributes on a JSX Tag and Reading the `props` Object
- **Handle**: `pass-and-read-props-object`
- **Rule**: Write key-value attributes on the child component's JSX tag in the parent, and read those exact property names from the `props` object passed to the child component function.
- **Root Distinction**:
  - *Junior blurred view*: A child component either has hardcoded text inside it or can automatically see variables from its parent component without declaring a parameter.
  - *Senior grounding*: Every `<ArticleCard ... />` tag in the parent packages its attributes into an independent `props` object that React passes as the first argument to that `ArticleCard` call, and the child can only read what it receives through its parameter using the exact matching property name.
- **Real Beginner Mistake (events, in order)**:
  1. A developer passes an attribute on the child tag in the parent list file, or spells the attribute with one name in the parent file.
  2. In the child card file, the developer either forgets to declare the parameter in the function parentheses and tries to use the variable name directly, or reads a different property name from the parameter object.
  3. When the child omits the parameter and uses the bare variable name, JavaScript stops immediately with an uncaught ReferenceError and the page goes blank.
  4. When the parent passes one attribute name and the child reads a different property name, JavaScript evaluates the missing property as undefined.
  5. React renders nothing for undefined between tags and logs zero Console errors, leaving the card heading blank on screen.
- **Interview Depth**:
  - How Vite and React turn `<ArticleCard title="New Park Opens Today" summary="The park on Main Street opens at noon." />` into a function call: Vite compiles the JSX tag into `jsxDEV(ArticleCard, { title: "New Park Opens Today", summary: "The park on Main Street opens at noon." })`, and during rendering React invokes `ArticleCard(props)` with that object as the first argument.
  - Why HTML attributes on lowercase DOM tags (`<article className="card">`) are fixed by the HTML specification, whereas props on capital-letter React component tags (`<ArticleCard title="..." summary="..." />`) can have any custom name you choose.
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: Any direct `ArticleCard({ title: 'New Park Opens Today', summary: 'The park on Main Street opens at noon.' })` function call written in `src/components/ArticleList.jsx`.
    - **Who supplies it**: Vite compiles the JSX attributes on `<ArticleCard ... />` into a single JavaScript object, and React passes that object into `ArticleCard(props)` when rendering the tag.
    - **What Vite and React do**:
      1. In `ArticleList.jsx`, our code writes `<ArticleCard title="New Park Opens Today" summary="The park on Main Street opens at noon." />` and `<ArticleCard title="Library Extends Hours" summary="The downtown branch now stays open until 9 PM." />`.
      2. Vite compiles each `<ArticleCard ... />` tag into a React element object whose `props` property holds `{ title: '...', summary: '...' }`.
      3. When React renders the two tags, it calls `ArticleCard(props)` twice, handing the first call the first `props` object and the second call the second `props` object.
- **React Does**:
  - When `ArticleCard` omits its parameter (`function ArticleCard()`) and tries to render `<h3>{title}</h3>`, the page stays blank and Chrome logs `Uncaught ReferenceError: title is not defined`.
  - When `ArticleList` passes `<ArticleCard headline="New Park Opens Today" />` and `ArticleCard(props)` renders `<h3>{props.title}</h3>`, `props.title` is `undefined`, the `Elements` panel shows an empty `<h3></h3>` inside `<article class="card">`, and the Console logs zero errors.
  - When `ArticleList` passes matching `title` and `summary` attributes to two `<ArticleCard />` tags and `ArticleCard(props)` renders `<h3>{props.title}</h3>` and `<p>{props.summary}</p>`, the `Elements` panel renders two `<article class="card">` elements with their respective headings and paragraphs.
- **Example Step**: Updates `src/components/ArticleList.jsx` and `src/components/ArticleCard.jsx` so `ArticleList` renders two `<ArticleCard />` tags with `title` and `summary` props (`'New Park Opens Today'` / `'The park on Main Street opens at noon.'` and `'Library Extends Hours'` / `'The downtown branch now stays open until 9 PM.'`), and `ArticleCard(props)` renders both cards with distinct text.
- **Code names**: `src/components/ArticleList.jsx`, `src/components/ArticleCard.jsx`, `ArticleList`, `ArticleCard`, `props`, `props.title`, `props.summary`, `title`, `summary`, `headline`, `undefined`, `'New Park Opens Today'`, `'The park on Main Street opens at noon.'`, `'Library Extends Hours'`, `'The downtown branch now stays open until 9 PM.'`, `jsxDEV`, `ReferenceError: title is not defined`
- **Visual idea**: Side-by-side browser preview comparing a mismatched prop name (`headline="New Park Opens Today"` in `ArticleList` while `ArticleCard` reads `props.title`, producing an empty heading with zero Console errors) versus matching prop names rendering two distinct article cards.

### Principle 2: Unpacking the Single `props` Object with Parameter Destructuring (`{ title, summary }`)
- **Handle**: `destructure-single-props-arg`
- **Rule**: Wrap destructured prop names in curly braces inside the component's parameter list (`function ArticleCard({ title, summary })`), because React always passes all props inside one object as the first argument.
- **Root Distinction**:
  - *Junior blurred view*: Passing two attributes on `<ArticleCard title="..." summary="..." />` passes two separate positional arguments `(title, summary)` to `function ArticleCard(title, summary)`.
  - *Senior grounding*: React always calls a component function with a single `props` object as its first argument, so `{ title, summary }` inside `function ArticleCard({ title, summary })` is JavaScript object destructuring that unpacks properties from that first argument object.
- **Real Beginner Mistake (events, in order)**:
  1. A developer wants to read two props inside the card component without repeating the `props.` prefix on every line.
  2. The developer writes the two prop names inside the function parentheses separated by a comma, but forgets to wrap them in curly braces.
  3. When React calls the component, JavaScript assigns the entire `props` object to the first parameter name and assigns `undefined` to the second parameter name.
  4. The component tries to render the first parameter inside a heading tag, expecting it to be a string.
  5. React sees a plain JavaScript object inside JSX children and crashes the page with an uncaught error stating that objects are not valid as a React child.
- **Interview Depth**:
  - Equivalence of `function ArticleCard(props)` (reading `props.title` and `props.summary`) and `function ArticleCard({ title, summary })` (reading `title` and `summary` directly): both receive the exact same first argument object from React.
  - Are all JSX attributes placed into the `props` object? No: `key` is reserved by React to track component identity across renders and is stripped from `props` (`props.key` is `undefined` and triggers the Console error ``ArticleCard: `key` is not a prop. Trying to access it will result in `undefined` being returned. If you need to access the same value within the child component, you should pass it as a different prop.``).
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: The word `props` anywhere inside `export default function ArticleCard({ title, summary })`.
    - **Who supplies it**: JavaScript's parameter object destructuring `{ title, summary }` receives React's unnamed first argument object and extracts `.title` and `.summary` into local variables before the function body runs.
    - **What React and JavaScript do**:
      1. React calls `ArticleCard({ title: 'New Park Opens Today', summary: 'The park on Main Street opens at noon.' })`, passing one object as the first argument.
      2. The curly braces `{ title, summary }` inside the parameter parentheses `({ title, summary })` tell JavaScript to look up `.title` and `.summary` on that first argument object and create two local variables named `title` and `summary`.
      3. Without those curly braces (`function ArticleCard(title, summary)`), JavaScript treats `title` as the name for the whole first argument (`{ title: 'New Park Opens Today', summary: '...' }`) and sets the second parameter `summary` to `undefined`.
- **React Does**:
  - When `ArticleCard` is declared without curly braces as `function ArticleCard(title, summary)` and `ArticleList` renders `<ArticleCard title="New Park Opens Today" summary="The park on Main Street opens at noon." />`, `title` holds `{"title":"New Park Opens Today","summary":"The park on Main Street opens at noon."}`, `summary` is `undefined`, `<div id="root"></div>` becomes empty, and Chrome logs `Uncaught Error: Objects are not valid as a React child (found: object with keys {title, summary}). If you meant to render a collection of children, use an array instead.`.
  - When `ArticleCard` is declared with curly braces as `function ArticleCard({ title, summary })`, `title` is `'New Park Opens Today'`, `summary` is `'The park on Main Street opens at noon.'`, and both cards render cleanly with zero Console errors.
  - When a parent passes `key="park-1"` and the child tries to read `props.key`, `props.key` returns `undefined` and React logs ``ArticleCard: `key` is not a prop. Trying to access it will result in `undefined` being returned. If you need to access the same value within the child component, you should pass it as a different prop. (https://react.dev/link/special-props)``.
- **Example Step**: Refactors `src/components/ArticleCard.jsx` from `function ArticleCard(props)` to parameter destructuring `function ArticleCard({ title, summary })` so `<h3>{title}</h3>` and `<p>{summary}</p>` read cleanly without repeating `props.`.
- **Code names**: `src/components/ArticleCard.jsx`, `ArticleCard`, `props`, `{ title, summary }`, `(title, summary)`, `title`, `summary`, `undefined`, `key`, `props.key`, `Error: Objects are not valid as a React child (found: object with keys {title, summary}). If you meant to render a collection of children, use an array instead.`, ``ArticleCard: `key` is not a prop. Trying to access it will result in `undefined` being returned. If you need to access the same value within the child component, you should pass it as a different prop. (https://react.dev/link/special-props)``
- **Visual idea**: Side-by-side comparison of `function ArticleCard(title, summary)` (missing curly braces -> `title` receives the whole object -> `Error: Objects are not valid as a React child`) versus `function ArticleCard({ title, summary })` (curly braces unpack `title` and `summary` strings -> rendered cards).

### Principle 3: Passing Typed Values (`"..."` vs. `{...}`) and Flowing Props Down from a Common Parent
- **Handle**: `typed-props-and-common-parent`
- **Rule**: Use quotes for string literal props and curly braces `{}` for numbers, booleans, objects, and variables, and pass shared data down from a common parent component to its children.
- **Root Distinction**:
  - *Junior blurred view*: Every attribute value in quotes (`readTime="3"`) is automatically converted to the right type, and props only go one level deep into leaf cards.
  - *Senior grounding*: Quotes on a JSX attribute always pass a JavaScript string (`"3"`), whereas curly braces `{}` evaluate a JavaScript expression of any type (`{3}`, `{true}`, `{{ name: 'Maya Lin' }}`, or `{category}`), allowing a common parent like `App` to pass data down through multiple levels and sibling branches of the Component Render Tree.
- **Real Beginner Mistake (events, in order)**:
  1. A developer adds a reading-time prop to each article card in the list file and wraps the number in quotation marks like an HTML attribute.
  2. Inside the card component, the developer adds 2 minutes of discussion time to the prop using the plus operator (`readTime + 2`).
  3. Because the parent used quotation marks, the prop arrives inside the card as the string `'3'` instead of the number `3`.
  4. JavaScript performs string concatenation (`'3' + 2`) instead of addition (`3 + 2`).
  5. The page loads with zero Console errors, but the card displays `32 min total` instead of `5 min total`.
- **Interview Depth**:
  - Why passing an inline object literal as a prop requires double curly braces (`author={{ name: 'Maya Lin', role: 'Editor' }}`): the outer curly braces open a JavaScript expression inside JSX, and the inner curly braces are the JavaScript object literal `{ name: 'Maya Lin', role: 'Editor' }`.
  - How props replace the static `src/siteData.js` module workaround from Lecture 06 when a parent component owns data: `App` (the lowest common parent of `SiteHeader` and `ArticleList`) passes `category="City News"` down to both `<SiteHeader category="City News" />` and `<ArticleList category="City News" />`, and `ArticleList` in turn renders `<ArticleCard ... />` children below it.
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: `import { category } from '../siteData.js'` inside `SiteHeader.jsx` or `ArticleList.jsx` once `App.jsx` passes `category` as a prop.
    - **Who supplies it**: The common parent `App` in `src/App.jsx` passes `category="City News"` on both `<SiteHeader category="City News" />` and `<ArticleList category="City News" />`.
    - **What React does**:
      1. `App` renders `<SiteHeader category="City News" />` and `<ArticleList category="City News" />`.
      2. React calls `SiteHeader({ category: 'City News' })` for the left branch and `ArticleList({ category: 'City News' })` for the right branch.

### Principle 4: The Read-Only Contract: Never Mutate Props; Derive Local Variables Instead
- **Handle**: `props-read-only-contract`
- **Rule**: Treat `props` and every object inside `props` as read-only inputs during render; when a component needs to transform or format a prop for display, store the result in a new local `const` variable instead of assigning to `props`.
- **Root Distinction**:
  - *Junior blurred view*: Because `props` arrives as a function argument inside the child component, the child owns `props` and can modify `props.readTime = props.readTime + 2` or `article.title = 'BREAKING: ' + article.title` before returning JSX.
  - *Senior grounding*: The parent component owns the data and hands the child a read-only snapshot for the current render; React freezes the `props` object in development so direct assignment throws a `TypeError`, and mutating a nested object prop corrupts the parent's data across renders.
- **Real Beginner Mistake (events, in order)**:
  1. A developer wants the card component to add 2 minutes of discussion time to its reading time or prepend a label to the title before displaying it.
  2. Instead of creating a new local variable, the developer assigns the new value directly back onto a property of the `props` object inside the card function.
  3. Because React freezes the `props` object with `Object.freeze` before calling the component, JavaScript blocks the property assignment in strict mode.
  4. Execution halts immediately with an uncaught TypeError in the Console, and the browser page goes blank.
- **Interview Depth**:
  - What happens if a parent passes a nested object as a prop (`const featuredArticle = { title: 'New Park Opens Today', readTime: 3 }` passed to `<ArticleCard article={featuredArticle} />`) and the child mutates `article.title = 'BREAKING: ' + article.title`: React only shallow-freezes the top-level `props` object (`Object.isFrozen(props)` is `true`), not nested objects inside it, so mutating `article.title` silently corrupts `featuredArticle` in memory and causes a second `<ArticleCard article={featuredArticle} />` (or a StrictMode re-render) to display `BREAKING: BREAKING: New Park Opens Today`.
  - How a child component changes data when the user clicks a button if a child can never mutate its own props: props are immutable snapshots from above; interactive changes live in state (`Q12 #use_state`) owned by the component or its parent, and a child asks its parent to update state by calling a callback prop (`Q23 #callback_props`).
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: Any `Object.freeze(props)` call in `ArticleList.jsx` or `ArticleCard.jsx`.
    - **Who supplies it**: React freezes the `props` object internally when creating the element in development mode, and ES modules run in JavaScript strict mode where assigning to a frozen object property throws a `TypeError`.
    - **What React and JavaScript do**:
      1. When `ArticleList` renders `<ArticleCard title="New Park Opens Today" readTime={3} />`, React creates the `props` object `{ title: 'New Park Opens Today', readTime: 3 }` and freezes it (`Object.isFrozen(props)` is `true`).
      2. If `ArticleCard(props)` writes `props.readTime = props.readTime + 2` (or `props.title = 'BREAKING: ' + props.title`), JavaScript throws `Uncaught TypeError: Cannot assign to read only property 'readTime' of object '#<Object>'` (or `'title'`).
      3. When `ArticleCard({ title, summary, readTime })` instead writes `const totalTime = readTime + 2` (or `const displayTitle = 'BREAKING: ' + title`), it creates a brand-new local constant inside the function scope without touching the frozen `props` object.
- **React Does**:
  - When `ArticleCard(props)` runs `props.readTime = props.readTime + 2`, `Object.isFrozen(props)` is `true`, `<div id="root"></div>` becomes empty, and Chrome logs `Uncaught TypeError: Cannot assign to read only property 'readTime' of object '#<Object>'`.
  - When `ArticleCard(props)` runs `props.title = 'BREAKING: ' + props.title`, `<div id="root"></div>` becomes empty, and Chrome logs `Uncaught TypeError: Cannot assign to read only property 'title' of object '#<Object>'`.
  - When `ArticleList` passes a shared object `const featuredArticle = { title: 'New Park Opens Today', readTime: 3 }` to two `<ArticleCard article={featuredArticle} />` tags and `ArticleCard({ article })` mutates `article.title = 'BREAKING: ' + article.title`, the first card renders `<h3>BREAKING: New Park Opens Today</h3>` and the second card renders `<h3>BREAKING: BREAKING: New Park Opens Today</h3>`.
  - When `ArticleCard({ title, summary, readTime })` computes `const totalTime = readTime + 2` and renders `<p>{totalTime} min total ({readTime} min read)</p>`, `props` stays untouched and both cards render cleanly (`5 min total (3 min read)` and `7 min total (5 min read)`).

## Interview Points
- A parent component passes data to a child component by writing JSX attributes on the child tag (`<ArticleCard title="New Park Opens Today" readTime={3} />`), and React bundles all of those attributes into a single `props` object passed as the first argument to the child function.
- Inside the child component, you read props either from `props.title` or by destructuring the first argument object with curly braces (`function ArticleCard({ title, readTime })`); forgetting the curly braces (`function ArticleCard(title, readTime)`) assigns the whole `props` object to `title` and throws `Error: Objects are not valid as a React child` when rendered.
- Not every JSX attribute becomes a property on `props`: React reserves `key` (and `ref` in legacy patterns) for its own internal reconciliation, so reading `props.key` returns `undefined` and logs a special-props Console error.
- Quotation marks on a JSX attribute (`readTime="3"`) always pass a string, whereas curly braces (`readTime={3}`, `isNew={true}`, `author={{ name: 'Maya Lin' }}`) evaluate any JavaScript expression and preserve its data type.
- Because data in React flows one way down the Component Render Tree, when two sibling components (`SiteHeader` and `ArticleList`) need the same value, their common parent (`App`) owns that value and passes it down to both siblings via props.
- Props are read-only snapshots owned by the parent: React shallow-freezes the `props` object in development so `props.title = ...` throws `TypeError: Cannot assign to read only property 'title' of object '#<Object>'`, and mutating a nested object prop corrupts shared data across renders; child components must compute derived values in local `const` variables or request changes from the parent via state and callback props.
