# Q10 Principle Map (River Version v2): Conditional Rendering with if, ? :, and &&
- **Version**: River Version (`v2`)
- **Bank Row**: `questions/questions.md` row 10, Version 4
- **Topic Tag**: `#conditional_rendering` | `❱ CORE`
- **Interview Question**: *How do you show, hide, or switch JSX based on a condition?*

## Authorized Scope
- How React controls conditional branching with standard JavaScript syntax (`if` / `else` statements, the ternary conditional operator `? :`, the logical AND operator `&&`, and `let` variables assigned before `return`) instead of framework-specific template directives or manual DOM visibility mutations (`element.style.display = 'none'`).
- How an `if` statement inside the component function body (before the final `return`) returns an alternate JSX tree early or returns `null` to render zero DOM nodes when a component should be hidden altogether (`if (!isPublished) { return null; }`), and how assigning JSX to a `let` variable inside an `if / else` block before `return` keeps complex multi-branch logic readable.
- Why an `if` statement cannot be written directly inside JSX curly braces (`{if (isSubscriberOnly) ...}` fails at build time with a syntax error because `{}` only accepts JavaScript expressions), and how the ternary operator `condition ? <BranchA /> : <BranchB />` switches between two JSX expressions inline inside `{}`.
- How the logical AND operator (`condition && <Element />`) shows one piece of JSX when a boolean condition is `true` and renders nothing when it is `false`, how React treats `false`, `null`, and `undefined` as empty holes in the JSX tree that produce zero DOM nodes, and why passing a string `"false"` in quotes (`isBreaking="false"`) is truthy in JavaScript and renders the right-hand JSX anyway.
- Why placing a number directly on the left side of `&&` (`{commentCount && <p>{commentCount} comments</p>}`) prints a literal `0` into the DOM when the number is `0` (because `0 && <p>...</p>` short-circuits to `0`, and React renders numbers as text nodes), and how comparing against zero (`{commentCount > 0 && <p>{commentCount} comments</p>}`) converts the left side into a boolean (`false`) that renders nothing.
- Out of scope: interactive toggling in response to user clicks with event handlers (`Q11 #event_handling`) and `useState` (`Q12 #use_state`), rendering arrays of items with `.map()` and `.filter()` (`Q18 #rendering_lists`), and how conditional tree positions preserve or reset component state across re-renders (`Q25 #component_identity`).

## General Concepts Introduction (Runway Plan)
- **Theme**: On a real news page, not every story card looks the same: an unpublished draft story should not appear on the public feed at all, a subscriber-only story must swap its summary for a sign-in notice, the `Live` badge belongs only on breaking news, and the comment counter at the bottom of a card should disappear when a story has zero comments.
- **Ways**:
  - `if` / `else` statements and `return null` outside JSX (before the component's `return` statement) when hiding an entire component or preparing a `let` variable across multiple branches.
  - The ternary conditional operator `condition ? <BranchA /> : <BranchB />` inside JSX curly braces `{}` when switching between two pieces of markup inline.
  - The logical AND operator `condition && <Element />` inside JSX curly braces `{}` when showing one piece of markup if a boolean condition is `true` or rendering nothing at all if it is `false`.
- **Recall**:
  - React is declarative: instead of finding DOM nodes and toggling `.hidden` classes or `style.display = 'none'` by hand, our component returns a description of the UI that should exist for the current data (Lecture 01, `Q01 #what_is_react`).
  - Curly braces `{}` inside JSX open a window for JavaScript expressions (values that evaluate to a result), not full JavaScript statements (Lecture 03, `Q03 #jsx_expressions`).
  - Parent components pass boolean, number, and string props down to child components (`isBreaking={true}`, `commentCount={4}`), while quotes always pass a string (`"false"`) (Lecture 08, `Q08 #props`).
  - Default parameter values (`isPublished = true`, `readTime = 3`) in a component's destructured parameter list supply fallbacks when a parent tag omits an optional prop (Lecture 09, `Q09 #children`).
- **Runway topics**:
  - How JavaScript statements (`if / else`) differ from JavaScript expressions (`a ? b : c` and `a && b`), and why JSX curly braces `{}` only accept expressions.
  - Which JavaScript values React renders as visible text in the DOM (`strings` and `numbers` like `0`) versus which values React treats as empty holes that produce zero DOM nodes (`null`, `undefined`, `false`, `true`, and `""`).
  - How the project files (`src/App.jsx`, `src/components/SiteHeader.jsx`, `src/components/ArticleList.jsx`, `src/components/ArticleCard.jsx`, and `src/components/Badges.jsx`) move badge and status decisions into `ArticleCard.jsx` driven by props from `ArticleList.jsx`.
- **Example**: The city news page from Lecture 09 (`App` rendering `SiteHeader` and `ArticleList`, and `ArticleList` rendering `ArticleCard` entries for `'New Park Opens Today'`, `'Library Extends Hours'`, and an unpublished draft `'Mayor Budget Draft'`, where each card conditionally hides drafts, switches between the summary and a subscriber prompt, shows `Live` and `New` badges from boolean props, and shows a comment count only when `commentCount > 0`).

## Principle Thread
- **Anchor**: How React components branch, switch, and exclude markup using standard JavaScript control flow (`if` and `return null`, `? :`, and `&&`) and how React's rendering rules for `null`, `false`, and `0` govern what appears in the DOM.
- **Axis**: Outside-in progression from the whole component's return statement to two-way inline switching, one-way inline inclusion, and numeric boolean coercion:
  1. Guarding the whole component before `return` with an `if` statement and returning `null` when nothing should render (Principle 1).
  2. Switching between two JSX expressions inside `{}` with the ternary operator `? :`, or using `if` with a `let` variable before `return` when branches grow (Principle 2).
  3. Showing or hiding a single JSX element inside `{}` with the logical AND operator `&&` and a boolean prop, relying on React rendering `false` as nothing (Principle 3).
  4. Comparing numbers explicitly (`commentCount > 0 && ...`) on the left side of `&&` so a `0` value evaluates to `false` instead of printing a literal `0` in the DOM (Principle 4).
- **Why This Axis**: The sequence moves from the outer boundary of `ArticleCard` inward to its smallest inline expression: first, `ArticleCard` decides at the top of the function whether the card itself should render at all (`if (!isPublished) return null`) (Principle 1); once the card renders its `<article className="card">` shell, it needs to choose between two mutually exclusive paragraphs inside `{}` (`isSubscriberOnly ? ... : ...`), which explains why `if` cannot sit inside `{}` and why `? :` exists (Principle 2); next, when a badge inside `<article>` has only one branch (show `<LiveBadge />` or show nothing), `? :` with `: null` simplifies to `isBreaking && <LiveBadge />` because React renders `false` as nothing (Principle 3); and once the reader understands how `&&` returns its left operand when falsy, the classic `0 && <p>...</p>` trap where `0` prints on screen has an immediate physical explanation and fix (`commentCount > 0 && ...`) (Principle 4).

## Principles

### Principle 1: Returning Early with `if` and Returning `null` to Render Nothing
- **Handle**: `if-return-and-null`
- **Rule**: Use a standard JavaScript `if` statement before the component's `return` statement to return a different JSX tree early, or `return null` when the component should render nothing at all.
- **Root Distinction**:
  - *Junior blurred view*: Hiding a component in React requires keeping its HTML in the DOM and toggling a CSS `hidden` class, or React has a special template attribute like `v-if` / `ngIf` for hiding a tag.
  - *Senior grounding*: A React component is a plain JavaScript function; checking `if (!isPublished) { return null; }` at the top of the function stops execution before the JSX return statement and tells React to create zero DOM nodes for that component.
- **Real Beginner Mistake (events, in order)**:
  1. The article list file renders three card tags, including an unfinished draft card with `isPublished={false}`.
  2. Inside the card component, the developer unpacks the story props and returns the `<article className="card">` markup directly without checking `isPublished` first.
  3. React calls the card function for all three tags in the list.
  4. Because the third call never checks `isPublished` or returns `null`, it executes the final `return` statement just like the published stories.
  5. The unfinished draft story appears on the public page in the browser with zero Console errors.
- **Interview Depth**:
  - What React puts in the browser DOM when a component returns `null` (or `undefined` or `false` in React 19): React treats `null`, `undefined`, and `false` as intentional empty holes in the render tree and inserts zero DOM nodes and zero placeholder comments into `<section>`.
  - Why `react.dev` notes that returning `null` from inside a child component is best reserved for guard conditions (such as `if (!isPublished) return null` or `if (!article) return null`), whereas callers often prefer conditionally including or excluding the tag in the parent so the parent file makes the visibility obvious at a glance.
  - Why `if (cond) { return <A />; } return <B />;` and `return cond ? <A /> : <B />;` are equivalent in React: JSX elements are lightweight blueprint objects rather than stateful instances, so returning early vs. branching inline produces the exact same description for React to render.
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: A third `<article class="card">` element or an empty wrapper node inside `<section>` in the browser's `Elements` panel even though `ArticleList.jsx` wrote three `<ArticleCard ... />` tags.
    - **Who supplies it**: The `if (!isPublished) { return null; }` guard at the top of `ArticleCard.jsx` returns `null` to React on the third call, and React skips creating any DOM node for a `null` return value.
    - **What JavaScript and React do**:
      1. `ArticleList` renders three `<ArticleCard />` tags, passing `isPublished={false}` on the third card (`title="Mayor Budget Draft"`).
      2. On the first two calls to `ArticleCard`, `isPublished` is `true`, so `if (!isPublished)` is skipped and the function returns the `<article className="card">` React element.
      3. On the third call to `ArticleCard`, `isPublished` is `false`, so `if (!isPublished)` runs `return null;` immediately and React inserts nothing into `<section>`.
- **React Does**:
  - When `ArticleList` renders `<ArticleCard title="Mayor Budget Draft" summary="Unfinished notes for next week." readTime={3} isPublished={false} />` and `ArticleCard` lacks `if (!isPublished) { return null; }`, `<section>` in the `Elements` panel renders `<article class="card"><h3>Mayor Budget Draft</h3><p>Unfinished notes for next week.</p><p>5 min total · 3 min read</p></article>` with zero Console errors.
  - When `ArticleCard` checks `if (!isPublished) { return null; }` before `return`, `<section>` in the `Elements` panel contains only the published `<article class="card">` elements and zero DOM nodes for `'Mayor Budget Draft'`, with zero Console errors.
- **Example Step**: Updates `src/components/ArticleList.jsx` and `src/components/ArticleCard.jsx` by adding an unpublished third card (`title="Mayor Budget Draft"`, `isPublished={false}`) in `ArticleList.jsx` and adding `isPublished = true` with `if (!isPublished) { return null; }` at the top of `ArticleCard.jsx`.
- **Code names**: `src/components/ArticleList.jsx`, `src/components/ArticleCard.jsx`, `ArticleList`, `ArticleCard`, `isPublished`, `isPublished = true`, `isPublished={false}`, `!isPublished`, `return null`, `null`, `'Mayor Budget Draft'`, `'Unfinished notes for next week.'`
- **Visual idea**: Side-by-side browser and `Elements` panel comparison of `ArticleCard` without the `if (!isPublished) return null` guard (rendering the unfinished `'Mayor Budget Draft'` card on the public page) versus with `if (!isPublished) return null` (rendering only the published cards and zero DOM nodes for the draft).

### Principle 2: Switching Between Two JSX Branches Inside `{}` with the Ternary Operator (`? :`)
- **Handle**: `ternary-two-branches`
- **Rule**: Inside JSX curly braces `{}`, use the ternary conditional operator `condition ? <BranchA /> : <BranchB />` to switch between two pieces of JSX, or use an `if / else` statement with a `let` variable before `return` when the branches are too long to read inline.
- **Root Distinction**:
  - *Junior blurred view*: Because curly braces `{}` run JavaScript inside JSX, you can write `{if (isSubscriberOnly) { <p>...</p> } else { <p>...</p> }}` directly inside `<article className="card">`.
  - *Senior grounding*: JSX curly braces `{}` sit in a JavaScript expression slot (like an argument to `_jsxDEV`), so they reject statements like `if / else` at build time and require an expression that evaluates to a value, such as `isSubscriberOnly ? <p>...</p> : <p>{summary}</p>`.
- **Real Beginner Mistake (events, in order)**:
  1. A developer wants `ArticleCard` to keep one shared `<article className="card">` wrapper while switching only the middle paragraph between a subscriber notice and the story summary.
  2. The developer opens curly braces `{}` inside `<article className="card">` and writes an `if (isSubscriberOnly) { ... } else { ... }` statement inside the curly braces.
  3. When the file is saved, Vite's JSX parser tries to read the contents of `{}` as a JavaScript expression.
  4. The parser hits the `if` keyword where a value expression is required and halts the build with a parse error (`Unexpected token`).
  5. Vite displays a red error overlay in the browser instead of rendering the component.
- **Interview Depth**:
  - Why `{}` in JSX accepts `isSubscriberOnly ? <A /> : <B />` but rejects `if (isSubscriberOnly)`: Vite compiles `<article>{...}</article>` into `_jsxDEV("article", { children: [...] })`, and a JavaScript array or object property can hold an expression (`cond ? a : b`) but never an `if` statement.
  - Why duplicating the whole `<article className="card">...</article>` block inside two top-level `if / else` returns makes maintenance harder (changing `className="card"` or the reading-time footer requires editing two places), whereas an inline ternary `{isSubscriberOnly ? ... : ...}` keeps the shared `<article>` shell in one place.
  - How to refactor a messy or nested ternary when one condition controls multiple pieces of JSX: declare `let bodyContent = <p>{summary}</p>;` before `return`, reassign it inside `if (isSubscriberOnly) { bodyContent = <p>Subscribers only: Sign in to read this story.</p>; }`, and render `{bodyContent}` inside `<article className="card">`.
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: Both `<p>Subscribers only: Sign in to read this story.</p>` and `<p>{summary}</p>` in the browser DOM for the same card at the same time.
    - **Who supplies it**: JavaScript evaluates `isSubscriberOnly ? <p>Subscribers only: Sign in to read this story.</p> : <p>{summary}</p>` before React receives the card's `children` array, handing React only the winning branch.
    - **What JavaScript and React do**:
      1. When `ArticleCard` runs for the park story (`isSubscriberOnly` is `false`), JavaScript evaluates the condition before `?` as `false` and returns the expression after `:`, which is `<p>{summary}</p>`.
      2. When `ArticleCard` runs for the library story (`isSubscriberOnly={true}`), JavaScript evaluates the condition before `?` as `true` and returns the expression between `?` and `:`, which is `<p>Subscribers only: Sign in to read this story.</p>`.
      3. React receives only the chosen `<p>` element for each card and inserts that single `<p>` into the DOM.
- **React Does**:
  - When `ArticleCard.jsx` writes `{if (isSubscriberOnly) { <p>Subscribers only: Sign in to read this story.</p> } else { <p>{summary}</p> }}` inside `<article className="card">`, Vite fails to compile `src/components/ArticleCard.jsx` and displays the error overlay: `[plugin:vite:oxc] Transform failed with 1 error: [PARSE_ERROR] Unexpected token` pointing at `{if (isSubscriberOnly)`.
  - When `ArticleCard.jsx` writes `{isSubscriberOnly ? <p>Subscribers only: Sign in to read this story.</p> : <p>{summary}</p>}` (or assigns `let bodyContent` in an `if` statement before `return` and renders `{bodyContent}`), the first card (`isSubscriberOnly={false}`) renders `<p>The park on Main Street opens at noon.</p>` and the second card (`isSubscriberOnly={true}`) renders `<p>Subscribers only: Sign in to read this story.</p>` with zero Console errors.
- **Example Step**: Adds `isSubscriberOnly = false` to `src/components/ArticleCard.jsx` and passes `isSubscriberOnly={true}` on the second card (`title="Library Extends Hours"`) in `src/components/ArticleList.jsx`, using `isSubscriberOnly ? <p>Subscribers only: Sign in to read this story.</p> : <p>{summary}</p>` to switch the middle paragraph.
- **Code names**: `src/components/ArticleCard.jsx`, `src/components/ArticleList.jsx`, `isSubscriberOnly`, `isSubscriberOnly = false`, `isSubscriberOnly={true}`, `? :`, `bodyContent`, `<p>Subscribers only: Sign in to read this story.</p>`, `<p>{summary}</p>`, `[PARSE_ERROR] Unexpected token`
- **Visual idea**: Side-by-side comparison of writing `{if (isSubscriberOnly) ...}` inside JSX curly braces (Vite build error `Unexpected token`) versus `{isSubscriberOnly ? <p>Subscribers only: Sign in to read this story.</p> : <p>{summary}</p>}` (park card showing its summary and library card showing the subscriber prompt).

### Principle 3: Showing or Hiding One Piece of JSX with Logical AND (`&&`) and Boolean Props
- **Handle**: `logical-and-boolean`
- **Rule**: Use `{condition && <Element />}` inside JSX curly braces when you want to render `<Element />` if a boolean `condition` is `true` and render nothing when `condition` is `false`, and pass boolean props with curly braces (`isBreaking={false}`) rather than quotes (`isBreaking="false"`).
- **Root Distinction**:
  - *Junior blurred view*: The `&&` operator inside JSX is a special React syntax that always returns a boolean, and writing `isBreaking="false"` in quotes turns the condition off.
  - *Senior grounding*: JavaScript's `&&` operator returns its left value if falsy and its right value if truthy; when `isBreaking` is the boolean `false`, `false && <LiveBadge />` returns `false` (which React ignores and renders as nothing), whereas the non-empty string `"false"` is truthy in JavaScript so `"false" && <LiveBadge />` returns and renders `<LiveBadge />`.
- **Real Beginner Mistake (events, in order)**:
  1. A developer adds `{isBreaking && <LiveBadge />}` inside `ArticleCard.jsx` so only breaking stories show the `Live` badge.
  2. In `ArticleList.jsx`, the developer wants the second card (`Library Extends Hours`) not to show the `Live` badge and writes `isBreaking="false"` in quotation marks on the `<ArticleCard>` tag.
  3. Because quotation marks on a JSX attribute create a JavaScript string, `isBreaking` arrives inside `ArticleCard` as the 5-character string `'false'` instead of the boolean `false`.
  4. When JavaScript evaluates `'false' && <LiveBadge />`, any non-empty string is truthy, so `&&` evaluates and returns the right-hand side (`<LiveBadge />`).
  5. The library card renders `<span class="badge">Live</span>` on screen even though the attribute said `"false"`, with zero Console errors.
- **Interview Depth**:
  - Step-by-step evaluation of `isBreaking && <LiveBadge />` in JavaScript and React: when `isBreaking` is `true`, `true && <LiveBadge />` evaluates to the `<LiveBadge />` React element object and React renders `<span class="badge">Live</span>`; when `isBreaking` is `false`, `false && <LiveBadge />` short-circuits and evaluates to `false`, and React treats `false` (just like `null` and `undefined`) as an empty hole in the JSX tree and creates zero DOM nodes.
  - Complete rules for what React renders for primitive values inside `{}`: `null`, `undefined`, `false`, `true`, and `""` render nothing in the DOM, whereas strings (`"Live"`) and numbers (`0`, `4`, `NaN`) render as visible text nodes.
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: The word `false` printed anywhere inside `<article class="card">` in the browser DOM when `isBreaking` is `false` and `ArticleCard` evaluates `{isBreaking && <LiveBadge />}`.
    - **Who supplies it**: JavaScript's `&&` operator returns the boolean `false`, and React's DOM renderer strips boolean values (`true` and `false`) from JSX children so they produce zero DOM nodes.
    - **What JavaScript and React do**:
      1. On the second card (`isBreaking={false}`, `isNew={true}`), JavaScript evaluates `isBreaking && <LiveBadge />`: because the left side is `false`, `&&` stops immediately and returns `false`.

      3. React receives `false` and `<NewBadge />` as children of `<article className="card">`, ignores `false`, and renders only `<span class="badge">New</span>` in the DOM.
- **React Does**:

### Principle 4: Avoiding the Zero Trap on the Left Side of `&&` (`commentCount > 0 && ...`)
- **Handle**: `zero-trap-logical-and`
- **Rule**: Never put a number directly on the left side of `&&` in JSX (`{commentCount && <p>...</p>}`); always write an explicit comparison such as `{commentCount > 0 && <p>{commentCount} comments</p>}` so the left side evaluates to a boolean (`true` or `false`).
- **Root Distinction**:
  - *Junior blurred view*: Because `0` is falsy in an `if (commentCount)` statement, writing `{commentCount && <p>{commentCount} comments</p>}` inside JSX will also render nothing when `commentCount` is `0`.
  - *Senior grounding*: When the left side of `&&` is falsy, `&&` returns that exact left-hand value without converting it to `false`; `0 && <p>...</p>` returns the number `0`, and because React renders numbers as valid text in the DOM, React prints a literal `"0"` on the page.
- **Real Beginner Mistake (events, in order)**:
  1. A developer adds a comment counter line at the bottom of `ArticleCard.jsx` and wants it to appear only when a story has comments.
  2. The developer writes `{commentCount && <p>{commentCount} comments</p>}` inside `<article className="card">`.
  3. On the first card (`commentCount={4}`), `4` is truthy, so `4 && <p>4 comments</p>` returns `<p>4 comments</p>` and looks right.
  4. On the second card (`commentCount={0}`), `0` is falsy, so `0 && <p>0 comments</p>` short-circuits and returns the left operand `0` instead of `false`.
  5. React receives the number `0` as a child of `<article className="card">` and renders a stray text node `"0"` at the bottom of the card with zero Console errors.
- **Interview Depth**:
  - Why React renders `0` in the DOM instead of ignoring it like `false`, `null`, and `undefined`: `0` is a valid numeric display value in UIs (such as a table cell `<td>{score}</td>` or `<p>Items in cart: {0}</p>`), so ignoring `0` would make zero scores and zero balances vanish across React apps.
  - What happens with every falsy value in JavaScript on the left side of `&&` inside JSX:
    - `false && <X />` -> evaluates to `false` -> React renders nothing.
    - `null && <X />` -> evaluates to `null` -> React renders nothing.
    - `undefined && <X />` -> evaluates to `undefined` -> React renders nothing.
    - `"" && <X />` -> evaluates to `""` (empty string) -> React renders nothing.
    - `0 && <X />` -> evaluates to `0` -> React renders `"0"` in the DOM!
    - `NaN && <X />` -> evaluates to `NaN` -> React renders `"NaN"` in the DOM and logs the Console error `Received NaN for the \`children\` attribute. If this is expected, cast the value to a string.`.
  - Two clean ways to turn a numeric count or array length into a safe boolean before `&&`: write an explicit comparison (`commentCount > 0 && <p>{commentCount} comments</p>` or `items.length > 0 && <List />`) or convert to a boolean with `Boolean(commentCount) && ...` / `!!commentCount && ...`.
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: Any `0` character written in the JSX template of `ArticleCard.jsx` (`{commentCount && <p>{commentCount} comments</p>}`).
    - **Who supplies it**: JavaScript's `&&` operator evaluates `0 && <p>...</p>` to the number `0`, and React turns that number `0` into a DOM text node `"0"` inside `<article class="card">`.
    - **What JavaScript and React do**:
      1. `ArticleList` renders the library card with `commentCount={0}` (or relies on the default `commentCount = 0`).
      2. With `{commentCount && <p>{commentCount} comments</p>}`, JavaScript sees that the left operand `0` is falsy, stops evaluating `&&`, and returns `0` itself.
      3. React receives `0` as the last child of `<article className="card">` and appends the text `"0"` directly after `<p>5 min total · 3 min read</p>`.
      4. When changed to `{commentCount > 0 && <p>{commentCount} comments</p>}`, JavaScript evaluates `0 > 0` to the boolean `false`, `false && <p>...</p>` returns `false`, and React renders nothing.
- **React Does**:
  - When `ArticleCard` renders `{commentCount && <p>{commentCount} comments</p>}` with `commentCount={4}` on the first card and `commentCount={0}` on the second card, the first card in the `Elements` panel ends with `<p>7 min total · 5 min read</p><p>4 comments</p>`, and the second card ends with `<p>5 min total · 3 min read</p>0` (a bare `"0"` text node inside `<article class="card">`), with zero Console errors.
  - When `ArticleCard` renders `{commentCount > 0 && <p>{commentCount} comments</p>}`, the first card renders `<p>4 comments</p>` and the second card (`commentCount={0}`) renders nothing after `<p>5 min total · 3 min read</p>`, with zero Console errors.
  - When `{NaN}` is rendered as a JSX child, the DOM shows `"NaN"` and Chrome logs `Received NaN for the \`children\` attribute. If this is expected, cast the value to a string.`.
- **Example Step**: Completes the 6-file city news application (`index.html`, `src/main.jsx`, `src/App.jsx`, `src/components/SiteHeader.jsx`, `src/components/ArticleList.jsx`, `src/components/ArticleCard.jsx`, and `src/components/Badges.jsx`) by adding `commentCount = 0` to `ArticleCard.jsx` and rendering `{commentCount > 0 && <p>{commentCount} comments</p>}`, with `commentCount={4}` on the park story and `commentCount={0}` on the library story.
- **Code names**: `src/components/ArticleCard.jsx`, `src/components/ArticleList.jsx`, `commentCount`, `commentCount = 0`, `commentCount={4}`, `commentCount={0}`, `{commentCount && <p>{commentCount} comments</p>}`, `{commentCount > 0 && <p>{commentCount} comments</p>}`, `0`, `false`, `NaN`, `<p>4 comments</p>`, `Received NaN for the \`children\` attribute. If this is expected, cast the value to a string.`
- **Visual idea**: Side-by-side browser and `Elements` panel comparison of `{commentCount && <p>{commentCount} comments</p>}` (printing a stray `0` at the bottom of the library card when `commentCount` is `0`) versus `{commentCount > 0 && <p>{commentCount} comments</p>}` (showing `4 comments` on the park card and nothing on the library card).

## Interview Points
- React handles conditional rendering with standard JavaScript control flow rather than special template directives: `if / else` statements and `return null` outside JSX, the ternary operator `condition ? <A /> : <B />` inside `{}` for two-way switching, and the logical AND operator `condition && <A />` inside `{}` for one-way inclusion.
- Outside JSX (before `return`), an `if` statement can return an alternate JSX tree early or `return null` to render zero DOM nodes at all (`if (!isPublished) return null;`), or assign JSX to a `let` variable when a condition controls multiple values or would make inline ternaries hard to read.
- Inside JSX curly braces `{}`, only JavaScript expressions are valid, so `{if (cond) ...}` fails at build time with a syntax error (`Unexpected token`), whereas the ternary expression `{isSubscriberOnly ? <p>...</p> : <p>{summary}</p>}` evaluates to the chosen React element.
- In `{isBreaking && <LiveBadge />}`, JavaScript's `&&` short-circuits: when `isBreaking` is `true`, it returns `<LiveBadge />`; when `isBreaking` is `false`, it returns `false`, and React treats `false`, `null`, `undefined`, `true`, and `""` as empty holes in the JSX tree that produce zero DOM nodes.
- Never put a number directly on the left side of `&&` (`{commentCount && <p>{commentCount} comments</p>}`): when `commentCount` is `0`, `0 && <p>...</p>` evaluates to the number `0` (not `false`), and because React renders numbers as text nodes, it prints a literal `"0"` into the DOM; always write an explicit boolean comparison such as `{commentCount > 0 && <p>{commentCount} comments</p>}`.
