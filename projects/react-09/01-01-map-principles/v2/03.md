## 1. Curated Source Excerpts (`documentation official/react/learn/javascript-in-jsx-with-curly-braces.md`)

- **Opening the Window to JavaScript**: *"JSX lets you write HTML-like markup inside a JavaScript file, keeping rendering logic and content in the same place. Sometimes you will want to add a little JavaScript logic or reference a dynamic property inside that markup. In this situation, you can use curly braces in your JSX to open a window to JavaScript."*
- **Passing Strings with Quotes vs. Braces**: *"When you want to pass a string attribute to JSX, you put it in single or double quotes. Handle dynamic values by replacing `"` and `"` with `{` and `}`: `src={avatar}`."*
- **Where to Use Curly Braces**: *"You can only use curly braces in two ways inside JSX: 1. As text directly inside a JSX tag: `<h1>{name}'s To Do List</h1>` works, but `<{tag}>Gregorio Y. Zara's To Do List</{tag}>` will not. 2. As attributes immediately following the `=` sign: `src={avatar}` will read the `avatar` variable, but `src="{avatar}"` will pass the string `"{avatar}"`."*
- **Using Double Curlies**: *"In addition to strings, numbers, and other JavaScript expressions, you can even pass objects in JSX. Objects are also denoted with curly braces, like `{ name: "Hedy Lamarr", inventions: 5 }`. Therefore, to pass a JS object in JSX, you must wrap the object in another pair of curly braces: `person={{ name: "Hedy Lamarr", inventions: 5 }}`. You may see this with inline CSS styles in JSX. JSX does not require you to use inline styles (CSS classes work great for most cases). But when you need an inline style, you pass an object to the `style` attribute."*
- **Rendering Values (`react/reference/react/Fragment.md` & `jsx-runtime`)**: Strings and numbers render as text nodes. Booleans (`true`, `false`), `null`, and `undefined` are valid JSX children that render nothing. Plain objects and `Date` instances are not valid JSX children and throw `Error: Objects are not valid as a React child` when placed between tags.

## 3. Principle Contracts (River Version `v2`)

### Principle 1: Braces Between Tags (`braces-in-text`)
- **Rule (pure English)**: Between an opening tag and a closing tag, everything outside curly braces is plain text. Curly braces tell JSX to run the JavaScript inside and show its result in that spot.
- **DO THIS / DO NOT DO THIS**: `<h2>{title}</h2>` vs `<h2>title</h2>`.

### Principle 2: Braces in Attributes (`braces-in-attribute`)
- **Rule (pure English)**: Right after an equals sign on an attribute, use either quotes for fixed text or curly braces for a JavaScript value. Never wrap curly braces inside quotes, because the quotes turn the braces into ordinary text.
- **DO THIS / DO NOT DO THIS**: `<img src={avatarUrl} alt={title} />` vs `<img src="{avatarUrl}" alt="{title}" />`.

### Principle 3: Expressions, Not Statements (`expression-not-statement`)
- **Rule (pure English)**: Curly braces can hold only a JavaScript expression that produces a value, because React passes the contents of the braces as an argument to a function call. Statements that control program flow must stay above the return statement, or be written as an expression such as a ternary.
- **DO THIS / DO NOT DO THIS**: `<span>{isLive ? 'Live now' : 'Recorded'}</span>` vs `<span>{if (isLive) { 'Live now' }}</span>`.

### Principle 4: JSX Comments (`jsx-comment`)
- **Rule (pure English)**: Inside JSX tags, write a comment as a JavaScript block comment wrapped in curly braces. HTML comments stop the build, and plain double-slash lines between tags appear as visible text on the page.
- **DO THIS / DO NOT DO THIS**: `{/* Reminder: add reading time */}` vs `<!-- Reminder: add reading time -->`.

### Principle 5: What Values Appear on Screen (`rendered-values`)
- **Rule (pure English)**: When curly braces sit between tags, React displays strings and numbers on the page, including the number zero. React displays nothing at all for true, false, null, or undefined, and logs no warning in the Console.
- **DO THIS / DO NOT DO THIS**: `<p>Live: {isLive ? 'Yes' : 'No'}</p>` vs `<p>Live: {isLive}</p>`.

### Principle 6: Objects and Double Curlies (`double-curlies`)
- **Rule (pure English)**: React cannot display a plain object or a Date object as text between tags. Always read a string or number property from the object, or format the date into a string first. Use double curly braces only when passing an object to an attribute such as style, where the outer braces open JavaScript and the inner braces create the object.
- **DO THIS / DO NOT DO THIS**: `<p style={{ color: 'gray' }}>By {writer.name}</p>` vs `<p>By {writer}</p>`.
