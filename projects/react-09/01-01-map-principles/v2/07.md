# Q07 Principle Map (River Version v2): Mounting the Root Component with createRoot and Vite Tooling
- **Version**: River Version (`v2`)
- **Bank Row**: `questions/questions.md` row 07, Version 4
- **Topic Tag**: `#create_root` | `❱ CORE`
- **Interview Question**: *How does your root component attach to the browser DOM with createRoot, and how do build tools assemble it?*

## Authorized Scope
- How the browser page `index.html`, the Vite development server, the entry module `src/main.jsx`, `createRoot` from `react-dom/client`, and `root.render(<App />)` work together to attach the root component `App` to the browser DOM.
- Why `index.html` contains an empty container element (`<div id="root"></div>`) and why `document.getElementById('root')` must match that exact `id` attribute.
- Why `index.html` loads `src/main.jsx` with `<script type="module" src="/src/main.jsx"></script>`, and what Vite does before the browser runs the file (compiling JSX syntax into JavaScript function calls and resolving bare package specifiers like `'react-dom/client'`).
- Why mounting is split into two steps (`const root = createRoot(domNode)` followed by `root.render(<App />)`), why `createRoot` lives in `'react-dom/client'` instead of `'react'`, and why `root.render` requires a JSX element `<App />` rather than the component function `App`.
- Out of scope: props (`Q08 #props`), `children` (`Q09 #children`), `StrictMode` (`Q11 #strict_mode`), `useState` (`Q12 #use_state`), and server-side hydration with `hydrateRoot` (`Q162 #ssr_hydration`, mentioned only as an interview boundary note).

## General Concepts Introduction (Runway Plan)
- **Theme**: In Lectures 05 and 06 we built a multi-file news application headed by `src/App.jsx`, yet when you open `index.html` in the project root, `<body>` contains only an empty `<div id="root"></div>` and no `<App />` tag.
- **Ways**:
  - Classic multi-script HTML page: linking scripts directly in HTML without a build tool, which fails on JSX angle brackets and bare npm package imports.
  - Modern Vite + React entry pipeline: `index.html` provides `<div id="root"></div>` and loads `/src/main.jsx` as an ES module through Vite, which transforms JSX and mounts `<App />` via `createRoot` and `root.render`.
- **Recall**:
  - JSX compiles into plain JavaScript React element objects rather than running natively in the browser (Lecture 02, `Q02 #jsx`).
  - A React application is split across ES module files connected with `export` and `import` (Lecture 05, `Q05 #imports`).
  - `App` sits at the top of the Component Render Tree as the root component above `SiteHeader` and `ArticleList` (Lecture 06, `Q06 #ui_tree`).
- **Runway topics**:
  - How the project root adds `index.html` and `src/main.jsx` alongside `src/App.jsx`, `src/siteData.js`, and `src/components/`.
  - How the browser's `document.getElementById('root')` finds a real HTML element inside `index.html` by its `id` attribute.
  - What `<script type="module" src="/src/main.jsx"></script>` tells the browser, and what the Vite development server transforms before sending `/src/main.jsx` and `/src/App.jsx` to the browser.
  - How `'react-dom/client'` bridges React's component tree to the browser DOM through `createRoot` and `root.render`.
- **Example**: The city news page from Lectures 05 and 06 (`Latest Articles` header with `City News` subtitle and the `New Park Opens Today` article card with `Live` and `New` badges), wired from `index.html` and `src/main.jsx` into `<div id="root"></div>`.

## Principle Thread
- **Anchor**: How a React component tree written in `.jsx` files attaches to the physical browser DOM through `index.html`, Vite, `createRoot`, and `root.render`.
- **Axis**: Chronological mounting pipeline from cause to effect:
  1. `index.html` defines the physical `<div id="root"></div>` container that `document.getElementById('root')` looks up (Principle 1).
  2. `<script type="module" src="/src/main.jsx"></script>` and Vite load the entry module and compile JSX and package imports for the browser (Principle 2).
  3. `createRoot(domNode)` from `'react-dom/client'` creates the React root controller and `root.render(...)` triggers the initial DOM mount (Principle 3).
  4. Passing the JSX element `<App />` (rather than the function `App`) into `root.render(<App />)` hands React the root element description to render the tree (Principle 4).
- **Why This Axis**: Every step in the mounting pipeline depends on the step before it: `document.getElementById('root')` cannot find a container unless `index.html` provides `<div id="root"></div>` (Principle 1); `src/main.jsx` cannot execute in the browser unless `<script type="module">` and Vite load and transform it (Principle 2); `createRoot` cannot display anything on screen until `root.render` is called on the returned root object (Principle 3); and `root.render` cannot mount the component tree unless it receives the JSX element `<App />` rather than the raw function `App` (Principle 4).

## Principles

### Principle 1: The HTML Host Container (`index.html` and `document.getElementById`)
- **Handle**: `html-container-id-match`
- **Rule**: Place an empty container element in `index.html` and pass that exact DOM element to `createRoot` using `document.getElementById` with the matching `id` string.
- **Root Distinction**:
  - *Junior blurred view*: `createRoot` creates the `<div id="root"></div>` element on the page by itself, or accepts `<App />` directly.
  - *Senior grounding*: `index.html` must already provide the physical DOM element, and `document.getElementById` must find that element and pass it into `createRoot`.
- **Real Beginner Mistake (events, in order)**:
  1. A developer gives the empty container in the HTML file one ID name, or removes the empty container from the page body.
  2. The entry file looks up the container by a different ID name.
  3. Because no element in the HTML file has that ID, the browser lookup returns nothing.
  4. The entry file passes that empty result into React's root creator.
  5. React stops immediately with an uncaught error in the Console, and the browser page stays blank.
- **Interview Depth**:
  - Why client-rendered React apps ship an `index.html` whose `<body>` contains only an empty `<div id="root"></div>`.
  - Why passing `<App />` directly to `createRoot(<App />)` fails with the exact same error (`Error: Target container is not a DOM element.`), because a JSX element is a plain JavaScript object rather than a browser DOM node.
  - Why the ID `'root'` is a convention rather than a requirement, and how a non-React page can mount small React widgets into multiple HTML containers (such as `#header-widget` and `#comments-widget`) by calling `createRoot` on each DOM element.
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: `<main>`, `<header>`, `<h1>Latest Articles</h1>`, `<section>`, or `<article>` anywhere inside `index.html`.
    - **Who supplies it**: React creates those browser DOM elements at runtime and inserts them inside `<div id="root"></div>`.
    - **What the browser and React do**:
      1. The browser loads `index.html` and builds an empty `<div id="root"></div>` node in the DOM.
      2. `src/main.jsx` calls `document.getElementById('root')`, which returns that live `<div id="root"></div>` DOM object.
      3. When React mounts `App` into that container, React creates the `<main>`, `<header>`, `<section>`, and `<article>` DOM nodes and places them inside `<div id="root">...</div>` in the browser's `Elements` panel.
- **React Does**:
  - When `index.html` has `<div id="app"></div>` and `src/main.jsx` runs `createRoot(document.getElementById('root'))`, `document.getElementById('root')` returns `null`, the page stays blank, `<div id="app"></div>` stays empty in the `Elements` panel, and Chrome logs `Uncaught Error: Target container is not a DOM element.`.
  - When `src/main.jsx` runs `createRoot(<App />)`, the page stays blank, `<div id="root"></div>` stays empty, and Chrome logs `Uncaught Error: Target container is not a DOM element.`.
  - When `index.html` has `<div id="root"></div>` and `src/main.jsx` passes `document.getElementById('root')` to `createRoot` and renders `<App />`, the `Elements` panel contains `<div id="root"><main><header><h1>Latest Articles</h1><p>City News</p></header><section><h2>Section: City News</h2><article class="card"><span class="badge">Live</span><span class="badge">New</span><h3>New Park Opens Today</h3><p>The park on Main Street opens at noon.</p></article></section></main></div>`.
- **Example Step**: Adds `index.html` in the project root with `<div id="root"></div>` inside `<body>`, and connects `document.getElementById('root')` in `src/main.jsx` to that exact `id="root"` container so the news page from Lecture 06 has a physical DOM target on screen.
- **Code names**: `index.html`, `src/main.jsx`, `<div id="root"></div>`, `<div id="app"></div>`, `document.getElementById('root')`, `null`, `createRoot`, `App`, `<App />`, `Error: Target container is not a DOM element.`
- **Visual idea**: Side-by-side comparison of a mismatched ID (`<div id="app"></div>` in `index.html` + `document.getElementById('root')` returning `null` -> `Error: Target container is not a DOM element.`) versus a matching ID (`<div id="root"></div>` + `document.getElementById('root')` -> mounted news page inside `#root`).

### Principle 2: The Module Entry and Build Tool (`<script type="module">` and Vite)
- **Handle**: `vite-module-entry-transform`
- **Rule**: Load `src/main.jsx` from `index.html` with `<script type="module" src="/src/main.jsx"></script>` and run Vite so the browser receives standard ES modules with compiled JSX and resolved package imports.
- **Root Distinction**:
  - *Junior blurred view*: The browser natively understands `.jsx` files and package names like `'react-dom/client'` through a classic `<script src="...">` tag.
  - *Senior grounding*: The browser only understands standard JavaScript ES modules (`<script type="module">`), and Vite compiles JSX tags into JavaScript function calls and rewrites bare package imports before the browser receives the code.
- **Real Beginner Mistake (events, in order)**:
  1. A developer links the entry file in the HTML page with a classic script tag that omits the module attribute, or opens the HTML file directly from disk without starting the build server.
  2. When the module attribute is missing, the browser treats the entry file as a classic script that forbids module imports and stops on the first line with a syntax error.
  3. When the build server is not running, the browser receives raw JSX angle brackets or a bare package name, neither of which standard browser JavaScript understands.
  4. Execution halts before the React root is ever created, and the HTML container stays empty.
- **Interview Depth**:
  - What `<script type="module" src="/src/main.jsx"></script>` does in the browser: enables ES module `import`/`export` syntax and automatically defers script execution until the HTML document (`<div id="root"></div>`) has been parsed.
  - The two transformations Vite performs on the fly in development: compiling JSX syntax (`<App />`) into `jsxDEV(App, ...)` calls from `'react/jsx-dev-runtime'`, and resolving bare module specifiers (`'react'` and `'react-dom/client'`) to pre-bundled files inside `node_modules/.vite/deps/`.
  - Why `index.html` needs only one `<script type="module" src="/src/main.jsx"></script>` tag even when the application has dozens of component files.
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: `<script>` tags for `App.jsx`, `SiteHeader.jsx`, `ArticleList.jsx`, `ArticleCard.jsx`, `Badges.jsx`, or `siteData.js` inside `index.html`.
    - **Who supplies it**: The ES module `import` chain starting in `src/main.jsx` and served by Vite loads the rest of the Module Dependency Tree automatically.
    - **What the browser and Vite do**:
      1. The browser reads `<script type="module" src="/src/main.jsx"></script>` in `index.html` and requests `/src/main.jsx` from Vite.
      2. Vite compiles the JSX inside `/src/main.jsx` into `jsxDEV(App, ...)` and rewrites `'react-dom/client'` to its resolved `node_modules` URL.
      3. The browser sees `import App from './App.jsx'` inside `main.jsx`, requests `/src/App.jsx` from Vite, and follows every nested `import` (`SiteHeader.jsx`, `ArticleList.jsx`, `ArticleCard.jsx`, `Badges.jsx`, `siteData.js`) without needing extra `<script>` tags in `index.html`.
- **React Does**:
  - Without `type="module"` (`<script src="/src/main.jsx"></script>`), the browser leaves `<div id="root"></div>` empty and Chrome logs `Uncaught SyntaxError: Cannot use import statement outside a module`.
  - With `<script type="module">` but without Vite compiling JSX, when the browser hits a JSX tag like `<main>` or `<App />`, Chrome logs `Uncaught SyntaxError: Unexpected token '<'`.
  - With `<script type="module">` but without Vite resolving bare package names, when the browser hits `import { createRoot } from "react-dom/client"`, Chrome logs `Uncaught TypeError: Failed to resolve module specifier "react-dom/client". Relative references must start with either "/", "./", or "../".`.
  - With Vite running and `<script type="module" src="/src/main.jsx"></script>`, Vite transforms `root.render(<App />)` into `root.render(/* @__PURE__ */ jsxDEV(App, {}, void 0, false, ...))` and resolves `'react-dom/client'`, and the page mounts with zero Console errors.
- **Example Step**: Wires `<script type="module" src="/src/main.jsx"></script>` inside `index.html` and shows how that single entry script pulls in `src/App.jsx` and the rest of the news app files through Vite.
- **Code names**: `index.html`, `src/main.jsx`, `src/App.jsx`, `<script type="module" src="/src/main.jsx"></script>`, `<script src="/src/main.jsx"></script>`, `'react-dom/client'`, `jsxDEV`, `SyntaxError: Cannot use import statement outside a module`, `SyntaxError: Unexpected token '<'`, `TypeError: Failed to resolve module specifier "react-dom/client". Relative references must start with either "/", "./", or "../".`
- **Visual idea**: Diagram tracing the handoff from `index.html` (`<script type="module" src="/src/main.jsx"></script>`) through Vite (JSX compilation + bare import resolution) to `src/main.jsx` and down the `import` graph into `src/App.jsx`.

### Principle 3: Two-Step Mounting (`createRoot` from `react-dom/client`, Then `root.render`)
- **Handle**: `create-root-then-render`
- **Rule**: Import `createRoot` from `'react-dom/client'`, call `const root = createRoot(domNode)` to create the React root for that DOM container, and then call `root.render(<App />)` to display the component tree inside it.
- **Root Distinction**:
  - *Junior blurred view*: Calling `createRoot(document.getElementById('root'))` automatically renders the React application onto the screen.
  - *Senior grounding*: `createRoot` only creates the React root controller bound to the DOM container; nothing is rendered into that container until `root.render(<App />)` is called.
- **Real Beginner Mistake (events, in order)**:
  1. A developer imports the root creator and the root component in the entry file and creates the React root for the page container.
  2. The developer stops after creating the root object and forgets to call its render method with the root component.
  3. The browser loads the page and runs the entry file without throwing any Console error or warning.
  4. Because the render method never ran, the HTML container remains empty in the Elements panel and the browser screen stays blank.
- **Interview Depth**:
  - Why `createRoot` lives in `'react-dom/client'` instead of `'react'`: `'react'` holds platform-independent component and state primitives (shared across web, React Native, and server environments), while `'react-dom/client'` holds browser-DOM-specific mounting code.
  - Why React 18 and React 19 replaced legacy `ReactDOM.render(<App />, domNode)` with `createRoot(domNode)` + `root.render(<App />)`: `createRoot` sets up a concurrent root container once and returns a `root` object so the DOM node does not have to be passed again on later renders, and in React 19 `ReactDOM.render` is completely removed (`TypeError: ReactDOM.render is not a function`).
  - What happens if `<div id="root"><p>Loading...</p></div>` contains static HTML inside it before `root.render(<App />)` runs: on the first `root.render` call, React clears all existing child nodes inside `#root` before inserting the React DOM tree (whereas preserving server-rendered HTML requires `hydrateRoot`).
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: `import { render }` at the top of `src/main.jsx` or any `function render()` declaration in our project files.
    - **Who supplies it**: `createRoot(...)` returns a React root object that carries the `.render(...)` method as one of its properties.
    - **What React does**:
      1. `createRoot(document.getElementById('root'))` creates an internal React root wired to `<div id="root"></div>` and returns a root object with a `.render` method.
      2. Assigning that returned object to `const root` gives `src/main.jsx` access to `root.render` (or allows chaining `createRoot(...).render(<App />)` directly).
      3. Calling `root.render(<App />)` triggers the initial render pass of `App` and commits the resulting DOM nodes inside `<div id="root">`.
- **React Does**:
  - When `src/main.jsx` runs `const root = createRoot(document.getElementById('root'))` without calling `root.render(<App />)`, the page is blank, `<div id="root"></div>` is empty in the `Elements` panel, and the Console shows zero errors.
  - When `src/main.jsx` tries `import { createRoot } from 'react'`, Vite serves the module and Chrome throws `Uncaught TypeError: createRoot is not a function`.
  - When `src/main.jsx` tries legacy `ReactDOM.render(<App />, document.getElementById('root'))` in React 19, Chrome throws `Uncaught TypeError: ReactDOM.render is not a function`.
  - When `src/main.jsx` passes the container a second time to `root.render(<App />, document.getElementById('root'))`, Chrome logs the Console error `You passed a container to the second argument of root.render(...). You don't need to pass it again since you already passed it to create the root.`.
  - When `<div id="root"><p>Loading...</p></div>` has placeholder HTML and `root.render(<App />)` runs, React removes `<p>Loading...</p>` and replaces the inner HTML of `#root` with `<main><header>...</header><section>...</section></main>`.

### Principle 4: Passing a JSX Element (`<App />`) Instead of the Component Function (`App`) to `root.render`
- **Handle**: `render-jsx-element-not-function`
- **Rule**: Pass a JSX element `<App />` to `root.render(<App />)`, never the uninvoked component function reference `App`.
- **Root Distinction**:
  - *Junior blurred view*: Because `import App from './App.jsx'` imports the root component, passing `App` into `root.render(App)` tells React to call `App`.
  - *Senior grounding*: `App` is the JavaScript function definition, while `<App />` creates the React element object that `root.render` requires to start rendering the component tree.
- **Real Beginner Mistake (events, in order)**:
  1. A developer imports the root component function at the top of the entry file.
  2. On the last line of the entry file, the developer passes the bare component function name into the root's render method without wrapping it in angle brackets as a JSX tag.
  3. The render method receives a raw JavaScript function instead of a React element object.
  4. React refuses to render a function as a child, leaves the HTML container empty on screen, and logs an error in the Console.
- **Interview Depth**:
  - Why we pass `<App />` to `root.render(<App />)` instead of calling `root.render(App())` ourselves: `<App />` creates a React element object (`{ type: App, props: {} }`) so React invokes `App` inside its own rendering lifecycle, whereas calling `App()` directly executes the function before `root.render` even receives it and breaks hooks and component tree tracking.
  - Why a standard React application calls `root.render(<App />)` only once at startup in `src/main.jsx`, and how all subsequent screen updates happen through component state updates (`Q12 #use_state`) rather than calling `root.render` again.
- **Bridges**:
  - **Bridge 1**:
    - **Reader will not find**: Angle brackets `<` and `>` on `export default function App()` in `src/App.jsx` or on `import App from './App.jsx'` in `src/main.jsx`.
    - **Who supplies it**: Our code writes `<App />` inside `root.render(<App />)` to turn the imported function `App` into a React element.
    - **What Vite and React do**:
      1. `import App from './App.jsx'` brings the JavaScript function `App` into `src/main.jsx`.
      2. Writing `<App />` inside `root.render(<App />)` causes Vite to compile `<App />` into `jsxDEV(App, {})`, which returns a React element object pointing to `App`.
      3. `root.render` receives that React element object, calls `App()` and every child component in the Component Render Tree (`SiteHeader`, `ArticleList`, `ArticleCard`, `LiveBadge`, `NewBadge`), and inserts the resulting HTML tags inside `<div id="root">`.
- **React Does**:
  - When `src/main.jsx` calls `root.render(App)`, the browser page stays blank, `<div id="root"></div>` stays empty in the `Elements` panel, and Chrome logs the Console error:
    `Functions are not valid as a React child. This may happen if you return App instead of <App /> from render. Or maybe you meant to call this function rather than return it.`
    `  root.render(App)`
  - When `src/main.jsx` calls `root.render(<App />)`, React renders the full Component Render Tree into `<div id="root">`, displaying `Latest Articles`, `City News`, `Section: City News`, `Live`, `New`, `New Park Opens Today`, and `The park on Main Street opens at noon.`.
- **Example Step**: Completes the full 7-file mounted project (`index.html`, `src/main.jsx`, `src/App.jsx`, `src/siteData.js`, `src/components/SiteHeader.jsx`, `src/components/ArticleList.jsx`, `src/components/ArticleCard.jsx`, and `src/components/Badges.jsx`), verifying the live `Elements` panel tree inside `<div id="root">`.
- **Code names**: `src/main.jsx`, `src/App.jsx`, `App`, `<App />`, `root.render(App)`, `root.render(<App />)`, `jsxDEV`, `Functions are not valid as a React child. This may happen if you return App instead of <App /> from render. Or maybe you meant to call this function rather than return it.`
- **Visual idea**: Side-by-side comparison of `root.render(App)` (empty `#root` + Console error `Functions are not valid as a React child`) versus `root.render(<App />)` (complete mounted DOM tree inside `<div id="root">`).

## Interview Points
- `index.html` provides the physical HTML container element (by convention `<div id="root"></div>`), and `document.getElementById('root')` looks up that DOM node so React knows where in the page to attach.
- If `document.getElementById('root')` returns `null` (because the `id` in `index.html` does not match) or if `<App />` is passed directly to `createRoot`, React throws `Error: Target container is not a DOM element.`.
- `index.html` loads the entry file with `<script type="module" src="/src/main.jsx"></script>`, and build tools like Vite compile JSX tags into `jsxDEV` function calls, resolve bare package imports like `'react-dom/client'` from `node_modules`, and follow the ES module `import` graph so `index.html` only needs one `<script>` tag.
- `createRoot` is imported from `'react-dom/client'` (which handles browser DOM attachment, separate from `'react'`'s platform-independent component logic) and initializes the concurrent React root controller for that DOM container, replacing the removed legacy `ReactDOM.render` API.
- Mounting requires two calls: `const root = createRoot(domNode)` creates the root controller, and `root.render(<App />)` triggers the initial render and replaces any existing children inside `#root` with the rendered DOM tree (whereas server-rendered HTML uses `hydrateRoot`).
- `root.render` must receive a JSX element `<App />` (a React element object) rather than the uninvoked function `App` (which logs `Functions are not valid as a React child`), and after the initial `root.render(<App />)` call at startup, subsequent UI updates are driven by component state rather than calling `root.render` again.
