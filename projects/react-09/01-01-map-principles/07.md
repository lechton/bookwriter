## Authorized Scope
Lesson 07 teaches components that act as frames. Whatever the caller writes between a component's tags arrives as one prop, `children`, and the component places it with `{children}`. The caller then decides the content, and the frame decides the design around it. A prop stays the right tool for what every use must have, such as a title. Attributes the frame does not use pass on to its element with `{...rest}`. The attribute written last wins, so a class both sides set is joined, with a default from Q06 for the caller who sets none. The lesson builds a `CardContainer` for Town News's feed, which holds a text story, a photo story, and a quote. It builds on Q06, where attributes became the props object.

## Theme and Options
- **Theme**: Every story on a news site has the same design: the same border, the same spacing. Only the content changes. How does one card component show different content each time?
- **Option**: props: `<ContentCard name="John Hall" />` | Q06 `#props` | when the card decides the content's shape, such as a price tag with a name and a price
- **Option**: `children`: `<ContentCard><p>My name is John Hall</p></ContentCard>` | this lesson | when the caller decides the content, such as a story that has a photo, a quote, or only text
- **This lesson teaches**: `children`, and both together: a `title` prop with the body as `children`

## Principle Thread
- **Anchor**: A component can be a frame the caller fills: what the caller writes between its tags arrives as `children`, and the frame decides where it goes
- **Axis**: one tag from the inside out: the content between the tags, the choice between content and props, and the attributes on the tag
- **Why This Axis**: The content between the tags is the new idea, so it comes first: the reader must see where it goes before choosing between it and a prop. The choice comes second, because it needs both tools in hand. The attributes on the tag come last: they are what is left once the frame has taken its content and its own props, and passing them on is the only step that needs the rest syntax. One axis was rejected. "Caller side, frame side" splits each idea into two halves, so `children` would be taught twice.
- **Spoken Preview**: Everything in this lesson comes down to one idea: a component can be a frame that the caller fills. First, the children prop, which means the content between a component's tags arrives as one prop: the frame shows it wherever it writes children in braces, and nowhere if it forgets. Second, composition, which means children when the caller decides the content, props when the frame decides its shape: the body of a story goes between the tags, and its title stays a prop. Third, prop spreading, which means the attributes the frame does not use pass on to its element: the rest goes on with three dots, the attribute written last wins, and a class both sides set is joined.
- **Closing Line**: Content between the tags, a frame for the shape, and the rest passed on.

## Principles

### Principle 1: The children prop: the content between a component's tags arrives as one prop
- **Handle**: `children-prop`
- **Thread Step**: the content between the tags
- **Rule**: We read what the caller writes between a component's tags as the prop `children`, and we place `{children}` where the content belongs; a frame that never writes it drops the content without a warning.
- **Kind**: Model
- **Reader Question**: "I put a headline between `<CardContainer>` and `</CardContainer>`. Where does it go?"
- **Reader Expects**: it shows inside the card, as content inside an HTML `<div>` does
- **React Does**: the build passes the content between the tags as one more property of the props object, named `children`: `_jsxDEV(CardContainer, { children: ... })`; the name is always `children`, while a prop's name is the one we write; the frame decides where the content goes by writing `{children}`; a frame that never writes it shows nothing of the content, and a component inside the content never runs; `children` is the element itself for one child, an array for several, a string for text, and `undefined` for none, and `{children}` shows each of them
- **Placement**: `function CardContainer({ children })` and `{children}` inside the frame's markup
- **Real Mistake**: `CardContainer` returns `<article className="card"></article>` while the caller nests `<h2>New Park Opens Today</h2>`; the page shows an empty card, with no warning; with `{children}` inside the `<article>`, the headline shows; verified in React 19.3.1 and Chrome
- **Fix In**: this principle
- **Importance**: the card's main subject; the bank question's first part; the silent empty frame ships
- **Prediction**: four frames, holding one `<h2>`, an `<h2>` and a `<p>`, a text, and nothing: `children` is an element, an array of two, a string, and `undefined`, and the page shows each content; `children.map` throws "children.map is not a function" for the single `<h2>`
- **Required Lesson Proof**: `CardContainer` without `{children}`: the empty card; with it: the headline; the four kinds of content and what `children` holds for each; the call in the Sources panel.

### Principle 2: Composition: children when the caller decides the content, props when the frame decides its shape
- **Handle**: `children-or-props`
- **Thread Step**: the choice between content and props
- **Rule**: We pass content that changes from use to use as `children`, and we keep a prop for what every use must have and the frame must place, such as the title.
- **Kind**: Decision
- **Reader Question**: "One story has a photo, another a quote, another only text. Do I add a prop for each?"
- **Reader Expects**: yes, as in Lecture 6: one prop per piece, `title`, `author`, `imageUrl`, `quote`
- **React Does**: every piece a prop names must be drawn by the card in a fixed place, so a story without that piece leaves an empty place, and a story with a new kind of piece needs a new prop; with `children`, the caller writes the body and the card draws only the frame around it; a piece every story has, such as the title, stays a prop, so the frame puts it in the same place on every card
- **Placement**: `<CardContainer title="Rail Strike Ends">` with the body between the tags; the frame's markup with `<h2>{title}</h2>` and `{children}`
- **Real Mistake**: a rigid `NewsCard({ title, author })` that draws `<p>By {author}</p>`; the weather story, which has no author, shows "By " with nothing after it; with `CardContainer`, the weather story simply has no byline between its tags; verified in React 19.3.1 and Chrome
- **Importance**: the card's Friction and Code Experiment; the lesson's theme; reviewers flag a component with twenty props
- **Review Point**: Condition
- **Required Lesson Proof**: the rigid `NewsCard` with and without an author: the empty "By"; `CardContainer` with three bodies: a text story, a photo story, and a quote, each with its `title` prop in the same place.

### Principle 3: Prop spreading: the attributes the frame does not use pass on to its element
- **Handle**: `spread-the-rest`
- **Thread Step**: the attributes on the tag
- **Rule**: We take out the props the frame uses and pass only the rest to its element with `{...rest}`; the attribute written last wins, so a class the frame and the caller both set is joined, with an empty default for the caller who sets none.
- **Kind**: Decision
- **Reader Question**: "Callers want a `className` and an `aria-label` on the card. Do I list each one?"
- **Reader Expects**: the attributes on `<CardContainer>` reach its `<article>` by themselves, as attributes on an HTML tag do
- **React Does**: attributes on our component's tag only go into its props, so none reaches the `<article>` unless the frame passes it on; `({ children, ...rest })` takes `children` out and collects every other prop into `rest`, and `{...rest}` writes them all on the element; attributes apply in the order they are written, and the last one wins: `<article className="card" {...rest}>` with the caller's `className="featured"` gives `class="featured"`, and the card's base class is gone; written the other way, the caller's class is lost; a class both sides set must be joined: `'card ' + className` gives "card featured", but "card undefined" for a caller who passes no class, so the parameter list takes the default from Lecture 6, `className = ''`; spreading every prop instead of the rest puts props the element does not understand into the DOM
- **Placement**: `function CardContainer({ title, children, className = '', ...rest })` and `<article className={'card ' + className} {...rest}>`
- **Real Mistake**: `({ children, ...rest })` with `<article className="card" {...rest}>`, and the caller's `className="featured"`; the card loses its border and padding, because `class` is "featured"; the joined `'card ' + className` then shows `class="card undefined"` on a card with no class; `className = ''` gives "card featured" and "card "; also `{...props}` with `isFeatured` and `date`, which puts `date="May 3"` in the DOM and prints "React does not recognize the `isFeatured` prop on a DOM element"; verified in React 19.3.1 and Chrome
- **Importance**: the bank question's second and third parts; reviewers flag a lost base class and unknown props in the DOM; the junior fix and its catch are one answer
- **Review Point**: Do
- **Required Lesson Proof**: the frame that ignores its attributes: no class, no `id`, no `aria-label`; the spread after `className="card"`: `class="featured"`; the join without and with the default: "card undefined", then "card ".

## Senior Answer
Whatever we nest between a component's tags arrives as a prop named `children`. The component decides where it goes by writing `{children}`, and if it never does, the content is dropped without a warning. That makes a component a frame: the caller decides the content, and the frame decides the design around it. I use `children` for content that changes from use to use, and I keep a prop, such as `title`, for what every use must have. For attributes the frame does not use, I destructure what I need and collect the rest with `...rest`, then spread it on the element with `{...rest}`. The attribute written last wins, so a class both sides set must be joined. A default from destructuring, `className = ''`, keeps a missing class from becoming the text "undefined". I spread only the rest, because unknown props land in the DOM and React warns about them.
