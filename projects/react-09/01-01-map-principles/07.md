## Authorized Scope
Lesson 09 teaches how our components get onto the page. The browser loads `index.html`, and its body holds one empty element, `<div id="root">`. A module script tag loads `main.jsx`. The browser cannot read JSX or a package name such as `'react-dom/client'`. So the dev server rewrites each file into plain JavaScript before it sends it. `npm run build` does the same once and writes the result into `dist/`. In `main.jsx`, `createRoot` takes the empty element and gives React control of it. `root.render(<App />)` then shows the root component inside it. An app built fully with React has one root. Every new part of the page is a tag inside `App`. The lesson builds on Q01, where `main.jsx` was a prepared file. It builds on Q03, where the build first appeared, and on Q08, whose imports `main.jsx` uses. The project is the article site of Lessons 05 to 08. `App` shows `SiteHeader` and `ArticleList`, each in its own file in `components`.

## Theme and Options
- **Theme**: We wrote our components. How does React get onto a real web page?
- **Option**: A full-stack framework: `npx create-next-app@latest` | Q45 `#project_setup` | a site whose pages the server should send ready, with routing built in; the framework calls the mount code for us
- **Option**: A build tool with an entry file: `createRoot(document.getElementById('root')).render(<App />)` | this lesson | a single-page app built from scratch, where our own `main.jsx` starts React
- **Option**: React on part of an existing page: `createRoot(document.getElementById('comments')).render(<Comments />)` | this lesson | a site built with other tools that adds React to one area, such as a comments section
- **This lesson teaches**: a build tool with an entry file (Vite, `main.jsx`, and `createRoot`)

## Principle Thread
- **Anchor**: Mounting: the browser loads one page, and React fills one element of it with our components
- **Axis**: the order of one page load: the page arrives, its code arrives, React takes one element, React fills it, and the app grows from there
- **Why This Axis**: Each step needs the one before it. The empty element must exist before anything can fill it. The browser must receive `main.jsx` as plain JavaScript before any line of it runs. `createRoot` must take the element before `root.render` can show anything in it. Only after the first render does the question of where the app grows make sense. Two axes were rejected. "The files from top to bottom (`index.html`, `main.jsx`, `App.jsx`)" has no place for the build tool, which is not a file we write. "Who does the work: the browser, Vite, React" puts the root and the render in one group and leaves the growth of the app with no owner.
- **Spoken Preview**: Everything in this lesson comes down to one idea: mounting, which means the browser loads one page, and React fills one element of it with our components. First, the root element, which means the page arrives with one empty element: we leave that element empty in the HTML file and write every part of the page in our components. Second, the build tool, which means the page's code arrives as plain JavaScript: we open the project through the dev server, because a browser cannot read JSX or a package name by itself. Third, the React root, which means the page hands that one element to React: we find the element by the same id the HTML file gives it, and we hand React the element itself. Fourth, the initial render, which means the page shows the root component in that element: we ask the root to render once, with the root component written as a tag. Fifth, one root per app, which means the page grows inside the root component: a new part of the page is a new tag inside the root component, never a second root on the same element.
- **Closing Line**: One empty element, plain JavaScript, one root, one render, and the rest inside the root component.

## Principles

### Principle 1: The root element: the page arrives with one empty element
- **Handle**: `root-element`
- **Thread Step**: the page arrives
- **Rule**: We leave `<div id="root">` empty in `index.html` and write every part of the page in our components; React fills that element when `main.jsx` runs, and replaces anything we typed inside it.
- **Kind**: Model
- **Reader Question**: "`index.html` has only an empty `<div id="root">`. Where is the page I see, and where do I change it?"
- **Reader Expects**: the page's HTML lives in `index.html`, as on every plain HTML site, so the site's title can be typed into the div
- **React Does**: the browser reads `index.html` top to bottom and builds an empty `<div id="root">`; the `<script type="module">` tag loads `main.jsx`, which runs after the whole HTML is read; `main.jsx` hands the div to React, and React builds `App`'s elements inside it; View Page Source shows the file as the server sent it, with the div empty and two script lines the dev server adds; the Elements panel shows the live page, with the header and two articles inside the div; React clears whatever the file wrote inside the div on its first render
- **Placement**: `<div id="root"></div>` empty in `index.html`; the site's title in `SiteHeader`; HTML outside the div stays as the file wrote it
- **Real Mistake**: `<h1>Latest Articles</h1>` typed inside `<div id="root">` in `index.html`, to give the page a title; once `main.jsx` runs, the div holds only `App`'s header and articles, and the typed `<h1>` is gone; verified in React 19.3.1, Vite 8.3.4, and Chrome
- **Fix In**: this principle
- **Importance**: the card's Friction (an empty div and no idea where the page comes from); every later lesson inspects the page in the Elements panel, not in `index.html`
- **Prediction**: View Page Source shows `<div id="root"></div>` with nothing inside; the Elements panel shows the header and two articles inside the same div

### Principle 2: The build tool: the page's code arrives as plain JavaScript
- **Handle**: `build-tool`
- **Thread Step**: its code arrives
- **Rule**: We open the project through the dev server with `npm run dev`, never by double-clicking `index.html`, because the browser cannot read JSX or a package name; for a real server, `npm run build` writes the same plain JavaScript into `dist`.
- **Kind**: Model
- **Reader Question**: "Why can't I just double-click `index.html`, like any HTML page I wrote before?"
- **Reader Expects**: an HTML file opens straight from the disk, as every plain HTML page does, and its script tag loads `main.jsx` like any script
- **React Does**: a double-clicked file opens at a `file://` address; Chrome refuses to load a module script from there ("Access to script at 'file:///src/main.jsx' from origin 'null' has been blocked by CORS policy"), and the div stays empty; even from a plain file server, the browser stops at the first JSX tag ("Unexpected token '<'"), and a package name with no path fails ("Failed to resolve module specifier "react-dom/client""); the dev server answers each request at a `localhost` address and rewrites the file first: `<App />` becomes `_jsxDEV(App, {})`, and `'react-dom/client'` becomes a path into `node_modules/.vite/deps/react-dom_client.js`; `npm run build` does the same once and writes `dist/index.html` and one JavaScript file with no JSX left; `npm run preview` serves `dist`, and a double-clicked `dist/index.html` is blank too
- **Placement**: `npm run dev` in the project folder, then the `localhost` address it prints; `npm run build` before the site goes to a server
- **Real Mistake**: `index.html` double-clicked in the file manager to see the page; the browser opens `file:///.../index.html`, the page is blank, and the console shows "Access to script at 'file:///src/main.jsx' from origin 'null' has been blocked by CORS policy"; `npm run dev` and its `localhost` address show the page; verified in Vite 8.3.4 and Chrome
- **Fix In**: this principle
- **Importance**: the bank question's second half; the card's Code Experiment Naive; juniors send a `dist/index.html` by email and report a blank page
- **Prediction**: the Sources panel shows the served `main.jsx` with `_jsxDEV(App, {})` and an import from `node_modules/.vite/deps/react-dom_client.js`, where our file says `<App />` and `'react-dom/client'`
- **Required Lesson Proof**: the double-clicked `index.html`: blank, with the CORS line; the same project through `npm run dev`: the article site; the served `main.jsx` in the Sources panel; `npm run build`: the `dist` folder and its files.

### Principle 3: The React root: the page hands that one element to React
- **Handle**: `react-root`
- **Thread Step**: React takes one element
- **Rule**: We call `createRoot` once in `main.jsx` with the element itself, found by the same id that `index.html` gives it; React then controls everything inside that element and nothing outside it.
- **Kind**: Decision
- **Reader Question**: "What does `createRoot(document.getElementById('root'))` do with the empty element?"
- **Reader Expects**: `document.getElementById` finds the div, as in Lecture 1, and `createRoot` shows the app in it at once
- **React Does**: `document.getElementById('root')` returns the div, or `null` when no element has that id; `createRoot` takes the element and returns a React root, an object with two methods, `render` and `unmount`; nothing shows yet; from now on React controls the DOM inside that element, and HTML outside it stays as the file wrote it; with `null`, or with a tag such as `<App />` in place of the element, `createRoot` throws "Target container is not a DOM element." and the page stays blank; `createRoot` comes from `react-dom/client`, the package that puts React into a browser page
- **Placement**: `import { createRoot } from 'react-dom/client'` and `createRoot(document.getElementById('root'))` in `main.jsx`; the id string equal to the `id` in `index.html`; never inside a component
- **Real Mistake**: the div renamed to `<div id="app">` in `index.html` while `main.jsx` still asks for `'root'`; the page is blank, and the console shows "Target container is not a DOM element."; the matching id shows the page; verified in React 19.3.1 and Chrome
- **Importance**: the bank question's first half; createRoot's first Troubleshooting entry; interviewers ask what `createRoot` takes and returns
- **Review Point**: Do
- **Required Lesson Proof**: the renamed id: blank, with the error; `createRoot(<App />)`: the same error; the matching id with no `render` yet: an empty div and an empty console.

### Principle 4: The initial render: the page shows the root component in that element
- **Handle**: `initial-render`
- **Thread Step**: React fills it
- **Rule**: We call `render` on the root once, with the root component written as a tag, `root.render(<App />)`, and nothing else; React 19 has no `ReactDOM.render`, and the element is never passed a second time.
- **Kind**: Decision
- **Reader Question**: "My old tutorial writes `ReactDOM.render(<App />, document.getElementById('root'))` in one line. Why does our `main.jsx` use two steps?"
- **Reader Expects**: the one-line form still works, because tutorials and code answers online still print it
- **React Does**: React 18 marked `ReactDOM.render` as old, and React 19 removed it; `import ReactDOM from 'react-dom'` then gives no such function, and the page stops with "ReactDOM.render is not a function"; the new form splits the job: `createRoot` takes the element once, and `root.render(<App />)` says what to show in it; `render` takes one argument, a React element; the element passed again as a second argument logs "You passed a container to the second argument of root.render(...). You don't need to pass it again since you already passed it to create the root."; `root.render(App)`, a function without its tag, shows nothing and logs "Functions are not valid as a React child."; React calls `App` and builds its elements inside the div; `render` returns before the page changes, so a log on the next line still sees an empty div; Vite's `main.jsx` wraps the tag in `<StrictMode>`
- **Placement**: `root.render(<App />)` once, in `main.jsx`, right after `createRoot`; `<StrictMode>` around `<App />` as Vite writes it
- **Real Mistake**: `main.jsx` written from an old tutorial: `import ReactDOM from 'react-dom'` and `ReactDOM.render(<App />, document.getElementById('root'))`; the page is blank, and the console shows "ReactDOM.render is not a function"; `createRoot(...).render(<App />)` shows the page; verified in React 19.3.1, Vite 8.3.4, and Chrome
- **Importance**: the card's Code Experiment Naive and Under the Hood; the React 19 upgrade guide's first removal; interviewers ask what replaced `ReactDOM.render`
- **Review Point**: Do not
- **Required Lesson Proof**: the tutorial's one line: blank, with the error; the container passed again: the warning; `root.render(App)`: the warning and an empty div; `root.render(<App />)`: the article site.

### Principle 5: One root per app: the page grows inside the root component
- **Handle**: `one-root`
- **Thread Step**: the app grows from there
- **Rule**: In an app built fully with React, we add each new part of the page as a tag inside `App`, never as a second `createRoot` or a second `render`; a page only partly built with React gives each separate React area its own element and its own root.
- **Kind**: Decision
- **Reader Question**: "I want a footer under the articles. Do I add a second `createRoot` for it in `main.jsx`?"
- **Reader Expects**: each piece of the page is mounted on its own, as Lecture 1's plain JavaScript found each element and filled it
- **React Does**: a second `createRoot` on the same element logs "You are calling ReactDOMClient.createRoot() on a container that has already been passed to createRoot() before. Instead, call root.render() on the existing root instead if you want to update it.", and the element shows only the footer: the second render replaced the header and the articles; a second `root.render` on one root does the same with no warning, because each call replaces what the root shows; `<Footer />` written after `<ArticleList />` inside `App` shows all three; from then on the page changes from inside the components; a page partly built with React, such as an old site with one comments area, gives that area its own element and its own root, and each root is a separate tree
- **Placement**: `<Footer />` inside `App`'s return, after `<ArticleList />`; one `createRoot` and one `render` in `main.jsx`; a second root only on a second element of a page React does not fully own
- **Real Mistake**: `createRoot(document.getElementById('root')).render(<Footer />)` added under the first mount in `main.jsx`; the page shows only "Latest Articles, 2026", and the console shows "You are calling ReactDOMClient.createRoot() on a container that has already been passed to createRoot() before."; `<Footer />` inside `App` shows the header, the articles, and the footer; verified in React 19.3.1 and Chrome
- **Importance**: react.dev's rule for apps built fully with React; reviewers flag a second root; interviewers ask how many roots an app has and when there are more
- **Review Point**: Condition
- **Required Lesson Proof**: the second `createRoot` on `#root`: only the footer, with the warning; `<Footer />` inside `App`: the whole page; two elements with one root each: both areas show.

## Senior Answer
The browser loads `index.html`, and its body holds one empty element, usually `<div id="root">`. A module script tag loads `main.jsx`. The browser cannot read JSX or a package name. So a build tool such as Vite rewrites each file into plain JavaScript first. In development the dev server does it on every request. For production, `npm run build` writes the result into `dist`. In `main.jsx`, `createRoot` from `react-dom/client` takes the element, and from then on React controls everything inside it. `root.render(<App />)` shows the root component there, and React builds the page from the tree below `App`. This replaced `ReactDOM.render`, which React 19 removed. An app built fully with React has one root and one render call. Every new part of the page is a tag inside `App`. Only a page partly built with React has several roots, one per element.
