## Authorized Scope
Lesson 11 teaches how a component shows one element for each item of an array. The data moves out of the JSX into an array of objects, `articles`, in its own file. Inside the JSX, `articles.map(...)` turns each article into an `<ArticleCard />`, and React shows the array of elements in order. `filter()` before `map()` keeps only some items, such as the articles of one topic, City or Sport. Each element gets a `key` from the article's own `id`. With the key, React matches each article with the same element the next time the list is shown. The lesson shows it with text typed into a comment box. Then an article is added at the top of the data file, and the file is saved. The key is written on the tag inside `map()`, and the child never receives it as a prop. The lesson builds on Q04, where braces placed any value, and on Q07, where an array first appeared. It also builds on Q10, where `> 0` made a number safe on the left of `&&`.

## Theme and Options
- **Theme**: A page shows many items of the same kind: articles, comments, products. How does a component show one piece of markup for each item?
- **Options**: none (starting point: each card written by hand, one tag per article, Lectures 2 to 10)
- **This lesson teaches**: rendering a list with `map()` and keys

## Principle Thread
- **Anchor**: Rendering a list: an array of data becomes an array of elements, each with its own key
- **Axis**: from data to named elements, in two stretches: turning items into elements (every item, then only some), and naming the elements (what the name does, then where it goes)
- **Why This Axis**: Each step needs the one before it. `map()` comes first, because every later step works on the array it gives back. Filtering is a second array method placed before `map()`, so it needs `map()` in hand. The key names the elements `map()` makes, so it comes after them, and the question of where the key goes only makes sense once the reader knows what the key is for. Two axes were rejected. "Data, JSX, console" orders by where the reader looks, and it splits the key across all three. "Without a key, with an index, with an id" turns the lesson into a list of key forms and leaves no place for `map()` and `filter()`.
- **Spoken Preview**: Everything in this lesson comes down to one idea: rendering a list, which means that an array of data becomes an array of elements, each with its own key. First, mapping, which means turning every item into an element: we call map on the array, and the arrow function gives back one element for each item. Second, filtering, which means turning only some items into elements: we filter the array before we map it, and when nothing is left, we show a message instead of an empty space. Third, keys, which means naming each element so React can tell the items apart: each key comes from the item's own id, so a new item at the top leaves every other item with its own element. Fourth, the key's place, which means naming the element the map gives back: the key goes on the tag written inside the map, never inside the child component.
- **Closing Line**: Every item, only some items, one name each, and the name on the right element.

## Principles

### Principle 1: Mapping: turning every item into an element
- **Handle**: `map-to-elements`
- **Thread Step**: turning items into elements: every item
- **Rule**: To show one element per item, we call `map()` on the array inside the JSX, and its arrow function gives back the element: right after `=>`, or with `return` when the body starts with a curly brace.
- **Kind**: Model
- **Reader Question**: "I have the articles in an array. How do I show a card for each without writing every tag?"
- **Reader Expects**: a loop, as in plain JavaScript: a `for` loop, or `forEach`, that writes one card per article
- **React Does**: a `for` loop is a statement and cannot go inside the braces (Q04); `forEach` runs the function for each article but gives back `undefined`, so the braces place nothing; `map()` runs the function for each article and gives back a new array of what it returned; an arrow function gives back the expression right after `=>`, so `article => <ArticleCard ... />` gives three elements; React shows an array of elements in order; an arrow function whose body starts with `{` gives back nothing unless it says `return`, so every item becomes `undefined` and no card shows, with no warning
- **Placement**: `{articles.map(article => <ArticleCard key={article.id} article={article} />)}` inside `<main>` in `ArticleList`; the data in `articles.js`
- **Real Mistake**: `{articles.map(article => { <ArticleCard article={article} />; })}` in `ArticleList`, the curly brace added to make room for a second line later; the page shows the header and the footer and no card, and the console is empty; `article => <ArticleCard ... />`, or `return` inside the braces, shows the three cards; verified in React 19.3.1, Vite 8.3.4, and Chrome
- **Fix In**: this principle
- **Importance**: the bank question's first half; react.dev's arrow-function `<Pitfall>`; the empty list with no message is hard to trace
- **Prediction**: a `console.log` of the mapped array shows 3 elements, the first of type `ArticleCard` with the key `"1"`; with `forEach`, the braces receive `undefined` and the page shows no card
- **Required Lesson Proof**: the `forEach` version and the block body without `return`: no cards, no message; the arrow that gives back the element: three cards; the logged array.

### Principle 2: Filtering: turning only some items into elements
- **Handle**: `filter-then-map`
- **Thread Step**: turning items into elements: only some items
- **Rule**: To show only some items, we call `filter()` before `map()`; when the filtered array can be empty, we test its length with `> 0` and show a message instead.
- **Kind**: Decision
- **Reader Question**: "Each topic gets its own section with only its articles, and an empty section needs a message. How?"
- **Reader Expects**: an `if` inside the map's function that skips the other articles, and `&&` on the list, as Q10 showed one piece or nothing
- **React Does**: `filter()` runs a test for each article and gives back a new array of the articles that passed, here `article.topic === topic`; `map()` then turns only those into cards; for a topic with no articles, `filter()` gives an empty array, and `map()` gives an empty array, so the section shows only its heading; `shown.length && ...` gives back the length, `0`, a number, so a bare `0` appears under the heading, the trap of Q10 on a new value; `shown.length > 0 ? shown.map(...) : <p>No Sport articles yet.</p>` shows the message
- **Placement**: `const shown = articles.filter(article => article.topic === topic);` above the `return` of `ArticleList`, and the ternary in its JSX
- **Real Mistake**: `ArticleList({ topic })` with `{shown.length && shown.map(...)}`, used as `<ArticleList topic="City" />` and `<ArticleList topic="Sport" />`; the City section shows its card, and the Sport section shows a bare `0` under its heading; `shown.length > 0 ? ... : <p>No Sport articles yet.</p>` shows the message; verified in React 19.3.1 and Chrome
- **Importance**: react.dev's second section; every topic page and search result meets an empty list; the `0` ships with no error
- **Review Point**: Do
- **Required Lesson Proof**: the City and Sport sections with the bare length: the card and the `0`; with the ternary: the card and the message.

### Principle 3: Keys: naming each element so React can tell the items apart
- **Handle**: `keys-name-items`
- **Thread Step**: naming the elements: what the name does
- **Rule**: We give each element a `key` from the item's own id, so React matches every item with the same element the next time the list is shown; the array index fits only a list that never changes order, and a key made while rendering fits nothing.
- **Kind**: Model
- **Reader Question**: "The cards show fine. Why does React insist on a key?"
- **Reader Expects**: the key only quiets the console, so any unique value, such as the position in the array, will do
- **React Does**: when the list is shown again, React matches each new element with one from last time; with a key, it matches by key; without one, it matches by position, the first with the first; a new article saved at the top shifts every article down one position, so the element that held "Rain Expected This Weekend" now shows "New Park Opens Today", and the text typed into its comment box stays where it was, under the wrong article; `key={index}` does the same matching by position, so the warning goes and the bug stays; `key={article.id}` follows the article: React keeps Rain's element, moves it down, and builds one new element for the new article; `key={Math.random()}` changes on every render, so no element ever matches, every card is built again, and the typed text is gone
- **Placement**: `key={article.id}` on `<ArticleCard>`, inside `map()`; the `id` stored in each object of `articles.js`
- **Real Mistake**: `{articles.map(article => <ArticleCard article={article} />)}` with no key; the console shows "Each child in a list should have a unique "key" prop."; "Great news!" typed into the comment box of "Rain Expected This Weekend", then a new article saved at the top of `articles.js`: the text now sits under "New Park Opens Today"; `key={index}` removes the warning and moves the text the same way; `key={article.id}` keeps it under "Rain Expected This Weekend"; verified in React 19.3.1, Vite 8.3.4, and Chrome
- **Fix In**: this principle
- **Importance**: the bank question's second half; the card's Friction; interviewers ask why keys exist and why not the index
- **Prediction**: with `key={article.id}`, after the save, "Great news!" is still under "Rain Expected This Weekend", now the third card; with no key or the index, it is under "New Park Opens Today"
- **Required Lesson Proof**: the same typing and the same save with no key, with `key={index}`, with `key={Math.random()}`, and with `key={article.id}`: four results.

### Principle 4: The key's place: naming the element the map gives back
- **Handle**: `key-on-mapped-element`
- **Thread Step**: naming the elements: where the name goes
- **Rule**: We write the `key` directly on the tag the `map()` call gives back, never inside the child component and never inside a spread object, and when the child needs the id, we pass it again as a prop of its own.
- **Kind**: Decision
- **Reader Question**: "I put the key in, and the warning is still there. Where does it go?"
- **Reader Expects**: the key goes on the element that repeats on the page, the `<article>` inside the card, because that is what the Elements panel shows many times
- **React Does**: React needs the key on the elements of the array it receives, and that array holds `<ArticleCard>` elements, not `<article>` elements; a key on the `<article>` inside the card is one element of the card's own markup, so the warning stays and names `ArticleList`; React keeps the key for itself: the card's `key` prop is `undefined`, and the console says "`key` is not a prop"; a key hidden inside a spread object prints "A props object containing a "key" prop is being spread into JSX"; an item with several elements and no single tag uses `<Fragment key={article.id}>`, because `<>` takes no key
- **Placement**: `<ArticleCard key={article.id} article={article} />` inside `map()`; `<ArticleCard key={article.id} articleId={article.id} ... />` when the card needs the id
- **Real Mistake**: `key={article.id}` moved onto the `<article>` inside `ArticleCard`, while `ArticleList` writes `<ArticleCard article={article} />`; the cards show, and the console still shows "Each child in a list should have a unique "key" prop. ... Check the render method of `ArticleList`."; the key on `<ArticleCard>` removes it; verified in React 19.3.1 and Chrome
- **Importance**: react.dev's Challenge "Extracting a list item component"; the `<Pitfall>` on `key` not being a prop; reviewers flag keys on the wrong element
- **Review Point**: Do
- **Required Lesson Proof**: the key inside the card: the warning; on the tag inside `map()`: none; the card reading `key`: `undefined` and the warning; the keyed `Fragment`: titles and authors with no warning.

## Senior Answer
React shows an array of elements in order. So I keep the data in an array of objects and call `map()` inside the JSX. Its arrow function gives back one element per item. To show only some items, I call `filter()` first. When the result can be empty, I test its length with `> 0` and show a message. Every element in the array needs a `key`. React uses the key to match each item with the same element the next time the list is shown. Without a key, React matches by position. Then an item added at the top moves every typed text and every focus to the wrong item. The index fails the same way, and `Math.random()` rebuilds every element on each render. So the key comes from the data's own id. It goes on the tag inside `map()`, not inside the child. The child never receives it, so I pass the id again when the child needs it.
