## Authorized Scope
Lesson 04 teaches curly braces in JSX. It works inside one component, `ArticleCard`, that uses only local variables. They hold a headline, an author, an image address, a word count and the reading time computed from it, and whether the story is live. Curly braces open a window to JavaScript in two places: between tags, and right after an attribute's `=`. Everything outside them stays text. The code inside runs each time React calls the component, and its value takes the place of the braces. The braces hold one expression, code that gives back a value, or a comment. React shows strings and numbers as text and shows nothing for `true`, `false`, `null`, and `undefined`. An object is never shown as text, but an attribute such as `style` takes one, which is why some code has double braces. The lesson builds on Q01, where `{userName}` showed a name, and on Q03, where every tag became a call and an object.

## Theme and Options
- **Theme**: A page shows values that live in JavaScript: a headline, an author's name, the address of a photo. How does markup that looks like HTML read them?
- **Options**: none (starting point: fixed text between tags and fixed values in quotes, Q03)
- **This lesson teaches**: curly braces in JSX

## Principle Thread
- **Anchor**: Curly braces open a window to JavaScript: the code inside runs when React calls the component, and its value takes the place of the braces
- **Axis**: the path of one value through the window: where it opens (the text, an attribute), what it holds (an expression, a comment), and what comes out (a value the page shows, an object it does not)
- **Why This Axis**: A reader first needs to know where the window can open, because a brace in the wrong place is plain text. Only then does it matter what the window may hold: an `if` fails at the build, before anything runs, and a comment is the one thing it holds that gives no value. What comes out comes last, because it happens only when React runs the component and turns the value into the page; a reader who has not yet written a working expression cannot meet it. The six principles fall into three stretches of two, so a listener follows three steps instead of six. Two axes were rejected. "Kinds of value: string, number, boolean, object" puts the value table first, but the reader cannot place a value before knowing where braces go. "Text against attributes" splits the lesson in two halves that each repeat the same rules about expressions and values.
- **Spoken Preview**: Everything in this lesson comes down to one idea: curly braces open a window to JavaScript, and the value of the code inside takes their place. The first two principles say where the window opens. First, embedding expressions, which means curly braces put a JavaScript value where the text goes: the name of a variable in braces shows its value, and everything outside the braces stays text. Second, dynamic attributes, which means curly braces put a JavaScript value where the attribute value goes: the whole value goes in one pair of braces, with no quotes, and quotes stay for fixed text. The next two say what the window holds. Third, expressions, not statements, which means curly braces hold code that produces a value: a variable, a sum, a call, or a choice with a question mark, but never a statement such as if. Fourth, JSX comments, which means curly braces hold a comment the page never shows: a note in the markup goes inside braces, between a slash and a star. The last two say what comes out. Fifth, rendered values, which means curly braces show strings and numbers, and nothing for true, false, null, and undefined: a value the reader must see becomes text first. Sixth, double curlies, which means curly braces pass an object only to an attribute that expects one: an object is never shown as text, and the style attribute takes one inside a second pair of braces.
- **Closing Line**: The text or an attribute, an expression or a comment, and a value the page can show.

## Principles

### Principle 1: Embedding expressions: curly braces put a JavaScript value where the text goes
- **Handle**: `braces-in-text`
- **Thread Step**: where it opens: the text between tags
- **Rule**: We put a value from JavaScript into the text by writing it in curly braces; everything outside the braces stays text, and the code inside runs each time React calls the component.
- **Kind**: Model
- **Reader Question**: "Lecture 1 wrote `{userName}`. What do the braces actually do, and what stays text?"
- **Reader Expects**: the braces mark a name that the page fills in later, like a blank in a form letter; a habit from templates such as `${name}` in a JavaScript string
- **React Does**: the build passes the variable itself into the call: `<h2>{headline}</h2>` becomes `_jsxDEV("h2", { children: headline })`, while `<h2>headline</h2>` becomes `children: "headline"`; React calls `ArticleCard`, the code in the braces runs, and its value takes their place; text outside the braces is kept, but a line break between a value and text is removed; the Elements panel shows "City Library Extends Its Hours"
- **Placement**: braces between tags, alone (`<h2>{headline}</h2>`) or beside text (`<p>By {author}</p>`); `{' '}` where a line break separates a value from text
- **Real Mistake**: `const readTime = Math.ceil(wordCount / 200)` above the `return`, then `{readTime}` on one line and `min read` on the next, inside one `<p>`; the page shows "3min read"; `{' '}` after the braces shows "3 min read"; verified in React 19.3.1 and Chrome
- **Fix In**: this principle
- **Importance**: the card's main subject; every other principle uses this model; "3min read" ships often, and reviewers meet `{' '}` added by Prettier
- **Prediction**: the Sources panel shows `children: headline` with no quotes for `{headline}` and `children: "headline"` for the bare word; a `console.log` in a function called inside the braces prints each time React calls `ArticleCard`, once per save in the lesson's project
- **Required Lesson Proof**: `ArticleCard` with `<h2>headline</h2>`, then `<h2>{headline}</h2>`: the page and the Sources panel for each; `<p>By {author}</p>`: "By Samantha Robinson"; the line-break case and its `{' '}` fix.

### Principle 2: Dynamic attributes: curly braces put a JavaScript value where the attribute value goes
- **Handle**: `braces-in-attribute`
- **Thread Step**: where it opens: right after an attribute's equals sign
- **Rule**: We give an attribute a value from JavaScript by writing the whole value in one pair of curly braces, right after the equals sign and with no quotes, and we keep quotes for fixed text.
- **Kind**: Decision
- **Reader Question**: "My image address is in a variable. How do I put it into `src`?"
- **Reader Expects**: braces inside the quotes, `src="{avatarUrl}"`, or braces around one part of a longer address, because HTML attributes always sit in quotes
- **React Does**: quotes always pass fixed text, braces or not: `src="{avatarUrl}"` sets the text `{avatarUrl}`, and the browser requests `/%7BavatarUrl%7D`; braces right after `=` pass the variable's value; a value built from parts goes in one pair of braces, with `+` or a template literal; a boolean attribute such as `disabled` needs a boolean, so `disabled="false"` disables the button
- **Placement**: `src={avatarUrl}`, `alt={'Photo of ' + author}`, `` src={`/images/${imageId}.jpg`} ``, `disabled={isLive}`; quotes for fixed text, `className="byline"`
- **Real Mistake**: `<img src="/images/{imageId}.jpg" alt={headline} />`; the `src` attribute stays `/images/{imageId}.jpg`, the browser requests `/images/%7BimageId%7D.jpg`, and the image is broken; `` src={`/images/${imageId}.jpg`} `` loads `/images/library-hours.jpg`; also `disabled="false"`: the button stays disabled, and the console shows "Received the string `false` for the boolean attribute `disabled`. The browser will interpret it as a truthy value. Did you mean disabled={false}?"; verified in React 19.3.1 and Chrome
- **Importance**: the card's Friction (the broken image); the react.dev Challenge; reviewers flag a quoted variable on sight
- **Review Point**: Do not
- **Required Lesson Proof**: `ArticleCard` with `src="{avatarUrl}"` and `src="/images/{imageId}.jpg"`: broken images, and the `src` in the Elements panel; with `src={avatarUrl}` and the template literal: both images load.

### Principle 3: Expressions, not statements: curly braces hold code that produces a value
- **Handle**: `expression-not-statement`
- **Thread Step**: what it holds: an expression
- **Rule**: We put only an expression, code that produces a value, inside curly braces: a variable, a sum, a call, or a ternary; a statement such as `if` goes above the `return`, and its result goes into the braces through a variable.
- **Kind**: Decision
- **Reader Question**: "The label should say Live now only when the story is live. Can I write an `if` inside the braces?"
- **Reader Expects**: yes; any JavaScript can go inside, as in a script
- **React Does**: the braces become the value of one property in a call, such as `children: ...`; a value can only be an expression; `if`, `for`, and `const` give back no value, so the build stops before anything runs; a ternary gives back one of two values, and an `if` above the `return` can set a variable that the braces read
- **Placement**: `{headline}`, `{Math.ceil(wordCount / 200)}`, `{formatReadTime()}`, `{isLive ? 'Live now' : 'Recorded'}` inside the braces; `if` and `const` above the `return`
- **Real Mistake**: `<p>{if (isLive) { 'Live now' }}</p>`; the page stays empty, and Vite's overlay shows "[PARSE_ERROR] Unexpected token" under the `if`; `{isLive ? 'Live now' : 'Recorded'}` shows "Recorded"; verified in Vite 8.3.4 and Chrome
- **Importance**: the card's Under the Hood and Naive code; interviewers ask what may go inside the braces
- **Review Point**: Do not
- **Required Lesson Proof**: `ArticleCard` with `{if ...}`: the overlay; with the ternary: "Recorded"; with the `if` above the `return` and `{status}`: "Recorded"; `{Math.ceil(wordCount / 200)} min read`: "3 min read".

### Principle 4: JSX comments: curly braces hold a comment the page never shows
- **Handle**: `jsx-comment`
- **Thread Step**: what it holds: a comment, which gives no value
- **Rule**: We write a note between tags as a JavaScript comment inside curly braces, `{/* */}`; an HTML comment stops the build, and two slashes alone print on the page.
- **Kind**: Decision
- **Reader Question**: "The HTML I pasted in Lecture 3 has comments. How do I keep a note in my markup?"
- **Reader Expects**: `<!-- -->`, as in HTML, or `//`, as in the JavaScript above the `return`
- **React Does**: between tags, JSX reads text; an HTML comment is not JSX, so the build stops; `// note` is plain text there, so it shows on the page; inside braces the code is JavaScript again, so a JavaScript comment is allowed, and braces that hold only a comment give no value and add nothing to the DOM
- **Placement**: `{/* the headline from the old site */}` between tags; `//` above the `return`, in plain JavaScript
- **Real Mistake**: the pasted `<!-- the headline from the old site -->` inside `ArticleCard`; the page stays empty, and Vite's overlay shows "[PARSE_ERROR] HTML comments are not allowed in modules"; also `// the headline from the old site` between tags, which shows "// the headline from the old site" above the headline; verified in Vite 8.3.4 and Chrome
- **Importance**: Lecture 3's pasted page carries comments (message `03-04-01`); the `//` form is silent, so it ships
- **Review Point**: Do not
- **Required Lesson Proof**: `ArticleCard` with the HTML comment: the overlay; with `//`: the text on the page; with `{/* */}`: nothing added in the Elements panel.

### Principle 5: Rendered values: curly braces show strings and numbers, and nothing for true, false, null, and undefined
- **Handle**: `rendered-values`
- **Thread Step**: what comes out: a value the page shows, or nothing
- **Rule**: We expect strings and numbers to show as text, and `true`, `false`, `null`, and `undefined` to show nothing, so a value the reader must see, such as yes or no, becomes text before it reaches the braces.
- **Kind**: Model
- **Reader Question**: "My label says `Live: {isLive}`. Why does the page show only Live:?"
- **Reader Expects**: `false` prints as the word false, as `console.log(false)` does
- **React Does**: React turns strings and numbers into text, `0` and `NaN` too; it skips `true`, `false`, `null`, and `undefined` and adds no text for them, with no error; a misspelled property is `undefined`, so its place is empty; a function placed without its call shows nothing and logs "Functions are not valid as a React child"
- **Placement**: a string or a number inside the braces; `{isLive ? 'Yes' : 'No'}` for a boolean the reader must see
- **Real Mistake**: `<p>Live: {isLive}</p>` with `const isLive = false`; the page shows "Live: " and the console stays empty; `{isLive ? 'Yes' : 'No'}` shows "Live: No"; verified in React 19.3.1 and Chrome
- **Fix In**: this principle
- **Importance**: the card's render matrix; a blank label ships with no error; Q10 builds `&&` on "false shows nothing, 0 shows 0"
- **Prediction**: a list of `{'text'}`, `{42}`, `{0}`, `{true}`, `{false}`, `{null}`, and `{undefined}` shows text, 42, 0, and four empty items; `{writer.nmae}` shows nothing and logs nothing
- **Required Lesson Proof**: `ArticleCard` with the value list: the Elements panel; `Live: {isLive}` and its ternary fix.

### Principle 6: Double curlies: curly braces pass an object only to an attribute that expects one
- **Handle**: `double-curlies`
- **Thread Step**: what comes out: an object, which the page cannot show
- **Rule**: We show a field of an object or a formatted string, never the object itself, and we pass an object only to an attribute that expects one, such as `style`, where the outer braces open the window and the inner braces write the object.
- **Kind**: Decision
- **Reader Question**: "Why does my date crash the page, and why do some attributes have two pairs of braces?"
- **Reader Expects**: a date prints as a date, as it does in `console.log`; `{{ }}` is special syntax, a habit from Handlebars and Vue, which print values with double braces
- **React Does**: an object, a `Date` too, has no single text, so React stops the render with "Objects are not valid as a React child", and with no error boundary the whole page goes empty; a field such as `writer.name` or a method such as `toLocaleDateString('en-US')` gives text; `style` expects an object, so `style={{ color: 'gray' }}` is an object literal inside the braces, and React sets `style="color: gray;"`; `<h2>{{headline}}</h2>` is an object in the text, so it crashes too
- **Placement**: `{writer.name}`, `{publishedAt.toLocaleDateString('en-US')}` in the text; `style={{ color: 'gray' }}` on an attribute that takes an object
- **Real Mistake**: `<p>Published {publishedAt}</p>` with `const publishedAt = new Date(2026, 9, 15)`; the page goes empty, and the console shows "Objects are not valid as a React child (found: [object Date])"; `{publishedAt.toLocaleDateString('en-US')}` shows "Published 10/15/2026"; also `<h2>{{headline}}</h2>`, which shows "(found: object with keys {headline})"; verified in React 19.3.1 and Chrome
- **Importance**: a react.dev Recap bullet and Challenge; interviewers ask what `{{` means; a date in the text blanks the whole page
- **Review Point**: Do not
- **Required Lesson Proof**: `ArticleCard` with `{publishedAt}`: the empty page and the console error; with `toLocaleDateString`: the date; `style={{ color: 'gray' }}`: the style in the Elements panel.

## Senior Answer
Curly braces open a window from JSX to JavaScript. They work in two places: between tags, and right after an attribute's equals sign. The code inside runs each time React calls the component, and its value takes the place of the braces. Everything outside them stays text, so `src="{avatarUrl}"` passes the text, not the variable. The braces hold one expression, code that gives back a value: a variable, a sum, a function call, or a ternary. A statement such as `if` gives back nothing, so the build stops; I put it above the `return` and read its result. A note goes in as `{/* */}`. Strings and numbers show as text, while `true`, `false`, `null`, and `undefined` show nothing. An object, a date too, cannot be shown and crashes the render, so I show a field or a formatted string. Double braces are just an object inside the window, which is what `style` expects.
