## Authorized Scope
Lesson 03 teaches what JSX is and the rules it adds to HTML. JSX looks like HTML, but it is JavaScript. The build turns each tag into a call of a function from React, `jsx`, and the call returns a plain object, a React element. Four rules follow from that. Every tag is closed, `<img />` and `<br />` too, because the call must know where the tag's content ends. A component returns one root, because a function returns one value. A Fragment, written `<>` and `</>`, gives that one root without adding an element to the page. Attributes become the names of an object's properties, so `class` becomes `className` and `for` becomes `htmlFor`. The lesson works on HTML pasted from the old Town News site into `App.jsx`: a story card, a sign-up box, and a list of top stories. It builds on Q01, where a component describes the page, and on Q02, where React calls the component a tag names. Values from variables in curly braces stay out of this lesson.

## Theme and Options
- **Theme**: Most React work starts from markup that already exists, such as a page from an old site or a design in HTML. What changes when that HTML moves into a component?
- **Options**: none (starting point: the markup lives in an HTML file, which the browser reads as it is)
- **This lesson teaches**: JSX

## Principle Thread
- **Anchor**: JSX looks like HTML, but it is JavaScript: each tag becomes a call that builds an object
- **Axis**: the path of pasted HTML into JavaScript: the tag, its end, the return, the group, its attributes
- **Why This Axis**: The five principles follow one block of pasted HTML on its way to the page. First the build turns each tag into a call, which is the model. Then the build checks where each tag ends, then whether the component returns one value, and these three happen before anything runs, so the reader meets them as build errors in this order. The group comes next, because the Fragment only makes sense once the reader knows why one root is needed. The attributes come last, because they reach the page only when React runs: the build accepts `class`, and only the Console panel complains. One axis was rejected. "The parts of a tag from left to right: name, attributes, content, end" puts the attributes second, but the attribute rule is the only one that does not stop the build, and a reader who fixes it first still sees a broken page.
- **Spoken Preview**: Everything in this lesson comes down to one idea: JSX looks like HTML, but it is JavaScript. First, the JSX transform, which means each tag becomes a JavaScript call that returns an object: the build rewrites every tag as a call, and React builds the page from the objects. Second, closed tags, which means JavaScript must know where each tag ends: every tag needs a closing tag or a slash, the image and the line break too. Third, a single root, which means a JavaScript function returns one value: a component gives back one element that holds the rest. Fourth, Fragments, which means one JavaScript value that adds no element to the page: when the page needs no extra box, an empty tag groups the elements instead. Fifth, camelCase attributes, which means each attribute becomes a JavaScript property name: class becomes className, and for becomes htmlFor.
- **Closing Line**: One call per tag, every tag closed, one root, no extra box, and JavaScript names.

## Principles

### Principle 1: The JSX transform: each tag becomes a JavaScript call that returns an object
- **Handle**: `jsx-is-javascript`
- **Thread Step**: the tag: it becomes a call
- **Rule**: We read JSX as JavaScript: the build turns each tag into a call, the call returns an object that describes the element, and React builds the DOM from those objects.
- **Kind**: Model
- **Reader Question**: "My component returns something that looks like HTML. Is it HTML?"
- **Reader Expects**: yes, a kind of HTML that the browser reads, as it reads `index.html`
- **React Does**: the dev server rewrites each tag before the browser sees it; `<h2 className="headline">City Library Extends Its Hours</h2>` arrives as `_jsxDEV("h2", { className: "headline", children: "City Library Extends Its Hours" }, ...)`, and `vite build` writes `jsx("h2", ...)`; the call returns a plain object, a React element, with `type: 'h2'` and `props`; `<ArticleCard />` becomes a call that takes the function, and `<articleCard />` one that takes the text `"articleCard"`; React reads the objects when it renders and builds the DOM; the browser never receives a tag
- **Placement**: JSX wherever a JavaScript value can go: after `return`, or in a variable
- **Real Mistake**: none; the HTML picture breaks no code by itself, and the four rules below show where it misleads
- **Importance**: interviewers open with "what is JSX"; every rule of this lesson follows from it
- **Prediction**: `ArticleCard` stores its `<article>`, with `<h2 className="headline">City Library Extends Its Hours</h2>` and a `<p>`, in `const card`, logs it, and returns it; `console.log(card)` prints an object with `type: 'article'` and `props.children` holding two more objects, the first with `type: 'h2'` and `props: { className: 'headline', children: 'City Library Extends Its Hours' }`, not a string of HTML; the Sources panel shows `App.jsx` with `_jsxDEV` calls and no tags.
- **Required Lesson Proof**: `ArticleCard` with its markup in a variable and a `console.log`: the logged object; the same file in the Sources panel: the calls, and the import the dev server added.

### Principle 2: Closed tags: JavaScript must know where each tag ends
- **Handle**: `close-every-tag`
- **Thread Step**: its end: the call must know where the content stops
- **Rule**: We close every tag, with a closing tag or with a slash, `<img />` and `<br />` too, because JavaScript must know where each tag ends.
- **Kind**: Decision
- **Reader Question**: "My HTML has `<img>` with no closing tag. Why does the build stop?"
- **Reader Expects**: an image never has content, so it needs no closing tag, as in HTML
- **React Does**: the build reads everything after an open tag as its content until it finds the closing tag; an open `<img>` swallows the `<h2>` below it, the build meets `</article>` while it still waits for `</img>`, and it stops; nothing runs, and the overlay names the `<img>` and the `</article>`
- **Placement**: `<img src="/library.jpg" alt="The city library" />`, `<br />`, `<li>Rail strike ends</li>`; any tag may close itself
- **Real Mistake**: HTML pasted into `ArticleCard` with `<img src="/library.jpg" alt="The city library">`; the page stays empty, and Vite's overlay shows "Expected corresponding JSX closing tag for 'img'." with "Opened here" under the `<img>` and "Expected `</img>`" under `</article>`, then "Unexpected token. Did you mean `{'}'}` or `&rbrace;`?" at the last line of the file; verified in Vite 8.3.4 and Chrome
- **Importance**: the bank's hook and the card's Friction; pasted HTML fails at once, and the second message points at a line with no mistake
- **Review Point**: Do not
- **Required Lesson Proof**: `ArticleCard` with the open `<img>`: the overlay; with `<img ... />`: the image and the headline appear.

### Principle 3: Single root: a JavaScript function returns one value
- **Handle**: `one-root`
- **Thread Step**: the return: one value
- **Rule**: We return one root from every component, one element that holds the rest, because a JavaScript function returns one value.
- **Kind**: Decision
- **Reader Question**: "I pasted a heading and a paragraph after `return`. Why does the build fail?"
- **Reader Expects**: HTML allows any number of tags side by side, so JSX should too
- **React Does**: each tag becomes one call, so one value; `return` gives back one value; two calls side by side are not one value, so the build stops before anything runs; one element around both is one call whose content holds the other two
- **Placement**: one element around everything the component returns, such as the `<article>` or the `<section>` the page needs, or a Fragment (Principle 4)
- **Real Mistake**: `ArticleCard` returns `<h2>City Library Extends Its Hours</h2>` and `<p>The library now stays open until nine.</p>` side by side; the page stays empty, and the overlay shows "Adjacent JSX elements must be wrapped in an enclosing tag." with "Help: Did you want a JSX fragment `<>...</>`?"; verified in Vite 8.3.4 and Chrome
- **Importance**: the bank's hook; the first build error every newcomer meets; interviewers ask why the rule exists
- **Review Point**: Do not
- **Required Lesson Proof**: `ArticleCard` with the two tags side by side: the overlay; the same tags inside `<article>`: the card appears.

### Principle 4: Fragments: one JavaScript value that adds no element to the page
- **Handle**: `fragment-or-element`
- **Thread Step**: the group: one root that the page never sees
- **Rule**: When the elements need one root but the page needs no extra box, we group them with a Fragment, `<>` and `</>`, and we keep an element only when the page needs the box.
- **Kind**: Decision
- **Reader Question**: "So I wrap everything in a `<div>`?"
- **Reader Expects**: yes; a `<div>` is the usual way to group tags in HTML
- **React Does**: a `<div>` becomes a real element in the DOM, between the parent and the children; `<>` and `</>` are a Fragment, one call with the `Fragment` type; React puts its children straight into the parent and adds no element
- **Placement**: a Fragment when the group exists only to give one root; an element when the page needs the box, for its meaning (`<article>`, `<section>`) or for a style
- **Real Mistake**: `TopStories` returns two `<li>` wrapped in a `<div>`, and `App` places it in `<ul class="stories">`, styled as a flex row with a border on each `.stories > li`; the DOM is `<ul><div><li><li>`, the selector matches no item, and the items stack with no border; with `<>` and `</>`, the DOM is `<ul><li><li>`, the items sit side by side, and both have their border; verified in React 19.3.1 and Chrome
- **Importance**: the last part of the interview question; wrapper divs break list, flex, and grid layouts, and reviewers remove them
- **Review Point**: Condition
- **Required Lesson Proof**: `TopStories` with the `<div>`: the Elements panel shows the `<div>` inside the `<ul>`, and the two stories stack with no border; with the Fragment: no `<div>`, and the two stories sit in a row with their borders.

### Principle 5: camelCase attributes: each attribute becomes a JavaScript property name
- **Handle**: `camelcase-attributes`
- **Thread Step**: its attributes: the names React sets on the element
- **Rule**: We write each attribute as a JavaScript property name: `className` for `class`, `htmlFor` for `for`, camelCase for names of several words, and dashes only in `aria-*` and `data-*`.
- **Kind**: Decision
- **Reader Question**: "Can I keep `class` and `for` from my HTML?"
- **Reader Expects**: yes; attributes are copied to the page as written, as in HTML
- **React Does**: the attributes of a tag become the properties of the object the call receives; `class` and `for` are reserved words in JavaScript, so React uses `className` and `htmlFor`, the names of the DOM properties; other names of several words use camelCase (`tabIndex`); `aria-*` and `data-*` keep their dashes; the build accepts `class`, React 19 still sets it on the element, and the Console panel shows an error for each wrong name
- **Placement**: `className="signup"`, `htmlFor="email"`, `tabIndex="0"`; `aria-label` and `data-story-id` as in HTML
- **Real Mistake**: HTML pasted with `<label class="label" for="email">` and `<input id="email" tabindex="0">`; the page looks right and the label still focuses the box, and the Console panel shows "Invalid DOM property `class`. Did you mean `className`?" and the same for `for` and `tabindex`; verified in React 19.3.1 and Chrome
- **Importance**: the bank's hook; reviewers flag `class` on sight; a console full of these errors hides the ones that matter
- **Review Point**: Do
- **Required Lesson Proof**: `SignUp` with `class`, `for`, and `tabindex`: the three console errors, and a page that looks right; with `className`, `htmlFor`, and `tabIndex`: a clean console; `aria-label` and `data-form-id` print no error.

## Senior Answer
JSX is a syntax extension for JavaScript. It looks like HTML, but the build turns every tag into a function call, and the call returns a plain object that describes the element. React reads those objects and builds the DOM, so the browser never sees a tag. Because it is JavaScript, JSX is stricter than HTML. Every tag must be closed, `<img />` and `<br />` too, or the build cannot tell where the tag ends. A function returns one value, so a component returns one root. When the page needs no extra element, I use a Fragment, `<>` and `</>`: it gives one root and leaves nothing in the DOM, so a list or a flex row keeps working. A wrapper `<div>` inside a `<ul>` breaks both. Attributes become object keys, so I write `className` instead of `class` and `htmlFor` instead of `for`, while `aria-` and `data-` attributes keep their dashes.
