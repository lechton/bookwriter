### Some code gives back a value, and some code only does a job

- [runway] Expression and statement, and `Math.ceil`, used by Question 3 and Step 2.

- [p] ◇ {expression and statement} JavaScript code comes in two kinds. An **expression** is code that gives back a value: `540`, `wordCount`, `wordCount / 200`, and `Math.ceil(wordCount / 200)` are all expressions. A **statement** is code that does a job and gives back nothing we can keep: `const` makes a variable, `if` decides whether to run some lines, and `for` repeats them. A simple test tells them apart: an expression can stand on the right of `=`, and a statement cannot. ◼ Educational objective: the distinction Question 3 rests on, with the shortest code that shows it.

- [code] Plain JavaScript, expressions and a statement:

```js title="Plain JavaScript: expressions and a statement"
const wordCount = 540;
const readTime = Math.ceil(wordCount / 200); // 3
if (readTime > 2) { // a statement: it gives back no value
  console.log('A long read');
}
```

◼ **The what-this-introduces list:** 1. `wordCount / 200`: an expression, 2.7 here. 2. `Math.ceil(...)`: rounds a number up to the next whole number, 3 here. 3. `if (...) { ... }`: a statement.

- [p] ◇ {point into the code} `wordCount / 200` gives back 2.7, and `Math.ceil` rounds it up, so `readTime` holds 3. The `if` checks whether `readTime` is more than 2 and runs the line inside, so the Console panel shows "A long read". We could write `const result = Math.ceil(wordCount / 200)`, but never `const result = if (readTime > 2) ...`. ◼ Educational objective: the equals-sign test, applied once to each kind.

### The ternary operator chooses one of two values

- [runway] Ternary operator, used by Questions 3 and 5 and Step 2.

- [p] ◇ {the ternary} Sometimes the value depends on a yes-or-no question. The **ternary operator** asks it in one expression: a condition, a question mark, the value for yes, a colon, and the value for no. Because it gives back a value, it can stand on the right of `=`, where an `if` cannot. ◼ Educational objective: the expression that replaces an `if` in Questions 3 and 5 (Terms row New, refresher yes; message `04-10-01` tells Lecture 10 to recall it).

- [code] Plain JavaScript, a ternary:

```js title="Plain JavaScript: a ternary chooses a value"
const isLive = false;
const label = isLive ? 'Live now' : 'Recorded'; // 'Recorded'
```

◼ **The what-this-introduces list:** 1. `condition ? yes : no`: the ternary operator.

### Two ways to build a text from pieces

- [runway] String concatenation with `+` and the template literal, used by Question 2 and Step 1.

- [p] ◇ {building a text} An address such as `/images/library-hours.jpg` is often built from a fixed start, a value, and a fixed end. **String concatenation** joins texts with `+`. A **template literal** does the same in one text: it is written between backticks, and `${...}` inside it puts in the value of an expression. ◼ Educational objective: the two ways the fix of Question 2 can build the image address.

- [code] Plain JavaScript, two ways to build the same text:

```js title="Plain JavaScript: concatenation and a template literal"
const imageId = 'library-hours';
const first = '/images/' + imageId + '.jpg';
const second = `/images/${imageId}.jpg`; // the same text
```

◼ **The what-this-introduces list:** 1. `+` between texts: concatenation. 2. backticks and `${imageId}`: a template literal.

### JavaScript has values for yes, no, and nothing

- [runway] `true`, `false`, and `null`, used by Question 5 and Step 3.

- [p] ◇ {booleans and null} A yes-or-no value is a **boolean**: `true` or `false`. A variable such as `isLive` holds one. JavaScript also has two values that mean "nothing here": `undefined`, which Lecture 2 met as the result of a function that gives back nothing, and `null`, which we write on purpose when a value is missing. ◼ Educational objective: the four values Question 5 shows to be invisible, named before the question.

### A date is an object

- [runway] `Date` and `toLocaleDateString()`, used by Question 6 and Step 3.

- [p] ◇ {the Date object} JavaScript keeps a date in a **`Date`** object. `new Date(2026, 9, 15)` makes October 15, 2026; the months count from 0, so 9 is October. A date is an object, not a text, so to show it we ask it for a text: `toLocaleDateString('en-US')` gives back `'10/15/2026'`. ◼ Educational objective: the object that looks like text, which Question 6 places in the markup.

### Some HTML attributes take a yes or a no, and one takes CSS

- [runway] Boolean attribute (`disabled`) and the `style` attribute, used by Questions 2 and 6 and Step 3.

- [p] ◇ {boolean attributes} Some HTML attributes are on or off. A **boolean attribute** such as `disabled` works by being there: `<button disabled>` is disabled, and so is `<button disabled="false">`, because the browser looks only at whether the attribute exists, not at its text. ◼ Educational objective: the HTML fact behind the second mistake in Question 2.

- [p] ◇ {the style attribute} The **`style` attribute** sets CSS on one element: in HTML it holds CSS text, such as `style="color: gray"`. A class in a stylesheet is the usual way to style; `style` is for a value that only this element has. ◼ Educational objective: the attribute Question 6 shows taking an object in JSX; the rules of style objects stay with Lecture 83.

### Principles of React: Curly Braces Open a Window to JavaScript

- [preview] Everything in this lesson comes down to one idea: curly braces open a window to JavaScript, and the value of the code inside takes their place. The first two principles say where the window opens. First, embedding expressions, which means curly braces put a JavaScript value where the text goes: the name of a variable in braces shows its value, and everything outside the braces stays text. Second, dynamic attributes, which means curly braces put a JavaScript value where the attribute value goes: the whole value goes in one pair of braces, with no quotes, and quotes stay for fixed text. The next two say what the window holds. Third, expressions, not statements, which means curly braces hold code that produces a value: a variable, a sum, a call, or a choice with a question mark, but never a statement such as if. Fourth, JSX comments, which means curly braces hold a comment the page never shows: a note in the markup goes inside braces, between a slash and a star. The last two say what comes out. Fifth, rendered values, which means curly braces show strings and numbers, and nothing for true, false, null, and undefined: a value the reader must see becomes text first. Sixth, double curlies, which means curly braces pass an object only to an attribute that expects one: an object is never shown as text, and the style attribute takes one inside a second pair of braces. ◼ Educational objective: the map's Spoken Preview, word for word, read aloud before Question 1.

### Question 2: A variable in quotes is only text

- [question-cycle] Question 2: A variable in quotes is only text
    - Question: "My image address is in a variable. How do I put it into `src`?"
    - Code and result: `ArticleCard` declares `avatarUrl` ("/samantha-robinson.jpg") and `imageId` ("library-hours"); it returns the author's photo as `<img src="{avatarUrl}" alt="{author}" />` and the story's photo as `<img src="/images/{imageId}.jpg" alt={headline} />`; both images are broken; the Elements panel shows `src="{avatarUrl}"` and `src="/images/{imageId}.jpg"`, and the browser asked for `/%7BavatarUrl%7D` and `/images/%7BimageId%7D.jpg` (verified in React 19.3.1, Vite 8.3.4, and Chrome).
    - Verdict: does not do what the reader wanted.
    - Answer: quotes always pass fixed text, whatever is inside them, braces too; so `src` receives the characters `{avatarUrl}`, and the browser asks for that address (`%7B` and `%7D` are how an address writes the braces) and finds no photo; braces work only right after the `=`, with no quotes, and then they pass the variable's value; an address built from parts goes into one pair of braces as one expression, with `+` or a template literal; `alt="{author}"` shows the same mistake on the text a screen reader reads; the same holds for a yes-or-no attribute: `disabled="false"` passes the text "false", so the button stays disabled, and the Console panel shows "Received the string `false` for the boolean attribute `disabled`. The browser will interpret it as a truthy value. Did you mean disabled={false}?"; with `disabled={isLive}` and `false`, React leaves the attribute out; quotes stay right for fixed text, such as `className="byline"`.
    - Fix: `src={avatarUrl}`, `alt={author}`, and `` src={`/images/${imageId}.jpg`} ``; both photos load.
    - Rule: we give an attribute a value from JavaScript by writing the whole value in one pair of curly braces, right after the equals sign and with no quotes, and we keep quotes for fixed text.
    - Needs: concatenation and template literal (runway "Two ways to build a text"); boolean attribute (runway "Some HTML attributes take a yes or a no"); attributes as JavaScript names (recall Lecture 3).
    - Diagram: none; the Elements panel lines before and after carry the picture.

### Question 3: An if inside the braces stops the build

- [question-cycle] Question 3: An if inside the braces stops the build
    - Question: "The label should say Live now only when the story is live. Can I write an `if` inside the braces?"
    - Code and result: `ArticleCard` declares `isLive` as `false` and returns `<p>{if (isLive) { 'Live now' }}</p>` under the headline; the page stays empty, and Vite's overlay shows "[PARSE_ERROR] Unexpected token", pointing at the `if` (verified in Vite 8.3.4 and Chrome).
    - Verdict: does not do what the reader wanted.
    - Answer: the braces become the value of one property in the call of Question 1, `children: ...`; a value can only be an expression, code that gives back a value; `if` is a statement, it gives back nothing, so the build cannot place it and stops before anything runs; `const` and `for` stop it the same way; the ternary is an expression, so `{isLive ? 'Live now' : 'Recorded'}` shows "Recorded"; when the choice is longer, the `if` moves above the `return`, sets a variable, and the braces read the variable; anything that gives back a value works inside: `{Math.ceil(wordCount / 200)}`, `{wordCount / 200}`, a call such as `{formatReadTime()}`; braces cannot name a tag, so `<{tag}>` stops the build too; Lecture 10 uses the ternary to choose between pieces of markup.

    - Rule: we put only an expression, code that produces a value, inside curly braces: a variable, a sum, a call, or a ternary; a statement such as `if` goes above the `return`, and its result goes into the braces through a variable.
