### Some parts of a page appear only in some cases

- [p] ◇ {theme} Look at any website and count the parts that appear only sometimes. A shop marks some products "Sale". A mail app shows a number only when new mail has arrived. A blog asks visitors to sign in, and greets members by name instead. The design stays the same; the data decides which parts show. So every React developer meets the same question: how does a component show, hide, or switch a part of the page? ◼ Educational objective: the theme from the map's `## Theme and Options`, on pages every reader has seen.

- [p] ◇ {option 1: hiding with CSS} The first answer comes from HTML. Every element can carry the `hidden` attribute, a yes-or-no attribute like the `disabled` of Lecture 4: ◼ Educational objective: say what the first code is for before it appears; the reader's own HTML habit comes first.

- [code] Hiding the label with the `hidden` attribute:

```jsx title="Hiding with CSS"
<span className="new-label" hidden={!isNew}>New</span>
```

◼ **The what-this-introduces list:** 1. `hidden`: an HTML attribute that tells the browser not to draw the element. 2. `!isNew`: "not new", taught in the runway section on truthy and falsy values.

- [p] ◇ {option 1: point into the code, where it fits} When `isNew` is `false`, `!isNew` is `true`, so the `<span>` gets `hidden`. The element is still written into the page: the Elements panel shows `<span class="new-label" hidden="">New</span>`, and the browser simply does not draw it. A class with `display: none` works the same way. This is **hiding with CSS**: the element exists, and only its drawing is switched off. It fits a part that must keep its place in the page while it is hidden. ◼ Educational objective: a fair account of the first option (map Supporting row on the `hidden` attribute), with what the Elements panel really shows.

- [p] ◇ {option 2: conditional rendering} The second answer is React's: leave the element out of the JSX. ◼ Educational objective: the chapter's option, introduced by its purpose before its code.

- [code] Leaving the label out of the JSX:

```jsx title="Conditional rendering"
{isNew && <span className="new-label">New</span>}
```

◼ **The what-this-introduces list:** 1. `&&`: the logical AND of JavaScript, taught in the runway section "&& gives back one of its two sides".

- [p] ◇ {option 2: point into the code, who decides what, where it fits} Read it as "if `isNew`, the label; otherwise nothing". When `isNew` is `false`, this JSX gives React nothing to build, so the Elements panel shows no `<span>` at all. This is **conditional rendering**: the component decides, each time it runs, which JSX it returns, and React builds only that. React has no special syntax for it; the choice is plain JavaScript. It fits every part that depends on data, and every part whose data may be missing, because JSX that is left out never runs. ◼ Educational objective: the term with its code, who acts (our code chooses, React builds), and the contrast with the first option.

- [ways] Two ways to show a part of the page only in some cases ◼ (1) Show a part only in some cases by **hiding with CSS** (HTML and Lecture 4): the element is always in the DOM, and an attribute such as `hidden` tells the browser not to draw it. ### JavaScript sorts every value into truthy or falsy

- [runway] Truthy and falsy, the logical NOT `!`, and the comparison operators `>` and `===`, used by Questions 1, 2, and 4.

- [p] ◇ {truthy and falsy, named with code} An `if` needs a yes or a no. When we give it any other value, JavaScript turns that value into one. A few values count as no: `false`, `0`, an empty text `''`, `null`, `undefined`, and `NaN`. They are called **falsy**. Every other value counts as yes and is called **truthy**: `true`, every number but `0`, every text with something in it, every object, and every array, even an empty one. ◼ Educational objective: the term with its full list, which Question 2's trap and its variations rest on.

- [code] Values an `if` reads as yes or no:

```js title="Truthy and falsy"
if (0) { } // falsy: the block is skipped
if ('false') { } // truthy: a text with letters in it
if ([]) { } // truthy: an empty array is still an object
```

◼ **The what-this-introduces list:** 1. Three surprises of the list above, each with its answer.

- [p] ◇ {the logical NOT and the comparisons} The **logical NOT**, `!`, turns a value into its opposite yes or no: `!null` is `true`, so `if (!article)` reads "if there is no article". The **comparison operators** give a real `true` or `false`: `count > 0` asks "is the count above zero?", and `count === 1` asks "is the count exactly one?". Three equals signs compare the value and its kind, so `'1' === 1` is `false`. ◼ Educational objective: the refreshers the map marks `yes`, each with the line a question uses it in.

### && gives back one of its two sides

- [runway] The logical AND `&&`, in plain JavaScript first, used by Question 2 and Step 2.

- [p] ◇ {&& in plain JavaScript} The **logical AND**, `&&`, reads two sides. When the left side is falsy, it stops there and gives back the left side itself. When the left side is truthy, it gives back the right side. It is the mirror of `||` from Lecture 6, which gives back its left side when that side is truthy. ◼ Educational objective: plain JavaScript first (`principle-definition` Pass 3): what `&&` gives back, before React meets it.

- [code] What `&&` gives back:

```js title="The logical AND"
true && 'New'; // 'New': the left side is truthy
false && 'New'; // false: the left side itself
0 && 'New'; // 0: the left side itself, a number
```

◼ **The what-this-introduces list:** 1. Three lines, three results, and the third is the one Question 2 meets.

- [p] ◇ {the rule} `&&` does not answer yes or no. It gives back one of its two sides, and which one depends on the left. ◼ Educational objective: the closing rule of the runway, the fact Question 2's answer recalls in a few words.

### An if can end a function early

- [runway] The early return and the chain of `if`, `else if`, and `else`, used by Questions 1, 3, and 4.

- [p] ◇ {the early return} Lecture 4 placed statements such as `if` above the `return`. A `return` inside that `if` ends the function at once, and no line after it runs. Ending a function this way is called an **early return**. ◼ Educational objective: the term with its plain meaning; why a guard at the top keeps the later lines from running.

- [code] An early return in plain JavaScript:

```js title="An early return"
function firstLetter(name) {
  if (!name) {
    return ''; // ends here, the next line never runs
  }
  return name[0];
}
```

◼ **The what-this-introduces list:** 1. `return ''` inside the `if`: the early return. 2. `name[0]`: the first letter, which would throw for `null`.

- [p] ◇ {if, else if, else} When there are more than two cases, `if` can be followed by `else if` and a last `else`. JavaScript tries each test from the top and runs the first block whose test is true, and only that one; `else` runs when no test was true. ◼ Educational objective: the chain Question 4's fix uses.

- [code] A chain of three cases:

```js title="if, else if, and else"
let size;
if (count === 0) {
  size = 'none';
} else if (count === 1) {
  size = 'one';
} else {
  size = 'many'; // every other count
}
```

◼ **The what-this-introduces list:** 1. `let size`: a variable the chain fills (recall Lecture 1). 2. `else if` and `else`: the second and the last case.

### Principles of React: Conditional Rendering

- [preview] Everything in this lesson comes down to one idea: conditional rendering, which means that each time it runs, a component chooses which JSX to return. First, returning null, which means choosing to show nothing: when there is nothing to show, the component returns null at its very top, before any line reads the missing data. Second, logical AND, which means choosing one piece or nothing: we put a true or false value on its left side, never a bare number, because a zero shows up on the page. Third, the ternary operator, which means choosing between two pieces: we write the choice inside the JSX, so the parts both cases share are written only once. Fourth, an if statement and a variable, which means choosing among many pieces: we make the choice above the return and place the result in the JSX, instead of putting one ternary inside another. ◼ Educational objective: the map's Spoken Preview, word for word, one paragraph for the anchor and one per principle in the lecture, read aloud before Question 1.

> [!PRINCIPLE]
> **Principle 1: Returning null: choosing to show nothing**
> *When a component has nothing to show for its props, it returns `null` from an `if` at its very top, before any line reads the missing data; when the parent decides whether the component appears at all, the parent leaves out its tag instead.*
>
> React runs a component and builds the JSX it returns, and every line of that JSX runs. So when the data is missing, `{user.name}` reads a property of `null` and throws, and the whole page goes blank. Hiding the result with CSS comes too late, because the line has already run. An `if` at the very top that returns `null` ends the function before any line reads the data. `null` shows nothing, so React builds no element there, and the rest of the page stays. The component still runs; it only chooses to show nothing. When the parent knows the data is missing, it can leave out the tag, and then the component does not run at all.
>
> *We should do this:*
> `function Profile({ user }) {`
> `  if (!user) {`
> `    return null; // nothing shows, the page stays`
> `  }`
> `  return <h2>{user.name}</h2>;`
> `}`
>
> *We should not do this:*
> `function Profile({ user }) {`
> `  return <h2>{user.name}</h2>; // null: the page goes blank`
> `}`

### Question 2: An article with no comments shows a bare 0

- [question-cycle] Question 2: An article with no comments shows a bare 0
    - Question: "The 'New' label should show only on new articles, and the comment count only when there are comments. Do I need an `if` for that?"
    - Code and result: the card from Question 1 adds `{article.isNew && <span className="new-label">New</span>}` above the title (line 7) and `{article.commentCount && <p>{article.commentCount} comments</p>}` below the summary (line 11); the park article shows "New" and "3 comments"; the rain article shows no label, as wanted, and a bare `0` under its summary (verified in React 19.3.1 and Chrome).
    - Verdict: does not do what the reader wanted.
    - Answer: the reader reads `&&` as "if", and for the label that reading works; but `&&` gives back one of its two sides (runway); for the park, `article.isNew` is `true`, so `&&` gives the `<span>`; for the rain, it is `false`, so `&&` gives `false`, and `false` shows nothing (Lecture 4); for the comments, the rain's `commentCount` is `0`, which is falsy, so `&&` gives back the `0` itself; `0` is a number, and numbers show on the page, so React writes the text `0` into the card; react.dev puts it plainly: do not put numbers on the left side of `&&`; the fix asks a real yes-or-no question, `article.commentCount > 0`, which gives `false` for the rain; `!!article.commentCount` and `Boolean(article.commentCount)` turn the number into a boolean too, and are common in real code; the same trap hides in other values: a quoted prop `isNew="false"` is a text with letters in it, so it is truthy and the label shows (verified); an empty array is truthy too, so `tags && <ul className="tags">` leaves an empty `<ul>` (verified), and Lecture 11 tests the array's length instead; an empty text and `undefined` show nothing.
    - Fix: `{article.commentCount > 0 && <p>{article.commentCount} comments</p>}`; the rain article shows no `0`, and the park still shows "3 comments" (verified).
    - Rule: to show a piece or nothing, we write `condition && <Piece />` with a true or false value on the left, such as `commentCount > 0`, never a bare number.
    - Needs: `&&` (runway "&& gives back one of its two sides"); truthy, falsy, and `>` (runway "JavaScript sorts every value into truthy or falsy"); numbers show and `false` does not (recall Lecture 4); a quoted value is a text (recall Lecture 6); array (recall Lecture 7).
    - Window plan: `ArticleCard.jsx`, lines 6 to 12, the card's `<article>` with the two new lines (`startLine="6"`); the fix, line 11 alone (`startLine="11"`).
    - Diagram: what `&&` gives back for each article, and what the page shows for it.

> [!PRINCIPLE]
> **Principle 2: Logical AND: choosing one piece or nothing**
> *To show a piece or nothing, we write `condition && <Piece />` with a true or false value on the left, such as `commentCount > 0`, never a bare number.*
>
> We read `a && b` as "if a, then b", and we expect nothing to show when `a` is "nothing". But `&&` does not answer yes or no. When the left side is falsy, it gives back the left side itself. `false` shows nothing, so a boolean on the left works. `0` is falsy too, but it is a number, and React shows numbers, so a bare `0` appears on the page. A comparison such as `count > 0` gives a real `true` or `false`, and then nothing shows when the count is zero.
>
> *We should do this:*
> `const count = 0;`
> `{count > 0 && <p>{count} messages</p>} // shows nothing`
>
> *We should not do this:*
> `const count = 0;`
> `{count && <p>{count} messages</p>} // shows a bare 0`

### For the interview

- [interview] > **The Interview Question:** How do you show, hide, or switch JSX based on a condition?

- [interview] **1. The Hidden Signal** ◼ The interviewer wants to hear that React has no special syntax for conditions and that the choice is plain JavaScript, and then which form fits which case. A junior answer lists `if`, `&&`, and the ternary. A strong answer sorts them by how many pieces the choice has, names the `0` trap without being asked, and says that JSX that is left out makes no element, while CSS hiding keeps it.

- [interview] **2. The Classic Trap** ◼ The classic trap is "`&&` is a short `if`". On the article site, `{article.commentCount && <p>...</p>}` put a bare `0` under the rain article, because `&&` gives back its left side when that side is falsy, and React shows numbers. The fix is a real yes-or-no question on the left: `article.commentCount > 0`. A second trap is "I hide it with `display: none`": the featured card still ran its JSX, read `article.title` from `null`, and blanked the whole page.

- [interview] **3. What is Actually Going On** ◼ React runs a component and builds whatever JSX it returns. With `featured` set to `null`, the card's first lines return `null`, so React builds nothing for it, and the rest of the page stays. Inside the JSX, `article.isNew && <span>` gives the label or `false`, and `false` shows nothing. `isSignedIn ? <p>{summary}</p> : <p>Sign in...</p>` gives exactly one of two paragraphs, while the title and the author are written once. The three comment wordings are chosen above the `return` and placed with `{commentText}`.

- [interview] **4. Where It Gets Tricky** ◼ *What does a component return to show nothing?* `null`; `undefined` from a bare `return;` shows nothing too in React 19, but `null` says it on purpose. *Is returning `null` the same as leaving the tag out?* No: with `null`, the component still runs, so a log at its top prints; when the parent leaves the tag out, the component never runs. *Why does `isNew="false"` show the label?* The quotes make it a text with letters in it, which is truthy; `isNew={false}` is a boolean. *Why does an empty array on the left of `&&` leave an empty list?* An empty array is truthy; test its length, as Lecture 11 does. *What happens to a part that is left out and then comes back?* React builds it again from scratch; Lecture 14 shows it with a click, and Lecture 73 shows how to hide a part and keep what is inside it.

### Glossary

- [glossary] Conditional rendering ◼ Choosing, each time a component runs, which JSX it returns, with plain JavaScript. JSX that is left out makes no element in the DOM.
- [glossary] Early return ◼ A `return` inside an `if` near the top of a function, which ends it before the lines below run. In a component, `if (!article) { return null; }` shows nothing.
- [glossary] Truthy and falsy ◼ How JavaScript reads any value as a yes or a no. `false`, `0`, `''`, `null`, `undefined`, and `NaN` are falsy; every other value, even an empty array, is truthy.
- [glossary] Logical AND (`&&`) ◼ An operator that gives back its left side when that side is falsy, and its right side otherwise. In JSX it shows one piece or nothing, as long as the left side is a boolean.
- [glossary] Ternary operator ◼ `condition ? a : b`, an expression that gives back `a` when the condition is truthy and `b` otherwise. In JSX it shows exactly one of two pieces.
- [glossary] Hiding with CSS ◼ Keeping an element in the DOM and telling the browser not to draw it, with the `hidden` attribute or `display: none`. The element and everything inside it stay.

function ArticleCard({ article, isSignedIn }) {
  if (!article) {
    return null;
  }
  return (
    <article className="card">
      <h2>{article.title}</h2>
      {isSignedIn ? <p>{article.summary}</p> : <p>Sign in to read.</p>}
      {article.commentCount > 0 && <p>{article.commentCount} comments</p>}
    </article>
  );
}
