### One card design, different content each time

- [p] ◇ {theme} Every website shows the same kind of card many times. A shop shows each product in the same frame, and a news site shows each story in the same box. The design stays the same; only the content changes. So every React developer meets the same question: how does one card component show different content each time? ◼ Educational objective: the theme from the map's `## Theme and Options`, from the owner's approved first section of Lecture 7 (`lecture-structure` Section 12).

- [p] ◇ {option 1: props} React gives two answers. The first one you know from Lecture 6: the card takes a prop and places the value in its own markup. ◼ Educational objective: the reader's known option first, introduced by its purpose before its code.

- [code] Option 1, a prop:

```jsx title="Option 1: a prop"
<ContentCard name="John Hall" />
```

◼ **The what-this-introduces list:** 1. `name="John Hall"`: a prop, as in Lecture 6.

- [p] ◇ {option 1: point into the code, who decides} Inside `ContentCard`, the code is `<p>My name is {name}</p>`. The card decides what the content looks like, and the caller only gives the value. This fits when every use has the same shape, such as a price tag that always shows a name and a price. ◼ Educational objective: who decides what, and where the option fits, so it is not a straw man.

- [p] ◇ {option 2: children} The second answer is to write the content between the card's tags. ◼ Educational objective: the chapter's option, introduced by its purpose before its code.

- [code] Option 2, content between the tags:

```jsx title="Option 2: content between the tags"
<ContentCard>
  <p>My name is John Hall</p>
</ContentCard>
```

◼ **The what-this-introduces list:** 1. content between `<ContentCard>` and `</ContentCard>`.

- [p] ◇ {option 2: point into the code, the term, the contrast} Look at what sits between `<ContentCard>` and `</ContentCard>`: the whole line `<p>My name is John Hall</p>`. React takes everything written between the opening tag and the closing tag and hands it to the card as a prop. With a prop from Lecture 6, the information sits in an attribute whose name we choose; here it sits between the tags, and the prop's name is always **`children`**. Inside the card, the code is just `{children}`. Here the caller writes the content, and the card only gives the design around it. ◼ Educational objective: the owner's direction for explaining `children` (`intro-examples.md`, Example 2): the place, what fills it, the name, and the contrast with a prop.

- [p] ◇ {the chapter's choice} In this chapter, we write one React component that keeps the design the same and lets each story decide its own content. In React, this approach is enabled by a prop named `children`. We will see it with one child, with several, and with none, then when to keep a prop beside it, and how the card passes on the attributes it does not use. ◼ Educational objective: the owner's sentence, kept, followed by the chapter's path in the axis order.

### Three dots collect the rest and spread it out

- [runway] Rest syntax and spread syntax (`...`), used by Question 3 and Step 3.

- [p] ◇ {rest and spread} Three dots do two jobs in JavaScript. In destructuring, `...rest` collects every property we did not name into a new object: this is **rest syntax**. In JSX, `{...rest}` on a tag writes every property of an object as an attribute: this is **spread syntax**. ◼ Educational objective: the one form Question 3 needs, shown on a plain object first.

- [code] Plain JavaScript, rest syntax:

```js title="Plain JavaScript: rest syntax"
const story = { title: 'Rail Strike Ends', id: 'top', section: 'News' };
const { title, ...rest } = story;
console.log(rest); // { id: 'top', section: 'News' }
```

◼ **The what-this-introduces list:** 1. `...rest` in destructuring: every property not named.

### Principles of React: A Component Is a Frame the Caller Fills

- [preview] Everything in this lesson comes down to one idea: a component can be a frame that the caller fills. First, the children prop, which means the content between a component's tags arrives as one prop: the frame shows it wherever it writes children in braces, and nowhere if it forgets. Second, composition, which means children when the caller decides the content, props when the frame decides its shape: the body of a story goes between the tags, and its title stays a prop. Third, prop spreading, which means the attributes the frame does not use pass on to its element: the rest goes on with three dots, the attribute written last wins, and a class both sides set is joined. ◼ Educational objective: the map's Spoken Preview, word for word, read aloud before Question 1.

### Question 1: The card shows nothing of what sits between its tags

- [question-cycle] Question 1: The card shows nothing of what sits between its tags
    - Question: "I put a headline between `<CardContainer>` and `</CardContainer>`. Where does it go?"
    - Code and result: `CardContainer` returns `<article className="card"></article>`; `App` writes `<CardContainer>` with `<h2>New Park Opens Today</h2>` between its tags; the page shows an empty card, with no warning; a `Byline` component nested the same way never runs: its `console.log` stays silent (verified in React 19.3.1, Vite 8.3.4, and Chrome).
    - Verdict: does not do what the reader wanted.
    - Answer: in HTML, content inside a `<div>` always shows; but `CardContainer` is our component, and its tag only tells React to call it; the content between its tags goes where Lecture 3 showed: into the props object, under the name `children`, as the Sources panel shows, `_jsxDEV(CardContainer, { children: ... })`; the card shows it only where its markup writes `{children}`; this card never does, so the headline is dropped, and a component in the content is never called; the fix reads `({ children })` and writes `{children}` inside the `<article>`; four frames make the shapes visible: one `<h2>` arrives as the element itself, an `<h2>` and a `<p>` as an array of two, a text as a string, and nothing as `undefined`, and `{children}` shows each; so the frame places `children` and never assumes a shape: `children.map(...)` throws "children.map is not a function" when the caller nests one element.
    - Fix: `function CardContainer({ children })` with `<article className="card">{children}</article>`; the headline shows.
    - Rule: we read what the caller writes between a component's tags as the prop `children`, and we place `{children}` where the content belongs; a frame that never writes it drops the content without a warning.
    - Needs: `children` in the compiled call (recall Lecture 3); props and destructuring (recall Lecture 6); array (runway "An array keeps several values in order").
    - Window plan: `CardContainer` and `App` as a chain, `CardContainer` on lines 1 to 3 (`startLine="1" continues="bottom"`), `App` from line 4 (`startLine="4" continues="top"`); the fix shows `CardContainer` again as lines 1 to 3, its parameter list and its return both changed (`startLine="1"`).
    - Diagram: the four frames against what `children` holds in each, as a small table.

> [!PRINCIPLE] Principle 1: The children prop: the content between a component's tags arrives as one prop. A model with a Real Mistake, so a pair: right, `Panel({ children })` returning `<section className="panel">{children}</section>` around `<p>John Hall, Austin</p>` (the text shows); wrong, a `Panel` that returns `<section className="panel"></section>` (an empty panel); verified.

### Question 2: A prop for every piece leaves an empty byline

- [question-cycle] Question 2: A prop for every piece leaves an empty byline
    - Question: "One story has a photo, another a quote, another only text. Do I add a prop for each?"
    - Code and result: a rigid `NewsCard({ title, author })` draws `<h2>{title}</h2>` and `<p>By {author}</p>`; `App` shows the rail strike story with `author="James Smith"` and a weather story with no author; the second card shows "By " with nothing after it (verified in React 19.3.1 and Chrome).
    - Verdict: does not do what the reader wanted.
    - Answer: each prop names a piece the card draws in a fixed place, so a story without that piece leaves the place empty, and a story with a new kind of piece, a photo or a quote, needs a new prop and a new place in the card; the card's design and the story's content are tied together; the two options of the opening answer it: the content that changes from story to story goes between the tags, and the card keeps only the frame; a piece every story has, the title, stays a prop, because the frame must put it in the same place on every card; react.dev calls a component with a `children` prop a frame with a hole its parent fills, used for panels, cards, and grids; both together is the common case: `<CardContainer title="Rail Strike Ends">` with the body between the tags.
    - Fix: `CardContainer({ title, children })` with `<h2>{title}</h2>` and `{children}`; the weather story has no byline between its tags, so none shows.
    - Rule: we pass content that changes from use to use as `children`, and we keep a prop for what every use must have and the frame must place, such as the title.
    - Needs: the two options (the opening); `undefined` shows nothing (recall Lecture 4); `children` (Question 1).
    - Diagram: the rigid card's fixed places against the frame with one hole.

> [!PRINCIPLE] Principle 2: Composition: children when the caller decides the content, props when the frame decides its shape. Right: `<ProfileCard title="John Hall"><p>Austin, Texas</p></ProfileCard>` with `<h2>{title}</h2>` and `{children}` in the frame; wrong: a rigid `ProfileCard({ title, phone })` drawing `<p>Phone: {phone}</p>`, which shows "Phone: " when no phone is passed; verified.

### Question 3: The caller's class replaces the card's own

- [question-cycle] Question 3: The caller's class replaces the card's own
    - Question: "Callers want a `className` and an `aria-label` on the card. Do I list each one?"
    - Code and result: `App` writes `<CardContainer className="featured" id="top-story" aria-label="Top story">`; with `({ children })`, none of the three reaches the `<article>`; with `({ children, ...rest })` and `<article className="card" {...rest}>`, the `id` and the `aria-label` arrive, but the card loses its border and padding: the Elements panel shows `class="featured"` (verified in React 19.3.1 and Chrome).
    - Verdict: does not do what the reader wanted.
    - Answer: attributes on our component's tag only go into its props, so the frame must pass them on; listing each one never ends, so the frame takes out what it uses, `children`, and collects the rest with `...rest`, then writes them all on its element with `{...rest}`; attributes apply in the order they are written, and the last one wins: `className="card"` first, then the caller's `className` from `rest`, so the caller's class replaced the card's; written the other way round, the card's class would replace the caller's; when both sides set a class, the frame joins them: `className={'card ' + className}` gives "card featured", but a card with no class gets `class="card undefined"`, because `className` is `undefined` and `+` turns it into the text "undefined"; the default from Lecture 6 completes it, `className = ''` in the parameter list, which gives `class="card "`; spreading every prop, `{...props}`, instead of the rest puts props the element does not understand into the DOM: `date="May 3"` lands on the `<article>`, and the console shows "React does not recognize the `isFeatured` prop on a DOM element".
    - Fix: `function CardContainer({ children, className = '', ...rest })` with `<article className={'card ' + className} {...rest}>`; "card featured" with the `id` and the `aria-label`, and "card " for a card with no class.
    - Rule: we take out the props the frame uses and pass only the rest to its element with `{...rest}`; the attribute written last wins, so a class the frame and the caller both set is joined, with an empty default for the caller who sets none.
    - Needs: rest and spread syntax (runway "Three dots collect the rest and spread it out"); a default value (recall Lecture 6); `+` (recall Lecture 4); `aria-*` attributes (recall Lecture 3).
    - Diagram: the attributes in the order they are applied, the last one winning.

> [!PRINCIPLE] Principle 3: Prop spreading: the attributes the frame does not use pass on to its element. Right: `Panel({ children, className = '', ...rest })` with `<section className={'panel ' + className} {...rest}>` (gives `class="panel wide"` and `id="contact"`, and `class="panel "` with no class); wrong: `<section className="panel" {...rest}>` (gives `class="wide"`, the panel's own class lost); verified.

- [grounding] Is `children` the same as the children of the render tree in Lecture 5? ◼ Friction target: the map's Supporting row on the render tree. Tactile scene: in Lecture 5, a component's children were the components its own markup names; now a caller places content inside another component's tags. Bold key terms: **render tree**, **`children` prop**. Concrete operational resolution: content passed as `children` becomes a child of the frame in the render tree, because the frame is the one that shows it, even though the caller wrote it; react.dev's example places `Copyright` under the component that shows it, not under `App`, which wrote it. ◼ Educational objective: one `> [!WILD]` card after the principles, adding a fact the cycles did not state.

### Step 1: First, we put each story between the frame's tags <App.jsx>

- [p] ★ The children prop. Decision: one frame, `CardContainer`, draws the border and the spacing; each story writes its whole content between the frame's tags: a headline, a sentence, and a byline; a headline and the park photo; a headline, a quote, and a byline. ### Step 2: Next, we move the title to a prop <App.jsx>

- [p] ★ Composition. Decision: every story has a title, and the design puts it at the top of every card, so the title leaves the content and becomes a prop that the frame places itself, `<h2>{title}</h2>` above `{children}`; the body stays between the tags. Result: the page looks the same, but now no story can forget its title or put it in another place, and the bodies hold only what differs (verified). ◼ Meaningful pedagogical commentary: the line between what the frame owns and what the caller owns.

### Step 3: Finally, we pass the top story's attributes on <App.jsx>

- [p] ★ Prop spreading. Decision: the feed marks the top story with `className="featured"` and `aria-label="Top story"`; the frame takes out what it uses, gives `className` an empty default, collects the rest, and writes `<article className={'card ' + className} {...rest}>`.
