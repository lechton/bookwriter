### Principles of React: Mounting the Root Component

- [preview] Everything in this lesson comes down to one idea: mounting, which means the browser loads one page, and React fills one element of it with our components. First, the root element, which means the page arrives with one empty element: we leave that element empty in the HTML file and write every part of the page in our components. Second, the build tool, which means the page's code arrives as plain JavaScript: we open the project through the dev server, because a browser cannot read JSX or a package name by itself. Third, the React root, which means the page hands that one element to React: we find the element by the same id the HTML file gives it, and we hand React the element itself. Fourth, the initial render, which means the page shows the root component in that element: we ask the root to render once, with the root component written as a tag. Fifth, one root per app, which means the page grows inside the root component: a new part of the page is a new tag inside the root component, never a second root on the same element. ◼ Educational objective: the map's Spoken Preview, word for word, one paragraph for the anchor and one per principle in the lecture, read aloud before Question 1.

> [!PRINCIPLE]
> **Principle 1: The root element: the page arrives with one empty element**
> *We leave `<div id="root">` empty in `index.html` and write every part of the page in our components; React fills that element when `main.jsx` runs, and replaces anything we typed inside it.*
>
> On a plain HTML site, the page we see is the HTML file, so we change the page by changing the file. A React project starts the same way: the browser reads `index.html` and builds what it finds there. But its body holds only one empty `<div id="root">` and a module script. When the script runs, React first removes whatever the file wrote inside the `<div>`, and then builds the elements our components return. So **View Page Source** shows the file as it arrived, and the Elements panel shows the live page. Every change to what the page shows goes into a component.
>
> *We should do this:*
> `<div id="root"></div> <!-- React fills it from the components -->`
>
> *We should not do this:*
> `<div id="root"><h1>My Site</h1></div> <!-- React removes the h1 -->`

### For the interview

- [interview] > **The Interview Question:** How does your root component attach to the browser DOM with createRoot, and how do build tools assemble it?

- [interview] **1. The Hidden Signal** ◼ The interviewer wants the path from the address bar to the first article on screen, in order, with who acts at each step. A junior answer names `createRoot` and stops. A strong answer starts with the browser reading `index.html`, says why the files need a build tool, says what `createRoot` takes and what `render` receives, and says where the app grows after that: inside `App`, not in new roots.

- [interview] **2. The Classic Trap** ◼ The classic trap is "React puts the components into `index.html`". View Page Source of the article site shows `<div id="root"></div>` with nothing inside, in development and in the build. React builds the page in the browser, inside that element, after `main.jsx` runs. A second trap is quoting `ReactDOM.render`, which React 19 removed: the call stops the page with "ReactDOM.render is not a function".

- [interview] **3. What is Actually Going On** ◼ The browser loads `index.html`, builds an empty `<div id="root">`, and loads `main.jsx` through a module script. The browser cannot read JSX or the name `'react-dom/client'`, so Vite sends `main.jsx` rewritten: `<App />` arrives as `_jsxDEV(App, {})`, and the package name as the address of a file. `createRoot(document.getElementById('root'))` takes the `<div>` and gives back a root. `root.render(<App />)` makes React call `App` and build the title, the two articles, and the footer inside the `<div>`. For production, `npm run build` writes the same plain JavaScript into `dist`, about 220 kB for our site.

- [interview] **4. Where It Gets Tricky** ◼ *How many roots does an app have?* One, when React builds the whole page; one per area when React runs only parts of an old page. *What happens if the id is wrong?* `getElementById` gives `null`, and `createRoot` throws "Target container is not a DOM element." *Why are `react` and `react-dom` two packages?* `react` holds what components need on any screen, and `react-dom` puts it into a browser page; React Native uses the same `react` with another partner. *Can code on the line after `root.render` read the new page?* No: `render` returns before the page changes, so a log of the `<div>` on the next line prints an empty text. *What does Strict Mode in `main.jsx` do?* It runs development checks, such as calling each component twice, which Lecture 46 explains. *What if the page's HTML comes from a server?* Then React attaches with `hydrateRoot` instead of `createRoot` (Lecture 104).

### Glossary

- [glossary] Mounting ◼ Showing a React app on a page for the first time: the browser loads one page, and React fills one element of it with our components.
- [glossary] Build tool ◼ A program such as Vite that turns our files into plain JavaScript the browser can run: each JSX tag into a call, and each package name into the address of a file. Its dev server does it on every request, and `npm run build` does it once into `dist`.
- [glossary] Module script ◼ A `<script type="module">` tag. It may use `import`, and the browser runs it only after the whole page is read.
- [glossary] `createRoot` ◼ The function from `react-dom/client` that takes one element of the page and gives back a React root.
- [glossary] React root ◼ The object `createRoot` gives back. React controls everything inside its element, and its `render` method says what to show there.
- [glossary] `root.render` ◼ The method that shows one React element, usually `<App />`, inside the root's element. It replaced `ReactDOM.render`, which React 19 removed.

### Summary

- [review-title] **Mounting: the browser loads one page, and React fills one element of it**

- [review-subtitle] ❒ The root element: the page arrives with one empty element
- [always-rule] ➔ ALWAYS leave `<div id="root">` empty in `index.html`, and write everything the page shows in components.
- [never-rule] ➔ NEVER type content inside the root element; React removes it on its first render.

- [review-subtitle] ❒ The build tool: the page's code arrives as plain JavaScript
- [always-rule] ➔ ALWAYS open the project through `npm run dev` and its `localhost` address while you work.
- [if-then-rule] ➔ IF the site goes to a server THEN send the `dist` folder from `npm run build`, checked first with `npm run preview`.
- [never-rule] ➔ NEVER double-click `index.html`, in `src` or in `dist`; a `file://` page stays blank.

- [review-subtitle] ❒ The React root: the page hands that one element to React
- [always-rule] ➔ ALWAYS pass `createRoot` the element itself, found by the same id that `index.html` gives it.
- [never-rule] ➔ NEVER call `createRoot` inside a component; it belongs in `main.jsx`, once.

- [review-subtitle] ❒ The initial render: the page shows the root component in that element
- [always-rule] ➔ ALWAYS call `render` once, with one argument: the root component written as a tag.
- [never-rule] ➔ NEVER copy `ReactDOM.render` from an old tutorial; React 19 removed it.

- [review-subtitle] ❒ One root per app: the page grows inside the root component
- [if-then-rule] ➔ IF the app is built fully with React THEN add each new part of the page as a tag inside `App`, with one root and one `render`.
- [if-then-rule] ➔ IF React runs only parts of an existing page THEN give each React area its own element and its own root.

- [closing-line] One empty element, plain JavaScript, one root, one render, and the rest inside the root component. ◼ Educational objective: the map's Closing Line, the last spoken sentence of the lesson. The five subtitles above are the five thread labels word for word, so the summary repeats the structure the preview announced (`lecture-structure` Section 13).

**DO THIS:** hand one empty element to React and render the root component once

```jsx right
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

**DO NOT DO THIS:** start the app with the removed one-call form

```jsx wrong
import ReactDOM from 'react-dom';
import App from './App.jsx';

ReactDOM.render(<App />, document.getElementById('root'));
```

- [comparison-table]

| | **ONE ROOT**<br>(an app built with React) | **SEVERAL ROOTS**<br>(React in part of a page) |
| ---: | :--- | :--- |
| **What `index.html` holds** | One empty element:<br>`<div id="root">` | The old page, with one empty<br>element per React area |
| **What `main.jsx` calls** | `createRoot(...)` once<br>and `render(<App />)` once | One `createRoot` and one `render`<br>per area, each on its own element |
| **A new part of the page** | A new tag inside `App`:<br>`<Footer />` | Inside its area's component, or<br>a new area with its own element |
| **Who builds the rest of the page** | React, from the tree below `App` | The old server; React never touches it |
| **When it fits** | A new app built from scratch<br>with a build tool such as Vite | An old site that moves to React<br>one area at a time |
| **When a framework fits instead** | Pages that should arrive already filled:<br>the framework calls this code for us (Lecture 45) | Once the whole page is React,<br>react.dev suggests moving to a framework |
