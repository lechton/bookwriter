# Lecture 11: Rendering Lists and Keys
> INTERVIEW QUESTION | ❱ CORE | How do you render a list from an array, and why does React demand a key on every item?

```page caption="Three cards with the same design and different data. Each card has a comment box."
heading: Latest Articles
card: title=New Park Opens Today | author=Mary Jones | input
card: title=Rain Expected This Weekend | author=Oliver Brooks | input
card: title=Five Soups for Cold Days | author=Samantha Robinson | input
```

A site shows the same kind of item many times: articles, comments, products. Only the data differs. Until now, `ArticleList` wrote one `<ArticleCard />` tag per article, so thirty articles would need thirty tags. How does one array of articles become one card per article, and why does React ask for a key?

## From one tag per article to one array

The articles move out of the JSX into one array in `src/articles.js`. Each article has an `id`, a number that belongs to that article and to no other.

```js title="articles.js"
export const articles = [
  { id: 1, title: 'New Park Opens Today', author: 'Mary Jones', topic: 'City' },
  { id: 2, title: 'Rain Expected This Weekend', author: 'Oliver Brooks', topic: 'Weather' },
  { id: 3, title: 'Five Soups for Cold Days', author: 'Samantha Robinson', topic: 'Food' },
];
```

::: row caption="The same three cards on the page, written two ways."
::: col title="By hand" tag="Lectures 2 to 10" tone=plain
```jsx
<main>
  <ArticleCard article={articles[0]} />
  <ArticleCard article={articles[1]} />
  <ArticleCard article={articles[2]} />
</main>
```
A new article needs a new tag.
:::
::: col title="A rendered list" tag="this lecture" tone=good
```jsx
<main>
  {articles.map(article => (
    <ArticleCard key={article.id} article={article} />
  ))}
</main>
```
A new article needs only a new object in `articles.js`.
:::
:::

That is **rendering a list**: an array of data becomes an array of elements, each with its own key.

## Every item, only some items, one name each

```ladder anchor="An array of data becomes an array of elements, each with its own key."
group: Items become elements
Every item | map() | One card per article | a b c > A B C
Only some items | filter() | One section per topic | a b c > B
group: Elements get names
One name each | key={id} | A typed comment stays put | A:1 B:2 C:3
The name's place | <Card key> | On the tag inside map() | A:1 > a
```

## 1. Every item: map() and an arrow that gives back

To stop writing tags by hand, we call `articles.map()`. We add a curly brace after the arrow, to leave room for a second line later:

```jsx title="ArticleList.jsx" bad="2-4"
<main>
  {articles.map(article => {
    <ArticleCard article={article} />;
  })}
</main>
```

::: row caption="One curly brace decides what map() gives back."
::: col title="`article => { <ArticleCard />; }`" tone=bad
```page size=mini
heading: Latest Articles
empty: no cards
quiet: Console: no messages
```
No card, and no message to explain why.
:::
::: col title="`article => ( <ArticleCard /> )`" tone=good
```page size=mini
heading: Latest Articles
card: title=New Park Opens Today | author=Mary Jones
card: title=Rain Expected This Weekend | author=Oliver Brooks
card: title=Five Soups for Cold Days | author=Samantha Robinson
```
Three cards, one per article.
:::
:::

An **arrow function** gives back the expression right after `=>`. After `=> {`, the body is a block, and it gives back only what `return` names; without `return`, it gives back `undefined`.

```chain
!`articles.map(article => { <Card />; })` -> `[undefined, undefined, undefined]` -> no cards
+`articles.map(article => ( <Card /> ))` -> `[<Card>, <Card>, <Card>]` -> three cards
```

`map()` calls the function once per item and collects what it gives back into a new array, and React shows an array of elements in order. A `for` loop cannot go inside the braces, because it is a statement, and `forEach()` gives back `undefined`, so neither shows anything.

```jsx title="ArticleList.jsx" good="2-4"
<main>
  {articles.map(article => (
    <ArticleCard article={article} />
  ))}
</main>
```

> [!PRINCIPLE]
> **Principle 1: Mapping: turning every item into an element**
>
> To show one element per item, we call `map()` on the array inside the JSX, and its arrow function gives back the element: right after `=>`, or with `return` when the body starts with a curly brace.
>
> *We should do this:*
>
> ```jsx
> {items.map(item => (
>   <Item item={item} /> {/* one element per item */}
> ))}
> ```
>
> *We should not do this:*
>
> ```jsx
> {items.map(item => {
>   <Item item={item} />; // **PROBLEMATIC:** missing return renders nothing
> })}
> ```

## 2. Only some items: filter() first, and a message for none

Each topic gets its own section. `ArticleList` receives a `topic`, keeps only that topic's articles with `filter()`, and maps what is left. `App` renders `<ArticleList topic="City" />` and `<ArticleList topic="Sport" />`, and there is no Sport article yet.

```jsx title="ArticleList.jsx" bad="6-8"
export default function ArticleList({ topic }) {
  const shown = articles.filter(article => article.topic === topic);
  return (
    <section>
      <h2>{topic}</h2>
      {shown.length && (
        shown.map(article => <ArticleCard article={article} />)
      )}
    </section>
```

::: row caption="The Sport section has no article."
::: col title="`shown.length && ...`" tone=bad
```page size=mini
section: City
card: title=New Park Opens Today | author=Mary Jones
section: Sport
line: 0 | bad
```
A bare `0` under the Sport heading.
:::
::: col title="`shown.length > 0 ? ... : <p>`" tone=good
```page size=mini
section: City
card: title=New Park Opens Today | author=Mary Jones
section: Sport
line: No Sport articles yet. | good
```
A message instead of an empty space.
:::
:::

`filter()` gives back a new array with only the items that pass the test. For Sport, that array is empty, its `length` is `0`, and this is Lecture 10's trap again: `0 && ...` gives back `0`, and React draws numbers. A real comparison and a ternary give the reader a message:

```jsx title="ArticleList.jsx" good="1-5"
{shown.length > 0 ? (
  shown.map(article => <ArticleCard article={article} />)
) : (
  <p>No {topic} articles yet.</p>
)}
```

> [!PRINCIPLE]
> **Principle 2: Filtering: turning only some items into elements**
>
> To show only some items, we call `filter()` before `map()`; when the filtered array can be empty, we test its length with `> 0` and show a message instead.
>
> *We should do this:*
>
> ```jsx
> const shown = items.filter(item => item.isOpen);
> {shown.length > 0 ? (
>   shown.map(item => <Item item={item} />) {/* cards */}
> ) : (
>   <p>Nothing here yet.</p> {/* shown when array is empty */}
> )}
> ```
>
> *We should not do this:*
>
> ```jsx
> const shown = items.filter(item => item.isOpen);
> {shown.length && shown.map(item => <Item item={item} />)} // **PROBLEMATIC:** renders 0 on page
> ```

## 3. One name each: a key from the item's id

The cards show fine, but the console warns:

```console
warn: Each child in a list should have a unique "key" prop.
```

To see what the key does, we type "Great news!" into the comment box of the rain card. Then we add a new article, "Library Opens on Sundays", at the top of `articles.js`, and save.

::: row arrows caption="Without keys, the typed comment moves to another article."
::: col title="Before the save" tone=plain
```page size=mini
card: title=New Park Opens Today | input
card: title=Rain Expected This Weekend | typed=Great news!
card: title=Five Soups for Cold Days | input
```
:::
::: col title="After the save, no key" tone=bad
```page size=mini
card: title=Library Opens on Sundays | input
card: title=New Park Opens Today | typed=Great news! | bad=typed
card: title=Rain Expected This Weekend | input
card: title=Five Soups for Cold Days | input
```
:::
:::

When a list is shown again, React matches each new element with one it already built and keeps it. Without a key, it matches by position: the first with the first, the second with the second. The new article pushed every article down one place, so the second card on the page now receives the park article's data, while the text typed into its box stays where it was.

```chain caption="What React keeps for the card that holds the typed text."
!by position: the 2nd card, "Great news!" -> now shows New Park Opens Today
+by key: the card with key 2, "Great news!" -> still shows Rain Expected This Weekend
```

A **key** names each element. With `key={article.id}`, React matches by name: every article keeps its own element, and only the new article gets a new one. The four possible keys give four results after the same typing and the same save:

::: row caption="The same typing and the same save, with four keys: the first three cards after the save."
::: col title="no key" tone=bad
```page size=mini
card: title=Library Opens on Sundays | input
card: title=New Park Opens Today | typed=Great news! | bad=typed
card: title=Rain Expected This Weekend | input
```
The text moves to the park.
:::
::: col title="`key={index}`" tone=bad
```page size=mini
card: title=Library Opens on Sundays | input
card: title=New Park Opens Today | typed=Great news! | bad=typed
card: title=Rain Expected This Weekend | input
```
The warning goes. The bug stays: the index is the position.
:::
::: col title="`key={Math.random()}`" tone=bad
```page size=mini
card: title=Library Opens on Sundays | input
card: title=New Park Opens Today | input
card: title=Rain Expected This Weekend | input | bad=input
```
A new key on every render: every card is built again, and the text is gone.
:::
::: col title="`key={article.id}`" tone=good
```page size=mini
card: title=Library Opens on Sundays | input
card: title=New Park Opens Today | input
card: title=Rain Expected This Weekend | typed=Great news! | good=typed
```
The text stays with the rain article.
:::
:::

```jsx title="ArticleList.jsx" good="2"
{articles.map(article => (
  <ArticleCard key={article.id} article={article} />
))}
```

The index is a safe key only for a list that never inserts, deletes, or reorders, such as the links in a footer.

> [!PRINCIPLE]
> **Principle 3: Keys: naming each element so React can tell the items apart**
>
> We give each element a `key` from the item's own id, so React matches every item with the same element the next time the list is shown; the array index fits only a list that never changes order, and a key made while rendering fits nothing.
>
> *We should do this:*
>
> ```jsx
> {items.map(item => (
>   <Item key={item.id} item={item} /> {/* follows the item */}
> ))}
> ```
>
> *We should not do this:*
>
> ```jsx
> {items.map((item, index) => (
>   <Item key={index} item={item} /> {/* **PROBLEMATIC:** index tracks position */}
> ))}
> ```

## 4. The name's place: on the tag inside map()

The Elements panel shows `<article class="card">` many times, so the key seems to belong on the `<article>` inside `ArticleCard`. The warning stays.

::: row caption="React needs the key on the items of the array that map() gives back."
::: col title="Key inside the card" tone=bad
```jsx title="ArticleCard.jsx" bad="3"
function ArticleCard({ article }) {
  return (
    <article key={article.id} className="card">
```
```console
warn: Each child in a list should have a unique "key" prop. Check the render method of `ArticleList`.
```
:::
::: col title="Key on the tag inside map()" tone=good
```jsx title="ArticleList.jsx" good="2"
{articles.map(article => (
  <ArticleCard key={article.id} article={article} />
))}
```
```console
quiet: No messages
```
:::
:::

`map()` gives back an array of `<ArticleCard>` elements, and those are the items React matches. The `<article>` inside the card is one element of the card's own markup, not an item of any array. The warning even names `ArticleList`, the component with the `map()`.

React keeps the key for itself: the card never receives a `key` prop, and reading it gives `undefined`. A card that needs the id gets it again under another name, such as `articleId={article.id}`. An item made of several tags uses `<Fragment key={article.id}>`, because `<>` takes no key.

> [!PRINCIPLE]
> **Principle 4: The key's place: naming the element the map gives back**
>
> We write the `key` directly on the tag the `map()` call gives back, never inside the child component and never inside a spread object, and when the child needs the id, we pass it again as a prop of its own.
>
> *We should do this:*
>
> ```jsx
> {items.map(item => (
>   <Item key={item.id} item={item} /> {/* on the array item */}
> ))}
> ```
>
> *We should not do this:*
>
> ```jsx
> function Item({ item }) {
>   return <li key={item.id}>{item.name}</li>; // **PROBLEMATIC:** warning stays
> }
> ```

## For the interview

- **Why does React need a key?** To match each item with the element it built last time. Without one, React matches by position, so an item added at the top moves typed text and focus to the wrong item.
- **Is `key={index}` fine?** Only for a list that never inserts, deletes, or reorders. The index is the position, so it hides the warning and keeps the bug. Many tutorials use it on fixed lists with no inputs, where the bug never shows.
- **Why not `key={Math.random()}`?** It changes on every render, so nothing matches, every element is built again, and typed text and focus are lost.
- **Must keys be unique on the whole page?** No, only among the items of one array.
- **Can the child read its key?** No. `props.key` is `undefined`; pass the id under another name.
- **Why does an empty list with `length &&` show a 0?** `0 && ...` gives back `0`, and React draws numbers. Write `length > 0`.

## Where you will meet this

- Every list from data: comments, search results, cart items, messages. Each comes from an array, goes through `map()`, and takes its key from the item's id.
- Data from a server: each record already has an id that can be its key.
- Rows with inputs, such as quantities in a cart or checkboxes in a to-do list: index keys move the entries to other rows when the list is sorted or an item is deleted.

## Summary

| step | write | instead of |
| --- | --- | --- |
| +Every item | `items.map(item => <Item />)`, or `return` after `=> {` | a `for` loop or `forEach()` in the braces; `=> {` with no `return` |
| +Only some items | `filter()` before `map()`, and `length > 0 ? ... : <p>` | a bare `length` left of `&&` |
| +One name each | `key={item.id}` | no key, the index on a list that changes, `Math.random()` |
| +The name's place | the key on the tag written inside `map()` | a key inside the child, or inside a spread object |

**Every item, only some items, one name each, and the name on the right element.**

**DO THIS:**

```jsx right
const shown = articles.filter(article => article.topic === topic);
return shown.length > 0 ? (
  <ul>
    {shown.map(article => (
      <li key={article.id}>
        <ArticleCard article={article} />
      </li>
    ))}
  </ul>
) : (
  <p>No {topic} articles yet.</p>
);
```

**DO NOT DO THIS:**

```jsx wrong
const shown = articles.filter(article => article.topic === topic);
return (
  <ul>
    {shown.length && shown.map((article, index) => (
      <li key={index}>
        <ArticleCard article={article} />
      </li>
    ))}
  </ul>
);
```
