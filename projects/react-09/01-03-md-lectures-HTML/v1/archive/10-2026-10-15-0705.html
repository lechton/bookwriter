Lecture 10: Conditional Rendering in React

Interview Question

CORE

How do you show, hide, or switch JSX based on a condition?

Imagine this scenario:

  1. You build an article card that shows an urgent alert and reader comments when enabled.
  2. You write {commentCount && <p>Comments</p>}, but a raw number 0 prints on the screen.
  3. How do you branch markup cleanly in React without leaving unwanted numbers on the page?

Every web page needs to branch its markup

Every web page needs to adapt its markup to changing data. A shop shows an "Out of Stock" note when an item count reaches zero, an article shows an urgent alert when news breaks, and a discussion section hides comments when they are turned off. In static HTML, all content is permanent and unchanging. In modern applications, data changes constantly based on user actions and server responses. A developer needs a reliable way to show different elements, switch between two options, or render nothing at all.

In plain JavaScript, developers changed visibility by searching the page with document.getElementById and adding a CSS class like hidden, or setting style.display = 'none'. That approach tells the browser what commands to run step by step. In React, a component is a function that returns a description of what the user interface should look like for the current props. You never search the page or toggle classes on DOM nodes yourself. Instead, you write plain JavaScript control flow directly in your component to return the JSX for each case. React compares that description to the page and creates, updates, or removes real DOM nodes to match.

This chapter answers five core questions: How does React show or hide elements without manual DOM queries? How do you protect a component from crashing when data is missing? When should you use a ternary operator instead of logical AND? Why does a count of zero print a stray zero on the screen? How do you organize complex branching without nesting ternaries inside JSX?

Later in this track, Lecture 11 shows how to render lists of items from arrays, using {tags.length > 0 && <ul>{tags.map(...)}</ul>} to guard against empty collections.

  • Lecture 3 (JSX is JavaScript): JSX elements are plain JavaScript object descriptions that React turns into living browser DOM nodes.
  • Lecture 4 (JSX expressions): Braces inside JSX hold expressions, not statements. Inside braces, booleans, null, and undefined print nothing, while numbers and strings print directly to the screen.
  • Lecture 6 (Passing props): A parent passes values down to children as props. Quoted strings pass text, while curly braces pass numbers, booleans, and variables.

How JavaScript evaluates conditions, operators, and falsy values

In Lecture 4, we learned that curly braces inside JSX open a window where JavaScript evaluates code. However, JavaScript strictly separates statements from expressions. An expression produces a single value that can be passed to a function or assigned to a variable, such as 2 + 2 or user.name. A statement performs an action or controls program flow, such as an if block, a for loop, or a variable declaration. Because JSX tags compile into function calls, you cannot place an if statement directly inside JSX curly braces. For inline branching inside JSX markup, you must use JavaScript expressions.

The ternary operator (? :) is an inline JavaScript expression that takes three operands. First comes a condition, followed by a question mark (?), an expression to evaluate if the condition is truthy, a colon (:), and an expression to evaluate if the condition is falsy. For example, isLive ? <LiveBadge /> : <StaticDate /> checks isLive. If isLive is true, the expression evaluates to <LiveBadge />. If isLive is false, it evaluates to <StaticDate />. Because the whole ternary evaluates to a single value, it fits cleanly inside JSX curly braces.

The logical AND operator (&&) evaluates expressions from left to right using short-circuit evaluation. If the left side is falsy, JavaScript stops immediately and returns that exact left-hand value without evaluating the right side. If the left side is truthy, JavaScript evaluates and returns the right side. For example, in isUrgent && <AlertBadge /> if isUrgent is true, JavaScript evaluates and returns <AlertBadge />. If isUrgent is false, JavaScript stops and returns false.

In JavaScript, values are either truthy or falsy when tested in a boolean condition. There are six primary falsy values: false, null, undefined, 0, NaN, and the empty string "". All other values are truthy, including non-empty strings like "false", objects, and empty arrays []. Because an empty array is truthy, testing tags && <TagList /> evaluates to true even when tags has no items. Testing tags.length > 0 produces an explicit boolean comparison using > that evaluates to false when the list is empty.

Why React leaves omitted elements out of the browser DOM

When React runs a component function, the browser DOM has not been updated yet. The component executes in JavaScript memory to produce a tree of React elements. If a component attempts to find its own markup using document.getElementById('comments') the browser method returns null because that element is not in the page yet. Attempting to call .classList.add('hidden') on null throws an unhandled TypeError that halts execution and causes the whole page to go blank.

In plain HTML, setting style={{ display: 'none' }} hides an element visually, but the physical HTML element remains in the browser DOM and accessibility tree, consuming memory and confusing screen readers. In React, conditional rendering uses DOM omission: when a condition is false, the component simply does not include that JSX element in its return value. React compares the returned tree against the real page and removes the corresponding node completely, or never creates it in the first place.

When a component receives data through props, that data may be uninitialized or missing. In JavaScript, reading a property on undefined, such as article.title when article is undefined, throws a fatal TypeError: Cannot read properties of undefined (reading 'title') In React, an unhandled error during render unmounts the component tree, blanking the application. An early return checks for missing data at the very top of the function: if (!article) return null; When a component returns null, React renders nothing for that component while leaving the rest of the application intact on screen.

Why does calling classList in the component throw an error?

ANSWER

The code does not work. The element does not exist in the document while React runs the component function.

While a component runs, React executes the function in JavaScript memory to calculate a tree of element descriptions. The browser DOM has not been updated yet, so document.getElementById('comments') finds nothing and returns null. Why does one missing property access clear the entire page?

ANSWER

The code does not work. Reading a property on undefined throws a fatal JavaScript error that crashes the render pass.

In Lecture 4, we saw that rendering {undefined} directly in JSX produces nothing on the screen without crashing. But reading a property on undefined, such as article.title, is an unhandled JavaScript error. When an error throws during render, React unmounts the entire component tree, leaving the user with a completely blank screen.

The fix is a defensive early return placed at the very top of the component function. Checking if (!article) return null; intercepts the missing data before any property access occurs. When a component returns null, React renders an empty slot for that component, allowing the rest of the application to render safely.

The alert banner appears only for urgent stories, and the header switches cleanly between the live badge and the timestamp.

When should you use a ternary operator instead of logical AND?

ANSWER

The code works. Each operator matches the exact shape of its branch.

The ternary operator evaluates to one of two expressions: condition ? <BranchA /> : <BranchB /> This makes it the right choice when you must choose between two visible outcomes. The logical AND operator evaluates to its right-hand expression when the left side is truthy, and to false when the left side is falsy. Because React suppresses false, logical AND is the right choice when you want to show an element or render nothing at all.

A common mistake is writing two separate && expressions with opposite conditions to simulate a choice: {isLive && <LiveBadge />} and {!isLive && <StaticDate />} This duplicates the condition across two lines. If someone edits one condition and forgets the other, both elements or neither element may appear. When both branches share wrapper markup, branch only the piece that differs, such as className={'card ' + (isUrgent ? 'urgent' : '')}

Branch shape decides the operator
Binary Choice (Branch A or Branch B):
isLive ? <LiveBadge /> : <StaticDate />  -> exactly one element renders

Show-or-Nothing (Branch A or Nothing):
isUrgent && <AlertBadge />  -> badge when true, false suppressed when false

The logical AND operator evaluates to its right-hand element when true, and to false when false, which React leaves out of the page. When two branches share common markup, branch only the piece that changes.

QUESTION 4

An unread counter of 0 prints a raw 0 on screen

An article card component displays an unread comment badge using the logical AND operator:

Unread Counter Short Circuit
1export default function CommentCounter({ count }) {
2 return (
3 <div className="counter-box">
4 {count && <p>{count} Comments</p>}
Count is 0 here
5 </div>
6 );
7}

When a story has 5 comments, the badge displays "5 Comments". But when a story has 0 comments, the screen displays a literal, stray "0" right where the badge should be.

Why does a count of zero print a raw 0 onto the page?

ANSWER

The code does not work. The logical AND operator returns 0, and React renders numbers as visible text.

In JavaScript, && short-circuits and returns its left side whenever that side is falsy. When count is 0, JavaScript evaluates 0 && <Badge /> to 0, not to false. React suppresses booleans (false, true), null, and undefined, but it treats numbers as legitimate user content and renders them as real browser text nodes. Therefore, React creates a DOM text node containing "0" and paints it onto the screen.

The exact same issue occurs with NaN, which prints "NaN" on screen and triggers a console warning. Furthermore, non-empty strings like "false" and empty arrays [] are truthy in JavaScript, so isUrgent="false" and tags && <TagList /> both display their elements.

Short-circuit evaluation of 0 vs comparison
Raw number 0:
count is 0 -> 0 && <Badge /> returns 0 -> React renders text node "0"

Explicit boolean comparison:
count is 0 -> count > 0 is false -> false && <Badge /> returns false (omitted)

The fix is to convert the numeric check into an explicit boolean comparison by writing {count > 0 && <p>{count} Comments</p>} Comparing count > 0 produces false when count is zero, which React suppresses completely.

PRINCIPLE 4

Put a boolean on the left of &&, never a number

stray zero an unwanted 0 displayed on screen when a numeric zero short-circuits in JSX

The logical AND operator returns its left side whenever that side is falsy. In JavaScript, 0 is falsy, so 0 on the left evaluates to the number 0. React leaves booleans, null, and undefined out of the page, but it renders numbers as visible text. A condition with 0 prints a stray zero on the screen. Compare numbers with zero using a comparison operator so the left side is always a real boolean.

prints nothing

How do you branch across several conditions without nesting ternaries in JSX?

ANSWER

The code works. The nested ternaries evaluate correctly, but they make the template difficult to read.

Curly braces inside JSX hold only a single expression, so handling three or more branches inline forces you to chain multiple ternary operators. Matching each question mark to its colon requires mental effort, and adding another branch requires editing a fragile expression.

Because JSX elements are plain JavaScript objects in memory, you can move branching above the return statement using standard let variables and if/else statements. You declare a variable such as let badge = null; set it using plain JavaScript statements, and embed {badge} once inside your returned markup.

Nested inline ternaries vs extracted variable above return

else if (isLive) badge = <Live />;
return <header>{badge}<h1>{title}</h1></header>;  (clean, readable, flat)

Simple binary choices and short show-or-nothing checks stay inline inside JSX. When branching logic outgrows a single clean expression, extract the logic above the return statement.

Declarative conditional rendering fundamentally changes how developers build dynamic interfaces. Instead of mutating the DOM after elements are created, React components describe exactly which elements should exist for any given combination of props. By using early returns for missing data, ternaries for binary choices, boolean-guarded logical AND operators for show-or-nothing branches, and variables for complex logic, you build user interfaces that are predictable, resilient to edge cases, and completely free of stray zeroes or layout flickering.

Where you will meet this

  1. Authentication and Navigation Bars: When building site headers, you conditionally render login buttons for guest visitors, user avatars for signed-in members, and administrative links for staff using ternary operators.

For the interview

The Interview Question: How do you show, hide, or switch JSX based on a condition?

1. The Hidden Signal

The interviewer is not asking whether you know the syntax of an if statement or a question mark. They are probing whether you understand how React manages the browser DOM declaratively. A junior candidate talks about toggling CSS classes with document queries. A senior engineer explains that components are pure functions of props and state: React renders what the returned JSX describes, and omits what the JSX leaves out. They immediately highlight the difference between expressions and statements inside JSX braces, explain how React treats falsy values, and address the stray zero trap.

2. The Classic Trap

The most famous trap is writing {count && <Badge />} with a numeric zero. Candidates assume that because 0 is falsy in JavaScript, React will render nothing. But in JavaScript, 0 && <Component /> returns 0. React suppresses booleans, null, and undefined, but it treats numbers as visible user content and renders a literal "0" onto the physical screen. Another classic trap is using two separate inverted && expressions ({isLive && <A />} and {!isLive && <B />}) to simulate an if/else branch, which duplicates the condition and causes visual desynchronization when conditions drift.

3. What is Actually Going On

In React, conditional rendering uses standard JavaScript control flow. Braces inside JSX open an expression window, so an if statement cannot live directly inside markup. For a binary choice between two elements, use a ternary: {isLive ? <LiveBadge /> : <StaticDate />} For a show-or-nothing element, use logical AND: {isUrgent && <AlertBadge />} When a condition evaluates to false, React leaves that element out of the tree entirely; it produces zero DOM nodes, meaning the element is never created in the browser page. When data may be uninitialized, place an early return if (!data) return null; at the top of the component to prevent property read crashes. When logic has three or more cases, move branching above the return statement into standard if statements and a let variable.

4. Where It Gets Tricky

What happens if you pass a quoted string like isUrgent="false" to a component? In JavaScript, all non-empty strings are truthy. Writing isUrgent="false" passes the literal string "false", so {isUrgent && <Alert />} evaluates to true and shows the alert. To pass a real boolean, you must use curly braces: isUrgent={false}.

What happens if an uninitialized calculation produces NaN? In JavaScript, NaN is falsy. But like 0, NaN && <Component /> returns NaN. React prints "NaN" directly onto the screen and logs a console warning. Always guard calculations with !Number.isNaN(val) && val > 0

What happens if you check an empty array with tags && <TagList />? In JavaScript, an empty array [] is an object, and all objects are truthy. Even with zero items, tags && <TagList /> evaluates to true, mounting <TagList /> with an empty collection. Always check length: tags.length > 0 && <TagList />

Glossary

  • Conditional Rendering: The technique of displaying, hiding, or alternating user interface markup based on JavaScript conditions and props.
  • Early Return: Exiting a component function early with null or fallback markup before executing the main JSX return.
  • Ternary Operator: A JavaScript inline operator (? :) that evaluates a condition and chooses between two alternative expressions.
  • Short-Circuit Evaluation: The evaluation model where logical AND (&&) stops and returns the left operand immediately if it is falsy.
  • Suppression Whitelist: React's built-in rule that renders zero DOM nodes for booleans (true, false), null, and undefined.
  • Stray Zero: An unwanted 0 displayed on the screen when a numeric zero short-circuits on the left side of logical AND.

➔ ALWAYS convert numbers to explicit booleans (count > 0 && ...) before using the && operator to prevent the stray zero bug.

➔ NEVER place a raw numeric counter or unverified calculation on the left side of &&.

❒ Complexity Management & DOM Ownership

➔ IF branching logic exceeds one clean expression THEN move the calculation before the return statement using standard if statements and a variable.

➔ NEVER manipulate CSS classes or styles imperatively using classList on DOM elements managed by React.
