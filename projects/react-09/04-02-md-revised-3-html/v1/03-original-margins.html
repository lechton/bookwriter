Interview question❱ CORE
What is JSX, what syntax rules must every snippet follow, and how do Fragments group elements without wrapper nodes?

React JSX Syntax

Two different ways to write markup

The same markup can reach the page in two ways:

An HTML file forgives mistakes. A tag left open, or two tags side by side, still gives a page. A component does not forgive them. The build first rewrites its markup into JavaScript, and one open tag, or two tags side by side after return, stops the whole file. Wrong attribute names are the one mistake the build lets through, and the Console shows them as errors. We still move markup into components, because a component is a function: we place it anywhere with one tag, and later fill it from data. So the markup must follow JavaScript's rules.

The React markup (JSX) vs Normal HTML

Markup in a component follows five rules. Two words come first. A root is the one outermost tag a component returns, and it holds all the others. A box is an extra element on the page, such as a <div>; the interview question calls it a wrapper node.

We learn the rules in this order. The first rule explains the others: once a tag is a call, the next two rules follow. The build checks those two before anything runs, so their mistakes appear as error overlays. The Fragment solves the problem that the one-root rule creates. The attribute names come last, because the build accepts wrong ones, and only the Console complains.

This rewrite is the JSX transform. The tag's name becomes the call's first argument. Example: let's group the items with a <div> (the CSS rules break!)

Here, an extra <div> or <section> breaks the page's CSS rules. In the previous example, an extra element did no harm: a <section> around a name and a line changed nothing on the page.

CSS is sensitive to the hierarchy of DOM elements. Many CSS rules style an element by its place under its parent: a rule can style only the <li> items that sit directly inside a list, for example. When we add a new element in between, such as a <div>, the items are no longer directly inside the list, and the rule stops applying. The page loses that style, and neither the build nor the Console warns us.

These CSS rules often come from a web designer, not from the React developer. So a React developer can break a style without knowing that it exists. A React developer needs to know how the page's CSS depends on its elements.

FactJavaScript keeps some words for itself, such as return, class, and for: they are reserved words. HTML's aria-* attributes, such as aria-label, describe an element to screen readers; data-* attributes, such as data-form-id, store our own values on an element.

Names of several words use camelCase, where each later word starts with a capital, such as tabIndex. Only aria-* and data-* keep their dashes.

For the interview

  • What is JSX? Not HTML. The build turns each tag into a function call. The call returns a plain object, a React element, and React builds the DOM from those objects. The browser never sees JSX, and every rule follows from that.
  • Is JSX just HTML with a few differences? That is the classic trap. An HTML file accepts an open <img>, two tags side by side, and class. In a component, the first two stop the build, and class works but logs an error in the Console.
  • Does a Fragment appear in the Elements panel? No. Its children sit directly inside the parent, as the two <li> items did in the list.
  • Can I keep the HTML comments of my old page? No: <!-- ... --> stops the build. Inside the markup, a comment is written {/* ... */}.
  • Old tutorials start each file with import React from 'react'. Do I need it? Not for JSX. The old transform turned each tag into React.createElement, which needed React in the file. React 19 requires the new transform, which adds its own import; the Network panel's Response shows it.

Where you will meet this

  • A designer's HTML mockup, or a snippet copied from a CSS library: we close every open <input> and <img>, give every group of tags side by side after return one root, and rename every class.
  • A component that returns several table cells for one row: we group the cells with a Fragment. A <div> inside a <tr> breaks the table, and React logs an error that a <div> cannot be a child of a <tr>.
  • An icon pasted from a design tool as SVG markup: we rename each attribute of several words, so stroke-width becomes strokeWidth.

Summary

One call per tag, a capital letter for our components, every tag closed, one root, a Fragment when the page needs no box, and JavaScript names.
