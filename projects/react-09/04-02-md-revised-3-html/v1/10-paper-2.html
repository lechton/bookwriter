React Conditional Rendering

Two different ways to keep a part off the page

A part of the page can stay off the screen in two ways:

Fact! turns true into false and false into true. In a condition, null, undefined, 0, and '' count as false, so !user is true when user is null.

We compare the two ways on a New label, with isNew set to false. Both pages show no label. Only the Elements panel shows the difference:

We leave a part out in almost every case. Hidden JSX still runs: <h2 hidden={!user}>{user.name}</h2> still reads user.name, and throws when user is null. JSX that is left out never runs. We hide a part only when it must keep what is inside it while it is gone, such as text the user typed into a field. Hiding keeps that text. Leaving the part out throws it away.

Leaving a part out is conditional rendering. Each time React calls a component, the component chooses which JSX to return, with plain JavaScript.

Conditional rendering: four kinds of choice

We call each part of the JSX that may or may not appear a piece: a label, a line of text, or a whole child component. A choice covers either the whole component or one piece inside it. For a piece, the tool depends on how many outcomes the choice has:

We learn the four in this order, because each builds on the one before. When the whole component has nothing to show, it returns null. When one piece shows or not, we use &&. When one of two pieces always shows, we use the ternary. When there are three or more outcomes, we use if and a variable.

Why is the if chain easier to read?

Each branch of the if chain holds one case, and we read the cases from top to bottom. The first branch runs for 0, the second for 1, and the else for any other count. The JSX only places the result, <p>{text}</p>:

FactInside JSX braces, only an expression can go: code that gives a value, such as count > 0 or a ternary. An if is a statement: it does something but gives no value, so it cannot go inside the braces.

For the interview

  • Is && an inline if? No. It gives back one of its two sides, so 0 && <Badge /> gives back 0, and React shows it. We put a true or false value on the left: count > 0 && <Badge />.
  • Is returning null the same as leaving the tag out in the parent? The page looks the same when the parent puts nothing around the tag. When the parent has its own markup there, such as a heading, only leaving the tag out removes that too. With null, the component still runs every time its parent renders, and a console.log inside it still prints. When the parent leaves the tag out, the component never runs.
  • Why not just display: none? Hidden JSX still runs, so <h2 hidden={!user}>{user.name}</h2> still throws when user is null. A hidden element also stays in the DOM with what is inside it, such as typed text. A part that is left out is removed, and when it comes back, React builds it again, empty. So we hide only a part that must keep what is inside it while it is gone.
  • return null or return; with no value? return; gives undefined. Before React 18, returning undefined threw an error. Now both show nothing. null says that the choice is on purpose.
  • Why would <ArticleCard article={park} isSignedIn="false" /> show the summary to a visitor? A prop written in quotes is text, and any non-empty text is truthy, the opposite of falsy. So the ternary takes its first side. isSignedIn={false}, in braces, passes a real false.

Where you will meet this

  • An unread badge, shown only when there are unread messages: we write unread > 0 && <Badge />, never unread && <Badge />, which shows a 0 when there are none.
  • A header that shows "Sign in" to a visitor and an avatar to a signed-in reader: we use a ternary.
  • An order status with one wording for each of four stages (placed, packed, shipped, delivered): we pick the wording with an if chain into a variable.
