# Brief 2026-10-20-01: Root-First, Trap-First Conversational Principle Boxes

## Why

While reviewing the Principle boxes in `11-argon.md` and `11-gemini.md`, the owner pointed out that the `The Mechanics:` / `The Advice:` paragraphs were stiff and hard to read because they stuffed story-specific code (`const shown = emails.filter(...)`, `{shown.length && rows}`) into the English prose and repeated the code blocks below three times. The owner rewrote Principle 2 directly in chat to show the exact voice and pacing required:

- `**Why it happens:** To show only matching items, run filter() first and then map() over the result. When no items match, the filtered array's length is 0. This can be a trap. If you use conditional rendering { length && list }, the left side cannot be 0 otherwise it will show zero on the screen - yes, the number 0 will appear on your screen! You see, JavaScript stops at 0 and hands that number to React. React happily prints a stray 0 on the screen, whereas it renders nothing for false.`
- `**The Rule:** For conditional rendering prefer length > 0, for example { length > 0 && list } or { length > 0 ? list : <p>Empty</p> }, so an empty list produces false instead of 0.`

When Principle 3 was first drafted in that voice, it jumped into recounting the row-shifting story ("If a user ticks the checkbox on the first row (index 0) and a new item arrives at the top of the list..."). The owner rejected that draft as still too complex and gave the deeper rule: go back to the root mental model that the text itself teaches - the order of the DOM elements on the screen and the order of a variable (an array) in memory are two separate things, and `key` is the chain that links each DOM element on the screen to its object in memory. Once all four Principles of Lecture 11 were rewritten around that root-first, trap-first conversational standard, the owner approved them and asked to update the lessons and copy all four examples into the Revision 3 skills.
