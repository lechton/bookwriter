# Brief 2026-10-10-01: Question, Answer, Then the Rule

## Why

Lectures 17 and 18 were written under skills v7.1 and passed every script, yet the owner's review found problems that no script could see. The principle map split a failure from its fix (map 17 put `queue-in-order` and `updater-from-previous` in two principles), so the lecture showed the bug in one place and the cure in another. Principle boxes used words the lecture never taught (a `setTimeout` side note in Lecture 17 Principle 1). The summary widened a bounded rule ("pass an updater when you change the same state twice in one click") into ALWAYS. One question said "multiple clicks" when the bug comes from one click. Question titles were story labels in Title Case. Scenarios repeated the code line by line in bullets. A `//` comment followed JSX markup, which JSX prints on the page. An ASCII diagram in Lecture 17 showed a repaint that never happens. Lecture 18's Question 1 used `user.details.bio` while its cards used `user.bio`. No blueprint existed for Lecture 18.

The owner's model of a lecture is a chain: a reader's question, an answer on the reader's own code, then a prescriptive principle that states the rule the answer showed. Anything new that a principle needs must already be taught in the introduction (the runway) and recalled briefly where it is used. Algorithmic checks come last, after the reading checks.

The work below changes skills, scripts, and instructions only. Lectures 17 and 18 and the Lecture 17 blueprint were not touched, and no lecture was written.

## Groups

**#2026_10_10_01_group_1, Fix In.** A map principle with a Real Mistake now names, in a `Fix In` field, the principle whose code fixes it, or `this principle` when its own Placement is the fixing code (map 15 `setter-to-screen`). The lecture shows the failure and the fix in one question cycle. `diagnose-map.mjs` fails a missing Fix In and a pointer to a principle that does not exist. Maps 15 to 18 gained the field (15 P1 `this principle`, 16 P1 `compute-next-once`, 17 P2 `updater-from-previous`, 18 P1 `copy-every-level`).

**#2026_10_10_01_group_2, Terms carry ideas.** The map's Terms list names every idea the reader lacks, not only new words, so the blueprint knows what the runway must teach.

**#2026_10_10_01_group_3, the blueprint.** The blueprint is required and must match the lecture. It opens with a recall list (each earlier lesson in a few words, naming the lesson) and a runway (each gap taught before the questions). The free-form `[principle-notes]` tag gives way to one `[question-cycle]` plan per principle with eight lines: Question, Code and result, Verdict, Answer, Fix, Rule with boundary, Needs, Diagram. The PROPER example is map 17 Question 2; the HALF WAY example is the Lecture 17 blueprint, whose Principle 3 boundary was lost on the way to the lecture. Comments in blueprint code are judged by what they say, not by a word count.

**#2026_10_10_01_group_4, reading gates first.** Pre-lecture Section 19 and verification Section 21 list the reading gates first and the mechanical gates last. The completion report gives one line per reading gate, naming what was found and fixed, before any script output. `diagnose-lecture.mjs` prints its content checks first and its mechanical metrics last. The 20-word sentence count is now a pointer to reread, not a ceiling.

**#2026_10_10_01_group_5, the question cycle in the lecture.** The lecture skeleton (lecture-structure Section 07) opens with the recall list and the runway, then one question cycle per principle in this order: `### Question N: {plain sentence}`, the scenario in prose and code, the bold question, `---`, `**ANSWER**`, the verdict starting with `**The code`, the answer, the fix, an ASCII diagram where the order of events matters, and the box. Scenarios do not echo the code in bullets; counts are true; the summary keeps each rule's boundary. `diagnose-lecture.mjs` Invariant 11 checks the cycles against the map: count, order, heading form, bold question, `---`, `**ANSWER**`, a verdict that agrees with the map's Real Mistake, and exactly one box with the same number. It is required from Lecture 19 on; older lectures are checked only if they already have Question headings. The documented closing order (Where you will meet this and For the interview after the practical example) stays; Lecture 17 deviates from it.

**#2026_10_10_01_group_6, the answer before the box.** `principled-theory` was rewritten: the runway, then the answer that does what the paragraph under the box used to do. `principle-definition` adds "A rule the reader can follow" (prescriptive, boundary kept) and "Nothing the cycle did not show". Story names stay in the question and answer; the box uses general names. When Fix In points at a principle, its right card is the fix. A side note explains only a word the box uses; `diagnose-lecture.mjs` Invariant 13 fails a side note for a word the box never uses and flags one whose word first appears in the box.

**#2026_10_10_01_group_7, the reader's code is the picture.** Lecture-voice Section 04 drops outside metaphors (the waiter, newsroom, hallway, and photograph examples) in favor of the reader's own code and ASCII diagrams. Section 06 sets readability as the sentence standard. Section 07 asks that a name get its role on first mention and that the noun be repeated when "it" could point at two things. The interview's third beat explains without an analogy.

**#2026_10_10_01_group_8, comments.** A comment says what the reader cannot see in the line (the value at that moment, the reason). A comment after JSX markup is written `{/* ... */}`, because JSX prints `//` on the page. `diagnose-lecture.mjs` Invariant 12 fails a `//` comment after a closing `>` in JSX code and in principle cards.

## What the scripts now report on existing lectures

Invariants 12 and 13 apply to every lecture, so older lectures now report failures they always had: `//` comments after JSX markup in every one of Lectures 01 to 18 (in code windows and principle cards alike), and side notes for words the box does not use in Lectures 01, 06, 09, 10, 11, 13, and 17. Lectures 17 and 18 also fail Invariant 11, since they already use Question headings but ask their question inside the prose rather than on a bold line. The build does not call `diagnose-lecture.mjs`, so none of this blocks a build. These are findings for a later revision, not regressions.
