# Brief 2026-10-15-05: One File Is a Choice for Learning

## Why

The owner asked whether the lessons tell the reader that one large `App.jsx` holding every component is a choice for the lesson, not how real apps are built. Lecture 2 said that every component lives in `App.jsx` and that Lecture 8 splits them, but not that this was a choice or how real apps differ. Lecture 3 only said "Every component lives in `App.jsx`". No skill asked for the explanation.

The explanation has to be accurate in both directions. react.dev's "Your First Component" says that you can keep multiple components in the same file, which is convenient when they are small or tightly related, and that a crowded file can be split. So one file is not wrong. A whole page of main components in one file is what real apps avoid, and the series uses it only because `import` and `export` come in Lecture 8 (bank Q08).

## Group 1: One File Is a Choice for Learning (#2026_10_15_05_group_1)

- `lecture-structure` Section 12: a lesson that keeps several components in one file before Lecture 8 says once, in its project section, what React allows, what a real app usually does, why this lesson differs, and where the split is taught. It has one proper example (Lecture 2's paragraph, and the short form a later lesson uses) and two counter-examples: Lecture 3's old sentence, which says nothing, and an overcorrection that calls one file bad practice.
- `pre-lecture`: the blueprint plans those sentences in the project `[p]`.

## Applied

- Lecture 2 and its blueprint: the project paragraph now has the full explanation, and the files panel row reads "Every component this lesson writes, in one file until Lecture 8". The answer to "Can several components live in one file?" adds that real apps keep small, related components together, while each main component usually gets its own file.
- Lecture 3 and its blueprint: two sentences in the project paragraph, and the same files panel row.

Lectures 4 to 7 will apply the rule when they are written.
