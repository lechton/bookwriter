# Brief 2026-10-20-02: Question Bank Version 4 Release (Pedagogical Dependency Order for Q01 to Q47 and Plain Hooks)

## Overview & Metadata

- **Date**: 2026-10-20
- **Status**: Released as Version 4 in `projects/react-09/questions/questions.md`.
- **Archived**: `projects/react-09/questions/archive/questions-v3.md` and `projects/react-09/questions/archive/topics-v3.md`.
- **Trigger**: Version 3 artificially froze rows 1 to 28 (`brief_2026_10_05_02.md`), leaving five major pedagogical dependency inversions in the early lessons:
  1. `#component_anatomy` (old Q02) was taught before `#jsx` (old Q03) and `#jsx_expressions` (old Q04), forcing learners to write component returns and compare `<ArticleCard />` tags against `{ArticleCard()}` calls before knowing JSX syntax or `{}` expressions.
  2. `#imports` (old Q08) and `#create_root` (old Q09) were delayed until after `#ui_tree`, `#props`, and `#children`, forcing multi-component examples in Q02 to Q07 to cram parent and child component declarations into a single `App.jsx` file.
  3. `#rendering_lists` (old Q11) and `#purity` (old Q12) were placed before `#event_handling` (old Q13) and `#use_state` (old Q14). Because state and events did not exist yet, both lessons had to fake re-renders and list changes by editing source files in VS Code and relying on Vite HMR saves.
  4. `#event_handling` (old Q13) crammed child-to-parent callback props (`onSelect`) into basic DOM event handling before `useState` existed (forcing parent handlers to call `window.alert()`), while the standalone `#callback_props` question sat stranded in `❱❱ MORE` at Q47.
  5. Lingering newsroom vocabulary ("The National Times masthead", "StoryCard", "tonight's story list") remained in the Hook column of `questions.md`, deferred to Version 4 by `brief_2026_10_15_07.md`.

## Key Pedagogical Improvements in Version 4

1. **Syntax & Expressions Before Component Anatomy (Q02 & Q03 before Q04)**:
   - `#jsx` moves from Q03 to **Q02**, and `#jsx_expressions` moves from Q04 to **Q03**.
   - `#component_anatomy` moves from Q02 to **Q04**, where its question and hook explicitly establish defining a standalone `PascalCase` component and rendering a child component inside a parent component as a JSX tag (`<ArticleCard />`) rather than a direct function call (`{ArticleCard()}`).
   - The re-render DOM/state destruction proof for declaring a component inside another component moves to **Q25 (`#component_identity`)**, where component identity and state preservation across re-renders are taught.
2. **Modules & Mounting Before Props (Q05 to Q07 before Q08)**:
   - `#imports` moves from Q08 to **Q05**, `#ui_tree` moves from Q05 to **Q06**, and `#create_root` moves from Q09 to **Q07**.
   - From Q05 onward, parent (`App.jsx`) and child (`ArticleCard.jsx`) components live in separate files. At Q06 (`#ui_tree`), the learner sees both the Component Tree and the Module Dependency Tree together, followed by mounting the root tree in `main.jsx` at Q07 (`#create_root`).
   - `#props` (**Q08**), `#children` (**Q09**), and `#conditional_rendering` (**Q10**) then flow down a real, mounted multi-file component tree.
3. **Events, State, and the Render Cycle Before Purity and Dynamic Lists (Q11 to Q18)**:
   - `#event_handling` moves from Q13 to **Q11** and focuses purely on DOM events (`onClick`, `onSubmit`, `e.preventDefault()`, `e.stopPropagation()`).
   - `#use_state` moves from Q14 to **Q12**, followed immediately by `#render_and_commit` at **Q13**.
   - `#purity` moves from Q12 to **Q14** (after Events, `useState`, and Render & Commit), so pure rendering, side effects in event handlers, and `<StrictMode>` double-rendering are proven with real state re-renders instead of file saves.
   - `#state_snapshots` (**Q15**), `#state_updates` (**Q16**), and `#state_objects` (**Q17**) follow in sequence.
   - `#rendering_lists` moves from Q11 to **Q18** (directly before `#state_arrays` at **Q19**), so rendering arrays with `.map()`, filtering, `key={item.id}`, and why `key={index}` scrambles DOM state when list order changes are taught with real interactive state.
4. **Callback Props Restored to CORE Before Lifting State (Q23 before Q24)**:
   - `#callback_props` moves from Q47 (`❱❱ MORE`) to **Q23 (`❱ CORE`)**, directly before `#lifting_state` (**Q24**).
   - Learners first master how a child component notifies its parent via a callback prop (`onSelect`, `onDelete`) to update parent state (Q23), and then combine downward props and upward callback props to share state between sibling components in `#lifting_state` (Q24).
5. **1-to-1 Permutation of Q01 to Q18 and Unchanged Numbers from Q48 to Q180**:
   - Rows **1 to 18** are an exact 1-to-1 permutation of old rows 1 to 18.
   - Rows **19 to 22** (`#state_arrays`, `#controlled_inputs`, `#reacting_to_input`, `#state_structure`) keep their exact numbers.
   - Rows **23 to 47** shift by +1 as `#callback_props` moves from Q47 to Q23 (`❱ CORE` now spans Q1 to Q42; `❱❱ MORE` spans Q43 to Q75).
   - Rows **48 to 180** (133 questions, including all of ADVANCED, LEGACY, and all 80 React Server questions) keep their exact numbers unchanged.
6. **Plain Hooks (`brief_2026_10_15_07.md`)**:
   - All newsroom vocabulary in the Hook column ("The National Times masthead", "tonight's story list", "StoryCard", "About the paper") is replaced with plain website terms ("the site header", "the article list", "ArticleCard", "the About page").
