# Brief 2026-10-15-10: Direct Working Lecture Targeting for Phase 2 Code Comment Audits

## Why

Previously, `#2026_10_04_10_group_1` required the on-demand Phase 2 code comment audit (`code-comment-audit/SKILL.md`) to apply exclusively to `02-01-md-revised/<version>/{NN}.md` and demanded that working lectures in `01-02-md-LECTURES/` remain token-free. This caused immediate pipeline divergence: standard PDF generation (`01-04-md-lectures-PDF/<version>/{NN}.pdf`) compiled from `01-02-md-LECTURES/` showed zero target underlines and unaligned speech bubble pointer tails, while the user expected to inspect the primary lecture PDF.

## Group 1: Working Lecture Code Comment Audit Rule (#2026_10_15_10_group_1)

The code comment audit workflow in React 08 is clarified to ensure standard builds directly reflect calibrated token anchors:

1. **Direct Working Lecture Application**:
   - The on-demand Phase 2 code comment audit pass (`code-comment-audit`) applies target token tildes (`~token~`) and speech bubble calibrations directly to the active working lecture in `01-02-md-LECTURES/<version>/{NN}.md`.
   - Initial drafting (Phase 1) remains pure code with natural comments and zero tildes to conserve cognitive focus for pedagogical structure and storytelling.

2. **Standard Build Output Alignment**:
   - Compiling the working lecture (`node src/build-lectures.mjs {NN}`) produces HTML in `01-03-md-lectures-HTML/` and PDF in `01-04-md-lectures-PDF/` with full token styling (`.token-target`, dotted underlines) and calibrated speech bubble pointer tails (`--token-offset`).
   - If a revised pedagogical copy is maintained in `02-01-md-revised/<version>/`, the audited changes are synchronized to it so both output streams remain aligned.

3. **Mechanical Verification Command**:
   - Algorithmic audit verification runs via `node src/diagnose-lecture.mjs {NN} --audit` on the working lecture (or with `--revised` on the revised copy).
