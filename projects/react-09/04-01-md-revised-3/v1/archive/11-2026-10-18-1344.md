# React Rendering Lists

## Two different ways to render one card per article

A page often shows many items of the same kind: articles, comments, products. Each item appears with the same markup, and only its data differs. There are two ways to get one card per article:

```tree caption="Two ways to get one card per article: write each tag by hand, or draw the cards from the array."
Two different ways to render one card per article
- Fixed: written by hand | one tag per article, typed into the JSX
- Dynamic: rendering a list from an **array** | one tag, repeated for every article in the array
```

> [!FACT] An array keeps its values in order and counts them from 0. In `articles`, an array of article objects, `articles[0]` is the first article, `articles[1]` the second, and `articles[2]` the third.

We compare the two ways inside a component's `return`. `ArticleCard` draws one card from the article it receives. With three articles in `articles`, both ways show the same three cards. Then we add a fourth article at the end of the array, and only one page shows it:

::: row caption="The array with a fourth article added at the end. Compare the two pages."
::: col title="Fixed: written by hand" tone=bad
```page size=mini
card: title=New Park Opens Today
card: title=Rain Expected This Weekend
card: title=Five Soups for Cold Days
```
```jsx
<main>
  <ArticleCard article={articles[0]} /> {/* One tag per article */}
  <ArticleCard article={articles[1]} />
  <ArticleCard article={articles[2]} />
</main>
```
With four articles in the array, the page still shows three cards. The fourth article needs a fourth tag in the component.
:::
::: col title="Dynamic: from the array" tone=good
```page size=mini
card: title=New Park Opens Today
card: title=Rain Expected This Weekend
card: title=Five Soups for Cold Days
card: title=Library Opens on Sundays | good=title
```
```jsx
<main>
  {articles.map(article => ( /* One tag for every article */
    <ArticleCard article={article} />
  ))}
</main>
```
With four articles in the array, the page shows four cards, from one tag. Principle 1 explains how `map()` works.
:::
:::

Why does the difference matter? By hand, the component must know how many articles exist and in what order, so every new article is a change to the code. From the array, a new article is one more object in the data, with no change to any component. The same component can also show only the articles it is asked for, such as the articles of one topic, as Principle 2 shows. So by hand fits only a few items that never change, such as two links in a footer. Every list that comes from data is drawn from the data.

> [!FACT] Each JSX tag, such as `<ArticleCard />`, makes a React element: React's description of what to show, not yet the card on the page. From each element, React builds the real card on the page.

Drawing the cards from the array is **rendering a list**. An array of data becomes an array of elements, one per item, and React shows them in order. Each element also gets a key, which keeps each card with its own article when the list changes.

## Rendering a list: four steps in two pairs

Rendering a list takes four steps, in two pairs. The first pair creates the cards from the array. The second updates the cards correctly when the list changes, so each card stays with its own article:

```tree caption="The four steps of rendering a list: first create the cards, then update them correctly when the list changes."
Dynamic: rendering a list from an array
- Create the cards | from the array to the page
  - Cards for every article | `map()`
  - Cards for only some articles | `filter()`, then `map()`
- Update the cards when the list changes | each card stays with its article
  - Key from the article's id | not from its position
  - Key on the tag `map()` returns | not inside the card
```

We take the steps in this order because each one needs the one before it. `map()` comes first, because every later step works on the array it gives back. `filter()` runs before `map()`, so it needs `map()` in hand. The key names the elements that `map()` makes, so it comes after them. Where the key goes makes sense only once we know what the key does.

::: pagebreak

# Principles

## 1. Cards for every article: map()

*How? `map()` gives back one element per article, in a new array*

```tree size=mini here="Cards for every article"
Dynamic: rendering a list from an array
- Create the cards
  - Cards for every article
  - Cards for only some articles
- Update the cards when the list changes
  - Key from the article's id
  - Key on the tag `map()` returns
```

> [!FACT] An **arrow function** is a short way to write a function: the parameter, then `=>`, then what it gives back. `article => article.title` takes an article and gives back its title.

> [!FACT] **`forEach()`** calls a function once for each item of an array and gives back `undefined`. **`map()`** calls a function once for each item and collects what the function gives back into a new array, with one entry per item. It passes each item to the function as its parameter: in `article => ...`, the name `article`, which we choose, holds the park article on the first call, the rain article on the second, and so on.

> [!PRINCIPLE]
> **Principle 1: Cards for every article: `map()`**
>
> To show one element per item, we call `map()` on the array inside the JSX.
>
> The arrow function can give back the element directly, inside parentheses `( )`. Or it can use curly braces `{ }`, and then it needs an explicit `return`. Notice: a missing `return` is easy to overlook.
>
> *We should do this:*
>
> ```jsx
> function ArticleList() {
>   return (
>     <main>
>       {articles.map(article => ( /* Parentheses: the card is given back */
>         <ArticleCard article={article} />
>       ))}
>     </main>
>   );
> }
> ```
>
> *We should not do this:*
>
> ```jsx
> function ArticleList() {
>   return (
>     <main>
>       {articles.map(article => { // **PROBLEMATIC:** curly braces open a body with no return
>         <ArticleCard article={article} />; // Never given back: no card
>       })}
>     </main>
>   );
> }
> ```

### Example: let's open curly braces after the arrow (every call gives back undefined!)

Here, curly braces after the arrow make every call of the function give back `undefined`, so no card appears. Nothing warns us: the page shows no card, and the Console shows no message. A developer often adds the braces to make room for a second line later, and the cards vanish with no clue.

We want one card per article. The articles live in their own file, `articles.js`, as one array of objects. Each object has an `id`, a number that belongs to that article and to no other, then its title, its author, and its topic:

```js title="articles.js"
export const articles = [ // One object per article
  { id: 1, title: 'New Park Opens Today', author: 'Mary Jones', topic: 'City' },
  { id: 2, title: 'Rain Expected This Weekend', author: 'Oliver Brooks', topic: 'Weather' },
  { id: 3, title: 'Five Soups for Cold Days', author: 'Samantha Robinson', topic: 'Food' },
];
```

The parent, `ArticleList.jsx`, imports the array and places one card per article. The child, `ArticleCard.jsx`, draws one card, with a box where a reader can write a comment. Both live in `src/components/`, so `ArticleList` imports the array from one folder up. A `for` loop cannot go inside JSX braces, because it is a statement, and braces take only an expression. So we call `map()`, and open curly braces after the arrow:

```jsx title="ArticleList.jsx" bad="7-9" role=PARENT
import { articles } from '../articles.js'; // The data, one folder up
import ArticleCard from './ArticleCard.jsx';

export default function ArticleList() {
  return (
    <main>
      {articles.map(article => { // **PROBLEMATIC:** curly braces open a body with no return
        <ArticleCard article={article} />;
      })}
    </main>
  );
}
```

```jsx title="ArticleCard.jsx" role=CHILD
export default function ArticleCard({ article }) {
  return (
    <article className="card">
      <h2>{article.title}</h2>
      <p className="author">By {article.author}</p>
      <input placeholder="Write a comment" /> {/* What a reader types stays here */}
    </article>
  );
}
```

### Why does every call give back `undefined`?

> [!FACT] When a curly brace follows `=>`, the function has a **block body**: it gives back only what a `return` inside it names, and without `return` it gives back `undefined`. With parentheses, or nothing, after `=>`, the function gives back that expression by itself.

`map()` collects what the function gives back for each article, and the bracket after the arrow decides what that is. With parentheses, the arrow function gives back the element. With curly braces and no `return`, it gives back `undefined`. `forEach()` fails too, for another reason: it gives back `undefined` whatever its function does. What each version gives back for the three articles, and so what the page shows:

```chain caption="What each version gives back for the three articles, and so what the page shows."
!`articles.forEach(...)` -> `undefined` -> nothing to place: no cards
!`articles.map(article => { <ArticleCard />; })` -> `[undefined, undefined, undefined]` -> no cards
+`articles.map(article => <ArticleCard />)` -> `[<ArticleCard>, <ArticleCard>, <ArticleCard>]` -> three cards
```

We write the parentheses in `ArticleList.jsx`, so the arrow gives back each card:

```jsx title="ArticleList.jsx" good="7-9" role=PARENT
import { articles } from '../articles.js';
import ArticleCard from './ArticleCard.jsx';

export default function ArticleList() {
  return (
    <main>
      {articles.map(article => ( /* Parentheses: the card is given back */
        <ArticleCard article={article} />
      ))}
    </main>
  );
}
```

Writing `return <ArticleCard article={article} />;` inside curly braces works the same way. With a fourth article in `articles.js`, this same line gives four cards.

### What turns an array into elements

With all the ways tried inside the JSX braces side by side:

```tree dir=right caption="Every way tried inside JSX braces to turn an array into elements, and what each gives back."

## 2. Cards for only some articles: filter(), then map()

*When? A section shows only its topic's articles, and a topic can have none*

```tree size=mini here="Cards for only some articles"
Dynamic: rendering a list from an array
- Create the cards
  - Cards for every article
  - Cards for only some articles
- Update the cards when the list changes
  - Key from the article's id
  - Key on the tag `map()` returns
```

> [!FACT] **`filter()`** calls a function for each item and gives back a new array of only the items for which the function gave back `true`. An array's **`length`** is its number of items; an empty array has a length of `0`.

> [!PRINCIPLE]
> **Principle 2: Cards for only some articles: `filter()`, then `map()`**
>
> To show only some items, we call `filter()` before `map()`. It keeps only the items that pass a test.
>
> When no item passes, the array is empty, and its length is `0`. Then we show a message, with `length > 0` and the ternary. Notice: a bare `length` on the left of `&&` puts a `0` on the page instead.
>
> *We should do this:*
>
> ```jsx
> function ArticleList({ topic }) {
>   const shown = articles.filter(article => article.topic === topic);
>   const cards = shown.map(article => <ArticleCard article={article} />);
>   return (
>     <section>
>       <h2>{topic}</h2>
>       {shown.length > 0 ? cards : <p>None yet.</p>} {/* No articles: the message */}
>     </section>
>   );
> }
> ```
>
> *We should not do this:*
>
> ```jsx
> function ArticleList({ topic }) {
>   const shown = articles.filter(article => article.topic === topic);
>   const cards = shown.map(article => <ArticleCard article={article} />);
>   return (
>     <section>
>       <h2>{topic}</h2>
>       {shown.length && cards} {/* **PROBLEMATIC:** a bare length shows 0 */}
>     </section>
>   );
> }
> ```

### Example: let's put a bare length left of && (React shows the 0!)

Here, a bare length left of `&&` puts a 0 on the page. For a topic with no articles, `filter()` gives back an empty array, and its length is `0`. `&&` gives back that `0`, and React shows a number as text. Every topic page and every search result can meet an empty list, and the 0 reaches the page with no error.

We want one section per topic, each with only the articles of its own topic, and a message when a topic has none. To keep the example small, the parent, `App.jsx`, places two sections, City and Sport, and passes each its topic. The child, `ArticleList.jsx`, keeps the topic's articles with `filter()`, turns them into cards with `map()`, and stores the cards in a variable, `cards`. Of the three articles, only the park article is City, and none is Sport. We use `&&`, the usual way to show a piece or nothing:

```jsx title="App.jsx" role=PARENT
import ArticleList from './components/ArticleList.jsx'; // Our component, from its own file

export default function App() {
  return (
    <main>
      <ArticleList topic="City" /> {/* One article: the park */}
      <ArticleList topic="Sport" /> {/* No article at all */}
    </main>
  );
}
```

```jsx title="ArticleList.jsx" bad="10" role=CHILD
import { articles } from '../articles.js';
import ArticleCard from './ArticleCard.jsx';

export default function ArticleList({ topic }) {
  const shown = articles.filter(article => article.topic === topic); // This topic's articles
  const cards = shown.map(article => <ArticleCard article={article} />);
  return (
    <section>
      <h2>{topic}</h2>
      {shown.length && cards} {/* **PROBLEMATIC:** a bare length shows 0 */}
    </section>
  );
}
```

`ArticleCard.jsx` stays as it was.

### Why does a 0 appear?

> [!FACT] `a && b` gives back `a` when `a` counts as false in a condition, as `0`, `false`, and `null` do, and `b` otherwise. In JSX, React shows nothing for `false` or `null`, but it shows a number as text. A comparison such as `shown.length > 0` always gives a real `true` or `false`, and the ternary `condition ? a : b` gives `a` when the condition is true and `b` otherwise.

`&&` gives back one of its two sides, and React shows whatever it gets back. With the `&&` version and the three articles, what each step gives back for each section:

| section | `filter()` gives back | `shown.length` | `shown.length && cards` gives back | the page shows |
| --- | --- | --- | --- | --- |
| City | `[park]` | `1` | `cards`, one card | the park card |
| !Sport | `[]` | `0` | `0` | a bare 0 |

So the line in the section is `{shown.length > 0 ? cards : <p>None yet.</p>}`. The comparison gives a real `false` for Sport, and the ternary shows the message. `filter()` runs before `map()`, so `map()` turns only the kept articles into cards.

## 3. Key from the article's id, not its position

*Why? React matches each card by its key when the list changes*

```tree size=mini here="Key from the article's id"
Dynamic: rendering a list from an array
- Create the cards
  - Cards for every article
  - Cards for only some articles
- Update the cards when the list changes
  - Key from the article's id
  - Key on the tag `map()` returns
```

> [!FACT] A **key** is an attribute React reserves, written on each element of a list: `key={article.id}`. `map()` also passes each item's position to the function, as a second parameter: `items.map((item, index) => ...)`, where `index` is 0 for the first item; with two parameters, they go in parentheses.

> [!PRINCIPLE]
> **Principle 3: Key from the article's id, not its position**
>
> We give each element a `key`, taken from the item's own id. With the key, React matches each item with the same card the next time the list is shown.
>
> The array index works only for a list whose positions never change: items are only added or removed at the end, and never sorted or moved. A key made while rendering, such as a random number, never works.
>
> *We should do this:*
>
> ```jsx
> function ArticleList() {
>   return (
>     <main>
>       {articles.map(article => (
>         <ArticleCard key={article.id} article={article} /> // The key follows the article
>       ))}
>     </main>
>   );
> }
> ```
>
> *We should not do this:*
>
> ```jsx
> function ArticleList() {
>   return (
>     <main>
>       {articles.map((article, index) => (
>         <ArticleCard key={index} article={article} /> // **PROBLEMATIC:** the index is the position
>       ))}
>     </main>
>   );
> }
> ```

### Example: let's add an article at the top with no key (the comment moves to another card!)

Here, a comment typed under one article moves to another card when a new article arrives at the top of the list. The cards show fine without a key, so the key looks like a way to quiet the Console. But with no key, React matches each card by its position. A card that holds nothing of its own hides the mistake, which is why many lists seem fine without keys. It shows as soon as a card holds something, such as typed text or a checked box.

We want a comment typed under the rain article to stay under the rain article. We go back to the single list of all three articles. The parent, `ArticleList.jsx`, places the cards with no key. The child, `ArticleCard.jsx`, holds the comment box. A reader types "Great news!" into the comment box of the rain card, the second card. Then we add a new article, Library Opens on Sundays, at the top of `articles.js`, and save the file:

### Why does the comment move to another card?

When a list is shown again, React matches each new element with a card it already built. It keeps that built card, and changes only what differs, such as the title. With no key, it matches by position: the first element with the first built card, the second with the second. The new article pushed every article down one place. So the second built card now receives the park article's title, while the text typed into its box stays where it was.

A key names each element, so React matches by name instead of by position. We write the key on the tag inside `map()`, in `ArticleList.jsx`, from the article's own id:

```jsx title="ArticleList.jsx" good="2"
{articles.map(article => (
  <ArticleCard key={article.id} article={article} /> // Named by the article's id
))}
```

With `key={article.id}`, the rain card is named 2, the rain article's id, and React finds the built card named 2 wherever it now sits:

```chain caption="After the new article arrives at the top: what React keeps for the built card that holds the typed text."
!by position: the 2nd card, holding "Great news!" -> now shows New Park Opens Today
+by key: the card named 2, the rain article's id, holding "Great news!" -> still shows Rain Expected This Weekend
```

So with `key={article.id}`, every article keeps its own built card, and only the new article gets a newly built one. Keys must differ among the items of one array. When two items share a key, React warns that it found two children with the same key, and it cannot tell them apart.

### Which key to choose

The four keys side by side:

```tree dir=right caption="The four keys of the experiment, and what each does after a new article arrives at the top."
Which key?
- +key from the article's id | follows the article: the typed text stays with its article
- !key from the index | is the position: the text moves when an item is added, removed, or moved above it
- !key from Math.random() | new on every render: every card is rebuilt, the text is lost
- !no key | matches by position: the text moves the same way, and the Console warns
```

The index fits a list like a fixed row of tabs built from an array that never changes. Adding an item at the end is safe too, since every position stays as it was. But removing an item anywhere else moves every later item up one place, just as adding one at the top moved them down.

## 4. Key on the tag map() returns, not inside the card

*Why? React reads the key only on the elements `map()` gives back*

```tree size=mini here="Key on the tag `map()` returns"
Dynamic: rendering a list from an array
- Create the cards
  - Cards for every article
  - Cards for only some articles
- Update the cards when the list changes
  - Key from the article's id
  - Key on the tag `map()` returns
```

> [!PRINCIPLE]
> **Principle 4: Key on the tag `map()` returns, not inside the card**
>
> We write the `key` directly on the tag that `map()` gives back. That tag is the item of the list React matches.
>
> A key on a tag inside the child component is not an item of the list, so React does not use it, and the warning stays.
>
> *We should do this:*
>
> ```jsx
> function ArticleList() {
>   return (
>     <main>
>       {articles.map(article => (
>         <ArticleCard key={article.id} article={article} /> // On the tag map() returns
>       ))}
>     </main>
>   );
> }
> ```
>
> *We should not do this:*
>
> ```jsx
> function ArticleList() {
>   return (
>     <main>
>       {articles.map(article => (
>         <ArticleCard article={article} /> // No key on the tag map() returns
>       ))}
>     </main>
>   );
> }
> function ArticleCard({ article }) {
>   return <article key={article.id}>{article.title}</article>; // **PROBLEMATIC:** inside the child
> }
> ```

### Example: let's move the key onto the `<article>` inside the card (React never reads it!)

Here, a key written on the `<article>` inside the card is never read by React, so the Console's warning stays. React reads the key only on the elements `map()` gives back, and those are the `<ArticleCard>` elements. The mistake is tempting, because the Elements panel shows the `<article>` tag once per card. So it looks like the tag that repeats, and the place for the key:

```dom title="Elements panel: the list of three cards"

*  <article class="card">...</article>
*  <article class="card">...</article>
*  <article class="card">...</article>
</main>

We want the key where React looks for it, so the warning goes. `articles.js` is back to its first three articles, without the Library article. The parent, `ArticleList.jsx`, writes `<ArticleCard article={article} />` with no key. We move the key onto the `<article>` inside the child, `ArticleCard.jsx`:

```jsx title="ArticleList.jsx" role=PARENT
import { articles } from '../articles.js';
import ArticleCard from './ArticleCard.jsx';

export default function ArticleList() {
  return (
    <main>
      {articles.map(article => (
        <ArticleCard article={article} /> // No key on the tag map() returns

    </main>
  );
}
```

```jsx title="ArticleCard.jsx" bad="3" role=CHILD
export default function ArticleCard({ article }) {
  return (
    <article key={article.id} className="card"> {/* **PROBLEMATIC:** a key inside the child */}
      <h2>{article.title}</h2>
      <p className="author">By {article.author}</p>
      <input placeholder="Write a comment" />
    </article>

}
```

### Why does React never read the key inside the card?

React looks for the key on the items of the array it receives, and that array holds `<ArticleCard>` elements. The `<article>` inside a card is not an item of any array, so a key there names nothing React matches. When `map()` gives back another tag around the card, the key moves to that outer tag. A list of articles is often marked up as a list, so each card sits in an `<li>` inside a `<ul>`, and the key goes on the `<li>`:

```jsx title="ArticleList.jsx" good="3"
<ul className="articles">
  {articles.map(article => (
    <li key={article.id}> {/* The tag map() returns: the key goes here */}
      <ArticleCard article={article} />
    </li>
  ))}
</ul>
```

### Can the card read its own key?

React keeps the key for itself: the card never receives it as a prop. A card that tries to read it, as in `function ArticleCard({ key, article })`, gets `undefined`, and a warning:

```devconsole caption="Chrome's Console, when ArticleCard reads its key as a prop."
x ArticleCard: `key` is not a prop. Trying to access it will result in `undefined` being returned.
```

Here the card can still read `article.id`, because it receives the whole article. A component that receives only some fields, and needs the id too, gets it as a prop of its own, under another name, such as `<ArticleCard key={article.id} articleId={article.id} title={article.title} />`.

### A key hidden inside a spread object

> [!FACT] A **spread** `{...props}` on a tag passes every field of the object `props` as its own attribute.

A key can also end up hidden inside an object spread onto the tag. This happens when a card's props are first gathered into one object, key included:

```jsx title="ArticleList.jsx" bad="2-3"
{articles.map(article => {
  const props = { key: article.id, article: article }; // **PROBLEMATIC:** the key inside the object
  return <ArticleCard {...props} />;
})}
```

React still reads the key from the spread object, but only as a fallback kept for older code, which a future version of React may drop. It warns, "A props object containing a "key" prop is being spread into JSX". So the key comes out of the object and is written directly on the tag, while the other props can still be spread: `const props = { article: article };` then `<ArticleCard key={article.id} {...props} />`.

### A key on a Fragment

> [!FACT] `<>` and `</>`, a Fragment, group several tags without adding a tag to the page, but take no attributes. The long form, `<Fragment>`, imported with `import { Fragment } from 'react';`, can take a key.

When each item is several tags with no single tag around them, the key goes on a `Fragment`. This is a different, simpler list, with no card component. With the three articles, it gives each title followed by its author, and no warning:

```jsx title="ArticleList.jsx" good="2"
{articles.map(article => (
  <Fragment key={article.id}> {/* Several tags per item: the key goes here */}
    <h2>{article.title}</h2>
    <p>{article.author}</p>
  </Fragment>
))}
```

### Where the key goes

The places a key can be written, side by side:

```tree dir=right caption="The places a key can be written, and what each gives."
Where does the key go?
- +key on the tag map() returns | <ArticleCard key>, or <li key> when the card sits in an <li>
- +key on <Fragment key>, the long form | when each item is several tags; <> takes no key
- !key inside the child | the warning stays: the child's <article> is not an array item
- !key inside a spread object | React still reads it for now, but warns: write key on the tag
```

## Putting the four together

We want one topic section that uses all four steps. It keeps the topic's articles with `filter()` and turns them into cards with `map()`. A list of articles is marked up as a list, so each card sits in an `<li>` inside a `<ul>`, and the key, from the article's id, is on the `<li>`, the tag `map()` gives back. When the topic has no articles, a ternary on `length > 0` shows a message. `App` renders `<ArticleList topic="City" />` and `<ArticleList topic="Sport" />`. With the three articles, City shows the park card, and Sport shows "None yet.":

**DO THIS:**

```jsx right
import { articles } from '../articles.js';
import ArticleCard from './ArticleCard.jsx';

export default function ArticleList({ topic }) {
  const shown = articles.filter(article => article.topic === topic);
  const cards = shown.map(article => (
    <li key={article.id}>
      <ArticleCard article={article} />
    </li>
  ));
  return (
    <section>
      <h2>{topic}</h2>
      {shown.length > 0 ? <ul>{cards}</ul> : <p>None yet.</p>}
    </section>
  );
}
```

Here is the same section with two mistakes, marked in red. It names each item by its index, so a comment typed under one article moves to another when a new article of that topic is added at the top (line 7). And it puts a bare length left of `&&`, so a topic with no articles, such as Sport, shows a bare 0 instead of a message (line 14):

**DO NOT DO THIS:**

```jsx wrong bad="7,14"
import { articles } from '../articles.js';
import ArticleCard from './ArticleCard.jsx';

export default function ArticleList({ topic }) {
  const shown = articles.filter(article => article.topic === topic);
  const cards = shown.map((article, index) => (
    <li key={index}>
      <ArticleCard article={article} />
    </li>
  ));
  return (
    <section>
      <h2>{topic}</h2>
      {shown.length && <ul>{cards}</ul>}
    </section>
  );
}
```

## For the interview

- **How do you render a list from an array?** Keep the data in an array of objects and call `map()` inside the JSX. Its arrow function gives back one element per item, and React shows the array of elements in order. To show only some items, call `filter()` first. When the result can be empty, test its `length` with `> 0` in a ternary: the cards when it is true, a message when it is 0.
- **Why does React need a key?** To match each item with the card it built on the page last time, when the list is shown again. Without a key, React matches by position, so an item added at the top moves typed text to the wrong item.
- **Is `key={index}` fine?** Only for a list whose positions never change: no item is ever inserted or removed anywhere but the end, or moved. The index is the position, so it hides the warning. When a row holds typed text, the text moves to another row as soon as an item is inserted above it or the list is sorted. Lists whose rows hold nothing of their own hide this bug, which is why many tutorials get away with index keys.
- **Why not `key={Math.random()}`?** It changes on every render, so no key matches the last one: every card is built again from scratch, and typed text is lost.
- **Must keys be unique on the whole page?** No, only among the items of one array. Two separate lists can use the same ids.
- **Can the child read its key?** No. React keeps the key, so `key` read as a prop is `undefined`, with a warning. When the child needs the id and does not receive the whole item, pass the id again under another name, such as `articleId`.
- **Where does the key go?** On the tag `map()` gives back: on `<ArticleCard key>` when `map()` returns the card, on the `<li>` when the card sits in one, and on a `<Fragment key={...}>` when each item is several tags with no tag around them. Never inside the child.
- **Why does an empty list with `length &&` show a 0?** For an empty array, `length` is `0`, and `0 && ...` gives back `0`, which React shows as text. Write `length > 0 ? cards : message`, so an empty list shows the message instead of a 0 or an empty space.

## Where you will meet this

- Every list built from data: comments, search results, cart items, messages. Each comes from an array, goes through `map()`, and takes its key from each item's id.
- Data from a server: each record usually arrives with its own id, ready to be its key. When the data has no id, give each item one once, when it is created, and store it with the item; never while rendering. `crypto.randomUUID()`, a browser function that gives back a new unique string on HTTPS pages and on localhost, can make it.
- Rows that hold input, such as quantities in a cart or checkboxes in a to-do list: when the row itself holds what was typed or checked, as the comment box does, index keys or no keys move those entries to other rows. This happens when the list is sorted, or an item is added or deleted anywhere but the end.
- A Console warning about keys: it names the component whose `map()` needs the key, so you know which file to open.

The home page of a small news site groups its articles by topic: City, Weather, Food, and Sport. Each article appears as a card with its title, the author's name, and a box where a reader can write a comment. Here is the page, after a reader has typed a comment under the rain article:

Every card has the same three parts, and only its data differs. Each section shows only the articles of its own topic. The Sport section has no article, so it shows a message instead. | --- | --- | --- |
