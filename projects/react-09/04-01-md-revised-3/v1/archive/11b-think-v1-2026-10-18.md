# Lecture 11: Rendering Lists and Keys
> INTERVIEW QUESTION | ❱ CORE | How do you render a list from an array, and why does React demand a key on every item?

::: pagebreak

::: page tint=blue
::: comic layout=think title="Example: how to delete the wrong email" caption="Here, a tick we put beside one email ends up beside another, and we delete an email we never read. The inbox has no key on its rows. On the left, the page in the browser at each step: Row 1, Row 2, and Row 3 are the DOM elements on the page, and each id comes from an object in the `emails` array. On the right, what the user thinks."
::: panel step=1 title="We tick “Invoice for March”."
```mail table
toolbar: Delete selected
email: Bob Smith | Invoice for March | | checked good pointer id:1
email: Anna Lee | Team meeting moved | | id:2
email: Mom | Photos from the trip | | id:3
```

> [!THINK] OK, let me tick “Invoice for March”, so I can delete it.

Behind the scenes: the tick is saved in the checkbox of Row 1, a DOM element on the page. The `emails` array knows nothing about it.
:::
::: panel step=2 title="A new email arrives at the top of the emails array." tone=bad
```mail table
toolbar: Delete selected
email: Sara Kim | Lunch on Friday? | | checked unread bad id:4
email: Bob Smith | Invoice for March | | id:1
email: Anna Lee | Team meeting moved | | id:2
email: Mom | Photos from the trip | | id:3
```

> [!THINK] Oh, a new email just came in: “Lunch on Friday?”.

> [!THINK] Wait... why is it ticked? I never ticked that one! And my invoice has no tick any more.

Behind the scenes: the objects in the `emails` array moved down one place. The DOM elements on the page did not, so the tick is still in Row 1, which now shows the object with id 4.
:::
::: panel step=3 title="We click Delete selected." tone=bad
```mail table
toolbar: Delete selected | clicked
sent: sent to the server: `delete=4`, the id of “Lunch on Friday?”
email: Sara Kim | Lunch on Friday? | | checked unread bad id:4
email: Bob Smith | Invoice for March | | id:1
email: Anna Lee | Team meeting moved | | id:2
email: Mom | Photos from the trip | | id:3
```

> [!THINK] I didn't notice a thing. Delete!

Behind the scenes: the form sends the id from the ticked checkbox in Row 1: `4`, not `1`.
:::
::: panel step=4 title="After the delete." tone=bad
```mail table
toolbar: Delete selected
email: Sara Kim | Lunch on Friday? | | deleted id:4
email: Bob Smith | Invoice for March | | bad id:1
email: Anna Lee | Team meeting moved | | id:2
email: Mom | Photos from the trip | | id:3
```

> [!THINK] Oh no. “Lunch on Friday?” is gone, and I never even read it.

> [!THINK] And the invoice I wanted to delete is still here!
:::
:::

The tick did not follow the invoice. It stayed in Row 1, a DOM element on the page, and the form sent the id of the object that moved into Row 1. The next part shows why.
