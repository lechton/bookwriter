## Example: how to delete the wrong email

Our inbox shows the same emails in two places. In our code, the emails are an array of objects, `emails`. On the page, the same emails are a list of DOM elements, one per email. These are two different lists. So when the order of one list changes, the order of the other does not follow, and we may click in one DOM element while the code thinks we mean a different object in the array.

```twolists
left: The `emails` array of objects, in our code
{ id: 1, subject: '🔥 FLASH SALE: Extra 15% off' }
{ id: 2, subject: 'Team meeting moved' }
{ id: 3, subject: 'Photos from the trip' }
right: The list of DOM elements, on the page
🔥 FLASH SALE: Extra 15% off
Team meeting moved
Photos from the trip
note: Without a key, the two lists are connected only by their order: the first object goes with the first DOM element, the second with the second, and so on.
```

```mail table

```

> [!THINK] OK, another spam mail. Let me tick “🔥 FLASH SALE: Extra 15% off”, so I can delete it.

Behind the scenes: the tick is saved in the checkbox of the first DOM element on the page, not in the `emails` array. Without a key, the first DOM element is linked to the first object in the array only because both are first.
:::
::: panel step=2 title="A new email arrives at the top of the emails array." tone=bad
```mail table
toolbar: Delete selected
email: Sara Kim | Lunch on Friday? | | checked unread bad id:4
email: ShopNow | 🔥 FLASH SALE: Extra 15% off | | id:1
email: Anna Lee | Team meeting moved | | id:2
email: Mom | Photos from the trip | | id:3
```

> [!THINK] Oh, a new email just came in: “Lunch on Friday?”.

> [!THINK] Wait... why is it ticked? I never ticked that one! And the spam mail has no tick any more.

Behind the scenes: every object in the `emails` array moved down one place. The DOM elements on the page did not move. So the first DOM element keeps its tick, and it now shows the new first object in the array: “Lunch on Friday?”.
:::
::: panel step=3 title="We click Delete selected." tone=bad
```mail table
toolbar: Delete selected | clicked
sent: sent to the server: `delete=4`, the id of “Lunch on Friday?”
email: Sara Kim | Lunch on Friday? | | checked unread id:4
email: ShopNow | 🔥 FLASH SALE: Extra 15% off | | id:1
email: Anna Lee | Team meeting moved | | id:2
email: Mom | Photos from the trip | | id:3
```

> [!THINK] Delete.

Behind the scenes: the tick is in the first DOM element, and the first object in the array is now “Lunch on Friday?”. So the form sends its id, `4`. We meant the spam mail, but the code understands the lunch email.
:::
::: panel step=4 title="After the delete." tone=bad
```mail table
toolbar: Delete selected
email: Sara Kim | Lunch on Friday? | | deleted id:4
email: ShopNow | 🔥 FLASH SALE: Extra 15% off | | bad id:1
email: Anna Lee | Team meeting moved | | id:2
email: Mom | Photos from the trip | | id:3
```

> [!THINK] Oh no. “Lunch on Friday?” is gone, and I never even read it.

> [!THINK] And the spam mail I wanted to delete is still here!

Behind the scenes: the array changed, and the ticked DOM element did not follow its email. The two lists were connected only by their order.
:::
:::

Without a key, the `emails` array and the list of DOM elements are connected only by their order. When the order of the array changes, the DOM elements do not follow, so a click in one DOM element can reach a different object in the array. A key made from each email's id connects each DOM element to its own object in the array, whatever the order. The next part shows how.
