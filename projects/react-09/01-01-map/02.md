# Q02: JSX Syntax and the Single-Root Rule
* **Topic Tag**: `#jsx` | `❱ CORE`
* **Interview Question**: *What is JSX, what syntax rules must every snippet follow, and how do Fragments group elements without wrapper nodes?*
* **Core Truth**: JSX is a JavaScript syntax extension that compiles into nested `_jsx` function calls; every component must return a single root element because JavaScript functions cannot return multiple values without an enclosing container.
* **The Friction**: Pasting raw HTML into a component triggers fatal compiler errors: unclosed tags crash the parser, adjacent tags trigger syntax errors, and wrapping everything in redundant `<div>` tags pollutes the DOM tree and destroys flexbox and grid layouts.
* **The Mechanism**: Strict JSX closure rules, camelCase attributes (`className`, `htmlFor`), and React Fragments (`<React.Fragment>` or `<>...</>`) to group sibling elements without creating DOM wrapper nodes.
* **Under the Hood**: Why JavaScript functions cannot return multiple expressions (`return a, b` returns only b), and how Fragments compile into virtual container objects that React unpacks directly into the parent DOM container.
* **The Code Experiment**:
  * *Naive*: Returning adjacent `<h1>` and `<p>` elements without a root, or wrapping them in five redundant styling divs.
  * *React*: Clean `<>...</>` Fragment enclosing siblings, producing a pristine flat DOM layout.
* **Scope Boundary**: Focus strictly on JSX grammar, compiler transforms to `_jsx()`, single-root rationale, and Fragment containers. Do not introduce dynamic curly brace expressions or props.
