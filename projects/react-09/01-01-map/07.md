# Q07: Mounting the Root Component with createRoot and Vite Tooling
* **Topic Tag**: `#create_root` | `❱ CORE`
* **Interview Question**: *How does your root component attach to the browser DOM with createRoot, and how do build tools assemble it?*
* **Core Truth**: React requires an explicit mounting bridge to bind virtual DOM element trees to a physical HTML container; `createRoot` initializes a concurrent root container, and build tools (like Vite) bundle modern JSX into browser-compatible modules.
* **The Friction**: A newcomer writes modular React components but does not understand how they appear in the browser window. Looking at `index.html`, there is only an empty `<div id="root"></div>`. Trying to link component files directly via traditional `<script src="App.jsx">` fails immediately with syntax errors.
* **The Mechanism**: The mounting pipeline: `index.html` loads `main.jsx` as a module; `createRoot(document.getElementById('root'))` creates the React root; `root.render(<App />)` mounts the virtual tree into the physical DOM.
* **Under the Hood**: Why React separates core reconciler logic (`react`) from DOM mounting targets (`react-dom/client`); how `createRoot` prepares concurrent rendering queues compared to legacy `ReactDOM.render`.
* **The Code Experiment**:
  * *Naive*: Opening a raw `.jsx` file directly in Chrome via `file://`, or calling legacy `ReactDOM.render`.
  * *React*: Modern Vite scaffolding: `index.html` referencing `<script type="module" src="/src/main.jsx">`, which calls `createRoot(rootElement).render(<App />)`.
* **Scope Boundary**: Focus on the browser attachment bridge, the role of `index.html`, `main.jsx`, `createRoot`, and build tool dev servers. Do not write full-stack server rendering or routing logic.
