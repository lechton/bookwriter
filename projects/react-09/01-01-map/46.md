# Q46: Choosing a Framework or a Build Tool
* **Topic Tag**: `#project_setup` | `❱❱ MORE`
* **Interview Question**: *How do you choose between a full-stack framework and a standalone build tool?*
* **Core Truth**: React is a library for building UI, not a complete application platform; a full-stack framework (Next.js App Router, React Router in framework mode, Expo for native apps) supplies routing, data loading, code splitting, and server or build-time rendering as one integrated system, while a build tool (Vite, Parcel, Rsbuild) supplies only JSX transformation, bundling, and a dev server, leaving every one of those decisions to our own code.
* **The Friction**: A team scaffolds a public site that lists articles as a client-only Vite single-page app. Months later, link previews in chat and social apps show no title because their crawlers read only the empty `<div id="root">` HTML, the first article paint waits for a large bundle plus a fetch inside `useEffect`, and the team is hand-building routing, code splitting, and server rendering. Another team picks Next.js for an internal dashboard behind a login that never needs server rendering, and pays for a server deployment it did not need.
* **The Mechanism**: React's official recommendation: start a new app with a framework (`npx create-next-app@latest`, `npx create-react-router@latest`, `npx create-expo-app@latest`); build from scratch with a build tool (`npm create vite@latest`) when the app is client-only, is embedded in an existing page, or the team deliberately wants to own routing and data fetching. Create React App was deprecated in February 2025 and is not a choice for new projects.
* **Under the Hood**: What each layer owns: the build tool transforms JSX, bundles modules, and serves files in development; the framework adds a router, route-level data loading that runs before the route renders, automatic code splitting per route, and rendering on the server or at build time, which sends finished HTML and removes the request waterfall of fetching inside client effects after the bundle loads.
* **The Code Experiment**:
  * *Naive*: A public article site built as a client-only SPA that fetches each article in `useEffect` after the bundle loads, producing an empty HTML shell for link-preview crawlers and a loading spinner for every reader.
  * *React*: The same site started with a framework, where the article route loads its article before rendering and the server sends finished HTML; contrasted with a client-only internal analytics dashboard where Vite alone is the simpler, correct choice.
* **Scope Boundary**: Focus on the decision criteria between a framework and a build tool, what each one provides, and the deprecation of Create React App. Do not teach Server Components, Server Functions, or streaming (Q101+), and do not repeat the `createRoot` mounting covered in Q9.
