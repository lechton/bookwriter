# Q15: State as a Snapshot
* **Topic Tag**: `#state_snapshots` | `❱ CORE`
* **Interview Question**: *Why does state appear frozen inside a render, even right after you set it?*
* **Core Truth**: A state variable holds one fixed value for the whole of one render: setting state does not change the variable we already have, it asks React for a new render in which `useState` returns the new value, and every event handler created during a render keeps reading that render's value, even if it runs later.
* **The Friction**: A developer writes a `handleThemeClick` handler: `setTheme('dark'); console.log(theme); sendAlert(theme);`. The console prints `'light'`, and the alert sends `'light'`, even though `setTheme('dark')` was just called. Frustrated, the developer assumes React's setter is broken or has a timing bug.
* **The Mechanism**: Snapshot mental model. React calls the component with the state for this render, and the JSX and event handlers it returns are computed from that value. Inside that render the state variable is a `const` that never changes; neither later setter calls nor a `setTimeout` delay can change what a handler from that render sees. Calling `setNumber(number + 1)` three times in one handler therefore adds 1, not 3, because each call reads the same `number`.
* **Under the Hood**: JavaScript closure semantics: when `ArticleView` renders with `theme = 'light'`, all handlers created during that render close over that specific value. The setter requests a *new* render with a *new* snapshot, but cannot reach back and change the variable inside the handler that is already running.
* **The Code Experiment**:
  * *Naive*: Calling `setCount(count + 1)` and reading `count` on the next line or passing it to an API call, expecting the new number; calling the same setter three times in a row and expecting the count to rise by three.
  * *React*: A `StoryFeedback` form that computes `const nextRating = 5` once and passes `nextRating` to both `setRating` and `sendRating`, and an alert scheduled with `setTimeout` that reports the rating from the render that created it.
* **Scope Boundary**: Focus strictly on the snapshot concept, closure capture within a single render, and why repeated setter calls read the same value. Do not introduce updater functions as the fix (Q17) or `useRef` for mutable storage (Q29).
