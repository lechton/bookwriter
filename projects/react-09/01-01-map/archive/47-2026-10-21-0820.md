# Q47: Designing Callback Contracts Across a Deep Tree
* **Topic Tag**: `#callback_props` | `❱❱ MORE`
* **Interview Question**: *How do you design robust inverse data flow patterns and avoid callback prop drilling?*
* **Core Truth**: A callback prop is a contract: the component that owns the state decides what a change means, and the child only reports what happened (`onArchive(articleId)`), never how to change the state. When a callback must travel through many layers that never call it, the fix is structural: let the owner render the child directly through a composition slot, or put a reducer's `dispatch` in context so any descendant can send an action.
* **The Friction**: `AdminPage` owns the article list, and an `ArchiveButton` five levels down must archive an article. The developer passes `setArticles` through `ArticleList`, `ArticleSection`, `ArticleCard`, and `ArticleActions`. Each middle component lists a prop it never uses, `ArchiveButton` now rebuilds the whole array itself, and when a second button needs the same change, the archive logic exists in two places and drifts apart.
* **The Mechanism**: (1) Name callbacks by event (`onArchive`, `onSelect`) and pass the minimum data (`onArchive(article.id)`), keeping the state update inside the owner's `handleArchive`. (2) Shorten the path with composition: the owner renders `<ArticleCard actions={<ArchiveButton onArchive={handleArchive} />} />`, so intermediate layers forward JSX, not callbacks. (3) For deep trees or many senders, pair `useReducer` with context and let descendants call `dispatch({ type: 'archived', id })`.
* **Under the Hood**: Why event-shaped callbacks scale: the child depends only on a function signature, so the owner can change its state shape, add analytics, or switch to a reducer without touching the child. The `dispatch` function React returns from `useReducer` keeps the same identity on every render, so a context that carries only `dispatch` never changes value and its consumers do not re-render when the articles change.
* **The Code Experiment**:
  * *Naive*: Threading `setArticles` through four layers so a leaf button rebuilds the article array, duplicating the archive logic in every button that needs it.
  * *React*: The owner keeps `handleArchive(id)` and hands `onArchive` only to the button it renders through an `actions` slot; for the full app, an `ArticlesDispatchContext` exposes `dispatch` so any button sends `{ type: 'archived', id }`.
* **Scope Boundary**: Focus on callback contract design, event-style naming, composition slots that shorten callback paths, and dispatch through context. Build on handler props (Q13), `children` (Q7), lifting state (Q23), and reducer with context (Q28) without re-teaching them; do not introduce external state libraries (Q60).
