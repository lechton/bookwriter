# Q74: Seamless Screen Transitions with ViewTransition
* **Topic Tag**: `#view_transitions` | `❱❱ MORE`
* **Interview Question**: *How do you animate between two screens with ViewTransition?*
* **Core Truth**: React's View Transitions integration coordinates with the browser's native View Transitions API to smoothly animate DOM changes across page navigations and major UI transitions during state changes.
* **The Friction**: A reader clicks an article thumbnail on the homepage. The browser cuts abruptly to the full article page; the thumbnail snaps instantly into a full-bleed hero image with no visual continuity, disorienting the reader and feeling like a clunky legacy website.
* **The Mechanism**: View Transitions in React (`<ViewTransition>` or `document.startViewTransition()` in React 19). Marking an update as a transition instructs React to capture DOM snapshots before and after the commit, allowing CSS pseudo-elements to morph elements smoothly.
* **Under the Hood**: The browser View Transition pipeline: the browser captures a snapshot of the current DOM, pauses rendering, executes the React DOM commit, captures the new DOM snapshot, and runs CSS morph animations (`::view-transition-old` / `::view-transition-new`) between matching `view-transition-name` elements.
* **The Code Experiment**:
  * *Naive*: Navigating between article list and detail views with instantaneous DOM swaps, producing harsh visual cuts.
  * *React*: Wrapping the article navigation transition in a View Transition, smoothly morphing the thumbnail into the full hero banner with CSS `view-transition-name: article-hero`.
* **Scope Boundary**: Focus on React 19 View Transitions integration, browser compatibility principles, and `view-transition-name` coordination. Do not cover full third-party animation libraries like Framer Motion.
