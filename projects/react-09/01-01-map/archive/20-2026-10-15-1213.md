# Q20: Controlled Inputs
* **Topic Tag**: `#controlled_inputs` | `❱ CORE`
* **Interview Question**: *How do you make an input, textarea, or select fully controlled by React state?*
* **Core Truth**: A controlled field takes its displayed value from React state through a prop (`value` for inputs, textareas, and selects; `checked` for checkboxes and radios) and reports each change through `onChange`, where our handler writes the new value into state; state becomes the single source of truth, so whatever we put in state is what the field shows.
* **The Friction**: A reader types a correction into a `<textarea defaultValue="">` and, after submit, the handler calls `setText('')`, yet the old text stays in the box, because a `defaultValue` field keeps its own value and never reads state again. The developer switches to `value={text}` but forgets `onChange`, and now the field refuses every keystroke while the console warns that a `value` prop without an `onChange` handler renders a read-only field.
* **The Mechanism**: The controlled pair: `<textarea value={text} onChange={e => setText(e.target.value)} />`, `<select value={section} onChange={e => setSection(e.target.value)}>` (instead of `selected` on an `<option>`), and `<input type="checkbox" checked={isUrgent} onChange={e => setIsUrgent(e.target.checked)} />`. The handler must set state synchronously from `e.target`, and the initial state must be a string such as `''`, never `undefined`.
* **Under the Hood**: The browser changes the field's DOM value on each keystroke, and React calls `onChange` for every keystroke (unlike the browser's native `change` event, which waits for the field to lose focus). After the resulting render, React writes the state value back to the DOM, so a handler that does not set state, or sets it to something else (such as an uppercased copy), decides what the field finally shows. Starting with `value={undefined}` and later passing a string makes React warn that a component is changing an uncontrolled input to be controlled.
* **The Code Experiment**:
  * *Naive*: Setting `value={text}` without an `onChange` handler (freezing the field so the reader cannot type), or letting `value` start as `undefined` before becoming a string.
  * *React*: An `ArticleCorrectionForm` with a controlled `<input>`, `<textarea>`, `<select>`, and checkbox, enforcing a live character count and clearing every field after submit by setting state.
* **Scope Boundary**: Focus on the controlled pair for each field type, the synchronous `onChange` rule, and the uncontrolled-to-controlled warning. Do not cover choosing between controlled fields and uncontrolled `FormData` (Q39), reading fields through refs (Q30), or React 19 form actions and `useActionState` (Q40 to Q44).
