# Q17: Batching and Updater Functions
* **Topic Tag**: `#state_updates` | `❱ CORE`
* **Interview Question**: *How does React queue multiple state updates, and when do you need an updater function?*
* **Core Truth**: React waits until all the code in an event handler has run before it re-renders, so several setter calls in one handler produce one render (batching); a setter given a value replaces the queued state with that value, while a setter given an updater function (`p => p + 1`) receives the result of the updates queued before it, which is what we need when the next value depends on the previous one and more than one update is queued before the render.
* **The Friction**: In a ticket order, a user clicks "+3 Tickets". The handler calls `setTickets(tickets + 1)` three times in a row. Instead of increasing by 3, the counter only increments by 1, because each call reads the same snapshot value and queues "replace with `0 + 1`" three times.
* **The Mechanism**: The updater function form of the setter (`setTickets(t => t + 1)`), named by convention after the first letter of the state or with a `prev` prefix. The updater must be pure and only compute the next value from its argument, because React calls it during the next render (and twice in development under StrictMode, Q46).
* **Under the Hood**: The update queue: during the next render React walks the queue in order, starting from the current state; a value entry replaces the running result, and an updater entry is called with the running result. So `setNumber(number + 5); setNumber(n => n + 1);` from `0` renders `6`, and `setNumber(number + 5); setNumber(n => n + 1); setNumber(42);` renders `42`.
* **The Code Experiment**:
  * *Naive*: Calling `setTickets(tickets + 1)` three times in one click handler, resulting in a single increment.
  * *React*: Calling `setTickets(t => t + 1)` three times, so the queue applies three increments and the counter rises by 3, followed by the mixed value-then-updater queue traced step by step.
* **Scope Boundary**: Focus on batching within one event handler, the update queue, the updater function, and when it is needed. Do not cover `flushSync` (Q65), batching inside timeouts and promises and other React 18 batching internals (Q75), or reducers (Q26).
