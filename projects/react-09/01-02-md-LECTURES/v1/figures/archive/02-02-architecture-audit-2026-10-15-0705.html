Component Anatomy & Capitalization Architecture Audit

An architectural comparison evaluating how React compiles custom components, enforces PascalCase, and executes declarative trees.

Contract Dimension Naive JavaScript Reflex (Anti-Pattern or Bug) React Platform Reality (Compiler & Runtime Contract)
1. Capitalization (AST Branching) Lowercase Function Tags Transpiler compiles <articleCard /> to string literal _jsx("articlecard"), creating an empty unknown HTML element that fails silently. PascalCase Identifiers Transpiler compiles <ArticleCard /> to unquoted identifier _jsx(ArticleCard), instructing React to invoke the component function.
2. Invocation Mode (Tree Custody) Direct Function Calls Calling {ArticleCard()} runs synchronously as plain JavaScript, inlining child markup without giving React custody of component lifecycle. Declarative JSX Tags Writing <ArticleCard /> passes a function reference, allowing React to orchestrate rendering, reconciliation, and component boundaries.
3. Return Syntax (ASI Protection) Naked Multi-Line Return Placing markup on the line after return causes automatic semicolon insertion, returning undefined and rendering a blank card. Parenthesized Expressions Opening parentheses on the same line as return ( signals that markup continues across lines, preventing semicolon insertion.
4. Function Scope (Component Identity) Nested Component Definitions Declaring ArticleCard inside App allocates a new function identity on every render, causing React to destroy and rebuild DOM nodes. Top-Level Declarations Declaring components at module top level preserves function identity across renders, retaining living DOM nodes, input text, and cursor focus.
Architectural Verdict Silent Failure & DOM Loss Treating components like normal JavaScript helper functions creates empty tags, blank screens, and accidental DOM destruction. Reliable Component Contracts PascalCase functions declared at the top level and invoked as declarative tags guarantee predictable rendering and stable DOM identity.
