Architecture Audit
Plain Local Variables vs Declarative useState

Six architectural criteria distinguishing temporary stack variables from React state memory.

CriterionArchitecture Facet Imperative HabitPlain Local Variable Declarative ModelComponent Memory (useState)
Memory Storage Stored on local JavaScript call stack; inaccessible to React runtime Preserved in React internal fiber node outside the component function
Update Trigger Direct assignment (likes = next) changes memory silently; screen never updates Calling setter (setLikes(next)) writes state and requests a component re-render
Render Survival Function runs from top on every render, resetting variable to initial value React retrieves stored value for each slot, ignoring initial value on re-renders
Instance Scope Moving variable outside component shares one copy across all cards on page React allocates private, isolated memory slots for every rendered card instance
Initial Calculation Evaluates initial function argument on every single render pass (useState(fn())) Initializer arrow (useState(() => fn())) instructs React to run calculation only on mount
Handler Wiring Invoking setter directly in JSX (onClick={setLikes()}) causes infinite crash Passing function reference (onClick={() => setLikes()}) defers execution until click
Audit verified against React 19.3.0 and Chrome 154 JavaScript execution lifecycle.
