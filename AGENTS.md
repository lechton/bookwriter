### The Golden Rule: De-Prescribe Before Adding Rules
- **The Common AI Fallacies**:
  1. *The Reflexive Ban Fallacy*: AI models commonly default to proposing bans, inventing negative prohibitions, and brandishing authoritarian language like *"never do this"* and *"never do that"*.
  2. *The Exclusionary Fallacy*: Models also commonly interpret positive guidance (*"do this"*) as a strict commandment that *"anything other than this is forbidden"*.
- **The Golden Rule**: The FIRST thing to consider when fixing an unwanted model behavior or addressing a defect is **how to make a subtle edit in existing rules to remove the prescriptions or conflicts that created the problem**, rather than stacking new rules, bans, or prohibitions on top.
- **Root-Cause Pruning over Rule Accumulation**: Before proposing or writing any new rule, determine what existing instruction forced or encouraged the bad output. Remove the offending prescription, resolve the conflict, or soften the over-specified constraint. Keep the instruction system lean, flexible, and grounded in clear standards rather than micro-managing behavior through endless negative prohibitions.

## Always-on conventions
- Never hard-wrap. One continuous line per paragraph, bullet, or prompt, in every file.
- **Chat-Only Constraint ("nnn")**: When the user prompt contains `"nnn"`, do NOT edit, create, or touch any files, and do not run modifying commands. Strictly discuss, analyze, and respond in the chat until explicitly ordered to edit files.
- **Execution Trigger ("ppp")**: When the user prompt contains `"ppp"`, it means "proceed" — immediately execute the approved plan, author or edit files, and run builds without requesting further confirmation.
- **Instructions-and-Skills-Only Execution Trigger ("ppi")**: When the user prompt contains `"ppi"`, you are allowed to proceed and edit the instructions AND/OR the skills files, but NOT any lecture or other project file to adapt from them. You MUST stop the moment you finish polishing and fixing the instructions and skills.
- **Instruction Root-Cause & Pruning Trigger ("iii")**: When the user prompt contains `"iii"`, it means: "When there is a problem, focus on the instructions that enabled this problem, examine pruning or editing them to solve the issue in the future, and present the proposed instruction changes directly broken down by section with exact diffs (showing removals, additions, and registry updates) so the user can clearly see what will be pruned and added before approval."
- Lectures are TTS-safe: no code, no symbols a synthetic voice cannot read, no em-dashes; a standalone lesson that never addresses whoever commissioned it.
- **Organic Lexical Audit (OLA)**: Always introduce new lexical terms using visceral, real-world, high-stakes contexts. Don't just explain the feature—create a scenario where the newbie would physically hit a wall without it (e.g., "if you rename the ID, the button breaks silently and you lose the sale").
- **Typology Tagging**: Every lecture's interview question must include its curriculum typology (`❱ CORE`, `❱❱ MORE`, or `❱❱❱ ADVANCED`). Format: `> INTERVIEW QUESTION | ❱ CORE | [Question text]`.
- **Table Formatting**: The top row of a markdown table acts as the header. Format column titles using a break: `**MAIN TITLE**<br>(subtitle)`. To prevent awkward grey-box padding breaks in the PDF, use `<br>` to manually wrap long code strings inside table cells (e.g., `` `element.addEventListener`<br>`('click', fn)` ``).
- **Summary Code Block Formatting**: When writing right/wrong examples in summaries, DO NOT put comments inside the code block.
  1. Add `right` or `wrong` directly to the fence language tag (e.g., ` ```jsx right ` or ` ```jsx wrong `). This automatically generates the side-panel SVG indicator (green check or red cross).
  2. Put the instruction on the line exactly above the code block using flush-left bold text without emojis: `**DO THIS:** [instruction]` or `**DO NOT DO THIS:** [instruction]`.
- **Authoritative Quotes**: Before authoring, search available books (e.g. EPUBs/PDFs in `documentation official/`) and official sources. Exercise strict reserve: only include a verbatim quote if it makes a genuine contribution—meaning it is highly pertinent, insightful, or counter-intuitive. When used, cite it properly as a formal publication to the reader (e.g., citing the book's author/title, never linking to a GitHub repository).
- Do not edit a section's `## Explanation`. It builds the figure (PNG), which guides the Gemini infographic.
- A section's title format is "Topic: Lesson"; examples are real, runnable scripts in the National Times world.

## Accessibility & Performance Lectures (`diagram-lab/output/accessibility-01`)
- Instructions & Law: `instructions.md` and `AUTHOR-BRIEF.md`.
- **Harmonious Code + UI Step Rhythm**:
  1. Mandatory Text Lead-in: Every `### ` heading MUST open with 2–3 sentences of conceptual framing before any code block or canvas appears (prevents floated marginalia `h3` collisions in PDF layout).
  2. Minimal Code Precedes UI: Under each section, the minimal code snippet directly precedes the UI canvas every single time.
  3. Minimal UI Comparison (`layout="compare"`): Max 2 elements (one wrong, one right), default to `width="2/3"`, no black bottom console strip.
  4. Dark Surface Simulation (`surface="dark"`): Use for evaluating contrast on dark containers/footers so failures (e.g. 1.1:1 ratio) realistically blend into the dark slate card.
  5. Tight Control Attachment & Ghost Outlines: Outlines wrap tightly around the interactive control itself (`.ui-control-wrapper`). Stripped focus (`outline: none`) uses `ghost` (dashed red perimeter + `✕ 0px` badge) so invisible focus is visually emphasized.
  6. Explain Before and After: Frame the concept in prose, show the code snippet, show the UI consequence, and follow with concrete analytical derivation. Multi-step lessons repeat this loop cleanly.
  7. Page 2 Fit Budget: Keep Section 1 lead-in prose strictly to 2–3 concise sentences (3–4 lines) and code snippets to 2–4 lines without mid-line wrapping, ensuring Heading, Lead-in, Code Editor, and 2/3 Compare Canvas fit together on Page 2 without pushing the canvas to Page 3.
  8. Speech Bubbles & Tooltips: Assistive tooltips and screen-reader bubbles sit directly below the interactive control with a centered upward pointer (▲) directed at the control, followed by the evaluation chip at the bottom.
  9. No Numbered (1) Badges in Compare Mode: Compare layouts contrast two alternate states, not sequential keyboard tab stops; numbered focus badges are suppressed in compare mode.
