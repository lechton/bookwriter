A MODULE IS A CLOSURE
1// session.js — evaluated once, shared everywhere
2let reader = null; // private — never exported
3
4export function login(name) { reader = name; }
5export function current() { return reader; }
6
7// — called from two different files —
8login("Ada Lovelace"); // comment-form.js (write)
9current(); // masthead.js (read)
MODULE & SHARED-SCOPE FLOW
Stage 1: The module runs once
import "./session.js"
module scope
reader: null
First import evaluates the file top-to-bottom — one scope is born.
Stage 2: Exports capture it
login()
current()
captured
reader
Both exported functions close over the private reader.
Stage 3: One file writes
login("Ada…")
module scope
reader: "Ada…"
comment-form.js sets the one shared reader.
Stage 4: Another file reads
current()
✓ same value
"Ada Lovelace"
masthead.js, a different file, sees it. reader itself is never importable.
SUMMARY
A module's top-level scope is a closure, created once on first import. State you declare but don't export stays private — the exported functions close over it, and they are the only doors in. Every file that imports them shares the one live instance, which is exactly how a module becomes a singleton store.
