Stage 1: A diamond shape

label

One source feeds two deriveds; one effect reads both — paths split and rejoin.
Stage 2: The source changes
price = 200
Both deriveds now depend on a new value at once.
Stage 3: Topological order
✓ withTax = 240
✓ label = "200 pts"
effect
Both middles recompute first; the effect then runs once.
Stage 4: The glitch it avoids
✗ naive order
effect(240, "100 pts")
A wrong order runs the effect on a half-updated mix — a glitch.
SUMMARY
In a diamond, one source feeds two deriveds and a single effect reads both. A correct system updates in topological order — both middle deriveds before the bottom effect — so the effect never runs on a half-updated mix. The failure has a name: a glitch, the brief flash of an inconsistent state.
