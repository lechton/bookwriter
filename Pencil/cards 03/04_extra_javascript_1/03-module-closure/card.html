Summary

In JavaScript, a module's underlying code is evaluated only once the first time it is imported. This caching behaviour means any module-level variable automatically becomes a shared singleton state for your entire application. Because the variable itself is deliberately left unexported, it remains strictly private and encapsulated from the outside world. Other files can only modify or read this state by calling the specific exported functions, which act as a controlled, secure public API. Ultimately, this structural pattern ensures safe and perfectly synchronised data access for every importer.

Explanation
A module's top-level code runs once, the first time it is imported; variables you don't export stay private to the module, and the exported functions close over them. Every file that imports those functions talks to the same single instance, so the module acts as one shared store — a singleton.
