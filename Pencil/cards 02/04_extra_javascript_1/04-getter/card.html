A Getter Runs a Function Every Time You Read It
article.js
1const article = {
2 author: "Ada Lovelace",
3 get byline() { return "By " + this.author; },
4};
5article.byline;
Line by Line
1—A plain object holding two kinds of property: ordinary stored data, and a computed accessor.
2—author is a normal data property — reading it simply hands back the stored string, no code runs.
3—The get keyword makes byline an accessor: a property that is secretly a function, run on every read. Here it just joins "By " with the current author (this is article) and returns the result — a fresh value, never stored.
5—Reading article.byline with no parentheses runs the getter and returns "By Ada Lovelace"; change author and the next read recomputes, so it can never go stale.
Explanation
A getter is a property defined with the get keyword; reading it runs a function instead of returning a stored value, with no parentheses at the call site, so its value is recomputed every time and can never go stale — the first step of interception, a plain-looking read that secretly runs code.
Reading article.author and article.byline look identical but behave differently:
article.author returns the stored string no code runs
article.byline runs the function (joins "By " + author) By Ada Lovelace
✓ article.byline → accessor: a function runs on read → fresh "By Ada Lovelace"
article.author → data property: the stored string is returned directly, no code runs
read with no parentheses, yet code runs → thisis interception, the first rung toward reactivity
data property — stores a value; reading it returns that value as-is
getter (accessor) — defined with get; reading it runs a function and returns the result
interception — making an ordinary read or write secretly run code
byline looks like data but runs code on every read — that is a getter; because a read can run code, a read can be made to do bookkeeping, the first rung of interception that reactivity is built on.
