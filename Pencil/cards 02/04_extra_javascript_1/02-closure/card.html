A Closure Keeps a Function's Variables Alive and Private
clapButton.js
1function createClapButton() {
2 let claps = 0;
3 return { clap() { claps++; }, total() { return claps; } };
4};
5const article = createClapButton();
6article.clap();
7article.clap();
8article.total();
Line by Line
1—A factory function. Each time it runs, everything inside its braces is a fresh, private scope.
2—claps is a local variable, private to this scope — no code outside can name it directly.
3—Returns two functions defined inside, clap() and total(). Both use claps, so both capture it — they close over it.
4—The function returns here and its call is finished. Normally claps would be discarded now — but it is not.
5—article holds the two returned functions. Because they still reference claps, that scope is kept alive.
6–7—Calling clap() twice raises the very same claps to 1, then 2 — the private value persists between calls.
8—total() reads that same claps back, giving 2. The only way to touch claps is through clap() and total().
Explanation
When a function finishes, its local variables are normally discarded. But a function defined inside it and then returned keeps a live reference to those variables, so they stay alive — a function bundled with the variables it captured is called a closure.
The returned functions keep the inner scope alive after the call ends:
