A Proxy Intercepts Every Read and Write Through Traps
proxy.js
1const target = { headline: "Markets rally" };
2const article = new Proxy(target, {
3 get(t, k) { console.log("read", k); return t[k]; },
4 set(t, k, v) { console.log("write", k); t[k] = v; },
5});
6article.headline;
7article.claps = 5;
Line by Line
1—target is the real object we want to watch — here it has one property, headline.
2—new Proxy(target, handler) wraps target: from now on, reads and writes go to article, the proxy, which runs your handler first.
3—The get trap runs on every property read: it logs the access, then returns the real value from target — your code runs in the gap before the value comes back.
4—The set trap runs on every property write: it logs, then stores the value on target.
6—Reading article.headline fires the get trap, which logs "read headline" and returns "Markets rally".
7—Writing article.claps = 5 fires the set trap — even though claps never existed before. A proxy catches every property, including brand-new ones.
Explanation
A proxy is an object that stands in front of a target; every operation on it — get, set, and more — first runs a trap function you supply, then reaches the target. Unlike a getter, which guards one property you named in advance, a proxy intercepts every property — even ones added later.
A read and a write, both routed through the proxy's traps:
article.headline get trap returns "Markets rally"
article.claps = 5 set trap stores claps — new!
✓ read article.headline → get trap runs (logs) → returns "Markets rally"
✓ write article.claps = 5 → set trap runs (logs) → stores a brand-new property

trap — the handler a proxy runs for one kind of operation, like get or set
interception — running code in the gap before a read or write reaches the target
A proxy intercepts every read and write through traps — even properties added later — exactly how a reactive framework runs its bookkeeping on your plain code, with no calls for you to write.
