Own Properties First, Then Inherited from the Prototype
Article.js
1class Article { publish() { return "live"; } }
2const piece = new Article();
3piece.headline = "Markets rally";
4piece.headline;
5piece.publish();
6piece.author;
Line by Line
1—Defining a method in the class body puts publish() on Article.prototype — one shared copy, not on each object.
2—Creates piece, a new Article object. It starts with no own properties, but carries a hidden link to Article.prototype.
3—Adds headline directly onto piece — a brand-new own property, stored on the object itself, separate from the prototype.
4—Reading headline finds it on piece itself, its own property, so the result is "Markets rally".
5—piece has no own publish, so the lookup follows the link up to Article.prototype and uses it there — we never put it on piece, so it is inherited, and the result is "live".
6—author is not on piece and not anywhere up the chain, so the result is undefined.
Explanation
JavaScript looks on the object itself first: a property added to the object — its own property — is found there at once. If it isn't there, the lookup follows the object's link to its prototype and inherits the property from there, continuing up the chain until it is found or the chain ends at null, which gives undefined.
