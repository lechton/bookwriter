A Module's State Is Created Once and Shared by Every Importer
session.js
1let reader = null;
2export function login(name) { reader = name; }
3export function logout() { reader = null; }
4export function current() { return reader; }
Line by Line
1—reader is a module-level variable, created once the first time this file is imported. It is private — never exported — so no other file can name it directly.
2—login() is exported. It writes the private reader. Exporting the function, not the variable, is the only way in.
3—logout() is exported too; it clears that same one reader.
4—current() is exported; it reads the private reader back. Importers get the value only through this function.
Explanation
A module's top-level code runs once, the first time it is imported; variables you don't export stay private to the module, and the exported functions close over them. Every file that imports those functions talks to the same single instance, so the module acts as one shared store — a singleton.
Two files import the functions and reach the same one instance:
comment-form.js
import { login }
writes
session.js · module scope
reader: "Ada Lovelace"
reads
masthead.js
import { current }
✓ comment-form.js → login("Ada Lovelace") → sets the one shared reader
✓ masthead.js → current() → reads that same reader → "Ada Lovelace"
✗ import { reader } → impossible — reader is never exported
module — a file whose top-level code runs once and whose exports are shared
private (module) — a variable not exported, reachable only through the module's functions
singleton — one shared instance everyone gets, not a fresh copy per import
Import the functions and every file shares one reader — change it in one file and all the others see the change. The module is a singleton store.
