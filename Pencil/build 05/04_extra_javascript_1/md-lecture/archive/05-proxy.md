# 5 | Proxy: A Proxy Intercepts Every Read and Write Through Traps

We just saw how a getter can run code when we read the byline property. But a getter has a serious limitation: it only guards the one specific property you named in advance. What catches a property you did not name? In our newsroom, we need to audit our article objects. We want to log a message to the console every single time any property is read or written, even for properties we invent later. Look at the code snippet you have in front of you, titled: Proxy: A Proxy Intercepts Every Read and Write Through Traps.

JavaScript gives us a tool to wrap an entire object, intercepting everything that happens to it. We take our original article object, which we call the target, and we hand it to a new Proxy. A proxy is an object that wraps a target and intercepts its operations through traps. Our proxy sits entirely in front of the target. Any code trying to read or write the article must go through the proxy first.

We give our proxy two specific handlers to run when an operation is intercepted. We call these handlers traps. A trap is a handler function a proxy runs for a specific operation, like get or set. We define a get trap to run whenever a property is read, and a set trap to run whenever a property is written. Inside our get trap, we print the word read followed by the name of the property, and then we return the real value from the target. Inside our set trap, we print the word write, save the new value onto the target, and finish.

Now, when we read the headline property through our proxy, the get trap fires first. It prints our log message, then hands back the headline. If we decide to add a brand-new property to the article, setting a claps count to five, the set trap fires. Even though the claps property never existed before, the proxy intercepts the write, logs it, and stores the number. Now we can run code on every read and every write, catching properties we never named in advance. What is the most useful thing to run there?
